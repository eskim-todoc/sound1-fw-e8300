# 레지스터 변경 검증 체크리스트

IQS323 등 I2C 디바이스의 레지스터 값을 변경할 때 반드시 거쳐야 하는 검증 절차.
실기 테스트 전에 이 체크리스트를 통과해야 한다.

---

## 체크리스트

### 1. 변경 대상 비트 식별

- [ ] 변경할 레지스터 주소, 비트 범위, 변경 전/후 값을 명시
- [ ] 해당 레지스터의 **전체 비트 필드**를 데이터시트에서 확인 (변경 대상 비트뿐 아니라 같은 레지스터의 다른 비트도)
- [ ] 변경하지 않는 비트가 의도한 값으로 유지되는지 확인

### 2. 데이터시트 근거 확인

- [ ] 변경하려는 값에 대한 데이터시트 설명을 **원문 그대로** 인용
- [ ] "~일 것이다", "~인 것 같다" 같은 추측이 포함되어 있으면 **변경 금지** → 추가 조사 필요
- [ ] 해당 모드/값이 다른 레지스터나 기능에 미치는 영향을 데이터시트에서 확인

### 3. 전후 동작 시뮬레이션

- [ ] 변경 전: 현재 동작과 문제점을 정확히 서술
- [ ] 변경 후: 예상되는 동작을 단계별로 서술
- [ ] 변경이 초기화 시퀀스의 다른 단계에 영향을 주는지 확인
- [ ] 변경이 런타임 동작(폴링, 이벤트, LTA 추적)에 영향을 주는지 확인

### 4. 부작용 체크

- [ ] 해당 레지스터를 참조하는 다른 레지스터/기능이 있는지 확인
- [ ] Auto Re-ATI, Reseed 등 자동 기능에 영향을 주는지 확인
- [ ] Power Mode 전환 시 해당 설정이 유지되는지 확인

### 5. 불확실성 명시

- [ ] 확실하지 않은 부분이 있으면 **"미확인"으로 명시**하고 사용자에게 알림
- [ ] 미확인 항목이 있으면 실기 테스트 전에 해결 방안 제시 (데이터시트 추가 확인, Azoteq 문의 등)

---

## 적용 예시

```
[변경 요청] ATI Setup(0x36) LSB의 ATI Mode 비트(Bit2:0)를 100→000으로 변경

1. 비트 식별
   - 레지스터: 0x36, Bit2:0 (ATI Mode)
   - 변경 전: 100 (Full), 변경 후: 000 (Disabled)
   - 같은 레지스터의 Bit3(ATI Band), Bit15:4(Resolution Factor)는 변경 없음

2. 데이터시트 근거
   - "000: Disabled" → 데이터시트에 Disabled 시 보상값 적용 여부 기술 없음
   - ⚠ 불확실: Disabled가 보상값 무시인지, ATI 알고리즘만 중지인지 명확하지 않음

3. 동작 시뮬레이션
   - 변경 후: 보상값이 적용되지 않으면 → Counts가 보정 없이 출력 → 터치 감지 불가능?
   - ⚠ 불확실: 확인 필요

4. 부작용
   - Auto Re-ATI 동작 여부: Disabled면 Re-ATI도 비활성?
   - ⚠ 불확실

5. 결론: 미확인 항목 2건 → 실기 테스트 전 추가 확인 필요 → 사용자에게 위험 고지
```
