## 1. 배경

LED 운용 스펙 사진(`led_ind_state.JPG`)이 갱신되었고, 이에 맞춰 펌웨어 LED 패턴을 일치시켜야 한다. 동시에 절전 모드 진입 조건과 ULP 진입 후 잔여 코드 정리, 그리고 시각적 품질 개선(LED Dimming 효과) 요청이 함께 들어왔다.

---

## 2. 요구사항

### 2.1 LED 패턴 사진 반영 (스펙 갱신본)

> [!IMPORTANT]
> 갱신된 패턴 표는 사진 `led_ind_state.JPG` 가 정본. 아래는 사진 표를 코드 관점에서 정리한 사본이다.

| 상태 | 색상 | 패턴 | ON | OFF | 주기 | 비고 |
|---|---|---|---:|---:|---:|---|
| `LED_ST_POWER_ON` | 하늘색 | 점멸 ×5 | 80 ms | 220 ms | 300 ms | 변경 없음 |
| `LED_ST_POWER_OFF` | 파랑 | 점멸 ×4 | 100 ms | 200 ms | 300 ms | 변경 없음 |
| **`LED_ST_MAPPING_ISD_BATT_READY`** | **파랑** | **점멸** | **200 ms** | **800 ms** | **1000 ms** | **신설 (배터리 > 20% & ISD 연결)** |
| **`LED_ST_MAPPING_NO_ISD_BATT_READY`** | **파랑** | **지속 ON** | — | — | — | **신설 (배터리 > 20% & ISD 미연결)** |
| **`LED_ST_MAPPING_ISD_BATT_LOW`** | **보라** | **점멸** | **100 ms** | **900 ms** | **1000 ms** | **신설 (0% ≤ 배터리 ≤ 20% & ISD 연결)** |
| **`LED_ST_MAPPING_NO_ISD_BATT_LOW`** | **보라** | **지속 ON** | — | — | — | **신설 (0% ≤ 배터리 ≤ 20% & ISD 미연결)** |
| `LED_ST_ERROR_*` | 빨강 | 점멸 | 180 ms | 180 ms | 360 ms | 변경 없음 |
| `LED_ST_BATT_CRITICAL` | 노랑 | 점멸 | 1100 ms | 1100 ms | 2200 ms | 변경 없음 |
| `LED_ST_BATT_MID` | 노랑 | 지속 ON | — | — | — | 변경 없음 |
| `LED_ST_BATT_READY` | 녹색 | 지속 ON | — | — | — | 변경 없음 |
| `LED_ST_IN_USE` | 흰색 | 지속 ON | — | — | — | 변경 없음 |
| **`LED_ST_PAIR`** | 파랑 | **점멸** | **500 ms** | **500 ms** | **1000 ms** | **변경 (180/180 → 500/500)** |
| `LED_ST_OTA_QCC` | 녹색 | 점멸 | 1100 ms | 1100 ms | 2200 ms | 변경 없음 |
| `LED_ST_OTA_EZAIRO` | 녹색 | 점멸 | 180 ms | 180 ms | 360 ms | 변경 없음 |

**제거**: 기존 `LED_ST_MAPPING_NO_ISD`, `LED_ST_MAPPING_ISD` 두 상태는 위 4종으로 분화되며 폐지.

### 2.2 절전 모드 진입 가드

다음 상태 중 **하나라도 활성**이면 절전 모드 진입을 보류한다:

| 항목 | 판단 신호 |
|---|---|
| 매핑 진행 중 | `BLE_communicationState.mappingConnection == true` |
| 페어링 진행 중 | `tdc_led_get_ind_state() == TDC_LED_IND_STATE_PAIR` |
| OTA 진행 중 | `tdc_led_get_ind_state() == TDC_LED_IND_STATE_OTA_QCC` 또는 `TDC_LED_IND_STATE_OTA_EZAIRO` |

배터리·ISD 연결 여부와는 **무관** — 위 셋 중 하나라도 활성이면 절전 진입을 차단한다.

### 2.3 절전 모드 ULP 루프 이후 코드 정리

`func_sleep()` 의 `while (1) // ULP loop` 종료 이후 코드(2026-04-23 기준 [main.c:729-747](../src/2__cm3/Cortex-M3-src/main.c#L729))는 **도달 불가**(롱-터치 시 `SYS_WATCHDOG_RESET()` 으로 칩 리셋). 잔여 코드를 모두 제거해 가독성·오해 가능성을 줄인다.

### 2.4 `debug_led_pattern()` 제거

이전 LED 운용 분석/구현 단계에서 디버깅 용도로 도입한 함수. 현행 Arbiter 구조에서는 더 이상 호출되지 않으므로 선언·정의 모두 제거.

### 2.5 LED Dimming 효과 (타이머 3 활용)

이전 터치 센서 ULP 진입 코드에서 타이머 3 을 사용했으나, 현재 Run 모드 동작 중에는 타이머 3 이 1 ms 주기로 시스템 tick 만 만들어 주고 LED 밝기 변조에는 활용되지 않고 있다. 이를 활용해 LED 표시에 부드러운 Dimming 효과를 주고 싶다.

대상 시각 효과:
- **점멸할 때**: ON 구간을 거친 ON/OFF 토글이 아닌, 점진적 fade-in / fade-out 으로 표시
- **색상이 변경될 때** (Arbiter 가 best 선택을 다른 상태로 갱신): 이전 색이 fade-out 후 새 색이 fade-in

> [!NOTE]
> "Dimming" 의 구현 방법(PWM 듀티 변조, 시간 함수 형태)은 구현계획에서 정의한다. 본 요구사항은 "타이머 3 을 활용한 부드러운 시각 전환" 만 명시.

## 3. 비목표 (Out of Scope)

- LED 우선순위 (prio) 재조정 — 현 prio 75 (매핑) / 70 (PAIR) / 80 (OTA) 유지
- LED Arbiter 전체 재설계 — 새 매핑 4종은 기존 Arbiter 위에 얹기만
- 충전기 연결 시 동작 변경 — 기존 그대로 유지
- 배터리 LED 단독 표시 시 LOW(20%) 임계값 추가 — 매핑일 때만 LOW 분기. 단독 배터리 표시는 기존 10/80% 임계 그대로
- 사용자 LED off 플래그 동작 변경 — 기존 그대로 유지

## 4. 제약

- **호환성**: 기존 enum 값 추가는 새 항목을 enum 끝쪽에 배치 (Legacy 매핑 영향 없도록)
- **빌드**: Eclipse 환경에서만 빌드 가능. 컴파일러는 GCC ARM. 작업 시 대괄호 초기화/지정자 초기화 사용 시 누락 항목 0 초기화 의도 유지
- **회귀 위험 최소화**: 단계별 커밋(LED 패턴 → 가드 → 정리 → Dimming) 으로 분리해 회귀 추적이 쉽도록 한다
- **레지스터 변경 금지**: 본 작업에서는 PMIC/타이머 H/W 레지스터를 직접 변경하지 않는다 (타이머 3 은 기존 1 ms tick 그대로 활용)

## 5. 수용 기준

- [ ] 사진 표와 패턴 디스크립터 테이블이 일치한다 (오실로스코프 ±5 % 이내)
- [ ] 매핑 모드에서 배터리 20 % 이하면 보라색 LED, 20 % 초과면 파랑 LED 가 표시된다
- [ ] 매핑 모드에서 ISD 연결 시 점멸, 미연결 시 지속 ON 이 표시된다
- [ ] 페어링 / OTA / 매핑 중 어느 하나라도 활성이면 커버 닫기·충전 분리 등의 평소 절전 트리거가 와도 절전 모드로 진입하지 않는다
- [ ] 위 셋 중 어느 것도 활성이 아니면 평소 트리거에 절전 모드로 진입한다
- [ ] `func_sleep()` 의 ULP 루프 이후 dead code 가 없다
- [ ] `debug_led_pattern()` 정의/호출이 코드에서 사라진다
- [ ] LED 가 점멸 / 색상 전환 시 부드러운 Dimming 으로 보인다 (육안)
