## 3. 자산

> [!CAUTION]
> **이 절이 이 문서의 존재 이유다.** 무엇을 했는지는 `git log` 로 알 수 있지만 아래는 여기에만 있다.

### 자산_1 (정정) - `__LINE__` 을 품는 것은 `TDC_PRINTF_E` 뿐이다

직전 인수인계의 «모든 `TDC_PRINTF_*` 가 `__LINE__` 을 품는다» 는 **틀렸다.**

| 매크로 | 위치 | `__LINE__` |
|---|---|---|
| `TDC_PRINTF_E` | `util/tdc_printf.h:35~37` | **품는다** (`tdc_printf_file_func_line(...)`) |
| `TDC_PRINTF_W` · `_I` · `_D` · `_V` | `:43` · `:49` · `:55` · `:61` | **없다** (`SEGGER_RTT_printf` 뿐) |

`map_live` 에서 예측 12바이트 · 실제 8바이트로 어긋났고, «적게 나왔으니 다행» 으로 넘기지 않고 파고들어 찾았다. 밀린 운반체 11개 중 3개가 `_I`·`_V` 라 바이트를 안 바꿨던 것이다.

**`.text` 변화를 셀 때는 `grep -c "TDC_PRINTF_E"` + 명시 `__LINE__` 만 센다.**

### 자산_2 - `.text` 예측은 바이트가 아니라 **명령어 수**로 한다

`98448d0` 에서 `cmp -l` 이 **41바이트**를 냈는데 예측은 18이었다. 두 바이너리를 각각 디스어셈블해 명령어 단위로 diff 하니 **바뀐 명령어는 정확히 17개**로 예측과 일치했다.

바이트가 더 많은 이유는 **Thumb-2 가 즉치를 두 형식으로 싣기** 때문이다.

| 형식 | 쓰임 |
|---|---|
| `MOV.W Rd, #imm` | 「modified immediate」 패턴에 맞는 값 |
| `MOVW Rd, #imm16` | 임의의 16비트 값 |

줄 번호가 밀리며 형식 경계를 넘으면 **4바이트가 통째로** 바뀐다. 이번에 형식이 뒤바뀐 것이 **8건**이었다.

> [!IMPORTANT]
> `ecap`(2바이트)·`live`(8바이트)에서 «운반체 1개 = 1바이트» 가 통했던 것은 **형식이 안 바뀐 우연**이다. 그 모델로 «41 ≠ 18 이니 잘못됐다» 고 결론냈어도 틀렸고, «많이 다르네» 로 넘겼어도 틀렸다. **명령어 수는 운반체 수와 1:1이라 안정적이다.**

### 자산_3 - 검증기는 도구와 **전제를 공유하면 안 된다**

이번 세션 최대의 함정이다.

1차 스크립트가 `tdc_isd_fpga.c` 의 **`#else` 가지 15줄을 지웠다.** 진짜 죽음이 0인 파일인데도 그랬다.

```c
#ifdef CM3_I2C_controls_FPAG
    if (tdc_hal_i2c_isd_read(...))     // CM3 가 직접 I2C
#else
    if (tdc_hal_i2c_cfx_read(...))     // <- 이게 지워졌다
#endif
```

**더 나쁜 것은 검증이 통과시켰다는 점이다.** 1차 검증은 «살아 있는 줄이 전후 완전 일치» 였고, 그 마스크가 **제거 도구와 같은 가정(조건부의 첫 가지가 활성)** 을 썼다. `#else` 가지는 양쪽 계산에서 똑같이 빠지므로 **지워지든 남든 결과가 같다. 그 실수를 볼 수 없는 구조였다.**

`ecap`·`live` 에서 이 검증이 통했던 것은 **두 파일에 조건부 `#if` 가 하나도 없었기 때문**이다. 검증이 강해서가 아니다. (두 작업의 결과 자체는 안전하다.)

**해법 - 가정을 공유하지 않는 검증기**: 활성/비활성을 계산하지 않고 **구조만 본다.** 지워진 줄이 원본에서 어떤 전처리기 블록 안에 있었는지 되짚어, 감싼 것 중 하나라도 조건부의 **비활성 가지**면 잘못된 삭제로 판정한다.

### 자산_4 - 검증기는 **알려진 버그로 먼저 시험한다**

검증기 자체가 검증되지 않은 코드다. **통과가 «문제 없음» 인지 «못 봄» 인지 구분하려면 잡혀야 할 것을 넣어 봐야 한다.**

1차 스크립트가 만든 버그본을 검증기에 넣어 **15줄 전부를 지목**하는 것을 확인한 뒤 본 작업에 썼다. 순환이 아니다 - **알려진 정답이 있는 입력**으로 시험하는 것이다.

### 자산_5 - 결정적 죽음 vs 조건부 비활성

착수 전 계량을 정정했다. «남은 죽은 코드 191줄» 은 두 가지를 섞은 수치였다.

| | 형태 | 판정 근거 | 지워도 되나 |
|---|---|---|---|
| **결정적** | `#if 0` · `#if 1` | **소스에 답이 박혀 있다** | **된다** |
| **조건부** | `#ifdef X` · `#ifndef X` · `#if defined(X)` | **빌드 설정이 정한다** | **안 된다** |

결정적 116 + 조건부 85 였다. `tdc_isd_fpga.c` 는 `#ifdef CM3_I2C_controls_FPAG` **16블록**이 CM3 직접 I2C 와 CFX 경유 두 벌을 유지하는 구조라 **한 줄도 건드리면 안 된다.** 그걸 «죽은 코드 15줄» 로 보고한 것이 애초의 잘못이었다.

**확정한 규칙**:

| 형태 | 조건부 밖 | 조건부 안 |
|---|---|---|
| `#if 0` 블록 | 지운다 | **지운다** (어느 설정에서도 안 산다) |
| `#if 1` 의 `#else` | 지운다 | 안 한다 |
| `#if 1` 언랩 | 지운다 | **안 한다** (미용 변경이라 얻는 것이 없고 diff 검증 판정이 흐려진다) |
| 조건부 가지 내용 | - | **절대 안 지운다** |

### 자산_6 - 전처리기가 중괄호를 쪼갠다

`impedance` `case 0` 을 추출했더니 본문이 **490줄**로 나왔다(실제 117줄). `switch` 전체를 삼킨 것이다.

```c
#if 1
    if (...) {        // 여는 '{' 가 이 가지에 있고
#else
    if (...) {        // '{' 가 또 있고
#endif
    }                 // 닫는 '}' 는 하나뿐
```

원시 텍스트만 세면 여는 것이 하나 많아 **짝이 영영 안 맞는다.** 죽은 가지를 빼고 세도록 매처에 `#if`/`#else`/`#elif`/`#endif` 추적을 넣었다.

**이건 컴파일러가 못 잡는다** - `case 1` 이하가 `case 0` 안에 중첩된 형태가 되어 문법상 성립할 수 있다. **구조 지표만이 잡았다**(`case` 9→17, `if` 28→41, `for` 9→17).

### 자산_7 - 유사도는 후보를 좁히는 도구이지 판단이 아니다

`stim_para_setting` 의 `bi:14·16·18·20·22·24` 가 **전부 29줄**이었다. 본문 md5 로 대조하니 **`case 24` 만 달랐다** - `for (i = 0; i < 6)` vs `< 2`.

인자 없이 여섯을 합쳤다면 마지막 두 전극(30·31) 구간에서 6회를 읽어 **FIFO 를 넘겨 읽는다. 자극 본체에서 조용히 깨졌을 것이다.**

차이를 파고드니 구조가 드러났다 - `6 × 5 + 2 = 32 = df_MaxNumOfElectrode` 이고, 한 번에 6개인 이유는 한 읽기가 PCM 4슬롯(읽기 1 + NopBacktel 3)을 써서 `6 × 4 = 24 = df_MaxNumTransferableChannel` 이기 때문이다.

`difflib` 로 80% 이상 다섯 쌍을 뽑았는데 **95% 두 쌍 중 하나는 합치면 안 됐다**(`mono:10 ↔ bi:35` 는 `disable_backtel` 한 줄이 더 있다). **diff 를 눈으로 봐야 갈린다.**

### 자산_8 - 같은 이름의 독립 `static` 을 그대로 승격하면 합쳐진다

`stim_para_setting` 의 mono·bi 두 함수가 `flowControlCounter`·`tempCounter`·`sent_stimulConfig`·`p_mapdata`·`p_stimulDAC_setting` 을 **각자** 갖고 있었다. 함수-지역이라 이름이 같아도 별개다. 그대로 승격하면 하나로 합쳐져 **모노폴라 설정 중에 바이폴라 카운터가 밟힌다.** `s_mono_`/`s_bi_` 로 갈랐다.

`backtelBuff` 는 이름이 같은데 **성격도 달랐다** - mono 는 스택 지역변수`[64]`, bi 는 `static[32]`.

검증은 **bss 심볼 대조**로 했다. 원본의 맹글링 이름 13개와 새 접두어 이름 13개가 1:1 로 대응한다.

### 자산_9 - `Copy-Item` 은 타임스탬프를 보존한다

bss −4 를 추적하려고 원본으로 되돌려 빌드했는데 **크기가 그대로 나왔다.** PowerShell `Copy-Item` 이 원본의 `LastWriteTime` 을 함께 복사해 make 가 최신으로 보고 **재컴파일을 건너뛴 것**이다.

```powershell
(Get-Item $f).LastWriteTime = Get-Date
```

**«빌드했는데 안 바뀌었다» 는 결론 전에 정말 컴파일됐는지 봐야 한다.**

### 자산_10 - 죽은 코드 제거에는 구조 지표를 쓸 수 없다

`tests/metrics.sh` 는 행 앵커로 세므로 **`#if 0` 안의 `if`·`for` 도 센다.** `ecap` 제거 후 `if` 46→35, `else` 19→14, `for` 15→12 로 줄었다.

**도구의 결함이 아니라 용도의 문제다.** 지표는 «함수 추출로 분기가 보존됐는가» 를 보는 자이고, 죽은 코드 제거는 애초에 분기를 줄이는 작업이다. 이 작업의 불변량은 **«살아 있는 줄 동일»** 이므로 다른 자를 쓴다.

### 자산_11 - `metrics.sh` 의 공백 의존 결함 (수정 완료)

`specific_stim` 지표 대조에서 `for` 가 −1 로 나왔다. 계획-검증이 **«정확히 −2»** 를 못 박아 둔 덕에 차이가 드러났다.

원인은 원본 `:587` 이 `for(;pcm_index...` 로 **`for` 뒤에 공백이 없어** 패턴 `'^[[:space:]]*for \('` 이 세지 못한 것이다. `'[[:space:]]*\('` 로 고쳤다(4패턴).

**«변했지만 의도한 것» 으로 넘겼으면 도구 결함을 못 찾았다. 지표가 변하면 왜 그 크기만큼인지 따져야 한다.**

### 자산_12 - 순서를 지킨 덕에 재분해를 안 해도 됐다

`live` 의 `HoldOn` 이 **285줄**로 가장 컸지만 상당수가 죽은 `#else` 안이라 «지금 나누면 죽은 코드에 이름을 붙이는 꼴» 이라며 남겨 뒀다. 죽은 코드 106줄을 지우니 **143줄**이 됐고, 계획이 미리 정해 둔 «150줄 이하면 추가 분해 불필요» 에 걸려 **미뤄 둔 재분해가 없던 일이 됐다.**

먼저 나눴다면 죽은 코드를 담은 함수 둘이 생겼고, 그 뒤 죽은 코드를 지우면 껍데기만 남은 함수를 다시 합쳐야 했다.

### 자산_13 - 호스트 게이트를 여는 방법이 두 번 실증됐다

`isd/` 는 `tests/unit/run.sh` 의 `TEST_TARGETS` 에 `.c` 가 하나도 없다(`-I "$SRC/isd"` 는 include 경로일 뿐). **게이트를 여는 방법은 «순수 함수를 새 파일로 뽑아 그 파일을 TEST_TARGET 으로 등록» 이다.**

| 실증 | 위치 | 결과 |
|---|---|---|
| 1차 | `ble/tdc_ble_map_field_range.c` (위험_4) | 431 → 483 PASS |
| 2차 | `isd/tdc_isd_stim_mode_encode.c` (단계_2) | 483 → **514 PASS**, `isd/` 최초 |

`EN___STIMULATION_MODE` 가 있는 `tdc_shm.h` 가 SDK `hw.h` 를 포함해 «호스트에선 안 되겠다» 고 넘길 뻔했으나 **3줄짜리 probe 로 시험하니 통과**했다. 추측했다면 인자를 `int` 로 낮춰 열거형 완전성 검사를 잃었을 것이다.

### 자산_14 - 절차로 굳힌 것들

| 절차 | 계기 |
|---|---|
| **`switch` 밖에 뭐가 있는지 먼저 본다** | `specific_stim` 124줄 · `ecap` 275줄 · 이월_F · 이월_2 = 네 번째 사례 |
| **다파일 기계 치환은 전부 검증 후 일괄 쓰기** | 스크립트가 파일 1을 쓰고 파일 2에서 중단해 부분 적용이 남았다 |
| **이름 치환은 `(?<![\w.])(?<!->)` 로 멤버를 배제** | `impedanceCheck.iterationNum` 의 멤버까지 바뀌었다 |
| **블록 경계에 여는 `{` 를 넣지 않는다** | `invalid storage class for function`(중첩 함수로 해석) |
| **makefile 등록 스크립트는 멱등이어야 한다** | `.o` 중복 등록 → `multiple definition` 링크 실패 |
| **스크립트는 heredoc 말고 Write 도구로** | bash heredoc 이 역슬래시를 반복해 먹었다 |
| **ARM 빌드는 `make all SHELL=cmd.exe`** | bash 가 `-Dchess_storage(a)=` 를 파싱 못 한다 |
