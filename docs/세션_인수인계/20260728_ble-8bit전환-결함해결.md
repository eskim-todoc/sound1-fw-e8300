## 2. 무엇을 했나

### 2.1 BLE 구조 분석 (코드 무변경)

7노드 fan-out 으로 전면 분석하고 참고 문서 13종을 [`docs/참고/ble/`](../참고/ble/README.md) 에 정비했다.

| 폴더 | 내용 |
|---|---|
| `프로토콜/` | 명령 63개 카탈로그(SSOT) · 21바이트 패킷 구조 · 응답 규약 |
| `코드구조/` | fetch/step 아키텍처 · 복잡도 실측 · 결합도와 계층 경계 |
| `라이브모드/` | **상태 4층 사양** · 실측 로그 대조 |
| `재구조화/` | 6단계 로드맵 · 알려진 결함 목록 · 바이폴라 결함 기록 |

**핵심 규명 3건**

1. **복잡도 근인은 셋** - 함수 분해 부재(`fetch_packet` 단일 함수 1,724줄) · 라이브 상태 4층 분산 · 프로토콜 파서가 자극 FSM 의 tick 드라이버를 겸함
2. **라이브모드가 어려운 이유** - 상태가 4개 층에 독립 존재하는데 **층간 관계가 코드 어디에도 명시돼 있지 않다**
3. **폴더 분할의 걸림돌은 `ble/` 내부가 아니라 `isd/` 와의 역결합** - `isd/` 6파일이 `ble/` 상태를 56회 참조·클리어한다. 읽기가 아닌 **쓰기 결합**이라 헤더 분리로 해소되지 않는다

### 2.2 SPI 패킷 버퍼 8비트 전환 (B1~B3c)

SPI1 은 이미 `SPI_WORD_SIZE_8` 인데 **DMA 만 32비트**로 퍼 담아 버퍼가 `int[21]`(84바이트)이었다. 프로토콜 요구가 아니라 설정 문제였다.

| 단계 | 범위 | 커밋 |
|---|---|---|
| B1 | DMA 매크로 2곳 + HAL 버퍼 (2파일) | `2c624ac` |
| B2 | RX 경로 (11파일, 시그니처 연쇄 13개) | `6a19316` |
| B3a | `ble/` (8파일) | `138d98c` |
| B3b | `isd/` (5파일, 버퍼 14 · 호출 21) | `0f5fbd3` |
| B3c | `dfu/`·`sys/` + 어댑터 제거 + 이름 정리 57곳 | `a35d1a3` |

**바꾸지 않은 것** (중요)
- `transferLength`(21) - **워드 개수**라 워드가 8비트로 줄어도 그대로
- `DMA_*_ADDR_INCR_1` - "워드 크기 1개 분" 증가라 4바이트 -> 1바이트로 자동 축소
- `DMA_LITTLE_ENDIAN` - **유지 필수**(§4 노하우_3)

### 2.3 발견해 고친 기존 결함 3건

전환과 무관한 **잠복 결함**이었고, 실기 검증 과정에서 드러났다.

| # | 결함 | 커밋 |
|---|---|---|
| 1 | **바이폴라 기준전극** - 미사용 표식 99 를 거르지 않아 `electrodeMap[98]`(32원소 배열) 범위 밖 읽기 | `d46d448` |
| 2 | **EEPROM 슬롯 0 허용** - 검증이 `>= 0` 이라 `map[-1]` **쓰기**가 가능. BLE 레이어 5곳 + 저장 계층 8함수 심층 방어 | `daa44f8` |
| 3 | RX 디버그 로그가 20원소 배열의 `[20]` 을 읽던 범위 밖 접근 | B1 에 포함 |

## 3. 불가침 (이번 세션 신규 + 기존)

| 항목 | 이유 |
|---|---|
| **`DMA_LITTLE_ENDIAN`** (신규) | 하드웨어 레퍼런스 §19.4.2.6 의 "8비트 동일 워드 크기에서 니블 재배치" 는 **byte ordering 이 켜진 경우(`DMA_BIG_ENDIAN`=1)에만** 적용된다. `LITTLE`(0)을 유지해야 발동하지 않는다. `tdc_hal_dma.h` 주석에 근거를 남겼다 |
| **`transferLength`=21** (신규) | 워드 개수다. 바이트 수로 오해해 84 로 바꾸면 즉시 깨진다 |
| **`tdc_isd_stim_para_setting.c:794` 마스킹 비대칭** (신규) | 좌변에 `0x1F &` 를 넣어 대칭으로 만들면 32 이상 오염값이 검증을 통과한다. **범위 밖 값 탐지기 역할이므로 존치**(2026-07-28 은수님 판단) |
| BLE 프로토콜 정의 · 공유 ABI · SDK 심볼 · `sections.ld` | 기존과 동일 |

## 4. 검증 노하우 (이 세션의 자산)

### 노하우_1 - 포인터 전환과 원소 대입은 위험 성격이 다르다

| 유형 | 컴파일러 | 대응 |
|---|---|---|
| `int*` -> `uint8_t*` (포인터) | **경고/에러로 반드시 드러남** | 그냥 바꾸고 컴파일러가 잡게 한다. 누락 원천 불가 |
| `buf[i] = 어떤_int` (원소 대입) | **조용히 잘림** | `-Wconversion` 을 일시 활성화해 축소 변환을 전부 찾아낸다 |

이번에 시그니처 6개만 바꾸고 빌드하니 컴파일러가 **3단계에 걸쳐** 연쇄를 전부 검출했다(fetch 6 -> dfu static 4 -> handle_option 3).

### 노하우_2 - 전환 기간용 어댑터로 파일 단위 이행

호출부가 57곳이라 한 커밋에 몰 수 없었다. 신규 API 를 **병행 도입**하고 마지막에 구 API 를 제거했다.

```c
void tdc_hal_spi_write_tx_buffer_u8(const uint8_t*, int);  // 신규
void tdc_hal_spi_write_tx_buffer(int*, int);               // 어댑터 (마지막에 삭제)
```

> [!CAUTION]
> **어댑터는 캐스팅이 아니라 변환 복사여야 한다.** `uint8_t` 버퍼를 `int*` 로 캐스팅해 넘기면 호출자가 4바이트씩 읽어 즉시 깨진다. 원소별로 복사해야 한다.

전부 이행한 뒤 `_u8` 접미사를 원래 이름으로 되돌렸다(57곳 일괄).

### 노하우_3 - 하드웨어 문서의 조건절을 놓치지 말 것

"8비트 동일 워드 크기에서 니블 재배치" 서술을 보고 실기 게이트를 계획에 넣었는데, 원문이 **`If byte ordering is enabled`** 조건부였다. `BYTE_ORDER` 는 1비트(`LITTLE`=0/`BIG`=1)이고 현 설정이 `LITTLE` 이라 **발동 자체가 불가능**했다.

은수님의 상식적 반문("크기 변환이 없는데 재배치할 것이 무엇인가")이 재검증을 촉발했다. **서술만 보고 게이트를 세우지 말고 조건절과 현재 설정값을 연결해 볼 것.**

### 노하우_4 - 메모리 배치 가설은 `nm` 으로 실측한다

"내 변경이 `.data` 배치를 바꿔 결함을 발현시켰다" 는 추정을 세웠으나, 두 빌드의 심볼 상대 거리를 대조해 **기각**했다.

```powershell
arm-none-eabi-nm -n -S 2__cm3.elf | Select-String "심볼명"
```

`electrodeMap` <-> `s_tdc_table` 거리가 전환 전후 **모두 0x100** 으로 동일했다. 추정으로 단정했다면 엉뚱한 방향으로 갔을 것이다. **이전 커밋을 체크아웃해 빌드하고 `nm` 으로 대조하는 것이 가장 확실하다.**

### 노하우_5 - 레거시 대조로 "왜 지금 터졌나" 를 밝힌다

바이폴라 결함이 왜 하필 지금 드러났는지를 구버전 대조로 규명했다.

| | `electrodeMap[98]` 이 읽는 것 |
|---|---|
| Sound1 | `s_tdc_table` (UI 명령 테이블) -> 함수·문자열 포인터 |
| Sullivan1.5 | `s_ci_ctx` (tiny-AES-c 의 `AES_ctx`) -> AES 라운드 키 |

**구버전에도 같은 결함이 있다.** 읽히는 값이 다를 뿐이다. Sullivan 은 `.bss` 라 AES 초기화 전이면 0 이 읽혀 **에러 없이 조용히 전극 0 이 기준전극**이 된다.

### 6.5 8비트 전환이 만든 유리한 조건

패킷이 바이트 배열이 되어 **프로토콜 문서의 오프셋과 코드 인덱스가 1:1 대응**한다. 함수를 추출할 때 파라미터 의미가 명확해져 1b 가 전보다 수월하다.
