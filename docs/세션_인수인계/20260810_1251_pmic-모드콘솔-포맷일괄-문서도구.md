### 2.2 PMIC ISL9122A 모드 조회·변경 (`cdf71bf` → `31b51e9` → `1a47748`)

작업: [`tasks/cm3/20260807_1146_pmic-mode-console`](../tasks/cm3/20260807_1146_pmic-mode-console/) · 참고: [`참고/pmic-isl99122a/README.md`](../참고/pmic-isl99122a/README.md)

**은수님 질문에 대한 답 — 절반만 맞다.**

| 진술 | 판정 | 근거 |
|---|---|---|
| 입력이 낮아지면 **부스트로 승압** | **맞다** | §5.6 |
| 입력이 크면 **입력을 출력으로 바이패스** | **아니다 — 강압(Buck)한다** | §5.7 *"in buck mode, VIN > VOUT"* |
| 그 둘을 **바이패스 모드 하나**가 한다 | **아니다** | p.9 `VIN_BYP = ±1% × VOUT` |

데이터시트가 **bypass 를 두 뜻으로 쓴다** — **Auto Bypass**(Normal 에 내장, 끄는 비트조차 없다)와 **Forced Bypass**(`FMODE=0x3`, 스위칭을 꺼서 **승압도 과전류 보호도 없다**). **«높으면 그대로 쓰고 낮아지면 승압» 하는 IC 모드는 없다.**

기능: 드라이버 3함수(`read_mode`·`write_mode`·`mode_name`) + 콘솔 `m`·`m0`/`m2`/`m3`·`c`. **`m1` 은 데이터시트 금지값이라 양쪽에서 거부**하고 `m3` 는 경고 2줄을 띄운다.

**병합해도 펌웨어가 한 바이트도 안 바뀐다** — `main.c` 의 콘솔 호출이 주석이라 `--gc-sections` 가 콘솔과 새 함수를 전부 걷어낸다. 심볼 1,423 동일 · 크기 차이 0 · 바이트 총합 173,067 동일. **그래서 실기 대기를 늘리지 않았다.**

## 3. 자산

> [!CAUTION]
> **직전 문서의 자산_1~18 은 그대로 유효하다.** 여기에는 **이 구간에서 새로 알아낸 것만** 적는다.

### 자산_19 - 「(미병합)」 같은 표기는 표를 무의미하게 만든다

실기 대기 목록의 「병합」 칸에 7건이 **`(미병합)`** 으로 적혀 있었다. 병합 커밋을 따로 만들지 않고 `claude_develop` 에 직접 커밋한 것들이라 «**병합 해시가 없다**» 는 뜻으로 쓴 표기였는데, **읽으면 «아직 안 들어갔다» 로 보인다.**

`git merge-base --is-ancestor` 로 14개 해시를 전수 확인하니 **전부 들어가 있었다.**

**이 표의 존재 이유는 «문제가 나왔을 때 어느 커밋인지 바로 찾는 것»** 이다. 되짚을 수 없는 표기는 그 이유를 없앤다.

### 자산_20 - 되돌릴 때 커밋이 겹겹이 쌓여 있다

정정하다 드러났다. **`git revert <분해 커밋>` 을 단독으로 하면 충돌한다.**

| 파일 | 이 파일을 건드린 커밋 (**오래된 순**) |
|---|---|
| `isd/tdc_isd_map_live.c` | `b4b1681` 분해 → `0516c1b` 죽은 코드 → `367ca9b` 포맷 |
| `isd/tdc_isd_map_impedance.c` | `b4b1681` 분해 → `98448d0` 죽은 코드 → `367ca9b` 포맷 |
| `isd/tdc_isd_map_specific_stim.c` | `e0495bb` 통합 → `dab2674` 분해 → `98448d0` → `367ca9b` |
| `isd/tdc_isd_stim_para_setting.c` | `a372f7f` 가드 → `e0495bb` 통합 → `34a674f` 분해 → `367ca9b` |

**최신 커밋부터 역순으로 벗긴다.** `367ca9b`(포맷)은 149파일 중 크기가 바뀐 함수가 1개뿐이라 **먼저 벗길 후보가 아니다.**

### 자산_21 - `__LINE__` 운반체는 **래퍼 매크로까지** 센다 (자산_1 3차)

`TDC_ISD_DEBOUNCE_FAIL`(`isd/tdc_isd_fpga.h:18~30`)이 `TDC_PRINTF_E` 와 `tdc_sys_error_update(..., __LINE__)` 를 **함께** 품는다. **한 호출이 운반체를 두 개 싣는다.**

`grep -c "TDC_PRINTF_E"` 로만 세면 이런 래퍼를 놓친다. clang-format 의 −4바이트가 정확히 이것이었다(2 × 2바이트).

### 자산_22 - 「크기 불변」이 「줄 번호 불변」이 아니다

PMIC 작업에서 `tdc_test_tx_pmic.c` 에 60줄 넘게 끼워 넣어 **7곳의 `TDC_PRINTF_E` `__LINE__` 이 전부 밀렸는데** 편집하지 않은 함수의 **크기는 그대로**였다.

밀린 값이 전부 **`movs`(0~255) 범위 안에서** 움직여 인코딩 폭이 안 바뀐 것이다. **심볼 크기 표는 «폭이 바뀐 것» 만 본다** — 그것으로 충분하다. 코드 생성이 달라졌다면 폭이 아니라 명령어 구성이 바뀌어 크기가 크게 튄다.

### 자산_23 - 콘솔 명령 문자로 `w`·`s`·`a`·`d` 를 쓰면 안 된다

`tdc_test_tx_pmic.c` 의 입력기가 **이 넷을 엔터 없이 즉시 소비한다**(방향키 대체, `:103~118`). `mode` 라고 치면 **`d` 에서 «+10 단계» 로 빠져나간다.**

코드를 읽어서 미리 지웠다. 안 그랬으면 실기에서 «명령이 안 먹는다» 로 시간을 버렸을 것이다.

### 자산_24 - `git show HEAD:경로` 로 개행을 판정하면 안 된다

| 명령 | 같은 객체 |
|---|---|
| `git show HEAD:<경로>` | 작업 트리가 CRLF 면 **CRLF 라고 보고** |
| **`git cat-file -p HEAD:<경로>`** | **LF** (필터를 안 거치는 유일한 읽기) |

이 오판 위에서 «`.gitattributes` 도입 전부터 CRLF 였다» 는 이력 추적까지 했는데, **그 추적도 같은 `git show` 를 썼으므로 근거 전체가 결함을 공유**하고 있었다.

**부수 사실**: `text=auto` 면 git 이 비교 시 양쪽을 정규화해 **작업 트리가 CRLF 여도 `git status` 는 깨끗하다.** PowerShell 출력 계열이 기본 CRLF 라 스크립트로 파일을 통째로 다시 쓰면 이 상태가 된다.

### 자산_25 - clang-format 은 한 번 돌려서 고정점에 안 간다

| 원인 | 조치 |
|---|---|
| **`ReflowComments: Always` 가 진동** — `tdc_ble_protocol.h` 는 1→2패스 12줄, **2→3패스 96줄로 악화** | `ReflowComments: Never` |
| 그래도 2파일이 1패스에서 안 끝난다 | **2패스** (2→3 차이 0 확인) |

**`--dry-run -Werror` 가 0 이 될 때까지 돌린 뒤 커밋한다.**

### 자산_26 - 옵션 이름은 `--dump-config` 로 존재부터 확인한다

참고 문서가 조건_5 를 위해 `KeepEmptyLinesAtTheStartOfBlocks: false` 를 처방하고 있었다. **그 이름은 clang-format 22 에 없고**(v19 부터 `KeepEmptyLines.AtStartOfBlock`), **옛 이름은 에러도 안 내고 무시된다.**

같은 성격으로 **본보기 `main.c` 도 완벽하지 않았다** — 181자 한 줄이 조건_6 위반이었고 `ColumnLimit: 160` 이 잡았다.

### 자산_27 - 스캔 PDF 에는 OCR 대신 렌더해서 본다

`pymupdf` 로 페이지를 **170 DPI PNG 로 렌더해 `Read` 로 직접 보는 것**이 한글에서 더 정확하고 표 구조도 살아 있다. 실측으로 한글 시험지의 표·각주·작은 글씨까지 판독됐다.

**스캔 판정**: 쪽당 텍스트 100자 미만. `E:\workspace` PDF 64개 중 **63개는 텍스트 레이어가 있고 1개만 스캔**이었다.

> [!NOTE]
> **Windows 콘솔이 CP949 라 파이썬 `print` 의 한글이 깨져 보인다. 값 자체는 멀쩡하다.** 확인이 필요하면 파일로 쓰고 `Read` 로 본다.

| 4 | 실기 전이면 **코드 변경을 늘리지 않는다.** §4.2 의 분석 작업(특히 **3프로젝트 ABI 전수 대조**)으로 돌린다 — 코드를 안 건드리고 진짜 잠재 결함을 다룰 수 있는 유일한 항목이다 |
| 5 | 실기가 끝났으면 `claude_main` 병합 상신 (**승인 후**) |

> [!IMPORTANT]
> **실기 12건이 이 프로젝트의 현재 최대 위험이다.** 자동 검증이 덮은 것은 **컴파일·구조 지표·심볼 크기·호스트 514 PASS** 이고, **자극이 실제로 나오는지는 아무것도 보지 않았다.** `isd/` 는 호스트 러너가 컴파일조차 하지 않는다.
