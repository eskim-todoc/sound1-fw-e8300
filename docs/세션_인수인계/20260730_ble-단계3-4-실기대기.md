## 2. 무엇을 했나

### 2.1 단계_3 - 0x66 계층 네이밍 (`fb76532`)

**두 설계를 시도해 1차가 기각됐다.** 이 경위가 이 세션의 핵심 자산이다.

| 시도 | 결과 |
|---|---|
| ① 디스크립터 테이블 (23엔트리 + 순회 루프) | 지표는 전부 우수(`text` **-1,276B**, 함수 409->101줄, 검증 6종 통과)했으나 **은수님 검토에서 기각** -> `05c3a81` revert |
| ② **확정 - 프로토콜 계층을 함수 이름에** | `tdc_ble_cmd_0x66_subNN_idxKK_<이름>` + 명령 단위 파일 |

기각 사유는 [`구현-검증.md`](../tasks/ble/20260729_ble-descriptor-table/구현-검증.md) 에 남겼다. 요지는 *"배열에 숫자를 집어넣어 한참 분석해야 한다"* 였다. 매크로 인자 `(f, 0, 17, 1, 1, 100)` 이 정의를 찾아가야 뜻을 알고, 필드 배열 + 슬롯 `first` 오프셋의 **이중 관리**라 인덱스 1 에 필드 하나만 추가해도 슬롯 14줄이 연쇄로 밀렸다.

```
mapping/
├── tdc_ble_mapping.c        디스패치
├── tdc_ble_cmd_0x66_live.c  0x66 라이브 자극  <- 신규 894줄
├── tdc_ble_map_stim.c       0x65 만 잔류 (845 -> 116줄)
├── tdc_ble_map_flash.c
└── tdc_ble_map_measure.c
```

409줄 한 덩어리였던 `all_parameter` 가 **15줄 목차 + 18~21줄 함수 15개**가 됐다. 크기는 **+588B 늘었으나 의도된 교환**이다.

### 2.2 명령 카탈로그 함수 기준 전환 (`cbda6d3`)

### 2.3 단계_4 - 라이브 상태 계약 (`5a7b32b` · `4cd72d1`)

`en__HoldOn` 게이트 4곳(하위 3·4·5·6)을 이름 있는 가드 하나로 수렴했다.

// 수락 조건 : 라이브 자극 유지 중(en__HoldOn)에만.

## 5. 검증 노하우 (이 세션의 자산)

### 노하우_1 - 지표가 좋은 설계가 기각될 수 있다

단계_3 의 1차 구현은 `text` **-1,276B**, 함수 **409->101줄**로 모든 정량 지표가 우수했고 검증 6종을 통과했다. 그럼에도 기각됐다. 확정 구현은 정반대로 크기가 **+588B 늘었다.**

**설계 판단의 실질 기준**은 "프로토콜이 바뀌면 몇 곳을 고치는가"였다.

| 설계 | 인덱스 1 에 필드 하나 추가 시 |
|---|---|
| 디스크립터 테이블 | 필드 배열 1줄 + **슬롯 14줄 연쇄** + 단언 1줄 = **3곳** |
| 계층 네이밍 | 함수 하나 = **1곳** |

### 노하우_2 - 리팩토링 유형마다 불변량이 다르다

| 유형 | 지표 |
|---|---|
| 파일 이동 | `.elf` 바이트 동일 (`-ffile-prefix-map` 필요) |
| 함수 추출 | **조건 분기 총수 보존** |
| 테이블 주도 전환 | 분기 총수를 쓸 수 없다 -> **파싱 필드·경계 상수 집합** |
| **가드 수렴** (신규) | **게이트 관련은 수렴, 본문은 불변** |

단계_4 실측: `en__HoldOn` 비교 5->1 · `en__Command_Order` 5->1 · `else` 14->10, 반면 `if (` 45 **불변** · `for (` 18 **불변** · `en__OutOfDataRange` 7 **불변**. `if (` 가 불변인 것이 "분기를 없앤 게 아니라 이름 있는 자리로 옮겼다"를 증명한다.

### 노하우_3 - 테스트 선행 + 뮤테이션

단계_3·4 모두 **커밋_1 을 테스트로 두고 기존 코드에서 통과시킨 뒤** 전환했다. 단계_3 에서는 뮤테이션 2건(청크 첨자 밀기 · 범위 상한 완화)으로 **테스트가 실제로 잡는지**까지 확인했다.

테스트가 없던 영역을 먼저 덮는 것이 핵심이다. 단계_3 착수 시 데이터 인덱스 2~15 는 커버리지 0, 단계_4 착수 시 게이트 4곳 중 2곳이 0 이었다.

### 노하우_4 - 플랫폼별 `sizeof` 차이는 호스트 테스트로 못 잡는다

`stimulationMode` 만 `EN___STIMULATION_MODE` 이고 **ARM EABI 는 `-fshort-enums` 가 기본이라 1바이트**, 호스트 테스트 컴파일러(MinGW x86)는 **4바이트**다. 폭을 상수로 적으면 **호스트 테스트가 전부 통과하면서 실기에서만 인접 바이트를 덮는다.**

이 구조체를 폭 기반으로 다루는 코드(직렬화 · `memcpy` · 오프셋 접근)를 쓸 때 반드시 고려할 것.

### 노하우_5 - 공유 상태는 파싱 유효 범위까지 바꾼다

데이터 인덱스 카운터를 `map_flash`(최대 **34**)와 공유하므로 0x66 하위 1 에 **16~35 가 실제 도달**한다. `default:` 는 죽은 코드가 아니라 살아 있는 방어 코드다.
