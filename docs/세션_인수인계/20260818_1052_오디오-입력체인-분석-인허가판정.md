### 2.1 답 셋

**① 두 마이크는 계수를 그대로 쓴다.** Sound1 `SPH0641LM4H-1`(Knowles) 과 Sullivan 1.5 `SPK0641HT4H-1`(Syntiant) 은 **감도 −26 dBFS · AOP 120 dB SPL 이 같고** SNR 이 0.2 dB 차이다. 실질 차이는 **PSRR 15 dB**(Sullivan 우세)뿐이다. AGC 노이즈 게이트 29.5 dB SPL 이 두 마이크 잡음 바닥(29.7 / 29.5)에 그대로 맞아 **재튜닝 불필요**.

**② `>>5` 는 바꿀 수 없다.** 헤드룸용이 아니라 **볼륨 곡선 수렴점을 마이크 풀스케일(120.00 dB SPL)에 맞추고** **AGC 출력을 HEAR FFT 한계 65,535 에 맞추는** 값이다. 빼면 수렴점이 89.9 dB SPL 로 내려와 **그 위에서 볼륨이 최대 19.9 dB 뒤집힌다.**

**③ 인허가 보고서(EPTR-TD23D)는 그대로 쓴다.** ADC 판정표 **29개가 우리 계산과 전수 일치**했고, 그 표는 실측이 아니라 «감도 −26 dBFS + `>>5`» 에서 유도된 **이론값**이다. 마이크 입력을 보는 시험은 **ID-1·2 둘뿐**이고 ID-3·4·5 는 오실로스코프로 자극 펄스를 본다.

### 2.2 기준선

```
0x7FFFFF = 120 dB SPL      6 dB 오르면 코드 2배
노이즈 게이트 29.5 dB SPL (코드 250)   회전점 75 dB SPL (코드 47,173)
볼륨 1칸 3.3 dB (0~9 → 0~29.7 dB)      AGC 출력 상한 65,535
attack 1.1 ms / release 100 ms
```

## 3. 자산

> [!CAUTION]
> **직전 문서의 자산_1~27 은 그대로 유효하다.** 여기에는 이 구간에서 새로 얻은 것만 적는다.

### 자산_28 - **데이터시트의 인쇄된 수식보다 SDK 구현이 우선이다**

데시메이션 게인 유니티를 하드웨어 레퍼런스 p.445 의 인쇄식으로 계산해 **1979.7** 이라 판정하고, 펌웨어의 `1092` 가 **−5.17 dB 밀려 있다**고 문서 전체에 경고를 달았다. **틀렸다.**

```c
// SDK: include/shared/analog_in.h  Sys_Calc_Gain_Factor_Val()
/* GF = round[2^(11+floor[log2(sfcr)])/(sfcr+1)] */    ← floor 가 있다
while (SFCR != 1) { SFCR >>= 1; log2++; }
```

`SFCR = 29` → `floor(log2(29)) = 4` → `2^15 / 30` → **1092**. **펌웨어 값이 SDK 계산 그 자체였다.**

렌더한 PDF 이미지에서 floor 괄호를 놓쳤고 **SDK 에 계산 함수가 있는지 확인하지 않았다.** 바로 직전 세션에 자산_26 으로 «옵션 이름은 `--dump-config` 로 존재부터 확인한다» 를 적어 놓고 **같은 종류의 실수를 반복했다.**

> [!IMPORTANT]
> **은수님이 «SDK 에 `Sys_Calc_Gain_Factor_Val()` 이 있는데 그걸로 계산하면 1092 아니었나» 라고 짚어 주셔서 잡혔다.** 이 구간 최대 현안이 한 마디로 사라졌다.

### 자산_29 - **볼륨 곡선은 한 점에서 만나고 그 점을 지나면 교차한다**

감쇠 구간 출력 `slope[v]×in + ybias[v]` 를 볼륨 0·9 로 연립하면 10개 곡선이 **`in* = −72.2481` 한 점**에서 만난다. **그 점을 지나면 순서가 뒤집힌다.**

`AUDIO_INPUT_RSHIFT = 5` 가 그 수렴점을 **마이크 풀스케일(120.00 dB SPL)에 정확히 맞춘다.** 빼면 89.90 dB SPL 로 내려와 그 위가 전부 역전된다(볼륨 9 가 볼륨 0 보다 **19.89 dB 조용**).

또 하나의 제약: **HEAR FFT 가 BFP 이전에 ×128** 하므로 `INT24_MAX / 128 = 65,536.0` — **AGC 출력이 65,535 를 넘으면 24비트가 넘친다.** `>>5` 가 그것도 정확히 맞춘다(2²³ → 2¹⁸ → 2¹⁶).

> [!CAUTION]
> **`AUDIO_INPUT_RSHIFT` 는 단독으로 못 바꾸는 상수다.** `ybias`·`slope` 20개와 임계 2개가 전부 이 값을 전제한다. 내가 처음에 «6 dB 과하니 `>>4` 로 줄이면 분해능이 좋아진다» 고 쓴 것은 **틀렸고 정정했다**(05 §3.1).

### 자산_30 - 정적 분석이 «역전 없음» 이라도 정수 연산은 다르다

세 구간 기울기가 전부 양수라 «입력↑ → 출력↓» 은 수식상 불가능한데, **고정소수점 시뮬레이터를 돌리니 실제로 일어났다**(Q12.12 게인이 41 까지 작아져 1 LSB 가 0.21 dB, 기울기 0.072 dB/dB 보다 3배 크다).

**다만 크기는 0.14 dB 로 작다.** 처음에 «−3.9 dB» 로 보고할 뻔했는데 **그건 내가 만든 «포락선» 지표의 착시**였다 — 추세가 아니라 최대·최소의 차였다. **지표를 만들 때 그것이 무엇을 재는지 먼저 정의해야 한다.**

### 자산_31 - 인허가 보고서가 우리 분석을 역으로 검증했다

EPTR-TD23D 의 ADC 판정표 29개가 우리 계산과 **하나도 틀리지 않고 일치**했다. 이것이 **02 의 체인 해석과 자산_28 의 «데시메이션 게인 유니티» 를 외부 문서로 뒷받침**한다.

**«남이 만든 문서와 내 계산이 독립적으로 같은 값을 낸다» 는 것은 강한 검증**이다. 실측이 없을 때 쓸 수 있는 몇 안 되는 수단이다.

### 자산_32 - 데이터시트 표가 이미지면 렌더해서 읽는다

Knowles·Syntiant 마이크 PDF **둘 다 스펙 표가 이미지**다. 텍스트 레이어에 헤더만 있고 셀 값이 없어 **자동 추출로는 수치가 안 나온다.** 190 DPI 로 렌더해 판독했다(자산_27 의 두 번째 적용).

**스펙 표 위치**: Sound1 2~3쪽, Sullivan 2~3쪽. `docs/참고/mic/README.md` 에 적어 뒀다.
