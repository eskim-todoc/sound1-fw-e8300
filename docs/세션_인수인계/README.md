# 세션 인수인계

**TL;DR**: **다음 컨텍스트가 읽을 요약**을 모으는 곳이다. 세션 종료 시점이든 compact 직전이든 목적이 같아 한 폴더에 둔다. **최신 1건만 읽으면 이어서 작업할 수 있게** 쓰는 것이 규약이다.

> [!IMPORTANT]
> **세션 시작 시 이 폴더의 최신 문서 1건을 읽는다.** 그 문서가 «지금 상태 · 남은 것 · 알아야 할 함정» 을 담고 있어야 하며, 담고 있지 않다면 그 문서가 잘못 쓰인 것이다.

## 왜 별도 폴더를 새로 만들지 않는가

compact 요약과 세션 인수인계는 **독자만 다르고 내용이 같다**.

| | 인수인계 | compact 요약 |
|---|---|---|
| 독자 | 다음 세션(다른 컨텍스트) | 같은 세션(압축된 컨텍스트) |
| 내용 | 지금 상태 · 남은 것 · 자산 | **동일** |

**둘을 나누면 «어디에 쓸지» 를 매번 판단해야 하고, 같은 성격의 문서가 두 곳에 흩어진다.** 이 프로젝트는 이미 그 문제를 겪었다 — 이월 라벨이 각 작업 폴더 안에만 있어 *"뭐가 남았지"* 를 물을 때마다 폴더를 뒤져야 했다(2026-08-05 에 통합).

**폴더를 늘리는 대신 파일명과 인덱스로 구분한다.**

## 작성 규약

| 항목 | 규칙 |
|---|---|
| 파일명 | `YYYYMMDD_HHmm_<주제>.md` — **시각 prefix 필수**(하루에 여러 번 나올 수 있다) |
| 시점 | ① 세션 종료 ② **compact 직전** ③ 큰 작업 묶음이 끝났을 때 |
| 분량 | 제한 없음. 다만 **§0 지금 상태**와 **§자산**은 반드시 앞쪽에 |
| 갱신 | 이 README 표에 한 줄 추가 |

### 반드시 담을 것

| # | 절 | 내용 |
|---|---|---|
| 0 | **구간** | **직전 기준점 해시 · 구간 커밋 수 · 구간을 잡는 명령.** 아래 CAUTION 참조 |
| 1 | **지금 상태** | 브랜치 · `origin` 격차 · 테스트 통과 수 · 빌드 크기 · 상시 점검 항목 |
| 2 | 한 일 | 병합 해시와 함께. 해시가 없으면 되짚을 수 없다 |
| 3 | **자산** | **가장 중요.** 이번에 알아낸 함정·규칙. 모르면 다시 빠지는 것들 |
| 4 | 남은 것 | **왜 막혀 있는지**까지. "남았다" 만으로는 다음 사람이 판단 못 한다 |
| 5 | 권장 순서 | 다음 세션이 첫 30분에 할 일 |

> [!CAUTION]
> **§0 구간이 추적의 뼈대다.** compact 가 두 번 이상 일어나면 **대화 컨텍스트에서는 «지난 요약 이후» 라는 경계가 사라진다** — 1차 요약과 그 뒤 대화가 통째로 다시 요약되기 때문이다.
>
> **그래서 앵커를 git 에 둔다.** 다음 요약은 **직전 요약 문서가 커밋된 지점**부터 구간을 잡는다. 해시를 손으로 적지 않는다 — 그건 자기참조라 문서를 커밋하는 순간 한 커밋 뒤처진다.
>
> ```sh
> PREV=$(git log --format=%H --reverse -- "docs/세션_인수인계/<직전문서>.md" | head -1)
> git log $PREV..HEAD --format=%B
> ```
>
> 컨텍스트가 통째로 날아가도 성립한다.
>
> 전제가 하나 있다 — **커밋 메시지에 «왜 그렇게 했는지»를 적어야 한다.** "무엇을 바꿨다" 만 적으면 `git log` 로 재구성이 안 된다. 대화에만 있고 커밋에 없는 것(접은 대안·구두 지시)은 본문이 담는다.

> [!CAUTION]
> **§자산이 이 문서의 존재 이유다.** 무엇을 했는지는 git log 로도 알 수 있지만, **왜 그렇게 했고 어디에 함정이 있었는지**는 여기에만 남는다.
