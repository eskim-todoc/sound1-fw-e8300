# 08. 왜 믹서에서 5비트를 내리는가

**TL;DR**: `AUDIO_INPUT_RSHIFT = 5` 는 «헤드룸 확보» 가 아니라 **두 가지 설계 제약을 동시에 만족시키는 유일한 값**이다. ① **10개 볼륨 곡선이 만나는 수렴점을 마이크 풀스케일에 정확히 맞춘다** — 안 맞추면 **90 dB SPL 위에서 볼륨이 뒤집힌다**(볼륨 9 가 볼륨 0 보다 **19.9 dB 조용해진다**). ② **AGC 출력 상한을 65,535 로 만든다** — HEAR FFT 가 BFP 이전에 내부적으로 **×128** 하므로 `65,535 × 128 = 8,388,480 ≤ INT24_MAX` 여야 한다.

> [!NOTE]
> 이 문서는 **은수님 지적으로 다시 조사해 쓴 것**이다. 처음 [05](05_포화와%20절삭.md)·[06](06_게인%20상호작용과%20역전%20현상.md) 은 `>>5` 를 단순 헤드룸으로 보고 **«6 dB 과하니 `>>4` 로 줄이면 분해능이 좋아진다» 고 잘못 적었다.** §5 에 정정 내역이 있다.

## 1. 은수님 기억의 검증 결과

> *"`>>5` 를 안 하고 볼륨과 dB, 게인 등을 적용한 AGC 를 계산해보면 볼륨이 9, 10 등의 설정에서는 오히려 Attenuation 이 AGC out max 보다 커져서, 입력 dBSPL 이 커지는 경우 역으로 소리가 작아지는 현상이 발생했거든? … 65535 가 최대값이어야 하던가 … HEAR 의 계산상 FFT 최대값이 65535 였던가 … BFP 랑 이런저런 이슈"*

**AGC 고정소수점 코드를 그대로 재현한 시뮬레이터**로 `>>5` 유무를 비교했다.

| 기억 | 판정 | 실측 |
|---|---|---|
| **역전 현상이 있었다** | **맞다** | §2 — 볼륨 역전 **최대 19.89 dB** |
| **볼륨 9 등 높은 설정에서 심했다** | **맞다** | 볼륨이 높을수록 정확히 비례해 심해진다 |
| **Attenuation 출력이 AGC out max 를 넘었다** | **맞다** | `>>5` 없으면 볼륨 0 · 120 dB SPL 에서 **829,439** = 상한의 **12.7배** |
| **AGC out max 가 65,535 여야 한다** | **맞다** | §3 — `INT24_MAX / 128 = 65,536.0` 정확히 떨어진다 |
| **HEAR FFT · BFP 때문** | **맞다** | `FrequencyAnalysis.c:92` 에 «BFP 1/4 게인» 이 적혀 있고 주석 처리된 `df_maxAudioForLogarithm 65535 //FFT 입력` 도 있다 |
| «입력이 커질 때 출력이 작아진다» | **부분적** | 입력 대 출력 직접 역전은 **최대 0.14 dB** 로 작다. **크게 체감되는 것은 볼륨 역전(§2)** 이다 |

> [!IMPORTANT]
> **결론과 조치는 완전히 옳았다.** 기전만 기억과 조금 다르다 — «입력↑ → 출력↓» 보다 **«볼륨↑ → 출력↓»** 가 압도적으로 크다. 둘 다 `>>5` 로 해결된다.

## 2. 제약_1 - 볼륨 곡선의 수렴점

### 2.1 10개 곡선은 한 점에서 만나도록 설계됐다

감쇠 구간의 출력은 `출력 = slope[v] × 입력 + ybias[v]` 다. 볼륨 0 과 9 의 식을 같게 두고 풀면

```
0.73241·in − 25.3529 = 0.072388·in − 73.0380
              in* = −72.2481   (AGC 내부 10log10 눈금)
```

**10개 곡선 전부가 이 한 점에서 만난다**([04](04_AGC%20동작%20상세.md) §4 의 «120 dB SPL 출력» 열이 전부 −78.267 로 같은 이유).

### 2.2 `>>5` 가 그 점을 풀스케일에 맞춘다

| | 수렴점 `in*` 에 해당하는 믹스 코드 | **그때의 음압** |
|---|---|---|
| **`>>5` 있음 (현행)** | 262,090 ≈ 믹서 최대 262,143 | **120.00 dB SPL = 마이크 풀스케일** |
| `>>5` 없음 | 262,090 (마이크 코드) | **89.90 dB SPL** |

> [!IMPORTANT]
> **`>>5` 는 수렴점을 «입력의 맨 끝» 에 정확히 놓는다.**
>
> 그래서 동작 범위 전체가 수렴점 **앞쪽**에 머물고, **볼륨 순서가 끝까지 유지된다.** 맨 끝에서만 차이가 0 으로 수렴한다.
>
> `>>5` 가 없으면 수렴점이 **89.9 dB SPL** 로 내려온다. 그 위는 **수렴점을 지난 영역이라 곡선이 교차해 순서가 뒤집힌다.**

### 2.3 실측 - 볼륨 역전

볼륨 0 대비 볼륨 9 의 출력.

| 음압 | **`>>5` 있음 (현행)** | **`>>5` 없음** |
|---:|---:|---:|
| 85 dB SPL | +23.10 dB | +3.23 dB |
| **90** | +19.80 dB | **−0.07 dB ← 역전 시작** |
| 100 | +13.20 dB | **−6.67 dB** |
| 110 | +6.60 dB | **−13.31 dB** |
| **120** | −0.01 dB (수렴) | **−19.89 dB** |

> [!CAUTION]
> **`>>5` 가 없으면 90 dB SPL 위에서 «볼륨을 올릴수록 소리가 작아진다».** 120 dB SPL 에서는 볼륨 9 가 볼륨 0 보다 **19.9 dB(약 1/10) 조용하다.**
>
> **이것이 은수님이 겪은 현상의 정체다.** 시끄러운 환경에서 볼륨을 올렸는데 오히려 작아지니 «역전» 으로 보인 것이다.

절대값으로 보면 더 분명하다 (`>>5` 없음, 120 dB SPL):

| 볼륨 | 0 | 3 | 6 | 9 |
|---|---:|---:|---:|---:|
| 출력 | **829,439** | 385,023 | 180,223 | **83,967** |

**볼륨이 올라갈수록 출력이 단조 감소한다.** 그리고 전부 AGC 출력 상한 65,535 를 크게 넘는다 — 은수님이 *"Attenuation 이 AGC out max 보다 커져서"* 라고 하신 그대로다.

## 3. 제약_2 - HEAR FFT 의 65,535

### 3.1 근거는 코드에 있다

```c
// definitionsForAlgorithm.h:60  (주석 처리돼 있으나 의도가 남아 있다)
// #define df_maxAudioForLogarithm   65535  //FFT 입력
```

```c
// FrequencyAnalysis.c:89~97
/* 일반적으로 시간 영역의 크기 A인 신호를 FFT 변환을 하면 주파수 영역에서 크기는 FFT_SIZE 배로 커진다.
 * 시간 영역의 신호가 사인파형일 경우에는 두 개의 피크로 크기가 분산되기 때문에 1/2 게인이 적용된다.
 * 현재는 FFT에 window를 적용하기 때문에 입력 값의 크기가 약 1/2 적용된다. …
 * 실제 동작 테스트로, HEAR의 BFP 연산은 1/4 게인이 적용되는 것을 확인했다. (정우님 테스트 결과)
 * … 'FFT_SIZE' * '1/2_분산_피크' * 1/2_윈도우' * '1/4_BFP' = 'FFT_SIZE / 16' 이다. */
```

### 3.2 65,535 가 나오는 계산

**BFP 는 넘칠 것 같으면 스케일을 내리는 장치다. 그 앞단의 누산이 24비트를 넘으면 안 된다.**

BFP **이전**까지의 게인:

```
FFT_SIZE × 1/2(정현파 피크 분산) × 1/2(윈도우) = 512 / 4 = 128
```

24비트에 담기려면

```
AGC 출력 × 128  ≤  INT24_MAX
AGC 출력        ≤  8,388,607 / 128  =  65,536.0
```

| AGC 출력 | × 128 | 판정 |
|---|---|---|
| **65,535** | 8,388,480 | **≤ 8,388,607 통과** |
| 65,536 | 8,388,608 | **> INT24_MAX 넘침** |

> [!IMPORTANT]
> **`INT24_MAX / 128` 이 정확히 65,536.0 으로 떨어진다.** 따라서 **24비트에 담기는 최대 AGC 출력이 정확히 65,535** 다.
>
> 은수님이 «65535 가 최대값이어야 하던가» 라고 기억하신 것이 **숫자까지 정확하다.**

### 3.3 현행 체인이 그 값을 정확히 맞춘다

| 단계 | 값 |
|---|---|
| 마이크 풀스케일 | 8,388,607 = 2²³ |
| 믹서 `>>5` (÷32) | **262,143 ≈ 2¹⁸** |
| AGC 최대 입력에서의 게인 | **×0.25 = −12.04 dB** (전 볼륨 공통) |
| **AGC 출력 상한** | **65,535 ≈ 2¹⁶** |

**2²³ → 2¹⁸ → 2¹⁶.** 시프트 5비트 + AGC 2비트 = **7비트를 내려 24비트를 17비트로 만든다.**

시뮬레이터 실측으로 확인했다 — **볼륨 0~9 전부 120 dB SPL 에서 출력 65,535**(반올림으로 65,471 인 볼륨 2개 포함).

## 4. 부수 효과 - 정수 양자화

`>>5` 는 세 번째 문제도 함께 없앤다.

AGC 게인은 **Q12.12 정수**다. 게인이 작아지면 정수값이 작아져 양자화가 거칠어진다.

| | 120 dB SPL 에서의 게인 정수 (볼륨 0 → 9) |
|---|---|
| **`>>5` 있음** | **1024, 1024, 1024, 1023, 1024, 1024, 1024, 1024, 1024, 1023** |
| `>>5` 없음 | 405, 314, 243, 188, 146, 113, 88, 68, 53, **41** |

`>>5` 가 없으면 볼륨 9 에서 게인 정수가 **41** 까지 떨어진다. 1 LSB 가 **0.21 dB** 인데, 감쇠 구간의 실제 기울기는 **입력 1 dB 당 0.072 dB** 밖에 안 된다. **양자화 잡음이 신호 기울기보다 3배 크다.**

그 결과 출력이 계단처럼 울퉁불퉁해진다.

| | 90~120 dB SPL 구간의 출력 역전 횟수 (볼륨 9) | 최악 국소 하강 |
|---|---|---|
| **`>>5` 있음** | **1회** | **0.00 dB** (1 LSB) |
| `>>5` 없음 | **97회** | 0.14 dB |

> [!NOTE]
> **이 효과는 작다** — 최악 0.14 dB 로 들리지 않는다. 그래도 «입력이 커지는데 출력이 줄어드는» 구간이 실제로 생기는 것은 맞다. **은수님 기억의 그 부분이 여기에 해당한다.**
>
> `>>5` 가 있으면 게인 정수가 1024 라 1 LSB 가 0.008 dB — 기울기(0.072)의 1/9 로 충분히 곱다.

## 5. 앞선 문서의 오류 정정

> [!CAUTION]
> **[05](05_포화와%20절삭.md) §3.1 에 «`>>5` 는 6 dB 과하다. `>>4` 로 줄이면 작은 소리 분해능이 2배 좋아진다» 고 적었다. 틀렸다.**
>
> `>>5` 는 헤드룸용이 아니라 **수렴점 정렬과 FFT 65,535 를 위한 값**이다. `>>4` 로 바꾸면
>
> | | `>>5` (현행) | `>>4` |
> |---|---|---|
> | 볼륨 수렴점 | **120.0 dB SPL** | **114.0 dB SPL** → 그 위 전부 볼륨 역전 |
> | AGC 출력 상한 | **65,535** | **131,072** → FFT 에서 **24비트 넘침** |
>
> **두 제약을 동시에 깬다. 바꾸면 안 된다.**

[06](06_게인%20상호작용과%20역전%20현상.md) §4.1 의 «정적으로는 역전하지 않는다» 도 **입력 대 출력** 에 대해서는 유효하지만, **볼륨 대 출력** 을 다루지 않았다. 현행 설정에서는 볼륨 역전이 없으므로(수렴만 한다) 문서의 결론 자체는 맞지만, **«왜 없는가» 가 `>>5` 덕분이라는 점이 빠져 있었다.**

## 6. 정리 - `>>5` 는 바꿀 수 없는 값이다

| 제약 | 요구 | `>>5` 가 만족시키나 |
|---|---|---|
| **볼륨 순서 유지** | 수렴점 = 마이크 풀스케일 | **정확히 일치 (120.00 dB SPL)** |
| **FFT 오버플로 방지** | AGC 출력 ≤ 65,535 | **정확히 일치 (65,535)** |
| 게인 양자화 | Q12.12 정수가 충분히 클 것 | 1024 (여유 충분) |
| 믹서 합산 오버플로 | 2입력 + 최대게인 < INT24 | 여유 6.2 dB |

> [!IMPORTANT]
> **네 제약을 한 값이 동시에 만족한다.** 우연이 아니라 **AGC 상수(`ybias`·`slope`)가 `>>5` 를 전제로 계산된 것**이다.
>
> `AUDIO_INPUT_RSHIFT` 를 바꾸려면 **`m_attenuation_region_ybias_db_Q8_16[]` 10개와 `m_noise_region_ybias_db_Q12_12[]` 10개, 그리고 두 임계값을 전부 다시 계산해야 한다.** 단독으로 건드릴 수 있는 상수가 아니다.

## 7. 검증 방법

시뮬레이터는 `calculate_agc_gain()` 의 고정소수점 연산을 그대로 재현했다.

| 재현한 것 | 비고 |
|---|---|
| `agc_input < 1` 강제 · `<< 5` · `10·log10(x/2^47)` | `m8p16` 하한 −128 포화 포함 |
| 3구간 분기와 각 정수 시프트(`>>20`·`>>16`·`<<4`) | 음수 우측 시프트 = floor |
| `INT24` 클램프 3곳 | |
| `dB → 선형` (`10^(dB/10)`, Q1.23 → Q12.12) | `mathlib_gain` 상쇄 포함 |
| `apply_agc_gain` 의 `>>12` 와 클램프 | |

**attack/release 는 정상상태(목표값 도달)로 두었다.** 과도 응답은 [04](04_AGC%20동작%20상세.md) §6 · [06](06_게인%20상호작용과%20역전%20현상.md) §4.2 에서 따로 다룬다.

> [!NOTE]
> **실기로 확인하지 않았다.** 시뮬레이터는 소스 코드의 산술을 재현한 것이지 하드웨어를 재현한 것이 아니다. 특히 `cfx_pwr_to_dB` / `cfx_dB_to_pwr` 는 **하드웨어 가속기**라 반올림 방식이 내 근사와 다를 수 있다. **1 LSB 수준의 결론(§4 의 «역전 1회 · 0.00 dB»)은 그만큼 불확실하다.** 볼륨 역전 19.9 dB 같은 큰 결론은 영향받지 않는다.
