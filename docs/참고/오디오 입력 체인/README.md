# 오디오 입력 체인 - 마이크에서 AGC까지

**TL;DR**: 소리(dB SPL)가 **마이크 → IOC 데시메이션 → 24비트 → `>>5` → 믹서(게인) → AGC** 를 거치며 어떤 숫자가 되는지 전 구간을 수치로 추적했다. 핵심 넷 — **① `0x7FFFFF` = 120 dB SPL** ② **믹서는 어떤 조건에서도 포화하지 않는다**(여유 6.2 dB) ③ **게인이 «역으로 줄어드는» 정적 현상은 없으나, 볼륨 효과가 큰 입력에서 0 으로 소멸하고 동적으로는 줄어들 수 있다** ④ **`>>5` 는 바꿀 수 없는 값이다** — 볼륨 수렴점을 풀스케일에 맞추고 AGC 출력을 FFT 한계 65,535 에 맞춘다.

> [!NOTE]
> **2026-08-11: 최대 현안이던 «데시메이션 게인 −5.17 dB» 미확정이 해소됐다.** `1092` 는 SDK 의 `Sys_Calc_Gain_Factor_Val(29)` 가 주는 **유니티 값 그 자체**다 — 밀림은 없다. 데이터시트 인쇄식의 `log2` 에 **floor** 가 들어가는 것을 놓친 오독이었다. 경위는 [`07`](07_미확정%20사항과%20측정%20절차.md) §1.
>
> **따라서 이 문서 묶음의 dB SPL 값은 그대로 유효하다.**

## 한 장 요약

### 신호 흐름과 배율

| # | 단계 | 코드 위치 | 배율 | 누적 |
|---|---|---|---|---|
| 1 | 마이크 PDM 출력 | (하드웨어) | 감도 −26 dBFS | `0x7FFFFF` = 120 dB SPL |
| 2 | IOC 데시메이션 + `ADC_GF` | `lib_audio_in.h:112` | **`1092` = 유니티** | **0 dB** (`Sys_Calc_Gain_Factor_Val(29)`) |
| 3 | FIFO → `g_lib_dmic_in_buffers` | `lib_audio_in.c` | ×1 | 24비트 정수 |
| 4 | **믹서 `>> 5`** | `audioMixer.c:302·317·341` | **÷32 (−30.1 dB)** | 최대 262,143 **(게인 곱 이전)** |
| 5 | 믹서 게인 (**I2S 경로만**) | `audioMixer.c:341` | ×0 ~ ×7.82 (뮤트 ~ +17.86 dB) | 유니티면 262,143 유지 · 최대면 2,048,836 |
| 6 | 빔포밍 정규화 `>>1` | `audioMixer.c:419` | ÷2 (2채널 평균이므로 레벨 보존) | |
| 7 | **AGC `<< 5`** | `agc.c:181` | **×32 (+30.1 dB)** | **4번과 상쇄** |
| 8 | AGC 로그·게인 결정 | `agc.c:186~304` | −12 ~ +29.7 dB | |
| 9 | AGC 게인 적용 | `agc.c:307~336` | | 믹스 도메인 출력 |

> [!IMPORTANT]
> **4번(`>>5`)과 7번(`<<5`)이 정확히 상쇄된다.** 목적은 서로 다른데(전자는 합산 오버플로 방지, 후자는 로그 라이브러리 정확도) 배율이 같아 맞물린다. **그래서 AGC 가 로그를 취하는 값은 마이크 24비트 원본과 같은 눈금이다.**

### 기억할 숫자

| 항목 | 값 |
|---|---|
| **24비트 풀스케일 = 음압** | **`0x7FFFFF` = 120 dB SPL** (= 마이크 AOP) |
| 6 dB 오르면 | 코드 **2배** |
| 마이크 잡음 바닥 | 29.7 dB SPL (코드 **256**) |
| **AGC 노이즈 게이트** | **29.5 dB SPL** (코드 **250**) |
| **AGC 회전점** | **75 dB SPL** (코드 **47,173**) |
| 볼륨 1칸 | **3.3 dB** (0~9 → 0~29.7 dB) |
| 믹서 게인 1칸 | 0.1406 dB (0~255, 128=0 dB, 범위 ±17.86 dB) |
| AGC 출력 상한 | 믹스 코드 약 **65,535** (**−42 dBFS 상당**) |
| attack / release | **1.1 ms / 100 ms** (정착 5 ms / 500 ms) |

### 실무에서 바로 쓸 결론 여섯

1. **하위 8비트는 신호가 아니다.** 마이크 잡음 바닥이 코드 256 이라 그 아래는 전부 잡음이다. 24비트 중 실제로 쓰는 것은 상위 16비트 정도다.
2. **믹서는 포화하지 않는다.** 최대 입력 · 최대 게인 · 2입력 합산에서도 4,097,672 로 `INT24_MAX` 의 **절반**이다. 여유 6.2 dB.
3. **믹서 게인은 I2S 스트리밍 중에만 걸린다.** 그 외 경로(단일 DMIC · 빔포밍)는 게인 테이블을 아예 통과하지 않는다. → [06](06_게인%20상호작용과%20역전%20현상.md)
4. **볼륨을 올려도 큰 소리는 그대로다.** 10개 볼륨 곡선이 120 dB SPL 에서 **한 점으로 모인다.** 볼륨 효과가 0 이 된다.
5. **작은 소리에서 분해능이 나쁘다.** 노이즈 게이트 근처(29.5 dB SPL)에서 `>>5` 뒤에 남는 값이 **7** 이라 1 LSB 가 **1.16 dB** 다. AGC 의 게이트 판정이 그만큼 거칠다. **다만 이것은 낭비가 아니라 대가다** → 6번.
6. **`AUDIO_INPUT_RSHIFT = 5` 는 바꿀 수 없는 값이다.** 헤드룸용이 아니라 **볼륨 곡선 수렴점을 마이크 풀스케일에 맞추고**(안 맞추면 90 dB SPL 위에서 **볼륨이 19.9 dB 뒤집힌다**) **AGC 출력을 FFT 한계 65,535 에 맞추는** 값이다. → [08](08_왜%20믹서에서%205비트를%20내리는가.md)
