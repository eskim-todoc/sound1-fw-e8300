## 1. 개요

E8300 외부기기에 Azoteq IQS323 정전용량 터치센서를 사용한다. 3채널 Self-Capacitive 중 Sensor 0(CH0)만 사용하며, 싱글 터치 감지와 3초 롱터치 이벤트로 전원 제어를 수행한다.

| 항목 | 값 |
|---|---|
| IC | Azoteq IQS323 (ProxFusion) |
| I2C 주소 | `0x44` |
| RDY/MCLR 핀 | DIO16 |
| 사용 채널 | Sensor 0 (CH0) — Self-Capacitance |
| 비활성 채널 | Sensor 1, 2 |
| 터치 감지 | 100ms 폴링, CH0 Touch 비트 확인 |
| 롱터치 판정 | 3초 연속 터치 유지 (소프트웨어) |

## 3. 초기화 시퀀스

`tdc_iqs323_init()` — `Initialize()`에서 인터럽트 활성화 후 호출.

```
1) mclr_reset()          — DIO16 LOW 1ms → INPUT 복원 → 50ms 부팅 대기
                           IQS323 POR → Reset Event SET → Auto-ATI 시작

2) sensor_setup()        — [Reset Event SET 상태 → ATI 중에도 통신 가능]
   touch_settings()        Sensor 1,2 비활성, Sensor 0만 활성화
   events_enable()         Touch Threshold/Hysteresis 설정, Events Enable

3) ack_reset_event()     — Reset Event 클리어
   confirm_reset_event()   Reset Event 해제 확인

4) re_ati_trigger()      — RE-ATI 트리거 (Sensor 0 단일 채널 캘리브레이션)
   (50ms 대기)
   wait_re_ati_done()    — ATI Event 플래그 확인 (최대 10회, 100ms 간격)
```

**핵심 원리**: Reset Event가 SET된 동안에는 Auto-ATI 실행 중에도 통신 윈도우가 연속 제공된다 (데이터시트). 이를 활용하여 Auto-ATI 완료를 기다리지 않고 바로 설정을 진행한 뒤, Sensor 0만 활성화된 상태에서 RE-ATI를 수행한다.

**소요 시간**: MCLR(51ms) + 설정(~60ms) + RE-ATI(~150ms) ≈ **~260ms**

## 4. 레지스터 설정 값

### Events Enable (`0xD3`) — `0x52`

| 이벤트 | 설정 |
|---|---|
| ATI Error / ATI Event / Touch Event | **활성** |
| Power / Slider / Prox Event | 비활성 |

### Sensor Setup

| 레지스터 | 값 | 설명 |
|---|---|---|
| `0x30` (Sensor 0) | `0x0101` | CTx0 활성, Channel Enable |
| `0x40` (Sensor 1) | `0x0000` | 비활성 |
| `0x50` (Sensor 2) | `0x0000` | 비활성 |

### Touch Settings (`0x62`) — `0x5050`

| 항목 | 값 | 의미 |
|---|---|---|
| Touch Threshold | 80 (0x50) | (80 × LTA) / 256 |
| Touch Hysteresis | 80 (0x50) | (80/256) × Touch Threshold |

### 미설정 항목 (IC 기본값 사용)

ATI Setup/Base(`0x36`~`0x38`), Prox Threshold(`0x61`), Event Timeout(`0xD2`), Filter Beta(`0xB0`~`0xB4`), Report Rate(`0xC1`~`0xC4`), Conversion Frequency(`0x31`), PXS Mode(`0x32`)

## 5. 런타임 동작

### 5.1 폴링 (`tdc_iqs323_process`)

100ms 간격으로 System Status(0x10) 읽기. CH0 Touch 비트로 TOUCH/NOT_TOUCH 판정.

### 5.2 롱터치 (`proc_touch`)

| 전이 | 동작 |
|---|---|
| RESET/NOT_TOUCH → TOUCH | 첫 터치 시각 기록 |
| TOUCH 유지 ≥ 3초 | 롱터치 이벤트 1회 보고 (`true` 반환) |
| TOUCH → NOT_TOUCH | 롱터치 플래그 리셋 |

### 5.3 절전 모드

`func_sleep()` 루프에서 `tdc_iqs323_process()` 호출:
1. 롱터치 감지 → 터치 해제 대기
2. 해제 확인 → `SYS_WATCHDOG_RESET()` → MCU 전체 리셋 → `tdc_iqs323_init()` 재실행

## 6. 이슈 이력 및 해결

### 6.1 절전 후 워치독 리셋 시 RE-ATI 타임아웃

**증상**: MCU만 리셋, IQS323 전원 유지 → I2C 버스 불일치 → 설정 타임아웃.

**원인**: MCU 리셋 시 I2C 핀 글리치 → IQS323 자체 워치독(255ms) 발동 → Auto-ATI 진행 중에 MCU가 통신 시도.

**해결**: MCLR 하드 리셋 추가. 항상 IQS323을 POR 상태에서 시작.

### 6.2 완전 전원 차단 후에도 간헐적 실패

**증상**: 파워서플라이 차단/재공급에서도 RE-ATI 타임아웃 간헐 발생.

**원인**: MCLR 후 50ms 부팅 대기만으로는 Auto-ATI가 미완료. Auto-ATI 중에 RE-ATI 트리거 → 무시됨.

**해결**: Reset Event SET 상태에서 Auto-ATI 완료를 기다리지 않고 바로 설정 → ACK Reset → RE-ATI (섹션 3 참조). Auto-ATI 대기 단계 자체를 제거하여 근본적으로 해소.

### 6.3 터치 누른 채 전원 인가 시 Auto-ATI 무한 루프

**증상**: 터치 상태에서 부팅 시 Auto-ATI가 수렴 못 함 (3채널 기본 활성 → ATI 완료 즉시 Re-ATI 재실행 루프).

**원인 로그**:
```
TRY 1~10:  LSB=0xA0, MSB=0x20  → Reset Event=1, ATI Active=1, CH2 Touch=1
TRY 11:    LSB=0xB2            → ATI Event=1 (완료) + ATI Active=1 (즉시 Re-ATI)
TRY 13~20: MSB=0x0F            → CH0/CH1 Touch+Prox → ATI Active 유지 → TIMEOUT
```

**해결**: 섹션 3의 최적화된 시퀀스가 이 문제도 해소. Reset Event SET 상태에서 바로 Sensor 1,2 비활성화 → RE-ATI는 Sensor 0만으로 수행하여 터치 중에도 단일 채널이 수렴 가능.

## 7. 향후 검토: ATI 레지스터 덤프 방식

### 7.1 개념

ATI가 성공한 시점에서 캘리브레이션 결과 레지스터를 읽어 저장해두고, 이후 부팅 시 ATI를 실행하지 않고 저장된 값을 직접 쓰는 방식.

### 7.2 관련 레지스터

ATI 결과는 센서별로 다음 3개 레지스터에 저장됨:

| 레지스터 | 이름 | 내용 |
|---|---|---|
| `0x36` | ATI Setup | ATI Resolution Factor, ATI Band, ATI Mode |
| `0x38` | ATI Multipliers/Dividers | Fine/Coarse Fractional Multiplier/Divider |
| `0x39` | Compensation | Compensation Divider + Compensation 값 |

Sensor 0만 사용하므로 `0x36`, `0x38`, `0x39` 3개 레지스터.

### 7.3 적용 방법

```
[1회 캘리브레이션 (개발/제조 단계)]
  1. 정상 환경에서 tdc_iqs323_init() 실행 → RE-ATI 성공
  2. 0x36, 0x38, 0x39 레지스터 읽기 → 값 기록
  3. 기록된 값을 펌웨어에 상수로 하드코딩

[이후 매 부팅]
  1. MCLR 리셋 → 설정 (sensor_setup, touch_settings, events_enable)
  2. ATI Mode를 "Disabled"(0x00) 또는 "Compensation Only"(0x01)로 설정
  3. 저장된 0x38, 0x39 값을 직접 쓰기
  4. RE-ATI 실행하지 않음 → ATI 대기 시간 0ms
```

### 7.4 예상 효과

| 항목 | 현재 (RE-ATI) | 덤프 방식 |
|---|---|---|
| ATI 소요 시간 | ~150ms | **0ms** |
| 총 초기화 시간 | ~260ms | **~110ms** |
| 터치 중 부팅 | RE-ATI가 터치 상태로 캘리브레이션 (일시 부정확) | 항상 정상 기준값 사용 |

### 7.5 위험 요소

| 위험 | 설명 | 대응 |
|---|---|---|
| **보드 간 편차** | 캘리브레이션 값은 PCB/전극 용량에 의존. 보드마다 다를 수 있음 | 제조 단계에서 보드별 캘리브레이션 필요. 또는 NVM에 저장 |
| **환경 드리프트** | 온도/습도 변화로 전극 용량이 변하면 고정 값이 부정확해짐 | Auto Re-ATI를 활성 상태로 유지. ATI Band 내에서 LTA가 자동 추적 |
| **ATI Mode Disabled 시 Re-ATI 불가** | ATI Mode=Disabled면 런타임 Re-ATI가 동작하지 않음 | ATI Mode를 "Full"로 유지하되, Compensation 값만 사전에 쓰는 방식 권장 |
| **센서 교체/수리 시 재캘리브레이션** | 하드웨어 변경 시 저장된 값이 무효 | 캘리브레이션 모드 진입 기능 필요 |

### 7.6 권장 판단

| 상황 | 권장 |
|---|---|
| 개발/프로토타입 단계 | **현재 방식 (RE-ATI) 유지**. 260ms는 충분히 빠르고, 보드 간 편차 걱정 없음 |
| 양산 단계에서 초기화 시간이 중요할 때 | 덤프 방식 검토. 단, ATI Mode="Full" 유지 + NVM 저장 + 캘리브레이션 모드 구현 필요 |
| 터치 중 부팅 정확도가 중요할 때 | 덤프 방식이 유리. 항상 정상 기준값으로 시작하므로 터치 중 부팅에도 즉시 정확 |
