## TL;DR

"많이 나아졌다"는 평가 후 5가지 추가 피드백을 받아 반영했다. 핵심은 (1) 자극 펄스가 COLA와 동일한 시프트 레지스터 구조(다음 패킷 수신 시 이전 패킷 데이터 출력)라는 새 도메인 지식 반영, (2) 채널당 PCM 패킷 중 첫 패킷만 실데이터·나머지는 NOP이라는 구조를 시각적으로 구분, (3) CIS/NofM 각각에 대해 연속 2펄스를 확대해 duration·다음 자극까지·IDLE 시간을 화살표로 보여주는 신규 다이어그램 추가.

## 반영 내역

| 요청 | 반영 |
|---|---|
| 하단 안내 문구("프레임(PCM 패킷) 수...") 삭제 | `<footer>` 블록 및 관련 CSS(`footer`, `footer code`) 전체 제거 |
| "펄스 파형" → "자극 펄스" 명칭 변경 | 두 패널의 행 라벨 변경 |
| 자극 펄스도 COLA처럼 "다음 패킷 수신 시 이전 패킷 출력" 시프트 구조 | `drawPulseRow`의 `groupX`를 PCM 대비 **+2슬롯**으로 변경(COLA는 +1슬롯 그대로, 자극 펄스는 그보다 한 단계 더 지연 — "다음 COLA 수신 시작 시점에 이전 COLA 데이터가 출력"되는 시프트 레지스터 구조를 그대로 반영) |
| 채널당 PCM 패킷: 첫 패킷=자극 데이터, 나머지=NOP → NOP만 옅은 회색 | `drawChannelRow`에서 그룹 전체를 먼저 `idle-fill`로 채운 뒤, 첫 슬롯(슬롯폭 1개분)만 채널 틴트로 덮어써 구현. 바깥 테두리는 기존대로 채널 색 유지, 패킷 경계 세로선도 유지 |
| CIS/NofM 비교 테이블에 연속 2펄스 확대 다이어그램(duration·다음 자극까지·IDLE 화살표 표시) | 신규 `.pulse-detail` 섹션(통계 카드 바로 아래) + `drawPulseDetailDiagram()` 함수. 펄스 모양은 고정 픽셀 예산(116px)으로 그려 duration 값에 관계없이 항상 읽기 쉽게 하고, IDLE 구간은 "축척 아님"을 명시한 채 고정 폭(70px)에 브레이크(사선 2개) 표시로 압축 표현. 화살표 3개: ①전체 구간 상단("다음 자극까지 X (rate)"), ②첫 펄스 negative phase만("duration p usec"), ③펄스 종료~다음 펄스 시작("자극 후 IDLE ≈ X"). NofM은 불가 조건일 때 동일하게 "불가" 메시지로 대체 |

## 수치 검증 (Python 재현)

여러 (K,p) 조합에서 `frames/channelsPerMs/rate`로부터 유도한 `period = 1e6/rate`, `idle = period - (2p+GAP)` 값을 재계산해 CIS/NofM 각각 사리에 맞는 수치(예: K=32,p=13 → CIS 750pps·idle≈1.30ms; NofM 항상 2ms 주기·p=13이면 idle≈1.97ms)임을 확인했다.

## 한계

이번에도 브라우저 렌더링 없이 정적 코드 검토 + Python 수치 재현으로만 검증했다. 특히 신규 2펄스 다이어그램은 텍스트 라벨 길이와 캔버스 폭(460px) 간 여유를 계산상으로만 확인했으므로, 실제 폰트 렌더링에서 라벨이 살짝 좁게 보일 가능성은 남아있다.
