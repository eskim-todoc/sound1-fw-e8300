## TL;DR

은수님이 `docs/참고/nofm/기반 지식 정보.md`에 직접 작성한 요구사항(CIS/NofM 자극 출력 패턴, PCM/COLA 타이밍)을 `stimulationParaCal.c` 실제 코드와 대조 검증했다. 공식은 100% 일치 확인. 이 문서는 이후 페르소나 분석 단계의 공통 근거(single source of truth)로 사용한다.

## 1. 원본 요구사항 (기반 지식 정보.md 요약)

- 대상: e8300 인공와우 외부기, 32채널 예시
- CIS: 사용 가능 채널을 1→N 순서로 반복 출력 (Interleaved 아님, 번호순 표시)
- NofM: 항상 **16 of M** (N=16 고정). M≤16이면 의미 없음 → CIS 사용
- e8300은 PCM 인터페이스로 20bit/채널 자극정보 패킷을 1ms당 24개, FIFO로 무한 반복 전송
- PCM 패킷 → FPGA → todoc 자체 COLA 프로토콜로 변환 → 무선으로 내부이식장치 전송
- 자극펄스: biphasic, negative 선행. pulse phase 최소 길이 13usec (neg 13 + gap 4 + pos 13)
- 이 최소 duration 전송하는 COLA 프로토콜 시간 ≈ 33usec
- PCM clk 480kHz → 20bit 패킷 1개 전송 ≈ 41.6usec, 펌웨어는 41usec로 계산 사용 (0.6usec 여유는 의도적 — 다음 패킷이 이전 COLA 전송 완료 전에 들어오면 clock rate error 상태 진입하기 때문)
- duration 13 초과 시 1usec당 phase별 COLA 전송시간 증가 (예: 14 → 35usec)
- 10usec 여유를 추가로 두어 e8300-FPGA 클럭 차이 대응
- **NofM은 채널당 PCM 3패킷 고정** (3패킷 초과 duration 불가), 채널 rate 항상 일정 (동일 16채널 매번 선택 가정) → 3×8=24 (1ms당 8채널) → 2ms에 16채널 전부 출력 → **PPS=500**
- **CIS**는 duration에 따라 채널당 PCM 패킷 수가 가변 → 채널 rate도 가변

### 요청 산출물

- HTML/JS 단일 파일, 그 자체로 설정 가능한 구조
- 입력: 사용가능 채널 수, duration(13~255)
- 출력: CIS·NofM 자극 펄스 출력 패턴(수 ms 구간) + PCM 전송 패턴 + COLA 전송 패턴 시각화
- 목적 통찰: duration → PCM 패킷 수 → COLA 전송시간 → 실제 자극 시점 → IDLE 시간 → CIS/NofM 상대 전력소모 비교

## 2. 참고 이미지 해석 (`cis, nofm 출력 패턴.JPG`)

5행 타임라인 (가로축 0~3ms):
1. N of M (16 of 32), duration 13us, PCM 패킷 3개/채널 — 채널 번호가 색상 블록(청록/노랑 교차)으로 표시, 8채널씩 1ms
2. N of M (16 of 32), duration 33us, PCM 패킷 3개/채널 (고정이므로 33us에도 3패킷 그대로)
3. CIS(32채널), duration 13us, PCM 패킷 1개/채널 — 1ms에 24채널 (1~24), 2ms에 25~32+1~16, 3ms에 17~32+1~8 반복
4. CIS(32채널), duration 33us, PCM 패킷 2개/채널 — 1ms에 12채널(1~12), 2ms에 13~24, 3ms에 25~32+1~4
5. CIS(32채널), duration 16us, PCM 패킷 2개/채널 ("첫 us 때문에 패킷 2개 필요") — 1ms에 12채널

각 행 하단에 실제 biphasic 펄스 파형(negative-먼저, 사각파 형태) 예시 스케치 포함.

## 3. 소스 코드 검증 결과 — `stimulationParaCal.c`

경로: `src/2__cm3/Cortex-M3-src/signalProcessing/stimulationParaCal.c` (2026-07-02 기준 작업 브랜치)

### 3.1 채널당 필요 PCM 프레임 수 — `calculationNumFramePerOneChannle(int pulsewidth)`

```c
duration = pulsewidth;
duration += duration;                              // 2 × pulsewidth (neg+pos phase)
duration += FPGA_interphaseGapTokenTime;            // + 4  (interphase gap)
duration += FPGA_electrodAndStimulLevelTokenTime;    // + 10 (전극번호+자극크기 전송)

tokenTime = FPGA_oneChannelDataTokenTime;           // 41
numFramePerChannel = 1;
while (duration >= tokenTime) {
    numFramePerChannel++;
    tokenTime += FPGA_oneChannelDataTokenTime;      // +41 씩 누적
}
```

즉 `raw = 2×pulsewidth + 14`, `numFramePerChannel = floor(raw / 41) + 1` (41의 배수 경계에서 `<` 비교이므로 정확히는 위 while 루프와 동일한 계단함수).

**검증 (JPG 예시와 완전 일치):**
| pulsewidth(duration) | raw = 2p+14 | 41 경계 | frames |
|---|---|---|---|
| 13 | 40 | <41 | **1** |
| 14 | 42 | ≥41, <82 | **2** |
| 16 | 46 | ≥41, <82 | **2** ("첫 us 때문에 2개 필요") |
| 33 | 80 | ≥41, <82 | **2** |

### 3.2 1ms당 전송 가능 채널 수 — `calculationTransferableChanneNum`

```c
TransferabelChannelNumPerOneMilSec = df_MaxNumTransferableChannel / numFramePerChannel;  // 24 / frames (정수 나눗셈)
```

### 3.3 NofM 고정 오버라이드 — `calculationStimulParaN_cfxShare()`

```c
if (stimulationStrategy == df_stimulationStrategy_nOFm) {
    if (numFrequencyBand < 16) { /* NofM 사용 불가 에러 로그 */ }
    else {
        frameNumPerOneChannel  = 3;  // 채널당 3 프레임 고정
        transferableChannelNum = 8;  // 1ms당 최대 8채널 고정
    }
}
```
→ **NofM은 duration/pulsewidth와 무관하게 항상 3프레임·8채널/ms로 고정**. (단, `setting_stimulationRange()`는 별도로 duration 기반 DAC 레벨 계산에 pulsewidth를 계속 사용 — 프레임 수 계산에만 고정값이 override됨)

### 3.4 검증된 상수 (`definitionsForAlgorithm.h`, FPGA 헤더)

| 상수 | 값 | 의미 |
|---|---|---|
| `FPGA_oneChannelDataTokenTime` | 41 | 채널 1개 PCM 프레임 슬롯 시간(usec), 이론값 41.66usec |
| `FPGA_interphaseGapTokenTime` | 4 | interphase gap (usec) |
| `FPGA_electrodAndStimulLevelTokenTime` | 10 | 전극번호+자극크기 전송 시간(usec) |
| `df_MaxNumTransferableChannel` | 24 | 1ms당 최대 PCM 프레임(=채널) 수 |
| `df_MaxNumOfElectrode` | 32 | 최대 전극(채널) 수 |
| `df_stimulationStrategy_CIS` | 1 | enum |
| `df_stimulationStrategy_nOFm` | 2 | enum |
| `df_stimulationStrategy_medium` | 3 | enum |

### 3.5 미검증/펌웨어 범위 밖 항목 (도메인 지식으로만 존재, 코드 상수 아님)

- PCM clk 480kHz, 20bit/패킷 → 41.6usec 이론값: **CM3 펌웨어 코드에는 등장하지 않음** (FPGA 하드웨어 스펙 수준의 지식). `FPGA_oneChannelDataTokenTime` 정의 주석에 "41.66usec"로 명시되어 있어 정합.
- COLA 프로토콜 자체의 정확한 bit-level 전송 시간(≈33usec @ duration13, +1usec/phase 증가분): FPGA 내부 로직이라 CM3 소스에는 없음. 은수님 도메인 지식을 그대로 신뢰하고 시각화 파라미터로 사용.
- 10usec 여유값의 정확한 계산 근거는 코드에 없음 (은수님 설명 그대로 채택).

## 4. 웹페이지 계산 모델에 반영할 최종 공식 (JS 포팅 대상)

```
frames(pulsewidth)      = floor((2*pulsewidth + 14) / 41) + 1        // 41 배수 경계 계단함수, CIS·기본 공식
channelsPerMs(frames)   = floor(24 / frames)                          // CIS
NofM: frames = 3 (고정), channelsPerMs = 8 (고정) — pulsewidth와 무관, 단 16 <= M 조건에서만 유효
PCM 프레임 전송시간      = frames * 41 usec (채널당)
COLA 전송시간(추정)      = pulsewidth13일 때 33usec 기준 + (pulsewidth-13)*1usec/phase*2phase  (은수님 도메인 지식, §3.5 참조)
```

CIS 채널 wrap 패턴: 사용가능채널수 K개일 때, 1ms에 `channelsPerMs`개씩 1→K를 반복하며 순환 (K<24인 경우 K에서 wrap).
