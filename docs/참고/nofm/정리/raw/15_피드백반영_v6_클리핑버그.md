## TL;DR

은수님이 ASCII 다이어그램으로 상세히 설명해주신 내용을 분석한 결과, **캔버스 폭이 "자극 펄스" 렌더링에 필요한 실제 폭보다 부족해 마지막 채널(들)의 펄스가 잘려 그려지던 실제 버그**를 발견·수정했다. 그 외 배너 깜빡임(정적 문구로 전환), 채널 순환 경계 표시, NofM ms 눈금 추가, CSS Grid로 인해 NofM 컬럼이 사라질 수 있던 잠재 버그도 함께 수정했다.

## 1. 핵심 버그: 자극 펄스 클리핑

**증상**: "테이블에 그림을 제대로 못 그리는" — ASCII 예시(duration=13, duration=255)를 분석한 결과, 자극 펄스는 `PCM 시작 + (f+1)슬롯` 위치에서 시작해 `f슬롯` 폭만큼 그려지는데, 캔버스 폭은 단순히 `msWindow × 24슬롯`으로만 계산되어 있어 **표시 구간의 마지막 채널의 펄스가 캔버스 오른쪽 경계를 넘어가 잘렸다.**

**검증(Python)**: 기본값(K=32,p=13,5ms)만 해도 2슬롯이 잘리고, duration=255(f=13)에서는 최대 14슬롯이 잘리는 것을 확인했다.

**수정**: `renderPanel`에서 `marginSlots = tl.f + 1`을 계산해 ruler·채널·COLA·자극펄스 4개 캔버스 모두 `(msWindow×24 + marginSlots)`슬롯 폭으로 통일 — Python 재검산 결과 모든 케이스에서 정확히 여유폭 안에 들어맞음(초과분 0, 여유도 없이 딱 맞음 — 과도한 마진 없이 정확한 필요량만 추가).

## 2. 그 외 반영

| 요청 | 반영 |
|---|---|
| NofM 한계 안내가 duration 48~54 구간에서만 깜빡이며 나타남 | 조건부 배너(`updateBanner`) 완전 제거, "⚠ NofM의 한계는 54usec 입니다..." 고정 문구를 duration 슬라이더 바로 아래 작은 글씨로 항상 표시 |
| 채널·PCM 패킷 행에 마지막 채널→1번 채널 경계 표시 | `drawChannelRow`에 `lastActiveChannel` 추적 추가, 채널 0으로 돌아가는 지점에 굵은 점선 마커. NofM(16채널 고정)에도 동일 적용, 범례에 설명 추가 |
| NofM 쪽에도 ms 눈금 | NofM 패널에 `nofm-ruler` 캔버스 추가, CIS와 별도로 자신의 `marginSlots` 기준으로 렌더링 |
| "테이블이 가변 길이가 되어 CIS 때문에 NofM이 사라지지 않게" | **잠재 버그 발견**: `.stats` grid의 `1fr 1fr` 컬럼은 기본적으로 `min-width:auto`라서, 캔버스처럼 폭이 큰 콘텐츠가 있으면 grid item이 그 콘텐츠 크기 이하로 줄어들지 못해 반대쪽(NofM) 컬럼이 밀려나거나 사라질 수 있다(CSS Grid의 잘 알려진 함정). `.stats > div { min-width: 0; }`를 추가해 두 컬럼이 항상 `1fr 1fr` 비율을 지키도록 수정 |

## 3. 검증

Python으로 여러 (K, p, msWindow, isNofM) 조합에서 "펄스 우측 끝 위치 ≤ 확장된 캔버스 폭"을 재확인 — 전부 정확히 경계선에 맞아떨어짐(마진 계산식이 필요충분조건임을 확인).

## 4. 한계

여전히 브라우저 렌더링 확인은 못했다. CSS Grid `min-width:0` 수정이 실제 여러 브라우저에서 기대대로 동작하는지, 그리고 클리핑 버그가 시각적으로 완전히 해소되었는지는 은수님이 직접 확인해 주셔야 한다.
