## TL;DR

메시지 초반의 "(c)를 (b)로" 지시는 메시지 말미의 "(a)(b)(c) 다 없애고"로 최종 대체된 것으로 판단해, 자극 펄스 행의 시간 주석을 전부 제거했다(펄스 모양만 남김). 대신 통계 테이블에 "자극율(Stimulation rate)" 행을 신설(Hz/kHz 자동 단위). 라벨명 변경, duration 막대의 패킷수별 계단 그라데이션, 썸 세로 정렬 보정도 함께 반영했다.

## 반영 내역

| 요청 | 반영 |
|---|---|
| 테이블 "1ms당 IDLE" 제거 | `idleUsecPerMs`/`fmtPct` 함수 포함 완전 삭제 |
| 자극 펄스 (a)(b)(c) 전부 제거 | `drawPulseRow`를 펄스 모양+채널번호만 그리도록 원복, 행 높이 118→40px, `drawAnnotationArrow`/`fmtUs` 삭제 |
| 테이블에 "자극율(Stimulation rate)" 신규 행 | `채널당 rate` 바로 아래 추가. CIS=`channelsPerMs(f)×1000`Hz, NofM=`8×1000=8000`Hz(고정). `fmtHz()`로 1000Hz 이상이면 kHz로 자동 전환 |
| "사용 가능 채널 수" → "활성 채널 수" | 라벨 텍스트만 변경 |
| "Duration / Pulse Phase Width (p)" → "Duration" | 라벨 텍스트만 변경 |
| Duration 막대에 패킷 수(frames(p))별 그라데이션 | `buildDurationTrackGradient()` 신규 — frames(p) 계단함수의 실제 구간 경계(13개 밴드, f=1~13)에서 하드 컬러 스톱을 만들어 `linear-gradient`로 적용(부드러운 그라데이션 아님, 패킷 수 늘 때마다 명도 82%→35%로 단계적으로 어두워짐) |
| 슬라이더 썸(●)이 트랙 대비 아래로 처짐 | `::-webkit-slider-thumb`에 `margin-top:-6px`(트랙4px/썸16px 높이차 보정) 추가 — WebKit 특유의 세로 미정렬 보정 |
| 테이블 밑 범례(계열 표시) 전부 제거 | `.legend` 섹션·CSS 규칙 삭제 |

## 검증

- Python으로 `frames(p)` 계단 경계 재계산 → 13개 밴드가 0%~100%를 빈틈없이 커버하고 명도가 82→35로 단조 감소함을 확인.
- `자극율` Hz/kHz 값 여러 (K,p) 조합에서 재계산 — 항상 1000Hz 이상(=1kHz 이상)이라 kHz로 표시됨을 확인(c≥1이므로 구조적으로 Hz 단위가 나올 수 없음 — 그래도 코드는 두 단위 모두 처리하도록 일반적으로 작성).
- HTML/JS 정적 검사(괄호·태그·id 참조, 제거된 요소·함수의 잔여 참조 없음) 전부 통과.

## 한계

이번에도 브라우저 렌더링은 못했다. 특히 커스텀 그라데이션 트랙이 Firefox `-moz-range-track`에서도 의도대로(appearance:none 적용 시 input 자체 배경이 트랙으로 보이는지) 렌더링되는지는 실기 확인이 필요하다.
