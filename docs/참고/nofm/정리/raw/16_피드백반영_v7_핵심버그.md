## TL;DR

은수님이 스크린샷 5장으로 짚어주신 문제를 이미지로 직접 확인 후 하나씩 수정했다. 그중 1번은 실제 로직 버그(1ms에 1채널만 들어가는 대형 duration에서 자극 펄스가 NOP 슬롯 위치를 "다음 COLA"로 오인)였고, Python으로 버그 재현 → 수정 → 재검증까지 마쳤다.

## 1. 핵심 버그: 자극 펄스가 NOP 슬롯을 "다음 COLA"로 오인 (실제 로직 오류)

**증상**: duration≥239(채널당 PCM 패킷 13개, `channelsPerMs(13)=1`)에서 자극 펄스가 이상한 위치에 그려짐.

**원인**: 기존 공식 `groupX = pcmGroupX + (f+1)×slotPx`는 "바로 다음 슬롯에 실제 다음 채널의 COLA가 있다"고 가정했다. 이는 1ms에 여러 채널이 들어가는 경우(예: duration=13, 24채널/ms)엔 맞지만, **1ms에 1채널만 들어가고 나머지가 NOP인 경우, 그 다음 슬롯은 NOP이라 실제 COLA가 없다.** Python으로 재현: f=13일 때 기존 공식은 슬롯14(NOP)를 가리켰지만, 실제 다음 COLA는 슬롯25(다음 ms 첫 채널)에서 시작해야 함을 확인.

**수정**: `forEachGroupWithNext()` 신규 함수 — 각 그룹이 "같은 ms 안의 다음 채널로 바로 이어지는지" 또는 "그 ms의 마지막 채널이라 다음 ms까지 건너뛰어야 하는지" 판별해 정확한 다음 COLA 시작 위치를 계산. 여러 (K,p,msWindow) 조합에 대해 "펄스 우측 끝 ≤ 확장된 캔버스 폭"을 Python으로 재검증했다.

## 2. NofM 한계 마커 — 슬라이더 썸 중앙 정렬

기존 CSS `calc()`의 썸 반지름 가정(8px)이 실제 렌더링과 어긋날 가능성을 배제하기 위해, **JS로 실측 트랙 폭을 읽어 직접 위치를 계산**하도록 변경(`positionNofmLimitMark()`, `renderAll()`마다 재계산 + 리사이즈 시에도 자동 반영).

## 3. Duration=55 부근에서 화면이 "깜빡이는" 레이아웃 점프

NofM이 불가 상태로 전환될 때 `#nofmDisabled`(전체 타임라인 자리, ~145px)와 `.disabled-msg.small`(2펄스 그림 자리, ~60px)가 각각 **정상 콘텐츠와 비슷한 최소 높이(min-height)를 갖도록 고정**하고 내용을 flex로 중앙 정렬 — 상태 전환 시 페이지가 출렁이지 않게 함.

## 4. 2펄스 상세 그림 — duration에 따라 커지고 스크롤 생기던 문제

**원인**: `pxPerPacket=10`(고정)으로 실제 packet 폭을 그리다 보니, 재자극 주기(`periodPackets`)가 커질수록(저속 조건) 캔버스 자체가 매우 넓어져 가로 스크롤이 필요했다(예: K=32,p=255→약 15,600px).

**수정**: 캔버스 크기를 `520×40px`로 **고정**하고, 대신 `pxPerPacket = 고정폭 / periodPackets`로 **매 렌더마다 스케일 자체를 재계산**해 항상 고정 박스 안에 맞춤. Python으로 극단값(K=1~32, p=13~255, NofM)까지 음수·오버플로우 없이 항상 고정폭 안에 들어맞음을 확인.

## 5. 검증

- 자극 펄스 정렬: Python으로 K=1,16,20,31,32 / p=13,54,239,255 / NofM 조합에서 "우측 끝 ≤ 확장 캔버스 폭" 전부 통과.
- 2펄스 고정 크기: 동일 조합에서 pxPerPacket·negW가 항상 양수이고 reservationW 안에 들어맞음을 확인.
- HTML/JS 정적 검사(괄호·태그·id 참조) 전부 통과.
