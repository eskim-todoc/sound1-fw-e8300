## TL;DR

이번 라운드에서 실제 버그 2건(자극 펄스 정렬 공식이 다중 프레임 채널에서 틀림, NofM 2펄스 그림이 고정 3패킷이 아니라 CIS처럼 `frames(p)`를 씀)을 발견·수정했고, 2펄스 그림을 "채널 자신의 예약 슬롯" 기준에서 "실제 재자극 주기(패킷 수 환산)" 기준으로 재설계했다.

## 1. 버그 수정

- **자극 펄스 정렬 버그**: 기존엔 모든 채널에 대해 무조건 `PCM 대비 +2슬롯`으로 자극 펄스를 그렸다. 이는 `f=1`(단일 패킷)일 때만 우연히 맞고, `f>1`(다중 패킷 채널)에서는 틀렸다. 올바른 위치는 "이 채널의 COLA 구간이 끝나는 지점"(`COLA 시작(+1슬롯) + COLA 폭(f슬롯) = PCM 대비 +(f+1)슬롯`)이다. Python으로 f=1,2,3,13 전부 재검산해 새 공식이 일치함을 확인했다.
- **NofM 2펄스 그림 버그**: `drawPulseDetailDiagram`이 NofM 호출 시에도 내부적으로 `frames(p)`를 다시 계산해 CIS와 동일한 가변 패킷 수로 그려지고 있었다. NofM은 duration과 무관하게 항상 3패킷 고정이므로, 함수에 `fixedF` 파라미터를 추가해 CIS는 `frames(p)`, NofM은 리터럴 `3`을 명시적으로 전달하도록 수정했다.

## 2. 2펄스 그림 재설계 (예약 슬롯 → 실제 주기 기준)

이전 라운드는 "채널 자신의 예약 슬롯(frames(p)개)" 기준으로 두 펄스를 간격 없이 이어 그렸다. 이번 피드백은 "duration=255면 13패킷 자극 후 남은 11패킷(=24-13)이 NOP이고 그 다음 자극"이라는 예시로, **실제 재자극까지 기다려야 하는 패킷 개수**를 명확히 그려야 한다고 지적했다. 재설계:

```
periodPackets = round(1e6 / rate_pps / 41)   // 실제 재자극 주기를 41usec 패킷 단위로 환산
```
- 펄스 1개당 예약 폭 = `periodPackets`개 패킷(실측 축척) — 그 안에서 `fixedF`개 패킷만큼만 파형을 그리고 나머지는 NOP(옅은 회색), 파형이 차지하는 마지막 지점에 점선 경계로 "자신의 패킷" vs "대기 NOP" 구분 표시.
- 펄스 2는 `periodPackets` 뒤에서 동일하게 반복.
- Python 검증: CIS(K=32,p=13)→33패킷, NofM→49패킷, CIS(K=20,p=54)→61패킷 — 모두 `fixedF` 이상이라 항상 파형이 예약 안에 들어맞음(별도 방어 코드 불필요, 물리적으로 항상 성립함을 증명).
- 극단값(K=32,p=255→약 780패킷)은 폭이 매우 넓어질 수 있어 `.pulse-scrollwrap`(가로 스크롤)으로 감쌌다 — 통상적인 설정에서는 스크롤 없이 표시됨.

## 3. 그 외 반영 내역

| 요청 | 반영 |
|---|---|
| COLA·자극 펄스 행에 채널 번호 표기 | `drawChannelLabel` 헬퍼 추가, 두 행 모두 상단에 채널 번호 텍스트 렌더링 |
| 모든 자극 펄스 그림에서 interphase gap을 별도 간격으로 띄우지 않기 | `drawBiphasicShape` 공용 헬퍼로 통일 — gap 4usec를 neg/pos에 2usec씩 흡수해 항상 붙여서 그림(메인 타임라인·2펄스 그림 공통 적용) |
| COLA·자극 펄스 행 높이를 채널·PCM 패킷 행과 동일하게 | 22px/32px → 40px로 통일 |
| 2펄스 그림을 CIS/NofM 테이블의 왼쪽 라벨이 있는 행으로 통합 | 별도 `.pulse-detail` 2컬럼 카드 제거, `#statsGrid` 안에 "자극 펄스 상세(연속 2펄스)" 라벨 행으로 직접 편입 |
| Duration 막대의 NofM 한계(54) 표시 위치를 슬라이더 썸(동그라미) 중앙에 정확히 | 커스텀 썸(16px, `::-webkit-slider-thumb`/`::-moz-range-thumb`) 적용 후 `calc(8px + 0.169421 * (100% - 16px))`로 썸 inset 보정한 위치 계산 |

## 4. 한계

여전히 브라우저 없이 정적 코드 검토 + Python 수치 재현으로만 검증했다. 커스텀 슬라이더 썸 크기(16px)는 CSS로 명시했으므로 대부분의 브라우저에서 일관되게 적용되지만, 일부 구형 브라우저의 `-moz-range-thumb` 렌더링 세부 여백까지는 실측하지 못했다.
