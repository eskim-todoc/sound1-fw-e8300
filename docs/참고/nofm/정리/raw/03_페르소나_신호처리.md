## 1. CIS 채널 출력 순서 — 일반 알고리즘

### 1.1 핵심 파라미터

- `K` : 사용 가능 채널 수 (1~32)
- `f` : `duration`(pulse width)에서 유도된 채널당 프레임 수
- `c = floor(24 / f)` : 1ms에 전송 가능한 채널 수 (24는 고정 하드웨어 상수)

### 1.2 핵심 통찰 — 닫힌 형태(O(1)) 공식

실기 로직(`stimulationStrategy.c:692-734`)을 추적하면, 전역 인덱스는 **매 ms마다 초기화되지 않고 계속 이어지며(K>c일 때)**, ms `t`(0-indexed) 시작 시점의 절대 소비량은 `t * c` 입니다. 따라서:

```
startIndex(t) = (t * c) mod K
```

이 하나의 공식으로 이전 ms를 순회 시뮬레이션할 필요 없이 임의의 t에서 바로 채널 목록을 구할 수 있습니다.

### 1.3 의사코드

```
function getCisChannelSequenceForMs(t, K, f):
    c = floor(24 / f)

    if K < c:
        # 모든 채널이 1ms 안에 다 들어가는 경우 → wrap 없음, 매 ms 동일
        return [0, 1, 2, ..., K-1]          # 나머지 (c - K) 슬롯은 무자극(NOP)

    else:  # K >= c  → wrap 분기 (K==c는 경계, 나머지 0이라 결과는 wrap 없는 것과 동일)
        start = (t * c) mod K
        return [ (start + j) mod K  for j in 0 .. c-1 ]
```

> [!NOTE]
> **검증 단계 정정**: 실제 코드 조건은 `if (K < c)`(엄격한 부등호, `stimulationStrategy.c:624`)이며, `K = c`인 경우는 else 분기(wrap 로직)를 탄다. 다만 나머지가 0이라 관찰되는 동작은 `K < c`와 동일하다. 위 의사코드는 이 정정을 반영함.

- 반환값은 0-indexed 채널 인덱스 목록. 실제 채널 번호(1-indexed) 표시가 필요하면 `+1`.

### 1.4 검증 — 문제의 예시(K=31, c=24)

공식 `startIndex(t) = (t·24) mod 31`로 계산:

| t (ms) | startIndex | 출력 채널(1-indexed) |
|---|---|---|
| 0 | 0 | 1~24 |
| 1 | 24 | 25~31, 1~17 |
| 2 | 17 | 18~31, 1~10 |

→ 문제에서 제시한 예시와 완전히 일치함을 확인했습니다.

## 2. N-of-M 채널 출력 순서 — 의사코드 (단순화 가정)

가정: 8채널 고정, Phase0/Phase1 각 8채널, 매번 동일한 16채널 풀 선택(적응형 피크 선택 없음).

이 단순화된 모델은 사실 **CIS 공식의 특수 케이스**(K=16, c=8)와 완전히 동일합니다(K/c=2, 나머지 없음 → jitter 없음).

```
function getNofMChannelSequenceForMs(t, pool16):
    # pool16: 길이 16 고정 채널 배열 (인덱스 순서 = 실제로는 크로스토크 최소화용 인터리빙 순서)
    phase = t mod 2
    start = phase * 8          # phase 0 → 0, phase 1 → 8   (= (t*8) mod 16 과 동일)
    return pool16[start : start+8]
```

> [!NOTE]
> 실제 펌웨어(`stimulationStrategy.c:66-119, 140-385`)는 이보다 훨씬 복잡합니다: Phase0마다 신호 피크 8+8개를 새로 선택(`Peak_Pick`)하고, 인접 채널 간섭을 줄이도록 재배치(`Interleaving`)하며, 직전 자극 전극과의 거리를 계산해 시작 방향(정방향/역방향)을 매 사이클 동적으로 선택(`Packet`)합니다. "동일 16채널 고정"은 문제에서 지시한 단순화 가정이며, 실제 동적 선택 알고리즘 전체 재현은 본 문서 범위 밖입니다(추가 검증 필요).

## 3. 채널별 실제 자극 rate(PPS) 일반식

### 3.1 케이스 K ≤ c (여유 있음)

모든 채널이 매 ms마다 정확히 한 번씩 출력되고 wrap이 없으므로:

```
rate = 1000 pps   (모든 채널 동일, 자극 간격 = 1ms 고정)
```

### 3.2 케이스 K > c (wrap 발생)

라운드로빈이 정확히 K칸 주기이고 ms당 c개씩 소비되므로, 특정 채널의 재자극 간격(ms)은:

```
평균 간격 = K / c  (ms)
평균 rate = 1000 × c / K   (pps)
```

단, `K/c`가 정수가 아니면 **채널별 실제 순간 간격은 완전히 균일하지 않고 `floor(K/c)`와 `ceil(K/c)` 두 값 사이를 오갑니다** (전체 평균은 K/c로 수렴). `K/c`가 정수로 나누어 떨어지면(예: K=32,c=8→4) 모든 채널이 정확히 균일한 간격으로 자극됩니다.

> [!WARNING]
> "몇 개 채널이 floor(K/c) 간격을, 몇 개가 ceil(K/c) 간격을 갖는가"의 정확한 조합적 분포까지는 검증하지 않았습니다 — **추가 검증 필요**. 위 두 값 범위와 평균값(K/c, rate=1000c/K)은 소스 로직으로 직접 도출·검증되었습니다.

## 4. duration(=f) 증가에 따른 c·rate 변화표

| f | c | K=32 rate(pps) | K=32 간격(ms) | K=24 rate(pps) | K=24 간격(ms) | K=16 rate(pps) | K=16 간격(ms) |
|---|---|---|---|---|---|---|---|
| 1 | 24 | 750.0 | 1~2 (avg 1.33) | 1000.0 | 1 (고정, K=c) | 1000.0 | 1 (고정, K<c) |
| 2 | 12 | 375.0 | 2~3 (avg 2.67) | 500.0 | 2 (고정) | 750.0 | 1~2 (avg 1.33) |
| 3 | 8  | 250.0 | 4 (고정) | 333.3 | 3 (고정) | 500.0 | 2 (고정) |
| 4 | 6  | 187.5 | 5~6 (avg 5.33) | 250.0 | 4 (고정) | 375.0 | 2~3 (avg 2.67) |
| 5 | 4  | 125.0 | 8 (고정) | 166.7 | 6 (고정) | 250.0 | 4 (고정) |

## 확실하지 않아 추가 검증이 필요한 부분

1. **pulse width → f 변환의 단위**: `pulsewidth` 인자가 이미 usec 단위인지 명시적 주석 확인 불가.
2. **K>c 케이스의 간격 분포 정확한 조합**: 평균값·범위만 검증, 세부 분포는 미검증.
3. **N-of-M 실제(비단순화) 채널 선택 알고리즘**: peak-pick·인터리빙 파라미터는 검증 범위 밖.
