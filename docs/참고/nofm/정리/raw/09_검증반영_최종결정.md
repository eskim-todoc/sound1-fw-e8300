## TL;DR

페르소나 분석(03~07)과 검증 리포트(08)에서 나온 모든 수치를 대조해, 실제 HTML/JS 구현에 쓸 **최종 확정 공식·상수·임계값**을 이 문서 하나로 정리한다. 이후 구현·검증 단계는 이 문서를 단일 근거로 삼는다.

## 2. 핵심 공식 (JS 구현 대상)

```js
// pulsewidth p(usec) → 채널당 필요 PCM 프레임 수
function frames(p) {
  const raw = 2 * p + 14;
  return Math.floor(raw / 41) + 1;
}

// 프레임 수 f → 1ms당 전송 가능 채널 수 (CIS)
function channelsPerMs(f) {
  return Math.floor(24 / f);
}

// CIS: 절대 ms 시점 t에 출력되는 채널 인덱스 배열(0-indexed)
function cisChannelsForMs(t, K, f) {
  const c = channelsPerMs(f);
  if (K < c) {
    return Array.from({length: K}, (_, i) => i); // 정적, wrap 없음, 나머지 (c-K) 슬롯그룹 NOP
  }
  const start = (t * c) % K;
  return Array.from({length: c}, (_, j) => (start + j) % K); // wrap 발생 (K===c 경계 포함)
}

// NofM: CIS 공식의 특수케이스 (K=16 고정, f=3 고정, c=8 고정) — 항상 성립
function nofmChannelsForMs(t, pool16 /* length-16 고정 배열 */) {
  const start = (t * 8) % 16;   // phase 0→0, phase 1→8
  return [pool16[start % 16], ...Array.from({length: 7}, (_, j) => pool16[(start + j + 1) % 16])];
}

// PCM 슬롯 레벨 idle (usec/ms) — CIS/NofM 공통 일반식
function idleUsecPerMs(K, f, c) {
  const used = Math.min(K, c) * f;   // NofM은 K=16,f=3,c=8 대입 시 8*3=24 → idle=0 항상
  return (24 - used) * 41;
}

// 채널당 평균 자극 rate(PPS) — CIS 일반식, NofM은 K=16,c=8 대입 시 500으로 자동 도출됨
function averageRatePps(K, c) {
  return K <= c ? 1000 : 1000 * c / K;
}
```

- **NofM 유효 조건**: `K(=M) >= 16`. `K < 16`(15 이하)이면 NofM 비활성 → CIS만 표시.
  - ⚠ 참고: 사용자 원본 요구사항(`기반 지식 정보.md`)은 "M이 16 이하면 CIS를 사용한다"고 서술했으나, 실제 코드(`numFrequencyBand < 16`)는 **M=16을 정상 NofM 동작값으로 허용**한다. 둘이 모순되는 것은 아니다 — M=16일 때 NofM(K=16,c=8)은 수학적으로 CIS(K=16,f=3)와 완전히 동일한 결과를 내므로(신호처리 페르소나 §2 검증), "M=16이면 사실상 CIS와 같아 구분 실익이 없다"는 사용자의 실용적 안내이지, 펌웨어가 M=16에서 NofM을 거부한다는 뜻은 아니다. **구현은 코드 기준(M≥16 허용)을 따르되, M=16에서는 "NofM=CIS와 동일 결과" 안내 문구를 표시한다.**
- **COLA 전송시간(추정, 코드 미검증)**: `COLA(p) = 2p + 7` usec — biphasic 파형 시각화(행 d)에만 참고용으로 사용, 반드시 "추정치" 라벨 병기.

## 3. NofM 3프레임 예산 초과 경고 임계값 (검증 확정)

- **채택**: `pulsewidth <= 54usec` 안전, `pulsewidth >= 55usec`부터 실제 필요 프레임이 4개 이상으로 3프레임 고정 예산(123usec)을 초과 — **코드의 `frames(p)` 계단함수로 직접 검증된 값**이므로 이것을 게이팅 기준으로 채택.
- **폐기(각주 처리만)**: COLA(p) 기준 58usec — 미검증 추정식에서 나온 값이라 게이팅 기준으로 부적합(검증리포트 §4).
- UX 배너 2단계: 48~54usec "임박"(노랑), 55usec 이상 "초과"(빨강).

## 4. IDLE 지표 — 라벨 분리 원칙 (UI 이슈 #7 반영)

이번 구현에서 IDLE은 **PCM 슬롯 레벨 단 하나만** 사용한다(위 §2 `idleUsecPerMs`). "채널 선택 레벨 유휴"라는 별도 지표는 만들지 않는다 — NofM의 채널 선택은 이번 시각화에서 "항상 동일 16채널 고정" 가정(요구사항 원문)이므로 애초에 해당 지표가 의미를 갖지 않는다. UI 스케치의 "NofM 51%" 같은 예시 수치는 채택하지 않으며, **NofM은 유효 조건 충족 시 PCM 슬롯 레벨 idle이 항상 0%**로 표시되어야 한다(코드 검증 사실).

## 5. 구현 우선순위 (범위 확정)

1. 컨트롤: 채널 수 K(1~32), duration/pulsewidth(13~255usec), 표시 ms 구간, CIS/NofM 동시비교.
2. CIS/NofM 각각 4행 타임라인: (a) 채널 시퀀스 (b) PCM 슬롯 그리드 (c) COLA 활성구간(추정치 라벨) (d) biphasic 파형 축약 아이콘.
3. 요약 통계 카드: 프레임 수, 채널/ms, PPS, idle(usec/%), CIS↔NofM idle 비교.
4. 경고 배너: duration 48~54(주의)/55+(초과), M<16(NofM 비활성), M=16(NofM=CIS 동일 안내).
5. 색상: CIS=blue, NofM=teal/aqua, idle=중립 회색(별도 색상축 아님). 라이트/다크 지원.
6. 단일 HTML 파일, 외부 의존성 없음(순수 HTML+CSS+JS).
