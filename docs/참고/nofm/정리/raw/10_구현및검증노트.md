## TL;DR

`docs/참고/nofm/정리/nofm-output-pattern-viewer.html`(단일 파일, 외부 의존성 없음)을 구현했다. 핵심 공식은 Python으로 재현해 JPG 예시·검증리포트(08) 임계값과 전부 일치 확인했다. **단, 이 세션에는 브라우저·Node.js가 없어 실제 렌더링/상호작용은 직접 열어보지 못했다** — 코드 리뷰 + 수치 교차검증만 수행했으니, 은수님이 브라우저로 직접 열어 확인해 주시기 바란다.

## 1. 구현 범위

- 컨트롤: 채널 수 K(1~32), duration/p(13~255usec), 표시 구간(5/10/20/50ms), 슬롯 폭(줌 3~16px). 슬라이더↔숫자입력 양방향 동기화.
- CIS/NofM 각 4행 타임라인(캔버스 기반): (a) 채널 시퀀스 (b) PCM 슬롯 그리드 (c) COLA 활성구간(추정) (d) biphasic 펄스 파형.
- 요약 통계: 프레임 수·1ms당 채널·PPS·IDLE(usec/%) — CIS/NofM 2열 비교.
- 경고 배너: K<16(NofM 비활성) / p≥55(초과, 빨강) / p 48~54(임박, 노랑) / K=16(NofM=CIS 동일, 안내).
- 다크모드 토글(localStorage 저장) + OS `prefers-color-scheme` 초기값 반영.
- 슬롯/채널 hover 툴팁(ms·slot·채널·frame 정보).

## 2. 핵심 구현 결정 (09_검증반영_최종결정.md 대비)

- CIS 채널 시퀀스: `K<c`는 정적 배열, 그 외(`K>=c`, 등호 포함)는 `startIndex(t)=(t*c)%K` wrap 공식 — 검증리포트 §1.1의 K<c 엄격부등호 정정을 그대로 반영.
- NofM: f=3·c=8 고정, `startIndex(t)=(t*8)%16` — CIS 공식의 특수사례와 동일 로직 재사용.
- IDLE: PCM 슬롯 레벨 단일 지표 `idleUsecPerMs(K,f,c)=(24-min(K,c)*f)*41` — UI 이슈 #7 반영, "채널 선택 레벨" 별도 지표는 만들지 않음.
- NofM 3프레임 초과 경고: **`frames(p) > f` (f=3)** 단일 기준으로 통일해 배너·(c)행·(d)행 모두 일관되게 판정하도록 구현 중 자체 발견한 불일치를 수정했다 — 처음엔 (c)행은 `cola(p)>groupBudget`, (d)행은 `2p+4>groupBudget`로 각각 다른 기준을 썼는데, 검증리포트가 확정한 유일한 게이팅 기준(계단함수, p≥55)과 어긋날 수 있어 `groupOverflow(p,f)=frames(p)>f`로 통일했다.
- NofM 유효조건: `K>=16`(코드 기준, UX 이슈 #8 반영 — 원 요구사항 문서의 "M≥17" 표현은 채택하지 않음).
- COLA(c행)·펄스 파형(d행)은 "추정치" 라벨을 배너·footer에 명시.

## 3. 수치 검증 (Python 재현, 브라우저 없이 로직만 검증)

Python으로 JS 핵심 함수(`frames`, `channelsPerMs`, `idleUsecPerMs`, `averageRatePps`, `cisChannelsForMs`)를 동일 로직으로 재현해 확인:

| 항목 | 결과 |
|---|---|
| `frames(13,14,16,33,54,55)` | `1,2,2,2,3,4` — JPG·검증리포트와 완전 일치 |
| CIS K=31 wrap 시퀀스(t=0,1,2) | `1~24` / `25~31,1~17` / `18~31,1~10` — 검증리포트 §1.1과 완전 일치 |
| IDLE: K=32,f=1·f=2 | 0usec (완전 패킹) |
| IDLE: NofM(K=16,f=3,c=8) | 0usec (항상, 검증리포트 §UI-7 기대와 일치) |
| IDLE: K=32,f=5(패킹 나머지 케이스) | 164usec/ms(16.4%) — 24 mod 5=4 슬롯 낭비 정상 반영 |
| rate: K=32/24/16, c=24 | 750 / 1000 / 1000 pps |
| NofM 초과 임계 | `frames(54)=3`(안전), `frames(55)=4`(초과) — 배너 임계값과 일치 |

⚠ **부수 발견**: 사용자 원본 `기반 지식 정보.md`의 K=31 예시 문장("18~31채널+1~14채널, ...")은 채널 수 합이 28개로 24를 초과해 자체 모순이 있다(정확히는 "18~31+1~10"이어야 24개로 맞음). 검증리포트(08)의 신호처리 페르소나가 소스 코드(`stimulationStrategy.c`)에서 독립적으로 재유도한 값도 "18~31,1~10"으로 이 구현과 일치한다 — 즉 **원본 문서의 해당 예시 문장에 오탈자가 있는 것으로 보이며, 구현은 코드 검증된 값을 따랐다.** 원본 문서 자체는 수정하지 않았다(은수님의 작업 메모이므로).

## 4. 알려진 한계

- **브라우저 미실행**: 이 세션 환경에는 Node.js·브라우저가 없어 실제 렌더링·인터랙션(슬라이더 반응, 캔버스 드로잉, 다크모드, 툴팁)을 직접 눈으로 확인하지 못했다. 수행한 것은 (1) JS 괄호/태그 balance 정적 검사 (2) HTML id 참조 무결성 검사 (3) 핵심 계산 로직의 Python 재현 검증뿐이다. **은수님이 브라우저로 직접 열어 골든 패스(기본값 32ch/13usec)와 엣지 케이스(K=15/16/17, p=54/55, p=255)를 확인해 주시기를 권장한다.**
- COLA(c행) 활성구간의 슬롯 내 정확한 오프셋(프레임 시작과 동시 시작인지 등)은 미검증 — 05 문서 §추가 검증 필요 참조, 이번 구현은 "그룹 시작점부터"로 단순 가정했다.
- 표(WCAG 대체 뷰) 토글은 UI 페르소나가 제안했으나 이번 구현 범위에서는 생략했다(시간 제약) — 필요 시 후속 추가 가능.
