# E8300 PCM↔COLA 타이밍 모델 스펙 (웹 시각화용)

> 페르소나: 임베디드 실시간 프로토콜/타이밍 엔지니어
> 근거: `stimulationParaCal.c`, `FPGA_ver2_8_0.h`, `dirver_PCM.h`, `definitionsForAlgorithm.h`, `stimulationStrategy.c` (모두 코드 검증됨). COLA 전송시간 추정식만 사용자 제공 도메인 지식(코드 미검증).

## 1. PCM 프레임 그리드 정의

### 1.1 상수 (코드 검증)

| 상수 | 값 | 출처 |
|---|---|---|
| `FPGA_oneChannelDataTokenTime` | 41 (usec) | `FPGA_ver2_8_0.h:145` — 주석 "41.66usec ... 1ms 동안 24채널" |
| `df_MaxNumTransferableChannel` | 24 | `definitionsForAlgorithm.h:61` |
| `FPGA_interphaseGapTokenTime` | 4 | `FPGA_ver2_8_0.h:147` |
| `FPGA_electrodAndStimulLevelTokenTime` | 10 | `FPGA_ver2_8_0.h:146` |
| `FPGA_pulsePhaseWidth_minimum` | 13 | `FPGA_ver2_8_0.h:148` |

> [!WARNING]
> **1ms 그리드 잔여 시간 불일치(추가 검증 필요)**: 주석은 41.66usec를 명시하지만 매크로는 정수 `41`. `24×41=984usec`, `1000-984=16usec/ms`가 소프트웨어 정수 연산에서는 설명되지 않음. FPGA 하드웨어 클럭이 실제로는 41.666...usec 단위로 동작하고, 펌웨어 정수 매크로 41은 근사치일 가능성. 웹페이지 1ms 그리드를 24×41usec로 그리면 우측에 16usec의 "미배정 잔여" 구간이 남는다는 점을 시각적으로 드러내거나 각주 권고.

### 1.2 슬롯 경계

```
slot i (i=0..23): t ∈ [i×41, (i+1)×41) usec (ms 시작 기준 상대시각)
slotStartUs(i) = i×41,  slotEndUs(i) = (i+1)×41
(984~1000usec: §1.1 미설명 잔여 16usec — 코드상 슬롯 아님)
```

### 1.3 FIFO 연속 전송 방식 (코드 검증)

`dirver_PCM.h`에 정의된 필러 패턴:
- `pcm_Mold_NopStandby = 0x25555` (16bit, 대기 상태 필러)
- `pcm_Mold_NopBacktel = 0x35555` (16bit, 백텔레메트리 상태 필러)
- `pcm_Mold_Stimulation = 0x40000` (실 자극 데이터: 선행펄스모양 1bit + 전극번호 5bit + 자극크기 8bit)

FIFO는 매 슬롯(41usec)마다 "실 채널 데이터" 또는 "NOP 필러" 중 하나로 24슬롯/ms를 끊김 없이 연속 전송 — 슬롯이 물리적으로 "비어있는" 시간은 없고 항상 어떤 토큰이 점유한다.

## 2. COLA 전송시간 추정식 유도 및 검산

> [!CAUTION]
> **이 절의 `COLA(p)` 공식은 코드로 검증되지 않은 추정식이다.** 소스 코드 어디에도 "COLA" 심볼이 존재하지 않는다(`grep -rn "COLA" src/` 결과 0건, 검증 단계에서 재확인). 실측 전까지 웹페이지에는 "추정치" 라벨 필수 병기.

### 2.1 유도

```
COLA(p) = 33 + 2×(p-13) = 2p+7   [p>=13, usec]  (도메인 지식 기반)
```

### 2.2 코드 검증된 `duration` 식과의 관계

```
duration_code(p) = 2p + 14   [usec]  (calculationNumFramePerOneChannle, 코드 검증)
```

`COLA(p)=2p+7`은 `duration_code(p)=2p+14`보다 항상 정확히 7usec 작다(구조적 일관성은 있으나 정확한 이유는 미확인).

### 2.3 프레임 수 스텝 함수 (코드 검증)

`numFramePerChannel = floor(duration/41)+1`과 동치. f=1~4 구간 전부에서 `COLA(p) ≤ f×41`이 8~9usec 여유로 성립(검산표 생략, 원본 참조).

## 3. IDLE 시간 정의 — 두 후보 비교

### (a) PCM 슬롯 레벨 idle (코드 검증 가능, 1차 권장)

```
idle_slot(ms) = (24 - Σ_channel frameNumPerChannel(channel)) × 41 usec
```

NofM은 `3×8=24`, 나머지 0 — **NofM 정상 동작 시 슬롯 레벨 idle은 항상 0**(코드 검증).

### (b) COLA 레벨 idle (§2 추정식 의존, 코드 미검증)

슬롯이 배정되어도 실제 COLA 전송이 41usec 전부를 쓰지 않고 남는 시간의 누적. 다중 프레임 채널에서 이 잔여가 마지막 프레임에 몰리는지 분산되는지는 소스로 확인 불가.

### 권고

주력은 (a)(코드 100% 검증), (b)는 시각적으로 구분(점선 테두리·회색조·"추정치·코드 미검증" 툴팁)하여 부가 정보로만 제공.

## 5. NofM 3프레임 고정 시 pulsewidth 임계값 — 두 기준 비교 (⚠ 최종 채택은 §09 참조)

3슬롯 예산 = `3×41=123usec`.

- **기준 A (COLA 기준)**: `COLA(p)≤123` → `2p+7≤123` → **p≤58**
- **기준 B (프레임수 계단함수 기준)**: `duration_code(p)<123` → `2p+14<123` → **p≤54** (p=55부터 4프레임 필요)

> [!CAUTION]
> 원 문서는 "기준 A(58usec)가 더 정확하다"고 판단했으나, **검증 단계에서 이 판단은 기각됨**. 실제로 코드가 강제하는 것은 계단함수(기준 B)뿐이며, `COLA(p)` 자체가 미검증 추정식이므로 "A가 더 정확"이라는 서열화는 근거가 없다. **웹페이지 게이팅 기준은 54usec(안전 상한)/55usec(초과 시작)를 채택**하고, 58usec(COLA 기준)는 참고 각주로만 유지한다.

## 추가 검증 필요 항목 총괄

1. 1ms=984usec vs 실제 1000usec의 16usec/ms 잔여 — FPGA 하드웨어 실측 필요
2. `COLA(p)=2p+7` 자체 — 오실로스코프/로직 애널라이저 실측 필요
3. 다중 프레임 채널의 COLA idle 시간이 마지막 프레임에 몰리는지 분산되는지 — 소스로 확인 불가
4. 슬롯 내 `colaActiveStartUs` 오프셋 — 소스로 확인 불가
5. NofM에서 pulsewidth>54usec일 때 실제 초과 여부 — 실측 검증 필요
