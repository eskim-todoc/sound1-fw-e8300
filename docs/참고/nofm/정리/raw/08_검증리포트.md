# 검증 리포트 — CIS/NofM 자극 출력 패턴 & PCM/COLA 타이밍 5건 전문가 분석 교차검증

> 검증 방법: 5건 문서가 인용한 모든 파일:라인 근거를 실제 소스에서 직접 Read/grep으로 재확인. 근거 문서가 `undefined`로 누락되어 있었으므로, 실제 저장소 코드를 1차 ground truth로 사용.

## 1. 문서별 근거 문서 모순 여부

### 1.1 [신호처리] 페르소나

- CIS 닫힌형 공식 `startIndex(t)=(t·c) mod K`: 코드 직접 추적·시뮬레이션 결과 **정확히 일치**. CONFIRMED.
- `c=floor(24/f)` 및 duration→c→rate 표: 전부 재계산 결과 일치. CONFIRMED.
- **ISSUE**: §1.3 "K≤c 분기가 line674 리셋에 대응" 서술이 §4.4 각주("K=c는 실제로 else/wrap 분기를 탐")와 자기모순. 실제 코드 조건은 `if (K<c)`(엄격 부등호). → §1.3을 "K<c(엄격)만 리셋 로직, K=c는 wrap분기를 타지만 나머지 0이라 우연히 동일 관찰"로 정정.
- **ISSUE**: 근거표의 `df_MaxNumTransferableChannel:137`, `df_MaxNumOfElectrode:143` 인용 — 실제 CM3측 파일(`2__cm3/signalProcessing/definitionsForAlgorithm.h`, 104줄)에는 없는 줄번호이며, 1__cfx측 파일(176줄)의 줄번호를 혼용 인용. 값(24,32) 자체는 맞으나 추적 근거가 틀림. → `2__cm3/signalProcessing/definitionsForAlgorithm.h:61`(24), `:68`(32)로 정정.

### 1.2 [전기자극] 페르소나

- 음상선행 디폴트, 전하량 계산, `Df_MaxDeliveryChargeLimitationKKK` 매크로명 불일치, NofM 3프레임 강제, pulsewidth 검사 독립성 — 전 항목 재확인 결과 실제 코드와 정확히 일치. **CONFIRMED, 5건 중 근거 충실도 최고.**

### 1.3 [임베디드타이밍] 페르소나

- FPGA 상수 4종·`df_MaxNumTransferableChannel` 등 인용 — 5건 중 가장 정밀한 줄번호 인용. CONFIRMED.
- 1ms=984usec vs 16usec 잔여 지적 — 산술 정확, hedge 적절. CONFIRMED.
- **ISSUE**: §5 "기준 A(COLA 58usec)가 기준 B(계단함수 54usec)보다 더 정확하다"는 결론 — 아래 §4에서 상세 기각.

### 1.4 [UI] 페르소나

- **ISSUE (설계 모호성, PLAUSIBLE)**: KPI 예시("유휴 슬롯 12/ms(25%)", "CIS 25%/NofM 51%")가 "유휴 슬롯"이라는 동일 라벨 아래 PCM 슬롯 레벨(NofM=항상 0, 코드 검증)과 채널 레벨(가변) 두 지표를 구분 없이 예시화 — 구현 시 "NofM도 duration에 따라 PCM idle이 변한다"는 잘못된 인상 위험.

### 1.5 [UX] 페르소나

- 핵심 임계값(duration=55usec) — 코드 계단함수 기준과 정확히 일치. CONFIRMED.
- **ISSUE (확정)**: "NofM 유효조건: M≥17(M≤16이면 CIS만 사용)" — 실제 코드(`stimulationParaCal.c:591`)는 `numFrequencyBand<16`(16 미만)일 때만 비활성. 즉 **M=16은 정상 NofM 작동값**이며 올바른 경계는 "M≥16 가능/M≤15 CIS 폴백". off-by-one 오류가 §0표·§5.1 본문·인라인 카피·템플릿D 전체에 일관 반복됨. [전기자극] 문서(§4.1, "numFrequencyBand<16이면 에러")가 정확히 서술해 교차검증으로도 UX 문서가 틀렸음이 뒷받침됨. → "M≥16"/"M≤15"로 전체 일괄 정정.

## 2. 코드 미검증 수치를 코드검증인 것처럼 서술한 부분

- `COLA(p)=33+2×(p-13)=2p+7`: [임베디드타이밍] 문서가 매 절마다 "코드 미검증·도메인 추정식"임을 명시(hallucination 아님, 정직한 라벨링).
- 다만 §5 최종 판단문장("기준 A가 더 정확")은 미검증 추정식에서 나온 숫자를 코드 검증 가능한 계단함수 기준보다 "더 정확하다"고 서열화한 것으로, 검증 가능성의 방향이 뒤바뀐 판단 — 근거 없음.
- [전기자극]의 "500pps"는 코드 리터럴로 직접 못 찾았다고 정직히 hedge했으나, 검증 단계에서 `stimulationStrategy.c`의 mod-16 wrap 로직(8채널/ms, 2ms에 1주기)으로 500pps가 **코드로 도출 가능**함을 확인 — UX/UI가 "500 고정"이라 단정한 것은 결과적으로 옳음. 전기자극 문서의 과잉 hedge는 사소한 보수적 오류.

## 4. 'NofM 3프레임 예산 초과 임계값' 재계산 검증 (핵심)

```
raw = 2×pulsewidth + 14
frames(pulsewidth) = floor(raw/41) + 1
3프레임 유지조건: raw < 123 → 2p+14 < 123 → p < 54.5 → p ≤ 54
p=54: raw=122 → frames=3(유지).  p=55: raw=124 → frames=4(초과 시작)
```

| 문서 | 제시 임계값 | 판정 |
|---|---|---|
| 전기자극 | pulseWidth≥약55µs | **일치(정확)** |
| UX | duration=55usec | **일치(정확, 계산과정까지 동일)** |
| 임베디드타이밍 기준B | p≤54 | **일치(정확)** — 그러나 문서는 이를 최종 채택하지 않음 |
| 임베디드타이밍 기준A | COLA(p)=2p+7≤123 → p≤58 | **불일치** — 코드 계단함수와 무관한 미검증 추정식 |

**판정**: 웹페이지 경고 기준은 **pulsewidth=55usec(초과 시작)/54usec(안전 상한)**을 채택한다. `COLA(p)` 추정식(58usec)은 (1) 코드에 "COLA" 심볼 자체가 0건, (2) 실측 검증 없음, (3) 55~58usec 구간에서 웹페이지가 "정상"으로 오판(false-negative, 더 위험한 방향)할 수 있어 게이팅 기준으로 부적합. 각주로만 유지.
