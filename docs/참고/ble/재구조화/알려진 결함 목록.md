# BLE 알려진 결함 목록

**TL;DR**: 2026-07-27 구조 분석에서 13건을 기록했고 그중 **1건(0x90)은 결함이 아닌 의도된 설계로 판명돼 취소**했다. 남은 것은 **기능 미동작 1건**(0x51·0x53·0x58 핸들러 부재), **자극 정지 관련 조사 대상 1건**(라이브 재진입 가드), 나머지는 로그·주석·이론적 위험이다. **구조 리팩토링과 섞지 말고 별도 트랙으로 처리**해야 한다 - 섞으면 회귀인지 원래 결함인지 구분할 수 없다.

> [!IMPORTANT]
> 이 목록은 **기록이며 조치는 아직 이뤄지지 않았다.** 발견 경위는 [`docs/tasks/ble/20260727_ble-protocol-restructure/분석.md §7`](../../../tasks/ble/20260727_ble-protocol-restructure/분석.md).

## 1. 심각도 분류

| 심각도 | 정의 | 건수 |
|---|---|---|
| **중** | 기능이 실제로 동작하지 않는다 | 1 (결함_2) |
| **조사 필요** | 안전에 관련되나 실위험도 미정량 | 1 (결함_4) |
| 낮 | 로그·주석·이론적 위험. 기능 영향 없거나 미미 | 9 |
| 정보 | 참고용 | 1 |
| **취소** | 결함이 아님으로 판명 | 1 (결함_1) |

> [!CAUTION]
> **분류 오류에서 얻은 교훈**: "핸들러가 없다"는 코드 사실과 "그것이 결함이다"라는 해석은 별개다. 서브에이전트 3개가 독립적으로 "0x90 핸들러 없음"을 확인했지만 그 **사실은 맞고 해석이 틀렸다**. 문서화된 설계 결정(`cm3-소스-트리-규약.md`)을 먼저 확인해야 한다.

## 2. 결함 상세

### 결함_1 - **취소.** 0x90 은 결함이 아니라 의도된 미지원

> [!NOTE]
> **최초 분류 오류를 정정한다.** 0x90 의 핸들러 부재를 결함으로 분류했으나, [`cm3-소스-트리-규약.md:41`](../../cm3-소스-트리-규약.md) 이 이를 **2026-07-27 2차 리팩토링의 확정 결정**으로 이미 기록하고 있다 - "`en__mapping_testStimulation`**(핸들러는 제거)**과 `ST__MAPPINGPAYLOAD_TEST_STIMULATION` 도 남겼다".
>
> 즉 **핸들러를 의도적으로 제거하고 프로토콜 정의만 존치**한 것이며, 설계대로 동작하고 있다.

**현재 동작 (참고용 기록)**

디스패처는 0x90 을 매핑 핸들러로 명시 라우팅하고(`tdc_ble_communication.c:306`), `fetch_packet` 에 case 가 없으므로 `default` 로 낙하해 `en__UndefinedCommand` 에러를 응답한다.

라우팅이 남아 있는 덕분에 **앱은 무응답 타임아웃 대신 명확한 에러 응답을 받는다.** 이는 결함_2(0x51·0x53·0x58 의 무응답)와 성격이 정반대다.

전용 페이로드 구조체 `ST__MAPPINGPAYLOAD_TEST_STIMULATION`(`tdc_ble_mapping.h:92-107`)은 미사용이나 **규약 §2.1 에 따라 존치 대상**이다.

**조치**: 불필요. 현상 유지.

### 결함_2 - 리모콘 0x51·0x53·0x58 핸들러 부재 (중)

| 헤더 | 열거값 |
|---|---|
| 0x51 | `en__remoteControl_read_OwnerNameOfExternalDevice` |
| 0x53 | `en__remoteControl_read_NRF_FirmwareInfo` |
| 0x58 | `en__remoteControl_readSystemErrorCode` |

`case` 문이 없어 명령이 처리되지 않는다. `tdc_ble_protocol.h:75` 주석이 이미 이 증상을 증언하고 있다 - "실제 사용되고 있나? 이거 보내면 묵묵 부답으로 시간 초과 타임아웃 발생함".

**조치 방향**: 실제 사용 여부 확인 후 핸들러 구현 또는 미지원 명문화.

### 결함_4 - 라이브 재진입 가드가 Stop 을 거부 (조사 필요, 안전 관련)

`tdc_ble_mapping.c:89-112` 의 재진입 가드는 아래 **두 조건이 동시에 성립**할 때 명령을 거부한다.

1. `mappingPacket.command != en__mapping_IDLE` (이전 명령 미완료)
2. 현재 라이브 서브상태가 `en__HoldOn` 도 `en__Standby` 도 아님

이때 0x61(연결 해제)만 예외로 통과하고, **`en__Stop`(서브커맨드 8)을 포함한 나머지 0x66 패킷은 전부 거부**되며 `en__PreviouCommnadIsNotCompleted` 에러가 나간다.

> [!WARNING]
> **정확한 표현은 "정지 명령이 안 먹는다"가 아니라 "상태 전이 구간에서는 정지 명령이 거부될 수 있다"이다.**
>
> 정상 라이브 운용 중에는 서브상태가 `HoldOn` 이므로(볼륨·감도·알람이 HoldOn 에서만 수락되는 것이 방증) Stop 이 정상 동작한다. 위험 창은 `allParameter` 수신 중 · `Start` 계산 중 · 알람 펄스 진행 중 같은 **전이 구간**에 한정된다.
>
> **위험 창의 실제 지속 시간은 아직 정량화되지 않았다.**

**조치 방향**: **위험 창 길이 정량화가 선행**되어야 한다. 그 뒤 가드 조건에 `en__Stop` 예외를 추가할지 검토한다. 단 재진입 가드는 명령 충돌을 막는 장치이므로 **예외를 늘리면 보호가 약해진다** - 정량화 없이 손대지 않는다.

### 결함_3 - RX 로그가 배열 범위 밖을 읽음 (낮)

디버그 로그(`tdc_ble_communication.c:282`)가 `p_Rx_dataPacket[20]` 을 출력하는데, `Rx_DataPacket` 은 20원소 배열이다(`tdc_hal_spi.c:22`, `BLE_DataPacketSize`=20). 인덱스 20 은 범위 밖이다.

**기능 영향은 없다** - 프로토콜 파싱은 `[0..19]` 만 사용하고, DMA 복사 루프도 `i < BLE_DataPacketSize` 로 정확하다(`tdc_hal_spi.c:159-162`). 범위 밖 **쓰기는 없다.**

**영향은 로그 해석에 한정**된다. 전 로그에서 이 값이 `01` 로 고정 출력되는데, 이는 수신 데이터가 아니라 인접 정적 변수를 읽은 것이다.

**조치 방향**: 로그 출력에서 `[20]` 접근 제거.

### 결함_5 - 0x64 가 명령을 수락하고 아무 동작도 안 함 (낮)

`en__mapping_eCAP_Measurement_alternative`(0x64) 는 `step` 의 case 에 도달하지만 실행부가 주석 처리돼 있다(`tdc_ble_mapping.c:1933`). 카운터만 리셋하고 끝난다.

**조치 방향**: 미지원 명문화 또는 구현.

### 결함_6 - 도달 불가 분기 (낮)

리모콘 0x57 핸들러(`tdc_ble_remote.c:1157-1164`)가 매핑 0x71 핸들러의 죽은 조건부 블록을 복사해 왔는데, 상수 대입만 바뀌면서 `if` 분기가 영구 도달 불가능해졌다.

### 결함_7 - 채워지지 않는 반환 구조체 (낮)

`tdc_ble_remote_step()` 이 반환하는 `ST__REMOTECONTROL_STATE` 의 필드가 한 번도 채워지지 않고 항상 초기값으로 반환된다. `tdc_ble_communication.c:432` 주석이 이를 의도된 상태로 문서화하고 있다(매핑의 대응 구조체는 실제로 채워짐).

### 결함_8 - 명령 유실 가능성 (낮)

`Rx_DataPacket` 은 큐가 아닌 단일 버퍼이고, `DMA0_IRQHandler` 가 소비 여부를 확인하지 않고 덮어쓴다(`tdc_hal_spi.c:159-164`). 한 tick 사이에 SPI 수신이 2회 이상 발생하면 앞 패킷이 조용히 유실된다.

**실제 발생 여부는 미확인**이다. 실측 로그 7종에서는 재현되지 않았다.

### 결함_9 - static 포인터 NULL 역참조 가능성 (낮)

`p_Rx_dataPacket` 은 static 포인터다(`tdc_ble_communication.c:235`). 최초 FETCH 이전(부팅 직후)에는 이 포인터가 NULL 인 채로 `:450` 에서 역참조된다.

**실제 하드폴트 발생 여부는 미확인**이다.

### 결함_10 - 주석-코드 불일치 (낮)

`en__mapping_recover_mppingData_exceptSlot_1`(0x70) 의 "헤더 only 패킷" 주석과 달리, 실제 코드는 2바이트를 더 읽는다.

### 결함_11 - 이름-동작 불일치 (낮)

라이브 서브커맨드 4 는 이름이 `en__MicSensitivityAdjust`(마이크 감도)인데 실제로는 `tdc_shm_change_audio_volume()`(오디오 볼륨)을 호출한다.

### 결함_12 - 응답 형식 비일관 (낮)

매핑군(0x60~0x67)은 헤더 에코 관례를 따르지만, 0x30 응답은 헤더를 생략하고 페이로드부터 쓴다.

### 결함_13 - TX 로그 부호확장 (정보)

TX 디버그 로그에 `FFFFFFxx` 로 표기되는 값이 있다. `char -> int` 부호 확장 + 출력 마스킹(`& 0xFF`) 누락이 원인이다(RX 에러 덤프에는 마스킹이 있다). **기능 영향은 미확인.**
