# BLE 프로토콜 참고

**TL;DR**: CM3 가 처리하는 BLE 명령 63개와 21바이트 SPI 패킷 규약을 정리한 레퍼런스 2종이다. 명령 헤더값을 조회하거나 새 명령을 추가하기 전, 또는 패킷 바이트 하나의 의미를 확인해야 할 때 코드를 다시 훑기 전에 먼저 여기를 본다.

## 파일

| 파일 | 목적 | 언제 쓰는가 |
|---|---|---|
| [`명령 카탈로그.md`](명령%20카탈로그.md) | CM3 가 아는 모든 BLE 명령 헤더값의 단일 출처(SSOT). 그룹 체계, 정의 위치, 처리 핸들러, 헤더 주석 검증 이력 | 특정 헤더값이 무엇을 하는지, 어느 파일·라인이 처리하는지 확인할 때. 새 헤더값을 배정하기 전 충돌 여부를 확인할 때. 핸들러 없는 명령(0x51·0x53·0x58·0x90)의 실제 동작을 확인할 때 |
| [`패킷 구조와 응답 규약.md`](패킷%20구조와%20응답%20규약.md) | 21바이트 SPI 패킷의 바이트 레이아웃, `[20]` 바이트의 진실(TX=길이 확정, RX=미확인), 데이터 인덱스 분할 전송 목록, 정상/에러 응답 규약(0xF0 경로와 매핑 default 경로의 공존) | 패킷 바이트 하나를 어떻게 해석해야 하는지 헷갈릴 때. RTT 로그의 `[SPI RX]`/`[SPI TX]` 마지막 바이트를 프로토콜 데이터로 오해하기 전에. 에러 응답 포맷을 새로 만들거나 파싱할 때 |

## 원본 정의와 근거 자료

- `src/2__cm3/source/ble/tdc_ble_protocol.h` — 모든 명령 헤더·페이로드 크기 상수의 원본. 두 문서 모두 이 파일을 1차 근거로 삼는다.
- `docs/참고/cm3-소스-트리-규약.md §2.1` — BLE 프로토콜 정의는 CM3 미참조여도 삭제하지 않는다는 규약(앱·리모콘과의 통신 규약이므로).
- `docs/참고/ble/` — 2026-07-27 캡처 RTT 로그 7종(연결·라이브·특정자극·라이브+알람+볼륨·연결해제·임피던스 개별/전체). 위 두 문서의 실측 근거이자 회귀 기준선.
- `docs/참고/ble/재구조화/재구조화 설계안.md` — 이 프로토콜 자체가 아니라 `ble/` 모듈 코드 구조 재설계를 다루는 별도 문서.

## 주의

이 폴더는 읽기 전용 분석 산출물이다. `tdc_ble_protocol.h`가 실제 소스이며, 여기 문서는 그것을 정제한 뷰일 뿐이다. 코드가 바뀌면(특히 핸들러 추가·헤더 재배정·에러 응답 경로 통합 시) 이 문서도 함께 갱신해야 정합성이 유지된다.
