# BLE 참고 문서

**TL;DR**: `2__cm3` BLE 계통의 **영속 레퍼런스 모음**. 프로토콜 규약 · 코드 구조 · 라이브모드 상태머신 · 재구조화 설계안 4개 폴더와, 동작 대조 기준선이 되는 **실측 RTT 로그 7종**으로 구성된다. BLE 관련 작업을 시작할 때 여기부터 본다.

## 2. 실측 RTT 로그

2026-07-27 오전 한 세션에서 매핑 시나리오 7종을 연속 수행하며 받은 CM3 RTT 로그 원본이다. 코드를 고친 뒤 "이 시점 동작과 같은가"를 대조할 **기준선(baseline)** 으로 쓴다. 가공 없이 그대로 두었으므로 **내용을 편집하지 말 것.**

### 캡처 조건

| 항목 | 값 |
|---|---|
| 일시 | 2026-07-27 10:02 ~ 10:11 (연속 세션) |
| 경로 | J-Link SWD 1000kHz -> RTT up[0] (`AUTO-RTT` 툴) |
| 대상 | Cortex-M3 (`2__cm3`) |
| 연결 내부기 | ISD SERIAL `0x1A31FFFF`, ID MATCH NUM 1 |

### 읽는 법

로그 태그가 서브시스템을 가리킨다.

| 태그 | 의미 |
|---|---|
| `[BATT]` | LSAD 배터리 계측 (`DATA` 원시값, `mV` 환산) |
| `[ISD]` | 내부기 연결·초기화 상태 |
| `[LINK]` | 백텔 기반 링크 상태 · TX 전력 조정 |
| `[MAPPING]` | 매핑 명령 수신·실행 |
| `[PARA]` | 자극 파라미터 계산 결과 |
| `[TOUCH]` | 터치센서 계측 |

`(SYSTIME : n)` 은 시스템 tick 이다.

> [!CAUTION]
> **로그 해석 함정 2건** (2026-07-27 구조 분석에서 확인)
>
> 1. **`[SPI RX]` 줄의 마지막 바이트 `01` 은 수신 데이터가 아니다.** 디버그 출력이 20원소 배열(`tdc_hal_spi.c:22`)의 인덱스 20 을 읽어 인접 정적 변수 값이 찍힌 것이다. TX 방향의 마지막 바이트는 정상적으로 전송 길이(`dataSize`)다. 상세는 [`프로토콜/패킷 구조와 응답 규약.md`](프로토콜/패킷%20구조와%20응답%20규약.md)
> 2. **`LINK CHECK TRIGGERED (LIVE, STANDBY)` 의 괄호 안은 런타임 값이 아니라 고정 리터럴이다.** 호출부는 `tdc_isd_map_live.c:783` 한 곳뿐이며 상태 표시가 아니다

> [!NOTE]
> **2차 리팩토링(2026-07-23~27) 직후 캡처다.** 이 시점의 `2__cm3` 는 사장 코드 정리가 끝난 상태(`claude_develop` `2e0f681`)이므로, 이후 회귀를 의심할 때 이 로그와 대조하면 된다. 다만 `[LINK]` 의 TX 전력 로그 형식은 같은 날 변경됐으므로(`ffa608d`) 그 이전 로그와는 문구가 다르다.
>
> 로그 7종 전체에 에러 응답(`0xF0`)·재시도·타임아웃이 **전무**하다. 깨끗한 기준선이다.
