시험 ID: `SW-FW-UnitTest-BOOT-ID-15`  
원본: [유닛 검증 보고서 1차본](../../SUVR-FW-TD24A%20%EC%86%8C%ED%94%84%ED%8A%B8%EC%9B%A8%EC%96%B4%20%EC%9C%A0%EB%8B%9B%20%EA%B2%80%EC%A6%9D%20%EB%B3%B4%EA%B3%A0%EC%84%9C_1%EC%B0%A8%EB%B3%B8.xlsx), `보고서_유닛 시험` 1590~1615행.  
아래 예상 결과는 보고서에 기록된 결과를 그대로 옮긴 비교값이다.

## 유닛 설명

<!-- source-cell:E1590 -->
파일에서 준비한 데이터를 실행 코어의 메모리에 옮긴다.<br>
<!-- /source-cell:E1590 -->

<!-- source-cell:F1590 -->
T<br>
<!-- /source-cell:F1590 -->


## 상세 설계 유닛

<!-- source-cell:G1590 -->

<!-- /source-cell:G1590 -->


## 시험 준비와 입력

<!-- source-cell:H1590 -->
- 입력 4워드 \[0x11,0x22,0x33,0x44\]와 EMPTY 조건을 준비한다. 지원 type별 대상/offset/전송 단위/길이를 기록한다. PC 요청 확인과 실제 목적 메모리 확인을 구분한다. 실제 확인에는 현 메모리 맵에서 실행 코드/스택/RTT/다른 코어 자료와 겹치지 않는 시험 영역/동등 경로가 먼저 승인/확인되어야 한다. 보고서의 offset=0 주소에 운영 이미지를 덮어쓰지 않는다.<br>
<!-- /source-cell:H1590 -->


## 가정 및 제한 조건

<!-- source-cell:I1590 -->
시험 입력 또는 가상 장치 응답은 유닛 입력 경계에 설정한다. 실행 결과를 미리 예상값으로 덮어쓰지 않는다. 실제 전원이나 RF 연결 확인과 소프트웨어 상태 확인을 구분한다. 운영 이미지 대신 격리된 시험 저장소를 사용한다. 초기 RTT 미사용 시 결과를 보존한 뒤 읽는다.<br>
<!-- /source-cell:I1590 -->


## 시험 절차

<!-- source-cell:J1590 -->
- PC에서 DMA source/대상 주소/모드/count/호출 횟수를 기록한다. K의 실제 전송 값/순서/단위 변환 확인은 안전한 격리 실기 시험에서 DMA 완료 뒤 지원 대상별 목적 메모리 주소와 원시 내용/길이를 읽어 입력과 대조한다. 8→24비트는 디버거 표시 단위를 명시하고 실제 word 패킹을 확인한다. 목적 메모리 자료가 없으면 요청 기록만 확인한 것으로 남긴다.<br>
<!-- /source-cell:J1590 -->


## 입력 조건별 기준과 예상 결과

### 비교 1

#### 입력 조건과 통과 기준

<!-- source-cell:K1590 -->
판정 범위<br>
- 대상별 전송 값/순서/길이는 입력과 같고 전송 단위 변환이 정확하다. 다른 코어 영역을 대상으로 쓰지 않는다.<br>
<!-- /source-cell:K1590 -->


#### 예상 결과 (보고서 기록값)

<!-- source-cell:L1590 -->
검증 결과<br>
입력 4워드=\[0x11,0x22,0x33,0x44\]의 전송 자료는 11 00 00 00 22 00 00 00 33 00 00 00 44 00 00 00이었다. 지원 대상마다 1회 전송됐고 길이=16바이트였다. 8→24비트 대상의 DMA count=16바이트, 32→32비트 대상=4워드, 반환값=0이었다.<br>
