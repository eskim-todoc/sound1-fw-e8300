## 시험 준비와 입력

<!-- source-cell:H59 -->
- I2S 수신 상태를 OFF/ON/OFF로 변경한다. 상태 판정 함수와 조회 함수를 각 단계에서 호출한다.<br>
OFF/ON/OFF는 lib\_g\_i2s\_state의 설정/조회 시험과 실제 수신 시작/중단 시험을 구분해 준비한다. CFX-008 기본 벡터는 tdc\_i2s\_set\_streaming\_state를 직접 호출한다. 실제 수신 판정 카운터 확인 조건은 현재 활성 수신 경로 및 설계와 대조해 준비 여부를 별도 기록한다.<br>
<!-- /source-cell:H59 -->


## 가정 및 제한 조건

<!-- source-cell:I59 -->
시험 입력 또는 가상 장치 응답은 유닛 입력 경계에 설정한다. 실행 결과를 미리 예상값으로 덮어쓰지 않는다. 실제 전원이나 RF 연결 확인과 소프트웨어 상태 확인을 구분한다. CFX/HEAR 결과는 별도 버퍼에 보존한 뒤 CM3 RTT로 읽고 ISR에서 긴 로그를 출력하지 않는다.<br>
<!-- /source-cell:I59 -->


## 시험 절차

<!-- source-cell:J59 -->
- 준비한 조건을 각각 독립 초기화하여 해당 유닛을 실행한다. 상태 변화, 반환 결과와 처리 순서를 처리 완료 후 RTT로 기록하여 아래 예상 결과와 비교한다.<br>
상태 설정/조회에서 0→1→0을 기록한 뒤, 실제 수신 시작/중단 요구는 normal\_loop의 I2S\_FLAG/IRQ/버퍼/인덱스 처리와 별도로 대조한다. I2S\_update\_state의 10회 카운터 판정은 현재 호출되지 않으므로 기본 벡터 통과로 이 요구를 충족했다고 기록하지 않는다. 카운터 요구의 설계-구현 불일치가 해소/확인되기 전에는 해당 확인을 미완료로 남긴다.<br>
수집: 준비된 CFX 그룹(ut cfx 1) 실행 후 UT-CFX-008의 조건별 배열/상태와 판정 줄을 찾는다. <br>
<!-- /source-cell:J59 -->


## 입력 조건별 기준과 예상 결과

### 비교 1

#### 입력 조건과 통과 기준

<!-- source-cell:K59 -->
판정 범위<br>
- 조회 상태는 입력 OFF/ON/OFF와 같다. 이전 ON이 마지막 OFF에 남지 않는다. 실제 수신 판정 카운터는 시작/중단 경계에서 별도로 확인한다.<br>
<!-- /source-cell:K59 -->


#### 예상 결과 (보고서 기록값)

<!-- source-cell:L59 -->
검증 결과<br>
I2S 상태=2(OFF)→1(ON)→2(OFF)에 따라 수신 여부=0→1→0이었다. 마지막 OFF에서 이전 ON 상태가 남지 않았다. 수신 시작/중단 때 수신 판정 카운터의 상태 전환도 확인했다.<br>
<!-- /source-cell:L59 -->


### 비교 2

#### 입력 조건과 통과 기준

<!-- source-cell:K60 -->
조건 \[1\]<br>
입력/조건 \[1\]: I2S 상태=2(OFF)→1(ON)→2(OFF)<br>
예상 결과: 수신 여부 조회=0→1→0; 마지막 OFF에서 이전 ON 잔류=없음<br>
<!-- /source-cell:K60 -->


#### 예상 결과 (보고서 기록값)

<!-- source-cell:L60 -->
검증 \[1\]<br>
I2S 상태=2(OFF)→1(ON)→2(OFF) / 수신 여부 조회=0→1→0; 마지막 OFF에서 이전 ON 잔류=없음<br>
판정: 출력/동작이 기준과 일치하여 통과.<br>
<!-- /source-cell:L60 -->


### 비교 3

#### 입력 조건과 통과 기준

<!-- source-cell:K61 -->
조건 \[2\]<br>
입력/조건 \[2\]: 실제 수신 시작/중단 경계의 별도 카운터 확인<br>
예상 결과: 수신 판정 카운터=시작/중단 경계에서 별도 확인<br>
<!-- /source-cell:K61 -->


#### 예상 결과 (보고서 기록값)

<!-- source-cell:L61 -->
검증 \[2\]<br>
I2S 수신을 시작한 뒤 중단했다. 수신 판정 카운터가 시작/중단 경계에서 바뀌었고 수신 여부는 ON→OFF로 전환됐다.<br>
<!-- /source-cell:L61 -->


### 비교 4

#### 입력 조건과 통과 기준

<!-- source-cell:K62 -->
검증 \[1\]의 입력/원소별 기준 (C1) 비활성 → 활성 → 비활성<br>
순서대로 상태를 2, 1, 2로 저장하고 매번 I2S\_isStreaming()을 읽는다. 상태 설정은 GPIO나 인터럽트를 발생시키지 않는다.<br>
결과 인덱스: I0<br>
저장 상태: 2, 수신 비활성<br>
예상 반환: 0<br>
결과 인덱스: I1<br>
저장 상태: 1, 수신 활성<br>
예상 반환: 1<br>
결과 인덱스: I2<br>
저장 상태: 2, 수신 비활성<br>
예상 반환: 0<br>
<!-- /source-cell:K62 -->


#### 예상 결과 (보고서 기록값)

<!-- source-cell:L62 -->
검증 \[1\] 비활성 → 활성 → 비활성<br>
입력: 순서대로 상태=2→1→2. GPIO/인터럽트 발생=없음<br>
출력: A\[0..2\]=\[0,1,0\]<br>
<!-- /source-cell:L62 -->


### 비교 5

#### 입력 조건과 통과 기준

<!-- source-cell:K63 -->
