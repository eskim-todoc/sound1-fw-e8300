# Sound1 펌웨어 설계 입력 문서 변경사항

## 시험 방법 안내 간소화 (2026-10-02)

시스템 시험 기준서의 본문/변경 비교 시트에서 I/A/D/T의 괄호 예시와 단일 문자 제한을 없애고 영문 명칭과 의미만 남겼다. 필요한 경우 I, A처럼 조합할 수 있으며 기존 81개 시험의 방법, ID, 요구사항 연결과 서식은 바꾸지 않았다. 설계 출력에도 같은 안내를 적용했다. `[작성자 전용]` 문서는 수정하지 않았다.

## 시험 방법 정리 (2026-10-01)

시스템 시험 기준서에 I(시각적 확인), A(분석 근거 확인), D(정량 측정 없이 동작 확인), T(정량 측정/비교)의 정의를 넣었다. 기존 81개 시험의 ID와 요구사항 연결, 순서는 유지하고 방법을 통과 조건에 맞췄다. 설계 입력을 먼저 반영하고 설계 출력의 같은 시험과 방법을 일치시켰다. 코드 분석 항목의 빈 절차도 짧게 보완했다.

변경 비교 시트에는 이번 수정 전/후를 표시한다. 실제 다른 글자만 진한 빨강/초록이며 방법이 바뀌지 않은 행은 중복하지 않는다. 표지와 원래 열 폭/글씨는 유지하고 인쇄 설정만 가로/너비 1쪽으로 조정하여 본문이 4쪽에 출력되도록 했다. `[작성자 전용]` 문서와 다른 입력 문서는 수정하지 않았다. 실제 시험 결과를 추가한 작업은 아니다.

Word는 본 파일에서 **검토 > 변경 내용 표시 > 모든 변경 내용**으로 비교할 수 있다. 변경 내용은 아직 수락하지 않았다. Excel은 본문 시트 이름 뒤에 `_변경 비교`가 붙은 시트에서 확인한다. 기존 열 구성 안에서 빨간 `[-]` 원문 다음 줄에 초록 `[+]` 수정문을 배치했다. 신규 행은 `[+]`, 유지 행은 표시 없이 보인다. 표지는 비교하지 않는다. 비교 내용은 2026-09-29 기준이며 이후 편집은 자동 반영되지 않는다. PowerPoint는 아래 위치별 설명과 원본으로 비교한다.

2026-09-29 재배치: Bluetooth 2개 항목은 기존 c) 대분류 안의 하나의 Bluetooth 중분류로 병합하고, 보안 10개 항목은 기존 e) 사이버 보안 그룹에 넣었다. SSTC 시험도 같은 요구사항 순서로 배치했다. 기존 80개 ID는 유지했다. 아래 행 번호는 최초 작성 당시 위치이며, 현재 파일에서는 요구사항 ID로 찾는다.

이번 파일에는 `[작성자 확인]` 표시를 붙이지 않았다. SR 5~6장은 2026-09-29 작성자가 실제 검증과 위험분석 재평가 완료를 확인하여 기존 문구로 복원했다. 날짜, 서명, 검토/승인란은 요청대로 빈칸을 유지했다.

## 공통 수정

### SRS 사용자 검토 반영 (2026-09-29)

- 기존 상세 내용 복원: SW-FW-RID-1, 2, 6, 11, 15, 16, 46. 현재 ID와 발생원 연결은 유지.
- 42: IQS323 명칭 제거. 45: 블루투스를 사용한 데이터 통신으로 표현 수정.
- 53은 SYS-RID-FW-30, 새 81은 SYS-RID-FW-31에 각각 연결. 81은 53 바로 아래에 배치하고 기존 번호는 유지.
- [E8300/QCC 연계]: 44, 45, 69, 70. [QCC 단독]: 47, 48, 49, 52, 71, 72, 76. [E8300/QCC 각각 확인, 향후 I2S]: 15.
- 비교 시트에도 반영했다. 후속 SSTC 수정으로 현재 SRS 81개 요구사항과 SSTC 81개 시험이 연결된다.

### SSTC 후속 반영과 추적 확인 (2026-09-29)

- SRS의 담당 접두어, 복원/수정한 요구사항에 맞춰 시험 내용을 갱신했다. 기존 시험 ID는 유지하고 시험 81을 시험 53 바로 아래에 추가했다.
- 시험 53 / SW-FW-RID-53 / SYS-RID-FW-30, 시험 81 / SW-FW-RID-81 / SYS-RID-FW-31로 분리했다.
- SW-FW-RID-1~81의 시험 연결 누락 0개, SRS와 SSTC의 SYS 번호 불일치 0개. SYS-RID-FW-1~50 모두 시험까지 추적된다.
- 상위 SYS 번호가 없는 SRS 자체 요구사항 31개는 임의로 상위 번호를 만들지 않고 SW 식별자로 시험에 연결했다.
- 펄스폭 하한, 8kHz의 판정 범위, 인증 실패 조건은 시험 제한 조건을 확인해야 한다. 식별자 연결 확인과 실제 요구 충족/시험 통과는 구분한다.

## 시스템 시험 기준서에서 달라진 부분

`기준서_시스템 시험`의 기존 B~J열 구성은 유지했다. E열은 연결할 SRS 식별자, F열은 시스템 요구사항 식별자, I열은 절차, J열은 합격 기준이다.

- 기존 시험 1~68번의 순서는 유지하고 신규 시험 69~80번을 뒤에 추가했다.
- 원본의 외부 Excel 참조가 한 행씩 어긋나 있던 부분을 실제 SRS 식별자로 바로잡았다. 원본의 연결 파일이 없어도 요구사항 번호가 보인다.
- 매트릭스에 정해진 시험 방법, 입력 조건과 예상 결과를 해당 시험의 I/J열에 반영했다.
- NofM은 기존 자극 기법 시험에 포함했다. 설정된 N개 채널의 선택, 미선택 채널의 무자극, 맵의 자극 순서를 확인한다.
- 오디오 확인에서 스피커 출력을 보던 부분은 Sound1의 입력 소스와 내부기 자극 출력 확인으로 바꿨다.
- 가속도 센서, 구형 CM3 코드 크기 제한, 이어피스 확인 항목은 현행 터치 센서, 부팅 무결성, Bluetooth 해제 시 동작으로 바꿨다.
- 매트릭스에 절차/합격 기준이 비어 있던 Classic/LE 통신은 실제 입력과 확인할 응답을 보충했다.
- 감사 기록 시험에는 권한 있는/없는 연결의 읽기, 전송 보호, 원격 수정 거부 확인을 포함했다.

## 시스템 Data 사용 범위

`7100-NRF 핀맵.docx`, `Ezairo7100 시스템 .docx`, BelaSigna300/Ezairo7150 자료는 **구형 제품의 원문 참고 자료**이다. 문서명, 핀 번호, 레지스터, 메모리 크기를 Sound1 사양으로 바꾸지 않았다. 그대로 Sound1의 설계 근거로 적용하면 안 된다.

`FIFO 구조.xlsx`도 기존 예제 원문으로 보존했다. Sound1 버퍼 크기와 주기를 확인한 자료로 오해하지 않도록 한다.

Sound1 칩의 현행 참고 자료는 `시스템 Data/Ezairo8300`에 추가한 Hardware Reference와 Firmware Reference이다. QCC5181의 실제 핀 연결은 해당 하드웨어 회로도를 기준으로 확인해야 하며, 구형 NRF 핀맵에서 이름만 바꿔 작성하지 않았다.
