# Sound1 설계 출력 문서 변경사항

## 시험 방법 안내 간소화 (2026-10-02)

시스템/유닛/통합시험 기준서의 본문과 변경 비교 시트에서 I/A/D/T의 괄호 예시와 단일 문자 제한을 없애고 영문 명칭과 의미만 남겼다. 필요한 경우 I, A처럼 조합할 수 있지만 이번에는 기존 시험 방법을 바꾸지 않았다. ID, 요구사항 연결, 비교 강조와 서식도 그대로다. 설계 입력의 공통 시험부터 반영했으며 필수성능시험 기준서와 `[작성자 전용]` 문서는 수정하지 않았다.

## 시험 방법/유닛 설명 정리 (2026-10-01)

시스템/유닛/통합시험 기준서에 I/A/D/T 정의를 넣었다. 시스템 시험 81개는 설계 입력과 같은 방법으로 맞췄다. 유닛 115개는 플래그의 용도와 상태, 고정 입력, 예상 결과를 제3자가 이해할 수 있게 풀어 썼다. 통합시험 17개도 최신 상세 설계의 참조를 유지하면서 허용/완료 조건을 명확히 했다.

주로 코드 분석이나 실행 후 RTT로 확인하고, 수치/배열/횟수/시간을 비교하면 T로 구분한다. GPIO 설정값 분석이나 OD 청취를 실제 전압/전류 측정으로 해석하지 않는다. 원래 입력과 기대값, ID 및 보조 대응표를 보존했다. I2S 복사 완료 플래그의 설계/코드 차이는 제거하지 않았다.

비교 시트는 이번 수정 전/후를 같은 ID로 짝지어 [-]/[+]와 실제 변경 문자만 진하게 표시한다. 바뀌지 않은 행은 한 번만 표시한다. 표지/원래 열 구성과 서식을 유지하고 긴 셀의 줄바꿈/행 높이를 조정했다. 시스템 5쪽, 유닛 12쪽, 통합 4쪽 출력에서 잘림을 확인했다. QCC 추가 위치는 기존 본문 제목/ID/행으로 유지한다.

은수님 후속 지시로 필수성능시험 기준서는 제외했으며 원본은 변경하지 않았다. 모든 `[작성자 전용]` 문서와 제품/시험 코드도 변경하지 않았다. 이번 문서 수정은 실제 시험 완료나 전체 시험 코드 준비 완료를 뜻하지 않는다.

참조 폴더의 펌웨어 문서 6종을 복사하여 Sound1용으로 작성했다. Word는 변경 내용 추적을 켰으며, Excel은 본문 옆의 `변경 비교` 시트에서 원본의 `[-]` 행과 변경된 `[+]` 행을 볼 수 있다. 원본 파일은 수정하지 않았다.

## 문서별 변경

2026-10-01 은수님 요청으로 이 폴더의 소프트웨어 아키텍쳐 기술서, 상세 설계서, 통합 계획서, 시스템 시험 기준서 파일명에 `[작성자 확인] ` 접두어를 붙였다. 문서 내용/변경 추적/비교 시트는 그대로이며 유닛 검증 기준서와 통합시험 기준서의 이름은 변경하지 않았다. 이 표시는 전체 실기 시험 완료를 뜻하지 않는다. 현재 파일 경로는 [QCC 자료 추가 위치 관리](../../../../QCC%20자료%20추가%20위치%20관리.md)의 파일 바로 찾기 목록을 사용한다.

## 통합시험 기준서 입력과 예상 결과 보완 (2026-10-01)

- 시험 001~017과 기존 표 형식을 유지하고 최신 상세 설계서/통합 계획서의 순서와 연결을 반영했다. 참여 항목 10개, 유닛 102개의 참조를 확인했다. 통합시험에서 모든 유닛을 다시 단독 시험하는 구성은 아니다.
- 고정 입력과 예상 결과를 추가했다. 혼합/공유 최대값 100, FFT bin 32, I2S 경로별 30/20/20, 빔포밍 블록 경계, NofM 선택/교차/시작점과 8자극/ms, 맵 반영 완료, 자동 종료 카운터, CRC 및 기동 슬롯의 조건을 문서 안에서 확인할 수 있다.
- RTT로 내부 상태/저장한 값을 읽고 실제 장치에서는 가능한 UART/Calibration/PMIC를 확인한다. 시험 입력 주입과 결과 저장은 시험 코드에 준비할 조건이지 이미 준비됐다는 뜻이 아니다. 전류/음압의 실제 측정과 디지털 패킷 비교도 구분한다.
- 수정 직전/수정 후를 같은 ID로 짝지은 34행을 기존 변경 비교 시트에 넣었다. [-]/[+] 행 배경은 연한 빨강/초록, 실제 차이 문자만 진한 색/굵게 표시한다. 표지는 비교하지 않는다.
- I2S 복사 완료 플래그의 설계/코드 차이는 제한 조건에 표시했다. 미선택 NofM 채널의 내부 크기 0이나 실패 직후 무조건 기본 슬롯 복귀처럼 실제 조건과 다른 판정은 바로잡았다.
- QCC 내부 통합시험 추가 안내는 빨간색으로 유지했다. 현재 E8300 연계 시험 012~014/36~38행과 마지막 017/41행을 확인했다. 실제 시험 결과를 작성하지 않았으며 유닛 검증 기준서, 상세 설계서와 펌웨어는 수정하지 않았다.

## 유닛 검증 기준서 입력과 관찰 방법 보완 (2026-10-01)

- 최신 소프트웨어 상세 설계서의 115유닛을 유지했다. 기존 시험 ID와 11열 구성, 방법의 한 글자 표기는 그대로다. CFX 42, HEAR 2, CM3 51, 부트로더 20유닛을 빠짐없이 연결했다.
- 실행/관찰 시험 D 96개와 정적 분석 A 19개로 구분했다. 입력 배열/상태/가상 응답을 준비하여 RTT로 실행 전후를 확인하고, 접근할 수 없는 내부 버스를 오실로스코프로 측정하도록 요구하지 않는다. UART/Calibration/PMIC 측정과 OD 청취는 적용 가능한 항목에서만 사용한다.
- AGC 3구간 경계의 정수 기대값, OD 64배 확대/포화, 빔포밍 블록 경계, NofM 순서, DAC/T/C 환산, 자동 절전 및 부트 시도 횟수의 경계를 구체화했다. 리모콘 연결 허용과 서비스 RTT 콘솔은 현재 코드의 실제 처리 경로에 맞췄다.
- `기준서_유닛 검증_변경 비교`는 이번 수정 직전 기준서와 수정 후 기준서를 비교한다. [-] 이전은 연한 빨강, [+] 수정은 연한 초록이며 실제로 달라진 문자만 진한 색/굵게 표시한다. 같은 ID/문구는 회색으로 유지하고 표지는 비교하지 않는다. 원본/1차본 대응표는 보존한다.
- 실제 실행을 위한 입력 주입/스냅샷/가상 응답은 시험 코드에 준비할 조건이다. 이번에는 제품 펌웨어 코드를 수정하거나 시험 합격 결과를 작성하지 않았다. QCC 내부 자료는 빨간 추가 위치로 남겼다.
- I2S 복사 완료 플래그 시험 `SW-FW-UnitTest-CFX-ID-15`에는 설계/코드 차이를 표시했다. 상세 설계서의 복사 후 완료=1 기대값을 유지하되 현재 코드에 설정문이 없다는 사실을 제한 조건에 적었다. 합격시키기 위해 기대값을 변경하지 않았다.
- 독립 호스트 검산 37개와 Excel 본문 출력 14쪽의 배치를 확인했다. 검산은 실제 제품 실행이나 실기 시험을 대신하지 않는다. 같은 파일 이름으로 저장했으며 최신 상세 설계서는 수정하지 않았다.

## 공통 스타일 적용 (2026-10-01)

- 대상은 소프트웨어 통합 계획서와 소프트웨어 아키텍쳐 기술서다. 요청받은 공통 DOTX 스타일을 내장하여 본문/표 10pt와 제목 수준별 들여쓰기를 적용했다. 표/그림/캡션도 해당 본문의 수준에 맞춰 정렬했다.
- 본문 내용, 요구사항 연결, 제목 번호, 삽입 그림과 기존 변경 추적은 유지한다. 연속 빈 문단과 목차 캐시는 정리했으며 표 뒤에는 정상 크기의 빈 문단을 둔다. 표지/개정 이력/머리말/꼬리말/여백은 변경하지 않았다.
- Word 출력 12쪽/18쪽을 확인했다. 파일 이름과 QCC 자료 추가 위치는 그대로이며 별도 접미어 문서는 만들지 않았다. 상세 설계서나 공통 템플릿 자체를 다시 수정한 것은 아니다.

## 식별 번호 유지 방식

시스템 시험은 확인된 설계 입력의 ID와 배치 순서를 유지했다. 통합 시험은 원본의 001~014를 유지하고 015~017을 추가했다.

상세설계와 유닛 검증은 **SAD의 모듈 아래 함께 시험할 수 있는 기능 단위**로 정리했다. CFX 42개, HEAR 2개, CM3 51개, 부트로더 20개로 총 115개다. 서로 대응하는 설정/조회는 묶고, AGC 계산/시간 변화/표본 적용이나 NofM 선택/교차/패킷처럼 별도로 판정할 단계는 나누었다. 함수 개수와 유닛 개수가 같아야 하는 것은 아니다.

CFX의 전략 선택과 NofM 대역 선택/교차 배치는 SAD에 맞춰 신호처리 모듈에 두었다. 패킷 헤더와 PCM 패킷 생성/출력은 내부 자극 장치 실행 모듈에 두고, 두 모듈 사이의 전달 관계를 설명했다.

SDDD와 SUVC에는 같은 새 유닛 번호를 사용한다. SUVC의 `원본 대응표`는 1.5세대 시험 186개의 유지/수정/이관/통합 또는 미적용 이유와 새 번호를 보여준다. `1차본 대응표`는 이전 325개 유닛의 역할이 연결되는 위치를 보여준다. 원본의 중복 CFX-055와 시험/설계 번호가 서로 다른 항목은 숫자가 아닌 역할로 대응했다. QCC 자료 대기는 NRF 유닛을 이름만 바꿔 대신하지 않았다.

SITC의 17개 시험 ID와 절차는 유지하고, 본문/비교 시트의 SI/SU 참조 68셀을 대조해 실제 값이 달라진 64셀을 수정했다. 참조가 길어진 행은 높이만 늘렸다. 현재 SIP에는 개별 SU-ID 참조가 없어 유닛 번호 때문에 변경하지 않았다.

## QCC 자료가 들어오면 추가할 곳

현재 파일별 삽입 위치와 진행 상태는 사운드1 폴더의 [QCC 자료 추가 위치 관리](../../../../QCC%20자료%20추가%20위치%20관리.md)에서 관리한다. 아래 내용은 최초 작성 당시 반영 범위이며, 위치 변경은 중앙 목록을 갱신한다.

E8300 코드로 확인한 다음 내용은 이미 반영했다.

- SPI로 전달되는 리모콘/매핑 명령과 응답
- 0x34 전원 정보, 0x35 LED 표시 요청, 0x36 오디오 연결 상태의 처리
- CFX의 마이크/I2S 혼합, 크래들 마이크와 일반 스트리밍의 게인 구분
- ISD_CHECK 내부기 연결 상태 및 QCC_CTRL 동작 제어

근거는 CM3의 `BleCommunication/ble_communication.c`, `QCC/snd_qcc.c`와 CFX의 `systemControl/main.c`이다. QCC의 내부 구현까지 확인했다는 뜻은 아니다.

QCC 자료를 받으면 SAD의 QCC 내부 소프트웨어 항목, SDDD의 QCC 내부 설계 절, SIP의 QCC 내부 구현/통합 부분에 내용을 추가하면 된다. QCC 내부 유닛 시험은 SUVC에 별도 코어 그룹으로 추가한다. 현재는 내부 유닛이나 내부 시험 결과를 만들지 않았다.

## 검사한 범위

- SDDD/SUVC의 유닛 115개 및 시험 ID 일치, 원본 시험 186개와 1차본 역할 325개 대응 확인
- SSTC에서 SW-FW-RID-1~81 및 SYS-RID-FW-1~50의 누락 여부 검사
- 저장된 Excel 본문과 비교 행을 작성 데이터와 대조
- Word의 실제 삽입/삭제 이력과 변경 추적 설정 확인. QA 사본에서 변경을 모두 거부하면 원본 본문/표의 텍스트가 복원됨을 확인
- 참조 원본 6종의 SHA256 불변 확인
- Word PDF 변환 및 전체 페이지 배치 확인, Excel 표지/본문/비교와 긴 시험 벡터 출력 확인

재구성 단계에서 혼합, AGC 정수 연산, 매핑, 프레임 수, DAC 변환과 NofM 순서의 독립 산술 검산 21건을 수행했다. 코드 분석에 사용한 62개 파일의 해시가 변하지 않았음을 확인했다. 당시 Word의 변경 후 출력 69쪽과 Excel 본문/비교의 배치를 확인했다. 이후 상세 설계서의 문구/서식과 순서도 보완은 아래 별도 항목에 정리했다. 이것은 펌웨어 115유닛 전체를 장비에서 실행하여 합격시킨 결과가 아니다. 실제 시험 결과 보고서는 해당 시험을 수행한 관찰값과 근거로 작성한다. QCC 내부 설계와 시험은 자료 수령 후 추가 검토한다.

## SAD 후속 보완 2026년 9월 30일

요구사항 추적성 표의 81개 항목을 ID 순으로 정렬했다. 식별자와 연결 내용은 유지했다. 검증 답변 두 곳은 확인된 내용을 `예,`로 표현하고 QCC 내부 자료 대기는 유지했다.

5장 `지원 소프트웨어`에 FatFs, tiny-AES-c, onsemi CRC 지원 코드, SEGGER RTT의 종류, 버전, 출처를 표로 정리했다. 기존 검증은 6장으로 옮기고 SOUP 답변을 `예, 사용되는 지원 소프트웨어의 종류, 버전 및 출처를 식별하여 관리한다.`로 변경했다. 코드 수정/시험 과정 설명은 SAD에서 생략했다. 상세 근거와 미결 확인 사항은 [Sound1 SOUP 사용 및 검토](../../../../../../시스템/Sound1%20SOUP%20사용%20및%20검토.md)에 유지한다. 본문 변경 추적을 유지하고 목차를 갱신했다.

## SIP 그림 보완 2026년 9월 30일

2장 그림 1을 SAD의 공통 소프트웨어 구조도로 교체했다. 코어별 실행 위치와 여러 코어가 나누어 수행하는 기능 모듈, 부트로더의 기동 단계가 같은 그림으로 연결된다. 통합 순서 본문과 기존 서식은 변경하지 않았다. 원본 그림의 삭제 추적은 보존했다. QCC 내부는 자료 추가 영역으로 남겼으며, 공통 그림 파일은 `이미지 참조/소프트웨어 구조도.png`다.

## SSTC 비교 강조와 SDDD 그림 보완 2026년 9월 30일

SSTC의 `기준서_시스템 시험_변경 비교`에서 같은 시험 ID의 전후 문장을 비교하여 실제 달라진 글자만 진한 빨강/녹색과 굵은 글씨로 강조했다. 공통 문구는 회색이며 기존 행 배경색은 유지했다. 추가/삭제만 있는 항목은 전체 문구를 강조했다. 셀 값, 시험 ID, 본문 시트와 인쇄 설정은 변경하지 않았다.

후속 요청으로 ID 63의 비어 있던 통과 조건을 추가했다. 리모콘에 배터리 잔량이 표시되고 전달 정보와 대응하며, 잔량 변경 후 재조회하면 변경 상태가 표시되는지 확인한다. 준비 조건과 절차도 함께 보완하고 비교 시트에 반영했다. SW 요구사항 81개/SYS 요구사항 50개 연결 누락과 SRS 대비 상위 연결 불일치가 없으며, 통과 조건이 비어 있는 시험 항목도 없음을 재확인했다.

SDDD의 하드웨어 그림 1은 SAD의 시스템 블록도를 그대로 사용했다. MCU간 제어 인터페이스의 시스템 제어, 신호처리, 내부기 실행, 블루투스 그림 4개는 같은 코어 경계와 기능 모듈 표현으로 상세화했다. 부트로더의 기동 단계, CM3/CFX/HEAR의 역할과 데이터 전달, FPGA/PMIC 경로를 구분했다. 당시에는 본문과 유닛 순서도 17개를 유지했으나, 후속 유닛 재구성에서는 원본 기반 기술 설명과 새 기능 단위의 처리 순서로 정리했다. 앞부분 구조 그림 5개는 유지하고 원본 일반 AGC 그림과 새 AGC 특성 그래프를 포함했다. 그림 원본은 `이미지 참조`에 저장했고 QCC 내부는 자료 추가 영역으로 남겼다.

## SDDD/SUVC 재구성 검토 순서

SDDD의 각 코어 첫 부분에서 유닛 목록을 확인한 뒤 해당 유닛의 목적과 입출력, 처리 설명을 읽으면 된다. 같은 `SU-ID`로 SUVC를 찾으면 준비 조건, 방법, 절차와 통과 기준을 볼 수 있다. 기존 항목의 이동은 두 대응표에서 확인한다. Word는 1.5세대 원본 대비 실제 변경 추적을 유지한다. Excel 변경 비교는 공통 글자를 회색, 다른 글자를 진한 빨강/녹색으로 표시한다. 새 기준은 검토 후 시험에 적용하며, 문서 편집 완료를 시험 합격으로 취급하지 않는다.
