# IQS323 제어운영 적용가이드

**TL;DR**: Azoteq 외부 자료 4종을 Sound1 제어 방향(Fixed MULT/COMP + 노터치 게이트 조건부 Re-ATI)에 매핑한 개발 참조 문서. **온도 드리프트는 카운트 감소 방향(약 −18cnt/°C, 고온=미탐 위험)**으로 정량 확인됐고, 인터치 중 자동보정 Follow UI는 우리 회로(CRX1 더미채널+C52 DC-block)로 **적용 불가** — 노터치 게이트 조건부 Re-ATI가 유일한 능동 드리프트 보정 수단이다. 모든 정량·주장에 `[자료 §섹션]` 출처를 달았고, adversarial 검증(원문 1:1 대조)을 통과한 내용만 수록한다. 데이터시트 확인이 남은 4항목은 §10에 후속 과제로 기록.

> [!NOTE]
> **출처 자료**: `azd004_azoteq_sensing_v1.1`(센싱 일반론), `azd125-capacitive_sensing_design_guide_v1.2`(설계 가이드), `IQS323_User_Guide_v1.1`(운영), `iqs323-example-code`(Arduino 예제). 분석 과정: [`tasks/touch/20260619_external-reference-integration`](../../../tasks/touch/20260619_external-reference-integration/분석.md).
> **검증 신뢰도**: 정독 인용 50여 건을 원문과 1:1 대조(adversarial) → [확인됨] 42건. [과장]·[근거없음]·[섹션오류] 적출 8건은 본 문서에서 정정·출처 보정 반영.

## §1. 개요 — IQS323 터치 센서 운영 방식

### 1.1 제품 구성

- IQS323 ProxFusion IC, **자기 커패시턴스(self-capacitive)** 방식
- 사용 채널: **CRX0**(터치 전극), **CRX1**(ESD 더미채널 — 내부 CalCap 사용, 외부 환경 미감지)
- 회로 특수성: **C52 100nF DC-block**(CRX1 핀 직렬), **크래들 뚜껑 닫힘 = 터치 폴링 완전 중단**

### 1.2 카운트(Counts) 정의와 터치 방향

- 카운트 = 내부 기준 커패시터(Cs)를 채우는 데 필요한 전하 이동 사이클 수 [AZD004 §2]
- 자기 커패시턴스: **터치(전도체 접촉) 시 카운트 감소** [AZD004 §3.1 "counts decrease when touching"]
- 판정: LTA보다 카운트가 낮아지면 터치 — 현 펌웨어 `(LTA−Counts)×256/LTA` 공식과 정합

### 1.3 제어 아키텍처 — 5층 방어

```
[공장 보정]   Fixed MULT/COMP write → ATI 자동 의존성 제거
[노터치 확인] 터치 없는 구간만 Re-ATI 허용 (크래들 닫힘·노터치 폴링 확인)
[자동 차단]   ATI Mode=Disabled + CH timeout 비활성 (이중 차단)
[절전 재동기] RESEED at 절전 진입 (LTA baseline 강제 동기화)
[장애 복구]   WDT 재부팅 → 부팅 시퀀스 전체 재실행
```

## §2. 신호 처리 — MULT / COMP / ATI 구조

### 2.1 ATI 2단계 구조 [AZD004 §4.4]

| 단계 | 대상 | 목표 값(전형) |
|---|---|---|
| ① Multiplier Calibration | Coarse + Fine MULT | Base **100~200 cnt** |
| ② Compensation Calibration | COMP | Target **500~1000 cnt** |

- **민감도 공식**: `민감도 ∝ Target / Base` [AZD004 §4.4]
- 민감도 상승 시 카운트 노이즈도 증가하는 트레이드오프 존재 [AZD004 §4.4]

### 2.2 Fixed MULT/COMP 운영 근거

현 펌웨어가 사전 측정한 MULT/COMP를 직접 write하는 방식은 **ATI 2단계 결과값을 수동 주입하는 것과 수학적으로 동등**하다 [AZD004 §4.4].

> [!WARNING]
> **EV-Kit 예제의 ATI 보상값을 직접 차용 금지** [적용 불가]. 우리 회로(C52 + 더미채널 + 단일버튼)의 기생 커패시턴스 프로파일이 EV-Kit(3버튼+슬라이더, C52 없음)과 달라, **보드 변종별 실측값 사용이 필수**다.

### 2.3 ATI 실패 처리 권고 [AZD004 §12.7]

- ATI 재시도(ReATI) 사이에 **delay를 추가**해 상호작용(interaction) 중 constant errors를 방지 — 원문 권고 [AZD004 §12.7]
- 3회 재시도 후에도 ATI Error → "Possible Hardware Issue" 처리(소프트웨어 권고 절차, IC 강제 아님)
- 현 제어: ATI Mode=Disabled로 자동 ATI 경로 차단 → 이 오류 경로는 **부팅 시 1회 Auto-ATI 단계에만** 해당

## §3. LTA 드리프트 보정 메커니즘

### 3.1 LTA IIR 필터 — 1차 자동보정 [AZD004 §5.1~§5.3]

- LTA(Long Term Average) = IIR 필터로 환경 드리프트를 느리게 추적
- 필터 공식: `yk = (1 − 1/2^β)×y(k−1) + xk/2^β`
- Beta 범위: **Counts 필터 0~4**(빠른 응답), **LTA 필터 6~10**(느린 환경 추적) [AZD004 §5.2~§5.3]
- 노터치 상태에서 자동 추적, 인터치 상태에서 LTA halt(정지)

### 3.2 LTA halt timeout 처리 [AZD004 §5.3]

- stuck-touch 시 halt 최대 시간 경과 후 RESEED(LTA를 현재 counts로 강제 동기화)가 수행될 수 있음 (정책적 동작)
- 이후 자동 Re-ATI가 **트리거될 수 있음** (원문 "may also automatically trigger a re-ATI" — **항상 보장 아님**)
- 현 제어: ATI Mode=Disabled + CH timeout 비활성으로 이 자동 트리거 경로를 **의도적으로 봉쇄**

### 3.3 Reseed 명령 [AZD004 §5.3, User Guide §3.5.4]

- 명시적 Reseed = 자료가 허용하는 정상 LTA 조작법. LTA를 현재 counts로 강제 동기화
- 단, LTA가 ATI Target과 크게 다를 경우 ATI 자동 트리거 가능(조건부 "may trigger")
- **ATI Mode=Disabled 상태에서 Reseed 후 ATI 자동 트리거 차단 효과는 [자료 미명시]** → §10 후속 과제

### 3.4 Follow UI (온도 자동보정) — 현 하드웨어 [적용 불가] [AZD125 §8.2.1]

- 인터치 상태에서 레퍼런스 채널 변화 × 가중치(Wf)로 LTA를 추종 → 드리프트 중에도 터치 델타 유지
- 가중치: `Wf = |Ns,i − Ns,f| / |Nr,i − Nr,f| × 100` (예시 150%)
- 별도 레퍼런스 전극(0.2mm 트레이스) + 별도 Cx 핀 + 별도 채널 **필수**
- **[적용 불가]**: CRX1이 내부 CalCap 더미채널(외부 환경 미감지) + C52 100nF DC-block 복합 제약

> [!IMPORTANT]
> **인터치 중 드리프트 보정은 노터치 게이트 조건부 Re-ATI가 현 하드웨어의 유일한 능동 수단**이다. 이는 "when the device is not in touch"에서만 자동 추종을 허용하는 [AZD125 §8.1] 원칙과 정확히 일치한다.

## §4. 환경 드리프트 정량 참고

### 4.1 온도 드리프트 — 유일하게 정량 자료 존재 [AZD125 §8.2.4]

- 실험: ATI 후 카운터 고정 + ATI 비활성 상태에서 FR-4 PCB 워치 기기 25→50°C 변화
- 센서 채널: 1000 → 550 cnt (**−450 cnt**)
- 레퍼런스 채널: 700 → 400 cnt (−300 cnt)
- 선형 추정: 약 **−18 cnt/°C**(센서), −12 cnt/°C(레퍼런스) [추정, 25°C 구간 선형 가정]
- **방향: 온도 상승 → 카운트 감소 = 터치 방향** → 고온에서 오탐보다 **미탐(민감도 저하) 위험**이 큼

> [!NOTE]
> 이 수치는 ATI 후 1000 cnt 기준 예시다. 우리 고정 보상값 기준 실제 카운트가 다르면 절댓값도 다르다. 방향(감소)은 자기 커패시턴스 방식에서 공통.

### 4.2 배터리 구동 / 들고 있는 상태 [AZD125 §5.1, §5.3]

- 터치 루프 = C1(손가락↔전극 <10pF) · C2(몸↔지구 >100pF) · C3(모듈↔지구) 직렬 합성
- 배터리 기기에서 **C3 감소 → C1 변화 감지량 감소 → 터치 delta 감소**(민감도 저하)
- 전극 주변 시스템 GND 플레인이 있으면 C3 부족을 부분 보완 [§5.3]
- 정량 수치: [자료 미명시] — 방향만 확인

### 4.3 수분 / 습도 [AZD125 §9 + AZD004 §3.1]

- 수분이 전도체처럼 동작 → 자기 커패시턴스에서 카운트 **감소** → **터치 오탐** 유발
- 변화 속도 빠름 → LTA 추종 불가, 터치와 유사하게 인식
- 정량 수치: [자료 미명시]

> [!CAUTION]
> **수분 오탐 방향**: 자기 커패시턴스에서 전도체(수분) 접촉은 카운트 **감소** 방향(터치로 오탐)이다. "카운트 급증"은 상호 커패시턴스(mutual) 방식의 동작이며 자기 커패시턴스와 반대다 — 혼동 주의 [AZD004 §3.1].

### 4.4 노이즈 / SNR 기준 [AZD125 §10.1]

| 기능 | 최소 SNR | 임계값 최소(노이즈 밴드 4 cnt 기준) |
|---|---|---|
| 비임계(근접) | ≥ 3 | 12 cnt |
| 임계(터치) | ≥ 5 | 20 cnt (전형 신호 최소 25 cnt) |

> [!NOTE]
> 현 펌웨어 Touch Threshold는 raw counts 차이가 아닌 LTA 대비 비율 계수(`delta×256/LTA`)로 동작한다. SNR 기준(cnt 단위)을 계수 단위로 직접 적용하려면 변환 검증이 필요하다.

## §5. 부팅 · 초기화 시퀀스

### 5.1 현 드라이버 순서 (자료 권고와 정합) [User Guide §3.5.1, AZD004 §12.7]

```
MCLR (하드 리셋, 전원 인가 동등)
→ IC Auto-ATI 완료 대기 (WAIT_FOR_ATI)
→ ACK Reset (SHOW_RESET_BIT 응답, SYSTEM_CONTROL bit0=1)
→ 설정 write: Fixed MULT/COMP + ATI Mode=Disabled + CH timeout 비활성 + 이벤트 비트
→ 정상 폴링 시작
```

자료 권고 순서("전원 인가 → IC Auto-ATI → ACK Reset → 설정 write")와 일치.

### 5.2 부팅 시 ATI Error 처리 [20260618_touch-review 확정]

- ATI_Error = "IQS323 failed to calibrate one or more channels correctly" [User Guide §3.6.1]
- **ATI Error 비트는 상태 보고 플래그이며 conversion 정지를 유발하지 않음** — Fixed MULT/COMP write 이후엔 측정 동작에 영향 없음
- **단 Max Counts 포화는 conversion 정지** → 이 경우만 MCLR 필요 → **MCLR 조건부화**(포화 감지 시에만 MCLR)

> [!IMPORTANT]
> 터치 부팅으로 ATI_Error가 떠도 카운트는 **하향**(터치=감소)이라 Max Counts(상한) 포화와 반대 방향 → conversion 정지 안 함 → **Fixed write로 무해화, MCLR 불필요**. Max Counts 포화(드문 이상)만 MCLR을 안전망으로 유지.

## §6. 절전 · 복귀 시퀀스

**절전 진입** (실제 코드 순서, `main.c:944~952`)
```
① 절전 레지스터 적용: Touch Threshold=255(최둔감) 등 — 정상속도 I2C로 기록 [apply_sleep_settings]
② Power Mode 전환: SYSCLK 강하 30.72M→2.56M [ci_power_sleep]
③ I2C prescale 조정 (SCL ~122kHz 유지)
④ RESEED: LTA를 현재 counts로 강제 동기화 [User Guide §3.5.4] [tdc_drv_iqs323_reseed]
```

> [!IMPORTANT]
> **RESEED는 클럭 강하(Power Mode 전환) 이후**에 발행된다. 임계값 설정(①)과 RESEED(④)는 별도 단계이며, ② Power Mode 전환이 그 사이에 위치한다. (임계값 변경은 정상속도 I2C 보장을 위해 클럭 강하 전에 먼저 기록)

**절전 복귀**: WDT 재부팅 → 부팅 시퀀스 전체 재실행 (런타임 복귀 FSM 없음)

> [!WARNING]
> Reseed 후 ATI 자동 트리거 위험: [User Guide §3.5.4]는 Reseed가 ATI를 트리거할 수 있다고 명시(조건부 "may"). ATI Mode=Disabled에서 IC 하드웨어 레벨로 완전 차단되는지는 [자료 미명시] — §10 후속 과제. 현재는 ATI Mode=Disabled + CH timeout 비활성 이중 차단이 설계 의도.

## §7. 통신 윈도우 운영

**Force Communication** [AZD004 §12.6]
- 0xFF 주소에 write → IQS323이 RDY LOW(통신 윈도우 열림)
- Event Mode에서 이벤트 외 구간 설정 read/write 시 이 방법으로 윈도우 강제 개방

**현 드라이버 운영 모드**: Streaming Mode (주기적 RDY) [추정]
- Event Mode 미채택 — Arduino 예제 init 마지막 `setEventMode()` 단계가 현 드라이버에 없음
- Streaming은 터치 없는 구간에도 주기적 RDY 발생 → 불필요한 I2C 통신 가능
- Event Mode 채택 시 전력·노이즈 이점 있으나 상위 polling 구조 변경 필요 [개선 여지, 단기 우선순위 낮음]

## §9. 개발 적용 체크리스트

### 9.1 레지스터 설정 (필수 — 현 드라이버 적용 사항)

| 항목 | 값 | 근거 | 현 상태 |
|---|---|---|---|
| ATI Mode | Disabled (ATI_SETUP_LSB bits[2:0]=000) | Auto-ATI 경로 차단 | 적용됨 |
| CH timeout | 비활성 (SYSTEM_CONTROL MSB bit[2:0]=111) | stuck-touch Re-ATI 이중 차단 | 적용됨 |
| MULT/COMP | 보드 변종별 **실측값** 고정 write | EV-Kit 값 차용 불가 | 적용됨 |
| 터치 임계값 | `TDC_DRV_IQS323_TOUCH_THRESHOLD` | EV-Kit 값 차용 불가 | 적용됨 |
| 이벤트 비트 | touch·ati_error·ati_event 활성화 | 상태 감지 | 적용됨 |

### 9.2 레지스터 설정 (검증·조정 필요)

| 항목 | 현 상태 | 위험 | 조치 |
|---|---|---|---|

### 9.3 시퀀스 체크

- [ ] MCLR → Auto-ATI 대기 → ACK Reset → 설정 write 순서 준수
- [ ] Fixed MULT/COMP write 시점 = ACK Reset 이후
- [ ] CH timeout 비활성(SYSTEM_CONTROL MSB bit[2:0]=111) 확인
- [ ] ATI_Error 비트 확인 후 무해화(Fixed write로 대체), Max Counts 포화 시에만 MCLR
- [ ] 절전 시퀀스: 절전 레지스터(Threshold=255) → Power Mode 전환(클럭 강하) → I2C prescale → RESEED 순서 (RESEED는 클럭 강하 **이후**, `main.c:944~952`)
- [ ] WDT 재부팅 후 부팅 시퀀스 전체 재실행 확인

## §10. 데이터시트 확인 잔여 과제

외부 자료 4종으로 해소되지 않아 IQS323 데이터시트 확인이 필요한 항목:

1. **MULT/COMP 포화 한계값** — ATI 실패의 정확한 물리 경계(Max Counts 발생 조건)
2. **ATI Mode=Disabled에서 Reseed → ATI 자동 트리거 차단 효과** — IC 하드웨어 레벨 명세
3. **ATI Mode=Disabled에서 LTA halt timeout → Re-ATI 발동 여부** — "may" 조건의 구체 조건
4. **Filter Beta IC reset 기본값** — EV-Kit 예제값(NP_LTA=5)과 동일 여부

### 즉시 착수 가능한 검증 (실측)

1. 데이터시트에서 Filter Beta reset 기본값 확인 → 권고 범위(6~10) 비교 → 명시 write 여부 결정
2. 고온 운영 환경 실측 — 온도 범위에서 카운트 감소량이 Touch Threshold를 침범하는지
3. SNR 기준 검증 — 현 Touch Threshold가 노이즈 밴드 기준 SNR≥5를 충족하는지 계수 단위 환산
