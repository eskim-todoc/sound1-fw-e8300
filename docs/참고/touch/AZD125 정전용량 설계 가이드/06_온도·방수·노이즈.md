# AZD125 — 온도·방수·노이즈

> [!NOTE]
> **TL;DR**: AZD125 v1.2 §8~§10 정리. 온도 드리프트는 비-터치 시 IC가 자동 추종하며, 장기 '인-터치' 추종은 Follow UI(센서+레퍼런스 전극, Follow Weight 공식)로 구현한다. 방수는 수직 배치·간격 확보·비전도성 하우징으로 대응하고, 노이즈는 HW/SW 체크리스트와 SNR 임계(비핵심 ≥3, 핵심 ≥5)로 관리한다.

> [!IMPORTANT]
> 본 문서는 추출 텍스트(`-layout` 변환본)의 §8 Temperature Effects, §9 Water Immunity and Humidity, §10 Noise 범위만 옮긴 것이다. 수치·공식·표는 원문 그대로이며, 원문에 없는 내용은 추가하지 않았다. 페이지·줄 번호는 추출본 기준(소스: `azd125.txt`).

## 8. 온도 영향 (Temperature Effects)

> 원문 §8, 줄 1523~1767, Page 31~35

### 8.1 일반 (General)

> 원문 §8.1, 줄 1525~1536, Page 31

- 온도 변화는 정전용량 센서 측정값에 영향을 줄 수 있다. Azoteq IC는 온도 드리프트를 추적하고, **디바이스가 터치되지 않은 상태**에서 감도를 유지하도록 디바이스를 자동 튜닝한다. (줄 1526~1527)
- '인-터치(in-touch)' 온도 추적은 §8.2 참조. (줄 1528)
- 사용자 인터페이스(UI) 설정은 **온도 쇼크**용 또는 **최대 근접 검출**용으로 최적화할 수 있다. 높은 감도를 유지하면서 쇼크 이벤트를 처리하려면 추가 UI와 레이아웃 기법이 필요하다. (줄 1530~1532)
- 기판(substrate) 재료의 열역학적 특성이 큰 역할을 한다. (§3.1.4 참조) — 얇은 **FPC** 설계는 온도 의존성이 높고, **LDS** 기술은 온도 안정성이 높다. (줄 1534~1536)

### 8.2 Follow UI 설정 (Follow UI Setup)

> 원문 §8.2, 줄 1538~1542, Page 31

- 일부 IC는 **Follow UI** 기능을 제공하며, 이는 장기 '인-터치' 추적을 가능하게 한다. (줄 1539)
- 예시 응용: **착용 검출(wear detection)** — 디바이스를 장시간 착용하여 지속적인 정전용량 센싱이 필요한 경우. (줄 1540~1541)

#### 8.2.1 전극 구성 (Electrode Configuration)

> 원문 §8.2.1, 줄 1544~1588, Page 31~32

- 가장 단순한 형태에서 Follow UI 시스템은 **센싱 전극**과 **레퍼런스 전극**을 필요로 하며, 둘 다 독립적인 **자기 정전용량(self-capacitance)** 전극으로 동작한다. (줄 1546~1547)
- 센싱 전극: 사용자 상호작용을 검출하는 것이 목적이므로 사람의 존재에 민감하도록 설계해야 한다. (줄 1547~1549)
- 레퍼런스 전극은 다음을 만족하도록 설계해야 한다. (줄 1549~1552)
  - 사용자 상호작용의 영향을 받지 않을 것.
  - 센싱 전극이 겪는 것과 **동일한 온도 변화**를 겪을 것.

레퍼런스 전극 설계 가이드라인 (줄 1554~1588):

| 항목 | 내용 | 원문 위치 |
|---|---|---|
| 크기 | 레퍼런스 전극은 센싱 전극보다 **작아야** 한다(사람 상호작용에 둔감하게 유지). 일반적으로 폭 **0.2 mm**의 PCB 트레이스. | 줄 1556~1558 |
| 폭 제한 | 너무 민감해지지 않도록, 폭은 **오버레이 두께의 절반 이하**(equal to or less than half)여야 한다. (Figure 8.1 참조) | 줄 1558~1560 |
| 배치 | 센싱 전극과 **동일 영역에 걸치도록(span the same region)** 배치 → 전체 센싱 영역의 온도 변화를 레퍼런스 전극이 검출. (Figure 8.2 참조) | 줄 1568~1578 |
| 핀/채널 | 센서와 레퍼런스 전극은 **별도의 Cx 핀**·**별도 채널**에 연결해야 한다. 예: 센서=Cx0/Channel 0, 레퍼런스=Cx1/Channel 1. | 줄 1586~1588 |

> [!NOTE]
> Figure 8.1(레퍼런스 전극 폭 사이징), Figure 8.2(레퍼런스 전극 PCB 커버리지)는 추출본에 그림 자체가 포함되지 않고 캡션만 존재. (줄 1565, 1583)

#### 8.2.2 GUI 구성 (GUI Configuration)

> 원문 §8.2.2, 줄 1590~1613, Page 32

정확한 GUI 구성 절차는 사용하는 IQS 디바이스에 따라 다르나, 일반적으로 Follow UI 구성 시 수행할 **4가지 주요 단계**: (줄 1592~1602)

| 단계 | 동작 | 설명 |
|---|---|---|
| 1 | **Follower 채널 지정** | 센서 전극의 채널을 Follower로 선택. |
| 2 | **Reference / Leader 채널 지정** | 레퍼런스 전극에 사용되는 채널을 Reference 또는 Leader로 선택. |
| 3 | **Follow Event 선택** | 따라가는 동작을 트리거할 이벤트 선택. 특정 채널이 proximity 또는 touch 상태가 될 때일 수 있음. |
| 4 | **Follow Weight 조정** | Follower 채널이 reference/leader 채널을 얼마나 공격적으로 따라갈지 결정하는 수치 값. 결정 방법은 §8.2.3. |

> [!NOTE]
> 위 목록은 Follow UI 활성화에 필요한 일반적 동작 목록일 뿐이며, 상세 지침은 해당 IQS 디바이스의 application note·datasheet·setup guide를 참조해야 한다. (줄 1612~1613)

#### 8.2.3 Follow Weight 결정 방법 (How to Determine the Follow Weight)

> 원문 §8.2.3, 줄 1615~1654, Page 32~33

**1단계 — 온도 특성 시험 수행 (Temperature Characterisation Test)** (줄 1619~1636)

- 원하는 동작 온도 범위 내에서 응용의 온도 응답을 결정한다. 온도를 신뢰성 있게 제어할 수 있는 환경이 필요하다.
- 시험 전 전극을 캘리브레이션하는 **기준 환경 온도(Reference Environmental Temperature, T<sub>ref</sub>)** 를 선택. 일반적으로 **T<sub>ref</sub> = 25 °C**.
- 다음을 확인할 것:
  - 센서·레퍼런스 채널 **둘 다 활성화**(Azoteq GUI에서 counts 값으로 확인).
  - 센서·레퍼런스 채널 **둘 다 T<sub>ref</sub>에서 ATI 절차 완료**. 완료 후 **두 채널의 ATI를 비활성화(disabled)**.
  - 채널은 **activation 상태가 아니어야** 한다.
  - (선택) GUI 로깅 기능 사용 시 시험 결과 후처리에 도움.
- 이후 환경 온도를 최대(**T<sub>max</sub>**) 또는 최소(**T<sub>min</sub>**) 동작 온도로 변경하고, 해당 온도 도달 시 센서·레퍼런스 채널의 counts 값을 기록. 온도 변화에 따라 두 채널의 counts 값이 증가 또는 감소할 것으로 예상.

**2단계 — Follow Weight 계산** (줄 1637~1648)

온도 특성 시험 결과로부터 Follow Weight W<sub>f</sub>(백분율)를 다음 식으로 계산: (식 (2))

$$
W_f = \frac{|N_{s,i} - N_{s,f}|}{|N_{r,i} - N_{r,f}|} \times 100
$$

여기서:
- N<sub>s,i</sub> : T<sub>ref</sub>에서 센서 채널 counts 값
- N<sub>s,f</sub> : T<sub>max</sub> 또는 T<sub>min</sub>에서 센서 채널 counts 값
- N<sub>r,i</sub> : T<sub>ref</sub>에서 레퍼런스 채널 counts 값
- N<sub>r,f</sub> : T<sub>max</sub> 또는 T<sub>min</sub>에서 레퍼런스 채널 counts 값

**3단계 — Follow Weight 검증** (줄 1649~1654)

- 센서 채널이 activation 또는 proximity 상태(또는 following 시퀀스 개시에 요구되는 조건)일 때 1단계 온도 시험을 반복.
- 시험 중 **T<sub>ref</sub>와 T<sub>min</sub>/T<sub>max</sub>에서 counts delta가 동일**해야 한다. 동일하지 않으면 동일해질 때까지 Follow Weight를 미세 조정.

#### 8.2.4 Follow Weight 계산 예시 (Example Illustration)

> 원문 §8.2.4, 줄 1656~1738, Page 33~35

예시 설정 (줄 1661~1684):
- Figure 8.2의 전극 사용: 센서 전극 = Cx0, 레퍼런스 전극 = Cx1. 이미 **워치(watch) 디바이스**에 내장된 PCB로 가정.
- GUI에서 센서=Channel 0, 레퍼런스=Channel 1 할당. Channel 0 = follower, Channel 1 = reference.
- 워치 응용이므로 follow event = **touch 상태** 선택.
- 상온(25 °C)에서 ATI로 **Channel 0 = 1000 counts**, **Channel 1 = 700 counts** 설정.

> [!NOTE]
> Channel 0(센서) target(1000)을 Channel 1(레퍼런스) target(700)보다 **높게** 설정한 것은, 레퍼런스 전극이 사용자 상호작용을 검출하지 않도록 보장하는 추가 주의 조치. Channel 1도 1000으로 설정했다면 더 민감하여 레퍼런스 채널이 사용자에게 영향받을 약간의 가능성이 있다. 700으로 낮춤으로써 레퍼런스 채널을 사용자로부터 격리. (줄 1677~1681)

온도 스윕 (줄 1683~1689):
- 워치를 50 °C까지 동작시키기 위해 **T<sub>ref</sub> = 25 °C → T<sub>max</sub> = 50 °C** 제어 온도 스윕 수행.
- Figure 8.3(SCOPE 뷰 예시): 샘플 0~100에서 25 °C 유지, 샘플 101~375에서 50 °C로 가열, 샘플 500까지 50 °C 유지.
- 센서(파랑)·레퍼런스(빨강) 채널 counts 모두 감소했으나, 파랑이 빨강보다 더 많이 감소. 이 감소율 차이를 Follow Weight가 포착하여, 레퍼런스 채널로 센서 채널의 LTA를 예측.

계산 (줄 1705~1713, 식 (3)):

$$
W_f = \frac{|1000 - 550|}{|700 - 400|} \times 100 = 150\%
$$

즉, 시험 동작 범위 내에서 레퍼런스 채널이 1 count 변할 때 센서 채널은 **1.5 count** 변할 것으로 예상.

검증 (줄 1715~1738):
- (3)의 Follow Weight 적용 후, Channel 0를 touch 상태로 두고 시험 반복. (Figure 8.4)
- 샘플 50에서 터치 인가 → Channel 0 신호와 LTA 라인 사이에 T<sub>ref</sub> = 25 °C에서 counts delta 형성.
- 샘플 100에서 가열, 두 개의 LTA 표시:
  - **연파랑 라인**: 신호 드리프트를 따라가 counts delta 유지(레퍼런스 채널과 할당된 Follow Weight가 제어).
  - **녹색 라인**: Follow UI 없는 LTA — 터치 이벤트 때문에 정지 상태 유지.
- 샘플 450(50 °C)에서 터치 제거 → Channel 0가 따라간 LTA 레벨로 회복하여 성공적 터치 릴리스를 나타냄. Follow UI가 없으면 녹색 라인이 온도 변화를 따라가지 못해 디바이스가 릴리스를 등록하지 못함.
- §8.2.3 3번째 항목에 따라, T<sub>ref</sub>와 T<sub>max</sub>에서 counts delta가 동일함을 Figure 8.4에서 확인.

> [!IMPORTANT]
> 생산 변동(production variation)을 고려하여, 최종 Follow Weight 결정 전 **여러 디바이스 샘플**에 대해 Follow Weight를 계산하는 것이 가장 좋다. (줄 1737~1738)

#### 8.2.5 Follow Weight 트러블슈팅 (Troubleshooting)

> 원문 §8.2.5, 줄 1749~1767, Page 35

| 증상 | 대응 | 원문 위치 |
|---|---|---|
| 센서 채널에 드리프트가 거의/전혀 없음 | 응용에 Follow UI 불필요. 단, 시스템이 드리프트 내성이라고 결론짓기 전 **여러 샘플에서 'no drift' 결과 확인** 권장. | 줄 1754~1756 |
| 센서 채널에는 큰 드리프트, 레퍼런스 채널에는 드리프트 없음 | 레퍼런스 채널 감도 개선 필요: **resolution factor 증가**, 부족하면 채널 **base 값을 약간 낮춤**. 그래도 안 되면 레퍼런스 전극을 더 크게/더 잘 배치하도록 **재설계**. 이후 레퍼런스 채널이 여전히 사용자 상호작용에 둔감한지 검증. | 줄 1757~1763 |
| 센서 채널이 T<sub>min</sub>/T<sub>max</sub> 도달 전 timeout 상태 진입 | 센서 채널을 덜 민감하게 조정: **resolution factor를 낮춤**. 재시험으로 timeout 미발생 확인 + 사용자 검출에 충분히 민감한지 검증. | 줄 1764~1767 |

## 9. 방수 및 습도 (Water Immunity and Humidity)

> 원문 §9, 줄 1770~1800, Page 36

- 정전용량 터치 센싱 성능은 센싱 영역의 **수분 축적 또는 액체 흘림**에 영향받을 수 있다. 수분/액체가 전기 전도성을 띠기 때문에, 터치 센서 위에 도체를 올려놓은 것과 유사하게 정전용량 센서에 영향을 준다. (줄 1772~1775)
- 수분은 다음 이유로 예측 불가능: (줄 1776~1781)
  - 전도도가 가변적.
  - 물방울의 모양·크기가 가변적.
  - 변화가 빠르게 일어나 환경 변화보다 **터치처럼 보임**.

설계를 수분 내성으로 만드는 방법 (줄 1783~1792):

| 기법 | 내용 |
|---|---|
| 수직 배치 | 응용을 수직(지면에 수직) 구성으로 설치 → 축적된 수분이 중력으로 자연스럽게 흘러내림. 터치 패드에 액체가 고일 기회가 없어야 함. |
| 버튼 간격 | 버튼 사이에 충분한 간격. |
| 패드-그라운드 간격 | 터치 패드와 그라운드 사이 충분한 간격. |
| 트레이스 라우팅 | 수분/액체와 접촉할 수 있는 표면에서 멀리 전극 트레이스 라우팅. |
| 하우징 | 비전도성(non-conductive) 하우징 사용 시도. |

- 수분 변화에 매우 취약한 설계(비방수 디바이스에 일반적)는, 수분 민감 영역의 **반대면에 LDS**(plastic printed sensing pads)처럼 수분에 둔감한 재료를 사용해 영향을 줄일 수 있다. (줄 1794~1796)
- 터치 패널에 액체 풀(pool)이 생긴 것을 검출하고 액체 풀이 제거될 때까지 터치 기능을 비활성화하도록 설계할 수 있다. 이는 **guard channel**을 사용해 큰 물체를 검출함으로써 달성. (줄 1798~1800)

## 10. 노이즈 (Noise)

> 원문 §10, 줄 1810~1834, Page 37

- 정전용량 센서는 **low femto-farad** 수준의 매우 작은 신호를 검출한다. 기생 정전용량 대비 신호가 매우 작으므로, 최적 SNR을 위해 **노이즈 내성** 설계가 중요. (줄 1812~1814)
- 노이즈 내성 개선 절차: (줄 1814~1820)
  - 먼저 설계에 **self** 또는 **mutual** 정전용량을 사용할지 결정.
  - PCB 레이아웃이 하드웨어 체크리스트를 준수하도록 함.
  - 제작 후 설정 튜닝 가능 시, 튜닝 체크리스트에 따라 디바이스 튜닝.

**하드웨어 체크리스트** (줄 1822~1828):

- 전극 크기를 제한 — 필요 이상으로 크지 않게.
- 전극과 오버레이 사이 **에어 갭 제거**.
- 전극 트레이스를 최대한 짧게, 터치 영역에서 멀리 라우팅.
- 프린지 E-field 제한을 위해 **밀집된 리턴(그라운드) 평면** 사용.
- Rx·Tx 라우팅 시 커넥터 회피.
- 양호한 전원 공급 설계 원칙 적용.

**소프트웨어 튜닝 체크리스트** (줄 1830~1834):

- Mutual 정전용량 센싱은 **변환 주파수 1 MHz 이상** 사용.
- activation·release debounce 값 최적화.
- 노이즈 저감을 위해 **count filter beta** 최적화.
- 오검출 저감을 위해 threshold 값 최적화.

### 10.1 근접·터치의 허용 SNR 레벨 (Acceptable SNR levels for proximity and touch)

> 원문 §10.1, 줄 1836~1846, Page 37

근접·터치 임계값 설정 가이드라인. 이 임계값 disclaimer는 서로 다른 기능 구현에 대한 **최소 SNR 요구**를 규정. (줄 1837~1840)

| 기능 분류 | SNR 요구 |
|---|---|
| **비핵심 기능** (proximity triggers) | SNR ≥ **3** |
| **핵심 기능** (touch triggers, 0 mm touch) | SNR ≥ **5** |

(줄 1842~1843)

#### 10.1.1 벤치 시험 SNR 레벨 (Bench test SNR levels)

> 원문 §10.1.1, 줄 1848~1925, Page 37~38

예시를 통한 임계값 선택 단계 (줄 1853~1858):

| 단계 | 내용 | 계산 |
|---|---|---|
| 1. 노이즈 밴드 식별 | 본 예시 노이즈 밴드 = **4 counts**. | — |
| 2. 비핵심 기능 임계값 | 노이즈 밴드의 최소 **3배**. | Threshold<sub>non-critical</sub> = 3 × 4 = **12 counts** |
| 3. 핵심 기능 임계값 | 노이즈 밴드의 최소 **5배**. | Threshold<sub>critical</sub> = 5 × 4 = **20 counts** |
| 4. 최소 일반 신호 레벨 | 최소 핵심 기능 임계값의 최소 **125%**. | Signal<sub>min</sub> = 1.25 × 20 = **25 counts** |

명시된 노이즈 레벨 기준 결론 (줄 1869~1873):

- 비핵심 기능: 허용 임계값 **최소 12 counts**.
- 핵심 기능: 허용 임계값 **최소 20 counts**.
- 최소 일반 신호 레벨: **최소 25 counts**.

> 이 임계값들은 신호와 노이즈를 신뢰성 있게 구분하고, 핵심 기능이 더 높은 임계값으로 신뢰성을 높이도록 보장한다. 구체적 응용 요구·공차에 따라 조정. (줄 1875~1877)

> [!NOTE]
> Figure(줄 1879~1906, Page 38) "Example case for signal level determination" — Counts 축 0~40, Sample number 축 0~100. Minimum Signal Level / Minimum non-critical function Threshold / Minimum critical function Threshold / Noise Band 4개 예시 라인 표기. 추출본은 그래프 라벨·축 값만 포함하고 그림 자체는 없음.

단기 노이즈 모니터링 (줄 1917~1925):
- 단기 노이즈 모니터링은 짧은 기간 동안 시스템 변동을 관찰하는 것. 일반적으로 **표준편차 약 1**로 노이즈 측정. 단, **최대 3 표준편차(3σ)** 까지의 간헐적 변동은 가능함을 인지해야 함.
- 효과적 노이즈 검출 임계값 확립을 위해, 시스템 평균 노이즈 레벨의 **최소 3배**로 임계값 설정이 권장됨. 이는 일반 변동과 잠재적 이상을 구분할 만큼 임계값을 견고하게 하여, 유의미한 편차에 대한 민감도를 유지하면서 오경보를 최소화.

#### 10.1.2 양산 전 시험 (Pre-production testing)

> 원문 §10.1.2, 줄 1927~1966, Page 39

생산 수준 성능(특히 핵심 기능) 보장을 위한 다수 유닛 시험 계획 (줄 1929~1962):

| 항목 | 내용 |
|---|---|
| **1. 다수 유닛 시험** | 비핵심 기능: **100개** 시험. 핵심 기능: **1000개** 시험 + 그중 **최소 100개**를 일반 사용 모사를 위해 **수 시간** 시험(짧은 false trigger도 로깅되어 누락되지 않게 보장). |
| **2. 핵심 기능 연장 시험** | 핵심 기능은 첫 **10,000개**에 대해 더 긴 양산 시험 → **100 ppm 미만** 실패율 보장. |
| **3. 시험 기준** | 각 유닛을 명시 임계 레벨에 대해 평가하여 요구 SNR 레벨 충족 확인(비핵심 3, 핵심 5). 실패·예상 성능 이탈 모니터링. 핵심 기능은 모든 실패/이슈에 면밀히 주의. |
| **4. 분석 및 조정** | 시험 단계 결과를 분석하여 실패/성능 편차의 패턴·경향 파악. 신뢰성·성능 개선을 위해 제조 공정·제품 설계에 필요한 조정 수행. |
| **5. 문서화 및 보고** | 모든 시험 결과(실패·이슈 포함) 문서화. 시험 유닛 성능·개선 사항을 담은 상세 보고서 작성. |
| **6. 품질 보증 조치** | 생산 공정 전반에 엄격한 QA 조치 적용으로 결함 최소화·일관된 품질 보장. 생산 공정을 지속 모니터링·검토하여 최적화 기회 식별. |
