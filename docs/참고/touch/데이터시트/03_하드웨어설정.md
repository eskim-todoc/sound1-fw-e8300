## 6.1 Inactive Rxs

`Pattern Definitions`의 `Inactive Rxs`는 현재 실행 중 conversion에서 선택되지 않은 Rx들의 상태를 설정. **최적 noise rejection을 위해 'VSS'로 설정 권장.**

> [!NOTE]
> **왜 VSS인가?** 선택되지 않은 Rx 핀을 floating 상태로 두면, PCB 패드·배선·센서 전극이 인접 도체와 기생 커패시턴스(capacitive coupling)를 형성해 부유 전위가 진동한다. 이 전위 진동이 측정 회로의 기준 전위에 노이즈로 더해진다. VSS로 단락하면 낮은 임피던스 경로가 생겨 전하가 즉시 방전되므로 부유 전위 진동이 억제된다. 또한 활성 Rx 채널의 커패시턴스 측정 시 비활성 핀이 의도치 않은 기생 커패시터 역할을 하는 경로도 차단된다.
> - 핵심 원리: **낮은 임피던스 종단(VSS) = 부유 전위 진동 억제 = 노이즈 감결합**
> - 원문은 이유를 기술하지 않고 "VSS 권장"만 명시. 위 설명은 회로 원리 해설이다.
>
> ```
> ── CH0 측정 중 (IQS323 순차 측정) ──────────
>
>  활성 채널         비활성 채널 (Inactive Rxs)
>  ┌────────────┐    ┌────────────────────────┐
>  │ CRx0/CTx0  │    │ CRx1/CTx1  → 0x0A:VSS │
>  │ ADC 측정 중 │    │ CRx2/CTx2  → 0x0A:VSS │
>  │ Cx 변화 감지│    └────────────────────────┘
>  └────────────┘      ↓ 저임피던스 종단 효과
>        │             부유 전위 없음
>        ▼             기생 Cx 경로 차단
>   정확한 Counts
>
>  Floating(0x00) 설정 시:
>  CRx1 ─┬─[기생 Cp]──→ 인접 도체
>         └─ 부유 전위 진동 → ADC 노이즈 ⚠
>
>  Inactive Rxs 레지스터 Bit[3:0]:
>    0x00=Floating  0x05=Bias
>    0x0A=VSS       0x0F=VREG
> ```
>
> 활성 채널 측정 중 비활성 핀을 VSS로 묶어 노이즈 경로를 차단하는 구조.

## 6.2 Prox Control Settings

`Prox Control` register는 ProxFusion® 모듈의 다양한 구성 옵션 포함. 일부 설정은 모든 측정 타입에 적용.

### 0v5 Discharge

conversion 동안 reference capacitor(Cs)는 전압이 어떤 threshold에 도달할 때까지 충전. conversion 완료 후 Cs는 다음 conversion 준비 위해 완전 방전.

`0v5 Discharge` bit set 시 Cs를 0V 대신 **0.5V로 방전**. set 시 charging curve가 더 선형이나 약간의 noise 유발 가능. **대부분 응용은 Cs 완전 방전 권장**.

> [!NOTE]
> **왜 0.5V 시작이 더 선형인가?** RC 충전 곡선 `V(t) = Vdd·(1 − e^(−t/τ))`에서 선형 근사가 유효한 구간은 **V가 0에 가까운 곡선 초입**이다(테일러 1차 전개가 성립하는 구간). 0.5V ≪ Vdd 조건이므로 이 선형 구간 내에 위치하며, 매 conversion마다 동일한 초기 전압(0.5V)에서 출발해 측정 재현성이 높아진다. 반면 완전 방전(0V)에서 시작해도 같은 선형 구간을 쓰므로 정확도 자체는 0V 시작이 더 기준으로서 깔끔하다.
> - `0v5 Discharge` 단점: 이전 conversion의 잔류 전하가 일부 인계되어 **약간의 노이즈가 추가**될 수 있다 — 원문 "this can introduce some noise" 직접 기술.
> - 결론: 대부분 응용에서 완전 방전(기본값) 유지 권장. 0v5 Discharge는 선형성 개선이 필요한 특수 케이스에만 시도.

### Cs Size

`Cs Size` 옵션으로 Cs 커패시터 크기 선택. **40 pF 또는 80 pF**. 40pF/80pF 선택은 측정을 다른 동작 영역에 둠. **대부분 응용은 80 pF 적절**.

> [!NOTE]
> **Cs Size가 동작 영역을 결정하는 원리** — charge-transfer 방식에서 카운트 값은 `Count ∝ Cs / Cx` 관계를 따른다. 매 사이클에서 Cx에 모인 전하가 Cs로 전송되고, Cs 전압이 임계에 도달하기까지 필요한 전송 횟수가 카운트다.
>
> | Cs | 특성 | 적합 상황 |
> |---|---|---|
> | **40 pF** | 포화까지 전송 횟수 적음 → 카운트 변화 빠름 | 전극 면적이 작고 기생 정전용량이 낮은 환경 |
> | **80 pF** | 포화까지 전송 횟수 많음 → 측정 범위 넓음 | 기생 정전용량이 큰 실제 PCB 환경, 대부분 응용 |
>
> - **SW 주의**: Cs Size 변경 후 ATI 기준점도 달라지므로 **반드시 ATI 재실행** 필요.
> - 원문은 "different operating regions"로만 기술. 위 설명은 charge-transfer 원리 해설이다.

### S/H Bias Select

mutual capacitance conversion은 Sample and Hold(S/H) 회로 사용. `S/H Bias Select`는 sampling 후 S/H 회로가 얼마나 적극적으로 hold하는지 선택. **10 µA로 설정 권장**.

> [!NOTE]
> **S/H 회로의 역할** — mutual-cap 측정에서는 Tx 전극이 구동 신호를 인가하고 Rx 전극에서 Tx-Rx 사이 커패시턴스(Cm)를 통해 유도된 전하를 읽는다. S/H 회로는 다음 두 단계로 동작한다.
> - **샘플(charge) 단계**: 스위치를 닫아 Rx 전극의 전하를 sample capacitor에 취득
> - **홀드(hold) 단계**: 스위치를 열어 취득한 전하를 유지한 채 후속 변환으로 전달
>
> `Bias Current`는 hold 단계에서 sample capacitor를 목표 전위로 유지하는 구동 전류다. 전류가 부족하면 hold 전압이 목표치에 미치지 못해 유효 신호가 줄어들거나 역전된다. 과도하면 소비 전력만 증가한다. **10 µA는 Azoteq 권장 기본값.**
>
> - **self-cap 측정에서 S/H가 없는 이유**: self-cap은 단일 전극에서 GND 방향 커패시턴스 변화를 직접 측정한다. 단일 노드 적분 방식이라 별도의 sample-and-hold 증폭기가 필요 없다.
>
> ```
> Mutual-Cap S/H 동작 (Self-Cap은 해당 없음)
>
> ── SAMPLE 단계 (SW 닫힘) ──────────────────
>  CTx ──[구동 파형]──→ 전극 A
>                          │ Cm(상호 커패시턴스)
>                          ▼
>                       전극 B (Rx)
>                          │
>                        SW 닫힘
>                          ▼
>                     Cs_s(S/H 커패시터) 충전
>
>  Cs_s 전압                  ← SW 열림
>  ↑    /─────────────────────────────────
>  │   /  충전 중             고정됨
>  └──────────────────────────────→ 시간
>       │ SAMPLE 단계 │ HOLD 단계  │
>
> ── HOLD 단계 (SW 열림) ────────────────────
>  SW 열림 → 전하 격리
>  Bias (10µA) → Cs_s 전위 유지 → ADC 전달
>
>  Bias 부족 시: 전압 처짐 → 유효 신호 손실 ⚠
>  S/H Bias Select = 10 µA 고정 권장
> ```
>
> SAMPLE 단계에서 Cm 통해 전하를 취득하고 SW가 열리는 순간 전압이 고정된다. HOLD 단계에서 Bias Current가 그 전위를 유지해 ADC에 전달한다.

## 6.3 Engine Bias Current

conversion 동안 ProxFusion® 모듈 입력에 constant bias current 적용 가능. `Prox Input and Control`의 `Prox Engine Bias Current` bit set으로 enable. current는 `Pattern Selection and Engine Bias Current`의 `Engine Bias Current`·`Engine Bias Current Trim` 값으로 선택.

특정 경우 bias current로 measurement setup을 bias → 측정 동작점 이동. **Azoteq 엔지니어 권고가 없으면 모든 측정에서 bias current disable 권장.**

> [!NOTE]
> **Engine Bias Current 사용 시 주의** — 원문은 "특정 경우에 측정 동작점을 이동시키는 용도"라고만 기술하며 메커니즘을 상세히 설명하지 않는다. Azoteq 엔지니어 권고 없이 임의 적용 시 노이즈 증가·선형성 저하·채널 간 간섭 등 부작용이 있다. **기본값은 disable이며, 이 설정을 변경해야 할 명시적 이유가 없다면 건드리지 않는 것이 안전하다.**

## 6.4 Dead Time

`Prox Input and Control`의 `Dead Time Enable` bit set 시 conversion마다 charge·transfer phase 사이에 dead time 추가 → ProxFusion® 모듈 측정 회로를 in/out switch할 시간 확보.

> [!IMPORTANT]
> **Dead time은 capacitance 측정에서 항상 enable, inductive 측정에서 disable.**

> [!NOTE]
> **왜 capacitive는 ON, inductive는 OFF인가?**
>
> - **Capacitive → Dead time 필수**: charge-transfer의 각 사이클에서 스위치를 고속으로 전환할 때 회로 내 과도 응답(글리치)이 발생한다. dead time은 이 전환 사이에 짧은 휴지 구간을 삽입해 전하가 완전히 안정화(settle)되기를 기다리는 시간이다. 과도 전류가 남아 있으면 Cs에 안착한 전하량에 오차가 생겨 카운트 정확도가 떨어진다.
> - **Inductive → Dead time 금지**: 유도성 측정은 LC 공진을 이용한다. 공진 파형이 진행 중에 dead time을 삽입하면 공진 에너지가 단절되어 파형이 왜곡되고 측정 정확도가 손상된다. 원문은 이유를 기술하지 않으며, 위 설명은 원리 해설이다.
>
> 따라서 **conversion frequency 설정 시 Dead Time Enable 상태도 함께 확인**해야 한다(§6.5 참조).
>
> ```
>  사이클 1                  사이클 2
>  ┌──────┐                  ┌──────┐
>  │ 충전 │                  │ 충전 │
>  │ (Cx) │                  │ (Cx) │
> ─┘      └──[DT]──┐      ──┘      └──[DT]──
>  CTx High  Dead   │ CTx   CTx High  Dead
>  (Cx 충전)  Time  │ Low   (Cx 충전)  Time
>                   │(→Cs)
>                   └──→ 전달(→Cs)
>
>  흐름: Cx 충전(High) → [DT] → Cs 전달(Low)
>  DT = High→Low 전환 직후 삽입 (글리치 흡수)
>
>  Capacitive: DT=ON  (글리치 흡수 필수)
>  Inductive:  DT=OFF (LC 공진 연속성 유지)
> ```
>
> CTx High(충전) → Dead Time → CTx Low(전달) 순서. DT는 High→Low 전환 직후에 삽입되어 과도 전류가 사라지기를 기다린다.

## 6.5 Charge Transfer Frequency

charge transfer frequency(Fxfer, conversion frequency라고도 함)는 `Conversion Frequency Setup`의 `Conversion Frequency Fraction`·`Conversion Frequency Period`로 설정. 고저항 센서는 Fxfer를 낮춰야 할 수 있음.

- **`Conversion Frequency Fraction`='127' 고정** + `Conversion Frequency Period`로 원하는 conversion frequency 선택 권장.
- conversion frequency 설정 시 `Prox Input and Control`의 `Dead Time Enable` 고려 — capacitance는 enable, inductive는 disable.
- 적절한 `Conversion Frequency Period` 값은 **Table A.1, A.2** 참조([06 레지스터레퍼런스](06_레지스터레퍼런스.md) A.6).

> [!NOTE]
> **Fraction=127 고정 이유** — `Conversion Frequency Fraction`은 내부 분수 분주기(fractional divider)의 소수점 이하 미세 조정 비트다. 127로 고정하면 분수 보정 항이 0이 되어 클럭 지터가 최소화되고, 실제 Fxfer는 `Conversion Frequency Period` 하나로만 결정된다. 두 레지스터를 동시에 조정하면 의도치 않은 주파수가 나올 수 있으므로 Fraction은 불변값으로 두는 것이 설계 관행이다.
>
> ```
>  f_OSC = 14 MHz (내부 클럭, 고정)
>       │
>       ▼
>  ┌──────────────────────────────┐
>  │  Fractional Divider          │
>  │  Fraction = 127 = 0x7F (고정)│
>  │  → 보정항 = 0, 지터 최소화   │
>  │  Period = N (가변, 조정 대상) │
>  └──────────────────────────────┘
>       │
>       ▼
>  f_xfer (변환 주파수)
>
>  Dead Time ON (정전용량, Table A.1):
>  ┌────────┬───────────────────────┐
>  │ Period │ f_xfer                │
>  ├────────┼───────────────────────┤
>  │   2    │ 1.75 MHz              │
>  │   5    │ 1.00 MHz ← 자기용량  │
>  │        │           최대 권장   │
>  │  12    │  500 kHz ← 기본 권장 │
>  │  16    │  389 kHz              │
>  │  23    │  280 kHz              │
>  └────────┴───────────────────────┘
>  (상호용량 최대 2 MHz = Period≈7)
>
>  고저항 센서 조건:
>    1/f_xfer ≳ 5 × Rs × Cx
>    → Rs 크면 Period 늘려 f_xfer 낮춤
>
>  Fraction = 0x7F — 절대 변경 금지
> ```
>
> **고저항 센서에서 Fxfer를 낮춰야 하는 이유 — RC 시정수**
>
> 센서 저항 Rs와 커패시턴스 Cx는 RC 저역통과 필터를 형성한다(`τ = Rs × Cx`). 각 사이클에서 Cx가 Rs를 통해 충전·방전될 때, Cx의 전압이 다음 전송 단계 전에 충분히 정착(settle)해야 정확한 전하량이 Cs로 전달된다.
>
> ```
> 충분한 정착 조건:  1/Fxfer ≳ 5 × Rs × Cx
> ```
>
> Rs가 크면 τ가 커지고, 한 사이클의 허용 시간(1/Fxfer)도 길어져야 한다. Fxfer가 너무 높으면(주기가 너무 짧으면) Cx가 완전히 충전되기 전에 전송 단계로 넘어가 전하 부족 → 카운트 오차가 발생한다.
>
> - **SW**: `Conversion Frequency Period` 값을 Table A.1(Dead Time OFF)/A.2(Dead Time ON)에서 직접 조회. `Fraction = 0x7F`는 절대 변경하지 않는 불변 상수로 주석 처리 권장.

### 6.6.1 Reset Indication

reset 후 `System Status`의 `Reset Event` bit가 set되어 reset 이벤트 발생을 표시. master가 `System Control`의 `ACK Reset` bit set 시 clear. reset 조건에서는 communication window가 IQS323에 의해 계속 open.

reset 이벤트 후 칩 설정은 start-up value로 복귀. 복구하려면 master는 먼저 `ACK Reset` bit set으로 reset 이벤트를 acknowledge한 뒤 모든 application setting을 I²C로 IQS323에 재기록.

`Reset Event` bit가 set인 동안:

- device는 I²C event mode에 진입 불가
- communication window가 계속 open되므로 ATI가 훨씬 오래 걸림

> [!NOTE]
> **펌웨어 초기화 시 주의 — Reset Event 미처리 시 두 가지 함정**
>
> 1. **event mode 진입 불가**: `Reset Event`가 set인 상태에서 RDY 핀 인터럽트만 기다리면 event mode가 열리지 않아 영구 block 상태가 된다. polling 방식으로 loop를 돌며 ACK 처리를 먼저 완료해야 한다.
> 2. **ATI 지연**: communication window가 계속 열려 있어 ATI 소요 시간이 정상보다 훨씬 길어진다 — ATI가 끝나지 않은 것처럼 보일 수 있다.
>
> **올바른 재초기화 순서:**
> 1. RDY 핀 폴링으로 communication window 열림 대기
> 2. `System Status` 읽기 → `Reset Event` bit 확인
> 3. `ACK Reset` bit set → write (`Reset Event` clear)
> 4. 전체 설정 레지스터를 순서대로 I²C write (Prox Control, Dead Time, Conversion Freq, ATI 파라미터 등)
> 5. ATI 재실행 트리거 → ATI 완료 확인
> 6. event mode 진입 허용

### 6.6.2 Software Reset

`System Control`의 `Soft Reset` bit set으로 IQS323 강제 reset.

> [!NOTE]
> **Soft Reset 사용 시나리오**
> - ATI 무한 루프, I²C NACK 반복, 카운트 값 이상 등 펌웨어가 오동작을 감지했을 때 능동적 복구
> - 전원 재공급 없이 설정 전체를 갱신해야 할 때 클린 스타트
>
> Soft Reset을 write하면 `Reset Event` bit가 set되므로, 이후 §6.6.1의 ACK-and-write 재초기화 루틴과 동일한 경로로 연결해야 한다. watchdog 만료(255ms)에 의한 reset도 동일한 `Reset Event` 경로를 타므로 **reset 복구 핸들러는 원인을 구분하지 않고 단일 함수로 처리**해도 무방하다.

### 6.6.3 Hardware Reset

Ready/Master Clear(RDY/MCLR) pin을 low로 당기면 device hard reset. communication window가 open이면 IQS323은 MCLR 기능을 disable하고 RDY/MCLR을 low로 당김 → **window open 시 master는 hard reset 불가**(RDY/MCLR이 low).

RDY window 후 pin이 MCLR로 복귀할 때 switchover delay 존재. switchover 완료 전 reset 시도 시 무시. **typical switchover time = 150 µs**(pin이 high로 간주되어 MCLR로 작동하기까지). MCLR reset·input level은 §4.2 참조.

> [!NOTE]
> **RDY/MCLR 듀얼 기능 핀 — 펌웨어 타이밍 제약**
>
> RDY/MCLR은 하나의 핀이 두 역할을 한다.
> - communication window 열림 중: device가 low로 구동 → **RDY 출력**
> - window 닫힌 후: master가 low로 당기면 → **MCLR 입력**
>
> 이로 인해 hard reset 시 다음 3단계 시퀀스가 필요하다.
>
> ```
> ① RDY 핀이 high (window 닫힘) 확인
> ② 150 µs 이상 대기  ← switchover 완료 대기
> ③ MCLR low 인가 (§4.2 지정 시간 유지)
>
> 타이밍 상세:
>
>  RDY/MCLR
>  핀 전압
>  HIGH ─────────┐ (IQS323이 low 구동 중)
>                │← window open →│
>   LOW          └───────────────┘
>                                 ↑ window 닫힘
>                                 │
>                         [150µs switchover]
>                                 │
>                                 ↓ MCLR 기능 활성
>  MCU
>  제어  ─────────────────────────└─[LOW 인가]─
>                                  ↑
>                          여기서부터 유효
>
>  ①건너뜀: device가 LOW 구동 중 → 무시
>  ②건너뜀: switchover 미완료  → 무시
> ```
>
> - ①을 건너뛰면: device가 이미 low를 구동 중이어서 reset이 무시된다.
> - ②를 건너뛰면: switchover 미완료 상태여서 reset이 무시된다.
> - I²C event mode 중에는 RDY window가 자주 열리므로, hard reset 전에 polling mode로 전환하거나 window 닫힘 타이밍을 정확히 포착하는 설계가 필요하다.
