## 7.1 OutA Functionality

`OutA`는 **push-pull 출력 핀**으로 범용 출력 또는 event indicator로 사용. `OutA Mask` register가 OutA 동작 제어. default = `0x00` → OutA low. start-up 동작은 Figure 4.3/4.4 참조.

### 7.1.1 OutA as a General Purpose Output

- `OutA Mask`에 `0x0000` write → OutA low (0 V)
- `OutA Mask`에 `0x7FFF` write → OutA high (VDD)
- 그 외 값 → §7.1.2 동작

> [!NOTE]
> **push-pull 출력**이란 VDD 방향(source)과 GND 방향(sink) 양쪽을 능동으로 구동하는 토폴로지다. open-drain과 달리 외부 pull-up 저항 없이 high/low 두 상태를 저임피던스로 스위칭한다.
>
> `0x0000`과 `0x7FFF`는 **GPO 상수 출력** 전용 값이다. `0x7FFF`는 하위 15비트가 모두 1이지만 Event Indicator 모드(§7.1.2)로 동작하지 않는다 — 데이터시트가 이 두 값만 GPO 모드로 명시 처리하고 그 외 값을 §7.1.2로 넘긴다. `0x0000`/`0x7FFF`를 쓰면 이벤트와 무관하게 OutA가 상수 low/high로 고정된다.

### 7.1.2 OutA as an Event Indicator

- `Slider Setup and Calibration`의 `Total Channels`=0 → `OutA Mask`가 `System Status` register의 어느 event가 OutA를 제어할지 선택.
- `Total Channels`>0 → slider enabled, `OutA Mask`가 `Gesture Status` register의 event 선택.
- 두 경우 모두 OutA를 **최상위 bit(bit15)** 로 active high/active low 설정: bit15='1'→active low, '0'→active high.
- **예시**: HOLD slider event 동안 OutA low, 그 외 high를 원하면 — slider 구성 시 `OutA Mask`가 `Gesture Status`에서 선택. OutA가 HOLD 중 low여야 하므로 active low 구성 + HOLD event 선택(`OutA Mask` 5번째 bit). 따라서 `OutA Mask`에 `0x8020` write.

> [!NOTE]
> **Event Indicator 동작 원리**: `OutA Mask`의 bit[14:0]은 Status register의 어느 이벤트 비트가 OutA를 트리거할지 선택하는 OR 마스크다. 해당 비트 중 하나라도 set되면 OutA가 활성화된다. bit15는 극성 플래그다(1=active-low, 0=active-high).
>
> `0x8020` 역산: `bit15=1`(active-low) + `bit5=1`(HOLD 이벤트 = `0x0020`) → HOLD 발생 시 OutA가 GND로 내려간다.
>
> `Total Channels` 값에 따라 소스 레지스터가 `System Status`(슬라이더 비활성) ↔ `Gesture Status`(슬라이더 활성)로 자동 전환된다. 모드 전환을 별도 처리하지 않아도 OutA 동작이 일관되게 유지된다. MCU 관점에서 OutA를 GPIO 인터럽트 핀에 연결하면 의미 있는 이벤트 발생 시에만 I²C 읽기를 트리거할 수 있어 불필요한 폴링을 제거한다.
>
> ```
>  OutA Mask (16비트)
>  ┌────────┬───────────────────────────┐
>  │ bit15  │ bit[14:0]                 │
>  │ (극성) │ (이벤트 OR 마스크)         │
>  └───┬────┴───────────┬───────────────┘
>      │                │
>      │  소스 자동 선택 (Total Channels 값)
>      │  Total=0 → System Status 비트 참조
>      │  Total>0 → Gesture Status 비트 참조
>      │                │
>      │       ┌────────▼────────┐
>      │       │ 이벤트 비트 OR  │
>      │       │ (1개라도 set?)  │
>      │       └──┬──────────┬───┘
>      │         YES         NO
>      │          │           │
>      │    [OutA 활성]  [OutA 비활성]
>      │          │
>      └──────────▶ bit15 극성 적용
>           bit15=0 → OutA HIGH (active-high)
>           bit15=1 → OutA LOW  (active-low)
>  ```
>
> 이벤트 OR → 활성 판정 → 극성 반전 → OutA 핀 출력 흐름. NO(비활성) 경로는 OutA가 반전 상태로 고정.

## 7.2 Slider

IQS323은 on-chip gesture recognition으로 slider 처리 가능. **single channel slider**로 단일 채널 on-chip tap·hold 인식 가능. Slider event는 OutA로 표시(§7.1.2). enabled 제스처는 `Gesture Status`에, touch 위치는 `Slider Position`에 보고.

### 7.2.1 Setup

- slider 사용 채널은 §5.12처럼 setup. **3개 mutual-cap 채널 slider면 TxA를 shared Tx로 사용**.
- `Slider Setup and Calibration`의 `Total Channels`=non-zero + `Enable Mask`의 `Channel X Enable` bit로 slider 채널 enable.
- `Enable Status Pointer`를 정확히 set → enabled 채널 중 어느 것이라도 touch 시 slider 활성. order code별 status pointer가 다름에 유의.
- `Delta Links`가 slider 내 채널 처리 순서 결정. `Delta Link 0` = slider의 첫 element. (예: 채널1이 slider 첫 element면 `Delta Link 0`='0x472' for Release UI order codes.)
- `Slider Resolution`이 slider position 출력 범위 정의. gesture setup register는 `Slider Resolution`에 맞게 set. touch position은 0(첫 element 시작)~`Slider Resolution`(마지막 element 끝).
- `Slider Calibration and Bottom Speed`의 `Upper Calibration Value`·`Slider Setup and Calibration`의 `Lower Calibration Value`로 slider position end-point를 물리 slider end-point에 맞게 offset.
- slider 출력 position은 `Slider Setup and Calibration`의 `Slow/Static Beta`, `Calibration and Bottom Speed`의 `Bottom Speed`, `Slider Top Speed`로 **동적 필터**(pixel/sample period 단위, Figure 7.1).
- `Slider Setup and Calibration`의 `Static Filter` bit set 시 touch 움직임 속도 무관하게 `Slow/Static Beta`로 slider position 필터.

> [!NOTE]
> **슬라이더 위치 계산 — centroid 알고리즘**: 각 채널 i의 delta 값 Δᵢ(= raw counts − LTA)를 채널 위치 인덱스로 가중 평균한다.
>
> `Position = Σ(Δᵢ × pᵢ) / ΣΔᵢ`
>
> 손가락이 채널 경계에 걸쳐 있을 때 두 채널의 Δ 비율로 서브-채널 해상도를 보간하므로, 실제 채널 수보다 높은 해상도의 위치 출력이 가능하다. `Delta Link 0`이 물리적 첫 번째 전극(p=0)에 매핑되고 이후 링크가 순서대로 p값을 증가시킨다. 채널 번호와 물리 배치가 일치하지 않는 PCB 레이아웃에서도 Delta Links 재매핑만으로 centroid 계산을 올바르게 유지할 수 있다.
>
> **동적 필터**: 손가락이 느리게 이동할 때(변화량 < `Bottom Speed`)는 `Slow/Static Beta`의 강한 평활로 노이즈를 억제하고, 빠르게 이동할 때(> `Slider Top Speed`)는 필터 강도를 낮춰 지연(lag) 없이 추적한다. `Static Filter` bit를 세우면 속도와 무관하게 `Slow/Static Beta` 고정 필터로 전환되어 진동 환경의 위치 떨림 억제에 유용하다.
>
> ```
>  Centroid 계산 예시 (3채널 슬라이더)
>
>  전극 배치:  [CH0]   [CH1]   [CH2]
>  위치 인덱스: p=0     p=1     p=2
>
>  손가락이 CH0~CH1 경계에 걸친 경우:
>    Δ0 = 80,  Δ1 = 40,  Δ2 = 0
>
>  Σ(Δᵢ × pᵢ) = (80×0) + (40×1) + (0×2) = 40
>  ΣΔᵢ        = 80 + 40 + 0              = 120
>
>  Position = 40 / 120 ≒ 0.33
>  → CH0 끝(0)과 CH1 중간(1) 사이 1/3 지점
>
>  Counts ↑
>       │  ┌──┐
>  Δ80  ┤  │CH0│
>  Δ40  ┤        ┌──┐
>       │        │CH1│
>  Δ0   ┤               ──── (CH2 반응 없음)
>       └──────────────────→ 위치
>         0       1      2
>  ```
>
> 손가락 위치에 따른 채널별 Δ 비율로 서브-채널 해상도 보간 원리.

### 7.2.2 Gestures

slider enabled 시 on-chip gesture recognition 수행. 모든 제스처는 `Gesture Enable` register로 개별 enable, `Gesture Status`에 보고. 인식 제스처: **Single Tap, Swipe, Flick, Hold**.

- gesture parameter는 **pixel·milliseconds** 단위. 어떤 gesture든 보고되려면 touch가 최소 `Minimum Time` register 값만큼 등록되어야 함(false touch 방지).

**Tap and Hold**
- **Tap**: touch가 `Minimum Time`보다 길고 `Maximum Tap Time`보다 짧으며 시작점에서 `Maximum Tap Distance` 이내 이동. tap은 감지된 cycle에서만 보고.
- **Hold**: touch가 `Minimum Time`과 `Minimum Hold Time` 둘 다보다 길고 시작점에서 `Maximum Tap Distance` 이내. hold 감지 후 release까지 계속 보고.

**Swipe and Flick**
- touch가 `Minimum Time`보다 길고 시작점에서 `Minimum Swipe Distance` 이상 이동. 조건 충족 후 `Maximum Swipe Time` 전에 release면 **flick**, 아니면 **swipe**. swipe·flick은 감지 cycle에서만 보고.

> [!NOTE]
> **제스처 파라미터 상호관계**:
>
> | 파라미터 | Tap | Hold | Swipe | Flick |
> |---|---|---|---|---|
> | Minimum Time | 공통 게이트 | 공통 게이트 | 공통 게이트 | 공통 게이트 |
> | Maximum Tap Time | 상한 (초과 시 Tap 무효) | — | — | — |
> | Minimum Hold Time | — | 추가 하한 | — | — |
> | Maximum Tap Distance | 이내 | 이내 | — | — |
> | Minimum Swipe Distance | — | — | 이상 이동 필요 | 이상 이동 필요 |
> | Maximum Swipe Time | — | — | 초과 시 Swipe | 이내여야 Flick |
>
> `Minimum Time`은 모든 제스처의 공통 선행 조건(최소 지속시간 게이트)이다. 이 값 미만의 터치는 정전기·진동·EMI 등 false touch로 간주해 어떤 제스처도 보고하지 않는다.
>
> Tap ↔ Hold 구별은 순전히 시간 기준이다. `Maximum Tap Time` 이내이면 Tap, `Minimum Hold Time` 이상까지 지속되면 Hold다. Hold는 `Maximum Tap Time`을 사용하지 않는다. Swipe ↔ Flick은 동일한 거리 조건을 통과한 뒤 `Maximum Swipe Time` 이내 release 여부로 분기한다 — Flick은 고속(단시간 + 충분한 이동) Swipe의 부분집합이다.
>
> `Slider Resolution` 변경 시 pixel 단위인 `Maximum Tap Distance`·`Minimum Swipe Distance`도 함께 재조정해야 한다.
>
> ```
>  Swipe 제스처 인식 — 채널 활성화 시계열
>
>  시간 →
>  CH0 │▓▓▓▓│░░░░░░░░░░│        터치 시작
>  CH1 │░░░░│▓▓▓▓▓▓│░░░│        중간 이동
>  CH2 │░░░░│░░░░░░│▓▓▓│        끝 도달
>       │←──────────────→│
>            총 이동 시간
>
>  ▓ = 해당 채널이 touch 상태
>  순서: CH0 → CH1 → CH2 (단방향 Swipe)
>
>  ① touch 등록 (≥ Minimum Time)
>          │
>  ② 이동량 ≥ Minimum Swipe Distance?
>          │  NO → Tap/Hold 판정으로 분기
>          │  YES ↓
>  ③ release 시점이 Maximum Swipe Time 이내?
>          YES → Flick 보고
>          NO  → Swipe 보고
>  ```
>
> CH0→CH1→CH2 순서 활성화와 이동 거리·시간 조건으로 Swipe/Flick 분기 흐름.

## 7.3 Reference UI

reference channel이 primary sensing channel의 LTA를 조정(primary가 touch/prox 상태일 때 reference channel LTA 변화량을 primary LTA에서 차감). 이로써 count drift 효과 제거.

- 예: wear-detect 응용에서 PCB·센서 element의 dielectric 파라미터가 시간에 따라 변해 성능 저하 → Reference UI로 온도·습도 인한 count drift를 보정해 온도 변화에 영향받지 않음.
- reference channel 센서는 sensing channel과 같은 조건에 노출되어야 하고, 사용자가 reference channel counts에 영향 줄 수 없어야 함.
- single reference channel은 multiple follower channel 가능. 단 follower channel은 multiple reference 불가.
- reference channel 설계 상세는 **AZD125**.

### 7.3.1 Setting Descriptions

`Channel Setup` register는 `Channel Mode`, `Reference Sensor ID`, `Follower Event Mask` 파라미터 포함. `Follower Weight`는 `Follower Weight` register에 정의.

**Table 7.1 — Reference UI Setting Descriptions**

| Setting | Description | Options |
|---|---|---|
| Channel mode | 채널을 reference/follower로 구성 | Independent / Reference / Follower |
| Reference Sensor ID | 채널이 reference로 선택되면 어느 채널이 reference 역할인지 선택 | 원하는 reference 채널 번호로 set |
| Follower Event Mask | reference channel은 follower가 prox/touch 상태일 때 ATI하면 안 됨. 이 mask로 follower의 `Prox`·`Touch` flag(`System Status`)를 선택해 reference channel ATI를 disable. **채널이 reference channel일 때만 set** | |
| Follower Weight | 채널이 follower면 reference channel 조정을 얼마나 적극적으로 추적할지 결정 | Register value / 4096 |

> [!NOTE]
> **Reference UI 동작 원리**: 온도·습도 변화는 sensing 채널과 reference 채널의 LTA를 동시에 같은 방향으로 이동시킨다. follower 채널의 LTA에서 reference 채널 LTA 변화량을 `Follower Weight / 4096` 비율로 차감하여 공통 모드 드리프트를 제거한다.
>
> `Follower Weight`의 수학적 의미는 12비트 고정소수점 gain 계수다(4096 = 2¹²). `4096`이면 reference 변화를 100% 추적해 완전 차동 보정, `<4096`이면 분수 비율만큼 느리게 추적, `>4096`이면 reference보다 적극적으로 follower LTA를 끌어당긴다.
>
> **`Follower Event Mask`는 안전장치 인터록이다**. follower가 touch/prox 상태일 때 reference 채널이 ATI를 수행하면, 실제 터치에 의한 counts 상승이 "환경 드리프트"로 오인되어 LTA가 상향 보정된다 — 터치 해제 직후 ghost prox 발생 또는 감도 급락으로 이어진다. `Follower Event Mask`에 follower의 `Prox`·`Touch` 비트를 OR하면 reference 채널 ATI가 차단되어 이 시나리오를 원천 방지한다. **채널이 reference channel일 때만 set**한다는 점에 주의.
>
> ```
>  Reference UI — 드리프트 보정 원리
>
>  온도 상승 시 (노터치 상태):
>  Counts ↑
>        │  follower(CH0) LTA ─────────────╲
>   500  ┤  ···················──────────── ╲ 함께 drift
>        │  reference(CH1) LTA·············╲╲
>   480  ┤                         (동시 상승)
>        │
>  보정 후:
>  follower LTA 보정량 = ref LTA 변화 × (FollowerWeight / 4096)
>  ┌───────────────────────────────────────────┐
>  │  ref LTA +20 상승, FollowerWeight=4096    │
>  │  → follower LTA 보정 = 20 × 1.0 = 20     │
>  │  → follower LTA 실효 드리프트 = 0 (제거) │
>  └───────────────────────────────────────────┘
>
>  채널 역할 분리:
>  ┌──────────┐  드리프트 관찰   ┌──────────────┐
>  │CH1(ref)  │ ───────────────→ │ LTA 변화량   │
>  │(환경 노출│                  │ 추출         │
>  │ 사용자   │                  └──────┬───────┘
>  │ 접촉 불가│                         │ × (Weight/4096)
>  └──────────┘                         ▼
>  ┌──────────┐               ┌──────────────────┐
>  │CH0(follower)│ LTA 갱신 ←─│ follower LTA 보정│
>  │(실제 터치│               └──────────────────┘
>  │ 감지 채널│
>  └──────────┘
>
>  Follower Event Mask 인터록:
>  CH0 Touch/Prox SET → CH1 ATI 차단
>  (터치를 드리프트로 오인 방지)
> ```
>
> Reference(CH1) LTA 변화량을 Follower(CH0) LTA에서 차감 — 공통 모드 온도/습도 드리프트 제거 원리.

### 7.3.2 Example Setup

Ch0=follower, Ch1=reference 예:

- Ch0가 follower, Ch1이 reference이므로 Ch0의 `Reference Sensor ID`='0x01'(Ch1 선택).
- `Channel Mode`='Reference'면 `Reference Sensor ID` 미사용 → Ch1의 `Reference Sensor ID`='0x00'.
- Ch1이 reference이므로 Ch0이 prox/touch일 때 Ch1 ATI를 disable하도록 `Follower Event Mask` set. Ch0의 `Prox`·`Touch` flag는 `System Status` upper byte의 1st·2nd bit → `Follower Event Mask`의 1st·2nd bit=1 → Ch1에 **0x03** write.
- `Channel Mode`='Follower'면 `Follower Event Mask` 미사용 → Ch0='0x00'.
- follower 채널에 `Follower Weight` 필수. '4096'→reference 직접 추적, >4096→적극 추적, <4096→느린 추적. AZD125 참조.

**Table 7.2 — Reference UI Example Settings**

| Setting | Channel 0 | Channel 1 |
|---|---|---|
| Channel mode | Follower | Reference |
| Reference Sensor ID | 0x01 | 0x00 |
| Follower Event Mask | 0x00 | 0x03 |
| Follower Weight | Bit value/4096 | 0x00 |

## 7.4 Release UI

long term touch·proximity 이벤트의 감지·해제를 위해 **추가 LTA(Activation LTA)** 사용. Activation LTA는 `Channel X Activation LTA` register에서 read. 표준 LTA와 달리 **채널이 prox/touch 상태여도 계속 update**. `Activation LTA Filter Betas`의 IIR beta filter로 필터.

- touch/prox 이벤트 감지 시 LTA는 frozen이나 Activation LTA는 계속 update.
- counts와 Activation LTA 차이가 `Events Enable and Activation Settling Threshold`의 `Activation Settling Threshold`보다 작은 상태가 `Release UI Settings`의 `Delta Snapshot Sample Delay` 지정 연속 샘플 수 이상이면, LTA와 counts의 absolute delta가 채널의 `Delta Snapshot` register에 기록.
- `Release UI Settings`의 `Release Delta Percentage`로 정의된 Delta Snapshot의 percentage가 touch/prox 상태 이탈에 사용:

$$\text{If } (\text{Counts} - \text{Activation LTA}) > \left(\text{Delta Snapshot} \times \frac{\text{Release Delta Percentage}}{128}\right)$$

채널이 reseed되어 touch·prox 상태 이탈.

- Release UI는 fixed threshold와 counts 비교가 아니라 **counts 변화율** 기반으로 long term touch 이벤트 감지·이탈.
- Release UI order code는 `Sensor Setup`의 `Release UI Enable` bit set으로 enable.

> [!NOTE]
> **Release UI가 필요한 이유**: 표준 방식에서 LTA는 touch 진입 직후 frozen되지만, 손이 장시간 접촉하면 피부 커패시턴스가 안정화되어 counts가 서서히 LTA 쪽으로 수렴한다 — 결국 `counts − LTA` 차이가 고정 release threshold 이하로 내려가 의도치 않게 touch 이탈이 발생한다.
>
> **Delta Snapshot 캡처 조건**: `counts − Activation LTA` 차이가 `Activation Settling Threshold` 미만인 상태가 `Delta Snapshot Sample Delay` 연속 샘플 이상 유지되면 그 시점의 `|LTA − counts|`를 Delta Snapshot으로 확정한다. 이 값은 "이 채널에서 정상 touch 시 기대되는 delta 크기"의 참조값이다.
>
> **공식 해석**: `Release Delta Percentage / 128`은 7비트 고정소수점 비율이다. 값이 64이면 Delta Snapshot의 50%, 128이면 100%를 의미한다. 고정 임계값과 달리 원래 신호 크기에 비례한 상대적 기준을 사용하므로, 채널마다 신호 크기가 달라도 동일한 퍼센트 기준으로 일관된 release 감도를 유지할 수 있다. 즉 long press 이탈의 기준이 "절대 counts 레벨"이 아니라 "처음 touch 시 확인된 delta 대비 얼마나 회복했는가"의 변화율이 된다.
>
> ```
>  Counts ↑
>        │
>   500  ┤·····┬──────────────────── 표준 LTA (touch 진입 후 frozen)
>        │     │ touch 진입
>   490  ┤     │  ╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌ Activation LTA (계속 update)
>        │     │
>   450  ┤     │      ─────────────  Counts (서서히 LTA 쪽 수렴)
>        │     │           │
>   Snap │     │    ← Delta Snapshot 확정
>   shot │     │           │  (Activation 안정 후)
>        │     │
>        │     │  Release 판정:
>        │     │  (Counts − ActLTA) > Snapshot × (RelPct/128)
>        │     │  → YES: reseed → touch 이탈
>        │
>        └─────────────────────────→ 시간
>         노터치  touch 진입    장시간 접촉
>  ```
>
> 표준 LTA(frozen) vs Activation LTA(계속 추적) 역할 비교 — Delta Snapshot 기준 상대 release 원리.

## 7.5 Movement UI

movement 감지용(wear detection 응용 — long term touch 중 채널에 movement가 보이는 경우 vs 보이지 않는 경우 구분).

- 예: 손목 착용 시계는 touch 중 counts 변동, 책상 위 시계는 touch지만 counts 변동 없음.
- Movement UI enabled 채널은 추가 LTA인 **Movement LTA** 추적. `Channel X Movement LTA` register에서 read. 채널이 prox/touch 상태여도 계속 update.
- counts와 Movement LTA 차이가 `Movement UI Settings`의 `Movement Threshold`보다 크고 `Movement Debounce Enter` 지정 연속 샘플 이상이면 `Movement Status`의 `Channel X Movement Status` bit set.
- 차이가 `Movement Threshold`보다 작은 상태가 `Movement Debounce Exit` 이상이면 clear.
- movement는 counts의 유의미한 변동으로 표시. movement 중 `Channel X Movement Status`가 계속 set/clear. movement 정지 시 Movement LTA가 counts 값에 수렴하고 bit clear.
- `Movement Status` bit가 `Movement Timeout` register보다 오래 clear면 채널 reseed, touch·prox 상태 clear.
- Movement UI enabled 채널은 movement 있으면 touch 상태 유지, movement 없으면 touch 이탈·외부 환경 재calibrate.
- Movement LTA는 `Movement LTA Filter Betas`의 IIR beta filter로 필터. `Movement Threshold`+Movement LTA Betas로 touch 상태가 timing out·reseeding되지 않도록 필요한 movement량 조절.
- Movement UI order code는 `Sensor Setup`의 `Movement UI Enable` bit set으로 enable.

> [!WARNING]
> Movement UI는 ULP 모드와 함께 사용 금지. 자동 전력 모드 전환은 'Automatic No ULP'로 설정. (원문 §5.5 각주)

> [!NOTE]
> **Movement LTA와 Movement Threshold의 관계**: Movement LTA는 touch 상태에서도 IIR 필터로 counts를 계속 추적한다. Movement LTA가 counts에 수렴하는 속도는 `Movement LTA Filter Betas`(IIR beta)로 결정된다. beta가 크면(느린 추적) 작은 움직임도 Movement LTA와 차이를 만들어 낮은 threshold로도 movement 감지가 민감해진다. `Movement Threshold`와 IIR beta는 서로 trade-off 관계이며 함께 조정해야 한다.
>
> **Enter/Exit dual-debounce 구조**: Enter와 Exit 모두 동일한 `Movement Threshold`를 사용하되 `Movement Debounce Enter`와 `Movement Debounce Exit`를 분리하여 적용한다. 히스테리시스 임계값을 별도로 두는 방식이 아니라, 동일 임계값에 대해 진입과 해제의 debounce 카운터를 독립적으로 조정하는 **dual-debounce 비교기** 패턴이다. Enter debounce와 Exit debounce를 분리함으로써 진입은 민감하게, 해제는 느리게(또는 그 반대로) 독립 조정할 수 있다.
>
> **`Movement Timeout` → reseed**: `Movement Status` bit가 `Movement Timeout`보다 오래 clear이면 채널 reseed가 트리거된다. "정적 접촉은 진짜 착용이 아닌 물체 거치"로 간주하는 wear-detect 의미론이다. ULP 모드 금지 조건은 ULP에서의 긴 샘플 간격이 Movement debounce 타이밍을 틀어지게 만들어 Movement LTA 추적의 시정수가 의도와 달라지기 때문이다.
>
> ```
>  [착용 중 — counts 변동 있음]
>  Counts ↑
>        │  ~~~~~~~~~~~~~~~~~~~  ← Counts (맥박·움직임으로 출렁)
>   490  ┤  ╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌  ← Movement LTA (IIR 추적)
>        │  │← 차이 > Threshold│
>        │  Movement Status = SET → touch 유지
>        └──────────────────→ 시간
>
>  [책상 위 거치 — counts 변동 없음]
>  Counts ↑
>        │  ───────────────────  ← Counts (정적, 변동 없음)
>   490  ┤  ╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌  ← Movement LTA (Counts에 수렴)
>        │  │차이 < Threshold   │
>        │  Movement Status = CLEAR → Timeout 후 reseed → touch 이탈
>        └──────────────────→ 시간
>  ```
>
> 착용(counts 출렁 → Movement 유지) vs 거치(counts 정적 → Timeout reseed) 대비.

## 7.6 Watchdog Timer

IQS323은 hardware watchdog timer 구현. kick되지 않으면 **255 ms 후 expire**하고 software reset 트리거.

- I²C 통신 중 byte 단위 read·write가 일어날 때마다 IQS323이 watchdog kick. 따라서 master가 I²C START condition을 보내고 I²C transaction을 완료하지 않으면 IQS323은 255 ms 후 reset.
- I²C transaction은 master가 §8.9처럼 통신을 종료할 때 완료.
- communication window 밖에서는 IQS323이 매 cycle 자동으로 watchdog kick. master의 수동 kick 불필요.

> [!NOTE]
> **Watchdog 동작 요약**: kick 조건은 두 가지다.
>
> 1. **communication window 내**: I²C byte 단위 read/write가 발생할 때마다 자동 kick
> 2. **communication window 밖**: IQS323이 매 cycle 자동으로 kick (master 개입 불필요)
>
> 주의할 케이스는 master가 START를 보낸 뒤 transaction을 완료하지 않는 경우다 — 이때는 kick이 발생하지 않아 255 ms 후 SW reset이 트리거된다. I²C 통신 도중 MCU 예외·timeout 등으로 transaction이 중단되면 IQS323이 reset되므로, 펌웨어에서 I²C transaction을 반드시 완료(STOP 또는 REPEATED START 후 완료)해야 한다.
>
> ```
>  [정상 통신 — Watchdog 유지]
>
>  MCU ──START──byte R/W──byte R/W──STOP──
>                │           │
>               kick        kick      ← 매 byte마다 자동 kick
>  타이머 ─┬────────────┬───────────────
>          reset       reset     (255ms 만료 없음)
>
>  [비정상 — transaction 미완료]
>
>  MCU ──START──(MCU 예외 발생, STOP 없음)
>                │
>               kick (마지막)
>  타이머 ─┬──────────────────────────────
>          reset    ← 이후 kick 없음
>                          │
>                    255ms 후 만료
>                          │
>                          ▼
>                   SW reset (IQS323 재시작)
>  ```
>
> 정상 I²C 완료(kick 연속) vs START 후 중단(kick 단절 → 255ms 후 리셋) 흐름 대비.
