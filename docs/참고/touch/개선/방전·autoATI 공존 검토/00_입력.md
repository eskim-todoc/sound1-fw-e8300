# 00 · auto-ATI 중 CRX0 수동방전 공존 — 오케스트레이터 입력 (공통)

> **TL;DR**: 모든 페르소나의 공통 입력. ESD 물리누적이 미지수라 보수적으로 수동방전(CRX0 VSS 200ms + CRX1 CalCap)을 유지하면서 auto-ATI Full을 함께 쓸 수 있는지, 어려우면 대안은 무엇인지 검증한다. 핵심 긴장: **측정 보정 레이어(auto-ATI/Re-ATI)와 물리 전하 제거 레이어(채널 토글 방전)가 같은 0x30을 두고 충돌하는가.**

> [!IMPORTANT]
> 근거: [은수님 안 평결·하이브리드 권고](../은수님%20안%20평결·하이브리드%20권고.md) · [4_타당성검증 B1~B6](../생각정리/4_타당성검증.md) · [펌웨어 분석](../펌웨어%20구현·시퀀스%20분석.md) · [데이터시트/](../../데이터시트/) · 코드 `tdc_drv_iqs323.c`(discharge_crx0 938·sensor_setup 440·apply_settings 1023). 데이터시트·코드 근거, 추정은 "확인 필요".

---

## 1. 배경

하이브리드 권고는 **ATI Full 복귀**로 드리프트(이슈 6)를 해결하면 200ms 수동방전·CalCap을 폐기 검토하자고 했다. 그러나 검증(A6)에서 **"auto-ATI는 LTA 재캘리브레이션, 수동방전은 물리적 전하 제거로 메커니즘이 상이"** → ESD가 LTA 드리프트가 아니라 **물리 전하 누적**이면 auto-ATI가 방전을 대체하지 못함이 드러났다. ESD 정체가 미지수인 현 시점, **보수적으로 방전을 유지하면서 auto-ATI를 도입**할 수 있는지가 본 검토의 질문.

## 2. 현재 코드 사실 (출발점)

- **수동방전** `discharge_crx0()`(`drv.c:938`): 200ms 폴링마다 `0x30 LSB 0x02`(CRX0 disable+VSS) → `0x01`(enable+ctx0) 토글. verify 없음.
- **CRX1 CalCap 더미**(`sensor_setup` 479~510): CH1을 내부 CalCap 부하로 활성(measurement cycle 유지) + **CH1 ATI Disabled**(전역 ATI_ERROR 회피).
- **현재 ATI**: CH0·CH1 모두 ATI Mode=**Disabled**(0x36=0x0408). auto-ATI/Re-ATI 비동작.
- **방전 전제**: CRX0 방전(CH0 disable 순간)에도 CalCap CH1이 cycle 유지 → RDY 먹통 방지.

## 3. 검증 질문 (Q)

- **Q1**: auto-ATI Full 사용 중 200ms마다 CRX0 enable 토글(0x30 0x02↔0x01)이 **auto-ATI/Re-ATI 수렴을 교란**하나? (ATI 진행 중 채널 disable 시 거동 — 02 §5.9~5.11)
- **Q2**: 방전 동안 CH0 측정 공백(CalCap CH1이 cycle 유지) 시 **CH0 LTA·판정·ATI**에 영향? auto-ATI Full에서 CH1 CalCap을 **CH1만 ATI Disabled + CH0만 Full**로 둘 수 있나?
- **Q3**: 방전 후 enable 시 카운트 튐이 **LTA를 흔들어 auto Re-ATI를 재트리거**(노터치 카운트가 ATI Band 이탈)하나? 터치-방전-Re-ATI 진동 위험?
- **Q4**: `0x30 LSB` 토글(0x02↔0x01)이 auto-ATI 관련 비트나 다른 Sensor Setup 비트를 건드리나? (ATI Setup은 0x36 별개지만, 0x30 enable·linearise·invert 비트 — B2 유형 충돌 점검)
- **Q5**: "ESD 물리누적 방전"과 "auto-ATI 드리프트 보정"은 **다른 레이어**인가? 방전이 정말 auto-ATI로 대체 불가한 고유 기능인가? (ESD=IC 입력 물리 전하 vs LTA 드리프트)
- **Q6 (대안)**: 공존이 어려우면 — ① auto-ATI/Re-ATI 진행 중 방전 보류(시간분리) ② 방전 빈도 하향(200ms→?) ③ Re-ATI 억제(자동 끄고 부팅 1회 ATI + 수동 Re-ATI) + 방전 유지 ④ ESD 실측 후 방전 제거/유지 결정 ⑤ HW 방전(직렬저항·방전 경로) ⑥ 방전을 채널 enable 토글이 아닌 Inactive Rxs(Pattern Def 0x34) 등 다른 경로로.

## 4. 제약

- order 001=Release UI. self-cap 터치 시 counts 감소. 웜부트 MCLR POR(B4).
- B1: 진짜 baseline 오염원=Reseed. B2: 0x30 LSB는 INACTIVE_RXS 의미로 코드가 씀(데이터시트 A.5 비트정의와 해석 차이 — 실칩 미확정).
- 현재 ATI Disabled가 채택된 실증 이유: **Full auto-ATI 발동 시 I²C 무응답 사례**(드라이버 주석). auto-ATI 도입 시 통신관리 선행 필요.
