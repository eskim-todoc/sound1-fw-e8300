# 03 · 종합 평결 · 대안 권고

> **TL;DR**: **auto-ATI Full 상시 + 200ms 방전 직접 공존은 조건부불가**(Re-ATI 진동·I²C hang·0x30 비트 충돌). **단 충돌 근원이 "런타임 자율 Re-ATI" 하나뿐 → auto Re-ATI만 끄면(부팅 1회 ATI + Disabled 고정 + LTA 추적) 공존 가능.** 레이어 분리(방전=핀 물리전하, auto-ATI=IC 내부 보정)는 참이라 ESD 물리누적이면 방전은 고유 기능. **🔴 단 현재 방전 코드(0x30 0x02)는 데이터시트상 VSS가 아니라 Linearise — 방전이 진짜 방전인지부터 실측해야.**

## 1. 페르소나 verdict

| 페르소나 | 공존 | 권장 대안 |
|---|---|---|
| C1 데이터시트 | 조건부불가 | Re-ATI 억제 + 방전 0x34 경로 |
| C2 코드 통합 | 조건부불가 | 부팅 1회 Full + Re-ATI 억제 + 시간분리, 방전 유지 |
| C3 Adversarial | 조건부불가 | 시간분리+빈도하향, ESD 실측 후 방전 제거 가능 시 auto-ATI 단독 |
| C4 대안 설계 | 조건부불가 | ③Re-ATI 억제 ⊕ ④ESD 실측 ⊕ ⑤HW 방전 |
| C5 정합·레이어 | 조건부가능 | 방전 0x30 RMW/0x34 분리 + 실측 2건 후 결정 |

→ **직접 공존 조건부불가(4), 경로 분리 시 조건부가능(1).**

## 2. 핵심 발견

1. **충돌 4축**: (가) 0x30 LSB 공유(방전 토글이 Linearise·Invert·Release UI·Enable 비트 blind write) (나) 방전 카운트 튐 → Re-ATI 진동 (다) ATI 수렴 중 채널 disable 교란 (라) **Full ATI I²C 무응답**(현 펌웨어가 ATI Disabled 택한 실증 이유).
2. **🔴 치명(C3)**: I²C hang 중 방전 disable(0x02)만 들어가고 복원(0x01)이 RDY 타임아웃에 막히면 **CH0 영구 disable + 터치 먹통**, verify 없어 SW 감지·복구 불가.
3. **충돌 근원은 "런타임 자율 Re-ATI" 하나**(C4·W4): auto-ATI(부팅 캘리브레이션)와 auto-Re-ATI(런타임 자동 재보정)를 분리해 **후자만 끄면 진동(나·다) 원천 제거** → 공존 가능.
4. **레이어 분리 참**(C5·W3): 방전(핀 전기상태 ①)은 auto-ATI(IC 내부 ②③)로 **대체 불가한 고유 기능** — 단 ESD가 물리누적일 때만.
5. **🔴 B2 라이브 발견**: `0x30 0x02`는 데이터시트상 **Linearise(VSS 아님)**. **현재 방전의 물리 효력 미검증** — VSS는 0x34, 핀 enable은 0x33.

## 3. 공존 평결

- **"auto-ATI Full 상시" + 200ms 방전**: ❌ 조건부불가. Re-ATI 진동·I²C hang·비트 충돌.
- **"부팅 1회 ATI + auto Re-ATI 끔 + LTA 추적" + 방전**: ✅ 조건부가능. 충돌 근원(Re-ATI) 제거 + 통신관리·방전 안전화 전제.

## 4. 대안 권고 (단계, 실측 게이트 중심)

| 순서 | 작업 | 목적 |
|---|---|---|
| **0** | 통신관리 선행(RDY 핸드셰이크·타임아웃) | I²C hang(축 라)·CH0 영구 disable 방지 |
| **1 (실측)** | **🔴 방전 물리효력**: `0x30 0x02`가 실칩 핀 VSS 단락인가(B2). + **ESD 정체**: LTA 드리프트 vs 핀 물리누적 | 방전 존폐의 대전제 |
| **2** | **auto Re-ATI 억제**: 부팅 노터치 게이트 후 ATI 1회(Full 수렴) → ATI Disabled 고정 + 수동 Re-ATI만 + LTA 추적(비대칭 BETA) | 진동 원천 제거, 공존 성립 |
| **3a** | ESD = LTA 드리프트 → **방전 폐기**(auto-ATI/LTA가 해소) | 공존 문제 소멸 |
| **3b** | ESD = 물리누적 → **방전 유지 + 안전화**: ① 0x30 blind→RMW(또는 0x34 경로) ② verify+강제 복원 ③ 빈도 200ms→2~5s | 비트 충돌·영구 disable·교란 완화 |
| **4** | (물리누적 심함) **HW 방전**(직렬저항·블리더) | 0x30 토글 제거 = 충돌 4축 근본 소멸 |

## 5. 은수님 질문에 대한 답

> "ESD 물리누적 미지수면, CRX1 CalCap 살리고 CRX0 수동방전을 auto-ATI 중에도 할 수 있나? 어려우면?"

- **CRX1 CalCap**: 방전(채널 토글)을 유지하는 한 measurement cycle 유지용으로 **그대로 살림**. 방전 폐기 시 CalCap도 불요.
- **auto-ATI 중 방전 가능?**: **"Full 상시"로는 어렵다**(Re-ATI 진동·I²C hang). **"부팅 1회 ATI + auto Re-ATI 끔"이면 가능** — 충돌이 자율 Re-ATI 하나라 그것만 끄면 방전과 안 싸움.
- **어려우면(권장)**: ① 통신관리 선행 ② **먼저 "현재 방전이 진짜 핀 VSS 방전인지"(0x30 0x02) 실측** — 아니면 0x34/0x33으로 고쳐야 진짜 방전 ③ ESD 정체 실측(드리프트면 방전 자체가 불필요) ④ 물리누적 확정 시 방전 안전화(RMW·verify·빈도) 또는 HW 방전.

**핵심**: 은수님 직관(방전 유지하며 auto-ATI)은 **"auto Re-ATI만 끄면 실현 가능"**. 단 **"현재 방전이 ESD를 실제로 빼고 있는가"부터 의심·실측**해야 한다(0x30=VSS 미확정). 방전 폐기 여부는 ESD 정체 실측이 가른다.
