# IQS323 터치 제어 재설계 — 분석·권고 (정식)

> **TL;DR**: HW·SW·데이터시트 분석 위에서 6관점 zero-base 재설계를 발산·토론·검증한 결과, **진짜 문제는 `Reseed`가 부팅/모드전환 시점 counts로 LTA를 seed해 진입 baseline을 오염시키는 것**(이슈 1~4)으로 수렴. 권고는 **① Reseed를 "노터치 게이트" 뒤로 지연(SW only·최우선) → ② FIXED를 ATI Full로 복귀(이슈 6·8·9) → ③(선택) 이벤트모드 → ④(보류) Release UI**. 전면 재작성 불필요. 각 단계는 독립 롤백 가능하며 실측 게이트 3종이 선행한다.

> [!NOTE]
> 탐구 전 과정·근거는 [생각정리/](생각정리/) 참조: [00 방법론](생각정리/00_방법론·진행방식.md) · [01 문제·제약](생각정리/01_문제정의·제약·평가축.md) · [1_설계안 P1~P6] · [2_비판 P1~P6] · [3 쟁점해결](생각정리/3_쟁점해결토론.md) · [4 타당성검증](생각정리/4_타당성검증.md) · [5 종합결론](생각정리/5_종합결론.md). HW는 [회로 구성·분석](회로%20구성·분석.md), SW는 [펌웨어 구현·시퀀스 분석](펌웨어%20구현·시퀀스%20분석.md).

## 1. 진단 — 무엇이 진짜 문제인가

요구사항 문서의 이슈 9건은 서로 얽혀 보이지만, 검증 결과 **두 뿌리**로 정리된다.

| 뿌리 | 증상(이슈) | 진짜 원인 |
|---|---|---|
| **A. 진입 baseline 오염** | 1~4 (터치/부팅 중 초기화 → 터치 먹통) | `apply_settings` Reseed(`drv.c:1134`)·`func_sleep` reseed(`main.c:880`→`drv.c:932`)가 **손가락 닿은 시점 counts로 LTA를 seed**. (auto-ATI 아님 — 현 FIXED가 auto-ATI 결과를 덮어쓰므로) |
| **B. baseline 드리프트·변동** | 6·8·9 (드리프트→먹통·카운트 340~660 변동·threshold 들쭉날쭉) | **autoATI 포기(FIXED)** 로 IC 자동 충/방전 보정이 사라짐 → 200ms 방전으로 우회했으나 카운트 절대값이 부팅마다 변동 |

> [!IMPORTANT]
> **현재 구현은 "틀린" 것이 아니다.** self-cap 유지(회로 제약)·FIXED 채택(터치 중 autoATI 회피)은 합리적 선택이었다. 다만 **baseline을 새로 잡는 순간(Reseed)에 노터치 여부를 확인하지 않는 한 곳**이 비어 있었고, autoATI를 통째로 버리며 드리프트 보정까지 함께 잃었다.

## 2. 권고안

### 권고 A (뿌리 A 해소) — Reseed를 노터치 게이트 뒤로
- 모든 LTA 시딩(`apply_settings` Reseed·`func_sleep` reseed)을 **"`ch0_touch==0` 연속 N tick 확인 후 발행"** 으로 변경.
- 상시 접촉 시: timeout 강제 시딩(둔감 baseline) + dirty 플래그 + **해제 순간 1회 recapture**.
- 기존 `boot-touch-ignore` 가드(`tdc_touch.c:319~325`)를 "해제 보조"에서 **"baseline 확정 게이트"로 승격**.
- **SW only, 데이터시트 비의존, 회귀 위험 최소.** 이슈 1~4를 구조적으로 해소.

### 권고 B (뿌리 B 해소) — FIXED → ATI Full 복귀 + 터치중 차단
- ATI Mode를 Disabled(0x08) → **Full**로 복귀. IC 자동 보정으로 드리프트·카운트 변동(이슈 6·8·9) 정규화.
- **터치 중 Re-ATI 차단**: ① 터치 중 LTA frozen(자연 방어) ② ATI Band Large로 터치 delta 트리거 확률 저감 ③ 수동 ATI/Re-ATI는 노터치 게이트 후만.
- **self-cap counts 부호를 그대로 비교**하면 Linearise/Invert 불요 → **0x30 방전 충돌(B2)·Release UI 복잡도 회피**.
- ATI Full 안정화 후 **200ms CRX0 방전·CalCap 더미 점진 폐기 검토**(드리프트 보정을 IC로 환원).

## 3. 단계적 로드맵

| Phase | 작업 | 위험 | 선행 게이트 |
|---|---|---|---|
| **0** | 정정: [펌웨어 분석 §11](펌웨어%20구현·시퀀스%20분석.md)(B4 웜부트), 코드 주석 불일치, `write_and_verify` 값 비교 | 무위험 | — |
| **1** ★ | **권고 A** (Reseed 노터치 게이트 + boot-touch-ignore 승격) | SW only | (실측1) |
| **2** | **권고 B** (ATI Full 복귀 + 터치중 차단) | SW, 중 | (실측1) 확정 |
| **3** 선택 | RDY edge ISR 이벤트모드(폴링 폐지) — power button(DIO16) 통합 | SW, 가능(B5) | wake 실측 |
| **4** 보류 | Release UI(장기터치 해제 보조) | 높음 | (실측3) |

- **전원**: Channel Timeout 채택 시 Auto No ULP 강제(B6) → (실측2). 초과 시 ULP+SW롱터치 fallback.

## 4. 실측 게이트 (선행 필수)

| # | 실측 | 무엇을 | 결정 |
|---|---|---|---|
| 1 | **오염 실채널** | 터치한 채 MCLR 부팅 시 auto-ATI vs FIXED+Reseed 후 LTA/Counts RTT 캡처 | Phase 1·2 착수 |
| 2 | **self-cap 1ch 전류·절전예산** | Event mode 실보드 NP/LP 전류 + 인공와우 절전 사양 | No-ULP/Channel Timeout |
| 3 | **0x30 LSB Linearise 비트** | 실칩이 데이터시트 A.5 매핑을 따르는지 | Release UI 채택 |

## 5. 채택하지 않은 선택지와 이유

| 선택지 | 판정 | 이유 |
|---|---|---|
| **전면 zero-base 재작성** | 기각 | 6비판 만장일치 반대 — 회귀 격리 불가. 진짜 문제는 국소(Reseed) |
| **Reference UI (CRX1 드리프트 보정)** | 기각 | 회로 부적합(C52=100nF DC차단·J4 미연결·§7.3 비접촉 요건). 드리프트는 ATI Full 단독 |
| **mutual-cap (TxA 구동)** | 보류 | 전극 쌍 HW 필요(현 J3 단일 패드). ATI Full(self)이 더 안전한 1순위 |
| **Release UI 주력** | 격하→보류 | 진입 baseline 못 풂(B3) + 0x30 방전 충돌(B2). 해제 보조로만, 실측 후 |
| **웜부트 LTA 보존 의존** | 조건부 | 현 코드는 웜부트 POR(B4). reset-cause 분기 인프라 신규 필요 |
| **HW 변경(페라이트·guard·470Ω·전극)** | 별도 트랙 | 시간축 리스크 큼. SW 단계와 분리, 회로 문서 §12 개선 검토로 이관 |

## 6. 리스크·롤백

- 각 Phase 독립 배포·롤백. Phase 1(Reseed 게이트)은 실측 전에도 안전(어느 오염원이든 노터치 게이트는 무해).
- 상시 접촉 영구 미확정 → timeout fallback 부등식 고정.
- 게이트 임계(N tick)·ATI Band는 실측 튜닝 의존 → 상대(delta/LTA) 판정 권장.
- 자동 Re-ATI 내부 LTA 갱신 거동 단정 불가 → RTT 모니터.

## 7. 다음 행동

1. **(은수님)** 실측 1·2 환경 준비 — 터치한 채 부팅 RTT 캡처, self-cap 1ch 전류계 측정.
2. **(Phase 0)** 문서·코드 정정 — 본 권고 승인 시 즉시 가능(무위험).
3. **(Phase 1 설계)** Reseed 노터치 게이트 상세 설계 → 4단계 프로세스로 별도 작업화.
