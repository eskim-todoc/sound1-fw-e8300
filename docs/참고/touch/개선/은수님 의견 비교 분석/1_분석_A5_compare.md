# A5 · 이전 결론 대조 (Q8)

> **TL;DR**: 두 안은 **목표(ATI Full 복귀·빠른 수렴)가 사실상 같고, 충돌은 단 한 점 — "LTA를 새로 잡는 순간(seed/Reseed/ATI)에 손가락 여부를 보느냐"** 다. 은수님 안은 안 보고 "자기정상화"로 사후 수렴시키려 하고, 이전 결론(B1/S2)은 그 순간을 **노터치 게이트로 막는다**. 핵심 쟁점 M6/Q3에서 은수님 7단계의 자기정상화는 **데이터시트상 부분적으로만 성립**한다 — 터치 인식(=LTA frozen)의 전제가 "delta가 threshold를 넘었을 때"인데 부팅 baseline=터치면 delta≈0 → **frozen이 걸리지 않아 LTA가 터치 카운트를 학습**할 위험이 있다(02 §5.5·5.8). 단 self-cap 부호 덕에 손 떼면 counts↑ → delta가 음수→0 부근 → 곧바로 stuck은 아니나, ATI Disabled 현 펌웨어에선 seed 시점 1회가 baseline을 결정해 버린다. **결론: 이전 결론 우세(노터치 게이트가 더 안전·결정적), 은수님 안은 "게이트 추가 + 빠른 BETA"를 받아들이면 거의 동일 수렴 → 하이브리드가 최적해.** 은수님의 빠른 BETA·ATI Full·드리프트 해소 통찰은 이전 결론의 약점(수렴 속도·과도구간)을 정확히 보완한다.

> [!IMPORTANT]
> 근거: 데이터시트 [02 §5.5·5.5.1·5.6·5.8·5.9·5.10·5.11](../../데이터시트/02_proxfusion동작.md), 코드 `tdc_drv_iqs323.c:1128·1134·1142`·`tdc_touch.c:216·318-325`, 이전 검증 [4_타당성검증 B1·B4](../생각정리/4_타당성검증.md)·[5_종합결론 S2](../생각정리/5_종합결론.md). 추정은 "확인 필요" 표기. 제약: order 001=Release UI, self-cap 터치 시 counts 감소, 웜부트 MCLR POR(B4).

## 1. 임무 — 무엇을 대조하는가

| | 은수님 안 | 이전 결론 (B1 / S2) |
|---|---|---|
| **auto-ATI** | **다시 켠다 (Full)** | **다시 켠다 (Full)** ← 동일 |
| **터치 중 ATI/seed** | **허용**. 터치 카운트로 MULT/COMP 세팅 후 **자기정상화**로 회복(7단계) | **차단**. baseline 갱신(Reseed·ATI All)을 **노터치 게이트 뒤로 지연** |
| **수렴 가속** | **빠른 BETA**로 LTA가 노터치 카운트를 빠르게 추적 | 명시 안 함 (게이트로 시점 자체를 제어) |
| **드리프트** | auto-ATI가 해결 → 수동 방전 불요 | ATI Full 복귀로 정규화 (이슈6·8·9), 방전 점진 폐기 검토 |
| **상시접촉/부팅터치** | 자기정상화가 처리한다고 봄 | 게이트 + timeout fallback + 해제 순간 recapture |

→ **공통분모가 매우 크다.** 충돌은 "터치 중 seed 허용 + 자기정상화" vs "노터치 게이트". 이 한 축이 Q8의 전부다.

## 2. 명제 검증 (대조 관점) — M1·M2·M3·M4·**M6(핵심)**·M8

### M6 (핵심, Q3) — "터치 지속 부팅 → 해제 전까지 LTA 멈춤 → 노터치 시 추적(자기정상화)"

은수님 안의 성패를 가르는 명제. **데이터시트로 분해하면 전제가 깨진다.**

- **frozen의 전제 = 터치 *인식***: 02 §5.5 "LTA는 touch·proximity 이벤트 중 frozen", §5.8 보충 "터치 상태에서 LTA가 계속 갱신되면 터치된 counts를 기준선으로 학습 → 떼어도 미인식". 즉 frozen은 **`(LTA − Counts) > Threshold`로 터치가 *판정된* 뒤**에만 걸린다(02 §5.9 판정식, System Status CHx Touch bit set 시).
- **부팅 baseline=터치면 delta≈0**: MCLR POR(B4) 직후 seed(또는 ATI 후 Reseed) 시점에 손가락이 닿아 있으면, 그 터치 카운트가 곧 LTA가 된다 → `LTA ≈ Counts` → `delta ≈ 0 < Threshold` → **터치 미인식 → CHx Touch bit 0 → LTA frozen 안 걸림**. 이전 결론 B1·B3가 지목한 바로 그 구멍.
- **따라서 은수님 7단계의 "해제 전까지 LTA 멈춤"은 성립하지 않을 수 있다**: frozen이 안 걸린 상태에서 LTA는 (느리든 빠르든) 터치 카운트를 계속 추적한다. 손을 떼면 counts↑(self-cap, 02 §5.7) → 이번엔 `Counts > LTA` → delta 음수 → 역시 터치 미인식 → LTA가 더 큰 노터치 카운트를 추적 → **결과적으로 노터치(500)로 수렴은 한다.** 여기까진 은수님 4단계와 일치.
- **그러나 결정적 차이 — "수렴 도중" 구간**: 손 떼는 순간부터 LTA가 500에 도달하기 전까지 LTA<실제 노터치 counts. 이 과도 구간에서 **진짜 터치가 들어오면** counts가 (이미 낮은) LTA 부근으로 떨어져 delta가 충분히 안 생겨 **터치 미인식**(M5/Q4 부작용과 동일 메커니즘). 빠른 BETA가 이 구간을 짧게 만들수록 완화되나 0은 아니다(확인 필요 — 실측).

> [!WARNING]
> **자기정상화는 "결국 수렴"은 맞지만 "그 사이 안전"은 보장 못 한다.** 부팅 직후~손 뗌~LTA 수렴까지의 과도 구간에서 터치 미인식/지연이 발생할 수 있고, ATI Disabled 현 펌웨어처럼 **seed가 1회성**이면 그 1회가 터치 카운트면 baseline이 오염된 채 고정된다(B1). 이전 결론의 노터치 게이트는 이 과도 구간 자체를 제거한다 — 우열의 핵심.

### M1 (Q1) — 터치 카운트로 MULT/COMP 세팅이 안전한가

- auto-ATI Full은 측정 counts를 ATI Target(Sound1 400, 02 §5.9)으로 정규화한다. 터치 중이면 self-cap counts가 감소(300 등)한 상태에서 보정 → MULT/COMP가 **노터치보다 높은 감도 쪽**으로 잡힌다. 손 떼면 counts가 ATI Target을 넘어설 수 있고, 02 §5.10 Re-ATI Boundary(`Target ± ATI Band`) 밖이면 **자동 Re-ATI 트리거 또는 ATI Error**(02 §5.11). 즉 "적절히 세팅"은 노터치 전제에서만 성립 — 터치 중 보정은 **자동 재진동(Re-ATI loop) 위험**(Q5). 이전 결론이 "터치 중 Re-ATI 차단"을 명시한 이유와 정확히 맞물린다.

### M2·M3 (Q2) — LTA seed 값, 노터치 추적

- ATI Full 완료 직후 IC는 Reseed에 준하는 LTA 시딩을 한다(02 §5.5.1 "최신 counts로 LTA seed"). 현 코드는 ATI Disabled라 `apply_settings`의 **명시적 Reseed**(`tdc_drv_iqs323.c:1134`)가 그 역할 — **seed 시점 counts가 LTA**. 터치 중이면 터치 카운트가 seed됨(B1). 손 떼면 추적은 하나(M3 부분 성립), **seed 1회가 baseline을 결정**하는 ATI Disabled 구조에선 추적 BETA만으로는 빠르게 못 따라잡을 수 있다(BETA 현재값 reset 0 — 확인 필요).

### M4 — 터치 인식 시 LTA frozen

- 사실(02 §5.5). 단 **M6에서 본 대로 "인식"이 선행 조건** → 부팅 터치는 인식이 안 돼 frozen도 안 걸리는 게 문제. M4 자체는 옳으나 은수님 7단계 논리의 약한 고리.

### M8 (Q7) — auto-ATI가 드리프트 해결 → 수동 방전 불요

- **이전 결론과 완전 일치**(5_종합결론 §2·§7: ATI Full 복귀 → 200ms 방전 점진 폐기 검토). 이건 충돌이 아니라 **양 안의 합의점**. 은수님 9단계가 옳다.

## 3. 충돌 해소 — 어느 게 옳은가

| 쟁점 | 판정 | 근거 |
|---|---|---|
| auto-ATI Full 복귀 | **양 안 합의** | 02 §5.9 정규화, 5_종합결론 Phase 2 |
| 빠른 BETA로 수렴 가속 | **은수님 통찰 채택** (이전 결론이 빠뜨린 보강) | 02 §5.6 IIR β, 과도구간 단축 |
| 드리프트·방전 폐기 | **양 안 합의** (M8) | 5_종합결론 §7 |
| **터치 중 seed 허용 vs 노터치 게이트** | **이전 결론 우세** | M6 frozen 전제 붕괴(§2)·B1 seed 1회 오염·과도구간 터치 미인식. 게이트가 결정적·실측 비의존 |
| 상시접촉/부팅터치 처리 | **이전 결론 우세** | 자기정상화는 "결국 수렴"뿐, 게이트는 즉시 안전 + timeout fallback |

**종합 우열: 이전 결론(B1/S2) ＞ 은수님 안(순수 자기정상화).** 단 격차는 "노터치 게이트 한 줄" 뿐 — 은수님 안에 게이트를 더하면 역전된다.

## 4. 하이브리드 (권장 최적해)

은수님 안의 강점(ATI Full·빠른 BETA·드리프트 해소·절전 단순화)을 **전부 살리고**, 유일한 약점(터치 중 seed)을 이전 결론의 게이트로 막는다.

1. **ATI Mode = Full 복귀** (은수님 1·9, 이전 Phase 2 합의) — 정규화로 카운트 변동·드리프트 해소.
2. **baseline 갱신(자율 auto-ATI 결과 채택·Reseed·ATI All)을 노터치 게이트 뒤로** (이전 S2): `ch0_touch==0` 연속 N tick 확인 후에만 seed. 현 `boot_touch_ignore`(`tdc_touch.c:318-325`)를 seed 게이트로 **승격**.
3. **빠른 BETA** (은수님 6): 게이트 통과 후 노터치 수렴을 가속 + 게이트 미통과 시 과도구간 최소화. Fast Filter Band(02 §5.6)와 병행해 터치 흡수 부작용 경계(Q4 — A3 관점, 확인 필요).
4. **터치 중 Re-ATI 차단** (이전): ATI Band/Channel Timeout로 인한 터치 중 자동 재보정 억제(02 §5.10, 코드 `tdc_drv_iqs323.c:1142` CH Timeout Disable 유지) — M1/Q5 진동 방지.
5. **상시접촉 fallback**: 게이트가 timeout이면 강제 seed 후 해제 순간 recapture (이전 S2).

> [!NOTE]
> 하이브리드는 본질적으로 **5_종합결론 S2(ATI Full 게이팅) + 은수님 빠른 BETA**다. 은수님 안은 S2에서 "게이트"만 빼고 "BETA"를 더한 형태로 볼 수 있으며, 게이트를 되돌려 넣으면 두 안이 한 점에서 만난다.

## 5. 발견 (Findings)

- **두 안의 목표는 동일**(ATI Full·빠른 수렴·드리프트 해소). 충돌은 "seed 시점 손가락 여부 확인" 단 한 축.
- **은수님 자기정상화(M6/Q3)는 데이터시트상 전제가 깨진다**: frozen은 "터치 인식 후"에만 걸리는데 부팅 터치는 delta≈0이라 인식 안 됨 → frozen 미발동 → seed/추적이 터치 카운트를 baseline으로 삼을 위험(02 §5.5·5.8, B1·B3).
- **self-cap 부호 덕에 "영구 stuck"은 아니다**(손 떼면 counts↑로 회복) — 이전 B3와 동일 결론. 그러나 **과도 구간 터치 미인식**과 **ATI Disabled에서 seed 1회 오염**이 잔존 위험.
- **빠른 BETA는 은수님의 정당한 기여** — 이전 결론이 명시하지 않은 과도구간 단축을 메운다. 단독으로는 게이트를 대체 못 하나 게이트와 결합 시 최적.
- **M8(드리프트·방전 폐기)·auto-ATI Full은 충돌이 아닌 합의점.**
- **실측 의존**: B1 오염 실채널(터치한 채 MCLR 부팅 시 seed 후 LTA/Counts RTT 1회), BETA 현재값(reset 0 추정 — 확인 필요), 빠른 BETA 과도구간 오인식 — 모두 실측 게이트 뒤로.

## 6. 결론

**이전 결론(B1/S2, 노터치 게이트)이 우세**하나, 은수님 안과의 거리는 "게이트 한 줄"이며 은수님의 **ATI Full·빠른 BETA·드리프트 해소** 통찰은 이전 결론을 강화한다. 두 안은 적대가 아니라 **상보적** — 권장 해법은 **하이브리드(ATI Full + 노터치 seed 게이트 + 빠른 BETA + 터치중 Re-ATI 차단)**. 은수님 안을 "순수 자기정상화(게이트 없음)"로 채택하면 부팅 터치 과도구간·seed 1회 오염 위험이 남으므로 **조건부지지**: "게이트 추가"를 조건으로 지지한다.
