# 00 · 은수님 의견 — 오케스트레이터 입력 (공통)

> **TL;DR**: 모든 분석 페르소나의 공통 입력. 은수님 제안 10단계 원문, 검증 대상 명제로 분해, HW·데이터시트·코드·이전 검증(B1~B6) 제약, 8개 검증 질문, 6 페르소나. **핵심 쟁점: "터치 중 auto-ATI 허용 + LTA 자기정상화 + 빠른 BETA"가 성립하는가, 이전 결론(Reseed 게이트/터치중 차단)과 어느 쪽이 옳은가.**

## 1. 은수님 제안 (원문 10단계)

1. auto-ATI 기능을 사용하는 방향.
2. 터치 중 상태로 auto-ATI 진행 시, 터치 중이라 카운트가 작은 값일 텐데, 자동 보정되므로 이 상태로 MULT·COMP가 적절한 값으로 세팅됨.
3. 이 상태에서 손을 뗌 → 카운트 값이 더 커짐 → 카운트가 커진 것은 노터치 상태 → LTA가 카운트를 추적하기 시작.
4. 결과적으로 초기화 시작 시 터치로 카운트가 300이었어도, 노터치에서 500이 되면 LTA는 500으로 수렴.
5. 이제 터치 발생 → 카운트 작아짐 → 터치 인식. LTA 추적 멈춤.
6. 추가로 LTA가 카운트를 최대한 빠르게 추적하도록 BETA 조정.
7. 터치 지속 상태로 부팅돼도, 위 과정이면 터치 해제 전까지 LTA 추적이 멈추니, 실제 노터치가 돼야 LTA가 추적 → 첫 부팅 시 터치 해제 인식을 지금처럼 가능.
8. 노말→절전 진입 시에도 동일 개념으로 노터치 확인 가능. 노터치 확인되면 절전 모드에서 추가 터치센서 세팅 불필요(auto-ATI니까).
9. auto-ATI 모드라 드리프트 이슈도 해결 → 수동 방전 과정 불필요.
10. 즉, auto-ATI + BETA 조정(빠른 카운트 수렴)으로 해결될 것으로 예상.

## 2. 검증 대상 명제 (분해)

| 명제 | 내용 | 검증 질문 |
|---|---|---|
| M1 | auto-ATI가 터치 중 카운트로 MULT·COMP를 "적절히" 세팅 | Q1 |
| M2 | auto-ATI 직후 LTA가 (터치) 카운트로 시작, 손 떼면 노터치 카운트 추적 | Q2 |
| M3 | LTA가 노터치(500)로 수렴 → 이후 터치 시 카운트 감소 → 인식 | Q2·Q3 |
| M4 | 터치 인식 시 LTA frozen (추적 멈춤) | Q3 |
| M5 | 빠른 BETA로 LTA 수렴 가속 | Q4 |
| M6 | 터치 지속 부팅 → 해제 전까지 LTA 멈춤 → 노터치 시 추적(자기정상화) | **Q3(핵심)** |
| M7 | 절전 진입도 동일, 노터치 확인되면 추가 세팅 불필요 | Q6 |
| M8 | auto-ATI가 드리프트 해결 → 수동 방전 불필요 | Q7 |

## 3. 핵심 검증 질문 (8)

- **Q1**: 터치 중 auto-ATI가 **터치 카운트**로 MULT/COMP/compensation을 잡는 것이 안전한가? (max counts 초과, ATI Error, ATI Target 범위 — 06 A.6·A.12·A.7, 02 §5.9~5.11)
- **Q2**: auto-ATI 완료 직후 **LTA는 어떤 값으로 seed**되나? (터치 카운트? ATI 후 reseed 효과?) 손 떼면 LTA가 노터치 카운트를 추적하나? (02 §5.5·5.9)
- **Q3 (핵심)**: **터치 중 LTA frozen**(02 §5.5)이 "터치로 인식된" 상태 전제인데, 부팅 직후 baseline=터치라 delta≈0 → **터치 미인식 → frozen 안 됨**? 그럼 LTA가 터치 카운트를 추적해버리나, 아니면 은수님 7단계처럼 자기정상화되나? **이것이 은수님 안의 성패를 가른다.**
- **Q4**: 빠른 BETA의 부작용 — 천천히 누르는/약한 터치를 LTA가 흡수해 **터치 미인식**? Fast Filter Band(02 §5.6)와 상호작용? 과도 구간(손 뗀 직후~수렴) 오인식?
- **Q5**: 노터치 카운트가 ATI Target보다 크게 벗어나면 **auto Re-ATI 자동 트리거**(02 §5.10) → 재보정/진동? 은수님 4·5단계에 도움인가 방해인가?
- **Q6**: 절전(저속 클럭·주변 OFF)에서 auto-ATI/Re-ATI가 동작하나? 환경 변화 시 추가 세팅 정말 불필요? (02 §5.2, ULP 상호배타 B6)
- **Q7**: auto-ATI가 self-cap 드리프트를 실제로 해결 → 200ms 수동 방전 불필요? (이전 이슈 6·7과 정합)
- **Q8**: 은수님 안(터치중 auto-ATI 허용·자기정상화) vs 이전 결론(터치중 차단·Reseed 게이트, B1) — **충돌 해소**. 어느 게 옳은가, 어떤 조건에서, 하이브리드 가능한가.

## 4. 제약 (절대 준수)

- order code **001 = Release UI**(Movement UI 불가).
- self-cap: 터치 시 counts **감소**(02 §5.7).
- 회로: CRX0 활성, CRX1 CalCap 더미(현), 전원 R28 0Ω 무필터.
- 코드 현황: 현재 ATI Mode=Disabled(FIXED), 200ms CRX0 방전, BETA 미설정(reset 0 — 확인 필요). 웜부트도 MCLR POR(B4 반증).
- 이전 검증 B1~B6은 [4_타당성검증](../생각정리/4_타당성검증.md). 특히 **B1**(진짜 오염원=Reseed)·**B4**(웜부트 POR)는 은수님 안 평가의 토대.
