# 1 · 설계안 P2 — 측정 방식 재검토파

> **TL;DR**: "self-cap이 전원 스위치에 최선인가?"를 빈 종이에서 되묻는다. 9개 이슈의 다수가 **self-cap+autoATI 미사용**의 부산물이라는 데서 출발해, ① **측정 원리 재선택**(self / mutual / inductive / current 비교)과 ② **ATI를 다시 켜되 '터치 중 ATI 금지'로 게이팅**하는 두 축으로 재설계한다. 결론: 1순위 = **Self-cap + ATI Full(터치-게이팅) + 둔감·견고 튜닝**(SW-only, 확실), 2순위 = **Mutual-cap(TxA shared Tx)으로 드리프트 원천 차단**(전극 쌍·Cp Rx-VSS 100pF 재검토 필요한 조건부). order code 001 = **Release UI**만 가능(Movement UI 불가)이며, Release UI는 본 설계에서 "장기 터치 고착 방어"의 보조 안전장치로만 쓴다. **현재 구현과의 핵심 차이: autoATI를 버리지 않고 '게이팅'으로 되살려 self-cap 드리프트의 근본을 IC 자동보정에 되돌려준다.**

> [!NOTE]
> 입력: [01 문제정의·제약·평가축](01_문제정의·제약·평가축.md). 근거: 데이터시트 [02 ProxFusion 동작](../../데이터시트/02_proxfusion동작.md)·[03 하드웨어설정](../../데이터시트/03_하드웨어설정.md)·[06 레지스터레퍼런스](../../데이터시트/06_레지스터레퍼런스.md), 회로 [회로 구성·분석](../회로%20구성·분석.md), 펌웨어 [펌웨어 구현·시퀀스 분석](../펌웨어%20구현·시퀀스%20분석.md). 본 문서는 Phase 1 발산안 1건이며, 단일 정답이 아니다.

## 1. 설계 철학

전원 스위치는 본질적으로 **둔감해도 되는 on/off 롱터치 검출기**다. 정밀 정전용량 추적이 목표가 아니라 "손가락이 닿았나 / 2~3초 유지됐나"만 견고하게 판정하면 된다. 그런데 현재 설계는 정반대로 가 있다 — 미세 self-cap 변화를 FIXED MULT/COMP로 절대 카운트 추적하다가 드리프트·카운트 변동·threshold 들쭉날쭉이라는 9개 이슈를 SW로 떠안았다.

본 페르소나는 두 질문을 근본에서 다시 던진다.

1. **측정 원리 질문**: self-cap이 정말 이 용도에 최선인가? self-cap은 "전극↔GND parasitic"을 직접 본다 → 환경·온습도·ESD 전하가 그대로 baseline에 실려 드리프트한다(이슈 6). **Mutual-cap**은 Tx→Rx 결합(차동)을 봐서 공통모드 드리프트에 강하고, **Inductive**는 금속 뒤 코일로 정전기·습기에 면역이다. 측정 원리부터 다시 고른다.
2. **ATI 정책 질문**: 9개 이슈의 시발점은 "전원 버튼 겸용이라 **터치 중 ATI**가 그 정전용량을 기준 잡아 먹통"(이슈 1~3)이다. 이건 **autoATI 자체의 죄가 아니라 ATI를 '터치 중에' 돌린 죄**다. ATI를 버리는 대신 **터치 중에는 절대 ATI를 트리거하지 않도록 게이팅**하면, IC의 자동 충/방전 보정을 되찾아 드리프트(이슈 6~9)를 원천 제거할 수 있다.

> 핵심 명제: **"autoATI를 포기"한 것이 이슈 6~9(드리프트·카운트 변동·threshold 들쭉날쭉)의 근원이다. 포기가 아니라 게이팅이 답이다.** 측정 원리 재선택은 이 게이팅을 더 쉽게(드리프트 자체가 작아) 만든다.

## 2. 측정 원리 재선택 (4모드 비교)

PXS Mode는 `Prox Control`(0x32/0x42/0x52) bits[5:0]로 선택([06 A.7]): Self 0x10 / Mutual 0x13 / Current 0x1D / Inductive 0x3D.

| 모드 | 원리 | 터치 시 counts | 드리프트 강건성 | HW 요구 | 전원스위치 적합도 |
|---|---|---|---|---|---|
| **Self 0x10** | 전극↔VSS parasitic | **감소** | 약(공통모드 드리프트 직격) | 현 회로 그대로(CRX0/CTx0) | ◎ 즉시 가능, 단 드리프트 대책 필수 |
| **Mutual 0x13** | TxA→CRx0 결합(차동) | **증가**(Invert 필요, [02 §5.7]) | **강**(공통모드 상쇄) | TxA(B6) 구동 + Tx-Rx **전극 쌍** 필요 | ○ 드리프트 원천 차단, 단 전극 기하·Cp Rx-VSS 재검토 |
| **Inductive 0x3D** | LC 발진 변화 | 증가(Invert) | **최강**(금속·습기·ESD 면역) | **코일 추가**(현 회로 없음) | △ 전원스위치엔 과설계, 코일 HW |
| **Current 0x1D** | 외부 전류 측정 | — | — | — | ✕ 터치 측정 원리 아님([02 §5.12.2]) |

### 2.1 Self-cap (현 원리) 재평가 — "버릴 이유는 없다, 운용이 틀렸다"

- **장점**: 현 회로(CRX0→R31→C51→J3) 그대로, 단일 전극으로 동작. SW만으로 전환 0.
- **단점**: 전극↔GND parasitic을 직접 봐서 환경 드리프트·ESD 전하가 baseline에 직격. **이것이 이슈 6의 물리적 원인.** 현재는 이를 autoATI 없이 FIXED로 버티다 200ms VSS 방전으로 미봉.
- **재평가 결론**: self-cap이 나빠서가 아니라 **ATI를 끈 채 self-cap을 쓴 운용**이 문제. ATI Full을 되살려 IC가 매 conversion 충/방전 보정·LTA 추적을 하면 self-cap 드리프트는 IC가 흡수한다. → **1순위 안의 토대**.

### 2.2 Mutual-cap — 드리프트 원천 차단의 정공법 (조건부)

- **왜 강건한가**: mutual-cap은 Tx 구동 신호가 Rx로 결합되는 양을 측정. 손가락이 결합을 **흡수(steal)** 하면 counts 증가([02 §5.7] "mutual은 사용자 상호작용으로 counts 증가"). 환경 드리프트는 Tx·Rx 양쪽에 공통으로 실려 **차동에서 상쇄**된다 → self-cap의 공통모드 드리프트(이슈 6)를 물리적으로 제거.
- **HW 실현 경로**: 미사용 **TxA(B6, R30 0Ω→NC 플로팅)** 를 shared Tx로 구동([02 §5.12.1] "self는 동일 CRx/CTx, mutual은 별도 Tx"). CRX0(J3)를 Rx로 유지. Wav Pattern: Self 0x03 → **Mutual 0x0E**([02 Table 5.2]). Conversion freq ≤2MHz 권장([06 A.6]).
- **조건/리스크 (확인 필요)**:
  - **전극 기하**: mutual은 Tx 전극과 Rx 전극이 인접한 **전극 쌍**이 있어야 결합장이 형성된다. 현재 전원 버튼 패드(J3)가 단일 패드라면 TxA 라인을 J3 인접에 별도 전극으로 배선해야 함 → **HW 변경**(전극 추가/배선). 단일 패드만 있으면 mutual 불가. → **확인 필요 (전극 물리 구조)**.
  - **Cp Rx-VSS 한계**: 데이터시트 §3.2는 mutual @fxfer=1MHz에서 **Cp Rx-VSS ≤ 100pF**를 요구한다. 현 CRX0 라인의 **C51=100pF**가 정확히 이 상한에 걸린다([회로 §7.1]). mutual 전환 시 C51 재검토(축소/제거) 필요. → **확인 필요 (HW)**.
  - **Cm Tx-Rx 0.2~9pF** 범위 안에 전극 쌍 결합이 들어와야 ATI 수렴([01 §3.2]).
- **판정**: 강건성 최상이나 **HW 전제(전극 쌍·C51)** 가 붙는 **조건부 2순위**. 전극 쌍이 물리적으로 없으면 채택 불가.

### 2.3 Inductive / Current — 기각

- **Inductive(0x3D)**: 금속 표면 뒤 코일로 정전기·습기·ESD에 면역이라 충전 채터링·ESD 누적(이슈) 방어엔 이상적이나, **현 회로에 코일이 없고**(데이터시트 §2.5 Fig 2.2의 C6/C7/coil 부재), Dead Time disable·FOSC Tx 14MHz·Conv Period=0 등 별도 설정([02 §5.12.1])이 필요한 **전면 HW 재설계**. 전원 버튼 하나에는 과설계 → 기각(단, 차세대 방수 버튼 후보로 메모).
- **Current(0x1D)**: 외부 전류 측정용이며 터치 검출 원리가 아님([02 §5.12.2] "정확도 낮음, 대부분 비활성 권장") → 기각.

> **측정 원리 결론**: **1순위 self-cap + ATI 게이팅(SW-only, 확실)**, **2순위 mutual-cap(전극 쌍·C51 확인 후 조건부, 드리프트 원천 차단)**. inductive/current 기각. 아래 핵심 메커니즘은 1순위를 본문으로, mutual 전환점을 분기로 기술한다.

## 3. 핵심 메커니즘

### 3.1 측정 방식 — Self-cap + ATI Full (게이팅)

- PXS Mode = Self 0x10, CRX0/CTx0 단일 채널(현 회로 그대로). Wav Pattern 0 = 0x03([02 Table 5.2]).
- **Cs Size = 80pF**, **S/H Bias 10µA**, **0v5 Discharge = off(완전 방전)** — 데이터시트 §6.2 대부분 응용 권장값. 현 코드가 이 권장을 따르는지 확인 필요.
- **Max Counts**는 정상 노터치 예상 max 바로 위 단계로 설정([02 §5.4.2]) — stuck 방지.
- **CRX1(J4)·CRX2** 미사용. 현재의 **CalCap 더미(CH1)와 200ms VSS 방전은 모두 폐지**(ATI를 되살리므로 드리프트 미봉책 불필요). 측정 cycle 유지를 위한 더미 활성 채널 트릭이 사라진다.

### 3.2 ATI 정책 — "터치 중 ATI 금지" 게이팅이 본 설계의 심장

현재는 ATI Mode=Disabled(000)로 **autoATI를 완전히 끄고** FIXED MULT/COMP를 직접 write한다([펌웨어 §7]). 본 설계는 정반대다.

- **평상시 ATI Mode = Full(100)** ([06 A.12]) — IC가 divider·multiplier·compensation을 자동 선택, LTA를 환경에 맞춰 추적. self-cap 드리프트를 IC가 흡수 → 이슈 6~9 원천 해소.
- **자동 Re-ATI는 켜되**(LTA가 ATI Band 벗어나면 자동, [02 §5.10]), **터치 중에는 절대 ATI/Re-ATI가 일어나지 않도록 게이팅**한다. 그 수단:
  - LTA·ATI는 데이터시트상 **touch/prox 이벤트 중 frozen**([02 §5.5]) — 즉 **터치가 인식된 상태면 IC가 스스로 LTA를 얼리므로** "터치 중 ATI가 그 정전용량을 기준 잡는" 이슈 1~3의 핵심 메커니즘은 **이벤트가 정상 트리거되는 한 데이터시트가 이미 막아준다**.
  - 문제는 **초기화/콜드부트 직후** — 터치된 채 ATI를 처음 돌리면 그 정전용량이 baseline이 된다. 이때만 SW가 게이팅: **부팅 직후 ATI는 "터치 해제 확인(CH0 Touch bit=0 또는 counts가 노터치 대역)" 후에만 트리거**. 손가락이 닿아 있으면 ATI를 보류하고, ATI Band/Activation LTA로 해제를 감지해 해제 순간 1회 Re-ATI(0xC0 bit2).
  - **수동 Re-ATI 트리거**([02 §5.11] ATI Error 시 자동 재시도 안 됨 → SW가 0xC0 bit2 set)도 **반드시 터치 해제 상태에서만** 발행.
- **콜드부트 시 "터치된 채 부팅" 대비 2단 안전망**:
  1. 부팅 직후 일정 시간(예: INIT 윈도) ATI 보류 + Release UI(§3.5)로 "지금 닿아있음 vs 환경"을 분리.
  2. 그래도 해제가 안 잡히면, **둔감 baseline로 임시 ATI** → 해제 감지 시 정상 Re-ATI로 교정.

> 이 게이팅 한 가지가 "autoATI 포기 → FIXED → 드리프트 → 200ms 방전 → CalCap 더미"로 이어진 미봉책 사슬 전체를 끊는다.

### 3.3 LTA 관리

- **평상시**: IC 자동 LTA(IIR, `LTA Filter Betas` 0xB1). 노말 NP beta / 절전 LP beta 분리 설정([02 §5.6]). 현재는 Filter Betas가 reset 0(미설정)이므로 **명시 설정 필요**.
- **노터치 freeze 방지**: 현재 Prox가 `PROX_ENABLE=0`으로 꺼져 LTA freeze 방어 수단 하나가 빠져 있다([펌웨어 §14-7]). ATI Full + Channel Timeout으로 대체하되, **Prox를 약하게(둔감 threshold) 다시 켜** baseline 추적 보조를 검토.
- **Reseed는 모드 전환·콜드부트 직후 "터치 해제 확인 후"에만**(0xC0 bit3). 현재 절전 진입 시 무조건 reseed하는 것과 달리, **해제 게이팅**을 건다.
- **Fast Filter Band**(0xB4) 설정으로 급격 변화(터치) 시 fast filter, 미세 드리프트는 normal filter로 분리([02 §5.6]).

### 3.4 판정 (threshold)

- **상대 delta 판정 유지**: `(LTA − Counts) > Touch Threshold`([02 §5.7]). ATI Full이면 LTA·Target이 정규화되어 **카운트 절대값 변동(이슈 8)이 사라지므로** 고정 threshold가 비로소 의미를 가진다(이슈 9 해소).
- **둔감·견고 튜닝**: 전원 스위치는 둔감해도 되므로 threshold를 현재(100)보다 **여유 있게(예: 큰 delta 요구)** + **Touch Hysteresis 충분히** + **Touch Debounce(Prox Debounce Enter/Exit 유사)** 로 채터링·노이즈 무시. 정확한 수치는 ATI Full 후 실측 튜닝.
- **Dual Direction = off, Invert = off**(self-cap, [06 A.5]). mutual 전환 시 **Invert = on**(counts 증가).

### 3.5 모드 전환 (롱터치)

- **롱터치 검출**: TOUCH 상태가 2~3초 지속 → 전환 트리거. FSM은 현 구조(`proc_long_touch`) 유지 가능 — 본 페르소나의 변경점은 **측정/ATI 계층**이지 UX FSM이 아니다(그 부분은 P3 상태머신파 영역).
- **노말↔절전 전환 시 ATI 재트리거 정책**: 전환은 "지속 터치"라 **전환 순간 손가락이 닿아 있다.** 따라서 전환 직후 ATI/Reseed를 즉시 하지 말고, **터치 해제 확인 후 1회 Re-ATI**(0xC0 bit2)로 새 환경(주변장치 on/off로 정전용량 변함)에 맞춘다. 이것이 이슈 4("설정 시점 터치 우려")의 정공 해법.
- **웜부트 비대칭 대응**: E8300만 리셋되고 IC는 웜 → IC 레지스터·LTA 보존. 복귀 시 **재설정을 최소화**(이미 ATI Full로 추적 중이므로 전체 재write 불필요), reset_event 비트로 콜드/웜 구분([06 A.2] bit7).

### 3.6 통신

- 본 페르소나는 측정/ATI에 집중하므로 통신은 **현 폴링 + RDY 윈도우 유지**를 기본으로 한다(이벤트 모드 최적화는 P5 전력·이벤트파 영역).
- 단 **ATI Active/ATI Event/ATI Error 비트(0x10 bit5/4/6)를 명시적으로 폴링**해 게이팅 상태머신을 구동(현재는 ati_error를 `(void)`로 무시 — [펌웨어 §9]). ATI 진행 중에는 터치 판정을 보류.
- **write_and_verify 실 검증화**: 현재 read만 하고 값 비교 안 함([펌웨어 §14-3]). ATI Mode·PXS Mode 같은 결정적 레지스터는 **read-back 값 일치 검증** 필수(원리가 바뀌면 오기록 영향이 치명적).

### 3.7 Release UI — 보조 안전장치 (order code 001 가능 범위)

order code 001은 **Release UI만** 가능(Movement UI 불가, [01 §5 WARNING]). Release UI는 본 설계의 **주 판정**이 아니라 **장기 터치 고착 방어 보조**로만 쓴다.

- Release UI는 **Activation LTA**(터치 중에도 계속 update, [04 §7.4])로 "counts 변화율" 기반 해제를 본다. ATI 게이팅이 막지 못한 초장기 터치(손가락이 오래 붙어 LTA가 frozen인 상태)에서 **해제 시점을 변화율로 잡아** 고착을 푼다.
- 설정: `Sensor Setup`(0x30) bit6 Release/Movement UI Enable=1 → 001에선 Release UI로 동작([01 §5 WARNING]). `Release UI Settings`(0xD4) Release Delta Percentage·Delta Snapshot Sample Delay, `Events Enable`(0xD3) Activation Settling Threshold 설정.
- **주의**: Release UI는 자체로 측정 원리를 바꾸지 않는다 — self/mutual 위에 얹는 해제 보조다. P1(데이터시트 기능 활용파)이 이를 주 판정으로 밀 수 있으나, 본 페르소나는 **측정 원리 + ATI 게이팅을 1차, Release UI를 2차 안전망**으로 둔다.

## 8. 리스크

- **ATI 게이팅 상태머신 복잡도**: "터치 해제 확인 후에만 ATI/Re-ATI/Reseed"를 콜드부트·웜부트·노말↔절전 4경로에 빠짐없이 적용해야 함. 한 경로라도 누락되면 이슈 1~3 재발. → 게이팅을 **단일 함수로 중앙화**(모든 ATI/Reseed 트리거가 해제 게이트를 경유)해 누락 방지.
- **ATI 수렴 중 공백**: ATI Active 동안(짧지만) 판정 보류 → 그 순간 시작된 터치를 놓칠 수 있음. 롱터치 2~3초 여유로 흡수되나 실측 필요.
- **Mutual 채택 시 HW 의존**: 전극 쌍·C51이 안 맞으면 조건부 안이 무력화. self-cap 1순위가 **확실한 fallback**이라 리스크는 한정적.
- **Release UI 튜닝 난이도**: Release Delta %·Activation Settling Threshold가 환경 의존 → 보조로만 써서 주 판정 실패 시 영향 격리.
- **현 코드 회귀**: CalCap 더미·200ms 방전 폐지 시 measurement cycle·RDY 동작 영향([펌웨어 §8] 전제) — ATI Full로 활성 채널이 항상 유효하므로 더미 불필요하나, 전환 시 RDY 먹통 회귀 없는지 검증.

## 9. 현재 구현과의 핵심 차이 (1~2줄)

현재는 "터치 중 ATI 먹통"을 피하려 **autoATI를 통째로 포기**하고 FIXED+200ms VSS 방전+CalCap 더미라는 미봉책 사슬로 self-cap 드리프트를 SW가 떠안았다. P2는 **autoATI(ATI Full)를 되살리되 '터치 해제 확인 후에만 ATI/Re-ATI'로 게이팅**해 드리프트 보정을 IC에 되돌려주고, 한 단계 더 나아가 **mutual-cap(TxA shared Tx)으로 드리프트 원천을 차단**하는 조건부 상위안을 제시한다.
