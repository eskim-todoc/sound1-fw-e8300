# 비판 · 설계안 P1 (데이터시트 활용파)

> **TL;DR**: 3렌즈 모두 **조건부**. order code 001=Release UI 준수·이중 LTA·Event Mode 메커니즘은 데이터시트로 견고히 보장된다. 그러나 9건 이슈 도미노 전체가 **"self-cap에서 Release UI가 touch를 유지한다"**는 단일 미검증 가정 + **웜부트 시 Activation LTA·Delta Snapshot·touch 상태 IC 보존**이라는 미실측 전제에 매달려 있다(단일 실패점). CRX1 Reference UI는 §7.3 '사용자 비접촉 reference' 요건을 회로상 못 채워 사실상 채택 불가. 살아남으려면 self-cap Release UI 동작·웜부트 보존을 머지 전 실측 게이트로 통과해야 한다.

> [!NOTE]
> 본 문서는 워크플로우가 생성한 18개 비판 중 P1 관련 3개를 종합한 것이다. 비판 원문을 왜곡하지 않되 구조화했다. 설계안 본문은 [1_설계안_P1_데이터시트활용](1_설계안_P1_데이터시트활용.md) 참조.

## 렌즈 A — 가능성 (HW·데이터시트 실현가능성) · verdict: 조건부

### 핵심 findings
- **[견고] order code 001=Release UI 제약 위반 없음** — §10.1+A.1이 001=Release UI 명시 확정. 0x30 bit6을 Release UI로만 쓰고 Movement UI 전용 레지스터(0x64/0x23/Movement LTA/0xD4 Movement Timeout)를 전혀 건드리지 않음. 설계의 가장 견고한 부분.
- **[보장] 이중 LTA·Release UI 변화율 공식은 데이터시트 명문** — §7.4가 표준 LTA frozen / Activation LTA update / 해제 공식을 그대로 보장. 레지스터(0x20·0x23·0xD4·0xD3·0xB3)도 A.32/A.34/A.29에 실재.
- **[보장] Event Mode + RDY 인터럽트** — §8.11.2·§8.15 Program Flow + §8.13 Force Comm으로 절차 명시. RDY(C7)=INTERRUPT_n active-low 배선 확인됨. 단 E8300 GPIO 핸들러는 신설 필요.
- **[보장] ATI Full·Re-ATI·ATI Band Large** — §5.9·§5.10·A.12. ATI Target 정규화로 이슈 8·9 절대카운트 무관화 논리 정합.
- **[권장] Linearise+Invert** — §5.4.1 권장 사항. 단 self-cap에서의 정확한 Invert 비트값은 실측 튜닝 필요.

### blocking issues
| # | blocking | 치명도 |
|---|---|---|
| A-1 | **CRX1 Reference UI가 §7.3 핵심 제약 정면 위반 소지** — reference는 '사용자가 counts에 영향 못 줌'을 요구하나 CRX1은 J4(터치전극과 동일 규격 스프링핀 커넥터)로 배선되어 사용자 접촉 가능 라인일 공산이 큼. C52=100nF는 CH0 C51=100pF의 1000배(DC차단)라 self-cap reference 동작 자체 미검증. | 이슈 6(환경드리프트 차감) 수단 상실에 국한(fallback 명시됨) |
| A-2 | **자기방어 논리의 순환 의존** — 방어(a)는 'Release UI가 self-cap에서 touch 유지→표준 LTA frozen→re-ATI 안 됨'에 전적 의존하나, 이 사슬 전체가 미검증 가정에 매달림. 방어(b) Follower Event Mask는 reference 채널 ATI만 금지, CH0 자신의 ATI는 못 막음. self-cap Release UI 실패 시 (a)(b) 동시 붕괴→이슈 1~3 도미노 출발점 재발. | 단일 미검증 가정에 9건 도미노 집중(과도한 리스크 집중) |

### suggestions 요약
- 웜부트 Delta Snapshot 보존을 설계 전제에서 분리, 실제 read해 유효성 코드 검증
- **self-cap Release UI 동작을 1순위 go/no-go 게이트로 격상** (확인필요 목록의 한 줄이 아니라)
- Reference UI를 기본 설계에서 제외→옵션 강등, 2-tier fallback을 기본안으로 순서 역전
- ATI Resolution Factor(bits[15:4]) 구체값 미지정 → ATI Error 회피 위해 확정
- 0x30 LSB 비트맵을 A.5 기준 단일 확정 (INACTIVE_RXS 더미 매핑과 충돌 가능성)

## 렌즈 B — 요구·이슈 충족 · verdict: 조건부

### 핵심 findings
- **[타당] Release UI 핵심 주장이 §7.4와 정합** — '터치 중 ATI 불필요'로 이슈 1~3 연쇄 출발점을 끊는 논리에 근거 있음. 이슈 8·9를 변화량 비율 정규화로 푸는 방향도 데이터시트 의도와 일치.
- **[부분결함] 이슈5 방어 비대칭** — Follower Event Mask(§7.3.1 Table 7.1)는 'reference channel ATI를 disable'하는 CH1 보호용이지 CH0(실제 터치센서) 보호가 아님. '두 겹 방어' 표현은 과장, **CH0는 단일 방어선**.
- **[핵심] 경계 윈도우 취약** — LTA frozen은 'touch 유지 중'에만 성립. ① 터치 진입 직전 ② 해제 직후 reseed ③ debounce 중 — 이 전이 구간에선 frozen이 아니라 ATI Full 복귀 시 자동 re-ATI 트리거 가능. 설계안은 이 구간을 다루지 않음.
- **[신규이슈] Delta Snapshot 미포착 시 해제 불능** — Snapshot은 settle 구간이 있어야 기록(§7.4). 부팅 중 터치/콜드부트/채터링에선 미포착·소실 가능→해제식 우변 0→즉시해제 또는 영구미해제.
- **[재발위험] 부팅 중 ATI 타이밍** — 실측 확정 'MCLR 직후 auto-ATI는 sensor_setup보다 먼저 돈다'. 콜드부트 시퀀스가 이 타이밍을 명시 제어 안 함→'터치된 채 콜드부트'에 방어 없음.
- **[검증됨] 전력모드** — Automatic No ULP는 §5.8·§7.4와 정합. CH0 Timeout Disable로 장기터치 보호도 타당.

### blocking issues
| # | blocking |
|---|---|
| B-1 | **부팅 중 터치 해소가 단일 미검증 가정(웜부트 시 Activation LTA·Delta Snapshot·touch 상태 IC 보존)에 전적 의존.** 거짓이면 이슈 1~4(터치 중 초기화 먹통) 그대로 재발. 설계 스스로 '확인 필요'로 표기. 실측 전엔 요구 충족 단정 불가. |
| B-2 | **콜드부트/충전 채터링 '손가락 닿은 채' 진입 경로 방어 부재.** 실측 확정된 'MCLR 직후 auto-ATI 선행' 때문에 닿은 정전용량이 baseline화되는 이슈 1~3 원본이 콜드부트에서 재발. 충전 채터링이 빈번할 수 있음에도 미처리. |

### suggestions 요약
- 방어(b)가 CH1 보호임을 명확히, CH0 전이 구간 re-ATI 방어 보강(SW 게이팅 + ATI Band 폭 정량 평가)
- 웜부트 보존 전제를 구현 전 실측 P0로 분리, 미보존 시 fallback 설계
- 콜드부트/채터링 '터치된 채 부팅' 명시 시퀀스 추가
- Delta Snapshot 미포착(=0) 거동 실측 + 안전 디폴트(fallback 절대 threshold 병행)
- self-cap Release UI 동작을 확인필요 중 최우선 검증

## 렌즈 C — 복잡도·리스크 · verdict: 조건부

### 핵심 findings
- **[복잡도] 신규 파라미터 폭발** — SW 우회 4종 제거 대가로 Release Delta%·Activation Settling Threshold·Sample Delay·Activation LTA Beta + ATI(Base·ResFactor·Band)·Reference Weight·Linearise+Invert·debounce 신설. §6의 확인필요 8개 중 6개가 실측 튜닝. **SW 분기 복잡도를 IC 파라미터 튜닝 복잡도로 교환**, 후자는 진단 가시성이 더 낮음.
- **[가시성 역행] 진단 후퇴** — 현 read_touch_margin()은 RTT로 직접 관측 가능. Release UI 해제 판정의 DeltaSnapshot은 칩 내부 상태라 외부 결정론적 관측·재현 어려움→해제 오판정 root cause 좁히기가 현재보다 어려움.
- **[자기모순] 정규화 주장의 한계** — DeltaSnapshot은 손가락 압력·접촉면적·건습에 따라 매 터치 달라짐. 비율(%)은 정규화하나 분모(DeltaSnapshot) 자체의 개체편차는 잔존. 약한 터치→작은 분모→조기 해제 가능. '절대카운트 무관'이 곧 '편차 없음'은 아님.
- **[의존성] 단일 가정 도미노** — 설계 자체가 '이슈 1→9 연쇄 출발점을 Release UI가 끊으면 8건 도미노 해소'로 명시. 강점이자 최대 리스크(SPOF). 현 구조는 우회책별 독립 실패하나 본 설계는 상호 결합도 높음.

### blocking issues
| # | blocking |
|---|---|
| C-1 | **CH1 Reference 채널 ATI 수렴 실패→전역 ATI_ERROR 재현 리스크.** 현 CalCap 더미가 ATI Disabled인 이유가 'CalCap 부하 auto-ATI 수렴 실패→전역 ATI_ERROR SET→터치 판정 차단'. CH1을 진짜 Reference로 전환하면 C52=100nF DC차단 라인이라 ATI 수렴 미보장. CH1 ATI 실패 시 Event Mode에서 ATI All 재트리거 루프에 부팅이 빠질 수 있음. **CH1 ATI 수렴 실증이 머지 전 필수 게이트.** |
| C-2 | **self-cap Release UI 동작 미검증 = 설계 전체 전제.** §7.4 예시는 일반 long-term touch, self/mutual 명시 없음. 추가로 Linearise invert + self-cap 기본 로직 + 해제 변화율 공식의 **3중 부호 정합**이 틀리면 해제 판정 역전. 실칩 검증 없이 머지 불가. |

### suggestions 요약
- **3단계 머지 게이트로 단일실패점 분산**: ①ATI Full 복귀+터치중 Re-ATI SW 차단 → ②Release UI 단독 → ③Reference UI 마지막. 각 단계 독립 롤백.
- Reference UI는 default 보류, ATI Full+Release UI를 1차안으로 (회로상 비접촉 reference 전극 부재로 §7.3 충족엔 HW 변경 필요→현 HW에서 사실상 미충족)
- DeltaSnapshot·Activation LTA·표준 LTA를 주기 RTT 덤프하는 진단 경로 신설
- 웜부트 IC 상태 보존 실측을 콜드/웜 분기 구현 전 선행

### 치명 blocking 요약 (3렌즈 교차 수렴)
1. **self-cap에서 Release UI가 touch를 유지/해제하는지 미검증** — A·B·C 3렌즈 모두 지목한 설계 전체의 단일 전제. 부호 3중 정합(Linearise+Invert+해제식) 포함.
2. **웜부트 시 Activation LTA·Delta Snapshot·touch 상태 IC 보존 미실측** — 부팅 중 터치 해소 도미노의 토대.
3. **CRX1 Reference UI 채택 불가 위험** — §7.3 사용자 비접촉 요건 + ATI 수렴(C52 100nF) + 전역 ATI_ERROR 재현.

### 이 안이 살아남으려면 (해결 필수)
1. **실측 게이트 1**: self-cap CRX0에서 Linearise+Invert ON 상태로 (Counts−ActivationLTA) 부호 방향·Delta Snapshot 기록·해제 공식 발화를 다른 설계 진행 전 우선 검증.
2. **실측 게이트 2**: 워치독 리셋(웜)·채터링(콜드) 양쪽에서 0x20·0x14·DeltaSnapshot 보존 여부 실측 후 모드전환 FSM 확정.
3. **Reference UI 강등**: ATI Full+Release UI를 기본안으로, Reference UI는 CRX1 적합성(비접촉 전극·ATI 수렴) 입증 시에만 추가 (순서 역전).
4. **단계적 머지**: ①ATI Full → ②Release UI → ③Reference UI 3단 게이트로 도미노 SPOF 분산, 각 단계 독립 롤백·RTT 진단 경로 확보.
