# 쟁점 해결 토론 · 해법 4안 (S1~S4)

> **TL;DR**: 검증(B1~B6)이 강제한 문제 재정의 위에서 핵심 쟁점 3개(진입 LTA 오염·MCLR auto-ATI·Re-ATI 차단)의 해법 4안을 토론·교차검증했다. **4안 모두 같은 결론으로 수렴**: 진짜 오염원은 auto-ATI가 아니라 **Reseed**이며, 방어의 핵심은 **"Reseed/ATI 시딩을 노터치 게이트 뒤로 지연"**(SW-only, 데이터시트 비의존)이다. 4안 모두 이를 1순위 Phase로 둔다. Release UI는 진입을 못 풀고(B3) 0x30 LSB 충돌(B2)을 떠안으므로 "해제 전용·검증게이트 뒤"로 격리한다. 가장 견고한 조합은 **[Reseed defer 게이트(코어)] + [노터치 후 master ATI All] + [선택적 reset-cause 분기] + [실측 게이트 뒤로 격리한 Release UI·Auto No ULP]**다. 4안 교차검증 결과 모두 **feasible: 조건부**(실측 게이트 잔존).

> [!NOTE]
> 본 문서는 워크플로우가 생성한 해법 4안(solutions)과 교차검증 4건(checks)을 종합·구조화한 것이다. 각 해법의 코드·데이터시트 근거는 [4_타당성검증](4_타당성검증.md)의 B1~B6에 의존한다.

## 핵심 쟁점 3개

| 쟁점 | 내용 | 검증이 강제한 재정의 |
|---|---|---|
| **쟁점1 · 진입 LTA 오염** | "터치된 채 부팅/모드전환 시 그 정전용량이 baseline이 되어 방어 무력화"(이슈 1~4). Release UI가 진입을 풀어주는가? | **(B1)** 진짜 오염원은 auto-ATI가 아니라 `apply_settings` 내 **Reseed**. **(B3)** Release UI는 미캡처 시 진입을 **못 푼다** — 진입은 별도 메커니즘 필요 |

| **쟁점3 · Re-ATI 차단** | ATI Full 복귀 시 터치 중 칩이 자율 Re-ATI를 터치 용량으로 실행할 위험 | **(B1)** 자율분은 버리고 신뢰 baseline은 노터치 게이트 후 master ATI에서만 생성. **(B4 반증)** 웜부트 보존에 의존 금지 |

## S1 — ReleaseUI 중심

### 접근
검증이 강제한 재정의(B1 Reseed가 오염원·B4 웜부트 보존 거짓·B2 0x30 충돌) 위에서, **Release UI를 "해제 전용"으로 격리**하고 진입은 별도로 해결. 설계 원칙 3선: ① baseline 분리(부팅/Reseed counts를 LTA 판정에 직결 금지), ② 부호·충돌 격리(Release UI는 검증게이트 통과 후만), ③ 점진 도입(검증 의존 낮은 것부터).

### 이슈 1~4 해법 — 진입 baseline 3중 분리
- **(A) Reseed defer**: `apply_settings` 8단계 RESEED(`drv.c:1134`)와 절전 reseed를 "무조건 실행"에서 "노터치 게이트(ch0_touch==0 연속 N tick) 통과 후 실행"으로 변경. 상시접촉 시 timeout 강제 Reseed + `s_boot_baseline_dirty` 플래그 + 해제 순간 1회 자동 recapture. **이것이 "진입을 푸는" 실제 메커니즘**(Release UI 아닌 SW defer-and-recapture).
- **(B) ATI Full을 진입 baseline 1차 출처로, 부팅/판정 baseline 분리**: 자율 auto-ATI는 두되 결과를 즉시 판정 LTA로 직결 안 함. DS Figure 8.3(설정 후 ATI All)대로 노터치 게이트 통과 시점에만 master가 ATI All 트리거. → "터치 중 정전용량이 ATI 기준"이 구조적으로 불가능.
- **(C) boot-touch-ignore 가드 승격**: 현행 사후 무시(`touch.c:319-325`)를 진입 게이트로 승격 — dirty baseline 동안 TOUCH를 정상 터치로 승격 금지, recapture 후 첫 정상 해제→재터치만 유효.

### Re-ATI 차단
3중: ① 터치 상태 기반 Re-ATI 인히빗(터치 중 ATI Mode=Disabled/Comp Only, 노터치 후만 Full ATI All 1회), ② ATI Band 넓게+LTA filter beta 느리게로 터치 transient 흡수, ③ Re-ATI 발동 관측 시 ch0_touch 확인 후 오염 결과 사후 무효화. **권장 운용 = "상시 Full"이 아니라 "노터치 게이트 후 master ATI All + 운용 중 Comp Only"**.

### MCLR 대응
2-트랙: **트랙 가(현행 FIXED 유지)** — auto-ATI 결과는 어차피 버려지므로 Reseed 게이팅만으로 무해(최소 변경). **트랙 나(ATI Full 재채택)** — 자율 선행분은 버리고 설정 후+노터치 후 master ATI All만 신뢰 baseline으로. (나-1 권장: 막으려 경쟁 말고 선행분 폐기 후 재-ATI.)

### 단계적 도입
**Phase 0**(문서/코드 정정, 무위험) → **Phase 1**(Reseed defer + 노터치 게이트, SW-only·데이터시트 비의존, **최우선·단독으로 이슈1~4 해소**) → **Phase 2**(reset-cause 분기 + RDY ISR) → **Phase 3**(ATI Full 복귀 + Re-ATI 차단 + 주기방전 폐지) → **Phase 4**(Release UI 해제전용 + Auto No ULP, 검증게이트 최다·최후).

### 잔여 리스크
R1(B1 오염채널 실측 미완·완화: Reseed defer는 두 경우 안전), R2(B2 비트매핑 미검증·치명·완화: 실측 게이트+SW 대체), R3(B2 충돌·Phase3 방전폐지로 해소), R4(B3 spurious reseed·recapture로 단명화), R5(B4 보존 LTA 양면성), R6(B6 전력 미상), R7(B5 핀 공유·wake 미검증).

### 교차검증 (S1) — feasible: 조건부
- **잔여 blocking**: ① **[Phase4a/B2] 0x30 LSB Linearise 실칩 미검증 + discharge_crx0 200ms 충돌 실재 확정**(치명, 단 SW defer-and-recapture로 격리됨), ② Phase4b/B6 전력예산 사양·1ch 실측 부재, ③ Phase2b/B5 power button 공유·wake 미검증, ④ Phase3/B1 운용모드 baseline 오염 0 미검증, ⑤ Phase1 신규 defer-and-recapture 로직 단위검증 필요.
- **보완점**: **`func_sleep reseed(drv.c:880)` 라인 참조 오류 정정 필수** — 실제는 `main.c:880`→`drv.c:932`(drv.c:880은 wait_re_ati_done). Phase1 단독 효과 주장은 코드상 타당(Reseed=유일 LTA 시딩점). 검증 정합성 우수(B4 비의존·조건부 격리). boot-touch-ignore 승격 시 "부팅 직후 의도적 첫 터치 1회 무효화" UX 회귀 주의.

## S2 — ATIFull 게이팅

### 접근
"오염 채널은 auto-ATI 아닌 Reseed(B1). baseline 깎는 동작 **전체**를 게이트 뒤로." S1과 같은 진단, 더 단순한 메커니즘.

### 이슈 1~4 해법
부팅 LTA 확정 보류(`s_baseline_pending`), `is_release_confirmed`(touch 0 디바운스 + counts 회복) 뒤 commit에서만 ATI All. 현 Reseed가 부팅 counts로 LTA 잡는 게 B1 오염이라 끊음. 상시접촉 미승격, 손 떼면 정상화. 절전 reseed도 동일 게이트.

### Re-ATI 차단
터치 중 LTA freeze(DS 02 §5.5/§7.4) + SW 가드: 수동 ATI 게이트 거부, 자동 Re-ATI는 Events Mask로 무시, ATI Band Large로 확률 저감. **self-cap counts 부호 그대로 비교라 Linearise/Invert 불요 → 0x30 방전충돌 무관(B2 회피)**.

### MCLR 대응
선행 auto-ATI 결과 불신, compensation 버려 의도값 재설정(B1 후반 정식화), baseline은 게이트로만. **콜드/웜 동일 시퀀스**, 웜부트 보존 가정 안 함(B4 반증 수용).

### 단계적 도입
[0] 오염채널+counts 부호 RTT 실측(B1/B2) → [1 SW only] 게이트+ATI Full(이슈1~5 가장 견고) → [2] Band Large+Events Mask → [3 선택] RDY ISR(B5) → [4 보류] Release UI(B2/B3). [전원] Channel Timeout은 Auto No ULP 강제(B6).

### 잔여 리스크
상시접촉 baseline 영구 미확정(손 떼야 정상화), 게이트 임계 실측 의존, 자동 Re-ATI 내부 LTA 갱신 단정 불가(RTT 모니터), 전원 예산 미확정(LP/3ch 37µA 보수 상한), 이벤트 wake 미검증, 분석.md:165 정정·0x30 비트매핑 미확정.

### 교차검증 (S2) — feasible: 조건부
- **잔여 blocking**: ① **[B1 실측 게이트] 단계[0] 오염채널 RTT 미완 시 [1] 어느 시딩점을 막을지 미확정**(치명), ② B6 절전예산 판정 불가, ③ B5 wake 실측, ④ B2/B3는 [4 보류]로 봉인(Release UI 미채택 시 비-blocking).
- **보완점**: 'baseline 깎는 동작 전체를 게이트 뒤로'가 B1이 도출한 진짜 위협(Reseed=`tdc_drv_iqs323.c:1133-1134`)을 정확히 겨냥. 단계[0] RTT 실측 1순위 명문화 유지. **주의 — ATI Full 켜는 순간 stuck-touch→auto-reATI→ATI_ERROR→I2C 무응답(코드 주석 명시 위험) 회귀 가능**: 현 운용은 이미 ATI Disabled+CH timeout disable로 Re-ATI 이중 차단 중이므로 그 차단을 풀고 freeze+Events Mask로 대체하는 트레이드오프를 [0] 실측 후 결정. `is_release_confirmed`의 counts 회복 조건은 self-cap 부호 정합 임계를 실측 튜닝.

## S3 — 부팅 비의존

### 접근
Reset Event/부트원인 분기로 **MCLR을 부팅 원인에 따라 조건부화**, 웜부트 IC 상태 재사용 + Reseed/ATI를 노터치 가드 뒤로 게이팅. B4 반증·B1 후반부 수용.

### 이슈 1~4 해법
- 웜부트: init_begin을 reset-cause 분기로 바꿔 MCLR·Reseed 스킵 → IC 보존 노터치 LTA 승계.
- 콜드: Reseed를 boot-touch-guard 노터치 후로 지연(`s_boot_touch_ignore`를 게이트로 승격).
- `func_sleep`이 터치 해제 후에만 절전 LTA reseed. Release UI는 해제 보조로 격하.

### Re-ATI 차단
자동 Re-ATI는 터치 중 LTA frozen으로 미트리거 + Band Large 보강. 수동·부팅 ATI All은 노터치 게이트 후만. Follower/Events Mask는 Reference UI 시만(CRX1 미검증 보류).

### MCLR 대응
웜은 MCLR 스킵으로 auto-ATI 자체 미발생(함정 제거), 콜드는 노터치 후 명시 ATI All 재실행으로 손가락 값 덮어씀.

### 단계적 도입
[1·2단계 SW only] 부트원인 분기 + Reseed/ATI 게이팅(3쟁점 저위험 코어) → [3단계] 이벤트모드 wake·데드맨·Auto No ULP·Release UI(B5/B6 실측 게이트 전까지 단독 의존 금지).

### 잔여 리스크
웜부트 승계 LTA 노터치 실측 필수, 채터링 오분류, 0x30 방전 충돌, 절전전류 예산 미확보.

### 교차검증 (S3) — feasible: 조건부
- **잔여 blocking**: ① **[핵심] 부트원인 분기 인프라 부재 — reset-cause 검출 코드가 main.c·initialize.c·HAL 어디에도 없음**(grep 0건, from-scratch 신규 구현, E8300 워치독 원인 판별 가능성 미검증)(치명), ② **[용어 혼동] 'reset event bit7 분기'는 IQS323 칩 reset_event 비트와 CM3 부트원인을 혼동** — `drv.c:428` bit7은 reserved, 칩 비트가 아니라 CM3측 리셋원인 필요, ③ B4 승계 LTA 출처 양면성, ④ B5 wake·⑤ B6 예산·⑥ 채터링/방전 충돌.
- **보완점**: 분기 키를 'CM3 리셋 원인(콜드 POR vs 워치독 웜)'으로 재정의, HAL 리셋상태 레지스터 가용성 먼저 확인(불가 시 비휘발 SW 플래그 fallback). `func_sleep`은 이미 release 대기(`main.c:802~812`) 구현됨 → `main.c:884` 저클럭 reseed만 가드 대상으로 좁힘. 가드 진입에 디바운스/연속샘플로 채터링 방지.

## S4 — 하이브리드 단계

### 접근
부팅과 Reseed 시점 LTA 시딩을 손가락 접촉과 분리. 진짜 오염채널 = 자율 auto-ATI 아닌 `apply_settings` 내 Reseed.

### 이슈 1~4 해법
지연 Reseed + boot-touch-ignore 강화. 무조건 RESEED 제거 → 노터치 연속 샘플 확인 시점에만 수동 RESEED 발동해 확정 시점을 손 떨어진 첫 안정 구간으로 이동. Release UI는 미캡처 시 진입 못 푸므로 진입은 시딩 분리로 해결.

### Re-ATI 차단
ATI Band Large로 터치 delta 자동 Re-ATI 비트리거 산정, 터치/ignore 동안 수동 Re-ATI·Reseed 금지로 봉쇄.

### MCLR 대응
ATI Setup Full 복귀하되 자율 결과 노터치 확인 전 commit 금지, baseline 확정 ATI를 노터치 샘플 확인 시점 수동 재트리거.

### 단계적 도입
[1단계] ATI Full 복귀 터치중차단(SW only) → [2단계] Release UI(방전 LSB 충돌 해소 선행) → [3단계] RDY edge ISR 이벤트 모드.

### 잔여 리스크
오염채널 확정·LSB 매핑·wake source·단일 채널 전류 실측 게이트, 어떤 단계도 반증된 가정 비의존.

### 교차검증 (S4) — feasible: 조건부
- **잔여 blocking**: ① **[B4 정면충돌·미해결] 'Reseed만 지연하면 된다'고 보지만, 매 웜부트마다 `initialize.c:449`→`mclr_reset()`로 IC 무조건 POR → RESEED 시점만 옮겨도 강제 MCLR/POR+재초기화는 그대로 남음**(치명, S4 문서에 MCLR 경로 처리 누락), ② 지연 RESEED의 '안정 구간 이동' 보장 미검증 + 상시접촉 fallback(타임아웃 강제) 미명시, ③ ATI Full 복귀가 B1 메커니즘·B2 비트충돌·ATI 중 I²C disabled 자기간섭 재도입, ④ Release UI 0x30 충돌 B2 상속, ⑤ B5 RDY 잔여, ⑥ B6 전류.
- **보완점**: **S4 문서에 웜부트 MCLR/POR 경로를 명시 포함** — reset-cause 분기로 웜부트 MCLR 스킵을 1단계와 묶어 설계. 지연 RESEED에 상시접촉 fallback을 `INIT_TIMEOUT_MS(2500)` 패턴(`touch.c:220-228`)으로 고정. B1·B2·B5 blocking이 각 단계에 매핑되므로 3단계 점진은 방향 옳음 — 각 단계를 독립 롤백 게이트+실칩 PoC로 마일스톤화. Full ATI(1단계)가 드리프트를 칩 내부 보정으로 흡수하면 방전 로직 폐기 가능 → 1·2단계를 '방전 폐기'로 연결하면 0x30 충돌 동시 해소.

## 수렴

### 4안이 공통 수렴하는 해법 방향
1. **진짜 오염원 = Reseed(B1)** — 4안 모두 auto-ATI가 아니라 `apply_settings` 내 Reseed(및 절전 reseed)를 LTA 오염의 단일 채널로 지목.
2. **핵심 해법 = "Reseed/ATI 시딩을 노터치 게이트 뒤로 지연"** — 4안 모두 이를 **1순위 Phase**(SW-only, 보드변경·데이터시트 비의존)로 두고, **이 단계만으로 이슈1~4 진입 오염이 구조적으로 해소**된다고 합의.
3. **Release UI는 진입을 못 푼다(B3) → "해제 전용·검증게이트 뒤"로 격리** — 4안 모두 진입을 Release UI에 의존하지 않음.
4. **반증된 B4(웜부트 보존)에 비의존** — 4안 모두 웜부트 보존을 as-is 전제로 쓰지 않음(S3·S4는 쓰려면 코드 수정+실측 선행을 명시).
5. **미검증·조건부 항목(B2·B5·B6)은 실측 게이트 뒤 최후 단계로 격리.**

### 차이점
| 축 | S1 | S2 | S3 | S4 |
|---|---|---|---|---|
| Release UI | 해제전용·Phase4 격리(가장 정교) | [4 보류]·Linearise 불요로 회피 | 해제 보조로 격하 | 2단계, 0x30 충돌 떠안음 |
| ATI Full 운용 | 노터치 후 master ATI All + 운용중 Comp Only | 게이트 후 commit·freeze+Events Mask | 노터치 후만 | 상시 Full 복귀(자기간섭 리스크) |
| 웜부트 처리 | 2-트랙(보존/비보존 모두 성립) | 콜드/웜 동일(보존 안 함) | **reset-cause 분기로 MCLR 스킵**(인프라 부재가 약점) | 명시 누락(개선점) |
| 부호 처리 | Linearise+Invert(Release UI 채택 시) | **불요**(부호 그대로 비교) | 표준 touch 경로 | Linearise+Invert |

### 가장 견고한 조합
> [!IMPORTANT]
> **권장 조합** = **[S1/S2의 Reseed defer 노터치 게이트(코어, Phase 1, SW-only)] + [S2의 부호 회피(Linearise/Invert 불요·0x30 충돌 무관)] + [S1의 ATI 운용모드(노터치 후 master ATI All + 운용중 Comp Only, Re-ATI 인히빗)] + [S3의 reset-cause 분기(선택, CM3 리셋원인으로 재정의·인프라 가용성 먼저 확인)] + [Release UI·Auto No ULP를 실측 게이트 뒤 최후로 격리]**.
>
> 이유: **S2의 부호 회피**가 B2의 0x30 LSB 충돌(가장 치명적·확정된 blocking)을 **원천 회피**하므로 Release UI에 의존하지 않는 한 R2/R3 리스크가 사라진다. **S1의 defer-and-recapture**가 상시접촉 fallback과 진입 게이트를 가장 정교하게 다룬다. **S3의 reset-cause 분기**는 선택적 최적화(웜부트 MCLR 스킵)이되 인프라 부재가 약점이라 SW 플래그 fallback을 보유한다. **S4의 ATI 상시 Full 복귀는 권장하지 않음**(stuck-touch→ATI_ERROR→I2C 무응답 회귀 위험, S2 교차검증 지적).

### 반드시 실측해야 할 항목 (우선순위)
1. **(B1) 오염 실채널** — 터치한 채 MCLR 부팅 시 auto-ATI compensation vs FIXED+Reseed 후 LTA/Counts RTT 1회 캡처. **Phase 1 게이트(단, Reseed defer는 두 경우 모두 안전하므로 실측 전에도 배포 가능)**.
2. **(B6) 절전 전류** — self-cap 1ch NP/LP 실측 + 인공와우 절전 예산 사양 확보. Phase 4 게이트.
3. **(B2) 0x30 LSB 비트매핑** — Linearise(bit1) 실칩 동작. Release UI 채택 시에만(부호 회피 채택 시 불요).
4. **(B5) wake-source** — 슬립/ULP DIO16 인터럽트 wake 보장 + power button semantics 통합. Phase 2 게이트.
5. **(B4) 보존 LTA 출처** — reset-cause 분기 채택 시 웜부트 승계 LTA 노터치 여부.

> [!NOTE]
> **결론**: 4안의 토론은 단일 핵심 해법으로 수렴한다 — **"Reseed/ATI 시딩 시점을 노터치로 게이팅"하는 SW-only Phase 1이 핵심 요구(진입 baseline 오염)를 데이터시트·실측 의존 없이 단독 해결**한다. 나머지(Release UI·ATI Full·이벤트 wake·전력)는 모두 부가 견고성이며 실측 게이트 뒤로 격리되어, 미검증 항목의 실패가 핵심 요구를 깨지 않도록 설계가 보장된다.
