# 05 · 종합 결론

> **TL;DR**: 6관점 발산 → 18비판 → 6 blocking 검증 → 4해법 토론이 **하나로 수렴**했다. **진짜 문제는 autoATI도 Release UI 부재도 아니라, `Reseed`가 부팅/모드전환 시점 counts로 LTA를 seed해 진입 baseline을 오염시키는 것**(B1). 해법은 **"baseline 갱신을 노터치 확인 게이트 뒤로 지연"**(SW only, 데이터시트 비의존). ATI Full 복귀로 드리프트·카운트변동(이슈6·8·9)을 해소. zero-base 사고의 결론은 "전면 재작성"이 아니라 **"현재 구현에서 비어 있던 한 곳(Reseed 시점)을 메우기"** 였다.

## 1. 탐구가 도달한 한 문장

> **"현재의 self-cap·FIXED·200ms 방전 구조는 틀린 게 아니라, baseline을 새로 잡는 순간(Reseed)에 '손가락이 닿았는지'를 보지 않는 한 곳이 비어 있었다."**

zero-base로 6개 상이한 철학(데이터시트활용·측정재검토·FSM·강건성·전력·HW협업)이 독립 설계했는데, 검증을 거치자 **4개 해법이 모두 같은 지점**을 가리켰다. 이것이 우연이 아니라 문제의 본질임을 시사한다.

## 2. 만장일치 수렴 (4해법 공통)

| 합의 | 내용 | 근거 |
|---|---|---|
| **진짜 오염원** | auto-ATI/Release UI가 아니라 **`apply_settings` Reseed(`drv.c:1134`)·`func_sleep` reseed(`main.c:880`→`drv.c:932`)가 부팅·절전진입 시점 counts로 LTA seed** | B1 |
| **핵심 해법** | baseline 갱신(Reseed·ATI All)을 **"노터치 확인 게이트(ch0_touch==0 연속 N tick) 통과 후"** 로 지연. 상시접촉 시 timeout fallback + 해제 순간 recapture | S1~S4 전원 |
| **드리프트 해소** | **FIXED → ATI Full 복귀** (이슈6·8·9: 드리프트·카운트 340~660 변동·threshold 들쭉날쭉). 단 터치 중 Re-ATI 차단 | B1 함의·4안 |
| **Release UI 격하** | 진입 baseline 못 풂(B3) + 200ms 방전과 0x30 LSB 충돌(B2) → **해제 보조로만, 채택 시 실측 게이트** | B2·B3 |
| **전원** | Channel Timeout 쓰면 **Auto No ULP 강제**(B6), 절전예산 실측 필요 | B6 |

## 3. 결정적 반증 — 웜부트는 IC를 보존하지 않는다 (B4)

- 내가 [펌웨어 분석 §11](../펌웨어%20구현·시퀀스%20분석.md)에서 "웜부트=MCLR 미수행=IC 보존"이라 서술했으나 **검증 결과 거짓**: 워치독 리셋 후 `Initialize()`→`tdc_touch_init_begin()`→`mclr_reset()`이 **무조건 실행**(reset-cause 분기 없음) → IC가 매 웜부트 POR.
- **함의**: "웜부트 LTA 연속성"에 기댄 설계(S3 일부)는 reset-cause 분기(콜드 POR vs 워치독 웜) **인프라 신규 구현**이 선행돼야 함(현 코드 reset-cause 검출 0건). → 펌웨어 분석 §11 **정정 필요**.

## 4. 가장 견고한 해법 — S2 (ATI Full 게이팅)

교차검증에서 S2가 최고 평가:
- **self-cap counts 부호를 그대로 비교** → Linearise/Invert 불요 → **B2(0x30 방전 충돌) 자체를 회피**.
- baseline 깎는 동작 전체(Reseed·ATI All·자율 auto-ATI 결과)를 노터치 게이트 뒤로 → B1이 지목한 진짜 위협을 정확히 겨냥.
- 웜부트 보존 가정 안 함(B4 수용), 콜드/웜 동일 시퀀스.

## 5. 단계적 로드맵 (검증 의존도 오름차순, 각 단계 독립 롤백)

| Phase | 내용 | 위험 | 게이트 |
|---|---|---|---|
| **0** | 문서·코드 정정 — 펌웨어 분석 §11(B4), 주석 불일치(0x5E/0xE4·2.8초), `write_and_verify` 값 비교 | 무위험 | 없음 |
| **1** ★최우선 | **Reseed defer + 노터치 게이트** — `apply_settings:1134`·`func_sleep`(`main.c:880`/`drv.c:932`)·boot-touch-ignore 승격. **이슈 1~4 진입오염 구조 해소** | SW only, 데이터시트 비의존 | (실측1) 오염 실채널 RTT 1회 |
| **2** | **ATI Full 복귀 + 터치중 Re-ATI 차단** — FIXED 폐기, 이슈 6·8·9 해소. self-cap 부호 그대로(S2) → 방전·Linearise 무관 | SW, 중 | (실측1) 확정 후 |
| **3** 선택 | **RDY edge ISR 이벤트모드** — 폴링 폐지. power button(DIO16) 통합 | SW, B5 가능 | wake-source 실측 |
| **4** 보류 | **Release UI** — 0x30 LSB Linearise 실측 + 방전 충돌 해소 후에만 | 높음 | (실측3) 0x30 비트 |

> 전원: Channel Timeout 채택 시 Auto No ULP(B6) → (실측2) self-cap 1ch 전류·절전예산. 초과 시 ULP+SW롱터치 fallback.

## 6. 반드시 실측할 것 (우선순위)

1. **(실측1) 오염 실채널** — 터치한 채 MCLR 부팅 시 auto-ATI compensation vs FIXED+Reseed 후 LTA/Counts RTT 캡처. → Phase 1·2 게이트.
2. **(실측2) self-cap 1ch 전류·절전예산** — Event mode 실보드 NP/LP 실측 + 인공와우 절전 사양 확보. → No-ULP/Channel Timeout 결정.
3. **(실측3) 0x30 LSB Linearise 비트** — 실칩이 데이터시트 A.5 매핑을 따르는지. → Release UI 채택 게이트.

## 7. 현재 구현 대비 (요약, 상세는 권고 문서)

| 항목 | 현재 | 권고(Phase 1~2) |
|---|---|---|
| 진입 baseline (이슈1~4) | 무조건 Reseed → **터치 시점 오염** | **노터치 게이트 후 Reseed** → 해소 |
| 드리프트·카운트변동 (이슈6·8·9) | FIXED + 200ms 방전 **우회** | **ATI Full 복귀** → 정규화 |
| 200ms CRX0 방전 | 상시 | ATI Full 안정화 후 **점진 폐기 검토** |
| CalCap 더미 | 방전 전제로 필요 | 방전 폐기 시 **불요** |
| 웜부트 | (오인) 보존 → 실제 POR | reset-cause 분기로 **진짜 보존 선택지** |

## 8. 메타 결론 — zero-base가 알려준 것

- "현재를 버리고 새로"가 아니라, **현재가 옳게 한 것(self-cap 유지·FIXED로 터치중 ATI 회피)과 비어 있던 것(Reseed 게이트)을 분리**해냈다.
- 6관점 독립 발산이 한 점으로 수렴한 것은 **문제의 본질이 단순(=Reseed 타이밍)** 했음을 역설적으로 입증.
- 가장 큰 가치는 "더 좋은 새 방법"보다, **"무엇이 진짜 원인이고(Reseed) 무엇이 곁가지였나(auto-ATI·Release UI 논쟁)"를 검증으로 가려낸 것**.
