# 01 · 문제 정의 · 제약 · 가능성 맵 · 평가축

> **TL;DR**: 모든 설계 페르소나의 공통 입력. 요구사항(전원 스위치·모드전환·상시전원·충전채터링)과 이슈 9건, HW 자원/제약(회로 분석), 현재 SW 현황(펌웨어 분석), IQS323 능력(데이터시트)을 한데 모으고, 무엇이 SW만으로/조건부/HW필요인지 가능성 맵과 8개 평가축을 정리한다. **order code 001 = Release UI(Movement UI 아님)** 같은 결정적 제약 포함.

> [!IMPORTANT]
> 본 문서는 [회로 구성·분석](../회로%20구성·분석.md)·[펌웨어 구현·시퀀스 분석](../펌웨어%20구현·시퀀스%20분석.md)·[데이터시트/](../../데이터시트/)에서 검증된 사실만 모은 것이다. 설계 에이전트는 이 제약 안에서 zero-base로 발상하되, 본 문서에 없는 능력을 가정하면 "확인 필요"로 표기한다.

## 1. 문제 정의 (요구사항)

IQS323 터치를 **전원 스위치 겸 터치 센서**로 사용. 사용 시나리오:

1. 터치 = 전원 스위치
2. **절전→노말**: 2~3초 지속 터치 → 노말 부팅 (**E8300(CM3)만 워치독 리셋**)
3. **노말→절전**: 2~3초 지속 터치 → 절전 진입
4. 노말·절전 모두 **터치 IC 전원 상시 유지** (중단 없음)
5. 보드 최초 전원 연결 시에만 터치 IC **콜드 부팅**
6. **충전 케이블 연결 시 ~1µs 전원 채터링** → IC 재부팅 여부 불확실 (보수적으로 재부팅 가정 권고)

→ 핵심 구조: 터치 IC는 (콜드부트 1회 제외) **상시 웜**, E8300만 리셋되는 비대칭. 모드 전환 트리거가 "지속 터치"라 **초기화·전환 시점에 손가락이 닿아 있는** 상황이 빈번.

## 2. 이슈 9건 (현재 방식에서 관찰)

| # | 이슈 |
|---|---|
| 1~3 | 전원 버튼 겸용 → autoATI 사용 시 **터치 중 ATI가 그 정전용량을 기준**으로 잡아, 터치 해제·재터치가 인식 안 됨 (모드 전환·초기화 시점) |
| 4 | 노말→절전 시 터치 해제 확인 후 설정해도, 설정 시점 터치 우려 잔존 |
| 5 | 그래서 **autoATI 포기, FIXED MULT/COMP** 채택 |
| 6 | autoATI의 내부 충/방전 보정이 없어 **self-cap 드리프트** → 일정 터치 후 먹통 |
| 7 | 대응으로 **CRX0 주기적 VSS 방전**(자체 방전) |
| 8 | FIXED라 매 부팅 시 정전용량에 따라 **RESEED 카운트가 340~660대로 변동**, MULT/COMP 고정이라 터치 시 CUR 값 편차 큼 |
| 9 | 고정 threshold라 CUR 편차로 **터치가 됐다 안 됐다** |

## 3. HW 제약·자원 (회로 분석 근거)

| 자원 | 상태 | 가용성 |
|---|---|---|
| **CRX0** (B2) | R31 100Ω + C51 100pF → J3 전극 | **활성 측정 채널** (self-cap) |
| **CRX1** (A1) | C52 100nF + R32 0Ω → J4 (배선 완료) | **가용** — 현재 SW상 CalCap 더미. Reference/VSS/추가채널 전환 가능(빌드) |
| **CRX2** (C1) | R33 470Ω → NC | 전극 미연결 (HW 변경 시 채널 추가 가능) |
| **TxA** (B6) | R30 0Ω → NC (플로팅) | 미사용 — mutual Tx 구동·guard 구동 후보 |
| **OUTA** (B4) | NC | 미사용 — event indicator 출력 후보 |
| **RDY/MCLR** (C7) | INTERRUPT_n + C58 1nF | RDY 이벤트(active low) + reset 핀 겸용 |
| **전원** | 1.8V_QCC → R28 **0Ω(무필터)** → VDD. C54 4.7µF + C55 100pF | 전원 경로 필터 없음(채터링·ESD 취약). R28 페라이트 교체 가능 |
| I²C 풀업 | IQS323 회로 측 없음 (마스터 측 추정) | 확인 필요 |
| CRX0 직렬 | 100Ω (데이터시트 권장 470Ω 미만) | ESD 여유↓ |

- 부품: IQS323**001**CSR (WLCSP11). VCC 1.71~3.6V, VREG 1.53V.

## 4. 현재 SW 현황 (펌웨어 분석 근거 — 비교 대상)

- 측정: **self-cap**(PXS 0x10), CRX0 단일.
- ATI: **autoATI 미사용, FIXED MULT/COMP**(보드변종, ATI Mode=Disabled 0x08).
- 드리프트 대응: **200ms 폴링마다 CRX0 VSS 방전**(0x30 0x02→0x01).
- CH1: 내부 **CalCap 더미**(measurement cycle 유지용, CH0 방전 전제).
- 통신: **폴링** I²C + RDY 윈도우 핸드셰이크(이벤트 IC지만 인터럽트 미사용).
- 판정: threshold/hysteresis 100/80, prox 비활성. 노말 2.4s / 절전 2.2s 롱터치.
- 절전: apply_sleep(255/255 둔감) → ci_power_sleep → reseed(100/80) → ULP 200ms 폴링 → 11회(2.2s) 워치독 리셋(웜부트).

## 5. IQS323 능력 (데이터시트 — 설계 재료)

| 능력 | 비고 | 출처 |
|---|---|---|
| **PXS 모드** | Self 0x10 / Mutual 0x13 / Inductive 0x3D / Current 0x1D | [06 A.7] |
| **ATI** | Full(자동) / Disabled / Compensation Only / from Divider. Target=Counts×(ResFactor/16) | [02 §5.9, 06 A.12] |
| **Re-ATI** | LTA가 ATI Band 벗어나면 자동. 수동 트리거(0xC0) | [02 §5.10] |
| **Reference UI** | reference 채널이 primary LTA를 환경 드리프트 보정(CRX1 활용 가능) | [04 §7.3] |
| **Release UI** | **장기 터치/근접 해제**(Activation LTA·변화율 기반). **order code 001/002 한정** | [04 §7.4] |
| **Movement UI** | 움직임 감지(wear). **order code A01 한정** | [04 §7.5] |
| **Slider/제스처** | 단일 채널로 tap/hold 인식 가능(slider+gesture) | [04 §7.2] |
| **이벤트/스트리밍** | 이벤트 모드(RDY는 event 시만 low) / 스트리밍 | [05 §8.11] |
| **전력모드** | NP/LP/ULP/Halt/Automatic/Auto No ULP | [02 §5.2~5.3] |
| **임계·필터** | threshold·hysteresis·prox·debounce·dual direction·max counts·filter beta·fast filter | [02 §5.6~5.7, 06] |
| **Watchdog** | 255ms (I²C 통신으로 kick) | [04 §7.6] |

> [!WARNING]
> **결정적 제약 — order code**: 현재 칩은 **IQS323-001** = I²C 0x44, **Release UI**, configurable. **Movement UI는 A01 한정**이므로 현재 칩으로는 Movement UI 레지스터(0x64/0x23 등)가 무의미. Release UI는 사용 가능. (데이터시트 §10.1) → 펌웨어가 "Release/Movement UI Enable"(0x30 bit6)을 쓰면 001에선 **Release UI**로 동작.

## 6. 가능성 맵 (zero-base 발상 경계)

| 분류 | 항목 |
|---|---|
| **SW만으로 가능** | PXS 모드 전환, ATI Full/Disabled/Compensation Only, Re-ATI 수동, **Release UI**(001), Reference UI(CRX1 채널 사용), 이벤트 모드, 전력모드 전환, threshold/hysteresis/debounce/dual-direction 조정, prox 활성, max counts, filter beta, slider/tap-hold |
| **조건부(HW/설정 전제)** | mutual-cap(TxA 구동 + 전극/배선), inductive(코일 필요), guard electrode(CRX1 J4 또는 TxA를 실드로 연결·구동), CRX1 Reference(C52 영향 검토), CRX1 VSS(C52 단락 전제) |
| **HW 변경 필요** | 전원 경로 필터(R28→페라이트), CRX0 직렬 100→470Ω, CRX2 전극 연결, I²C 풀업 확인 |
| **불가/무의미(현재 칩)** | Movement UI(A01 전용) |

## 7. 평가축 (8축)

설계안·비교·검증에 공통 적용.

| 축 | 질문 |
|---|---|
| ① 요구 충족 | 전원 스위치 UX(2~3초 롱터치·모드 전환·콜드/웜부트)를 안정적으로 만족하나 |
| ② 이슈 해결 | 9개 이슈(터치중 ATI 먹통·드리프트·카운트 변동·threshold 들쭉날쭉)를 해소하나 |
| ③ 강건성 | 충전 채터링 재부팅·ESD 누적·**터치 중 초기화/부팅**을 견디나 |
| ④ 복잡도 | SW 구현·유지보수 복잡도(상태·예외·튜닝 부담) |
| ⑤ 전력 | 평균 소비·절전 효율 |
| ⑥ HW 변경 요구 | SW만 / 부분 HW / 회로 재설계 |
| ⑦ 리스크·실패모드 | 먹통·오작동·진단 가시성·개체편차 |
| ⑧ 데이터시트 정합 | 데이터시트가 보장하는 사용인가(검증된 범위) |

## 부록 — zero-base 발상 시드 질문 (페르소나 참고용)

- 전원 스위치는 **단순 on/off 롱터치**다. 굳이 정밀 정전용량 추적이 필요한가? (둔감·견고 우선?)
- "터치 중 초기화" 문제의 근원은 **부팅 시점 LTA 기준 설정**이다. LTA를 부팅과 분리할 방법은? (Release UI? Reference? 고정 baseline?)
- 드리프트는 self-cap+autoATI 미사용의 부산물. **ATI를 다시 켜되 터치 중 ATI만 막으면** 되지 않나? (조건부 Re-ATI?)
- 카운트 변동은 FIXED+RESEED 타이밍. **delta(LTA−Counts) 상대 판정**이면 절대 카운트 무관 아닌가? (이미 delta 기반인데 왜 변동? — 검증 포인트)
- 충전 채터링 재부팅은 **콜드부트 복구를 빠르고 안전하게** 만들면 수용 가능 아닌가? (재부팅 회피 vs 재부팅 수용)
