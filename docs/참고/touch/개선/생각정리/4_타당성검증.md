# 타당성 검증 · blocking 6항목 (B1~B6)

> **TL;DR**: 재설계 토론이 전제한 핵심 가정 6개를 코드·데이터시트로 검증한 결과 **반증 1, 조건부사실 4, 실측필요 1**. 가장 중요한 발견은 B1·B4다. (1) **진입 baseline 오염의 진짜 채널은 auto-ATI가 아니라 apply_settings 내 Reseed**다 — 현 펌웨어는 FIXED MULT/COMP로 auto-ATI를 이미 폐기했다. (2) **"웜부트=IC 보존"은 거짓** — 코드는 매 웜부트마다 MCLR로 IC를 POR시켜 LTA를 재초기화한다. self-cap+Release UI는 부호반전 비트(Linearise·Invert)를 강제하나 그 비트가 200ms 주기방전(0x30 LSB)과 정면 충돌한다. 1ch 절전 전류는 데이터시트에 부재(3ch만)로 실측 필요.

> [!NOTE]
> 본 문서는 워크플로우가 생성한 6항목 검증(verds)을 종합·구조화한 것이다. 검증은 코드(`tdc_drv_iqs323.c/.h`·`tdc_touch.c`·`main.c`·`initialize.c`·`ci_dio.c`)와 데이터시트 정리본(`01~06`)을 직접 인용·대조했다. 검증이 다루는 해법안은 [3_쟁점해결토론](3_쟁점해결토론.md) 참조.

## B1 — MCLR auto-ATI 선행 (조건부사실)

### verdict 분해

| 부분 | 판정 | 근거 |
|---|---|---|
| 전반부: "MCLR 리셋 직후 IQS323이 sensor_setup보다 먼저 자율 Full auto-ATI 실행" | **사실** | DS §6.6.1 reset → start-up value 복귀, ATI Setup(0x36) 기본값 **0x040C**=ATI Mode Full. 코드가 이 자율 auto-ATI를 sensor_setup보다 먼저 대기 |
| 후반부: "그 정전용량이 ATI 기준이 되어 방어 무력화" | **조건부** (현 펌웨어엔 미해당) | 현 운용 경로는 auto-ATI 결과를 **버린다** |

### 핵심 근거

- **선행 메커니즘(사실)**: `tdc_touch.c:216-228` `try_finish_init()`이 진입 즉시 `if (!is_auto_ati_done()) return false;`로 ATI Active bit(0x10 bit5)가 0이 될 때까지 매 tick 재시도. 완료(또는 timeout) 후에야 `apply_settings()` → 그 안에서 `sensor_setup()` 실행. 즉 자율 auto-ATI가 sensor_setup보다 **시간적으로 선행**.
- **현 FIXED 경로가 auto-ATI를 폐기(조건부의 핵심)**: 운용 경로 `apply_settings()`(`tdc_drv_iqs323.c:1088-1146`)는 `write_ati_compensation()`(line 1128)으로 보드변종 FIXED MULT/COMP를 직접 덮어쓰고 ATI Setup을 0x08(ATI Disabled)로 고정 → **Reseed(0x08)**(line 1134). 즉 auto-ATI compensation을 baseline으로 쓰지 않음. 문제정의 이슈 #5("autoATI 포기, FIXED MULT/COMP 채택")가 이 우회를 이미 채택.
- **진짜 잔존 오염원 = Reseed**: Reseed(DS §5.5.1 "최신 측정 counts로 LTA를 seed")가 `apply_settings` 실행 시점의 counts로 LTA를 잡으므로, 그 시점에 터치 중이면 터치된 정전용량이 LTA(터치 판정 기준)가 됨. boot-touch-ignore 가드(`tdc_touch.c:319-325`)로 완화 중.

### 설계 함의 (impact)

- "MCLR→자율 auto-ATI 선행" 메커니즘 자체는 사실 → auto-ATI를 다시 켜는 재설계안은 반드시 '터치 중 auto-ATI'를 막아야 한다.
- 그러나 현 펌웨어는 FIXED로 auto-ATI를 이미 폐기 → **zero-base 방어의 핵심은 'auto-ATI 차단'이 아니라 '부팅/Reseed 시점 LTA 시딩 분리'**.
- DS 권장 Program Flow(Figure 8.3: 설정 **후** ATI All)와 현 코드(설정 전 자율 auto-ATI 대기)의 괴리도 정합 후보.
- **실측 권고**: 터치한 채 MCLR 부팅 시 (i) 자율 auto-ATI compensation, (ii) FIXED 덮어쓰기+Reseed 후 LTA/Counts를 RTT로 1회 캡처해 오염 실채널이 auto-ATI인지 Reseed인지 확정.

## B2 — Release UI 해제식 부호 (조건부사실)

### 핵심 근거

- **부호 문제(사실)**: Release UI 해제 조건은 (Counts − ActivationLTA) > (DeltaSnapshot × Release%/128) [04 §7.4]. self-cap은 터치 시 Counts가 LTA 대비 **감소**(02 §5.7). 따라서 터치 중에는 좌변이 음수 → 항상 양수인 우변을 결코 초과 못 해 해제가 fire 안 됨. self-cap에서 이 식이 의도대로 동작하려면 카운트 부호를 뒤집어야 함.
- **데이터시트 권장 조합(사실)**: 02 §5.4.1 — "Linearise Counts set 시 counts inverted → Invert bit를 적절히 set해 채널 로직 정합. Release UI 사용 시 특히 권장." 즉 **Linearise(0x30 bit1)=1 + Invert(0x30 bit3)=1** 쌍이 self-cap+Release UI 권장.
- **0x30 LSB 정면 충돌(사실)**: Sensor Setup(0x30) LSB는 bit1 Linearise·bit3 Invert·bit6 Release UI Enable. 그런데 `discharge_crx0()`(`tdc_drv_iqs323.c:942-947`)가 200ms 폴링마다 0x30 LSB에 0x02→0x01을 쓴다. Release UI에 필요한 비트가 매 200ms 클리어됨 → **방전 우회 구조와 Release UI는 0x30 LSB 한 바이트를 두고 직접 충돌**.
- **비트매핑 실칩 미검증(잔여)**: §8 IMPORTANT — 현재 코드가 0x30 LSB를 데이터시트와 다른 의미("핀별 VSS")로 해석하는데도 동작 중 → 실칩이 A.5 매핑(0x02 write가 실제 Linearise를 켜는지)을 따르는지 자체가 미확인.

### 설계 함의 (impact)

1. self-cap에서 Release UI를 쓰려면 Linearise(bit1)+Invert(bit3)를 **반드시 동반 set** — 하나만 켜면 영원히 fire 안 됨 또는 즉시 오발.
2. **"방전 우회 구조"와 "Release UI"는 동시 사용 시 0x30 LSB read-modify-write로 비트 보존하거나 방전 경로를 CRX0 외로 바꿔야 함** — order code 001이 Release UI를 지원해도 현 방전 아키텍처와 양립 불가.
3. **검증 게이트**: Release UI 채택 결정 전 0x30 LSB 비트(특히 Linearise bit1) 실칩 동작을 RTT/오실로 실측으로 먼저 확정.

## B3 — Delta Snapshot settling (조건부사실)

### 핵심 근거

- **캡처 게이트(전제는 사실)**: DS §7.4 — |Counts − Activation LTA| < Activation Settling Threshold가 연속 N샘플(Delta Snapshot Sample Delay) 지속해야만 Delta Snapshot 기록. "터치된 채 부팅"이면 부팅 직후 손가락 정전용량이 이미 실려 settle 게이트를 통과한 적이 없으므로 **캡처 미발생** — 전제 사실확인.
- **미캡처 시 우변 0**: Delta Snapshot 레지스터는 POR 디폴트 0 → 해제식 우변 = 0×pct/128 = 0.
- **"즉시/영구미해제" 이분 가정은 부정확(반증)**: self-cap 부호상 Activation LTA가 터치 중에도 Counts를 추적하므로 손가락 부착 동안 좌변 ≤ 0 → `0 > 0` 거짓 → **즉시해제 안 됨**. 손가락을 떼면 Counts 상승으로 좌변 > 0 → 우변 0을 즉시 충족 → 정상 이탈 → **영구미해제도 아님**. 단 좌변이 미세 양수로 뜨는 noise 케이스에서 부팅 직후 1회 **spurious reseed** 가능(조건부).
- 현 펌웨어는 Release UI 미사용(0x30 bit6=0). 본 함의는 P1(데이터시트 활용) 설계안 채택 시에만 발효.

### 설계 함의 (impact)

- Release UI를 "터치부팅 자동 복구" 수단으로 단독 사용하는 발상은 **불충분·불확정**. 부팅 진입 baseline은 캡처 선행 조건 때문에 Release UI로 못 푼다.
- 부팅 시점 터치를 풀려면 보조 장치 필수 — 부팅 시 강제 RESEED + 손가락 제거 후 빠르게 캡처되도록 Settling Threshold/Sample Delay 튜닝, 또는 미캡처(우변 0) 구간 reseed를 SW가 별도 게이팅.
- Release UI는 '이미 settle된 장기터치 해제'엔 정합하나 '부팅 시점 터치'엔 직접 해를 주지 못함 → **RESEED/baseline 분리 전략과 병행** 필수.

## B4 — 웜부트 IC 보존 (반증)

### verdict 분해

| 부분 | 판정 |
|---|---|
| 전제: 웜부트는 CM3만 리셋(SYS_WATCHDOG_RESET), 터치 IC 전원 유지 | **사실** |
| 핵심 주장: "MCLR 미수행 → IC 내부 LTA·touch 상태 보존" | **반증(거짓)** |

### 핵심 근거

- **전원 유지(사실)**: 절전 롱터치 11회 누적 → `main.c:929 SYS_WATCHDOG_RESET()`. `func_sleep()`은 FPGA/nRF/QCC/PMIC만 OFF, IQS323 VDD(1.8V_QCC) 미차단.
- **그러나 웜부트마다 MCLR 강제(반증)**: CM3 워치독 리셋 후 재진입 경로 `main()` → `func_normal()` → `Initialize()` → `initialize.c:449 tdc_touch_init_begin()` → `tdc_touch.c:295 mclr_reset()` → IC POR. 이 경로는 무조건 실행되며 **reset-cause(웜/콜드) 분기가 없다**.
- **결정적 증거**: `initialize.c:444` 주석 "warm reset (워치독) 후 NRF 잔존 SPI 상태가…" 바로 뒤 :449에서 MCLR 호출. `tdc_drv_iqs323.h:374` "MCLR 하드 리셋. ~55ms 블로킹. IQS323 POR 발생 → Auto-ATI 시작."
- **결과**: MCLR=하드리셋=POR → 레지스터/LTA가 start-up default로 초기화. apply_settings()가 이후 새 LTA를 깐다. 즉 보존이 아니라 **매 웜부트마다 LTA·touch 상태 재초기화**.
- **문서 모순**: `펌웨어 구현·시퀀스 분석.md:165` "웜부트…MCLR 미수행 → IC 레지스터 상태 보존"은 코드와 불일치(오류). 같은 문장의 "Initialize()부터 재시작"이 곧 :449 MCLR 경로 — 자기모순.

### 설계 함의 (impact)

- "웜부트 = IC 웜 = LTA/상태 보존" 가정 위에 세운 설계안(부팅 시 ATI/LTA 재설정 생략, 모드전환 시 LTA 연속성 의존)은 현 펌웨어에서 **성립하지 않음**.
- 진짜 'IC 보존'을 원하면 **코드 수정 선행** — `initialize.c:449` 경로에 reset-cause 분기(콜드 POR vs 워치독 웜) 추가, 웜부트 시 MCLR 스킵 + Reset Event 미발생 상태로 통신만 재수립(DS §6.6.1: Reset Event clear면 event-mode 통신 가능, LTA 보존).
- 그 경우에도 보존 LTA 출처(절전 직전 노터치 vs 손가락 닿은 채)가 **양면적** → 실측 검증 필요.
- **분석.md:165부터 정정 필요**(거짓 전제 재참조 방지).

## B5 — RDY 인터럽트 (조건부사실)

### 핵심 근거

- **연결(사실)**: RDY는 DIO16에 하드와이어. `Board_OTE_ver1_5.h:46`·`tdc_drv_iqs323.h:26` → RDY/INTERRUPT_n/DIO16/Accelerometer 동일 물리핀, Active Low.
- **edge ISR 구현 가능(사실)**: 동일 파일 `ci_dio.c:121` `Sys_DIO_IntConfig(...DIO_INT_EVENT_FALLING_EDGE...)` 실증 템플릿 존재 + `DIO_0/1_IRQHandler`+`NVIC_EnableIRQ`. 핀소스 치환(DIO_34→DIO_16)+여유 IRQ 채널로 **보드변경 없이 SW만으로 즉시 구현 가능**.
- **풀업(충족 가능)**: 외부 풀업은 IC측 부재이나 ① IC RDY 내부 200kΩ active pull-up, ② E8300 DIO 내부 풀업 enable로 idle 레벨 확정 가능. 현재 `DIO_NO_PULL` → 보드변경 없이 변경 가능.
- **현재 상태**: RDY는 순수 GPIO 폴링(`Sys_GPIO_Read`). accel-int sleep 블록은 `#if 0`. DIO16은 `isPowerButtonPushed()`(`cfx_cm3_sharedMemory.c:129`)에서 power button으로 active-low 폴링 중 → **동일핀 공유**.
- **미검증(잔여)**: 슬립/ULP에서 DIO 인터럽트 wake-source 동작은 코드 근거 없음 — RDY event-mode wake 보장 미확인.

### 설계 함의 (impact)

- '폴링→이벤트 모드 전환'은 타당. HW/SW 전제 대부분 성립, 외부 부품 부재가 blocker 아님.
- 반드시 처리할 2건: ① **DIO16 power button(폴링)과 공유** → RDY ISR과 power-button 폴링 semantics 통합, ② **sleep/ULP wake-source 보장 실측**. wake 보장 깨지면 '이벤트 모드 wake' 부분 실패 가능 — 잔여 검증 포인트.

## B6 — Auto No ULP 전류 (실측필요)

### 핵심 근거

- **상호배타 전제(사실)**: DS §5.8 WARNING — "채널 prox/touch timeout 사용 시 ULP 모드 금지. 자동 전력 전환은 'Automatic No ULP'로 설정." §5.3 'Automatic No ULP' = "ULP에 절대 진입 안 함." 즉 Channel/Event Timeout(장기터치 release reseed)을 쓰려면 ULP 차단이 데이터시트 강제. P6 설계의 인용은 정확.
- **1ch 전류 수치 부재(추정만)**: DS §3.4 전류표는 self-cap을 **3채널 기준으로만** 제공(1.8V: NP 125µA / LP 37.0µA / ULP 4.00µA). **1채널 행 없음.** 측정조건도 모드별 report rate 상이(LP 60ms vs ULP 160ms) — ULP 절감 상당분이 report rate를 늘린 데서 나옴.
- **1ch 단순 환산 불가**: NP 소비에 채널 무관 고정 오버헤드(CPU 14MHz·clock·digital) 포함 → self 125µA(3ch)를 1/3로 보는 것은 **과소추정 위험**. 회로 분석 문서(회로 구성·분석.md:103)도 "실측 확인 필요(추정)"로 명기.
- **절전 예산 부재**: 공통제약 문서에 구체적 절전 전류/배터리 예산 수치가 **0건**(grep) → 허용 여부 판정 자체가 실측·사양 확인 대기.

### 설계 함의 (impact)

1. "Auto No ULP 강제"는 Channel Timeout/Release-reseed를 쓰는 모든 설계(P1·P6)의 데이터시트상 **필연·확정 제약**. 회피하려면 Channel Timeout 기반 release를 포기하고 SW 롱터치/자체 reseed로 대체.
2. worst-case는 ULP 4µA가 아니라 **LP 37µA(3ch)~그 1ch 환산값(미상)**이며 단순 1/3보다 큼 → 예산 산정 시 보수적으로 LP/3ch(37µA) 상한 근사.
3. 판정에는 ① 인공와우 절전 전류 예산 사양 확보, ② 실보드 self-cap 1ch NP/LP 실측(Event mode, 실 report rate)이 **둘 다 필요**. 초과 시 P6 fallback(ULP + SW 롱터치, Channel Timeout 비사용)으로 분기.

## 검증 종합

### 확정된 사실 (코드·데이터시트로 보장)

- **(B1 전반부)** MCLR 직후 IQS323은 start-up 0x040C(Full)로 복귀해 sensor_setup보다 **시간적으로 선행**하여 자율 Full auto-ATI 수행.
- **(B1 / 진짜 오염원)** 현 FIXED 경로의 LTA 시딩 단일점은 `apply_settings` 내 **Reseed**(`tdc_drv_iqs323.c:1134`)와 절전 진입 reseed(`main.c` → `tdc_drv_iqs323.c:932`). auto-ATI compensation은 `write_ati_compensation()`(1128)으로 폐기됨.
- **(B2)** self-cap+Release UI는 Linearise(bit1)+Invert(bit3) 동반 set 필수이고, 그 비트는 `discharge_crx0()`가 200ms마다 덮어쓰는 0x30 LSB와 **정면 충돌**.
- **(B5)** RDY는 DIO16 하드와이어, falling-edge ISR 템플릿이 `ci_dio.c`에 실재 → 보드변경 없이 구현 가능. DIO16은 power button과 물리 공유.
- **(B6 전제)** Channel Timeout 사용 시 Auto No ULP 강제는 데이터시트 §5.8 WARNING으로 확정.

### 반증된 가정 (설계 전제로 사용 금지)

- **(B4)** "웜부트 = IC 보존" — **거짓**. 코드는 매 웜부트마다 `initialize.c:449`→`mclr_reset()`로 IC를 POR시켜 LTA를 재초기화한다. 보존을 원하면 reset-cause 분기 코드 수정이 **선행**. `분석.md:165` 서술은 오류 → 정정 필요.
- **(B1 후반부)** "auto-ATI가 터치 정전용량을 baseline으로 잡아 방어 무력화" — 현 FIXED 펌웨어엔 **미해당**(과거 autoATI 방식에만 사실). 오염원은 Reseed로 재지정.
- **(B3)** "미캡처 → 우변 0 → 즉시해제 또는 영구미해제" — **부정확**. self-cap 부호상 둘 다 아니며 noise 시 spurious reseed만 위험.

### 실측 필요 항목 (우선순위순)

| 순위 | 항목 | 검증 내용 | 게이트 대상 |
|---|---|---|---|
| 1 | **B1 오염 실채널** | 터치한 채 MCLR 부팅 시 자율 auto-ATI compensation vs FIXED+Reseed 후 LTA/Counts를 RTT 1회 캡처 | Reseed 게이팅 설계 확정 |
| 2 | **B6 절전 전류** | self-cap **1ch** NP/LP 실측(Event mode, 실 report rate) + 인공와우 절전 예산 사양 확보 | Auto No ULP/Channel Timeout 채택 가부 |
| 3 | **B2 비트매핑** | 0x30 LSB Linearise(bit1) 실칩 동작 — 0x02 write가 실제 Linearise를 켜는가 (§8 미해결) | Release UI enable |
| 4 | **B5 wake-source** | 슬립/ULP에서 DIO16 인터럽트 wake 보장 + power button 폴링 semantics 통합 | RDY 이벤트 모드 wake |
| 5 | **B4 보존 LTA 출처** | (보존 트랙 채택 시) 웜부트 승계 LTA가 노터치였는지 | 웜부트 MCLR 스킵 분기 |

> [!IMPORTANT]
> **핵심 메시지**: 재설계의 zero-base 방어는 "auto-ATI 차단"이 아니라 **"Reseed 시딩 시점을 노터치로 게이팅"**이다(B1). "웜부트 보존"은 현재 거짓이므로 전제로 쓰려면 코드 수정+실측이 선행한다(B4). 미검증·조건부 항목(B2·B3·B6)은 모두 실측 게이트 뒤로 격리해야 한다.
