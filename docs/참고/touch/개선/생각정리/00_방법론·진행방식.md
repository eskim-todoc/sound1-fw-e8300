# 00 · 방법론 · 진행 방식

> **TL;DR**: 현재 구현을 출발점으로 삼지 않고 **zero-base**로 다관점 설계를 발산→교차 토론/비판→현재 비교→타당성 검증→종합한다. 다중 에이전트(6 설계 페르소나 + 비판 렌즈)가 토론하듯 주고받으며, 모든 중간 산출을 `생각정리/`에 문서로 남긴다.

## 핵심 원칙

1. **Zero-base**: "지금 self-cap·FIXED·200ms 방전·CalCap을 어떻게 고칠까"가 아니라, **"빈 종이에서 이 요구사항을 가장 잘 푸는 제어는 무엇인가"** 부터 시작. 현재 구현은 마지막에 비교 대상으로만 등장.
2. **근거 기반**: 모든 주장은 HW(회로 분석)·데이터시트(SSOT)·실제 코드 중 하나에 근거. 추정은 "추정/확인 필요" 명시. 할루시네이션 0.
3. **다관점 토론**: 단일 정답을 밀지 않고, 상이한 철학의 설계안을 병렬 발산 → 서로 비판 → 살아남는 것 + 하이브리드.
4. **과정 투명**: 결과뿐 아니라 발산·비판·조율·고민을 `생각정리/`에 족족 기록(개별 문서 분할 허용).

## 설계 페르소나 (Phase 1, 6관점)

각 페르소나는 같은 [01 문제정의·제약](01_문제정의·제약·평가축.md)을 입력받되 **서로 다른 철학**으로 설계한다.

| # | 페르소나 | 철학 |
|---|---|---|
| P1 | 데이터시트 기능 활용파 | IQS323 내장 UI(Release UI·Reference UI·ATI·이벤트모드) 최대 활용 |
| P2 | 측정방식 재검토파 | self-cap이 최선인가? mutual/inductive/ATI on 등 측정 원리부터 재선택 |
| P3 | 상태머신·UX파 | 전원 스위치 UX(롱터치·모드전환)를 견고한 FSM·디바운스로 |
| P4 | 강건성파 | 충전 채터링·ESD 누적·터치 중 콜드/웜부트 최악 가정 방어 |
| P5 | 전력·이벤트파 | 이벤트 모드·ULP·저전력 최적, 폴링 vs 인터럽트 |
| P6 | HW협업·근본개선파 | 회로 개선 전제(guard CRX1/TxA·전원 페라이트·채널) HW+SW 통합 |

## 비판 렌즈 (Phase 2)

- **렌즈 A — HW/데이터시트 가능성**: 회로·데이터시트로 실현 가능한가, order code 제약(001=Release UI) 위반은 없나.
- **렌즈 B — 요구/이슈 충족**: 전원 스위치 UX 충족? 9개 이슈 재발? 새 이슈 유발?
- **렌즈 C — 복잡도/리스크**: 구현·유지보수 복잡도, 실패 모드, 의존성.

## 문서화 규칙

- 각 에이전트 산출은 고유 파일로 `생각정리/`에. 번호 prefix로 Phase·순서 식별.
- 토론에서 의견이 갈리거나 조율되면 그 과정을 별도 메모로 남긴다(`2_비판_*` 또는 별도 `메모_*`).
- 결론은 근거 링크와 함께. "왜 이게 낫고 저게 못한가"를 트레이드오프로.
