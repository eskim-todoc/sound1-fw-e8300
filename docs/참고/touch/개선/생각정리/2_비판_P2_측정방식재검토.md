# 비판 · 설계안 P2 (측정방식 재검토파)

> **TL;DR**: 3렌즈 모두 **조건부**. 1순위 self-cap+ATI Full 게이팅은 HW 변경 0·데이터시트 정합으로 실현 가능하나, **핵심 메커니즘('터치 중 LTA frozen이 이슈 1~3을 막는다')이 순환 의존**이다 — frozen은 '터치가 이미 인식된 상태'를 전제하는데 이슈 1~3은 바로 그 인식이 안 되는 상황. 2순위 mutual-cap은 J3 단일 전극·TxA 플로팅이라 **현 HW로 불가(HW 변경 필수)**. ATI 게이팅을 4경로에 누락 없이 적용해야 하는 상태머신 복잡도 급증도 부담. 살아남으려면 '터치된 채 ATI 트리거 후 해제·재터치 인식' 단일 실험을 머지 전 통과해야 한다.

> [!NOTE]
> 본 문서는 워크플로우가 생성한 18개 비판 중 P2 관련 3개를 종합한 것이다. 비판 원문을 왜곡하지 않되 구조화했다. 설계안 본문은 [1_설계안_P2_측정방식재검토](1_설계안_P2_측정방식재검토.md) 참조.

## 렌즈 A — 가능성 (HW·데이터시트 실현가능성) · verdict: 조건부

### 핵심 findings
- **[견고] order code 001 제약 위반 없음** — 001=Release UI configurable(§10.1), A01만 Movement UI. 0x30 bit6을 Release UI로만 쓰고 Movement UI 레지스터 미사용 + Release UI를 '주 판정'이 아닌 '장기터치 고착 방어 보조'로 격하.
- **[정합] 1순위 self-cap+ATI Full 게이팅 — HW 변경 0** — 인용 레지스터 전부 실재(PXS 0x10 Self, Wav0=0x03, ATI Mode=Full bits[2:0]=100, Reseed/Re-ATI 0xC0). 현 FW가 ATI Disabled(0x36 LSB 0x08)인 것도 확인. Full 전환은 단일 레지스터 write 수준.
- **[불가] 2순위 mutual-cap — 실질 HW 변경 필요, SW-only 아님** — mutual은 Tx-Rx 전극 쌍 필수(Cm 0.2~9pF). 회로상 J3는 단일 스프링핀 1전극, TxA(B6)는 R30→NC 플로팅. 전극 추가 없이 불가. '현 HW로 불가, HW 변경 전제 조건부'가 정확.
- **[오류] Cp Rx-VSS 100pF 분석 미세 오류** — 설계는 'C51=100pF가 정확히 상한 일치'라 하나, 100pF 상한은 '@fxfer=1MHz, RCx=0Ω 기준'(각주 ⁱⁱ). 현 CRX0는 R31=100Ω 직렬 → **이미 0Ω 기준 상한 조건을 초과**. mutual 전환 시 C51 축소뿐 아니라 R31 재검토 동반 필요.
- **[조건부] ATI-frozen 전제** — '터치 중 LTA frozen'은 'touch 이벤트 인식 시'에만 성립. ATI Full 수렴 중(ATI Active) 판정 공백 동안 이벤트 미인식→frozen 비성립 시나리오가 §7 가정표에도 '확인 필요'. 데이터시트는 '항상'이 아니라 '이벤트 인식 시' 보장.

### blocking issues
| # | blocking |
|---|---|
| A-1 | **2순위 mutual: 현 HW(J3 단일 전극, TxA 플로팅 NC)로 Tx-Rx 전극 쌍 없음→mutual-cap 결합장 미형성.** Cm 0.2~9pF 충족 불가. 전극 추가/배선 HW 변경 없이는 데이터시트 보장 사용 아님. 단 2순위는 명시적 조건부이고 1순위 self-cap이 확실한 fallback이라 설계 전체를 무효화하진 않음(→반대 아닌 조건부). |

### suggestions 요약
- mutual(2순위)을 'HW 변경 필수(전극 쌍 신설+C51 제거+R31 재검토)'로 재분류, Cp 100pF 한계가 RCx=0Ω 기준임 반영
- ATI Active 구간 frozen 성립을 실칩 측정으로 게이트, 측정 전까지 '부팅 직후 ATI 보류'를 1차 방어로
- Release UI bit6 실칩 read-back 확인 + write_and_verify 실검증화
- Cs 80pF는 IQS3dd/IQS3ed 리비전 의존 — 현 칩 리비전(IQS323-001CSR) 확인 후 검증

## 렌즈 B — 요구·이슈 충족 · verdict: 조건부

### 핵심 findings
- **[부분 OK] UX 골격 보존** — FSM은 현 구조(proc_long_touch) 유지, 측정·ATI 계층만 변경. 웜부트 비대칭도 reset_event 비트로 처리. 단 '측정 신뢰성↑→UX 따라옴' 간접 논증.
- **[핵심] 이슈 1~5 재발 위험** — '터치 해제 확인 후에만 ATI'는 LTA frozen에 의존하나 frozen은 **이벤트 정상 트리거 전제** 위에서만 성립. 콜드부트/채터링 직후 ATI 미완 구간엔 LTA·threshold 기준 자체가 없어 touch 이벤트 미포착→frozen 미성립→이슈 1~3 사각지대 재발. 설계도 §7 '확인 필요' 1순위로 자인.
- **[타당] 이슈 6~9 해소 원리** — ATI Full로 매 conversion 자동선택+Target 정규화→raw count 340~660 변동(이슈 8) 흡수, 고정 threshold(이슈 9) 일관. 단 '**ATI가 터치 중 절대 안 걸린다'가 보장될 때만 성립** — 이슈 6~9 해소가 이슈 1~5 게이팅 완전성에 인질.
- **[신규이슈] ATI 수렴 공백** — ATI Active 동안 판정 보류→그 순간 시작된 터치 놓침. FIXED는 수렴 대기 없어 즉시 판정 가능했음. 채터링 재부팅 연쇄 시 공백 누적 가능(신규 실패모드).
- **[신규이슈] Release UI가 단순 bit6 아님** — Release UI는 slider 인프라(Enable Status Pointer 0x552·Delta Links·element order code·Total Channels)에 묶임. 'bit6=1만 켜면 동작'이 아니라 slider+gesture 서브시스템 설정 동반→'보조로만'보다 복잡도 큼.
- **[HW 불성립] mutual 2순위** — TxA NC·J3 단일 패드라 전극 쌍 없음→사실상 HW 재설계안. 드리프트 '원천 차단' 가치는 현 보드에서 실현 불가에 가까움.

### blocking issues
| # | blocking |
|---|---|
| B-1 | **[치명] ATI 게이팅 완결성이 '이벤트 트리거 전제'에 의존하나 콜드부트/재부팅 ATI 미수렴 구간에서 깨짐**→이슈 1~3(터치된 채 부팅 시 정전용량 baseline화)이 사각지대 재발. 설계의 2단 안전망(INIT 윈도 ATI 보류 + 둔감 임시 ATI)도 '둔감 baseline로 임시 ATI'를 콜드부트에 거는 것이라, 터치된 채면 그 baseline이 또 터치 정전용량 포함→**순환 의존**. '터치 해제 감지'를 ATI 없이 무엇으로 하느냐가 닭-달걀 문제로 미해결. 이슈 6~9 해소 전제이기도 해 실패 시 연쇄 붕괴. |

### suggestions 요약
- 콜드부트 닭-달걀을 ATI 비의존 1차 기준으로 끊기: 부팅 직후 절대 카운트 노터치 대역(FIXED 실측 340~660 보수적 하한)을 raw-count 게이트로
- ATI 수렴 공백 정량화 후 롱터치 타이머와 경합 명시 처리(ATI Active 동안 카운터 일시정지)
- Release UI를 보조로 쓰려면 slider 인프라 동반 부담 명시, bit6 실동작을 '가정'→'블로킹 확인' 승격
- mutual 2순위를 'HW 변경 필요'로 재분류, Cp 100pF vs C51 등치를 '검증 필요'로 강등
- write_and_verify 실검증화를 ATI Mode·PXS Mode 결정 레지스터에 구현 필수 게이트로 격상

## 렌즈 C — 복잡도·리스크 · verdict: 조건부

### 핵심 findings
- **[가장 치명] 순환 의존** — 설계 심장(§3.2)은 '터치 중 LTA frozen이 이슈 1~3을 막는다'에 기대나, frozen 전제는 '이벤트가 인식된 상태'. 이슈 1~3의 본질은 '터치된 채 부팅·전환되어 ATI가 정전용량을 baseline화→애초에 터치 이벤트 미인식'. frozen 작동하려면 터치 인식 필요, 터치 인식하려면 baseline 정상 필요, baseline 오염되면 터치 미인식→frozen 미성립 — **순환**. 설계 본인도 §7에서 인정.
- **[복잡도] SW 상태머신 급증** — 현 FIXED는 ATI 관련 분기 사실상 없음(ati_error조차 (void) 무시). P2는 '터치 해제 확인 후 ATI' 게이트를 콜드/웜/노말→절전/절전→노말 4경로 전부 적용 + ATI Active/Event/Error 폴링 상태머신 + 수렴 중 판정 보류 + Release UI 보조. 설계 자신이 '한 경로라도 누락되면 이슈 1~3 재발' 인정. **평가축 ④에서 현 구현보다 명백히 무거움.**
- **[충돌] 수렴 중 판정 공백 ↔ 롱터치** — 'ATI Active 동안 판정 보류'인데 요구는 '터치 해제 직후 1회 Re-ATI'. 모드 전환·해제마다 Re-ATI 돌고 그 직후가 재터치 구간. 채터링 재부팅 연쇄 시 공백 누적.
- **[개선] 개체편차·진단 가시성** — ATI Full은 매 conversion 보정·정규화로 개체편차 IC 흡수(현 FIXED 하드코딩 대비 개선). ATI Error 폴링·write_and_verify 실검증화로 진단 가시성도 향상. 복잡도 증가를 일부 정당화.
- **[격리됨] mutual 2순위 리스크 한정** — HW 게이트(전극 쌍 존재·Cp vs C51)가 명확, self-cap 1순위가 확실한 fallback이라 '몰래 들어오는 복잡도'는 아님.
- **[회귀] 폐지 항목 리스크** — CalCap 더미·200ms 방전 폐지 시 measurement cycle 정지·RDY 먹통 회귀 가능성 미검증(설계 §8 자인).

### blocking issues
| # | blocking |
|---|---|
| C-1 | **단일 핵심 메커니즘('터치 중 LTA frozen이 이슈 1~3을 막는다')이 순환 의존이며 설계 자신이 '확인 필요'로 분류한 미검증 가정.** frozen은 '터치가 이미 인식된 상태'를 전제하는데 이슈 1~3은 바로 그 인식이 안 되는 상황. 거짓이면 이슈 1~3 재발+설계 전체 붕괴. **채택 전 실칩에서 '터치된 채 ATI 트리거 시 이후 해제·재터치 인식되는가'를 반드시 측정해야 하는 BLOCKING 게이트.** |

### suggestions 요약
- **단일 검증 실험을 게이트로 강제**: 패드 누른 채 콜드부트→ATI Full→해제→재터치 인식되는지(frozen이 baseline 오염을 막는지) 실칩 측정
- 4경로 게이트 누락 방지: '단일 함수 중앙화' + grep으로 0xC0 bit2/bit3 직접 write가 중앙 함수 밖에 없음을 정적 검증, 4경로 회귀 테스트
- ATI Full 수렴 시간 실측해 '판정 보류 윈도 ≤ 롱터치 여유' 정량 확인, 길면 Compensation Only 절충 검토
- CalCap·200ms 방전 폐지 전 RDY/measurement cycle 회귀 격리 검증, 빌드 플래그로 롤백 경로 확보
- mutual은 빌드 플래그로 dead path 분기, 런타임 혼입 방지

### 치명 blocking 요약 (3렌즈 교차 수렴)
1. **'터치 중 LTA frozen이 이슈 1~3을 막는다'는 순환 의존** — B·C 렌즈가 동일 지목한 설계 심장. frozen 전제(터치 인식)와 문제 본질(인식 실패)이 상충. 실칩 검증 전 채택 불가.
2. **콜드부트/채터링 ATI 미수렴 구간의 '터치된 채 부팅' 닭-달걀** — ATI 비의존 1차 기준(raw-count 게이트) 없이는 미해결.
3. **mutual 2순위는 현 HW 불가** — 전극 쌍 부재. SW-only 오해 차단 필요(치명 아님, 1순위 fallback 존재).

### 이 안이 살아남으려면 (해결 필수)
1. **단일 검증 게이트**: 패드 누른 채 콜드부트→ATI Full→해제→재터치 인식 + frozen의 baseline 오염 차단 여부를 실칩 측정. 실패 시 게이팅을 'SW 해제 확인 후 ATI'에 전적 의존시키고 frozen 의존 문구를 보조로 격하.
2. **ATI 비의존 raw-count 게이트** 명시 설계로 frozen-event 의존 사각지대 보완.
3. **4경로 중앙화 + 정적/회귀 검증**으로 게이트 누락(=이슈 1~3 재발) 방지.
4. **mutual 2순위 분리** — 'HW 변경 필요'로 재분류, 차세대 보드 후보로 격리. self-cap 1순위에 전력 집중.
5. **폐지 항목(CalCap·200ms 방전) 회귀 격리 검증** + 롤백 빌드 플래그 유지.
