# 비판 · 설계안 P5 (전력·이벤트파)

> **TL;DR**: 3렌즈 모두 **조건부**. 레지스터 배선(plumbing) 자체는 견고하나 결함이 거동에 집중된다. ① **RDY→E8300 인터럽트 wake 경로가 HW/SW 모두 미구현·미검증**(현 코드는 DIO16을 MCLR 출력+폴링으로만 사용, GPIO edge ISR 부재, 풀업 '마스터 측 추정')—'폴링 제거'라는 척추가 미검증 가정 위. ② **Release UI 해제 부호(Linearise+Invert self-cap) 미확정**—틀리면 '터치 중 해제 영구 미인식' 현재와 동일 먹통 재현. ③ **자기모순**: '저전력 재설계'를 표방하나 §5.8로 No-ULP 강제(LP 37µA, ULP 4µA의 ~9배)되며, 동시에 터치 중 CH0 Timeout Disable로 stuck 복구를 끈다(전력 페널티는 내고 stuck 이득은 못 받음). 살아남으려면 이벤트 모드 전환을 최후로 미루고 Full ATI+Release UI를 현 폴링 위에서 먼저 검증하는 단계화가 필요하다.

> [!NOTE]
> 본 문서는 워크플로우가 생성한 18개 비판 중 P5 관련 3개를 종합한 것이다. 비판 원문을 왜곡하지 않되 구조화했다. 설계안 본문은 [1_설계안_P5_전력이벤트](1_설계안_P5_전력이벤트.md) 참조.

## 렌즈 A — 가능성 (HW·데이터시트 실현가능성) · verdict: 조건부

### 핵심 findings
- **[검증 완료] order code 제약 위반 없음** — Release UI만 쓰고 Movement UI 레지스터 미호출. 001=Release UI. 0xD3 상위(Activation Settling Threshold)도 'Release UI order code 한정'으로 001 유효.
- **[정확] 레지스터 비트/값 매핑** — Interface Events bit7, Power Mode 101=Automatic No ULP, CH0 Timeout Disable bit8, ATI Mode 100=Full, Linearise/Invert/Release UI 비트. CH Timeout Disable이 MSB(0x07) 조작인 점도 현 펌웨어와 정합.
- **[성립 가능] RDY 인터럽트 HW 경로** — RDY/MCLR(C7)→INTERRUPT_n→E8300, 내부 200kΩ active pull-up. 외부 풀업 부재라도 내부만으로 active-low 엣지 가능. 단 200kΩ 약한 풀업이라 RC(C58 1nF)·버스 용량 엣지 시정수·노이즈 마진 실측 필요(설계도 '확인 필요' 게이트로 명시).
- **[일치] 코드 ground truth** — force_window_open()·write_and_verify·s_boot_touch_ignore 보유→'재사용' 주장 타당. HW 변경 0.
- **[주의] 전력 수치 정합** — 'ULP 4µA'는 Self-cap 3채널 값. 본 회로는 Self-cap 1채널이라 실측 다를 수 있음. Automatic No ULP 채택 시 ULP 미진입→최저 LP(37µA) 수준. **'4µA'는 본 설계에서 사실상 미달성 목표**(설계도 §7 자인).

### blocking issues
| # | blocking |
|---|---|
| A-1 | **[치명·근원 미해결] Release UI Delta Snapshot이 '터치 중 콜드부트' 시 미캡처 가능.** Snapshot은 settling 구간(Counts−ActivationLTA < Settling Threshold, Sample Delay 연속) 이상 지속될 때만 기록. 손가락이 부팅 시점부터 닿아 있으면 settling 구간 자체가 없어 Snapshot이 0/미갱신→해제식 우변 0→오판(즉시해제 or 영구미해제). **'baseline 시점 무관' 헤드라인 주장이 데이터시트로 미성립.** 문제 근원(부팅 시점 기준 오염)을 Release UI가 자동으로 푼다는 중심 논거가 무너짐. 설계는 §6·§7 '확인 필요'로만 약하게 처리. |
| A-2 | **[치명·통신] 이벤트 모드 진입은 'Reset Event bit set 아닐 것' 요구(§8.12), ATI 중 I²C disabled(§8.4).** P5는 POR 후 ATI Full, 해제 확정 후 수동 Re-ATI, 절전 진입 Re-ATI를 모두 호스트 능동 트리거. Re-ATI 구간 I²C 막히면 Force-Comm으로도 설정/조회 불가. 이벤트 모드에서 RDY는 reset/event 시에만 low이므로 ATI 완료 통보(ATI Event)를 enable해 그 RDY로만 재진입해야 하나, P5는 ATI Event enable을 '필요 시'로만 언급→**Re-ATI 후 통신 재개 핸드셰이크 미명시**. 미해소 시 Re-ATI 후 먹통(통신 윈도우 상실). |

### suggestions 요약
- 'baseline 시점 무관' 주장을 데이터시트 근거로 재기술: Snapshot이 settling 없이는 미캡처→'터치 중 콜드부트'는 ①s_boot_touch_ignore 유지 ②해제 확정 후 강제 Reseed+Re-ATI ③그 다음 Release UI 정상 동작 2단계 분리. 근원 해결 톤 낮추기
- 수동 Re-ATI↔이벤트 모드 핸드셰이크 명시 시퀀스(ATI Event/Error enable→Re-ATI→I²C 비통신 인지→RDY 대기→통신 재개·에러 확인)
- Release UI 3파라미터(Sample Delay·Settling Threshold·Release Delta%) 실측을 1차 게이트로 격상, RTT로 Counts·Activation LTA·Delta Snapshot 동시 덤프
- 전력 목표를 'ULP 4µA' 아닌 'No ULP에서 LP 37µA'로 정정, ULP는 stuck 복구 포기 절전 전용 옵션으로 분리
- RDY 풀업·엣지 실측을 선행 HW 게이트로 확정

## 렌즈 B — 요구·이슈 충족 · verdict: 조건부

### 핵심 findings
- **[견고] 레지스터 인코딩 전부 정합** — 설정 배선(plumbing) 견고. **결함은 비트 오기록이 아니라 요구·이슈 레벨 거동에 있음.**
- **[과장] 콜드부트 '근원 해결'** — TL;DR은 'baseline 시점 무관'이라 단언하나 §6·§7은 'ATI Full이 터치 중 실행되면 그 정전용량 캘리브레이션→첫 진입 판정 오염→s_boot_touch_ignore 계승' 자인. **Release UI는 해제는 풀지만 진입 threshold LTA 오염은 못 풂.** 요구 #5·#6에 이 한계 상속.
- **[재발] 이슈 #9가 새 형태로** — 해제를 Release Delta%/128 변화율에 전적 의존. 2~3s 롱프레스 중 손가락 미세이동·정착으로 counts가 Activation LTA로 수렴→조기 해제→칩 reseed+상태 이탈. 호스트 롱터치 타이머가 enter→release로 동작하므로 가짜 release에 카운터 리셋→모드전환 실패. 절대카운트 편차(구)가 Delta% 오튜닝(신)으로 치환됐을 뿐 '됐다 안 됐다' 동일.
- **[신규 실패모드] 이벤트 모드 enter-edge 손실** — RDY는 enabled event 시에만 low, 지속 터치는 중간 이벤트 무발생. touch-enter 윈도우 놓치면 롱터치 타이머 시작조차 안 되고 다음 edge(release)까지 자가복구 불가. 폴링은 단발 누락에 강건하나 **event enter-edge 손실은 비대칭적으로 치명**(롱프레스 조용히 누락).
- **[자기모순] 전력 절감 명분** — '저전력 재설계'이나 §5.8로 No-ULP 강제→LP ~37µA vs ULP ~4µA(~9배 손해). stuck 복구 위해 No-ULP 택했다면서 동시에 터치 중 CH0 Timeout Disable로 stuck 복구 끔→전력 페널티 내고 stuck 이득 못 받음.
- **[경쟁조건] §8.4** — 자동 Re-ATI + Force-Comm 윈도우 겹치면 모드전환 write 직전 Re-ATI 발동 시 설정 stall 레이스(치명 아님, 미처리).

### blocking issues
| # | blocking |
|---|---|
| B-1 | **내부 모순 — 터치 중 stuck-touch 자동복구 상실.** §5.8은 Channel/Event Timeout이 곧 stuck-touch reseed 안전망임을 명시. 그런데 설계는 '터치 중 CH0 Timeout Disable=1'로 설정→롱프레스(2~3s, 요구 #2/#3 핵심 윈도우) 동안 칩 HW stuck 복구를 의도적으로 끔. 동시에 'Event Timeouts stuck 복구'를 안전망으로 광고→**같은 기능을 안전망으로 광고하면서 가장 필요한 순간(터치 중) 끄는 정면 모순.** 이 구간 유일 해제 검출기는 Release UI 하나뿐, 오튜닝되면 무한 stuck→모드전환 영구 먹통. |
| B-2 | **Release UI 단일 의존 해제 신뢰성이 요구 충족의 SPOF.** 진입은 threshold, 해제는 Release UI 변화율 하나에 전적 의존. stuck 복구를 터치 중 껐으므로 Release Delta%·Settling Threshold·Sample Delay 실측 튜닝이 빗나가면 (a)해제 못 잡음→영구 stuck (b)조기 해제→롱터치 카운터 리셋, 양방향 모두 전원 스위치 UX 파손. 이 파라미터들이 설계 자신이 '확인 필요(실측)'로 분류→요구 충족이 미검증 실측치에 걸림. 무조건 지지 불가. |

### suggestions 요약
- 터치 중 CH0 Timeout Disable 재검토: 롱터치 최대시간보다 넉넉히 긴 Touch Event Timeout을 '터치 중에도 enable' 유지→Release UI 실패 시 HW reseed가 stuck 자동 회수(이중 안전망). Re-ATI만 호스트가 해제확정 후, timeout-reseed는 살려둠
- 호스트 롱터치 판정을 enter-edge 단발 의존하지 말 것(Force-Comm 주기 200~300ms status 확인 하이브리드로 enter-edge 누락·가짜 release 교차검증)
- Release UI 파라미터 실측을 설계 승인 선행 게이트로 명문화
- 콜드부트 '근원 해결' 문구를 '해제 검출 개선 + 진입 LTA 오염은 boot-touch-ignore 병행'으로 정정
- 전력 명분 정합('LP 스테핑 기반 폴링 제거 절전'으로 한정, ULP 4µA는 stuck 복구 포기 옵션 분리, 수치 결정표화)
- 자동 Re-ATI↔Force-Comm 레이스 대응(ATI Active bit 확인 후 윈도우 진입 or ATI 완료 ACK 게이트 뒤 직렬화)

## 렌즈 C — 복잡도·리스크 · verdict: 조건부

### 핵심 findings
- **[과도] 동시 도입 폭** — (1)이벤트 모드+RDY 인터럽트 (2)Full ATI 재도입 (3)Release UI 이중 LTA (4)Automatic No ULP 자동 스테핑 (5)터치 중 조건부 Channel Timeout 토글 — 5개 독립 대형 변경을 한 zero-base에 동시 투입. 각각 별도 실패 모드·상호작용(Timeout Disable↔ULP 금지↔Power Mode 정책). 현 코드는 폴링·FIXED·방전이라 재사용분 적음→**사실상 드라이버 재작성**. 단일 PR/검증 단위 분해 불가→회귀 시 원인 격리 어려움.
- **[척추가 가정] RDY 인터럽트 wake 미구현** — 현 펌웨어에 없음. RDY=DIO16이지만 코드는 MCLR용 GPIO 출력으로 구동, 상태는 폴링. DIO16 edge-detect ISR·NVIC·웨이크 소스 부재(GPIO 인터럽트는 SPI1만). 절전 루프는 ULP_TIMER(200ms)+WAIT_FOR_INTERRUPT 즉 타이머 wake. **'폴링 제거'가 신규 ISR+디바운스+풀업 실재 검증이라는 미검증 의존성에 통째로 걸림.**
- **[자가당착 위험] Release UI 해제 부호** — §7.4 해제식 (Counts−ActivationLTA)>Snapshot×Release%/128. self-cap 진입은 counts 내려감(§5.7). 해제식 성립하려면 counts가 LTA 위로 올라와야→Linearise+Invert 추가. 펌웨어 §8이 0x30 LSB 인코딩이 INACTIVE_RXS 방전 로직과 충돌·해석 불일치 지적, P5도 'Linearise+Invert self-cap 부호'를 미검증. **해제 판정 부호 미확정 — 단일 실패점.**
- **[가시성 저하] 이벤트 모드** — 평소 RDY high라 라이브 디버깅 어려움. Activation LTA·Delta Snapshot 보려면 Force-Comm 강제, 그 read가 watchdog kick·전력 모드 개입. **의존하는 실측 튜닝이 가장 보기 어려운 모드에서 이뤄져야 하는 역설.**
- **[충돌] Force-Comm ↔ MCLR 핀** — 통신 윈도우 open 시 IC가 RDY/MCLR을 low로 당기고 MCLR disable(150µs switchover). 매 터치 진입/해제마다 0xC0 write를 Force-Comm으로 수행→윈도우 구간 HW 리셋(채터링 복구 결정성) 일시 무력화. '채터링 복구 결정적·빠름' 주장과 미묘 상충.

### blocking issues
| # | blocking |
|---|---|
| C-1 (BLOCKER-1) | **RDY→E8300 인터럽트 wake 경로가 HW/SW 모두 미검증·미구현.** 절전 wake·폴링 제거가 이 단일 가정에 의존하나, 현 코드는 DIO16을 MCLR 출력+폴링으로만 쓰고 GPIO edge ISR 없으며 회로 측 RDY/I²C 풀업도 '마스터 측 추정'(§2.5 4.7kΩ 권장 대비 부재). 풀업 실재·DIO16 wake-from-deep-sleep 가부가 선행 게이트로 확정 전엔 설계 동작 자체 미보장. |
| C-2 (BLOCKER-2) | **Release UI 해제 판정 부호/극성(Linearise+Invert self-cap) 미확정.** P5가 '문제 근원 해결' 핵심으로 내세운 해제 경로가 §7.4 식 방향+self-cap 부호+Linearise+Invert 정합에 의존하고, 그 0x30 비트 인코딩이 펌웨어 §8에서 이미 데이터시트와 불일치 관찰. 부호 반대면 '터치 중 해제 영구 미인식'이라는 현재와 동일 먹통 재현. 실측으로 부호 확정 전 채택 불가. |

### suggestions 요약
- **단계적 도입(de-risk by phasing)**: ①Full ATI+조건부 Re-ATI를 현 폴링 구조 위에서 먼저(이슈 6·8·9 단독 확인) → ②Release UI 해제 판정만 추가(부호 실측) → ③마지막에 이벤트 모드+RDY. 이벤트 모드는 가장 큰 미검증 의존성이라 끝까지 미룸
- BLOCKER-1 선행 게이트화(풀업 실측, DIO16 edge ISR+절전 wake, Force-Comm↔MCLR switchover PoC), 통과 못 하면 '폴링 유지+Full ATI/Release UI만' 축소안 폴백
- BLOCKER-2 부호 실측 프로토콜(Linearise OFF/ON × Invert OFF/ON 4조합 RTT 덤프 표로 확정 후 0x30 비트 고정), 0x30 INACTIVE_RXS 충돌 선해소
- write_and_verify를 전력/타이밍 민감 비트(0xC0)로 한정, 나머지 초기화 1회만 verify
- Automatic No ULP vs 순수 ULP 전력 정책(stuck 복구 상실 트레이드오프)을 설계 승인 전 사용자 결정 항목으로 표면화

### 치명 blocking 요약 (3렌즈 교차 수렴)
1. **RDY→E8300 인터럽트 wake 경로 미구현·미검증** — A·C 렌즈 지목. '폴링 제거' 척추가 신규 ISR+풀업 실측에 통째로 의존.
2. **Release UI 해제 부호(Linearise+Invert self-cap) 미확정** — A·B·C 모두 지목. 틀리면 현재와 동일 먹통 재현.
3. **'저전력' 자기모순 + 터치 중 stuck 복구 상실** — B 렌즈 핵심. No-ULP 강제로 전력 페널티(~9배) 내고 터치 중 CH0 Timeout Disable로 stuck 이득 못 받음.
4. **콜드부트 '근원 해결' 과장** — Release UI는 해제만 풀고 진입 LTA 오염은 boot-touch-ignore 여전히 필요.

### 이 안이 살아남으려면 (해결 필수)
1. **단계적 도입**: Full ATI+조건부 Re-ATI를 현 폴링 위에서 먼저 검증 → Release UI 부호 실측 추가 → 이벤트 모드를 최후 단계로. 전면 재작성 회피.
2. **BLOCKER-1 선행 게이트**: 풀업 실측·DIO16 edge ISR+절전 wake·Force-Comm↔MCLR switchover PoC. 미통과 시 폴링 유지 축소안.
3. **BLOCKER-2 부호 실측 프로토콜**: 4조합 RTT 덤프로 0x30 비트 고정, INACTIVE_RXS 충돌 선해소.
4. **터치 중 Timeout 정책 재검토**: 넉넉한 Touch Event Timeout을 터치 중에도 enable해 HW reseed 이중 안전망 확보.
5. **전력 명분·목표 정정**: ULP 4µA 아닌 LP 37µA로, '저전력'을 'busy-loop 제거 절전'으로 한정. Power Mode 정책을 사용자 결정 항목으로 표면화.
