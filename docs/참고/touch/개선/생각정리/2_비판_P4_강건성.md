# 비판 · 설계안 P4 (강건성파)

> **TL;DR**: 3렌즈 모두 **조건부**. Full ATI 복귀로 이슈 6·8을 가장 확실히 차단하고, Reset Event 분기·데드맨 4겹으로 '실패해도 복구'하는 철학은 견고하다. 그러나 **한 번에 7개 미검증 기능(Release UI·Reference UI·Full ATI·Dual Direction·Linearise·Event Mode·데드맨 4겹)을 동시 도입**해 복잡도가 수배 팽창하고, ① Release UI 이탈 판정의 self-cap 부호 정합 미검증, ② 데드맨 #4(노터치 수동 Re-ATI)가 §8.4 'ATI 중 I²C disabled'로 **자기간섭**(통신 블랙아웃 유발), ③ Channel Timeout·Power Mode Timeout·롱터치 2.4s **3타이머 정렬 미해결**이라는 세 BLOCKING이 있다. Reference UI는 CRX1(C52 100nF·J4 전극 미연결)로 회로상 빈 껍데기라 실질은 Release UI 단독. 살아남으려면 단계적 활성화·타이머 부등식 고정·부호 실측이 필요하다.

> [!NOTE]
> 본 문서는 워크플로우가 생성한 18개 비판 중 P4 관련 3개를 종합한 것이다. 비판 원문을 왜곡하지 않되 구조화했다. 설계안 본문은 [1_설계안_P4_강건성](1_설계안_P4_강건성.md) 참조.

## 렌즈 A — 가능성 (HW·데이터시트 실현가능성) · verdict: 조건부

### 핵심 findings
- **[확정] order code 001=Release UI 위반 없음** — §10.1 001='3 button self capacitance with Release UI'. Movement UI 레지스터 미사용. A.32/A.34가 'Release UI order code 한정'으로 001에서 유효.
- **[정확] 핵심 레지스터 비트 전부 실재** — Automatic No ULP=0xC0 bits[6:4]=101, ATI Band Large bit3, Re-ATI/ACK/Soft Reset, Event Mode bit7, Reset Event bit7, Event Timeouts ×512ms. 매핑 정확.
- **[보장] Dual Direction·Full ATI·Watchdog** — §5.7(Counts>LTA+Th OR Counts<LTA−Th)·§5.9·§7.6·§8.8. 데이터시트 보장 사용(평가축 ⑧ 충족).
- **[불가] Reference UI는 현 회로로 실현 불가에 가까움** — CRX1은 C52=100nF(CH0 C51 100pF의 1000배, DC차단/AC커플링) + J4 전극 미연결('배선 완료, SW 미사용'). §7.3 'reference는 sensing과 동일 환경 노출+사용자 비접촉' 요건을 전극 없는 J4가 못 채움→드리프트 보정 기준으로 무의미. graceful degradation으로 'Release UI 단독'이 사실상 기본값.
- **[강한 주장] Release UI '터치 중 부팅 무력화'가 보장보다 강함** — Delta Snapshot은 settling 선행 필요(§7.4). '터치 누른 채 콜드부트' 직후엔 정착된 Snapshot 없을 수 있어 손 뗌 판정 즉시 보장 단정 불가. 설계도 '전원버튼 적용성=확인 필요, long-term touch 해제용으로 명시' 자인.
- **[검증 필요] Linearise+Invert+Dual Direction 동시 활성** — invert된 좌표계에서 양극성 판정 정합을 데이터시트가 조합 예시로 주지 않음. 논리상 가능, 실칩 검증 영역.
- **[충돌 소지] ATI 중 통신 제약** — §8.4 'Reset Event bit set 아니면 ATI 동안 I²C disabled'. 매번 Full ATI 재실행 + write-verify·Force Comm을 ATI 중 시도하면 통신 막힘. Program Flow 순서 엄수 필요, 데드맨 수동 Re-ATI도 ATI 중 통신창 닫혀 즉시 확인 불가.

### blocking issues
| # | blocking |
|---|---|
| A-1 | **CRX1 Reference UI는 현 HW로 실현 불가** — C52 100nF DC차단 + J4 전극 미연결. 설계가 '주방어 Release UI + 보조 Reference UI 이중화'를 핵심 가치로 내세웠으나 보조축이 회로상 빈 껍데기. '단일 실패점 제거' 이중화 주장이 HW 사실로 미성립→실질은 Release UI 단독. 살리려면 J4 전극 연결+C52 재검토(HW 변경) 선행 필요. |

### suggestions 요약
- Reference UI를 '보조 이중화 핵심'에서 빼고 'HW 변경 시 옵션'으로 강등, 강건성 서사를 Release UI 단독 기준으로 재기술
- Release UI '터치 중 부팅'을 Delta Snapshot 미정착 콜드부트 케이스로 구체화, BOOT_TOUCH_GUARD를 '미정착 시 hysteresis 우선'으로 규정
- ATI 중 통신 차단(§8.4)과 write-verify/Force Comm/수동 Re-ATI를 시퀀스 다이어그램으로 분리, ATI Event 확인 후에만 후속 발행
- Linearise+Invert+Dual Direction 3비트 조합 self-cap 정합을 실칩 1순위 검증
- 데드맨↔No ULP 전력 트레이드오프는 §5.8로 회피 불가임 명확화, Report Rate 튜닝으로 닫기

## 렌즈 B — 요구·이슈 충족 · verdict: 조건부

### 핵심 findings
- **[정합] 전원 스위치 2~3초 롱터치** — Dual Direction self-cap + 둔감 threshold가 §5.7과 정합. 롱터치 2.4s FSM 유지 합리적. 단 Release UI를 '주 이탈 판정'으로 올린 것이 요구 시나리오와 미스매치 소지.
- **[튜닝 의존] 이슈 1~4·9 근본 해소가 '구조적' 아닌 '튜닝 의존'** — §7.4 Release UI는 'long term touch 해제용'이고 설계도 '전원버튼 적용성=확인 필요' 자인. 즉 이슈 1~4 해소가 미검증 가정 위.
- **[확실] 이슈 6·8 해소** — Full ATI 복귀로 ATI Target 자동 정규화→'매 부팅 raw 340~660 변동' 직접 원인 제거. **9건 중 가장 확실한 재발 차단.**
- **[잔존] 이슈 1~3 재발 위험** — §8.4로 웜부트 경로에서 Re-ATI 돌면 그 구간 I²C 먹통=‘터치 중 ATI 먹통' 변종. 설계는 'LTA frozen이라 Re-ATI 안 걸림'으로 방어하나 frozen 진입 전(부팅 직후 시드 구간)·ATI Band 튜닝 실패 시 빈틈.
- **[잔류] ATI Error stuck-touch 데드락** — §5.11 'ATI Error 시 자동 re-ATI 안 됨, master 수동'. 손가락 stuck 상황에선 노터치 게이트가 영원히 안 열려 자가복구 불가. Channel Timeout reseed가 유일 탈출구인데 그 값이 '확인 필요'→복구 지연.
- **[전력 트레이드오프] ULP 포기** — §5.8/§7.5로 No ULP 강제는 불가피하나 요구 #4와 정면 트레이드오프. 절전 평균 소비 증가는 '요구 충족'이 아니라 '요구 완화'.
- **[회귀 위험] 복잡도 → 이슈 9 재현** — 튜닝 변수 폭증, 확인필요 8개 중 다수 실측 의존. 하나라도 빗나가면 둔감/과민으로 이슈 9가 다른 형태로 재현.

### blocking issues
| # | blocking |
|---|---|
| B-1 | **Release UI 이탈 판정 부호/방향 정합 미검증(치명 가능).** §7.4 이탈식 (Counts−ActivationLTA)>(...). self-cap은 터치 시 Counts가 LTA 아래(좌변 음수), 우변 양수→Linearise+Invert로 부호 안 뒤집으면 이탈 영원히 미성립. 데이터시트는 '§7.4 Linearise 권장'까지만, Release UI 내부 비교와 맞물리는지 미명시. 깨지면 주 이탈 메커니즘 통째 작동 불능→이슈 #4 재발. 실칩 검증 전 P4 심장 미검증. |
| B-2 | **Release UI 단일 채널 전원버튼 적용성이 설계 전체 단일 의존점인데 '확인 필요'.** 이슈 1~4·9 '근본 해소'가 전부 이 한 메커니즘에 걸림. 적용 불가/튜닝 실패 시 fallback인 '표준 hysteresis 단독'은 곧 부팅 시점 LTA 의존 문제 회귀→이슈 1~4 재발. 두 경로가 같은 오염 LTA 공유하면 이중화 아님. |

### suggestions 요약
- Release UI 부호 정합을 1순위 PoC로 분리(Linearise+Invert에서 release 시 양 방향 증가 실칩 캡처), 통과 못 하면 핵심 가정 폐기/재설계
- 이슈 1~4 해소를 'Release UI 의존'에서 'BOOT_TOUCH_GUARD + 노터치 게이트 Reseed' 부팅 비의존 경로로 1차 방어 이전, Release UI는 보조 강등
- 웜부트 경로 §8.4 빈틈 차단(Re-ATI 강제 억제, 노터치 확인 후만 수동 트리거)
- ATI Error stuck-touch 데드락 대비(Channel Timeout 값 구체화, ATI Error 이벤트 N회 연속 시 강제 reseed)
- 전력 요구를 정량 게이트로(No ULP 절전 평균 실측, 초과 시 Report Rate/데드맨 단계적 degrade)
- ESD 근본(R31 100Ω·R28 0Ω 무필터)은 HW 보강을 '권고' 아닌 필수 전제로 격상, SW-only 한계 명시 제외
- Release→Reference→Dead-man 단계적 활성을 강제 마일스톤으로, 각 단계 이슈 9건 회귀 체크리스트

## 렌즈 C — 복잡도·리스크 · verdict: 조건부

### 핵심 findings
- **[동시활성 부담] 7개 미검증 기능 동시 도입** — Release UI·Reference UI·Full ATI·Dual Direction·Linearise·Event Mode·4겹 데드맨. §6 확인필요 8항목, 다수 실측 튜닝 의존. 현 구현(self-cap+FIXED+200ms 방전+CalCap) 단일채널·고정값 대비 SW 상태·예외·튜닝 표면 수배 팽창. 설계 자신도 '복잡도 증가는 강건성파 본질적 트레이드오프' 인정.
- **[자기간섭] ATI 중 통신 lockout** — §8.4. Full ATI + Event Mode + 수동 Re-ATI 모두 사용. Re-ATI 도는 동안 I²C 막히면 RDY 핸드셰이크·write-verify·Reset Event 포착 모두 실패 가능. **데드맨 #4가 스스로 통신 블랙아웃 유발 — 설계 어디에도 미처리.**
- **[충돌] 데드맨 #1 ↔ 롱터치** — Channel Timeout reseed vs 정상 2.4초 롱터치. §5.2 'power mode timeout보다 긴 채널 timeout→power 강하'까지 얽혀 Channel Timeout·Power Mode Timeout·롱터치 FSM **3타이머 상호 정렬을 실측으로 맞춰야 함**→튜닝 실패 시 정상 롱터치 끊김 or stuck 안 풀림 양방향 오류.
- **[개체편차 전가] FIXED→Full ATI** — 카운트 정규화로 개체편차 해소하나 대가로 Release UI가 Delta Snapshot 상대 판정에 의존. ESD 누적·전극 편차로 settling 안 잡히면 스냅샷 오염. 개체편차가 자리만 옮김+**진단 가시성 저하**(변화율이 절대 카운트보다 읽기 어려움).
- **[회로 부적합] Reference UI** — CRX1 C52=100nF AC커플링이라 self-cap baseline 추종 특성이 CH0와 다를 수 있어 '드리프트 동등 추종' 전제 깨질 위험. graceful degradation 경로는 적절하나 이중화 한 축이 실효성 불확실인 채 복잡도만 추가.
- **[HW 미검증] Event Mode 전환** — I²C 풀업 칩 측 부재(마스터 측 추정), RDY 인터럽트 배선·풀업 미확인. 폴링→이벤트 전환은 드라이버 핸드셰이크 재작성→복잡도·회귀 위험.
- **[자기모순] Linearise+Invert 짝** — 0x30에 Linearise(bit1)·Invert(bit3)·Dual Direction(bit2) 동시 set. 코드분석 §8에서 이미 0x30 LSB 비트 해석(Inactive Rxs vs Linearise/Invert) 데이터시트↔코드 불일치 관찰된 영역→회귀 함정 가능성 높음.

### blocking issues
| # | blocking |
|---|---|
| C-1 | **데드맨 자기간섭 — 설계 보강 필수.** §8.4(ATI 중 I²C disabled)와 데드맨 #4·Event Mode·write-verify가 같은 시간축 충돌. Re-ATI 발행→ATI 중 I²C 막힘→그 사이 Reset Event/Touch 이벤트·검증 write 유실 가능. lockout 윈도우 동안 동작(폴링 fallback·ATI 완료 대기·ATI 소요 상한) 미명시. **4겹 데드맨이 상호/칩 내부 상태와 간섭 안 함을 증명 전엔 '자동 복구 보장' 미성립.** |
| C-2 | **타이머 3중 정렬 미해결.** Channel Timeout(#1)·Power Mode Timeout(§5.2)·롱터치 2.4s 세 타이머가 모두 'touch 지속시간'을 보고 다른 동작(reseed/power 강하/모드전환). 값 정렬을 실측 전제로만 두면 정상 2.4초 롱터치 끊김(UX 파손) or stuck 안 풀림(강건성 파손) 양쪽 동시 존재. 정렬 규칙을 부등식으로 못박지 않으면 튜닝 지옥. |

### suggestions 요약
- **단계적 활성화 명문화**: ①Full ATI+write-verify(저위험) → ②Release UI 단독 → ③Event Mode/RDY → ④Reference UI → ⑤데드맨 4겹. 각 단계 독립 검증·롤백 게이트
- §8.4 lockout과 데드맨·Event Mode 상호작용을 시퀀스 다이어그램 분석(Re-ATI 중 이벤트 유실 처리, §8.4 예외 활용)
- 타이머 정렬 부등식 고정: Channel Timeout > 롱터치 2.4s + 마진, Power Mode Timeout 정책 명시(0x00 강하 금지 검토)
- Release UI 진단 가시성 확보(Delta Snapshot·Activation LTA·Release% 마진 RTT 상시 로깅)
- CRX1 Reference는 C52 적합성 실측 전까지 '선택 기능' 코드 분리(CRX1_REF_ENABLE 플래그)
- Linearise+Invert+Dual Direction 부호 조합을 0x30 비트 단위 실칩 검증

### 치명 blocking 요약 (3렌즈 교차 수렴)
1. **Release UI 이탈 판정 self-cap 부호 정합 미검증** — A·B·C 모두 지목한 설계 심장. Linearise+Invert가 코드분석 §8 충돌 비트필드 위.
2. **데드맨 #4(수동 Re-ATI)의 §8.4 자기간섭** — ATI 중 I²C disabled로 통신 블랙아웃 자가유발. '자동 복구 보장' 미성립.
3. **Channel Timeout·Power Mode Timeout·롱터치 2.4s 3타이머 정렬 미해결** — 부등식 미고정 시 양방향 실패 동시 존재.
4. **Reference UI 회로상 실현 불가** — C52 100nF·J4 전극 미연결로 이중화가 빈 껍데기.

### 이 안이 살아남으려면 (해결 필수)
1. **단계적 활성화**를 강제 마일스톤으로(①Full ATI+verify → ②Release UI → ③Event Mode → ④Reference UI → ⑤데드맨), 각 단계 독립 롤백·이슈 9건 회귀 체크리스트.
2. **Release UI 부호 정합 1순위 PoC** — 실패 시 핵심 가정 폐기/재설계.
3. **§8.4 lockout 시퀀스 분석** — 데드맨·Event Mode·write-verify의 ATI 중 동작을 다이어그램으로 명시, 이벤트 유실 처리 정의.
4. **타이머 부등식 고정** — Channel Timeout > 롱터치+마진, 정상/stuck/power 강하 3구간 시간축 비중첩 설계.
5. **Reference UI를 HW 변경 옵션으로 강등** — 강건성 서사를 Release UI 단독 기준으로 재기술, ESD HW 보강을 필수 전제로 격상.
