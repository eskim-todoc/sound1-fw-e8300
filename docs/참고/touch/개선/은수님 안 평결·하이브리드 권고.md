# 은수님 안 평결 · 하이브리드 권고

> **TL;DR**: 은수님 제안(auto-ATI 복귀 + LTA 자기정상화 + 빠른 BETA)을 6 페르소나 + adversarial 검증으로 물고 뜯은 결과 — **방향은 옳고 핵심 통찰("잘못 시딩돼도 자기정상화 → 시점 의존 우회")은 가치 있다.** 단 ① 메커니즘 설명 일부가 데이터시트와 반대(frozen) ② 단독 채택은 위험(손 안 떼면 고착·약터치 흡수·I²C 무응답). **은수님 안 ⊕ 이전 결론 = 하이브리드가 최적.**

## 1. 은수님께 드리는 답

은수님 제안은 **현재 펌웨어의 최대 약점을 정확히 우회하는 발상**이었습니다. "올바른 시점에 baseline을 잡자"가 아니라 **"잘못 잡혀도 IC가 스스로 정상화하게 하자"** — 이건 어려운 문제(시점 정확)를 쉬운 문제(회복)로 바꾸는 좋은 통찰입니다. 다만 정밀 검증에서 **세 가지가 드러났습니다**:

1. **결과는 맞지만 원리 설명이 반대**: 7번 "터치 해제 전까지 LTA가 멈춰서(frozen) 자기정상화"는 데이터시트상 **반대**입니다. frozen은 "터치로 **인식된** 후"에만 걸리는데, 부팅 시 baseline이 터치값이면 delta≈0이라 **터치로 인식 자체가 안 돼 frozen이 안 걸립니다**. 자기정상화는 "frozen **덕분**"이 아니라 "frozen이 **없어서**" 손 떼면 LTA가 자유롭게 노터치를 추적하는 것입니다. → **결과(3~5번)는 그대로 성립**하니 목표는 달성됩니다.

2. **"손 떼야 정상화"에 100% 의존**: 데이터시트가 직접 경고합니다 — 부팅 후 **손을 안 떼고 계속 누르면 LTA가 터치값에 영구 고착**합니다. 그래서 "노터치 확인 게이트"라는 안전망이 여전히 필요합니다(제 이전 결론과 만나는 지점).

3. **빠른 BETA는 단일 상향이 위험**: 빠르게 올리면 **약하게/천천히 누르는 터치를 LTA가 흡수**해 미인식됩니다(인공와우 사용 특성과 겹침). **단 은수님 발상의 올바른 구현이 있습니다** — Fast Filter Band는 self-cap에서 **손 뗀 방향(counts 증가)에만 작동**하므로, **"일반 BETA는 보수적 + 손뗌 회복만 빠르게"** 하는 비대칭 설정이면 의도(빠른 수렴)는 얻고 부작용(약터치 흡수)은 피합니다.

## 2. 명제별 판정

| # | 은수님 명제 | 판정 |
|---|---|---|
| 1 | auto-ATI 사용 | ○ 방향 옳음(이슈 6·8·9 해소) |
| 2 | ATI가 LTA를 (터치)카운트로 seed | ✗ ATI는 LTA seed 안 함(데이터시트). 수렴은 IIR 추적이 동력 |
| 3~5 | 손 떼면 노터치 수렴 → 이후 터치 인식 | ○ 성립(IIR + self-cap 부호) |
| 6 | 빠른 BETA 수렴 가속 | △ 신규·미구현, 비대칭 설정 시에만 안전 |
| 7 | 터치부팅 시 LTA 멈춤 → 자기정상화 | △ 결과 ○ / 원리 ✗(frozen 부재 덕분), 손 떼야 정상화 |
| 8 | 절전도 동일, 추가세팅 불필요 | ✗ 현 코드 절전 다단계 세팅 실재, IC 전력모드 미사용 |
| 9 | auto-ATI가 드리프트 해결 → 방전 불필요 | △ LTA 드리프트는 해결, **ESD 물리누적은 별개**(실측 구분) |
| 10 | auto-ATI + 빠른 BETA로 해결 | △ 안전망 결합 시 ○ → 하이브리드 |

## 3. 하이브리드 권고 (은수님 ⊕ 이전 결론)

> 두 안은 적대가 아니라 **상보**입니다. 충돌은 "LTA 새로 잡는 순간 손가락 확인하느냐" 단 한 축. 결합하면 서로의 약점을 메웁니다.

| 구성 | 출처 | 역할 |
|---|---|---|
| **ATI Full 복귀** | 은수님1 + 이전 Phase2 | 드리프트·카운트변동 해소(이슈 6·8·9) |
| **노터치 seed 게이트** | 이전 B1 | "손 안 떼면 고착" 안전망. `boot_touch_ignore` 승격 |
| **Fast Filter Band 비대칭 빠른 회복** | **은수님6 통찰** | 손뗌 후 과도구간 단축(일반 BETA는 보수적) |
| **터치중 Re-ATI 차단** | 이전 | 진동·재보정 방지 |
| **I²C 통신관리(RDY 핸드셰이크·타임아웃)** | 검증 V3 | ATI Full = I²C 무응답 재현 방지(현 펌웨어가 끈 이유) |

## 4. 단계적 실행 (실측 게이트 뒤)

| Phase | 작업 | 비고 |
|---|---|---|
| 0 | 정정(펌웨어 §11 B4 등) | 무위험 |
| 1 ★ | **노터치 seed 게이트** (boot_touch_ignore 승격) | SW only, 자기정상화 안전망 |
| 2 | **ATI Full 복귀 + 터치중 차단 + I²C 통신관리** | (실측: I²C 무응답·Max Counts) |
| 2b | **Fast Filter Band 비대칭 BETA** (은수님 기여) | 일반 beta 보수적 + 손뗌 회복 가속 |
| 3 | 방전·CalCap 폐기 검토 | **ESD 물리누적 실측 후**(드리프트≠ESD) |

## 5. 실측 게이트 (은수님 안 추가분)

기존 3종(오염 실채널·1ch 전류·0x30 Linearise)에 추가:
- **BETA 부호 세만틱** — Beta 클수록 빠름인지 실칩 확인.
- **자기정상화 과도구간** — 손뗌~수렴 동안 재터치 미인식 빈도·시간.
- **ATI Full I²C 무응답** — Full 재활성 시 RDY 점유 통신 멈춤 재현 여부.
- **드리프트 정체** — LTA 드리프트(ATI 해결) vs ESD 물리누적(방전 필요) 구분.

## 6. 한 줄 결론

> **은수님의 "auto-ATI + 빠른 수렴" 방향과 "자기정상화" 통찰은 채택하되, "손 안 떼면 고착·약터치 흡수·I²C 무응답"을 막을 안전망(노터치 게이트 + 비대칭 BETA + 통신관리)을 결합한 하이브리드가 최적이다. 은수님 안은 이전 결론을 더 견고하게 만드는 보강이지, 대체가 아니다.**
