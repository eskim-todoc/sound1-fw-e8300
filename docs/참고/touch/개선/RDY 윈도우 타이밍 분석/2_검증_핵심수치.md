# RDY 윈도우 타이밍 — fan-in 교차검증 (핵심 수치)

> **TL;DR**: 5개 페르소나(데이터시트타이밍·스트리밍동작·레지스터기본값·펌웨어적용값·검증반론) 산출을 교차검증. **합의 6건**(default=Sound1=Streaming+NP+ReportRate0+Timeout200ms, t_Low≠200ms, 200µs는 원문 부재), **충돌 1건**(Streaming vs Event 권장 — Sound1은 Streaming 유지), **미해결 2건**(ReportRate0의 실제 주기·STOP후 RDY복귀 지연 → 실측). 원문(SSOT) 우선.

## 0. 노드 실행 메타 (모델 · Effort)

| 노드 | 페르소나 | 모델 · Effort | 신뢰도 | 채택 |
|---|---|---|---|---|
| 01 | 데이터시트 타이밍 추출가 | Sonnet (claude-sonnet-4-6) · 목표 high * | 높음 | 채택 |
| 02 | 스트리밍 모드 메커니즘 분석가 | Sonnet (claude-sonnet-4-6) · 목표 high * | 높음 | 채택 |
| 03 | 레지스터 기본값 조사가 | Sonnet (claude-sonnet-4-6) · 목표 high * | 높음 | 채택 |
| 04 | Sound1 펌웨어 적용값 분석가 | Sonnet (claude-sonnet-4-6) · 목표 high * | 높음 | 채택 |
| 05 | adversarial 검증가 | Sonnet (claude-sonnet-4-6) · 목표 high * | 높음 | 채택(반증 1건 반영) |

> [!NOTE]
> \* 5개 노드 모두 `model: "sonnet"` + `subagent_type: general-purpose`로 호출. **Effort는 Agent 도구 스키마에 인자가 없어 호출 시 명시 불가** — 목표 high(`서브에이전트 활용.md §3.1`), 실제 세션 기본값 상속. 상세는 [`00_입력.md`](00_입력.md) 역할표 각주 참조.

## 1. 합의 사항 (다수 페르소나 일치 + 원문 근거)

| 합의_번호 | 내용 | 근거(원문) | 일치 페르소나 |
|---|---|---|---|
| 합의_1 | 칩 reset default 통신 모드 = **I²C Streaming** (0xC0 bit7=0) | §8.11, 메모리맵 §9 (0xC0=0x0000) | 레지스터·펌웨어·검증 |
| 합의_2 | 칩 default 전력 모드 = **Normal Power** (0xC0 bits[6:4]=000), Power Mode Timeout=0(자동 강하 없음) | 메모리맵 §9, §5.3 | 레지스터·펌웨어 |
| 합의_3 | 모든 Report Rate(NP/LP/ULP/Halt) default = **0 ms** | 메모리맵 §9 (0xC1~C4=0x0000) | 레지스터·펌웨어 |
| 합의_4 | **I²C Transaction Timeout default = 200 ms** (범위 2~230ms), RDY low 시점부터 측정 | §8.8, 0xD1=0x00C8 | 데이터시트·레지스터·검증 |
| 합의_5 | **t_Low ≠ Transaction Timeout** — 200ms는 마스터 *무응답* 시 강제 닫힘 상한. 정상 서비스 시 STOP 즉시 닫힘 | §8.8, §8.9 | 데이터시트·스트리밍·검증 |
| 합의_6 | **Sound1 펌웨어 = 칩 default 그대로** (Report Rate·Power Mode·Timeout·통신모드 미변경 → Streaming+NP+0+200ms) | `tdc_drv_iqs323.c` 0xC0 전수, 0xC1~C5·0xD1 write 없음 | 펌웨어 |

## 2. 충돌 사항 (페르소나 간 불일치 → 재정)

| 충돌_번호 | 쟁점 | 페르소나 주장 | 재정 |
|---|---|---|---|
| 충돌_1 | "기본 세팅 = Streaming인가" | 검증반론: *Azoteq 권장 초기화 후엔 Event Mode가 보통* (§8.12 "usually enabled"). 펌웨어: *Sound1은 Streaming(bit7=0) 유지* | **둘 다 참, 층위가 다름.** 칩 reset default·Sound1 실제 = **Streaming**. Azoteq *권장 관행* = Event. 은수님 질문의 "기본 세팅"은 칩 default ∩ Sound1 실제 → **Streaming 확정** |

## 3. 미해결 — 원문 미명시·실측 필요

| 미해결_번호 | 항목 | 상태 | 해소 방법 |
|---|---|---|---|
| 미해결_1 | **Report Rate=0일 때 실제 RDY 주기(T_주기)** | 원문 미명시. "측정 완료 즉시 RDY low" 메커니즘만 확인. 절대 주기는 측정 사이클 시간(ATI Target·conversion freq·활성 채널수 의존) | RTT 타임스탬프 / 오실로스코프 실측. §3.4 표의 self-cap 3ch NP=16ms는 *특정 측정조건(ATI512·Fxfer500k) 예시*이므로 참고 상한으로만 |
| 미해결_2 | **STOP 후 RDY HIGH 복귀 지연** | **원문에 수치 없음.** RDY open-drain → 외부 pull-up(4.7kΩ)·기생용량의 RC 시정수 의존 | 실측. (기존 md 정리본의 "~200µs"는 추정치) |

> [!WARNING]
> **md 정리본 수치 오류 발견**: `데이터시트/05_i2c인터페이스.md` §8.9 노트의 `"STOP 후 약 200µs 이내 RDY HIGH 복귀"`는 **원문에 존재하지 않는 추정값**이다. 원문에 등장하는 유일한 µs 수치는 §6.6.3 **MCLR switchover 150µs**(RDY window 종료 후 핀이 MCLR 입력으로 전환되기까지)뿐이며, 이는 RDY 복귀 지연과 다른 항목이다. → 정정 권고(별도 작업).

## 4. 교차검증 결론

은수님 질문("기본 세팅 + Streaming에서 RDY High/Low/주기")의 답은 다음 세 수치로 수렴하며, 그중 **주기는 Report Rate=0 특성상 데이터시트 단일값이 없어 실측이 필요**하다. 통신 윈도우(t_Low)는 마스터 동작에 따라 가변이다. 상세 답은 [`3_종합결론.md`](3_종합결론.md).
