# IQS323 RDY 윈도우 타이밍 분석 — 데이터시트 원문 수치 추출

> **TL;DR**: IQS323 RDY 라인의 핵심 타이밍 — 윈도우 open 유지(t_Low)는 Transaction Timeout 2~230ms(기본 200ms)가 상한이며 STOP으로 조기 종료. STOP 후 RDY HIGH 복귀 지연은 데이터시트 미명시. MCLR 전환 지연은 별도 150µs(typical). open-drain, V_OL ≤ 0.3V(Isink=20mA). 원문 §8.6~8.9, §4.4, §7.6 근거.

> [!NOTE]
> 모든 수치는 Azoteq IQS323 데이터시트 **Revision v1.11 (August 2025)** 원문 근거. "원문 미명시"라고 표기된 항목은 데이터시트에 해당 수치가 없음.

## 2. t_Low — RDY가 LOW를 유지하는 시간 (comm window open 구간)

### 2.1 t_Low를 결정하는 요인

RDY LOW 유지 기간은 **단일 고정 수치가 아니라**, 아래 세 가지 요인에 의해 결정된다.

| 요인 | 동작 | 원문 근거 |
|---|---|---|
| **요인_1: STOP condition** | master가 I²C STOP을 전송하면 즉시 comm window 닫힘 → RDY 릴리즈 | §8.9 "A standard I²C STOP will close the current communication window." |
| **요인_2: I²C Transaction Timeout** | STOP 없이 방치 시, window 시작(RDY goes low)부터 Timeout 시간 경과하면 자동 닫힘 | §8.8 "communications window is closed (RDY goes high) and processing continues as normal" |
| **요인_3: 0xFF End Communications Command** | Stop Bit Disable bit = 1 설정 시, STOP은 무시되고 0xFF 명령으로만 window 닫힘 | §8.9 "terminated using the end communications command (0xFF) shown in Figure 8.1" |

> [!IMPORTANT]
> **t_Low 상한**: I²C Transaction Timeout 범위 **2~230 ms**, 기본 **200 ms** (§8.8).
> master가 START를 보낸 이후에는 Transaction Timeout이 비활성화되고, §7.6 Watchdog(**255 ms** 만료, SW reset)이 상한을 대신한다.

### 2.2 Streaming 모드 vs Event 모드에서의 RDY 주기

| 모드 | RDY 주기 | 원문 근거 |
|---|---|---|
| **Streaming** | 해당 power mode의 Report Rate마다 RDY LOW assert | §8.11.1 "data is constantly reported at the relevant power mode report rate" |
| **Event Mode** | enabled event 하나 이상 트리거 시 또는 reset 시에만 RDY LOW | §8.11.2 "RDY line will only go low when one or more of the enabled events are triggered or if the device resets" |

Report Rate 레지스터 (모두 ms 단위, 16-bit, 범위 0~3000):

| 레지스터 주소 | 레지스터 명 | 기본값 | 원문 근거 |
|---|---|---|---|
| 0xC1 | Normal Power Mode Report Rate | 0x0000 | §A, Default Values Table |
| 0xC2 | Low Power Mode Report Rate | 0x0000 | §A, Default Values Table |
| 0xC3 | Ultra Low Power Mode Report Rate | 0x0000 | §A, Default Values Table |
| 0xC4 | Halt Mode Report Rate | 0x0000 | §A, Default Values Table |

> [!NOTE]
> 기본값 0x0000이므로 **Report Rate를 명시적으로 설정하지 않으면 최소 주기(연속)로 동작**할 수 있다. ULP 모드에서 Report Rate = (Auto Prox Cycle Select × Ultra Low Power Report Rate) ms (§8.11.1).

## 3. STOP 이후 RDY HIGH 복귀 지연

### 3.1 원문 수치

> [!WARNING]
> **원문 미명시**: 데이터시트 §8.9, §8.6, §8.7 어디에도 "I²C STOP 후 RDY가 HIGH로 복귀하기까지 걸리는 지연(예: ~200 µs)"에 대한 수치 명시가 없다.

원문 §8.9 (p.31):
> "A standard I²C STOP will close the current communication window."

—— 닫힘 자체만 언급. 복귀 지연 수치 없음.

### 3.2 관련 수치: MCLR 전환 지연 (혼동 주의)

§6.6.3에는 RDY window 닫힘 후 핀이 **MCLR 기능으로 전환**되기까지의 지연이 명시되어 있다. 이는 RDY HIGH 복귀 자체의 지연이 아니라, HIGH 복귀 이후 MCLR로서의 기능 전환 지연이다.

| 항목 | 수치 | 원문 근거 |
|---|---|---|
| MCLR 기능 전환 지연 (t_sw) | **150 µs (typical)** | §6.6.3, p.23 각주 i: "Typical Switchover time with setup as in reference schematic." |

원문 (p.23):
> "There is a switchover delay when the pin changes back to MCLR functionality after an RDY window is closed. … The typical time for the switchover to be completed is **150 µs** from the time when the pin is considered high to it acting as MCLR."

> [!NOTE]
> "~200 µs" 수치가 기존 md 정리본(05_i2c인터페이스.md §8.9 Note)에 "DS 미명시 — 실측 추정"으로 표기되어 있다. 이는 원문이 아닌 추정값임을 해당 문서 자체가 인정하고 있다.

## 4. I²C Transaction Timeout 상세

원문 §8.8 (p.30~31):

> "If the communication window is not serviced within the time specified in milliseconds by the I²C Transaction Timeout register, the communications window is closed (RDY goes high) and processing continues as normal."

> "The default I²C Transaction Timeout is set to **200 ms**. The I²C Transaction Timeout must be between **2 ms and 230 ms**. The I²C Transaction Timeout is measured from the start of the communications window (RDY goes low)."

> "Once communication between the master and the IQS323 has begun (START condition on I²C lines), the I²C transaction timeout is disabled leaving the **watchdog timer** in control."

| 항목 | 수치 | 원문 근거 |
|---|---|---|
| 기본값 | 200 ms | §8.8, 레지스터 0xD1 = 0x00C8 (= 200 dec) |
| 범위 | 2 ms ~ 230 ms | §8.8 |
| 측정 시작점 | RDY goes low | §8.8 |
| START 이후 상태 | 비활성화, Watchdog 인계 | §8.8 → §7.6 |
| Watchdog 만료 시간 | 255 ms (byte 이벤트 없으면 SW reset) | §7.6 |

원문 Table 4.4 — Digital I/O Characteristics (§4.4, p.13):

| 파라미터 | 조건 | 수치 | 원문 근거 |
|---|---|---|---|
| **V_OL (RDY/MCLR Output low voltage)** | Isink = 20 mA | ≤ 0.3 V | Table 4.4 |
| **출력 구조** | — | **open-drain, active low** | §8.6 "open-drain active low RDY signal" |
| **Pull-up** | 레퍼런스 회로 기준 | 외부 pull-up 필요 (pin 설명 "Active pull-up, 200 kΩ resistor to VDD" 언급) | p.9 핀 설명 |
| V_OH (Output high voltage) | Isource = 20 mA | ≥ VDD − 0.2 V | Table 4.4 |

> [!NOTE]
> open-drain 구조이므로 RDY HIGH는 IC가 능동 구동하지 않고 외부 pull-up 저항에 의존한다. pull-up 저항값과 버스 기생 정전용량에 따라 RDY가 HIGH로 복귀하는 RC 시정수가 결정된다(이것이 "STOP 후 RDY HIGH 복귀 지연"의 실제 물리적 원인이나, 데이터시트는 수치를 명시하지 않는다).

## 9. Communication During ATI

원문 §8.4:
> "Provided the Reset Event bit in the System Status register is not set, I²C communications are disabled for the duration of the ATI process."

ATI 실행 중에는 comm window가 열리지 않는다. 단, Reset 조건에서는 comm window가 연속 open된다(§8.8 관련 원문: "Under a reset condition communication windows will continuously be opened by the IQS323.").

## 10. Known Issue — I²C Settings Register

원문 Appendix C (Known Issues):

> "Once set, the bits in the I²C Settings register cannot be cleared."
> Versions Affected: IQS323-00x v1.3 and below.

Stop Bit Disable bit를 set하면 device reset 없이 해제 불가(해당 버전 한정). reset 후 설정 재쓰기 필요.
