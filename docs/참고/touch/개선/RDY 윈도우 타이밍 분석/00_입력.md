# IQS323 스트리밍 모드 RDY 윈도우 타이밍 분석 — 오케스트레이터 입력

> **TL;DR**: "기본 세팅 + 스트리밍 모드"에서 IQS323의 RDY 라인이 High↔Low로 토글되는 **주기·Low 폭·High 폭**을 데이터시트 원문(SSOT) + Sound1 펌웨어 적용값 기준으로 정밀 도출한다. 5개 페르소나 병렬 분석 + fan-in 교차검증.

## 1. 요청 (은수님)

> docs/참고/touch/개선 폴더에 터치센서 데이터시트 읽고, **기본 세팅일 때 스트리밍 모드로 동작할 때, RDY 윈도우가 High-Low 되는 시간 정보**를 알려줘. 얼마나 High, 얼마나 Low, 주기는 몇, 이런 정보. 여러 페르소나 돌려서 분석하고 문서정리까지 잘 해놔.

## 2. 분석 대상 3대 수치

| 기호 | 의미 | 결정 요인 |
|---|---|---|
| **T_주기** | RDY 한 사이클(Low→High→다음 Low) 전체 시간 | Report Rate (전력 모드별 레지스터, ms) |
| **t_Low** | RDY가 Low로 유지되는 시간 = communication window open 구간 | 통신 시: I²C 트랜잭션 시간 + STOP 후 ~200µs / 미통신 시: I²C Transaction Timeout |
| **t_High** | RDY가 High(release)로 유지되는 시간 | T_주기 − t_Low |

## 3. "기본 세팅" 해석 — 양면 모두 분석

- **해석 A (칩 default)**: IQS323 레지스터 reset default 값 기준 (NP/LP/ULP Report Rate, Transaction Timeout, Streaming/Event 비트 default).
- **해석 B (Sound1 적용값)**: Sound1 펌웨어가 초기화 시퀀스에서 실제 write 하는 값 기준.

두 해석을 모두 산출하고 차이를 명시한다.
