# Sound1 시스템 구조

Sound1(TD24A-A-EXT)은 E8300의 CM3, CFX, HEAR가 자극 처리의 역할을 나누고, 별도 QCC5181이 블루투스 통신과 오디오 입력을 연결하는 외부장치다. **코어는 실행 위치이고, 모듈은 기능 구분이다.** 신호처리와 내부기 실행 기능은 한 코어 안에서 끝나지 않는다.

이 문서는 SAD/SDDD/시험 문서를 작성하거나 펌웨어를 변경할 때 먼저 읽는 구조 설명이다. 코드를 대체하는 명세나 실기 검증 보고서는 아니다. 2026-09-29 작업 트리의 실제 진입점, 호출, 공유 변수와 활성 조건부 코드를 대조했다. 검토 파일 목록과 변경 감지는 [분석 기준 파일](분석%20기준%20파일.json), [확인 도구](구조%20근거%20확인.py)를 사용한다. 해시 일치는 내용의 정확성이나 시험 통과를 뜻하지 않는다.

## 1 외부장치와 내부장치의 경계

![Sound1 외부장치 안의 E8300과 QCC 및 내부 이식장치의 연결](../인허가/사운드1/DHF/03_설계%20출력/SW/펌웨어/이미지%20참조/시스템%20블록도.png)

그림 1. 외부장치, E8300, 내부 이식장치를 구분한 시스템 구성

두 디지털 마이크의 입력은 E8300의 오디오 입력 경로에서 처리한다. DMIC2는 E8300뿐 아니라 QCC에도 연결되며, 전화 통화 시 QCC가 DMIC2의 음성을 수음하여 통화 상대에게 송신한다(은수님 확인, 2026-10-13). DMIC2의 QCC 마이크 입력과 QCC가 E8300에 보내는 I2S 오디오는 서로 다른 경로다. 코드에서 DMIC1을 EZ, DMIC2를 QCC라고 부르지만, DMIC2의 FIFO 입력을 QCC의 I2S 입력으로 해석하면 안 된다. CFX가 두 DMIC FIFO를 각각 읽고, QCC의 I2S FIFO는 별도로 읽는다. [CFX 진입점](../../../src/1__cfx/systemControl/main.c)의 `normal_init`, `tdc_copy_DMIC_buffers`, `PCM_LiveStimulation_Mode`가 E8300 측 입력을 구분한다. QCC 측 마이크 핀, 클록 및 통화 오디오 설정의 세부 계약은 별도 근거가 필요하다.

CFX의 자극 패킷은 PCM으로 FPGA에 전달되고, CM3는 I2C로 FPGA 상태와 백텔(내부기에서 되돌아오는 정보)을 확인한다. TX PMIC는 무선 링크 전원 제어 대상이다. 내부기의 자극칩과 전극은 E8300 내부 부품이 아니다. 그림의 무선 연결은 기능 경로이며 RF 회로 배선도나 승인된 회로도를 대체하지 않는다.

| 경계 | 전달 내용 | 현재 확인한 구현 |
|---|---|---|
| DMIC 2개 → E8300 | PDM 입력, FIFO 블록 | CFX 오디오 경로 및 두 마이크 버퍼 |
| DMIC2 → QCC → 통화 상대 | 통화 마이크 입력과 Bluetooth 통화 송신 | DMIC2의 양쪽 연결과 QCC의 통화 수음은 은수님 확인. QCC 내부 처리/핀/클록/프로파일/코덱의 세부 계약과 실측은 별도 확인 |
| QCC → CFX | I2S 오디오, 입력 유효 GPIO | `normal_loop`, `PCM_LiveStimulation_Mode` |
| QCC ↔ CM3 | SPI 명령/응답 | CM3 SPI slave/DMA, `bleCommunication` |
| CM3 → QCC | 동작 요청, 내부기 연결 표시 | `QCC_CTRL`, `ISD_CHECK` |
| CFX → FPGA | PCM 자극/설정/NOP 패킷 | `pcmDataOut` |
| CM3 ↔ FPGA/TX PMIC | 설정, 상태, 백텔 읽기, 송신 전원 조정 | `isd_interface` 하위 상태 처리 |
| CM3 ↔ 터치 센서 / CM3 → LED | 터치 입력 / 표시 | `tdc_touch_process`, LED 요청/중재 |
| 부트로더/CM3 ↔ 비휘발성 저장장치 | 이미지, 맵, 사용자 설정 | NVM/FatFs, `ci_map_*`, OTA 파일 쓰기 |

2026-10-12에 QCC 요구사항·아키텍처·상세설계·통합계획·유닛 기준서 5개를 직접 확인했다. QCC 내부 설명은 이 제공 설계의 범위까지 추가했다(6.2절). QCC 소스/빌드 산출물, FPGA RTL, 내부기 펌웨어 및 최신 회로도 전체는 이번 분석의 입력이 아니다. 제공 설계를 실제 구현이나 실측 결과로 취급하지 않으며, 실제 핀/태스크/전원 회로의 미비는 보존한다.

## 2 코어와 기능 모듈은 서로 다른 구분이다

![세로 코어 영역 위에 가로 기능 모듈을 겹쳐 표시한 소프트웨어 구조](../인허가/사운드1/DHF/03_설계%20출력/SW/펌웨어/이미지%20참조/소프트웨어%20구조도.png)

그림 2. 실행 위치와 여러 코어에 걸친 기능의 대응

가로 영역이 코어 경계를 가로지른다는 것은 같은 코드가 모든 코어에서 실행된다는 뜻이 아니다. 각 영역 안의 서로 다른 유닛이 데이터와 완료 상태를 주고받아 하나의 기능을 완성한다. 부트로더는 별도 코어가 아니라 CM3에서 응용 프로그램보다 먼저 실행되는 단계다.

| 기능 | CM3 | CFX | HEAR | QCC 연계 |
|---|---|---|---|---|
| 시스템 제어 | 기동, 전원/터치/LED, 맵/설정 파일, 동작 상태 | 오디오/PCM 초기화, 블록 처리 순서, 대기/복귀 | CFX가 기동/정지하는 함수체인 | 전원 정보 전달, 제어 핀 연계. 내부 구현은 별도 |
| 신호처리 | 맵의 펄스폭/T/C로 DAC 범위, T/C 코드, 전송량 계산 | 입력 혼합, AGC, 대역 대표값, 비선형 매핑, CIS/NofM | 절대값/최댓값, 윈도 FFT, 크기 계산 | I2S 오디오 공급. E8300의 신호처리 계산과 구분 |
| 내부 자극 장치 실행 | PMIC/FPGA/내부기 설정, 연결 확인, PCM 모드 요청 | 자극/설정/NOP 패킷 생성 및 PCM FIFO 기록 | 별도 내부기 제어 유닛으로 보지 않음 | 연결 상태를 GPIO로 받음 |
| 블루투스 통신 | 명령 해석, 매핑/리모콘 처리, 응답, OTA 수신 | 적용할 설정/오디오를 공유 메모리나 I2S로 받음 | 직접 BLE 명령 처리 없음 | 무선 연결과 SPI 명령/응답 중계 |

기존 문서의 네 기능 모듈을 유지하면서 실행 위치를 분명하게 한다. 오디오 믹서가 `systemControl/`에 있다는 이유로 신호처리 기능에서 제외하거나, 파일 이름에 NRF가 있다는 이유로 NRF 하드웨어를 그리지 않는다.

## 3 전원을 켜면 어떤 순서로 동작하는가

1. [부트로더 main](../../../src/0__bootloader/main.c)이 초기 GPIO와 디버그 조건을 설정한다. CAL 입력에 따라 서비스 모드 또는 일반 부트로더로 분기한다.
2. [이미지 적재](../../../src/0__bootloader/source/bootloader.c)의 `bootloader_boot`가 저장장치를 준비하고 부트 상태에 따라 이미지를 선택한다. 파일/섹션 검사, 필요한 복호화와 메모리 적재 후 CFX와 CM3 응용 프로그램의 시작 위치로 연결한다. HEAR 코드/데이터 적재와 런타임 함수체인 시작은 다른 단계다.
3. CFX `main`은 자체 우선순위/메모리 중재/루프 스택/포화 연산/인터럽트를 설정하고 `is_CFX_started`를 게시한다. **CFX 초기화가 전부 부트로더로 이동한 것은 아니다.**
4. [CM3 main](../../../src/2__cm3/Cortex-M3-src/main.c)의 `tdc_normal_boot_sequence`가 CFX 시작을 기다리고 `Initialize`를 실행한 뒤 `is_enabled_CFX_iteration`을 설정한다.
5. CFX `normal_init`이 HEAR, 오디오, PCM, I2S를 준비한다. CM3는 내부기 설정과 맵 적용을 진행하고, 준비 완료 후 Live 자극 모드로 전환한다.

부트 상태의 기본/대체 슬롯 선택과 재시도는 [부트 상태 관리](../../../src/0__bootloader/source/bootmgr/ci_boot.c)의 `snd_boot_determine_slot_num`에서 확인한다. 슬롯 상태 필드는 1~4를 표현하지만 [CM3 OTA 수신](../../../src/2__cm3/Cortex-M3-src/BleCommunication/ci_ble_control_ota.c)의 명령 처리는 1~2 범위를 검사한다. 이를 근거 없이 모든 경로에서 동일한 A/B 슬롯 계약이라고 단순화하지 않는다. 이번에는 슬롯 경계 오류 처리의 완전성까지 검증하지 않았다.

## 4 음성 입력에서 전극 자극까지

### 4.1 입력 블록과 실행 위치

CFX의 FIFO ISR은 `mic0`, `mic1`, `pcm_out`, `dac1` 등의 준비 플래그를 세운다. 실제 혼합과 후속 처리는 `normal_loop`에서 시작한다. 따라서 “FIFO ISR 안에서 모든 빔포밍과 FFT를 계산한다”라고 쓰지 않는다. [ISR 코드](../../../src/1__cfx/systemControl/interrupt_service_routine.c)와 [메인 루프](../../../src/1__cfx/systemControl/main.c)를 함께 확인한다.

마이크 경로는 16 kHz 설정, 블록은 16표본, FFT 버퍼는 512표본이다. 16표본은 1 ms 입력량이지만, 이것만으로 모든 계산의 1 ms 이내 완료를 실측/보장했다고 할 수는 없다. 메인 루프는 플래그를 소비하고 HEAR 완료를 기다리는 경로도 갖는다.

### 4.2 모드별 입력 선택

| 조건 | 실제 입력 처리 |
|---|---|
| 일반 동작, 두 마이크 | 앞쪽 마이크에 지연을 적용하여 두 입력 평균. 좌/우 귀 정보에 따라 앞쪽 마이크 선택 |
| 한 마이크 또는 방향 미지정 | DMIC1 단독 입력 경로 |
| I2S 스트리밍 | DMIC1과 I2S를 각 게인 적용 후 합산. 빔포밍 평균과 달리 마지막에 2로 나누지 않음 |
| I2S의 일반 스트리밍 | I2S 게인 unity, 마이크에 Gain A |
| I2S의 크래들 마이크 | 마이크 Gain A, I2S Gain B |
| 매핑 연결 중 I2S 혼합 | 두 게인을 unity로 사용 |

근거는 `PCM_LiveStimulation_Mode`와 [오디오 믹서](../../../src/1__cfx/systemControl/audioMixer.c)다. [CFX 설정 처리](../../../src/1__cfx/systemControl/system_control.c)의 맵 변경 분기에서 매핑 Live의 한 마이크 설정을 확인할 수 있다. 다만 일반 루프에도 마이크 수 자동 전환이 있으므로, 분기 한 곳만 보고 “매핑 연결 전체 기간에 반드시 한 마이크로 유지”된다고 보장하지 않는다. 이 상호작용은 해당 모드 변경 작업에서 별도 확인한다.

빔포밍은 입력 시프트 `>>5`와 두 채널 평균 `>>1`을 구분한다. 현재/직전 블록을 사용한 1표본 지연에 앞쪽 마이크의 하드웨어 소수 지연 설정이 더해진다. 음향 감쇠나 주파수별 ADC 기준은 이 코드만으로 결정되지 않으며, 기구/마이크 특성과 측정 배치를 별도로 고려한다.

### 4.3 CFX와 HEAR가 나누는 연산

1. CFX가 혼합 입력을 준비하고 HEAR `HEAR_FC_agc_preprocessing`을 호출한다.
2. HEAR는 16표본의 절대값/최댓값을 구하고 Event 0을 발생시킨다.
3. CFX `HEAR_LiveStimulation_Mode`가 `audio_agc`를 실행한다. AGC 전의 혼합 최댓값이 `maxAudioInput`에 기록된다.
4. CFX가 FFT 입력을 갱신하고 HEAR `HEAR_FC_fft_vmag`를 호출한다. HEAR가 윈도 FFT/크기 연산을 마치면 Event 1을 보낸다.
5. CFX가 `pcmDataOut`으로 들어가 Live 모드의 `stimulationStrategy`를 실행한다. 대역 대표값과 비선형 매핑, 전략에 따른 채널 선택/배치 결과를 PCM에 기록한다.

근거: [HEAR 함수체인](../../../src/3__hear/microcode.hct), [AGC](../../../src/1__cfx/signalProcessing/agc.c), [PCM 분기](../../../src/1__cfx/internalDevice/driver_PCM.c), [자극 전략](../../../src/1__cfx/signalProcessing/stimulationStrategy.c).

`maxAudioInput`은 ADC 전체 범위의 장시간 최대나 RMS가 아니라 **혼합 후 AGC 전의 최근 16표본 절대값 최대**다. CM3 `readAudioSignalMax`는 이 값을 읽는다. 앱 폴링 사이의 모든 블록 최댓값을 보관하는 peak hold로 설명하면 안 된다.

OD 관찰 출력도 정수 배열과 물리 출력을 구분한다. `HEAR_LiveStimulation_Mode`는 AGC 출력에 `lib_loopback_AGC_out`의 64배 확대/24비트 포화를 적용해 DAC1 FIFO로 보낸다. [출력 설정](../../../src/1__cfx/systemControl/main.h)은 `SD_2_LEVEL`, `OD1_ENABLE`이며 OD1_P/OD1_N은 차동 PDM 출력이다. 핀에서 직접 아날로그 사인파를 찾지 않고 청취 수신기 또는 측정용 저역통과 필터 후 차동 출력을 확인한다. CFX-020 시험 코드는 RAM 목적지로 증가 배열/포화 경계 배열을 계산할 뿐 연속 사인파를 재생하지 않는다. 정상 오디오 경로의 순음/무음 청취와 RAM 시험 통과를 같은 결과로 취급하지 않는다.

### 4.4 CIS와 NofM의 시간 단위

CIS는 CM3가 펄스폭에서 계산한 프레임 수/전송 가능량을 사용한다. NofM은 현재 CM3 계산에서 정상 밴드 수 조건일 때 자극당 3프레임, 1 ms당 8채널로 설정한다. CFX는 16개 선택 결과를 두 phase에 걸쳐 전송하며 phase 0에서 대역 분석/매핑/선택/배치/패킷 생성을 갱신한다. **기본 CIS 맵의 2프레임을 NofM에도 그대로 적용하지 않는다.**

근거: [CM3 계산](../../../src/2__cm3/Cortex-M3-src/signalProcessing/stimulationParaCal.c) `calculationStimulParaN_cfxShare`, CFX `stimulationStrategy_NofM`, `stimulationStrategy_NofM_PCM_Write`. 16개 미만 밴드 조건은 오류 로그가 있지만 그 사실만으로 안전한 차단이 보장된다고 판단하지 않는다. 실제 스코프 파형에는 패킷 수신/내부기 출력 지연도 포함되므로 별도 내부기 계약과 시험 근거가 필요하다.

2026-09-30 상세설계 대조에서 선택 후 순서도 확인했다. `(크기 << 5) | (31 - 인덱스)` 점수는 같은 크기일 때 낮은 인덱스를 우선한다. 선택 인덱스를 오름차순으로 정렬한 뒤 하위 8개와 상위 8개를 교차한다. 예를 들어 0~15가 선택되면 `0,8,1,9,...,7,15`다. `stimulationStrategy_NofM_Packet`은 직전 마지막 전극과 이번 배열 양 끝의 거리를 비교하며, 끝이 더 멀면 **마지막 한 개만 맨 앞으로 옮긴다.** 전체 배열을 역순으로 뒤집는 것이 아니다. 해당 경로는 위 [자극 전략](../../../src/1__cfx/signalProcessing/stimulationStrategy.c)의 선택/교차 배치/패킷 함수에서 확인한다.

## 5 맵 변경은 코어 사이의 순서가 중요하다

| 순서 | 작성/처리 주체 | 전달과 확인 |
|---|---|---|
| 1 | CM3 | 파일에서 맵/사용자 설정을 읽어 공유 구조체를 채움 |
| 2 | CM3 | `cm3Command_mapChange=1`, CFX 적용 완료 플래그 초기화 |
| 3 | CFX | 공유 맵을 로컬 변수로 반영, 방향/헤더/FFT pass bin 갱신 후 `cfx_Reloaded_MapdataFlag=1` |
| 4 | CM3 | 맵 적용 확인 후 펄스폭/T/C로 DAC 범위, T/C 코드와 전송량 계산 |
| 5 | CM3 → CFX | 계산 완료 플래그를 게시, CFX는 T/C 및 전송량을 반영하고 완료 플래그를 지움 |
| 6 | CM3 + CFX | 내부기 설정/읽기 확인 완료 후 Live PCM 모드 요청과 출력 |

근거: [공유 메모리 접근](../../../src/2__cm3/Cortex-M3-src/systemControl/cfx_cm3_sharedMemory.c) `changeConnected_isd_num_CFX`, `changeProgramMapNum`, [CFX 맵 이벤트](../../../src/1__cfx/systemControl/system_control.c), [CM3 독립 자극 실행](../../../src/2__cm3/Cortex-M3-src/internalDevice/isd_interface_stimulationStandAlone.c).

2026-10-02 실패 경로 대조에서는 위 정상 순서와 별도로 미확정 처리를 발견했다. CM3의 전하량 제한 조건은 현재 정의한 매크로 이름과 달라 활성화되지 않는다. DAC 범위 초과 시 `calculationStimulParaN_cfxShare()`는 false를 반환하지만 초기화되지 않은 지역 T/C 배열을 공유 영역으로 복사하려는 경로가 남고, 독립 자극 실행 호출자는 성공 여부 분기 없이 완료를 게시한다. 실패 후 기존 값 보존/안전값 변경/출력 차단 중 어느 정책인지 여기서 임의로 정하지 않는다. 시험용 관찰에서는 미정의 배열 읽기만 생략하며 이를 제품의 실패 후 보존 동작으로 해석하지 않는다.

공유 메모리는 CM3의 `.shared_memory` 구조와 CFX의 대응 구조/주소를 함께 유지해야 한다. 필드 추가나 순서/자료형 변경은 한쪽만 수정할 수 없다. 위 플래그는 실제 전달 순서에 대한 설명이지 `volatile`만으로 모든 묶음 갱신이 원자적이라는 보장이 아니다. `PCM_mode`처럼 양쪽에서 바꾸는 필드도 있으므로 일괄적으로 “CM3 단독 작성”이라고 지정하지 않는다. SpecificCommand의 읽기 표시/인덱스도 관련 변경 시 함께 확인한다.

## 6 CM3 상태 제어와 QCC의 연결

CM3 `tdc_normal_iteration`은 입력 수집 후 `systemControl → update_mapNum → isd_interface → bleCommunication` 순서로 처리한다. 시스템 제어는 일부 지난 tick의 내부기/매핑 상태를 받고 다음 상태를 만든다. 이 순서를 바꾸면 같은 데이터라도 반영 시점이 달라질 수 있다.

정상 루프의 iteration과 시스템 tick은 [CFX/FIFO 인터럽트 처리](../../../src/2__cm3/Cortex-M3-src/systemControl/driver_timmer.c)에서 열고, [TIMER3](../../../src/2__cm3/Gen1_5/common/ci_timer.c)는 LED 중재와 자체 tick을 담당한다. 타이머 세 개가 있다는 식의 옛 주석이나 “CM3에 타이머가 없다”는 잔존 주석을 현재 하드웨어 설명으로 옮기지 않는다. 불리언 iteration 플래그는 이벤트 누적 큐가 아니므로 블로킹 중의 tick 횟수 보존도 별도 확인 사항이다.

| QCC 경로 | CM3/CFX가 실제 사용하는 정보 |
|---|---|
| SPI 0x34 | 배터리 잔량, 충전 상태, 크래들 뚜껑 상태 |
| SPI 0x35 | LED 표시 요청, DFU 연결 상태 |
| SPI 0x36 | 오디오 연결/종류. 크래들 마이크 여부를 공유 메모리에 반영 |
| 리모콘/매핑 명령 | 설정 조회/변경, 맵 및 내부기 제어와 응답 |
| OTA 명령 | CM3의 파일 수신/쓰기 처리. 재기동 후 적재는 부트로더 |
| I2S + 유효 플래그 | CFX의 입력 상태와 혼합 경로 |
| ISD_CHECK / QCC_CTRL | CM3가 QCC에 연결 상태/동작 모드를 출력 |

근거: [BLE 명령 처리](../../../src/2__cm3/Cortex-M3-src/BleCommunication/ble_communication.c), [QCC 핀 제어](../../../src/2__cm3/Cortex-M3-src/QCC/snd_qcc.c), [SPI 설정](../../../src/2__cm3/Cortex-M3-src/systemControl/driver_SPI.h).

`NRF_On_OFF`, `setting_nrf_ble_adv_info`는 남아 있는 함수 이름이다. 이름을 QCC로 치환하는 것만으로 동작을 설명하지 말고 호출과 실제 GPIO/SPI 처리를 확인한다. E8300의 송수신 계약은 현재 코드에 근거하고, 제공된 QCC 설계의 대응과 미확인은 6.2절에서 구분한다.

OTA의 시작/종료 명령은 ACK를 만들며 그 자체로 DFU 연결 플래그를 바꾸지 않는다. DFU 상태는 SPI 0x35의 입력 상태 4(OTA_EZAIRO)/0(NONE)을 받아 연결 플래그 1/0으로 반영한다. 명령 응답과 상태 통보를 한 경로로 설명하지 않는다. 근거는 위 BLE 명령 처리와 [OTA 처리](../../../src/2__cm3/Cortex-M3-src/BleCommunication/ci_ble_control_ota.c)다.

절전도 한 종류로 묶지 않는다. CM3 일반 절전, 크래들 뚜껑 닫힘 경로, 시험용 fake sleep이 별도로 있다. CFX는 CM3의 ULP 요청을 받아 입출력을 정지하고 wake-up 인터럽트를 기다린다. 특정 경로의 시간이나 복귀 조건을 문서에 넣을 때는 해당 함수와 현재 설정을 다시 확인한다.

### 6.1 감사기록의 생성과 조회

2026-10-12 확인. 감사기록 기능은 별도 코어가 아니라 CM3의 초기화, 리모콘 명령 처리와 정상 반복 경로에 나뉜다. 상세 설계의 기존 CM3-001/046/005에 각각 포함한다.

- [초기화](../../../src/2__cm3/Cortex-M3-src/systemControl/initialize.c)의 `ci_event_log_init()`는 유효한 기존 기록을 보존하고 파일이 없거나 관리 정보가 잘못된 경우 초기화한다.
- [리모콘 명령 처리](../../../src/2__cm3/Cortex-M3-src/BleCommunication/remoteControl.c)의 연결 확인 명령은 받은 시간, 블루투스 주소를 갱신한 뒤 연결 이벤트 `0x40`을 기록한다. 일반 명령의 처리 허용 플래그는 암호학적 인증 결과와 구분한다. 연결 해제 기록 호출은 주석 처리되어 있어 자동 기록한다고 설명하지 않는다.
- [기록 저장/조회](../../../src/2__cm3/Gen1_5/FS/ci_event_log.c)는 4,096바이트 파일에 관리 정보 16바이트와 기록 16바이트 최대 255개를 둔다. 기록은 시간 6바이트, 주소 6바이트와 이벤트 4바이트다. 배열의 끝에 도달하면 처음으로 돌아간다. [시간 처리](../../../src/2__cm3/Gen1_5/common/ci_timer.c)는 받은 기준 시간에 1ms tick의 경과 시간을 반영한다.
- 정상 반복에서 [개발/점검 명령](../../../src/2__cm3/Gen1_5/ui/tdc_ui_command.c)의 `--dump_log`를 처리하면 기록을 읽어 RTT로 출력한다. 이 경로에는 인가자 확인이나 암호화 처리가 없으며, QCC 무선 암호화와 다른 경로다. 조회 완료 안내만으로 읽기 성공을 판정하지 않고 실제 반환값/출력 내용을 확인한다. 출하 시 디버그 접근 제한은 별도 확인 대상이다.

제품 함수와 RAM 파일을 사용한 보충 실행에서 초기화 중 `f_sync` 실패와 기록 중 `f_close` 실패를 넣어도 반환값이 0인 경우를 확인했다. 이는 실기 시험 결과가 아니며 오류 반환 보완 대상으로 남긴다. 입력/실행 증거와 문서 반영 범위는 [설계 출력 작업의 감사기록 보완 항목](../../tasks/인허가/20260929_1755_DHF-펌웨어-설계출력/작업.md)에 연결한다. 현재 통합 시험에는 감사기록 입력에서 저장/조회까지의 연속 경로가 명시되어 있지 않다.

### 6.2 제공 자료로 확인한 QCC 설계

제공 문서의 `스마트케이스`, `CC`와 일부 TD24B 표기는 작성자의 미갱신 표기이며 실제 내용은 외부기 QCC라는 은수님의 확인을 적용한다. 원문 ID는 기능과 문서 내 제목을 함께 보존한다. 빈 요구표나 충전 기능을 복제한 잔존 추적표만으로 새 외부기 기능을 만들지 않는다.

| QCC 기능 모듈 | 설계 유닛 | 역할과 경계 |
|---|---|---|
| SI-ID-QCC-001 시스템 관리 | SU-ID-QCC-001 초기화/설정, 002 시스템 상태, 003 장치 상태, 004 블루투스 상태 | 라이브러리/PIO 초기화, SPI 중계, Standalone/TWS 구성, 장치명과 연결 활성 관리 |
| SI-ID-QCC-002 HW 인터페이스 | SU-ID-QCC-005 PIO, 006 Power, 007 NVM | GPIO/주변기능, 배터리·충전 상태, 절전, 비휘발성 저장 API |
| SI-ID-QCC-003 블루투스 | SU-ID-QCC-008 Classic, 009 BLE, 010 AUTH service, 011 BLE Data | 오디오/I2S, 광고/연결, GATT 인증 접근, GAIA 메시지와 SPI 전달 |
| SI-ID-QCC-004 보안 | SU-ID-QCC-012 보안 처리, 013 보안 툴박스, 014 보안 NVM | CRA 응답/인증 상태, 암호 서비스 호출, 키/난수의 저장 접근 |

E8300의 신호처리·내부기 제어 모듈과 QCC의 네 모듈은 서로 다른 장치의 기능 구분이다. QCC가 공급한 I2S 데이터의 혼합·AGC·FFT·CIS/NofM 처리는 앞 절의 E8300 경로다. 통화 송신은 DMIC2 → QCC → Bluetooth 통화 상대의 경로이며, DMIC2 → E8300의 자극 처리 입력과 함께 연결된다(은수님 확인, 2026-10-13). QCC 측 마이크 핀/클록, 프로파일/코덱과 두 경로의 동시 동작 조건 및 실측은 아직 확정하지 않는다.

| 연결/정책 | 확인 범위와 남은 자료 |
|---|---|
| I2S | QCC 요구는 24비트/16kHz. E8300 PCM slave/24비트와 16kHz 입력 설정을 대조했다. 0~8kHz 신호 대역과 샘플링 주파수를 구분한다. QCC clock/frame/핀/유효 신호 타이밍과 실측은 추가 확인 대상이다. |
| GPIO | E8300 QCC_CTRL(DIO24)은 High 정상/Low 종료, ISD_CHECK(DIO13)은 High 연결/Low 미연결이다. QCC shutdown_ind 본문/그림에는 반대 조건이 섞여 있다. 실제 PIO 번호와 논리 반전 여부를 확인하기 전 E8300 계약을 바꾸지 않는다. I2S_FLAG(DIO29)는 Low 유효다. |
| SPI 상태 | 0x34의 charger_connected는 0/1이다. QCC의 미연결/연결/충전/비충전 4상태를 그대로 전송하지 않고 변환표를 확인해야 한다. 0x35 DFU/LED와 0x36 연결·오디오 종류의 QCC 통보 시점도 추가 자료가 필요하다. |
| 프레임 | QCC BLEData의 type 1바이트+data 0~19바이트는 논리 메시지다. E8300 SPI의 21바이트는 BLE 데이터 20바이트+길이 필드 1바이트로 계층이 다르다. 크기 자체를 상충으로 보지 않으며 변환·응답·CRC 계약은 별도 대조한다. |
| 연결 제한 | QCC SRS의 송수신 없음 3분, 실패 5회 후 1분 제한과 QCC SUVC의 인증 미완료 30초를 반영할 수 있다. 기존 무명령 종료 의도와의 차이, 타이머 시작/갱신/허용 오차, 연속 실패 리셋/재기동 정책은 자료 미비다. |
| 인증과 저장 | 16바이트 Nonce A/B와 Status 0 실패/1 성공/2 진행/3 시간 초과를 제공했다. AES-CMAC 기반 CRA와 의료진 키의 SHA-256 파생은 전송 암호화와 구분한다. 원문의 HMAC/ENC 명칭, 키 ID/역할, UUID, 직렬화/검증 벡터, AES NVM의 모드·IV·난수 복구·무결성은 추가 확인 대상이다. |
| OTA/부트 검사 | QCC 자체 OTA와 E8300 OTA 전달 상세 및 QCC 부트 무결성 구현은 미제공이다. E8300 CRC 검사나 기존 OTA 결과를 QCC 보안 검증으로 확대하지 않는다. |

### 7.1 시험 코드와 정상 펌웨어의 경계

2026-10-16에 추가한 SYS-054/073/077/080은 CM3의 시험별 `TDC_SYS_TEST_번호_ENABLE`로 선택한다. 신규 기본값은 모두 0이다. [시스템 시험 통합 사용방법](../../../tests/system/README.md)에 SYS-007/012/023/050/051을 포함한 준비, 명령, 확인값과 원복 순서를 둔다. 관련 코드의 진입점은 [저장 시험 공통 제어](../../../src/2__cm3/Cortex-M3-src/test/tdc_sys_test_storage.c)이며 UI에서 한 명령씩 실행한다. 내부기/매핑 분리, 기존 오류/LED 강제 설정을 확인한 뒤 정상 전경 제어 대신 현재/다음 PCM의 NOP를 유지한다. Timer 3/CFX IRQ/워치독은 유지한다. `stop`은 남은 로그를 취소할 뿐 파일/오류를 원복하거나 자극을 재개하지 않는다. 물리적 무자극과 실제 LED는 별도 확인 대상이다.

- [SYS-054](../../../src/2__cm3/Cortex-M3-src/test/tdc_sys_test_54.c): 부트 드라이브의 비암호화 FEZ를 읽고 파일/섹션 CRC와 길이를 검사한다. 손상은 읽은 RAM에만 주입한다. 실제 부트로더와 같은 헤더 정의/CRC 규칙을 참조하지만 적재/실행/기동 거부를 수행하지 않는다. 암호화 FEZ는 미지원, VOLATILE 예외는 부분 검사로 구분한다.
- [SYS-073](../../../src/2__cm3/Cortex-M3-src/test/tdc_sys_test_73.c): 실제 감사 init/write를 호출하되 파일 연산과 작업 버퍼를 시험 전용 RAM으로 연결한다. 오류를 받은 제품 함수가 갱신한 오류 코드와 기존 LED 요청을 관찰한다. 제품이 오류를 알리지 않으면 불일치를 보존한다. 직접 LED 오류 주입은 별도 명령이며 실제 저장 실패 검출과 구분한다. 실제 감사 파일/제품 감사 버퍼/시각/주소는 변경하지 않는다.
- [SYS-077](../../../src/2__cm3/Cortex-M3-src/test/tdc_sys_test_77.c): 가상 ISD 정보만 별도 파일에 실제 CRC/AES 래퍼로 저장하고 암호문/복원문을 읽는다. 실제 개인정보/키는 출력하지 않는다. 기존 시험 파일을 덮어쓰지 않으며 닫기/동기화 실패는 성공 왕복과 구분한다. 전원 차단 후 저장 유지까지 확인하는 기능은 아니다.
- [SYS-080](../../../src/2__cm3/Cortex-M3-src/test/tdc_sys_test_80.c): 시험 전용 `SYS80.TST`에 설정과 제품 CRC를 저장/검증한 뒤 CRC는 유지하고 데이터 한 바이트만 손상시킨다. `check`가 두 CRC와 제품 읽기 함수의 반환을 확인하고, 불일치일 때 `ci_map.c`의 사용자 설정 기본값으로 시험 파일을 저장/재검증한다. `arm/check/clear`는 재부팅이나 실제 사용자 설정 변경 없이 실행한다. `clear`는 식별된 시험 파일만 제거한다. 이전 방식의 백업을 가진 사용자를 위한 `restore`만 실제 ISD1 설정 전체를 원복하며 재확인 후 백업을 제거한다. 함수 안의 파일 복구와 실제 부팅/맵/알림/BLE 적용 시험은 구분한다(2026-10-16 후속 요청 반영).

이 시험 경계는 기존 파일 래퍼의 실패 반환 누락, 감사 init/sync/close 오류 처리와 부트 CRC 예외를 수정하는 기능이 아니다. 시험 빌드의 파일 진단 출력은 HOLD 구간에서 제한하고 결과를 60바이트 이내 행으로 보관/재시도한다. OFF에서는 새 경계와 UI/main 분기를 제거한다. PC 재현/SDK 빌드는 실제 LED, NVM 전원 차단 유지, 부팅 거부나 시스템 시험 합격을 의미하지 않는다.

2026-10-15에 추가한 [SYS-050/051 감사기록 표시](../../../tests/system/audit.md)는 CM3 `TDC_SYS_TEST_AUDIT_ENABLE`로 선택한다. `--sys50/51`은 2026-05-29의 고정 시간과 가상 주소를 기존 이벤트 구조의 읽기 전용 RAM 벡터로 구성하여 RTT로만 보낸다. TIME/ADDR/EVENT 필드는 보존하되 60바이트 제한 때문에 같은 기록 번호의 세 행으로 나누고 매 행 TEST로 출처를 표시한다. 실제 감사 파일, 기준 시간, 주소, 연결/오류 상태와 정상 전원 경로는 변경하지 않는다. 이 출력은 6.1절의 해제 기록 미연결과 무결성 오류 자동 기록 미확인을 보완하거나 통과시킨 결과가 아니다. 시작 시 SYS-023 상수가 1로 변경된 것을 확인하고 기존 SYS-007/DIO35 설정과 함께 보존했다.

2026-10-14에 추가한 [SYS-023 저전력 알람 시험](../../../tests/system/sys23.md)은 CM3 `TDC_SYS_TEST_23_ENABLE`로 선택한다. `--sys23 start`는 정상 전경을 계속 실행하면서 `systemControl`의 저배터리 알람 비교에만 19%를 사용한다. QCC 잔량, 전원 종료/충전/오류 판단, LED 표시, 맵과 NVM은 바꾸지 않는다. 기존 `--batt`는 LED 전용이다. 현재 제품의 40% 미만 종료가 20% 미만 알람보다 먼저라는 불일치를 수정하거나 시험으로 감추지 않는다.

시험은 실제 잔량 40~100%, 방전/충전기 미연결, 내부기 Live 연결, 매핑 미연결과 알림 사용 설정에서 시작한다. 기존 `stimulation_IndicatorOut`과 CFX의 알림 공유 경로를 사용하고 직접 트리거를 세우거나 알람 전류를 바꾸지 않는다. 한 회차 종료/stop/5초/준비 조건 상실 시 시험 입력만 해제한다. 진행 중 알람은 기존 함수가 끝내므로 stop은 물리적 자극 정지가 아니다. CM3 로그의 요청/게이트/완료와 실제 전극 출력 검증을 구분한다. 정상 잔량 19%에서의 전체 시스템 동작을 통과시킨 시험은 아니다. 이번 작업 시작 시 사용자가 켠 DIO35의 CM3/CFX 값은 모두 1이며 그대로 보존했다.

2026-10-14에 추가한 [SYS-012 DIO35 표시](../../../tests/system/dio35.md)는 CM3/CFX에서 각각 `TDC_SYSTEM_TEST_DIO35_ENABLE`로 선택한다. 처음에는 양쪽 0으로 추가했으며 같은 날 후속 확인 시 작업본은 CFX 1/CM3 0이었다. 이 설정을 임의 변경하지 않았고 SYS-012에는 양쪽 1이 필요하다. CM3의 `ci_dio_configure_normal` 마지막에서 Low 래치/GPIO 출력을 준비하고, CFX는 FIFO4 ISR에서 High, `pcmDataOut` 반환 직전에 Low를 쓴다. CM3 초기화가 끝난 뒤 공유 실행 허용 플래그로 CFX의 정상 처리가 시작되므로 측정 중 초기화를 반복하지 않는다. 동일 핀은 하나의 하드웨어 자원이므로 측정 중 CM3의 별도 토글과 병용하지 않는다. 현재 보드의 DIO35는 GPIO 출력으로 사용할 수 있는 미사용 핀/테스트 패드임을 은수님이 확인했다(2026-10-14). EXTCLK 겸용 핀이므로 다른 보드나 회로 변경 시에는 연결을 다시 확인한다. 실기 미실행 상태는 유지한다.

이 폭은 안정된 Live 모드에서 입력 준비 대기, CFX/HEAR 연산, 자극 계산/PCM FIFO 기록과 링크 확인을 포함한다. ISR 진입 전 지연과 실제 직렬 전송/내부기 자극 완료는 포함하지 않는다. 다른 PCM 모드에서도 표시되며 요청이 겹치면 에지가 합쳐질 수 있으므로 High 폭만으로 모든 블록의 1ms 충족을 선언하지 않는다. 실제 파형과 최대 폭/주기/누락은 별도 측정한다. 정상 처리/시험 입력, 공유 메모리 구조 및 전하량 보호에는 변경이 없다.

2026-10-13에 추가한 시스템 시험 `SW-FW-SYS-Test-ID-7`은 [전용 RTT 명령](../../../tests/system/README.md)으로 분리한다. `TDC_SYS_TEST_7_ENABLE=1`일 때만 일반 UI에서 `--sys7`을 등록하며 0인 빌드에는 이 명령/분기가 없다. 같은 날 사용자가 켜 둔 작업본의 값 1은 유지한다. 시험 진입 뒤 CM3 전경의 정상 ISD/맵/절전 제어 대신 현재/다음 PCM의 NOP 유지, 기존 오류 LED 요청, RTT와 워치독을 처리한다. Timer 3와 CFX 인터럽트는 유지한다. 기존 계산 관찰은 전용 RAM 계산 뒤 DAC 상태를 복원하며 시험 값을 공유 맵/NVM/내부기 설정으로 보내지 않는다. 종료 후 정상 자극으로 자동 복귀하지 않는다.

이 명령은 위에서 확인한 전하량 검사 비활성/성공 반환/실패 자료 게시 문제를 수정하지 않는다. `t=<uA> c=<uA> w=<us>` 입력은 시험 코드에서 C x w와 한도를 비교하고, 초과 시 기존 오류 코드/빨간 LED 처리에 연결한다. PASS는 그 전하량 비교만 뜻하며 DAC/맵의 적합성을 검사하지 않는다. 제품 계산을 그대로 보는 `charge`/`dac`, 오류 직접 주입인 `led`와 구분한다. 내부기/매핑 연결과 기존 오류를 확인해 진입을 거절하지만, 소프트웨어 상태 확인이나 NOP 요청만으로 물리적 무자극을 증명하지 않으므로 내부기를 분리한 시험 환경이 필요하다. LED의 실제 관찰 결과는 별도로 남긴다.

같은 날 추가한 일괄 시험은 기존 시험 경계 안에서만 동작한다. CM3/BOOT의 시험 콘솔은 RTT DOWN0의 ASCII 명령을 받고, 코어별 실행기는 한 유닛의 결과를 전부 배출한 뒤 다음 유닛을 실행한다. CFX/HEAR는 시험 전용 XMEM mailbox에 결과를 게시하고 CM3가 전송 완료 ACK를 보내야 다음 입력을 사용한다. token/session/sequence로 이전 실행의 결과를 구분하며 제품 공유 구조체에는 필드를 추가하지 않는다. 함수 진입, 초기 정지 및 메모리 독점은 여전히 호출자가 준비한다.

CM3의 실제 입력 관찰 그룹은 생산자를 정지한 상태에서 여러 유닛의 상태를 시험 전용 버퍼에 보관한 뒤 `OBSERVED`로 출력한다. 입력 자체를 주입하거나 실행 중 상태를 원자적으로 읽는 기능은 아니다. 시험 콘솔은 기존 워치독 refresh만 수행하며 설정을 바꾸지 않는다. HEAR 중지/타임아웃 뒤 복원이 끝나지 않았으면 정상 실행으로 돌아가지 않는다. [일괄 실행 매뉴얼](../인허가/사운드1/DHF/04_설계%20검증/SW/펌웨어/유닛%20시험%20일괄%20실행%20매뉴얼.md)에 명령과 준비/종료 순서를 둔다.

CM3-051의 RAM 시험에는 각 SPI 응답 완료를 시험 경계에서 모의 처리하도록 추가했다. IRQ를 정지한 시험에서 두 번째 응답이 기다리던 문제를 해소하는 시험 도구 수정이며, 제품 OTA 오류 응답의 기존 불일치 4필드와 사전 기대값은 유지한다. 실제 SPI 송수신이나 실기 완료를 확인한 것은 아니다.

2026-10-02에 추가한 TD24A 유닛 시험 코드는 `TDC_UNIT_TEST` 빌드에서만 사용한다. CFX는 `test` 소스 폴더를 포함하고, CM3/부트로더는 디버거 호출 진입점을 시험 전용 참조로 유지한다. 정상 루프에 자동 실행을 넣지 않았으며 CM3/CFX 공유 구조체의 필드, 순서와 주소 계약도 변경하지 않았다.

계산 시험은 실제 함수에 RAM 입력을 주고 사용한 상태를 복원한다. FIFO/주변장치/파일 경계의 시험 훅은 기본값이 0이며, 이 경우 원래 접근 경로를 유지한다. 생산자/ISR/다른 코어를 정지하는 것은 시험 호출자의 책임이다. 결과의 `done`은 기록 완료만 뜻한다. 입력을 따로 적용해야 하는 관찰과 코드 분석을 전체 유닛 합격으로 취급하지 않는다.

CM3 기동 시험은 실제 기동 함수의 실행 허용 대입을 사용하되 대기/하드웨어 초기화 경계만 RAM 입력으로 바꾼다. 맵 변경은 실제 함수와 재계산 플래그를 사용하고 파일 경계만 격리한다. 내부기 상태 설정/변경 플래그는 실제 private 상태를 조회하며 공유 RAM과 함께 복원한다. 이 경로도 시작 시 자동 실행하지 않으며 기본 NULL 경계는 제품 경로를 유지한다. 준비/허용 순서 시험을 실제 CFX 응답이나 하드웨어 초기화 완료로 확대하지 않는다.

CFX 결과는 현재 시험 이미지의 XMEM 워드 주소를 이용해 CM3의 XRAM 창에서 읽는다. CM3가 24비트 음수의 부호를 복원하고 전경에서 RTT로 배출한다. HEAR는 실제 완료 이벤트가 있어야 결과를 기록하며, 타임아웃 뒤에도 완료 전까지 메모리를 복원하지 않는다. 정상 부트/파일 갱신/리셋을 시험 함수에서 자동 실행하지 않는다.

보완한 수치 시험은 CFX 중간값 고정과 별도로 실제 SDK Log2/Exp2/나눗셈 경로를 실행하고 원본 계산값과 사전 하한/상한을 보존한다. HEAR는 독립 DFT를 기준으로 창/FFT/크기/블록 지수를 비교한다. 이 준비와 PC 경계 시험을 실기 합격으로 해석하지 않는다.

부트로더 RAM 파일 시험은 SDK FIL을 약 4KB의 지역 객체로 두지 않는다. 시험용 `sections.ld`의 `.tdc_ut_boot_workspace`는 기존 RTT 제어 블록 뒤의 BRAM에만 배치하며 정상 빌드에는 해당 객체가 없다. NOLOAD 공간이므로 매 사용 전 초기화한다. 시험 정지 조건에는 다른 코어의 해당 BRAM 사용도 포함한다. 물리 FatFs/NVM, 이미지 DMA/코어 점프 또는 리셋은 RAM 시험에서 자동 실행하지 않는다.

정상 빌드에도 적용되는 별도 수정은 기존 RTT printf의 길이 제한이다. 포맷 함수가 반환한 필요 길이가 버퍼보다 길어도 실제 저장된 바이트까지만 전송한다. CM3 출력 버퍼를 호출별로 분리했으므로 정상 경로의 스택 사용 변화는 실기 최악 깊이에서 추가 확인해야 한다. 시험 로그는 [유닛 시험 사용 방법](../../../tests/unit/README.md)의 60바이트/부분 전송/취소 규칙을 따른다. 현행 ID별 범위와 미완료 사항은 해당 작업의 시험 코드 대응표를 사용한다.

## 8 근거 파일과 분석의 한계

FatFs/AES/CRC/RTT의 출처, 사용 경로와 검증 범위는 [Sound1 SOUP 사용 및 검토](Sound1%20SOUP%20사용%20및%20검토.md)에서 관리한다. 해당 문서의 버전 식별과 호스트 시험을 제품의 전체 안전성 검증으로 해석하지 않는다.

핵심 근거는 위 각 절의 링크와 심볼이다. CFX는 `src/1__cfx/.cproject`의 ASIP Designer 도구 체인, CM3/부트로더는 각 `.cproject`의 Cross ARM GCC 구성에서 출발했다. HEAR 함수체인 원본은 `src/3__hear/microcode.hct`, CFX가 사용하는 크기/주소 정의는 `src/1__cfx/hear/microcode.h`다. 생성물과 원본의 일치 여부는 HEAR 변경 작업에서 재생성/빌드로 추가 확인해야 한다.

현재 문서는 E8300 주요 정상 경로의 정적 분석과 6.2절의 QCC 제공 설계 대조 결과다. 전체 유닛의 정확성, 공유 메모리의 모든 경쟁 조건, 최악 실행시간, 실제 RF 회로/음향 성능, OTA 보안성이나 실기 시험 통과를 검증한 결과가 아니다. QCC 자료의 내부 상충과 구현/측정 미비를 보존하며, 위에서 표시한 매핑 마이크 전환 및 비정상 NofM 밴드 조건은 관련 상세 설계/수정 시 재확인한다.
