# 16/32채널 선택 리매핑 (이식본)

> **이 문서는 이식본이다.** `sullivan-1-5-fw-hw-test-link-pwr-bt-period`에서 구현한 16/32채널 리매핑 기능을, 같은 CFX/CM3(ez8300) 코드를 공유하는 파생 프로젝트가 **자기 제품(16채널 또는 32채널)에 맞게 이식**할 수 있게 경로에 의존하지 않고 정리했다. 라인 번호는 원천 프로젝트 기준 참고값이다.

**TL;DR**: 16채널 자극기는 **32채널 기판의 가로 커넥터(32채널 기준 전극 17~32) 자리**에 배선된다. 그런데 매핑 앱은 제품이 몇 채널이든 **항상 1부터** 시작하는 번호를 보낸다. 그래서 16채널 제품은 앱의 1~16을 내부 17~32로 옮겨야 한다. 이 변환을 **`tdc_convert_app_electrode_to_internal()` 한 곳**에서 처리하고, 제품 채널 수는 **`TDC_DEVICE_CHANNEL_NUM` 빌드 매크로**로 가른다. **핵심 함정**: 같은 대응표가 **CM3와 CFX 양쪽에 복제**돼 있어(`electrodeMap` ↔ `addr_electrodeMap`), CM3 배열만 16채널로 바꾸면 CFX가 만드는 라이브 자극이 어긋난다. 그래서 **배열은 둘 다 32채널로 두고 번호만 변환**한다.

## 1. 배경 — 왜 리매핑이 필요한가

### 1.1 하드웨어 사실

- 32채널 기판에는 **세로 커넥터(전극 1~16)** 와 **가로 커넥터(전극 17~32)** 가 있다
- **16채널 자극기는 가로 커넥터만 쓴다** → 16채널의 물리 전극은 32채널 기준 **전극 17~32**에 대응한다
- 근거 이미지: `docs/참고/전극 번호/16채널 PCB, 전극 채널 매핑.png` · `32채널 PCB, 전극 채널 매핑.png`

### 1.2 소프트웨어 사실

- 매핑 앱은 제품 채널 수와 무관하게 **1부터** 번호를 보낸다
- 따라서 16채널 제품에서 앱의 전극 **N**은 내부 전극 **N + 16**이다

| 16채널 앱 번호 | 내부(32채널 기준) 번호 | 공통 PCB 핀 |
|---|---|---|
| 1 | 17 | 18 |
| 2 | 18 | 19 |
| … | … | … |
| 16 | 32 | 17 |

## 2. 변환 함수 — 한 곳에서 처리

```c
int convert_app_electrode_to_internal(int app_electrode_num)
{
    // 미사용(99)·범위 밖은 그대로 반환 — 숨기면 호출부 범위 검사가 이상을 못 잡는다
    if ((app_electrode_num < 1) || (MAX_ELECTRODE_NUM < app_electrode_num))
        return app_electrode_num;

#if (DEVICE_CHANNEL_NUM == 16)
    internal = app_electrode_num + (MAX_ELECTRODE_NUM / 2);   // 앱 1~16 → 내부 17~32
    if (internal > MAX_ELECTRODE_NUM)  internal = 99;         // 앱이 17↑ 보내면 없는 전극 → 99
#else
    internal = app_electrode_num;                            // 32채널: 변환 없음
#endif
    return internal;
}
```

| 입력(앱) | 16채널 반환 | 32채널 반환 |
|---|---|---|
| 1~16 | **+16 (17~32)** | 그대로 |
| 17~32 | **99** (없는 전극) | 그대로 |
| 99·범위 밖 | 그대로 (범위 검사가 처리) | 그대로 |

> [!NOTE]
> **변환은 한 함수로 모은다.** 앱 전극번호를 쓰는 모든 경로(맵 초기화·테스트 자극·라이브 자극)가 이 함수를 거치면, 16/32 분기가 흩어지지 않고 새 경로도 자동으로 맞는다. 원천 프로젝트 사용처: 맵 초기화(`ci_map.c`)·테스트 자극(`testStimulation.c`)·라이브 자극(`mapping_Live.c`).

## 3. 빌드 분기

```c
// processorDirective.h (또는 동등 빌드 설정 헤더)
#define TDC_DEVICE_CHANNEL_NUM 32   // 제품에 따라 16 또는 32
```

변환 함수가 이 매크로로 동작을 가른다. **제품 빌드마다 이 값만 바꾸면** 나머지 코드는 그대로 둔다.

## 4. 핵심 함정 — CM3/CFX electrodeMap 복제

같은 전극-PCB 대응표가 **두 곳에 복제**되어 있다.

| 위치 | 심볼 | 역할 |
|---|---|---|
| CM3 | `electrodeMap[32]` (전극 매핑 소스) | CM3 자극 경로(테스트/맵)의 대응표 |
| CFX | `addr_electrodeMap[32]` (자극 전략 소스) | **라이브 자극 PCM을 CFX가 만들 때** 사용 |

> [!WARNING]
> **CM3 배열만 16채널용으로 바꾸면 안 된다.** 라이브 자극 PCM은 **CFX가** 만들고 CFX는 자기 `addr_electrodeMap`을 쓴다. CM3만 16채널로 바꾸면 라이브 자극은 여전히 32채널 배선으로 나가 **두 경로가 어긋난다.** 원천 프로젝트에서 **2026-07-31 실기에 실제로 겪은 문제**다.

**해결**: 두 배열을 **모두 32채널 값으로 유지**하고, 앱 전극번호를 §2 함수로 변환해서 넘긴다.
- 변환된 번호가 공유메모리를 거쳐 CFX에 전달되고, CFX는 그 번호를 그대로 인덱스로 쓴다
- 따라서 **CFX를 고치지 않고도** 16채널 배선에 맞출 수 있다
- 배열을 16채널용으로 바꾸는 방식보다 **두 소스를 동기화할 필요가 없어** 안전하다

## 5. MRI/시험 맵의 16ch/32ch 선택 (선택 사항)

원천 프로젝트는 시험용 맵을 펌웨어에서 직접 심을 때도 채널 수를 골랐다.

- 리모콘 `0x59` **옵션 8** + value(`16`/`32`/`0xFF`)로 `map_init_16ch`/`_32ch`/`(제품기본)` 함수 호출
- **16ch 맵 함수**: 앞 16채널만 §2 변환으로 채우고, 17~32 자리는 99(미사용)·레벨 0
- **32ch 맵 함수**: 32채널 전부 변환(그대로)
- 상세: 원천 프로젝트 `docs/tasks/stimulation/20260804_mri-test-map-generation/분석.md`

## 6. 이식 체크리스트 (자기 프로젝트에서)

1. [ ] 제품이 **16채널을 지원하는지** 확인한다. 32채널 전용이면 변환은 항등이라 부담 없다
2. [ ] 앱 전극번호를 쓰는 경로를 **한 변환 함수**로 모은다 (§2)
3. [ ] **빌드 분기 매크로**(`DEVICE_CHANNEL_NUM` 등)를 두고 제품별로 설정한다
4. [ ] **CM3와 CFX 두 대응표가 같은 32채널 값인지** 확인한다:
   - CM3 `electrodeMap[]` 정의
   - CFX `addr_electrodeMap[]` 정의 (자극 전략 소스)
   - 둘의 32개 값이 **완전히 일치**해야 한다
5. [ ] 16채널 지원 시 **배열을 바꾸지 말고 번호를 변환**한다 (§4 함정)
6. [ ] 16채널의 물리 배선이 정말 **32채널 가로 커넥터(17~32)**인지 자기 기판 도면으로 확인한다 (제품마다 다를 수 있다)
7. [ ] 변환이 99·범위 밖을 **그대로 통과**시키는지 확인한다 (범위 검사와 책임 분리 — [99 이슈 이식본](electrodeMap%2099%20인덱스%20범위%20이슈%20(이식).md) 참조)

## 7. 미확인 / 이식 시 확인 필요

| 항목 | 내용 |
|---|---|
| CFX 대응표 실제 경로·값 | 파생 프로젝트마다 다르다. sound1은 표준 구조(`src/1__cfx/...`). **이식 시 자기 프로젝트에서 두 배열 값을 직접 대조하라** |
| 16채널 배선 방향 | 32채널 가로 커넥터라는 것은 원천 제품 기준. **자기 제품 도면으로 재확인** |
| 실기 검증 | 원천 프로젝트도 16채널 실기 자극 파형은 미측정 |
