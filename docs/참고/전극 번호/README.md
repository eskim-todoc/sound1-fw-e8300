# 전극 번호 - 참고 자료 및 이식 적용 결과

**TL;DR**: 원천 프로젝트(`sullivan-1-5-fw-hw-test-link-pwr-bt-period`)의 이식 문서 2건을 가져와 **sound1 에서 체크리스트를 실제로 돌렸다.** 결과는 **대부분 이미 방어돼 있고 원천보다 앞서 있다** — 원천이 «무방비» 로 남긴 eCAP·impedance 를 sound1 은 2026-08-05·06 에 이미 막았다. **다만 체크리스트 7번(루프 상한 이중가드)에서 새 결함을 찾았다**: 리모콘 `0x4D` 맵 쓰기에 범위 검사가 통째로 없어 매핑 앱 경로와 비대칭이다. → [`상시 점검 대장.md`](../../상시%20점검%20대장.md) **위험_4** 로 등록.

## 2. 이식 체크리스트 - 99 인덱스 범위 이슈 (2026-08-06 sound1 대조)

### 2.1 배열·크기

| 항목 | sound1 값 |
|---|---|
| CM3 배열 | `int electrodeMap[32]` — `board/electrodeMapping.c:3` |
| CFX 배열 | `int _XMEM addr_electrodeMap[32]` — `1__cfx/signalProcessing/stimulationStrategy.c:14` |
| 크기 매크로 | `df_MaxNumOfElectrode` = **32** (CM3 `stim/tdc_stim_definitions.h:68`, CFX `signalProcessing/definitionsForAlgorithm.h:143`) |

> [!IMPORTANT]
> **§4 함정(CM3/CFX 복제) 통과.** 두 배열 값이 완전히 일치한다.
> ```
> 31,12,11,9, 7,5,3,1, 0,2,4,6, 8,10,13,15, 17,18,20,22, 24,26,28,30, 14,29,27,25, 23,21,19,16
> ```
> 양쪽 다 `#if 1 / #else` 로 항등 배열(임피던스 지그용)을 대안으로 갖는 구조까지 같다.

### 2.3 원천 프로젝트와의 차이 - sound1 이 앞서 있다

이식 문서 §4 는 원천 기준으로 eCAP·impedance·SpecificStimulation 을 «무방비/부분» 으로 적었다. **sound1 은 그 셋을 모두 막았다.**

| 경로 | 원천 (2026-08-04) | **sound1 (2026-08-06)** |
|---|---|---|
| 자극 파라미터 설정 | 방어됨 | 방어됨 (이월_D, 2026-07-27) |
| 특정 자극 (0x65) | **부분** | **방어됨** — 파싱 1~32 + 인접 검사 (2026-07-30) |
| eCAP 측정 | **무방비** | **방어됨** — 0x63·0x64 파싱 9+6블록 (2026-08-05, 위험_1·2) |
| 임피던스 측정 | **무방비** | **방어됨** — 파싱 + `0x1F` 마스크 (2026-08-06, 위험_3) |

> [!NOTE]
> sound1 은 이식 문서 §6 의 **대안 3(«패킷 수신 시 1회 검증·거부», «가장 근본적»이라 적혔으나 원천은 미적용)** 을 실제로 채택했다. 매핑 명령마다 파싱에서 범위를 강제하고, `isd/` 는 그 뒤에서 2차 방어를 둔다.

### 2.4 체크리스트 7번에서 찾은 새 결함

> [!CAUTION]
> **«루프 상한이 `usableElectrodeNum` 만 보는지, `&& (i < MAX)` 이중가드가 있는지 확인한다»** — 이 항목이 걸렸다.
>
> `stim_para_setting.c:465`
> ```c
> for (i = 0; i < p_mapdata->numFrequencyBand; i++)   /* 상한 무제한 */
> {
>     ... p_mapdata->usableStimulationElectrodIndex[i] ...   /* 배열은 [32] */
> }
> ```

**`numFrequencyBand` 가 32를 넘을 수 있는가**가 쟁점이고, **넘을 수 있다.** 리모콘 경로에 검증이 없다.

| 경로 | `numFrequencyBand` 검증 |
|---|---|
| 0x66 라이브 | **있음** — `tdc_ble_cmd_0x66_live.c:110~111` 1~32 |
| 매핑 앱 맵 쓰기 | **있음** — `tdc_ble_map_flash.c:607~612` `case 10: // 주파수 밴드 수` 1~32 |
| 펌웨어 기본값 | 있음 — 상수 24 또는 32 (`fs/tdc_fs_map.c:617~627`) |
| **리모콘 `0x4D` 맵 쓰기** | **없음** — `ble/remote/tdc_ble_remote.c:421~424` 12필드를 그대로 복사 |

상세와 도달 사슬은 [`상시 점검 대장.md` §2.6 위험_4](../../상시%20점검%20대장.md) 에 등록했다.

## 3. 이식 체크리스트 - 16/32채널 리매핑 (2026-08-06 sound1 대조)

> [!IMPORTANT]
> **2026-08-06 은수님 판단: «16채널 당장은 불필요».** 이 이식은 **보류**한다. 아래 대조 결과는 나중에 16채널 제품 계획이 생길 때 그대로 쓸 수 있게 남긴다.

| # | 항목 | sound1 결과 |
|---|---|---|
| 1 | 제품이 16채널을 지원하는가 | **불필요 (2026-08-06 은수님 판단)** — 다만 `electrodeMapping.c:4` 에 «16채널 자극기용 임시. 2025.01.02» 배열이 **주석으로 남아 있다.** 과거에 시도한 흔적 |
| 2 | 변환 함수로 모았는가 | **없다** — `convert_app_electrode_to_internal()` 에 해당하는 함수가 sound1 에 없다. 앱 전극번호를 그대로 쓴다 |
| 3 | 빌드 분기 매크로 | **없다** — `DEVICE_CHANNEL_NUM` 류 없음 |
| 4 | CM3/CFX 대응표 일치 | **일치** (§2.1) |
| 5 | 배열 대신 번호 변환 | 해당 없음 (16채널 미지원) |
| 6 | 16채널 배선이 32채널 가로 커넥터인가 | **미확인** — 자기 기판 도면 필요 |
| 7 | 변환이 99·범위 밖을 통과시키는가 | 해당 없음 (변환 없음) |

> [!IMPORTANT]
> **sound1(E8300)이 32채널 전용이면 이 이식은 불필요하다.** 변환이 항등이 되므로 함수를 만들 이유가 없다. 16채널 제품 계획이 있을 때 착수한다.
>
> **착수 시 함정 하나만 기억하면 된다** — 이식 문서 §4: **CM3 `electrodeMap[]` 만 16채널용으로 바꾸면 안 된다.** 라이브 자극 PCM 은 CFX 가 자기 `addr_electrodeMap[]` 로 만들기 때문에 두 경로가 어긋난다. 원천 프로젝트가 2026-07-31 실기에서 실제로 겪었다. 배열은 둘 다 32채널로 두고 **번호만 변환**한다.
