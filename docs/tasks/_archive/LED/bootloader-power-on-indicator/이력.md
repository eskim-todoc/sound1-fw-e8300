# 부트로더 단계 LED 조기 점등 — 이력

**TL;DR**: 2026-04-27 조사 시작 ~ 2026-04-30 구현·검증 완료. Step 3 SLOWCLK_DIV32 보정 후 가드 ON+UART 비활성에서 SKYBLUE fade cycle 정상. 첫 LED 인지 1,670 → 약 540 ms (단축 ~1,130 ms, 68%). 가드 OFF 디폴트 회귀 — 기존 부트로더 동작 영향 없음. 사후 갱신으로 cycle 540→360 ms(OFF 180→0)로 부트로더 종료~CM3 진입 추가 ~100 ms 단축.

상태: **완료** (사용자 검증 통과)

## 1. 결과 요약

- **사용자 검증**: Step 3 보정 후 정상 동작 (가드 ON + UART 비활성 시 SKYBLUE fade cycle 정상)
- **회귀**: 가드 OFF 디폴트 회귀 — 기존 부트로더 동작 (UART, 디버그 LED, CM3 부팅) 영향 없음
- **정량 효과** (요구사항.md §1.2 timeline 기반):
  - 기존: 첫 LED 인지 = 1,670 ms (ROM 500 + 부트로더 440 + CM3 730)
  - 본 작업: 첫 LED 인지 ≈ 540 ms (ROM 500 + 부트로더 T-B = 수십 ms 후)
  - **단축: ~1,130 ms (약 68%)**
  - 사후 갱신 (2026-05-07, §8): 부트로더 cycle 540 → 360 ms (OFF 180 → 0). 첫 LED 인지 시점은 동일 (ON portion 360 ms 그대로), 부트로더 종료 후 CM3 진입까지 **추가로 ~100 ms 단축**
- **빌드 가드**: `TDC_BOOT_LED_ENABLE` (Step 4 시점 디폴트 = 1, 정식 채택). 비활성화는 `-DTDC_BOOT_LED_ENABLE=0` 으로 override

## 4. 사용자 측정 1 차 오동작 → Step 3 보정 (학습 큰 사건)

### 4.1 현상

Step 1/2 commit 후 사용자 빌드·측정: 동작 가시성 모호. 사용자 진단:
> "동작을 하는 건지 안 하는 건지 모르겠다. CM3에서 시스템 클럭 설정한 후에 관련 클럭들에 대한 div 설정하는 항목을 부트로더에서도 동일하게 해야할거 같아. 타이머 클럭에 문제가 있는거 같아."

### 4.2 원인 진단

이중 문제:

#### a. RSL10 General Timer 의 클럭 체인 — Step 2 의 가설 잘못

[`ci_timer.h:56`](../../../../src/2__cm3/Gen1_5/common/ci_timer.h):
```
공식: T = 2^prescale × (tick + 1) / 40 kHz   (SLOWCLK = 1.28 MHz 기준)
```

즉 **General Timer = SLOWCLK / 32 = 40 kHz** 가 base clock. SYSCLK 30.72 MHz 가 아님.

Step 2 의 reload = 307 (30.72 MHz / 100 kHz - 1 가정) 은 무의미한 값. (40 kHz 기반에서 reload 307 → 7.7 ms 주기 ISR — fade 시간 모두 7.7 배 늘어남).

#### b. 부트로더에 D_CLK 분주 설정 자체 부재

[`ci_power.c:154-156`](../../../../src/2__cm3/Gen1_5/common/ci_power.c) (CM3 측):
```c
// SLOWCLK은 반드시 1.28 MHz로 설정
D_CLK->CFG_1 = (ADCCLK_PRESCALE_8 | ADCCLK_SRC_SYSCLK | SDMCLK_PRESCALE_2
              | SLOWCLK_PRESCALE_24 | SLOWCLK_SRC_SYSCLK | UARTCLK_SRC_SYSCLK);
D_CLK->CFG_2 = (UCLK_PRESCALE_8 | UCLK_SRC_ADCCLK);
delay_ms(5);
```

부트로더에는 이 분주 설정이 없어 SLOWCLK 가 디폴트값 (불명) 으로 동작. SYSCLK 30.72 MHz 변경 후에도 SLOWCLK 분주 미설정 → Timer base clock 불명.

### 4.3 보정 (Step 3, commit `27f2c28`)

`tdc_boot_led_init()` 안에:

1. **D_CLK 분주 설정 추가 (CM3 와 동일)**: `SLOWCLK_PRESCALE_24` → SLOWCLK = 1.28 MHz → Timer = 40 kHz 보장. UARTCLK_SRC_SYSCLK 유지 → UART baud 영향 없음.
2. **`tdc_delay_ms(5)` 안정화 대기** (CM3 ci_power.c:158 동일).
3. **PWM 매개변수 재계산** — Timer 25 us tick (= 1/40 kHz, 분해능 한계):
   - reload 307 → **0**
   - PWM 주기 = 100 bin × 25 us = **2.5 ms = 400 Hz** (깜빡임 안전)
   - 1 ms 단위 phase tick 은 별도 카운터로 ISR 40 회 마다 호출 (`s_tdc_boot_led_isr_in_ms`)

duty G:B = 30:40 그대로 유지 (k_led_mix[en__LED_SKYBLUE] 비율).

### 4.4 검증

사용자 재측정: **"정상동작하는거 같아"** — Step 3 보정 후 의도 형태 동작 확인.

### 4.5 학습 (회고 후보)

- **Cortex-M MCU 의 peripheral 은 시스템 클럭 직결이 아니라 분주된 sub-clock 기반인 경우가 많다.** General Timer 가 그 예 — SLOWCLK 분주값에 의존.
- **CM3 측 클럭 분주 설정을 부트로더가 안 하면 같은 peripheral 동작이 다르게 나온다.** 부트로더는 보통 polling 기반이라 분주에 둔감하지만, ISR 기반 신규 모듈을 부트로더에 추가하면 분주 설정도 옮겨와야 한다.
- **SDK 함수의 인자 단위 (cycles vs us vs ms)** 는 헤더 주석으로 확인. ci_timer.h:56 같은 공식 주석이 결정적 단서.

## 8. 사후 변경 — OFF phase 0 (2026-05-07)

부트로더 SW PWM `TDC_BOOT_LED_T_OFF_MS` **180 → 0** ([`tdc_boot_led.c:54`](../../../../src/0__bootloader/source/led/tdc_boot_led.c)). cycle = 540 → **360 ms**. 부트로더 종료 후 CM3 진입까지 **약 100 ms 단축**.

근거: OFF 180 ms 의 wait 는 CM3 진입 직후 자체 초기화 시간 (현재 측정 ~730 ms, [`power-on-early-lighting`](../power-on-early-lighting/) 으로 단축 중) 으로 자연 흡수됨. 사용자가 보는 LED 패턴 (SKYBLUE fade in/peak/out → OFF → 정식 LED_ST_POWER_ON) 은 동일.

phase machine 자체는 그대로 유지 (FADE_OUT 후 OFF phase 진입 → t ≥ TOTAL=360 즉시 만족 → DONE → 다음 1 ms tick 에서 wait 탈출). D-5 결정 행은 유지하고 본 항목으로 사후 갱신만 표기.

영향:
- [`bootloader.c:1376`](../../../../src/0__bootloader/source/bootloader.c) wait 주석 540 → 360 갱신
- [`tdc_boot_led.h:19,27`](../../../../src/0__bootloader/include/led/tdc_boot_led.h) 주석 540 → 360 갱신
- [`power-on-early-lighting/이력.md §5`](../power-on-early-lighting/이력.md) V10 분석의 절대 시간 정렬 (이전: T_PowerOn = ROM 500 + 부트로더 540 = 1040, cycle 가 작업 ≈440 보다 길어 cycle 가 종료 결정) → (변경 후: ROM 500 + max(작업 ~440, cycle 360) = ROM 500 + ~440 = **~940 ms**, 작업이 종료 결정). 약 **100 ms 단축**. V10 결론 (영향 없음) 자체는 변하지 않음 (QCC 자체 schedule + 안전 마진 충분)
- **CM3 측 보상** (2026-05-07): [`LedOutput.c`](../../../../src/2__cm3/Cortex-M3-src/systemControl/LedOutput.c) 에 `LED_BOOT_HANDOFF_OFF_MS = 100 ms` 매크로 + `LED_TX_LEAD_OFF` phase 추가. `LED_ST_POWER_ON` reset 분기에서 leading OFF 100 ms 후 FADE_IN 진입. 부트로더 자체 잔여 ~100 ms + 본 leading 100 ms ≈ 200 ms 자연 OFF 로 변경 전 부트로더 OFF gap (~180 ms) 보전. [`power-on-early-lighting/이력.md §5.7`](../power-on-early-lighting/이력.md) 참조.
- **CM3 측 보상 갱신** (2026-05-07 (2)): 100 ms leading OFF 가 사용자 체감 부족 (첫 OFF gap 200 ms 가 burst OFF 180 ms 와 비슷해 분리감 X). `LED_BOOT_HANDOFF_OFF_MS` (100) → **`LED_POWER_LEAD_OFF_MS` (400)** rename + POWER_OFF 도 적용 + cross-fade 전용 `LED_DIMMING_TX_FADE_MS = 60 ms` 분리 + POWER_ON burst 5 → 4. [`power-on-early-lighting/이력.md §5.8`](../power-on-early-lighting/이력.md) 참조.
