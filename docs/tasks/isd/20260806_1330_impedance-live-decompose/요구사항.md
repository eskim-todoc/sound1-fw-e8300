# 요구사항 - impedance · live 분해

**TL;DR**: `isd/` 에 남은 **단일 함수 두 개**를 나눈다. 단계_3·4 와 같은 형태이나, **둘 다 기계 추출로** 하고 검증은 구조 지표에 맡긴다.

## 1. 대상 선정 근거

단계_3·4 를 마친 뒤 `isd/` 를 «줄 수 / 함수 수» 로 다시 훑었다.

| 파일 | 줄/함수 | 실기 게이트 | 판정 |
|---|---|---|---|
| `map_live` | **809** (1함수) | 라이브 자극 | **대상** |
| `map_ecap` | 727 (2함수) | **닫힘** (앱이 0x63·0x64 미사용) | **제외** |
| `map_impedance` | **664** (1함수) | 0x62 임피던스 | **대상** |
| `tdc_isd_init` | 320 (3함수) | 초기화 | 후속 |

**`ecap` 제외는 [분해 분석](../20260806_0834_isd-대형함수-분해-분석/분석.md) §2.3 의 판단을 그대로 따른다** — 검증할 수 없는 분해는 위험을 없애는 것이 아니라 미루는 것이다. 2026-08-06 은수님이 eCAP 미사용을 확인했다.

## 2. 요구사항

### 요구사항_1 - 상태·하위명령 별로 나눈다

- `impedance`: `flowCounter` 상태 9개 + `startFlag` 리셋 + `switch` 밖 전송 블록
- `live`: `subCommand` 하위명령 10개

### 요구사항_2 - 기계로 추출한다

단계_4 에서 쓴 방식을 그대로 쓴다. 본문은 원문 그대로 옮기고 껍데기만 생성한다.

### 요구사항_3 - 구조 지표로 검증

두 파일 모두 **분기 총수 보존**을 기대한다. 이번엔 병합할 중복이 없으므로 **`return` 증가(추출 함수 수) 외에는 전부 불변**이어야 한다.

### 요구사항_4 - `switch` 밖을 빠뜨리지 않는다

`impedance` 는 `switch` 밖에 **71줄 전송 블록**이 있다. 자산_5 의 다섯 번째 사례다.

## 3. 제약

| # | 제약 |
|---|---|
| 제약_1 | 동작 불변 |
| 제약_2 | 포맷 조건 · CP949 금지 문자 |
| 제약_3 | `#if 0` 은 건드리지 않는다 |
| 제약_4 | 실기 대기가 11건이 된다 |

## 4. 완료 조건

- [ ] 두 디스패처가 상태 표만 남는다
- [ ] 구조 지표가 `return` 외 전부 불변
- [ ] 호스트 514 PASS 유지
- [ ] ARM 에러 0 · 경고 증가 0
- [ ] `data`·`bss` 불변
