# 요구사항 검증

**TL;DR**: 3축 통과. 보완 1건 — 요구사항_3 이 «`return` 외 전부 불변» 을 기대했는데, **두 파일의 기대치가 다르다**(추출 함수 수가 다르다). 파일별로 숫자를 못 박았다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 8단계 · 폴더 규약 | 통과 |
| **코드 전 승인** | **확보** - 2026-08-06 은수님이 후속 재량을 명시 위임 |
| `ecap` 제외 판단 | **기존 분석 계승** - 새로 정하지 않았다 |

## 축_2 - 논리 정합성

### 정합_1 - 두 파일을 한 작업으로 묶어도 되는가

된다. **같은 형태 · 같은 방법 · 같은 검증**이다. 다만 커밋은 파일별 되짚기가 되도록 한 번에 하되 메시지에서 갈라 적는다.

### 정합_2 - 기계 추출을 두 번째 쓰는 것이 안전해졌는가

**아니다. 파일마다 다른 함정이 있다.** 단계_4 에서 통했다고 이번에도 통한다는 보장이 없다.

- `live` 는 `case` 라벨이 **열거형 이름**이라 정규식이 다르다
- `live` 는 `ISD_state` 가 **함수 인자**라 추출 함수에 넘겨야 한다
- `live` 는 `switch` 에 **`default` 가 없다** - 임의로 넣으면 지표가 바뀐다
- `impedance` 는 반환값이 없다(`void`)

**스크립트를 재사용하지 않고 파일마다 다시 쓴다.** 공통 부분만 베낀다.

### 누락 - 기대치가 파일마다 다르다

> [!WARNING]
> 요구사항_3 은 «`return` 증가 외 불변» 이라고만 했다. **증가폭이 파일마다 다르므로 숫자를 못 박지 않으면 검증이 안 된다.**

**보완**:

| 파일 | 추출 함수 | `return` 기대 |
|---|---|---|
| `impedance` | 11 (`void`) | **불변** (void 라 `return` 문이 없다) |
| `live` | 10 (+디스패처) | **+10** |
