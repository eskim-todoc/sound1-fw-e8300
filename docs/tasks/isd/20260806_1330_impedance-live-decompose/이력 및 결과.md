# 이력 및 결과 - impedance · live 분해

**TL;DR**: `isd/` 에 남아 있던 **단일 함수 두 개**(`map_impedance` 664줄 · `map_live` 809줄)를 각각 **11 · 11함수**로 나눴다. 이로써 `ecap`(검증 불가로 제외)을 빼면 `isd/` 에 500줄 넘는 함수가 없다. **기계 추출이 두 번 틀렸고 두 번 다 자동 검증이 잡았다.**

## 배경

2026-08-06 은수님 — *"그거 다 하고, 같은 선상에서 비슷한 맥락으로 할게 있으면 알아서 해봐. 나한테 안 물어봐도 돼."*

단계_3·4 를 마친 뒤 `isd/` 를 «줄 수 / 함수 수» 로 다시 훑어 남은 대상을 골랐다.

| 파일 | 분해 전 | 실기 | 판정 |
|---|---|---|---|
| `map_live` | 809줄 **1함수** | 라이브 자극 | **대상** |
| `map_ecap` | 1,454줄 2함수 | **불가** (앱 미사용) | 제외 유지 |
| `map_impedance` | 664줄 **1함수** | 0x62 임피던스 | **대상** |
| `tdc_isd_init` | 962줄 3함수 (320 줄/함수) | 초기화 | 후속 후보 |

단계_3 의 선례대로 **폭발 반경이 작은 impedance 를 먼저** 했다.

## 자산

### 자산_S - 원시 C 텍스트는 중괄호가 맞지 않을 수 있다

impedance `case 0` 을 추출했더니 **본문이 490줄**로 나왔다(실제 117줄). `switch` 전체를 삼킨 것이다.

원인은 전처리기 분기다.

```c
#if 1
    ...
    if (...)          // <- 여는 '{' 가 이 가지에 있고
    {
#else
    ...
    if (...)          // <- '{' 가 또 있고
    {
#endif
    }                 // <- 닫는 '}' 는 하나뿐
```

**`#if 1` 가지의 `{` 를 `#endif` 뒤의 `}` 가 닫는데 `#else` 가지에도 자기 `{` 가 있다.** 원시 텍스트만 세면 여는 것이 하나 더 많아 짝이 영영 안 맞는다.

**죽은 전처리기 가지를 빼고 세야 한다.** 매처에 `#if`/`#else`/`#elif`/`#endif` 추적을 넣었다.

> [!CAUTION]
> **구조 지표가 즉시 잡았다.** `case` 9→17 · `if` 28→41 · `for` 9→17 로 전반이 부풀었다. 지표 없이 빌드만 했다면 컴파일은 통과했을 수도 있고, 통과했다면 그대로 커밋됐을 것이다.

### 자산_T - 이름 치환은 구조체 멤버를 건드리면 안 된다

`static int iterationNum` 을 `s_iterationNum` 으로 바꾸는 치환이 **`mappingPacket->impedanceCheck.iterationNum` 의 멤버까지** 바꿨다. 이름만 같은 남이다.

```python
re.sub(r'(?<![\w.])(?<!->)\b%s\b' % name, 's_' + name, txt)
```

앞이 `.` 이거나 `->` 면 넘긴다. **컴파일러가 잡았다** — 계획이 말한 «마지막 방어» 가 실제로 작동한 사례다.

### 자산_U - 블록 경계는 «여는 괄호 다음» 부터다

`startFlag` 블록을 뽑을 때 여는 `{` 까지 포함해 **함수가 닫히지 않았다.** `invalid storage class for function` 이라는, 원인이 바로 안 보이는 에러가 났다(중첩 함수 정의로 해석된 것).

**행 번호를 손으로 적을 때는 여는 괄호를 포함했는지 반드시 확인한다.**

### 자산_V - 자동 검증 셋이 서로 다른 층을 잡았다

이번 작업에서 세 번 틀렸고 각각 다른 것이 잡았다.

| 실수 | 잡은 것 |
|---|---|
| 전처리기로 인한 블록 경계 오류 | **구조 지표** (빌드는 통과했을 수 있다) |
| 구조체 멤버 오치환 | **컴파일러** |
| 여는 괄호 포함 | **컴파일러** |

**어느 하나만 있었으면 놓쳤다.**
