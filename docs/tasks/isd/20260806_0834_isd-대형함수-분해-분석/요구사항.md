# 요구사항 - isd 대형 함수 분해 분석

**TL;DR**: BLE 이월이 전량 소진돼 다음 리팩토링 대상을 정해야 하는데, 실기 대기 5건이 쌓여 코드를 바꿀 수 없다. 그래서 **`isd/` 대형 함수를 코드 무변경으로 조사**해, 무엇을 어떤 순서로 분해할지와 **안전망 없이 어떻게 검증할지**를 확정한다.

## 1. 배경

| 사실 | 근거 |
|---|---|
| BLE 이월(A~I·1·2)이 전량 소진됐다 | [`세션_인수인계/20260806_0752`](../../../세션_인수인계/20260806_0752_ble-이월-전량소진-검증방법정립.md) §1 |
| 잠재 위험이 0건이다 | [`상시 점검 대장.md`](../../../상시%20점검%20대장.md) §2 |
| 실기 미검증 병합이 **5건** 쌓였다 | 대장 §1 알림_2 |
| 은수님이 원격이라 실기가 불가능하다 | 2026-08-05 지시 |

**코드를 더 바꾸면 실기 대기가 6건이 되어 문제 발생 시 원인 좁히기가 어려워진다.** 2026-08-06 은수님이 «분석만 선행» 을 선택했다.

## 2. 요구사항

### 요구사항_1 - 대상 확정 (실측 기반)

`src/2__cm3/source` 에서 분해 가치가 남은 파일·함수를 **실측으로** 가려낸다.

> [!IMPORTANT]
> **자산_3 을 적용한다** — «이월 항목의 전제는 착수 시점에 자주 뒤집힌다»(이번 세션에만 3회). 문서에 적힌 후보를 그대로 믿지 않고 줄 수·함수 수·분기 수를 직접 센다.

### 요구사항_2 - 검증 가능성 판정

각 대상에 대해 **두 게이트**의 상태를 확정한다.

| 게이트 | 판정 기준 |
|---|---|
| **호스트 테스트** | `tests/unit/run.sh` 의 `TEST_TARGETS` 에 그 `.c` 가 있는가 |
| **실기** | 앱이 그 경로를 트리거하는 명령을 보내는가 |

**둘 다 닫혀 있으면 분해 결과를 확인할 방법이 없다.** 위험_1 때 «조치 위치를 `isd/` 가 아니라 파싱으로 잡은» 것과 같은 판단이 필요하다.

### 요구사항_3 - 중복 전수 조사

`isd/` 안에서 **같은 로직이 여러 곳에 복제된 것**을 전수로 찾는다. 분해보다 통합이 먼저일 수 있다.

### 요구사항_4 - 죽은 코드 계량

`#if 0` 등으로 **컴파일되지 않는 줄**을 정확히 센다. 분해 전에 제거하면 대상 자체가 줄어든다.

> [!CAUTION]
> `#else` 와 중첩을 처리해야 한다. `#if 0 ... #else ... #endif` 에서 죽는 것은 앞 가지이고, `#if 1 ... #else ... #endif` 에서는 뒷 가지다. 단순 `#if 0`~`#endif` 매칭은 틀린 값을 낸다.

### 요구사항_5 - 착수 순서와 검증 방법 제시

무엇을 먼저 할지와, 각 단계를 **어떤 방법으로 검증할지**를 함께 낸다. 검증 방법 없는 순서는 쓸모가 없다.
