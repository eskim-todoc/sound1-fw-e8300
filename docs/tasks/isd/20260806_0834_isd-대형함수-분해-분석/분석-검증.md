# 분석 검증

**TL;DR**: **오류 2건을 잡았다.** ① `tdc_isd_map_specific_stim.c` 를 과소평가했다 — 629줄 **단일 함수**에 **실기 검증까지 되는** 대상인데 §6 착수 순서에서 이름조차 없었다. ② 중복 위치 줄 번호 2개가 틀렸다(`grep` 이 낸 `case`/`default` 줄을 `switch` 줄로 오기). 둘 다 정정하고 §6 순서를 바꿨다.

## 축_1 - 지침 준수

| 항목 | 판정 | 비고 |
|---|---|---|
| 사실에 `파일:라인` 근거 | 통과 | §8 근거 목록 |
| 추측을 추측이라 명시 | 통과 | §3.3 «0 이 도달 가능한지는 확인하지 않았다» |
| HW 5게이트 | 통과 | §3.3 에서 방어 추가를 **보류**하고 «불확실성 명시» |
| 한글 라벨 | 통과 | `발견_N` · `단계_N` · `오탐_N` |
| Mermaid (ASCII 금지) | 통과 | §6.5 |
| 코드 무변경 (제약_1) | **통과** | `git status` 에 `src/` 변경 없음 |

## 축_2 - 논리 정합성

### 정합_1 - 「검증 불가」와 「위험 거의 0」이 모순인가

모순이 아니다. **실행되지 않으므로 지금 위험이 0이고, 실행되지 않으므로 확인할 수 없다** — 같은 사실의 두 면이다. §2.3 이 이를 «위험이 사라진 게 아니라 미래로 미뤄진다» 로 정리했다. 정합적이다.

### 정합_2 - 단계_2 가 「호스트 게이트를 연다」는 주장이 성립하는가

성립한다. 뽑아낼 두 함수는 `EN___STIMULATION_MODE` 하나를 받아 `int` 를 내는 순수 함수이므로 `isd/` 의 의존 사슬(shm · i2c · FPGA)을 타지 않는다. **자산_8**(«호스트 컴파일 장벽은 헤더 한 줄»)의 반대 방향 적용이다 — 사슬을 끊는 대신 **사슬에 닿지 않는 조각을 떼어낸다.**

다만 이 주장에는 조건이 붙는다.

> [!WARNING]
> **두 함수를 어디에 둘지가 남는다.** `isd/` 안의 기존 `.c` 에 넣으면 그 파일 전체를 링크해야 해서 게이트가 안 열린다. **새 파일**(예: `isd/tdc_isd_stim_mode_encode.c`)로 떼야 `TEST_TARGETS` 에 단독으로 넣을 수 있다. §6.2 에 이 조건을 보완했다.

### 정합_3 - 단계 순서가 의존관계와 맞는가

| 주장 | 검토 |
|---|---|
| 단계_1(죽은 코드) → 단계_2(중복) | **맞다.** 죽은 코드 안에도 중복 스위치가 있을 수 있어 먼저 지우면 대상이 정확해진다 |
| 단계_2 → 단계_3(분해) | **맞다.** 중복이 남은 채 분해하면 같은 블록을 여러 함수에 복제한다 |

### 정합_4 - 「실기 가능 여부」가 순서에 제대로 반영됐는가

> [!CAUTION]
> **반영되지 않았다. 이것이 오류_1 이다.** 아래 §정정 참조.

## 축_3 - 근거 검증

### 재확인한 주장

| 주장 | 재확인 결과 |
|---|---|
| `isd/` 가 `TEST_TARGETS` 에 없다 | **확인.** `run.sh:140~145` 네 항목 전부 `ble/` 밑 |
| `ecap_step` 호출처 2곳 | **확인.** `tdc_ble_mapping.c:389`(호출) · `:403`(주석) |
| 죽은 코드 235줄 | **확인.** 구역 10곳 합 237 - 중첩 지시자 2줄 = 235 |
| `switch` 밖 275줄 | **확인.** `:1242` `if (flowCounter == backtelStart_flowCounter)` ~ `:1516` |
| `en__referenceNA = 0` | **확인.** `tdc_shm.h:69` |
| `case 5`·`case 6` 이 서로의 복제가 아니다 | **확인.** `case 5` = eCAP 샘플링 레지스터(`:653~`), `case 6` = 인터벌 템플릿(`:958~`) |

### 오류_1 (중대) - `specific_stim` 을 과소평가했다

분석 §1.1 은 `tdc_isd_map_specific_stim.c` 를 «대상_3» 으로 **인정해 놓고**, §6 착수 순서에서는 **한 번도 언급하지 않았다.** 단계_3 은 `stim_para_setting`, 단계_4 는 `ecap` 이라 이 파일이 빠졌다.

**실측하니 순위가 뒤바뀐다.**

| 파일 | 줄 | 함수 | 줄/함수 | 실기 | 폭발 반경 |
|---|---|---|---|---|---|
| `tdc_isd_map_ecap.c` | 1,519 | 2 | 760 | **불가** | — |
| `tdc_isd_map_specific_stim.c` | 629 | **1** | **629** | **가능** | 특정자극(0x65)만 |
| `tdc_isd_stim_para_setting.c` | 1,178 | 6 | 196 | **가능** | **모든 자극** |

근거:

| 사실 | 출처 |
|---|---|
| `specific_stim_step` 호출처 1곳 | `tdc_ble_mapping.c:413`, `case en__mapping_specific_stimulation:` 안 |
| 0x65 를 앱이 쓴다 | [`상시 점검 대장.md`](../../../상시%20점검%20대장.md) §4 «바이폴라 99 - 특정자극(0x65) 경로 / 2026-07-30 / **실기 확인 완료**» |
| 0x65 는 매핑(피팅) 기능 | 명령 이름 `en__mapping_specific_stimulation` |
| `stim_para_setting` 은 라이브 경로 | 호출처 `tdc_isd_map_live.c:161`·`:549`·`:588`·`:731` + `tdc_isd_stim_standalone.c:104` |

> [!IMPORTANT]
> **`specific_stim` 이 `stim_para_setting` 보다 먼저다.**
>
> - **줄/함수가 더 나쁘다** (629 vs 196) — 분해 효용이 크다
> - **실기 검증이 된다** — 0x65 는 앱이 보내고 이미 실기로 확인한 이력이 있다
> - **폭발 반경이 작다** — 피팅 중에만 쓰이는 진단 기능이다. `stim_para_setting` 은 **일상 청취의 자극 본체**라 실패하면 소리가 안 난다
>
> 세 지표가 전부 `specific_stim` 을 가리킨다. §6 을 정정했다.

### 오류_2 - 중복 위치 줄 번호 오기

§3.1 표에서 `specific_stim` 행을 «`:~377`(default `:380`) / `:399`» 로 적었다. `grep "en__referenceNA"` · `grep "en__semi_simultaneously"` 가 낸 것은 **`switch` 줄이 아니라 그 안의 `default`/`case` 줄**인데 그대로 옮겼다.

| | 오기 | **실제** |
|---|---|---|
| 기준전극 `switch` | `:~377` | **`:368`** |
| 출력모드 `switch` | `:399` | **`:386`** |

**자산_6 의 또 다른 사례다** — «검증 도구의 실패 모드는 틀린 값이 아니라 매번 다른 방식». 이번엔 `grep` 이 **맞는 파일의 틀린 줄**을 냈다. 이 작업에서만 계량 오류가 **두 번**이다(`#if 0` 집계, 이것).

### 오류_3 (경미) - 중복 통합 감소량 과대

§6.2 가 «약 200줄 감소» 라고 적었다. 실측하면 한 쌍이 35~43줄(`specific_stim:368~402` = 35, `ecap:858~896` = 39, `stim_para:189~231` = 43)이라 5쌍 ≈ 195줄이고, 공통 함수 2개 + 호출부 5곳 ≈ 40줄이 새로 생기므로 **순감소는 약 150줄**이다.

### 미검증으로 남기는 것

| 항목 | 왜 미검증인가 |
|---|---|
| `isd/` 나머지 7파일의 죽은 코드 | 요구사항_4 는 «대상» 한정이었다. 전수를 하려면 별건 |
| `p_mapdata->stimulationMode` 가 0 이 될 수 있는가 | §3.3. 플래시 맵 데이터 생산 경로 역추적이 필요하다 |
| `#if 0` 안에 되살릴 참고 코드가 있는가 | **은수님만 판단할 수 있다.** 특히 `ecap:1334~1435`(100줄)는 통째로 죽어 있다 |

## 판정

**조건부 통과.** 오류 3건을 §정정 으로 반영한다. 정정 후 §6 착수 순서는 다음과 같다.

| 단계 | 대상 | 실기 | 비고 |
|---|---|---|---|
| **1** | 죽은 코드 제거 (264줄) | 불필요 | `#if 0` 보존 여부 은수님 확인 |
| **2** | `stimulationMode` 중복 통합 (5쌍) | 자극 1회 | **새 파일**로 떼야 호스트 게이트가 열린다 |
| **3** | `specific_stim` 분해 (605줄 단일 함수) | 0x65 1회 | **정정으로 승격** |
| **4** | `stim_para_setting` 분해 | 라이브 자극 | 폭발 반경 최대 |
| **5** | `ecap` 분해 | **불가** | 권하지 않음 |
