## 3. 치환 방법과 그 위험

기계 치환을 쓴다. 10블록을 손으로 지우면 실수한다.

> [!CAUTION]
> **자산_5 와 자산_B 를 둘 다 적용한다.**
>
> | 자산 | 대비 |
> |---|---|
> | **자산_5** «패턴에 안 맞는 것이 조용히 빠진다» | 파일별 기대 건수(2·2 / 1·1 / 2·2)를 스크립트에 못 박고 **어긋나면 중단** |
> | **자산_B** «건수는 맞는데 결과가 틀릴 수 있다» | 치환된 10줄을 **전부 출력해 눈으로 확인** |
>
> 추가로 **부분 적용을 막는다** — 3파일을 전부 검증한 뒤 한꺼번에 쓴다. 파일별로 쓰다가 2번째에서 중단하면 1번째만 바뀐 상태가 남는다.

블록 끝은 **중괄호 짝맞추기**로 찾는다. 정규식으로 `switch ... }` 를 잡으면 **중첩 스위치를 통째로 삼킨다**(`flowCounter` 스위치 안에 `stimulationMode` 스위치가 들어 있다).

## 4. 불변량

**유형: 순수 중복 통합 (동작 불변)**

| 항목 | 기대 |
|---|---|
| 기존 호스트 테스트 | **483 PASS 유지** |
| 신규 스위트 | 6개 모드 × 2함수 + 경계 |
| ARM | 에러 0 · **경고 증가 0** |
| `data` · `bss` | **불변** (새 전역 없음) |
| **`text`** | **감소해야 한다** — 같은 분기 5벌이 1벌이 된다. **늘면 무언가 잘못된 것** |
| 줄 수 | 약 150줄 순감소 |

> [!NOTE]
> **`.elf` 바이트 동일을 기대하지 않는다.** 함수 호출로 바뀌므로 코드 생성이 달라진다. 자산_1·2 의 «순수 개명·승격» 불변량은 여기 해당하지 않는다.

## 5. 실기 확인 항목

분석-검증 §누락 을 반영한다 — **`ecap` 2쌍은 실행되지 않아 실기로 확인할 수 없다.**

| 항목 | 덮는 쌍 | 확인 내용 |
|---|---|---|
| **특정자극(0x65)** | 3 | 모노폴라 · 바이폴라 자극이 정상 출력되는가 |
| **라이브 자극** | 4·5 | 일상 청취 자극이 정상인가. **바이폴라 맵으로도** 확인 |
| ~~eCAP~~ | 1·2 | **불가** — 앱이 0x63·0x64 를 안 보낸다 |

> [!IMPORTANT]
> **자극 모드별로 봐야 한다.** 이 변경은 모드 → 비트 변환을 건드렸다. 모노폴라만 확인하면 바이폴라·공통접지 분기는 검증되지 않는다. 호스트 테스트가 6개 모드를 전부 덮지만, **호스트는 «내가 만든 값» 을 볼 뿐 «내부기가 그 값을 어떻게 받는지» 는 못 본다.**
