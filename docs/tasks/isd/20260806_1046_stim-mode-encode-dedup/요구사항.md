# 요구사항 - 자극 모드 인코딩 중복 통합

**TL;DR**: `stimulationMode` → 내부기 레지스터 비트 변환이 **3파일 5쌍(스위치 10블록)** 에 복제돼 있다. 이를 **순수 함수 2개로 모으고**, 그 과정에서 **`isd/` 로직에 처음으로 호스트 테스트를 붙인다.** 동작은 한 비트도 바뀌지 않아야 한다.

## 1. 배경

[isd 대형 함수 분해 분석](../20260806_0834_isd-대형함수-분해-분석/분석.md) §6.2 가 정한 **단계_2** 다. 2026-08-06 은수님이 «단계_2 중복 통합» 을 선택했다.

분석이 이 단계를 분해(단계_3·4)보다 앞에 둔 이유가 둘이다.

| 이유 | 내용 |
|---|---|
| **선행 조건** | 중복이 남은 채 분해하면 같은 블록을 여러 함수에 **복제**하게 된다 |
| **호스트 게이트** | 뽑아낼 함수가 순수 함수라 `isd/` 의 의존 사슬에 닿지 않는다. **`isd/` 를 처음으로 호스트가 검증한다** |

## 2. 요구사항

### 요구사항_1 - 5쌍을 공통 함수로 모은다

| 파일 | 쌍 |
|---|---|
| `isd/tdc_isd_map_ecap.c` | 2 |
| `isd/tdc_isd_map_specific_stim.c` | 1 |
| `isd/tdc_isd_stim_para_setting.c` | 2 |

한 쌍은 **기준전극 2비트 + 출력모드 2비트** 두 스위치다.

### 요구사항_2 - 동작을 한 비트도 바꾸지 않는다

> [!CAUTION]
> **출력모드 스위치에는 원래 `default` 가 없었다.** 범위 밖 값이 오면 아무것도 OR 되지 않아 하위 2비트가 0으로 남아 **모노폴라처럼 동작**했다.
>
> 통합하면서 `default` 를 넣게 되는데, **그 값을 0으로 두어 원본 동작을 보존한다.** 여기서 «더 나은 값» 을 고르면 순수 통합이 아니라 동작 변경이 된다. `en__referenceNA`(0)가 실제로 도달 가능한지는 아직 미조사다([분석 §3.3](../20260806_0834_isd-대형함수-분해-분석/분석.md)).

### 요구사항_3 - 시프트는 호출부에 남긴다

`<< 2` 는 5쌍 전부 **스위치 밖**에 있다. 레지스터를 한 비트씩 쌓아 올리는 흐름이 그대로 보여야 어느 필드가 어디에 놓이는지 읽힌다. 함수는 **값만** 돌려준다.

### 요구사항_4 - 호스트 테스트로 경계를 고정한다

새 모듈은 **순수 함수만** 가져야 한다. 공유메모리·I2C·FPGA에 닿는 순간 `isd/` 의 사슬을 타서 단독 링크가 깨진다.

### 요구사항_5 - `isd/` 나머지는 건드리지 않는다

이번 작업은 통합만 한다. 함수 분해(단계_3·4)와 죽은 코드 제거(단계_1)는 별건이다.

## 3. 제약

| # | 제약 | 출처 |
|---|---|---|
| 제약_1 | 동작 불변 (요구사항_2) | 자극 경로다 |
| 제약_2 | 코드 포맷 조건 11개 | [`참고/clang-format/README.md`](../../../참고/clang-format/README.md) |
| 제약_3 | `.c`/`.h` 주석에 CP949 비호환 문자 금지 | 프로젝트 `CLAUDE.md` |
| 제약_4 | 신규 심볼 `tdc_` 접두어 | 루트 지침 §7 |
| 제약_5 | **실기 대기가 7건이 된다** | 대장 §1 알림_2 |

## 4. 완료 조건

- [ ] 스위치 10블록이 전부 호출로 바뀌고 **잔여 0**
- [ ] 새 모듈이 순수 함수만 갖는다
- [ ] 호스트 테스트가 6개 모드 × 2함수를 덮는다
- [ ] 기존 483 PASS 전부 유지
- [ ] ARM 에러 0 · **경고 증가 0**
- [ ] `text` **감소** (중복 제거이므로 늘면 이상) · `data`·`bss` 불변
