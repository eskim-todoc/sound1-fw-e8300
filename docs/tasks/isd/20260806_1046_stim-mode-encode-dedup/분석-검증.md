# 분석 검증

**TL;DR**: 3축 통과. 보완 1건 — §1.1 이 «5쌍 공통» 이라 적었지만 **`ecap` 2쌍은 실행되지 않는 코드**(eCAP 미사용)라 성격이 다르다. 통합 판단에는 영향이 없지만, 실기 확인 항목을 정할 때 갈라야 한다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 근거에 `파일:라인` | 통과 - §1 표 |
| 추측 배제 | **통과** - §2 에서 헤더 의존을 추측하지 않고 실측했다 |
| 테이블 주도 금지 | 통과 - §3.2 에 기준을 적용한 근거 |
| 과분해 금지 | 통과 - §3.1 에서 «한 함수 4비트» 를 배제한 이유가 가독성이지 취향이 아니다 |
| HW 5게이트 | 통과 - 비트 배치 불변, 불확실성(`default`)은 §3.3 에 명시 |

## 축_2 - 논리 정합성

### 정합_1 - 「5쌍이 같다」는 결론이 통합을 정당화하는가

한다. 다만 **«같다» 의 범위를 정확히 해야 한다.**

| 같은 것 | 다른 것 |
|---|---|
| 분기 구조 · 상수 · `default` 유무 · 시프트 위치 | 스위치 대상 표현식 · 주석 · 빈 줄 · 뒤따르는 코드 |

**다른 것 넷은 전부 함수 밖에 남는다.** 표현식은 인자로 넘기고, 나머지 셋은 호출부에 그대로 둔다. 따라서 통합 대상은 «같은 것» 뿐이다. 정합적이다.

### 정합_2 - §3.3 「결과가 같다」가 참인가

참이다. 원본 출력모드 스위치는 `default` 가 없어 범위 밖 값에서 **아무 대입도 일어나지 않는다.** 그 직전에 `w_isd_registerValue <<= 2` 가 하위 2비트를 0으로 만들어 두므로 결과는 `| 0` 과 같다.

**다만 «같다» 가 «옳다» 는 아니다.** 범위 밖 자극 모드가 조용히 모노폴라로 처리되는 것은 그 자체로 미심쩍다. 이 작업은 그것을 **보존**하고, 판단은 별건으로 남긴다. 그 별건의 착수 조건은 `en__referenceNA`(0) 도달 가능성 조사다.

### 정합_3 - §4 「자체 테스트 대상」 선택이 맞는가

맞다. `COMMON_SRC` 에 넣으면 `map_measure`·`map_flash`·`map_stim`·`remote` 네 스위트가 전부 이 파일을 링크한다. 쓰지도 않는 파일을 링크하는 것이고, 그 스위트들이 깨질 때 원인이 하나 늘어난다.

### 누락 - `ecap` 2쌍의 성격이 다르다

> [!WARNING]
> §1.1 은 5쌍을 «공통» 으로 묶었는데, **쌍 1·2 는 `tdc_isd_map_ecap.c` 에 있고 그 함수는 실행되지 않는다.** 2026-08-06 은수님 확인 — *"ecap 기능을 지금 실제로 사용하고 있지 않아"*.

| 쌍 | 파일 | 실행 |
|---|---|---|
| 1·2 | `map_ecap.c` | **안 됨** (앱이 0x63·0x64 미사용) |
| 3 | `map_specific_stim.c` | 0x65 특정자극 |
| 4·5 | `stim_para_setting.c` | 라이브 자극 |

**통합 판단에는 영향이 없다** — 코드가 같으므로 함께 모으는 것이 맞고, 오히려 «실행 안 되는 사본» 이 따로 남지 않아 좋다.

**영향은 실기 확인 항목에 있다.** 쌍 1·2 는 실기로 확인할 수 없으므로, 실기는 **특정자극(0x65)과 라이브 자극**만 보면 된다. 계획 §실기 항목에 반영한다.
