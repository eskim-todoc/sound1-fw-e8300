## 자산

### 자산_E - 다파일 기계 치환은 «전부 검증 후 일괄 쓰기»

자산_5(누락)·자산_B(결과 오류)에 이은 **세 번째 실패 유형**이다.

2차 시도에서 `specific_stim` 이 기대 건수에 못 미쳐 중단했는데, **그 시점에 `ecap` 은 이미 파일에 쓰여 있었다.** 파일별로 쓰면 중간 실패가 부분 적용을 남긴다.

**검증을 다 통과한 뒤에 한꺼번에 쓴다.**

### 자산_F - 정규식으로 중첩 블록의 끝을 잡을 수 없다

`switch ... { ... }` 를 정규식으로 잡으면 **바깥 스위치가 안쪽을 통째로 삼킨다.** `isd/` 는 `flowCounter` 스위치 안에 `stimulationMode` 스위치가 들어 있는 구조라 정확히 이 함정에 걸린다.

**여는 중괄호부터 짝을 세야 한다.** 주석 안의 중괄호는 건너뛴다.

### 자산_G - 헤더 의존은 추측하지 말고 컴파일해 본다

`tdc_shm.h` 가 SDK `hw.h` 를 포함해서 «호스트에선 안 되겠다» 고 넘길 뻔했다. 실제로 컴파일해 보니 **통과**했다.

추측했다면 인자를 `int` 로 낮춰 열거형 완전성 검사와 타입 안전성을 잃었을 것이다. **3줄짜리 probe 파일 하나면 확인된다.**

### 자산_H - Eclipse 생성물 등록 스크립트는 멱등해야 한다

`subdir.mk` 등록 스크립트를 다시 돌려 같은 `.o` 가 두 번 들어갔고 `multiple definition` 으로 링크가 깨졌다. **«이미 있는가» 를 먼저 확인하는 가드**를 넣어야 한다.

### 자산_I - 호스트 게이트를 여는 방법이 두 번째로 성립했다

[위험_4 조치](../../ble/20260806_0942_map-write-range-guard/이력%20및%20결과.md) 자산_D 에 이어 두 번째다. 이번엔 **`isd/` 안에서** 성립했다는 점이 다르다.

**`isd/` 를 통째로 호스트에 올릴 필요가 없다.** 검증하고 싶은 로직을 순수 함수로 떼어 새 파일에 두고 `TEST_TARGETS` 에 단독으로 넣으면 된다. 단계_3·4 분해에서도 같은 방법을 쓸 수 있다.
