# 구현 검증

**TL;DR**: 완료 조건 6개 전부 충족. 스위치 **10블록 전량** 치환·잔여 0, **165줄 순감소**(예상 150), 호스트 **483 → 514 PASS**, ARM **에러 0·경고 0**, `text` **-240B**·`data`·`bss` 불변. **`isd/` 로직에 처음으로 호스트 테스트가 붙었다.**

**165줄 순감소.** 계획 예상 150줄보다 15줄 더 줄었다(주석·빈 줄이 예상보다 많았다).

신규 모듈 `.c` 90줄 + `.h` 40줄을 더하면 전체로는 **약 35줄 감소**다. 다만 **줄 수보다 «분기가 5벌에서 1벌» 이 본질**이다.

## 5. 세 가지 대비가 실제로 작동했다

계획 §3 이 대비한 실패가 **셋 다 실제로 일어났다.**

| # | 실패 | 잡은 것 |
|---|---|---|
| 1 | 정규식이 `flowCounter` 바깥 스위치만 잡고 중첩된 대상을 삼켜 **0건** | **건수 못 박기** → 즉시 중단 |
| 2 | `specific_stim` 은 `)` 뒤에 주석이 있어 헤더~`{` 판정에서 탈락, **1건 부족** | 동 → 중단 |
| 3 | 2번 중단 시점에 **`ecap` 은 이미 쓰인 상태**였다 | 원복 후 **일괄 쓰기**로 재설계 |

> [!CAUTION]
> **3번이 새로 배운 것이다.** 자산_5(누락)·자산_B(결과 오류)는 알고 있었지만, **«검증 실패 시 앞 파일이 이미 바뀐 채로 남는»** 상황은 대비하지 않았다. 다파일 기계 치환은 **전부 검증 후 일괄 쓰기**여야 한다.

## 6. 빌드 중 겪은 것 - makefile 등록 스크립트 재실행

`ble/subdir.mk` 등록 스크립트를 **멱등하지 않게** 짜 두고 다시 돌려 `tdc_ble_map_field_range` 항목이 **두 번** 들어갔고, 링크가 `multiple definition` 으로 실패했다.

**Eclipse 생성물을 손으로 건드릴 때는 «이미 있는가» 를 먼저 봐야 한다.** 중복 3줄을 제거해 해소했다.
