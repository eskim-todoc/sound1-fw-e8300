# 요구사항 검증

**TL;DR**: 3축 통과. 보완 1건 — **요구사항_2(동작 불변)를 무엇으로 입증할지**가 빠져 있었다. 이 작업은 «5쌍이 정말 동일한가» 가 전제인데, 그 전제 자체를 검증 항목으로 넣지 않으면 다른 것을 하나로 합칠 수 있다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 8단계 | 통과 |
| 작업 폴더 (날짜 + 시각 prefix) | 통과 - `20260806_1046_` |
| **코드 전 승인** | **확보** - 2026-08-06 은수님이 선택지에서 «단계_2 중복 통합» 선택 |
| `tdc_` 접두어 | 제약_4 |
| 테이블 주도 금지 | **주의** - 모드→값 표를 배열로 만들고 싶은 유혹이 있다. 6개뿐이므로 `switch` 를 유지한다 |
| HW 5게이트 | **해당** - 레지스터 비트를 다룬다. 다만 **비트 배치를 바꾸지 않고 같은 값을 같은 자리에 넣으므로** 대상 식별·근거·전후 시뮬레이션이 «동일» 로 귀결된다. 불확실성은 요구사항_2 의 `default` 건 하나이며 명시했다 |

## 축_2 - 논리 정합성

### 정합_1 - 「동작 불변」을 무엇으로 입증하는가

> [!WARNING]
> **초안에 빠져 있었다.** 요구사항_2 는 «바꾸지 마라» 라고만 하고, **5쌍이 정말 같은지 확인하라**는 말이 없었다. 5쌍 중 하나라도 다르면 통합 자체가 결함이 된다.

**보완 - 착수 전에 5쌍을 전수 대조한다.**

| 확인 항목 | 방법 |
|---|---|
| 분기 구조 | `case` 라벨 구성이 같은가 |
| 상수 | OR 하는 값이 같은가 |
| `default` 유무 | 기준전극은 있고 출력모드는 없는가 |
| 시프트 위치 | `<< 2` 가 스위치 밖인가 |
| 뒤따르는 코드 | 쌍마다 다른 것이 있는가(`sent_stimulConfig` 등) |

**뒤따르는 코드는 호출부에 남긴다.** 함수 안으로 끌어들이면 쌍마다 달라 통합이 깨진다.

### 정합_2 - 요구사항_3(시프트 호출부)과 요구사항_1(중복 제거)이 충돌하지 않는가

충돌하지 않는다. 중복인 것은 **스위치 본문**이고 시프트는 한 줄이다. 시프트까지 함수로 넣으면 «값을 만드는 함수» 가 «레지스터를 조작하는 함수» 가 되어 순수성이 깨지고, 요구사항_4(호스트 단독 링크)가 무너진다.

### 정합_3 - 요구사항_4(순수 함수)가 달성 가능한가

가능하다. 입력은 `EN___STIMULATION_MODE` 하나, 출력은 `int` 다. 다만 **그 열거형이 `cfx_link/tdc_shm.h` 에 있고 그 헤더가 SDK `hw.h` 를 끌어온다.** 호스트에서 컴파일되는지 **착수 전에 실측해야 한다** — 안 되면 인자 타입을 `int` 로 낮춰야 하고, 그러면 타입 안전성을 잃는다.

| 출력모드에 `default` 없음 | [분석 §3.3](../20260806_0834_isd-대형함수-분해-분석/분석.md) |
