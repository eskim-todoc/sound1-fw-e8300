# 요구사항 검증

**TL;DR**: 3축 통과. 완료조건에 **«실기 대기가 늘지 않는다»** 를 넣은 것이 이번 요구사항의 핵심이다 — 코드를 지우는 변경인데도 그렇게 걸 수 있는 이유가 요구사항_3 에 있다.

## 축_2 - 논리 정합성

### 정합_1 - 지표 대조를 배제한 판단이 맞는가

맞다. `metrics.sh` 는 `^[[:space:]]*if \(` 같은 행 앵커로 세므로 **`#if 0` 안의 줄도 센다**. 죽은 코드를 지우면 지표가 줄어드는 것이 정상이고, 줄어든 크기가 «맞는지» 를 판정할 기준이 없다.

**대신 살아 있는 줄 대조가 더 강하다.** 지표는 «분기 수가 같은가» 를 보지만, 살아 있는 줄 대조는 «코드가 같은가» 를 본다.

### 정합_2 - 「실기 불필요」를 완료 조건에 걸어도 되는가

걸어도 된다. **단, 요구사항_3 을 통과했을 때만이다.** 순서가 중요하다.

1. 살아 있는 줄이 같다 → 소스가 같다
2. `.text` 차이가 `__LINE__` 뿐이다 → 바이너리가 같다
3. 그러므로 실기가 볼 것이 없다

**2를 건너뛰고 1만으로 «실기 불필요» 를 주장하면 안 된다.** 컴파일러가 같은 소스에서 다른 코드를 낼 이유는 없지만, 그것을 확인하는 비용이 낮으므로 확인한다.

### 정합_3 - 조건부 `#if` 를 남기는 것이 맞는가

맞다. `#ifdef DisalbedBackTel` 같은 것은 **빌드 설정에 따라 살아난다**. 지금 컴파일되지 않는다고 죽은 코드가 아니다.
