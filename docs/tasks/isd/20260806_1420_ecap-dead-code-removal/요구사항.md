# 요구사항 - ecap 죽은 코드 제거

**TL;DR**: `tdc_isd_map_ecap.c` 의 **컴파일되지 않는 235줄**과 그 지시자를 걷어낸다. 살아 있는 코드는 한 글자도 바뀌면 안 되고, 그것을 **바이트 수준으로 증명**한다.

## 1. 배경

[분해 분석](../20260806_0834_isd-대형함수-분해-분석/분석.md) §6.1 의 **단계_1**. 분석이 1순위로 두면서도 «`#if 0` 안에 되살릴 참고 코드가 있는지는 은수님만 판단할 수 있다» 며 보류했다.

2026-08-06 은수님 — *"ecap 죽은 코드 제거해."* **ecap 만 지시했다.**

## 2. 요구사항

### 요구사항_1 - 컴파일되지 않는 것만 지운다

| 형태 | 처리 |
|---|---|
| `#if 0 ... #endif` | 블록 전체 삭제 |
| `#if 0 ... #else ... #endif` | 앞 가지 삭제, 뒷 가지만 남기고 지시자 삭제 |
| `#if 1 ... #else ... #endif` | 뒷 가지 삭제, 앞 가지만 남기고 지시자 삭제 |
| `#if 1 ... #endif` | 지시자만 삭제 |
| **조건부 `#if`/`#ifdef`** | **건드리지 않는다** - 빌드 설정에 따라 갈린다 |

### 요구사항_2 - 살아 있는 줄 불변을 증명한다

**지표 대조로는 안 된다.** `metrics.sh` 는 원시 줄을 세므로 죽은 구역의 분기도 세고 있다. 제거하면 당연히 줄어들어 «변했다» 만 나오고 그 이상을 못 본다.

**살아 있는 줄만 뽑아 전후를 직접 대조한다.**

### 요구사항_3 - `.text` 차이를 바이트까지 설명한다

> [!CAUTION]
> **자산_1**: «바이트 동일 주장은 `cmp -l` 전수 비교. 디스어셈블리에서 즉치 하나 찾은 것으로는 부족하다.»
>
> 크기가 같아도 내용이 다를 수 있다. 다른 바이트가 **몇 개이고 각각 무엇인지** 대야 한다.

### 요구사항_4 - ecap 만 한다

다른 파일의 `#if 0` 도 남아 있지만 **보존 여부는 파일마다 은수님 판단**이다. 지시받은 것만 한다.

## 3. 제약

| # | 제약 |
|---|---|
| 제약_1 | 살아 있는 코드 무변경 |
| 제약_2 | 조건부 `#if` 는 유지 |
| 제약_3 | 파일 구조(함수 경계)는 건드리지 않는다 |

## 4. 완료 조건

- [ ] `ecap` 의 죽은 줄이 **0** 이 된다
- [ ] 살아 있는 줄이 전후 **완전 일치**
- [ ] `.text` 차이가 **바이트 단위로 설명**된다
- [ ] ARM 에러 0 · 경고 증가 0
- [ ] 호스트 514 PASS 유지
- [ ] **실기 대기가 늘지 않는다** (바이트 등가를 증명했다면)
