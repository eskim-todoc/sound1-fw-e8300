# 계획

**TL;DR**: 스크립트가 지우고 **자기 검증(살아 있는 줄 대조)을 내장**해 어긋나면 파일을 쓰지 않는다. 그 뒤 `.text` 를 바이트 비교한다. **불변량이 통과하면 실기 대기를 늘리지 않는다.**

## 1. 절차

| 단계 | 내용 | 실패 시 |
|---|---|---|
| 1 | 원본 사본 저장 | - |
| 2 | 스크립트 실행 - 죽은 구역 삭제 | - |
| 3 | **스크립트 내부에서 살아 있는 줄 대조** | **파일을 쓰지 않고 중단** |
| 4 | ARM 빌드 | - |
| 5 | 원본 되돌려 빌드 → `.text` 추출 (**타임스탬프 갱신**) | - |
| 6 | 제거본 복원 → 빌드 → `.text` 추출 | - |
| 7 | `cmp -l` 전수 비교 → **차이를 `__LINE__` 로 설명** | 설명 안 되면 되돌린다 |
| 8 | 호스트 회귀 | - |

> [!IMPORTANT]
> **3단계가 스크립트 안에 있는 것이 핵심이다.** 검증을 사람이 따로 돌리게 두면 잊는다. 대조가 어긋나면 파일 자체가 안 써진다.

## 2. 불변량

**유형: 죽은 코드 제거 (살아 있는 코드 보존)**

| 항목 | 기대 |
|---|---|
| **살아 있는 줄** | **전후 완전 일치** (가장 강한 조건) |
| 죽은 줄 | 235 → **0** |
| `text`·`data`·`bss` **크기** | **전부 불변** |
| **`.text` 바이트** | **밀린 `__LINE__` 즉치만 다르다.** 그 외 1바이트라도 다르면 실패 |
| 구조 지표 | **줄어든다** (분석 §2 - 이 작업에는 쓰지 않는다) |
| 호스트 | 514 PASS 유지 |

## 3. `__LINE__` 사전 분류 (분석-검증 보완)

첫 제거 지점은 **395줄**이다.

| 살아 있는 `__LINE__` | 위치 | 판정 |
|---|---|---|
| 68 · 218 · 361 · 373 | 395 앞 | **안 밀림** |
| 1244 · 1260 | 395 뒤 | **밀림** |

**예상 차이 바이트: 2개 이하.** (각 즉치의 하위바이트가 우연히 같으면 더 적다)

## 4. 실기 판단

> [!IMPORTANT]
> **불변량을 통과하면 실기 대기를 늘리지 않는다.**
>
> 근거 사슬이 셋이다.
> 1. 살아 있는 줄이 같다 → **소스가 같다**
> 2. `.text` 차이가 `__LINE__` 뿐이다 → **바이너리가 같다**
> 3. 바뀐 것은 앱에 보내는 오류 보고의 줄 번호뿐 → **동작이 같다**
>
> **2를 건너뛰고 1만으로 주장하면 안 된다.** 확인 비용이 낮으므로 확인한다.

## 5. 위험

| 위험 | 완화 |
|---|---|
| 산 가지를 잘못 지움 | 3단계 자기 검증 |
| 지시자만 지우고 내용이 어긋남 | 동 |
| 컴파일러가 다른 코드를 냄 | 7단계 바이트 비교 |
| 원본 재빌드가 실제로 안 됨 | **자산_Q** - `LastWriteTime` 갱신 |
