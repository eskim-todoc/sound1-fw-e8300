# 구현 검증

**TL;DR**: 완료 조건 6개 전부 충족. **살아 있는 줄 1,188개 완전 일치**, `.text` 186,516바이트 중 **다른 바이트 2개**이고 둘 다 예측한 `__LINE__` 이다. **실기 대기가 늘지 않는다.**

## 1. 완료 조건

| # | 조건 | 결과 |
|---|---|---|
| 1 | 죽은 줄 0 | **충족** - 235 → **0** |
| 2 | 살아 있는 줄 완전 일치 | **충족** - 1,188개 |
| 3 | `.text` 차이를 바이트로 설명 | **충족** - §3 |
| 4 | ARM 에러 0 · 경고 증가 0 | **충족** |
| 5 | 호스트 514 PASS | **충족** |
| 6 | 실기 대기 불변 | **충족** - §4 |

## 2. 제거 결과

| 항목 | 전 | 후 |
|---|---|---|
| 줄 수 | 1,455 | **1,188** (-267) |
| 죽은 줄 | 235 (16.2%) | **0** |
| 전처리기 조건 분기 | 10곳 | **0** |

267 = 죽은 줄 235 + 지시자 32.

## 3. `.text` 바이트 전수 비교

```
before 186,516 바이트 / after 186,516 바이트
cmp -l 결과: 다른 바이트 2개
  오프셋 48963  220 -> 65
  오프셋 49045  236 -> 81
```

계획 §3 이 **«2개 이하»** 를 예측했고 정확히 2개다. 각각을 짚으면 이렇다.

| 원본 줄 | 제거본 | 16진 | 하위바이트 | `cmp` 관측 |
|---|---|---|---|---|
| 68 · 218 · 361 · 373 | 그대로 | - | 동일 | (차이 없음) |
| **1244** | **1089** | `0x4DC` → `0x441` | 220 → 65 | **오프셋 48963** |
| **1260** | **1105** | `0x4EC` → `0x451` | 236 → 81 | **오프셋 49045** |

상위바이트(`0x04`)가 둘 다 같아 즉치당 1바이트씩만 달라졌다.

> [!IMPORTANT]
> **395줄 앞의 `__LINE__` 4개가 안 밀린 것이 제거 범위가 의도대로였다는 방증이다.** 만약 앞쪽 것도 밀렸다면 첫 제거 지점보다 위를 건드렸다는 뜻이다.

**나머지 186,514바이트는 완전히 동일하다.**

## 4. 실기 판단 - 대기가 늘지 않는다

계획 §4 의 3단 사슬이 전부 성립했다.

| 단 | 근거 |
|---|---|
| 1 | 살아 있는 줄 1,188개 완전 일치 → **소스가 같다** |
| 2 | `.text` 차이가 `__LINE__` 2바이트뿐 → **바이너리가 같다** |
| 3 | 바뀐 것은 앱에 보내는 오류 보고의 줄 번호(1244→1089, 1260→1105) → **동작이 같다** |

**코드를 267줄 지웠는데 실기 대기가 11건 그대로다.**

> [!NOTE]
> **`metrics.sh` 가 죽은 구역의 분기도 세고 있었기 때문이다.** 도구의 결함이 아니라 용도의 문제다 - 지표는 «함수 추출로 분기가 보존됐는가» 를 보는 자이고, 죽은 코드 제거는 애초에 분기를 줄이는 작업이다.
>
> **다음 사람이 «분기가 사라졌다» 고 오해하지 않도록 남긴다.** 사라진 분기는 전부 컴파일되지 않던 것이다.

## 6. 남은 것

`ecap` 은 완료. 다른 파일의 죽은 코드는 **파일마다 은수님 판단**이라 손대지 않았다.

| 파일 | 죽은 줄 |
|---|---|
| **`map_live`** | **145 (15.9%)** - `HoldOn` 재분해를 막고 있다 |
| `tdc_isd_init` | 61 |
| `map_impedance` | 46 |
| `tdc_isd.c` | 36 |
| 그 외 4파일 | 10~22 |

> [!CAUTION]
> **다른 파일에 같은 작업을 한다면 전제 하나가 깨진다.** ecap 은 `TDC_PRINTF` 가 0건이라 소스에 보이는 `__LINE__` 6개가 전부였다. `map_live` 등은 `TDC_PRINTF` 를 쓰므로 **매크로 안에 숨은 `__LINE__`**(자산_1)까지 세어야 하고, 그만큼 `.text` 차이가 커진다.
