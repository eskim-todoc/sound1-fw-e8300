# 요구사항 - specific_stim 분해

**TL;DR**: `tdc_isd_map_specific_stim_step()` **576줄 단일 함수**를 flowCounter 상태별로 나눈다. 동작은 한 줄도 바뀌지 않아야 하고, 그것을 **구조 지표 불변**으로 입증한다.

## 1. 배경

[분해 분석](../20260806_0834_isd-대형함수-분해-분석/분석.md) §6.3 의 **단계_3**. 선행 단계_2(중복 통합)는 [`20260806_1046`](../20260806_1046_stim-mode-encode-dedup/) 에서 끝났다.

2026-08-06 은수님 — *"분해할거 다 분해하고 작성할거 다 작성하고 실기는 마지막에 몰아서 하자. ... 같은 선상에서 비슷한 맥락으로 할게 있으면 알아서 해봐."*

## 2. 요구사항

### 요구사항_1 - flowCounter 상태별로 나눈다

각 `case` 본문을 함수로 뺀다. 디스패처에는 **상태 표만** 남긴다.

### 요구사항_2 - `switch` 밖 블록도 함께 나눈다

> [!CAUTION]
> `switch` 밖에 **124줄 블록**(`if (flowCounter > cofigureDoneCounter)`)이 있다. **자산_5 가 기록한 «기계 추출이 놓치는 예외» 의 네 번째 유형**이다. `case` 만 보고 작업하면 통째로 남는다.

### 요구사항_3 - 함수-지역 `static` 을 파일 범위로 승격

함수를 나누면 상태 사이로 값을 넘길 수 없다. 승격이 유일한 방법이고, **단일 인스턴스 성질이 같아 안전**하다(자산_4).

### 요구사항_4 - 동작 불변을 지표로 입증

`tests/metrics.sh` 로 **분기 총수 보존**을 확인한다. 지표가 변하면 **왜 그 크기만큼인지** 설명할 수 있어야 한다.

### 요구사항_5 - 과분해하지 않는다

4줄 위임을 함수로 빼지 않는다. 다만 **같은 코드가 두 case 에 있으면 합친다**.

## 3. 제약

| # | 제약 |
|---|---|
| 제약_1 | 동작 불변 (자극 경로다) |
| 제약_2 | 코드 포맷 조건 11개 · CP949 금지 문자 |
| 제약_3 | `tdc_` 접두어 · 계층이 드러나는 이름 |
| 제약_4 | `#if 0` 블록은 **건드리지 않는다** (제거는 단계_1, 별건) |
| 제약_5 | 실기 대기가 8건이 된다 |
