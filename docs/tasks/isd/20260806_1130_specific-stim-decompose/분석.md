# 분석

**TL;DR**: `flowCounter` 상태는 **8개 + `switch` 밖 출력 구간**이다. 함수-지역 `static` **15개**가 상태 사이로 값을 나르며, 그중 어느 것도 한 상태에 갇혀 있지 않아 **전부 승격**해야 한다. `case 5`·`case 7` 은 **경계값만 다른 같은 코드**다.

## 1. 함수 구조 실측

`tdc_isd_map_specific_stim_step()` `:26~600` (576줄)

| 구간 | 줄 범위 | 크기 | 내용 |
|---|---|---|---|
| 머리 | 26~78 | 53 | 변수 선언 + `startFlag` 리셋 |
| `case 0` | 82~171 | **90** | 프레임 수 · 전하량 검사 · **DAC 설정 계산** · 유지시간 |
| `case 1` | 173~216 | 44 | 펄스폭 최소화 · 8비트 백텔 · 바이폴라 아니면 +6 점프 |
| `case 3` | 218~278 | 61 | 바이폴라 기준전극 버퍼 구성 + FIFO 클리어 |
| `case 5` | 280~305 | 26 | 기준전극 전송 0~23 |
| `case 7` | 307~334 | 28 | 기준전극 전송 24~31 |
| `case 9` | 336~401 | **66** | 자극 파라미터 레지스터 전송 |
| `case 14` | 403~426 | 24 | 펄스폭 검증 → `cofigureDoneCounter` 확정 |
| `case 20` | 428~468 | 41 | 설정 요약 로그 |
| `default` | 470~471 | 2 | |
| **`switch` 밖** | **474~597** | **124** | 자극 출력 (유지시간 도래 / 계속) |
| 꼬리 | 599 | 1 | `flowCounter++` |

> [!CAUTION]
> **`switch` 밖 124줄이 이 파일에서 두 번째로 큰 덩어리다.** `case` 만 보고 분해하면 통째로 남는다. 자산_5 가 기록한 유형(이월_F 경계 4건 · 이월_2 0x40 · ecap 275줄)의 **네 번째**다.

## 2. static 의존 지도

15개 전부가 **두 상태 이상**에 걸쳐 있다.

| static | 쓰는 곳 | 읽는 곳 |
|---|---|---|
| `flowCounter` | 머리 · `case 1` · 꼬리 | 디스패처 · `case 14` · 출력 게이트 |
| `stimulationTime_msec` | 머리 · 출력 | 출력 게이트 |
| `stimulationHoldTime_msec` | `case 0` | 출력 게이트 · `case 20` |
| `cofigureDoneCounter` | `case 14` | 출력 게이트 |
| `numFramePerChannel` | `case 0` | 출력 · `case 20` |
| `TransferabelChannelNum` | `case 0` | 출력 · `case 20` |
| `stimulDAC_slope` · `_offsetResolution` · `_offsetValue` | `case 0` | `case 9` · `case 20` |
| `stimulLevel_255` | `case 0` | 출력 · `case 20` |
| `bipolarReferenceElectrodeNum[32]` | `case 3` | `case 5` · `case 7` · `case 20` |
| `channel_index` | 머리 · 출력 | 출력 |
| `pulseDurationNop_idex` | 출력 | 출력 |
| `bipolarFIFO_index` | `case 9` · 출력 | (디버깅용) |
| `mappingPacket` | `case 0` | 거의 전부 |

**한 상태에 갇힌 것이 하나도 없다.** 전부 승격 대상이다.

## 3. `case 5` · `case 7` 은 같은 코드다

| | `case 5` | `case 7` |
|---|---|---|
| 루프 | `for (i = 0; i < df_MaxNumTransferableChannel; i++)` | `for (i = df_MaxNumTransferableChannel; i < df_MaxNumOfElectrode; i++)` |
| 본문 | 동일 | 동일 |
| 뒤처리 | 동일 (NOP 채움 + 출력 모드 전환) | 동일 |

**경계값 두 개만 다르다.** `_send_reference_range(first, last)` 하나로 합친다. 둘이 이어 붙어 0~31 전체를 빈틈·겹침 없이 덮는다는 관계도 호출부에서 눈에 보이게 된다.

> [!NOTE]
> 합치면 `for` 지표가 **4 → 2** 로 준다. 요구사항-검증 정합_1 이 허용한 «설명 가능한 변화» 다.

## 4. `pcm_index` 처리

부모가 `= 0` 으로 두고 `switch` 와 그 뒤 블록이 이어 쓴다.

| 대상 | 처리 | 근거 |
|---|---|---|
| flow 함수 | 각자 `= 0` 선언 | 부모가 `switch` 앞에서 0으로 두고 **한 호출에 한 case 만** 실행된다. 모든 case 는 0에서 시작한다 |
| 출력 함수 2개 | **인자로 받음** | `switch` 가 남긴 값을 이어받는다 |

출력 구간은 `cofigureDoneCounter`(초기 100, `case 14` 에서 확정) 를 넘어야 도는데, 그때 flowCounter 는 14를 넘어 `case 20` 외에는 매칭되는 case 가 없다. **따라서 실질적으로 늘 0** 이지만, 그 추론에 기대지 않고 넘긴다.

## 5. 분해 경계

| 함수 | 근거 |
|---|---|
| `_calc_dac_setting()` | `case 0`(90줄) 안에서 **DAC 설정만 60줄**. 자족적 계산이라 분리 가치가 있다 |
| `_flow00` ~ `_flow20` | 상태 하나 = 함수 하나 |
| `_send_reference_range()` | §3 |
| `_wait_cfx_idle()` | 출력 채움 안의 **CFX 동기화 22줄**. 관심사가 다르다 |
| `_output_finish()` · `_output_fill()` | `switch` 밖 블록의 두 갈래 |

**`default` 는 함수로 빼지 않는다** — `break` 한 줄이다(과분해 금지).
