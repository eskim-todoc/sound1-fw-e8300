# 요구사항 검증

**TL;DR**: 3축 통과. 보완 1건 — 요구사항_4 가 «지표 불변» 을 요구했지만 **분해가 지표를 바꿀 수 있는 정당한 경우**(중복 병합)를 배제하지 않았다. 「불변 또는 설명 가능」으로 고쳤다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 8단계 · 작업 폴더 규약 | 통과 |
| **코드 전 승인** | **확보** - 2026-08-06 은수님이 단계_3·4 진행과 후속 재량을 명시적으로 위임 |
| 과분해 금지 | 요구사항_5 |
| 테이블 주도 금지 | 해당 없음 - 상태 표는 `switch` 로 유지 |
| HW 5게이트 | **해당 없음** - 레지스터 값·순서를 바꾸지 않고 코드를 옮기기만 한다 |

## 축_2 - 논리 정합성

### 정합_1 - 「지표 불변」이 항상 옳은가

> [!WARNING]
> **아니다.** 요구사항_5 가 «같은 코드가 두 case 에 있으면 합친다» 고 했는데, 합치면 **분기 수가 줄어든다.** 요구사항_4 의 «불변» 과 정면으로 부딪친다.

**보완**: 기준을 «불변» 이 아니라 **«불변 또는 크기까지 설명 가능»** 으로 둔다. 지표가 변했을 때 «의도했다» 로 넘기지 않고 **정확히 몇이 왜 줄었는지** 대야 한다.

### 정합_2 - static 승격이 정말 안전한가

안전하다. 근거가 셋이다.

| 근거 | 내용 |
|---|---|
| 저장 위치 | 함수-지역·파일 범위 `static` 둘 다 `.bss` |
| 초기화 | 둘 다 프로그램 시작 시 1회 |
| 인스턴스 수 | 둘 다 1개 |

**`bss` 크기 불변으로 사후 확인 가능**하다. 완료 조건에 넣었다.

### 정합_3 - 제약_4(`#if 0` 유지)가 분해와 충돌하지 않는가

부분적으로 충돌한다. `#if 0` 안에서 쓰는 변수(`w_FPGA_registerValue`)가 함수 밖에 선언돼 있어, 함수를 나누면 그 선언이 어느 함수로 갈지 정해야 한다.

**해소**: 선언을 `#if 0` **블록 안으로** 옮긴다. 되살릴 때 그대로 동작하고, 지금은 컴파일되지 않아 무해하다. 부수적으로 미사용 변수 경고가 하나 줄어든다.
