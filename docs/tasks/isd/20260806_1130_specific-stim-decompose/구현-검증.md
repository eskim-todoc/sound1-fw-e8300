# 구현 검증

**TL;DR**: 완료 조건 6개 충족. 구조 지표는 계획이 못 박은 대로 **`for` 정확히 -2, 나머지 0**. 호스트 514 PASS 유지, ARM 에러 0·경고 0, **`data`·`bss` 불변**. 다만 **지표 대조 과정에서 도구 자체의 결함을 찾아 함께 고쳤다.**

## 1. 완료 조건 대조

| # | 조건 | 결과 |
|---|---|---|
| 1 | 디스패처가 상태 표만 | **충족** - 88줄, 각 case 가 호출 한 줄 |
| 2 | `switch` 밖 블록도 분해 | **충족** - `_output_finish` · `_output_fill` · `_wait_cfx_idle` |

| 6 | `data`·`bss` 불변 | **충족** - 4,664 / 21,804 그대로 |

## 2. 구조 지표

계획-검증 정합_1 이 **«`for` 정확히 -2, 나머지 정확히 0»** 을 못 박았다.

| 지표 | 전 | 후 | 판정 |
|---|---|---|---|
| `case` | 8 | 8 | 불변 |
| `switch` | 1 | 1 | 불변 |
| `default` | 1 | 1 | 불변 |
| `if` | 22 | 22 | 불변 |
| `else` | 8 | 8 | 불변 |
| **`for`** | **13** | **11** | **-2** (예상대로) |
| `or` | 3 | 3 | 불변 |
| `and` | 0 | 0 | 불변 |

### 2.1 도구가 처음엔 -1 을 보고했다

첫 대조에서 `for` **12 → 11 (-1)** 이 나왔다. 예상은 -2 였으므로 원인을 팠다.

**원본 `:587` 이 `for(;pcm_index...` 로 `for` 뒤에 공백이 없었다.** `tests/metrics.sh` 의 패턴이 `^[[:space:]]*for \(` 라 이 줄을 세지 못했고, 새로 쓴 코드는 공백이 있어 세어져 감소분 하나를 상쇄했다.

**도구를 고쳤다** — `if`·`for`·`while`·`switch` 패턴을 `[[:space:]]*\(` 로 바꿔 `for(` 형태도 센다. 고친 뒤 재측정하니 **13 → 11** 로 정확히 나온다.

> [!CAUTION]
> **«변했지만 의도한 것» 으로 넘겼다면 도구 결함을 못 찾았다.** 계획-검증이 크기까지 못 박아 둔 덕에 -1 과 -2 의 차이가 드러났다.
>
> 자산_6(«검증 도구의 실패 모드는 매번 다른 방식»)의 새 형태다. 이번엔 **소스의 포맷 불일치가 도구를 새게 했다.**

## 3. ARM 빌드

| 항목 | 전 | 후 |
|---|---|---|
| `error:` | 0 | **0** |
| `warning:` | 0 | **0** |
| `text` | 186,360 | **186,484** (+124B) |
| `data` | 4,664 | **4,664** |
| `bss` | 21,804 | **21,804** |

**+124B 는 함수 호출 11개의 오버헤드**다. 계획이 «수백 바이트면 정합» 이라 했으므로 범위 안이다.

**`bss` 불변이 static 승격의 증거다** — 함수-지역과 파일 범위 `static` 이 같은 섹션에 같은 크기로 놓였다.
