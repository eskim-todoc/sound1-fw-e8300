# 분석 검증

**TL;DR**: 3축 통과. 보완 1건 — §2 가 «전부 승격» 이라 결론냈지만 **비-static 지역변수는 어떻게 되는지**를 안 다뤘다. 그쪽이 오히려 실수하기 쉽다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 근거에 `파일:라인` | 통과 - §1 표 |
| 과분해 금지 | 통과 - §5 에서 `default` 를 뺀 근거 |
| 자산 적용 | 통과 - 자산_4(승격) · 자산_5(`switch` 밖) |

## 축_2 - 논리 정합성

### 정합_1 - 「한 상태에 갇힌 static 이 없다」가 「전부 승격」을 정당화하는가

한다. 함수-지역 `static` 은 **그 함수 안에서만 보이는 전역**이므로, 값을 넘겨야 하는 상대가 다른 함수가 되는 순간 접근이 끊긴다. §2 표가 15개 모두 그렇다고 보였다.

### 누락 - 비-static 지역변수는 어떻게 되는가

> [!WARNING]
> §2 는 `static` 만 다뤘다. **`w_isd_registerValue`·`pcm_index`·`i`·`r_FPGA_registerValue`·`deliveryCharge_pico`·`tempInt` 등은 `static` 이 아니다.** 이들을 잘못 처리하면 조용히 깨진다.

**보완 - 성격이 둘로 갈린다.**

| 종류 | 처리 | 예 |
|---|---|---|
| 한 case 안에서만 나고 죽는 것 | **그 함수의 지역변수로** | `w_isd_registerValue` · `i` · `deliveryCharge_pico` · `tempInt` · `r_FPGA_registerValue` |
| case 와 그 뒤 블록에 걸치는 것 | **인자로 전달** | `pcm_index` (§4) |

`w_FPGA_registerValue` 는 **`#if 0` 안에서만** 쓰인다. 선언을 그 블록 안으로 옮긴다(요구사항-검증 정합_3).

`bufferForSPI_tx`·`buffer_tx_index` 는 출력 종료 갈래에서만 쓰이므로 그 함수의 지역으로 간다.

### 정합_2 - §3 병합이 동작을 바꾸지 않는가

바꾸지 않는다. `_send_reference_range(0, N)` 과 `_send_reference_range(N, 32)` 는 원본 두 루프와 **범위가 정확히 같다**. 본문·뒤처리도 동일하다.

**다만 한 가지 확인이 필요했다** — 두 case 가 각각 NOP 채움과 출력 모드 전환을 **따로** 했다. 합친 함수도 호출마다 그것을 하므로 동일하다. (한 번만 하도록 바꿨다면 동작이 달라졌을 것이다.)

### 정합_3 - §4 「실질적으로 늘 0」인데 굳이 넘기는가

넘긴다. **추론이 맞아도 코드가 그 추론에 의존하는 것은 다른 문제다.** `cofigureDoneCounter` 를 누가 언제 바꾸느냐가 달라지면 전제가 무너진다. 인자 하나로 그 걱정을 없앤다.

## 축_3 - 근거 검증

| 주장 | 확인 |
|---|---|
| 구간 줄 범위 | **실측** |
| static 15개와 사용처 | **코드 전수** |
| `case 5`·`case 7` 동일성 | **코드 대조** |
| 출력 구간 진입 조건 | **코드 확인** - `cofigureDoneCounter` 초기 100, `case 14` 에서 확정 |
