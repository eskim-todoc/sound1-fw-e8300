## 4. 예측 빗나감의 원인 - 자산_1 이 틀렸다

계획 §3 이 «적게 나와도 넘기지 않는다. 첫 수순은 `tdc_printf.h` 확인» 이라고 정해 뒀다. 그대로 했다.

> [!CAUTION]
> **자산_1 의 «모든 `TDC_PRINTF_*` 호출이 `__LINE__` 을 품는다» 는 틀렸다.**

`util/tdc_printf.h` 실측.

| 매크로 | 정의 | `__LINE__` |
|---|---|---|
| **`TDC_PRINTF_E`** `:35~37` | `tdc_printf_file_func_line(__SHORT_FILE__, __func__, __LINE__);` + `SEGGER_RTT_printf(...)` | **품는다** |
| `TDC_PRINTF_W` `:43` | `SEGGER_RTT_printf(...)` | 없다 |
| `TDC_PRINTF_I` `:49` | 동 | 없다 |
| `TDC_PRINTF_D` `:55` | 동 | 없다 |
| `TDC_PRINTF_V` `:61` | 동 | 없다 |

밀린 운반체 11개 중 **3개가 `TDC_PRINTF_I`·`_V`** 여서 바이트를 안 바꿨다.

진짜 운반체(명시 `__LINE__` + `TDC_PRINTF_E`)만 세니 **9개, 그중 밀린 것 8개 → 8바이트**로 정확히 맞았다.

**자산을 고쳤다** — [인수인계 문서](../../../세션_인수인계/20260806_0752_ble-이월-전량소진-검증방법정립.md) 자산_1.

> [!IMPORTANT]
> **«적게 나왔으니 다행» 으로 넘겼다면 틀린 모델을 계속 썼다.** 다음 사람이 `grep -c "TDC_PRINTF_"` 로 세어 과대 예측하고, 그 차이를 설명 못 해 시간을 버렸을 것이다.

## 5. 부수 성과 - `HoldOn` 285 → 143줄

계획 §4 가 «150줄 이하면 추가 분해 불필요» 를 미리 정해 뒀다. **143줄이므로 불필요하다.**

| live 의 함수 | 줄 |
|---|---|
| `sub_hold_on` | **143** |
| `sub_read_equalizer` | 101 |
| `sub_start` | 95 |
| 나머지 7개 | 27~57 |

[impedance·live 분해](../20260806_1330_impedance-live-decompose/분석.md) §2.2 에서 «죽은 코드를 지운 뒤 재검토» 로 미뤄 둔 건이 **«안 해도 되는 것» 으로 결론났다.**

> [!NOTE]
> **순서를 지킨 덕이다.** 먼저 나눴다면 죽은 코드를 담은 함수 둘이 생겼고, 그 뒤 죽은 코드를 지우면 껍데기만 남은 함수를 다시 합쳐야 했다.
