# 계획

**TL;DR**: ecap 절차에 **디스어셈블 단계**를 더한다. 예측치는 **12바이트**이고, **빗나가면 자산_1 부터 의심**한다.

## 1. 절차

| 단계 | 내용 |
|---|---|
| 1 | 원본 사본 · 지표 기준선 |
| 2 | 스크립트 실행 (**살아 있는 줄 대조 내장**) |
| 3 | 밀린 `__LINE__` 을 **미리 계산**해 예측치 확정 |
| 4 | ARM 빌드 |
| 5 | 원본 되돌려 빌드 → `.text` 추출 (**타임스탬프 갱신**) |
| 6 | 제거본 복원 → 빌드 → `.text` 추출 |
| 7 | `cmp -l` 전수 비교 |
| **8** | **차이 주소를 디스어셈블해 명령어 확인** |
| 9 | 호스트 회귀 |

## 2. 예측치

| 항목 | 예측 |
|---|---|
| 삭제 줄 | 155 (죽은 145 + 지시자 10) |
| 죽은 줄 | 145 → **0** |
| `text`·`data`·`bss` **크기** | **전부 불변** |
| **`.text` 바이트 차이** | **12개** (하위 11 + 상위 1) |
| 호스트 | 514 PASS |

## 3. 예측이 빗나가면 (분석-검증 보완)

> [!IMPORTANT]
> **적게 나와도 넘기지 않는다.** 원인이 둘이고 성격이 정반대다.
>
> | 원인 | 뜻 | 확인 |
> |---|---|---|
> | 예측이 과했다 | **모델이 틀렸다** | **`tdc_printf.h` 를 직접 읽는다** |
> | 실제로 안 바뀐 곳이 있다 | 다행 | 디스어셈블로 확인 |

**첫 수순은 `tdc_printf.h` 확인이다.** §2 예측이 자산_1 의 «모든 `TDC_PRINTF_*` 가 `__LINE__` 을 품는다» 에 의존하고, **그 자산이 검증 없이 인용됐기 때문**이다.

자산이 틀렸다면 **자산 자체를 고친다.** 다음 사람이 같은 오예측을 하지 않도록.

## 4. `HoldOn` 판단

제거 후 크기를 실측하고 정한다.

| 크기 | 판단 |
|---|---|
| 150줄 이하 | 다른 함수와 비슷 → **추가 분해 불필요** |
| 200줄 이상 | 분해 검토 (별건) |

## 5. 실기

불변량을 통과하면 **대기를 늘리지 않는다.** ecap 과 같은 3단 사슬이다.
