# 요구사항 검증

**TL;DR**: 3축 통과. 보완 1건 — 요구사항_5 가 «심볼 1:1 대응» 을 요구했는데 **무엇과 무엇을 대조하는지**가 없었다. 분해 후 심볼만 봐서는 원본에 무엇이 있었는지 모른다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 8단계 · 폴더 규약 | 통과 |
| **코드 전 승인** | **확보** - 2026-08-06 은수님이 단계_3·4 와 후속 재량을 위임 |
| HW 5게이트 | **해당 없음** - 레지스터 값·순서를 바꾸지 않고 코드를 옮긴다 |
| 과분해 금지 | case 단위가 기준. `default` 는 빼지 않는다 |

## 축_2 - 논리 정합성

### 정합_1 - 요구사항_3(합침)과 요구사항_5(불변)가 부딪히지 않는가

부딪힌다. 합치면 `for` 가 준다. 단계_3 에서 정한 기준을 그대로 쓴다 — **«불변 또는 크기까지 설명 가능»**.

### 정합_2 - 요구사항_4(기계 추출)가 안전한가

**손으로 하는 것보다 안전하다.** 본문을 원문 그대로 옮기므로 오전사가 원천적으로 없다. 대신 다른 위험이 생긴다.

| 기계 추출의 위험 | 대비 |
|---|---|
| 블록 경계를 잘못 잡음 | 중괄호 짝맞추기 + case 집합이 기대와 다르면 중단 |
| 필요한 지역변수 누락 | 블록이 참조하는 이름만 골라 선언. **누락되면 컴파일이 깨진다** |
| 잘못된 것을 합침 | 요구사항_3 의 해시 대조 |

**컴파일러가 마지막 방어**다 — 변수를 빠뜨리면 빌드가 실패한다.

### 정합_3 - 「text 감소」가 이번에도 기준이 되는가

된다. 중복 8블록을 합치므로 방향이 정해져 있다. 다만 **함수 호출 오버헤드가 16개 늘어** 상쇄가 있으므로, 감소폭 자체는 예측하지 않는다.

### 누락 - 심볼 대조의 상대가 없다

> [!WARNING]
> 요구사항_5 는 «심볼이 1:1 대응» 을 요구했는데, **분해 후 `.elf` 만 보면 원본에 무엇이 있었는지 알 수 없다.**

**보완 - 원본으로 되돌려 한 번 더 빌드하고 심볼 목록을 뽑아 대조한다.** 원본의 함수-지역 static 은 `이름.N` 형태로 맹글링돼 있어 이름만으로도 대응을 확인할 수 있다.

## 축_3 - 근거 검증
