# 이력 및 결과 - stim_para_setting 분해 (단계_4)

**TL;DR**: 자극 본체 두 상태 기계(**모노폴라 320줄 · 바이폴라 708줄**)를 case 별 **16함수**로 나눴다. 중복 8블록을 인자화해 합쳐 **`text` -540B**. **1,111줄을 손으로 옮기지 않고 기계로 추출**했고, 구조 지표가 **예측치와 정확히 일치**해 그것을 뒷받침한다.

## 배경

[분해 분석](../20260806_0834_isd-대형함수-분해-분석/분석.md) §6.4 의 **단계_4**. 분석이 «자극 본체 · 최고 위험» 으로 분류한 대상이다.

## 자산

### 자산_M - «비슷해 보인다» 를 md5 로 확인하라

`bi` 의 `case 14·16·18·20·22·24` 가 **전부 29줄**이어서 여섯이 같아 보였다. **다섯만 같았고 `case 24` 는 달랐다** (루프 상한 6 vs 2).

여섯을 인자 없이 합쳤다면 마지막 두 전극(30·31)의 기준전극 읽기가 6회로 늘어 **FIFO 를 넘겨 읽는다.** 자극 본체에서 조용히 깨졌을 것이다.

**본문 md5 로 대조했더니 즉시 갈렸다.** 줄 수가 같다는 것은 근거가 아니다.

### 자산_N - 유사도 대조로 병합 후보를 찾되, 80~95% 는 대개 «합치면 안 되는 것»

전체 case 를 `difflib` 로 대조해 80% 이상 쌍을 뽑았다. 결과가 갈렸다.

| 쌍 | 유사도 | 판정 |
|---|---|---|
| `bi:14`~`bi:22` | **완전 동일** | 병합 |
| `bi:24` | 95% (루프 상한만) | 병합 (인자화) |
| `bi:8` ↔ `bi:10` | 92% (전극 범위만) | 병합 (인자화) |
| `mono:10` ↔ `bi:35` | 95% | **병합 불가** - `tdc_isd_fpga_disable_backtel()` 한 줄이 더 있다 |
| `mono:14` ↔ `bi:39` | 85% | **병합 불가** - 에러 로그와 `else` 분기가 다르다 |

**«거의 같다» 가 «같다» 는 아니다.** 유사도는 **후보를 좁히는 도구**이고, 판단은 diff 를 눈으로 봐야 한다.

### 자산_O - 같은 이름의 독립 static 은 승격 시 반드시 갈라야 한다

두 함수가 **각자의** `flowControlCounter`·`tempCounter`·`sent_stimulConfig`·`p_mapdata`·`p_stimulDAC_setting` 을 갖고 있었다. 함수-지역 `static` 이라 이름이 같아도 별개다.

**그대로 파일 범위로 올리면 하나로 합쳐져 두 상태 기계가 서로를 밟는다.** 모노폴라 설정 중에 바이폴라 카운터가 움직이는 식이다.

`s_mono_` · `s_bi_` 접두어로 갈랐다. **심볼 대조에서 13:13 로 1:1 대응**함을 확인했다.

### 자산_P - 1,000줄 넘는 재구성은 기계로

`specific_stim`(576줄)은 손으로 썼지만 이건 **1,111줄에 case 22개**다. 손으로 옮기면 오전사가 반드시 난다.

**본문은 원문 그대로 옮기고 껍데기만 생성**하는 스크립트를 썼다. 스크립트가 한 일은 넷이다.

1. case 블록을 중괄호 짝맞추기로 잘라낸다
2. 블록이 참조하는 지역변수만 골라 그 함수에 선언한다
3. `static` 이름에 접두어를 붙인다
4. case 집합이 기대와 다르면 **중단**한다

**검증은 구조 지표가 했다** — `for` -12(병합 산술 그대로) · `return` +16(신규 함수 수) · 나머지 전부 불변.

### 자산_Q - `Copy-Item` 은 타임스탬프를 보존한다 (make 가 속는다)

`bss` -4 를 추적하려고 원본을 되돌려 빌드했는데 **크기가 그대로 나왔다.** PowerShell `Copy-Item` 이 원본의 `LastWriteTime` 을 함께 복사해 make 가 «최신» 으로 판단하고 재컴파일을 건너뛴 것이다.

```powershell
Copy-Item $src $dst -Force
(Get-Item $dst).LastWriteTime = Get-Date   # <- 이게 없으면 make 가 속는다
```

**«빌드했는데 안 바뀌었다» 는 결론을 내리기 전에 정말 컴파일됐는지 봐야 한다.**

### 자산_R - `bss` 미세 변화는 정렬 패딩일 수 있다

승격 후 `bss` 가 **-4** 였다. static 승격은 중립이어야 하므로 추적했고, **심볼 13개가 1:1 로 대응**함을 확인했다(합계 300바이트 동일).

원인은 `-fdata-sections` 로 각 static 이 자기 섹션을 갖는데, **선언 순서가 바뀌며 섹션 간 정렬 패딩이 달라진 것**이다. 데이터 손실이 아니다.

**심볼 집합을 대조하지 않고 «4바이트니까 괜찮겠지» 로 넘기면 안 된다.** 진짜로 하나가 사라졌어도 같은 크기로 보인다.
