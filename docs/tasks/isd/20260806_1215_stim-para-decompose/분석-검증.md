# 분석 검증

**TL;DR**: 3축 통과. 보완 1건 — §4 가 «`pcm_index` 는 `switch` 뒤에 쓰는 곳이 없다» 고 단정했는데, **그것을 확인한 근거**를 적지 않았다. 단계_3 에서는 반대였으므로 확인이 필요하다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 근거에 실측 | 통과 - md5 · 유사도 · 심볼 |
| 추측 배제 | **통과** - «여섯이 같아 보인다» 를 해시로 확인해 하나가 다름을 찾았다 |
| 과분해 금지 | 통과 - §2.2 에서 플래그 인자 병합을 **거부**한 근거가 가독성이다 |

## 축_2 - 논리 정합성

### 정합_1 - 병합 판정 기준이 일관되는가

일관된다. 기준은 **«인자로 흡수했을 때 호출부에서 의미가 보이는가»** 다.

| 병합한 것 | 인자 | 호출부에서 보이는가 |
|---|---|---|
| `read_reference_burst(count)` | 개수 | **보인다** - `(6)` 다섯 번, `(2)` 한 번. 6×5+2=32 가 드러난다 |
| `send_reference_range(first, last)` | 구간 | **보인다** - 두 호출이 0~24, 24~32 로 이어짐이 드러난다 |
| 거부한 것 | `bool disableBacktel` | **안 보인다** - 참/거짓이 무엇을 뜻하는지 호출부에 없다 |

### 정합_2 - §3 의 static 분리가 충분한가

충분하다. 다만 **사후 확인이 필요하다** - 접두어를 붙였다고 정말 갈렸는지는 심볼로 봐야 한다. 요구사항-검증의 보완(원본 대조)이 그것을 맡는다.

### 누락 - `pcm_index` 단정의 근거

> [!WARNING]
> §4 가 «`switch` 뒤에 쓰는 곳이 없다» 고 단정했다. **단계_3(`specific_stim`)에서는 정반대였다** - `switch` 밖 블록이 `pcm_index` 를 이어 썼다. 같은 모듈이라도 다르다.

**보완 - 확인했다.** 두 함수의 `switch` 뒤에는 `flowControlCounter++` 와 (bi 만) 에러 시 카운터 리셋뿐이고 `pcm_index` 참조가 없다. 그래서 각 함수가 자기 것을 선언해도 된다.

**단정하기 전에 봐야 한다.** 앞 작업에서 그랬다는 것은 근거가 아니다.
