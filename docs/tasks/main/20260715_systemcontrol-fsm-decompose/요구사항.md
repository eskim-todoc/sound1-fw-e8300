# 요구사항 — systemControl() FSM 분해

**TL;DR**: `systemControl()` 281줄 / `static` 10개의 암묵 상태머신을 **동작을 보존한 채** 명시적 FSM 구조로 분해한다. 상태를 구조체로 드러내고, 충전기 축을 최상위로 단계를 분리하며, 죽은 코드를 제거한다. 실기 검증 수단이 없으므로 동작 변경은 범위 밖.

---

## 1. 배경

은수님 지시(2026-07-15):

> `tdc_normal_iteration()` 함수의 내용을 보면 사실상 각 정보를 취득한다 -> `systemControl()`이 상태를 점검 한다 -> `isd_interface()` 사용 여부가 결정된다 -> ... 이런 구조잖아. 이게 결국 event_collect -> handler 의 단계를 거치는 건데, 이 구조를 좀 더 깔끔하고 불필요한 과정은 생략하고, 안 쓰이는건 없애는 방향으로 개선이 될까? 함수 인자만 변경한다기 보다는 순서와 과정, 내용을 비롯해서 전체 구조를 개혁할 생각도 가지고 있어.

범위를 A / B / C 로 나눠 A · B 는 완료(`a96b589`, 빌드 · 실기 확인). 본 작업은 **C — `systemControl()` 내부 분해**다.

추가 지시:

> 네가 안전하다고 하는 방향으로 해볼게. 다만, 할건 다 해야한다는건 잊지 말자.

즉 안전한 순서(문서 선행)를 따르되, C 를 생략하지 않는다.

## 3. 요구사항

### 요구사항_1 — 상태를 구조체로 드러낸다

흩어진 `static` 10개를 성격별로 묶어 명시적 상태 구조체로 만든다. 지금은 함수 본문 어디서든 접근 가능해 "누가 언제 바꾸는지" 추적이 어렵다.

**수용 기준**: 함수 본문에 나체 `static` 지역 상태가 남지 않는다. 각 상태의 소유 단계가 이름으로 드러난다.

### 요구사항_2 — 충전기 축으로 단계를 분리한다

최상위 분기는 충전기 상태(`df_Connected` / `df_Disconnected` / 재연결)다. 이 축으로 핸들러를 나눠 각 단계가 독립적으로 읽히게 한다.

**수용 기준**: 최대 중첩 깊이가 현재의 절반 이하. 각 핸들러는 자기 단계의 상태만 만진다.

### 요구사항_3 — 안 쓰이는 것을 제거한다

죽은 변수 · 죽은 분기를 찾아 제거한다. A 단계에서 `Led_Pattern` 계통을 걷어냈듯, 남은 것을 마저 정리한다.

**수용 기준**: 제거 대상은 각각 "사용처 0" 근거(`파일:라인`)를 제시한다. 추측 제거 금지.

### 요구사항_4 — 동작을 보존한다 (대전제)

FSM 분해는 **구조 변경만** 한다. 판정 결과 · 타이밍 · 부수효과(LED 요청 · PMIC · 로그)가 바뀌면 안 된다.

**수용 기준**: 분기 경로별 전후 등가를 정적으로 대조한다. 동작 변경이 불가피하면 별도 항목으로 분리해 승인을 받는다.

## 6. 성공 판정

1. `systemControl()` 본문이 충전기 축 기준으로 분리되고, 각 핸들러가 자기 상태만 소유한다.
2. 제거된 코드는 전부 "사용처 0" 근거를 갖는다.
3. 분기 경로별 동작 등가가 정적으로 대조된다.
4. 은수님 Eclipse 빌드 통과 + 실기 동작 확인.
