## 축_2 — 논리 정합성

### 결함_1 (발견 · 반영 필요) — `veryLowBattery` 소비처 누락

`분석.md §9 위험` 은 `veryLowBattery` / `stimulationTrigger` 를 "핸들러 시그니처에 명시"하라고만 했다. 실측하니 **`veryLowBattery` 는 파워오프 핸들러 내부(`:308`)에서도 읽힌다**.

| 라인 | 사용 | 소속 (§7.2 분해 기준) |
|---|---|---|
| `:260`, `:264` | 쓰기 | `systemControl()` 잔여 (배터리 판정) |
| `:268` | 읽기 | `systemControl()` 잔여 (파워오프 트리거) |
| `:272` | 읽기 | `systemControl()` 잔여 |
| **`:308`** | **읽기** | **`tdc_sysctl_handle_poweroff()` 내부** |

즉 `tdc_sysctl_handle_poweroff()` 는 `veryLowBattery` 를 **입력으로 받아야** 한다. §7.2 표에 시그니처가 없어 누락 위험이 있다.

**반영**: ⑤ 계획에서 각 핸들러의 **완전한 시그니처**를 확정한다.

### 결함_2 (발견 · 반영 필요) — `stimulationTrigger` 는 출력

`stimulationTrigger` 는 `:332`(`tdc_sysctl_handle_running()` 내부)에서 쓰이고 `:408`(`systemControl()` 잔여)에서 출력에 반영된다. 즉 **핸들러가 값을 만들어 호출자에게 돌려줘야** 한다.

**반영**: `tdc_sysctl_handle_running()` 이 `bool` 반환(자극 트리거 발생 여부) 또는 `bool *out` 파라미터를 갖도록 ⑤ 에서 확정.

### 정합 확인 (통과 항목)

| 빈 `else`(`:376~378`) 제거가 분기 의미 변경? | 없음 — 본문이 비어 `df_Defalut` 시 no-op. 제거해도 no-op |

## 축_3 — 근거 검증 (실증)

### 실증_1 — dead 3개가 정말 dead 인가

`static` **지역**변수이므로 함수 밖 접근이 원천 불가하지만, 동명 심볼이 다른 곳에 있을 가능성을 배제하기 위해 전 프로젝트 grep.

| 변수 | 프로젝트 전체 출현 | 내역 | 판정 |
|---|---|---|---|
| `PowerOn_StartCounter` | 4회 | `systemControl.c` 내부만 (선언 1 · 주석 1 · 쓰기 2) | ✅ dead 확정 |
| `normalModeCounter` | 3회 | `systemControl.c` 내부만 (선언 1 · 쓰기 2) | ✅ dead 확정 |
| `CounterAfterCoverClosed` | 4회 | `systemControl.c` 내부만 (선언 1 · 쓰기 3) | ✅ dead 확정 |

**함수 밖 접근 0건. `분석.md §3.1` dead 판정 실증 통과.**

### 실증_2 — `ISD_Disconnection_counter` 초기값 (결함 발견)

`분석.md §9` 이 "0 이 아님 주의"라고만 했다. 실측:

```
src/2__cm3/processorDirective.h:115:#define Df_Disconnection_BLE_Time_ms 2000
```

**초기값 = 2000.** 구조체 도입 시 이 값을 반드시 승계해야 한다. `tdc_sysctl_state_t` 를 zero-init 하면 **0 으로 시작해 동작이 바뀐다** — `:248` 의 `ISD_Disconnection_counter < 300` 판정이 부팅 직후 참이 되어 전원버튼이 무시된다(현재는 2000 이라 거짓).

> [!CAUTION]
> **회귀 위험 1순위.** ⑤ 계획에서 초기화 방식을 명시하고, ⑧ 검증에서 초기값 2000 승계를 확인해야 한다.

### 실증_3 — `powerButtonPushed` 지역 수정 전파

| 라인 | 동작 |
|---|---|
| `:134` | 파라미터 (값 전달) |
| `:246`, `:253` | **지역 수정** (`= false`) |
| `:268`, `:277` | 수정된 값을 읽음 |

즉 게이트(`:241~254`)가 끈 버튼 상태를 **이후 파워오프 트리거(`:268`)가 본다**. 핸들러로 분리하면 값 전달로는 전파되지 않으므로 **반환값 재대입**이 필수. `분석.md §9` 의 완화책("게이트 핸들러는 값을 반환")이 **실증으로 타당함 확인**.
