# 계획 — systemControl() FSM 분해

**TL;DR**: 5단계 순차 구현(dead 제거 → 상태 구조체 → 핸들러 3개 추출 → 조립 → 이름 정정). 각 단계는 독립 검증 가능하고 앞 단계 통과를 전제한다. **회귀 1순위는 `ISD_Disconnection_counter` 초기값 2000 승계** — zero-init 하면 부팅 직후 전원버튼이 무시되는 회귀가 난다.

---

## 1. 분석 검증에서 위임받은 3건 반영

| 위임 | 반영 위치 |
|---|---|
| 핸들러 완전 시그니처 | §3 (전 핸들러 시그니처 확정) |
| `ISD_Disconnection_counter = 2000` 승계 | §2.2 (초기화 명시) · §6 (검증 라벨_2) |
| 검증 라벨 명시 | §6 |

## 2. 단계 구성

계층 분해는 **유닛 → 모듈 → 시스템** 순, 의존성은 **테스트 순서**로 표현한다(루트 `CLAUDE.md §7`).

### 2.1 단계_1 — dead 제거 (선행 없음)

| 대상 | 조치 | 근거 |
|---|---|---|
| `PowerOn_StartCounter` | 선언 `:138` · 쓰기 `:223`/`:363` 삭제 | 읽기 0 (`분석-검증.md` 실증_1) |
| `normalModeCounter` | 선언 `:140` · 쓰기 `:237~238` 삭제 | 읽기 0 |
| `CounterAfterCoverClosed` | 선언 `:141` · 쓰기 `:183`/`:192`/`:200` 삭제 | 읽기 0 |
| 빈 `else` `:376~378` | 블록 삭제 | 본문 없음 |
| `:220` 주석 | "`StartFlag` · `PowerOn_StartCounter` 정리 위임" 문구 갱신 | 위임 이행됨. `StartFlag` 는 dead 아님(주석이 부정확했음) |

**독립 검증 가능**: 이 단계만으로 빌드 통과 + 동작 불변이어야 한다.

### 2.2 단계_2 — 상태 구조체 도입 (단계_1 통과 전제)

```c
/* systemControl 전용 상태. 단계별 소유를 이름으로 드러낸다.
 * 파일 static 1개로 모아 함수 본문의 나체 static 지역변수를 없앤다. */
typedef struct
{
    bool start_flag;              /* 부팅 첫 진입 완료 */
    bool cradle_cover_closed_edge;/* 크래들 뚜껑 닫힘 엣지 (1회성) */
    bool poweroff_enabled;        /* 파워오프 시퀀스 진행 중 */
    int  poweroff_start_counter;  /* burst 종료 검출용 */
    int  isd_disconnection_counter;
    int  low_batt_indicator_counter;
    int  prev_carrying_case_state;
} tdc_sysctl_state_t;

static tdc_sysctl_state_t s_sysctl = {
    .start_flag                 = false,
    .cradle_cover_closed_edge   = false,
    .poweroff_enabled           = false,
    .poweroff_start_counter     = 0,
    .isd_disconnection_counter  = Df_Disconnection_BLE_Time_ms,  /* = 2000. zero-init 금지 */
    .low_batt_indicator_counter = 0,
    .prev_carrying_case_state   = df_Defalut,
};
```

> [!CAUTION]
> **`isd_disconnection_counter` 초기값 2000 승계 필수.** 0 으로 시작하면 `:248` 의 `< 300` 판정이 부팅 직후 참이 되어 **전원버튼이 무시되는 회귀**가 발생한다 (`분석-검증.md` 실증_2).

원본 초기값 대조표:

| 원본 | 초기값 | 신규 필드 | 승계 |
|---|---|---|---|
| `StartFlag` `:147` | `false` | `start_flag` | ✅ |
| `s_tdc_cradle_cover_closed_edge` `:142` | `false` | `cradle_cover_closed_edge` | ✅ |
| `isPowerOffEnabled` `:148` | `false` | `poweroff_enabled` | ✅ |
| `PowerOff_StartCounter` `:139` | `0` | `poweroff_start_counter` | ✅ |
| `ISD_Disconnection_counter` `:143` | **`Df_Disconnection_BLE_Time_ms` (2000)** | `isd_disconnection_counter` | ⚠️ **명시 승계** |
| `lowBatteryIndicatorCounter` `:144` | `0` | `low_batt_indicator_counter` | ✅ |
| `prev_batteryChargerConnectionStatus` `:145` | `df_Defalut` | `prev_carrying_case_state` | ✅ |

**독립 검증 가능**: 구조체 전환만으로 빌드 통과 + 초기값 7개 전수 일치.

### 2.3 단계_3 — 핸들러 추출 (단계_2 통과 전제)

§3 시그니처대로 3개 추출. 각 핸들러는 자기 상태만 만진다.

### 2.4 단계_4 — 조립 (단계_3 통과 전제)

`systemControl()` 잔여를 축 분기 + 조립으로 정리.

### 2.5 단계_5 — 이름 정정 (단계_4 통과 전제)

`prev_batteryChargerConnectionStatus` → `prev_carrying_case_state` (단계_2 에서 이미 반영되므로 실질은 §5 질의 결과 처리).

## 3. 핸들러 시그니처 (확정)

분석 검증 결함_1 · 결함_2 반영.

### 3.1 `tdc_sysctl_handle_error()`

```c
/* 에러 발생 시 ERROR 소스 LED 요청. 원본 :384~405 */
static void tdc_sysctl_handle_error(ST__ERROR_CODE mcu_error);
```

- 입력: `mcu_error`
- 출력: 없음 (부수효과 = `led_request`)
- 상태: 없음

### 3.2 `tdc_sysctl_gate_power_button()`

```c
/* 매핑 연결 중 또는 ISD 최근 연결(<300) 시 전원버튼을 무시한다.
 * 반환: 게이팅 후의 버튼 상태. 호출자가 재대입해야 이후 판정에 전파된다.
 * 원본 :241~254 */
static bool tdc_sysctl_gate_power_button(bool power_button_pushed, bool mapping_connected);
```

- **반환값 필수** (`분석-검증.md` 실증_3 — `:246`/`:253` 의 지역 수정이 `:268` 로 전파됨)
- 상태: `s_sysctl.isd_disconnection_counter` 읽기 (`:248`)

### 3.3 `tdc_sysctl_handle_poweroff()`

```c
/* 파워오프 시퀀스 진행 / 탈출 판정. 원본 :291~318
 * very_low_battery : :308 탈출 조건에서 읽는다 (분석-검증 결함_1)
 * conneded_ISD     : :310 탈출 조건
 * out_state        : enablePMIC / systemOff 반영 대상 */
static void tdc_sysctl_handle_poweroff(bool very_low_battery, bool conneded_ISD, ST__SYSTEM_STATE *out_state);
```

- 상태: `s_sysctl.poweroff_enabled` / `poweroff_start_counter` / `isd_disconnection_counter` 쓰기

### 3.4 `tdc_sysctl_handle_running()`

```c
/* 정상 운영: 저배터리 자극 알림 / ISD 카운터 / 3분 타임아웃. 원본 :319~360
 * 반환: 자극 트리거 발생 여부 (호출자가 stimulationTrigger 에 반영, 분석-검증 결함_2) */
static bool tdc_sysctl_handle_running(int battery_percent, bool conneded_ISD, ST__SYSTEM_STATE *out_state);
```

- **반환값 = `stimulationTrigger`** (`:332` → `:408`)
- 상태: `s_sysctl.low_batt_indicator_counter` / `isd_disconnection_counter` / `poweroff_enabled` / `poweroff_start_counter` 쓰기

### 3.5 `tdc_sysctl_handle_charging()`

```c
/* 충전기 연결 시 처리 (크래들 뚜껑 엣지 감지 포함). 원본 :171~207 */
static void tdc_sysctl_handle_charging(ST__USB_CONNECTOR charger, bool power_button_pushed, ST__SYSTEM_STATE *out_state);
```

- 상태: `s_sysctl.cradle_cover_closed_edge` 읽기/쓰기, `s_sysctl.start_flag` 쓰기(`:207`)

## 4. 테스트 순서 (의존성)

의존성은 "A 는 B 통과 전제"로 표현한다.

```mermaid
flowchart LR
    T1["단계_1<br/>dead 제거"] --> T2["단계_2<br/>상태 구조체"]
    T2 --> T3["단계_3<br/>핸들러 추출"]
    T3 --> T4["단계_4<br/>조립"]
    T4 --> T5["단계_5<br/>이름 정정"]
```

| 순서 | 단계 | 전제 | 검증 수단 |
|---|---|---|---|
| 1 | dead 제거 | 없음 | 정적: 제거 심볼 잔존 0 / 빌드: 경고 감소 |
| 2 | 상태 구조체 | 단계_1 | 정적: 초기값 7개 대조표 일치 |
| 3 | 핸들러 추출 | 단계_2 | 정적: 분기 경로별 전후 등가 대조 |
| 4 | 조립 | 단계_3 | 정적: 호출 순서 · 반환 전파 확인 |
| 5 | 이름 정정 | 단계_4 | 정적: rename 잔존 0 |

**커밋 단위**: 단계별 1커밋(총 5). 회귀 시 이분 탐색이 가능하도록 한다.

## 5. 은수님 질의 (⑦ 진입 전 답변 필요)

### 질의_1 — `:367` 의 의도 (`분석.md §8 질문_1`)

```c
else  // 충전기가 꼽혔다가 빠진 상태.
{
    if (prev_batteryChargerConnectionStatus == df_Disconnected)  // 실제로는 carryingCase 값
    {
        systemStatus.enablePMIC = false;
        systemStatus.systemOff  = true;
    }
}
```

- **가능성_1 (의도대로)**: 캐리잉 케이스 상태로 판정하는 게 맞다 → 이름만 정정, 동작 보존
- **가능성_2 (버그)**: 충전기 상태를 보려 했으나 `carryingCase` 를 담아버림 → 동작 변경 필요

**기본 방침**: 가능성_1 로 간주(동작 보존). 가능성_2 라면 **별도 작업**으로 분리한다 — 구조 변경과 동작 변경을 섞으면 회귀 원인 분리가 불가능해지기 때문(`요구사항.md §4`).
