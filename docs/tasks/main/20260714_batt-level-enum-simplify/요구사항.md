# 요구사항: 배터리 레벨 enum 단순화 분석

**TL;DR**: 배터리 percent(QCC 제공)를 7단계 `EN__BATTERY_LEVEL`로 이산화하는 `snd_batt_get_level()`이 실제로 `systemControl()` 외에 쓰이는지(특히 **BLE 패킷 전송**), 그리고 `systemControl()` 내부의 enum 비교(<40% 저전력·<20% ISD가드)를 배터리 percent 직접 비교로 대체할 수 있는지 분석한다. 불필요하면 어떻게 걷어낼지(enum·getter·고아 전역 처리) 개선 방향까지 도출. 분석까지 수행, 계획·구현은 은수님 결정 후.

## 1. 사용자 요청 (원문)

> "snd_batt_get_level();을 통해 EN__BATTERY_LEVEL 정보를 얻어 오는데, 이건 실제로 systemControl() 외에는 사용되는 곳이 없지? systemControl() 내에서도 EN__BATTERY_LEVEL을 사용할 필요없이 배터리 레벨을 직접 사용해도 되지 않아? 이것에 대한 분석을 좀 해봐. 다른곳에서 사용되는게 있는지와 (특히 BLE 패킷 관련해서), 사용하지 않을 시 어떻게 개선하면 되는지 등. 서브에이전트 잘 돌려봐. 문서 정리 잘 하고."

## 2. 배경 (직접 확인)

- `snd_batt_get_level()` 정의: `batteryNPowerControl.c:47~88` — `snd_batt_get_percent()`를 7단계 `EN__BATTERY_LEVEL`로 매핑(margin-free, 20%p 그리드 0/20/40/60/80/100).
- 유일 호출처: `main.c:577` `batteryLevel = snd_batt_get_level();` → `func_normal` 지역변수 → `systemControl()`(`main.c:618`) 4번째 인자.
- `systemControl()` 시그니처: `systemControl.h:29` `EN__BATTERY_LEVEL batteryLevel`.
- 내부 소비 2곳: `systemControl.c:251~253`(0per/0btw20/20btw40 → **<40% 저전력**), `:324`(≤0btw20 → **<20%**).
- 직전 작업(배터리→LED 마진 제거)에서 `updateBatteryLevel()` 삭제로 `batteryLevelStatus`/`prev_batteryLevelStatus`(EN__BATTERY_LEVEL 전역)가 write-only 고아가 됨.

## 3. 분석 질문 (핵심)

- 질문_1: `snd_batt_get_level()`·`EN__BATTERY_LEVEL`·`en__batteryPower_*`가 **전 트리에서** 정확히 어디서 쓰이는가? `systemControl()`(+ main 전달 경로) 외 실사용 소비처가 정말 없는가?
- 질문_2: **BLE 패킷** 관련해서 배터리 레벨/percent가 전송되는가? (인바운드 QCC→E8300 0x34 수신 외에, E8300이 배터리 상태를 앱/QCC로 **송신**하는 경로가 있는가 — back-telemetry·status 패킷 등.) 송신 시 percent 형태인가 level enum 형태인가?
- 질문_3: `systemControl()`의 enum 비교(<40%·<20%)를 배터리 percent 직접 비교(`percent < 40`, `percent < 20`)로 바꾸면 **동작이 동일한가**? 경계값(20/40 포함/배제) 정합성은?
- 질문_4: enum을 안 쓰기로 하면 어떻게 개선하는가? — `systemControl()` 파라미터(EN__BATTERY_LEVEL → int percent) 변경, `main.c` 호출부(`snd_batt_get_percent()` 직접 전달), `snd_batt_get_level()`·`EN__BATTERY_LEVEL` enum·고아 전역(`batteryLevelStatus` 등)의 존치/삭제 판단.
