# 분석: 배터리 레벨 enum 단순화

**TL;DR**: `snd_batt_get_level()`(percent→7단계 `EN__BATTERY_LEVEL`)은 **`main.c:577` 단 한 곳**에서만 호출되고, 그 값은 `systemControl()`으로 pass-through되어 내부 **두 임계 비교**(`251~253` <40% 강제 전원종료·`324` <20% 저배터리 자극알림)에만 소비된다. **은수님 가설("systemControl 외 사용처 없음") 참으로 확정**(반증 검증까지 통과, 할루시네이션 0). BLE 배터리 송·수신 5경로는 **전부 raw int percent**(`snd_batt_get_percent`/`readBatteryPercentage`)를 쓰고 enum은 0건 관여 → **enum 제거 시 BLE 영향 전무**. 두 비교는 `percent<40`·`percent<20`으로 **100% 동치**(전 구간·경계 발산 0). 따라서 `systemControl()` 파라미터를 `int battery_percent`로 바꾸고(옵션 A), `snd_batt_get_level()`·enum·고아 전역·유령 선언까지 정리(옵션 B)하는 **A+B 동시 적용**을 권장한다. 이미 `batteryLevelStatus` 등은 writer까지 주석 처리된 이중 dead다.

> 3개 분석 페르소나(01 census / 02 BLE / 03 재설계) + 반증 검증(06). 상세는 [`에이전트-로그/`](에이전트-로그/).

## 1. 사용처 census (페르소나 01 + 06 독립 재검)

`EN__BATTERY_LEVEL`/`en__batteryPower_*`/`snd_batt_get_level`이 등장하는 파일은 **6개뿐**(06이 tests 포함 전 폴더 독립 grep으로 01과 100% 일치 확인, 추가 소비처 0):

| 심볼 | 위치 | 성격 |
|---|---|---|
| `EN__BATTERY_LEVEL` typedef(7단계) | `batteryNPowerControl.h:17~26` | 정의 |
| `snd_batt_get_level()` 정의 | `batteryNPowerControl.c:47~88` (선언 `.h:63`) | percent→enum 매핑(margin-free) |
| `snd_batt_get_level()` **호출** | `main.c:577` **(유일)** | 결과를 지역변수 `batteryLevel`(main.c:463)에 저장 |
| `batteryLevel` 전달 | `main.c:618`(→`systemControl` 인자) | **pass-through**(main은 비교 0건) |
| **실소비 ①** | `systemControl.c:251~253` | `0per||0btw20||20btw40` = **<40% → 강제 전원종료** |
| **실소비 ②** | `systemControl.c:324` | `≤0btw20` = **<20% → ISD 저배터리 자극알림** |
| 시그니처 파라미터 | `systemControl.h:29`, `systemControl.c:125` | `EN__BATTERY_LEVEL batteryLevel` |

**결론**: `EN__BATTERY_LEVEL` 값을 읽어 분기하는 곳은 systemControl 2곳뿐. main은 조회→전달만. **은수님 가설 참 확정.**

### 1.1 고아(dead) 사슬 — 직전 작업 후속
`updateBatteryLevel()` 삭제(선행 `20260714_battery-led-refactor`)로 다음이 이중 dead가 됨:
- `batteryLevelStatus`/`prev_batteryLevelStatus`(`batteryNPowerControl.c:221~222`, EN__BATTERY_LEVEL 전역): read 0건. write는 `calculationBatteryBoundary()`(`:230~231`)뿐인데, 그 호출 사슬 `calculationBatteryBoundary ← ci_battery_init ← initialize.c:362`가 **주석 처리**되어 write조차 미실행.
- `main.h:67` `debugging_for_monitoring()`: 정의·호출 0건 **유령 선언**이며 EN__BATTERY_LEVEL을 타입으로 참조 → enum 삭제 시 **함께 지우지 않으면 컴파일 에러**(06 확인).

## 2. BLE 패킷 조사 (페르소나 02 — 은수님 강조점)

배터리 정보가 BLE/원격 패킷에 오가는 경로 **전수**:

| 방향 | 경로 | 소스 | 형태 |
|---|---|---|---|
| 인바운드 | `0x34` Power info 수신 | `ble_communication.c:130` `snd_batt_set_percent()` | percent 대입 |
| 아웃바운드 | `0x33` 레거시 Battery 응답 | `ble_communication.c:91~117` `snd_batt_get_percent()` | raw int percent |
| 아웃바운드 | `0x43` 리모콘 외부기기 상태 | `remoteControl.c:964~989` `readBatteryPercentage()` | raw int(0~100 클램프) |
| 아웃바운드 | `0x67` 매핑 deviceStatus | `mappingControl.c:2060~2092` `readBatteryPercentage()` | raw int |
| 아웃바운드 | `0x66` liveStimulation sub7 | `isd_interface_mapping_Live.c:438~471`(internalDevice/) | raw int |

**결론**: 5경로 **전부 raw int percent**(동일 전역 `s_snd_batt_percent`). `EN__BATTERY_LEVEL`/`snd_batt_get_level()`은 BLE·원격 경로 어디에도 **0건 등장** → **enum 제거 시 BLE 코드 수정 불필요**(은수님 핵심 우려 해소). `batteryLevel_CfX_to_CM3` 공유메모리 필드는 reader(`readBatteryLevel_FromCFX`)가 코드베이스에 없어 BLE와 무관한 별개 레거시.

> [!NOTE]
> `readBatteryPercentage()`(`batteryNPowerControl.c:330`)는 BLE 아웃바운드 3경로가 쓰므로 **살아있는 함수**다(dead 아님). `snd_batt_get_percent()`도 LED·BLE 전반이 쓰므로 유지. 이번 정리 대상은 **레벨(enum) 계통만**이며 percent 계통은 건드리지 않는다.

## 3. percent 직접사용 등가성 (페르소나 03 + 06)

`snd_batt_get_level()` 경계(`batteryNPowerControl.c:47~88`): `0→0per`, `1~19→0btw20`, `20~39→20btw40`, `40~59→40btw60`, `60~79→60btw80`, `80~99→80btw100`, `100→100per`.

| 소비처 | 현재(enum) | percent 등가 | 검증(06) |
|---|---|---|---|
| `systemControl.c:251~253` | `0per‖0btw20‖20btw40` (= 0~39%) | `battery_percent < 40` | pct=0,19,20,39,40,100,255·음수 전부 동치, 발산 0 |
| `systemControl.c:324` | `≤ 0btw20` (= 0~19%) | `battery_percent < 20` | 동일하게 동치, percent==0 양쪽 정확 포함 |

**부수효과 보존(06 실측)**: `251~253` = **강제 전원종료**(POWER_OFF LED → `enablePMIC=false`+`systemOff=true`), `324` = ISD 연결 시 **10분 주기**(`df_lowbatteryIndicationPeriod_ms=600000`) 저배터리 자극알림. percent 대체로 로직·상수 그대로 보존.

**RESET 주의 해소(06)**: systemControl의 두 가드는 `chargerState==Disconnected` 분기 **안**에만 있어, `0x34` 수신 전(RESET, percent=0) 구간엔 애초 실행되지 않음 → percent=0 저전력 오판정 위험은 systemControl엔 **해당 없음**(LED 블록의 `batt_is_reset_state` 가드와는 다른 상황).

## 4. 개선 옵션

### 옵션 A — 최소(시그니처만 percent화)
- `systemControl()` 파라미터 `EN__BATTERY_LEVEL batteryLevel` → `int battery_percent`(`systemControl.h:29`·`.c:125`).
- 내부 `251~253` → `battery_percent < 40`, `324` → `battery_percent < 20`.
- `main.c:577` `snd_batt_get_level()` → 제거하고 `main.c:618`에 `snd_batt_get_percent()` 직접 전달(지역변수 `batteryLevel` 폐기 또는 `int` 재활용).
- **3파일 ~15줄, 위험 매우 낮음.** `snd_batt_get_level()`·enum·고아 전역은 그대로 둠(정리 미완).

### 옵션 B — 전체 정리(옵션 A + dead 제거)
옵션 A + 아래 **삭제 대상(06 전수 확인, 10개 사이트)**:

| 대상 | 위치 |
|---|---|
| `EN__BATTERY_LEVEL` typedef | `batteryNPowerControl.h:17~26` |
| `snd_batt_get_level()` 선언·정의 | `batteryNPowerControl.h:63`, `.c:47~88` |
| 고아 전역 `batteryLevelStatus`/`prev_batteryLevelStatus` | `batteryNPowerControl.c:221~222` (+ write `:230~231`) |
| 유령 선언 `debugging_for_monitoring` | `main.h:67` (enum 타입 참조 — 필수 삭제) |
| 지역변수 `EN__BATTERY_LEVEL batteryLevel` | `main.c:463` |
| 파라미터 타입 | `systemControl.h:29`, `.c:125` |

> [!WARNING]
> 고아 전역 삭제 시 그 write문(`batteryNPowerControl.c:230~231`, `calculationBatteryBoundary()` 본문)도 함께 제거해야 한다. `calculationBatteryBoundary()` 자체도 dead(호출 사슬 주석)라 통째 제거 후보이나, 범위가 커지므로 계획에서 삭제 경계를 확정한다(전역만 vs 함수째).

### 추천
**A+B 동시 적용** — 01·02·06이 소비처 0·BLE 영향 0·이중 dead를 모두 확정했으므로 추가 위험이 거의 없고, 배터리 계통이 "percent 단일 소스"로 통일되어 가독성·일관성이 크게 개선된다. 최소 변경만 원하면 옵션 A만으로도 은수님 질문(percent 직접사용)은 충족.

## 5. 동작 변경 여부
- **percent 등가 대체는 동작 불변**(§3, 회귀 아님). enum·getter·고아 삭제도 실행 경로에 영향 없는 순수 dead 제거.
- 유일한 실질 주의: 시그니처 변경이므로 **호출부(`main.c:618`) 동기 수정 필수**(누락 시 컴파일 에러) — 호출부는 1곳뿐이라 위험 낮음.
