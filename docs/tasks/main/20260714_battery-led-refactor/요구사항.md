# 요구사항: 배터리·LED 코드 리팩토링

**TL;DR**: `main.c` `func_normal()`이 배터리 percent(QCC 제공)로 LED 상태를 결정하는 로직이 인라인 하드코딩(히스테리시스 if-else 체인, 매직넘버)으로 흩어져 함수가 길고 지저분하다. 은수님은 (1) 과거 `updateBatteryLevel()`의 함수 캡슐화 정신을 현 QCC 구조에 맞게 되살리고, (2) 하드코딩을 함수로 분해하고, (3) QCC가 이미 측정·필터링하므로 불필요해진 **배터리 변화 마진(히스테리시스)을 제거**하기를 원한다. 본 작업은 분석·계획까지 수행하고 구현 착수 여부는 은수님이 결정한다.

## 1. 사용자 요청 (원문)

> "main.c의 func_normal()을 보면 배터리 레벨에 맞춰 LED 상태를 설정하는 코드가 있어. 매핑 연결 상태에서도 배터리 레벨에 따라 LED 상태가 설정되는 코드가 있고. 몇 가지가 마음에 안 들어.
> ① 하나는 과거에 사용했던 updateBatteryLevel() 함수를 개선해서 지금의 구조에 맞게 적용하지 못하는 게 아쉽고.
> ② 그 다음은 너무 하드 코딩 방식이라 소스코드가 func_normal()에서 길어진 상태가 마음에 안 들어.
> ③ 그 다음은 배터리 레벨의 변화 마진을 주었던 것으로 알고 있거든? 그런데 배터리 레벨은 QCC에게 입력 받을거고, 배터리 레벨에 대한 측정은 QCC가 알아서 잘 할거니까 지금처럼 변화에 대한 마진을 둘 필요가 없어.
> 위 내용을 어떻게 개선하면 좋을지, 잘 분석하고 계획을 만들어봐. 그 다음 수정할지 말지를 결정하게. 서브에이전트 잘 사용하고 문서정리 잘 해봐."

## 2. 대상 코드 (실측 확인)

| 대상 | 위치 | 현황 |
|---|---|---|
| 배터리 LED 블록 | `main.c:542~578` | `snd_batt_get_percent()` → 히스테리시스 if-else 체인(진입/이탈 임계 상이) → `led_request(LED_SRC_BATTERY, ...)` |
| 매핑 LED 블록 | `main.c:620~654` | `s_map_low_active` 래치(pct 20/22 히스테리시스) × ISD 연결 여부 4분기 |
| 과거 함수 `updateBatteryLevel()` | `batteryNPowerControl.c:336` (정의 생존) / `main.c:448` (호출 주석 처리) | 배터리 레벨→7단계 `EN__BATTERY_LEVEL` enum 매핑 + "노이즈 추세 반전 방지" 마진 로직, `readBatteryLevel_FromCFX()` **자체 측정**(현 구조는 QCC 측정으로 대체됨) |
| 현 배터리 소스 | `main.c:451` `snd_batt_get_level()`, `snd_batt_get_percent()`, `snd_batt_get_state()` | QCC가 0x34(Power info)로 percent/state 주입 → E8300은 조회만 |

## 3. 목표

- 목표_1: 배터리 percent → LED 상태 매핑 로직을 **함수로 캡슐화**해 `func_normal()`에서 인라인 하드코딩을 걷어낸다. 과거 `updateBatteryLevel()`이 가졌던 "레벨 매핑을 한 함수에 모으는" 구조적 장점을 QCC 기반 현 구조에 맞게 되살린다.
- 목표_2: 매직넘버(진입/이탈 임계값)를 의미 있는 상수 또는 데이터(테이블) 기반으로 정리해 가독성을 높인다.
- 목표_3: **배터리 변화 마진(히스테리시스) 제거** — 배터리 블록의 진입/이탈 임계 이원화(sticky band, `prev_batt_st` 의존)와 매핑 블록의 `s_map_low_active` 히스테리시스를 단일 임계 매핑으로 단순화. 근거: QCC가 배터리 레벨을 측정·필터링해 제공하므로 E8300 쪽 채터링 방지 마진이 중복.
- 목표_4: `분석.md`·`계획.md`까지 작성(자체 검토 포함) + 서브에이전트 fan-out 분석 로그. 구현(코드 변경)은 **은수님 승인 후 별도 단계**.

## 5. 작업 범위

### 5.1 범위 내 (In Scope)
- 배터리 LED 블록(`main.c:542~578`)의 함수 분해 + 마진 제거
- 매핑 LED 블록(`main.c:620~654`) 중 **배터리 레벨 기반 부분**(`s_map_low_active` 마진)의 정리
- 과거 `updateBatteryLevel()`의 구조를 참고한 신규 캡슐화 함수 설계(`tdc_` 접두어)
- 매직넘버 상수화/테이블화

### 5.2 범위 외 (Out of Scope)
- 범위외_1: `func_normal()`의 나머지 4구역(부팅·센서·시스템제어·절전전이) 분해 — 그건 선행 `20260709_func-normal-refactor` 소관. 이번은 배터리→LED 한정.
- 범위외_2: ISD LED 블록(`main.c:580~618`) 자체의 재설계 — 단, ISD 미연결 시 배터리 LED 재송출(순서 의존) 관계는 마진 제거 영향 분석에 포함.
- 범위외_3: QCC 측 배터리 측정·필터링 로직(QCC 펌웨어 소관) — E8300은 QCC 제공 값을 신뢰한다는 전제.
- 범위외_4: 레거시 `updateBatteryLevel()` 정의(`batteryNPowerControl.c`) 자체의 삭제 여부 — 분석에서 재사용/폐기 판단 후 계획에서 제안, 최종은 승인.
