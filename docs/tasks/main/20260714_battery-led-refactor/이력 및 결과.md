# 이력 및 결과: 배터리·LED 코드 리팩토링

**TL;DR**: `main.c` `func_normal()`의 배터리→LED 결정 로직을 (1) 과거 `updateBatteryLevel()`의 캡슐화 정신을 QCC 기반 구조에 맞게 되살리고, (2) 인라인 하드코딩을 함수로 분해하며, (3) QCC가 이미 측정·필터링하므로 불필요해진 배터리 변화 마진(히스테리시스)을 제거하는 방향의 분석·계획 작업. 8단계 프로세스로 진행하며 구현 착수는 은수님 승인 후.

## 시계열 로그

### 2026-07-14

- **작업 착수**: 은수님 지시 — "`main.c` `func_normal()`의 배터리 레벨→LED 설정 코드가 (1) 과거 `updateBatteryLevel()`을 현 구조에 맞게 못 살린 게 아쉽고, (2) 하드코딩이라 함수가 길고, (3) 배터리 변화 마진을 뒀는데 QCC가 배터리 레벨을 입력·측정하므로 마진이 불필요하다. 잘 분석·계획하고 수정 여부는 그다음 결정. 서브에이전트 잘 쓰고 문서 정리."
- **선행 조사 (직접)**:
  - 기존 `20260709_func-normal-refactor` 작업 발견 — `func_normal()` 5구역 **동작 보존** 분해 계획(7-Step) 완료·미구현 상태. 이번 작업은 그와 달리 **동작을 변경**(마진 제거)하므로 별도 신규 작업으로 분리(은수님 "새 작업" 명시).
  - `updateBatteryLevel()` 실체 확인: `batteryNPowerControl.c:336` 정의 **생존**, `main.c:448` 호출은 **주석 처리**. 배터리 레벨을 7단계 `EN__BATTERY_LEVEL` enum으로 매핑 + "노이즈 추세 반전 방지" 마진 로직 내장. `readBatteryLevel_FromCFX()`로 **자체 측정**(현 구조는 QCC가 측정, 이 경로가 낡음).
  - 현 구조: `main.c:451` `batteryLevel = snd_batt_get_level()` — "직접 측정 않고 QCC에서 배터리 정보 받으면 업데이트". LED 블록(538-655)은 `snd_batt_get_percent()`를 직접 재사용해 인라인 히스테리시스(40/41·65/64·20/22) 수행.
  - **미커밋 변경 발견**: `main.c` 배터리 임계값이 작업트리에서 `40/41/65/64` → `10/12/80/78`로 되돌려져 있음(주석 옛값을 실제 값으로). 은수님 WIP로 추정 — 보존하고 분석 baseline 판단에 반영, 승인 게이트에서 확인.
