# 분석: 배터리·LED 코드 리팩토링

**TL;DR**: `func_normal()`의 배터리→LED 결정은 `snd_batt_get_percent()`(QCC 제공)를 인라인 if-else 히스테리시스로 등급화한다. "변화 마진"의 코드적 정체는 **진입≠이탈 이중 임계 + `prev_batt_st`(배터리)·`s_map_low_active`(매핑) static 참조**이며, 제거하면 해당 분기와 static 변수 자체가 사라진다. 과거 `updateBatteryLevel()`은 "경계 테이블→등급" 골격에 단방향 래칫 마진을 얹은 함수로, 자체 CFX 측정 기반이라 직접 부활은 불가하고 **7단계 enum 이산화는 이미 `snd_batt_get_level()`로 포팅 완료**됐으며 정의 자체는 dead code다. QCC percent는 E8300에서 클램프·필터 없이 단순 대입되고 히스테리시스는 관찰된 노이즈 버그 수정이 아니라 최초 설계 시 방어적 관례였다 — **마진 제거는 조건부 안전(저위험, 반증 실패)**이나 QCC 송신 주기·충전기 커넥터 바운스는 실측 게이트로 확인 권고. 재캡슐화는 **옵션 B(테이블 구동)가 "updateBatteryLevel() 정신"에 최적**(전 구간 트레이스 무결함 검증), 보존 필수 5항목(override 2단·순서·`led_set_isd_conn_state()` 봉인·pct 공유·RESET→IDLE)은 옵션 무관 동일.

> 4개 분석 페르소나(01~04) + 반증 검증(06). 인용 전수 재대조 결과 **순수 할루시네이션 0건**. 상세는 [`에이전트-로그/`](에이전트-로그/) 참조.

## 1. 현 배터리→LED 데이터 흐름 (페르소나 01)

### 1.1 배터리 블록 (`main.c:542~578`)

`pct = snd_batt_get_percent()`(QCC 제공, override 시 UI 값) → 히스테리시스 if-else → `led_request(LED_SRC_BATTERY, batt_st)`.

**작업트리 실측 상태 전이표**(baseline = 미커밋 `10/12/80/78`):

| 조건 | 결과 | 근거 |
|---|---|---|
| `state == RESET` (& !override) | `LED_ST_IDLE` | `main.c:558` |
| `pct < 10` | `BATT_CRITICAL` (항상) | `main.c:563` |
| `10 ≤ pct < 12` & `prev==CRITICAL` | `BATT_CRITICAL` (유지) | `main.c:565` ← **마진** |
| `pct ≥ 80` | `BATT_READY` (항상) | `main.c:567` |
| `78 ≤ pct < 80` & `prev==READY` | `BATT_READY` (유지) | `main.c:569` ← **마진** |
| 그 외 | `BATT_MID` | `main.c:571` |

Sticky band 폭 = **2%p**(`{10,11}`, `{78,79}`). 참고: 커밋본은 `40/41/65/64`(폭 1%p) — 미커밋 변경이 옛값으로 되돌리면서 밴드가 **넓어졌다**(선행 `20260709_func-normal-refactor/에이전트-로그/04`가 커밋본 기준으로 낸 서술과 방향이 반대 — 검증 confirmed, 그 문서 결론을 그대로 적용 불가).

### 1.2 "변화 마진"의 코드적 정체

- 배터리: **진입 임계(10, 80) ≠ 이탈 임계(12, 78)** 이중화 + `prev_batt_st`(`main.c:555`) 참조 분기 2줄(`565`, `569`). 이 두 줄이 곧 마진. 제거 시 체인이 4분기(RESET/CRITICAL/READY/MID)로 축소되고 `prev_batt_st` static을 아무도 안 읽어 **변수 자체 삭제 가능**.
- 매핑(`main.c:627~631`): `s_map_low_active` 불리언 래치 — `pct<=20` LOW, `pct>=22` 해제, `pct==21` 직전 유지. 이것도 동형 마진. 제거 시 `bool low = (pct<=T)` 순수 계산으로 축소, **static 삭제 가능**.

### 1.3 순서 의존 (마진 제거와 무관, 절대 보존)

배터리(`batt_st` 산출) → ISD(`batt_st` 소비, 미연결 시 `led_request(LED_SRC_BATTERY, batt_st)` 재송출 `main.c:610`) → 매핑(`isd_conn` 소비, `642/646`). `led_set_isd_conn_state()`(`main.c:616`)는 ISD `led_request` 확정 뒤에 위치해야 1-tick IN_USE(백색) 잔상 race를 막는다(`LedOutput.c:87,709,725` ISR 재검증).

## 2. 과거 `updateBatteryLevel()` (페르소나 02)

- **구조**(`batteryNPowerControl.c:336~`): 100회 주기 throttle + 충전/방전 비대칭 분기 + 최초1회 부트스트랩 + 충전/방전 별도 전압경계(`batteryBoundary`)로 7단계 `EN__BATTERY_LEVEL` 산출.
- **마진 = 단방향 래칫**: `prev_batteryLevelStatus` 비교로 방전 중엔 레벨 증가 금지·충전 중엔 감소 금지. 은수님이 말한 "변화 마진"과 동일 개념(구현 형태만 다름). ⚠️ 검증에서 충전 0% 하한(`c:501~504`)은 무조건 대입이라 래칫에 구멍이 있음(단 dead code라 실무 영향 0).
- **직접 부활 불가**: 입력이 `readBatteryLevel_FromCFX()` = E8300 자체 LSAD 전압측정. 현 구조는 QCC가 percent 주입 → 단위·경로 호환 불가. 공유메모리 필드도 이미 미사용 확정(`shared_memory.h`).
- **포팅 가치**: (a) 함수 캡슐화 정신 = 포팅 대상(목표_1). (b) 7단계 enum 이산화 = **이미 `snd_batt_get_level()`로 포팅 완료**(중복 주의). (c) 래칫/마진 = 목표_3에 따라 **포팅 금지**.
- **Dead code**: 호출자는 `main.c:448`(주석)뿐, `readBatteryPercentage()`도 QCC 값으로 우회 패치됨. ⚠️ 정정(검증): 준비 경로 `ci_battery_init()`도 `initialize.c:362`에서 **주석 처리**돼 미실행 — dead chain이 한 단계 더 깊음. `updateBatteryLevel()` 정의·선언은 삭제 후보(범위외_4, 승인 필요).

## 3. QCC 소스 신뢰성 · 마진 제거 안전성 (페르소나 03 + 검증)

- **주입 경로**: QCC → SPI `0x34`(Power info) → `ble_communication.c:130` `snd_batt_set_percent(battery_level)`. E8300 쪽 **클램프·필터 전무**(`batteryNPowerControl.c:42~45` 단순 대입). 수신은 **이벤트 구동**(SPI 도착 시), QCC 실제 송신 주기는 **코드상 확인 불가**.
- **히스테리시스의 출처**: 관찰된 QCC 노이즈 버그의 수정이 아니라 최초 설계(`3c2d3a7`, 2026-04-15)의 방어적 관례(docs 전수 grep에서 관련 버그 기록 0건). RESET 가드는 별도로 `9409f9f`(Rev.5)에서 부팅 초기 pct=0 CRITICAL 누출을 막으려 추가됨.
- **마진 제거 안전성 = 조건부 안전 (반증 실패)**:
  - 메인 루프는 빠르게 돌지만 `pct`는 `0x34` 수신 시에만 갱신 → 두 메시지 사이 반복은 동일 pct·동일 결과라 **마진 유무와 무관하게 chattering 불가**. chattering은 오직 "연속 `0x34`의 percent가 경계에서 실제로 진동"할 때만 가능 = QCC 내부 동작 의존(미확정).
  - `snd_batt_get_level()`·veryLowBattery는 이미 마진 없이 동작 중이나 "비가시적 소비처"라 LED로 일반화는 논리적 비약(그래서 "확정"이 아닌 "조건부").
  - ⚠️ 정정(검증): veryLowBattery 밴드는 20%p가 아니라 **40%p**(`systemControl.c:251~253`, 0per+0~20+20~40 OR, 주석 "40per 미만이면 저전력").
  - **신규 위험 후보(검증 발굴)**: 충전기 커넥터 바운스 시 충전/방전 토글마다 QCC가 충전상태별 보정으로 percent를 몇 %p 튀길 개연성(디바운스 없음 `ble_communication.c:135~152`). QCC 미확인이라 확정 불가 → 실측 게이트 후보.
- **실측 게이트 권고**: ① 임계 근처(10%/80%) 완속 충방전 중 QCC percent 로깅(경계 반복 교차 여부) ② `0x34` 실제 수신 간격 ③ 충전기 착탈/바운스 구간 percent 로깅.

## 4. 재캡슐화 설계 옵션 (페르소나 04 + 검증)

### 4.1 등급 구조
- 배터리: `LED_ST_IDLE`(RESET) + `BATT_CRITICAL/MID/READY` → **3등급, 컷 10/80**.
- 매핑: `LED_ST_MAPPING_{ISD,NO_ISD}_BATT_{LOW,READY}`(+미연결 `NONE`) → **2등급, 컷 20**.

### 4.2 옵션 비교

| 기준 | A (단일 임계 상수) | B (테이블 구동) | C (레벨 기반) |
|---|---|---|---|
| diff 크기 | 최소 | 중간 | 중간~큼 |
| 하드코딩 제거 효과 | 낮음(if-else 유지) | **높음**(데이터화) | 중간 |
| updateBatteryLevel 정신 부합 | 낮음 | **높음** | 중간 |
| 배터리 10/80 컷 재현 | 정확 | 정확 | **불가**(20%p 그리드) |
| 매핑 20 컷 재현 | 정확 | 정확 | 근접(`pct==20` 경계 상이) |
| 오버라이드 경로 | 단순 | 단순 | 복잡(percent→level 변환) |

- **옵션 B 검증 결과**: `{80,READY},{10,MID},{0,CRITICAL}` 내림차순 + `pct>=min_pct` + 첫 매치. pct 0~100 전 구간 수동 트레이스 → 옵션 A와 **완전 동일 결과, 결함 없음**. 유일 취약점 = "내림차순 불변식이 깨지면 조용히 오분류"(리뷰/주석 의존).
- **옵션 C 제약**: `snd_batt_get_level()`은 0/20/40/60/80/100 고정 20%p 그리드 → 배터리 CRITICAL 컷(10%) 재현 불가(→ 배터리 블록 비추천). 매핑 컷(20%)은 근접하나 `en__batteryPower_0btw20`은 `pct<20`이라 `pct==20`에서 현재(`pct<=20` LOW)와 결과가 갈림(주의).

### 4.3 보존 필수 5항목 (옵션 무관, 누락 시 회귀)

| # | 항목 | 누락 시 회귀 |
|---|---|---|
| 1 | `ENABLE_UI_CMD` override 2단(입력+출력) | UI 강제 LED 테스트 중 실제 QCC 상태가 새어 오버라이드 무력화 |
| 2 | 배터리→ISD→매핑 순서 + `batt_st`/`isd_conn` 인자 전달 | ISD 미연결 구간에 낡은 배터리 LED 재송출(오표시) |
| 3 | `led_set_isd_conn_state()` ISD 함수 마지막 봉인 | ISD 해제 순간 1-tick 백색 잔상 race 재발 |
| 4 | 매핑 블록 `pct` 1회 계산 공유 | 오버라이드 시 배터리(override pct)·매핑(실측 pct) 불일치 |
| 5 | `RESET → IDLE` 최우선 분기 | 부팅 초기 pct=0이 CRITICAL로 새는 회귀(`9409f9f` 이전 버그) |

## 5. 핵심 결정 (계획으로 구체화)

- 결정_1: **마진 제거는 의도된 동작 변경**임을 문서화(회귀 아님). 배터리 `prev_batt_st`·매핑 `s_map_low_active` static과 이중 임계 분기를 제거해 순수 함수화.
- 결정_2: **재캡슐화는 옵션 B(테이블 구동) 1순위** — "updateBatteryLevel() 정신"에 구조적으로 최적, 매직넘버를 데이터로. 옵션 A(단일 임계 상수)를 저위험 대안으로 병기. 매핑 블록은 스타일 통일 위해 percent 기반 단일 임계 권장(옵션 C 부분채택은 percent/level 비대칭 유발로 비권장).
- 결정_3: **`updateBatteryLevel()` 직접 부활 불가** → 구조만 참고한 신규 `tdc_led_request_battery()` 신설. 레거시 정의는 dead code 삭제 후보로 계획에 별도 제안(최종 승인).
- 결정_4: **보존 필수 5항목**을 신규 함수 시그니처·호출 순서로 강제(§4.3).
- 결정_5: **마진 제거 안전성은 저위험이나 조건부** — 실측 게이트(§3) 없이도 되돌리기 쉬운 변경이라 진행 가능하되, 계획에 실측 게이트를 "권고(선택)"로 명시.
