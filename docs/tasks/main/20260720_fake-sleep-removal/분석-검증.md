## 축_2 — 논리 정합성

### 결함_1 (발견 · 정정) — `#if 0` 참조를 고아 집계에 포함

`분석.md §4` 표는 `public_touch_settings` 를 "fake 안 1 / fake 밖 0 → 고아"로 집계했다. 그러나 그 1건은 **`#if 0` 블록 안**(`main.c:979~988`)이라 애초에 컴파일되지 않는다.

즉 이 심볼은 **fake 제거와 무관하게 이미 참조 0** 이었다. "fake 제거로 고아가 된다"는 인과가 성립하지 않는다.

**정정**: `public_touch_settings` 는 **고아 목록이 아니라 "기존 dead" 목록**으로 분류한다. §4.2 가 이미 `#if 0` 사실과 제외 방침을 적어 결론은 옳으나, §4 표의 분류가 부정확하다.

**영향**: 없음(어차피 제외 대상). 분류 오류만 정정.

### 결함_2 (발견 · 정정) — 규모 재집계 누락

`분석.md §6` 은 "직접 대상 283 + 고아 setter 28 = 311"로 집계했다. 그러나 §2 표의 #4(`main.h` 선언 3줄)와 #6(`ci_power.h` 선언 1줄)은 **283 에 이미 포함**돼 있는지 불명확하다.

§2 표 합산: 222+6+11+3+12+1+24+4 = **283** ✅ (헤더 선언 포함 확인)

**정정**: 283 은 정확하다. 다만 §6 이 "직접 대상 283"의 내역을 밝히지 않아 재검산이 필요했다. 표기만 보강.

### 결함_3 (발견) — 가설 수 부족

루트 `작업 규칙.md §5` 는 "root cause 가설 최소 3개 수립 후 cross-check"를 요구한다. §5 는 의심 1건(option 1 이 깨진다) → 반증 1건(정상 경로가 채운다)으로 2단이다.

**평가**: 이 조항은 **회귀 fix · 디버깅** 맥락의 규칙이다. 본 작업은 회귀 수정이 아니라 dead code 제거이고, §5 의 의심은 "가설"이 아니라 **정적 사실 확인**(누가 쓰는가)이라 반증 1건으로 결론이 확정된다. **적용 대상 아님**으로 판단하되, 아래 축_3 에서 반증을 한 번 더 독립 실증한다.

## 축_3 — 근거 검증 (재실증)

### 실증_1 — option 1 데이터 공급이 fake 와 독립인가 (핵심 재확인)

`분석.md §5` 의 결론이 틀리면 **기능 회귀**가 나므로 독립 실증한다.

| 검사 | 결과 |
|---|---|
| `s_debug_recent_*` 직접 대입 위치 | `tdc_touch.c:337~343` (7개 전부) |
| 그 코드를 감싼 함수 | `tdc_touch_process()` (`tdc_touch.c:273`) |
| 해당 함수 호출처 | `main.c:614` `tdc_collect_events()` 내부 |
| 호출 빈도 | 메인 루프 iteration 마다 1회 (`tdc_normal_iteration` → `tdc_collect_events`) |
| `#if` 가드 안인가? | `:337~343` 은 `#endif`(`:336`) **바깥** — 무조건 실행 |

> [!IMPORTANT]
> `:330~335` 의 `ci_printd` 는 `#if (TDC_TOUCH_DEBUG_PRINT_ENABLE)` 안이지만, **`:337~343` 대입은 그 `#endif` 밖**이라 디버그 플래그와 무관하게 항상 실행된다. 즉 option 1 데이터 공급은 빌드 설정과 무관하게 유지된다.

**실증 통과. `분석.md §5` 결론 확정.**
