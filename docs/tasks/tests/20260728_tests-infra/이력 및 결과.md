## 2. 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| 결정_1 | 호스트 컴파일러는 **MinGW-w64 (WinLibs POSIX/UCRT)** | winget 으로 설치 가능하고 gcc 가 바로 포함돼 MSYS2 의 pacman 추가 단계가 없다 |
| 결정_2 | **SDK 헤더를 그대로 사용** (스텁 헤더 미작성) | PoC 에서 `hw.h` 등 SDK 헤더가 호스트 gcc 로 문제없이 컴파일됨을 확인 |

## 3. 이슈

| # | 이슈 | 처리 |
|---|---|---|
| 이슈_1 | 호스트 컴파일러가 하나도 없어 오프라인 테스트가 원천 불가였다 | 은수님 승인 후 MinGW-w64 설치로 해소 |
| 이슈_2 | `map_stim` 외부 의존을 17개로 과대계상 | 자기 static 함수를 포함한 수치였다. **실제 7개**. 중복 제거 시 스텁 8개로 3파일 커버 |
| 이슈_3 | **0x66 하위 8종이 static 이라 직접 호출 불가** | 진입점 `tdc_ble_map_stim_live()` 간접 테스트로 해결. static 을 떼면 `src/` 변경이라 금지 |
| 이슈_4 | 링크 단계에서 로그 함수 미정의 | `map_stim` 만 `TDC_PRINTF_*` 사용. 스텁 2개 추가(8 -> 10개) |
| 이슈_5 | **`src/` 경고 11건 발견** | 호스트 `-Wall -Wextra` 가 `tdc_ble_map_stim_live()` 진입점의 미사용 변수를 잡아냈다. 원칙_4·수용_5 에 따라 고치지 않고 **결함_14** 로 기록 |

**인프라의 가치가 도입 즉시 증명됐다.** ARM 빌드에 `-Wall` 이 없어 보이지 않던 미사용 변수 11개를 호스트 빌드가 잡아냈다. 앞으로 러너가 매번 `src/` 경고를 보고하므로 같은 누락이 재발하면 즉시 드러난다.

**존재 이유**: 설계안 단계_3(패킷 디스크립터 테이블)의 회귀 안전망. 파싱을 테이블 주도로 바꾼 뒤 186 케이스가 그대로 통과하면 동작이 보존된 것이다. 단계_4(라이브 상태 계약)에도 유효하다 - 하위 3/4 의 `HoldOn` 요구가 이미 고정돼 있다.

**한계**: 파싱 로직 한정이며 자극 타이밍·하드웨어는 여전히 실기 소관이다. 검증 기준이 코드에서 역추출한 것이라 **결함도 함께 고정**된다(의도된 성질).

**게이트**: 실기 불필요. 다만 은수님이 `bash tests/unit/run.sh` 를 한 번 돌려 주시면 컴파일러 경로 탐색이 다른 환경에서도 동작하는지 확인된다.
