# 요구사항 - tests 오프라인 테스트 인프라

**TL;DR**: 설계안 단계_3 이 전제로 요구하는 **오프라인 파싱 테스트 인프라**를 만든다. 호스트(PC)에서 `ble/mapping/` 의 파싱 함수를 **실제 소스 그대로** 컴파일·실행해 입력 패킷 대비 결과를 검증한다. PoC 로 타당성이 실증됐고(9 PASS), 남은 일은 이를 **재현 가능한 구조**로 정식화하는 것이다.

## 1. 배경

설계안 §3 단계_3 은 이렇게 못박는다.

> **단계_3 부터는 `tests/` 인프라가 전제**다. 현재 `tests/` 는 사실상 비어 있다. 오프라인 파싱 테스트 없이 진행하는 것은 권하지 않는다.

현재 `tests/` 에는 로그·다이어그램 **문서 14개**만 있고 실행 가능한 테스트 코드는 **0개**다.

### 1.1 왜 지금인가

2026-07-28 단계_1b 로 파싱이 **명령별 함수 23개**로 분리됐다. 이전에는 `fetch_packet` 1,724줄 하나라 테스트 진입점이 없었으나, 이제 함수 단위로 호출할 수 있다. **폴더 개편이 테스트 가능성을 만들어낸 것**이다.

### 1.2 PoC 결과 (타당성 실증)

| 항목 | 결과 |
|---|---|
| 호스트 컴파일러 | MinGW-w64 gcc **16.1.0** (winget 설치) |
| SDK 헤더 호스트 컴파일 | **성공** - `hw.h` 등 그대로 통과, 스텁 헤더 불필요 |
| `map_measure.c` 링크·실행 | **성공** - 스텁 2개(`get_packet`·`error_send_to_app`)만으로 충분 |
| 테스트 결과 | **9 PASS / 0 FAIL** (정상 파싱 · 범위 초과 에러 · 16비트 조립) |

## 2. 목표

| # | 목표 | 측정 |
|---|---|---|
| 목표_1 | 파싱 함수를 **실제 소스 그대로** 호스트에서 실행 | 사본이 아닌 `src/` 파일을 직접 컴파일 |
| 목표_2 | 한 명령으로 전체 테스트 빌드·실행 | 러너 스크립트 1개 |
| 목표_3 | 실패 시 어느 검증이 깨졌는지 즉시 식별 | 케이스별 PASS/FAIL 출력 + 종료 코드 |
| 목표_4 | 단계_3 착수 시 **회귀 안전망**으로 동작 | 디스크립터 테이블 전환 전후 결과 동일 확인 |
