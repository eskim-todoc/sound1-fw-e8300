# 분석 검증 - tests 오프라인 테스트 인프라

**TL;DR**: 3축 검증 PASS. 분석이 세운 위험 5건 중 **위험_1(구조체 레이아웃)·위험_2(signed char)를 실측으로 해소**했고, 판단_2(`-Wall -Wextra` 적용 여부)는 **경고가 0이라 판단 자체가 불필요**해졌다. 잔여 결함 1건은 경미하다.

## 1. 검증 축_1 - 지침 준수

| # | 지침 | 준수 |
|---|---|---|
| 1 | 사실은 근거 제시, 추측 금지 | O - 스텁 목록·의존 수를 grep 으로, 컴파일 가능성을 PoC 로 |
| 2 | 결함 수정과 구조 작업 분리 | O - §5 "문서와 코드가 어긋나면 기록만" |
| 3 | 한글 라벨 · Alert · frontmatter | O |
| 4 | 코드 무변경 (③ 단계) | O - PoC 는 `$CLAUDE_JOB_DIR/tmp` 에만 존재 |

**축_1 판정: PASS**

## 2. 검증 축_2 - 논리적 정합성

| 확인 | 결과 |
|---|---|
| §1 이 `tdc_ble_reply.c` 를 스텁이 아닌 실물로 쓰는 근거 | **타당** - 응답 조립 결과가 검증 대상이므로 실물이어야 한다. 스텁으로 바꾸면 빌더 자체의 버그를 못 잡는다 |
| §2.1 이 `tdc_hal_spi_write_tx_buffer` 스텁을 "핵심 가치"로 든 것 | **타당** - 실기에서 로그로만 보던 응답 바이트열을 오프라인에서 단언할 수 있게 된다. 단계_3 회귀 안전망의 본체 |
| §4(`__LINE__` 제외)가 검증력을 떨어뜨리는가 | 떨어뜨리지 않는다. 에러의 **의미**는 major/minor 가 정한다. 라인은 위치 표시용이며 소스가 밀리면 바뀌는 값이라 단언 대상이 아니다 |
| §5 가 프로토콜 문서 대신 코드를 1차 근거로 삼은 것 | **타당하나 한계를 명시했는가** - "회귀 안전망이 목적"이라고 밝혔고 문서 불일치 사례(텔레코일)까지 들었다. 정직한 서술 |
| §3.1 이 Makefile 을 배제한 근거 | make 가 SDK 에만 있다는 것은 사실. 다만 **호스트 테스트가 SDK make 를 쓸 이유가 없다**는 논리가 더 본질적 |
| 위험_4(테스트 통과 != 실기 동작)를 인정한 것 | **중요** - 이 인프라의 한계를 명확히 했다. 자극 타이밍은 여전히 실기 소관 |

**축_2 판정: PASS**

## 3. 검증 축_3 - 근거 검증

| # | 주장 | 실측 | 판정 |
|---|---|---|---|
| 1 | 스텁 8개로 `mapping/` 3파일 커버 | 외부 의존 grep - measure 2 · flash 8 · stim 7, 중복 제거 시 8 | **확인** |
| 2 | `tdc_ble_reply_*` 는 실물 사용 가능 | `tdc_ble_reply.c` 는 외부 의존 0 (`stdint.h` 만) | **확인** |
| 3 | **위험_1** - 구조체에 포인터 필드 | `ST__MAPPING_PACKET` 정의 안에 `*` **없음** -> 호스트(64비트 포인터)와 타깃 레이아웃 동일 | **해소** |
| 4 | **위험_2** - `-fsigned-char` 일치 | x86 gcc 기본 signed. 타깃도 `-fsigned-char` | **확인** |
| 5 | 위험_3 - SDK 헤더 호스트 컴파일 | measure 확인 완료. **flash·stim 도 컴파일 성공**(아래 근거 6에서 확인) | **해소** |
| 6 | 판단_2 - `-Wall -Wextra` 경고 규모 | 3파일 전부 **경고 0** | **판단 불필요** |
| 7 | `p_RepositoryFor_ISD_info` 인덱스 45까지 | `map_flash.c` 0x6C 데이터 인덱스 3 의 `i = 41..46` 루프에서 `[i-1]` -> 최대 45 | **확인** |

> [!NOTE]
> **근거 6 이 중요하다.** `-Wall -Wextra` 로 `src/` 파일을 컴파일해도 경고가 0 이므로, 판단_2("기존 코드 경고가 쏟아질까")는 기우였다. **테스트 빌드에 경고 옵션을 그대로 켤 수 있다.**

**축_3 판정: PASS**

## 4. 발견 결함

### 결함_1 (경미) - `tdc_shm_get_pointer_current_map_data` 의 반환 타입을 확인하지 않았다

§2.1 은 이 스텁을 "정적 구조체 반환"으로 적었으나 실제 시그니처를 확인하지 않았다. `map_stim.c` 의 알림 자극(하위 5)이 `p_mapDataSharedMemory->C_level_uA[i]` 처럼 배열 필드를 읽으므로 **구조체 크기와 필드가 맞아야** 한다.

**조치**: ⑦ 착수 시 `tdc_shm.h` 에서 시그니처와 구조체 정의를 확인하고, 스텁이 그 타입을 그대로 반환하도록 만든다. 타입이 크면 정적 인스턴스 하나로 충분하다.
