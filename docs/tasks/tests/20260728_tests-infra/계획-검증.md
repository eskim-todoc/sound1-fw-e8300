## 4. 발견 결함

### 결함_1 (경미) - 케이스 목표 60개는 산술 추정이다

"명령 21개 x 3종 = 63" 은 **각 명령의 필드 수를 무시**한 계산이다. 0x62 는 범위 검사 필드가 5개라 경계 케이스만 10개(각 min-1/max+1)가 나오고, 0x69 는 헤더 only 라 1~2개면 충분하다.

**보완**: 목표를 **"명령마다 정상 1 + 범위 검사 필드마다 경계 2"** 로 재정의하고, 총계는 **결과로 기록**한다(사전 목표가 아니라). 60개는 하한선 참고치로만 둔다.

### 결함_2 (중대) - 0x66 하위 명령 8종은 static 이라 직접 호출할 수 없다

단계_1b-3b 에서 하위 명령을 `static void tdc_ble_map_stim_live_*` 로 만들었다. **static 심볼은 다른 번역 단위에서 링크되지 않으므로 테스트가 직접 호출할 수 없다.**

**선택지**

| 안 | 방법 | 판정 |
|---|---|---|
| 안_가 | `tdc_ble_map_stim_live()` 진입점을 통해 **간접 테스트** - 패킷의 하위 명령 바이트로 분기시킨다 | **채택** |
| 안_나 | static 을 떼어 외부 노출 | **금지** - `src/` 변경(수용_5 위반) |
| 안_다 | 테스트가 `.c` 를 `#include` 해서 static 에 접근 | 사본은 아니지만 링크 모델이 달라져 실제 빌드와 어긋난다. 채택하지 않는다 |

**안_가 가 옳다.** 어차피 실제 호출 경로가 `tdc_ble_map_stim_live(packet)` -> 하위 분기이므로, **진입점 테스트가 실사용에 더 가깝다.** 하위 명령 번호를 `pkt[1]` 에 넣으면 원하는 분기에 도달한다.

**조치**: 계획 §3.3 에 "0x66 은 `tdc_ble_map_stim_live()` 진입점으로 하위 8종을 간접 테스트"를 명시한다. 같은 이유로 `map_flash`·`map_measure` 는 전부 비-static 이라 직접 호출이 가능하다.
