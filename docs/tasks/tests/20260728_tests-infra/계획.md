# 계획 - tests 오프라인 테스트 인프라

**TL;DR**: **3커밋**으로 만든다 - ① 하네스(러너·매크로·스텁) + measure 테스트 → ② flash 테스트 → ③ stim 테스트 + 문서. `src/` 는 한 줄도 건드리지 않으므로 위험이 낮고, 각 커밋이 **그 자체로 실행 가능한 테스트**를 남긴다.

## 1. 판단 확정

| # | 판단 | **확정** | 근거 |
|---|---|---|---|
| 판단_1 | 커밋 분할 | **3커밋** (하네스+measure / flash / stim+문서) | 각 커밋이 독립 실행 가능. 스텁이 점증하는 순서 |
| 판단_2 | `-Wall -Wextra` 적용 | **적용** (`src/` 포함 전체) | 분석-검증 근거 6 - 경고가 0 이라 부담이 없다 |
| 판단_3 | 테스트 케이스 목표 | **명령마다 정상 1 + 범위 검사 필드마다 경계 2** (총계는 사전 목표가 아니라 결과로 기록. 60개는 하한 참고치) | 분석 §5.1, 계획-검증 결함_1 |

## 2. 산출 파일

```
tests/unit/
├── run.sh              러너 - 컴파일러/SDK 탐색 + 빌드 + 실행

├── stub_ble.c/.h       프로덕션 심볼 스텁 8개 + stub_* 조회 API
├── test_map_measure.c  0x62 · 0x63 · 0x64
├── test_map_flash.c    0x68 · 0x69 · 0x6A · 0x6B · 0x6C · 0x6D · 0x6E · 0x6F · 0x70 · 0x71
└── test_map_stim.c     0x65 · 0x66(하위 1~8)
```

`.gitignore` 에 빌드 산출물(`tests/unit/build/`) 추가.

## 3. 커밋별 계획

### 3.1 커밋 1 - 하네스 + measure

| 항목 | 내용 |
|---|---|
| 러너 | 컴파일러 3단 탐색(`CC` -> PATH -> winget 경로) · SDK 탐색(`EZAIRO_SDK` -> 기본 경로) · 실패 시 안내 후 비0 종료 |
| 매크로 | `CHECK(name, cond)` · `CHECK_EQ(name, actual, expected)` · `TEST_BEGIN/END` |
| 스텁 | 8개 전부 (measure 는 2개만 쓰지만 뒤 커밋에서 재사용) |
| 테스트 | 0x62(정상·경계 5필드) · 0x63 · 0x64 |
| 검증 | 전 케이스 PASS · 의도적 실패로 비0 종료 확인 |

**첫 확인 항목** (분석-검증 결함_1): `tdc_shm_get_pointer_current_map_data` 의 반환 타입을 `tdc_shm.h` 에서 확인하고 스텁 시그니처를 맞춘다.

### 3.2 커밋 2 - flash

멀티 패킷 명령(0x68·0x6C·0x6D)의 **데이터 인덱스 연속성**이 초점이다. 연속 호출로 시퀀스를 재현하고, 순서를 어겼을 때 `en__DATA_Order` 에러가 나는지 단언한다.

응답 바이트열도 단언한다 - 중간 패킷은 `[명령, 인덱스]` 2바이트 루프백이 나가야 한다.

### 3.3 커밋 3 - stim + 문서

0x66 하위 명령 8종. 하위 1(전체 파라미터)은 데이터 인덱스 1~15 시퀀스라 가장 길다.

> [!IMPORTANT]
> **0x66 하위 8종은 `static` 이라 직접 호출할 수 없다**(단계_1b-3b 산출물). `tdc_ble_map_stim_live()` **진입점을 통해 간접 테스트**한다 - 패킷의 `pkt[1]`(하위 명령 번호)로 원하는 분기에 도달한다. static 을 떼는 것은 `src/` 변경이라 금지(수용_5), `.c` 를 `#include` 하는 방식은 링크 모델이 실제 빌드와 어긋나므로 쓰지 않는다. 어차피 실사용 경로가 진입점 경유이므로 **간접 테스트가 더 실제에 가깝다.**
>
> `map_measure`·`map_flash` 는 전부 비-static 이라 직접 호출이 가능하다.

`docs/사용방법/` 에 실행 안내를 남긴다.

## 4. 수용 판정

| # | 기준 | 방법 |
|---|---|---|
| 수용_1 | 한 명령 실행 | `bash tests/unit/run.sh` |
| 수용_2 | 경고 0 | `-Wall -Wextra` |
| 수용_3 | 전 케이스 PASS | 종료 코드 0 |
| 수용_4 | 실패 시 비0 | 케이스를 일부러 깨서 확인 후 되돌림 |
| 수용_5 | **`src/` 변경 0** | `git diff src/` 가 비어 있음 |
| 수용_6 | 재현 가능 | 사용 방법 문서 |
| 수용_7 | 케이스 수 기록 | 실행 출력 집계 (하한 60 참고) |

> [!IMPORTANT]
> **수용_5 가 이 작업의 불가침이다.** 테스트를 통과시키려고 프로덕션 코드를 고치는 순간 안전망이 아니라 공범이 된다. 테스트가 실패하면 **테스트가 틀렸거나 진짜 결함**이며, 후자면 기록만 하고 고치지 않는다(원칙_4).
