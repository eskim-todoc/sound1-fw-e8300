## 4. 발견 결함

### 결함_1 (경미) - `map_stim` 의존 수를 과대 계상했다

요구사항 §6 미결_1 은 "stim 은 의존 17개"라며 범위 축소를 검토 대상으로 뒀다. 그러나 그 17개는 **자기 파일의 static 함수 8개를 포함한 수치**다.

**실제 외부 의존**

| 파일 | 외부 의존 |
|---|---|
| `map_measure.c` | 2 |
| `map_flash.c` | 8 |
| `map_stim.c` | **7** |

**중복 제거 후 필요한 스텁 8개**

| 스텁 | 쓰는 파일 |
|---|---|
| `tdc_ble_mapping_get_packet` | 전부 |
| `tdc_ble_mapping_get_seq_index` / `set_seq_index` | flash · stim |
| `tdc_sys_error_send_to_app` | 전부 |
| `tdc_hal_spi_write_tx_buffer` | flash · stim |
| `tdc_shm_get_pointer_repository_for_read_write_map_data_isd_info` | flash |
| `tdc_shm_get_pointer_repository_for_read_write_map_data_stimul_para` | flash |
| `tdc_shm_get_pointer_current_map_data` | stim |

`tdc_ble_reply_*` 는 **실물을 함께 컴파일**하면 되므로 스텁이 아니다.

**조치**: 미결_1 을 "범위 축소 검토"가 아니라 **"`mapping/` 3파일 전부 대상"** 으로 확정하고 ③ 분석에 반영한다.

### 결함_2 (경미) - 테스트 코드의 `tdc_` 접두어 적용은 재검토가 필요하다

`tdc_` 는 **프로덕션 심볼**의 프로젝트 접두어다. 테스트 하네스의 지역 함수(`check`·`reset` 등)까지 `tdc_` 를 붙이면 오히려 프로덕션 심볼과 섞여 혼동된다.

**조치**: ③ 분석에서 "**프로덕션 심볼을 흉내내는 스텁은 원래 이름 그대로**(링크 대체이므로 필연), **테스트 전용 헬퍼는 `tdc_` 없이 짧은 이름**" 으로 규칙을 정한다.
