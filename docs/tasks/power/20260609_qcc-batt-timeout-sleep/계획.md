# 계획 — QCC 배터리 타임아웃 시 절전 진입 (방법 E)

**TL;DR**: main.c 단일 파일 2곳 변경. ① fake_0x34 블록을 "타임아웃 3초 감지 → 플래그 set"으로 축소(배터리 fake 제거). ② `func_normal()` static 플래그 2개 추가. ③ systemControl 직후 전용 블록에서 파워오프 패턴 요청 + burst 완료 시 `systemOff=true`. 기존 절전 경로(`664→break→func_sleep`) 재사용.

## 변경 파일: `src/2__cm3/Cortex-M3-src/main.c` (단일)

### 단계_1 — func_normal() static 플래그 2개 선언

`func_normal()` 함수 시작부(지역 변수 선언 영역)에 추가:

```c
static bool qcc_batt_timeout            = false;  /* QCC 0x34 수신 타임아웃 발생 */
static bool qcc_timeout_poweroff_started = false; /* 타임아웃 파워오프 패턴 1회 요청 가드 */
```

### 단계_2 — fake_0x34 블록 수정 (main.c:396-427)

- 타임아웃 `2000` → `3000`.
- 타임아웃 분기: `snd_batt_set_percent(9)`·`snd_batt_set_state(DISCHARGING)`·`snd_charger_set_state(DISCONNECTED)` **3줄 제거** → `qcc_batt_timeout = true;` 로 대체.
- 로그는 의미에 맞게 갱신(`[FAKE_0x34] QCC BATT TIMEOUT -> POWER OFF`).
- `else if (snd_batt_get_state() != RESET)` 정상 수신 분기는 **그대로 유지**.

```c
if (3000 < (ci_timer_get_tick() - fake_0x34)) {
    fake_0x34_done   = 1;
    qcc_batt_timeout = true;
    ci_printw("[FAKE_0x34] QCC BATT TIMEOUT -> POWER OFF (SLEEP) \r\n");
}
else if (snd_batt_get_state() != EN__SND_BATT_STATE_RESET) {
    fake_0x34_done = 1;
    /* 기존 EXIT-DMA 로그 유지 */
}
```

### 단계_3 — systemControl 직후 전용 파워오프 트리거 블록 추가

위치: `systemState = systemControl(...)`(main.c:434) 이후 ~ `if (systemState.systemOff == true)`(main.c:664) **직전**(main_counter/update_CM3Status 다음). 같은 iteration에 systemOff가 즉시 664에서 처리되도록.

```c
/* QCC 배터리 타임아웃 → 파워오프 패턴 후 절전.
 * QCC 미수신 시 systemControl이 df_Default 게이트(LED_NA)에 막혀 자체 파워오프
 * 시퀀스에 도달하지 못하므로, 여기서 직접 POWER_OFF 패턴을 요청하고 burst 완료
 * 후 systemOff를 세팅해 기존 절전 경로(664→break→func_sleep)를 탄다.
 * 상세: docs/tasks/power/20260609_qcc-batt-timeout-sleep/분석.md §4 */
if (qcc_batt_timeout) {
    if (!qcc_timeout_poweroff_started) {
        led_request(LED_SRC_POWER, LED_ST_POWER_OFF);
        qcc_timeout_poweroff_started = true;
        ci_printi("[FAKE_0x34] LED PATTERN IS POWER OFF (QCC TIMEOUT) \r\n");
    }
    else if (!tdc_led_is_burst_pending()) {
        systemState.systemOff = true;
    }
}
```

## 타이밍 정리

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| QCC 배터리 대기 타임아웃 | 2000ms | 3000ms |
| 타임아웃 시 동작 | fake 배터리 9% 세팅(시스템 가동) | 파란 파워오프 패턴 → 절전 |
| 타임아웃 전 LED | 꺼짐(LED_NA) | 꺼짐(LED_NA) — 유지 |

## 주의 사항

- 파워오프 패턴은 **끝까지(BLUE 4회 깜빡 ≈1.4초) 재생 후** 절전 — 기존 롱터치 절전과 동일(`!tdc_led_is_burst_pending()` 게이트).
- 절전 진입 보류 조건(매핑/페어링/OTA 중, main.c:675)은 기존 그대로 적용됨 — 타임아웃 절전도 동일 가드 통과.
- `else if` 정상 수신 분기 무변경 → QCC 정상 케이스 회귀 없음.
- 중괄호: 단일문도 `{}` 필수(루트 지침) 준수.

## 검증 계획 (단계 ④ 종료 시)

- 정적 검증 서브에이전트 fan-out:
  - 빌드 정합: 신규 식별자(`qcc_batt_timeout`·`LED_ST_POWER_OFF`·`tdc_led_is_burst_pending`·`led_request`) 선언/시그니처 일치, 타입(`EN__SND_BATT_STATE_RESET` enum) 존재.
  - 회귀: `else if` 정상 분기·기존 절전 경로(664-689) 무변경 확인. fake 배터리 setter 제거가 다른 호출처에 영향 없는지 grep.
  - 스타일: 중괄호·주석 밀도·네이밍(tdc_/snd_ 관례) 일관.
- 실기 검증(은수님): ① 부팅 후 QCC 미연결 3초 → 파란 깜빡 → 절전 진입 확인, ② QCC 정상 수신 시 기존 동작 유지.

## 위험·완화

- 위험_1: 전용 블록 위치가 systemOff 체크보다 뒤면 1-iteration 지연 → 664 직전 배치로 같은 iter 처리.
- 위험_2: LED arbiter 우선순위에서 POWER_OFF가 밀릴 가능성 → 기존 롱터치 파워오프도 동일 `LED_SRC_POWER` 사용해 정상 동작 입증됨(회귀 없음).
- 위험_3: 절전 후 웨이크업 시 static 플래그 잔존 → 본 작업 범위 밖(기존 fake_0x34_done도 동일 패턴). 필요 시 후속.

## 자체 검토

- 지침 준수: 단일 파일·기존 경로 재사용으로 회귀 최소. 중괄호·네이밍·주석 규칙 반영.
- 논리 정합: 3단계가 플래그 선언→감지→트리거로 의존 정렬, 방법 E 분석과 1:1.
