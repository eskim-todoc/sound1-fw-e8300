# 요구사항 — QCC 배터리 타임아웃 시 절전 진입

**TL;DR**: `main.c`의 "QCC 대체용 디버깅 코드"(fake_0x34) 블록에서, QCC 0x34(배터리 정보) 수신 대기 타임아웃을 **2000ms → 3000ms**로 늘리고, 타임아웃 시 동작을 **fake 배터리 9% 세팅 → 파란색 파워오프 패턴 재생 후 절전(func_sleep) 진입**으로 바꾼다.

## 1. 배경

부팅 시 하늘색 파워온 패턴 후, QCC로부터 배터리 정보(0x34)를 받아야 정상 동작한다. 현재 디버깅 코드는 2초 내 미수신 시 가짜 배터리 9%·충전기 분리를 세팅해 시스템을 강제 가동한다. 은수님은 이를 "타임아웃 시 그냥 꺼지게(절전)" 바꾸길 원한다.

## 2. 요구사항 항목

- 요구사항_1: 타임아웃 임계치를 **2000ms → 3000ms**로 변경한다.
- 요구사항_2: 타임아웃 시 **fake 배터리 9%·DISCHARGING·충전기 분리 세팅을 제거**한다.
- 요구사항_3: 타임아웃 시 **파란색 깜빡이는 파워오프 패턴**(`LED_ST_POWER_OFF`)을 재생한다.
- 요구사항_4: 파워오프 패턴 재생 완료 후 **절전 모드(func_sleep)로 진입**한다.
- 요구사항_5: 타임아웃 전(QCC 대기 중)에는 **LED가 꺼진 채(en__LED_NA) 대기**하는 현재 동작을 유지한다.
- 요구사항_6: QCC 정상 수신 시(타임아웃 전 배터리 수신) 기존 정상 동작·로그는 그대로 유지한다.

## 3. 기대 시퀀스

```
부팅 → 하늘색 파워온 패턴 → (QCC 0x34 대기, LED 꺼짐)
  ├─ 3초 내 배터리 수신 → 정상 동작 (기존)
  └─ 3초 초과 → 파란색 파워오프 패턴(깜빡) → 절전(func_sleep)
```

## 4. 범위 밖 (Out of Scope)

- 절전 후 웨이크업 동작·QCC 재수신 로직.
- 파워오프 패턴의 색·횟수 변경(기존 `LED_ST_POWER_OFF` BLUE 4회 그대로 사용).
- 정상 롱터치 절전 경로·저전력 자동 파워오프 로직.

## 5. 확인 필요 사항 (계획 단계에서 제시)

- 확인_1: "이 블록에서"라는 지시지만, 구조상 절전 트리거는 `systemControl()` 호출 **이후**에 둬야 한다(이유: 분석.md §게이트). fake 블록 + systemControl 직후 2곳 변경이 불가피 — 계획에서 승인 요청.
- 확인_2: 파워오프 패턴을 **끝까지(4회 깜빡 ≈1.4초) 재생 후** 절전 진입 — 기존 롱터치 절전과 동일 방식. (추측 적용, 계획에 명시)

## 6. 자체 검토

- 지침 준수: 회귀 위험 코드 — 호출 경로 grep·root cause 다중 확인 후 착수.
- 논리 정합: 요구사항 6항목이 은수님 지시 문구(타임아웃 3초·fake 제거·파워오프 패턴·절전·꺼진 채 대기)와 1:1 대응.
