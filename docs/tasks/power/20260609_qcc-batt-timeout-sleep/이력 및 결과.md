## 완료 요약

**결과**: main.c의 QCC 배터리 타임아웃 디버깅 로직을 "fake 배터리 9% 강제 가동" → "타임아웃 3초 후 파워오프 패턴 + 절전 진입"으로 변경(방법 E). 단일 파일 3곳 변경.

**변경 (`src/2__cm3/Cortex-M3-src/main.c`)**:

1. **func_normal 변수부** — `bool qcc_batt_timeout`·`qcc_timeout_poweroff_started` 지역 플래그 2 추가(static 아님 — 무한 재절전 방지).
2. **fake_0x34 블록** — 타임아웃 `2000→3000`ms, `snd_batt_set_percent(9)`·`snd_batt_set_state(DISCHARGING)`·`snd_charger_set_state(DISCONNECTED)` 3줄 제거 → `qcc_batt_timeout=true`. 정상 수신 `else if` 분기 무변경.
3. **systemControl 직후 전용 블록** — `qcc_batt_timeout`이면 `led_request(LED_SRC_POWER, LED_ST_POWER_OFF)`(파란 깜빡) 1회 → `!tdc_led_is_burst_pending()`(4회 재생 완료) 시 `systemState.systemOff=true` → 기존 절전 경로(664→break→func_sleep) 진입.

**핵심 설계 근거**: QCC 미수신 시 systemControl이 `df_Default` 게이트(`en__LED_NA`)에 막혀 자체 파워오프 시퀀스(`df_Disconnected` 분기 내)에 도달 못 함 → fake 블록만으론 절전 불가. systemControl을 우회해 절전 경로만 재사용(방법 E).

**검증**: 정적 검증 fan-out 2 PASS(빌드 가시성·회귀·스타일). 컴파일러 직접 실행 불가 환경이라 **실기 빌드·동작 검증은 은수님 몫**(① QCC 미연결 3초 → 파란 깜빡 → 절전, ② QCC 정상 수신 시 기존 동작 유지).

**자체 검토**: ① 지침 준수 — 회귀 디버깅 규칙(호출 경로 grep·root cause 다중 가설 A/C/E cross-check) 적용, 중괄호·네이밍 준수. ② 논리 정합 — df_Default 게이트 발견으로 방법 E 도출, 요구사항 6항목 전부 충족.

**완료**: 은수님 실기 검증 통과("잘 동작한다"). `claude_develop` 커밋(코드/문서 분리)·origin 푸시 완료. (상태: 완료)
