# 분석 — QCC 배터리 타임아웃 시 절전 진입

**TL;DR**: 절전 경로(`systemOff`→`break`→`func_sleep`)는 확인됐다. 핵심 함정은 **QCC 미수신 시 systemControl이 `df_Default` 게이트(LED_NA)에 막혀 자체 파워오프 시퀀스에 도달하지 못한다**는 것. 따라서 fake 블록만 고쳐선 안 되고, `systemControl()` 호출 직후에 **전용 파워오프 트리거 블록**을 둬 기존 절전 경로를 직접 탄다(방법 E).

## 1. 현재 코드 (main.c:396-427, fake_0x34 블록)

```c
if (2000 < (tick - fake_0x34)) {            // 타임아웃 2000ms
    snd_batt_set_percent(9);                // 가짜 배터리 9%
    snd_batt_set_state(DISCHARGING);
    snd_charger_set_state(DISCONNECTED);    // ★ 실제 핵심 역할
}
else if (snd_batt_get_state() != RESET) {   // QCC 정상 수신
    // 로그만
}
```

> 서브에이전트 read-only fan-out 2개(절전 경로 / LED 패턴)로 병렬 조사 후, main.c·systemControl.c 직접 정독으로 교차 확인.

## 2. 핵심 함정 — `df_Default` 게이트 (systemControl.c)

`systemControl()`은 `chargerState.chargerConnectorPluggedIn` 값으로 3분기한다:

| chargerConnectorPluggedIn | 동작 | 파워오프 시퀀스 도달? |
|---|---|---|
| `df_Defalut` (QCC 0x34 미수신) | `Led_Pattern = en__LED_NA` 만, 그 외 **아무 동작 없음** | ❌ |
| `df_Connected` (충전기 연결) | 충전 처리 | ❌ |
| `df_Disconnected` (정상) | normalMode + **파워오프 시퀀스(L267~319)** | ✅ |

- 파워오프 시퀀스(`veryLowBattery || powerButtonPushed` → `LED_ST_POWER_OFF` → burst 완료 시 `systemOff=true`)는 **`df_Disconnected` 분기 안에만** 존재(systemControl.c:267-319).
- **현재 fake가 `snd_charger_set_state(DISCONNECTED)`를 부르는 진짜 이유**가 이것 — charger를 df_Disconnected로 만들어 systemControl을 `df_Default` 게이트에서 탈출시켜 정상 동작시킨다. 배터리 9%는 그 정상 동작의 입력값일 뿐.

## 3. 절전 진입 경로 (확인 완료)

```
systemControl() → systemState.systemOff = true
  → main.c:664 systemOff 체크 (매핑/페어링/OTA 중이면 보류)
  → main.c:688 led_force_fade_off()
  → main.c:689 break   (func_normal while 루프 탈출)
  → main.c:311 func_sleep()   (main while: func_normal(); func_sleep();)
```

- `led_request(LED_SRC_POWER, LED_ST_POWER_OFF)` = 파란색 BLUE 180ms ON/OFF × 4 burst (LedOutput.c:263).
- 재생 완료 판정: `tdc_led_is_burst_pending()` == false (timer 무관, 정확).
- `led_request`는 main.c에서 이미 직접 사용 중(main.c:520·540·552·590 등) — 신규 의존성 없음.

## 4. 구현 방법 비교

| 방법 | 내용 | 평가 |
|---|---|---|
| 방법 A (단순 재사용) | fake 블록에서 `powerButtonPushed=true`만 | ❌ df_Default 게이트라 systemControl 파워오프 미도달 |
| 방법 C (charger 조작 재사용) | 타임아웃 후 매 iter `charger=Disconnected`+`powerButtonPushed=true` | ⚠️ df_Disconnected 첫 진입 시 StartFlag=false → **하늘색 파워온 패턴 재생** 부수효과. 요구사항_5 위반 |
| **방법 E (전용 트리거)** ★ | fake 블록=타임아웃 플래그만 / systemControl 직후 전용 블록에서 `led_request(POWER_OFF)`+burst 완료 시 `systemOff=true` | ✅ 부수효과 0. systemControl df_Default 게이트와 무관하게 절전 경로 직접 진입 |

**선택: 방법 E.** systemControl을 우회(거치지 않고)하되, 절전은 기존 `systemOff`→`func_sleep` 경로를 그대로 재사용해 회귀 위험을 최소화한다.

## 5. 방법 E 동작 검증 (논리)

- 타임아웃 전: `qcc_batt_timeout=false` → 전용 블록 미동작. systemControl df_Default → LED_NA(꺼짐). ✅ 요구사항_5.
- 타임아웃: 전용 블록 1회차 `led_request(POWER_OFF)`(BLUE 깜빡 시작). 이후 iter `!burst_pending` 되면 `systemState.systemOff=true` → 664 → break → func_sleep. ✅ 요구사항_3·4.
- LED arbiter: `LED_SRC_POWER`가 최우선 — 같은 iter의 BATTERY/ISD 요청(systemControl이 df_Default라 미요청)과 무관하게 POWER_OFF 출력. ✅
- charger 조작·배터리 fake 모두 불필요 → 제거. ✅ 요구사항_2.

## 6. 상태 변수 (func_normal static)

- `qcc_batt_timeout` (bool): fake 블록에서 set, 전용 블록에서 read.
- `qcc_timeout_poweroff_started` (bool): 전용 블록 내 led_request 1회 가드.
- 선언 위치는 `func_normal()` 함수 레벨 static (양 블록 공유). 구현 시 함수 시작부 확정.
