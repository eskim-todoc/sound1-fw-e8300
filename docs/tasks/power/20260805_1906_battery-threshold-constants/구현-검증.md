# 구현 검증 - 배터리·시간 임계 매크로 상수화

**TL;DR**: 이 유형의 불변량은 **`.elf` 바이트 동일**이다. 순수 토큰 치환이므로 컴파일 결과가 1비트도 달라져선 안 된다. **md5 `ad3b9326060e45028a1343dd1eab79df` 가 전후 완전 일치**했다. 값 전수 대조·사용처 전수 확인도 통과했다.

## 1. 불변량 - `.elf` 바이트 동일

| 항목 | 변경 전 | 변경 후 | 판정 |
|---|---|---|---|
| **md5** | `ad3b9326060e45028a1343dd1eab79df` | `ad3b9326060e45028a1343dd1eab79df` | **완전 동일** |
| text | 185,444 | 185,444 | 동일 |
| data | 4,668 | 4,668 | 동일 |
| bss | 21,804 | 21,804 | 동일 |

### 왜 바이트 동일이 성립하는가

| 조건 | 확인 |
|---|---|
| 매크로는 전처리 단계 치환 | 값이 같으면 생성 코드가 같다 |
| `__FILE__` 미사용 | 세 파일 모두 **0건** (경로가 `.rodata` 에 박히지 않는다) |
| `__LINE__` 위치 | `main.c:213` **단 1건**, 편집 구간(331~340)보다 **앞** -> 값이 밀리지 않는다 |
| `tdc_sys_control.c` 의 `__LINE__` | **0건** -> 상단에 17줄을 추가해도 무관 |
| 헤더 줄 수 증가의 영향 | `__LINE__` 은 **각 `.c` 파일 자신의 줄 번호**다. 헤더가 길어져도 `.c` 의 값은 변하지 않는다 |

> [!IMPORTANT]
> **크기 동일보다 강한 검증이다.** 크기만 보면 서로 다른 상수로 바꿔치기해도 통과할 수 있다. 바이트 동일은 **모든 즉치값이 그대로임**까지 덮는다.

### 남은 매직넘버 확인

```sh
grep -nE "battery_percent\s*<\s*[0-9]|counter\s*[<>]\s*[0-9]{2,}" src/2__cm3/source/sys/tdc_sys_control.c
```

**결과 0건.** 대상 표현이 모두 치환됐다.

## 3. 단위 근거 (`_MS` 접미어의 정당성)

시간 임계 3개에 `_MS` 를 붙였다. 근거 3건이 서로 일치한다.

| 근거 | 내용 |
|---|---|
| 초기화 상수 이름 | `isd_disconnection_counter` 가 `Df_Disconnection_BLE_Time_ms`(2000)로 초기화된다 (`tdc_sys_control.c:141`, `processorDirective.h:52`) |
| 주석과 값의 일치 | 같은 카운터의 `180000` 에 붙은 주석이 **"3분"** 이다. 180,000 ms = 180 초 = 3 분 |
| 호출 주기 | `tdc_sys_control_step()` 은 `main.c:574` 에서 **1 tick 마다** 호출된다 (`main.c:65` "1 tick 분 입력 스냅샷") |

> [!NOTE]
> `:59` 의 `640` 에 붙어 있던 주석은 "0.6초" 인데 실제로는 **0.64초**다. **값은 그대로 두고** 새 매크로 주석에 "약 0.64초" 로 적었다. 원 주석의 반올림 표기도 그대로 뒀다 - 값을 안 바꾸는 작업에서 주석 문구까지 고치면 diff 의도가 흐려진다.
