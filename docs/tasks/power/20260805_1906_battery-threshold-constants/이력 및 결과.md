# 이력 및 결과 - 배터리·시간 임계 매크로 상수화

**TL;DR**: 은수님 요청 - *"단순 상수 값으로 쓰여진 게 무엇을 위한 것이었는지 파악이 어려워지기 시작했어."* 배터리 퍼센트 임계 5개를 `tdc_pwr_battery.h` 에 `TDC_BATT_*_PCT` 로 모으고, `tdc_sys_control.c` 의 시간 임계 3개를 `TDC_SYS_*_MS` 로 상수화했다. **값은 하나도 바꾸지 않았고 `.elf` md5 가 완전히 동일하다.** 부수로 죽은 매크로 2건을 제거했다.

## 8단계 면제 근거

루트 지침 §3 의 *"단순 수정(오타·설정값·자명한 한 줄)은 8단계 면제"* 를 적용했다. 근거 3건:

| # | 근거 |
|---|---|
| 1 | **순수 토큰 치환**이라 컴파일러가 동작 등가를 보장한다. 검증이 `.elf` 바이트 비교 한 줄로 끝난다 |
| 2 | 요구사항·설계 결정(**이름·범위**)을 은수님이 `AskUserQuestion` 으로 **직접 확정**했다. 계획 승인 게이트가 이미 지나갔다 |
| 3 | 신규 로직 0, 분기 0, 상태 0 |

다만 추적성을 위해 이 기록과 [`구현-검증.md`](구현-검증.md) 는 남긴다.

## 판단 기록

### 판단_1 - 왜 한 곳에 모으는가

값이 흩어져 있으면 **상호 순서 관계가 안 보인다.** 이번 조사에서 드러난 것:

```
CUTOFF(40) > STIM_ALERT(20) = MAP_LOW(20) > LED_CRITICAL(10)
```

이 순서 때문에 **방전 중에는 40% 에서 먼저 꺼지므로 LED CRITICAL(10%)을 볼 수 없다.** 충전 경로(`handle_charging()` - `battery_percent` 를 인자로 아예 받지 않는다)에서만 보인다. 값이 `tdc_sys_control.c` 와 `main.c` 에 흩어져 있으면 이 사실이 코드에서 드러나지 않는다.

그래서 **정의를 한 블록에 모으고 순서 관계를 주석으로 명시**했다. 은수님이 말한 *"까먹는 경향"* 의 실제 대상은 개별 값이 아니라 **값들 사이의 관계**다.

### 판단_2 - 배터리는 헤더, 시간은 `.c` 상단

| 대상 | 위치 | 이유 |
|---|---|---|
| 배터리 5개 | `pwr/tdc_pwr_battery.h` | **두 파일이 쓴다.** 두 파일 모두 이미 이 헤더를 include 하므로 새 의존이 0 |
| 시간 3개 | `sys/tdc_sys_control.c` 상단 | **한 파일만 쓴다.** 헤더로 올리면 불필요하게 노출된다 |

규칙: **여러 파일이 쓰면 헤더, 한 파일이면 그 파일 상단.**

### 판단_3 - 죽은 매크로 2건을 함께 제거

`tdc_sys_control.c:31`·`:33` 의 두 매크로는 **정의만 있고 사용처가 전 코드베이스에 0건**이었다.

| 매크로 | 값 | 상태 |
|---|---|---|
| `LED_OnTime_afterCoverClosed` | 4501 | 사용처 0 |
| `BLE_OffTimeAfterISD_Disconnected` | 1000 | 사용처 0. **실제 동작은 `:59` 의 벌거벗은 `640`** |

후자가 특히 나빴다. **이름이 정확히 그 용도인데 값이 다르다**(1000 vs 640). 이 상태에서 `TDC_SYS_BLE_OFF_DELAY_MS 640` 을 새로 만들면 *"1000 짜리와 640 짜리 중 뭐가 진짜지"* 가 되어 **혼란이 커진다.** 작업 목적이 혼란 제거인데 반대로 가므로 함께 제거했다.

### 판단_4 - `TDC_BATT_LED_CRITICAL_PCT` 의 사용 위치

이 상수(10)는 LED 경계 테이블에서 **MID 행의 하한**으로 쓰인다.

```c
{TDC_BATT_LED_READY_PCT,    TDC_LED_ST_BATT_READY},    /* pct >= 80      */
{TDC_BATT_LED_CRITICAL_PCT, TDC_LED_ST_BATT_MID},      /* 10 <= pct < 80 */
{0,                         TDC_LED_ST_BATT_CRITICAL}, /* pct <  10      */
```

이름은 CRITICAL 인데 행은 MID 라 살짝 어긋나 보인다. 의미는 정확하다 - *"이 값 미만이면 CRITICAL"* 이고, 테이블 구조상 그 값이 MID 행의 하한이 된다. 은수님이 확정한 이름이라 유지하고 헤더 주석으로 관계를 적었다. `TDC_BATT_LED_MID_PCT` 로 바꾸면 표와 더 자연스럽게 읽히므로, 선호가 있으시면 알려주시면 된다.
