# 저전력 모드 전환 영향 분석

**TL;DR**: `func_sleep()`의 `ci_power_sleep()` 활성화로 SYSCLK 30.72 → 2.56 MHz(약 1/12) 전환 시 SDMCLK 1/384, ADCCLK 1/48, UCLK 1/24576까지 떨어지며 SLOWCLK·SLOWCLK_DIV32만 분주 보정으로 유지됨. 영향 받는 서브시스템(TIMER3·워치독·I2C·LED·터치 폴링) 별 정량 분석과 구체적 변경안을 제시 — 칩 스펙 근거는 별도 참고/칩/Ezairo 8300 클럭·타이머·I2C 스펙 정리.md 참조.

## 배경

`func_sleep()` 의 `// ci_power_sleep();` 를 활성화하여 SYSCLK 을 **30.72 MHz → 2.56 MHz** 로 전환하려고 함. 배수 약 1/12. 저전력 모드 진입 후 다음 서브시스템이 영향을 받음:

- 일반 목적 타이머 (TIMER3, 현재 1ms 주기 가정)
- 워치독 리프레시 간격
- I2C 마스터 통신 속도
- ULP 루프의 LED 깜빡임, 터치 폴링

본 문서는 각 영향을 정량 분석하고 구체적 변경안을 제시. 스펙 근거는 별도 문서 [`참고/칩/Ezairo 8300 클럭·타이머·I2C 스펙 정리.md`](../../../참고/칩/Ezairo%208300%20클럭·타이머·I2C%20스펙%20정리.md) 참조.

## 1. 현재 vs 목표 클럭 비교

### 1.1 ci_power.c 에서 정의된 설정값

[ci_power.c:155](../src/2__cm3/Gen1_5/common/ci_power.c) (Active)
```c
D_CLK->CFG_1 = (ADCCLK_PRESCALE_8 | ADCCLK_SRC_SYSCLK
              | SDMCLK_PRESCALE_2
              | SLOWCLK_PRESCALE_24 | SLOWCLK_SRC_SYSCLK
              | UARTCLK_SRC_SYSCLK);
D_CLK->CFG_2 = (UCLK_PRESCALE_8 | UCLK_SRC_ADCCLK);
```

[ci_power.c:170](../src/2__cm3/Gen1_5/common/ci_power.c) (Sleep)
```c
D_CLK->CFG_1 = (ADCCLK_PRESCALE_32 | ADCCLK_SRC_SYSCLK
              | SDMCLK_PRESCALE_64
              | SLOWCLK_PRESCALE_2 | SLOWCLK_SRC_SYSCLK
              | UARTCLK_SRC_SYSCLK);
D_CLK->CFG_2 = (UCLK_PRESCALE_4096 | UCLK_SRC_ADCCLK);
```

### 1.2 파생 클럭 주파수 (계산값)

| 클럭 | 소스·분주 (Active) | Active 값 | 소스·분주 (Sleep) | Sleep 값 | 비율 |
|---|---|---:|---|---:|---:|
| **SYSCLK** | CCO 30.72M | **30.72 MHz** | CCO 2.56M | **2.56 MHz** | 1/12 |
| SDMCLK | SYSCLK/2 | 15.36 MHz | SYSCLK/64 | 40 kHz | 1/384 |
| ADCCLK | SYSCLK/8 | 3.84 MHz | SYSCLK/32 | 80 kHz | 1/48 |
| **SLOWCLK** | SYSCLK/24 | **1.28 MHz** | SYSCLK/2 | **1.28 MHz** | **1 (유지)** |
| **SLOWCLK_DIV32** | SLOWCLK/32 | **40 kHz** | SLOWCLK/32 | **40 kHz** | **1 (유지)** |
| UCLK | ADCCLK/8 | 480 kHz | ADCCLK/4096 | **19.5 Hz** | 1/24576 |
| UARTCLK | SYSCLK | 30.72 MHz | SYSCLK | 2.56 MHz | 1/12 |

### 1.3 핵심 관찰

1. **SLOWCLK 과 SLOWCLK_DIV32 는 변화 없음** — `SLOWCLK_PRESCALE` 을 24→2 로 동시 조정한 의도적 설계. 스펙이 "SLOWCLK = 1.28 MHz 고정" 을 강력 권고 (HW p.315).
2. **공식 "Standby 모드" 가 아님** — CCO 는 살아있고 저주파로만 동작. `SYSCLK_SEL_STANDBY` 는 쓰지 않음. 따라서:
   - SLOWCLK_DIV32 가 우회(=SYSCLK) 되지 않음. **/32 분주 그대로 유효.**
   - I2C 자동 disconnect 동작하지 않음. `CONNECT_IN_STANDBY` 비트 설정 불필요.
3. **SYSCLK 파생 클럭만 비례 느려짐** — SDMCLK, ADCCLK, UARTCLK, I2C SCL, UCLK.

## 2. 일반 목적 타이머 (TIMER3) 영향 분석

### 2.1 타이머 클럭 소스

HW §19.8: "The general-purpose timers are clocked from **SLOWCLK, divided by 32**."

→ 타이머 입력 클럭 = **SLOWCLK_DIV32 = 40 kHz (Active/Sleep 둘 다 동일)**

### 2.2 타이머 주기 공식 (HW p.763 원문)

$$T = \frac{2^{\text{PRESCALE}} \times (\text{TIMEOUT\_VALUE} + 1)}{f_{\text{SLOWCLK\_DIV32}}}$$

| 필드 | 특성 |
|---|---|
| `PRESCALE` (3-bit) | 2 의 지수. 0 → ×1, 1 → ×2, ..., 7 → ×128 |
| `TIMEOUT_VALUE` (24-bit) | **`+1` 된** 값이 사이클 수 |

### 2.3 현재 코드 검산

[ci_timer.c:152](../src/2__cm3/Gen1_5/common/ci_timer.c):
```c
Sys_Timer_Config(TIMER3, TIMER_PRESCALE_1, TIMER_FREE_RUN, tick);
```

- PRESCALE field = 0 (`TIMER_PRESCALE_1` = 2^0 = 1)
- tick = 19 → TIMEOUT_VALUE+1 = 20
- **T = 1 × 20 / 40 kHz = 500 μs**

주석 `/* Make around 1msec timer */` 과 약 2배 오차. GPIO 토글 측정 시 관측 주기(1 ms = 0.5 ms × 2) 와 혼동했을 가능성. 헤더의 `OTE_1_5_GEN_TIMER_TICK_1MS_PM_NORMAL = 39` 가 정확한 1 ms 값 (2^0 × 40 / 40k = 1 ms 완료).

### 2.4 Sleep 모드에서의 타이머 동작

**SLOWCLK_DIV32 유지 → 타이머 주기도 유지**. 재설정 불필요.

### 2.5 롱-터치 전용 긴 주기 타이머 설계

**요구사항** (사용자 지시):
- 1 ms 웨이크업 불필요 — 롱-터치 3 s 감지만 가능하면 됨
- 타이머 주기를 길게, WFI 로 거의 내내 sleep
- 워치독 (기본 3.28 s) 타임아웃 회피

**주기 후보** (PRESCALE_128 기준, 2^7 × (N+1) / 40k):

| TIMEOUT_VALUE | 주기 | 3s 감지 카운트 | 워치독 여유 |
|---:|---:|---:|---|
| 155 | 499.2 ms | 6회 | ×6.5 |
| 311 | 998.4 ms | 3회 | ×3.3 |
| 467 | 1497.6 ms | 2회 | ×2.2 |

**추천: 500 ms 주기 (TIMEOUT_VALUE=155, PRESCALE_128), 6회 카운트**. 워치독 여유 ×6.5 로 충분한 마진.

### 2.6 타이머 래퍼 함수 추가 필요

현재 `ci_timer_init(uint32_t tick)` 은 PRESCALE 하드코딩. 긴 주기 전용 오버로드 필요:

```c
int ci_timer_init_prescaled(uint32_t prescale_field, uint32_t tick);
```

내부 구현은 `Sys_Timer_Config(TIMER3, prescale_field, TIMER_FREE_RUN, tick)` 호출. 기존 `ci_timer_init` 는 하위 호환 위해 그대로 유지 (내부에서 `ci_timer_init_prescaled(TIMER_PRESCALE_1, tick)` 호출).

## 3. 워치독 영향 분석

### 3.1 워치독 클럭

HW §19.9: "The watchdog timer runs on the SLOWCLK_DIV32 divided by 32." → 실효 SLOWCLK/1024 = 1.25 kHz

**SLOWCLK 유지 → 워치독 타임아웃도 유지** (기본 3.28 s).

### 3.2 리프레시 주기 요구사항

- 현재 ULP 루프: `SYS_WATCHDOG_REFRESH()` 매 루프 호출
- 타이머 475 μs 주기 → 루프 속도 약 1000 Hz → 워치독 타임아웃(3.28s) 대비 매우 여유
- **변경 불필요**

## 4. I2C 영향 분석

### 4.1 현재 설정

[driver_i2c.h:12](../src/2__cm3/Cortex-M3-src/systemControl/driver_i2c.h)
```c
#define I2C_MASTER_PRESCALE_240 ((uint32_t) (0x4FU << I2C_CFG_MASTER_PRESCALE_Pos))  // 128 kHz
```

- PRESCALE = 0x4F = 79
- SCL = SYSCLK / ((79+1) × 3) = SYSCLK / 240

### 4.2 Sleep 모드에서의 SCL

동일 PRESCALE 로 SYSCLK 만 낮아지면:
```
SCL_sleep = 2.56 MHz / 240 = 10.67 kHz
```

**IQS323 동작 가능 여부**
- IQS323 데이터시트 상 I2C Standard-mode(100 kHz)·Fast-mode(400 kHz) 지원
- 최저 동작 주파수는 데이터시트에서 명시되지 않는 경우가 많음. 일반적으로 Standard I2C 디바이스는 **몇 kHz 까지도 동작 가능**.
- 다만 **IQS323 내부 타임아웃** (SDA/SCL idle 시 자체 상태 리셋 등) 고려 필요 → 데이터시트 재확인 권장.

**SYSCLK 최소 요구사항**
- HW §18.4.3: Fast-mode(400 kbps) 엔 SYSCLK ≥ 1.5 MHz. Standard-mode(100 kbps) 는 명시 없음. 2.56 MHz SYSCLK 에서 Fast-mode 까지는 여유 있음.

### 4.3 PRESCALE 변경 옵션

IQS323 의 규격 이내에서 SCL 이 약 100 kHz 유지되도록:

| PRESCALE | hex | (P+1)×3 | SCL @ 2.56MHz |
|---|---|---:|---:|
| 6 | 0x06 | 21 | **122 kHz** 완료 권장 |
| 7 | 0x07 | 24 | 107 kHz |
| 8 | 0x08 | 27 | 95 kHz |

**추천: PRESCALE = 0x06 (21 분주) → 약 122 kHz**

### 4.4 구현 시 고려사항

- PRESCALE 은 `I2C*_CFG` 레지스터 비트 [15:8]. `ci_power_sleep()` 복귀 후에도 그대로 유지되면 Active 모드에서 SCL = 30.72M/21 = 1.46 MHz 로 Fast-mode Plus 한계(1 MHz) 초과 → **Sleep 모드 진입 시 변경, 복귀 시 복원 필요**.
- 현재 구현은 Sleep 모드에서 다시 Active 로 복귀하지 않고 워치독 리셋으로 재부팅하므로 **복원 고려 불필요**. Sleep 진입 시 PRESCALE 만 덮어쓰면 됨.

### 4.5 수정 방식 선택

**X안: Sleep 모드 전용 헤더 매크로 추가 + 런타임 재설정**
- 예: `I2C_MASTER_PRESCALE_21` 추가, `ci_power_sleep()` 호출 직후 `I2C0->CFG` 재기록.

**Y안: 저속 그대로 수용 (10.67 kHz)**
- IQS323 데이터시트 확인 후 이 속도에서도 확실히 동작한다면 코드 변경 없음.
- 단점: 터치 상태 읽기 latency 증가 (전송 12배 느림).

**추천: X안**. 안정 마진 확보 + 응답성 유지. IQS323 실기 테스트가 이미 128 kHz 에서 안정 동작 확인되었으므로 동일 수준 유지.

## 5. ULP 루프 재설계

긴 주기 타이머 + WFI + 카운터 기반 롱-터치 판정으로 전면 재설계.

### 5.1 새 루프 구조

```c
// func_sleep() 내부, ci_power_sleep() 후
ci_timer_init_prescaled(TIMER_PRESCALE_128, 155);  // ≈ 500 ms

int touch_cnt = 0;

while (1)  // ULP loop
{
    SYS_WAIT_FOR_INTERRUPT;     // 500 ms idle
    SYS_WATCHDOG_REFRESH();     // 매 웨이크업마다 refresh

    tdc_touch_state_t state;
    if (tdc_touch_get_state(&state) && state == TDC_TOUCH_STATE_TOUCH)
    {
        if (++touch_cnt >= 6)   // 6 × 500ms = 3s
        {
            ci_printi("[MAIN] LONG TOUCH, RESET \r\n");
            delay_ms(20);
            SYS_WATCHDOG_RESET();
        }
    }
    else
    {
        touch_cnt = 0;
    }
}
```

### 5.2 제거되는 코드

기존 [main.c:689-771](../src/2__cm3/Cortex-M3-src/main.c) 의 다음 로직 모두 제거:

- `long_touch_event_cnt` 상태머신 (0/1)
- `blue_cnt`, `cyan_cnt`, `color_type` 변수
- cyan ↔ blue LED 깜빡임 switch 문
- 가속도 센서 / 캐링케이스 인터럽트 (이미 `#if 0` 블록)

### 5.3 tdc_touch 레이어와의 관계

**롱-터치 판정을 main.c 의 카운터로 이동** → `tdc_touch_process()` 는 ULP 모드에서 호출하지 않음.

- `tdc_touch_get_state()` 만 호출하여 즉시 상태 조회
- `proc_long_touch()` 의 tick 기반 판정은 현재 run 모드에서만 유효 (tick 증가 주기 가정)
- ULP 모드에선 main.c 의 `touch_cnt` × 500ms 로 판정

tdc_touch 레이어 자체는 변경 불필요. 단지 ULP 루프 안에서 `tdc_touch_process()` 대신 `tdc_touch_get_state()` 만 사용.

### 5.4 소비 전력 추정

- 기존: 500 μs 마다 CPU wake → ISR 실행 → WFI 복귀. 초당 2000회 wake.
- 신규: 500 ms 마다 wake → 샘플링 → WFI. 초당 2회 wake.
- **wake 빈도 1000배 감소** + CPU clock 12배 감소 → 동적 전력 대폭 절감.

## 7. 스펙 근거 한줄 요약

| 결론 | 스펙 근거 |
|---|---|
| SLOWCLK = 1.28 MHz 로 고정 유지해야 함 | HW §10.2.4: "optimized for a SLOWCLK frequency of 1.28 MHz" |
| 타이머는 SLOWCLK/32 로 동작 | HW §19.8: "clocked from SLOWCLK, divided by 32" |
| SLOWCLK_DIV32 는 공식 Standby 모드에서만 우회 | HW §10.2.4: "disabled... when the STANDBYCLK is selected as the SYSCLK source" |
| 현재 방식은 공식 Standby 모드가 아님 | ci_power.c 는 `tdc_Trims_SetOperatingFrequency` (프로젝트 래퍼) 만 호출, `SYSCLK_SEL_STANDBY` 는 안 씀 |
| I2C SCL = SYSCLK / ((PRESCALE+1)×3) | HW §18.4.5.1: "SCL is prescaled by (PRESCALE + 1) × 3" |
| 2.56 MHz SYSCLK 에서 Fast-mode 가능 | HW §18.4.3: "at least 1.5 MHz for Fast-mode" |

## 부록 A. 변경 작업 우선순위

1. 롱-터치 해제 감지 제거 (스펙 의존성 없음, 즉시 착수 가능)
2. `ci_power_sleep()` 주석 해제 (단독 효과 검증 — I2C 속도 저하 외 큰 변화 없어야 함)
3. I2C PRESCALE 재설정 추가 (실기 테스트로 122 kHz 동작 확인)
4. 통합 검증 — 실기에서 Sleep 진입 → 터치 감지 → 워치독 리셋 확인

각 단계가 독립적으로 빌드·동작 가능하도록 분할.
