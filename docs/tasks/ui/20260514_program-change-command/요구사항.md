# 요구사항: UI 명령어로 프로그램(맵) 변경

**TL;DR**: `tdc_ui_command.c`의 RTT 디버그 콘솔에 프로그램(맵) 변경 명령어를 추가한다. 1~4를 입력하면 `changeProgramMapNum(N)`을 호출해 맵을 전환한다. 단, **ISD 연결 + LiveStimulationStandAlone 모드** 두 조건이 모두 충족된 상태에서만 동작하고, 그 외 상태에서는 거부 메시지를 출력한다.

## 1. 배경

`tdc_ui_command.c`는 RTT 디버그 콘솔로 사용되며, 현재 다음 핸들러를 제공한다 ([`src/2__cm3/Gen1_5/ui/tdc_ui_command.c`](../../../../src/2__cm3/Gen1_5/ui/tdc_ui_command.c)):

| 명령어 | 기능 |
|---|---|
| `--help` | 사용 가능한 명령어 목록 |
| `--led ...` | LED 상태/패턴 override 및 확인 |
| `--batt ...` | 배터리 % override |
| `--isd on\|off` | ISD 연결 override |
| `--map on\|off` | (BLE) 매핑 연결 override |
| `--err ...` | 에러 주입 |
| `--vol <1~10>` | 오디오 볼륨 변경 |
| `--init_all_map` | 모든 맵 초기화 |
| `--dump_log` | 이벤트 로그 덤프 |
| `--write_integrity_err` | 무결성 에러 기록 |

기존 명령들은 LED·배터리·매핑 상태 override나 일회성 트리거가 대부분이고, **프로그램(맵) 번호를 디버그 콘솔에서 직접 전환하는 수단이 없다.** 디버깅·검증 작업 중 BLE 리모컨이나 매핑 앱 없이 맵 전환을 시도해야 할 때 외부 도구가 필요하다.

## 2. 사용자 요청

원문:
> tdc_ui_command.c 를 활용해서 프로그램 변경에 대한 명령어를 추가해야 해.
> * changeProgramMapNum() 함수에 1~4를 입력하면 프로그램을 변경할 수 있어.
> * ISD가 연결된 상태, LiveStimulationStandAlone 모드 상태여야 해.

## 3. 요구사항

### 요구사항_1: 새 명령어 추가

`tdc_ui_command.c`에 프로그램(맵) 번호 변경 명령어 1건 신설. 명령어 이름·문법은 §4 디자인 결정에서 확정 후 사용자 승인.

### 요구사항_2: 입력 범위 1~4

- 입력값 = `1, 2, 3, 4` 중 하나
- 범위 밖이면 에러 메시지 출력 + 동작 거부

### 요구사항_3: 동작 = `changeProgramMapNum(N)` 호출

성공 시 [`cfx_cm3_sharedMemory.c:464`](../../../../src/2__cm3/Cortex-M3-src/systemControl/cfx_cm3_sharedMemory.c) 의 `changeProgramMapNum(N)` 을 그대로 호출. 부수 효과는 기존 함수에 위임 (EEPROM 맵 데이터 복사·FFT pass bin 읽기·`setCommandMapChange_Cm3ToCfx()`·`set_newMapLoadeFlagForStimulParaSetting()`).

### 요구사항_4: 전제 조건 — ISD 연결 + LiveStimulationStandAlone 모드

다음 두 조건이 **모두** 충족된 상태에서만 동작:

- **(가)** ISD가 연결된 상태
- **(나)** LiveStimulationStandAlone 모드 상태 (= 매핑 앱 미연결 + 자극 출력 활성)

조건 미충족 시: 명령 거부 + 사유 출력 + `changeProgramMapNum()` 미호출.

> [!NOTE]
> 두 조건의 구체 판별 함수·변수 매핑은 ②분석 단계에서 확정.

### 요구사항_5: 출력 메시지

기존 핸들러 컨벤션 ([cfx_cm3_sharedMemory.c:464](../../../../src/2__cm3/Gen1_5/ui/tdc_ui_command.c) `output_printf` 사용, `OK:` / `invalid` / `unknown` prefix) 일관 유지:

- 성공: `OK: program = <N>` (또는 유사)
- 범위 오류: `invalid: 1~4`
- 전제 조건 미충족: `denied: <사유>` (예: `denied: ISD not connected`, `denied: not in LiveStimulationStandAlone mode`)

### 요구사항_6: 기존 코드 컨벤션 준수

- 정적 함수명: `handle_program` (또는 유사, 기존 `handle_volume` 등 패턴) — `tdc_` prefix는 static handler엔 미적용 (기존 코드와 일관)
- 등록 테이블 (`s_tdc_commands[]`)에 신규 entry 추가
- `--help` 출력에 자동 노출 (테이블 등록 시 자동 처리됨)

## 4. 디자인 결정 — ②분석 단계에서 확정 후 ③계획 단계 승인

| 결정 항목 | 후보 | 비고 |
|---|---|---|
| 명령어 이름 | `--prog` / `--map_num` / `--program` | `--map`은 이미 매핑 override로 사용 중 → 충돌 회피 |
| 인자 형식 | `--prog <1~4>` | `--vol <1~10>` 패턴 차용 |
| ISD 연결 판별 | `isIsdConnected()` / `read_connected_ISD_Num() != 0` / `snd_isd_interface_get_state().conneded_ISD` | 분석 단계 확인 |
| StandAlone 모드 판별 | `BLE_communicationState.mappingConnection == false` + ISD 자극 상태 | 분석 단계 확인 |
| Override (`--map on`)와의 관계 | override 영향 받을지 / 실 상태만 볼지 | 분석 단계 결정 |

> [!IMPORTANT]
> 추천 (작성자 1차 의견): 명령어 = **`--prog <1~4>`**, 가드 판별은 **실 상태만**(override 무시) — 이유는 분석.md/계획.md에 정리하고 ③ 계획 단계에서 사용자 승인 받음.

## 5. 검증 기준 (AC)

| 항목 | 통과 기준 |
|---|---|
| AC-1 | ISD 연결 + StandAlone 모드에서 `--prog 1` 입력 → `changeProgramMapNum(1)` 호출 + `OK` 출력 |
| AC-2 | 동일 조건 `--prog 2/3/4` 각각 호출 정상 |
| AC-3 | `--prog 0`, `--prog 5`, `--prog abc` → `invalid` 메시지 + 미호출 |
| AC-4 | ISD 미연결 상태 → `denied: ISD not connected` (또는 유사) + 미호출 |
| AC-5 | 매핑 앱 연결 상태 (mappingConnection=true) → `denied: not in LiveStimulationStandAlone mode` + 미호출 |
| AC-6 | `--help` 출력에 신규 명령어 자동 노출 |
| AC-7 | 기존 명령어 동작 회귀 없음 (`--led show` 등 random 1~2건 확인) |
| AC-8 | 빌드 경고 0, 신규 빌드 에러 없음 |

## 6. 범위 외 (Non-goal)

- 사용 가능한 맵 인덱스 (`readConnected_ISD_usableMapIndex()`) 자동 skip — 본 명령은 강제 전환 (디버그 도구) 목적. 사용자 입력 그대로 호출.
- 맵 전환 후 LED 표시·자극 출력 검증 — `changeProgramMapNum()` 내부에 위임 (회귀 검증 범위에서 가시 확인만)
- 다른 UI 명령어와 묶음 변경

## 7. 위험·고려사항

| 위험_1 | StandAlone 모드 판별 변수 위치·접근 가능성 — 분석 단계에서 확정 |
| 위험_2 | `--map on/off` override가 실 상태 판별에 영향을 줄 수 있는가 — 분석 단계에서 확정 |
| 위험_3 | `changeProgramMapNum()` 호출이 비동기 효과 (CFX 명령) — 즉시 OK 출력해도 실제 적용은 다음 cycle에 일어남 (출력 메시지에 이를 반영할지 결정) |
