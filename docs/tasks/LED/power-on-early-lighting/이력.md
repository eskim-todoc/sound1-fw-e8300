## 4. 사후 fix history (학습 큰 사건)

### 4.1 Fix A — tdc_touch_init_begin() 위치 (2026-05-04)

#### 현상
V10 검증에서 워치독 리셋 (3초 터치 슬립 → 깨움) 시 SPI 에러 회귀 (`DMA0/1_CNTS->TRANSFER_WORD_CNT_SHORT`).

#### 1차 가설 (사후 무효 확인)
P11 (`tdc_touch_init_begin()`) 이 init_I2c 직후라 `init_cm3_SPI()` 시점이 늦어져 NRF 잔존 SPI 통신과 race.

#### 적용
P11 위치를 `init_cm3_SPI()` 직후로 이동 (commit `8803e29`).

#### 사후 분석 (2026-05-06)
- **가설 약점 확인**: I2C 와 SPI 는 별개 버스라 P11 위치 (`init_I2c()` 직후) 가 직접 `init_cm3_SPI()` 와 race 경로 없음
- **NRF 코드 모두 dead** ([`ResetNRF()`](../../../../src/2__cm3/Cortex-M3-src/systemControl/initialize.c#L74), [`NRF_Off_Command()`](../../../../src/2__cm3/Cortex-M3-src/systemControl/systemControl.c) 의 `Sys_GPIO_Set_*` 모두 주석)
- **근본 원인은 별개**: 사용자 피드백 (NRF→QCC 교체 레거시, SPI master = QCC, ISD_CHECK 와 batt/charge 송신 게이트 불명) 조합 분석 결과 V10 SPI race 의 본질은 **QCC wakeup 후 첫 SPI burst timing** 이며 CM3 측 fix 만으로는 해결 못 함

#### 결과
- Fix A 의 가설은 무효이지만 **코드 변경 자체는 더 안전한 시점으로 정착** — `init_cm3_SPI()` 직후 = SPI bus init 직후이므로 터치 MCLR 펄스 발생 시 SPI line 영향 가능성 최소화. 보수적 위치 유지
- V10 SPI 에러 자체는 본 작업 외부 이슈로 분리 (§5)

### 4.2 Fix B-LED — POWER_OFF burst race 시리즈 (2026-05-06)

#### 발견 경위
사용자 V10 재테스트 중 부수적으로 POWER_OFF 양상 변화 보고. 본 작업의 **ISR 책임 분리 (commit `cecbc3d`) 가 도입한 race**.

#### Root cause
`led_arbiter_tick()` 가 CFX_0 ISR 에서 제거되어 TIMER3 ISR 단독 실행 → main loop iter 와 비동기 → `LedOutputPattern` 이 1-tick stale 상태 → systemControl 의 burst 종료 검출 (`current_led_pattern != en__LED_POWER_Off`) 이 stale=`en__LED_NA` 시 즉시 true → systemOff 트리거 → `led_force_fade_off()` → POWER_OFF burst 미표시.

#### 적용 단계

| Fix | Commit | 변경 |
|---|---|---|
| Fix B-LED-1 | `dcd1204` | systemControl 의 burst 종료 검출을 `!led_is_power_burst_in_progress()` 함수로 변경. burst flag 는 `led_engine_run()` 이 직접 set/clear 하므로 ISR phase 무관 정확 |
| Fix B-LED-2 | `211cc15` | LedOutput.c `led_engine_run()` reset 분기 시작에서 `if (p->burst_cnt > 0) s_power_burst_in_progress = true;` 즉시 set — fade-out Phase A 동안에도 burst 진행 중으로 표현. **검증 전 본질 전환** |
| Fix B-LED-3 (최종) | `9876044` | timer/tick 기반 set 의 race risk 회피 — flag set/clear 책임 명확 분리. **set**: `led_request()` 가 burst 패턴 (`burst_cnt > 0`) 요청 시점 즉시 (외부 호출). **clear**: `led_engine_run()` 이 burst 자가 해제 시 (LED 핸들러 내부). + 네이밍 컨벤션 적용 (`s_tdc_burst_pending`, `tdc_led_is_burst_pending()`). 호출처 4곳 갱신 (systemControl.c × 2, tdc_ui_command.c × 2) |

#### 검증
사용자 재측정 OK — POWER_OFF 패턴 일관 표시 확인.

#### 학습 (회고 후보)
- **ISR 책임 분리 시 main loop 와 동기화 가정 의존성 확인 필수** — 한 ISR 에서만 갱신되던 상태가 분리 후 stale 보일 수 있음
- **타이머/tick 기반 flag 갱신은 race 잠재** — flag 의 set/clear 주체를 외부/내부로 명확 분리하면 timer 무관 정확
- **Fix 의 근본 분석 = 가설 단일화 회피** — Fix A 의 첫 가설 약점을 추후 발견. 처음부터 가설 3 개 cross-check 했으면 더 좋았음 ([분석·디버깅 규칙](../../../../../docs/지침/코딩/분석·디버깅%20규칙.md) §2 적용 사례)

## 5. V10 SPI 잔존 이슈 — 본 작업 외부 (이후 필요 시 재개)

### 5.1 현상

ULP wakeup (사용자가 의도적으로 트리거 한 시나리오) 시 SPI1_COM_IRQHandler 의 CS_RISE 검사에서 `DMA0_CNTS->TRANSFER_WORD_CNT_SHORT (1)` 와 `DMA1_CNTS->TRANSFER_WORD_CNT_SHORT (3)` 출력. 첫 패킷 부분 송수신 후 자가 복구 (~931 ms 소요).

cold boot (#1) 와 wakeup (#2) 비교 측정값:

| 측정 | #1 cold (정상) | #2 wakeup (오류) |
|---|---|---|
| `[TOUCH] INIT FINISH ELAPSED` (t3_tick 단위) | 178 ms (chip 새 ATI) | **33 ms** (chip 잔존, 즉시 done) |
| `[FAKE_0x34] WAIT` (main_tick 단위) | 55 ms | **931 ms** (자가 복구 후 정상 batt 정보) |
| SPI 에러 | 없음 | 있음 (DMA0=1, DMA1=3) |

### 5.2 분석 결과 (이번 세션 cross-check 후)

- **DIO24 (QCC_CTRL) 외부 풀-다운 10K** → warm reset 시 GPIO INPUT fallback 시점에도 LOW 자동 → QCC SHUTDOWN 진입. **CM3 측 GPIO 잔존 가설은 폐기**
- **IQS323 전원 유지** → 33 ms ELAPSED (chip 잔존 ATI) 정확히 설명
- **QCC 동작 (담당자 피드백)**: SYS_CTRL=0 → 약 2 초 후 딥슬립, =1 → 깨어남 (전원 cycle 과 동일). 깨어나면 기본 시스템 정보 SPI 송신
- **사용자 관찰의 모순**: ISD_CHECK=0 인데도 batt/charge 정보 도착 → QCC 측 송신 게이트 가정과 실제 펌웨어 동작 불일치
- **결론**: SPI race 의 본질은 **QCC NORMAL 진입 직후 internal wakeup + SPI master init 도중 CS / clock line 첫 burst 가 짧게 잡히는 것**. CM3 측 fix (delay·silent retry 등) 는 임시 mitigation 일 뿐 진짜 해결 아님. **QCC 펌웨어 시퀀스 명확화 (담당자 영역)** 가 본질

### 5.3 결정

본 작업의 회귀가 아니라 **V10 검증 강화로 노출된 잠재 이슈**. 본 작업 (LED 조기 점등 + 터치 병렬화) 의 V1~V9 목표는 달성. 본 작업과 SPI race 는 도메인 분리 가능.

→ **V10 SPI 항목은 본 작업 외부로 분리. 별도 task 신설 없이 종결.** 이후 필요 시 본 이력.md §5.2 분석을 시발점으로 새 작업을 다시 열 수 있다 (사용자 결정 2026-05-06).

| `g_tdc_timer_t3_tick` / `tdc_timer_get_t3_tick()` 사용처 | LED arbiter (간접 — fade·burst 카운터 자체는 ISR 호출 주기 기준 유지) + tdc_touch (`s_mclr_done_tick` 기준) |
| `tdc_touch_init_begin()` 호출자 | systemControl `StartFlag` 분기 → Initialize() ParLED P11 (init_cm3_SPI 직후) 로 이관. 호출자 변경 (Initialize) |
| `led_request()` 호출자 | Fix B-LED-3 — burst 패턴 (`burst_cnt > 0`) 요청 시 `s_tdc_burst_pending = true` set 부수효과 추가 |
| `tdc_led_is_burst_pending()` (Fix B-LED-3 신규) | systemControl × 2 + tdc_ui_command × 2 (4 곳) |
| `systemControl.c` `StartFlag == false` 분기 | 분기 골격 (if/else, `Led_Pattern` 셋업, `StartFlag`, `PowerOn_StartCounter`) 보수적 유지. 분기 안 LED·터치 init 호출만 제거. 변수 자체 cleanup 은 별도 작업 위임 (현재 사용처 dead 확인) |

## 7. 후속 작업

- **systemControl `StartFlag` 분기 cleanup** — 본 작업에서 분기 골격은 보수적 유지. 변수 (`StartFlag`, `PowerOn_StartCounter`) read 가 dead 임을 확인했으므로 별도 cleanup task 후보
- **NRF dead code 정리** — `ResetNRF()` / `NRF_Off_Command()` / `NRF_On_Command()` 의 `Sys_GPIO_Set_*` 모두 주석. NRF51 → QCC 교체 (사용자 피드백) 의 잔재. 별도 정리 task 후보 (`legacy/nrf-cleanup` 같은 이름)
- **V10 SPI race (필요 시 재개)** — §5 분석을 시발점으로. QCC 담당자 펌웨어 시퀀스 (특히 wakeup 후 첫 SPI burst timing, ISD_CHECK 게이트 가정) 확인 후 진행
- **`ci_timer.c` 전체 `tdc_timer.c` 리팩토링** — Q10=A 결정의 trade-off (`g_ci_*` / `g_tdc_*` 혼재) 해소
