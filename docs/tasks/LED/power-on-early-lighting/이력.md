## 4. 사후 fix history (학습 큰 사건)

### 4.1 Fix A — tdc_touch_init_begin() 위치 (2026-05-04)

#### 현상
V10 검증에서 워치독 리셋 (3초 터치 슬립 → 깨움) 시 SPI 에러 회귀 (`DMA0/1_CNTS->TRANSFER_WORD_CNT_SHORT`).

#### 1차 가설 (사후 무효 확인)
P11 (`tdc_touch_init_begin()`) 이 init_I2c 직후라 `init_cm3_SPI()` 시점이 늦어져 NRF 잔존 SPI 통신과 race.

#### 적용
P11 위치를 `init_cm3_SPI()` 직후로 이동 (commit `8803e29`).

#### 사후 분석 (2026-05-06)
- **가설 약점 확인**: I2C 와 SPI 는 별개 버스라 P11 위치 (`init_I2c()` 직후) 가 직접 `init_cm3_SPI()` 와 race 경로 없음
- **NRF 코드 모두 dead** ([`ResetNRF()`](../../../../src/2__cm3/Cortex-M3-src/systemControl/initialize.c#L74), [`NRF_Off_Command()`](../../../../src/2__cm3/Cortex-M3-src/systemControl/systemControl.c) 의 `Sys_GPIO_Set_*` 모두 주석)
- **근본 원인은 별개**: 사용자 피드백 (NRF→QCC 교체 레거시, SPI master = QCC, ISD_CHECK 와 batt/charge 송신 게이트 불명) 조합 분석 결과 V10 SPI race 의 본질은 **QCC wakeup 후 첫 SPI burst timing** 이며 CM3 측 fix 만으로는 해결 못 함

#### 결과
- Fix A 의 가설은 무효이지만 **코드 변경 자체는 더 안전한 시점으로 정착** — `init_cm3_SPI()` 직후 = SPI bus init 직후이므로 터치 MCLR 펄스 발생 시 SPI line 영향 가능성 최소화. 보수적 위치 유지
- V10 SPI 에러 자체는 본 작업 외부 이슈로 분리 (§5)

### 4.2 Fix B-LED — POWER_OFF burst race 시리즈 (2026-05-06)

#### 발견 경위
사용자 V10 재테스트 중 부수적으로 POWER_OFF 양상 변화 보고. 본 작업의 **ISR 책임 분리 (commit `cecbc3d`) 가 도입한 race**.

#### Root cause
`led_arbiter_tick()` 가 CFX_0 ISR 에서 제거되어 TIMER3 ISR 단독 실행 → main loop iter 와 비동기 → `LedOutputPattern` 이 1-tick stale 상태 → systemControl 의 burst 종료 검출 (`current_led_pattern != en__LED_POWER_Off`) 이 stale=`en__LED_NA` 시 즉시 true → systemOff 트리거 → `led_force_fade_off()` → POWER_OFF burst 미표시.

#### 적용 단계

| Fix | Commit | 변경 |
|---|---|---|
| Fix B-LED-1 | `dcd1204` | systemControl 의 burst 종료 검출을 `!led_is_power_burst_in_progress()` 함수로 변경. burst flag 는 `led_engine_run()` 이 직접 set/clear 하므로 ISR phase 무관 정확 |
| Fix B-LED-2 | `211cc15` | LedOutput.c `led_engine_run()` reset 분기 시작에서 `if (p->burst_cnt > 0) s_power_burst_in_progress = true;` 즉시 set — fade-out Phase A 동안에도 burst 진행 중으로 표현. **검증 전 본질 전환** |
| Fix B-LED-3 (최종) | `9876044` | timer/tick 기반 set 의 race risk 회피 — flag set/clear 책임 명확 분리. **set**: `led_request()` 가 burst 패턴 (`burst_cnt > 0`) 요청 시점 즉시 (외부 호출). **clear**: `led_engine_run()` 이 burst 자가 해제 시 (LED 핸들러 내부). + 네이밍 컨벤션 적용 (`s_tdc_burst_pending`, `tdc_led_is_burst_pending()`). 호출처 4곳 갱신 (systemControl.c × 2, tdc_ui_command.c × 2) |

#### 검증
사용자 재측정 OK — POWER_OFF 패턴 일관 표시 확인.

#### 학습 (회고 후보)
- **ISR 책임 분리 시 main loop 와 동기화 가정 의존성 확인 필수** — 한 ISR 에서만 갱신되던 상태가 분리 후 stale 보일 수 있음
- **타이머/tick 기반 flag 갱신은 race 잠재** — flag 의 set/clear 주체를 외부/내부로 명확 분리하면 timer 무관 정확
- **Fix 의 근본 분석 = 가설 단일화 회피** — Fix A 의 첫 가설 약점을 추후 발견. 처음부터 가설 3 개 cross-check 했으면 더 좋았음 ([분석·디버깅 규칙](../../../../../docs/지침/코딩/분석·디버깅%20규칙.md) §2 적용 사례)

## 5. V10 SPI 잔존 이슈 — 본 작업 외부 (현재 형태로 수용)

### 5.1 현상

ULP wakeup (사용자 의도적 트리거) 또는 watchdog reset 시 SPI1_COM_IRQHandler CS_RISE 검사에서 partial burst detect: `DMA0_CNTS->TRANSFER_WORD_CNT_SHORT (1)` + `DMA1_CNTS->TRANSFER_WORD_CNT_SHORT (3)` (3 clock CS toggle, 정상 21-word 패킷 아님). 자가 복구 후 정상 통신.

### 5.2 분석 결과

**부트로더 시간 정렬** (출처: [`bootloader-power-on-indicator/이력.md:15`](../bootloader-power-on-indicator/이력.md)):

- ROM 500 ms + 커스텀 bootloader 540 ms = **CM3 main 진입 (t3=0) = _전원 인가 후 약 1040 ms_ (T_PowerOn 기준)**

**사용자 오실로 측정 (DIO33 + SPI CS)**:

- 부트로더 진입 시 DIO33 HIGH (~T_PowerOn 500 ms) → **862 ms 후** SPI CS LOW 340 µs 토글 (T_PowerOn ~**1362 ms**)
- **service_mode (부트로더에서 CM3 진입 차단, QCC_CTRL=0 유지) 에서도 CS LOW 토글** → **QCC 자체 schedule 확정** (QCC_CTRL trigger 무관)

**측정 결과 (절대 시간 정렬)**:

| 시나리오 | 핵심 시점 | t3 (ms) | T 절대 (ms) | race detect |
|---|---|---|---|---|
| POR (cold) — 1단계 partial burst (오실로) | CS LOW 340 µs | _-322_ | T_PowerOn ~1362 | _CM3 SPI not-ready 라 detect 못 함_ (사용자 변경 코드의 흡수) |
| POR (cold) — 2단계 정상 RX | `[FAKE_0x34 EXIT-DMA]` | 776~781 | T_PowerOn ~1816~1821 | 정상 (사용자 가설 1.7s + 120 ms 오차) |
| Watchdog (warm) — partial burst | `[SPI] DMA-MISMATCH` | **1577** | T_watchdog 2617 | **있음** (RX_CNT=1, TX_CNT=3) |
| Watchdog (warm) — 정상 RX | (자가 복구 후) | ~1592 | T_watchdog ~2632 | 정상 (partial burst +14 ms) |

**QCC 동작 모델**:

- POR 1단계 (partial burst): _전원 인가_ 후 자체 schedule, T_PowerOn + ~1.36 s, **QCC_CTRL trigger 무관** (service_mode 측정 확정)
- POR 2단계 (정상 21-word): T_PowerOn + ~1.82 s (= 사용자 가설 1.7 s + 120 ms 오차)
- Wakeup (sleep → QCC_CTRL HIGH): SET-NORMAL trigger, SET-NORMAL + ~0.86 s (cold 보다 빠른 wake)

partial burst signature (RX_CNT=1, TX_CNT=3, RX=`00`, TX=`01 02 03` = init 초기값) 는 _정상 21-word 시퀀스 아님_ → **QCC 측 비정상 동작** (wake 완료 직전 transient 구간 SPI 시도). QCC 펌웨어 영역.

**CM3 측 race 처리 (완벽 정상)**:

| 단계 | t3 (ms) | 소요 시간 |
|---|---|---|
| QCC partial burst detect | 1577 | — |
| `SPI1_COM_IRQHandler` mismatch dump + SPI/DMA re-init | 1577~1578 | **1 ms** |
| `bleCommunication SPI_CMMM_ERROR` recovery (NVIC + DMA + SPI 재초기화) | 1578 | (next iter) |
| QCC 정상 21-word 송신 → CM3 RX | ~1592 | 14 ms 후 |
| CM3 RX 처리 + TX 응답 | 1592~1594 | **2 ms** |
| **Total recovery + 정상 통신** | | **~17 ms** |

→ **CM3 측 추가 코드 변경 불필요**.

### 5.3 사용자 영향 평가

| 시나리오 | 영향 |
|---|---|
| Cold (POR) | partial burst 잠재 (T_PowerOn ~1362) 하지만 CM3 측 detect 안 됨 (변경 코드 흡수). **무 영향** ✅ |
| Watchdog | 첫 batt 정보 ~810 ms 지연 (cold 56 ms vs warm 803 ms). 그러나 **POWER_ON 패턴 종료 (t3=1800) 208 ms 전** 정상 batt 정보 도착 → BATT LED 정확 표시 ✅ |

→ **사용자 영향 없음**. 안전 마진 충분 (race latency 가 10 배 이상 튀지 않는 한 안전).

### 5.4 결정

**V10 SPI race 는 본 작업 외부 분리 + 현재 형태 수용**. 본 작업 (LED 조기 점등 + 터치 병렬화) 의 V1~V9 목표 달성 + V10 검증으로 노출된 잠재 이슈 정확히 분석 + CM3 측 추가 변경 불필요로 결론.

→ 별도 task 신설 없이 본 이력 + [`진행상황.md` V10 분석 노트](진행상황.md) 시발점으로 향후 재개 가능. QCC 측 fix 는 담당자 영역 (옵션).

### 5.5 부수 학습 (회고 등록)

- **RTT 출력 누락 시 측정 환경 1순위 의심** — [`docs/회고/환경.md`](../../../../docs/회고/환경.md). RTT 400 kHz throughput 한계로 트레이스 5+ 라인 일관 누락 → 1000 kHz 변경 후 모두 정상.
- **`ci_printe` 회피** — [`docs/회고/코딩.md`](../../../../docs/회고/코딩.md). 디버그 트레이스에 `ci_printw`/`ci_printi` 사용.

### 5.6 사후 변경 (2026-05-07) — 부트로더 cycle 540 → 360 ms

[`bootloader-power-on-indicator/이력.md §8`](../bootloader-power-on-indicator/이력.md) 의 OFF phase 180 → 0 변경에 따라 본 §5 절대 시간 정렬의 _전제값_ 갱신:

- 이전: T_PowerOn = ROM 500 + 부트로더 cycle 540 ≈ **1040 ms** (cycle 가 작업 ~440 보다 길어 cycle 가 종료 결정, t3=0 기준)
- 변경 후: T_PowerOn = ROM 500 + max(작업 ~440, cycle 360) ≈ **~940 ms** (작업이 종료 결정). 약 -100 ms 시프트

§5.2 표의 T 절대값은 본 변경 후 측정 시 약 -100 ms 시프트되지만 V10 결론 (CM3 측 영향 없음, QCC 자체 schedule 무관) 은 그대로. 향후 V10 작업 재개 시 재측정값으로 §5.2 표 갱신 필요.

## 7. 후속 작업

- **systemControl `StartFlag` 분기 cleanup** — 본 작업에서 분기 골격은 보수적 유지. 변수 (`StartFlag`, `PowerOn_StartCounter`) read 가 dead 임을 확인했으므로 별도 cleanup task 후보
- **NRF dead code 정리** — `ResetNRF()` / `NRF_Off_Command()` / `NRF_On_Command()` 의 `Sys_GPIO_Set_*` 모두 주석. NRF51 → QCC 교체 (사용자 피드백) 의 잔재. 별도 정리 task 후보 (`legacy/nrf-cleanup` 같은 이름)
- **V10 SPI race (필요 시 재개)** — §5 분석을 시발점으로. QCC 담당자 펌웨어 시퀀스 (특히 wakeup 후 첫 SPI burst timing, ISD_CHECK 게이트 가정) 확인 후 진행
- **`ci_timer.c` 전체 `tdc_timer.c` 리팩토링** — Q10=A 결정의 trade-off (`g_ci_*` / `g_tdc_*` 혼재) 해소
