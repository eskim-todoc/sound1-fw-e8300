## 1. 배경

### 1.1 현재 부팅 흐름에서 LED_ST_POWER_ON 시작까지의 지연

CM3 앱이 시작되어 사용자가 파워온 LED 버스트(SKYBLUE, 180ms ON / 180ms OFF × 5회)를 볼 때까지는 다음 순차 처리가 모두 끝나야 한다.

```
1. main()                         ─ warm reset, PRIMASK/NVIC 정리, RTT/AES 초기화
2. func_normal() 진입
3. CFX 시작 대기                  ─ is_CFX_started == 1 스핀 루프
4. Initialize()                   ─ FS / MAP / FFT / 이벤트 로그 / ISD 정보 복사 /
                                    인터럽트 활성화 / I2C / SPI / PMIC OFF 등 (수십 ~ 수백 ms)
5. is_enabled_CFX_iteration = 1   ─ CFX가 이 플래그를 보고 normal() 진입, FIFO/PCM 설정 후
                                    1ms FIFO 인터럽트 시작
6. snd_qcc_set_mode(NORMAL)
7. 메인 루프 while(1) 진입
8. CFX 1ms 틱 도달 → iterationFlag = true
9. systemControl() 호출 → StartFlag == false 분기 →
   led_request(LED_SRC_POWER, LED_ST_POWER_ON)   ← 여기서야 LED 시작
```

5 번의 CFX iteration 활성화 시점에 이르기까지 **1ms 시간 정보 자체가 존재하지 않는다.** LED 엔진(`led_arbiter_tick()`)은 CFX FIFO 인터럽트가 유일한 틱 소스이므로, CFX가 normal 모드로 진입해 FIFO 인터럽트가 주기적으로 발생해야 비로소 LED 페이드/PWM 이 돌아간다.

### 1.2 사용자 체감 문제

사용자가 기기의 전원을 누른 직후부터 LED가 처음 들어올 때까지의 시간은 **단순 무응답 구간**으로 인식된다. 이전 작업([터치 초기화 분할 Rev.2](%5B%EA%B5%AC%ED%98%84%EA%B3%84%ED%9A%8D%5D%20%ED%84%B0%EC%B9%98%20%EC%84%BC%EC%84%9C%20%EC%B4%88%EA%B8%B0%ED%99%94%20%EB%B6%84%ED%95%A0%20Rev.2%20by%20%EA%B9%80%EC%9D%80%EC%88%98.md))은 "Auto-ATI 1.5 초를 LED 버스트 안으로 숨기기"를 달성했지만, **그 버스트가 시작되는 시점 자체**는 여전히 Initialize() 뒤에 있다. 즉 LED 점등 앞 단 지연은 그대로 남아 있다.

## 2. 목표

### 2.1 상위 목표

부팅 직후 **LED_ST_POWER_ON 점등 시점을 현재 대비 앞당겨**, 사용자가 "기기가 켜졌다"는 피드백을 최대한 빨리 받을 수 있게 한다.

### 2.2 구체 목표

| # | 항목 | 기대 결과 |
|---|---|---|
| G1 | LED_ST_POWER_ON 요청이 Initialize() 본체 **이전**(또는 아주 초반) 에 발행 | 사용자 체감 "켜짐 인식" 시점 최소화 |
| G2 | Initialize() 의 나머지 단계를 LED 버스트 구간(총 ~1.8 초) 과 **병렬 진행** | 체감 부팅 시간 단축 |
| G3 | CFX와 공유되는 상태 (ISD 정보, EEPROM 로드 플래그 등) 는 **현재 순서를 엄격히 유지** | CFX 오동작 / 시퀀스 회귀 방지 |
| G4 | 터치 센서 초기화처럼 이미 병렬화된 단계와 **충돌하지 않게** 통합 | Rev.2 에서 얻은 이득 유지 |
| G5 | 1 ms 틱 소스 전환 (LED 구간 타이머 ↔ CFX FIFO) 시 **틱 중복/손실/jitter 최소화** | `g_ci_timer_main_tick` 2배 증가, `led_arbiter_tick` 2회 호출 같은 회귀 방지 |

### 2.3 비목표 (Out of Scope)

- CFX 쪽 시퀀스 / 초기화 변경 (CM3 측 재배치만 다룸)
- 부트로더 / `main()` 상위 (warm reset, PRIMASK 리셋) 재편
- LED 패턴 자체 (색상 · 주기 · 횟수) 변경
- 하드웨어 타이머 드라이버 (`Sys_Timer_*`) API 수정

## 3. 제약

### 3.1 CFX 동기화 제약 (매우 중요)

> [!CAUTION]
> 아래 순서는 CFX 펌웨어가 가정하는 시나리오 위에 성립하므로, 재배치 시 반드시 지켜야 한다.

| 순서 | 항목 | 이유 |
|---|---|---|
| C1 | CM3 는 `cfx_cm3_sharedMemoryAll.is_CFX_started == 1` 을 본 뒤에야 CFX 공유 메모리에 쓸 권리가 있다 | CFX main loop 가 첫 반복에서 `is_CFX_started = 1` 을 설정 ([`src/1__cfx/systemControl/main.c:47`](../src/1__cfx/systemControl/main.c)) |
| C2 | `ci_filesystem_copy_isd_info_from_filesystem_to_shared_memory()` 는 `ci_map_init_map_data_all()` 완료 후에만 유효 | 원본 `g_ci_filesystem_ptr_entire_map->map[i].isd_info` 가 초기화되어 있어야 함 |
| C3 | `cfx_cm3_sharedMemoryAll.CFX_EEPROM_data_is_Loaded = 1` 설정은 ISD 정보 복사 **후** 실행 | CFX / CM3의 다른 모듈이 이 플래그로 ISD 정보 읽기 가능 여부를 판정 |
| C4 | `cfx_cm3_sharedMemoryAll.is_enabled_CFX_iteration = 1` 은 CFX가 normal 진입을 시작하는 신호 | 이 플래그 설정 시점 이후 CFX가 FIFO 설정·PCM 준비를 개시하고 1 ms 틱이 활성화됨 |

### 3.2 하드웨어/전원 선행 제약

| # | 항목 | 근거 |
|---|---|---|
| H1 | `ci_power_normal()` — SYSCLK 30.72 MHz 활성화 | 모든 주변 기기 클럭 베이스. DIO/Timer/I2C 선행 조건 |
| H2 | `ci_dio_configure_normal()` — LED GPIO 포함 DIO 구성 | LED R/G/B 핀이 GPIO OUT 으로 구성되어야 점등 가능 |
| H3 | `enable_CFX_trigger_for_iteration()` + `enable_interrupt()` — CFX_0, FIFO_5 NVIC 활성화 & PRIMASK 해제 | LED 엔진을 ISR 기반으로 돌리려면 인터럽트 허용 상태 필요 |
| H4 | `init_I2c()` — I2C 드라이버 상태 머신 초기화 | 터치 초기화 (`tdc_touch_init_begin()`) 내부에서 I2C 사용 |
| H5 | `snd_fatfs_*` / `ci_filesystem_nvm_init()` — FS 초기화 | ISD 정보 복사 (C2) 의 선행 조건 |

### 3.3 타이머 제약 (판단이 필요한 영역)

현재 CM3 는 하드웨어 타이머 없음 가정 하에 **CFX FIFO 인터럽트 (1 ms)** 만을 유일한 시간 기준으로 쓴다. LED 엔진 `led_arbiter_tick()` 도 `CFX_0_IRQHandler / FIFO_5_IRQHandler` 에서 호출된다 ([`driver_timmer.c:11-25`](../src/2__cm3/Cortex-M3-src/systemControl/driver_timmer.c)).

LED 버스트를 CFX iteration 활성화 **전** 에 시작하려면, 해당 구간 동안 1 ms 틱을 공급할 **임시 시간 소스**가 필요하다. 후보는:

| 옵션 | 설명 | 예상 장단점 |
|---|---|---|
| T-A | **TIMER3 를 Initialize 초반에 `ci_timer_init()` 로 재활용**, CFX iteration 활성화 직전에 `ci_timer_uninit()` | `TIMER_3_IRQHandler` 가 이미 `enable_iteration + g_ci_timer_main_tick++ + led_arbiter_tick` 호출하도록 구현됨. 코드 변경 최소 |
| T-B | **TIMER2 를 새로 도입** 하여 별도 1 ms ISR 로 `led_arbiter_tick` 만 호출 | `ci_timer_*` 프레임워크와 독립. 분리 명확. 코드 증가 |
| T-C | 타이머 없이 `Sys_Delay` / `__NOP` 카운팅으로 busy-wait | 부정확 / 에너지 낭비. 배제 |

> [!WARNING]
> T-A 옵션은 **CFX iteration 활성화 타이밍과 겹치면 틱이 중복** 증가할 수 있다 (Rev.2 에서 명시된 위험). T-A / T-B 모두 전환 시 **정확히 한 소스만 활성**인 상태를 보장해야 한다.

### 3.4 리소스 제약

- Ezairo 8300 CM3 는 TIMER0~3 네 개가 있으며 현재 TIMER3 만 ULP (sleep) 모드에서 ~500 ms 웨이크업용으로 쓴다. Normal 모드에서는 전부 미사용. TIMER2 · TIMER3 모두 후보로서 가용하다.
- LED 엔진 ISR 실행시간: 추정 ~15 μs @ 30.72 MHz ([`ci_timer.c:25`](../src/2__cm3/Gen1_5/common/ci_timer.c) 주석). 1 ms 주기 대비 약 1.5 % 부하.

## 4. 수용 조건

### 4.1 기능

- [ ] 정상 부팅 시 (충전기 미연결, 에러 없음) LED_ST_POWER_ON 점등 시점이 현재 대비 **유의미하게 앞당겨짐** (RTT 로그 타임스탬프 기반으로 실측 가능해야 함)
- [ ] LED 버스트 패턴 (색상 · 주기 · 횟수 · fade) 이 기존과 동일하게 보임
- [ ] 터치 센서 초기화 (Auto-ATI 1.5 초 대기) 가 현재와 동일하게 LED 버스트 뒤에서 병렬 진행됨
- [ ] CFX 가 Initialize 완료 후 정상적으로 normal 모드 진입 (`is_CFX_started`, `is_enabled_CFX_iteration` 흐름 유지)
- [ ] 충전기 연결 부팅 / MCU 에러 부팅 경로에서 LED 패턴이 과거와 동일 (POWER_ON 미표시)
- [ ] Ezairo 워치독 리셋 후 재부팅 시에도 동일하게 동작
- [ ] ULP (sleep) 모드 진입 / 복귀 동작 정상 (TIMER3 를 재활용할 경우 ULP 타이머와의 충돌 여부 검증)

### 4.2 비기능

- [ ] `g_ci_timer_main_tick` 이 1 ms 당 정확히 1 증가 (전환 구간 포함)
- [ ] `led_arbiter_tick()` 이 1 ms 당 정확히 1 회 호출 (중복/누락 없음)
- [ ] RTT 로그에 전환 시점 단서 포함 (디버깅 편의)
- [ ] 기존 파일 수정 최소화, 새 파일 생성 지양 (지침 준수)

## 5. 용어

| 용어 | 의미 |
|---|---|
| **체감 켜짐 시점** | 사용자가 LED 빛을 처음 인식하는 순간 |
| **LED 버스트** | `LED_ST_POWER_ON` 패턴 1 회 사이클 전체 (SKYBLUE, ON 180 ms / OFF 180 ms × 5 = 약 1.8 초) |
| **CFX iteration** | `cfx_cm3_sharedMemoryAll.is_enabled_CFX_iteration` 플래그로 CFX가 normal 모드 진입 후 생성하는 1 ms FIFO 틱 |
| **임시 시간 소스** | CFX iteration 활성화 전에만 존재하는 별도 1 ms 틱 (TIMER3 또는 TIMER2 기반) |
| **Early POWER_ON 구간** | Initialize 초반에 LED 버스트를 시작하여 Initialize 나머지 + 터치 Auto-ATI 가 병렬 진행되는 시간 창 |

## 6. 열린 질문 (사용자 결정 필요)

다음 항목들은 상세 분석 단계에서 근거를 수집해 결정한다. 본 요구사항 단계에서는 **항목만 확정**하고, 분석 문서에서 후보·평가를 제시한다.

| # | 질문 | 관련 |
|---|---|---|
| Q1 | Early POWER_ON 구간에서 쓸 1 ms 틱 소스 — TIMER3 재활용 (T-A) vs TIMER2 신규 (T-B) | §3.3 |
| Q2 | LED_ST_POWER_ON 요청을 발행하는 **코드 위치** — Initialize 초반, main() 직후, 아니면 별도 bring-up 함수 | §2.2 G1 |
| Q3 | CFX 시작 대기 스핀 루프 (main.c:335-344) 를 유지할지, LED 틱이 도입되면 이 스핀을 `SYS_WAIT_FOR_INTERRUPT` 로 바꿀지 | §1.1 단계 3 |
| Q4 | Initialize() 자체를 "LED 시작 전 필수 부분" + "버스트 중 병렬 가능 부분" 으로 분할할지, 아니면 전체를 그대로 두고 LED 요청만 더 앞으로 옮길지 | §2.2 G2 |
| Q5 | 1 ms 틱이 존재하지 않는 구간(메인 루프 진입 전)에 `tdc_touch_init_begin()` 과 같은 현재의 병렬 초기화가 어떻게 영향받는지 확인 및 처리 방안 | §3.1 C2, §3.3 |
