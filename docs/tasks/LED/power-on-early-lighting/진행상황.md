SPI 에러 (V10 회귀) 는 여전 — **Fix B-SPI 분석 시 사용자 피드백 반영 필수** (이전 NRF GPIO 부활 후보는 폐기):
- **NRF (NRF51) 는 레거시** — QCC 로 교체됨, 관련 함수 `ResetNRF()` / `NRF_Off_Command()` / `NRF_On_Command()` 의 GPIO 주석은 **의도적**, 부활 불필요 (dead code)
- **SPI 통신의 master = QCC** (CM3 는 slave, [`driver_SPI.c:201`](../../../src/2__cm3/Cortex-M3-src/systemControl/driver_SPI.c) `SPI_SELECT_SLAVE` 와 일관)
- **SND_QCC_MODE_NORMAL 진입 시 QCC → CM3 SPI 전송 시작 약속** — 기본 시스템 정보 (배터리, 충전 상태 등)
- 따라서 SPI race 의 진짜 분석 축은 `snd_qcc_set_mode()` 흐름 + 워치독 리셋 시 QCC 모드 상태 + CM3 `init_cm3_SPI()` 시점

### 커밋 5 skip 사유

LedOutput.c 검토 결과 t3_tick 통일의 의미 있는 적용 지점이 없음.
- BLE pairing latch (`ci_timer_get_tick()` 호출 2곳, line 358/563) 는 CFX iteration 활성 후 동작이라 main_tick 기준이 의미적으로 적절. t3_tick 으로 바꿔도 의미 동등이지만 어색.
- LED arbiter 자체 ms 카운터들 (`timer_ms`, `burst_done_cnt`, `s_tx_ms`, `s_fade_off_t`) 은 이미 `led_arbiter_tick()` 호출 주기 (TIMER3 1ms) 기준으로 증가 → t3_tick 절대값으로 변경 시 fade/burst 리팩토링 회귀 위험만 큼, 의미상 동등.

### 커밋 4 보수적 옵션 채택 사유

구현계획 §3.6 의 "분기 자체 삭제" 의도와 달리 분기 골격 (if/else) · `systemStatus.Led_Pattern` 셋업 · `StartFlag` · `PowerOn_StartCounter` 변수는 보수적으로 유지. 분기 내 LED·터치 init 호출 (`turnOffLED` · `led_request` · `tdc_touch_init_begin`) 만 제거. 변수 자체 cleanup 은 별도 작업으로 위임 (현재 사용처 dead 확인 — `PowerOn_StartCounter` read 없음, `batteryNPowerControl.updateBatteryLevel` 호출이 main.c:378 에서 주석 처리).

### 2. Fix B-SPI 분석 진입 (메인 태스크)

**전제** (사용자 피드백 2026-05-06):
- NRF 관련 코드는 모두 dead — `ResetNRF()` / `NRF_Off_Command()` / `NRF_On_Command()` 의 GPIO 주석 해제 후보 **폐기**. 본 task 에서 손대지 않음.
- SPI master = **QCC**. CM3 는 slave.
- `snd_qcc_set_mode(SND_QCC_MODE_NORMAL)` 진입 시 QCC → CM3 SPI 전송 시작 (기본 시스템 정보) 이 약속.

**분석 축**:
1. `snd_qcc_set_mode()` 정의 + 호출처 grep — 특히 `NORMAL` / `SHUTDOWN` 전이 시점
2. 워치독 리셋 (3초 터치 슬립 → 깨움) 시 시나리오:
   - CM3 reset, **QCC 는 모드 유지** 가정 (CM3 가 reset 됐다고 QCC mode 가 자동 변경되지 않음)
   - 즉 깨움 직후 QCC 는 NORMAL 모드 → SPI master 로서 계속 전송 시도
   - CM3 의 `init_cm3_SPI()` ([`driver_SPI.c:196`](../../../src/2__cm3/Cortex-M3-src/systemControl/driver_SPI.c)) 호출 시점에 QCC 가 이미 SPI 전송 중 → DMA `TRANSFER_WORD_CNT_SHORT` race
3. Fix 후보 (가설 3 개 cross-check 권장):
   - **F1**: CM3 init 초기에 `snd_qcc_set_mode()` 로 QCC 를 IDLE/SHUTDOWN 같은 안전 모드로 명시 전환 → SPI 전송 멈춤 → CM3 SPI init 안전
   - **F2**: `init_cm3_SPI()` 강건화 — DMA disable + status clear + pending IRQ clear 시퀀스 보강
   - **F3**: SPI init 전 QCC 모드 안내 핸드셰이크 (HOST→QCC GPIO/UART 신호) — 기존 핸드셰이크 채널 존재 여부 조사 필요
