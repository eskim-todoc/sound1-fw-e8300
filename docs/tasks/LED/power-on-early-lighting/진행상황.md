# POWER_ON LED 조기 점등 및 초기화 병렬화 — 진행상황

**TL;DR**: ✅ 완료 — LED·터치 V1~V9 + POWER_OFF Fix B-LED-3 검증 OK, 머지 승인 대기. G1~G5(P3-Early·병렬 Initialize·ISR 책임 분리·`g_tdc_timer_t3_tick`·터치 FSM·POWER_OFF burst 분리) 모두 달성. V10 SPI 에러는 본 작업 외부 이슈로 분리(QCC NORMAL 진입 직후 internal wakeup + SPI master init 첫 burst race로 결론, CM3 측 fix만으로는 해결 불가).

최종 갱신: 2026-05-06 (LED 마무리)

## 현재 단계

**✅ 완료 — LED·터치 V1~V9 통과 + POWER_OFF (Fix B-LED-3) 검증 OK. 머지 승인 대기**

LED·터치 영역의 본 작업 목표 (G1~G5) 달성:
- LED_ST_POWER_ON 조기 점등 (P3-Early, `ci_dio_configure_normal()` 직후) ✅
- Initialize 나머지를 LED 버스트와 병렬 진행 ✅

- 터치 초기화 FSM 명시화 + 시간 기준 t3_tick 통일 ✅
- 1 ms 틱 중복/손실 없음 (V3·V4·V5) ✅
- POWER_OFF burst pending 책임 분리 (Fix B-LED-3) ✅

V10 SPI 에러 (ULP wakeup 시) 는 본 작업 외부 이슈로 분리 — 본 작업이 도입한 회귀 아니라 V10 검증 강화로 노출된 잠재 이슈. 회로 (DIO24 풀-다운 10K) + QCC 동작 (담당자 피드백) cross-check 결과 **QCC NORMAL 진입 직후 internal wakeup + SPI master init 도중 첫 burst race** 가 본질. ## V10 SPI 분석 노트 (이후 필요 시 재개용)

본 작업 마무리 시점 (2026-05-06) V10 SPI race 분석 결과. 별도 task 신설 없이 본 진행상황·이력에만 기록. 이후 필요 시 새 작업의 시발점으로 활용.

### 1. 요약

POR (보드 전원 인가) 또는 watchdog reset 시 QCC → CM3 SPI 통신 초기에 partial burst (3 clock CS toggle, 정상 21-word 패킷 아님) 가 발생. 부트로더 시간 정렬 + 사용자 오실로 측정 + RTT 트레이스 측정 결과:

- **원인**: QCC 자체 wake-up 시퀀스의 transient 구간 SPI 시도 (펌웨어 결함 시그너처 — 담당자 영역)
- **CM3 측 처리**: 17 ms 내 자가 복구 (mismatch detect → SPI/DMA re-init → 정상 RX → TX 응답) — **완벽 정상**
- **사용자 영향**: 없음 (POWER_ON 패턴 종료 208 ms 전 정상 batt 정보 도착, BATT LED 정확 표시 보장)

→ **현재 형태로 수용 결정**. CM3 측 추가 변경 불필요. QCC 측 fix 는 담당자 영역 (옵션).

### 2. 핵심 사실

#### 2.1 회로 + 외부 칩 동작

- **DIO24 (QCC_CTRL)**: 외부 풀-다운 10 KΩ. CM3 측 GPIO INPUT 시 자동 LOW (QCC SHUTDOWN). NORMAL 시 CM3 가 HIGH driving
- **IQS323 (터치)**: warm boot 시 전원 유지 → 잔존 ATI (TOUCH ELAPSED 짧음, 33 ms 수준)
- **`snd_qcc_set_mode()`**: 단순 GPIO toggle (DIO24). NORMAL=HIGH, SHUTDOWN=LOW. SPI 통신 자체는 없음 ([snd_qcc.c:77-90](../../../src/2__cm3/Cortex-M3-src/QCC/snd_qcc.c))
- **`snd_qcc_init()`**: `ci_dio_configure_normal()` 안에서 호출 ([ci_dio.c:93](../../../src/2__cm3/Gen1_5/common/ci_dio.c)). DIO24 OUT 설정 + 초기 SHUTDOWN(LOW)

#### 2.2 부트로더 시간 정렬

[`bootloader-power-on-indicator/이력.md:15`](../bootloader-power-on-indicator/이력.md):

- ROM bootloader: **500 ms**
- 커스텀 bootloader (SW PWM 포함): **540 ms** (1 cycle 보장 — 본 부트로더 작업 결과)
- **→ CM3 main 진입 (t3=0) = 전원 인가 후 약 1040 ms (T_PowerOn 기준)**

본 작업의 모든 t3 값에 1040 ms 를 더하면 _전원 인가 기준_ 절대 시간.

#### 2.3 QCC 측 동작 (담당자 피드백)

- SYS_CTRL=0 → 약 2 초 후 딥슬립 진입
- SYS_CTRL=1 → 깨어남 (전원 cycle 과 동일한 wakeup)
- 깨어나면 기본 시스템 정보 (배터리·충전 상태 등) SPI 송신
- **wakeup → 첫 SPI 패킷 송신까지 ≈ 1.7 초** (담당자 후속 피드백)

#### 2.4 사용자 V10 검증 코드 변경

- `main.c:361 snd_qcc_set_mode(NORMAL)` 삭제 → `initialize.c` 끝으로 이동
- `init_cm3_SPI()` 도 `initialize.c` 끝 (`snd_qcc_set_mode` 직전) 으로 이동
- `ci_dio.c:ci_dio_configure_normal()` 에서 `Sys_SPI_DIOConfig` 주석 + `NRF_SPI_CS_PIN` 을 GPIO output HIGH 로 사전 설정
- `DIO_PIN_Config.h` `SPI_DIO_PIN_CFG` 풀업 약화 (60K → WEAK)
- 효과: CM3 SPI ready 시점이 t3=731 (T_PowerOn 1771 ms) 로 늦춰짐 → POR 1단계 partial burst 흡수 (CM3 측 detect 못 함)

#### 2.5 사용자 오실로 측정 (DIO33 + SPI CS)

- 부트로더 시작 시 **DIO_NUM_ELAPSE_TIME_CHECK (DIO33) HIGH** 설정 → T_PowerOn ~500 ms 시점
- DIO33 HIGH 후 **862 ms** 시점에 SPI CS LOW **340 µs** 토글 → T_PowerOn ~**1362 ms**
- CS HIGH idle 도달 시점 = DIO33 HIGH 시점 = QCC self power-up ≈ ROM time (500 ms) 와 우연 일치
- **service_mode (부트로더에서 CM3 진입 차단, QCC_CTRL=0 유지) 에서도 CS LOW 토글 발생** → **QCC 자체 schedule 확정** (QCC_CTRL trigger 무관)

#### 3.2 Watchdog (warm) — Log 3 (RTT 1000 kHz)

전제: 이전 보드 동작 끝에서 `[QCC] MODE: SHUTDOWN` + CFX SLEEP 진입 → long touch → CM3 만 watchdog reset (QCC SHUTDOWN 상태에서 sleep 유지).

| watchdog reset trigger | — | 0 | — |
| ROM + 커스텀 bootloader | — | 0 ~ 1040 | — |
| CM3 main 진입 `[POWER-ON START]` | 0 | 1040 | — |
| `init_cm3_SPI()` + `[QCC SET-NORMAL]` HIGH | 731~733 | 1771~1773 | **0** (wake trigger) |

#### 3.3 partial burst signature

```
[SPI] DMA-MISMATCH t3=1577 ms / RX_CNT=1 / TX_CNT=3
[SPI] RX_BUFF (LSB->): 00
[SPI] TX_BUFF (LSB->): 01 02 03
```

해석:

- **TX_CNT=3, RX_CNT=1**: SCK 3 clock 토글 후 CS RISE → **정상 21-word 패킷 시퀀스 아님**
- **TX_BUFF = `01 02 03`**: `init_cm3_SPI()` 직후 `SPI_Tx_Buffer[i] = 1+i` 초기값 그대로 ([driver_SPI.c:224](../../../src/2__cm3/Cortex-M3-src/systemControl/driver_SPI.c)) — CM3 측 미준비 상태에서 SCK 3 clock 들어와 의미 없는 초기값 빠져나감
- **RX_BUFF = `00`**: QCC 가 MOSI 에 0x00 1 word 만 띄움 (dummy / NUL)

### 4. QCC 동작 모델 (분석 결론)

세 측정 시점 (POR 1단계 / POR 2단계 / Wakeup) 모두 **QCC 측 자체 schedule** 로 일관 설명:

| 시나리오 | trigger | 첫 SPI 시점 | 비고 |
|---|---|---|---|
| **POR 1단계 (partial burst)** | _전원 인가_ 후 자체 schedule | T_PowerOn + ~1.36 s (= bootloader 시작 + 862 ms) | 오실로 측정으로 직접 확인. service_mode 에서도 발생 → **QCC_CTRL trigger 무관 확정** |
| **POR 2단계 (정상 21-word)** | (1단계 후 재시도 또는 자체 schedule) | T_PowerOn + ~1.82 s (= 1.7 s 가설 + 120 ms 오차) | RTT log 측정 |
| **Wakeup (sleep → QCC_CTRL HIGH)** | _SET-NORMAL HIGH_ trigger | SET-NORMAL + ~0.86 s (cold 보다 빠른 wake) | RTT log 측정 |

QCC 가 _두 모드_ (cold-start vs wake-from-sleep) 에서 _다른 init 시간 + 다른 trigger_ 동작.

partial burst signature (RX_CNT=1, TX_CNT=3) 는 정상 21-word 시퀀스 아닌 **QCC 측 비정상 동작** — wake 완료 직전 transient 구간의 SPI 시도 추정. _QCC 펌웨어 분석은 담당자 영역_ 이라 본 작업 외부.

### 5. CM3 측 race 처리 (완벽 정상)

| 단계 | t3 (ms) | 동작 | 소요 시간 |
|---|---|---|---|
| QCC partial burst detect | 1577 | CS_RISE IRQ → `SPI1_COM_IRQHandler` mismatch 분기 | — |
| 에러 dump + SPI/DMA re-init | 1577~1578 | `clear_SPI_Tx_Buffer` + `ci_SPI_enable_DMA` + SPI re-enable | **1 ms** |
| `bleCommunication SPI_CMMM_ERROR` recovery (next iter) | 1578 | NVIC + DMA + SPI 완전 재초기화 + IDLE 복귀 | (next iter) |

| **Total recovery + 정상 통신 시작** | | | **~17 ms** |

### 6. 사용자 영향 평가

#### 6.1 Cold (POR)

- partial burst (T_PowerOn ~1362) 는 CM3 측 SPI not-ready 구간에 흡수 → **사용자 영향 없음**
- 정상 RX (T_PowerOn ~1820) → main loop 정상 동작
- POWER_ON 패턴 (T_PowerOn 1040~2840) 진행 중 정상 batt 정보 도착 → 패턴 종료 후 BATT LED 정확 표시 ✅

#### 6.2 Watchdog

- partial burst (t3=1577) → CM3 detect → 17 ms 내 recovery → 정상 RX (t3=~1592)
- POWER_ON 패턴 종료 (t3=1800) **208 ms 전** 정상 batt 정보 도착 → BATT LED 정확 표시 ✅
- 첫 batt 정보 지연 ~810 ms (cold WAIT=56 ms vs warm WAIT=803 ms) — 사용자 인지 불가 (POWER_ON 패턴 안에 흡수)

#### 6.3 안전 마진

- POWER_ON 1800 ms 윈도우 안에 batt 정보 도착하면 안전. 현재 worst case 여유 208 ms (= 1800 - 1592)
- race latency 가 _10 배 이상_ 으로 튀지 않는 한 사용자 영향 없음 (현재 측정 일관성: cold ±5 ms, watchdog partial burst 시점 일관)

### 7. 결정

**V10 SPI race 는 본 작업 외부 분리 + 현재 형태 수용**:

| 영역 | 결정 |
|---|---|
| **CM3 측 코드 변경** | 불필요 (race 처리 메커니즘 완벽) |
| **QCC 펌웨어 fix** | _옵션_ — 담당자 영역. partial burst 자체는 비정상이지만 사용자 영향 없으므로 우선순위 낮음 |
| **본 분석 작업** | 마무리. 이후 필요 시 본 노트 + [`이력.md §5`](이력.md) 시발점으로 재개 |

#### 7.1 향후 재개 시 검증 실험 (1건)

`init_cm3_SPI()` 를 다시 Initialize 앞쪽 (예: `init_I2c()` 직후, t3 ≪ 100 ms = T_PowerOn ~1100 ms) 으로 옮긴 빌드로 cold 측정 → t3 ≈ 322 ms (T_PowerOn ~1362 ms) 부근에 **partial burst dump 출력** 되는지 확인. detect 시 _POR 1단계 partial burst 가 watchdog partial burst 와 동일 메커니즘_ 이라는 직접 증거.

#### 7.2 QCC 담당자 추가 질문 (옵션)

1. POR 시 QCC 가 자체 schedule 로 두 단계 SPI 시도 (1단계 +1.36s, 2단계 +1.82s) — 펌웨어 동작과 일치?
2. partial burst (3 clock 후 CS RISE) 가 QCC 어떤 펌웨어 분기에서 발생? (handshake? wake-detection? 펌웨어 결함?)
3. Wake-from-sleep 시 SET-NORMAL+~860 ms 가 정확한 wake-to-first-data 시간?

- 계획 3종의 **내부 링크 일부가 구 프리픽스 경로**로 남아 있음 (migration 후 정리 안 됨). 별도 `meta/internal-links-fix` 작업에서 일괄 수정 예정. 콘텐츠 손실 없음.

NRF51 → QCC 교체 (사용자 피드백 2026-05-06) 의 잔재. 별도 정리 task 후보 (`legacy/nrf-cleanup` 같은 이름). 본 task 에서는 손대지 않음.
