# LED Fade-Off 비차단 변환 — 구현계획

**TL;DR**: 사용자 결정 3건(정적 플래그 `s_led_isr_active` 사용·옵션 A로 sleep 진입 LED 보호·fade-off 중 high-priority 진입 시 즉시 중단)을 기반으로 LedOutput.c에 fade-off 상태머신을 도입하고, `led_isr_active_set()` API 추가, initialize.c에서 ISR 활성/비활성 시점에 호출하여 폴링 30/40 ms 블로킹을 ISR 1 ms tick 상태머신으로 변환한다.

작성일: 2026-04-27
연계: [요구사항.md](요구사항.md), [분석.md](분석.md)

|---|---|

## 3. 함수별 변경

### 3.1 `turnOffLED()` — `LedOutput.c:632-662`

```c
void turnOffLED(void)
{
    if (!led_arbiter_can_run())
    {
        /* ISR 비활성 (Initialize-time) 또는 영구 suspended (sleep 진입 후) —
         * arbiter 가 fade-off step 을 진행할 수 없음. 즉시 OFF 1 회. */
        LED_outputColor    = en__LED_BLACK;
        s_led_pwm_on_count = 0;
        LED_OUT();
        return;
    }

    /* 비차단 fade-off 시작 — 다음 ISR tick 부터 arbiter 가 step 진행 */
    s_fade_off_state = LED_FADE_OFF_ACTIVE;
    s_fade_off_t     = 0;
    s_fade_off_max   = LED_DIMMING_FADE_MAX_MS;  /* 30 */
}
```

**제거**: `s_led_isr_suspended` set/clear 4 줄, 폴링 for 루프, `delay_ms` 호출.

### 3.2 `led_force_fade_off()` — `LedOutput.c:363-391`

```c
void led_force_fade_off(void)
{
    /* 모든 src 강제 NONE — Arbiter 가 즉시 IDLE 결정하도록 */
    for (int src = 0; src < LED_SRC__MAX; src++)
    {
        s_req[src] = LED_ST_NONE;
    }
    s_pair_latch_until_tick = 0;

    /* 본 함수 호출 사이트는 main.c:638 sleep 진입 한 곳뿐 — ISR 활성 가정.
     * 그러나 안전상 동일 검사. */
    if (!led_arbiter_can_run())
    {
        LED_outputColor    = en__LED_BLACK;
        s_led_pwm_on_count = 0;
        LED_OUT();
        s_led_isr_suspended = true;  /* 옵션 A: sleep 진입 LED 보호 */
        return;
    }

    /* 비차단 fade-off 시작 (40 ms) — 호출자(main.c:638) 는 break 로 즉시 main loop
     * 탈출, func_sleep() 의 NRF/QCC/PMIC OFF 처리 동안 ISR 이 자연 tick 으로
     * fade 진행 → turnOffLED() 진입 시점엔 BLACK 안정 도달 (또는 진행 중). */
    s_fade_off_state = LED_FADE_OFF_ACTIVE;
    s_fade_off_t     = 0;
    s_fade_off_max   = LED_DIMMING_FADE_MAX_MS + 10;  /* 40 */

    /* 옵션 A: sleep 진입 동안 LED 보호 — fade 완료 후 ISR 차단.
     * arbiter 가드 순서를 fade-off step 분기 → suspended 가드 순으로 두어
     * 본 set 이후에도 진행 중인 fade 는 끝까지 진행되도록 한다 (§3.3 참조). */
    s_led_isr_suspended = true;
}
```

> [!NOTE]
> `s_led_isr_suspended = true` 를 함수 끝에서 선반영해도 fade 가 계속 진행되도록 **arbiter 가드 순서를 바꾼다** (§3.3). 기존 동작 ("fade 후 영구 lock") 의도 보존.

### 3.3 `led_arbiter_tick()` — `LedOutput.c:513` 가드 순서 재구성 + fade-off 분기

```c
void led_arbiter_tick(void)
{
    /* (가드 1) Fade-off step — suspended 가드보다 먼저 처리.
     *
     * 이유: led_force_fade_off() 가 fade 시작과 동시에 s_led_isr_suspended = true
     *       로 sleep 진입 보호를 걸어둔다. 만약 suspended 가드가 먼저면 fade 가
     *       진행 안 됨 → 옵션 A 동작 깨짐. fade-off step 분기를 먼저 두어
     *       fade 는 끝까지 진행되고, 완료 후엔 본 분기를 빠져나가 (가드 2) 로 차단. */
    if (s_fade_off_state == LED_FADE_OFF_ACTIVE)
    {
        /* 새 high-priority 요청 검사 — best != IDLE 이면 fade-off 즉시 중단 후
         * 정상 arbiter path 진행 (cross-fade 메커니즘이 자연 처리).
         * 결정 사항 §0: ERROR 등 진입 시 기존 fade 중단 + 새 패턴 fade 적용. */
        if (compute_best_state() != LED_ST_IDLE)
        {
            s_fade_off_state = LED_FADE_OFF_IDLE;
            /* fall through to (가드 2) 검사 후 정상 arbiter */
        }
        else
        {
            /* fade-off step 진행 */
            uint8_t perceived = (uint8_t) (((uint32_t) (s_fade_off_max - s_fade_off_t) * 255UL)
                                            / s_fade_off_max);
            s_led_pwm_on_count = perceived_to_pwm(perceived);
            LED_OUT();

            if (++s_fade_off_t >= s_fade_off_max)
            {
                LED_outputColor    = en__LED_BLACK;
                s_led_pwm_on_count = 0;
                LED_OUT();
                s_fade_off_state = LED_FADE_OFF_IDLE;
            }
            return;
        }
    }

    /* (가드 2) Suspended — main loop 가 직접 LED state 를 조작하던 구간 보호.
     * 본 작업 후엔 led_force_fade_off() 의 sleep 진입 보호가 유일한 set 사이트. */
    if (s_led_isr_suspended)
    {
        return;
    }

    /* === 이하 기존 arbiter 로직 (변경 없음) === */
    bool user_off = (readLED_indicatorOnOff() == 2);
    /* ... */
}
```

### 3.4 `compute_best_state()` 신규 (private static)

기존 `led_arbiter_tick()` 본문의 best 계산 부분을 함수로 추출 — fade-off 중단 검사에서 재사용.

```c
static led_state_t compute_best_state(void)
{
    bool        user_off = (readLED_indicatorOnOff() == 2);
    led_state_t best     = LED_ST_IDLE;
    int         max_p    = -1;

    /* PAIR latch 처리 */
    if (s_req[LED_SRC_BLE_IND] != LED_ST_PAIR
        && ci_timer_get_tick() < s_pair_latch_until_tick)
    {
        s_req[LED_SRC_BLE_IND] = LED_ST_PAIR;
    }

    for (int src = 0; src < LED_SRC__MAX; ++src)
    {
        led_state_t st = s_req[src];
        int         p  = led_prio_of(st);

        if (user_off && !led_is_error(st)
            && st != LED_ST_POWER_ON && st != LED_ST_POWER_OFF)
        {
            continue;
        }

        if (p > max_p)
        {
            max_p = p;
            best  = st;
        }
    }
    return best;
}
```

`led_arbiter_tick()` 본문에서는 이 함수를 호출해 best 를 얻은 뒤 기존 로직 (legacy pattern 업데이트, engine run, LED_OUT) 진행.

> [!NOTE]
> PAIR latch 처리는 부수효과 (`s_req[LED_SRC_BLE_IND]` 갱신) 가 있다. fade-off 분기에서 호출 → 정상 path 에서 다시 호출하면 latch 적용이 두 번 평가되지만 idempotent (`!= LED_ST_PAIR` 검사가 가드). 동작 동등.

## 8. 부수 효과 (분석 §4.1 잠재 버그 해소)

기존 sleep 진입 시퀀스의 `s_led_isr_suspended` 풀림 버그가 본 변환으로 자연 해소:

```text
[기존]
led_force_fade_off()  → suspended = true (영구 의도)
…
turnOffLED()          → set true (no-op) → fade → clear false  ★ 풀림
ci_power_sleep        → IRQ 시 LED 갱신 가능 (의도와 반대)

[변환 후]
led_force_fade_off()  → fade-off state ACTIVE + suspended = true
…
turnOffLED()          → !led_arbiter_can_run() (suspended) → 즉시 OFF, suspended 손대지 않음 완료
ci_power_sleep        → IRQ 시 가드 1 (fade-off IDLE) → 가드 2 (suspended) → 즉시 return 완료
```

T-9 로 수치 검증.
