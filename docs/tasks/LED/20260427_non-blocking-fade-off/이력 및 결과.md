## 4. 부수 효과 — 잠재 버그 자연 해소

[분석.md §4.1](분석.md) 에서 식별한 `s_led_isr_suspended` 풀림 잠재 버그가 본 변환으로 해소:

```text
[기존]
led_force_fade_off()  → suspended = true (영구 의도)
…
turnOffLED()          → set true (no-op) → fade → clear false  ★ 풀림
ci_power_sleep        → IRQ 시 LED 갱신 가능 (의도 위반)

[변환 후]
led_force_fade_off()  → fade-off state ACTIVE + suspended = true
…
turnOffLED()          → !led_arbiter_can_run() (suspended) → 즉시 OFF, suspended 손대지 않음 ✓
ci_power_sleep        → IRQ 시 가드 1 (fade-off IDLE) → 가드 2 (suspended) → 즉시 return ✓
```

## 8. 사후 fix — fade-off cancel 시 prev 색 잔존 (commit `85c250f`)

본 작업 머지 후 사용자 측정에서 POWER_ON 첫 띡- 14 펄스 중 **첫 펄스가 fade-in 형태로 좁아지고 ~48 ms gap 후 나머지 13 펄스 출력**되는 anomaly 관찰.

### 8.1 원인

`led_arbiter_tick()` cancel 분기에서 `s_fade_off_state = LED_FADE_OFF_IDLE` 만 설정하고 fall-through. 이 시점 `LED_outputColor` 는 직전 색상 (POWER_ON 직전엔 SKYBLUE 잔존) 상태. 정상 arbiter 진입 후 `engine_run()` cross-fade 분기가 `LED_outputColor != BLACK` 으로 보고 Phase A (FADE_OUT) 부터 가동. Phase A 진행 시간 ≈ ~48 ms gap, 첫 frame ≈ ~2.8 ms 짧은 펄스.

### 8.2 Fix

cancel 분기에 다음 3 줄 추가:

```c
LED_outputColor    = en__LED_BLACK;
s_led_pwm_on_count = 0;
LED_OUT();
```

cross-fade 분기가 `LED_outputColor == BLACK` 으로 보고 Phase B (FADE_IN) 직행 → 패턴 의도 형태 시작.

### 8.3 검증·재해석

사용자 측정: **첫 이상 펄스 + gap 모두 사라짐**, POWER_ON 14 펄스 정상.

부수 발견: 본 fix 로 이전 [LED G 미스터리 (B 작업, bootloader-power-on-indicator/진행상황.md §3.1)](../bootloader-power-on-indicator/진행상황.md) 의 "첫 이상 펄스" 도 함께 해소. 두 현상이 별개가 아니라 **같은 cross-fade Phase A 시퀀스의 시작·진행 두 측면** 이었음.

| 관측 | 정체 |
|---|---|
| 첫 이상 펄스 (~2.8 ms) | Phase A 첫 frame LED_OUT |
| ~48 ms gap | Phase A 나머지 frame 진행 시간 |
