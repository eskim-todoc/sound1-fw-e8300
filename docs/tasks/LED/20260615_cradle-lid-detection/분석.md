# 분석 (Rev.1)

**TL;DR**: BLE 0x34 data[2]=뚜껑 상태. `carryingCaseCoverOpen`에 반영할 신규 setter 필요. QCC 셧다운 후 BLE 통신 불가 → 뚜껑 열림 감지는 GPIO 폴링. CFX는 `enter_ULP_mode` 신호 생략으로 유지. QCC 2.2초 딜레이 필수.

> [!NOTE]
> 에이전트 05~12 (8개) 분석 결과 통합본. 에이전트별 상세 결과는 `에이전트-로그/` 참조.

## 1. BLE 패킷 구조 (0x34)

**파일**: `ble_communication.c:119~162`

| 인덱스 | 필드 | 값 정의 |
|---|---|---|
| `data[0]` | 배터리 레벨 | 0~100% |
| `data[1]` | charger_connected | 0=미연결, 1=연결 |
| `data[2]` | 크래들 뚜껑 상태 | **1=열림, 2=닫힘, else=열림 처리** (현재 미파싱) |

**현재 상태**: `data[2]` 파싱 코드 없음. 추가 필요.

## 2. carryingCaseCoverOpen 갱신 경로 분석

### 2.1 현재 갱신 주체

### 2.2 핵심 문제

`snd_charger_set_state(EN__SND_CHARGER_STATE_CONNECTED)` 호출 시 `carryingCaseCoverOpen = df_Disconnected`(2)로 항상 덮어씀 → BLE data[2]로 갱신해도 다음 충전 상태 업데이트 시 소실.

### 2.3 설계 결정: 신규 setter 신설 (방법 B)

```c
// batteryNPowerControl.c에 추가
void tdc_charger_set_cradle_cover_state(int state)
// state: 1=열림(df_Opened), 2=닫힘(df_Closed), else=열림처리
```

- `snd_charger_set_state()` 내 `carryingCaseCoverOpen` 갱신 라인 제거 (BLE 갱신값 보존)
- 데이터 흐름: `ble_communication.c → tdc_charger_set_cradle_cover_state() → cfx_cm3_sharedMemoryAll.chargerState.carryingCaseCoverOpen`

## 3. systemControl.c 뚜껑 감지 블록 분석

**파일**: `systemControl.c:161~205`

### 3.1 현재 구조

```
else if (chargerState.chargerConnectorPluggedIn == df_Connected)  // 충전기 연결 (라인 161)
{
    systemStatus.BLE_Off = true;
    systemStatus.enablePMIC = false;
    changePcmOutputMode(PcmBitStream_Mode_FillZero);

    if (chargerState.carryingCasePluggedIn == df_Connected)       // 크래들 연결 (라인 171)
    {
        if (chargerState.carryingCaseCoverOpen == df_Connected)   // 뚜껑 열림 (라인 173)
        {                                                          // df_Connected == df_Opened == 1
            CounterAfterCoverClosed = 0;                          // 카운터 리셋
        }
        else                                                       // 뚜껑 닫힘 (라인 178)
        {
            if (CounterAfterCoverClosed > LED_OnTime_afterCoverClosed)  // 4501 틱 초과
            {
                CounterAfterCoverClosed = 0;
                systemStatus.systemOff  = true;                   // 시스템 종료 → func_sleep()
                ci_printi("[SYSTEM] GO TO SYSTEM OFF\r\n");
            }
            CounterAfterCoverClosed++;
        }
    }
}
```

### 3.2 Rev.1 변경 계획

- 기존 4501 틱 타이머 대기 **삭제** → 첫 닫힘 감지 즉시 약 절전 진입
- 엣지 감지 플래그 `s_tdc_cradle_cover_closed_edge` 추가
- `systemOff` 대신 별도 `cradleLidClosed` 신호로 분기

### 3.3 df_Connected == df_Opened 동일값 주의

```c
// processorDirective.h
#define df_Connected  1
#define df_Opened     1   // 동일값
#define df_Closed     2
#define df_Disconnected 2 // 동일값
```

`carryingCaseCoverOpen == df_Connected`는 사실 `== df_Opened`와 동치. 기존 코드 스타일 유지.

## 5. 약 절전 루프 설계 핵심

### 5.1 충전기 연결 시 QCC 동작 (업데이트)

> [!IMPORTANT]
> **충전기 연결 상태에서는 QCC_CTRL=0이어도 QCC가 절전 진입하지 않음.** SPI 패킷 계속 수신 가능. 배터리레벨·충전여부·뚜껑상태를 이벤트 발생 시 즉각 패킷 전송.
>
> QCC_CTRL=0 상태에서 워치독 리셋으로 재부팅 → QCC_CTRL=1 복귀 순간 QCC가 즉각 상태 패킷 송신 → 재부팅 후 즉시 최신 상태 수신 가능.

따라서 약 절전 루프에서 `bleCommunication()` 호출은 **실질적으로 작동**하며, 뚜껑 열림 패킷 수신 시 즉각 감지 가능.

### 5.2 뚜껑 열림 감지: BLE 패킷 수신 (GPIO 폴링 폐기)

> [!IMPORTANT]
> **뚜껑 열림은 GPIO 직접 읽기 방식 사용 금지. 무조건 BLE 패킷 수신으로만 감지.**

약 절전 루프에서 `bleCommunication()` 호출 → `tdc_charger_set_cradle_cover_state(data[2])` 호출 → `tdc_cradle_get_cover_state()` 확인:

```c
BLE_communicationState = bleCommunication(dummy_isd);

// 패킷 수신 후 setter가 갱신한 상태 확인 (df_Connected == df_Opened == 1)
if (tdc_cradle_get_cover_state() == df_Connected)
{
    ci_printi("[CRADLE] LID OPENED PACKET RECEIVED - WATCHDOG RESET\r\n");
    delay_ms(20);
    SYS_WATCHDOG_RESET();
}
```

### 5.3 CFX 유지 방법

`enter_ULP_mode_Command_CM3_to_CFX = 1` 신호를 보내지 않으면 CFX는 정상 동작 유지. `OnOff_3V_PMIC_CM3_to_CFX(false)` 호출 시에도 CFX 독립 전원으로 유지됨 (1.5세대 V_LINK_ON 회로 구조).

### 5.4 워치독 안전성

- 타임아웃: **3.28초**
- 폴링 루프 주기: 200ms 이내 → 매 반복마다 `SYS_WATCHDOG_REFRESH()` 필수
