# ISD 연결/해제 LED 제어 — 이력 및 결과

**TL;DR**: working tree에 진행 중이던 ISD 연결/해제 LED 제어 코드를 정적 분석으로 검증하고, 문제 발견 시 수정안을 제시하는 작업. 본 문서는 시계열 로그와 완료 요약을 담는다.

## 시계열 로그

### 2026-06-02
- **착수**: 사용자(은수님)가 ISD 연결/해제 시 LED 동작 요구사항을 구두 설명. "연결 중=사용자 설정 LED 표시, 연결 해제=배터리 레벨 복귀" 원칙 확인.
- **지침 확인**: 루트 `CLAUDE.md`·헌법(`rules/CLAUDE.md`) 재확인, 온디맨드로 디버깅·MCU 지침 로드. 과거 `Sound1 LED` 잔상 버그 회고(다중 ISR race) 숙지.
- **현상태 파악**: working tree 미커밋 변경 8파일 확인 — `LedOutput.c/h`(s_isd_conn 플래그 + compute_best_state 억제 게이트), `main.c`(ISD 분기 재작성 + 배터리 임계 테스트값 + 인코딩 손상), `systemControl.c`(veryLowBattery 범위 변경 + 인코딩 손상), `ble_communication.c`·`ble_commonProtocol.h`(0x36 CLASSIC_STATE, 별개), `remoteControl.c`(passkey 우회 디버그, 별개), `nvmupdate.bat`.
- **코드 맥락 수집(서브에이전트 2병렬)**:
  - LED arbiter: `led_arbiter_tick()`은 현재 `TIMER_3_IRQHandler` 단일 진입점에서만 1ms 주기 호출 → 과거 다중 ISR 잔상 버그 해소 확인. `s_isd_conn`=volatile int(main set/ISR read), `s_req[]`=non-volatile.
  - ISD/사용자 설정: 연결 시 `changeConnected_isd_num_CFX` → `fn_copy_userSettingParameters_toCM3`로 그 ISD 설정 로드(readLED 호출 전 동기 완료). **연결 해제 시 userSettingValue 초기화 안 됨 → 직전 값 잔존.** `s_isd_conn` 게이트가 잔존값 무시의 핵심 장치임을 확인.
- **검증 방침 확정(사용자)**: 정적 분석 후 실기 / 문제 발견 시 수정안까지 제시.
- **Standard 4단계 진입**: 작업 폴더 `docs/tasks/LED/20260602_isd-conn-led-arbitration/` 생성, 요구사항.md·이력 작성.
- **정적 검증 워크플로 실행(background)**: 7 시나리오 + 6 리스크, 13 에이전트 병렬 (run `wf_965f523e-bab`, 65만 토큰, 184 tool use).
- **검증 결과**: 시나리오 **7/7 PASS**. 리스크 6건 — R1(`main.c:524` 조건, medium·요구사항무영향), R2(잔존값, low), R3(disconnect race, low), R4(결함아님), **R5(배터리 테스트값, medium·요구사항영향)**, R6(인코딩, low·전부 주석). ISD arbitration 로직 자체는 의도대로 동작 확정.
- **산출물 ②③ 작성**: 분석.md(검증 종합)·계획.md(수정안 A/B/C 그룹).
- **승인 게이트**: 미결정 2건 사용자 확인 요청.
- **사용자 결정**: ① 배터리 테스트값 **유지**(전기기계적안정성 시험 중, LED 검증은 배터리 40%↑로) — 그룹 A 미적용. ② 수정 범위 **B 그룹**(B-1·B-2).
- **④ 구현(B 그룹)**: `main.c` ISD 분기 수정 — B-1 `if (readLED_indicatorOnOff() == 1)` 명시 비교(dead branch 제거), B-2 `led_set_isd_conn_state(isd_conn)`를 if/else 분기 **뒤로 이동**(disconnect 1-tick 백색 잔상 race 제거). C 그룹 미적용(사용자 선택).
- **빌드/실기 대기**: 임베디드 ARM toolchain 빌드·J-Link RTT 실기 검증은 사용자 진행 예정.
- **2026-06-02 실기 검증 통과**: 은수님 빌드 후 실기 확인 — *"잘 동작하네"*. 7 시나리오 의도대로 동작 확인.

## 완료 요약

ISD 연결 중에는 그 ISD의 사용자 설정 LED 표시값(1=켜기/2=끄기)을 따르고, 연결 해제 시에는 잔존 설정값을 무시하고 배터리 레벨 LED로 복귀하는 동작을 구현·검증 완료.

- **핵심 장치**: `LedOutput.c compute_best_state`의 `s_isd_conn==1` 억제 게이트 — 연결 중에만 `user_off` 억제 적용, 해제 시 게이트가 닫혀 배터리 소스 생존.
- **적용 수정(B 그룹)**: B-1 `main.c:524 if (readLED_indicatorOnOff() == 1)`(dead branch 제거·fragility 해소), B-2 `led_set_isd_conn_state()`를 ISD 분기 뒤로 이동(disconnect 1-tick 백색 잔상 race 제거).
- **검증**: 정적 분석 7/7 PASS(13에이전트 워크플로) + 실기 검증 통과.
- **미적용(사용자 결정)**: 배터리 임계 테스트값 원복(전기기계적안정성 시험 중 유지)·C 그룹(인덴트·인코딩 복원).
- **후속**: 커밋은 별개 변경(`ble` 0x36 CLASSIC_STATE·`remoteControl` passkey 우회·배터리 테스트값) 분리 후 진행 예정 — 사용자 승인 대기.
