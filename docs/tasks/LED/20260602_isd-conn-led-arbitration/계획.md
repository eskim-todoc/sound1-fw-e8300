# ISD 연결/해제 LED 제어 — 수정 계획

**TL;DR**: ISD arbitration 로직은 검증 통과. 본 계획은 (A) 실기 검증 전 배터리 테스트값 처리, (B) 권장 LED 로직 수정 2건(`main.c:524` `==1`, disconnect 쓰기 순서), (C) 코드 위생 2건을 그룹별로 제시한다. **각 그룹 적용은 사용자 승인 후 진행, 별개 변경은 커밋 분리.**

## 그룹 A — 실기 검증 전 처리 (R5, 사용자 확인 필요)

> [!WARNING]
> 주석에 *"전기기계적안정성 시험을 위해"*라 명시됨 → **현재 다른 시험 진행 중인지 먼저 확인.** 시험 중이면 유지하고 배터리 40%↑로 LED 검증, 아니면 아래대로 원복.

**A-1. `main.c:491~493` 배터리 CRITICAL 임계 원복**
```c
// before
else if (pct < 40 /*10*/)                                    batt_st = LED_ST_BATT_CRITICAL;
else if (pct < 41 /*12*/ && prev_batt_st == LED_ST_BATT_CRITICAL) batt_st = LED_ST_BATT_CRITICAL;
// after
else if (pct < 10)                                           batt_st = LED_ST_BATT_CRITICAL;
else if (pct < 12 && prev_batt_st == LED_ST_BATT_CRITICAL)   batt_st = LED_ST_BATT_CRITICAL;
```

**A-2. `systemControl.c` `veryLowBattery` 원복** (LED 작업과 별개 — 커밋 분리)
```c
// before: 0per || 0btw20 || 20btw40 (40% 미만 전부)
// after:  en__batteryPower_0per 단일 조건
if (batteryLevel == en__batteryPower_0per) { veryLowBattery = true; }
```

## 그룹 B — 권장 LED 로직 수정

**B-1. `main.c:524` 조건 명시화 (R1)** — dead branch·fragility 제거
```c
// before
if (readLED_indicatorOnOff())          // 1·2 모두 참 → 설정=2여도 IN_USE 요청
// after
if (readLED_indicatorOnOff() == 1)     // 1(켜기)만 IN_USE, 2(끄기)는 else로 NONE
```
효과: 설정=2 시 `main.c:532 led_request(LED_SRC_ISD, LED_ST_NONE)`가 정상 실행 → arbiter 우연 억제에 의존하지 않고 의도가 코드에 명시.

**B-2. `main.c` disconnect 쓰기 순서 정정 (R3)** — 1-tick 백색 잔상 race 제거
- 현재: `led_set_isd_conn_state(isd_conn)`(519) → if/else 내 `led_request(LED_SRC_ISD,...)`(527/538)
- 제안: ISD 소스 상태를 먼저 확정한 뒤 마지막에 `s_isd_conn` 갱신. 즉 `led_set_isd_conn_state()`를 if/else 블록 **뒤로 이동**.
```c
// after (개념)
if (isd_conn) { if (readLED_indicatorOnOff()==1) led_request(LED_SRC_ISD, LED_ST_IN_USE);
                else                              led_request(LED_SRC_ISD, LED_ST_NONE); }
else          { led_request(LED_SRC_ISD, LED_ST_NONE); led_request(LED_SRC_BATTERY, batt_st); }
led_set_isd_conn_state(isd_conn);   // s_req[ISD] 확정 후 게이트 갱신
```
효과: 어떤 ISR 인터리빙에서도 "IN_USE 잔존 + 억제 해제" 조합 불성립.

## 그룹 C — 코드 위생 (선택)

**C-1. `LedOutput.c:87·698~701` (R2·R4)**
```c
static volatile int s_isd_conn = 0;   // false → 0 (타입 일관성)
// 억제 게이트 평탄화 + 인덴트 정렬
if (user_off && s_isd_conn == 1 && !led_is_error(st)
    && st != LED_ST_POWER_ON && st != LED_ST_POWER_OFF) { continue; }
```

**C-2. 인코딩 손상 복원 (R6)** — `main.c` 9곳·`systemControl.c` 3곳 주석. **별도 커밋**(`Fix(인코딩): 주석 em dash/≈ 깨짐 복원`). 재발 방지로 `.gitattributes`(`working-tree-encoding=UTF-8`)·`.editorconfig`(`charset=utf-8`) 권고.

## 적용 순서·검증

1. (A 확정 시) 배터리 테스트값 원복 → 빌드.
2. B-1·B-2 적용 → 빌드.
3. (선택) C-1·C-2.
4. **실기 검증**: J-Link RTT로 7 시나리오 재현. 특히 ③→④ 전환(연결 해제 시 배터리 복귀)·④→⑤(재연결 소등)·⑥→⑦(새 ISD 점등)을 LED 색·소등으로 확인. disconnect 순간 백색 잔상 tick 캡처(B-2 효과).
