# 부트로더 단계 LED 조기 점등 — 요구사항

**TL;DR**: 전원 입력 후 첫 LED 인지까지 약 1,670 ms(ROM 500 + 부트로더 440 + CM3 730) 무점등 문제를 해결하기 위해 부트로더 단계에서 SKYBLUE LED를 먼저 점등하여 약 1,170 ms(~70%) 단축. "부트로더 LED → 정식 LED_ST_POWER_ON 버스트"의 끊김 없는 두 단계 피드백 모델 채택. Rev.3에서 R-11 영향 시 본 작업 폐기 분기 명시, AC-3/AC-7 무점등 시간 제약 완화.

## 1. 배경

### 1.1 문제

사용자가 전원을 입력한 후 첫 LED 점등(정식 `LED_ST_POWER_ON` SKYBLUE 버스트 시작)까지 **약 1,670 ms** 소요. 그동안 외부 관측은 무점등 — "전원이 들어왔는지" 즉시 알기 어려움.

### 1.2 부팅 타임라인 (실측 — 오실로스코프, JTDO 마킹)

| 구간 | 길이 | 손댈 수 있는가 |
|---|---|---|
| 전원 입력 → 부트로더 첫 시작 | **500 ms** | ❌ Ezairo 내부 ROM 부트로더 (Flash 로드) — 물리적 한계 |
| 부트로더 첫 시작 → CM3 첫 시작 | **440 ms** | ✅ [`0__bootloader/main.c`](../../../../src/0__bootloader/main.c) (본 작업 영역) |
| CM3 첫 시작 → Power On LED | **730 ms** | ✅ CM3 앱 (인접 [`power-on-early-lighting`](../power-on-early-lighting/) 작업 대상) |
| **합계 (전원 → 첫 LED)** | **1,670 ms** | |

### 1.3 정량 가치

본 작업 적용 시:
- **첫 LED 인지 시간**: 1,670 ms → **500 ms** (ROM 영역만 남음)
- **단축**: 약 **1,170 ms (~70 %)**
- 부트로더 LED ↔ 정식 LED 사이 텀: 1,170 ms (인접 `power-on-early-lighting` 작업으로 730 ms 구간을 줄이면 함께 감소)

### 1.4 사용자 인지 모델 (확정 — Q-C)

**"끊김 없이 이어지는 두 단계 피드백"**

- 1단계 (부트로더 LED, 500 ms ~ 940 ms): "켜졌다" 신호
- 2단계 (정식 `LED_ST_POWER_ON` 버스트, 1,670 ms~): "다 켜졌다 / 정상 동작 진입" 신호

두 단계가 다른 색·다른 밝기로 보이면 **끊긴 인상**을 주므로 가능한 한 동일하게 보이도록 매칭한다.

> **전환 구간 OFF 는 끊김으로 보지 않음 (사용자 확인, 2026-04-30)**: 부트로더 LED 종료(`bootloader_boot_cm3()` 직전 OFF) → CM3 진입 → 정식 `LED_ST_POWER_ON` 첫 사이클까지 OFF 상태가 충분히 길게 유지되며, CM3 측은 OFF 상태에서 시작해 fade 로 자연스럽게 켜짐. 이 OFF 구간은 두 단계의 자연스러운 시각적 분리이므로 짧을 필요가 없고, **두 단계의 색감만 같으면 끊김 인지 없음**. 따라서 본 작업은 **무점등 시간 제약 없이 색감 매칭 (AC-2)** 에 집중.

### 1.5 현재 상태

부트로더 [`main.c:16-24`](../../../../src/0__bootloader/main.c) 에 디버깅용 `#if 1` 가드 블록이 이미 존재 (commit `1c52544`):

```c
#if 1  // 부팅 시간 체크를 위한 디버깅 코드
    Sys_DIO_Config(DIO_NUM_LED_R_UART_TX_E8300, DIO_CFG_LED);
    Sys_DIO_Config(DIO_NUM_LED_G_UART_RX_E8300, DIO_CFG_LED);
    Sys_DIO_Config(DIO_NUM_LED_B, DIO_CFG_LED);

    Sys_GPIO_Write(DIO_NUM_LED_R_UART_TX_E8300, 0);   // R=0(ON, active low)
    Sys_GPIO_Write(DIO_NUM_LED_G_UART_RX_E8300, 1);   // G=OFF
    Sys_GPIO_Write(DIO_NUM_LED_B, 1);                 // B=OFF
#endif
```

본 작업은 이 디버깅 블록을 **정식 부트로더 LED 점등** 으로 승격·정리한다.

## 3. 목표

**CM3-Bootloader 부팅 초기 (분석 단계에서 두 후보 시점 중 결정)** SKYBLUE 점등을 수행하고, 정식 `LED_ST_POWER_ON` 진입 시까지 **연속적으로 켜진 상태로 유지** 한다.

**점등 시작 시점 후보** (분석 단계 — Q-PWM-3 결과로 확정):
- **T-A**: `main()` 진입 직후 (현재 `#if 1` 디버깅 블록 위치). 시스템 클럭 = 7.68 MHz 기본값. 가장 빠른 점등.
- **T-B**: `bootloader_boot() → bootloader_load_manu_table() → Sys_Trims_SetOperatingFrequency()` 로 30.72 MHz 전환 직후. 클럭이 안정되어 PWM 주파수 일관성 확보. 사용자 단서: "비교적 적은 ms 내" 라면 T-B 채택 검토.

T-B 가 T-A 대비 늦어지는 시간이 충분히 작으면 T-B 우선, 아니면 T-A 채택 + 클럭 변경 시 SW PWM 주기 재계산 고려.

## 4. 수용 기준 (AC)

| ID | 기준 |
|---|---|
| AC-1 | 전원 입력 후 첫 LED 점등 시각: T-A 채택 시 ≤ **501 ms**, T-B 채택 시 ≤ **(500 + 클럭 전환까지 소요)** ms. 분석 단계 측정 결과로 정확한 상한 확정. 어떤 경우든 **현재 1,670 ms 대비 50% 이상 단축** 보장 |
| AC-2 | 부트로더 LED 점등 색상이 정식 `LED_ST_POWER_ON` SKYBLUE 와 **동일** — CM3 와 같은 mix 테이블(`{R=0, G=30, B=40}`) · 같은 PWM duty(`s_led_pwm_on_count` 정상 가동 시 100%) · 같은 `LED_DIMMING_PWM_STEPS` 분해능을 사용 |
| AC-3 | **부트로더 점등 구간 동안** LED 출력이 다른 색·밝기로 깜빡이거나 점멸하지 않을 것 (같은 색감 + 같은 PWM 구성 유지). 부트로더 OFF → CM3 OFF → 정식 `LED_ST_POWER_ON` fade-in 으로 이어지는 무점등 구간은 자연스러운 시각적 분리이므로 본 AC 의 대상이 **아님** (§1.4) |
| AC-4 | 부트로더 외 다른 동작에 회귀 없음 — 서비스 모드 진입 (`DIO_NUM_DMIC_CLK1_CAL` HIGH 분기), UART 사용 시 LED R/G 핀 공유 충돌 없음, JTAG/RTT 디버깅 정상, 부트로더 → CM3 440 ms 구간 길이 영향 무시 가능 |
| AC-5 | `#if 1` 디버깅 가드는 빌드 가드 매크로 `BOOTLOADER_LED_INDICATOR_ENABLE` 로 정리. **`#define BOOTLOADER_LED_INDICATOR_ENABLE 0` 으로 두면 본 작업의 모든 코드가 사라지고 부트로더가 LED 를 건드리지 않는 원래 상태가 되어야 함** |
| AC-6 | 부트로더 SW PWM 이 점등 시작부터 종료(`bootloader_boot_cm3()` 직전) 까지 안정적으로 동작 (반복 측정 시 깜빡임·끊김 없음). 타이머 인터럽트 누락·우선순위 충돌·CM3 이미지 로드(벡터 테이블 포함)로 인한 이상 펄스 없음 |
| AC-7 | **SW PWM 종료**: [`bootloader.c:1374`](../../../../src/0__bootloader/source/bootloader.c) 의 `bootloader_boot_cm3()` 호출 **직전** 에 SW PWM 명시 종료 (타이머 정지 + LED OFF). CM3 가 LED 를 다시 잡기 전까지의 무점등 시간 길이는 제약 없음 (CM3 측이 OFF 에서 fade 로 자연스럽게 시작하므로 — §1.4) |

## 5. 범위

### 5.1 In-scope

- [`src/0__bootloader/main.c`](../../../../src/0__bootloader/main.c) `#if 1` 블록 정리 (위치·색상·빌드 가드 매크로 `BOOTLOADER_LED_INDICATOR_ENABLE`)
- 부트로더 LED 점등 코드의 **시작 위치** 결정 (T-A: `main()` 직후 / T-B: `Sys_Trims_SetOperatingFrequency()` 30.72 MHz 전환 직후 — Q-PWM-3 결과로 확정)
- 부트로더 LED 점등 코드의 **종료 위치**: [`bootloader.c:1374`](../../../../src/0__bootloader/source/bootloader.c) 의 `bootloader_boot_cm3()` 호출 직전 (SW PWM 정지 + LED 핀 인계)
- **부트로더 SW PWM 구현** — CM3 LED 엔진과 동일한 mix 테이블(`{R=0, G=30, B=40}`) · 동일 PWM 분해능 / duty 산식 사용 (CM3 코드 재사용 또는 동일 로직 별도 작성). 타이머 ISR 1 개 점유.
- 부트로더용 타이머 선택 (사용자 단서: **타이머3 활용 가능 여부 파악 필요** — 분석 단계 핵심 항목)
- **CM3 이미지 로드 중 SW PWM 가동 가능 여부 검증**: 부트로더가 CM3 펌웨어를 메모리에 로드(리셋 핸들러부터 모든 벡터 테이블까지)하는 동안 부트로더 자신의 타이머 ISR 가용성 확보 — 본 작업 성립의 **선결 조건** (R-11)

### 5.2 Out-of-scope

- ROM 부트로더 500 ms 단축 (Q-B)
- CM3 앱 측 LED 조기 점등 (인접 [`LED/20260423_power-on-early-lighting`](../power-on-early-lighting/) 작업)
- LED 엔진 (`LedOutput.c`) 의 mix 테이블 / dimming 파라미터 / PWM 분해능 등 **값 변경**. 부트로더는 동일 값을 **참조** 만 함
- 정식 `LED_ST_POWER_ON` 의 패턴(180/180×5) · fade-in 동작 변경
- 서비스 모드 LED 동작 변경 ([`service.c:9-23`](../../../../src/0__bootloader/source/service/service.c)) — 단, 본 작업으로 부트로더 LED 가 켜진 채로 `service_main()` 진입 시 충돌 회피 로직만 검토 (R-6)

## 6. 부트로더 SKYBLUE 매핑 — 채택 옵션 C4 (SW PWM)

정식 `LED_ST_POWER_ON` SKYBLUE 는 PWM dimming + RGB cap [`LedOutput.c:839`](../../../../src/2__cm3/Cortex-M3-src/systemControl/LedOutput.c) 기준 `{R=0, G=30, B=40}`.

| 옵션 | 부트로더 출력 | 정식 LED 와 차이 | 채택 |
|---|---|---|---|
| C1 | G+B 풀밝기 (시안) | 색 가깝되 풀밝기 vs PWM dimming → 밝기 점프 | ✗ |
| C2 | R+G+B 풀밝기 (백색) | 색 다름, 풀밝기 | ✗ |
| C3 | 단일 LED (B 또는 G) 풀밝기 | 색·밝기 둘 다 차이 | ✗ |
| **C4** | **부트로더 SW PWM (CM3 와 동일 dimming/PWM/색상)** | **매칭 정확, 부트로더 코드↑ + 440 ms 영향 검증 필요** | ✅ |

**채택 사유** (사용자 결정, 2026-04-30):
- AC-2 / AC-3 의 "끊김 없는 두 단계 피드백"(§1.4) 을 가장 깔끔하게 충족
- C1~C3 의 색·밝기 점프를 원천 회피
- 색감 / dimming / PWM 분해능을 CM3 와 동일하게 유지하면 부트로더 → CM3 전환 시 별도 매칭 작업 불필요

### 6.1 분석 단계 핵심 조사 항목

| ID | 항목 | 사용자 단서 |
|---|---|---|
| Q-PWM-0 | **(선결)** 부트로더가 CM3 펌웨어를 메모리에 로드하는 동안 (리셋 핸들러부터 모든 벡터 테이블 포함) 부트로더 자신의 **타이머 인터럽트가 계속 동작 가능한가**. R-11 와 동일 항목 — 본 작업 성립 여부를 결정하는 1순위 검증 | 사용자가 명시 — "부트로더가 CM3 펌웨어를 리셋 핸들러부터 모든 벡터 테이블까지 전부 메모리에 로드하는데, 부트로더에서 타이머 인터럽트를 계속 사용할 수 있는지를 먼저 확인해야 함" |
| Q-PWM-1 | 부트로더에서 활용 가능한 타이머 — **타이머3 활용 가능 여부** 우선 확인 | 사용자가 명시 |
| Q-PWM-2 | CM3 LED 엔진 코드(`LedOutput.c` 의 `LED_OUT()`, `k_led_mix`, `LED_DIMMING_*` 매크로) 를 부트로더에서 그대로 빌드해 쓸 수 있는가, 아니면 동일 로직 별도 파일로 작성해야 하는가 (메모리/링커/include path 분리 정도에 따름) | - |
| Q-PWM-3 | **점등 시작 시점 결정 (T-A vs T-B)**: 시스템 클럭이 전원 인가 후 기본 7.68 MHz 였다가 호출 경로 `main() → bootloader_main() → bootloader_boot() → bootloader_load_manu_table() → Sys_Trims_SetOperatingFrequency()` 에서 30.72 MHz 로 전환됨 ([`bootloader.c:643`](../../../../src/0__bootloader/source/bootloader.c) 부근, 캘리브레이션 전제). 클럭 변경까지 소요 시간이 비교적 적은 ms 라면 **T-B (클럭 변경 후) 채택**, PWM 주파수 일관성 확보. 그렇지 않으면 **T-A (main 직후) 채택** + 클럭 변경 시 SW PWM 주기 재계산 처리 | 사용자가 명시 — "30.72MHz 설정까지 시간이 비교적 적은 ms 내로 처리가 된다면 이 클럭 설정 이후 LED 켜는 것을 고려해도 됨" |
| Q-PWM-4 | 부트로더 SW PWM 추가로 인한 부트로더 → CM3 440 ms 구간 영향 (코드 사이즈 + 타이머 ISR 점유) | - |
| Q-PWM-5 | **SW PWM 종료 시점**: [`bootloader.c:1374`](../../../../src/0__bootloader/source/bootloader.c) 의 `bootloader_boot_cm3()` 호출 **직전** 에 명시 종료 (타이머 정지 + LED 핀 상태 인계). CM3 측 LED 초기화 코드가 다시 잡기까지의 무점등 시간 측정 | 사용자가 명시 — "CM3 앱 로드 완료 후 bootloader_boot_cm3() 호출 전에 SW PWM 을 중지해야 함" |

## 8. 비기능 요구사항

- **빌드 가드 매크로**: `BOOTLOADER_LED_INDICATOR_ENABLE`. `0` 으로 두면 본 작업 코드 일체 컴파일되지 않음 (LED DIO 설정·SW PWM 타이머·ISR 핸들러·핀 인계 로직 전부 가드). `1` 이면 현 작업 의도대로 동작. (AC-5)
- **부트로더 코드 사이즈 영향**: SW PWM 도입으로 일부 증가 불가피. 현재 부트로더 → CM3 440 ms 구간 길이 변화는 **무시 가능 (≤ 50 ms 증가 허용)** 을 목표로 하며, 초과 시 사용자 보고 후 판단 (R-9).
- **코드 위치**: 가능한 `0__bootloader/main.c` 내 또는 신규 `0__bootloader/source/led_indicator/` 형태 모듈 1개로 정리. CM3 측 코드 재사용 가능 시 그쪽 우선.
- **타이머 ISR 우선순위**: 부트로더 다른 동작 (UART, 디버그 init, EEPROM WP, QCC CTRL 등) 의 타이밍에 영향 없을 것.
- **종료 절차**: SW PWM 종료 = [`bootloader.c:1374`](../../../../src/0__bootloader/source/bootloader.c) 의 `bootloader_boot_cm3()` 호출 **직전** (AC-7). 절차: ① SW PWM 타이머 정지 → ② LED 핀 상태 결정 (CM3 측 LED 초기화 코드와의 인계 — CM3 가 핀을 다시 잡기 전까지 무점등 시간 최소화) → ③ `bootloader_boot_cm3()` 호출.
- **클럭 변동 대응**: T-A 채택 시 7.68 → 30.72 MHz 전환점에 SW PWM 주기 재계산 hook 필요 (R-12). T-B 채택 시 무관.

## 10. 후속 단계

1. **사용자 승인** (본 문서 Rev.3)
2. `분석.md` 작성 — **Q-PWM-0 / R-11 단독 선행** 형태로 진행:
   1. **Phase 1 — 선결 검증 (Q-PWM-0 / R-11)**: 부트로더 영역에서 CM3 이미지 로드 중 SW PWM 타이머 ISR 가동 가능 여부 판정. 결과로 본 작업의 진행 여부 결정
      - **가능 판정 시**: Phase 2 진입
      - **불가 판정 시**: 본 작업 **폐기 처리** — `이력 및 결과.md` 에 폐기 사유와 분석 결과 기록, [`LED/20260423_power-on-early-lighting`](../power-on-early-lighting/) 으로 가치 이전 (별도 작업), `tasks/작업 목록.md` 에서 본 작업 행을 "취소" 로 옮김. 사용자 보고 후 종료
   2. **Phase 2 — 나머지 항목 정밀 분석 (Q-PWM-0 가능 판정 시에만)**:
      - Q-PWM-1 / R-7: 타이머3 부트로더 가용성
      - Q-PWM-2 / R-8: CM3 LED 엔진 코드 부트로더 재사용 가능 여부
      - Q-PWM-3 / R-12: 점등 시작 시점 결정 (T-A vs T-B), 클럭 전환 측정
      - R-1: GPIO 리셋 디폴트
      - R-3: CM3 측 LED 초기화 시퀀스 (Q-PWM-5 종료 시점과 연동)
      - R-4/R-5/R-6: UART · 서비스 모드 충돌
3. **사용자 승인** (분석.md, Phase 1 결과 기반 진행/폐기 결정 포함)
4. `구현계획.md` 작성 — 코드 변경 위치 · SW PWM 모듈 구조 · 가드 매크로 적용 범위 · 검증 방법
5. **사용자 승인** (구현계획.md)
6. 구현 + 사용자 검증 (오실로스코프 측정으로 AC-1 ~ AC-7 확인 — 특히 AC-2 색감 매칭, AC-3 점등 구간 안정성, AC-6 SW PWM 안정성)
7. `이력 및 결과.md` 작성 후 `claude_develop` 머지
