# 부트로더 단계 LED 조기 점등 — 분석

**TL;DR**: Phase 1으로 R-11(부트로더 SW PWM ISR이 CM3 펌웨어 로드 중에도 동작 가능한가)을 단독 검증하여 진행/폐기 결정 입력을 제공하고, Phase 2에서 Q-PWM-1/2/3·R-1/3/4/5/6/12를 정밀 분석. Rev.2에서 사용자 2차 피드백을 반영하여 D-1=Timer2·D-3=T-B·D-4 디버그 GPIO 빌드 가드 무력화·D-7 빌드 가드+UART 검증 핀 2단 분기·D-8 active HIGH로 확정.

작성일: 2026-04-30
Rev: Rev.2 — 사용자 2 차 피드백 반영 (Timer2 / GPIO 풀다운 / 검증 핀 분기 / active HIGH)
작업 브랜치: `claude_feature_bootloader-power-on-indicator` (base: `claude_develop`)
관련: [요구사항.md Rev.3](요구사항.md), [진행상황.md](진행상황.md)

| Rev | 변경 |
|---|---|
| Rev.0 (2026-04-30) | Phase 1 (R-11) 가능 ✅ 판정 + 구현 의무 사항 O-1~O-4. |

## 0. 분석 단계 구성

[요구사항.md §10](요구사항.md) 결정에 따라 분석을 두 Phase 로 분리:

| Phase | 항목 | 결과로 결정되는 것 |
|---|---|---|
| **Phase 1** | Q-PWM-0 / R-11 단독 — CM3 이미지 로드 중 부트로더 SW PWM 타이머 ISR 가용성 | 본 작업 진행/폐기 |

Rev.0 은 Phase 1 결과 + Phase 2 진입 권고. **Rev.1 은 Phase 2 정밀 분석 결과 추가** — 사용자 결정사항 + Explore 조사 결과 통합.

## 1. Phase 1 — R-11 검증

### 1.1 검증 대상 가설 (요구사항.md §7 R-11)

부트로더가 CM3 펌웨어 이미지를 메모리에 로드하는 동안 본 작업의 SW PWM 타이머 ISR 이 영향받을 가능성. 영향 케이스:

| Case | 내용 |
|---|---|
| ① | 벡터 테이블 영역에 부트로더 ISR 핸들러가 있는데 CM3 펌웨어 적재 중 핸들러가 덮어써짐 |
| ② | NVIC 설정·우선순위 영역이 CM3 적재 중 변경되어 부트로더 ISR 동작 깨짐 |
| ③ | 메모리 쓰기 동안 인터럽트 비활성 구간이 발생해 ISR 이 일정 시간 멈춤 |

### 1.2 조사 결과

#### F-1. 부트로더 메모리 영역 = CM3 PRAM5 (0x00060000, 65 KB)

[`0__bootloader/sections.ld:22`](../../../../src/0__bootloader/sections.ld) :
```ld
PRAM (xrw) : ORIGIN = 0x00060000, LENGTH = 65K /* PRAM5 */
```

부트로더 자신의 코드·데이터·벡터 테이블·스택이 모두 PRAM5 안에 위치.

#### F-2. CM3 펌웨어 적재 영역 = PRAM0~PRAM6 (0x00010000, 384 KB)

[`2__cm3/sections.ld:31`](../../../../src/2__cm3/sections.ld) :
```ld
PRAM (xrw) : ORIGIN = 0x00010000, LENGTH = 384K
```

**겹침 영역 존재**: CM3 적재 영역 (0x10000~0x70000) 안에 부트로더 영역 (0x60000~0x70000, PRAM5) 이 포함됨.

다만 펌웨어 빌드/링크 시점에서 CM3 펌웨어 이미지가 PRAM5 영역을 사용하지 않도록 **이미 분리되어 운용 중** (그렇지 않으면 부트로더가 CM3 적재 중 자기 자신을 덮어써서 즉사 — 실제로 동작하므로 분리되어 있다고 판단). Case ① 의 "부트로더 ISR 핸들러 덮어쓰기" 위험은 실 운용에서 검증된 분리 상태로 무력화됨.

> [!NOTE]
> 안전 측면에서 `bootloader_transfer_section_data` (`bootloader.c:344`) 의 SEC_CM3_P 처리에서 `Sys_Memory_Enable(... CM3_PRAM5_POWER_ENABLE | ..., 0)` 가 PRAM5 를 power enable 하지만 disable 인자가 0 이므로 실제 부트로더 PRAM5 영역의 데이터는 보존된다.

#### F-3. 부트로더는 모든 인터럽트를 비활성 상태로 시작

[`0__bootloader/main.c:39-42`](../../../../src/0__bootloader/main.c) :
```c
__set_PRIMASK(PRIMASK_DISABLE_INTERRUPTS);
Sys_NVIC_DisableAllInt();
Sys_NVIC_ClearAllPendingInt();
__set_PRIMASK(PRIMASK_ENABLE_INTERRUPTS);
```

PRIMASK 는 ENABLE 로 풀어두지만 NVIC 의 모든 IRQ 가 disable + pending clear 상태 → 실제 ISR 가동 없음.

**Case ② 무력화**: NVIC 설정은 부트로더 main 직후 위 코드로 통일 상태이며, 이후 부트로더가 NVIC 를 변경하지 않음.

#### F-4. 부트로더는 polling-only — 가동 중 ISR 없음

조사 (Explore agent grep, 2026-04-30):
- [`tdc_uart.c:95, 122`](../../../../src/0__bootloader/source/uart/tdc_uart.c) — UART TX/RX 전부 STATUS 레지스터 polling
- [`tdc_util.c:9`](../../../../src/0__bootloader/source/tdc_util.c) — `tdc_delay_us()` = `Sys_Delay()` busy-wait
- [`bootloader.c:457`](../../../../src/0__bootloader/source/bootloader.c) — DMA 완료 대기도 polling
- 부트로더 .c 전체에 `_IRQHandler`, `SysTick_Handler` 등 **활성 ISR 핸들러 정의 없음**

**Case ③ 무력화**: 부트로더가 인터럽트를 끄는 critical section 도, 활성 ISR 핸들러도 없음. SW PWM ISR 만 새로 추가하는 것이라 다른 ISR 와 충돌도 없음.

#### F-5. 부트로더는 타이머를 전혀 사용하지 않음

부트로더 폴더 전체에서 `Timer3`, `GPT3`, `Sys_Timer*`, `GeneralTimer` 등 타이머 사용 흔적 없음. **모든 타이머가 가용**.

(타이머3 가용성은 Phase 2 Q-PWM-1 에서 추가 정밀 확인하지만, 부트로더 영역에서의 충돌 가능성은 0.)

#### F-6. CM3 적재는 DMA 기반 — CPU 영향 없음

[`bootloader.c:261-`](../../../../src/0__bootloader/source/bootloader.c) `bootloader_transfer_section_data` 가 메모리 적재 핵심:
- DMA 채널 `SECTION_TRANSFER_DMA`, `CRC_CALCULATION_DMA` 사용
- CPU 는 DMA 시작 후 polling 으로 완료 대기 (line 457) — ISR 활성 시에도 대기 중 ISR 처리 가능

### 1.3 판정

| Case | 결과 |
|---|---|
| ① 벡터 테이블 / ISR 핸들러 덮어쓰기 | **무력화** (F-1, F-2: 부트로더 PRAM5 와 CM3 적재 영역의 실 운용 분리) |
| ② NVIC 설정 변경으로 ISR 깨짐 | **무력화** (F-3: 부트로더 NVIC 단일 상태 유지) |
| ③ 인터럽트 비활성 구간으로 ISR 멈춤 | **무력화** (F-3, F-4: 부트로더에 critical section 없음, polling-only) |

**R-11 판정 = 가능 ✅**

부트로더에 SW PWM 타이머 ISR 1 개를 추가하면, ISR 이 PRAM5 안에 위치 (부트로더 코드와 함께) 하므로 CM3 적재의 영향 없음. NVIC 비활성 상태에서 시작하므로 ISR 활성화는 본 작업 코드가 직접 NVIC_EnableIRQ 를 호출해서 켜야 하며, 종료 시 (`bootloader_boot_cm3()` 직전) NVIC_DisableIRQ + 타이머 정지로 정상 인계.

### 1.4 구현 시 의무 사항 (Phase 2 → 구현계획 입력)

| ID | 의무 사항 | 근거 |
|---|---|---|
| O-1 | 본 작업의 SW PWM 타이머 ISR / 데이터 구조는 **부트로더 PRAM5 안에만** 배치 (link 시 부트로더 sections.ld 영역 사용). CM3 영역에 상주하면 안 됨 | F-1 / F-2 겹침 |
| O-2 | SW PWM 활성화 = `Sys_NVIC_DisableAllInt()` (main.c:40) 이후 본 작업 코드에서 **명시적 NVIC_EnableIRQ + 타이머 IRQ enable** 수행 | F-3 |
| O-3 | SW PWM 종료 = [`bootloader.c:1374`](../../../../src/0__bootloader/source/bootloader.c) `bootloader_boot_cm3()` 호출 직전에 **NVIC_DisableIRQ + 타이머 정지 + LED OFF** | 요구사항.md AC-7 |

### 2.2 Q-PWM-2 / R-8 — CM3 LED 엔진 재사용 → 자체 구현

#### 사용자 결정 (2026-04-30)

CM3 LedOutput.c (`LED_OUT()`, `k_led_mix`, `tdc_led_write_gpio()`) **재사용 X**. 부트로더 SKYBLUE 단색 fade 루틴 **자체 구현**.

이유 — 부트로더 LED 와 정식 LED_ST_POWER_ON 의 매개변수 차이:

| 항목 | 부트로더 (본 작업) | 정식 LED_ST_POWER_ON | 비고 |
|---|---|---|---|
| 색 | SKYBLUE 단색 | LED_ST_* 별 다양 | 부트로더는 단일 |
| Fade-in | 30 ms | 30 ms | 동일 |
| Peak | **300 ms** | ~150 ms | **부트로더 2 배** (강조) |
| Fade-out | 30 ms | 30 ms | 동일 |
| Off 유지 | 180 ms | 180 ms | 동일 |
| 1 cycle | **540 ms** | ~390 ms | |

CM3 코드를 그대로 가져오면 시간 매개변수 분리 + 빌드 환경 분리 부담 大. SKYBLUE 단색 전용 가벼운 SW PWM 자체 구현이 코드량·복잡도 모두 적음.

#### 자체 구현 권고 형상

- SW PWM 타이머 ISR 1 ms 주기 (또는 더 빠르게 dimming 분해능 확보).
- LED 핀 직접 GPIO write (G = DIO15, B = DIO12 — §2.6 참조).
- duty 비율 = `k_led_mix[en__LED_SKYBLUE]` 와 동일 (R=0, G=30, B=40 — [LedOutput.c:820-912](../../../../src/2__cm3/Cortex-M3-src/systemControl/LedOutput.c) 참조). 부트로더는 이 상수만 차용.
- phase machine: `FADE_IN(30 ms)` → `PEAK(300 ms)` → `FADE_OUT(30 ms)` → `OFF(180 ms)` → 반복 (또는 1 cycle 후 정지).
- LED OFF 진입 시 cancel branch 처리는 [non-blocking-fade-off 이력 §8](../non-blocking-fade-off/이력 및 결과.md) 패턴 차용 — 색 변수와 카운터 명시적 0 reset.

### 2.3 Q-PWM-3 / R-12 — T-A vs T-B 클럭 전환점

#### 조사 결과 (Explore 2026-04-30) — main → Sys_Trims_SetOperatingFrequency 호출 흐름

| # | 단계 | 위치 | 시간 |
|---|---|---|---|
| 1 | `main()` 본체 (DIO config × 7, GPIO write × 4, NVIC clear, UART init) | [main.c:13-84](../../../../src/0__bootloader/main.c) | < 1 ms |
| 2 | `bootloader_main()` 진입 | [bootloader.c:1596](../../../../src/0__bootloader/source/bootloader.c) | 즉시 |
| 3 | `bootloader_boot()` 진입 | [bootloader.c:1380](../../../../src/0__bootloader/source/bootloader.c) | 즉시 |
| 4 | `NVMGetDefaultOptions()`, `NVMInit()` | NVM 초기화 | < 1 ms |
| 5 | `bootloader_read_nvm_boot_info()` | NVM/Flash 읽기 (BOOT_SPEED 스위치, QSPI 재시도 ≤ 3) | **수 ~ 수십 ms** |
| 6 | `bootloader_load_manu_table()` 진입 | [bootloader.c:1496](../../../../src/0__bootloader/source/bootloader.c) | 즉시 |
| 7 | **`NVMReadBytes(boot_manu_off, 256, _data_temp_buffer)`** | [bootloader.c:532](../../../../src/0__bootloader/source/bootloader.c) — EEPROM 256 byte 읽기 | **수십 ms** (저속 동기 I/O — 가장 큰 시간 소비) |
| 8 | CRC 검증 + 데이터 검증 + UART dump | bootloader.c:533-600 | 수 ms |
| 9 | `Sys_Trims_LoadManuTable()` + 전압 트림 × 8 + MANU_CLK 순회 | bootloader.c:601-642 | 수 ms |
| 10 | **`Sys_Trims_SetOperatingFrequency(max_target)`** ← **클럭 7.68 → 30.72 MHz** | [bootloader.c:643](../../../../src/0__bootloader/source/bootloader.c) | < 1 ms |

**T-A → T-B 시간 = 수십 ms** (NVMReadBytes EEPROM 읽기 비중 大).

#### T-A 채택 시 문제

- Fade-in 30 ms 시작 후 도중에 클럭 4 배 빨라짐 → SW PWM 타이머 IRQ 주기 4 배 빨라짐 → 남은 fade-in 시간 + Peak + Fade-out 모두 1/4 로 단축.
- Peak 300 ms → 75 ms 로 줄어 사용자 인지 패턴 ('삑—') 자체 깨짐.
- 보정하려면 `Sys_Trims_SetOperatingFrequency()` 호출 hook 추가 (외부 함수에 의존성 침습) — 부트로더 코드 변경량 大.

#### T-B 채택 (권고)

- 클럭 30.72 MHz 안정 상태에서 SW PWM 시작 → 타이머 reload 단일 상수.
- 점등 시작 지연 = 수십 ms (전체 단축 1170 ms 대비 무시 가능).
- 사용자 인지 패턴 일정성 보장.

#### 결정 = T-B

**SW PWM 시작 시점 = `Sys_Trims_SetOperatingFrequency()` 호출 직후** ([bootloader.c:643](../../../../src/0__bootloader/source/bootloader.c) 직후).

### 2.4 R-1 — GPIO 리셋 디폴트 + 자연 OFF 활용

#### 사용자 제공

- ROM 리셋 직후 모든 DIO = `DIO_MODE_DISABLE` (hi-Z 상태).
- LED 회로는 **풀다운 저항** 으로 LOW 인입 → **active HIGH** (D-8 §2.7) 라서 **물리적으로 OFF** 인 자연 상태 유지.

#### 결정 — main.c 디버그 GPIO 블록을 빌드 가드로 무력화

부트로더 [main.c:13-22](../../../../src/0__bootloader/main.c) 의 `#if 1` 디버그 LED 블록은 `Sys_DIO_Config()` + `Sys_GPIO_Set_*()` 로 LED 핀을 즉시 활성. active HIGH 일관 시 이 블록 결과는:

- `Sys_GPIO_Set_Low(DIO_NUM_LED_R_UART_TX_E8300)` → R = LOW = R LED **OFF** (active HIGH)
- `Sys_GPIO_Set_High(DIO_NUM_LED_G_UART_RX_E8300)` → G = HIGH = G LED **ON**
- `Sys_GPIO_Set_High(DIO_NUM_LED_B)` → B = HIGH = B LED **ON**
- 시각적 결과 = **G+B 풀밝기 = 청록색 (CYAN-ish)** — k_led_mix[en__LED_SKYBLUE] (G:B = 30:40) 비율과 다른 전체 ON.

본 작업 활성 시 이 디버그 블록이 그대로 실행되면:
- T < T-B (수십 ms): G+B 풀밝기 점등
- T = T-B: SW PWM SKYBLUE fade-in 시작 → 풀밝기 → 어두워졌다 다시 fade-in 처럼 보임 (의도와 불일치)

→ **빌드 가드 활성 시 main.c:13-22 디버그 블록 전체를 빌드 가드 분기로 무력화**. GPIO 가 `DIO_MODE_DISABLE` (hi-Z) 상태로 유지 → 풀다운으로 LED **자연 OFF**. T-B 도달 시 본 작업 코드가 GPIO config 활성 + SW PWM 시작 → fade-in 으로 자연 점등.

```c
/* main.c:13-22 영역 */
#if !BOOTLOADER_LED_INDICATOR_ENABLE
    /* 기존 디버그 LED (가드 OFF 시 그대로 동작) */
    Sys_DIO_Config(DIO_NUM_LED_R_UART_TX_E8300, ...);
    Sys_DIO_Config(DIO_NUM_LED_G_UART_RX_E8300, ...);
    Sys_DIO_Config(DIO_NUM_LED_B,               ...);
    Sys_GPIO_Set_Low(DIO_NUM_LED_R_UART_TX_E8300);   /* R OFF (active HIGH) */
    Sys_GPIO_Set_High(DIO_NUM_LED_G_UART_RX_E8300);  /* G ON  (active HIGH) */
    Sys_GPIO_Set_High(DIO_NUM_LED_B);                /* B ON  (active HIGH) */
#else
    /* 본 작업 활성 — 디버그 블록 무력화. GPIO = DIO_MODE_DISABLE 유지.
     * 풀다운 저항으로 자연 OFF. T-B 도달 시 본 작업 SW PWM 이 GPIO config 후 fade-in 진입.
     */
#endif
```

#### 부수 효과

부트로더 진입 알림 의도였던 디버그 LED (G+B 풀밝기) 가 빌드 가드 ON 시 사라짐. 대신 본 작업 SKYBLUE fade-in 이 T-B (= 수십 ms 지연) 에 시작하므로 사용자 인지 손실 X (오히려 강화).

### 2.5 R-3 — Off 유지 + 부트로더 점프 시점 처리

#### 사용자 결정 (2026-04-30)

부트로더 SW PWM 1 cycle = SKYBLUE **360 ms** + OFF **180 ms** = **540 ms**.

| 케이스 | 부트로더 작업 완료 시점 | 처리 |
|---|---|---|
| A | ≥ 540 ms | 작업 완료 직후 SW PWM 정리 ([O-3]) → `bootloader_boot_cm3()` |
| B | < 540 ms | **540 ms 도달까지 wait** → SW PWM 정리 ([O-3]) → `bootloader_boot_cm3()` |

#### 사용자 인지 패턴

```
시간:   0        360       540        ?         ? + 30
        ├────────┼─────────┼──────────┼─────────┼──────────────
        SKYBLUE  OFF       (CM3 진입) OFF       LED_ST_POWER_ON
                 fade in   wait ≥ 0   잔여      fade-in 30 ms
                                                 (CM3 측 OFF→ON)
        '삑—'    '_____'  ─────── ' __ '─────── '삑, 삑, 삑, 삑, 삑'
```

부트로더 OFF 유지 180 ms + CM3 진입 잔여 시간 + CM3 fade-out 30 ms = **최소 210 ms 의 OFF 시간** 보장. (CM3 실제 fade-in 까지의 시간이 더 길면 OFF 더 길어짐 — 자연스러움.)

#### 구현 형상

- 본 작업 모듈 내부 `bli_state_t` (phase + elapsed_ms) 상태 머신.
- `bootloader_boot()` 끝 (= `bootloader_boot_cm3()` 호출 직전, [bootloader.c:1374](../../../../src/0__bootloader/source/bootloader.c) 부근) 에 wait 로직:
```c
#if BOOTLOADER_LED_INDICATOR_ENABLE
    while (bli_get_total_elapsed_ms() < 540) {
        /* SW PWM ISR 가 LED 출력 갱신 — main loop 는 기다림만 */
    }
    bli_stop();  /* O-3: NVIC_DisableIRQ + 타이머 정지 + LED OFF */
#endif
    bootloader_boot_cm3(cm3_boot_data.stack_pointer, cm3_boot_data.init_pointer);
```

### 2.6 R-4 / R-5 / R-6 — UART/LED 핀 공유 + 빌드 가드 + 검증 핀 2 단 분기

#### 핀 매핑 (Explore 2026-04-30)

| LED | 부트로더 핀 (DIO 번호) | UART 공유 | 매크로 |
|---|---|---|---|
| R | **DIO8** | UART **TX** 와 공유 | `DIO_NUM_LED_R_UART_TX_E8300` ([main.h:10](../../../../src/0__bootloader/include/main.h)) |
| G | **DIO15** | UART **RX** 와 공유 | `DIO_NUM_LED_G_UART_RX_E8300` ([main.h:11](../../../../src/0__bootloader/include/main.h)) |
| B | **DIO12** | LED 전용 (UART 무관) | `DIO_NUM_LED_B` ([main.h:12](../../../../src/0__bootloader/include/main.h)) |

GPIO API: `Sys_DIO_Config(pin, cfg_flags)`, `Sys_GPIO_Set_High/Low(pin)`, `Sys_GPIO_Read(pin)`.

#### UART 사용 여부 검증 핀 (조사 결과)

부트로더가 이미 런타임에 UART 사용 여부를 검증 핀 레벨로 판단하는 로직이 존재:

```c
/* main.c:59 */
tdc_uart_set_enable(Sys_GPIO_Read(DIO_NUM_UART_ENABLE) == DIO_ACTIVE_LEVEL_UART_ENABLE);
```

- `DIO_NUM_UART_ENABLE` = UART 활성/비활성 검증 핀 (정의 위치: 부트로더 헤더, 본 작업 단계에서 식별 후 그대로 사용)
- `DIO_ACTIVE_LEVEL_UART_ENABLE` = 활성 레벨 (HIGH/LOW)
- 결과 = `true` → UART 활성, `false` → UART 비활성

#### 충돌

SKYBLUE = G + B → **G 핀 (DIO15) 이 UART RX 와 충돌**. UART 활성 시 G 핀을 LED 로 쓸 수 없음.

#### 사용자 결정 (2026-04-30, 2 차 갱신) — 빌드 가드 + 런타임 검증 핀 2 단 분기

| 빌드 가드 | 검증 핀 → UART | LED 동작 | UART 동작 |
|---|---|---|---|
| `=0` (기본) | 활성 | LED 무관 (본 작업 미빌드) | UART 정상 (RX/TX 모두) |
| `=0` (기본) | 비활성 | LED 무관 (본 작업 미빌드) | UART 비활성 (기존 부트로더 동작 그대로) |
| `=1` (활성) | 활성 | **LED 사용 X** (본 작업 런타임 비활성) | UART 정상 (RX/TX 모두) |
| `=1` (활성) | 비활성 | **LED 사용 O** (본 작업 SW PWM SKYBLUE 점등) | UART 비활성 |

핵심:
- **빌드 가드 OFF**: 본 작업 코드 자체가 빌드되지 않음. 부트로더는 기존과 동일하게 UART 검증 핀에 따라 분기 (UART 활성/비활성). LED 동작은 main.c 디버그 블록 (active HIGH 일관 시 G+B 풀밝기) 그대로.
- **빌드 가드 ON**: 본 작업 코드 빌드되지만 **런타임 시작 시 검증 핀 read**. UART 활성이면 본 작업 SW PWM 자체를 시작하지 않음 (LED 비활성, GPIO `DIO_MODE_DISABLE` 유지 → 풀다운 자연 OFF). UART 비활성이면 본 작업 SW PWM 시작 (T-B 도달 시).

#### 결정 형상 (의사 코드)

```c
/* T-B 도달 직후 (Sys_Trims_SetOperatingFrequency 직후) — bootloader.c:643 부근 */
#if BOOTLOADER_LED_INDICATOR_ENABLE
    bool uart_active = (Sys_GPIO_Read(DIO_NUM_UART_ENABLE) == DIO_ACTIVE_LEVEL_UART_ENABLE);
    if (!uart_active) {
        /* UART 비활성 → LED 점등 가능 */
        bli_init();   /* GPIO config (G/B as output, R as input or 0), Timer2 start, NVIC enable */
        bli_start_skyblue_cycle();
    }
    /* uart_active == true 이면 본 작업 비활성 — GPIO disable 유지, UART RX 정상 */
#endif
```

- [main.c:65](../../../../src/0__bootloader/main.c) — `tdc_uart_init()`

본 작업 활성 + UART 비활성 시: 부트로더가 자체적으로 UART 비활성 판단 후 `tdc_uart_init` 등이 무력화 (또는 RX 부분 skip). 본 작업이 G/B 핀 점유 정상.

### 2.7 LED 극성 — active HIGH 확정

#### 사용자 결정 (2026-04-30)

**LED 는 active HIGH** — GPIO HIGH = LED ON, GPIO LOW = LED OFF.

#### 회로 정합성

- **풀다운 저항**: 전원 인가 직후 GPIO 가 `DIO_MODE_DISABLE` (hi-Z) 상태일 때 풀다운으로 LOW 인입 → active HIGH LED → **물리적 OFF** 자연 유지 (사용자 명시 — §2.4 활용).

#### 기존 코드 정합성 재검토

- [main.c:18-22](../../../../src/0__bootloader/main.c) (디버그 LED 블록):
  - `Sys_GPIO_Set_Low(R)` → R = LOW = R LED **OFF** (active HIGH 기준)
  - `Sys_GPIO_Set_High(G)` → G = HIGH = G LED **ON**
  - `Sys_GPIO_Set_High(B)` → B = HIGH = B LED **ON**
  - 시각적 결과 = G+B 풀밝기 = **청록색 점등** (k_led_mix[en__LED_SKYBLUE] G:B=30:40 비율과 다른 100:100 풀밝기)
- [LedOutput.c:820-912](../../../../src/2__cm3/Cortex-M3-src/systemControl/LedOutput.c) 의 `LED_IS_ACTIVELOW` 컴파일 스위치 = **주석 처리** 상태 (정의 안 됨) → CM3 LED 출력 함수도 active HIGH 흐름. ✅ 정합.

#### [non-blocking-fade-off 이력 및 결과.md](../non-blocking-fade-off/이력 및 결과.md) §1 정보 갱신

이력 §1 의 OTE_ver1_5 commit message "active LOW" 정보는 본 작업 단계에서 사용자 직접 입력으로 갱신 (active HIGH). board 변경 또는 commit message 와 실 회로 불일치 가능성. 본 작업은 active HIGH 로 진행.

#### 결정

본 작업 자체 구현 시 **active HIGH 일관 적용**:
- LED ON = GPIO HIGH (`Sys_GPIO_Set_High(pin)`)
- LED OFF = GPIO LOW (`Sys_GPIO_Set_Low(pin)`) 또는 `DIO_MODE_DISABLE` (hi-Z + 풀다운)
- SW PWM ISR 의 ON/OFF 토글 = HIGH/LOW write
- duty cycle 의 "ON 비율" = HIGH 시간 / 주기 (직관적, 부정 논리 X)
