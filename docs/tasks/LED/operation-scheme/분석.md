# LED 운용 방식 분석

**TL;DR**: E8300 외부기기 RGB LED 1개로 전원·에러·BLE·매핑·배터리·ISD 등 다중 소스의 상태 표시. Arbiter가 매 tick 우선순위 기반으로 하나를 선출하고 패턴 엔진이 디스크립터 테이블·burst 자가 해제로 출력하는 구조. Rev.0~5 통합본으로 구현 완료, 실기 검증 대기 상태이며 표기 규칙(`ON Xms / OFF Yms` ≡ `(on_ms, period_ms)`)을 정의.

작성자: 김은수
최종 갱신: 2026-04-16 (Rev.0~5 통합본)
상태: 구현 완료. 실기 검증 대기.

> **표기 규칙**
> - 점멸 패턴: `ON Xms / OFF Yms` (한 주기 = X + Y ms)
> - 점멸 없음: `지속 ON`
> - 코드 디스크립터: `(on_ms, period_ms)` → `period_ms = on_ms + off_ms`
>   예) `(1100, 2200)` = ON 1100ms / OFF 1100ms

---

## 1. 개요

E8300 외부기기의 RGB LED 1개를 사용하여 기기 상태를 사용자에게 표시한다. 전원, 에러, BLE, 매핑, 배터리, ISD(자극장치) 등 여러 소스가 동시에 LED를 요청할 수 있으며, Arbiter(중재기)가 우선순위에 따라 하나를 선택하여 표시한다.

스펙 원본: [`docs/led_ind_state.JPG`](led_ind_state.JPG)

## 2. 아키텍처

```
 [요청 소스]                [Arbiter]                  [패턴 출력]             [HW]

 systemControl.c ──┐
   (Power On/Off)  │
                   │
 systemControl.c ──┤
   (Error)         │
                   │
 remoteControl.c ──┤                               ┌────────────────────┐
   (BLE/OTA/PAIR)  │   ┌────────────────────┐      │  Pattern Engine    │
                   ├──►│  led_request()     │      │                    │
 main.c ───────────┤   │                    ├─────►│  디스크립터 테이블 ├──► LED_OUT() ──► GPIO
   (Mapping)       │   │  · prio 테이블     │      │  burst 자가 해제   │     (RGB)
                   │   │  · user_off 필터   │      │                    │
 main.c ───────────┤   │  · PAIR 500ms latch│      └────────────────────┘
   (Battery)       │   └────────────────────┘
                   │
 main.c ───────────┘
   (ISD)
```

**동작 흐름**:
1. 각 소스가 `led_request(소스, 상태)`로 자신의 요청을 등록
2. Arbiter가 매 tick 가장 높은 우선순위 요청을 선택
3. Pattern Engine이 해당 패턴(색상, 점멸 타이밍)을 GPIO로 출력

## 3. LED 상태 한눈에 보기

### 색상·패턴 요약표

| 상태 | 색상 | 패턴 | prio | 소스 |
|---|---|---|---|---|
| POWER_OFF | 🔵 파랑 | ON 100ms / OFF 200ms × 4회 | 100 | Power |
| POWER_ON | 🔵 하늘색 | ON 80ms / OFF 220ms × 5회 | 95 | Power |
| ERROR_* (5종) | 🔴 빨강 | ON 180ms / OFF 180ms | 90 | Error |
| OTA_QCC | 🟢 녹색 | ON 1100ms / OFF 1100ms | 80 | BLE |
| OTA_EZAIRO | 🟢 녹색 | ON 180ms / OFF 180ms | 80 | BLE |
| MAPPING_ISD | 🔵 파랑 | 지속 ON | 75 | Mapping |
| MAPPING_NO_ISD | 🔵 파랑 | ON 1100ms / OFF 1100ms | 75 | Mapping |
| PAIR | 🔵 파랑 | ON 180ms / OFF 180ms (500ms latch) | 70 | BLE |
| BATT_CRITICAL | 🟡 노랑 | ON 1100ms / OFF 1100ms | 60 | Battery |
| IN_USE | ⚪ 흰색 | 지속 ON | 40 | ISD |
| BATT_READY | 🟢 녹색 | 지속 ON | 30 | Battery |
| BATT_MID | 🟡 노랑 | 지속 ON | 20 | Battery |
| IDLE | — | OFF | 10 | — |

### 우선순위 시각화

```
prio 100  ████████████████████████████████  POWER_OFF       ← Error도 선점하는 유일한 상태
prio  95  ██████████████████████████████    POWER_ON
prio  90  ████████████████████████████      ERROR_*         ← 일반 표시 전부 선점
prio  80  ██████████████████████████        OTA_QCC / OTA_EZAIRO
prio  75  ████████████████████████          MAPPING_ISD / MAPPING_NO_ISD
prio  70  ██████████████████████            PAIR
prio  60  ████████████████████              BATT_CRITICAL   ← IN_USE 선점 가능
prio  40  ████████████████                  IN_USE
prio  30  ██████████████                    BATT_READY
prio  20  ████████████                      BATT_MID
prio  10  ██████████                        IDLE (off)
```

### 점멸 속도 구분

같은 색상이라도 점멸 속도로 상태를 구분할 수 있다:

```
 녹색 계열:
   ■■■■■■■■■■■■■■■■■■■■       (지속 ON)   = BATT_READY / IN_USE(흰색)
   ■■■■■■     ■■■■■■     ■■■■■■  (느린)   = OTA_QCC     (1100ms / 1100ms)
   ■■ ■■ ■■ ■■ ■■ ■■ ■■ ■■ ■■    (빠른)   = OTA_EZAIRO  ( 180ms /  180ms)

 파랑 계열:
   ■■■■■■■■■■■■■■■■■■■■       (지속 ON)   = MAPPING_ISD
   ■■■■■■     ■■■■■■     ■■■■■■  (느린)   = MAPPING_NO_ISD (1100ms / 1100ms)
   ■■ ■■ ■■ ■■ ■■ ■■ ■■ ■■ ■■    (빠른)   = PAIR           ( 180ms /  180ms)

 노랑 계열:
   ■■■■■■■■■■■■■■■■■■■■       (지속 ON)   = BATT_MID
   ■■■■■■     ■■■■■■     ■■■■■■  (느린)   = BATT_CRITICAL (1100ms / 1100ms)
```

## 4. 소스별 동작 규칙

### 4.1 Power (전원)

요청 위치: `systemControl.c`

```
                  ┌──────────┐     버스트 5회 완료
 초기화 성공 ────►│ POWER_ON │────────────────────► NONE (자가 해제)
 & 에러 없음      └──────────┘

                  ┌───────────┐    버스트 4회 완료
 Power Off  ─────►│ POWER_OFF │────────────────────► NONE (자가 해제)
 조건 성립        └───────────┘
```

- 버스트 완료 시 Pattern Engine이 자동으로 `NONE`으로 해제
- `systemControl()`은 `led_is_power_burst_in_progress()`로 버스트 진행 여부를 게이트로 사용
- 초기화 중 에러 발생 시 POWER_ON 요청 자체를 내지 않음 → ERROR만 표시

### 4.2 Error (에러 표시)

요청 위치: `systemControl.c`

| 상태 | 조건 | 패턴 |
|---|---|---|
| `ERROR_MCU` | MCU 데이터 처리 에러 | 빨강 ON 180ms / OFF 180ms |
| `ERROR_MAP` | 매핑 데이터 에러 | 〃 |
| `ERROR_ACCEL` | 가속도센서 에러 | 〃 |
| `ERROR_FPGA` | FPGA 통신 에러 | 〃 |
| `ERROR_PMIC` | PMIC 에러 | 〃 |

- 5종 모두 동일한 빨강 빠른 점멸 (에러 구분은 이벤트 로그로 식별)
- `POWER_OFF` 외 모든 상태를 선점 (prio 90)
- 에러 복구 시 `led_request(ERROR, NONE)`으로 해제

### 4.3 BLE (블루투스 표시)

요청 위치: `remoteControl.c`, `ci_ota.c`

| 상태 | 조건 | 패턴 |
|---|---|---|
| `PAIR` | BLE 인증/연결 진행 중 | 파랑 ON 180ms / OFF 180ms (500ms latch) |
| `OTA_QCC` | QCC 펌웨어 업데이트 중 | 녹색 ON 1100ms / OFF 1100ms |
| `OTA_EZAIRO` | Ezairo 펌웨어 업데이트 중 | 녹색 ON 180ms / OFF 180ms |

- QCC와 Ezairo OTA는 점멸 속도로 시각 구분 (느린 vs 빠른)
- BLE `led_ind=BATT`는 별도 LED 상태가 아님 — 본체 배터리 판정 표시를 트리거하는 신호로만 해석 (사실상 no-op)
- PAIR latch: 인증 시간이 매우 짧아 LED 표시가 불가능할 수 있으므로, 최소 500ms 유지

### 4.4 Mapping (매핑 프로그램 연결)

요청 위치: `main.c` (매 tick)

```
                        ┌─────────────────┐
 매핑 연결 ────────────►│                 │
   & ISD 미연결         │ MAPPING_NO_ISD  │ ◄──── 파랑 점멸 (1100/1100)
                        │                 │
                        └────────┬────────┘
                                 ▲ ISD 연결
                                 │ 
                                 ▼ ISD 해제
                        ┌────────┴────────┐
                        │                 │
                        │  MAPPING_ISD    │ ◄──── 파랑 지속 ON
                        │                 │
                        └─────────────────┘

 매핑 해제 → NONE
```

- 매 tick `BLE_communicationState.mappingConnection` 확인
- BATT_CRITICAL, IN_USE, BATT_READY, BATT_MID를 선점 (prio 75)

### 4.5 Battery (배터리)

요청 위치: `main.c` (매 tick)

```
              ┌──────────────────────────────────────────────────────────┐
              │          배터리 퍼센트 판정 (충·방전 무관)               │
              │                                                          │
              │   0%        10%  12%              78%  80%         100%  │
              │   ├──────────┼────┼────────────────┼────┼──────────┤     │
              │   │          │    │                │    │          │     │
              │   │ CRITICAL │hyst│     MID        │hyst│  READY   │     │
              │   │  노랑    │    │   노랑         │    │  녹색    │     │
              │   │  점멸    │    │   지속 ON      │    │  지속 ON │     │
              │   │          │    │                │    │          │     │
              └──────────────────────────────────────────────────────────┘

   히스테리시스:
     CRITICAL 진입: pct < 10%     │ 해제: pct >= 12%  (±2%)
     READY 진입:    pct >= 80%    │ 해제: pct < 78%   (±2%)
```

| 상태 | 조건 | 패턴 |
|---|---|---|
| `BATT_READY` | 배터리 >= 80% | 녹색 지속 ON |
| `BATT_MID` | 10% <= 배터리 < 80% | 노랑 지속 ON |
| `BATT_CRITICAL` | 배터리 < 10% | 노랑 ON 1100ms / OFF 1100ms |

**판정 규칙**:
- `snd_batt_get_percent()`로 퍼센트 직접 참조
- 충전/방전 구분 없음 (충·방전 통합 규칙)
- 배터리 상태가 `RESET`(정보 미수신)이면 판정 보류 → `IDLE` 요청 (부팅 초기 노란색 LED 방지)

**BATT_CRITICAL 특수 규칙**:
- ISD 연결 중이라도 BATT_CRITICAL이 IN_USE를 선점 (prio 60 > 40)
- 단, 사용자 LED 비활성화 시 억제됨

### 4.6 ISD (자극장치)

요청 위치: `main.c` (매 tick)

| 상태 | 조건 | 패턴 |
|---|---|---|
| `IN_USE` | ISD 연결됨 | 흰색 지속 ON |

- `isd_state.conneded_ISD == true` → `IN_USE` 요청
- Mapping이 활성화되면 prio에서 자동 선점됨 (75 > 40)

## 5. Arbiter 동작

### 5.1 기본 로직

매 tick 실행:
1. 모든 소스의 현재 요청을 순회
2. 사용자 LED off 필터 적용
3. 가장 높은 prio의 상태를 선택
4. 선택된 상태의 패턴을 Pattern Engine으로 전달

### 5.2 사용자 LED off 플래그

`readLED_indicatorOnOff() == 2`일 때 활성화.

```
 ┌───────────────────────────────────────────────────┐
 │              사용자 LED off 적용 시               │
 │                                                   │
 │  표시 (예외):  ERROR_*  /  POWER_ON  /  POWER_OFF │
 │  억제 (OFF):   그 외 전부                         │
 │                                                   │
 │  → 안전·기기 생존 피드백만 유지                   │
 └───────────────────────────────────────────────────┘
```

### 5.3 PAIR latch (500ms)

BLE 인증 시간이 매우 짧을 수 있으므로, PAIR 요청이 들어오면 최소 500ms 동안 표시를 유지한다.

```
 시간 ──────────────────────────────────────────────►

 PAIR 요청 ──┐                            ┌── PAIR 해제 (자동)
             │        500ms latch         │
             ▼                            ▼
 LED:  ------■■■■■■■■■■■■■■■■■■■■■■■■■■■■------
             ▲                            ▲
             │                            │
          PAIR 해제가                  latch 만료.
          여기서 와도                  이 시점에 해제.
          무시함.
```

## 6. 패턴 디스크립터

코드에서 LED 패턴을 정의하는 테이블. `on_ms=0, period_ms=0`이면 지속 ON.

```c
/* LedOutput.c */
static const led_pattern_desc_t k_led_patterns[LED_ST__MAX] = {
/*  상태                    색상              on_ms  period  burst   사람이 읽는 패턴           */
    [LED_ST_NONE]           = { BLACK,           0,     0,    0 },  // OFF
    [LED_ST_IDLE]           = { BLACK,           0,     0,    0 },  // OFF

    [LED_ST_BATT_READY]     = { GREEN,           0,     0,    0 },  // 녹색 지속 ON
    [LED_ST_IN_USE]         = { WHITE,           0,     0,    0 },  // 흰색 지속 ON
    [LED_ST_BATT_MID]       = { ORANGE,          0,     0,    0 },  // 노랑 지속 ON
    [LED_ST_BATT_CRITICAL]  = { ORANGE,       1100,  2200,    0 },  // 노랑 ON 1100ms / OFF 1100ms

    [LED_ST_MAPPING_NO_ISD] = { BLUE,         1100,  2200,    0 },  // 파랑 ON 1100ms / OFF 1100ms
    [LED_ST_MAPPING_ISD]    = { BLUE,            0,     0,    0 },  // 파랑 지속 ON

    [LED_ST_PAIR]           = { BLUE,          180,   360,   0 },  // 파랑 ON 180ms / OFF 180ms
    [LED_ST_OTA_QCC]        = { GREEN,        1100,  2200,   0 },  // 녹색 ON 1100ms / OFF 1100ms
    [LED_ST_OTA_EZAIRO]     = { GREEN,         180,   360,   0 },  // 녹색 ON 180ms / OFF 180ms

    [LED_ST_ERROR_MAP]      = { RED,           180,   360,   0 },  // 빨강 ON 180ms / OFF 180ms
    [LED_ST_ERROR_MCU]      = { RED,           180,   360,   0 },  //   (에러 5종 모두 동일)
    [LED_ST_ERROR_ACCEL]    = { RED,           180,   360,   0 },
    [LED_ST_ERROR_FPGA]     = { RED,           180,   360,   0 },
    [LED_ST_ERROR_PMIC]     = { RED,           180,   360,   0 },

    [LED_ST_POWER_ON]       = { SKYBLUE,        80,   300,   5 },  // 하늘색 ON 80ms / OFF 220ms × 5회
    [LED_ST_POWER_OFF]      = { BLUE,          100,   300,   4 },  // 파랑 ON 100ms / OFF 200ms × 4회
};
```

`burst_cnt > 0`인 패턴은 N회 반복 후 자가 해제 (POWER_ON/OFF 게이트용).

## 7. 부팅 시퀀스

배터리 RESET 가드가 적용된 부팅 동작:

```
 시간 ─────────────────────────────────────────────────────────────────────►

 Initialize()        main loop 시작          QCC 0x34 수신 (~500ms)        버스트 완료
      │                    │                        │                          │
      ▼                    ▼                        ▼                          ▼
  batt_state=RESET     state==RESET              pct=90                    자가 해제
  batt_pct=0           → 판정 보류              state=DISCHARGING
                       → IDLE 요청              → BATT_READY 요청
                                                + POWER_ON 요청

 LED:  ────(off)──────────(off)───────────(하늘색 버스트 × 5)──────(녹색 지속 ON)───
                     ▲                    ▲
                     │                    │
              RESET 가드 덕분에         POWER_ON(prio 95) 이
              노란색(CRITICAL) 안 남.   BATT_READY(prio 30) 선점.
```

**핵심**: RESET 상태에서는 `pct=0`이어도 BATT_CRITICAL로 판정하지 않음 → 부팅 초기 노란색 LED 방지.

## 8. 요구사항 확정 (열린 이슈 8건)

설계 과정에서 발생한 8개 이슈와 결정 사항.

| # | 이슈 | 결정 | 근거 |
|---|---|---|---|
| 1 | 충전 중 LED 표시 | **폐지** | 충·방전 통합 규칙 채택. 스펙의 "충전 중 빨강 느린 점멸"은 통합 규칙과 상충 |
| 2 | 사용자 LED off 억제 범위 | **ERROR / POWER 예외, 나머지 전부 억제** | 안전·기기 생존 피드백만 유지 |
| 3 | READY/CRITICAL 수치 | **READY=80%, CRITICAL=10%, 히스테리시스 ±2%** | 스펙 이미지 기준 |
| 4 | PAIR latch | **최소 500ms** | 인증 시간이 짧아 최소 1주기(360ms) 이상 확보 필요 |
| 5 | BLE `led_ind=BATT` | **별도 상태 제거, 트리거 신호로만 해석** | 본체 배터리 판정과 충돌 방지 |
| 6 | POWER_ON/OFF 버스트 색/시간 | **기존값 유지** | 출하 제품에서 검증됨 |
| 7 | `LED_IS_ACTIVELOW` / `LED_B_pin_CFX_test` | **Active High 3채널 RGB 경로 기준** | Board_OTE_ver1_5.h에서 ACTIVEHIGH 확인 |
| 8 | 초기화 중 에러 → POWER_ON | **에러 시 POWER_ON 미요청** | ERROR와 POWER_ON 동시 래치 불가 |

## 9. 기존 코드 대응표

구 enum(`EN__LED_PATTERN`)에서 새 상태(`led_state_t`)로의 매핑:

| 기존 enum | 처리 |
|---|---|
| `en__LED_ISD_StimulationOut_batteryNormal/Low` | 제거 → `IN_USE` |
| `en__LED_StandbyForconneded_ISD_batteryNormal/Low` | 제거 → `BATT_READY` / `BATT_MID` / `BATT_CRITICAL` |
| `en__LED_MappingConneted_*` (4종) | 제거 → `MAPPING_ISD` / `MAPPING_NO_ISD` |
| `en__LED_BatteryChargingLevel_*` (7종) | 제거 (충전 레벨 dot-count 폐지) |
| `en__LED_Map_Error` 등 에러 5종 | 타이밍 ON 180ms / OFF 180ms 통일 |
| `en__LED_POWER_On/Off` | 유지 (게이트) |
| `en__LED_IND_BATT_STATE` | 제거 (BLE BATT는 no-op) |
| `en__LED_IND_PAIR_STATE` | `PAIR`로 통합 |

## 10. 검증 계획

### 10.1 단위 테스트

- 디스크립터별 ON 시간 / 한 주기 오차 ±1ms (tick 시뮬레이션)
- Arbiter 우선순위 선택: 모든 (소스 × 상태) 조합에서 최상위 prio 확인
- 사용자 off 플래그: 억제 대상 / 예외 대상 분리 확인
- PAIR latch: 해제 후 500ms 동안 유지 확인
- 히스테리시스: 9% → 11% → 9% 변화 시 CRITICAL 진입/유지/해제

### 10.2 통합 / HW 검증

오실로스코프 파형 확인 (±5% 이내):

| 패턴 | 대상 상태 |
|---|---|
| ON 180ms / OFF 180ms | PAIR, OTA_EZAIRO, ERROR_* |
| ON 1100ms / OFF 1100ms | BATT_CRITICAL, MAPPING_NO_ISD, OTA_QCC |
| ON 80ms / OFF 220ms × 5회 | POWER_ON |
| ON 100ms / OFF 200ms × 4회 | POWER_OFF |
| 지속 ON (DC 레벨) | BATT_READY, IN_USE, BATT_MID, MAPPING_ISD |

### 10.3 시나리오 테스트

| # | 시나리오 | 기대 결과 |
|---|---|---|
| a | 정상 부팅 → 배터리 90% | OFF → 하늘색 버스트 → 녹색 지속 ON. **노란색 없음** |
| b | 초기화 실패 | ERROR 즉시 (POWER_ON 없음) |
| c | 운용 중 ERROR 주입 | 기존 표시 즉시 선점 → 빨강 점멸 |
| d | POWER_OFF 요청 | ERROR보다 우선 → 파랑 버스트 |
| e | 매핑 연결 + ISD 미연결 | 파랑 ON 1100ms / OFF 1100ms |
| f | 매핑 연결 + ISD 연결 | 파랑 지속 ON |
| g | 배터리 9% + ISD 연결 | 노랑 ON 1100ms / OFF 1100ms (CRITICAL > IN_USE) |
| h | 배터리 9% + ERROR | 빨강 점멸 (ERROR > CRITICAL) |
| i | OTA_QCC | 녹색 ON 1100ms / OFF 1100ms |
| j | OTA_EZAIRO | 녹색 ON 180ms / OFF 180ms (i와 구분) |
| k | PAIR 100ms 짧은 이벤트 | 500ms latch로 표시 확인 |
| l | 배터리 30% (BATT_MID) | 노랑 지속 ON, 점멸 없음 |
| m | 사용자 LED off + BATT_CRITICAL | OFF (억제) |
| n | 사용자 LED off + ERROR | 빨강 점멸 (예외, 표시) |
