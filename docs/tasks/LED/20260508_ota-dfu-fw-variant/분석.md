# OTA DFU FW 이미지 변종별 LED 색상 정리 — 분석

**TL;DR**: 매크로 위치는 LedOutput.c 자체 (관심사 응집), 디폴트는 App (안전한 출고 default), 매크로 명은 `TDC_FW_VARIANT` (펌웨어 이미지 변종이라는 의미 명확). 디스크립터 표는 매크로 경유로 표기, 변종 매핑은 단일 헤더 주석에 표로 문서화.

작성일: 2026-05-08

---

## 1. 변경 영역 식별

`grep -n "en__LED_" LedOutput.c` 로 색 사용 위치 점검. 결과:

| 위치 | 사용 |
|---|---|
| `k_led_patterns[LED_ST__MAX]` (L196~223) | 디스크립터 표 — 패턴별 색 정의 |
| `k_led_mix[]` (L913~922) | 채널별 PWM duty cap (per-color 색감 보정) |
| `LED_black()` / `LED_White()` | Direct color (legacy) |

**변종 영향 범위 = 디스크립터 표 2 줄만**. `k_led_mix` 는 색 → R/G/B duty 매핑이라 변종 무관 (변종이 색 자체를 바꿔도 매핑은 그대로). Direct color 함수도 변종과 무관.

→ 매크로 분기는 디스크립터 표 입력 시점에서만 적용하면 충분.

---

## 2. 매크로 위치 후보 비교

| 후보 | 장점 | 단점 |
|---|---|---|
| **A. LedOutput.c 자체** | 관심사 응집, 디폴트가 코드 옆에, 외부 override 가능 (`-D`) | 다른 모듈에서도 변종 분기가 필요해질 때 헤더로 옮겨야 함 |
| B. board.h | 빌드 설정 응집 | LED 표현이 board.h 에 묻힘. 본 작업 시점엔 LED 만 영향 |
| C. processorDirective.h | 빌드 옵션 표준 위치 | LED-only 매크로를 빌드 옵션 파일에 두면 과잉 |

→ **A 선택**. 향후 변종 영향이 다른 모듈로 확대되면 `tdc_fw_variant.h` 같은 전용 헤더로 분리 가능 (현 단계 비파괴).

---

## 3. 디폴트 변종 결정

### 3.1 후보
- **(D-1) App 디폴트**: `#define TDC_FW_VARIANT TDC_FW_VARIANT_APP`
- (D-2) Factory Reset 디폴트: 사용자 현재 테스트 상태와 일치
- (D-3) 디폴트 없음 (`#error` 강제 명시): 안전하지만 빌드 옵션 항상 필요

### 3.2 비교

| 기준 | D-1 (App) | D-2 (Fact) | D-3 (강제) |
|---|---|---|---|
| 운용 출고 안전 | ✅ App=정식 | ❌ 잘못된 색으로 출고 위험 | ✅ |
| 사용자 현 setup 호환 | ❌ 한 줄 변경 필요 | ✅ | ❌ 한 줄 추가 필요 |
| "원래 시나리오" 일관 | ✅ 사용자 명시 = App | ❌ | △ |
| 빌드 시스템 변경 의존 | ❌ | ❌ | ✅ |

→ **D-1 (App) 선택**. 안전한 출고 default 가 우선. 사용자 현 setup 은 한 줄 변경 (`#define TDC_FW_VARIANT TDC_FW_VARIANT_FACTORY_RESET`) 으로 즉시 복귀.

---

## 4. 매크로 명 결정

### 4.1 후보
- (N-1) `TDC_LED_VARIANT` — LED 만의 변종
- **(N-2) `TDC_FW_VARIANT`** — 펌웨어 이미지 변종 (LED 는 그 식별 표시)
- (N-3) `TDC_OTA_DFU_VARIANT` — OTA DFU 컨텍스트 명시

### 4.2 비교

| 기준 | N-1 | N-2 | N-3 |
|---|---|---|---|
| 의미 정확성 | ❌ LED 가 이유가 아니라 결과 | ✅ 변종 = 이미지 종류 | △ DFU 가 매번 일어나는 게 아님 |
| 향후 확장성 | ❌ LED 외 분기 시 새 매크로 | ✅ 다른 분기도 같은 매크로 사용 | △ |
| 가독성 | ✅ 짧음 | ✅ 짧음 | ❌ 길음 |

→ **N-2 (`TDC_FW_VARIANT`) 선택**.

## 5. 색 매크로 추상화

```c
#define TDC_FW_LED_IN_USE_COLOR    en__LED_WHITE   /* 또는 PURPLE — 변종에 의해 결정 */
#define TDC_FW_LED_POWER_ON_COLOR  en__LED_SKYBLUE /* 또는 WHITE — 변종에 의해 결정 */
```

### 5.1 후보
- **(M-1) 색 매크로 추상화 (위와 같이)** — 디스크립터 표 행이 매크로 1 토큰으로 단순
- (M-2) `#if` 분기를 디스크립터 표 안에 직접 — 표 한 행이 여러 줄로 분할되어 표 가독성 손상

→ **M-1 선택**. 디스크립터 표는 한눈에 보이는 표 형태가 핵심 가치 (정렬된 칼럼).

---

## 6. 분기 형태

```c
#if (TDC_FW_VARIANT == TDC_FW_VARIANT_FACTORY_RESET)
    #define TDC_FW_LED_IN_USE_COLOR    en__LED_PURPLE
    #define TDC_FW_LED_POWER_ON_COLOR  en__LED_WHITE
#elif (TDC_FW_VARIANT == TDC_FW_VARIANT_APP)
    #define TDC_FW_LED_IN_USE_COLOR    en__LED_WHITE
    #define TDC_FW_LED_POWER_ON_COLOR  en__LED_SKYBLUE
#else
    #error "TDC_FW_VARIANT 미지원 값. APP 또는 FACTORY_RESET 만 허용."
#endif
```

`#elif (... == APP)` + `#else #error` 조합으로 잘못된 매크로 값 즉시 검출.

---

## 7. 인라인 코멘트 표기

기존:
```c
[LED_ST_IN_USE]   = { en__LED_PURPLE/*en__LED_WHITE*/, 0, 0, 0 },  // 흰색 지속 ON
```

변경:
```c
[LED_ST_IN_USE]   = { TDC_FW_LED_IN_USE_COLOR, 0, 0, 0 },  // 지속 ON (App=WHITE / FactRst=PURPLE)
```

코멘트는 표 안에서 변종별 색이 무엇인지 즉시 보이게 갱신. 정확한 매핑 표는 헤더 주석 블록에 둔다 (이중 문서화 회피, 표 한 곳에서 진실 유지).
