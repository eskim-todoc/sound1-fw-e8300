# OTA DFU FW 이미지 변종별 LED 색상 정리 — 요구사항

**TL;DR**: `LedOutput.c` k_led_patterns 표 안에 `en__LED_PURPLE/*en__LED_WHITE*/` 형태로 들어가 있던 OTA DFU 테스트용 임시 색 변경(현재=Factory Reset, 주석=App)을 빌드 매크로 `TDC_FW_VARIANT` 분기로 정리. 단일 매크로 한 줄 변경으로 두 변종 사이를 안전하게 전환.

작성일: 2026-05-08
작업 브랜치: `claude_feature_ota-dfu-fw-variant-led` (base: `claude_develop`)
모듈/슬러그: `LED/20260508_ota-dfu-fw-variant`

---

## 1. 배경

OTA DFU 테스트 시 동작 중인 펌웨어가 **운용 App 이미지**인지 **Factory Reset 이미지**인지 LED 색으로 즉시 식별하기 위해, 사용자가 [`LedOutput.c`](../../../../src/2__cm3/Cortex-M3-src/systemControl/LedOutput.c)의 패턴 디스크립터 표 2 곳을 임시 변경해 두었다.

| 상태 | 현재 (Factory Reset) | 주석 처리 (App) |
|---|---|---|
| `LED_ST_IN_USE` (L201) | `en__LED_PURPLE` | `en__LED_WHITE` |
| `LED_ST_POWER_ON` (L221) | `en__LED_WHITE` | `en__LED_SKYBLUE` |

```c
// 현재 형태 (코멘트 스왑 방식)
[LED_ST_IN_USE]   = { en__LED_PURPLE/*en__LED_WHITE*/,   0,    0,    0 },
[LED_ST_POWER_ON] = { en__LED_WHITE/*en__LED_SKYBLUE*/, 180,  360,  4 },
```

**문제**: 두 줄 모두 코멘트 스왑이라 ① 어느 쪽이 운용 디폴트인지 불분명, ② 두 곳을 동시에 잘못 바꾸면 일관성 깨짐 (예: IN_USE는 App, POWER_ON은 Factory Reset 으로 섞임), ③ 다른 작업자가 의도 파악 어렵고 실수로 한 줄만 되돌릴 위험.

---

## 2. 목표

빌드 매크로 한 곳 변경으로 두 변종 사이를 **원자적**으로 전환할 수 있도록 정리. 운용 디폴트는 App.

---

## 3. 범위

### In-scope
- `LedOutput.c` 안에 `TDC_FW_VARIANT` 매크로 분기 도입 (App / Factory Reset 두 변종)
- `LED_ST_IN_USE` / `LED_ST_POWER_ON` 의 색을 매크로 경유로 사용
- 기존 코멘트 스왑 흔적 제거
- 변종 의미 (어떤 색이 어떤 이미지인지) 헤더 주석으로 문서화

### Out-of-scope
- `ci_ble_control_boot.c` 의 QCC shutdown 시퀀스 변경 (snd_qcc_set_mode + 2200ms 대기) — OTA boot select 동작 fix 로 별도 작업
- `board.h` / `processorDirective.h` 등 빌드 설정 파일 수정 (현 단계는 LedOutput.c 자체 default 로 충분)
- 신규 색 값 추가, 디스크립터 표 다른 항목 손대기

---

## 4. 수용 기준 (Acceptance Criteria)

- AC-1. `TDC_FW_VARIANT` 미정의 시 디폴트가 **App** (즉 `LED_ST_IN_USE = WHITE`, `LED_ST_POWER_ON = SKYBLUE`).
- AC-2. `TDC_FW_VARIANT == TDC_FW_VARIANT_FACTORY_RESET` 정의 시 `LED_ST_IN_USE = PURPLE`, `LED_ST_POWER_ON = WHITE`.
- AC-3. 두 매크로 값(`TDC_FW_VARIANT_APP`/`TDC_FW_VARIANT_FACTORY_RESET`) 외 정의 시 컴파일 에러로 즉시 실패 (`#error`).
- AC-4. 디스크립터 표 두 줄에서 `/*...*/` 코멘트 스왑 흔적 제거. 매크로 사용으로 일관 표기.
- AC-5. 변종 매크로 정의 블록은 의도·맵핑·디폴트·사용법을 한눈에 보이는 헤더 주석으로 문서화 (변종 ↔ 색 표 포함).
- AC-6. 빌드 가드 OFF/ON 양쪽 모두 회귀 없음 — 디스크립터 표 외 다른 LED 동작 (점멸 시간, dimming, fade, GPIO 매핑) 무변경.
- AC-7. 본 작업은 **LedOutput.c + 작업 docs 산출물 만** 변경. `ci_ble_control_boot.c` 는 만지지 않는다.

## 5. 결정 / 선택지

### 결정_1: 매크로 위치 — LedOutput.c 자체 (board.h 아님)

이유: 변종이 LED 색만 영향을 주므로 관심사 응집. board.h 에 두면 빌드 설정과 LED 표현이 분리되어 추적 어려움. `#ifndef` 로 외부 override 가능 (`-DTDC_FW_VARIANT=...`) → 향후 필요 시 빌드 시스템 통합도 비파괴.

### 결정_2: 디폴트 = App

이유: ① App 이 정식 운용 시나리오, ② Factory Reset 은 명시적 opt-in 테스트 빌드여야 안전 (default factory reset 이면 실수로 출고 시 잘못된 LED 출력 위험), ③ 사용자가 알려준 "원래 시나리오 = App" 과 일치.

### 결정_3: 매크로 명 — `TDC_FW_VARIANT` (네이밍 컨벤션 `tdc_` prefix)

이유: 루트 [`docs/지침/코딩/네이밍 컨벤션.md`](../../../../../docs/지침/코딩/네이밍%20컨벤션.md) `tdc_` prefix 적용. `FW_VARIANT` 가 `LED_VARIANT` 보다 의미 정확 — 변종 자체는 펌웨어 이미지 종류이고 LED 는 그 식별 표시. 향후 다른 변종-종속 동작(예: 부트 메시지) 도 같은 매크로로 분기 가능.

### 결정_4: 색 매크로 — `TDC_FW_LED_IN_USE_COLOR` / `TDC_FW_LED_POWER_ON_COLOR`

이유: 변종이 결정한 LED 색을 한 단계 추상화하면 디스크립터 표 행이 깔끔. 색 자체에 변종 의미 부여하는 명명 (`TDC_FW_LED_*`) 으로 변종 컨텍스트 유지.

---

## 6. 위험·완화

### 위험_1: 빌드 시스템 변경 시 매크로 미전달
빌드 옵션으로 `-DTDC_FW_VARIANT=...` 전달 의도가 누락되어 항상 디폴트 App 으로 빌드되는 경우. → 디폴트가 App 이므로 운용 빌드는 정상. Factory Reset 빌드만 영향 받음. 완화: 본 매크로 사용법을 헤더 주석에 명시. 추후 빌드 옵션 통합 시 별도 작업으로.

### 위험_2: 디폴트 전환 = 사용자 현재 테스트 setup 깨짐
사용자가 현재 Factory Reset 으로 빌드 중. 본 작업 후 디폴트 = App 이라 사용자는 변종 매크로를 명시적으로 설정해야 Factory Reset 빌드 가능. → 사용자에게 마무리 보고 시 명확히 안내. 한 줄 변경으로 즉시 복귀 가능 (`#define TDC_FW_VARIANT TDC_FW_VARIANT_FACTORY_RESET` 로 디폴트 변경).

---

## 7. 검증 절차

V1. 디폴트 (App) 빌드 — 매크로 미정의 상태에서 컴파일 통과, `LED_ST_IN_USE` / `LED_ST_POWER_ON` 색이 각각 WHITE / SKYBLUE 로 매핑됨을 코드 리뷰로 확인.
V2. Factory Reset 빌드 — 본 파일 디폴트를 `TDC_FW_VARIANT_FACTORY_RESET` 로 변경 후 컴파일 통과, 색이 PURPLE / WHITE 로 매핑됨을 확인.
V3. 잘못된 매크로 값 — `#define TDC_FW_VARIANT 99` 시 `#error` 로 빌드 실패 확인.
V4. 디스크립터 표 다른 항목 (`BATT_READY`, `BATT_MID`, error 패턴 등) 색·타이밍 동일.
V5. 사용자 실기 검증 — 디폴트 빌드(App) 시 IN_USE/POWER_ON 색이 의도대로 (WHITE/SKYBLUE), Factory Reset 변종 빌드 시 (PURPLE/WHITE) 정상 출력.
