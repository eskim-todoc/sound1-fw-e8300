## 검증 결과

2026-10-19에 Python 3.12.10과 GCC 16.1.0으로 검사했다. 생성물이 현재 작업 파일에 섞이지 않도록 TEMP에 tests 사본과 읽기 용도의 src 연결을 구성했다. Python 출력 인코딩만 UTF-8로 지정했고 소스와 시험 플래그는 수정하지 않았다.

유닛 오류는 `tdc_ut_cm3_run`, `tdc_ut_boot_check`, `cm3-extra`, `remaining-analysis`, `coverage`다. 모두 더 이상 존재하지 않는 `docs/참고/인허가/사운드1/DHF/03_설계 출력/SW/펌웨어/SUVC-FW-TD24A 소프트웨어 유닛 검증 기준서.xlsx` 입력 경로에 의존한다. 다른 문서를 임의 대입하지 않았다.

시스템 3개 검사 스크립트는 현재 `processorDirective.h`의 SYS54/73/77/80 활성 설정에서 storage 코드를 링크하거나 해당 시험 기능을 명시적으로 끄는 구성이 빠져 있다. 설정은 현재 상태 그대로 보존했다. 위 결과를 전체 회귀검사 통과나 제품 시험 통과로 확대하지 않는다.

호스트 검사 단계는 별도 담당으로 나누고, 펌웨어 변경 요약과 문서 보존 범위도 독립적으로 검토했다. 통합과 커밋/푸시는 주 담당이 수행한다.

## 저장 범위 검사

선택한 파일에서 UTF-8/CP949 비호환 소스 문자, 대표적인 인증 토큰/개인키 패턴, 50MiB 초과 파일과 의존성 연결 폴더가 발견되지 않았다. 실제 커밋에도 인코딩 훅을 실행했다. 실측 사진 폴더 124개 파일은 모두 Git 제외 대상이 아님을 확인했다.

펌웨어 변경과 Sullivan 문서의 `git diff --cached --check`는 통과했다. SV 자료에는 추출 텍스트, Markdown 줄바꿈 표현과 기존 생성 스크립트의 후행 공백/마지막 빈 줄 경고가 170개 파일에서 15,479건 있었다. 당시 내용과 추출 결과를 보존하기 위해 일괄 치환하지 않았다. 새 작업 기록의 내부 링크 7개는 루트 문서 검사 도구로 통과했다.
