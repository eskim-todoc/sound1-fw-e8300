## 2. 작업 분류 (모듈·상태)

| 작업 | 모듈 | 추정 상태 | 근거 |
|---|---|---|---|
| LED 운용 방식 (`operation-scheme`) | LED | **완료** | `[이력] 구현 결과` 존재, 2026-04-21 이전 작업 |
| POWER_ON LED 조기 점등 (`power-on-early-lighting`) | LED | **진행** | 최신 수정 2026-04-23, 사용자 현재 작업 중 (untracked) |
| 저전력 모드 전환 (`low-power-mode`) | power | **완료(추정)** | 2026-04-22 작업, 이후 갱신 없음 — 사용자가 재검토 요청 가능 |
| 터치 레이어 분리 (`layer-separation`) | touch | **완료(추정)** | 구현계획 Rev.1, 2026-04-21 이후 갱신 없음 |
| 터치 센서 초기화 분할 (`init-split`) | touch | **완료(추정)** | 구현계획 Rev.2 + 로그(성공+실패) 존재 → 테스트까지 진행 |

> 완료(추정)는 관련 파일이 오래된 것 기준. 사용자님이 실제 상태와 다르면 `list.md` 수정 가능.

## 4. 내부 상호참조

내부 Sound1 문서들 중 다른 Sound1 문서 링크 여부는 본 migration에서 **영향 없음** (확인 결과 기존 파일들은 서로를 markdown 링크로 참조하지 않음 — 본문 내 파일명 텍스트 언급은 일부 있으나 링크 형태 아님). 확장 필요 시 사용자 후속 지시.

## 5. 위험·대응

| 위험 | 대응 |
|---|---|
| untracked 파일(POWER_ON LED 2건 + 로그 3건) 이동 시 사용자 의도와 다를 가능성 | 사용자 명시 승인(Q1=a, Q2=Y) 받고 진행, `진행상황.md`에 이동 이력 명시 |
| 완료(추정) 작업 중 실제로는 진행인 것이 있을 수 있음 | 모두 완료로 표시하되 `list.md`에 "(추정)" 주석, 사용자 확인 후 재분류 |
| 이력 추적 단절 (파일명 완전 변경으로 rename 감지 실패) | `git mv` 사용 → 대부분 100% 유사도 rename으로 감지, 미감지 시 git `log --follow`로 추적 가능 |
