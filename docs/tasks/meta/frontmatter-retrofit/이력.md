## 무엇을 했는가

Sound1 `docs/` 영속 9 파일(`지침/`·`사용방법/`·`참고/{칩·LED·터치}` 하위)에 YAML frontmatter 5필드(`name`·`purpose`·`type`·`applies_to: [Sound1]`·`tags`)와 첫 헤더 직후 `**TL;DR**:` 1~3줄을 일괄 in-place 추가. 본문 내용은 무변경. general-purpose 서브에이전트 1회 호출로 9 파일 분담 처리, 메인은 spot check 2 파일(`UI 명령어 사용법.md`, `[Sound1] Ezairo LED 패턴 사양 Rev.0 by 김은수.md`)로 형식·내용 정확도 확인. 헤더에 `[`·`]`이 포함된 1 파일은 YAML 파싱 안전을 위해 `name` 값을 큰따옴표로 감싼 처리(자기검증된 안전 패턴) — 별도 회고 가치 있음.

## 핵심 결정

- **사용자 명시 트리거로 일괄 소급 진입** — 평소 §6.5/§9.1은 점진적 소급이 원칙이지만 사용자가 "Sound1만 일괄 소급"을 명시 선택해 트리거 충족.
- **본 task 범위는 영속 9 파일 한정** — tasks/_archive 산출물은 과거 시점 기록물이라 일괄 소급 가치 낮음. Sound1 CLAUDE.md는 docs/ 외라 본 task 외이지만 §9.1 "루트 진입점 CLAUDE.md" 의무 대상이라 후속 권고.
- **서브에이전트 위임** — 9 파일 일괄 처리에 메인이 직접 read+edit하면 컨텍스트 부담 큼. general-purpose에 자기완결적 프롬프트(지침 §9.1 형식 + 9 파일 매핑 표)로 위임 후 spot check 2 파일.
- **분석 단계 간소화** — folder-readmes task의 분석 자료를 재사용해 각 파일 `purpose`·`type`·`tags`를 미리 고정. 서브에이전트는 본문 요약과 frontmatter 삽입에만 집중.

## 후속 영향

- **Sound1 CLAUDE.md frontmatter 추가** — `docs/` 외에 있어 본 task 외이지만 루트 §9.1 "루트 진입점 CLAUDE.md (루트·프로젝트 양쪽)" 의무 대상. 손댈 일이 생길 때 같이 처리(점진적 소급) 또는 사용자 명시 요청 시 별도 task.
- **tasks/_archive 산출물 frontmatter** — 사용자 추가 요청 시 별도 task로 분리 가능.
- **본 task가 templating 사례** — 다른 프로젝트(auto-rtt-viewer·ez8300-study) 마이그레이션 시 동일 서브에이전트 위임 패턴 재사용 가능.
- **YAML name 필드 큰따옴표 처리 패턴** — 헤더에 YAML 특수문자(`[`/`]`/`:` 등) 포함 시 큰따옴표 감쌈 — 회고 가치(별도 검토).
