# 이력 및 결과 — FPGA/ISD 통신 에러 디바운스

**TL;DR**: 부팅 초반 과도기(3~10회) 통신 에러로 빨간 LED가 "파르르르" 점멸하는 문제를, **각 `errorCodeUpdate` 호출 지점에 연속 실패 카운터를 두어 N(=15)회 초과 시에만 에러를 확정(그 전엔 WARN 로그만)**하는 방식으로 해결. 26개 지점에 `TDC_ISD_DEBOUNCE_FAIL` 매크로 일괄 적용. 빌드·실기 검증 대기.

---

## 1. 문제와 목적

- FPGA/ISD 통신 에러는 **부팅 초반 3~10회 과도기에만** 발생하고 그 후로는 정상 동작한다(은수님 관찰).
- 그런데 에러 발생마다 `errorCodeUpdate(en__FPGA_COMMUNICATION_ERROR)` → LED 점등, 통신 성공 시 `clearErrorFlag(COMM)` → 소등이 빠르게 반복되어 **빨간 LED가 파르르르 점멸**한다.
- **목적**: 초반 과도기 에러로 인한 이 점멸만 제거. 진짜 만성 통신 실패일 때만 LED가 켜지면 된다.

## 2. 접근 변천 (시도 정리)

| 안 | 방식 | 결과 |
|---|---|---|
| **㉮ LED 표시측 디바운스** | `systemControl` LED 판정에서 `FPGA_CommunicationErrorFlag`가 연속 N tick 지속 시에만 점등 | **폐기**. 은수님 지적: `systemControl`은 main 루프에서 1ms마다 플래그를 폴링하므로, 이 카운터는 "에러 발생 횟수"가 아니라 "플래그가 set된 채 유지된 시간(ms)"을 센다. 에러 1회라도 플래그가 15ms 유지되면 점등 → 의도와 불일치. systemControl 변경 **원복**. |
| **㉯ set측 각 지점 카운터** | 에러가 실제로 발생하는 지점(`errorCodeUpdate` 호출처)마다 전용 카운터. 연속 실패가 N회를 초과할 때만 `errorCodeUpdate` 실제 호출 | **최종 채택**. "실제 에러 발생 횟수" 기반이라 은수님 의도에 정확히 부합. 은수님이 일부 함수에 직접 적용하던 방식의 완성판. |

## 3. 최종 구현 (무엇을 어떻게)

### 3.1 인프라 (`isd_interface_FPGA.h`)
```c
#define TDC_ISD_ERR_DEBOUNCE_N (15)   // 연속 실패 임계 (이 값 초과 시에만 에러 확정)

#define TDC_ISD_DEBOUNCE_FAIL(_cnt, _mod, _tag, _op, _maj, _det)        \
    do {                                                               \
        if (++(_cnt) > TDC_ISD_ERR_DEBOUNCE_N) {                       \
            ci_printe(_mod " FAIL  ...cnt %2d  >> ERR set", ...);       \
            errorCodeUpdate((_maj), (_det), __LINE__);   /* 에러 확정 → LED */ \
        } else {                                                       \
            ci_printw(_mod " WARN  ...cnt %2d/%2d", ...); /* 누적 중, 에러 미확정 */ \
        }                                                              \
    } while (0)
```
- 각 지점은 `static int <카운터>;`를 두고 — **실패 시** `TDC_ISD_DEBOUNCE_FAIL(...)`, **성공 시** `<카운터> = 0;` (연속 실패만 누적, 성공 1회면 리셋).
- `systemControl.c`: ㉮ 변경 **원복** (LED 판정 무수정).

### 3.2 적용 범위 (26개 지점)
- **`isd_interface_FPGA.c` 통신 래퍼 16개**: I2C read/write 실패 시 디바운스. (read_FPGA_version, read_FPGA_systemResgister_1st, check_FPGA_PCM_Error, check_FPGA_FIFO_empty, read_FPGA_PulseWidth, read_FPGA_FIFO_counter, read_FPGA_backtelError_Flag, read_FPGA_backtelConfig, read_FPGA_backtel_FIFO, write_FPGA_reset, write_FPGA_enable_RF_tx, is_RF_tx_eanble, write_FPGA_disable_RF_tx, write_FPGA_clear_FIFO, read_txPowerLevel(활성보드), write_change_TxPowerLevel(활성보드))
- **`isd_interface_init_FPGA.c` init 본문 10개**: 각 case 검증 실패 시 디바운스. (init_txPowerIC c10, init_FPGA c11/c20, init_ISD c200×2, c205×2, c210×2, c260)

### 3.3 카운터 2개 이상 분리 지점 (은수님 핵심 요청)
한 case 안에 **독립적인 실패 모드**가 여러 개면 연속 실패 카운트를 분리해야 한다(합치면 추적이 섞임).

| case | 카운터 1 | 카운터 2 |
|---|---|---|
| 200 | `outer_rf_tx_error_cnt` (RF DISABLE 검증) | `inner_rf_tx_error_cnt` (RF ENABLE 검증) |
| 205 | `pulse_width_error_cnt` (펄스폭) | `tx_power_err_cnt` (TX 파워) |
| 210 | `backtel_cfg_err_cnt` (백텔 레지스터) | `fifo_clear_err_cnt` (FIFO 클리어) |

### 3.4 손대지 않은 범위 (은수님 "init 콜트리 한정")
- init 콜트리에서 호출되지 않는 함수: read_FPGA_systemResgister_2nd, read_FPGA_systemError_Flag, read_FPGA_IO_MUX, read_FPGA_optionalConfig, write_FPGA_systemResgister_1st/2nd, write_FPGA_backtelConfig
- 비활성 보드(`Board_is_OTE_VER_1_2`/`1_3`) 정의

### 3.5 로그 포맷
```
[FPGA] WARN  read_FPGA_version       RD      cnt  7/15           ← 누적 중 (에러 미확정)
[FPGA] FAIL  read_FPGA_version       RD      cnt 16  >> ERR set  ← 임계 초과, 에러 확정
[PMIC] WARN  read_txPowerLevel       RD      cnt  7/15
```

## 4. 검증 (정적)
- 매크로 호출 수: FPGA.c 16 / init.c 10 ✓
- `errorCodeUpdate` 직접 호출 잔존 = 범위 밖(비활성 보드 + init 미호출 함수)만 ✓
- 비표준 임계(`>3`/`>10`) 잔존 0 ✓
- case 205·210 카운터 2개 독립 누적·리셋 위치(성공 경로) 정확 — 디바운스 무력화 버그 없음 ✓
- `change_isd_state` 전부 보존, 괄호 균형(FPGA 119/119·init 83/83), 심볼 가시·세미콜론 OK ✓
- **빌드·실기 동작은 은수님 Eclipse 환경 필요** (대기).
