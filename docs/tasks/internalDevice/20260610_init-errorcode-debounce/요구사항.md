# 요구사항 — init 콜트리 errorCodeUpdate 일괄 디바운스

**TL;DR**: `isd_interface()`의 `init_txPowerIC`/`init_FPGA`/`init_ISD` 세 함수 콜트리(하위 함수 호출 포함) 안에서 `errorCodeUpdate()`가 불리는 모든 구간을, 산발적 디바운스 대신 **일괄 통합 카운터 + 상수 임계값**으로 일원화한다. 임계값은 3~10 범위로 조정 가능하도록 상수화.

---

## 1. 배경

- FPGA/ISD 초기화 시퀀스는 I2C 통신 실패가 1회만 발생해도 `errorCodeUpdate(en__FPGA_COMMUNICATION_ERROR, ...)`로 에러 플래그를 set하고, `systemControl`이 이를 매 루프 평가해 **빨간 LED**를 점등한다.
- 직전 수정으로 "통신 성공 시 즉시 `clearErrorFlag`" 복구 경로가 생겼으나, 그 결과 에러↔복구가 매우 빠르게 반복되어 **LED가 눈에 흔들리듯 깜빡**인다(은수님 관찰).
- 이를 막기 위해 "연속 N회 초과 실패 시에만 에러 표시"하는 디바운스를 도입했으나, 현재는 함수마다·case마다 **이름과 임계값이 제각각인 카운터가 산발 적용**되어 일관성이 없고 누락이 많다(분석.md 참조).

## 2. 목표 (Goal) — ㉮ LED 표시측 디바운스 확정 (2026-06-10)

> [!IMPORTANT]
> **은수님 실제 목적 확정**: 통신 에러는 **초반 3~10회 과도기에만 발생**하고 그 후로는 정상 동작한다. 이 초반 과도기 에러로 생기는 **LED "파르르르"(빠른 점멸)만 제거**하면 된다. ㉮/㉯ 중 이 목적에 부합하는 방식을 채택하면 된다(은수님 위임).

이 목적엔 **㉮ LED 표시측 디바운스**가 정확히 부합하여 채택한다:
- `systemControl` LED 판정에서 `FPGA_CommunicationErrorFlag`가 **연속 N tick 지속될 때만** 빨강 점등, **정상 1회면 즉시 소등**(점등 디바운스·소등 즉시).
- 초반 산발 과도기 에러는 "연속 N" 조건을 못 채워 점등 자체가 안 됨 → 파르르르 원천 차단. 만성 단선만 N tick 후 점등(안전 보존).
- init 콜트리 `errorCodeUpdate`·기존 산발 카운터 13개·복구 경로(`change_isd_state`)·앱 진단(errorCode 원본)은 **전부 무수정** → 회귀 최소.

> 워크플로우 적대적 검증(13 에이전트)에서 초판 권장 set측(관점 A)은 SET↔CLEAR 진동의 절반만 막아 reject, ㉮가 단순·견고·목적 부합으로 수렴. 상세: [`계획.md`](계획.md) §1·§3, [`분석.md`](분석.md) §7.

> [!NOTE]
> 초판 목표였던 "init 3콜트리 errorCodeUpdate 구간 디바운스 통합"은 ㉮ 채택으로 **비목표**가 되었다(콜트리·기존 카운터 무수정). 콜트리 범위는 분석 참고 자료로만 유지.

## 3. 범위 (Scope)

### 포함
- 위 3개 init 함수 본문에서 직접 호출하는 `errorCodeUpdate()`
- 위 3개 init 함수가 호출하는 하위 함수(주로 `isd_interface_FPGA.c`) 내부의 `errorCodeUpdate()` — **단, init 콜트리 컨텍스트에서 호출된 경우에 한정**
- 임계값 **상수 정의**(`#define`), 기본값 후보 + 조정 용이성
- 통합(일괄) 카운터 허용 — 함수별 독립 카운터 불요

### 제외
- 코드 구현 자체 — **이번 산출물은 문서까지**. 구현은 은수님 검토·결정 후 별도 진행.
- 범위 밖 호출 경로: `isd_path_Open()`·`enableStimul_10v()`(`isd_interface_init_ISD.c`), `isd_interface_mapping_*`, `isd_interface_stimulation*`, `earpieceUpate.c`, `initialize.c` 등에서의 `errorCodeUpdate()`
- LED 판정 로직(`systemControl.c`) 변경 — 본 작업은 에러 플래그 set 시점 디바운스만 다룬다

## 4. 제약 (Constraints)

- 임계값은 **상수**로 정의(예 `#define`), 3→10 등으로 손쉽게 조정 가능해야 함. 은수님: "3은 적은 듯, 10까지 해야 할 수도".
- 신규 심볼은 루트 네이밍 규칙상 `tdc_` 접두어.
- AI 서명 금지, Git Identity 김은수 명의(구현·커밋 시).
- 기존 동작 회귀 금지 — 디바운스 도입이 정상 연결 성공 흐름·기존 `clearErrorFlag` 복구 경로를 깨지 않아야 함.

## 5. 수용 기준 (Acceptance Criteria)

1. init 3함수 콜트리 내 `errorCodeUpdate()` 호출이 **빠짐없이** 동일 디바운스 정책을 따른다(누락 0).
2. 임계값이 단일 상수로 통일되어 한 곳에서 조정 가능.
3. 범위 밖(mapping·stimulation·earpiece 등) 호출은 디바운스 영향을 받지 않거나, 받더라도 의도적으로 명시·합의된 동작이다.
4. 산발적으로 흩어진 기존 카운터(함수 레벨 `error_cnt` 8개 + init 본문 명명 카운터 5개)가 정리되어 중복이 제거된다.
5. 정상 통신 회복 시 카운터가 리셋되어, 일시적 글리치가 임계 미만이면 LED가 흔들리지 않는다.

## 6. 미해결 질문 (은수님 결정 필요)

> 상세 옵션·트레이드오프는 [`계획.md` §결정 필요 사항](계획.md) 참조.

- 디바운스 대상이 `en__FPGA_COMMUNICATION_ERROR`만인지, init 콜트리의 **모든** majorError(CONFIG·RF_PowerIC·ISD 포함)인지
- "init 콜트리 컨텍스트 한정"을 어떤 메커니즘으로 보장할지
- 카운터를 완전 단일로 둘지, majorError별로 나눌지
- 임계 상수 기본값
