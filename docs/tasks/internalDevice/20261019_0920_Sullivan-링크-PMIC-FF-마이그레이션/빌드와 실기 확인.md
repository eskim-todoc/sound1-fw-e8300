# 링크·백텔·PMIC 이식본 빌드와 실기 확인

현재 작업 브랜치는 `develop_backup`이다. 원래 backup 브랜치 `claude_feature_sound1-eptc`의 `f9fa45ff`에서 시작했다. 이전 원격 develop 구조 병합은 사용하지 않았으며 기존 폴더/함수/빌드 설정을 유지했다. FF 감지·보정·전용 타이머·AUDIOFF 저장은 구현하지 않는다. 아래 실기 항목은 실행 절차와 예상 결과이며, 실제 측정 결과가 아니다. 수행한 검사와 현재 상태는 [작업 기록](작업.md)에 둔다.

## 1. 빌드와 시험 시작 순서

1. 저장소 `E:\workspace\projects\sound1-fw-e8300-backup`에서 브랜치를 확인한다. 이식본은 `develop_backup`에 있다. 이전 `claude_feature_sound1-link-pmic` 결과와 혼동하지 않는다.
2. Eclipse에서 프로젝트를 Refresh한다. CM3의 기존 `Cortex-M3-src`, `Gen1_5`, `systemControl` 등 폴더와 `.cproject`는 그대로다. 신규 모듈은 기존 `Cortex-M3-src/internalDevice` 및 `BleCommunication`에 추가했다. Refresh 후 기존 설정으로 Clean Build한다. CFX도 함께 빌드한다.
3. CM3와 CFX는 같은 브랜치의 이미지 쌍을 사용한다. 공유 구조체 끝에 링크 주기와 안정 NOP의 두 워드를 추가했으므로 한쪽만 예전 이미지와 섞지 않는다. 기존 필드의 순서는 유지했다.
4. 기존 패키징·다운로드 절차를 사용한다. 이 작업에서는 SDK로 분리 이미지의 컴파일/링크만 실행했으며 장치에 다운로드하거나 실제 전압·자극을 측정하지 않았다.
5. 먼저 버전·설정 조회와 기존 명령의 응답을 확인한 뒤 Normal, Mapping 대기, Mapping Live, 링크 손실과 재연결 순서로 확인한다.

현재 CM3의 DIO35, SYS7/23/AUDIT/54/73/77/80 스위치와 CFX DIO35는 모두0이다. 시험 코드를 포함한 기능은 보존했으며 사용자가 꺼 둔 값을 유지했다. 실기 시험용 빌드에서 필요한 스위치만 기존 시험 사용방법에 따라 선택한다.

## 2. 새 설정과 기본값

| 항목 | 값 | 해석 |
|---|---|---|
| 운영 설정 최저 | 112 = 2.8V | 두 하한과 강제 고정값의 설정 최저 |
| Normal 기본 하한 | 140 = 3.5V | 유효한 저장 설정이 있으면 저장값 우선 |
| Mapping 기본 하한 | 172 = 4.3V | 전용 검사와 Mapping Live 모두 적용 |
| 기본 상한 | 214 = 5.35V | 두 하한보다 커야 함. 최초 연결 전 기동 상한은214 유지 |
| 상승/하강 | 기본 +4 / -1 | 레벨1은25mV. 상승 step은1~40 설정 |
| 백텔 주기 | 기본3, 범위1~255 | 100ms 단위 설정. Normal/Mapping에 공통 적용 |
| 재시도 코인 | 기본1, 범위0~100 | 정상 전원 백텔을 받으면 재충전. 소진 뒤 다음 실패는 재초기화 |
| 링크 모드/가속 | 기본0 / 0 | 모드0 전원 상태, 모드1 수신 여부. 가속은 모드1에 적용 |
| force/infinite/NOP override | 휘발성 | 재부팅 때 자동 복원하지 않음. 맵 재계산 시 NOP는 자동표로 복귀 |

3.5V와4.3V는 고정 출력이나 부팅 시작 전압이 아니다. 초기화의 코드75(1.875V)와 기존 +5/+1 상승 절차는 별도로 유지한다. 실제 출력은 백텔, 하한·상한 및 시험용 force에 따라 달라진다. 전압 코드는 설정/레지스터 값이며 실측 전압과 구분한다.

CFX와 Mapping의 기존 카운터 증가/감소 방식을 유지했다. 설정3은 명목300ms이고 CFX는0~300의301회 호출로 한 주기가 된다. 정확한 벽시계300ms나 지터 상한을 보장한 것으로 해석하지 않는다. 실행 중인 백텔 순서는 주기 변경으로 중간 취소하지 않는다.

## 3. 프로토콜 조회와 예

기존 `8F 01/02/03/04`, `59 01/02`, `8C`는 기준 브랜치의 의미를 유지한다. `8F 04` fake sleep은 backup에 있던 구현을 그대로 유지한다. `8F 02`는 기존 OTA 상태 강제/백텔 우회이지 무한 코인 설정이 아니다.

요청은 `8F 20 access index [value]`, 정상 응답은 `8F 20 access index L payload`이다. access는0 읽기/1 쓰기이며 번호는 아래 표에서10진수다. 패킷 예는16진수다. 새 Sound1 프로파일은1.0이며 Sullivan 전체4.6 호환을 뜻하지 않는다.

| index | 값 | 쓰기 |
|---:|---|---|
| 0 | index1~15의15바이트 묶음 | 불가 |
| 1 | 마지막 성공 PMIC 읽기/쓰기의 레벨, Reset 이후0은 미확인 | 불가 |
| 2 | 주기1~255, 100ms 단위 | 저장 |
| 3 / 4 | Normal / Mapping 하한112 이상, 상한 미만 | 저장 |
| 5 | 상승 step1~40 | 저장 |
| 6 | force0 해제 또는112~214 | 휘발성 |
| 7 | 코인0~100, 255는 무한 시험 모드 | 개수만 저장. 0~100 쓰기 성공 시 무한 해제 |
| 8 | 무한0/1 | 휘발성. index7의255와 같은 상태 |
| 9 / 10 | 링크 mode0/1 / 가속0/1 | 저장 |
| 11 | 안정 NOP0~19 | 휘발성. 쓰면 override 활성 |
| 12 | 현재 펄스폭, 개별 읽기는2바이트 big-endian | 불가 |
| 13 | 실제 채널당 프레임 수 | 불가 |
| 14 | NOP override0/1 | 0은 현재 프레임의 자동표로 복귀 |
| 15 | 현재 자극 전략 | 불가 |
| 16 | 설정 상한, 두 하한보다 크고214 이하 | 저장 |
| 17 | FF OFF=0 | 0만 허용. 1/2/3 거부 |
| 18 이상 | FF 확장을 위한 예약/미지원 | 거부 |

index0의 묶음은 원본과 같이 각 값의 하위8비트만 보낸다. 펄스폭이255us를 넘을 때는 반드시 개별 index12의2바이트 응답을 사용한다. 예를 들어268us는 `01 0C`다. 묶음의 해당 한 바이트는 `0C`이므로 전체 펄스폭으로 해석하면 안 된다. 이 개별 조회 형식은 Sound1 프로파일의 명시적 차이다.

```text
버전/지원 옵션 읽기
RX  8F FF 00 00
TX  8F FF 00 00 0A 01 00 1E 00 00 00 01 00 00 00

Normal 하한 읽기 (저장값이 없는 초기 기본값 예)
RX  8F 20 00 03
TX  8F 20 00 03 01 8C

Mapping 하한 읽기 (초기 기본값 예)
RX  8F 20 00 04
TX  8F 20 00 04 01 AC

주기를 기본300ms로 저장
RX  8F 20 01 02 03
TX  8F 20 01 02 01 03

Normal 하한을2.8V로 저장 (이후 기본3.5V로 돌리려면 값8C)
RX  8F 20 01 03 70
TX  8F 20 01 03 01 70

force 해제
RX  8F 20 01 06 00
TX  8F 20 01 06 01 00

펄스폭 개별 읽기 (현재268us라는 가상 예)
RX  8F 20 00 0C
TX  8F 20 00 0C 02 01 0C

FF OFF 확인
RX  8F 20 00 11
TX  8F 20 00 11 01 00
```

정상 응답은 최대20바이트다. 오류는 기존 형태인 `F0 8F major minor lineHi lineLo`의6바이트이며, 행 번호는 빌드마다 달라질 수 있다. 범위/미지원 요청은 major8/minor6, 설정 저장 I/O 실패는 major10/minor2로 전달한다. 새 핸들러는 송신을 직접 하지 않고 기존 호출자가 한 번만 송신한다.

SPI 수신 경계는 논리 데이터20바이트를 제공하며 실제 BLE 논리 길이는 상위 파서에 전달하지 않는다. 이번 구현은 SPI 마지막 바이트를 길이라고 새로 가정하지 않는다. 따라서 패딩 때문에 사라진 누락 값과 의도적으로 보낸0을 항상 구별할 수 있는 것은 아니다. 앱은 읽기4바이트/쓰기5바이트의 올바른 요청을 보내고 응답을 받은 후 다음 요청을 보낸다.

force 쓰기 ACK는 설정 수락이며 그 순간 실제 전압을 썼다는 뜻이 아니다. 다음 백텔 처리에서 PMIC 쓰기를 시도하고 성공한 값만 관측값에 반영한다. index1=0일 때는0V를 측정했다는 뜻이 아니라 캐시가 무효라는 뜻이다.

## 4. 실기에서 비교할 동작

| 순서 | 입력/조건 | 예상 결과 |
|---:|---|---|
| 1 | 기존 명령과 새 버전/기본값 조회 | 기존 응답 유지, 새 응답 길이/값/지원 옵션 일치 |
| 2 | Normal의 LowStable/LowUnstable | 기본 +4, 상한214 clamp. High 두 상태는 -1, 하한에서 정지 |
| 3 | Normal 레벨140에서 Mapping 진입 | Mapping 하한172 미만이면 보정. I2C 실패 시 성공 처리 없이 복구 |
| 4 | Mapping에서 Normal 복귀 | 바로140으로 떨어뜨리지 않고 기존 백텔 제어에 따라 하강 |
| 5 | 정상 백텔 뒤 연속 미수신 | Normal/Live 모드0은 첫 실패에 코인 소모/재시도, 다음 실패에 재초기화. 정상 응답 뒤 재충전 |
| 6 | Mapping 전용 검사에서 미수신/과다 백텔 | 원본처럼 코인 없이 재초기화. 무한 플래그도 이 전용 경로의 실패 판정을 막지 않음 |
| 7 | 모드1/가속 선택 | Normal Live에만 수신 여부 정책. Mapping 전용/Mapping Live는 전원 상태 정책 유지 |
| 8 | 주기1/3/255와 검사 도중 변경 | 공통 설정 적용, 진행 중 검사 완결. 연결 직후 기존10회 준비 유지 |
| 9 | Mapping eCAP/임피던스/특정 자극 | 측정 도중 주기 백텔을 별도로 끼워 넣지 않음 |
| 10 | CFX 프레임1~9 및10~12 | 1~9 새 순서의 Duration 복원,10~12 기존 순서 유지. 범위 밖에서 읽기 완료 오통보 없음 |
| 11 | 재부팅 후 설정 재조회 | 저장된 유효값 복원, force/infinite/override는 자동 복원하지 않음 |
| 12 | FF 활성/예약 명령 및 기존 QCC/OTA/sleep | FF 활성 거부. 기존 제품 기능 회귀 확인 |

레지스터 실패와 전원 손실을 실제 장치에 주입하는 시험은 여기서 실행하지 않았다. 호스트 시험은 RAM 경계에서 오류를 주입한 결과다. 실제 시험에서는 장치·계측·복구 준비를 확인하고 기존 장비 시험 절차를 사용한다.

## 5. 저장과 빌드 범위의 한계

링크 설정은 `LINKPARM.TXT`의 기본40바이트를 원본과 같은 순서/리틀엔디언으로 저장한다. 파일 공간4096바이트를 확보하되 뒤쪽 확장 데이터는 덮어쓰거나 잘라내지 않는다. 유효한 기존 설정이 우선하며 잘못된/짧은 파일은 자동 삭제하지 않는다. 새 파일을 만들거나 설정을 쓸 때 seek/tell/write 길이/sync/close/되읽기를 모두 확인한 다음 RAM 설정과 CFX 주기를 갱신한다. 닫기 실패 뒤 해당 모듈의 파일 객체를 재사용하지 않으며 재기동 전 추가 쓰기를 거부한다.

이 형식은 IDENT와 값 범위를 검사하며 CRC/전원 차단 원자성을 제공하지 않는다. 범위 안의 값으로 손상된 경우까지 검출하거나 FAT 자체를 복구하는 기능은 이번 이식에 포함하지 않는다. 기존 FAT A/B 복구 논의는 별도 개선 범위다. 저장 실패가 나면 성공 ACK를 보내지 않으며 기존 RAM 설정은 유지하지만, 이미 수행된 디스크 쓰기가 이전 상태로 자동 복원된다는 뜻은 아니다.

호스트 재검사 명령은 저장소 루트에서 다음과 같다.

```powershell
python -X utf8 tests/link_pmic/run_host.py
python -X utf8 tests/link_pmic/cfx_check.py
python -X utf8 tests/unit/build_target_tests.py CM3 --normal
python -X utf8 tests/unit/build_target_tests.py CM3
python -X utf8 tests/unit/build_target_tests.py CFX --normal
```

분리 SDK 빌드는 장치 접근 없이 `tmp/unit-tests/target`에 실행 이미지·map·입력 해시와 검사 결과를 만든다. 과거 유닛 시험의 알려진 제품 불일치를 이번 기능 시험 통과로 지우지 않는다. 실제 Eclipse 배포 빌드와 장치 시험 결과는 아직 미실행이다.
