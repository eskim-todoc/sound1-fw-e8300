## 목표와 범위

`sullivan-1-5-fw-hw-test-link-pwr-bt-period`에서 사용하는 백텔 링크 확인, PMIC 레벨, FF(feedforward) 기능을 현재 Sound1으로 옮길 방법을 분석하고 계획한다. CFX와 CM3의 역할, 공유 메모리와 상태 전이, 범용 디버깅 프로토콜 헤더 차이를 함께 검토한다. 은수님이 그림과 상태도, 흐름도로 설명하는 문서를 요청했다.

이번 권한은 코드 조사와 계획 문서 작성이다. 펌웨어 구현, 설정값 변경, 장치 접근, NVM 기록, 커밋 및 푸시는 포함하지 않는다. 기존 dirty 코드와 문서는 보존한다. 인허가/DHF 및 SV 문서 자체를 수정하는 작업도 아니다.

## 수용 기준

1. FF의 실제 의미와 링크 확인 및 PMIC 조정의 관계를 코드 근거로 설명한다.
2. Sullivan과 대상 Sound1의 실제 활성 경로, 설정값, 공유 계약과 실패 처리를 비교한다.
3. 기존 범용 명령과 충돌하지 않는 권장 프로토콜 및 호환 대안을 바이트 예시로 설명한다.
4. 파일별 변경 책임, 단계별 선행 조건과 완료 기준, 회귀 시험, 미확정 항목을 제시한다.
5. 구조도, 실제/제안 상태도와 흐름도를 본문에 넣고 파싱과 로컬 렌더를 확인한다.
6. 분석 완료, 미구현 제안, 실기 미검증을 구분하고 근거 파일로 이동할 수 있게 한다.

### 분담 결과의 수렴과 정정

- Sullivan 조사에서 백텔 시퀀스/FF 장부/clock/token의 의존을 채택했다. 현재 donor의 낮은 하한과 SPL 표는 target 검증값으로 복사하지 않기로 권장했다.
- Sound1 조사에서 기존 상태기계/매핑/OTA/시험 hook 보존을 채택했다. TIMER3를 바꾸지 않고 미사용 후보 TIMER0를 별도로 초기화하는 계획을 추가했다.
- 프로토콜 조사에서 기존8F옵션 보존과 신규0x20 도메인, 응답 생성 후 호출자 single TX를 채택했다. 기존 Sullivan 앱용59 어댑터는 선택 사항으로 남겼다.
- 별도 재검토에서 가속 상승8회+다음 실패, FF3의 성공 cache와 백텔 phase2 되읽기, session/config token의 구분을 정정/명확화했다.
- index120~135는 runtime R이 아니라 active/staging 누적표임을 정정했다. LINKPARM 앞104바이트와4KiB 파일 확보, 기본 writer의 seek/sync/close 반환 누락도 반영했다.
- 그림 렌더에서 상태 라벨의 줄바꿈과 칩 경계 제목을 수정했다. TX PMIC는 FPGA 칩 전원으로 그리지 않고 무선 송신 경로의 기능 연결로 표시했다.
