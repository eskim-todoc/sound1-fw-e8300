# 계획 — 상호용량 재검토 후속 권고

**TL;DR**: 검토 결론은 **조건부 No-Go**(핵심 4주장 전부 반증, 근본 오해=차동≠공통모드상쇄). 따라서 "지금 상호용량 펌웨어 전환"은 권하지 않는다. 권고 경로는 **① SW-only 완화책 실기 검증 → ② reference tracking 별도 검토 → ③ mutual은 실측 게이트 통과 시 차세대 보드 트랙으로 보류**. 본 계획은 코드 변경이 아니라 **의사결정 + 후속 방향**이 산출물이며, 은수님 선택을 요청드린다.

> [!IMPORTANT]
> 본 작업(타당성 검토)은 제품 소스 코드 변경이 없다. 아래는 "무엇을 할지"에 대한 방향 결정이며, 실제 실행(SW 완화 검증/실측 스파이크/mutual 전환)은 은수님이 고르는 트랙에 따라 **별도 신규 작업(4단계)**으로 착수한다.

## 1. 결론 요약

- 은수님 가설 "상호용량 차동 → 하이젠베르크 회피"의 핵심 고리("차동=공통모드 상쇄")가 **범주 오류**로 확인됨. 공통모드 드리프트를 실시간 차감하는 IQS323 기능은 mutual이 아니라 **reference tracking**(별도 채널타입).
- mutual은 물리적으로 불가능하진 않으나(IC·배선 실재), **하이젠베르크 핵심인 경로_2(클럭 스위칭) 회피 근거가 없고**, 정량 전기특성(§3.2)·D패드 기하·R32=0Ω ESD가 전부 미검증.
- 상세: [`분석.md`](분석.md) · [`에이전트-로그/99_종합평결.md`](에이전트-로그/99_종합평결.md).

## 2. 권고 경로 (Track A — 기본 권고)

| 순번 | 조치 | 성격 | 비용 |
|---|---|---|---|
| A-1 | 이미 완결된 **제어재설계 권고(Reseed 게이팅 + ATI Full + FIXED 드리프트 SW 해소)**를 실기 검증 | SW-only, 기존 산출물 활용 | 낮음 |
| A-2 | 관측교란.md §7 **완화책**(스위칭 이격·저드라이브·변환윈도우 밖 토글·비트레이트 회피) 중 적용 가능분 반영 | SW/설정 | 낮음 |
| A-3 | **reference tracking** 채널타입이 은수님이 원한 "공통모드 드리프트 상쇄"를 실제로 제공하는지 별도 소규모 검토 | 조사 | 낮음 |
| A-4 | 부수: §5.7 인용 오류 정정, R32=0Ω·TxA(R30) DNP HW 사실 회로문서 명시, §3.2 전기특성표 데이터시트 md 반영 | 문서 | 낮음 |

## 3. 조건부 경로 (Track B — mutual 실측 스파이크, 선택)

mutual을 계속 살펴보려면 **펌웨어 전환이 아니라 실측 게이트가 먼저**다. 코드 마이그레이션(sensor_setup 재작성) 이전에 아래 4개를 벤치에서 확인:

1. 경로_2 실저감: mutual vs self, 애그레서(I2C·SYSCLK) on/off 시 counts 변화 정량 비교.
2. 데이터시트 §3.2 전기특성(Cm 0.2~9pF·Cp≤100pF·Cx/Cm 10~20) vs 실 D패드 측정.
3. self vs mutual SNR 절대 비교.
4. R32=0Ω 경로 CRX1 실전극화의 ESD/드리프트 영향.

→ 4개가 긍정일 때만 mutual을 차세대 보드 트랙으로 승격. (참고: 마이그레이션 자체는 `tdc_touch_iqs323.c` 1파일 국한 가능하나, "mutual 결과=CH0 Touch 비트 1개" 전제 성립 시에 한함.)

## 4. 비권고 (Track C)

- **지금 mutual 펌웨어 전환**: 전제(경로_2 회피)가 반증됐고 정량·기하·ESD 미검증이라 권하지 않음.

## 5. 은수님 결정 요청

1. 본 검토 결론(**조건부 No-Go**)을 수용하시는지.
2. 후속으로 어느 트랙을 가실지 — **Track A(SW-first 권고)** / **Track B(mutual 실측 스파이크)** / **둘 다** / **보류**.
3. 부수 조치(A-4: 인용오류·HW사실·전기특성표 문서 정정)를 이번에 처리할지.

승인/선택 후, 고르신 트랙을 별도 신규 작업으로 착수하겠습니다.
