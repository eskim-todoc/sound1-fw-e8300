# 10 · V4 — 주장_4 검증: CRX1 실전극화 시 ESD·단일채널 재발

**TL;DR**: 주장_4를 반증 시도. 과거의 "정확히 그 SW 방전 버그" 재발은 코드 직접 재확인상 타당하게 부정되나(discharge 코드 0건), 그 부정 근거("채널 수 증가")가 같은 fan-out P3의 "mutual=채널 1개 소모" 발견과 충돌한다. 원 회로문서를 직접 열람해 확인한 결과 CRX1 경로는 R32=**0Ω**(CRX0 R31=100Ω·데이터시트 권장 470Ω보다도 약함)이며, 이는 6개 페르소나 노드 어디도 인용하지 않은 사실이다. 실전극화는 이 "기능적으로 무해하던" 경로를 touch 판정에 직결시킨다. Full ATI 자동복구 근거도 CH0 전용 검증뿐 — mutual 확장 미검증. **refuted=true, 신뢰도 high.**

---

## (a) 주장 재기술

> 주장_4: CRX1 실전극화(CalCap 더미 폐기) 시 과거 ESD 전하누적·단일채널 방전 문제가 재발하지 않는다.

## (b) 반증 시도

### 사전 검증 — P5 forensic 주장의 독립 재확인 (일치)

코드베이스 직접 grep·Read로 P5 §0의 핵심 주장을 재검증했다(신뢰 위임이 아닌 독립 확인):

| 항목 | 독립 재확인 결과 |
|---|---|
| `discharge`/`DISCHARGE` 문자열 | `systemControl/` 전체 grep **0건** — 확인됨 |
| `CAL_ERROR`/`CALIBRATION_ERROR` | enum 값 1개 + 이름 문자열만 잔존, 헤더에 "(미사용)" 명시. `tdc_touch_get_state()`([`tdc_touch.c:423-433`])는 `st.pressed`만 검사, 단락 없음 — 확인됨 |
| `0x43`/`0x44`/`0x70` 레지스터 write | `tdc_touch_iqs323.c` 상단 `#define` 목록에 REG 자체가 없음, grep으로도 register 문맥 매치 0건(0x44는 I2C 슬레이브 주소 리터럴로만 등장, 무관) — 확인됨 |
| `tdc_touch_config.h` | "CRX1 변형, CRX0 방전"을 **"FullATI 단순안 전환으로 폐기된 토글"**로 명시 — 확인됨 |
| Re-ATI 게이트 | `tdc_touch_logic.c:154-161` `NOT_TOUCH && !ati_active && ati_error && 쿨다운경과` — P5 인용과 정확히 일치 |

**판정**: P5의 코드 고고학(§0~§1)은 정확하다. 이 좁은 사실(과거 정확히 그 SW 메커니즘은 재발 불가)은 **참**으로 인정한다. 반증은 아래 4개 지점을 겨냥한다.

### 반증 시도_1 — "채널 수 2개로 증가"라는 핵심 전제가 같은 fan-out의 P3와 충돌

P5 §1.2: "mutual 도입 시 CH1은 상시 활성 전극이 되므로... 활성 채널 ≥1 조건을 자연 충족 — **정지 메커니즘의 전제가 이중으로 소멸**."

그러나 [`03_P3_IQS323_IC능력.md §6`]: "CRX0-CRX1 mutual 페어링 1건은 **채널 1개**(예: Sensor0/Channel0)만 소모한다 — Tx·Rx가 두 물리핀에 걸쳐 있다고 채널이 2개 드는 것이 아니다... **CRX1 핀 자체는 위 페어링에서 Rx로 이미 점유되므로, CRX1을 동시에 다른 독립 채널의 Rx로 중복 사용할 수는 없다**."

- Azoteq 3-버튼 예제 패턴을 그대로 따르면, mutual 페어링은 Sensor0 하나(TX_SELECT=CTx0, RX_SELECT=CRx1)에 담기고 **Sensor1(0x40)은 오히려 disable로 남을 개연성**이 있다(CRX1 핀이 Sensor0의 Rx로 이미 점유되어, Sensor1이 독자적으로 같은 핀을 또 쓸 수 없으므로).
- 이 경우 시스템 전체의 활성 Sensor/Channel 개수는 **오늘과 동일하게 1개**다 — "CH1이 별도의 상시 활성 채널이 되어 채널 수가 늘어난다"는 P5의 전제가 성립하지 않는다.
- 함의: 향후 mutual 페어링에도 (ESD 완화 등 목적으로) 유사한 "잠깐 끄는" 재설정 코드가 도입되면, 그 페어링 자체가 시스템의 유일 활성 채널이므로 **"끄면 활성채널 0개 → IC 정지"라는 과거와 동일한 구조적 함정이 그대로 남아있다.** P5는 "그 코드가 지금 없다"만 확인했을 뿐 "채널 구조상 재발 불가능"을 입증하지 못했다 — 이 판정은 미검증 전제(채널수 증가) 위에 서 있다.

### 반증 시도_2 — R32=0Ω: 6개 노드 어디도 인용하지 않은 회로 근거 (신규 확인)

[`개선/회로 구성·분석.md §7.1·§7.2·§11.2`]를 직접 열람해 확인:

| 채널 | 직렬 경로 | 데이터시트 권장 | 상태 |
|---|---|---|---|
| CRX0(CH0, Tx 예정) | R31=**100Ω** → C51=100pF | 470Ω | §11.2: "R31이 권장 470Ω보다 작아 **ESD 방전 전류 제한이 약함**" — 기존 ESD 이슈와 연관 지목 |
| CRX1(CH1, Rx 예정) | C52=100nF → R32=**0Ω** | 470Ω | **CRX0보다도 서지 제한이 약함**(0Ω=사실상 무저항) |
| CRX2(미사용) | R33=470Ω | 470Ω | 권장치 일치(참고 대조군) |

§7.2 NOTE(원 문서 직접 인용): "현재 구현에서 CRX1을 내부 CalCap으로 SW 설정한다... 이 SW상 CalCap 설정은 IC 내부 기능이며, **외부 회로의 C52 100nF·J4 배선과는 직접 관련이 없는 것으로 보인다**." 즉 **CRX1 핀은 SW 모드와 무관하게 이미 물리적으로 C52·R32를 거쳐 J4(외부 커넥터·외곽 링 패드)에 상시 연결**되어 있다.

- **오늘의 상태**: ESD가 CRX1 핀에 도달하는 물리 경로는 이미 존재하나, CalCap 모드에서는 IC가 그 핀의 실제 전하를 측정에 반영하지 않으므로 **기능적으로 무해**하다.
- **실전극화 이후**: 이 경로가 touch 판정에 **직접 반영**된다 — 그것도 CRX0(이미 데이터시트 권장 미달로 지목된 R31=100Ω)보다 **서지 제한이 더 약한**(R32=0Ω) 경로를 통해서.
- **함의**: "실전극화 시 ESD 문제가 재발하지 않는다"는 주장과 정반대로, ESD가 유입될 물리 경로의 서지 제한 여유는 CRX0보다 오히려 나쁘다 — 재발 가능성을 낮추는 근거가 아니라 **높이는 근거**다. P1~P6 6개 노드 중 이 저항값(R32)을 검토한 노드는 없다(P4는 형상·프린징만, P5는 SW 레지스터 이력만 다룸).

### 반증 시도_3 — ESD 자가복구(Full ATI Re-ATI) 근거의 스코프: CH0 전용, mutual 미검증

- P5 §1.3 스스로 인정(NOTE): "07분석 §2.2가 지적한 Full ATI의 일반 자가복구 논리(...)는 **CH0 단독 기준으로 도출됐다.** CH1이 실전극이 되면 '밴드이탈'이 CH0/CH1 중 어느 쪽 기준인지, mutual pairing이 단일 LTA/ATI 세트로 도는지 별도인지는 IC 능력 문제 — 본 노드는 SW 이력·마이그레이션 관점만 답한다."
- [`07_분석_단일채널ESD.md §2`] 원문도 전부 "CH0(자기용량) LTA drift → 밴드 이탈 → 자동 Re-ATI"라는 self-cap 전용 서술로만 구성 — mutual Cm drift가 동일한 회복 동역학(시정수·수렴 범위)을 가진다는 근거는 어디에도 없다.
- P3([`03_P3 §4`])도 이 공백을 닫지 못한다 — "mutual 전용 ATI 알고리즘 분기는 없음"만 확인했을 뿐, "mutual Cm이 ESD 드리프트 하에서 Re-ATI로 실제 수렴·복구되는지"는 §5.3에서 "실측 게이트 필요"로 유보.
- 함의: 주장_4가 유일하게 기대는 회복 메커니즘(Full ATI 자동 Re-ATI)이 **mutual 시나리오에서도 작동한다는 근거 자체가 어느 노드에서도 확인되지 않았다** — "재발하지 않는다"는 결론의 핵심 전제가 검증 공백 위에 있다.

### 반증 시도_4 — `wait_ati_done_blocking()`의 검증 공백 (직접 코드 확인)

[`tdc_touch_iqs323.c:328-342`] 직접 확인: 이 함수는 `ati_active==0`(bit5)만 확인하고 **`ati_error`(bit6)는 확인하지 않는다.**

```c
if (read_register(...) && !(glitch) && (lsb & (1u << 5)) == 0) /* ati_active == 0 만 확인 */
    return true;
```

- 부팅 시 mutual 재설정 후 발행하는 Re-ATI가 "완료"(active=0)되었어도 "성공"(수렴, error=0)했는지는 검증하지 않고 `apply_settings()`가 그대로 진행한다.
- 실패 시 유일한 안전망은 런타임 Re-ATI 게이트([`tdc_touch_logic.c:154-161`])뿐이며, 이는 P5도 인정하듯 "게이트드 재시도"이지 "보장된 회복"이 아니다.
- 만약 mutual Cm이 P4([`04_P4 §4.2`])가 우려한 "면적비 역전·비해칭·중앙 사각지대" 문제로 ATI 수렴 가능 범위(P6 인용 0.2~9pF)를 벗어나면, 이 재시도 루프는 **영구히 성공 못 하고 반복만 한다** — 사용자 체감상 "터치 재차 먹통"과 사실상 동일한 결과이며, 내부 메커니즘만 "영구 lock"에서 "무한 재시도"로 바뀐 것이다.

### P5의 자체 인정 — 반증이 필요 없는 부분 (주장 자체의 근거 부족을 뒷받침)

P5 §1.2·§1.3 스스로: "전역 `ati_error` 교차오염... **변형된 형태로 재발 가능(완화됨)**." 세 하위 이슈 중 하나는 P5 본인이 이미 "재발 가능"이라 적어 놓았다. 주장_4는 "재발하지 않는다"는 무조건 명제인데, 이를 뒷받침해야 할 1차 근거 노드가 이미 부분 재발 가능성을 명시하고 있다 — 반증 시도 없이도 주장이 자기 근거와 어긋난다.

## (c) refuted 판정 + 신뢰도

**refuted = true, 신뢰도 = high**

근거 요약:
1. 과거의 "정확히 그 SW 방전 버그"(`discharge_crx0` 등)는 코드에서 완전히 삭제되어 **이 좁은 의미로는 재발 불가** — 참으로 인정.
2. 그러나 그 결론이 기댄 "채널 수 증가로 정지 메커니즘 이중 소멸"이라는 핵심 논거는 같은 fan-out **P3의 "mutual=채널 1개 소모" 발견과 정면 충돌** — 미검증·상충 전제.
3. 원 회로문서 직접 확인 결과 CRX1 경로(R32=0Ω)는 CRX0(R31=100Ω, 이미 권장 미달로 지목됨)보다도 ESD 서지 제한이 약하다 — 실전극화는 "기능적으로 무해했던" 경로를 touch 판정에 직결시켜, ESD 문제가 재발하지 않기는커녕 **악화될 개연성 있는 새 경로를 연다.**
4. 유일한 회복 근거(Full ATI 자동 Re-ATI)는 self-cap(CH0)에서만 검증됐고 mutual로의 확장은 P5·P3 모두 열어둔 공백이다.
5. P5 스스로 하위 이슈 하나("전역 ati_error 교차오염")에 "재발 가능(완화됨)"을 인정 — 주장_4의 "재발하지 않는다"는 무조건 명제와 이미 내부 모순.

5개 근거 중 코드 재확인(1)만 주장을 지지하고, 나머지 4개(2~5)는 모두 반증 방향이며 그중 2개(2, 3)는 본 검증에서 새로 확보한 근거(P3 상충·회로문서 R32)다. 이 정도 수렴이면 "불확실하면 refuted" 원칙 이전에 이미 반증 우위다.

## (e) 도입결정 함의

- 주장_4를 "확립된 사실"로 깔고 mutual 도입을 결정하면 위험하다 — P6의 실측 게이트 순서(§6)에 **"CRX1 실전극 ESD 노출 경로(R32=0Ω) 실측"**을 명시적으로 추가해야 한다.
- CRX1을 mutual RX가 아니라 P4·회로분석(§12)이 이미 제안한 **guard ring(CH0 동위상 실드)**으로 쓰는 대안은, 같은 R32=0Ω 경로를 능동 실드 전류로 활용해 오히려 CRX0 ESD를 개선할 여지가 있다 — mutual보다 이 경로의 ESD 리스크가 낮을 가능성이 있다(P6·P4 결론과 정합).
- 최소 게이트: mutual 강행 이전 (1) R31/R32 HW 재검토(470Ω 방향 포함), (2) Sensor 채널 소모 실제 구현 확정(P3 vs P5 전제 충돌 해소), (3) CH0 전용 검증된 Re-ATI 회복 로직의 mutual 확장 실측 — 이 셋 없이는 "재발하지 않는다"를 설계 근거로 채택 금지.

## 핵심 결론 (3~5줄)

1. 과거의 "정확히 그 SW 방전 버그"는 코드에서 완전히 삭제되어 재발 불가 — 이 좁은 사실은 참(grep·소스 직접 재확인).
2. 그 결론이 기댄 "채널 수 증가로 정지 메커니즘 이중 소멸"이라는 논거는 같은 fan-out P3의 "mutual=채널 1개 소모" 발견과 충돌하는 미검증 전제다.
3. 원 회로문서 직접 확인 결과 CRX1 경로(R32=0Ω)는 CRX0(R31=100Ω, 이미 권장 미달)보다도 ESD 서지제한이 약하다 — 실전극화는 기능적으로 무해했던 경로를 touch 판정에 직결시켜 ESD 문제를 재발·악화시킬 개연성 있는 새 경로를 연다(6개 페르소나 노드 어디도 인용하지 않은 근거).
4. 유일한 회복 근거(Full ATI 자동 Re-ATI)는 self-cap(CH0)에서만 검증됐고 mutual로의 확장은 P5·P3 모두 열어둔 공백이며, `wait_ati_done_blocking()`이 `ati_error`를 확인하지 않는다는 코드 사실이 이 공백의 실제 위험을 더한다.
5. P5 스스로 하위 이슈 하나에 "재발 가능(완화됨)"을 인정 — 주장_4의 "재발하지 않는다"는 무조건 명제와 이미 내부 모순. **refuted=true, 신뢰도 high.**

## 이 페르소나가 본 리스크·불확실성

- 회귀 렌즈로 볼 때 가장 우려되는 지점은 R32=0Ω 발견 — 실측 ESD 인가 전까지는 이론적 서지제한 부족 지적에 머물지만, 데이터시트 권장치·CRX0 대비 상대적으로 명백히 열위인 수치가 실제 회로도에 존재한다는 사실 자체는 확인됐다.
- 채널 수 가정(P5 vs P3) 충돌은 오케스트레이터의 fan-in 단계에서 반드시 조율해야 할 항목 — 두 노드가 서로 다른 레지스터 구성 그림을 전제하고 있어 이후 구현 설계 시 먼저 확정해야 한다.
- 본 검증은 "mutual이 반드시 나쁘다"를 주장하는 것이 아니라, "주장_4가 무조건 명제로서 근거가 불충분하다"를 반증한 것이다 — CRX0 자체 HW 개선(R31→470Ω 방향) 없이 mutual만 도입하면 위험이 기존(CRX0)에서 신규(CRX1, 더 약한 R32)로 확장될 뿐이라는 것이 핵심 우려다.
