# 분석 — 상호용량 센싱으로 하이젠베르크 돌파 가능성

**TL;DR**: 은수님 가설(상호용량 차동이 셀프캡 하이젠베르크를 회피)을 다분야 전문가로 검토한 결과, **핵심 4개 주장이 모두 반증**됐다. 근본 원인은 "차동=공통모드 상쇄"라는 범주 오류 — 그 기능은 mutual이 아니라 **reference tracking**(IQS323의 별도 채널타입)이다. mutual은 물리적으로 불가능하진 않지만(IC·배선 실재), 하이젠베르크의 핵심인 경로_2(클럭 스위칭 전하주입) 회피 근거가 없고, 정량 전기특성·전극기하·HW 리스크가 미검증이라 **현 근거로는 도입 불가(조건부 No-Go)**. 상세 평결: [`에이전트-로그/99_종합평결.md`](에이전트-로그/99_종합평결.md).

> [!NOTE]
> 근거는 전문가 6 노드([`01`](에이전트-로그/01_P1_상호용량센싱원리.md)~[`06`](에이전트-로그/06_P6_대안트레이드오프결정.md))와 검증 4 노드([`07`](에이전트-로그/07_V1_주장1_하이젠베르크회피.md)~[`10`](에이전트-로그/10_V4_주장4_ESD재발.md)). "사실/확인"과 "가설/미확인"을 구분 표기한다.

## 1. 요구_1 — 상호용량이 관측교란(하이젠베르크)을 회피하는가?

### 1.1 원리 (P1)

- **측정 대상 차이**: self-cap은 전극-대지 커패시턴스 `Cx`를 단일노드로 적분(터치 시 C↑→counts↓). mutual-cap은 Tx→Rx 결합용량 `Cm`을 측정(터치 시 손가락이 필드 가로채 Cm↓→counts↑, **부호 반대**, Invert 비트 필요).
- **비대칭 구조**: mutual은 Tx(능동 구동, 저임피던스)·Rx(Sample&Hold, 고임피던스)의 **비대칭 2단자** 측정. "대칭 두 채널을 빼는 감산회로"가 아니다.
- **부동 도전체 예외**: mutual은 "손가락=접지된 도체" 전제 위에 섬. 부동(floating) 도체에선 Cm이 오히려 증가해 부호 반전(AZD004 §3.2). 신체 착용기기라 사용자 접지상태 가변 → 이 전제가 self보다 더 중요한 리스크(미확인).

### 1.2 노이즈 물리 (P2) — 본 검토의 급소

- **두 종류의 "차동" 구분**: 관측교란.md의 디퍼런셜 프로브는 "관찰 방식"의 차동(신호생성 원리 불변). mutual은 "Tx 캐리어 동기검파"라는 "측정 원리 자체"의 차동 → 프로브와 **질적으로 다름**. 그래서 경로_2의 일부(캐리어와 **비동기**인 성분)에 저감 잠재력이 있다는 가설(H2, IC 회로 미확인).
- **애그레서별 판정(정성)**:
  - I2C 426.7kHz·SYSCLK 계열(30.72/2.56MHz): 근접결합·비대칭 배치, 캐리어와 비정수배 → 동기검파 가설이 맞으면 **조건부 저감**.
  - PMIC(ISL9122): 그라운드/파워플레인 경유 **공통모드 EMC 노이즈원**(azd004/06 §11.2) → mutual 저감 근거 약함. 단 절전 시 OFF(사실).
  - RX 직결결합·경로_1(접지)·report-rate(100ms) 에일리어싱: 아키텍처 무관 **잔존**.
- **결론**: "완전 회피"는 근거 없음. 정확한 표현은 **"조건부·부분적 완화(가설)"**.

### 1.3 검증 (주장_1 → ❌ 반증, 신뢰도 중상)

- "차동=공통모드 상쇄" 전제가 IQS323 채널분류(공통드리프트 차감은 **reference tracking**)와 어긋남.
- 유일 완화 가설(H2 동기검파)은 데이터시트 전하전달 구조상 self와 다르지 않아 근거 박약.
- 원 설계문서 **§5.7 핵심 인용이 직접 대조 결과 불성립**(인용 오류).
- 에일리어싱 잔존 + 전극 비대칭 + mutual의 작은 베이스라인은 AZD004 §9상 **오히려 노이즈에 더 취약**할 잠재 위험.

## 2. 요구_2 — IQS323가 현 HW로 지원하는가?

### 2.1 IC 능력 (P3) — 확인된 사실

- IQS323 mutual(projected) 지원은 Azoteq 공식 예제(`IQS323_3PROJ_BUTTONS_EV_KIT.h`) 비트 역산으로 **확립**: PXS Mode=0x13(Mutual)·Wav Pattern=0x0E(Table 5.2 일치)·Invert=1.
- self/mutual 구분은 Sensor Setup의 TX_SELECT와 Prox Input의 RX_SELECT가 **같은 핀이면 self, 다른 핀이면 mutual**. (과거 `0x70` Channel Mode는 mutual과 무관한 별개 기능 — Independent/Follower/Reference, P5가 정정.)
- 물리 아날로그 핀은 TxA·CRX0·CRX1·CRX2 4개. **TxA(R30)는 DNP/NC**(미배선). CRX0(중앙, 활성)·CRX1(외곽, 현 비활성) 둘 다 D패드 배선됨 → 신규 배선 없이 레지스터 시도 가능.

### 2.2 검증 (주장_2 → ❌ 반증, 신뢰도 중)

- 레지스터 비트는 실재(재확인). 그러나 6개 노드 전원이 데이터시트 **§3.2 전기특성표를 누락**:
  - Cm 권장 0.2~9pF, Cp(Rx-VSS) ≤100pF, Cx/Cm 비 10~20.
- 이 정량 제약을 **실제 D패드(치수 미확인)·C52(직렬 커패시터, 통상 RCx 스펙 미해당)**와 대조한 근거가 전무 → "레지스터만으로 지원"은 **정량 게이트를 건너뛴 과확신**.

## 3. 요구_3 — D패드 형상이 적합한가?

### 3.1 전극 물리 (P4) + 검증 (주장_3 → ❌ 반증, medium)

- D패드는 **self-cap 면적최대화 설계의 유산**. AZD125 §7.2가 "Tx가 Rx를 둘러싸는" mutual 선례를 제시하나, D패드는 면적비가 **역전**(작은 외곽링이 큰 중앙필을 감쌈), **단일 경계선**(비인터디지트), **해칭 부재**.
- 검증에서 PDF 아트웍을 200~2400dpi 재렌더링: 치수 데이터 전무 확인 + 외곽이 "단일 링"이 아니라 **2겹 동심밴드**, 대면적 필의 전기적 연결점 미확정(P4보다 깊은 불확실성).
- Steelman 4건 모두 "실측 없이는 불성립" → **"충분한 감도"의 근거 없음**. 프린징 결합 밀도 낮고 중앙부 사각지대 구조적 리스크.
- 회로도 해석(사실): 패드보드 J1=RX, J2=TX, J3=Touch_PAD→GND. IC보드 CRX0→R31(100Ω)→C51→J3, CRX1→C52→R32(0Ω)→J4. 패드 "TX" 라벨은 IC의 실제 Tx 구동(TxA)과 무관한 CRX1 신호.

## 4. 요구_4 — CRX1 실전극화 시 회귀 (P5) + 검증 (주장_4 → ❌ 반증, high)

- **정정**: 현재 코드는 FullATI 전환으로 CalCap 더미·0x43/44/70·방전을 **이미 완전 폐기**(CH1=disable). "실전극화"는 더미 폐기가 아니라 **disable 채널 재활성화**.
- **단일채널 정지 재발**: 구조적으로 불가(방전 코드 0건 + CH1 상시활성으로 조건 자연충족).
- **전역 ati_error 교차간섭**: 과거 "영구 lock"이 아니라 "게이트드 Re-ATI 빈도 증가"로 **변형 재발 가능**(실측 게이트).
- **auto-ATI 선행 타이밍 급소**: mutual에도 존재하나, 현 FW의 "설정 후 명시 Re-ATI+블로킹 대기" 패턴이 이미 치료 → **기존 해법의 확장 대상**(새 문제 아님).
- **HW 리스크(검증 발견)**: CRX1 경로 **R32=0Ω**(CRX0 R31=100Ω, 데이터시트 권장 470Ω보다 약함, 6개 노드 미인용). 실전극화는 이 "무해하던" 경로를 터치 판정에 직결 → ESD/드리프트 유입 경로 신설. mutual ATI 자동복구는 CH0 전용 검증뿐.
- **마이그레이션 규모**: 실질 변경 `tdc_touch_iqs323.c`의 `sensor_setup()` 1파일 국한 **가능**(FSM·연결층 계약 유지) — 단 "mutual 결과=CH0 Touch 비트 1개" 전제 성립 시.

## 5. 요구_5 — 대안 완화책 vs mutual (P6)

| 축 | 셀프캡 + SW 완화 | 상호용량 전환 |
|---|---|---|
| 비용 | ≈0 (SW-only) | PCB 재설계급(전극쌍·소자·인증) |
| 경로_2 회피 | 부분(신규 GPIO 스트림 위주) | **미확정**(프로브차동≠센싱차동 혼동 위험) |
| 기존 원인 커버 | 제어재설계 권고가 이슈 9건 전부 SW로 설명·해소 경로 확보 | 별도 논증 필요 |
| 리스크 | 낮음 | 정량·기하·ESD 미검증 다수 |

- 이미 완결된 "제어 재설계 분석·권고"가 mutual을 **"보류"로 결론**냈고, 본 검토는 이를 뒤집을 근거를 찾지 못함.
- P6 잠정 권고: **조건부 No-Go** — Reseed 게이팅+ATI Full+§7 SW 완화 먼저, 실측으로 잔여 노이즈 확정 시만 mutual을 차세대 보드 트랙으로.

## 6. 요구_6 — 종합 판정 (go/no-go)

**조건부 No-Go.** 핵심 4주장 전부 반증. 근본 오해 = "차동=공통모드 상쇄"(→실제는 reference tracking). 도입 정당화 불가하나 물리적 불가능은 아님(IC·배선 실재, 조건부 부분완화 가설 잔존).

### 6.1 뒤집을 수 있는 유일 축

P1·P2의 "경로_2 실저감 여부"를 데이터시트·회로 레벨 또는 **실측**으로 확정하면 재평가. 그 외 3주장(IQS323 정량·D패드·ESD)도 각각 실측 게이트 존재.

### 6.2 실측 게이트 (mutual 재평가 전제조건)

1. 경로_2 실저감: mutual vs self에서 애그레서 on/off 시 counts 변화 정량 비교.
2. 데이터시트 §3.2 전기특성 vs 실 D패드 Cm/Cp/Cx 측정.
3. self vs mutual SNR 절대 비교.
4. R32=0Ω 경로의 CRX1 실전극 ESD/드리프트 영향.

### 6.3 부수 조치

- 원 설계문서 §5.7 인용 오류 정정.
- R32=0Ω·TxA(R30) DNP-NC HW 사실 회로문서 명시.
- 데이터시트 §3.2 전기특성표 md 반영(기존 모든 분석서 누락).
- **reference tracking 별도 검토**(공통모드 드리프트 상쇄의 실제 IC 수단).
