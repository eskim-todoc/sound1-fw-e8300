# 요구사항 — 상호용량 센싱 방식 재검토

**TL;DR**: 셀프캡(CRX0 단일전극) 터치는 MCU·주변 소자 클럭이 sub-pF 측정에 전하를 주입하는 "관측교란(하이젠베르크)"에 취약하다. 두 전극 차동인 상호용량(Mutual, CRX0↔CRX1)이 이 교란을 회피할 수 있는지, 현 IQS323·D패드 HW로 도입 가능한지를 전문가 페르소나로 검토해 **도입 여부 판단 근거**를 만든다. 신규 브랜치·타당성 검토 단계이며 제품 코드 변경은 없다.

> [!NOTE]
> 은수님 지시(2026-07-03) 원문을 요구사항으로 정형화. 도입 확정이 아니라 **가능성 검토**가 목표.

## 1. 배경 (은수님 제시)

1. **문제**: 셀프캡 방식 터치 사용 시, 노말/절전 모드에서 쓰이는 MCU·주변 소자의 클럭에 의해 **"하이젠베르크"(관측이 대상을 흔드는 현상)**까지 고려해야 하는 상황이다. (근거: [`docs/참고/touch/터치 계측 관측 교란/터치 계측 관측 교란.md`](../../../참고/touch/터치%20계측%20관측%20교란/터치%20계측%20관측%20교란.md))
2. **가설**: **상호용량 센싱(Mutual-Capacitive Sensing)**은 두 채널 사이의 변화량 기반이라, 이 하이젠베르크 현상을 **회피**할 수 있지 않을까 고민 중이다.
3. **HW 현황**: 현재 터치 패드는 [`docs/참고/touch/Sound1_Touch_Sensor_ver2.PDF`](../../../참고/touch/Sound1_Touch_Sensor_ver2.PDF)의 **"D"자 형상**. 아래쪽 접점(패드 **중앙부**)이 현 사용 채널 **CRX0**, 위쪽 접점(패드 **주변부/외곽링**)이 **CRX1**로 사용될 것.

## 2. 목표 (요구사항)

- **요구_1**: 상호용량 센싱의 원리를 정리하고, 셀프캡의 관측교란(경로_1 접지 / 경로_2 스위칭·에일리어싱)을 **실제로 회피/저감하는지** 물리적으로 판정한다. (핵심 쟁점: 차동이 경로_2를 상쇄하는가)
- **요구_2**: 현 **IQS323** IC가 상호용량/projected 모드를 지원하는지, **CRX0↔CRX1 페어링**이 레지스터 설정으로 가능한지 확인한다.
- **요구_3**: **D패드 형상**(중앙 채움 CRX0 + 외곽 링 CRX1)이 상호용량 감지에 적합한 전극 기하인지 검토한다.
- **요구_4**: CRX1을 실전극화(과거 **CalCap 더미** 폐기)할 때 과거 CRX1-dummy를 유발한 **ESD 전하누적·단일채널 방전** 문제 재발 여부와 현 펌웨어(FullATI 셀프캡 설계) 마이그레이션 영향을 평가한다.
- **요구_5**: 상호용량이 아닌 **셀프캡 완화책**(slew-rate 제한·윈도우 밖 토글·동기 샘플링 등)과의 비교로, 무엇이 옳은 해법인지 트레이드오프를 제시한다.
- **요구_6**: 위를 종합해 **도입 여부 권고(go/no-go)** + 신뢰도 + 다음 검증 단계(실측 게이트)를 제시한다.

## 3. 제약

- **제약_1**: 신규 작업. 상호용량 도입 여부 미확정 → **신규 브랜치** `claude_feature_touch-mutual-cap-review`에서 진행. (완료)
- **제약_2**: 본 단계는 **타당성 검토 문서 산출**만. 제품 소스 코드 변경 없음(4단계 프로세스 ④에서도 코드 아닌 검토문서가 산출물).
- **제약_3**: 근거는 `docs/참고/touch` 전체 문서(내가 생성한 문서 포함) + `docs/tasks/touch` 관련 이력에서 수집. 데이터시트·앱노트 근거 우선, 추측 금지.
- **제약_4**: 할루시네이션 방지 — 핵심 주장은 adversarial-verify 노드로 반론 검증 후에만 확정.
