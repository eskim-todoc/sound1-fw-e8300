## 2. ② Re-ATI 게이트 4조건 · 터치중 보류 (급소) — [확정] 동등

99fullati §3.2 급소 게이트 규칙: **`CH0 Touch==0(노터치) AND ATI Active==0(미진행) AND ATI Error AND 쿨다운 경과`**.

```c
/* logic.c:140~146 */

    && !in->ati_active && in->ati_error
    && in->now_ms >= st->re_ati_cooldown_until_ms)
{
    out->action = TDC_TOUCH_ACT_RE_ATI;
    st->re_ati_cooldown_until_ms = in->now_ms + TDC_TOUCH_RE_ATI_COOLDOWN_MS;
}
```

| 조건 | 99fullati/B99 | 코드 | 판정 |
|---|---|---|---|
| 노터치 | CH0 Touch==0 | `curr_state == NOT_TOUCH` | [확정] |
| 미진행 | ATI Active==0 | `!in->ati_active` | [확정] |
| 드리프트 신호 | ATI Error==1 | `in->ati_error` | [확정] |
| 쿨다운 | 경과 | `now_ms >= cooldown_until_ms` | [확정] |

- **급소(터치중 보류)**: 첫 조건 `curr_state==NOT_TOUCH` 가 TOUCH 시 false → 발행 보류. B99 E5''(터치중 ATI Error 무시)·§6.2 "터치 중 드리프트 → 보류" 와 동등 [확정]. **터치중 Re-ATI 누출 = 0**(99fullati 검토_2 급소 충족).

## 6. ⑥ 쿨다운 — [확정] 정본 동등 + [경미] 동작 차이 1건

| 항목 | 정본(B99 §4.3) | 코드 | 판정 |
|---|---|---|---|
| 쿨다운 길이 | 발행 후 +10 tick = 약 2000ms @200ms | `cooldown_until = now + RE_ATI_COOLDOWN_MS(2000)`(`logic.c:145`·`time.h:25`) | 값 동등 [확정] |
| 발행 직후 재발행 차단 | cooldown=10 세팅 | `now >= until` 시만 발행, 발행시 until=now+2000 | 동작 동등 [확정] |
| 초기 첫 드리프트 | cooldown 0 → 즉발 가능 | `logic_init: until_ms=0`(`logic.c:71`) → `now>=0` 즉발 | [확정] 동등 |

### [경미-1] 쿨다운 구현 방식 차이 — 카운트 동결 vs 절대시각 진행

- **정본 동작(B99 §4.3 NOTE)**: 쿨다운은 **카운트 선감소형** — "게이트 미호출 tick(부팅 무시 구간·read hold)에선 감소 안 함"(동결).
- **코드 동작**: **절대시각 비교형**(`now_ms >= until_ms`) — 부팅무시/read hold 구간에서도 벽시계 `now_ms` 가 진행하므로 쿨다운이 **계속 만료를 향해 진행**. 게이트 미호출이어도 시간은 흐름.
- **차이 실효**: 부팅무시/read-hold 가 2초 이상 지속한 직후 첫 노터치 tick 에서 — 정본은 쿨다운 잔량 유지(추가 차단), 코드는 이미 만료(즉시 발행 가능). 즉 **신규가 정본보다 약간 더 일찍 재발행 가능**.
- **판정 [경미]**: ⓐ 쿨다운 목적(연속 발행 폭주 방지)은 절대시각 방식이 **동등 이상으로 달성**(burst 진행 중엔 ati_active=1 이 2차 조건으로 별도 차단 — B99 §4.3 삼중 안전 중 ati_active 게이트는 신규 `:141 !in->ati_active` 로 유지). ⓑ load-bearing 요구(터치중 보류·드리프트 단일 사이클 복구)에 영향 0. ⓒ 절대시각형이 오히려 견고(타이머 1소스). **근거 없는 로직 아님 — 의도적 설계 치환**(`time.h` 주석 "ms 만 바꾸면 카운트 자동 파생", 본 상수는 카운트 미사용·시각 직접). 정본 동작 표기와의 미세 차이일 뿐 누락·왜곡 아님.

> [!NOTE]
> 본 항목은 **할루시네이션(근거 없는 로직) 아님**. B99 §4.3 표의 "tick 선감소" 메커니즘을 동일 시간(2000ms)·동일 목적의 절대시각 비교로 구현한 것으로, 동작 결과가 read-hold/부팅무시 경계에서만 미세 상이. 정본 요구의 핵심(폭주 차단·삼중 안전)은 보존. [경미]로만 기록.

## 7. 게이트·stuck·롱터치 상호작용 (액션 충돌·순서) — [확정] 정본 동등

- **액션 충돌 0**: 게이트=NOT_TOUCH 전용(`:140`), stuck=TOUCH 전용(`:21·27`) → 한 step 에서 둘 다 action 설정 불가(상태 배타). B99 §3 CAUTION·99간결구조 §2.3 "단일 action 필드 안전" 동등 [확정]. 코드 순서(`:140 게이트 → :150 stuck_eval`)에서 stuck 이 게이트 action 을 덮을 수 있으나(`:153 out->action=sa`), 상태 배타라 게이트가 action 을 set 한 tick 엔 stuck 이 NONE 반환 → 실제 덮어쓰기 0 [확정].
- **롱터치는 action 아닌 별도 불리언**(`out->long_touch`, `:169`) → action switch 와 독립. B99 §2.2(롱터치=process return true) 동등 [확정].
- **순서 정합**: B99 §2.2 콜스택 "게이트→stuck→롱터치"(`:482·486·489`) ↔ 신규 `:140 게이트 → :150 stuck → :158 롱터치` 동일 순서 [확정].
- `prev_state` 갱신: 본문 말미 1회(`:177`)·부팅무시 분기 말미(`:135`)·hold 시 미갱신(`:100~104`). B99 E6 "prev 미갱신"·E9/E10 "prev 갱신" 동등 [확정].
