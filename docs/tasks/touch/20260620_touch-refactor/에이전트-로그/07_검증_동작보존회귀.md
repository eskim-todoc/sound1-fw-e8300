# 07 동작보존 회귀 검증 (adversarial)

**TL;DR**: 3레이어 설계(02 L2 순수 FSM·03 L1 포트·04 L3 어댑터·05 테스트·06 파일)가 B99 Full ATI 동작을 기능 동등 보존하는지 6 급소로 적대 검증했다. **종합: [보존] 4 · [위험] 5 · [누락] 2**. 6 급소 중 ① Re-ATI 게이트 터치중 보류·④ 부팅 Re-ATI·⑥ Beta/Power는 [보존](구조적으로 안전), ② read 실패 캐시 무효화는 입력 정규화로 [보존]하나 **11회 초과 강제 NOT_TOUCH tick의 게이트 발행 경로([위험_1])** 가 핵심 회귀 함정 — 02 설계의 "read_ok=false 시 동결(HOLD)"이 현 코드의 "≤10 hold, >10 NOT_TOUCH 강제 후 게이트 호출"과 다르게 처리될 수 있어 검증 케이스 명시 필요. ③ stuck 3단계는 [보존]하나 **stuck stage2 Re-ATI가 단일 action 필드와 게이트 action의 충돌 가능성([위험_2])**. ⑤ 절전은 02가 "L2 재사용 옵션"을 열어두어 요구사항_4(절전 미변경)와 충돌 위험([위험_3], 06은 상수 이동만 권고로 안전). 추가 적출: 쿨다운 카운트→절대시각화 미세 비동등([위험_4]), 부팅 무시 해제 "그 tick도 무시" 순서 누락 위험([위험_5]), 롱터치 `s_state_old` RESET 케이스 처리([누락_1]), stuck `s_prev` 초기값 RESET 보존([누락_2]). 모든 [위험]은 설계 수정 또는 05 테스트 케이스 강제로 회귀 0 달성 가능 — 구조 자체는 건전. 코드 근거 [파일:라인] 전수.

## 0. 검증 방법·기준

- **기준(ground truth)**: B99 §3 이벤트 천이표(E1~E10·S1~S3) + §2 콜스택 + §4 타이밍 + §6 예측 동작. "기능 동등(회귀 0)" = 동일 입력 시퀀스에 동일 액션·상태·반환.
- **적대 관점**: 순수화·레이어 분리가 ① 분기 조건을 누락, ② 전역→구조체 이주 중 race·초기값 변경, ③ 시간축(ms 차분 vs 카운트) 혼동, ④ 처리 순서 변경을 일으키는지 능동 적출.
- **직접 재확인한 코드**: `tdc_touch.c:85~139`(롱터치)·`:224~241`(게이트)·`:252~305`(stuck)·`:388~497`(init·process)·`:499~555`(get_state)·`main.c:981~1037`(ULP)·`tdc_drv_iqs323.c:1241~1289`(Beta/Power·부팅 Re-ATI). 라벨 [확정]=코드 명시·[위험]=설계가 바꿀 수 있음·[추정].

## 1. 급소 ① — Re-ATI 게이트 터치중 보류 → **[보존]** (단 [위험_1] 연동)

### 1.1 현 동작 (B99 E5·E5'·E5''·§6.2)

`proc_re_ati_gate` 4조건 [tdc_touch.c:234]:
```c
if (state_now == NOT_TOUCH && !s_last_ati_active && s_last_ati_error && s_cooldown == 0)
```
첫 조건 `NOT_TOUCH`가 터치중 보류 급소다. 터치 중(`state_now==TOUCH`) ATI Error가 떠도 발행 안 함 → 손가락 닿은 채 Re-ATI로 노터치 학습하는 회귀 차단 [B99 §6.2 확정].

### 1.2 설계 매핑

- 02: `fsm_eval_re_ati_gate()`가 4조건을 순수 분기로 보존, 입력 `in.pressed`/`curr_state`로 NOT_TOUCH 판정. 05 G2 케이스(`curr_state=TOUCH, error=true, cd=0 → 미발행`)로 명시 고정 [05:150].
- 03: `port_re_ati`는 "게이트는 호출측 L2 책임 — 포트는 무조건 발행" 계약 [03 §5]. 포트가 조건을 떠안지 않음 → 안전.

### 1.3 판정 **[보존]**

4조건 NOT_TOUCH 첫 분기가 L2 순수 함수 입력(`curr_state`)으로 노출되고 05 G2가 단일 케이스로 회귀 가드. 단 **`curr_state`를 무엇으로 채우는가**가 [위험_1](§2)와 직결 — read 실패 강제 NOT_TOUCH tick에서 게이트가 호출되며, 이때 `s_last_ati_error`가 false여야 발행 안 됨. 그 캐시 무효화가 입력 정규화로 옮겨가는 과정이 핵심.

## 2. 급소 ② — read 실패 캐시 무효화(stale 누출 차단) → **[보존] + [위험_1] 핵심**

### 2.1 현 동작 (B99 E6·E7·§6.2, 직접 확인 [tdc_touch.c:505~531])

read 실패 시 `tdc_touch_get_state`가 **두 가지를 동시에** 한다:
1. `s_last_ati_error/active = false` 무효화 [tdc_touch.c:512·513]
2. `return false`

그 뒤 `tdc_touch_process`의 처리가 **두 갈래**다 [tdc_touch.c:445~452]:
- **≤10회 (E6 hold)**: `:449 return false` → 게이트·stuck·롱터치 **호출 안 함**(동결). 캐시 무효화는 했지만 게이트가 안 불려서 무관.
- **>10회 (E7 강제)**: `:451 curr_state = NOT_TOUCH` 강제 → 그 뒤 게이트가 **호출됨** [tdc_touch.c:482]. 이때 `s_last_ati_error`가 **false로 무효화되어 있어야** 4조건(`NOT_TOUCH && error`)이 불충족되어 미발행. **이것이 급소의 진짜 작동 지점**이다.

> [!CAUTION]
> 급소가 막는 시나리오: 손가락 닿은 채(`pressed=1`) 통신 글리치로 read만 11회 연속 실패 → `:451`이 NOT_TOUCH로 강제 → 게이트 호출. 만약 캐시가 stale(`error=1`)로 남아 있으면 4조건 충족 → Re-ATI 발행 → **여전히 닿은 손가락을 노터치로 학습**. `:512` 무효화가 이를 차단 [B99 §6.2 확정].

### 2.2 설계 매핑 (02 §2.2·§1.3)

02는 "L3가 read 실패 시 `in.read_ok=false, pressed=false, ati_error=false, ati_active=false`로 정규화 주입 → L2는 stale 캐시를 가질 수 없음"으로 흡수 [02:106·62]. 전역 `s_last_ati_*` 제거 → race 0. **방향은 정확**하다.

### 2.3 [위험_1] 핵심 함정 — hold 동결(HOLD)과 강제 NOT_TOUCH(게이트 호출)의 분기 보존

02 §2.1은 `read_ok=false` 시 액션 `HOLD`로 "상태/게이트/stuck/롱터치 평가 자체를 스킵" [02:82]한다. 그러나 현 코드는 read 실패를 **단일 동결이 아니라 카운트 분기**로 처리한다:

| 현 코드 | read_fail_cnt | curr_state | 게이트 호출? | 02 설계가 보존해야 할 것 |
|---|---|---|---|---|
| E6 [:449] | +1 ≤ 10 | (미설정·동결) | **아니오** | `action=HOLD`, 게이트/stuck/롱터치 스킵 |
| E7 [:451] | +1 > 10 | **NOT_TOUCH 강제** | **예** | `curr_state=NOT_TOUCH`로 게이트 평가, 단 `ati_error=false`라 미발행 |

**적출**: 02 §2.1·§3.2 플로우차트([02:212~213])는 "fail_cnt+1 > hold → curr_state=NOT_TOUCH 강제 → 그 뒤 게이트/stuck/롱터치 평가"로 올바르게 그렸다. 하지만 02 §2.5 cfg의 `read_fail_hold_cnt`와 §2.1의 `HOLD` 액션 설명이 "동결"만 강조해, **>hold tick에서 게이트가 호출되되 정규화된 `ati_error=false`로 미발행되는 경로**가 시그니처 레벨에서 흐려질 수 있다. L2 `step`이 E7 경로에서:
1. `curr_state=NOT_TOUCH` 산출 (정규화 입력의 `pressed=false` 기반)
2. 게이트 평가 시 `in.ati_error=false`(정규화) → 4조건 불충족 → action=NONE

이 **두 단계가 모두** 보존되어야 한다. 만약 L2가 "read_ok=false면 무조건 HOLD로 early-return"하게 단순화하면 **E7의 NOT_TOUCH 강제 전이가 사라져** stuck 리셋·롱터치 래치 해제(B99 E7 side effect)가 누락된다.

> [!IMPORTANT]
> **[위험_1] 회귀 0 조건**: L2 `step`은 `read_ok=false`를 받으면 ① `read_fail_cnt++` ② `cnt ≤ hold`면 action=HOLD·평가 스킵 ③ `cnt > hold`면 **curr_state=NOT_TOUCH로 강제하고 게이트/stuck/롱터치를 정상 평가**(단 정규화로 error=false라 게이트 미발행, stuck NOT_TOUCH라 리셋, 롱터치 NOT_TOUCH라 해제). 05 RF3·MT5가 이를 검증하나 [05:186·280], **RF5(캐시 무효화 급소)는 "11회 초과 시 게이트 미발행"을 명시 단언해야** 한다 — 현 RF5 설명("터치중 error캐시→read실패 hold 중 게이트 미발행" [05:188])은 hold(≤10) 구간만 다루고 **>10 강제 진입 tick의 미발행**을 놓칠 여지. **05에 케이스 추가 권고**: `RF5b — read 11회 실패 후 강제 NOT_TOUCH tick에서 cnt_re_ati==0`.

### 2.4 판정 **[보존](방향) + [위험_1](검증 케이스 보강 필수)**

입력 정규화로 전역 캐시 제거·race 0는 구조적 개선. 단 E6/E7 두 갈래(동결 vs 강제 진입+미발행)를 L2가 정확히 재현하는지가 회귀 핵심. 05 RF5b 케이스 추가로 게이트.

## 3. 급소 ③ — stuck 3단계(30/60/90초) → **[보존] + [위험_2]**

### 3.1 현 동작 (B99 S1~S3, 직접 확인 [tdc_touch.c:252~305])

- TOUCH 아니면 `s_stage=0`·`s_prev=state_now`·early return [tdc_touch.c:258~262] — 해제 시 즉시 리셋.
- TOUCH 진입 엣지(`s_prev != TOUCH`)에 `s_stuck_tick0=tick`·`s_stage=0` [tdc_touch.c:266~270].
- `STUCK_MS <= (tick - anchor)`마다 stage 0→1→2: RESEED → Re-ATI → MCLR [tdc_touch.c:273~301]. 각 단계 후 anchor 갱신(30초 재카운트).
- stage2 Re-ATI는 **게이트 우회**(의도적 재캘리) [tdc_touch.c:286 주석].

### 3.2 설계 매핑

- 02 §3.3 S1~S3 [02:247~249]·05 ST3~ST8 [05:168~173]에 1:1 사상. stuck anchor 갱신은 L2 내부 시각 인자로 순수화 [02 §3.3].
- 02는 `stuck_anchor_ms`·`stuck_prev_state`·`stuck_stage`를 구조체 멤버로 [02:148~150].

### 3.3 [위험_2] 단일 action 필드 — stuck Re-ATI vs 게이트 Re-ATI 충돌

02 §2.1·§3.3은 action을 **단일 enum 필드**로 두고 "게이트(NOT_TOUCH 전용)·stuck(TOUCH 전용) 배타라 충돌 0" 논증 [02:252]. **이 논증은 맞다** — 한 tick에서 `curr_state`는 TOUCH 또는 NOT_TOUCH 하나뿐이라 게이트와 stuck이 동시 발행 불가. 코드도 게이트는 `NOT_TOUCH` 조건 [tdc_touch.c:234], stuck은 `state_now != TOUCH면 early return` [tdc_touch.c:258]이라 배타.

그러나 [위험_2] 적출: **stage2 Re-ATI와 게이트 Re-ATI가 같은 `TDC_TOUCH_ACTION_RE_ATI` enum 값**이다 [02:83]. L3가 action만 보고 `port_re_ati()`를 부르므로 동작은 동일하나, **05 ST4(stuck stage2 Re-ATI)와 G1(게이트 Re-ATI)이 같은 액션값이라 "어느 경로로 발행됐는지" 구분이 테스트에서 흐려진다**. 05 §2.4 NOTE가 "stage2 Re-ATI는 게이트 우회라 게이트 4조건과 무관하게 발행" [05:175]을 명시했으나, L2 step이 **게이트 평가를 먼저(NOT_TOUCH라 미발행) → stuck 평가(TOUCH라 stage2 발행)** 순서로 돌 때, 단일 action 필드라 stuck이 게이트 action을 덮어쓰는 게 아니라 **애초에 게이트가 NONE을 낸 뒤 stuck이 RE_ATI를 냄**. 순서 보존이 관건.

> [!IMPORTANT]
> **[위험_2] 회귀 0 조건**: L2 step 내부 순서가 현 process와 동일한 **게이트(:482) → stuck(:486) → 롱터치(:489)** [B99 §2.2]여야 한다. 02 §2.6 NOTE가 이 순서 보존을 명시 [02:195]하나, **단일 action 필드라 한 step에서 RESEED(stage0)와 게이트가 동시 산출될 수 없음을 05 SQ 케이스로 강제**해야 한다(게이트는 NOT_TOUCH·stuck stage0은 TOUCH라 배타). 05 SQ1/SQ2가 이를 다루나 [05:208~209], **stuck 액션이 단일 필드를 점유할 때 게이트가 직전에 NONE을 산출하는지** 명시 단언 권고. 또한 stage2 Re-ATI 발행 시 `re_ati_cooldown_until_ms`를 갱신하는가/안 하는가 — 현 코드는 stuck Re-ATI가 게이트 쿨다운을 **건드리지 않음**(별도 경로) [tdc_touch.c:288은 s_cooldown 미터치]. L2가 stuck RE_ATI에서 쿨다운을 갱신하면 회귀. **05에 케이스 추가 권고**: `ST4b — stuck stage2 Re-ATI 후 게이트 쿨다운 불변`.

### 3.4 판정 **[보존] + [위험_2]**

3단계 에스컬레이션·해제 리셋·30초 재카운트 모두 02·05에 사상됨. 단 ① 게이트→stuck→롱터치 순서 보존, ② stuck Re-ATI가 게이트 쿨다운 미터치를 05 케이스로 강제해야 회귀 0.

## 4. 급소 ④ — 부팅 Re-ATI → **[보존]**

### 4.1 현 동작 (B99 §2.1·§4.1, 직접 확인 [tdc_drv_iqs323.c:1253~1269])

부팅 Re-ATI는 `apply_settings` **내부**에 있다 [tdc_drv_iqs323.c:1255 `re_ati_trigger()` + 50틱 spin + `:1265 wait_re_ati_done()`]. `try_finish_init`이 `tdc_drv_iqs323_apply_settings()` 1회 호출 [tdc_touch.c:332]로 트리거.

### 4.2 설계 매핑

- 03: `port_apply_settings`가 `tdc_drv_iqs323_apply_settings`로 무변경 위임 [03 §4·§5 "ACK→설정→Full ATI write→Beta/Power→부팅 Re-ATI→RESEED→Power Mode 순서·내용 무변경(1 tick)" 계약].
- 06: `try_finish_init`은 L3 부팅 어댑터로 잔류, 드라이버 시그니처 무변경 [06 §2.2 (D)·(F)].
- 02: init FSM(부팅 Re-ATI 포함)은 **L2 밖** 명시 [02 §1.1 NOTE·미해결_1].

### 4.3 판정 **[보존]**

부팅 Re-ATI는 드라이버 `apply_settings` 내부 캡슐화라 L1 포트가 통째 위임하면 동작 0 변경. L2 순수화 범위 밖(init FSM은 L3+L1)이라 순수화 누락 위험 없음. **단 [실측 게이트 연동]**: 06 §4.1이 가드를 L3 호출측으로 격상하나 부팅 Re-ATI 가드(`#if TDC_TOUCH_FULL_ATI_ENABLE` [tdc_drv_iqs323.c:1249])는 **드라이버 내부**라 06 격상 대상 아님 — 안전. 02 미해결_1(init FSM 경계)이 종합 노드에서 "init은 L3 어댑터 + L1 포트"로 확정되면 회귀 0.

> [!NOTE]
> 잔여 주의: B99 §4.1 "부팅 Re-ATI 최악 약 1.3초 블로킹 + auto-ATI 2500ms 타임아웃 직렬 = 약 3.8초 부팅 1 tick 점유"는 **타이밍 특성이지 회귀 아님**(설계가 이를 안 바꿈). L1 위임이 블로킹 시간을 보존하므로 동등.

## 5. 급소 ⑤ — 절전 미변경(ULP 2.2초) → **[보존](06 권고) + [위험_3](02 옵션)**

### 5.1 현 동작 (B99 §2.3, 직접 확인 [main.c:981~1037])

ULP 루프는 `tdc_touch_get_state()` 1회 [main.c:993] + `touch_cnt` 자체 누적 + `>= ULP_LONG_TOUCH_COUNT(11)` 시 `SYS_WATCHDOG_RESET()` [main.c:1011~1015]. 손 뗌·read 실패 시 `touch_cnt=0` [main.c:1026·1035]. **`tdc_touch_process`·`proc_re_ati_gate`·`proc_stuck_timeout` 호출 0건** [B99 §2.3 확정]. L2 FSM 미경유.

### 5.2 [위험_3] 02와 06의 충돌

- **06 (안전)**: ULP 카운팅을 "L2로 끌어들이지 않고 상수만 `time.h`로 이동" [06 §3.2·§3.3 "총 약 5줄"]. `ULP_LONG_TOUCH_COUNT → TDC_TOUCH_ULP_LONG_TOUCH_CNT` 명칭 1곳 교체 [06:202]. **요구사항_4(절전 미변경) 보존**.
- **02·04 (위험)**: 02 §4.3·미해결_3이 "절전 ULP 롱터치도 동일 `tdc_touch_fsm_step` 재사용 가능"을 제안 [02:284~290]. 04 §4.3도 `tdc_touch_adapter_sleep_wake()`가 L2를 호출하는 구조를 그림 [04:267~287]. **만약 절전을 L2 FSM으로 재작성하면**:
  - 현 단순 카운트(`touch_cnt++`)를 절대시각 롱터치(02 §4.3 "첫 TOUCH 시각부터 ULP_LONG_TOUCH_MS 경과")로 바꿈 → **시간축 변경**.
  - 절전 ULP는 `ci_timer_get_tick()`이 prescaled(약 201.6ms/tick) [B99 §2.3·main.c:816]이라 ms 차분 신뢰 불가 [04 §2.3]. L2가 ms 절대시각 롱터치를 쓰면 **절전 시간축 혼동 회귀**.

> [!CAUTION]
> **[위험_3] 적출**: 04 §4.3 `adapter_sleep_wake()` 코드 예시는 실제로 `++s_touch_cnt >= TDC_TOUCH_ULP_LONG_TOUCH_CNT` **카운트 방식을 유지**한다 [04:278] — L2 `fsm_step`을 안 부르고 어댑터 내부 카운트. 이는 06 권고(상수만 이동)와 **일치**하며 안전. 그러나 04 §4.1 Mermaid는 `S3[L2 fsm_step_ulp 입력 카운트1]`로 L2 경유를 그려 [04:181] **문서 내 모순**. 02 §4.3은 명시적으로 "절전 L2 재사용은 선택(권장)·1차는 노말만" [02:290]. **종합 노드 확정 필요**: 절전은 ① L2 미경유 카운트 유지(06·04코드, 회귀 0) vs ② L2 재사용(02 제안, 시간축 회귀 위험). **권고: ①** — 요구사항_4 절전 미변경 + B99 §2.3 절전 L2 미경유 [확정] 보존.

### 5.3 판정 **[보존](06·04코드 채택 시) / [위험_3](02 L2 재사용 채택 시)**

절전을 L2 FSM으로 재작성하지 않고 카운트 로직 유지 + 상수만 `time.h` 이동이면 회귀 0. 종합 노드가 "절전 L2 미경유"를 명시 확정해야 [위험_3] 해소. 04 문서 내 Mermaid(§4.1)와 코드(§4.3)의 모순도 정리 필요.

## 7. 순수화 과정 추가 적출 (전역상태 race·시간축·초기값)

### 7.1 [위험_4] 쿨다운 카운트 → 절대시각화 미세 비동등

02 §2.4·§3.4가 게이트 쿨다운을 `s_cooldown--`(카운트)에서 `re_ati_cooldown_until_ms`(절대시각)로 결정화 [02:144·258]. **폴링 등간격이면 수학적 동등** 논증은 맞다 [02 §3.4·B99 §4.3 "+10 tick=2000ms"]. 그러나 02 스스로 [실측 게이트]로 남긴 미세 차이 [02:261·297]:

- 현 카운트 방식: "게이트 호출 tick에서만 감소"(read hold·부팅무시 tick엔 미감소) [B99 §4.3 확정].
- 절대시각 방식: 시각이 그 tick에도 흐름.

**적출**: read hold가 길면(최대 10×200ms=2000ms) 그 동안 카운트는 동결이나 절대시각은 2000ms 흐름 → **쿨다운이 hold 중 만료될 수 있음**. 시나리오: 게이트 발행(쿨다운 armed) → 직후 read 9회 실패(hold) → hold 종료 시 절대시각 쿨다운 이미 만료 → 첫 노터치 tick에서 즉시 재발행 가능. 현 카운트 방식은 hold 동안 미감소라 hold 후에도 쿨다운 잔여. **미세하나 비동등**.

> [!IMPORTANT]
> **[위험_4] 판정**: 02 §3.4 NOTE가 "① read hold 중엔 게이트 평가 동결이라 발행 불가, ② hold 종료 후 tick_ms 이미 흐른 값이라 첫 노터치 tick 만료 판정 → 실질 동등하거나 보수적"으로 자기 변호 [02:261]. **실질 영향은 "쿨다운이 더 빨리 풀려 재발행이 1~2 tick 빨라짐"**으로 안전 방향(과도 억제 완화)이나 **완전 동등은 아님**. 회귀 0을 엄격히 원하면 **카운트 필드 유지**(02 미해결_2 옵션). **권고: 완전 동등 위해 `re_ati_cooldown_remaining_cnt` 카운트 필드 유지** — 절대시각화의 "의미 명확" 이득보다 회귀 0(요구사항)이 우선. 05 G5~G7이 카운트 방식 전제 [05:153~155]라 카운트 유지가 테스트와도 정합. 종합 노드 결정.

### 7.2 [위험_5] 부팅 무시 해제 "그 tick도 무시" 순서

현 코드 [tdc_touch.c:465~479]: `s_boot_touch_ignore` 구간에서 `curr_state != TOUCH`면 `s_boot_touch_ignore=false` 후 **그 tick도 `return false`** [tdc_touch.c:478] (게이트 미호출). B99 E10 "ignore=false 복귀, 그 tick도 return false".

02 §3.2 플로우차트는 이를 `H[boot_ignore=false] → K2[그 tick도 무시] → O` [02:216·228]로 그려 **보존**. 그러나 [위험_5] 적출: 02 out 구조체에 `boot_released_log` [02:120]은 있으나, **"해제 tick에서 게이트/stuck/롱터치를 평가 안 함"** 이 step 순서에서 early-return으로 보장되는지가 시그니처 레벨에서 모호. 만약 L2 step이 boot_ignore 해제 후 fall-through로 게이트를 평가하면 **해제 tick에 게이트 발행 가능**(현 코드는 미발행).

> [!NOTE]
> **[위험_5] 판정**: 02 §3.2 Mermaid가 `H→K2→O`로 게이트(L)를 건너뛰게 그려 의도는 맞다. 단 05에 **BT2 케이스("부팅 해제 tick에 액션 0")** 가 있으나 [05:199] "그 tick도 동결" 명시가 약함. **05 BT2 강화 권고**: `해제 tick에서 cnt_re_ati==0 && stuck 미진행 && 롱터치 미평가` 단언. 구조는 보존, 테스트 강화로 회귀 0.

### 7.3 [누락_1] 롱터치 `s_state_old` RESET 케이스

현 `proc_long_touch` [tdc_touch.c:92~135]는 `s_state_old`를 switch — RESET·TOUCH·NOT_TOUCH·CALIBRATION_ERROR 4 케이스. RESET·NOT_TOUCH·default 모두 "TOUCH 진입 시 first_touch 기록·`s_is_long_touch=false`" 동일 [tdc_touch.c:96·128]. **초기 부팅 직후 첫 TOUCH(s_state_old=RESET)** 가 정상 first_touch를 기록하는 케이스.

02 §2.4 `lt_prev_state` [02:139]·05 LT1~LT7 [05:135~141]은 NOT_TOUCH→TOUCH 진입만 다루고 **RESET→TOUCH(부팅 직후 첫 터치) 케이스 미명시**. B99 상태머신은 `RESET → TOUCH: pressed1 E1` [B99:167]로 존재.

> [!IMPORTANT]
> **[누락_1] 판정**: 02 `fsm_init`이 `lt_prev_state`를 무엇으로 초기화하는지 미명시 [02:187]. 현 코드 초기값 `s_state_old = RESET` [tdc_touch.c:87]. L2가 RESET 초기값을 보존하고 RESET→TOUCH에서 first_touch 기록해야 **부팅 직후 첫 롱터치**가 동작. **05에 LT0 케이스 추가 권고**: `RESET(초기)→TOUCH에서 lt_first_touch 기록, 이후 2400ms 도달 시 fired`. 누락 시 부팅 후 첫 롱터치가 first_touch 미기록으로 오동작 가능. 02 `fsm_init`이 `lt_prev_state=RESET` 명시 필요.

### 7.4 [누락_2] stuck `s_prev` 초기값 RESET 보존

현 `proc_stuck_timeout` `s_prev` 초기값 `TDC_TOUCH_STATE_RESET` [tdc_touch.c:255]. 첫 TOUCH 진입(`s_prev != TOUCH`)에 anchor 기록 [tdc_touch.c:266]. **RESET→TOUCH도 진입 엣지로 인식**해 anchor 기록.

02 §2.4 `stuck_prev_state` [02:149]·05 ST1~ST8 [05:166~173]은 NOT_TOUCH→TOUCH만. **RESET→TOUCH 첫 진입 anchor 기록 미명시**.

> [!NOTE]
> **[누락_2] 판정**: [누락_1]과 동형. 02 `fsm_init`이 `stuck_prev_state=RESET`·`stuck_stage=0` 초기화 명시 필요 [02:148~150 구조체만, init 미명시]. RESET→TOUCH 진입에 anchor 기록 보존해야 부팅 직후 stuck 카운트 정상 시작. **05 ST1 강화 권고**: 초기 `s_prev=RESET` 전제 명시. 회귀 영향은 낮으나(부팅 직후 30초 TOUCH 지속은 비정상) 명시 보존 권고.
