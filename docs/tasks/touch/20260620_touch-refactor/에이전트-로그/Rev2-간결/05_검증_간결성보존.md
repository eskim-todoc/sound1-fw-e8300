# 05 간결성·제어방법 보존 검증 (Rev.2 adversarial)

**TL;DR**: Rev.2 설계 4노드를 적대적으로 검증한 결과 **[간결·보존] 합격, [과추상] 0건, [누락·회귀] 봉합 가능 4건**이다. ① **간결성** — 권장 3파일(순수 FSM·IQS323 직접·연결) + 시간상수 헤더 1, 포트 vtable·mock·어댑터·L1/L2/L3 추상 명명 **전부 폐기 확인**(Rev.1 대비 추상 레이어 0). 순수 FSM은 `tdc_*_logic/fsm.h`만 include해 HW 헤더 격리를 컴파일러가 강제. 함수는 작고 단일책임(공개 3·내부 static 1). ② **제어방법 보존** — FullATI 8대 제어(게이트 터치중 보류·read 실패 정규화 급소·stuck 3단계·부팅 Re-ATI·Beta/Power·단일채널·절전)가 B99 §3 이벤트표(E1~E10·S1~S3) **전수 동등**. 게이트·stuck 배타라 단일 action 필드 안전. ③ **테스트 용이** — 순수 FSM이 HW/timer/printf 0 include, 전역·static 0, in→out 결정론이라 mock 없이 구조체 주입만으로 유닛테스트. **그러나 봉합 필수 4건**: (가) **파일명·시그니처 4노드 불일치**(`tdc_touch_logic` vs `tdc_touch_fsm`, `tdc_iqs323` vs `tdc_touch_iqs323` vs `tdc_drv_iqs323`, cfg 인자 유무, in 필드명 `now_ms` vs `tick_ms`) — 99가 단일 확정 필수. (나) **원점 라인 인용 오류**(`s_last_ati_error/active` 캐시를 `tdc_touch.c:45·46`이라 인용하나 현 원점에 캐시 부존재 — FullATI 버전 라인). (다) **boot_ignore 해제 시 read 실패 상호작용**(02 §6-5 자인) — `read_ok && curr!=TOUCH` 보존 확인 필요. (라) **연결층 04가 02 폐기 필드 참조**(prev_state·boot 3불리언 로그) — out 5필드 축소와 충돌. 한자 0, 코드 근거 [파일:라인].

## 1. 축 ① 간결성 검증 — [간결·보존] 합격

### 1.1 파일 수 2~3개 충족

| 파일 | 성격 | 추상 레이어 | 판정 |
|---|---|---|---|
| 순수 FSM(`tdc_touch_logic`/`_fsm`.c/.h) | HW 0, 테스트 대상 | 0 | [간결] |
| IQS323 직접(`tdc_touch_iqs323`/`tdc_iqs323`.c/.h) | I2C 직접 | 0(평탄 static 3층) | [간결] |
| 연결(`tdc_touch`.c/.h) | 얇은 접착 | 0(switch 1덩어리) | [간결] |
| 시간상수(`tdc_touch_time.h`) | ms 1곳 | 헤더 전용 | [간결] |
| config(`tdc_touch_config.h`) | 빌드가드만 | — | [간결] |

- **코어 3파일 + 헤더 2(time·config)** = 요구사항 "2~3 간결" 충족. 합본 시 최소 2파일(FSM 별도 필수 + iqs+연결 합본)도 명시(01 §3.1 NOTE). [간결·보존]
- **순수성 컴파일 강제**: 순수 FSM이 `<stdbool.h>`·`<stdint.h>`·자기 헤더만 include, `hw.h`·`ci_timer.h`·`ci_printf.h`·iqs323 헤더 **금지**(02 §2.1, 01 §3.1). HW 호출이 섞이면 컴파일 단계에서 잡힘 — 밸리데이션 추적성의 구조적 보장. [확정·합격]

### 1.2 추상 레이어 0 — 과추상 재발 없음 [과추상 0건]

Rev.1 폐기 대상이 Rev.2 4노드 어디에도 **부활하지 않았음**을 전수 확인:

| Rev.1 추상 | Rev.2 4노드 잔존 여부 | 근거 |
|---|---|---|
| 포트 vtable·함수 포인터(`port_read_status` 등) | **0** — 연결층 `switch(out.action)` 직접 호출 | 01 §4, 04 §3.3 switch |
| mock 분리 파일 | **0** — in/out 구조체 주입으로 테스트 | 02 §5, 01 §4 |
| 어댑터 2파일(`adapter_normal/_sleep`) | **0** — `tdc_touch.c` 1파일 흡수, 절전은 M 잔류 | 04 §1, 01 §4 |
| L1/L2/L3 추상 명명 | **0** — 파일 분리로만 역할 표현 | 01 §4, 03 §1.1 |

> [!NOTE]
> **연결층 switch가 "추상의 전부"**(01 §2.1)라는 설계가 핵심이다. FSM은 `out.action` enum(5종)을 돌려주고 연결이 `switch`로 I2C 함수를 직접 부른다 — 함수 포인터 0, 간접 호출 0. 04 §3.3 본문이 `case RE_ATI→re_ati_trigger()` 식 직접 호출로 구현돼 과추상 0 확인. [과추상 0건]

### 1.3 함수 작고 단일책임

- 순수 FSM 공개 **3**(`init`·`set_boot_ignore`·`step`) + 내부 static **1**(`stuck_eval`). Rev.1의 보조함수 4→1 축소(02 §1). 게이트(4조건 1식)·롱터치(엣지 1식)는 본문 인라인 3~5줄이라 분리가 오히려 추적 분산 — **명확성 손상 지점(stuck 3단계 anchor)만 분리** 판단 타당. [간결·보존]
- IQS323: 공개 **6+2**(read_status·apply_settings·re_ati·reseed·mclr·is_ati_done + sleep·ulp), 나머지(RDY 윈도우·force comm·레지스터 helper·ack·sensor_setup·beta_power) 전부 static(03 §3 IMPORTANT). 현 헤더 18+ 공개 → 6+2 축소로 표면적 최소화. [간결·보존]
- 연결: `tdc_touch_process()` 한 함수에 init switch→게이팅→read 정규화→fsm_step→로그→액션 switch가 평평하게(04 §3.3) — "호출 흐름이 한 화면"(04 §1 NOTE). [간결·보존]

### 2.2 급소 3종 보존 정밀 검증

> [!IMPORTANT]
> 회귀 0의 급소 3종(02 §1 IMPORTANT)을 정본과 대조:
>
> **(가) read 실패 입력 정규화** — 연결층이 read 실패 시 `read_ok=false, pressed/ati_error/ati_active 전부 false`로 in 채움(02 §2.4, 03 §3.1, 04 §3.4). 이로써 현 FullATI의 캐시 무효화(B99 §2.2 "실패: 캐시 false 무효화")가 **입력 단계에서** 보장되고 전역 캐시 0 = race 0. **순수 FSM이 stale 캐시를 구조적으로 가질 수 없음**(컴파일 강제 + static 0). B99 §6.2 "read 글리치 중 터치 유지 → Re-ATI 누출 차단" 동등. [보존·확정]
>
> **(나) 터치 중 Re-ATI 보류** — 02 §3.1 게이트 첫 조건 `curr_state == NOT_TOUCH`로 경로_2(SW 강제 Re-ATI가 터치를 노터치 학습) 차단. 99 §3.2 CAUTION·검토_2 급소·B99 §3 E5/E5'/E5'' 정합. [보존·확정]
>
> **(다) read hold 동결** — 02 §3 read 실패 N회 이내면 `action=HOLD` 반환하고 게이트·stuck·롱터치 평가 0(B99 §3 E6 "상태 머신 진입조차 안 함"). 02 §3 mermaid C 경로가 즉시 out 채우고 종료. [보존·확정]

### 2.3 이벤트표 전수 동등 (B99 §3 E1~E10·S1~S3)

02 §4 전이·액션표가 B99 §3 이벤트표 13종을 전수 매핑. 본 검증 대조:

- E1~E4(터치 진입/유지/롱터치/해제): 02 §3.3 롱터치 인라인 + stuck anchor 동등. [보존]
- E5/E5'/E5''(드리프트 발행/쿨다운/ATI진행): 02 §3.1 게이트 4조건 + 쿨다운 절대시각화. **쿨다운 카운트(B99 §4.3 s_cooldown=10)→절대시각(until_ms) 변환은 폴링 등간격 전제 하 수학적 동등**(02 §1 IMPORTANT-2). [보존·실측 게이트: read hold 중 시각 흐름 미세차 02 §6-2]
- E6/E7(read 실패 ≤N/>N): 02 §3 HOLD×N 후 NOT_TOUCH 강제. [보존]
- E9/E10(부팅 무시): 02 §3 boot early 반환. **단 E10 해제 판정 `curr!=TOUCH`가 read 실패와 상호작용**(02 §6-5 자인) — §4 봉합 항목.
- S1/S2/S3(stuck 30/60/90초): 02 §3.2 stuck_eval 3단계, MCLR 드레인은 연결층(04 §3.3 20ms+WDT_RESET). [보존]

> [!NOTE]
> **게이트·stuck 배타성**: 게이트는 NOT_TOUCH 전용, stuck은 TOUCH 전용이라 한 step에서 action 충돌 0(B99 §3 CAUTION) → 단일 `action` 필드 안전(02 §2.2 NOTE). 본 검증 동의 — 롱터치는 action이 아닌 `long_touch` 불리언 분리도 정합(현 코드 롱터치=process return true, HW 액션 아님). [보존·확정]

| 격리 | `st`만 매 테스트 재초기화 | 02 §5 NOTE |

> [!NOTE]
> Rev.1 mock 추상 없이 동일 테스트 가능(02 §5 NOTE)이 Rev.2 간결 구조의 핵심 실익이다. 순수 함수라 호스트(PC) 컴파일·실행 가능. 02 §5 대표 케이스 6종(게이트 발행/차단·stuck 3단계·read hold·쿨다운·롱터치 엣지)이 밸리데이션 팀 확장 골격으로 충분. [간결·보존·합격]
>
> 단 **init 상태머신(NONE→MCLR_DONE→READY)은 순수 FSM 밖 연결층**(01 §2.4 CAUTION, 04 §4) — MCLR·auto-ATI·apply_settings가 HW 본질이라 순수화 이득 적고 복잡도만 증가. 순수 FSM은 READY 이후 운용 폴링만. 이 경계는 타당하나 **init 로직 자체는 유닛테스트 비대상**(HW 종속)임을 99가 명시할 것. [보존]

## 4. 축 ④ 누락·회귀·과추상 적출 — [누락·회귀] 봉합 4건

> [!CAUTION]
> 아래 4건은 **제어 동등 자체를 깨지는 않으나** 4노드 병렬 fan-out의 정합 공백·인용 오류로, 99 종합이 단일 확정해야 빌드·구현이 가능하다. 봉합 가능 = 설계 결함 아님.

### 4.1 [봉합-가] 파일명·시그니처 4노드 불일치 (최우선)

병렬 설계라 명명이 갈렸다. 99가 단일 확정 필수:

| 항목 | 01 | 02 | 03 | 04 | 99 확정 필요 |
|---|---|---|---|---|---|
| 순수 FSM 파일 | `tdc_touch_fsm` | **`tdc_touch_logic`** | `tdc_touch_fsm`(참조) | `tdc_touch_fsm` | 1택 |
| IQS323 파일 | `tdc_iqs323` | — | **`tdc_touch_iqs323`** | `tdc_drv_iqs323`(기존 유지) | 1택 |
| FSM step 시그니처 | `step(state,cfg,in,out)` | **`step(state,in,out)` cfg 폐기** | — | `step(state,cfg,in,out)` cfg 주입 | cfg 유무 1택 |
| in 시각 필드 | `tick_ms` | **`now_ms`** | — | `tick_ms` | 명칭 1택 |
| out 필드 수 | 8(led_request 등) | **5(boot_event enum)** | — | 8(prev_state·boot 3불리언) | 5 vs 8 1택 |
| action enum 접두 | `TDC_TOUCH_ACT_*` | `TDC_TOUCH_ACT_*` | — | `TDC_TOUCH_ACTION_*` | 1택 |
| 드라이버 read API | `read_status`(3-out struct) | — | **`read_status`(4-tuple struct)** | `read_status_full`(b*,b*,b*) | struct vs 3포인터 1택 |

> [!IMPORTANT]
> **가장 큰 봉합**: 02는 cfg를 폐기(컴파일 상수 직접 참조)하고 out을 5필드로 줄였는데, **04는 cfg 구조체 주입(`s_fsm_cfg`)·out 8필드(prev_state·boot_released_log·boot_ignore_led_request) 참조**로 작성됐다. 04 §3.3 로그 블록이 `out.prev_state`·`out.boot_released_log`·`out.boot_ignore_led_request`를 직접 읽는데 **02 out엔 이 필드들이 없다**(02가 boot_event enum 1개로 압축, prev_state는 호출측이 보관). → **04는 Rev.1 02 시그니처 가정으로 작성**(04 §7 합의 가정 표가 Rev.1 근거 자인). 99는 02 Rev.2(5필드·cfg 폐기)로 통일하고 04 로그·디스패치를 `out.boot_event`/`out.curr_state` 기반으로 재작성해야 한다. 미봉합 시 **컴파일 에러**. [누락·회귀: 봉합 필수]
>
> 드라이버 read API도 02/03은 `status_t` 구조체 1개 반환, 04는 `read_status_full(b*,b*,b*)` 3포인터 가정 — 99가 1택. 구조체 쪽이 04 §3.4 "read_ok=false면 나머지 false 정규화"를 더 안전히 캡슐화하므로 **struct 4-tuple 권장**(03 §3.1).

### 4.2 [봉합-나] 원점 라인 인용 오류 — `s_last_ati_error/active` 캐시

01 §3·03 §3.1 NOTE·04 §3.4가 "현 원점의 전역 ATI 캐시 `tdc_touch.c:45·46` 삭제"라 인용하나, **현 원점 `T:45·46`은 `s_boot_ready_tick`·`s_boot_5s_warned`이고 `s_last_ati_*` 캐시는 grep 0건**(부존재). 캐시는 FullATI develop 버전(B99 §1 `:521·522`)에만 존재.

- **영향**: 결론("전역 캐시 제거 = race 0")은 **유효**(애초에 현 원점엔 캐시가 없으니 신설 안 하면 됨). 다만 라인 인용이 비-원점이라 혼란. 99는 "현 원점엔 캐시 부존재 → Rev.2가 신설 안 함으로 자연 충족, FullATI 버전이 도입했을 캐시를 입력 정규화로 대체"로 정정 인용. [누락·회귀: 인용 정정 — 동작 무영향]

> [!NOTE]
> 이 패턴(B99/99 FullATI 라인 ↔ 현 원점 라인 혼용)은 4노드가 일관 경고했으나(01 §0·03 §1.2·04 §0) 본문 일부에서 FullATI 라인이 새어 들어옴. 04가 가장 엄격히 원점 라인 통일(§0 표). 99는 **원점 라인 = 신설 대상, FullATI 라인 = 동작 정본**으로 이원 인용 규칙을 명문화할 것.

### 4.3 [봉합-다] boot_ignore 해제 ↔ read 실패 상호작용

02 §6-5가 자인: E10 해제 판정이 `curr != TOUCH`인데 read 실패(E7 강제 NOT_TOUCH) 시 잘못 해제될 수 있다. 현 원점 코드 `T:354~355`는 **`if (got_state && curr_state != TOUCH)`** 로 read 성공 시에만 해제 판정(주석 "read 실패 시 curr_state는 쓰레기 값 → 해제 판정 보류")[확정].

- **봉합**: 02 step 본문 boot_ignore 분기를 **`in->read_ok && curr_state != TOUCH`** 로 작성해야 현 동작 동등. 02 §6-5가 "step 본문에서 보존 확인"이라 했으나 §3 mermaid·본문에 read_ok 가드가 명시 안 됨 → 99/구현이 명문화. [누락·회귀: 명문화 필요]

### 4.4 [봉합-라] 절전 ULP 시각축 — get_state 3-out 무시 정합

04 §6 `get_state`는 `read_status_full(&pressed,&e,&a)` 후 `ati`는 무시(ULP는 게이트 없음). 03은 `read_status`가 struct 반환이라 04의 3포인터 호출과 시그니처 불일치(4.1과 동일 근원). 또 04 §5 절전은 "어댑터화 안 함, M 구조 유지"로 절전 stuck 미구현(B99 §6.2 ULP 2.2초 선제) 유지 — **타당**(요구사항 "절전 미변경"). 단 get_state가 struct API 위에서 동작하도록 99가 시그니처 통일 후 04 §6 wrapper를 struct 기반으로 조정. [보존, 4.1에 흡수]

### 4.5 과추상 재발 적출 — [과추상 0건]

전수 확인 결과 vtable·mock·어댑터·불필요 레이어 **0건 재발**. 오히려 검증 중 발견한 위험은 "과추상"이 아니라 "과축소"(02가 cfg·out 필드를 줄였는데 04가 옛 필드 참조, 4.1) — **간결화 방향의 정합 공백**이지 추상 재발이 아니다. Rev.2 설계 철학("순수 FSM 유지, 주변 추상 포장 제거")은 4노드 전부 일관 준수. [과추상 0건 확정]

## 6. 99 종합 봉합 체크리스트 (구현 전 필수)

1. **[가-최우선]** 파일명 3종·FSM step 시그니처(cfg 유무)·in 필드명(`now_ms`/`tick_ms`)·out 필드 수(5/8)·action enum 접두·드라이버 read API(struct/3포인터)를 **단일 확정**. 02 Rev.2(cfg 폐기·out 5필드·struct read) 권장 — 04 로그/디스패치를 `out.boot_event`·`out.curr_state` 기반으로 재작성.
2. **[다]** 02 step boot_ignore 분기에 **`in->read_ok && curr!=TOUCH`** 가드 명문화(현 `T:355` 동등).
3. **[나]** 원점 라인 = 신설 대상, FullATI 라인 = 동작 정본 이원 인용 규칙 명문화. `s_last_ati_*` 캐시는 "현 원점 부존재 → 신설 안 함" 정정.
4. **[보존 재확인]** 쿨다운 절대시각화 read hold 중 동등성(02 §6-2)·N hold 값(B99 §6.4 #4 t_ati)·Beta 정수 해석 A/B(99 §4.1)는 [실측 게이트]로 구현 후 봉인.
5. **[테스트]** init 상태머신은 유닛테스트 비대상(HW 종속) 명시. 순수 FSM만 호스트 테스트 대상.

> [!NOTE]
> 본 검증은 빌드·실기 없이 정적이다. [실측 게이트] 항목(t_ati·Beta 정수·쿨다운 충분성·SYS_WATCHDOG_RESET 접근성)은 B99 §6.4·99 §6과 동일하게 구현 후 1회 빌드·실기로 봉인된다. 본 노드는 **간결성·제어보존·테스트용이의 설계 차원 합격 + 정합 봉합 4건**까지 확정한다.
