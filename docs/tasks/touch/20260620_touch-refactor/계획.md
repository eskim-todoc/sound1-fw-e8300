# 터치 간결 재작성 — 계획 (Rev.2)

**TL;DR**: 99 종합(Rev.2)의 3파일 간결 구조를 마이그레이션 **P1~P6**으로 구현. 각 단계 빌드 가능(점진, 한 번에 갈아엎지 않음). 공개 API 3종 시그니처 불변(main.c 호출처 0변경). 순수 FSM(`tdc_touch_logic`)은 HW include 0이라 호스트 테스트 가능(밸리데이션 자산), 정량 8종·실기 회귀는 다음주 Eclipse [실측 게이트]. 정본 [`에이전트-로그/Rev2-간결/99_종합_간결구조.md`](에이전트-로그/Rev2-간결/99_종합_간결구조.md).

## 1. 설계 확정 (99 종합 Rev.2)

- **3파일 + 헤더 2**: `tdc_touch_logic.c/.h`(순수 FSM) · `tdc_touch_iqs323.c/.h`(I2C 직접) · `tdc_touch.c/.h`(연결) · `tdc_touch_time.h` · `tdc_touch_config.h`(토글).
- **추상 0**: 포트·vtable·mock·어댑터·L1/L2/L3 명명 전부 폐기.
- **봉합 4건 확정**: 시그니처 단일화·캐시 미신설·boot 가드·get_state wrapper.

## 2. 마이그레이션 Phase

| Phase | 작업 | 산출 | 회귀 | 검증 게이트 |
|---|---|---|---|---|
| **P1** 시간상수 | `tdc_touch_time.h` 신설(ms 이전 + `TDC_TIME_TO_CNT` + 신규 ms) | `tdc_touch_time.h` | 낮음 | 빌드·파생 1:1 등가 |
| **P2** 순수 FSM | `tdc_touch_logic.c/.h`(구조체·enum·공개 3·`stuck_eval`, HW include 0) + 호스트 테스트 골격 | `tdc_touch_logic.c/.h` | 중 | 호스트 컴파일·대표 케이스 7종 |
| **P3** IQS323 슬림화 | `tdc_touch_iqs323.c/.h`(현 드라이버 흡수, 880줄 삭제, Full ATI·단일채널·Beta/Power·status 4-tuple·논블로킹 re_ati/reseed) | `tdc_touch_iqs323.c/.h`(~360줄) | **높음** | 빌드·실보드 부팅 ATI [실측] |
| **P4** 연결 재배선 | `tdc_touch.c` (init 상태머신·게이팅·정규화·`logic_step`·로그/액션 switch). **봉합-가/다 반영** | `tdc_touch.c/.h` | **높음** | 빌드·main.c 0변경 |
| **P5** config 정리 | 시간 수치 제거(time.h 이관)·CRX1/방전 토글 삭제 | `tdc_touch_config.h`(축소) | 낮음 | 빌드·미사용 매크로 0 |
| **P6** 실기 게이트 | 정량 8종 1곳 주입 봉인 + 실기 회귀 | 실측 로그 | [실측] | B99 §3 이벤트 13종 실기 동등 |

> P1·P2는 HW 무관(선행 안전). P3가 최대 삭제(880줄, 실보드 필수). P4가 봉합 적용점. 단일 가드 `TDC_TOUCH_FULL_ATI_ENABLE`로 Full 전환·임계·부팅 Re-ATI·Beta/Power 원자 묶음.

## 3. 회귀 0 검증 (단계 ④-검증)

- **순수 FSM 호스트 테스트**(P2): logic_step 대표 7종(게이트 발행/차단·stuck 3단계·read hold·쿨다운·롱터치·boot+read실패). mock 0, 구조체 주입. (이 환경엔 gcc 없음 → 코드 정합 정적 검증 + 다음주 빌드)
- **서브에이전트 fan-out**: ① 순수성(logic의 HW include 0)·② 봉합 4건 적용·③ 제어방법 8대 보존(B99 대조)·④ 시간 매크로 등가·⑤ main.c 호출처 불변·⑥ 한자 0. 전수 PASS까지 루프.

## 4. [실측 게이트] (다음주 Eclipse — 비범위)

- 정량 8종(Beta 해석·계수 12~24·Power·t_ati 등 99 §8) M6 실기 1회 주입
- 실기 회귀: 부팅·노말·게이트·stuck·절전·롱터치 동작 동등(B99)
- 호스트 테스트 실제 빌드·실행(밸리데이션 팀 또는 빌드 환경)

## 5. 승인 요청 항목

1. **본 계획(P1~P6, 3파일 간결 구조) 승인** 여부
2. **구현 방식**: P1~P6 일괄 구현(코드 정합 정적 검증) vs P3·P4(핫스폿) 후 중간 보고
3. **봉합 4건 확정**(시그니처 단일화 등) 99 권고대로 채택할지
