# 06 매핑 — 정독 발견 × v3 아키텍처 교차

**TL;DR**: 5개 정독 노드 발견을 v3 아키텍처 5대 결정과 교차한 결과, Fixed MULT/COMP·노터치 게이트·RESEED는 자료 전반에서 보강된다. ATI Disabled 상태에서 Reseed가 ATI를 트리거하는지, LTA halt timeout이 ATI Disabled를 우회하는지는 자료 미명시로 잔류한다. Filter Beta 기본값 방치와 Event Mode 미채택이 수정 후보로 신규 확인된다.

---

## 0. 매핑 전제 — v3 아키텍처 5대 결정 요약

| 결정 ID | 내용 |
|---|---|
| D1 | Fixed MULT/COMP write + ATI Mode=Disabled (Auto-ATI 의존성 제거) |
| D2 | 노터치 게이트 후 조건부 Re-ATI 허용 (터치 중 ATI 금지) |
| D3 | RESEED at 절전 진입 (LTA baseline 재동기화) |
| D4 | MCLR 조건부화 — ATI_Error는 변환 정지 안 함, Max Counts 포화 시만 MCLR |
| D5 | CH timeout 비활성화 이중 차단 (D1과 함께 Auto-reATI 경로 완전 봉쇄) |

추가로 코드 수준에서 확인된 구조적 특징:
- D6: 절전 복귀 = WDT 재부팅 (런타임 리셋 복구 루프 없음)
- D7: Streaming mode 운용 추정 (Event Mode 미채택)
- D8: 부팅 시 MCLR → Auto-ATI 1회 수행 → 고정 보상값 write 순서

## 1. D1 — Fixed MULT/COMP + ATI Mode=Disabled

### 1-1. 보강: ATI 2단계 결과값 수동 주입과 동등

**판정: 보강**

[AZD004 §4.4] ATI는 MULT(1단계) 후 COMP(2단계)를 순차 보정한다. MULT 보정 목표는 Base(100~200 카운트), COMP 보정 목표는 Target(500~1000 카운트). 현 펌웨어가 사전 측정된 MULT/COMP를 직접 write하는 것은 이 2단계 결과값을 수동 주입하는 것과 수학적으로 동등하다.

[AZD125 §5.4] "The effect of parasitic capacitance is reduced with the ATI algorithm." — Fixed 보상값 write는 ATI가 수행하는 기생 커패시턴스 보상의 결과를 고정하는 방식이며, 이 자료가 말하는 ATI 역할의 실체를 수동으로 대체한다.

[AZD004 §4.5] ATI가 보정하는 요소(기생 커패시턴스·온도·습도·레이아웃 편차·오버레이 두께)를 공장 측정 시점 기준으로 고정하는 것이 현 v3의 본질이다. 즉, 공장 측정 환경이 기준점이 되며 이후 환경 변화는 LTA가 흡수한다.

### 1-2. 보강: 온도 드리프트 실험 방법론과 동일 접근

**판정: 보강**

[AZD125 §8.2.3] Follow UI 가중치 결정 절차 1단계가 "ATI 완료 후 ATI를 비활성화"한 상태에서 온도를 변화시켜 카운터를 기록하는 것이다. 자료 §8.2.4 예시에서 ATI 후 카운터 1000/700(cnt)을 고정한 채 실험을 진행한다. 이 실험 설정이 v3의 Fixed base 운영 방식과 구조적으로 동일하다. 자료가 온도 특성 측정의 기준 방법으로 v3와 같은 방식을 사용하고 있어, Fixed base 운영이 자료 체계에서 이탈이 아님을 확인한다.

### 1-3. 보강: 예제코드 대비 의도적 이탈 명확화

**판정: 보강 (의도 명확화)**

[Arduino EV_KIT.h] 예제코드의 ATI_SETUP_LSB=0x8C → ATI Mode=Full. 현 드라이버는 0x08(Mode=Disabled)로 교체. 예제코드가 표준 흐름(Re-ATI 후 MULT/COMP 자동 갱신)을 제시하는 가운데, 현 드라이버의 D1 결정은 이 흐름에서 의도적으로 이탈한 것임이 코드 수준에서 명확하다 [노드 05]. 이탈 목적(Auto-reATI 경로 차단)이 D5와 결합하여 완결된다.

## 2. D2 — 노터치 게이트 후 조건부 Re-ATI

### 2-1. 보강: 터치 중 ATI 시도 금지 원칙 직접 일치

**판정: 보강 (가장 강력)**

[AZD004 §12.7] "To avoid constant errors due to interaction with the sensor during an ATI, it is recommended to add a delay between ReATI attempts." 그리고 "터치 중 ATI 시도 시 지속적 오류 발생 가능"을 명시한다. v3의 노터치 게이트(터치가 없는 상태가 확인된 순간에만 Re-ATI 허용)는 이 자료 경고에 정확히 대응하는 구현이다.

[AZD125 §8.1] "Our ICs can track the drift in temperature and automatically tune the device to maintain sensitivity **when the device is not in touch**." — 자료가 드리프트 추적·조정의 선행 조건으로 "노터치 상태"를 명시한다. v3 노터치 게이트의 이론적 근거와 정합한다.

[AZD004 §12.7] 3회 재시도 초과 시 "Produce Error: Possible Hardware Issue" 처리를 규정한다. 터치 중 ATI를 방치하면 이 3회 초과 경로로 빠질 수 있어, 노터치 게이트가 이 오류 경로 자체를 사전에 차단하는 역할도 수행한다.

### 2-2. 보강: 크래들 뚜껑 닫힘 구간이 안전한 Re-ATI 구간

**판정: 보강**

[00_오케스트레이터] 크래들 뚜껑 닫힘 = 터치 폴링 완전 중단(노터치 구간). 이 구간은 [AZD004 §12.7]에서 요구하는 "노터치 상태"가 물리적으로 보장되는 구간이다. 뚜껑 닫힘 감지 후 Re-ATI를 허용하는 v3 구조는 자료의 "노터치 확인 후 ATI" 원칙을 크래들 이벤트에 자연스럽게 적용한 것으로 해석된다.

## 3. D3 — RESEED at 절전 진입

### 3-1. 보강: 자료가 명시적으로 허용하는 동작

**판정: 보강**

[AZD004 §5.3] "LTA registers are read-only and values are seeded after ATI completion or upon an **explicit reseed command**." — 명시적 Reseed 명령은 자료가 허용하는 정상 LTA 조작법이다. 절전 진입 시 RESEED를 사용하는 현 구조는 이 허용 범위 안에 있다.

[User Guide §3.5.4] Reseed 명령의 의미는 "LTA를 현재 counts 값으로 강제 동기화"다. 절전 진입 시 환경 변화를 흡수하기 위해 LTA baseline을 현재 노터치 상태의 counts로 맞추는 것은, 자료의 Reseed 용도(드리프트 흡수)와 정합한다.

### 3-2. 미확인 잔류: Reseed가 ATI Disabled 상태에서도 ATI를 트리거하는지

**판정: 미확인 (자료 미명시)**

[User Guide §3.5.4] "Note that the Reseed command **may trigger an ATI routine** if the resulting LTA is significantly different from the target." 이 경고는 ATI 모드 조건을 명시하지 않는다. ATI Mode=Disabled + CH timeout Disable 이중 차단이 Reseed 유발 ATI를 실제로 막는지 여부는 [자료 미명시].

현 펌웨어의 이중 차단 구조(D1 + D5)가 이 경로를 차단하는 설계 의도임은 명확하나, 자료에서 ATI Mode=Disabled 상태에서의 Reseed 동작이 명시적으로 검증된 것은 아니다. 검증 항목으로 유지.

## 4. D4 — MCLR 조건부화 (ATI_Error vs Max Counts 포화 구분)

### 4-1. 보강: ATI_Error는 conversion 정지 안 함 — Fixed write로 무해화

**판정: 보강**

[20260618 직전 확정] ATI_Error는 conversion 정지를 유발하지 않는다. Fixed MULT/COMP write(D1)가 완료된 상태에서 ATI_Error 플래그는 존재해도 실제 측정 동작에 영향이 없다.

[User Guide §3.6.1] ATI Error = "The IQS323 failed to calibrate one or more channels correctly." 이 비트는 상태 보고일 뿐 conversion을 정지시키지 않는다는 것이 [20260618] 확정 사항이며, 5개 정독 노드 중 이 확정에 반증하는 자료는 없다.

[AZD004 §4.4] ATI 실패의 물리적 경계값(MULT/COMP 포화 한계)은 [자료 미명시]. Max Counts 포화가 conversion 정지를 유발하는 별도 조건이라는 것도 AZD004/AZD125/User Guide 어디에서도 명시 확인되지 않아 [자료 미명시] 상태 유지. MCLR 조건부화(포화 감지 시만 MCLR) 방향은 자료에서 반증되지 않았으나, 포화 경계 정량은 datasheet에서 별도 확인 필요.

### 4-2. 보강: 부팅 시 MCLR → Auto-ATI 순서가 자료 권고와 일치

**판정: 보강**

[User Guide §14 펌웨어 시퀀스 대조 표, 노드 04] 자료 권고 순서는 "전원 인가 → IC Auto-ATI → ACK Reset → 설정 write". 현 펌웨어는 "MCLR → Auto-ATI 완료 대기 → ACK Reset → 설정 write" 순서다. MCLR 하드 리셋은 전원 인가와 동등한 full reset이므로 자료 권고 순서와 정합한다.

## 5. D5 — CH timeout 비활성화 이중 차단

### 5-1. 보강: Auto-reATI 트리거 경로 봉쇄의 자료 근거

**판정: 보강**

[User Guide §4.1] Channel Event Timeout은 "stuck-touch 시 자동 re-ATI를 트리거하는 타이머"다. D1(ATI Mode=Disabled)만으로는 CH timeout 경유 자동 re-ATI가 차단되는지 자료 상 불명확하다. D5(CH timeout 비활성화)를 이중으로 추가한 것은 이 불명확성을 방어한 설계다.

[Arduino 예제, 노드 05] EV_KIT.h 기본 설정에 CH timeout 비활성화가 없다. 현 드라이버가 `write_register(SYSTEM_CONTROL, 0x00, 0x07)`로 MSB[2:0]=111 추가 설정한 것은 자료와 예제 모두에서 명시되지 않은 추가 방어다. 자료가 이 조합을 명시 권고하지는 않으나, 반증도 없다.

---

## 6. D6 — 절전 복귀 = WDT 재부팅

### 6-1. 보강: 예제 대비 단순·안전한 대안

**판정: 보강 (단순화 정당성 확인)**

[Arduino 예제, 노드 05] 예제는 STATE_CHECK_RESET에서 런타임 리셋 감지 시 STATE_START로 복귀하는 전체 재초기화 FSM 루프를 갖는다. 현 드라이버는 WDT 재부팅으로 대체한다. 임베디드 단일채널 환경에서 WDT 재부팅은 "MCLR과 동등한 full reset 후 초기화 시퀀스 재실행"이므로, 자료 권고(전원 인가 → Auto-ATI → ACK Reset → 설정 write)를 자연스럽게 재실행한다. 예제의 FSM 루프보다 단순하고 상태 오염 우려가 없어 단일채널 환경에서 더 안전하다.

## 7. D7 — Streaming Mode 운용 (Event Mode 미채택)

### 7-1. 수정 후보: Event Mode 미채택은 잠재적 튜닝 포인트

**판정: 수정 후보**

[Arduino 예제, 노드 05] 예제는 init 마지막에 setEventMode()로 EVENT_MODE_BIT를 활성화해 "이벤트 발생 시에만 RDY를 내리는" 이벤트 모드로 전환한다. 현 드라이버는 이 단계가 없어 주기적 RDY 발생(streaming mode)으로 동작하는 것으로 추정된다.

[User Guide §4.1, 노드 04] 기본값에서 모든 이벤트 비트가 비활성화되어 있으며, 현 펌웨어는 touch·ati_error·ati_event를 명시적으로 활성화한다. 이벤트 비트는 활성화했으나 Event Mode 자체(SYSTEM_CONTROL EVENT_MODE_BIT)는 미설정이다.

**영향**: Event Mode 미채택 → streaming mode에서 주기적 RDY 발생 → 터치 이벤트 없는 구간에서도 불필요한 I2C 통신 윈도우 발생 → 노이즈·전력 소비 증가 가능. v3 아키텍처에서 직접적 오류는 아니나, 전력 효율·노이즈 측면 개선 여지가 있다.

**수정 필요 여부**: 현재 polling 구조에서 Event Mode 활성화는 구조 변경을 수반하므로 즉시 필수 변경은 아니다. 하지만 v3 이후 최적화 검토 항목으로 기록한다.

## 8. D8 — Filter Beta 기본값 방치

### 8-1. 수정 후보: LTA Filter Beta 튜닝 포인트 신규 확인

**판정: 수정 후보**

[User Guide §4.7, 노드 04] Filter Beta 설정은 counts filter beta, LTA filter beta, LTA fast filter beta, fast filter band 4개 파라미터를 Normal Power / ULP 각각 별도 설정한다. 현 펌웨어는 Filter Beta 레지스터를 명시적으로 write하지 않아 IC 기본값을 그대로 사용한다.

[Arduino EV_KIT.h, 노드 05] 예제코드의 기본값: NP_LTA=5, LP_LTA=5, NP_COUNTS=2, LP_COUNTS=2, NP_LTA_FAST=3, FAST_FILTER_BAND=0x001E. 현 드라이버가 사용 중인 IC 기본값이 이 예제값과 동일한지 여부는 [자료 미명시] — IC 초기값과 예제 설정값이 다를 수 있다.

[AZD004 §5.3] LTA filter beta는 드리프트 추적 속도의 핵심 파라미터. beta=6~10이 전형 LTA 범위다. 예제의 NP_LTA=5는 이 범위 경계에 있다.

**영향**: LTA beta가 너무 낮으면 LTA가 빠르게 추적해 터치 신호를 감쇠시킨다. 너무 높으면 환경 드리프트에 LTA가 느리게 반응해 오탐 위험. IC 기본값과 예제값·권고 범위를 확인해 현 환경에 최적화할 여지가 있다.

## 9. Phase-1 버그 2건과 자료의 관계

### 9-1. 보강: Phase-1 버그 2건 원인과 자료의 간접 연결

**판정: 보강 (사후 원인 분석 지지)**

Phase-1 버그 2건(크래들 뚜껑 감지 관련, 약 절전 모드 진입 관련)의 공통 구조는 "Race condition에 의한 상태 오염"이다.

[AZD004 §12.7] 터치 중 ATI 시도 → 지속적 오류 발생 가능 경고는, 상태가 확정되지 않은 구간에서 캘리브레이션을 시도하면 부정확한 결과를 초래한다는 원리다. 크래들 Race 제거(v3 5층 방어 중 마지막)는 이 원리의 하드웨어 이벤트 버전으로 해석된다.

[AZD004 §5.3] LTA halt timeout 후 RESEED + 자동 Re-ATI 트리거 가능 경로는, 절전 진입/복귀 타이밍에서 LTA 상태가 모호한 구간에 자동 ATI가 발동할 수 있음을 시사한다. Phase-1의 약 절전 모드 진입 버그가 이 구간에서 발생했을 가능성을 자료가 간접 지지한다.

## 10. 미해결 3항목 매핑 기여 요약

### 미해결_1: ATI 실패 정확 조건·경계

5노드 교차 결과:
- [보강] 터치 중 ATI = 지속적 오류 [AZD004 §12.7] → D2 노터치 게이트로 이 경로 차단
- [보강] 3회 재시도 초과 = Hardware Error [AZD004 §12.7] → v3는 ATI 자체를 Disabled로 이 카운터를 의미 없게 함
- [자료 미명시 잔류] MULT/COMP 물리적 포화 한계값 — AZD004/AZD125/User Guide/예제코드 어디에도 정량값 없음. 데이터시트에서 별도 확인 필요.
- [자료 미명시 잔류] ATI Mode=Disabled 상태에서 Reseed가 ATI를 트리거하는지 여부 — 실제 IC 동작 테스트 또는 데이터시트 확인 필요.

### 미해결_2: 환경 드리프트 정량

5노드 교차 결과:
- [확인] 온도 드리프트 방향: 온도 상승 시 카운터 감소 [AZD125 §8.2.4]
- [확인] 온도 드리프트 규모 예시: 25→50°C에서 센서 채널 -450 cnt (ATI 후 1000 cnt 기준) [AZD125 §8.2.4]
- [추정] 선형 추정 시 약 -18 cnt/°C (센서 채널), -12 cnt/°C (레퍼런스 채널) [AZD125 §8.2.4 수치에서 선형 가정]
- [자료 미명시 잔류] 배터리 잔량·들고 있는 상태에서의 카운터 변화 정량 — 정성적 메커니즘(C3 감소)만 있음
- [자료 미명시 잔류] 습도 정량 — 방향(증가 = 오탐)만 확인, 수치 없음

### 미해결_3: 드리프트 자동보정 (Re-ATI 외)

5노드 교차 결과:
- [확인] LTA IIR(beta filter)이 1차 자동보정 메커니즘 [AZD004 §5.3]
- [확인] Follow UI(레퍼런스 채널 기반 LTA 추종)가 Re-ATI 없는 드리프트 보정 메커니즘이나, 우리 회로(레퍼런스 전극 없음, C52 DC-block)에 즉시 적용 불가 [AZD125 §8.2, 노드 02 + 03]
- [확인] 결론: Re-ATI(D2 노터치 게이트 조건부)가 현 회로에서 유일한 능동 드리프트 재보정 수단
- [수정 후보] LTA filter beta 튜닝으로 수동 드리프트 추적 속도 조정 가능 — 현 기본값 방치는 최적화 기회 미활용
- [자료 미명시 잔류] ATI Disabled 상태에서 LTA halt timeout이 자동 Re-ATI를 트리거하는지 여부

## 12. v3 아키텍처 신규 감사 항목 (자료 대조 후 추가)

자료 정독 결과, v3 아키텍처에서 기존에 확인되지 않았던 감사 항목이 신규로 도출되었다:

1. **CRX1 더미채널 이격 거리 감사**: [AZD125 §3.2.2] 비활성 전극이 GND 구동되면 터치 전극과 5mm 이상 이격 규칙이 동일 적용된다. CRX1 더미채널이 비활성 시 GND 구동 여부와 터치 전극과의 실제 물리 간격 확인 필요.

2. **Filter Beta 레지스터 설정 검토**: IC 기본값과 예제값, AZD004 권고 범위(LTA beta 6~10) 대조 후 적정값 write 여부 결정 필요.

3. **SNR ≥ 5 기준 현 임계값 검증**: [AZD125 §10.1] 터치 임계값 = 노이즈 밴드 × 5 이상. 현 펌웨어의 Touch Threshold(touch_settings 내 설정값)가 이 기준을 충족하는지 측정값 기반 검증 필요.

4. **Event Mode 채택 여부 결정**: streaming mode 대비 불필요한 RDY 억제 효과. 폴링 구조 변경 비용 대비 효익 평가 필요.

5. **오버레이-전극 밀착 확인**: [AZD125 §3.1.5] 1mm 공기 틈이 8mm 유리 오버레이와 동등 민감도 저하. 오버레이 밀착 상태와 재질·두께 현황 파악 필요.
