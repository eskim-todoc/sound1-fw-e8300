# 99 종합 — 적용 문서 설계 · v3 아키텍처 반영안

**TL;DR**: 외부 자료 4종 정독·매핑·adversarial 검증 전체를 통합한다. v3 아키텍처 5대 결정(D1~D5)은 전부 보강 판정이며 반증 없음. 수정이 필요한 것은 아키텍처 결정 자체가 아니라 구현 세부 2건(Filter Beta 기본값 방치·수분 오탐 방향 서술 오류)이다. 미해결 3항목 중 물리적 ATI 포화 한계와 ATI Disabled 상태에서 Reseed→ATI 트리거 차단 효과는 자료 미명시로 잔류, IQS323 데이터시트 확인 필요.

### §1. 개요 — IQS323 터치 센서 운영 방식

**1.1 제품 구성**

- IQS323 ProxFusion IC, 자기 커패시턴스 방식
- 사용 채널: CRX0(터치 전극), CRX1(ESD 더미채널, 내부 CalCap 사용 — 외부 환경 미감지)
- 회로 특수성: C52 100nF DC-block(CRX1 핀 직렬), 크래들 뚜껑 닫힘=터치 폴링 완전 중단

**1.2 카운트(Counts) 정의와 터치 방향**

- 카운트 = 내부 기준 커패시터(Cs)를 채우는 데 필요한 전하 이동 사이클 수 [AZD004 §2]
- 자기 커패시턴스: 터치(전도체 접촉) 시 카운트 감소 [AZD004 §3.1]
- 판정 방향: LTA보다 카운트가 낮아지면 터치 — 현 펌웨어 `(LTA-Counts)×256/LTA` 공식과 정합

**1.3 v3 아키텍처 5층 방어 요약**

```
[공장 보정] Fixed MULT/COMP write → ATI 자동 의존성 제거
[노터치 확인] 터치 없는 구간만 Re-ATI 허용 (크래들 닫힘·노터치 폴링 확인)
[자동 차단] ATI Mode=Disabled + CH timeout 비활성 이중 차단
[절전 재동기] RESEED at 절전 진입 (LTA baseline 강제 동기화)
[장애 복구] WDT 재부팅 → 부팅 시퀀스 전체 재실행
```

### §2. 신호 처리 — MULT/COMP/ATI 구조

**2.1 ATI 2단계 구조** [AZD004 §4.4]

| 단계 | 대상 | 목표 값 |
|---|---|---|
| 1단계 Multiplier Calibration | Coarse+Fine MULT | Base 100~200 cnt (전형) |
| 2단계 Compensation Calibration | COMP | Target 500~1000 cnt (전형) |

- 민감도 공식: `민감도 ∝ Target / Base` [AZD004 §4.4]
- 민감도 상승 시 카운트 노이즈도 증가하는 트레이드오프 존재 [AZD004 §4.4]

**2.2 Fixed MULT/COMP 운영 근거**

현 펌웨어가 사전 측정된 MULT/COMP를 직접 write하는 방식은 ATI 2단계 결과값을 수동 주입하는 것과 수학적으로 동등하다 [AZD004 §4.4]. EV-Kit 예제의 ATI 보상값(S0 COARSE=0x21 등)을 직접 차용하는 것은 **적용 불가** — 우리 회로(C52+더미채널+단일버튼)의 기생 커패시턴스 프로파일이 EV-Kit(3버튼+슬라이더, C52 없음)과 다르므로 보드 변종별 실측값 사용이 필수다 [09_검증 §1-7].

**2.3 ATI 실패 처리 권고** [AZD004 §12.7]

- 3회 재시도 후에도 ATI Error: "Produce Error: Possible Hardware Issue" 처리 (소프트웨어 권고 절차)
- Re-ATI 재시도 사이에 지연을 추가해 interaction 중 constant errors를 방지
- 현 v3: ATI Mode=Disabled로 자동 ATI 경로 자체를 비활성화하여 이 오류 경로가 부팅 시 1회 Auto-ATI 단계에만 해당하도록 제한

### §3. LTA 드리프트 보정 메커니즘

**3.1 LTA IIR 필터 — 1차 자동보정** [AZD004 §5.1~§5.3]

- LTA(Long Term Average) = IIR 필터로 환경 드리프트를 느리게 추적
- 필터 공식: `yk = (1 - 1/2^β)×y(k-1) + xk/2^β`
- Beta 범위: Counts 필터 0~4(빠른 응답), LTA 필터 6~10(느린 환경 추적) [AZD004 §5.2~§5.3]
- 노터치 상태에서 자동 추적, 인터치 상태에서 LTA halt

**3.2 LTA halt timeout 처리** [AZD004 §5.3]

- stuck-touch 시 halt 최대 시간(halt period) 이후 RESEED(LTA를 현재 counts로 강제 동기화) 수행
- 이후 자동 Re-ATI를 트리거할 수 있음 [조건부 — 원문: "may also automatically trigger a re-ATI"]
- 현 펌웨어: ATI Mode=Disabled + CH timeout 비활성화 이중 차단으로 이 자동 트리거 경로를 의도적으로 봉쇄

**3.3 Reseed 명령 허용 동작** [AZD004 §5.3, User Guide §3.5.4]

- 명시적 Reseed 명령은 자료에서 허용하는 정상 LTA 조작법
- Reseed = LTA를 현재 counts 값으로 강제 동기화
- 단, LTA가 ATI Target과 크게 다를 경우 ATI 자동 트리거 가능 [조건부 — 원문: "may trigger"]
- ATI Mode=Disabled 상태에서 Reseed 후 ATI 자동 트리거 차단 효과는 [자료 미명시] — 데이터시트 확인 필요

**3.4 Follow UI (온도 자동보정) — 현 하드웨어 적용 불가** [AZD125 §8.2.1]

- 인터치 상태에서 레퍼런스 채널 변화 × 가중치(Wf)로 LTA를 추종시키는 드리프트 자동보정 기능
- 별도 레퍼런스 전극(0.2mm 트레이스) + 별도 Cx 핀 + 별도 채널 필수 [AZD125 §8.2.1]
- **현 회로 [적용 불가]**: CRX1이 내부 CalCap 더미채널(외부 환경 미감지) + C52 100nF DC-block 복합 제약
- 결론: 인터치 중 드리프트 보정은 노터치 게이트 조건부 Re-ATI가 현 하드웨어의 유일한 능동 수단

### §4. 환경 드리프트 정량 참고

**4.1 온도 드리프트 (유일하게 정량 자료 존재)** [AZD125 §8.2.4]

- 실험 조건: ATI 후 카운터 고정 + ATI 비활성화 상태에서 FR-4 PCB 워치 기기 25→50°C 온도 변화
- 센서 채널(CH0): 1000 → 550 cnt (-450 cnt)
- 레퍼런스 채널(CH1): 700 → 400 cnt (-300 cnt)
- 선형 추정: 약 -18 cnt/°C(센서), -12 cnt/°C(레퍼런스) [추정, 25°C 구간 선형 가정]
- **방향**: 온도 상승 → 카운트 감소 = 터치 방향 → 고온에서 오탐보다 **미탐(민감도 저하) 위험**이 더 큼

> [!NOTE]
> 이 수치는 ATI 후 1000 cnt 기준 예시이며, 우리 고정 보상값 기준 실제 카운트가 다르면 절댓값도 다르다. 방향(감소)은 자기 커패시턴스 방식에서 공통.

**4.2 배터리 구동 / 들고 있는 상태** [AZD125 §5.1]

- C1(손가락↔전극 <10pF)·C2(몸↔지구 >100pF)·C3(모듈↔지구) 직렬 합성
- 배터리 기기에서 C3 감소 → C1 변화 감지량 감소 → 터치 delta 감소 (민감도 저하)
- 전극 주변 시스템 GND 플레인이 있으면 C3 부족을 부분 보완 [AZD125 §5.3]
- 정량 수치: [자료 미명시] — 방향만 확인

**4.3 수분 / 습도** [AZD125 §9]

- 수분이 전도체처럼 동작 → 자기 커패시턴스에서 카운트 감소 → **터치 오탐(미감지 방향이 아니라 오탐 방향)** 유발
- 변화 속도 빠름 → LTA 추종 불가, 터치와 유사하게 인식됨
- 정량 수치: [자료 미명시]

> [!CAUTION]
> 수분 오탐 방향 주의: 자기 커패시턴스 방식에서 전도체(수분) 접촉은 카운트 **감소** 방향 — 즉 수분이 터치로 오탐된다. "카운트 급증" 표현은 자기 커패시턴스 동작과 반대로 잘못된 서술이다 [08_검증 §3 의심항목15].

**4.4 SNR 기준** [AZD125 §10.1]

| 기능 | 최소 SNR | 임계값 최소(노이즈 밴드 4 cnt 기준) |
|---|---|---|
| 비임계(근접) | ≥ 3 | 12 cnt |
| 임계(터치) | ≥ 5 | 20 cnt (전형 신호 최소 25 cnt) |

- Touch Threshold는 raw counts 차이가 아닌 LTA 대비 비율 계수(delta×256/LTA)로 동작
- SNR 기준(cnt 단위)을 계수 단위로 직접 적용하는 것은 변환식 확인 필요 [09_검증 §1-9 함정_3]

### §5. 부팅·초기화 시퀀스

**현 드라이버 순서 (자료 권고와 정합)** [User Guide §3.5.1, AZD004 §12.7]

```
MCLR (하드 리셋) → 전원 인가 동등
→ IC Auto-ATI 완료 대기 (WAIT_FOR_ATI)
→ ACK Reset (SHOW_RESET_BIT 응답)
→ 설정 write: Fixed MULT/COMP + ATI Mode=Disabled + CH timeout 비활성화 + 이벤트 비트 설정
→ 정상 폴링 시작
```

자료 권고 순서: "전원 인가 → IC Auto-ATI → ACK Reset → 설정 write" [User Guide §3.5.1]. 현 드라이버는 정합.

**부팅 시 ATI Error 처리** [20260618 직전 확정]

- ATI_Error = "IQS323 failed to calibrate one or more channels correctly" [User Guide §3.6.1]
- ATI Error 비트는 상태 보고 플래그이며 conversion 정지를 유발하지 않음
- Fixed MULT/COMP write가 완료된 이후에는 ATI_Error 플래그가 있어도 실제 측정 동작에 영향 없음
- Max Counts 포화만 conversion 정지 → MCLR 필요 → MCLR 조건부화 방향으로 대응

### §6. 절전·복귀 시퀀스

**절전 진입**

```
Touch Threshold = 255 (최둔감, 오탐 방지)
→ Prox Threshold 설정
→ RESEED (LTA를 현재 counts로 강제 동기화) [User Guide §3.5.4]
→ Power Mode 전환
```

**절전 복귀**: WDT 재부팅 → 부팅 시퀀스 전체 재실행. 런타임 FSM 복귀 루프 없음.

> [!WARNING]
> Reseed 후 ATI 자동 트리거 위험: `User Guide §3.5.4`는 Reseed가 ATI를 트리거할 수 있다고 명시한다(조건부 "may trigger"). ATI Mode=Disabled 상태에서 IC 하드웨어 레벨로 이 경로가 완전히 차단되는지는 [자료 미명시]. 현재 ATI Mode=Disabled + CH timeout 비활성 이중 차단이 설계 의도이나, 데이터시트 Disabled 모드 Reseed 연동 명세 확인 필요.

### §7. 통신 윈도우 운영

**Force Communication** [AZD004 §12.6]

- 0xFF 주소에 write → IQS323이 RDY LOW(통신 윈도우 열림)
- Event Mode에서는 이벤트 외 구간에 설정 read/write 시 이 방법으로 윈도우 강제 개방

**현 드라이버 운영 모드**: Streaming Mode (주기적 RDY 발생) [추정]

- Event Mode 미채택 — Arduino 예제 init 마지막 `setEventMode()` 단계가 현 드라이버에 없음
- Streaming mode에서 터치 이벤트 없는 구간에서도 주기적 RDY 발생 → 불필요한 I2C 통신 윈도우 개방 가능
- Event Mode 채택 시 전력 절감·노이즈 억제 이점 있으나 상위 레이어 polling 구조 변경 필요 [개선 여지, 단기 우선순위 낮음]

## 2. 개발 적용 체크리스트

### 2.1 레지스터 설정 (필수 — 현 드라이버 적용 사항)

| 설정 항목 | 값 | 근거 | 현 상태 |
|---|---|---|---|
| ATI Mode | Disabled (0x08 ATI_SETUP_LSB bits[2:0]=000) | D1 — Auto-ATI 경로 차단 | 적용됨 |
| CH timeout | 비활성 (SYSTEM_CONTROL MSB bit[2:0]=111) | D5 — stuck-touch Re-ATI 이중 차단 | 적용됨 |
| MULT/COMP | 보드 변종별 실측값 고정 write | D1 — EV-Kit 값 직접 차용 불가 | 적용됨 |
| 터치 임계값 | TDC_DRV_IQS323_TOUCH_THRESHOLD (별도 정의) | EV-Kit 값 직접 차용 불가 | 적용됨 |
| 이벤트 비트 | touch·ati_error·ati_event 활성화 | 상태 감지 필요 | 적용됨 |

### 2.2 레지스터 설정 (검증·조정 필요)

| 설정 항목 | 현 상태 | 위험 | 조치 |
|---|---|---|---|
| Filter Beta | IC reset 기본값 사용 (명시 write 없음) | IC 기본값이 EV-Kit 값(NP_LTA=5, NP_COUNTS=2)과 다를 경우 필터 특성 이탈 가능 [09 함정_2] | IQS323 데이터시트에서 reset 기본값 확인 → 다를 경우 명시 write |
| Event Mode | 미채택 (streaming mode 추정) | 불필요한 주기적 RDY로 소비 전류·노이즈 증가 가능 | 단기 낮음 — 최적화 검토 항목으로 유지 |

### 2.3 초기화 시퀀스 체크

- [ ] MCLR → Auto-ATI 완료 대기 → ACK Reset → 설정 write 순서 준수
- [ ] Fixed MULT/COMP write 시점: ACK Reset 이후
- [ ] ATI Mode=Disabled write: 고정 보상값 write와 동일 단계
- [ ] CH timeout 비활성화: SYSTEM_CONTROL MSB bit[2:0]=111 확인
- [ ] ATI_Error 비트 확인 후 무해화(Fixed write로 대체)

### 2.4 절전·복귀 시퀀스 체크

- [ ] 절전 진입 전 Touch Threshold=255(최둔감) write
- [ ] RESEED 명령 전송 (LTA 재동기화)

## 3. 미해결 3항목 최종 결론

### 미해결_1: ATI가 실패하는 정확한 조건·경계

**자료 근거 확보된 간접 결론:**

- 터치(사용자 상호작용) 중 ATI 시도 시 지속 오류 발생 가능 — 원문: "interaction with the sensor during an ATI" 시 "constant errors" 유발 가능, ReATI 재시도 간 delay 추가 권고 [AZD004 §12.7]
- 3회 ReATI 초과 시 Hardware Error 처리 권고 (소프트웨어 레벨 권고 절차, IC 강제 아님) [AZD004 §12.7]
- ATI 자동 트리거 경로 2개: stuck-touch LTA halt timeout (조건부 "may" Re-ATI) [AZD004 §5.3], Reseed 후 LTA가 Target과 크게 다를 경우 (조건부 "may trigger") [User Guide §3.5.4]

**실용적 치환:**

현 펌웨어(ATI Mode=Disabled)에서 ATI 실패는 부팅 시 1회 Auto-ATI 단계에만 해당. 이후 자동 ATI 경로는 이중 차단으로 봉쇄됨. 따라서 "ATI 실패 조건 관리" = "부팅 시 Max Counts 포화 감지 후 MCLR 조건부화"로 실용적 치환 가능.

**자료 미명시 — 데이터시트 확인 필요:**

- MULT/COMP 물리적 포화 한계값(Max Counts 발생 정확한 경계) — 외부 자료 4종 어디에도 정량값 없음
- ATI Mode=Disabled 상태에서 Reseed 후 ATI 자동 트리거가 IC 하드웨어 레벨에서 완전히 차단되는지 — IC reset 기본값 및 Disabled 모드 동작 명세 확인 필요

### 미해결_2: 환경 드리프트(온도·배터리·터치 접촉) 카운터 변화 정량

| 환경 요인 | 결론 | 정량 | 자료 근거 |
|---|---|---|---|
| 온도 드리프트 방향 | **확정** — 온도 상승 = 카운트 감소 = 고온에서 미탐 위험 | 25→50°C 기준 약 -18 cnt/°C(센서, 추정) | [AZD125 §8.2.4] |
| 온도 드리프트 규모 | **예시 확보** — ATI 후 1000 cnt 기준 | -450 cnt (25°C 범위) | [AZD125 §8.2.4] |
| 배터리 구동 들고 있음 | **방향만 확인** — C3 감소 → delta 감소 | [자료 미명시] | [AZD125 §5.1, 정성] |
| 수분·습도 | **방향 확정** — 카운트 감소 = 터치 오탐 방향 | [자료 미명시] | [AZD125 §9 + AZD004 §3.1] |

> [!NOTE]
> 수분 방향 수정: 수분이 전도체처럼 작용하면 자기 커패시턴스에서 카운트 **감소** 방향으로 터치 오탐이 발생한다. "카운트 급증"이라는 서술은 자기 커패시턴스 동작 방향과 반대로 잘못된 표현이다 [08_검증 §7.1 치명적 오류].

**잔여 과제**: 우리 회로의 고정 보상값 기준 실제 카운트 범위에서 온도 드리프트 실측 필요. SNR ≥ 5 기준(20 cnt)과 잔여 드리프트 크기 비교 검증 필요.

### 미해결_3: 드리프트 자동보정 (Re-ATI 외) 메커니즘 유무

| 메커니즘 | 작동 조건 | 현 회로 적용 | 결론 |
|---|---|---|---|
| LTA IIR 추적 | 노터치 상태에서 자동 (beta 6~10) | **현재 동작 중** — beta 기본값, 튜닝 가능 | 노터치 구간 1차 자동보정 |
| Follow UI | 인터치 중, 별도 레퍼런스 전극 필수 | **적용 불가** (더미채널 + DC-block) | 하드웨어 개정 없이 불가 |
| LTA halt timeout Re-ATI | stuck-touch 일정 시간 후 자동 (조건부 "may") | **의도적 비활성** (이중 차단) | 봉쇄됨 |
| Reseed (수동) | 명시 명령 (절전 진입 시) | **현재 사용 중** | LTA 재동기화 수단 |
| Filter Beta 튜닝 | 파라미터 조정으로 추적 속도 변경 | **기본값 사용, 튜닝 가능** | 개선 포인트 |

**최종 결론**: Re-ATI 외 자동보정 메커니즘은 존재하나(LTA IIR 추적), 인터치 중 보정 수단인 Follow UI는 현 하드웨어에서 즉시 적용 불가. 따라서 **노터치 게이트 조건부 Re-ATI가 현 하드웨어에서 드리프트를 해소하는 유일한 능동 수단**이다. 이는 "when the device is not in touch" 조건에서만 드리프트 자동 추종을 허용하는 자료 원칙 [AZD125 §8.1]과 정확히 일치한다.

**잔여 미확인**: ATI Mode=Disabled 상태에서 LTA halt timeout이 "may" Re-ATI를 실제로 트리거하는지 여부 [자료 미명시]. Filter Beta IC reset 기본값과 EV-Kit 설정값(NP_LTA=5) 동일 여부 [자료 미명시].

### 4.2 아키텍처 수준 수정 불필요 — 구현 세부 수정 2건

v3 아키텍처(D1~D5)의 결정 자체는 수정 필요 없음. 레지스터 설정 수준의 조정 2건만 필요:

**수정_1: 수분 오탐 방향 서술 수정** (문서·주석 수정, 코드 무관)

- 기존 서술: "수분이 카운트 급증(터치 오탐) 유발"
- 수정 서술: "수분이 카운트 감소(터치 오탐) 유발" — 자기 커패시턴스에서 전도체 접촉은 카운트 감소 방향 [AZD004 §3.1]

**수정_2: LTA halt timeout Re-ATI 조건부 표현 수정** (문서·주석 수정, 코드 무관)

- 기존 서술: "LTA halt timeout 후 자동 Re-ATI 트리거"
- 수정 서술: "LTA halt timeout 후 자동 Re-ATI가 트리거될 수 있음 (항상 보장 아님)" — 원문: "may also automatically trigger a re-ATI" [AZD004 §5.3]

### 4.3 신규 확인된 개선 포인트 (즉시 필수 아님)

| 항목 | 내용 | 우선순위 |
|---|---|---|
| Filter Beta 검증 | IC reset 기본값 vs EV-Kit 값(NP_LTA=5) 동일 여부 데이터시트 확인. 다를 경우 명시 write 추가 | 중간 — 필터 특성 이탈 가능성 |
| Event Mode 채택 | streaming → event mode 전환으로 소비 전류·노이즈 절감. 상위 레이어 구조 변경 수반 | 낮음 — 최적화 항목 |
| SNR ≥ 5 기준 검증 | 현 Touch Threshold가 노이즈 밴드 × 5 기준 충족하는지 실측 검증 | 중간 — 안정성 관련 |
| 고온 환경 미탐 검증 | 운영 온도 범위 내 카운트 감소가 Touch Threshold를 침범하는지 실측 확인 | 중간 — 사용 환경 의존 |
| 레이아웃 감사 | CRX1 이격 거리, I2C 라인 4mm 이격, 오버레이 밀착 [AZD125 §3.2.2, §3.2.4, §3.1.5] | 낮음 — 하드웨어 리비전 시 |

### 4.4 데이터시트 확인 잔여 과제 (외부 자료 4종으로 해소 불가)

1. **MULT/COMP 포화 한계값**: ATI 실패의 정확한 물리적 경계 조건(Max Counts 발생 조건)
2. **ATI Mode=Disabled에서 Reseed→ATI 자동 트리거 차단 효과**: IC 하드웨어 레벨 명세
3. **ATI Mode=Disabled에서 LTA halt timeout→Re-ATI 발동 여부**: "may" 조건의 구체 조건
4. **Filter Beta IC reset 기본값**: 레지스터 초기값 명세
