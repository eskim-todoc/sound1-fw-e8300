# 01 정독 — AZD004 신호처리 (노드 01)

**TL;DR**: AZD004 §4~§8 정독 결과. ATI 실패의 정확한 조건은 자료에 명시 없으나, §12.7 프로그램 플로우에서 "3회 재시도 후 Hardware Error"로 처리하라 규정. 민감도는 Target/Base 비율에 정비례. LTA는 터치 구간 정지·환경변화 자동추적·halt timeout 후 RESEED를 내장한 드리프트 보정 메커니즘이며, 현 펌웨어의 LTA delta 판정 방식은 이 설계와 정합.

---

## 1. Charge Transfer 방법 요약 [AZD004 §2]

- 센싱 전극(작은 컨테이너)을 반복 충전·방전해 내부 기준 커패시터(Cs, 40~80 pF)를 채울 때까지 반복 횟수를 카운트함
- **카운트(Counts) = 내부 Cs를 채우는 데 필요한 전하 이동 사이클 수**
- 터치(접촉) 시 전극 커패시턴스 증가 → 1회 이동 전하량 증가 → 카운트 감소 (자기 커패시턴스 방식) [AZD004 §3.1]
- 상호 커패시턴스 방식은 반대 — 터치 시 카운트 증가 [AZD004 §3.2]
- **IQS323 연결**: IQS323은 자기 커패시턴스 기반이므로 터치 시 카운트 감소, 즉 LTA보다 카운트가 낮아지면 터치로 판정하는 현 펌웨어 방향과 정합

## 2. Signal Conditioning — MULT/COMP 구조 [AZD004 §4.1~§4.2]

### 2.1 Multipliers (MULT) — Resolution Control

- 내부 Cs가 작으므로 전극에서 들어오는 전하를 분할해 카운트 수를 늘림 → **Coarse Multiplier + Fine Multiplier 2단 구성** [AZD004 §4.1, Figure 4.1]
- 카운트 배율 상승 = 분해능 상승: "10% change on 40 counts → delta 4, vs 10% change on 1000 counts → delta 100" [AZD004 §4.1]
- 현 펌웨어: 공장 사전측정값으로 MULT를 고정 write → Auto-ATI가 결정했을 값 대신 사람이 최적화한 값 사용. 이 방식은 ATI Multiplier Calibration 1단계의 결과를 수동 고정하는 것과 동일 효과

### 2.2 Compensation (COMP) — Offset Subtraction

- 정적 기생 커패시턴스(Cp)를 조정 가능한 커패시터 뱅크로 차감 → DC 성분 제거 후 잔여 가변 커패시턴스에만 집중 [AZD004 §4.2]
- "Increasing the compensation value subtracts more parasitic capacitance, increasing the sensitivity" [AZD004 §4.2]
- COMP는 두 Multiplier 단계 이후에 수행됨 [AZD004 §4.2]
- 현 펌웨어: COMP도 고정 write. 공장 측정 Cp 기준으로 잔류 신호를 Target 근처로 맞춘 값

## 3. ATI 동작 메커니즘 [AZD004 §4.3~§4.5]

### 3.1 ATI 개요

ATI(Automatic Tuning Implementation)는 MULT와 COMP를 자동 보정해 사전 정의된 Base/Target 카운트에 도달시키는 알고리즘 [AZD004 §4.3].

### 3.2 ATI 2단계 [AZD004 §4.4]

**1단계 — Multiplier Calibration (Coarse)**

- 목표: 카운트를 ATI Base 값에 근접시킴
- "The Base value denotes the desired number of charge transfer cycles necessary to fill the internal reference capacitor, after the multiplier stage but without any compensation enabled" [AZD004 §4.4]
- 전형 Base 값: 100~200 카운트 [AZD004 §4.4]
- 알고리즘이 Coarse/Fine Multiplier를 조정하며 반복 수렴

**2단계 — Compensation Calibration (Fine)**

- 목표: Multiplier 고정 후 COMP를 조정해 카운트를 ATI Target 값까지 올림
- "The ATI routine adjusts the compensation value until the sensor reaches the Target counts" [AZD004 §4.4]
- 전형 Target 값: 500~1000 카운트 [AZD004 §4.4]

### 3.3 민감도 정량 관계 [AZD004 §4.4]

```
민감도 ∝ Target / Base
```

> "ATI is thus primarily controlled by these two parameters; the ATI Base and the ATI Target. These two parameters affect the sensitivity with the following relationship: Sensitivity ∝ Target / Base" [AZD004 §4.4]

- Base가 작을수록, Target이 클수록 민감도 상승
- 단, "increasing the sensor's sensitivity by increasing compensation can result in more noise on the sensor counts" [AZD004 §4.4] — 민감도↑ = 노이즈↑ 트레이드오프

### 3.4 ATI가 보정하는 요소 [AZD004 §4.5]

- 기생 커패시턴스 Cp
- 온도·습도 변화
- 전극 레이아웃·라우팅 편차
- 오버레이 두께·재질 변화
- PCB 기판 종류(FR4, FPC 등)

## 4. ATI 실패 조건 (미해결_1) [AZD004 §4.4, §12.7]

### 4.1 자료에 명시된 내용

AZD004 §4.4에서 ATI 실패 조건의 물리적 경계는 **명시되어 있지 않음** [자료 미명시].

자료에서 확인된 ATI 실패 관련 사항:

1. **프로그램 플로우 처리 규정** [AZD004 §12.7, Figure 12.9]:
   - ATI 시도 3회 미만이면 재시도(Force Comms → ATI All)
   - 3회 이상이면 "Produce Error: Possible Hardware Issue"로 처리
   - "To avoid constant errors due to interaction with the sensor during an ATI, it is recommended to add a delay between ReATI attempts" [AZD004 §12.7]

2. **터치 중 ATI 시도 금지 원칙** [AZD004 §12.7]:
   - 사용자 상호작용 중 ATI 시도 시 지속적 오류 발생 가능 → 지연 추가 권고
   - 이는 v3 아키텍처의 "노터치 게이트 후 Re-ATI 허용"과 완전히 정합

3. **LTA Filter Halt timeout 후 자동 Re-ATI** [AZD004 §5.3]:
   - "This clears the existing delta (zero difference between counts and LTA), thus clearing active states. This may also automatically trigger a re-ATI to recalibrate the sensor." [AZD004 §5.3]
   - LTA halt 타임아웃이 ATI 트리거 조건 중 하나

### 4.2 ATI Error 플래그 처리 (현 펌웨어 맥락)

- **직전 확정(20260618)**: ATI_Error는 conversion 정지 안 함(Fixed write로 무해화). Max Counts 포화만 conversion 정지 유발
- [추정] Max Counts 포화가 ATI 실패의 가장 직접적 결과 중 하나일 가능성: 기생 커패시턴스가 너무 커서 MULT를 최대로 줄여도 Target에 도달 불가하거나, COMP가 최대 범위를 벗어나는 경우 → 그러나 정확한 포화 조건 경계값은 AZD004에 없음 [자료 미명시]
- IQS323 User Guide에서 ATI Error 비트 정의와 MULT/COMP 한계값 확인 필요

## 5. 필터링 개요 [AZD004 §5]

### 5.1 IIR Beta 필터 [AZD004 §5.1]

수식:

```
yk = (1 - 1/2^β) * y(k-1) + x(k) / 2^β
```

- β가 클수록 새 샘플 가중치(1/2^β) 감소 → 느린 응답, 높은 노이즈 감쇠 [AZD004 §5.1]
- β = 0: 필터 없음(즉시 응답)
- β가 높을수록 "slowly-following counts" [AZD004 §5.1]

### 5.2 Counts(AC) 필터 [AZD004 §5.2]

- 원시 샘플에 Beta 필터 적용 → Filtered Counts 생성
- 전형 범위: β = 0(즉시 응답) ~ β = 4(지연 응답) [AZD004 §5.2]
- 터치 감지 응답성 유지가 목적 → 빠른 Beta 값 권장

### 5.3 Long Term Average (LTA) [AZD004 §5.3]

**LTA 핵심 동작 원리**:

- Filtered Counts의 IIR 저역통과 평균 → 환경 드리프트(온도·습도·기계적 변형) 추적 [AZD004 §5.3]
- 전형 Beta 범위: β = 6(빠른 추적) ~ β = 10(느린 추적) [AZD004 §5.3]
- **터치/근접 이벤트 발생 시 LTA 정지(halt)**: 사용자 상호작용이 LTA를 오염시키지 않도록 방지 [AZD004 §5.3]
- 이벤트 해제 시 LTA 필터 재개

**LTA Halt Timeout 메커니즘**:

> "Halting the LTA may in some rare instances cause the sensor to get stuck in a proximity or touch event. This may happen if the environmental conditions change suddenly, or an additional load is added to a sensor. Therefore, the LTA filter is only halted for a maximum time, known as the filter halt period." [AZD004 §5.3]

- Halt 시간 초과 시: LTA = 현재 카운트로 강제 설정(RESEED) → delta 초기화 → 이벤트 해제
- "This may also automatically trigger a re-ATI to recalibrate the sensor." [AZD004 §5.3]

**비대칭 추적 특성** [AZD004 §5.3]:

- LTA는 카운트가 LTA보다 **위에 있을 때** 더 빠르게 추적 (이물질 제거 시 카운트 상승 → 빠른 복귀)
- 카운트가 LTA보다 **아래일 때** 정상 속도로 느리게 추적 (터치 방향)

**운영 제약**:

> "Under normal circumstances, the customer should not adjust LTA values. Normally, LTA registers are read-only and values are seeded after ATI completion or upon an explicit reseed command." [AZD004 §5.3]

**현 펌웨어 연결**:
- LTA는 ATI 완료 후 자동 시드됨 → 부팅 시 MCLR → Auto-ATI → LTA 시드 순서는 정합
- 절전 진입 시 RESEED 명령 = LTA를 현재 카운트로 강제 업데이트 → 환경 변화 흡수 목적. 자료 §5.3 "explicit reseed command"로 허용된 동작

## 6. Linearised Counts [AZD004 §6]

### 6.1 선형화 원리 [AZD004 §6.1]

카운트는 커패시턴스에 **반비례**하므로 비선형 관계 발생:

```
Linearised Counts = Target^2 / Raw Counts   ... (옵션 방식, 식 1)
Linearised Counts = 3276750 / Raw Counts     ... (내장 방식, 식 2)
```

IQS323의 경우 어느 방식을 사용하는지는 AZD004에 명시 없음 [자료 미명시] — User Guide 또는 데이터시트 확인 필요.

### 6.2 Base와 Target 해석 [AZD004 §6.2]

- 식 1 방식 기기: Base/Target = raw counts 기준 (Base 100, Target 500이 전형)
- 식 2 방식 기기: Base/Target = 선형화 카운트 기준 (Base = 3276750/100 = 32767, Target = 3276750/500 = 6553)

### 6.3 민감도 평가 방법 [AZD004 §6.3]

선형화 카운트 사용 시 delta 해석:

```
Delta Counts(raw) = 3276750/Linearised_LTA - 3276750/Linearised_Counts
```

예시: LTA = 10000, Counts = 10500 → Delta raw = 327.67 - 312.07 = 15.6 counts [AZD004 §6.3]

**현 펌웨어 연결**: 현 펌웨어가 linearised counts를 사용하는지 raw counts를 사용하는지 `tdc_drv_iqs323.c` 확인 필요. 판정 임계값 설정 시 이 변환 적용 여부가 중요.

## 7. Debounce / Hysteresis [AZD004 §7]

### 7.1 Debounce [AZD004 §7.2]

- 근접 임계값 최초 교차 시 고속 반복 측정으로 N회 연속 초과 확인 후 이벤트 확정
- 노이즈·지터로 인한 거짓 트리거 방지 [AZD004 §7.2]

### 7.2 Hysteresis [AZD004 §7.3]

- 진입 임계값 > 이탈 임계값 → 터치 on/off 경계에서의 채터링 방지
- "It is recommended to add hysteresis to touch levels whenever possible to ensure a reliable and clean output." [AZD004 §7.3]

## 8. Power Modes [AZD004 §8]

| 모드 | 전형 주기 | 특징 |
|---|---|---|
| Normal Power (NP) | 10~50 ms | 고응답률, 고소비 전류 |
| Low Power (LP) | 50~200 ms | 중간 소비 |
| Ultra-Low Power (ULP) | 100~500 ms | 단일 채널(AutoProx)만 측정 |

**자동 전환** [AZD004 §8.1]:
> "Current consumption is decreased during long periods of no user interaction by transitioning to a lower power mode. When a sensor detects some user input, the device can automatically transition to a higher power mode for better responsiveness." [AZD004 §8.1]

**현 펌웨어 연결**:
- 절전 진입 = WDT 리셋 복귀 방식으로 구현 → IQS323 자체 ULP 자동전환 기능과는 다른 접근
- ULP의 "단일 채널 AutoProx" 특성은 CRX1 ESD 더미채널이 있는 우리 회로에서 어느 채널이 ULP 측정 채널로 선택되는지 추가 확인 필요 [자료 미명시]

## 9. 미해결 항목 기여 요약

### 미해결_1: ATI 실패 조건

- **자료 기여**: ATI 실패의 물리적 경계값은 AZD004에 미명시. 그러나 다음 간접 근거 확보:
  1. 터치 중 ATI 시도 → 지속적 오류 가능 [AZD004 §12.7]
  2. 3회 재시도 후 "Hardware Issue"로 처리 규정 [AZD004 §12.7]
  3. LTA halt timeout → 자동 Re-ATI 트리거 [AZD004 §5.3]
- **잔여 미해결**: MULT/COMP 포화 한계값·Max Counts 발생 조건 → User Guide 또는 IQS323 데이터시트 확인 필요

### 미해결_2: 환경 드리프트 정량

- **자료 기여**: AZD004는 드리프트 원인(온도·습도·기계적 변형·환경 변화)을 열거하나 정량값 미명시 [자료 미명시]
- LTA가 드리프트를 β = 6~10 속도로 추적한다는 정성적 정보만 존재

### 미해결_3: 드리프트 자동보정

- **자료 기여**: LTA 자체가 1차 드리프트 자동보정 메커니즘. LTA halt timeout 후 RESEED + 자동 Re-ATI가 2차 보정 [AZD004 §5.3]
- **현 펌웨어 호환성**: RESEED는 현 펌웨어에서 절전 진입 시 명시 사용 → 자동 보정 경로 일부 활성화됨. 단, LTA halt timeout 기반 자동 Re-ATI는 ATI Disabled 설정에서 실제로 동작하는지 확인 필요 [자료 미명시, 추정]

## 10. v3 아키텍처 보강/수정/반증 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| 노터치 게이트 후 Re-ATI | **보강** | "constant errors due to interaction during ATI" → 터치 중 ATI 금지 원칙과 완전 정합 [AZD004 §12.7] |
| Fixed MULT/COMP write | **보강** | ATI 2단계 = MULT(1단계) + COMP(2단계) 순 보정. 수동 고정은 이 결과값 직접 주입과 동등 [AZD004 §4.4] |
| RESEED at 절전 진입 | **보강** | "explicit reseed command"는 허용된 LTA 조작법 [AZD004 §5.3] |
| LTA delta 기반 터치 판정 | **보강** | AZD004 §5 전체가 LTA delta 방식을 기본 설계로 규정 |
| ATI Disabled 상태에서 LTA halt timeout Re-ATI | **미확인** | §5.3에서 "may also automatically trigger a re-ATI"라 명시하나, ATI Mode=Disabled 상태에서 이 자동 트리거가 실제로 발동하는지 여부는 User Guide/데이터시트 확인 필요 [자료 미명시, 추정] |
