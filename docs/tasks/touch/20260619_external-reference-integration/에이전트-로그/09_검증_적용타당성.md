# 09 검증 — 적용 타당성 (adversarial)

**TL;DR**: 자료 권고 17개를 우리 회로 6개 제약과 교차 판정한 결과, 완전 적용 가능 8개·조건부 5개·적용 불가 4개로 분류된다. 가장 큰 구조적 충돌은 Follow UI(온도 드리프트 자동보정)로, 레퍼런스 전극 부재 + C52 DC-block 복합 제약으로 현 하드웨어에서 불가하다. EV-Kit 예제 설정값(ATI Mode=Full·필터 beta·임계값)을 그대로 차용할 경우 3가지 함정이 있다.

---

## 0. 우리 회로 제약 요약

| 식별자 | 제약 내용 | 근거 |
|---|---|---|
| 제약_A | CRX1 ESD 더미채널 (내부 CalCap, 외부 CRX1 핀 무관) | `tdc_touch_config.h` TDC_TOUCH_CRX1_DUMMY_ENABLE=1 |
| 제약_B | C52 100nF DC-block (CRX1 핀에 직렬 삽입) | 회로 제약 확정 [00_오케스트레이터-입력 §1] |
| 제약_C | 크래들 뚜껑 닫힘 = 터치 폴링 완전 중단 (노터치 구간 확정) | v3 아키텍처 컨텍스트 |
| 제약_D | 절전 복귀 = WDT 리셋 재부팅 (런타임 리셋 복구 루프 없음) | v3 아키텍처 컨텍스트 |
| 제약_E | 자가용량 단일 터치버튼 1채널 (슬라이더·다중 버튼 없음) | 회로 구성 확정 |
| 제약_F | EV-Kit 구성과 다름: 3-버튼+슬라이더 vs 단일버튼+더미채널 | [05_정독_arduino코드 §6-1] |

## 1. 권고별 적용 타당성 판정

### 1-1. Follow UI (온도 드리프트 자동보정) — 적용 불가

**권고**: 별도 레퍼런스 전극(센서보다 작은 0.2 mm 트레이스)을 동일 온도 구역에 배치하고 별도 Cx 핀 + 채널을 할당해, 인터치 상태에서도 LTA를 온도에 추종시킨다 [자료 §8.2.1].

**충돌 분석**:
- 제약_A: 현재 CRX1은 내부 CalCap 더미 채널로 구성되어 있다. 레퍼런스 전극 역할을 하려면 외부 물리 전극과 연결되어야 하나, 더미 채널은 IC 내부 CalCap과 연결되어 외부 환경 변화(온도)를 감지하지 못한다.
- 제약_B: C52 100nF DC-block이 CRX1 핀에 직렬이므로, 설령 외부 레퍼런스 전극을 추가해도 DC 오프셋 제거가 불가해 드리프트 기준값을 안정적으로 읽을 수 없다. [자료 §8.2 + 02_정독_azd125환경 §5 결론]에서 C52와 Follow UI는 충돌하지 않는다고 분류했으나 이는 "소프트웨어 LTA 추종 메커니즘과 DC-block이 직접 충돌하지 않는다"는 좁은 의미다. 실제로는 DC-block이 레퍼런스 채널의 정량적 드리프트 기준값 자체를 오염시킨다.

**판정**: [적용 불가] 하드웨어 레퍼런스 전극 추가 + C52 경로 수정이 모두 필요하므로 현 하드웨어에서 불가.

**v3 함의**: 드리프트 자동보정이 Follow UI 없이는 LTA IIR 추적과 노터치 게이트 조건부 Re-ATI만 남는다. Re-ATI가 현실적 유일 드리프트 보정 수단이며 이는 v3 아키텍처가 선택한 경로와 일치.

---

### 1-2. CRX1 레퍼런스 모드 (TDC_TOUCH_CRX1_REF_ENABLE) — 조건부

**권고**: CH1을 Reference 모드(Channel Setup bits[3:0]=0x02)로 활성화하면 CH0 LTA가 레퍼런스 채널 변화에 연동되어 드리프트 보정 효과를 얻는다 [자료 §4.4 + `tdc_touch_config.h` §6].

**충돌 분석**:
- 제약_B: C52 DC-block이 CRX1에 직렬이다. C52가 있으면 AC 성분만 통과하므로 저주파 온도 드리프트(매우 느린 변화)는 DC-block에 의해 차단될 가능성이 높다. `tdc_touch_config.h`의 CRX1_REF_ENABLE 주석에 "C52(100nF) 있는 상태에서도 동작 (AC 경로로 정전용량 측정)"이라 명시하나, 실제로 온도 드리프트처럼 수 분에 걸친 변화가 AC 경로로 정확히 전달되는지는 [자료 미명시] — 이론적으로 100nF+레퍼런스 임피던스 조합의 차단 주파수보다 드리프트 주파수가 낮으면 차단된다 [추정].
- 제약_A: 현재 기본값이 DUMMY_ENABLE=1이라 REF_ENABLE과 상호 배타. 전환하려면 빌드 설정 변경 필요.

**판정**: [조건부] C52 있는 상태에서 레퍼런스 모드 효과(온도 드리프트 보정)는 AC 경로로 의존적이어서 느린 드리프트 성분이 차단될 수 있다. ESD 방전이 필요 없는 환경(ESD 이슈 해결 완료 후)에서 DUMMY_ENABLE→REF_ENABLE 전환 + 실측 검증 조건부 권고.

### 1-3. 비활성 전극 GND 구동 — 적용 가능 (레이아웃 감사 필요)

**권고**: ProxSense/ProxFusion 계열 IC에서 비활성 전극은 GND로 구동된다. 따라서 인접 전극을 GND pour 연장으로 취급하며, 터치 전극과 5mm 이상 이격이 필요하다 [자료 §3.2.2].

**충돌 분석**:
- 제약_A: 현재 CRX1은 더미 채널(CalCap, 외부 핀 무관)이므로 실제 CRX1 핀이 IC 측정 사이클에서 비활성 구간에 어떻게 구동되는지 확인이 필요하다. CalCap 모드에서 외부 CRX1 핀이 GND로 구동되는지, floating 상태인지는 [자료 미명시].
- [추정] CalCap 더미 채널은 IC 내부 CalCap을 사용하므로 외부 CRX1 핀이 IC 입력에서 분리되어 floating일 가능성이 있다. floating이면 GND 구동 문제가 없으나, GND 방전 경로도 없어 ESD 취약성이 남는다 — 이것이 CRX0 방전(`TDC_TOUCH_CRX0_DISCHARGE_ENABLE`) 기능이 추가된 이유와 일치.

**판정**: [적용 가능 + 레이아웃 감사 필요] CRX1이 비활성 시 GND 구동되면 터치 전극과 5mm 이격 규칙 적용 필요. PCB 레이아웃 검토 항목으로 추가 권고.

---

### 1-4. 노터치 게이트 후 Re-ATI — 적용 가능 (v3 보강)

**권고**: 사용자가 센서에 접촉 중 ATI를 시도하면 지속적 오류가 발생할 수 있다. ATI 재시도 사이에 지연을 추가하라 [자료 §12.7].

**충돌 분석**:
- 제약_C: 크래들 뚜껑 닫힘 = 폴링 중단 = 확실한 노터치 상태. 이 구간에서 Re-ATI를 허용하는 v3 구조는 자료 권고("사용자 상호작용 중 ATI 금지")와 완전히 일치한다.
- 제약_E: 단일 버튼 구성이므로 채널 간 ATI 간섭 문제 없다.

**판정**: [적용 가능] v3의 노터치 게이트 후 Re-ATI 허용 구조는 자료 §12.7 권고와 정합.

### 1-5. CH timeout 비활성화 (stuck-touch 자동 Re-ATI 차단) — 적용 가능

**권고**: stuck-touch 시 IQS323의 Channel Event Timeout이 자동으로 Re-ATI를 트리거한다 [자료 §4.1 + 04_정독_userguide운영 §7].

**충돌 분석**: 이 기능은 ATI Mode=Full 환경을 전제로 한다. 현 구성(ATI Mode=Disabled)에서 auto-reATI를 허용하면 고정 보상값이 덮어써질 위험이 있다. 현 드라이버는 SYSTEM_CONTROL MSB bit[2:0]=111로 CH0~CH2 timeout을 모두 비활성화한다 (`tdc_drv_iqs323_apply_settings()` 라인 1155).

**판정**: [적용 가능] v3 아키텍처 의도와 정합. ATI Mode=Disabled와 이중 방어 구조 유지 권고.

---

### 1-6. Reseed at 절전 진입 — 적용 가능

**권고**: Reseed 명령은 LTA를 현재 counts 값으로 강제 동기화한다. 단, LTA가 ATI target과 크게 다르면 ATI가 자동 트리거될 수 있다 [자료 §3.5.4].

**충돌 분석**: 현 드라이버 `tdc_drv_iqs323_reseed()`는 절전 진입 시 Touch Threshold=255(최둔감) + Prox Threshold + Reseed 순으로 실행한다. ATI Mode=Disabled + CH timeout 비활성화가 Reseed 후 ATI 자동 트리거를 이중 차단하는지는 [자료 미명시]이나, Disabled 상태에서 Reseed가 ATI를 트리거하는 경로가 열려 있을 가능성을 배제할 수 없다 [추정].

**판정**: [적용 가능 + 잠재 위험] Reseed 자체는 자료 허용 동작. 단, ATI Mode=Disabled 상태에서 Reseed → ATI 자동 트리거 경로가 IC 하드웨어 레벨에서 차단되는지 User Guide/데이터시트 추가 확인 필요.

### 1-7. EV-Kit ATI Mode=Full 기본값 차용 — 적용 불가 (함정 경고)

**EV-Kit 기본값**: ATI_SETUP_LSB=0x8C (bits[2:0]=100 = ATI Mode=Full), ATI_TARGET=200.

**함정**: 이 값은 EV-Kit 전용 PCB(3-버튼, 슬라이더, C52 없음, 단순 회로)를 대상으로 설정된 값이다 [자료 §05_정독_arduino코드 §4-2]. 우리 회로는 C52 DC-block + CRX1 더미채널 + 단일 버튼으로 EV-Kit와 기생 커패시턴스 프로파일이 전혀 다르다. ATI Mode=Full로 Auto-ATI를 실행하면 IQS323이 우리 회로 기생 커패시턴스에 맞는 MULT/COMP를 산출하지만, 이 값이 EV-Kit 기본값과 크게 다르다는 것을 실측으로 확인했다 (예: PACKAGE 변종 MULT_MSB=0x5C, COMP=0xEF63 vs EV-Kit S0=0x2169).

**판정**: [적용 불가] EV-Kit ATI 기본값의 직접 차용은 우리 회로에 부적절한 기생 용량 보상을 야기한다. 현재처럼 보드 변종별 실측 후 고정 MULT/COMP 사용이 올바른 접근.

### 1-8. EV-Kit 필터 Beta 기본값 차용 — 조건부 (조사 필요)

**EV-Kit 기본값**: NP_COUNTS_FILTER=2, NP_LTA_FILTER=5, LP_LTA_FILTER=5, NP_LTA_FAST_FILTER=3, FAST_FILTER_BAND=0x001E [EV_KIT.h §Filter Betas].

**현 드라이버**: Filter Beta 레지스터를 명시적으로 write하지 않아 IC reset 기본값을 사용한다 [04_정독_userguide운영 §12].

**문제점**: EV-Kit 기본값이 IC reset 기본값과 동일한지 여부가 불명확하다 [자료 미명시]. IC reset 기본값이 EV-Kit 값과 다를 경우, 현 드라이버는 의도와 다른 필터 특성으로 동작할 수 있다.

**판정**: [조건부] IC reset 기본값과 EV-Kit 설정값의 동일 여부를 IQS323 데이터시트에서 확인 필요. 다를 경우 Filter Beta를 명시적으로 write하거나, EV-Kit 값을 사용 근거와 함께 검증해야 한다. 특히 LTA_FILTER beta=5가 우리 회로 드리프트 특성에 맞는지는 온도 실측 후 판단 권고.

### 1-9. EV-Kit Touch Threshold=40 차용 — 조건부 (SNR 기준 검증 필요)

**EV-Kit 기본값**: CH0_TOUCH_THRESHOLD=0x28 (계수 40), CH0_TOUCH_HYSTERESIS=0x00 [EV_KIT.h §Channel Settings].

**충돌 분석**:
- 현 드라이버는 `TDC_DRV_IQS323_TOUCH_THRESHOLD` 별도 정의값을 사용하며 EV-Kit 값을 그대로 따르지 않는다.
- 더 중요한 것은 임계값이 SNR ≥ 5를 충족해야 한다는 원칙이다 [자료 §10.1]. 노이즈 밴드가 4 cnt일 때 임계 최소값=20 cnt, 전형 터치 신호 최소=25 cnt.
- 그러나 IQS323의 Touch Threshold는 raw counts 차이가 아니라 LTA 대비 비율 계수(counts delta × 256 / LTA)로 동작한다 (`tdc_drv_iqs323_read_touch_margin()` 구현 참고). 따라서 자료의 "cnt 단위" SNR 기준을 계수 단위로 직접 적용하는 것은 변환식 확인이 필요하다 [추정].

**판정**: [조건부] SNR ≥ 5 기준 준수 여부를 현 임계값 설정에 대해 검증할 것. 단 임계값이 raw count 차이인지 비율 계수인지 명확히 구분한 후 적용.

### 1-10. EV-Kit Event Mode 활성화 — 조건부

**EV-Kit 구조**: init 마지막 단계에서 EVENT_MODE_BIT를 세팅해 이후 RDY가 이벤트(터치/ATI) 발생 시에만 LOW가 된다 [IQS323.cpp §setEventMode + 05_정독_arduino코드 §3-3].

**현 드라이버**: SYSTEM_CONTROL에 EVENT_MODE_BIT를 설정하지 않아 streaming mode(주기적 RDY)로 동작한다 [추정]. 이로 인해 force_window_open()으로 매번 윈도우를 강제 열어야 한다 [05_정독_arduino코드 §6-4].

**충돌 분석**:
- 제약_C: 크래들 뚜껑 닫힘 구간에는 폴링을 완전히 중단하므로 이 구간에서 streaming mode RDY가 발생해도 무시된다.
- Event Mode 채택 시 이점: 불필요한 RDY를 억제해 소비 전류 감소 + 전자기 노이즈 감소 가능. 단 polling 구조를 event-driven으로 전환해야 하며, IQS323이 이벤트를 생성하지 않는 구간(터치 없음, ATI 없음)에서 상위 레이어가 IQS323 상태를 어떻게 polling할지 재설계 필요.
- 제약_D: WDT 재부팅 복귀 구조에서 Event Mode는 재부팅 후 다시 설정해야 하므로 추가 복잡성 없음.

**판정**: [조건부] Event Mode 채택은 전력 절감과 노이즈 억제에 이점이 있으나, 상위 레이어 polling 구조 변경이 필요하다. 단기 우선순위보다 낮은 개선 항목.

### 1-11. 오버레이 두께·공기 틈 — 적용 가능 (레이아웃 감사)

**권고**: 자가용량에서 오버레이 얇을수록 민감도 향상. 1mm 공기 틈이 8mm 유리와 동등한 민감도 저하를 유발한다 [자료 §3.1.2, §3.1.5].

**충돌 분석**: 현재 오버레이 재질·두께·밀착 상태는 [자료 미명시] — 기계 구조 확인 필요. 공기 틈 발생 시 민감도 급락과 습기 유입 경로가 동시에 형성된다.

**판정**: [적용 가능] 조립 검사 항목으로 오버레이-전극 밀착 확인을 추가 권고.

### 1-12. I2C 라인 4mm 이격 — 적용 가능 (레이아웃 감사)

**권고**: I2C 등 디지털 신호 라인은 용량 트레이스에서 최소 4mm 이상 이격 필요. 교차 시 90° 각도 유지 [자료 §3.2.4].

**판정**: [적용 가능] PCB 레이아웃 검토 항목. 현재 IQS323 SCL/SDA 라인과 CRX0 트레이스 간 이격 거리 확인 필요.

---

### 1-13. Arduino 예제 2-윈도우 read 방식 vs RESTART — 적용 가능

**예제 방식**: readRandomBytes()에서 RESTART(Repeated Start)를 사용해 단일 RDY 윈도우에서 주소 write + 데이터 read를 처리한다 [IQS323.cpp §force_I2C_communication, §readRandomBytes].

**현 드라이버**: read_register()가 2-윈도우 구조(1st window에서 addr write, 2nd window에서 data read)로 동작한다 [tdc_drv_iqs323.c §read_register]. 각 윈도우 사이에 wait_rdy_window_closed()로 윈도우 닫힘을 대기한다.

**충돌 분석**: 2-윈도우 방식은 RESTART를 지원하지 않는 I2C 드라이버 구조(Cortex-M3 전용 드라이버)에 대한 임베디드 적응이다. RESTART 적용 시 I2C 드라이버 수정이 필요하며, 현 구조에서 단일 윈도우 처리 이점(윈도우 닫힘 시간 절약)이 있으나 드라이버 변경 리스크가 있다.

**판정**: [적용 가능 + 단기 불필요] 기능상 동등. 성능 최적화 관점에서만 검토.

---

### 1-14. 런타임 리셋 복구 루프 — 조건부 (WDT 재부팅으로 대체 허용)

**예제 방식**: STATE_CHECK_RESET에서 SHOW_RESET_BIT 감지 시 STATE_START로 복귀해 전체 재초기화를 반복한다 [IQS323.cpp §run].

**현 드라이버**: WDT 재부팅으로 대체. `tdc_drv_iqs323.c` 레이어에 런타임 리셋 복구 루프 없다.

**판정**: [조건부] 임베디드 단일채널 환경에서 WDT 재부팅은 더 단순하고 확실한 상태 초기화를 보장한다. 단, 재부팅 시간(수 초) 동안 터치 감지 중단이 허용되는지 사용 시나리오에서 확인 필요. 현 v3 아키텍처에서 허용된 것으로 판단.

---

### 1-15. Proximity 임계값으로 터치 감지 — 조건부 (위험)

**권고**: 배터리 구동 기기에서 민감도가 낮으면 Proximity threshold를 터치 감지에 활용할 수 있다 [자료 §5.4].

**충돌 분석**: Proximity 임계값을 낮추면 온도·습도·노이즈 영향이 증폭된다 [자료 §4.1]. v3 Fixed base 안정성 요구사항과 반대 방향이다. 현재 TDC_TOUCH_PROX_THRESHOLD_ENABLE=0으로 비활성화되어 있으며 주석에 "실측에서 터치/노터치 채터링 유발이 의심"이라 명시되어 있다.

**판정**: [조건부] 배터리 구동 + 단일채널 + v3 Fixed base 조합에서 Proximity 임계값 기반 터치 감지는 안정성 위험이 높다. 현재 비활성 유지 권고.

---

### 1-16. 제품번호 확인 단계 누락 — 조건부 (개발 환경 위험)

**예제 방식**: init 첫 단계에서 제품번호(0x00 레지스터)를 읽어 IQS323 존재를 확인한다 [IQS323.cpp §init VERIFY_PRODUCT].

**현 드라이버**: 제품번호 확인 단계 없다.

**판정**: [조건부] 프로덕션 환경에서는 IQS323이 항상 장착되므로 생략 가능. 개발·디버깅 환경에서 I2C 오결선·IC 미장착 상황을 빠르게 감지하기 위해 ATI_DUMP_ENABLE 모드에서만 추가 권고.

---

### 1-17. 온도 드리프트 방향 — 적용 가능 (임계값 설계 참고)

**자료 수치**: 25→50°C 구간에서 FR-4 기기 센서 채널 약 -18 cnt/°C [추정, 자료 §8.2.4 선형화].

**충돌 분석**: 이 수치는 ATI 후 카운터 1000 기준 예시로, ATI Mode=Disabled + 고정 보상값 상태에서 실제 카운터 기준이 다르면 절댓값도 다르다. 드리프트 방향(온도 상승 시 카운터 감소)은 자가용량 방식에서 공통이다.

**판정**: [적용 가능] 드리프트 방향이 터치 판정 방향(카운터 감소=터치)과 동일하므로, 온도 상승 시 오탐보다는 오탐 해제(민감도 저하) 방향의 위험이 더 크다. 고온 환경에서 터치 감지 실패 가능성을 임계값 설계에 반영 필요.

## 3. EV-Kit 설정값 직접 차용 함정 3개

### 함정_1: ATI Mode=Full + EV-Kit MULT/COMP 초기값

EV-Kit COARSE/FINE 초기값 (S0=0x21, 0x69 등)은 EV-Kit 전용 PCB의 기생 용량 조건에서 ATI가 수렴할 때의 시작점이다. 우리 회로(C52 + 더미채널 + 단일버튼)에서 이 값으로 ATI Mode=Full로 동작시키면 ATI가 다른 수렴점을 찾거나 수렴 실패할 수 있다. **현재처럼 보드 변종별 실측 후 고정값 사용이 필수.**

### 함정_2: 필터 Beta IC reset 기본값 vs EV-Kit 값 혼동

현 드라이버는 Filter Beta 레지스터를 설정하지 않는다. IC reset 기본값이 EV-Kit 설정값(NP_LTA=5, NP_COUNTS=2)과 동일한지 불명확하다. 만약 IC reset 기본값이 beta=0(필터 없음)이면 LTA가 빠르게 진동해 노이즈 내성이 크게 낮아진다. IQS323 데이터시트에서 reset 기본값 확인 필요.

### 함정_3: Touch Threshold 계수 단위 혼동

EV-Kit의 Touch Threshold=40은 LTA 대비 비율 계수(delta×256/LTA)이다. 자료의 SNR ≥ 5 기준은 raw counts 차이(delta cnt)로 표현된다. 이 두 단위를 혼동해 EV-Kit 값 40을 "40 cnt"로 해석하면 틀린 적용이 된다. 현 펌웨어의 `tdc_drv_iqs323_read_touch_margin()`이 (LTA-Counts)×256/LTA 계산을 하는 것이 맞는 변환식 사용 사례다.

## 4. 미해결 항목 기여

### 미해결_1: ATI 실패 조건

- 자료 권고(ATI Mode=Disabled + CH timeout 비활성)는 ATI 실패로 가는 모든 자동 트리거 경로를 차단하는 방어 전략이며, v3 아키텍처 구현과 정합.
- 그러나 Reseed 후 ATI 자동 트리거가 ATI Mode=Disabled에서 IC 하드웨어 레벨에서 완전히 차단되는지는 이 adversarial 검토에서도 [자료 미명시] — 데이터시트 레지스터 비트 해설에서 Disabled 모드의 Reseed 연동 명세 확인 필요.
- EV-Kit 예제가 ATI_ERROR 비트를 런타임에서 읽지 않는 것은 ATI 실패를 방어적으로 처리하지 않는다는 의미. 현 드라이버의 wait_re_ati_done()에서 ati_error 비트를 확인하는 것이 더 견고하다.

### 미해결_2: 환경 민감도 정량

- 온도 드리프트 방향(상승 시 카운터 감소 = 민감도 저하 방향)이 오탐보다 미탐 방향의 위험임을 확인. 고온에서 터치 미감지가 더 큰 위험.
- Follow UI 적용 불가 판정으로 온도 드리프트 자동보정은 LTA IIR + 노터치 게이트 조건부 Re-ATI가 유일한 수단으로 재확인.

### 미해결_3: 드리프트 자동보정

- Follow UI = 적용 불가 (제약_A + 제약_B 복합).
- CRX1 Reference 모드 = 조건부 (C52 있으면 저주파 드리프트 차단 가능성, 실측 필요).
- 결론: 현 하드웨어에서 Re-ATI가 유일한 능동 드리프트 보정 수단이며, LTA IIR (beta 설정으로 조절 가능)이 수동 추적 기전으로 보조한다.

## 5. v3 아키텍처 보강/수정/반증 종합 판정

| v3 요소 | 판정 | adversarial 근거 |
|---|---|---|
| Fixed MULT/COMP (보드 변종별 실측) | **보강** | EV-Kit 값 직접 차용 불가 — 회로별 실측 필수 [§4-2 EV-Kit vs 우리 회로] |
| ATI Mode=Disabled + CH timeout 이중 차단 | **보강** | Auto-reATI 경로 차단이 고정 보상값 오염 방지에 필수 [§1-7 함정_1] |
| 노터치 게이트 후 Re-ATI | **보강** | 자료 §12.7 "터치 중 ATI 오류" 금지 원칙과 완전 정합, 크래들 닫힘=확실한 노터치 [§1-4] |
| Reseed at 절전 진입 | **보강 + 잠재 위험** | 자료 허용 동작. 단 ATI Mode=Disabled에서 Reseed→ATI 트리거 여부 미확인 [§1-6] |
| Follow UI 미채택 | **보강** | 레퍼런스 전극 없음 + C52 DC-block으로 회로상 불가 — 미채택이 올바른 선택 [§1-1] |
| WDT 재부팅 복귀 | **수정 불필요** | 단순·확실한 상태 초기화. FSM 복귀보다 재부팅 latency 있으나 허용 범위 [§1-14] |
| Filter Beta 기본값 방치 | **잠재 위험** | IC reset 기본값이 EV-Kit 값과 다를 경우 필터 특성 이탈 가능 [§3 함정_2] — 검증 필요 |
| Event Mode 미채택 | **개선 여지** | 현재 streaming mode로 불필요한 RDY 발생. 단기 우선순위 낮음 [§1-10] |

## 6. 결론

우리 회로의 6개 제약 중 C52 DC-block(제약_B)과 CRX1 더미채널(제약_A)이 가장 많은 권고를 차단한다. Follow UI(온도 자동보정)가 이 두 제약의 복합 효과로 완전히 적용 불가하며, 이것이 현 v3 아키텍처가 노터치 게이트 조건부 Re-ATI를 드리프트 보정의 핵심으로 채택한 구조적 근거다. EV-Kit 예제 설정값은 ATI 보상값·필터 Beta·임계값 세 영역에서 직접 차용 함정이 존재하며, 각각 실측·데이터시트 확인·단위 변환 검증이 필요하다.
