# 07 매핑 — 미해결 3항목 종합 답변

**TL;DR**: 미해결_1(ATI 실패 조건)은 자료에 물리적 경계값이 명시되지 않으나 간접 근거 3개로 실용적 결론 도출 가능. 미해결_2(환경 드리프트 정량)는 온도만 AZD125 §8.2.4 예시로 수치 확보(25→50°C 구간 -450/-300 cnt). 미해결_3(Re-ATI 외 자동보정)은 LTA IIR 추적이 1차 자동보정이며, Follow UI가 인터치 중 보정 기능을 제공하나 우리 회로 즉시 적용 불가로 Re-ATI가 현실적 유일 보정 수단.

---

## 1. 미해결_1: ATI가 실패하는 정확한 조건·경계

### 1.1 자료 직접 답 유무

Azoteq 외부 자료 4종 전체를 통해 **ATI 실패의 물리적 경계값(MULT/COMP 포화 한계, Max Counts 조건 등)은 자료에 명시되지 않음** [자료 미명시].

User Guide §3.6.1은 ATI Error를 "The IQS323 failed to calibrate one or more channels correctly"로 정의하나 실패 원인과 경계 조건의 정량값을 제공하지 않음 [자료 §3.6.1].

### 1.2 자료에서 확보된 간접 근거 3개

**근거 A — 터치 중 ATI 시도 시 지속 오류 발생** [AZD004 §12.7]:

> "To avoid constant errors due to interaction with the sensor during an ATI, it is recommended to add a delay between ReATI attempts." [AZD004 §12.7]

- ATI를 사용자 상호작용 중에 실행하면 연속 오류가 발생할 수 있음
- 재시도 횟수 상한: 3회 미만이면 재시도, 3회 이상이면 "Produce Error: Possible Hardware Issue"로 처리
- **함의**: v3 아키텍처의 "노터치 게이트 후에만 Re-ATI 허용" 구조가 이 원칙과 완전 정합. 터치 중 ATI 시도를 원천 차단함으로써 이 실패 경로를 제거.

**근거 B — LTA halt timeout이 자동 Re-ATI를 트리거** [AZD004 §5.3]:

> "This may also automatically trigger a re-ATI to recalibrate the sensor." [AZD004 §5.3]

- LTA halt 타임아웃 후 RESEED + 자동 Re-ATI 트리거가 ATI 실행 조건 중 하나
- 즉, ATI는 명시 명령(ATI All) 외에 stuck-touch timeout과 LTA halt timeout이라는 2개 경로로 자동 트리거될 수 있음
- **현 펌웨어 관련**: ATI Mode=Disabled + CH timeout Disable 이중 차단이 이 두 경로를 모두 막음

**근거 C — Reseed가 ATI를 자동 트리거할 수 있음** [User Guide §3.5.4]:

> "Note that the Reseed command may trigger an ATI routine if the resulting LTA is significantly different from the target." [User Guide §3.5.4]

- LTA를 현재 counts로 강제 동기화 후, 그 값이 ATI Target과 크게 다르면 ATI 자동 실행 가능
- **현 펌웨어 관련**: ATI Mode=Disabled 상태에서 Reseed가 ATI를 트리거하는지 여부는 [자료 미명시]. 이중 차단(ATI Mode=Disabled + CH timeout Disable)이 이를 막는다고 추정하나 자료 확인 없음 [추정].

### 1.3 ATI 실패 메커니즘에 대한 추론 (자료 기반)

AZD004 §4.4에서 ATI 2단계 구조를 설명한다.

- **1단계(MULT Calibration)**: Coarse/Fine Multiplier로 Base(전형 100~200 cnt) 근접 목표. 기생 커패시턴스가 너무 크거나 작아 어떤 MULT 설정으로도 Base 도달이 불가한 경우 실패 [추정, AZD004 §4.4]
- **2단계(COMP Calibration)**: COMP 조정으로 Target(전형 500~1000 cnt) 도달. COMP 최대/최소 한계를 벗어나는 경우 실패 [추정, AZD004 §4.4]

> "Increasing the sensor's sensitivity by increasing compensation can result in more noise on the sensor counts." [AZD004 §4.4]

정확한 MULT/COMP 포화 한계값, Max Counts 발생 경계는 IQS323 데이터시트에서 확인 필요 [자료 미명시].

### 1.4 현 펌웨어와의 연결: 미해결_1 실용적 결론

**핵심**: 현 펌웨어는 ATI Mode=Disabled로 자동 ATI 자체를 비활성화했으므로, "ATI가 실패하는 정확한 조건"은 **부팅 시 1회 Auto-ATI 단계에만 해당**한다.

부팅 시 Auto-ATI가 실패하더라도:
- 직전 확정(20260618) 사항: ATI_Error는 conversion 정지 안 함(Fixed write로 무해화)
- Max Counts 포화만 conversion 정지 → MCLR 필요 → MCLR 조건부화 방향으로 대응 중

따라서 미해결_1은 "ATI 실패 = Max Counts 포화 여부"로 실용적으로 치환 가능하며, 경계 조건 정량은 IQS323 데이터시트 확인이 필요한 잔여 과제다.

## 2. 미해결_2: 환경 드리프트 카운터 변화 정량

### 2.1 온도 드리프트 (유일하게 정량 자료 존재)

**자료 근거**: AZD125 §8.2.4 예시 (워치 기기, FR-4 PCB)

| 채널 | Tref=25°C | Tmax=50°C | 변화량 |
|---|---|---|---|
| 센서 채널(CH0) | 1000 cnt | 550 cnt | **-450 cnt** |
| 레퍼런스 채널(CH1) | 700 cnt | 400 cnt | **-300 cnt** |

[자료 §8.2.4]

**방향**: 온도 상승 → 카운터 감소. 자기 커패시턴스 방식에서 온도 상승은 기생 커패시턴스 특성 변화로 카운터 감소 유발.

**선형 추정** [추정, 선형 가정 시]:
- 센서 채널: 약 -18 cnt/°C (= 450 cnt / 25°C)
- 레퍼런스 채널: 약 -12 cnt/°C (= 300 cnt / 25°C)

> "It can be seen that both the sensor (blue) and reference (red) channel counts have decreased, but blue more so than red." [자료 §8.2.4]

**중요 맥락**: 이 예시는 ATI 후 카운터를 1000/700으로 고정하고 ATI를 비활성화한 상태에서 실험을 진행한 방법 [AZD125 §8.2.3]. **이는 v3의 Fixed base(ATI 비활성 + 고정 MULT/COMP) 운영 방식과 동일한 접근법**으로, v3 아키텍처의 온도 실험 모사 결과로 직접 활용 가능.

**기판 재질 보정**: AZD125 §3.1.4에 따르면 FR-4 기판 온도 의존성은 MEDIUM. FPC(PET)는 HIGH. 우리 제품이 FR-4라면 [추정] 위 수치 범위가 참고 가능한 최대 폭이다.

### 2.2 배터리 공급 / 들고 있는 상태

[자료 §5.1, AZD125]:
> "The total capacitance is the series combination of C1, C2 and C3. The total capacitance is dominated by the smallest capacitance in the series network. Therefore, when C3 « C1, any changes in C1 becomes less significant, resulting in a less sensitive system." [자료 §5.1]

- C1: 손가락 ↔ 전극 간 (< 10 pF)
- C2: 몸 ↔ 지구 간 (> 100 pF)
- C3: 모듈 ↔ 지구 간 (배터리 기기에서 작아짐)

**방향**: 기기를 들고 있을 때(배터리 구동) C3 감소 → 터치 시 C1 변화 감지량 감소 → 터치 delta 감소.

**정량 수치**: [자료 미명시] — 방향만 정성적으로 설명. 실측 데이터 없음.

보완 단서 [자료 §5.3]:
> "Typically a battery system can achieve acceptable proximity detection due to the capacitive fields between the sensing electrode and the battery or PCB ground." [자료 §5.3]

전극 주변 GND 플레인이 있으면 C3 부족을 부분적으로 보완하므로, 우리 제품이 시스템 GND로 전극을 둘러쌌다면 실제 영향은 이론치보다 작을 수 있다 [추정].

### 2.3 습도 / 수분

[자료 §9, AZD125]:

**방향**: 수분이 전도체처럼 동작 → 카운터 증가(커패시턴스 증가 효과) → 터치 오탐 방향.

**정량 수치**: [자료 미명시] — 크기·지속 시간 모두 자료에 없음.

특성:
- 변화 속도 빠름 → LTA가 추종 불가
- 액적 형태·크기 가변 → 예측 불가

### 2.4 SNR 기준과 드리프트 허용 범위 연결

[자료 §10.1, AZD125]:

| 기능 | 최소 SNR |
|---|---|
| 비임계(근접) | ≥ 3 |
| 임계(터치) | ≥ 5 |

- 단기 노이즈: 표준편차 ≈ 1 cnt, 순간 최대 3σ 가능
- 노이즈 밴드 = 4 cnt 기준 시 터치 임계값 최소 20 cnt

**드리프트와의 연결 [추정]**: 온도 드리프트 -18 cnt/°C를 LTA가 완전히 추종하지 못할 경우, 잔여 드리프트가 노이즈로 작용. SNR ≥ 5(임계값 ≥ 20 cnt) 기준 대비 잔여 드리프트 크기를 관리해야 함.

| 온도 선형 추정 | -12~-18 cnt/°C (채널별) | 감소 | [추정, §8.2.4 선형화] |

## 3. 미해결_3: Re-ATI 외 드리프트 자동보정 메커니즘

### 3.1 LTA IIR 필터 — 1차 자동보정 (Re-ATI 외)

**자료 근거**: [AZD004 §5.3], [User Guide §3.1.1]

> "The LTA is the Long Term Average of the counts signal. It tracks slow variations in the environment, and is used as a reference to detect movement." [User Guide §3.1.1, AZD004 §5.3 참조 위임]

> "Halting the LTA may in some rare instances cause the sensor to get stuck in a proximity or touch event. This may happen if the environmental conditions change suddenly, or an additional load is added to a sensor." [AZD004 §5.3]

LTA IIR 필터는 드리프트 자동보정의 1차 메커니즘:
- 노터치 상태 시 LTA가 beta(6~10) 속도로 느리게 카운터를 추적 → 환경 드리프트 자동 흡수
- 인터치 상태 시 LTA halt → 이 구간 드리프트는 흡수 불가 (→ Follow UI가 보완 역할)
- 비대칭 추적: 카운터가 LTA보다 위(이물질 제거 방향)에 있을 때 더 빠르게 추적 [AZD004 §5.3]

**현 펌웨어 상태**: Filter Beta 레지스터가 명시적으로 write되지 않아 IC 기본값 사용 중 [05_정독_arduino코드]. EV-Kit 예제 기준값: NP LTA beta=5, NP Counts beta=2 [EV_KIT.h]. 이것이 현 펌웨어의 실제 동작값과 일치하는지 확인 필요.

### 3.2 Follow UI — 인터치 중 자동보정 (Re-ATI 외)

**자료 근거**: [AZD125 §8.2]

Follow UI는 인터치 상태에서 LTA가 halt되는 구간에 레퍼런스 채널 변화를 가중치(Wf)로 반영해 LTA를 추종시키는 드리프트 자동보정 기능.

작동 원리:
- 인터치 중 온도가 변해도 레퍼런스 채널이 동일한 온도 변화를 감지
- 레퍼런스 채널 변화 × Wf → LTA도 같은 방향으로 추종
- 결과: 온도 드리프트 중에도 카운터 delta(터치 신호) 일정 유지

> "At sample 450, at 50°C, the touch is removed and it is shown how Channel 0 recovers to the level of the LTA that followed, indicating a successful touch release. Without the Follow UI, the device would not have registered a released touch event, since the green line did not follow the temperature change." [자료 §8.2.4]

**우리 회로 적용 가능성**:

| 조건 | 판정 | 근거 |
|---|---|---|
| 별도 레퍼런스 전극 필요 | **불충족** | CRX0(터치)+CRX1(ESD 더미)만 존재 — 레퍼런스 전극 설계 없음 |
| 레퍼런스 채널이 별도 Cx 핀 필요 | **불충족** | CRX1은 ESD 더미로 설계, 레퍼런스 전극 역할 불가 |
| 소프트웨어 LTA 추종 (C52 DC-block 충돌 여부) | **충돌 없음** | Follow UI는 DC-block과 무관한 소프트웨어 메커니즘 |
| 즉시 적용 가능 여부 | **즉시 적용 불가** | 하드웨어 레퍼런스 전극 추가 없이는 불가 |

**결론**: Follow UI는 Re-ATI 외 자동보정 메커니즘으로 확인되나, **우리 회로에 즉시 적용 불가**. 하드웨어 개정(레퍼런스 전극 추가) 없이는 도입 불가.

### 3.3 LTA halt timeout RESEED + 자동 Re-ATI — 2차 자동보정

**자료 근거**: [AZD004 §5.3]

> "Therefore, the LTA filter is only halted for a maximum time, known as the filter halt period. ... This may also automatically trigger a re-ATI to recalibrate the sensor." [AZD004 §5.3]

stuck-touch 시 LTA halt 타임아웃 후 RESEED와 자동 Re-ATI가 트리거될 수 있음.

**현 펌웨어에서의 차단**:
- CH timeout Disable(SYSTEM_CONTROL MSB bit[2:0]=111)로 1차 차단
- ATI Mode=Disabled로 2차 차단
- 따라서 현 펌웨어에서 이 자동보정 경로는 **의도적으로 비활성화됨**

**잔여 불확실성**: ATI Mode=Disabled 상태에서 LTA halt timeout이 유발하는 자동 Re-ATI가 실제로 발동하는지 여부는 [자료 미명시]. 이중 차단으로 막는다고 추정하나 자료 확인 없음 [추정].

### 3.4 Filter Beta 튜닝 — 드리프트 추적 속도 조절

**자료 근거**: [User Guide §4.7], [AZD004 §5.1~5.3]

LTA filter beta를 크게 하면 환경 드리프트 추적이 느려지고(터치 안정성 향상, 드리프트 보정 느림), 작게 하면 빠르게 추적(드리프트 보정 빠름, 터치 오탐 가능).

- **LTA fast filter beta**: 빠른 환경 변화 시 LTA 추적 가속
- **fast filter band**: 이 빠른 필터가 활성화되는 delta 기준

현 펌웨어는 Filter Beta 레지스터를 명시 write하지 않아 IC 기본값 사용 중. EV-Kit 기준값(NP LTA beta=5)이 우리 환경에 적합한지는 실측 필요 [자료 미명시 — User Guide는 파라미터 존재만 안내, 권고값 없음].

### 3.5 미해결_3 결론 요약

| 메커니즘 | 작동 조건 | 우리 회로 적용 가능 여부 |
|---|---|---|
| LTA IIR 추적 (1차, 자동) | 노터치 상태에서 자동 추적 | **현재 동작 중** (beta 기본값) — 튜닝 여지 있음 |
| Follow UI (인터치 중 자동) | 별도 레퍼런스 전극 + 채널 필요 | **즉시 적용 불가** — 하드웨어 개정 필요 |
| LTA halt timeout Re-ATI (자동) | stuck-touch 시 자동 | **의도적 비활성** (이중 차단) |
| Reseed (수동 트리거) | 절전 진입 등 명시 명령 | **현재 사용 중** — 절전 진입 시 |
| Filter Beta 튜닝 (파라미터) | LTA 추적 속도 조절 | **기본값 사용, 튜닝 가능** |

**최종 결론**: Re-ATI 외 드리프트 자동보정 메커니즘은 존재한다(LTA IIR 추적, Follow UI). 그러나 우리 회로에서 하드웨어 개정 없이 즉시 적용 가능한 것은 **LTA IIR 추적(노터치 구간 자동)** 뿐이다. v3 아키텍처의 "노터치 게이트 후 Re-ATI 허용" 구조는 LTA가 추종하지 못하는 인터치 중 드리프트를, 노터치 확인 후 Re-ATI로 해소하는 보완 설계이다 — AZD125 §8.1 "when the device is not in touch" 조건과 정확히 일치.

## 4. v3 아키텍처 보강/수정/반증 판정 종합

| 미해결 항목 | v3 아키텍처 판정 | 근거 요약 |
|---|---|---|
| 미해결_1: ATI 실패 조건 | **보강** | 터치 중 ATI 금지 원칙이 v3 노터치 게이트와 정합. 자동 ATI 경로(stuck-touch timeout·LTA halt timeout) 차단이 적절한 방어 설계로 확인 [AZD004 §12.7, §5.3] |
| 미해결_2: 드리프트 정량 | **보강** | 온도 드리프트 방향(감소)과 크기(-12~-18 cnt/°C 추정)가 확인됨. 현 임계값이 온도 범위 내 드리프트를 흡수할 수 있는지 SNR ≥ 5 기준 대비 검증 필요 항목 추가 |
| 미해결_3: 자동보정 | **보강+한계확인** | LTA IIR(노터치 구간)이 자동보정 메커니즘으로 동작 중. Follow UI는 적용 불가로 인터치 중 드리프트는 v3 Re-ATI 의존 확정. Filter Beta 튜닝이 잠재적 개선 포인트로 확인 |

## 5. 잔여 미확인 사항 (후속 노드 전달)

다음 항목은 본 노드에서 자료 미명시로 판정되어 후속 검증(08·09 노드) 또는 데이터시트 참조가 필요하다:

1. **ATI_Mode=Disabled 상태에서 Reseed가 ATI를 트리거하는가**: User Guide §3.5.4가 Reseed → ATI 자동 트리거를 명시하나, Disabled 모드에서 차단 여부는 [자료 미명시]. 현 이중 차단(ATI Mode=Disabled + CH timeout Disable)의 실효성은 데이터시트 확인 필요.

2. **ATI_Mode=Disabled 상태에서 LTA halt timeout Re-ATI 발동 여부**: [AZD004 §5.3]의 "may also automatically trigger a re-ATI"가 ATI Disabled 상태에서도 유효한지 [자료 미명시].

3. **Filter Beta 기본값 확인**: 현 펌웨어가 기본값을 사용 중이나 실제 IC 기본값이 EV-Kit 예제 기준값(LTA beta=5, Counts beta=2)과 동일한지 [자료 미명시]. 기본값과 EV-Kit 설정값이 다를 수 있음.

4. **MULT/COMP 포화 한계값**: ATI 실패의 정확한 물리적 경계 조건 — IQS323 데이터시트 확인 필요 [자료 미명시].

5. **현 임계값 SNR 검증**: AZD125 §10.1의 SNR ≥ 5 기준 대비 현 펌웨어 임계값 설정값이 충족되는지 실측 필요 [자료 미명시 — 현 임계값 수치 파악 선행 필요].
