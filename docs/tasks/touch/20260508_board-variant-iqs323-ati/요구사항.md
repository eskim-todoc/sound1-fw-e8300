# IQS323 ATI 보상값 보드 변종 매크로 정리 — 요구사항

**TL;DR**: `tdc_drv_iqs323.c` 의 ATI 보상값 6 개를 Mini/Develop 보드별로 분기하는 `#if 1 // Mini Board` / `#else // Develop Board` 형태를 LED 작업과 동일한 패턴(`TDC_BOARD_VARIANT` 매크로 + `#elif`/`#else #error`) 로 정리. 디폴트 = Mini.

작성일: 2026-05-08
작업 브랜치: `claude_feature_ota-dfu-fw-variant-led` (base: `claude_develop`) — LED 작업과 동일 브랜치 (사용자가 한 번의 빌드로 함께 검증)
모듈/슬러그: `touch/20260508_board-variant-iqs323-ati`
연계: ↔ [`LED/20260508_ota-dfu-fw-variant`](../../LED/20260508_ota-dfu-fw-variant/) (동일 패턴 — 빌드 변종 매크로 정리)

---

## 1. 배경

[`src/2__cm3/Cortex-M3-src/systemControl/tdc_drv_iqs323.c`](../../../../src/2__cm3/Cortex-M3-src/systemControl/tdc_drv_iqs323.c) L502~517 에 사전 측정된 Sensor 0 ATI 보상값 6 개 매크로가 있고, 두 보드 변종(Mini / Develop)에 따라 값이 달라 `#if 1` / `#else` 로 분기:

```c
/* 사전 측정된 Sensor 0 ATI 보상값 (고정 상수) — ATI Mode=Full 그대로 유지 */
#if 1 // Sound1 Mini Board
#define TDC_DRV_IQS323_ATI_SETUP_LSB 0x0C
... (Mini 값 6 개)
#else // Sound1 Develop Board
#define TDC_DRV_IQS323_ATI_SETUP_LSB 0x0C
... (Develop 값 6 개)
#endif
```

**문제**: `#if 1` 형태가 ① 어느 쪽이 디폴트인지 코드만 봐서는 모호 (주석 참고 필요), ② Mini ↔ Develop 전환을 위해 `1` 을 `0` 으로 바꿔야 하는데 의미가 명시적이지 않고, ③ `Board_is_TD_DEV_ver_1_4` 등 `processorDirective.h` 의 기존 보드 식별 매크로 체계와 무관해 보드 종류 컨텍스트가 두 곳으로 분산.

---

## 2. 목표

LED 작업의 `TDC_FW_VARIANT` 와 동일 패턴으로 `TDC_BOARD_VARIANT` 매크로 도입 — Mini / Develop 두 변종을 명시적 `#if`/`#elif`/`#else #error` 분기로 정리. 디폴트 = Mini (현재 활성 변종).

---

## 3. 범위

### In-scope
- `tdc_drv_iqs323.c` 의 ATI 보상값 분기 영역만 매크로 정리
- 빌드 매크로 `TDC_BOARD_VARIANT_MINI` / `TDC_BOARD_VARIANT_DEVELOP` 두 값 정의
- 변종 의미·맵핑·디폴트 헤더 주석 문서화
- 기존 ATI 매크로(`TDC_DRV_IQS323_ATI_*_LSB/MSB`) 6 개의 정의 위치만 변경, 이름·값·사용처는 무변경

### Out-of-scope
- `processorDirective.h` 의 `Board_is_*` 매크로 체계와 통합 (별개 컨텍스트 — 기존 매크로는 GPIO 핀 매핑 등 보드 하드웨어 일반, `TDC_BOARD_VARIANT` 는 IQS323 캘리브레이션 캡슐화. 향후 통합 검토는 별개 작업)
- 다른 ATI/터치 매개변수 변경
- 다른 드라이버에 `TDC_BOARD_VARIANT` 적용 (현 단계 IQS323 만 — 필요 시 후속)

---

## 4. 수용 기준 (Acceptance Criteria)

- AC-1. `TDC_BOARD_VARIANT` 미정의 시 디폴트 = Mini (현재 활성 값과 동등).
- AC-2. `TDC_BOARD_VARIANT == TDC_BOARD_VARIANT_DEVELOP` 정의 시 ATI 6 개 값이 Develop 보드 측정값으로 매핑.
- AC-3. 두 매크로 값 외 정의 시 `#error` 로 빌드 실패.
- AC-4. 분기된 ATI 매크로 6 개 이름·사용처는 변경 없이 보존 → `write_ati_compensation()` 호출 경로·동작 동등.
- AC-5. 기존 `#if 1 // Sound1 Mini Board` / `#else // Sound1 Develop Board` 흔적 제거.
- AC-6. 변종 매크로 블록은 의도·맵핑·디폴트·사용법을 한눈에 보이는 헤더 주석 + 표로 문서화.
- AC-7. LED 작업의 `TDC_FW_VARIANT` 와 명명·구조 일관 (다른 변종도 동일 패턴 적용 가능).

---

## 5. 결정 / 선택지

### 결정_1: file-local 매크로 (`processorDirective.h` 통합 안 함)
이유: ① 변종이 IQS323 ATI 보상값에만 영향 → 관심사 응집, ② `Board_is_*` 는 핀 매핑 등 보드 일반, `TDC_BOARD_VARIANT` 는 캘리브레이션 캡슐화 — 의미적 레이어 분리, ③ LED 의 `TDC_FW_VARIANT` 와 동일 file-local 패턴으로 일관성. 향후 다른 드라이버 영향 시 공용 헤더로 승격 가능 (비파괴).

### 결정_2: 디폴트 = Mini
이유: 현재 코드 상태가 `#if 1 // Mini` 이므로 현 활성 변종을 보존. 디폴트 전환으로 사용자 현 setup 깨짐 회피.

### 결정_3: 매크로 명 — `TDC_BOARD_VARIANT` (사용자 제안 그대로)
이유: LED 의 `TDC_FW_VARIANT` 와 명명 패턴 일관 (`TDC_<KIND>_VARIANT`).

### 결정_4: 변종 값 명 — `_MINI` / `_DEVELOP`
이유: 코드 주석에 이미 사용된 표현(`Sound1 Mini Board` / `Sound1 Develop Board`) 그대로 채택. 약어 회피로 가독성 ↑.

---

## 6. 위험·완화

### 위험_1: `Board_is_*` 매크로 체계와 의미 중복
보드 종류라는 큰 개념이 `Board_is_OTE_VER_*` (핀 매핑) 와 `TDC_BOARD_VARIANT` (IQS323 ATI) 두 곳에 존재. 향후 보드 분기가 늘어나면 통합 필요. → 본 작업은 IQS323 ATI 한 군데만 정리, 본문에 별개 컨텍스트임을 명시. 통합은 별개 작업.

### 위험_2: 디폴트 = Mini 가 다른 환경에서 잘못 빌드
다른 개발자가 Develop 보드에서 빌드 시 명시적으로 `TDC_BOARD_VARIANT_DEVELOP` 설정 안 하면 ATI 가 Mini 값으로 들어가 ATI 보상 어긋남. → 헤더 주석에 사용법 명시 + 빌드 옵션 안내. 향후 빌드 시스템에서 보드별 자동 분기 권고.

---

## 7. 검증 절차

V1. Mini (디폴트) 빌드 — 매크로 미정의 상태에서 컴파일 통과, IQS323 ATI 6 개 값이 Mini 측정값으로 매핑 (실기 터치 동작 정상).
V2. Develop 빌드 — `#define TDC_BOARD_VARIANT TDC_BOARD_VARIANT_DEVELOP` 또는 빌드 옵션 부여 시 ATI 6 개 값이 Develop 측정값으로 매핑.
V3. (선택) 잘못된 매크로 값 — `#define TDC_BOARD_VARIANT 99` 시 `#error` 발동.
V4. 회귀 — 본 작업 외 IQS323 동작 (init, RE-ATI, sensor read 등) 무변경.
