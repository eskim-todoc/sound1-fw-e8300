# IQS323 ATI 보상값 보드 변종 매크로 정리 — 분석

**TL;DR**: ATI 보상값은 IQS323 드라이버 단일 영역에만 영향 → file-local 매크로로 응집. 디폴트 = Mini (현재 `#if 1` 가 Mini 선택). 명명 `TDC_BOARD_VARIANT` 로 LED 의 `TDC_FW_VARIANT` 와 일관. `Board_is_*` 와는 의도적 분리 (핀 매핑 vs 캘리브레이션, 의미 레이어 다름).

작성일: 2026-05-08

---

## 1. 변경 영역 식별

`grep -n "TDC_DRV_IQS323_ATI_" tdc_drv_iqs323.c` 로 ATI 매크로 사용 위치 점검:

| 매크로 | 정의 위치 | 사용 위치 |
|---|---|---|
| `TDC_DRV_IQS323_ATI_SETUP_LSB/MSB` | L504/505 (Mini), L511/512 (Develop) | `write_ati_compensation()` |
| `TDC_DRV_IQS323_ATI_MULT_LSB/MSB`  | L506/507, L513/514                 | 동일 |
| `TDC_DRV_IQS323_ATI_COMP_LSB/MSB`  | L508/509, L515/516                 | 동일 |

→ 6 개 매크로 모두 한 함수에서만 사용. 정의 위치만 매크로 분기로 정리하면 충분. 이름·사용처 무변경.

---

## 2. 매크로 위치 후보 비교

| 후보 | 장점 | 단점 |
|---|---|---|
| **A. tdc_drv_iqs323.c 자체** | 관심사 응집, ATI 값과 분기 한 곳 | 다른 드라이버에 보드 분기 필요 시 헤더 분리 필요 |
| B. 신규 헤더 `tdc_board_variant.h` | 다중 파일 사용 시 단일 진실 | 현재 단일 파일만 영향 — 과잉 |
| C. processorDirective.h 통합 | 보드 식별 매크로 일원화 | 의미 레이어 다름 (핀 매핑 vs 캘리브레이션) — 응집 손상 |

→ **A 선택**. 향후 다른 드라이버에 보드 분기 필요 시 B 로 승격 가능 (비파괴).

---

## 3. `Board_is_*` (processorDirective.h) 와의 관계

`processorDirective.h` 의 보드 식별 매크로:
- `Board_is_TD_DEV_ver_1_4` — TD Dev (개발) 보드 v1.4
- `Board_is_OTE_VER_1_3` / `_1_4` / `_1_5` — OTE 보드 (현재 `_1_5` 활성)

**의미 레이어 비교**:
- `Board_is_*` : GPIO 핀 매핑, EEPROM SPI 위치 등 **하드웨어 일반**
- `TDC_BOARD_VARIANT` : IQS323 ATI 보상값 등 **드라이버 캘리브레이션**

**Mini/Develop ↔ OTE/TD_DEV 매핑 미확인** — 사용자 코드 주석에 "Sound1 Mini" / "Sound1 Develop" 표현이 IQS323 한 곳에만 등장. 기존 `Board_is_*` 의 OTE/TD_DEV 와 1:1 대응인지 명시되지 않았다.

후보 분기 형태:

| 후보 | 형태 | 평가 |
|---|---|---|
| (R-1) 독립 매크로 (선택) | `TDC_BOARD_VARIANT` 자체 | 현재 채택. 의미 레이어 분리. 사용자 의도 일치. |
| (R-2) `Board_is_*` 자동 매핑 | `#if defined(Board_is_TD_DEV_*) #define TDC_BOARD_VARIANT TDC_BOARD_VARIANT_DEVELOP #else ...` | Mini/Develop ↔ OTE/TD_DEV 매핑 가정 필요. 가정 깨질 시 잘못된 ATI. 기각. |
| (R-3) `Board_is_*` 직접 사용 | `#if defined(Board_is_TD_DEV_*) ... ATI Develop 값 ...` | 사용자 요청 패턴(`TDC_BOARD_VARIANT`) 미충족. 기각. |

→ **R-1 선택**. 향후 매핑 명확해지면 R-2 로 통합 가능. 현 시점은 ATI 캘리브레이션이라는 좁은 개념을 명확히 캡슐화.

## 4. 디폴트 변종 결정

| 후보 | 평가 |
|---|---|
| **(D-1) Mini 디폴트** | 현재 `#if 1 // Mini` = Mini 활성 → 동등 보존. 사용자 현 setup 호환. **선택**. |
| (D-2) Develop 디폴트 | 현 활성 변종 변경 → 사용자 현 setup 깨짐. 비채택. |
| (D-3) 디폴트 없음 (`#error`) | 안전하지만 빌드 옵션 항상 필요. LED 작업 디폴트 정책과 비대칭. 비채택. |

→ **D-1 선택**.

---

## 5. 매크로 명 / 변종 값 결정

| 항목 | 값 | 근거 |
|---|---|---|
| 매크로 명 | `TDC_BOARD_VARIANT` | 사용자 제안. LED 의 `TDC_FW_VARIANT` 와 일관. |
| 값 명 | `TDC_BOARD_VARIANT_MINI` / `TDC_BOARD_VARIANT_DEVELOP` | 코드 주석의 "Sound1 Mini Board" / "Sound1 Develop Board" 그대로 채택 (약어 회피, 가독성). |

---

## 6. 분기 형태

LED 작업의 `TDC_FW_VARIANT` 와 동일 형태:

```c
#define TDC_BOARD_VARIANT_MINI     0
#define TDC_BOARD_VARIANT_DEVELOP  1

#ifndef TDC_BOARD_VARIANT
#define TDC_BOARD_VARIANT  TDC_BOARD_VARIANT_MINI   /* 디폴트: Mini 보드 */
#endif

#if (TDC_BOARD_VARIANT == TDC_BOARD_VARIANT_MINI)
    /* Mini ATI 6 개 */
#elif (TDC_BOARD_VARIANT == TDC_BOARD_VARIANT_DEVELOP)
    /* Develop ATI 6 개 */
#else
    #error "TDC_BOARD_VARIANT 미지원 값. ..."
#endif
```
