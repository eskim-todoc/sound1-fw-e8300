# 그라운드_1 — IQS323 NP/LP/ULP/Halt 전력소비 정량 비교

**TL;DR**: 데이터시트 §3.4 전류표는 원문 PDF 재대조 결과 기존 정리본과 완전히 일치(오차 0건). 다만 Sound1 실제 구성을 코드로 전수 확인한 결과, 측정조건과 차이가 채널수·변환주파수 2가지뿐 아니라 총 5가지이며, 그중 인터페이스 선택(스트리밍 vs 이벤트)은 별도 응용노트(AZD004)가 전류에 "심각한(severe)" 영향이라 명시한 항목이라 채널수 감소 효과와 반대 방향으로 작용할 수 있다. 채널수 비례 근사는 타당하지 않다고 판단하며, 근거와 함께 정직한 범위 추정치·NP:LP:ULP:Halt 비율을 제시한다.

---

## 1. 데이터시트 §3.4 원문 재확인

원문(`docs/참고/touch/iqs323_datasheet.pdf`, `pdftotext -layout` 변환 후 656~677행, 원문 p.11) 직접 대조 결과, 아래 표는 기존 정리본(`docs/참고/touch/데이터시트/01_개요·전기·타이밍.md:176~191`)과 **완전히 일치**한다 — 재확인 과정에서 수치 오차 0건.

### 표_1 — Current Consumption (원문 그대로)

측정조건 원문 인용:

> Inductive Mode Setup: ATI Target = 256, FOSC = 14 MHz
> Self-capacitive Mode Setup: ATI Target = 512, Fxfer = 500 kHz
> Mutual capacitive Mode Setup: ATI Target = 512, Fxfer = 500 kHz
> Interface Selection: Event mode

| Power mode | Active channels | Report rate [ms] | 1.8V [µA] | 3.3V [µA] |
|---|---|---|---|---|
| Normal Power | Inductive (1 coil) | 10 | 128 | 129 |
| | **Self-capacitive (3 channels)** | **16** | 125 | **125** |
| | Mutual Capacitive (2 channels) | 16 | 171 | 172 |
| Low Power | Inductive (1 coil) | 80 | 11.0 | 11.5 |
| | **Self-capacitive (3 channels)** | **60** | 37.0 | **37.5** |
| | Mutual Capacitive (2 channels) | 60 | 50.0 | 50.5 |
| Ultra Low Power | Inductive (1 coil) | 200 | 6.50 | 7.00 |
| | **Self-capacitive (3 channels)** | **160** | 4.00 | **4.00** |
| | Mutual Capacitive (2 channels) | 160 | 9.00 | 9.00 |
| Halt | NA | 3000 | 2.00 | **2.00** |

Sound1이 self-capacitive 단일채널 구성이므로(§2 참조) 굵게 표시한 **Self-capacitive (3 channels)** 행을 기준선으로 삼는다. 1.8V/3.3V 값이 self-cap 행에서는 사실상 동일해(125/125, 37.0/37.5, 4.00/4.00, 2.00/2.00) VDD 정확값에 대한 민감도가 낮다 — Sound1의 정확한 IQS323 공급 전압은 **[미확인]**(하드웨어 스키매틱 미대조)이나, 이 표에 한해서는 결론에 미치는 영향이 미미하다. 이하 3.3V 열을 기준으로 서술한다.

## 2. Sound1 실제 구성 대조 (코드 직접 확인)

`tdc_touch_iqs323.c` 전체를 직접 읽고 레지스터 write 지점을 전수 확인한 결과다.

### 표_2 — 측정조건 vs Sound1 실제값

| 항목 | 데이터시트 측정조건 | Sound1 실제값 | 근거 |
|---|---|---|---|
| 채널 수 | Self-cap **3채널** | **CH0 1채널만** (CH1·CH2 disable) | `sensor_setup()` — `REG_SENSOR1_SETUP`(0x40)=0x0000, `REG_SENSOR2_SETUP`(0x50)=0x0000, `REG_SENSOR0_SETUP`(0x30)=0x0101 (`tdc_touch_iqs323.c:266~282`) |
| 변환주파수 Fxfer | **500 kHz** | **1.00 MHz** | `write_register(REG_CONV_FREQ, 0x7F, 0x05)` → 0x057F → Period=5 → Table A.1 기준 1.00MHz (`tdc_touch_iqs323.c:316`, 데이터시트 원문 Table A.1, 원문 p.62 인근) |
| ATI Target | **512** | **약 400 (근사)** | `REG_SENSOR0_ATI_SETUP`(0x36)=0x040C 명시 write(`tdc_touch_iqs323.c:437`) — 이 값은 공장 기본값과 동일(레지스터맵 A.12 기본값도 0x040C). ATI Base(0x37)는 코드에서 전혀 write되지 않아 기본값 0x0064(=100)로 남음. 공식 `ATI Target = ACTUAL ATI BASE × (ATI Resolution Factor/16)`(원문 p.18, 부록 A.12 원문 p.55)에 Resolution Factor=64(0x040C에서 도출) 대입 시 100×4=400 |
| 인터페이스 선택 | **Event mode** (bit7=1) | **Streaming** (bit7=0) | `REG_SYSTEM_CONTROL`(0xC0) write 전 지점 — `ack_reset()`(0x01), `beta_power_settings()`(0x50), `apply_settings()` Re-ATI(0x54)·RESEED(0x58), `tdc_touch_iqs323_re_ati()`(0x54), `tdc_touch_iqs323_reseed()`(0x58) — **모두 bit7=0**. 원문 부록 A.30(원문 p.61): "Bit 7: Interface Selection · 0: I2C Streaming · 1: I2C Events" |
| LP 리포트레이트 | 60ms (self-cap 특성) | **100ms** | `write_register(REG_LP_REPORT_RATE, 0x64, 0x00)` = 100 (`tdc_touch_iqs323.c:319`, 코드 주석 "LP report 100ms"로 명시) |
| NP 리포트레이트 | 16ms (self-cap 특성, 추정) | **[미확인]** — 레지스터(0xC1) 전혀 write 안 됨, 공장 기본값 0x0000 유지 | 코드 전체 grep 결과 `0xC1` write 지점 0건. 레지스터맵 상 0xC1 기본값 0x0000(원문 p.36 인근). "0"이 "가능한 최고속(자유 실행)"을 의미하는지 데이터시트에 명시적 서술 없음 — **[미확인]** |

> [!IMPORTANT]
> **인터페이스 선택(Streaming vs Event) 차이는 기존 배경자료가 명시적으로 나열하지 않았던 항목**이다. 이번 재검토에서 레지스터 비트 직접 디코딩으로 새로 확인했으며, §3에서 보듯 전류 영향의 방향과 크기가 채널수 차이 못지않게(오히려 더 크게) 중요할 수 있다.

### 참고 — 명칭 혼동 주의

Sound1 코드 내 `g_in_ulp_mode` / `tdc_touch_iqs323_set_ulp()` (`tdc_touch_iqs323.c:36~52`)와 `tdc_touch_time.h`의 `TDC_TOUCH_ULP_WAKE_MS`는 **IQS323 하드웨어의 ULP 전력모드가 아니라 Sound1 자체 CM3 MCU 절전(SYSCLK 강하 + 주기적 웨이크업)을 가리키는 별도 명칭**이다. 코드 주석(`tdc_touch_iqs323.c:497~499`)도 "절전도 노말과 동일한 IQS323 설정... CM3 클럭만 절감"이라 명시한다. IQS323 칩 자체는 `REG_PM_TIMEOUT=0`(`tdc_touch_iqs323.c:320~323`)로 항상 Normal Power에 고정되어 있어, 현재 코드에서 IQS323의 하드웨어 LP/ULP/Halt는 **전혀 진입하지 않는다**. 본 문서의 NP/LP/ULP/Halt는 전부 IQS323 칩 자체의 전력모드를 지칭한다.

## 3. 차이 항목별 전류 영향 분석

### 차이_1 — 채널 수 (3채널 → 1채널)

방향: 감소. 크기: **비례(÷3) 근사는 타당하지 않음**.

- 데이터시트 자체 데이터로 반증 가능: 동일 리포트레이트(16ms)에서 Self-cap **3채널**=125µA인데 Mutual-cap **2채널**=172µA로 채널이 더 적은데 전류가 더 높다. 즉 전류는 채널수만으로 결정되지 않고 센싱 방식별 고유 비용(고정 오버헤드 포함)이 더 크게 작용한다.
- self-cap 1채널 데이터 포인트가 데이터시트에 존재하지 않아 고정/가변 성분을 정밀 분리할 근거가 없다 — **[미확인]**.

### 차이_2 — 변환주파수 (500kHz → 1MHz)

방향: **증가 쪽 근거 있으나 정량 불가**.

- AZD004 응용노트 원문(p.5, azd004 pdftotext 217~220행): "the rate at which the sensing electrode is charged and discharged is known as the charge transfer frequency... This has some implications on... the duration of the sensing period and **overall system current consumption**." — Fxfer가 전류소비에 영향을 준다는 것은 원문이 명시하나 방향(증가/감소)·크기는 정량화되어 있지 않다.
- 물리적으로는 스위치드커패시터 특성상 스위칭 주파수 비례 성분(2배 시 최대 2배 증가)과, 동일 변환 횟수를 더 짧은 시간에 끝내고 유휴로 복귀하는 성분(오히려 감소)이 상충한다 — 이 균형점은 **[미확인]**.
- 참고로 AZD004는 "self-capacitive 기술은 통상 약 250kHz에서 동작"(원문 p.6)이라 서술 — 데이터시트 특성측정(500kHz)·Sound1 실제값(1MHz) 둘 다 이 "통상값"보다 높다.

### 차이_3 — ATI Target (512 → 약 400)

방향: **전류와 직접 연관 근거 없음** — 무시 가능한 것으로 추정.

- ATI Target·ATI Base·Resolution Factor 관련 서술(원문 p.16~19, §5.9~5.11) 전체를 확인했으나 카운트/감도/Re-ATI 경계 계산에만 관여하고 전류표와 연결하는 서술은 없음. AZD004에서도 "current"·"power" 키워드와 "ATI" 키워드가 함께 나오는 문맥 검색 결과 연관 서술 없음.

### 차이_4 — 인터페이스 선택 (Event → Streaming) — **가장 중요한 발견**

방향: **증가**. 크기: 정량화 안 됨이나 정성적으로 강함.

- AZD004 원문(p.27, azd004 pdftotext 1508~1515행), §12.4 "Streaming and Event Mode": "I2C streaming mode refers to the continuous reporting of data at the relevant power mode report rate... **However, the high amount of time spent doing communication has a severe impact on current consumption.**"
- 메인 데이터시트 원문(p.29, §8.11)도 "The I2C interface is selected using the Interface Selection bit in the System Control register"라 명시해 §3.4 표가 이 비트에 의존적임을 확인.
- 추론(자체, 인용 아님): 이 severe 영향은 통신 빈도에 비례할 가능성이 높다 — 스트리밍이면 리포트레이트마다 RDY 토글+통신준비가 발생하는데, NP는 4모드 중 리포트레이트가 가장 빠르므로(원문 표 기준 16ms) 이 페널티가 **NP에서 가장 크게, Halt에서는 사실상 0으로** 작용할 것으로 추정된다. Halt는 "no conversions or processing are done"(§5.2, 원문 p.14)이라 인터페이스 선택 자체가 무관하다.
- **직전 선행분석(`docs/tasks/touch/20260619_touch-fullati-control/에이전트-로그/06_분석_컨버전전력.md`, 2026-06-19, maturity: in-progress)도 독립적으로 "Sound1은... 스트리밍이라 절댓값은 다르다"고 확인**했으나, 이 severe 영향 서술(AZD004 §12.4)은 인용하지 않은 채 "단일채널이면... 표값보다 낮을 것"이라고만 결론지었다 — 본 문서는 이 지점을 보강한다. 채널수 감소(전류 ↓)와 인터페이스(전류 ↑, severe)가 반대 방향이라 순효과 방향조차 확신하기 어렵다.

### 차이_5 — LP 리포트레이트 (60ms → 100ms)

방향: **감소**(같은 조건 내에서 리포트레이트가 느려질수록 전류가 준다는 경향은 표 자체의 NP/LP/ULP 내부 추이로 확인됨).

### 차이_6 — NP 리포트레이트 (미기록, [미확인])

방향 불명. 레지스터가 공장 기본값(0x0000)에 머물러 있고 이 값의 정확한 동작 의미(자유실행 여부)를 원문에서 확인하지 못했다. 만약 "0=최고속 자유실행"이 맞다면 Sound1의 NP 실제 주기는 16ms보다 빠를 수 있어 전류가 오히려 더 높아지는 방향으로 작용할 가능성이 있다 — **[미확인]**.

## 4. 채널 수 비례 근사의 타당성 — 직접 답변

**결론: 타당하지 않다.** 근거:

1. **표_1 자체의 교차검증**(§3 차이_1)에서 self-cap 3채널(125µA) vs mutual-cap 2채널(172µA)이 채널수와 반비례하지 않음을 보였다 — 채널수 단독으로 전류를 설명할 수 없다.
2. **ULP는 채널수 비례가 원천적으로 성립하지 않는 구조**다. 메인 데이터시트(원문 p.14, §5.2): "Ultra-low power mode (ULP)... Intended for rapid wake-up from deep sleep on a **single channel**... **Other sensor channels are sampled at a slower rate** in order to optimize power consumption." AZD004(원문 p.21, azd004 1145~1149행)도 독립적으로 동일 메커니즘을 "AutoProx"라는 이름으로 확인: "on multi-channel devices, ULP will only sample on a single channel, keeping all other channels dormant." 즉 데이터시트의 ULP 3채널 특성치(4.00µA)는 "빠른 wake-up 채널 1개 + 느린 채널 2개"의 합성값이며, Sound1처럼 **채널이 원래 1개뿐인 구성은 이미 그 "wake-up 채널"과 동일**하다 — "나머지 채널을 느리게 돌려 절약"할 여지 자체가 없다. 따라서 나이브 3분의 1 근사(4.00/3≈1.33µA)는 과대 절감 추정이며, 실제로는 4.00µA에 더 가까울 것으로 추정한다.
3. **인터페이스 선택(차이_4)이 채널수보다 크거나 반대 방향으로 작용할 수 있다** — AZD004가 명시적으로 "severe"라 표현한 유일한 요인이 인터페이스 선택이며, 채널수 차이에는 그런 강한 표현이 붙은 서술을 찾지 못했다.

## 5. Sound1 구성 근사 전력소비치 (범위 제시)

정밀한 단일 수치는 위 5~6가지 차이가 서로 다른 방향·미확인 크기로 작용해 데이터 근거만으로는 도출할 수 없다고 판단한다. 대신 방향이 확인된 근거를 바탕으로 범위를 제시한다.

### 표_3 — 근사 범위 (3.3V 기준)

| 모드 | 데이터시트 원본(3채널) | 나이브 채널비례(÷3) | Sound1 추정 범위 | 비고 |
|---|---|---|---|---|
| NP | 125 µA | 41.7 µA | **약 40µA ~ 125µA 이상** (상한 불확정) | 채널수(↓)와 스트리밍 severe(↑)가 반대방향. 스트리밍 페널티는 리포트레이트가 가장 빠른 NP에서 가장 크게 작용할 것으로 추정(자체 추론) |
| LP | 37.5 µA | 12.5 µA | **약 12µA ~ 37.5µA** | 리포트레이트가 더 느림(100ms>60ms, 감소요인)과 스트리밍(증가요인)이 일부 상쇄 |
| ULP | 4.00 µA | 1.33 µA | **1.33µA ~ 4.00µA, 상한(4.00µA)에 더 가까울 것으로 추정** | 분산 ULP 메커니즘상 단일채널은 "나머지 채널 저속화" 이점을 받을 수 없음(§4-2) |
| Halt | 2.00 µA | 2.00 µA(채널무관) | **약 2.00µA (신뢰도 가장 높음)** | Halt는 "no conversions or processing"(원문 §5.2)이라 채널수·Fxfer·인터페이스 모두 무관 |

> [!NOTE]
> LP 구간에 대해 표_1 내부 데이터(60ms→37.5µA, 160ms→4.00µA)로 리포트레이트 100ms 지점을 보간해 봤으나, 단순 반비례 모델과 "고정오프셋+반비례" 모델이 각각 약 11.7µA·약 24.8µA로 2배 이상 차이가 나 — 데이터 2점만으로는 모델 선택 자체가 불확정이다. 이는 점추정치를 제시하지 않고 범위로 제시하는 이유를 뒷받침하는 근거로 첨부한다(가공의 정밀값을 만들지 않기 위함).

**정확한 절대치는 실측이 필요하다** — 이는 이미 진행 중인 프로젝트 방향(직전 커밋 "터치 무선 계측 준비", `dev-ver1.0.2-touch-measure`)과 일치한다.

## 6. NP:LP:ULP:Halt 비율

### 표_4 — 데이터시트 원본 비율 (self-cap 3채널, 3.3V, 원문 그대로 산출)

```
NP : LP : ULP : Halt = 125 : 37.5 : 4.00 : 2.00
                      = 62.5 : 18.75 : 2 : 1   (Halt=1 기준 정규화)
```

- NP 대비 LP = 30% (LP는 NP의 약 3.3분의 1)
- NP 대비 ULP = 3.2%
- NP 대비 Halt = 1.6%

### Sound1 구성에서의 예상 변화 방향 (비율 자체를 새로 산출하지 않고 방향만 제시)

- **ULP:NP 비율은 데이터시트의 3.2%보다 높아질 가능성이 크다** — §4-2에서 논한 대로 ULP 절대치가 나이브 근사보다 표값(4.00µA)에 더 가깝게 유지되는 반면, NP는 스트리밍 페널티로 오히려 원래보다 높아질 잠재력이 있어 분모(NP)가 커지는 동시에 분자(ULP)도 절감폭이 작으므로, 두 효과가 겹치면 비율 방향은 사례에 따라 다를 수 있다 — **정확한 방향은 [미확인]**, 다만 절대적 절감폭(NP 대비 ULP가 훨씬 낮다는 큰 그림)은 유지될 것으로 본다.
- **Halt:NP 비율은 1.6%보다 낮아질 가능성이 있다** — Halt는 약 2.00µA로 거의 고정인 반면 NP가 스트리밍 영향으로 상승한다면 분모가 커져 비율은 낮아진다.
