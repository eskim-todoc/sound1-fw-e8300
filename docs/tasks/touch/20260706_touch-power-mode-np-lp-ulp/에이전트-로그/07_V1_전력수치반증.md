# 검증_1 — 그라운드_1 전력수치 반증 시도

**TL;DR**: 그라운드_1의 §3.4 전류표(원문 전수 재대조 오차 0건)와 측정조건 차이 5종의 레지스터값은 코드·PDF와 전부 일치했다. 핵심 주장 인터페이스 선택이 채널수보다 전류에 더 크게 기여할 수 있다는 azd004 §12.4 severe 인용은 정확하나, 두 요인의 상대크기를 비교하는 정량 서술이 원문에 없어 이 비교는 반증도 확증도 불가능하다. 채널수 비례 근사 무효 결론은 ULP에서만 강하게 뒷받침되며 후보_2(05)와 정합한다.

## 3. 핵심 주장 반증 시도 — "인터페이스 선택이 채널수보다 전류에 더 크게 기여할 수 있다"

### 3.1 azd004 §12.4 원문 재확인

`azd004_layout.txt:1508~1524`를 직접 재확인한 전문:

> "I2C streaming mode refers to the continuous reporting of data at the relevant power mode report rate... The device will open a communication window after every measurement cycle, allowing the master to read the newest measurement data. This mode is useful for debugging or logging purposes... **However, the high amount of time spent doing communication has a severe impact on current consumption.**"
>
> "Event mode allows the device to bypass the communication window when no activity is sensed. Event mode is usually enabled since the master does not want to be interrupted unnecessarily during every cycle if no activity occurs."

그라운드_1의 인용은 이 원문과 정확히 일치한다. **인용 자체는 반증되지 않았다.**

### 3.2 반증 시도_1 — 두 요인의 상대크기를 직접 비교하는 서술이 존재하는가

§12.4 전문(위 인용 포함 전체 단락, `:1508~1567`)을 재확인했으나 **"severe"가 어느 정도의 배율인지 나타내는 수치·비율 서술은 어디에도 없다.** 채널수 효과 쪽도 데이터시트 §3.4 표 자체 외에는 별도의 정량 서술이 없다(그라운드_1도 이를 [미확인]으로 이미 인정). 즉:

- 인터페이스 선택 효과: 방향(스트리밍↑) 확인, 크기 미확인
- 채널수 효과: 방향(다채널→소채널 시 감소 경향) 확인, 크기 미확인

**두 요인 다 크기가 미확인인 상태에서 "어느 쪽이 더 큰가"를 결정할 수 있는 정량적 근거는 원문 어디에도 없다.** 그라운드_1의 논거(§4-3)를 다시 읽으면, 실제로는 "severe"라는 정성적 강조어가 인터페이스 선택에는 붙어 있고 채널수에는 그런 표현이 없다는 **어휘 강도의 비대칭**을 근거로 삼고 있다 — 이는 "AZD004가 채널수 효과를 severe라고 표현하지 않았다"는 사실이지 "채널수 효과가 인터페이스 효과보다 작다"는 것을 논리적으로 함의하지 않는다(서술 누락이 크기의 증거는 아님). 따라서 **"인터페이스 선택이 채널수보다 더 크게 기여할 수 있다"는 비교 주장 자체는 원문으로 반증할 수도 확증할 수도 없는, 정량 근거가 없는 추론이다.**

다만 그라운드_1은 이 부분에서 "~할 수 있다"(may/could) 수준의 헤지 표현을 일관되게 사용했고 "정량화 안 됨"이라고 스스로 명시했다 — **할루시네이션은 아니며, 적절히 조심스러운 추론**이다. 다만 §4 결론의 "타당하지 않다"는 단정 표현이 이 특정 비교 논거(어휘 강도 비대칭)만으로 정당화되는 강도보다는 다소 세게 들린다는 점은 지적할 필요가 있다.

### 3.3 반증 시도_2 — AZD004가 애초에 IQS323에 적용 가능한 문서인가

AZD004가 IQS323 고유 특성이 아니라 여러 Azoteq 제품군을 아우르는 일반 응용노트라, §12.4의 "severe" 서술이 IQS323에 실제로 적용되는지 의문을 제기해 반증을 시도했다. 그러나 메인 데이터시트 자체가 이를 직접 연결한다 — `iqs323_datasheet_layout.txt:903`: **"The NP, LP and ULP power modes are described in the AZD004 application note."** 이는 그라운드_1도 후보_2도 명시적으로 인용하지 않은 연결고리이나, IQS323 데이터시트가 스스로 "우리 파워모드의 상세 설명은 AZD004를 보라"고 지목한 것이므로 **AZD004 §12.4의 스트리밍/이벤트 서술이 IQS323에 실제로 적용된다는 근거는 오히려 강화된다** — 이 반증 시도는 실패했다(오히려 그라운드_1 결론을 보강하는 방향으로 귀결).

### 3.4 반증 시도_3 — 방향성 자체가 뒤집힐 가능성

§3.4 표는 4개 모드(NP/LP/ULP/Halt) 전부 "Interface Selection: Event mode" 단일 조건에서 측정되었다(`:661`, 표 헤더가 전체 표에 공통 적용). 스트리밍 전환 시 전류가 증가하는 메커니즘(매 리포트 주기마다 통신 창이 강제로 열림, §12.3 Figure 12.3 확인)은 물리적으로 "통신 빈도 × 통신 1회당 비용"에 비례할 개연성이 높고, 이는 리포트 주기가 가장 짧은 NP에서 가장 크고 Halt(3000ms, 게다가 Halt는 "no conversions or processing"이라 인터페이스 자체가 무관, `:901`)에서는 사실상 0이라는 그라운드_1의 방향성 추론은 §12.3 스트리밍 시퀀스 다이어그램(매 리포트 주기=매 통신창) 구조와 논리적으로 정합해, 방향을 뒤집을 반증 근거를 찾지 못했다.

| 하위 주장 | 판정 |

## 4. "채널수 비례 근사는 타당하지 않다" 결론 재평가

모드별로 근거의 강도가 다르다는 것을 재확인했다.

### 4.1 ULP — 강한 근거 (거의 확정적)

메인 데이터시트 §5.2(`iqs323_datasheet_layout.txt:897,899`)를 직접 재확인:

> "Ultra-low power mode (ULP) ... Intended for rapid wake-up from deep sleep on a single channel ... **Other sensor channels are sampled at a slower rate** in order to optimize power consumption."

AZD004(`azd004_layout.txt:1145~1149`, "8 Power Modes" 절, p.21)에서도 독립적으로 동일 구조를 재확인:

> "on multi-channel devices, ULP will only sample on a single channel, keeping all other channels dormant. This feature is sometimes referred to as 'AutoProx'."

두 문서(서로 다른 PDF, 서로 다른 절)가 동일 메커니즘을 독립적으로 명시하고 있어, "3채널 ULP 벤치마크(4.00µA)=빠른 웨이크업 채널 1개+느린 채널 2개의 합"이라는 그라운드_1의 구조적 논거는 **강하게 뒷받침된다.** Sound1처럼 채널이 원래 1개뿐이면 "나머지 채널을 늦춰 절약"할 대상 자체가 없으므로, 나이브 3분의 1 근사(4.00/3≈1.33µA)가 과대 절감 추정이라는 결론에 반증 근거를 찾지 못했다. **판정: 확인(CONFIRMED, ULP 한정.)**

### 4.2 NP/LP — 약한 근거 (판단이지 증명은 아님)

NP/LP에는 ULP 같은 "AutoProx" 구조가 원문에 서술되어 있지 않다(§5.2 재확인 결과 ULP 항목에만 붙어 있음, NP/LP 항목은 리포트레이트 언급뿐). 그라운드_1이 NP/LP에 대해서도 "비례하지 않는다"고 결론지은 근거는 사실상 §3 차이_4(인터페이스 선택)의 미확정 경쟁효과뿐이다. §3에서 확인했듯 이 경쟁효과는 방향은 있으나 크기가 미확인이므로, 엄밀히는 "비례 근사가 **틀렸다는 증명**"이 아니라 "경쟁 요인이 있어 **비례 근사를 신뢰할 근거가 부족하다**"는 수준의 결론이 정확하다. 그라운드_1의 §4 결론 헤더("타당하지 않다")는 이 구간에서 근거가 뒷받침하는 것보다 다소 단정적이나, 본문 표_3이 이미 NP/LP를 점추정 대신 넓은 범위로 제시하고 있어 **실질적으로는 올바르게 헤지되어 있다** — 헤더 문구와 본문 상세의 확신도 차이는 있으나 실무적 결론(정밀 근사 대신 범위 제시)에는 영향이 없다.

### 4.3 추가 발견 — 표 자체 내부 교차검증 (그라운드_1이 사용하지 않은 각도)

§3.4 표 내부에서 self-cap 3채널 고정 상태로 리포트레이트만 바뀌는 same-mode 비교를 직접 계산해 검증했다:

```
16ms→60ms  (3.75배 느림) : 125→37.5µA (3.33배 감소)  — 비례에 근접
60ms→160ms (2.67배 느림) : 37.5→4.00µA (9.4배 감소)  — 초과 비례(ULP AutoProx 효과 반영 추정)
160ms→3000ms(18.75배 느림): 4.00→2.00µA (2배 감소)   — 비례에 크게 못 미침(Halt 바닥값 존재)
```

이는 채널수와 무관하게 **같은 self-cap 3채널 안에서도 리포트레이트-전류 관계가 전 구간에서 선형/비례가 아님**을 원문 수치 자체로 보여준다. 그라운드_1은 이 각도를 사용하지 않았으나, 결과적으로 "단순 비례식은 이 IC의 전류 특성을 잘 설명하지 못한다"는 그라운드_1의 핵심 회의론을 채널수와 무관한 별도 경로로 뒷받침한다.

## 5. 후보_2(05)와의 정합성 확인

후보_2(05) §5.2가 인용한 원문(`iqs323_datasheet_layout.txt:895~899` 부근, "§5.2 근거로 3채널 벤치마크를 1채널로 환산 불가")을 동일하게 재확인한 결과, 그라운드_1과 **동일한 원문 문장(§5.2 ULP 단일채널 웨이크업 서술)을 근거로 사용하고 있음을 확인**했다. 다만 05는 문서 서두(§0)에서 스스로 "본 작업에서 AZD004는 열람하지 않음"이라고 명시했으므로, 두 문서는 **서로 다른 1차 자료 경로(메인 데이터시트 단독 vs 메인 데이터시트+AZD004)로 동일 결론에 독립 도달**한 셈이다.

결론의 방향도 일치한다 — 그라운드_1은 "실제로는 4.00µA(상한)에 더 가까울 것"이라 단정적으로 추정하고, 후보_2는 "정확한 크기는 확정 불가하나 벤치마크의 9.4배(37.5/4.00) 절감비보다는 못할 것"이라 더 보수적으로 서술한다 — **표현의 확신도는 다르지만 방향(나이브 비례 절감폭보다 실제 절감폭이 작을 것)은 동일**하다. 모순이나 상호 반박점을 찾지 못했다.

또한 후보_2 §3.1이 "ULP는 NP 대비 약 31배, LP 대비 9.4배" 수치를 언급할 때 "측정조건 상이(§5 참고)"라고 스스로 괄호로 단서를 붙여둔 것도 확인했다 — 이는 해당 벤치마크 비율을 Sound1의 실제 예상치인 것처럼 오도하지 않고 원 데이터시트 수치임을 명시한 것으로, 그라운드_1의 "근사는 범위로만 제시 가능"이라는 방법론적 절제와 일관된 태도다.

**판정: 정합(CONSISTENT)** — 두 문서 간 모순 없음. 오히려 독립 삼각검증으로 신뢰도가 강화되는 사례.
