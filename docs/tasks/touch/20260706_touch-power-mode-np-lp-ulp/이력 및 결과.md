# 이력 및 결과 — IQS323 전력모드(NP/LP/ULP) 딥다이브

**TL;DR**: 은수님 지시로 NP/LP/ULP 전력소모 비교·SW 호환성·센싱주기 정합성을 10페르소나(그라운드3·후보3·검증4)로 딥다이브 완료. 은수님 가설("ULP는 터치시에만 통신 가능")은 반박됐으나, 우려의 본질은 Auto Prox Cycle Select라는 다른 메커니즘으로 부활 확인. 2026-07-06 착수·완료.

## 시계열 로그

### 2026-07-06
- 선행: `20260705_touch-event-mode-adoption` 1·2차 완료(유휴 폴링주기 연장이 최선책으로 확정, duty 실측 대기 중).
- 은수님 신규 지시: NP/LP/ULP 전력비교·LP/ULP가 현재 SW 기능을 동일 수행 가능한지(예시: ULP는 터치시에만 통신 가능하다는 가설)·센싱주기 정합성. 여러 페르소나로 새 작업 폴더에 정리 요청.
- 단계 ①: `요구사항.md` 작성 — INV-CTRL-1~3 계승, 3개 질문 스코프 정의. 사전 확인(직접): 데이터시트 §3.4 전력소비표(NP 125µA·LP 37.5µA·ULP 4.00µA·Halt 2.00µA, 단 측정조건 3채널·Event mode로 우리 구성과 다름), §5.2·5.3 전력모드 선택 메커니즘, 선행 S3 문서의 과거 LP/ULP 회귀 이력(PM Timeout=0으로 강하 차단, 근거: "LP 전환 시 report rate 100ms로 RDY 윈도우가 느려져 force_window_open 45ms 폴링이 윈도우를 놓쳐 timeout") 재확인.
- 단계 ②: **WF1**(그라운드3+후보3, 6에이전트, 약140만토큰) 실행·완료 — 전력소비정량비교·모드별RDY통신동작·과거회귀재구성 / LP활용시나리오·ULP활용시나리오·SW폴링최적매칭.
- **WF2**(검증 4에이전트, 약82만토큰) 실행·완료 — 전력수치반증·force-comm무관성반증(최우선, AZD004 t_wait 연동·Auto Prox Cycle 재확인)·과거회귀반증(위상표류 정량화 모순 발견)·완전성할루시네이션감사(할루시네이션 1건·wake-write 죽은코드 발견).
- fan-in(직접): `99_종합.md`·`인덱스.md`·`분석.md`(②)·`계획.md`(③) 작성. 제품 소스 변경 0.
- 문서 정리 중 CJK 한자 재유입 1건(후보_1) 발견·정정, CJK 전수 재스캔 통과.

## 완료 요약

- **결론(fact-verified)**: 은수님 가설은 표면적으로 반박("Force Comm은 파워모드 무관 항상 작동")되나, 우려의 본질(LP/ULP에서 SW가 못 따라감)은 **Auto Prox Cycle Select**(POR 기본 32배, 코드 미설정)라는 다른 메커니즘으로 부활 — "틀린 진단, 맞는 걱정".
- **과거 회귀**: PM Timeout=0 전면 차단의 인과사슬 재구성됨(크기충돌+SW/LP리포트레이트 100ms 우연일치 위상표류). 단 정량화("피피엠 단위")는 데이터시트 자체 클럭공차(±5.5%)와 모순돼 정정됨(실제 맥놀이는 초~수십초 규모). 비례성(전면차단이 최선이었나) 재검토 여지는 있으나 실측 없이 확정 불가.
- **3개 활용 후보**: LP(조건부해소, 전제미확인·재발방지 잠금장치 없음), ULP(가설판정 정확하나 할루시네이션 1건 재발), SW폴링매칭(프레이밍 타당하나 wake-write가 죽은 코드) — **전부 미완결, 그대로 구현 승인 불가**.
- **완전성 공백(최중요)**: 선행 `20260705` 라운드가 확정한 255ms 내장 워치독+Reset Event 비트 미점검 공백을 이번 라운드가 재인용하지 못함 — LP/ULP+절전연장 방향일수록 이 위험이 커짐.
- **검증 품질**: 확정 할루시네이션 1건(후보_2, 선행 라운드에서 이미 정정된 오류의 재발 — 인용위생 문제로 기록), 경미오차 1건.
- **상태**: 딥다이브 완료. 은수님 결정(계획.md §4) 대기 — 실측 게이트 착수 여부·255ms 워치독 공백 해소 병행 여부·현행유지 선택지 인지 등. 코드 변경 0.
