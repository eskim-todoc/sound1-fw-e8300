# 검증_5 · 할루시네이션 감사 — 01~08 문서 전수 인용 대조

**TL;DR**: 01~08 문서가 인용한 레지스터 주소·비트값·라인번호·데이터시트 페이지 약 150건 이상을 `iqs323_datasheet.pdf`(pdftotext -layout 직접 재추출)와 실제 코드 원문에 전수 대조했다. 절대다수(약 95% 이상)는 문자 그대로 정확했다. 확정 오류 2건(그라운드_1의 오더코드 I2C 주소 반전, 후보_5의 "펌웨어 권장" 문구 오귀속 잔존)과 경미한 인용 오차 2건(후보_1의 부록 페이지 오프바이원, 후보_2의 라인 인용 근소 이탈)을 발견했다. 은수님의 "할루시네이션 절대 금지" 지시 기준으로 볼 때 전반적 신뢰도는 높으나, 두 확정 오류는 후속 반영이 필요하다.

## 2. 확정 오류 (Confirmed)

### 오류_1 — 그라운드_1: 데이터시트 Table 10.1 오더코드 I2C 주소가 반전 인용됨

**그라운드_1 원문 인용** (`01_G1_IC버전·에라타범위.md` §발견_4):
> "데이터시트 Table 10.1 Ordering Code(PDF 38페이지, `pdftotext -layout` 2189~2198행)에 따르면 오더코드 "001"은 I2C 주소 **0x58**, "002"는 **0x44**(둘 다 Release UI, "00x" 계열), "A01"(Movement UI, "A0x" 계열)은 이 발췌 범위에서 주소가 **확인되지 않았다[미확인]**."

**실제 PDF 원문** (본 노드가 그라운드_1이 명시한 바로 그 좌표 `2189~2198행`을 직접 펼쳐 확인, PDF 38페이지):

```
2189   IC NAME                                                             IQS323
2190                                                                       I2 C address = 0x44.
2191                                                              001      3 button self capacitance with
2192                                                                       Release UI, configurable via I2 C.
2193                                                                       I2 C address = 0x58.
2194   DEFAULT CONFIGURATION                     zzz        =     002      3 button self capacitance with
2195                                                                       Release UI, configurable via I2 C.
2196                                                                       I2 C address = 0x44.
2197                                                              A01      3 button self capacitance with
2198                                                                       Movement UI, configurable via I2 C.
```

**판정**: 반증 시도 결과 반증 실패가 아니라 **원문과 정면으로 불일치함을 확인**했다.
- 실제 값은 **001 = 0x44, 002 = 0x58** — 그라운드_1의 서술(001=0x58, 002=0x44)과 정확히 **반전**되어 있다.
- A01의 주소(0x44)는 그라운드_1이 스스로 인용한 바로 그 라인 범위(2189~2198행) **안**(2196~2197행)에 명확히 존재한다 — "이 발췌 범위에서 확인되지 않았다[미확인]"이라는 서술은 성립하지 않는다. 발췌 범위가 좁아서 잘린 것이 아니라, 범위 안에 있는데도 못 봤거나 옮기며 착오가 난 경우다.

**하류 영향 점검**: 후보_1(`04_C1_...md` §발견_2)이 같은 표를 독자적으로 재대조하며 **정확한 값**(001=0x44, 002=0x58, A01=0x44)을 도출했고, 이를 근거로 "0x44는 001(00x)과 A01(A0x) 양쪽에 공유되는 주소라 I2C 주소만으로는 계열을 구분할 수 없다"는, 그라운드_1의 낙관적 뉘앙스("정황상 00x 계열일 가능성이 높으나")보다 더 엄격한 결론을 냈다. 최종 권고(반드시 레지스터 실측 필요)는 두 문서 모두 동일하므로 실질적 의사결정에는 영향이 없었으나, 그라운드_1 문서 자체는 원문과 불일치하는 수치를 담고 있으므로 정정이 필요하다.

### 오류_2 — 후보_5: "펌웨어 권장은 Event mode 기본" 문구가 데이터시트 원문이 아닌데도 확정 사실처럼 재사용됨

**데이터시트 §8.11.2 실제 원문** (PDF 32페이지, 본 노드 직접 재확인):
> "In event mode the RDY line will only go low when one or more of the enabled events are triggered or if the device resets. This is usually enabled since the master does not want to be interrupted unnecessarily during every cycle if no activity occurred."

이 문장에는 "펌웨어 권장(firmware recommendation)"이라는 표현도, "streaming은 개발단계 임시용"이라는 서술도 **존재하지 않는다**. 본 노드가 "recommend"·"firmware" 전체 텍스트 grep으로 재확인한 결과도 이 절 부근에 해당 문구가 없음을 재확인했다.

**실제 출처**: `docs/참고/touch/데이터시트/05_i2c인터페이스.md` **350행·360행**의 `[!NOTE]` 콜아웃(Sound1 팀이 데이터시트 직역 사이에 추가한 자체 해설):
> "펌웨어 권장: **event mode를 기본**으로 사용하고, streaming은 개발·디버깅 단계에서 임시 활용한다."

본 노드가 이 파일을 직접 읽어 350행·360행 두 곳 모두에서 정확히 이 문구를 확인했다 — 이는 원문 번역이 아니라 사내 주석이다.

**후보_1(04)의 올바른 자가 정정** (§발견_1): 후보_1은 이 문구가 데이터시트 원문이 아니라 사내 `[!NOTE]` 해설이 인용 사슬(선행 세션 V3 → 오늘 요구사항.md)을 타고 "확정 사실"처럼 굳어진 것임을 정확히 찾아내 **[미확인]으로 하향 정정**했다. 이는 모범적인 자기교정이다.

**그러나 후보_5(08)는 이 정정을 반영하지 못한 채 확정 사실처럼 재사용**:
- §1 핵심 결론: "다만 이것이 "이벤트 모드를 영구 배제하라"는 뜻은 아니다. 데이터시트가 명시하는 장기 정합성(§8.11.2 "펌웨어 권장")은 실재하는 사실이다."
- §6.1 비교표: "데이터시트 권장과의 정합성 | 어긋남(...) | **정합(§8.11.2 "펌웨어 권장은 Event mode 기본")**"
- §8 정직한 한계: "데이터시트 권장(§8.11.2 "펌웨어 권장은 Event mode 기본")과 영구적으로 어긋난 상태로 남는다."

세 곳 모두 이 문구를 **§8.11.2 원문 근거**처럼 취급한다. 후보_5 자신이 §9에서 "후보_4의 구체 내용은... 열람 못 함"이라 밝히듯 병렬 실행 중이라 후보_1의 정정을 확인할 기회가 없었던 것으로 보이나, 결과적으로 **08번 문서 자체에는 원문에 없는 문구가 데이터시트 근거로 잔존**한다. 나머지 문서(그라운드_2/3, 후보_2/3/4)는 이 문구를 재사용하지 않아 문제가 없다.

**영향 평가**: 후보_5의 핵심 논거(§3~4, "Report Rate 독립 축"·"인터럽트 미사용")는 이 문구와 무관하게 별도로 성립하므로 최종 권고 자체가 뒤집히지는 않으나, "데이터시트 권장과 어긋난 상태로 남는다"는 §8 서술은 근거가 무너진 채로 남아 있다. 후속 통합 시 반드시 정정이 필요하다.

## 3. 경미 오류 (Minor — 페이지·라인 인용 오차, 내용 자체는 정확)

### 경미_1 — 후보_1: 부록 A.32/A.33 페이지 인용 오프바이원

후보_1(§2.3): "A.32/A.33 Events Enable(0xD3, **p.61-62**)". 본 노드가 목차(TOC, "A.32 ... 62"·"A.33 ... 63")와 페이지 푸터 경계(A.30 헤더는 60/61 푸터 사이 → p.61, A.32 헤더는 61/62 푸터 사이 → **p.62**, A.33 헤더는 62/63 푸터 사이 → **p.63**)를 교차확인한 결과, 정확한 페이지는 **p.62-63**이다. bit6=ATI Error·bit4=ATI Event·bit1=Touch Event라는 **비트 내용 자체는 원문과 정확히 일치**(A.32·A.33 두 표 모두 동일 비트 배치 확인)하므로, 이는 순수 페이지 번호 표기 오차다.

### 경미_2 — 후보_2: §6.6.3 "150 µs" 인용 라인 번호가 근소하게 벗어남

후보_2(§2.4): "원문(추출본 **1341~1343행**) "typical switchover time... 150 µs"". 본 노드 추출본에서 "The typical time for the switchover to be completed is 150 µs"는 **1346행**에 위치하며, 1341~1343행은 그 앞 문장("There is a switchover delay...")에 해당한다. 인용된 수치(150µs)와 그 의미("반환 전 대기 필요, 미준수 시 reset request 무시")는 원문과 **완전히 일치**하므로, 이는 인접한 문단 내 라인 포인터가 몇 줄 어긋난 경미한 오차다.
