# 00 · 오케스트레이터 입력 — 이벤트 모드 채택 딥다이브

**TL;DR**: 은수님이 이벤트 모드(0xC0 bit7 Streaming→Events)를 "RDY가 매번 토글되지 않는" 새 관측 방식으로 지시. 선행 작업(S3/V3/P3)에서 이미 부속 레버로 스펙까지 갔으나 I²C Lock-Up 에라타·강제개방 상시화 리스크로 보류됐던 것을 주역으로 승격해 재딥다이브. 그라운드 3·후보 5·검증 6, 총 14페르소나 병렬(Workflow, model:sonnet effort:max).

## 공통 입력 (전 페르소나 공유)

### 배경
- Sound1 E8300, IQS323 셀프캡 터치(CRX0 단일채널 활성, CH1 disable). 불변식 INV-CTRL-1~3(Full ATI·ATI에러 Re-ATI·첫터치해제) 유지 필수, 그 외 자유(레지스터·채널·측정방식·**force_window_open 프로토콜 자체까지**).
- 현재 `tdc_touch_iqs323.c`: 0xC0(System Control) write 6곳(237 ack_reset 제외 5곳: 318·447·453·465·471) 전부 bit7=0(Streaming). `force_window_open()`(:145-175)은 RDY==OPEN이면 0xFF 강제write 생략(조기반환), 아니면 0xFF write 후 최대 45ms 폴링. `read_register()`/`write_register()`(:180-228) 전부 이 함수 경유.
- 데이터시트 확정 사실(선행 작업에서 원문 대조 완료):
  - §8.11.1~8.11.2: Streaming=Report Rate마다 무조건 RDY assert, Events=활성 이벤트(ati_error·ati_event·touch_event, 0xD3=0x52로 이미 설정)시에만 RDY assert. §8.11.2 NOTE: "펌웨어 권장은 Event mode 기본, Streaming은 개발단계 임시용".
  - 부록C "I²C Lock Up": IQS323-00x v1.3 이하·A0x v1.4 이하. force communications(§8.13, 0xFF write) 사용 시 발생 가능성↑. 발생 시 모든 read byte가 상수 반환. 워크어라운드: 매 통신 끝 비존재 register 1byte read, 0xEE 아니면 hard reset.
  - A.1(0x00~0x02): Product Number/Major Version/Minor Version — 통상 레지스터 read로 접근(HW 추가 불요).
  - A.37(0xE1 Hardware ID): 0xF003=IQS3dd(00x), 0xF004=IQS3ed(A0x).
- 선행 발견(P3, sw-impl): §4.3 — `func_sleep()` 롱터치 재부팅 카운터가 read 실패 시 즉시 0 리셋. 강제개방 실패 빈도 증가 시 정상 기상 제스처 약화 위험.
- 선행 발견(V3, sw-mitigation): Report Rate(0xC1)가 ATI 버스트 내부 주기에도 적용되는지 미확인 — 병행 도입 시 INV-CTRL-1(Full ATI) 타이밍 위험.

## 역할 분담 (14페르소나, 3단)

| 단 | 페르소나 | 역할 |
|---|---|---|
| 그라운드 | G1 | IC 버전·에라타 적용범위 실측 가능성 — 0x00~0x02/0xE1 read로 SW-only 확정 가능한지, 코드에 필요한 추가(신규 read 함수) 스펙 |
| 그라운드 | G2 | force_window_open 프로토콜 정밀분석 — 조기반환 소멸 시 강제개방 빈도·트래픽 변화를 가능한 한 정량화(현재 코드·데이터시트 근거로) |
| 그라운드 | G3 | INV-CTRL-1~3 코드훅 재확인(선행 재탐색 G3 계승, 이번 프로토콜 재설계 범위까지 훅 재점검) |
| 후보 | C1 | 순수 Events 전환(P3 스펙 그대로, 재검토) — 5곳 write 반영, 237 제외 근거 재확인 |
| 후보 | C2 | Events + 에라타 워크어라운드 결합(매 통신 끝 더미 read+0xEE 검사) — 구현 스펙, 부가 트래픽 평가 |
| 후보 | C3 | Events + Report Rate(0xC1) 명시 결합 — ATI 버스트 간섭 여부 포함 설계 |
| 후보 | C4 | force_window_open()/wait_window_closed() 프로토콜 자체 재설계(조기반환 로직 개선안·타임아웃 재조정 등) |
| 후보 | C5 | 대안 비교군 — Events 도입 없이 Streaming 유지 + RDY 토글 최소화(Report Rate만 조정) — "정말 Events가 최선인가" 비교 |
| 검증 | V1 | 에라타 반증 시도 — G1 실측가능성·적용범위 판정을 반박 관점에서 재확인 |
| 검증 | V2 | 자기애그레서 트레이드오프 반증 — G2·C1의 "순 이득 있다/없다" 주장을 반박 시도 |
| 검증 | V3 | INV-CTRL-1~3 회귀 전수 재확인(C1~C4 전체 대상) |
| 검증 | V4 | 완전성 비평 — 데이터시트·에라타 문서 전체 재검토, 놓친 리스크 없는지 |
| 검증 | V5 | 할루시네이션 감사 — 전 노드 인용(레지스터값·라인번호·페이지) 원문 대조 전수 |
| 검증 | V6 | C4·C5 특이 검증 — 프로토콜 재설계안 실현성, 대안 비교의 공정성 |

## 실행 방식
Workflow 도구, phase(그라운드→후보→검증), 각 agent() model:"sonnet" effort:"max". 그라운드는 barrier(후보가 그라운드 사실 의존) 후 후보 pipeline/parallel, 검증은 후보 결과 전체 대상 병렬.
