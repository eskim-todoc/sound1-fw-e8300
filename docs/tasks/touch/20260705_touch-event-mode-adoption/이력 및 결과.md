# 이력 및 결과 — 이벤트 모드(0xC0 bit7) 채택 딥다이브

**TL;DR**: 은수님 지시로 이벤트 모드를 주역 방식으로 승격해 1차(14페르소나: 그라운드3·후보5·검증6)+2차(9페르소나: 그라운드3·후보2·검증4) 딥다이브 진행. 1차: 원 전제는 좁은 의미로만 참, 실질 이득은 "폴링→인터럽트 전환"(후보_4). 2차: 은수님이 "지금과 별 차이 없다"고 재확인 → 유휴 시 폴링 자체를 줄이는 결합 시나리오 검증 → 실제로 큰 차이(최대 98%+ 감소) 확인, 단 최선책은 이벤트모드·인터럽트 불요한 "유휴 폴링주기 연장"(후보_7 변형_1). 2026-07-05 착수·완료.

## 완료 요약

- **1차 결론(fact-verified)**: 원 전제는 3층 분해 결과 ① IC 자체 RDY assert 빈도 감소=참, ② 실질 의도(인터럽트 회피)=**불성립**(RDY는 애초에 busy-wait 폴링 전용, EXTI 0건), ③ 순수 트래픽 감소=방향 유지·크기 과대추정(1.3~2.0배→1.07~1.39배). 단 이 권고(후보_4)도 폴링 주기 자체는 유지한다는 한계가 있었음(은수님이 정확히 지적).
- **2차 결론(fact-verified)**: 유휴 시 폴링 자체를 줄이면 실제로 큰 차이(duty 1%에서 트래픽 약 98.6~98.9% 감소). **최종 1순위 권고는 이벤트모드·인터럽트 전부 불요한 "유휴 폴링주기 연장"(후보_7 변형_1)** — 후보_6(완전정지+인터럽트)보다 리스크 낮고 효과는 대등. duty 실측 결과에 따라 후보_6으로 격상 검토.
- **이벤트 모드(후보_1+2)**: 단독채택반대 유지, 조건부(IC버전실측+워크어라운드 개선) 검토 가능.
- **신규 발견(부수, 1차)**: IQS323 내장 255ms 통신 워치독+Reset Event 비트 런타임 미점검 구조적 공백 — 기존 안전장치 3종 전부 미탐지.
- **신규 발견(2차)**: (a) 게이팅 삽입 위치 그라운드_9-후보_6 불일치(구현 시 후보_6 방식 채택 필수), (b) "노말모드 WFI 부재" 서술이 오류였음을 확정(실제로는 이미 존재), (c) 이 프로젝트 선행 UX 분석(2026-06-15)의 "간접 접촉 빈도" 채널이 duty 가정에 누락됨.
- **검증 품질**: 1·2차 합산 하드 할루시네이션 0건(1차 확정 오류 2건, 하류 영향 없음).
