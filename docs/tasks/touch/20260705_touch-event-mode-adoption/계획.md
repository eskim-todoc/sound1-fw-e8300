# 계획 — 이벤트 모드 채택 딥다이브 권고 (1·2차 라운드 종합)

**TL;DR**: 1차 라운드는 "이벤트 모드 자체는 순 이득이 작다"를 확정했다. 은수님이 "지금과 별 차이 없는 것 아니냐"고 재확인하자, **폴링 주기 자체를 그대로 둔다는 1차 라운드의 숨은 전제를 깨는** 2차 라운드(결합 시나리오)를 진행했다 — 유휴(터치없음·ATI정상) 시 폴링 자체를 줄이면 실제로 큰 차이(트래픽 최대 98%+ 감소)가 난다. 단, 가장 리스크가 낮으면서 효과가 대등한 것은 **인터럽트도 이벤트 모드도 필요 없는 "유휴 시 폴링주기만 늘리는" 방식(후보_7 변형_1)**이었다 — 이것이 최종 1순위 권고다. 본 계획은 방향 결정이며 코드 변경은 승인 후 별도 작업(④).

> [!IMPORTANT]
> 제품 소스 변경 0(계획 단계 완료 시점 기준). 아래는 방향 결정이며, 실제 구현은 승인한 경로를 별도 작업으로 착수한다.

## 1. 결론 요약

- 은수님의 원래 전제("RDY가 매번 토글되지 않아 이득")는 좁은 의미로만 참이고, 실질적 이득(불필요한 인터럽트 회피)은 현재 아키텍처(RDY=busy-wait 폴링)에서 성립하지 않는다(1차 라운드).
- 1차 라운드가 권고했던 "폴링→인터럽트 전환"(후보_4)도, 자세히 보니 **폴링 주기(100ms) 자체는 그대로 유지**한다는 전제였다 — 이게 은수님이 "지금과 별 차이 없다"고 정확히 지적하신 지점이다.
- 2차 라운드: 유휴 구간엔 폴링 자체를 줄이는 결합 시나리오를 검증한 결과, **실제로 의미 있는 차이**(duty 1% 가정 시 트래픽 약 98.6~98.9% 감소)가 확인됐다.
- **핵심 발견**: 이 효과를 얻는 데 이벤트 모드 전환도 인터럽트 배선도 필요 없다 — **유휴 시 폴링주기만 100ms→500~1000ms로 늘리는 것만으로 대등한 효과**를 얻을 수 있고(후보_7 변형_1), 오히려 회귀위험은 더 낮다.
- 실사용 duty(터치 활성 비율)가 이 판단에 결정적인데, 이 프로젝트의 선행 UX 분석(2026-06-15)이 이미 "간접 접촉(안경다리·헤어·베개) 빈도 높음"을 문서화해뒀음에도 이번 duty 가정에는 반영되지 않았다 — duty 실측이 다음 관문이다.
- 상세: [`분석.md`](분석.md)·[`에이전트-로그/99_종합.md`](에이전트-로그/99_종합.md).

## 2. 권고 로드맵 (우선순위순, 2차 라운드 반영)

|---|---|---|---|
| **1** | **후보_7 변형_1 — 유휴 시 폴링주기 연장**(100ms→500~1000ms, Streaming 유지·인터럽트·레지스터 변경 불요) | **최우선 채택 권고** | 후보_6(완전정지+인터럽트) 대비 구현 복잡도·회귀위험 낮음, 트래픽 절감은 대등(검증_8). "훨씬 단순한 대안" 취지에 가장 부합 |
| **2 (병행)** | **실사용 duty(터치 활성 비율) 실측** — 간접 접촉(안경·헤어·베개) 포함 | 선결 게이트 | duty가 낮을수록(실사용 근접) 후보_6(완전정지)의 상대적 우위가 커짐(검증_8: duty 1%→10.9~20.8배, 5~10%→1.9~2.8배) — 실측 없이는 후보_6 격상 여부 판단 불가 |
| **3 (병행)** | **G1 — IC 버전 실측**(0x00~0x02·0xE1 부팅 1회 read+RTT 로그) | 선결 게이트 | SW-only 실현 가능 확정. 에라타(부록C) 적용범위 확정용, 이벤트 모드 자체 채택 여부와 별개로 유용 |
| **4 (조건부 격상)** | **후보_6 — 완전정지+RDY 인터럽트 하이브리드** | 순위 2 실측 결과 duty가 충분히 낮으면 격상 | 3불변식 무손상 확인됨. 단 구현 시 필수 정정 2건(§3) 반영 필요 |
| **5 (신규, 별도 트랙 제안)** | **255ms 워치독/Reset Event 비트 점검 공백 해소** | 항상 존재하는 위험 해소 | 이벤트 모드·인터럽트 채택 여부와 무관하게 기존 안전장치 3종이 전부 놓치는 시나리오(1차 라운드 검증_4 발견) |
| 비권고 | 이벤트 모드 자체(후보_1+2), Report Rate 단독(후보_3), Streaming+ReportRate만(후보_5) | 참고용 | 1차 라운드에서 순 이득 작음·에라타 리스크·자기모순 등으로 각각 비권고 확정(에이전트-로그 99_종합.md §2 참조) |

## 3. 구현 시 필수 반영 사항 (2차 라운드에서 발견된 정정 2건)

이벤트 기반 경로(순위 4, 후보_6)를 채택할 경우:

1. **게이팅 삽입 위치**: `tdc_touch_process()`에서 RDY 확인 게이트는 반드시 기존 경과시간 게이트(`tdc_touch.c:294~300`) **이전**에 배치해야 한다. 이후(301행)에 배치하면 "즉시 감지"라는 핵심 이점이 사라지고 기존과 동일하게 최대 100ms 지연이 재현된다(검증_7·9 공동 발견).
2. **"노말모드 WFI 부재" 서술은 오류다** — 실제로는 `main.c:452`(터치 처리 호출)와 `:738`(WFI)이 동일한 `while(1)` 루프 안에 있어 이미 WFI가 존재한다(검증_9·10 독립 재확인). DIO16 인터럽트를 이 WFI의 기존 웨이크소스 목록에 추가하는 형태이지, WFI를 신규 도입하는 것이 아니다 — 리스크가 1차 라운드가 서술한 것보다 낮다.

순위 1(변형_1)만 채택할 경우 위 두 정정은 해당 없음(인터럽트 자체를 쓰지 않으므로).

## 4. 정직한 한계

- 이벤트 모드 자체는 은수님이 원했던 형태의 "이득"을 주지 않는다(1차 라운드 핵심 결론, 불변).
- 순위 1(변형_1)의 트레이드오프: ATI 에러 최초 감지가 최악의 경우 현재(≤100ms)보다 최대 500~900ms 늦어질 수 있다 — 단 "놓치는" 것이 아니라 "늦게 잡는" 것뿐이며 Re-ATI 호출 자체는 보장된다(INV-CTRL-2 위반 아님).
- 순위 2(duty 실측)가 없으면 순위 1(변형_1)과 순위 4(후보_6) 중 어느 쪽이 실질적으로 더 나은지는 확정할 수 없다 — 다만 순위 1은 duty와 무관하게 항상 안전한 선택이다.

## 5. 은수님 결정 요청

1. **로드맵 순위 1(후보_7 변형_1 — 유휴 폴링주기 연장) 착수 동의 여부** — 가장 단순하고 낮은 리스크로 실제 차이를 만드는 경로입니다.
2. **순위 2(실사용 duty 실측, 간접 접촉 포함)를 병행할지** — 이 값에 따라 후보_6으로 격상할 실익이 갈립니다.
3. **순위 3(IC 버전 실측)을 병행할지** — 이벤트 모드 자체를 고려하지 않더라도 SW-only로 저비용입니다.
4. **순위 5(255ms 워치독/Reset Event 비트 점검 공백)를 이번 롤아웃에 포함할지, 별도 작업으로 분리할지.**
5. **할루시네이션 감사에서 발견한 확정 오류 2건**(1차: 그라운드_1 Table 10.1 반전, 후보_5 "펌웨어 권장" 오귀속) **정정 여부.**

승인 후, 선택한 경로를 별도 작업(④)으로 착수하겠습니다.
