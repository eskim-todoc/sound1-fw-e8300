# A06 · 제품 UX·사용자 경험 담당자 — 분석

> **TL;DR**: 인공와우 사용자의 터치 패턴과 사용 컨텍스트를 분석한 결과, P6(부팅마다 감도 다름)은 중등도 UX 문제이고, 자기정상화 과도기간 미인식은 경중도 문제이며, M3 빠른 Beta 단일 상향의 약터치 흡수는 고위험 문제다. 하이브리드(ATI Full + 노터치 게이트 + 비대칭 BETA)는 세 문제를 모두 완화한다. 단 과도기간 길이가 실사용 수용 한계(5~10초)를 넘는지 실측이 필수다.

---

## 1. 인공와우 착용자의 실제 터치 패턴 분석

### 1-1. 착용 맥락과 기기 위치

인공와우 외부 기기(사운드 프로세서)는 귀 뒤에 부착 또는 이어훅으로 고정된다. 터치패드는 기기 표면에 위치한다. 이 맥락에서 다음 특성이 도출된다.

| 특성 | 설명 | 터치 IC에 대한 시사점 |
|---|---|---|
| **간접 접촉 빈도 높음** | 안경 착용·헤어 터치·머리 베개 압착 시 패드에 의도치 않은 접촉 | 우발 터치 비율 높음 → Beta 빠르면 우발 터치가 LTA 흡수 위험 |
| **약지 또는 검지 끝 사용** | 대부분 조작이 귀 뒤를 찾아가는 단일 손가락 짧은 탭 | 터치 강도 일정하지 않음 · 경계 강도 탭 빈번 |
| **조작 빈도 낮음** | 볼륨·프로그램 변경 등 하루 수~수십 회 수준 | 먹통 인식까지 오래 걸릴 수 있음 |
| **시각 확인 불가** | 기기가 귀 뒤에 있어 누르는 동안 화면·LED 피드백 없음 | 미인식 시 재시도 반복 → 손가락 오래 유지 가능성 |
| **배터리 교체·케이스 수납 중 접촉** | 교체·수납 중 패드 면에 손바닥이나 소지품 닿음 | "손 안 떼는" 비전형 부팅 케이스 발생 가능 |

### 1-2. 터치 해제 속도와 패턴

- **짧은 탭(0.1~0.5초)**: 볼륨 1단계 변경 등 단일 기능 조작. 가장 빈번한 패턴.
- **누름 유지(1~3초)**: 프로그램 전환, 기기 재시작 등 롱프레스 기능.
- **스쳐 지나가는 접촉(50ms 미만)**: 귀 뒤 긁기·땀 닦기 등 비의도. 디바운스 내에 걸려야 정상.

**UX 핵심 시사점**: 탭 종료 후 손가락이 패드에서 완전히 멀어지는 시간은 인공와우 착용자 기준 평균 약 0.5~1.0초로 추정된다. 이 시간이 "자기정상화 과도기간" 내에 들어오는지가 중요하다.

## 2. 자기정상화 과도기간 — UX 영향 분석

### 2-1. 과도기간이란

autoATI + 빠른 Beta 조합에서, 부팅 직후 터치된 채 부팅이 완료된 경우:

1. 사용자가 손을 뗌
2. LTA가 노터치 counts를 향해 IIR로 수렴 시작
3. **수렴 완료까지 — 이 구간이 "과도기간"**
4. 수렴 완료 후 첫 터치부터 정상 인식

과도기간 동안 재터치 시 `(LTA - Counts)` delta가 Threshold에 못 미쳐 미인식된다.

### 2-2. 과도기간 길이 추정

데이터시트 §5.6 LTA IIR 수렴 모델 기반:

```
LTA_new = LTA_old + (Counts - LTA_old) × (Beta/256)
```

Beta = 10(기존 추정치), 노터치~LTA 차이를 Δ라 하면:

| 수렴 목표 | 필요 사이클 수 (beta=10) | 시간 (20ms 주기 기준) |
|---|---|---|
| Δ × 63% (1/e) | ~25 사이클 | ~500ms |
| Δ × 90% | ~58 사이클 | ~1.2초 |
| Δ × 99% (실용 완료) | ~117 사이클 | ~2.3초 |

**Beta = 20**으로 2배 빠르게 하면 약 1.15초에 99% 수렴.

Fast Filter Band(손 뗄 때 방향 비대칭)가 발동하면 실효 수렴은 추가로 빨라짐.

### 2-3. UX 수용 한계 판단

| 과도기간 | 사용자 체감 | 판단 |
|---|---|---|
| 0~2초 | 손 떼자마자 다시 탭 — 1회 미인식 후 재탭 성공 | **수용 가능** (미인식 1회는 오작동 아닌 "한 박자 늦음"으로 인식) |
| 2~5초 | 손 뗀 뒤 잠깐 기다려야 작동 | **경계** — 사용자가 고장 의심 시작 |
| 5~10초 | 반복 탭 시도, 불안 시작 | **비수용** — 수리 요청 가능성 |
| 10초 이상 | 완전 먹통으로 인식 | **치명** |

**결론**: Beta = 10 기준 과도기간 약 2.3초는 수용 경계에 위치. Beta = 20이면 약 1.15초로 수용 가능 범위 진입. **Fast Filter Band 비대칭 설계가 이 구간을 실질적으로 단축하므로, 구현 방식이 UX 수용성을 결정하는 핵심 변수.**

### 2-4. 정상 부팅(노터치 부팅) 시 과도기간

노터치 부팅 + 노터치 게이트 적용 시 Reseed는 노터치 counts로 시작하므로 과도기간이 실질적으로 0 또는 Threshold Hysteresis 내. **이 경우 UX 문제 없음.**

## 3. M3(빠른 Beta 단일 상향) — 약터치·우발 접촉 흡수 위험

### 3-1. 위험 메커니즘

Beta 단일 상향 시:
- LTA가 모든 방향(터치 방향 포함)으로 빠르게 counts를 추적
- 약하거나 느린 터치에서 `(LTA - Counts)` delta가 생기기 전에 LTA가 이미 counts를 따라감
- 결과: 터치를 인식하지 못한 채 LTA가 터치값으로 수렴 → "LTA 흡수"

### 3-2. 인공와우 사용자에서의 위험도

| 터치 유형 | Beta 단일 상향 시 흡수 위험 | 설명 |
|---|---|---|
| **귀 뒤 긁기 (스치는 접촉)** | 낮음 (디바운스 수준) | 50ms 미만, 흡수보다 디바운스가 먼저 차단 |
| **경계 강도 탭** | **높음** | Threshold 근처 강도, 느리게 누를 때 LTA가 먼저 따라가 delta 생성 실패 |
| **연속 탭 (볼륨 연속 조작)** | **높음** | 앞 탭 직후 재탭 시 LTA가 아직 터치값 근처 → delta 작음 |
| **안경 다리 마찰** | 중간 | 수초 지속 접촉 → LTA 완전 흡수 가능 |

### 3-3. Fast Filter Band 비대칭 설계의 보호 효과

이전 분석에서 확인된 바: **Fast Filter Band는 sensing 반대 방향(손 떼는 방향 = counts 증가)에만 fast beta를 적용.** self-cap에서 터치는 counts 감소 방향이므로, **터치 진입 시에는 normal(느린) beta가 유지된다.**

이 비대칭이 UX 측면에서 하는 일:

- 손 뗀 직후 → Fast Filter Band 발동 → LTA 빠르게 노터치 복귀 → **과도기간 단축**
- 터치 진입 시 → normal beta → LTA가 천천히 따라감 → **약터치 흡수 방지**

**결론: Fast Filter Band 비대칭 설계는 "빠른 수렴"과 "약터치 보호"를 동시에 달성하는 올바른 구현이다. 단순 Beta 상향은 이 비대칭을 깨므로 UX 관점에서 금지.**

## 4. P6(부팅마다 감도 다름) — 실제 사용자 체감 심각도

### 4-1. P6 발생 메커니즘 (UX 관점)

현 방전 코드(CRX0 VSS 200ms 방전) 부작용:
1. 부팅 시 방전이 발생 → CRX0 카운터가 특정 상태
2. 그 상태에서 LTA가 세팅 → baseline 값이 매 부팅 조금씩 다름
3. Threshold 마진이 달라 → 같은 강도 탭이 부팅마다 다르게 인식

### 4-2. 체감 강도 평가

| 감도 편차 규모 | 사용자 체감 |
|---|---|
| ±5% 이하 | 인지 불가 — 완전 무시 |
| ±10~20% | "오늘은 좀 무딘 것 같다" 수준 — 인지는 하나 장애는 없음 |
| ±30% 이상 | 특정 부팅에서 탭을 2~3번 해야 반응 → 명확히 인지 |
| 특정 부팅 시 미인식 | "고장" 인식 → CS 접수 |

**P6의 실제 위험**: 감도 편차 자체보다 **"특정 부팅에서 우연히 먹통"** 이 되는 최악 케이스가 핵심. 이 경우 사용자 재현이 어렵고(다음 부팅엔 정상) AS 원인 추적이 극히 어렵다.

### 4-3. 인공와우 사용자 특수성

- 인공와우는 청력이 IC에 종속 → 터치 오작동이 "잠깐 불편"이 아니라 **"청력 차단"** 을 의미할 수 있음
- 고령 착용자 비율이 높으면 터치 인식 실패 시 기기 고장으로 판단하고 재시도 없이 포기하는 경향
- **P6는 중등도 UX 문제이나 "청력 보조기" 맥락에서는 체감 심각도 상향 평가 필요**

## 5. 터치 먹통 발생 시 사용자 행동 패턴

### 5-1. 전형적 대응 시퀀스

1. **반복 탭 (1~3회)**: "내가 잘못 눌렀나" → 다시 탭
2. **강하게 탭**: "약해서 안 된 거겠지" → 더 세게
3. **기기 관찰**: 귀에서 분리해 육안 확인 (LED·화면 확인)
4. **기기 재시작**: 배터리 뽑았다 다시 끼움 (POR)
5. **AS 요청**: 위 단계 반복 실패 후

### 5-2. 4단계 "배터리 재삽입" 의미

사용자가 자연스럽게 발견한 해결 방법이 **POR(재부팅)** 이다. 이는:
- P1(autoATI + 터치 중 부팅 → 먹통)의 경우 재부팅해도 터치하고 있으면 재발
- P4(드리프트 누적 먹통)의 경우 재부팅 후 정상 복귀 (LTA 재초기화)

**UX 핵심 인사이트**: 사용자는 이미 "재부팅하면 고쳐진다"는 패턴을 학습해 있다. 이것이 P4 먹통을 오래 감추는 원인이 됐을 것 — **사용자 자가 해결이 제품 오류 은폐 메커니즘으로 작동.**

### 5-3. 먹통 발생 → AS 접수까지 기간

인공와우 사용자 특성상(고령, 기기 의존도 높음):
- 재부팅으로 해결되면 AS 보고 안 하는 경우 다수
- 단, 청력 보조기 특성상 먹통이 청력 손실로 직결되면 즉각 AS 접수
- P4 유형은 "점점 자주 먹통"이 되는 패턴 → 사용자 스스로 "수명이 다했나" 오판 가능

## 6. 집중 항목별 최종 판정

| 항목 | 판정 | 위험도 | 근거 |
|---|---|---|---|
| **인공와우 착용자 터치 패턴** | 간접 접촉·약한 탭 빈도 높음 | 참조 | 우발 접촉·경계 강도 탭이 주요 사용 패턴 |
| **자기정상화 과도기간 UX 영향** | Beta=10 기준 약 2.3초, 수용 경계 | 중 | Fast Filter Band 비대칭 시 1초대로 개선. 실측 필수 |
| **M3 빠른 Beta 단일 상향 시 약터치 흡수** | 경계 강도 탭·연속 탭에서 고위험 | **높음** | LTA가 터치 방향으로도 빠르게 추적 → 미인식 |
| **Fast Filter Band 비대칭 설계** | UX 관점 정합 — 권고 | 낮음(올바른 방향) | 손 뗄 때만 빠름, 터치 시 normal beta 유지 |
| **P6 부팅마다 감도 다름 체감** | 중등도 UX 문제, 청력 보조기 맥락에서 상향 평가 | 중~높음 | 최악 케이스 "특정 부팅 먹통"이 반복 불재현 특성 |
| **터치 먹통 시 사용자 행동** | 재부팅(POR)이 자가 해결, 오류 은폐 우려 | 참조 | AS 미접수로 드리프트 먹통이 장기간 잠복 가능 |

## 7. UX 관점 권고 사항

### 7-1. 필수 (UX 위험 차단)

1. **Fast Filter Band 비대칭 BETA** — Beta 단일 상향 절대 금지. 손 뗄 때만 빠르게, 터치 방향은 normal 유지
2. **노터치 게이트 + Reseed 지연** — 부팅 직후 손 유지 케이스(귀에 대고 스위치 켜기 등)에서 과도기간이 무한 연장되지 않도록 안전망 필수
3. **과도기간 실측** — 손 뗀 후 첫 정상 인식까지의 시간을 RTT로 측정. 목표: 2초 이내

### 7-2. 권고 (UX 개선)

4. **부팅 완료 알림 피드백** — 자기정상화 완료 시(LTA 수렴 후) LED 또는 비프음으로 "준비 완료" 신호. 과도기간 미인식에 대한 사용자 혼란 해소
5. **재부팅 AS 로그** — 사용자 POR 빈도를 로그화해 먹통 패턴 추적

### 7-3. 우선순위

```
필수 1 (약터치 보호) > 필수 3 (과도기간 실측) > 필수 2 (노터치 게이트) > 권고
```

## 8. 결론

> **UX 관점 판정: 은수님 안(autoATI + Beta 빠른 수렴)의 방향은 사용자 경험 개선에 유효하나, M3 "Beta 단일 상향"은 경계 강도 탭·연속 탭에서 미인식 위험을 유발한다. Fast Filter Band 비대칭 설계(손 뗄 때만 빠른 수렴)가 올바른 UX 구현이며, 노터치 게이트와 결합해야 "부팅 중 손 유지" 케이스에서도 안전하다. P6 감도 편차는 청력 보조기 맥락에서 중~높음 위험으로 평가되며, 하이브리드(ATI Full + 노터치 게이트 + 비대칭 BETA)가 UX 측면 모든 항목을 완화한다.**
