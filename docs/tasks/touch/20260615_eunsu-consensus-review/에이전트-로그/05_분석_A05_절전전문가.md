# A05 · 절전·전력 전문가 분석

> **TL;DR**: 현 펌웨어는 IQS323 IC 전력 모드를 단 한 번도 write하지 않아 IC가 NP(Normal Power, ~125µA 3ch) 고정으로 추정 동작하고 있으며, 펌웨어가 말하는 "ULP 모드"는 SW 플래그뿐이다. autoATI Full 재활성 시 Channel Timeout(stuck 복구)을 사용하면 데이터시트 §5.8 WARNING에 따라 ULP 진입이 강제 차단되고 LP(~37µA) 수준에 머문다. 인공와우 절전 전류 예산 수치가 문서 어디에도 없어 autoATI 상시 실행의 전력 허용 여부는 실측 게이트 통과 전까지 확정 불가다.

> [!NOTE]
> 근거: 공통 입력 배경, 데이터시트 정리본 [01 §3.4](../../../../../참고/touch/데이터시트/01_개요·전기·타이밍.md)·[02 §5.2/5.3/5.8/5.10/5.11](../../../../../참고/touch/데이터시트/02_proxfusion동작.md), 이전 분석 [A6 절전검증](../../../../../참고/touch/개선/은수님%20의견%20비교%20분석/1_분석_A6_power.md), [B6 Auto No ULP 전류](../../../../../참고/touch/개선/생각정리/4_타당성검증.md), 코드 `tdc_drv_iqs323.c/.h`·`main.c`·`drv.c`.

## 1. 전력 관점 핵심 사실 (ground truth)

### 1.1 현재 IQS323 IC 전력 모드 상태

| 레지스터 | 내용 | 현재 상태 |
|---|---|---|
| System Control(0xC0) bits[6:4] | IC Power Mode 필드 (000=NP·001=LP·010=ULP·011=Halt·100=Automatic·101=Automatic No ULP) | **미write** — POR reset 0x0000 → bits[6:4]=000 → **NP 고정 추정** |
| Report Rate(0xC1~0xC5) | NP·LP·ULP·Halt·Timeout 각 rate(ms) | **미write** — 모두 reset 0x0000 |
| `g_tdc_iqs323_in_ulp_mode` | 코드의 "ULP 플래그" | **순수 SW 플래그** — `apply_tuning()` 분기·마진 게이팅 용도만. IC 전력모드 조작 없음 |

> [!IMPORTANT]
> **결정적 함의**: 펌웨어가 "절전(ULP) 모드"라 부르는 상태에서도 IQS323은 실제로 IC NP 모드로 계속 동작 중이다. 실제 절전 효과는 E8300 CM3 SYSCLK 강하(30.72MHz → 2.56MHz, `ci_power_sleep`)에서만 온다. 즉 현재 IQS323은 절전 중에도 **self-cap 3ch NP 기준 ~125µA**를 소비하고 있을 가능성이 높다(확인 필요: 0xC0 reset값이 NP 고정인지).

### 1.2 데이터시트 전류표 (§3.4)

측정 조건: Self-cap ATI Target=512, Fxfer=500kHz, Interface=**Event mode**

| 전력 모드 | 활성 채널 | Report rate [ms] | 1.8V [µA] |
|---|---|---|---|
| Normal Power | Self-cap 3ch | 16 | **125** |
| Low Power | Self-cap 3ch | 60 | **37.0** |
| Ultra Low Power | Self-cap 3ch | 160 | **4.00** |
| Halt | — | 3000 | **2.00** |

> [!WARNING]
> 위 수치는 **3채널** 기준이다. 본 Sound1은 self-cap **1채널**만 사용하므로 단순 1/3 환산은 불가(CPU 14MHz·디지털 블록 고정 오버헤드 포함). 실 1ch 전류는 반드시 실측이 필요하며, 보수적 상한은 NP ~125µA·LP ~37µA·ULP ~4µA로 잡을 수 있으나 1ch에선 고정 오버헤드 비중이 더 커 단순 1/3보다 높을 가능성 있다.

### 1.3 ATI Full 실행 중 전력 소비

데이터시트에 ATI 실행 중 별도 전류 수치는 없다. 그러나 ATI Full 실행 중에는:
- IC 내부 14MHz CPU가 분주기·MULT·COMP를 탐색하는 연산 부하 증가
- 측정 사이클 반복(다중 측정으로 분주기 스윕) → 아날로그 블록 duty cycle 상승
- **추정: ATI 중 NP보다 일시적으로 소비 증가** (수치 데이터시트 미제공, 실측 필요)
- ATI 소요 시간: 전형적으로 수십~수백ms (채널 수·설정 복잡도에 따라 다름)

부팅 1회 ATI는 소요 시간이 짧아 배터리 영향 미미하나, **autoATI 상시(자동 Re-ATI 포함)** 운용은 얼마나 자주 트리거되느냐에 따라 평균 전류가 달라진다.

### 1.4 Channel Timeout과 Auto No ULP 강제 관계

데이터시트 [02 §5.8] **WARNING**:

> 채널 prox/touch timeout을 사용하는 경우 ULP 모드 금지. 자동 전력 전환은 'Automatic No ULP'로 설정.

- Channel Timeout = stuck-touch 자동 복구 안전망이자 장기 drif 후 자동 reseed 경로
- autoATI Full 재활성 시 자동 Re-ATI(stuck/drift 복구)를 쓰려면 Event Timeout/Channel Timeout도 함께 활성화하는 것이 안전 — **이 순간 ULP가 자동 차단됨**
- Automatic No ULP 채택 시 최저 도달 가능 전력은 **LP(~37µA, 3ch 기준)** — ULP 4µA의 ~9배

## 2. 은수님 명제 전력 관점 판정

| 명제 | 내용 | 전력 관점 판정 | 근거 |
|---|---|---|---|
| **M1** | autoATI는 LTA→카운터 수렴 구조 | 전력 중립 (ATI 메커니즘 이해 범위) | — |
| **M7** | 절전도 동일 개념, 추가 세팅 불필요 | **반증** | 현 코드 절전에 추가 세팅 실재(255/255→clk강하→reseed), IC 전력모드 미설정 |
| **M8** | autoATI가 드리프트 해결 → 방전 불필요 | **조건부 반증** | auto-ATI/Re-ATI 현재 ATI Disabled로 차단, BETA도 미write(0x0000). 성립시키려면 코드 추가 선행 |
| **M8(확장)** | autoATI 상시 실행이 배터리 상 가능 | **미결(실측 필요)** | 절전 전류 예산 수치 0건, 1ch 전류 미실측 |

### 2.1 M7 상세 — 절전 추가 세팅이 없다는 주장

현 `func_sleep` → `apply_sleep_settings` → `ci_power_sleep` → `reseed` 경로는 다음 다단계 추가 세팅의 묶음이다:

| 단계 | 세팅 내용 | 코드 위치 |
|---|---|---|
| 터치 해제 대기 | pressed 동안 100ms 폴링 블로킹 | `main.c:797~` |
| 둔감화 | touch_settings **255/255** write | `apply_sleep_settings:965` |
| ATI 재기록 | SLEEP ATI Setup + FIXED MULT/COMP | `973~1007` |
| CH Timeout Disable | 0xC0 MSB 0x07 | `1011` |
| 클럭 강하 | E8300 SYSCLK 30.72M → 2.56M | `ci_power_sleep` |
| Reseed | touch_settings 100/80 + 0xC0 0x08 | `reseed:921·932` |

M7("절전에서 추가 세팅 불필요")은 현 코드와 **정반대**. 더불어 절전 진입 시 IC 전력 모드는 여전히 미설정(NP 고정 추정)이라, 절전 실효는 E8300 클럭 강하에서만 발생하고 IQS323의 자체 절전은 이뤄지지 않고 있다.

### 2.2 M8 전력 관점 — autoATI 상시 운용 가능성

autoATI Full + 자동 Re-ATI를 활성화했을 때의 전력 시나리오:

| 시나리오 | 전력 모드 | 예상 IC 소비 | 비고 |
|---|---|---|---|
| 현재(ATI Disabled, 200ms 폴링) | NP 고정 추정 | ~125µA(3ch 기준, 1ch 미측) | 폴링 250ms(?) 주기 |
| autoATI Full + Channel Timeout 없음 | Automatic(ULP 가능) | ~4µA(ULP 3ch) ~ 더 낮을 수 있음 | stuck 복구 상실 위험 |
| autoATI Full + Channel Timeout 활성 | Automatic **No ULP** 강제 | ~37µA(LP 3ch, 1ch 미측) | ULP 차단, stuck 복구 유지 |
| ATI Full + Re-ATI 수동(터치 해제 후만) | Automatic(정책 선택) | 설정에 따라 4~37µA 범위 | 이전 분석 권고 방향 |

> [!NOTE]
> **배터리 예산 부재**: `docs/참고/touch/개발 요구 사항 및 예상 문제 정리.md` 등 전체 문서에서 인공와우 절전 허용 전류 수치가 **0건** 검색된다. autoATI 상시 실행이 배터리 상 허용되는지 판단 자체가 불가능한 상태다. 실측 게이트 통과 전 "가능하다"/"불가능하다" 모두 주장 불가.

## 3. 절전 모드별 autoATI 영향 심층 분석

### 3.1 NP(Normal Power) — 현재 실질 동작 모드

- IC가 매 16ms(self-cap, report rate reset 기본값 0이면 IC 내부 기본값으로 동작할 수 있음 — 확인 필요)마다 전체 채널 conversion 수행
- autoATI Full 재활성 시: 드리프트 감지 → 자동 Re-ATI 트리거 가능 → ATI 중 I²C 무응답 위험([이전 분석 A6 §2.3], [B6])
- **ATI 완료까지 수십~수백ms I²C 접근 불가** → 폴링 기반 현 코드에서 이 구간 처리 미비

### 3.2 LP(Low Power) — Channel Timeout 사용 시 최저 도달 가능 모드

- report rate 60ms → 전류 ~37µA(3ch)
- Channel Timeout과 autoATI 공존 가능: `Automatic No ULP`로 NP↔LP 자동 스테핑, ULP 미진입
- Re-ATI 트리거 빈도가 낮으면(drift 없으면) 평균 LP에 가깝게 유지 가능
- **이것이 stuck 복구(Channel Timeout)를 살리면서 최저 전력을 얻는 현실적 상한선**

### 3.3 ULP(Ultra Low Power) — Channel Timeout 포기 시에만 가능

- report rate 160ms → 전류 ~4µA(3ch)
- [02 §5.8] WARNING에 따라 Channel Timeout 사용 시 **ULP 진입 금지**
- ULP를 얻으려면: Channel Timeout(stuck 복구) 전면 포기 → 손 안 떼는 케이스에서 무한 stuck 위험
- 절전 전용으로 Channel Timeout을 비활성화하고 ULP 진입하는 옵션은 있으나, autoATI Re-ATI 발동 시 LP/NP로 즉시 복귀(ATI 사이클 중 전력 상승)

### 3.4 저속 클럭(2.56MHz) 환경에서 autoATI 동작 가능성

현 절전 코드는 E8300을 2.56MHz로 강하하면서도 IQS323 자체는 내부 14MHz CPU로 독립 동작한다. 이론상 IQS323의 ATI 수렴은 14MHz 기반이므로 E8300 클럭과 독립이지만:

- **저속 클럭에서 I²C master 타이밍**: 2.56MHz E8300에서 I²C fast mode(400kHz) 생성 가능 여부, ATI 완료 polling 주기의 타이밍 여유 — 코드 근거 없음, 미검증
- **Report Rate 미설정(0x0000)**: IC 기본 Report Rate가 불명확 → ATI 수렴 시간 예측 불가

## 4. 200ms CRX0 방전 코드의 전력 영향

현재 `discharge_crx0()`가 200ms마다 `0x30 LSB`에 0x02→0x01 write하며 방전을 수행한다. 이전 분석 B2에서 확인된 바:

- **0x30 0x02는 Linearise 비트일 가능성** — 실제 VSS 방전이 아닐 수 있음(실측 미확인)
- 200ms 폴링 자체가 E8300을 지속적으로 깨워 I²C 트랜잭션을 발생시킴 → 절전 효과 감소

autoATI Full 재활성 + Full ATI가 드리프트를 칩 자체 보정으로 해결한다면 200ms 방전 루프 제거 가능 → 폴링 busy-loop 소멸 → **전력 관점에서는 autoATI 복귀가 절전에 유리**. 단 이는 ESD 물리 누적(방전으로만 해결 가능)을 autoATI가 대체할 수 있다는 전제 하에서만 성립한다(이전 분석: LTA 드리프트≠ESD 물리 누적, 구분 실측 필요).

## 7. 전력 관점 권고

### 단기 (현 구조 내 개선)

1. **0xC0 PM 필드 write 추가**: 운용 시 `Power Mode = Automatic No ULP`, 절전 시 `Power Mode = LP` 또는 `Automatic No ULP`로 명시 설정 → IC 자체 절전 효과 확보(현재 0% 활용)
2. **Report Rate 설정 추가**: 0xC1(NP rate)·0xC2(LP rate) write → 실 report rate 제어로 전류 절감
3. **0xC0 PM 현재값 RTT 모니터링**: 운용·절전 상태에서 IC 실제 전력 모드 가시화

### autoATI Full 재활성 시 전력 정책

- **Channel Timeout 포함(권장)**: `Automatic No ULP` 채택 → LP 스테핑 가능, stuck 복구 유지, ULP 포기
- **Channel Timeout 미포함(절전 전용)**: `Automatic` 채택 → ULP 진입 가능(~4µA 목표), stuck 복구 없음 → 절전 전용 한정 허용 검토 가능
- **200ms 폴링 제거**: autoATI 드리프트 대체 성공 시(실측 후) → busy-loop 소멸 → 평균 전류 추가 절감

## 8. 결론

> 전력 관점 핵심 결론 (한 줄): **현 IQS323은 IC 전력 모드를 전혀 활용하지 않아 절전 효과가 E8300 클럭 강하에만 의존하며, autoATI Full 재활성화 + Channel Timeout 공존 시 Automatic No ULP 강제로 LP(~37µA)가 달성 가능한 최저선이다 — 그러나 인공와우 배터리 예산이 미확보 상태라 허용 여부 자체를 판정할 수 없어 실측 게이트가 선행 필수다.**

은수님 M7·M8 중 전력 관련 주장(절전 추가 세팅 불필요·autoATI로 방전 대체)은 현 코드 사실관계와 반대이거나 전제가 미성립한다. 다만 은수님 M8의 방향성(autoATI로 드리프트 자체 보정)이 성공하면 200ms 폴링 방전 루프 제거로 오히려 전력에 유리해지는 면이 있다. 최우선 실측 게이트는 ① 배터리 예산 사양 확보 ② 1ch NP/LP 실전류 측정 ③ 0xC0 PM 현재값 확인이다.
