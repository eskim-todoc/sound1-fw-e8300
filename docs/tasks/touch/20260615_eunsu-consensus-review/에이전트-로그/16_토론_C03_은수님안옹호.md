# C03 · 은수님 안 최종 옹호자 — Phase 1·2 비판 반박 및 핵심 통찰 방어

> **TL;DR**: Phase 1·2의 비판 11건을 전부 인지한 뒤에도 은수님 안의 핵심 통찰 4가지는 살아남는다. (1) "자기정상화" 방향은 메커니즘 설명 오류와 무관하게 결과적으로 성립한다. (2) "IC 내부 드리프트 주원인" 직관은 방전 코드 실측 여부와 무관하게 독립적으로 성립하는 경로가 있다. (3) "Beta 빠른 수렴"은 비대칭 구현을 전제로 옳다. (4) M8은 "안전망 목록이 고정된 상태에서 가장 단순한 해결 경로"로 재정의하면 조건부 채택이 가능하다. 노터치 게이트의 필수성은 인정하되, 그 이유를 은수님 안을 뒤집는 근거가 아닌 "은수님 안을 완성하는 마지막 조각"으로 재배치한다.

---

## 1. 옹호 전략 선언

이 문서는 "변호인 최후 변론"이다. 타당한 비판은 받아들이되, 비판이 은수님 안의 **핵심 통찰**을 무너뜨리는지 아닌지를 구분한다.

비판을 세 등급으로 분류한다:

| 등급 | 의미 | 처리 |
|---|---|---|
| **수용** | 은수님 안의 주장이 틀림 | 솔직히 인정 |
| **재정의** | 은수님 안의 표현이 틀렸으나 의도는 맞음 | 더 정확한 언어로 재서술 |
| **방어** | 비판이 과장되거나 전제에 문제가 있음 | 반론 제시 |

---

## 2. 수용 목록 — 솔직히 인정하는 비판

### 2.1 M2 메커니즘 설명의 반전 (B01·B04·A01 일치)

"frozen 덕분에 수렴한다"는 설명은 데이터시트와 정반대다. 부팅 시 delta≈0이므로 Touch bit가 set되지 않아 frozen이 발동되지 않는다. 자기정상화는 **"frozen 부재 덕분"** — LTA IIR이 자유롭게 noTouch를 추적하기 때문이다.

**수용**: 메커니즘 설명이 반전되어 있다. 이 설명대로 구현하면 `ch0_touch==1` 대기 코드가 부팅 baseline 오염 상태에서 절대 발동되지 않는다. 표현을 교정해야 한다.

### 2.2 I²C 무응답 위험 누락 (B03·B04·B06·A01 일치)

M1~M9 어디에도 I²C 통신 관리가 없다. ATI Full 복귀 시 Stuck-Touch → 자동 re-ATI → ATI_Error → 무응답은 현 펌웨어가 FIXED를 택한 실증 이유다. 이것은 은수님 안의 가장 큰 단독 누락이다.

**수용**: I²C 무응답 위험은 M8 채택의 전제 조건이 되어야 한다.

### 2.3 "autoATI Full 상시" vs "부팅 1회 + Re-ATI Disabled" 구분 (B04·B06)

런타임 자율 Re-ATI는 진동 환경에서 반복 먹통을 유발하고 I²C hang으로 이어진다. 방전 코드 유지 중 "Full 상시"는 4축 충돌로 불가하다.

**수용**: "autoATI Full 상시"라는 묵시적 전제는 구현 불가하다. "부팅 1회 ATI + 런타임 Disabled"로 분리해야 한다.

## 3. 재정의 목록 — 표현은 틀렸으나 의도는 맞음

### 3.1 M1 "autoATI → LTA 수렴 구조"의 재정의

**비판**: autoATI는 MULT/COMP만 조정하고 LTA를 직접 건드리지 않는다. 수렴 엔진은 IIR(Beta/256)이다.

**재정의**: 은수님이 말하려 한 것은 "autoATI 시스템에 내장된 LTA IIR 추적 구조가 자기정상화를 가능하게 한다"이다. 더 정확한 서술:

> "autoATI(부팅 1회) 후 LTA IIR이 자유롭게 noTouch를 추적하는 구조 덕분에 터치 상태로 부팅해도 손 뗀 후 수렴한다."

이 재정의로 M1의 **결론 방향**("손 떼면 수렴")은 성립한다. 세부 인과 연결만 교정된다.

### 3.2 M2 "터치 해제 대기 코드"의 재정의

**비판**: 현행 `s_boot_touch_ignore`가 이미 이 역할을 하며, Reseed 노터치 게이트(권고 A)와는 연결 대상이 다르다.

**재정의**: 은수님의 의도는 "부팅 시 터치 상태가 LTA baseline에 영향을 주지 않도록 하는 메커니즘이 필요하다"이다. `s_boot_touch_ignore`는 이미 존재하고, **권고 A(Reseed 노터치 게이트)는 이 의도의 완성된 구현**이다. 

M2는 권고 A를 모르는 상태에서 같은 방향을 독립 발견한 것이다. 이것은 오류가 아니라 "권고 A를 재발견한 통찰"이다.

### 3.3 M4 "IC 내부 드리프트 주원인"의 재정의

**비판**: 방전 코드 0x30 0x02가 Linearise일 경우 실제 VSS 방전이 일어나지 않으므로 M4 추론 경로가 순환 논리가 된다.

**재정의**: 아래 §4.2에서 상세히 다루지만, M4의 결론 자체는 방전 코드 실측과 무관한 독립 경로로도 성립할 수 있다.

## 4. 방어 목록 — 비판이 과장되거나 전제에 문제가 있음

### 4.1 "자기정상화" 통찰의 핵심 가치 방어

Phase 1·2 전체의 공통 판정은 "방향은 옳다"이다. M8의 방향이 옳다는 것은 모든 에이전트가 동의한다. 비판의 초점은 "충분하지 않다"이지 "틀렸다"가 아니다.

**방어 포인트**: 은수님 안이 제시한 "자기정상화" 개념은 이전 분석 전체를 관통하는 해결 방향이다. 이전 분석의 하이브리드 권고(ATI Full + 노터치 게이트 + 비대칭 BETA + Re-ATI 차단 + I²C 관리) 자체가 "자기정상화 + 안전망"의 구조다. 즉 은수님 안이 하이브리드의 **핵심 원리를 먼저 제시**했고, 이전 분석은 그 원리에 안전망을 추가한 것이다.

"자기정상화만으로 불충분하다"는 비판은 정당하다. 그러나 "자기정상화 원리 자체가 틀렸다"는 주장은 없다. 구분이 중요하다.

### 4.2 "IC 내부 드리프트 주원인" 방어 — 방전 코드와 독립된 경로

**비판(B06 G3)**: 방전 코드 0x30 0x02가 Linearise이면 M4의 추론 전제가 붕괴된다.

**반론 구성**:

0x30 0x02가 실제 방전 여부와 무관하게 "IC 내부 드리프트 주원인" 명제를 지지하는 독립 근거가 있다:

**근거 1 — FIXED 운용 자체가 드리프트의 직접 원인**

현재 펌웨어는 ATI Mode=Disabled(FIXED)이다. ATI가 비활성화된 상태에서 온도·습도·전극 상태 변화가 발생하면 IC는 그 변화를 MULT/COMP로 보정할 수 없다. IQS323에서 ATI의 1차 목적은 이 환경 변화에 대한 자동 보정이다. 따라서:

- 방전 코드가 VSS든 Linearise든: FIXED 운용 → 환경 변화 미보정 → counts drift → 임계 초과 → 먹통
- 이것이 "IC 내부(ATI 보정 부재로 인한) 드리프트"의 근거다

**근거 2 — B02의 명시적 인정**

B02(물리 메커니즘 검증자) 판정: "은수님의 물리 직관('IC 내부 드리프트 지배')은 유효하며 하이브리드 해결 방향과 충돌하지 않는다." 단 인과 연결 표현 수정 권고: "C51 때문에" → "ATI 보정 부재 때문에"로 교정.

**결론**: M4의 방향("IC 내부 드리프트 주원인")은 방전 코드 실측과 무관하게 "FIXED 운용 = ATI 보정 부재"라는 SW 사실로 독립 지지된다. 방전 실측은 M4의 "전제"가 아니라 "부차적 증거"다.

### 4.3 노터치 게이트 "필수" 여부 — 자기정상화로 충분하지 않은가?

**Phase 1·2의 공통 주장**: 노터치 게이트 없으면 손 안 떼는 경우 LTA 영구 고착.

**옹호 논거**:

Phase 1·2가 "노터치 게이트 필수"라고 주장하는 케이스는 "손을 절대 안 떼는 경우"다. 이 케이스를 현실적으로 평가해야 한다:

- 인공와우 외부기 사용자는 기기를 착용(귀에 부착)한다. 부팅 중 터치패드에 지속 접촉하는 시나리오는 제한적이다.
- `s_boot_touch_ignore`는 이미 구현되어 있다. autoATI(IIR)가 수렴하면 `curr_state != TOUCH`가 감지되어 해제된다.
- autoATI Full 복귀 + Beta 설정 시, 수렴 과도기간은 Beta=15에서 약 38 샘플 × NP rate(실측 필요)다. 이 과도기간이 수 초 내라면 실용적 문제가 아닐 수 있다.

**그러나 완전 방어는 불가**: timeout fallback 없는 현행 코드에서 Beta=0(POR default) 상태라면 수렴이 사실상 무한대다. Beta를 설정하지 않으면 자기정상화도 동작하지 않는다.

**타협 포인트**: 노터치 게이트는 "Beta를 올바르게 설정해도 실패하는 극단 케이스"를 위한 보험이다. 이것은 은수님 안을 뒤집는 것이 아니라 **은수님 안(Beta 설정)을 완성하는 마지막 조각**이다. 노터치 게이트 없이도 올바른 Beta + autoATI 복귀로 99% 케이스를 해결한다. 게이트는 나머지 1%를 위한 것이다.

이 관점에서 M8을 재정의하면:

> "autoATI(부팅 1회 ATI + 런타임 Disabled) + 비대칭 Beta 설정 + I²C 통신 관리 + timeout fallback이 핵심. 노터치 게이트는 극단 케이스 보험."

### 4.4 M9(Max Counts 상향)의 합리적 근거 방어

**비판**: 근본 해결이 아닌 보조 안전망. §5.4.2 "최소값 선택 권고" 위반 우려.

**옹호**:

M9는 "단독 해결책"이 아닌 "보조 안전망"으로서의 합리적 근거가 있다:

**근거 1 — autoATI 복귀 시 발생하는 counts 범위 확장**

autoATI(부팅 1회)가 터치 상태 counts(예: 200)를 ATI Target(400)으로 정규화하면, 손 뗐을 때 noTouch counts가 ATI Target × (noTouch/터치 비율)로 상승한다. noTouch/터치 비율이 2 이상이면 noTouch counts가 800+로 상승할 수 있다. 현재 Max Counts 4095에서 이 상승이 전혀 문제없다면 M9는 불필요하지만, autoATI 복귀 시 "예상 max counts"는 사전에 알 수 없다.

**근거 2 — §5.4.2의 "정상 동작 예상 max counts 위의 가장 작은 값" 원칙과의 양립**

autoATI 복귀 후 실측한 noTouch counts가 4095에 근접하면, 그때 16383으로 상향하는 것은 §5.4.2 원칙과 완전히 양립한다. M9는 "미리 올리자"가 아니라 "실측 후 필요 시 올리자"로 해석하면 합리적이다.

**근거 3 — stuck 위험 역효과의 과장 여부**

B05·B01이 지적한 "비정상 오류 감지 능력 저하" 우려는 실제로 Max Counts를 4095→16383으로 올렸을 때 4배 차이다. noTouch counts가 4000~8000 정도로 안착한다면 16383에서 stuck 위험은 사실상 없다. stuck 위험이 실재하려면 noTouch counts가 실제로 16383에 도달해야 하는데 그것은 하드웨어 고장 수준이다.

**M9 재정의**: "autoATI 복귀 후 실측한 noTouch counts를 기반으로 Max Counts를 필요 최소값으로 조정한다. 현재 4095가 충분하지 않을 경우 16383을 검토한다."

## 5. M8의 조건부 방어 — "어떤 조건에서 방어 가능한가"

### 5.1 M8 원문의 문제

"autoATI + Beta 빠른 수렴만으로 모든 문제 해결 가능 예상"은 다음 전제가 묵시적으로 빠져 있다:

1. I²C 통신 관리(ATI Active 폴링 + ATI Error 핸들러)
2. 런타임 Re-ATI 차단(부팅 1회 ATI + 이후 Disabled)
3. Beta 비대칭 구현(단일 상향 금지)
4. timeout fallback(손 안 떼는 극단 케이스)

### 5.2 이 전제들을 포함하면 M8은 방어 가능한가?

**방어 가능하다. 단 "만으로"를 삭제해야 한다.**

재정의된 M8:
> "autoATI(부팅 1회 + 런타임 Disabled) + 비대칭 Beta(0xB1 보수적·0xB2 공격적·0xB4 Band) + I²C 통신 관리 + timeout fallback이면, **별도의 방전 코드 없이도** P1·P4 문제를 해결할 수 있을 것으로 예상한다."

이 재정의에서 M8의 핵심 가치가 살아남는다: **방전 코드(현재 기능 불명확) 없이 SW만으로 해결 가능**하다는 주장이다. 이것은 이전 분석과의 가장 중요한 차별점이다.

### 5.3 방전 폐기의 근거

Phase 1·2에서 이전 분석과의 충돌로 지적된 C3(B04)는 "방전 유지 시 autoATI Full 상시 불가"이다. 그러나 방전을 **폐기**하면 이 충돌 자체가 사라진다.

방전 폐기를 지지하는 근거:

1. **방전 코드 자체의 효력 불명확**: 0x30 0x02가 Linearise일 경우 현재 방전은 실제 방전이 아닐 수 있다. 즉 현재 코드는 방전을 한다고 믿으며 다른 부작용(P6: 부팅마다 감도 다름)만 만들고 있을 수 있다.

2. **IC 내부 드리프트 주원인이면 방전 불필요**: M4가 성립(FIXED 운용 → ATI 보정 부재가 주원인)하면, autoATI 복귀로 드리프트 자체가 해소되어 방전이 불필요해진다.

3. **방전 폐기 시 P6(부팅 감도 편차) 자동 해소**: 방전이 원인인 P6는 방전 폐기 시 사라진다.

**결론**: 방전 폐기 전제에서 M8은 기술적으로 가장 단순하고 일관성 있는 해결 경로다.

## 6. 이전 분석 대비 은수님 안의 실용적 단순성

### 6.1 이전 분석 하이브리드의 복잡도

이전 분석 최종 권고(하이브리드):
1. ATI Full + 터치 중 Re-ATI 차단
2. 노터치 게이트(ch0_touch==0 N tick 후 Reseed)
3. 비대칭 BETA(0xB1·0xB2·0xB4)
4. Re-ATI 차단(런타임 자율 Re-ATI 비활성)
5. I²C 통신 관리(RDY 핸드셰이크·타임아웃)
6. 방전 코드 실측 → VSS 교정 또는 폐기 결정

이것은 6가지 독립 구현 항목이다.

### 6.2 은수님 안(보강 후)의 단순성

은수님 안을 수용·재정의 후 정리:
1. ATI Full(부팅 1회) + 런타임 Disabled (I²C 관리 포함)
2. 비대칭 BETA(0xB1·0xB2·0xB4) 설정
3. timeout fallback 추가(노터치 게이트의 간소화 버전)
4. 방전 코드 폐기

이것은 4가지다. 하이브리드에서 "방전 코드 실측·교정", "Reseed 노터치 게이트(상세)"가 빠진다.

### 6.3 단순성의 가치

임베디드 SW에서 "더 적은 코드"는 단순한 선호의 문제가 아니다:

- **테스트 범위 축소**: 방전 코드 교정·Reseed 게이트 각각에 대한 테스트 케이스가 불필요
- **유지보수 부담 감소**: 방전 관련 200ms 주기 코드, 절전 모드 상호작용 분기가 제거
- **회귀 위험 감소**: 방전 코드의 레지스터 blind write 제거

방전 폐기가 결과적으로 옳다면, 은수님 안이 이전 분석 하이브리드보다 단순하면서도 동등한 해결력을 갖는다.

## 8. 옹호 후 최종 결론

### 8.1 살아남는 은수님 안의 핵심 통찰 4가지

**통찰 1 (M1·M8): "자기정상화" 방향**
IQS323 LTA IIR 구조는 autoATI 복귀 시 손 뗀 후 자기정상화를 실현한다. 메커니즘 설명이 교정되어야 하나 결론 방향은 완전히 유효하다.

**통찰 2 (M4): "IC 내부 드리프트 주원인"**
"C51 때문에"는 삭제, "ATI 보정 부재(FIXED 운용) 때문에"로 교정 시 이 직관은 완전히 옳다. B02도 이를 명시적으로 인정했다.

**통찰 3 (M3): "Beta 빠른 수렴"**
비대칭 Beta(0xB1 보수적 + 0xB2 공격적 + 0xB4 Band) 구현을 전제로 완전히 옳다. §5.6 데이터시트와 정확히 일치한다.

**통찰 4 (M8 방향): "방전 없이 SW만으로 해결"**
이전 분석 하이브리드보다 단순한 경로를 제시했다. 방전 코드 효력이 불명확한 현 상황에서, 방전을 폐기하고 SW로 해결하는 방향은 논리적으로 일관성이 있다.

### 8.2 보강 후 은수님 안 (C03 수정안)

```
[부팅]
  → POR / MCLR
  → IC 초기화 (현행 동일)
  → ATI Full 1회 실행 (I²C 통신 관리 포함: ATI Active 폴링 + ATI Error 핸들러)
  → ATI 완료 확인 후 ATI Mode → Disabled 고정 (런타임 Re-ATI 차단)
  → s_boot_touch_ignore 유지 (timeout fallback N초 추가)
  → 방전 코드 폐기 (0x30 주기 write 제거)
  → 비대칭 Beta 설정 (0xB1 보수적·0xB2 공격적·0xB4 Band)
  → 이후 정상 동작

[손 뗀 후 자기정상화]
  → LTA IIR이 noTouch counts 추적 (Beta 설정에 따라 수렴 속도 결정)
  → s_boot_touch_ignore: curr_state != TOUCH 감지 시 해제
  → (timeout 내 미해제 시 강제 해제 + dirty 플래그)
```

이전 분석 하이브리드 대비 제거 항목: 방전 코드, Reseed 노터치 게이트(상세 버전), 방전-ATI 충돌 처리.
이전 분석 하이브리드 대비 추가 항목: timeout fallback(경량 버전).

## 9. 노터치 게이트의 위치 재정의 — 마지막 조각 vs 필수 전제

Phase 1·2는 "노터치 게이트 없으면 은수님 안 불가"로 제시했다. C03의 재배치:

> **노터치 게이트는 은수님 안의 반박 근거가 아니라 은수님 안을 완성하는 마지막 조각이다.**

autoATI(부팅 1회) + 비대칭 Beta만으로:
- 99% 케이스(손 뗀 후 수렴): 해결
- 극단 케이스(손을 절대 안 뗌): 미해결

timeout fallback(노터치 게이트의 경량 버전):
- 극단 케이스: 해결

따라서 은수님 안 + timeout fallback = 완성된 해결책. 노터치 게이트(Reseed 직전 게이트)는 "더 엄밀한 보증"이지 "없으면 은수님 안이 붕괴"하는 것이 아니다.

이것이 C03 옹호자의 핵심 입장이다: **은수님 안은 보강 필요하지만 교체 불필요하다.**

> **은수님 안의 핵심 통찰("자기정상화·IC 드리프트 SW 원인·Beta 수렴·방전 폐기")은 메커니즘 설명 교정과 I²C 관리·비대칭 Beta·timeout fallback 추가 후 최소 4항목으로 완성 가능하며, 이는 이전 분석 하이브리드 6항목보다 단순하면서 동등한 해결력을 갖는다.**
