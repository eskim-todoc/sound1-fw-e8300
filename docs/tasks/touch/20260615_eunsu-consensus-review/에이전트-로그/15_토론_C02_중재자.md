# C02 · 중재자 — Phase 1·2 대립 의견 타협안

> **TL;DR**: 논쟁 3건(autoATI+Beta 충분성·방전 필요성·터치해제대기 vs 노터치게이트)을 중재한다. 타협안 요약: (1) autoATI+Beta는 필요하나 충분하지 않고 노터치 게이트가 추가 필수, (2) 방전은 "실측 후 폐기 검토"가 유일한 중재 경로, (3) "터치 해제 대기"와 "Reseed 노터치 게이트"는 계층이 다른 별개 코드로 둘 다 필요하다. I²C 통신 관리는 타협 없이 선행 필수다.

---

## 1. 중재 대상 및 전제

### 1.1 중재 입력 요약

Phase 1(A01~A07)과 Phase 2(B01~B06) 전체를 통틀어 수렴한 공통 기반:

- 은수님 M1~M9의 **방향성** 자체는 Phase 1·2 모두 "옳다"고 인정 (전원 조건부)
- 성패를 가르는 안전망 3개: (1) 노터치 게이트, (2) 비대칭 Beta, (3) I²C 통신 관리
- 이전 분석 "하이브리드 권고" 5요소(ATI Full + 노터치 게이트 + 비대칭 Beta + Re-ATI 차단 + I²C 관리)는 Phase 1·2 모두 지지

대립이 실재하는 논쟁 3건:

| # | 논쟁 | 한쪽 | 다른 쪽 |
|---|---|---|---|
| 논쟁_1 | autoATI + Beta만으로 충분한가 | 충분(은수님 M8) | 노터치 게이트도 반드시 필수(A07·B04·B06) |
| 논쟁_2 | 드리프트 주원인이므로 방전 불필요한가 | 불필요 방향(M4·M8 함의) | ESD 물리누적 미실측이므로 방전 유지(B05·B02) |
| 논쟁_3 | "터치 해제 대기"와 "Reseed 노터치 게이트"는 같은가 | 같거나 대체 가능(M2 전제) | 다르고 둘 다 필요(B03·B04) |

## 2. 논쟁_1 중재 — "autoATI + Beta만으로 충분" vs "노터치 게이트 필수"

### 2.1 대립 핵심 정리

**은수님 M8 측**:
- autoATI는 LTA→카운터 수렴 구조이므로, 부팅 시 터치된 채 LTA가 오염되더라도 손을 떼면 IIR이 noTouch를 자유롭게 추적해 자기 수렴한다
- Beta 빠른 수렴 설정으로 수렴 시간을 단축하면 실용적 문제가 없다
- 노터치 게이트는 추가 복잡도로 불필요한 과잉 방어

**노터치 게이트 필수 측(A07·B04·B03)**:
- "frozen 부재 덕분에 수렴"이라는 메커니즘은 맞지만, 손을 절대 안 떼는 경우 LTA가 오염된 채 고착된다
- 수렴 과도기간 동안 재터치 미인식 위험이 존재한다
- P1의 진짜 뿌리는 autoATI 자체가 아니라 Reseed 타이밍이므로, autoATI 복귀만으로는 P1이 해결되지 않는다

### 2.2 타협 불가 확인 — 손 안 떼는 경계 조건

양측이 공통으로 인정하는 사실:
- autoATI 자기수렴은 **손을 뗀다는 전제** 하에 성립한다
- 손을 안 떼면 LTA는 오염된 상태로 고착되고, 이후 어떤 Beta 설정도 수렴을 보장하지 못한다

이 경계 조건에서 autoATI+Beta 단독 채택은 어떤 쪽도 방어할 수 없다.

> [!IMPORTANT]
> **타협 불가 항목**: 노터치 게이트(손 안 떼는 경계 조건 처리)는 생략 불가다. 이것은 "추가 안전망"이 아니라 autoATI 자기수렴의 **전제 조건을 보장하는 코드**다.

### 2.3 중재 타협안

**타협안_1**: "autoATI + Beta + 노터치 게이트"는 단계적으로 구현하되, 구현 순서를 다음과 같이 합의한다.

```
1단계: Reseed 노터치 게이트 구현 (ch0_touch==0 N tick → Reseed 허용)
  → P1(LTA 오염 원천 차단) 독립 검증 가능
  
2단계: autoATI Full 복귀 + 비대칭 Beta 구현
  → P4(드리프트 누적 먹통) 개선 검증 가능
  
3단계: 1단계 + 2단계 통합 RTT 검증
```

이 순서로 구현하면:
- 은수님이 M8에서 의도한 "자기수렴" 효과는 2단계에서 충분히 검증된다
- 노터치 게이트는 1단계에서 먼저 독립 동작해 P1을 해소한다
- 두 구조가 서로 다른 뿌리(Reseed 타이밍 vs ATI 보정 부재)를 각각 담당함이 단계 검증으로 확인된다

**autoATI 복귀 시 Re-ATI 차단 필요성 합의**:

은수님 M8의 "autoATI"가 "부팅 1회 ATI + 런타임 자율 Re-ATI"를 구분하지 않는다는 B06(G2)의 지적은 타협 가능하다:

- 은수님 의도: "autoATI가 드리프트를 스스로 교정하는 기능을 살리겠다"
- 실제 필요 구조: **부팅 1회 ATI(Full) + 런타임 자율 Re-ATI Disabled** + LTA 비대칭 Beta 추적

이 구조는 은수님 의도를 보존하면서 "런타임 자율 Re-ATI로 인한 I²C hang·진동 오인 Re-ATI" 위험을 제거한다. 은수님 M8의 표현을 이 방향으로 재해석하면 양측 수용 가능하다.

## 3. 논쟁_2 중재 — "드리프트 주원인이므로 방전 불필요" vs "ESD 미실측이므로 방전 유지"

### 3.1 대립 핵심 정리

**방전 불필요 방향(M4·M5·M8 함의)**:
- DC 블로킹 캡(C51) 때문에 전극측 물리 전하가 IC에 DC적으로 영향을 주기 어렵다
- 충전기 연결 시 복귀는 IC 리셋(POR) 메커니즘이 주효과이며 방전 코드의 물리 효력과 관계없다
- 드리프트는 ATI 보정 부재(SW)가 주원인이므로, autoATI 복귀로 방전 없이도 해결 가능하다

**방전 유지 측(B05·B02·B04)**:
- 방전 코드 `0x30 0x02`가 실제로 VSS 방전인지 Linearise인지 실측 미확인 (이전 분석 B2 라이브 발견)
- ESD 물리 누적 기여도가 실측 게이트 7종 미완료 상태에서 "0"으로 단정 불가
- "방전 폐기"는 물리 전하 누적 기여가 존재할 경우 그 경로를 완전히 차단하므로 리스크가 크다

### 3.2 논리 구조 점검 — 방전 폐기의 전제 충족 여부

방전 불필요 주장이 성립하려면 다음 두 전제가 모두 성립해야 한다:

| 전제 | 현재 상태 | 성립 여부 |
|---|---|---|
| 전제_A: 방전 코드가 실제로 물리 방전을 수행한다 (그래서 "방전에도 불구하고 드리프트" 증거가 의미 있다) | 0x30 0x02 = Linearise 가능성 (미실측) | **미확인** |
| 전제_B: ESD 물리 전하 누적 기여가 없거나 무시 가능하다 | 실측 게이트 7종 미완료 | **미확인** |

B02(물리메커니즘 검증)의 핵심 지적: "방전 코드가 실제 방전이 아니었다면, 이미 실질적으로 방전 없이 운영해온 것이다. 따라서 방전이 드리프트 억제에 기여했다는 증거가 없고, '방전에도 불구하고 드리프트'라는 논거 자체가 성립하지 않는다."

이 역설적 구조를 중재한다:

> [!WARNING]
> 전제_A가 미확인인 상태에서 "방전 폐기 후 autoATI"를 선택하는 것은 **기존 방전이 Linearise였다면 이미 방전 없이 운영 중이던 것을 그대로 유지하는 것**이 되어 실질 변화가 없다. 그러나 기존 방전이 실제 VSS 방전이었다면 물리 누적 방어를 제거하는 변화가 된다.

### 3.3 타협안

**타협안_2**: "방전 폐기"는 실측 선행 후 판단하고, 방전 코드 교정(Linearise → 실제 VSS)은 autoATI 구현과 병행 진행한다.

구체적으로:

```
즉시: 방전 코드 0x30 0x02의 실제 동작 RTT 실측
  → CRX0 핀 전압·counts 변화 관찰 (VSS 단락이면 핀이 0V로 당겨짐)
  
실측 결과 A (Linearise 확인): 방전이 물리 효력이 없었음 확인
  → "방전 폐기"는 실질적 변화 없음 → autoATI 도입 후 방전 루프 제거 결정 가능
  → 단, 실제 VSS 방전(0x34 경로) 시도 기회를 한 번은 확보 권고
  
실측 결과 B (VSS 단락 확인): 방전이 실제 물리 효력이 있었음 확인
  → 방전 폐기 시 물리 누적 방어 제거 → ESD 기여도 실측 게이트 통과 전까지 방전 유지
```

이 타협안의 합리성:
- 은수님의 "방전 불필요" 방향을 즉시 부정하지 않는다
- 물리 누적 우려 측의 "실측 없이 폐기 불가" 요구를 수용한다
- 실측 비용이 낮다(RTT 관찰 1회)

**방전 유지 중 autoATI 전환 시 충돌 처리 합의**:

방전 코드와 ATI Full 공존 충돌 4축(B04 C3, B03 §4)은 다음과 같이 해소한다:

```
ATI Full 진행 중 방전 일시 정지:
  ATI Active bit(bit5) 폴링 → set된 동안 discharge_crx0() skip
  ATI 완료 → 방전 재개
```

이렇게 하면 "autoATI 복귀 + 방전 유지"의 임시 공존이 가능하다. 방전 실측 결과에 따라 이후 방전 폐기 여부를 결정한다.

## 4. 논쟁_3 중재 — "터치 해제 대기"와 "Reseed 노터치 게이트"는 같은가

### 4.1 대립 핵심 정리

**같다(대체 가능) 측(M2 전제)**:
- "부팅 시 터치 인식 시 터치 해제 대기 코드"는 현행 `s_boot_touch_ignore`와 동일한 목적이다
- autoATI가 자기수렴하면 터치가 해제됐다고 인식되어 `s_boot_touch_ignore`가 해제된다
- 추가로 Reseed 타이밍을 별도 제어할 필요 없다

**다르고 둘 다 필요 측(B03·B04)**:
- 위치가 다르다: M2는 READY 이후 이벤트 출력 차단(사후 방어), 노터치 게이트는 Reseed 발행 직전 LTA 오염 원천 차단(사전 방어)
- 동작 조건이 다르다: `s_boot_touch_ignore`는 `ch0_touch==TOUCH`가 아니면 해제하는데, 부팅 시 baseline 오염 상태에서는 delta≈0이라 ch0_touch bit가 set되지 않아 "이미 해제된 것처럼" 동작한다
- "frozen 부재 덕분" 메커니즘을 오해하면 "터치 해제 대기"를 `ch0_touch==1 감지 후 대기`로 구현하게 되어 부팅 baseline 오염 시나리오에서 발동 자체가 안 된다

### 4.2 중재 — 계층이 다른 두 코드

B04(C2) 분석이 가장 명확하게 정리했다: 두 코드는 **연결 대상이 다른 별개 방어선**이다.

| 항목 | `s_boot_touch_ignore` (M2 의도) | Reseed 노터치 게이트 (권고 A) |
|---|---|---|
| 보호 대상 | 상위 레이어 터치 이벤트 출력 | LTA 시딩(baseline) |
| 위치 | READY 전이 이후 | `apply_settings()` 내 Reseed 직전 |
| 경계 조건 | timeout 없이 무한 대기 위험 | timeout fallback + dirty 플래그 포함 |
| autoATI 자기수렴 의존 | 의존함(수렴 후 ch0_touch==NOUCH → 해제) | 비의존(ch0_touch==0 N tick 확인 후 Reseed) |

은수님의 "터치 해제 대기"는 "사후 이벤트 차단"이고, 권고 A의 노터치 게이트는 "사전 LTA 오염 방지"다. 두 코드가 서로 다른 레이어를 지키므로 상호 대체 관계가 아니다.

> [!IMPORTANT]
> **타협 불가 항목**: "터치 해제 대기"와 "Reseed 노터치 게이트"는 같지 않고, 둘 다 필요하다. M2가 노터치 게이트를 대체할 수 없다는 것은 타협 없이 확정이다.

### 4.3 타협안 — 구현 통합 방향

**타협안_3**: 두 코드를 하나의 "부팅 시 터치 안전망" 구조로 통합 구현하되, 은수님 M2의 의도를 살리는 이름·위치를 유지한다.

```c
// 제안 구조 (개념 수준)

// [레이어 1] Reseed 노터치 게이트 (drv.c, Reseed 직전)
// → ch0_touch==0 N tick 확인 후 Reseed 허용
// → N tick 내 해제 안 되면: timeout fallback + dirty_lta 플래그 set
// → "은수님 M2의 '터치 해제 대기' 의도"가 이 레이어에서 실현됨

// [레이어 2] s_boot_touch_ignore (tdc_touch.c, READY 이후)
// → dirty_lta 플래그가 없으면 정상 통과
// → dirty_lta 플래그가 있으면 autoATI 자기수렴 대기 + 수렴 완료 시 정상 전환
// → timeout 강제 해제 로직 추가 (현행 5초 경고 후 무한 대기 개선)
```

이 구조에서 은수님의 M2 "터치 해제 대기 코드" 아이디어는 **레이어 1(사전 방어)**에서 더 정확하게 구현된다. 기존 `s_boot_touch_ignore`는 레이어 2로서 추가 방어선 역할을 한다.

`ch0_touch==0` 확인 방식에 대해:
- 부팅 시 baseline 오염 상태에서 ch0_touch가 set되지 않는다는 B04·B03 지적이 맞다
- 노터치 게이트는 `ch0_touch==TOUCH가 아님`을 N tick 연속으로 확인하는 방식이 올바르다
- "frozen 부재 덕분" 메커니즘 이해 없이 "ch0_touch==1 감지 후 대기"로 구현하면 부팅 오염 시나리오에서 발동 자체가 안 된다

## 5. 타협 불가 항목 명확화

Phase 1·2 전체에서 어느 에이전트도 이견을 제기하지 않아 **중재 없이 확정되는 항목**:

### 5.1 I²C 통신 관리 선행 (G1, A01·A02·B03·B04·B06 전원 동의)

- ATI Full 재활성화 전 RDY 핸드셰이크 강화 + ATI Active bit 폴링 + ATI Error 에러 핸들러 구현 필수
- 이를 생략하면 현 펌웨어가 ATI Disabled를 채택한 원인이 재현된다
- 타협 가능한 조건: 없음. autoATI 복귀의 **선행 필수 조건**

### 5.2 비대칭 Beta 설계 (A01·B01·B03 일치)

- LTA Beta 단일 상향: 금지 (약터치 흡수 메커니즘 확실)
- 올바른 구현: 일반 LTA Beta(0xB1) 보수적 + Fast Filter Band(0xB4) + LTA Fast Beta(0xB2) 공격적
- Fast Filter Band 값은 RTT 실측 없이 결정 불가

### 5.3 노터치 게이트와 "터치 해제 대기"의 비등가성 (B03·B04·A07 일치)

- 둘은 다른 코드, 둘 다 필요
- "터치 해제 대기"가 Reseed 노터치 게이트를 대체하는 경우 없음

### 5.4 방전 실측 선행 (B02·B04·B06 일치)

- 0x30 0x02의 실제 동작(VSS vs Linearise) 실측 전까지 방전 폐기 결정 불가
- 방전 폐기 주장(은수님 M4·M5·M8 함의)의 전제 자체가 방전 물리 효력을 가정한다

### 6.1 최종 타협 판정표

| **논쟁_1**: autoATI+Beta 충분 | M8: 충분 | 노터치 게이트 필수 | autoATI+Beta는 필요하나 단독 불충분, 노터치 게이트 병행 필수 | 가산형 타협 (은수님 방향 보존 + 안전망 추가) |

### 6.2 구현 순서 합의 (타협안 통합)

```
0단계(선행): 방전 코드 0x30 0x02 RTT 실측 + I²C 통신 관리 코드 구현
  → 이 두 가지 없이 이후 단계 진입 금지

1단계: Reseed 노터치 게이트 + s_boot_touch_ignore timeout 개선
  → P1 원천 해소 검증

2단계: ATI Full 복귀 + 런타임 Re-ATI Disabled + 비대칭 Beta 설정
  → P4 드리프트 개선 검증

3단계: ATI 진행 중 방전 일시 정지 처리
  → 방전 실측 결과에 따라: 방전 폐기 또는 유지 결정

4단계: 통합 RTT 검증 (부팅 터치·드리프트 시나리오 전수)
```

### 6.3 은수님 M1~M9 재평가

## 7. 중재자 최종 의견

### 7.1 은수님 1차 정리의 가치

은수님의 M1~M9는 문제의 **방향을 정확히 포착**했다. "잘못 시딩돼도 자기 정상화"(M1), "Beta 빠른 수렴"(M3), "autoATI 복귀"(M8) 모두 Phase 1·2 전체가 방향으로는 지지한다.

Phase 1·2가 추가한 것은 방향의 수정이 아니라 **경계 조건과 구현 순서**다:
- 손 안 떼는 경계: 노터치 게이트로 처리
- Beta 단일 상향 경계: 비대칭 설계로 처리
- ATI Full 재활성 경계: I²C 통신 관리로 처리
- 방전 공존 경계: 실측 후 결정, 그 전까지 ATI 충돌만 해소

### 7.2 타협 불가 최소 요건

다음 3가지는 어떤 구현 경로를 선택하더라도 피할 수 없다:

```
[필수 1] I²C 통신 관리 선행 구현
  → 없으면 ATI Full 복귀 자체가 위험

[필수 2] 노터치 게이트 (Reseed 직전 ch0_touch==0 N tick)
  → 없으면 P1이 손 안 떼는 시나리오에서 재현

[필수 3] 비대칭 Beta 설계 (Fast Filter Band + 공격적 Fast Beta)
  → 없으면 M3의 "빠른 수렴"이 약터치 흡수로 역효과
```

이 3가지를 충족하는 구현은 어떤 순서·구조로 진행하더라도 Phase 1·2의 중재 기준을 통과한다.

### 7.3 중재 한계 — 실측 없이 결론 낼 수 없는 항목

다음은 에이전트 토론으로 결론을 낼 수 없고 **실측이 유일한 판단 경로**다:

| 항목 | 실측 방법 | 결정하는 것 |
|---|---|---|
| 방전 코드 0x30 0x02의 실제 동작 | RTT + 핀 전압 측정 | 방전 폐기 가능 여부 |
| Fast Filter Band 최적값 | RTT 실측(노이즈 vs 약터치 delta) | 비대칭 Beta 값 결정 |
| Beta=0 POR default 동작 | RTT LTA 변화 관찰 | 현재 LTA 추적 상태 |
| ATI Full I²C 무응답 재현 | Stuck-Touch 유발 실험 | 통신 관리 로직 충분성 검증 |

이 4종의 실측 없이 구현 완료는 불가하다.

---

> **중재 한 줄 결론**: "autoATI + Beta"는 방향이 옳으나 단독 불충분하고, 노터치 게이트가 병행 필수이며(논쟁_1 가산형 타협), 방전 폐기는 실측 선행 후 판단한다(논쟁_2 지연형 타협), "터치 해제 대기"와 "Reseed 노터치 게이트"는 계층이 달라 둘 다 구현하되 은수님 M2 의도를 노터치 게이트(레이어 1)로 올바르게 실현한다(논쟁_3 명확화형 타협).
