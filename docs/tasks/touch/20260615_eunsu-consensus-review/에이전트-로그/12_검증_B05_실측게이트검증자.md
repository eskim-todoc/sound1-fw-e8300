# B05 · 실측 게이트 검증자 — 은수님 정리 실측/추론 분류 및 M8 확정 게이트

> **TL;DR**: 은수님 명제 M4~M9를 실측/추론 기준으로 분류한 결과, M4·M6·M7은 순수 추론, M5는 현상 실측이나 원인 해석은 추론, M9는 데이터시트 근거 기반 추론이다. M8("모든 문제 해결 가능")을 확신으로 전환하려면 이전 분석 실측 게이트 7종 중 미완료 5종을 포함해 총 9종의 실측 통과가 선행되어야 하며, 그중 4종(I²C 무응답·오염 실채널·자기정상화 과도구간·ESD 원인 분리)은 M8의 "치명 전제"에 직결된다.

---

## 1. 검토 대상 명제 및 역할 정의

본 B05 에이전트는 은수님 정리 M1~M9 중 **실측 없이 결론을 내린 항목**을 찾아내고, 각 결론이 확정되려면 어떤 실측이 필요한지를 adversarial 관점에서 정의한다.

집중 항목:
- **M8**: "autoATI + Beta만으로 모든 문제 해결 가능 예상" — 이 결론을 확신하려면 어떤 실측을 통과해야 하는가?
- **M4~M7**: 물리적 설명들이 실측인가 추론인가?
- **M9**: 카운터 최대값 증가 효과의 근거가 데이터시트인가 경험치인가 추론인가?
- **이전 분석 실측 게이트 7종**: 미완료 항목이 M8 결론에 어떤 영향을 주는가?

## 2. M4~M7 실측 여부 분류

### 2.1 판정표

| 명제 | 내용 | 실측/추론 분류 | 세부 근거 |
|---|---|---|---|
| **M4** | DC 블로킹 캡(C51 100pF) 때문에 터치패드보다 IC 내부 드리프트가 주원인 예상 | **순수 추론** | C51이 고주파 AC 경로를 차단한다는 회로 원리에서 연역. 드리프트 원인을 IC 내부 vs 터치패드로 실채널 분리 측정한 데이터 전무 |
| **M5** | 먹통 + 충전기 연결 → 터치 복귀 (DC 블로킹 캡 있어 터치패드 주원인 아님) | **현상 실측 + 원인 추론 혼재** | "충전기 연결 시 복귀했다"는 관찰은 실측. 그러나 복귀 원인(IC POR·VDD 재인가·GND 경로 안정화 중 무엇인지)은 미분리. "C51 덕분에 터치패드가 주원인이 아니다"는 부차 추론 |
| **M6** | 기구 GND 쇼트 → 터치패드 방전 가능성 있음 | **순수 추론** | 기구가 GND 쇼트될 경우의 논리적 추론. 실제 기구 조건·쇼트 저항 측정 없음 |
| **M7** | 기구 GND 쇼트가 주요 원인 아님 | **M6 기반 2차 추론** | M6 추론 위에 "크기가 작다"는 판단 추가. 실측 배제가 아닌 직관적 배제 |

### 2.2 M5 충전기 복귀 원인 미분리가 갖는 의미

M5에서 "충전기 연결 → 복귀"를 "드리프트가 IC 내부에서 왔고 C51로 차단된 패드쪽은 무관하다"는 결론의 근거로 사용하고 있으나, 이 연결 고리는 성립하지 않는다.

가능한 복귀 메커니즘 후보:

| 후보 | 메커니즘 | C51 역할 | M4 인과와 관계 |
|---|---|---|---|
| **가설_1**: IC 내부 POR | 충전기 VDD 인가 → IC Power-on-Reset → LTA 재초기화 | 무관 | M4 인과 지지 불가 |
| **가설_2**: VDD 전압 안정화 | 방전 직전보다 충전기 VDD가 더 안정 → counts 정상 범위 복귀 | 무관 | M4 인과와 무관 |
| **가설_3**: GND 경로 강화 | 충전기 GND → 패드 GND 경로 안정화 → 전극 용량 기준 복귀 | C51이 DC 블로킹하므로 패드 전하 변화 반영 안 됨 | M4 간접 지지 |
| **가설_4**: 드리프트 IC 내부 자연 소멸 | 충전기 연결과 무관하게 시간 경과 후 자연 수렴 | 무관 | M4 무관 |

**결론**: M5의 관찰 사실만으로는 M4("IC 내부 드리프트가 주원인")를 지지하거나 부정할 수 없다. M5는 M4의 근거가 아니라 **별도 해석이 필요한 독립 관찰**이다.

## 3. M9 — 카운터 최대값 증가 효과의 근거 분류

### 3.1 M9 명제

"ATI Target Counts(카운터 최대값)를 4096보다 크게 하면 더 안정적일까?"

### 3.2 근거 분류

| 구분 | 내용 |
|---|---|
| **데이터시트 근거 (있음)** | A.7 bits[7:6]=11 → Max Counts=16383까지 가능 (A01 검토 확인) |
| **효과 메커니즘 추론** | "더 안정적이다"는 결론은 A01 분석처럼 "터치 중 ATI 정규화 후 noTouch counts 상승 시 conversion 정지 방지"라는 추론에서 도출 |
| **직접 효과 실측** | 없음. Sound1 실보드에서 Max Counts 변경 전후 counts 거동 변화 데이터 없음 |
| **경험치** | 없음 |

### 3.3 B05 판정

M9는 **데이터시트 기반 합리적 추론**이다. 데이터시트상 기능 자체는 지원되며 M1(autoATI 재활성 시 Max Counts 충돌 위험)과 연결되면 "완충 목적" 측면에서 논리적이다.

단 "더 안정적이다"는 정도 효과는 실측 없이 단정할 수 없다. 또한 데이터시트 §5.4.2는 **"정상 동작 예상 max counts 위의 가장 작은 max counts 설정 권장"**을 명시하므로, Max Counts 무조건 상향은 오히려 하드웨어 이상 조기감지 능력을 낮춘다. 보조 안전망 수준으로만 위치 지정이 타당하다.

## 5. 실측 미완 상태에서 M8을 "확신"으로 사용할 경우 위험 시나리오

### 5.1 가장 위험한 시나리오

실측 게이트 미통과 상태에서 M8 단독 채택 시 예상 실패 시나리오를 심각도 순으로 나열:

| 시나리오 | 원인 명제 | 미통과 게이트 | 결과 |
|---|---|---|---|
| **ATI Full 재활성 직후 I²C 영구 단절** | M8 autoATI 복귀 | 게이트_6 | SDA stuck-low → CM3-IC 통신 단절 → 터치 완전 무반응. 이전 이력 재현 |
| **배터리 교체 후 LTA 영구 고착** | M8 전제_1(손 뗌 보장) | 게이트_9 | 배터리 재삽입 → 손 닿은 채 부팅 → LTA=터치값 고착 → 이후 모든 터치 무반응 |
| **자기정상화 과도구간 중 UX 실패** | M1·M8 수렴 의존 | 게이트_5 | 손 뗀 후 수 초간 터치 미인식 → 사용자 반복 터치 → LTA 재오염 악순환 |
| **ESD 물리누적 지속** | M8 "방전 불필요" 결론 | 게이트_7 | autoATI로 SW 드리프트는 보정하나 HW 전하 누적은 지속 → 동일 먹통 재현 |
| **Beta 반대 방향 설정으로 수렴 불가** | M3 Beta 조정 | 게이트_4 | Beta 올렸는데 실제로는 느려짐 → 자기정상화 수렴 속도 저하 |

### 5.2 M8 결론의 논리 구조상 취약점

M8("autoATI + Beta만으로 모든 문제 해결 가능")에는 암묵적 전제 6개(A04 분석 전제_1~6)가 내재되어 있으며, 이 중 실측으로 확인된 것은 0개다.

```
M8 결론
  ├── 전제_1: 부팅 후 손을 뗀다 → [게이트_9 미통과 → 불보장]
  ├── 전제_2: 수렴 시간 내 재터치 없다 → [게이트_5 미통과 → 시간 불명]
  ├── 전제_3: LTA 단조 수렴한다 → [게이트_1 미통과 → 실채널 미확인]
  ├── 전제_4: Beta 약터치 흡수 없다 → [게이트_4·8 미통과 → Beta 거동 불명]
  ├── 전제_5: ATI Full I²C 정상 작동 → [게이트_6 미통과 → 이전 이력 존재]
  └── 전제_6: 드리프트 원인이 SW임 → [게이트_7·3 미통과 → ESD 물리 미구분]
```

전제 6개 중 어느 하나라도 실패하면 M8은 해당 조건에서 불성립이다.

## 6. M4~M7 물리 설명들과 이전 분석의 정합성

### 6.1 이전 분석과 대조

| 명제 | 은수님 추론 | 이전 분석 판정 | B05 판정 |
|---|---|---|---|
| **M4** | C51 때문에 IC 내부 드리프트 주원인 | A03(이전 회로 분석): "드리프트 주원인은 ATI 보정 부재(FIXED 운용), C51은 self-cap 레퍼런스 표준 구성으로 오히려 측정을 가능하게 함" | 추론. 인과 연결 성립 않음. C51≠드리프트 원인 |
| **M5** | 충전기 복귀 = C51 덕분에 패드 주원인 아님 | 이전 분석: "복귀 원인 실측 미분리, IC POR일 가능성 배제 불가" | 현상 실측. 원인 해석은 추론이며 여러 가설 중 미검증 하나 |
| **M6** | GND 쇼트 → 방전 가능 | 이전 분석: "회로 토폴로지 분석 영역, 실측 없음" | 순수 추론 |
| **M7** | GND 쇼트가 주원인 아님 | 이전 분석: 동일 판정 | M6 기반 2차 추론 |

### 6.2 이전 분석 "SW 드리프트 주 + 물리 누적 부 가산 모델"과의 정합성

이전 분석(은수님 안 평결 §3, 제어재설계 권고 §1 뿌리 B)에서는 드리프트를 두 성분으로 분리한다:

```
전체 드리프트 = SW 드리프트(ATI 보정 부재) + ESD 물리 누적(방전 필요)
```

M4("IC 내부 드리프트 주원인")는 "SW 드리프트가 크다"는 방향으로는 이전 분석과 정합하지만, "물리 누적이 부차적이다"는 부분은 **게이트_7(ESD vs 드리프트 원인 분리) 미완료 상태에서 단정 불가**다.

### 7.2 M8 확정 가능 조건

M8을 "예상"에서 "확신"으로 격상하려면:

**필수 게이트 (M8 채택 불가를 해제하는 최소 조건)**:
1. 게이트_6(I²C 무응답) 통과 또는 통신 관리 코드 선행 구현
2. 게이트_1(오염 실채널 LTA/Counts RTT 캡처) 통과

**안전망 확정 게이트 (노터치 게이트 안전망 없이 M8 단독 불가함을 증명)**:
3. 게이트_5(자기정상화 과도구간) 측정
4. 게이트_9(배터리 교체 시나리오) 확인

**드리프트 구조 확정 게이트 (방전 폐기 여부 결정)**:
5. 게이트_7(ESD vs SW 드리프트 원인 분리)

## 8. 결론

> **M8("autoATI + Beta만으로 모든 문제 해결 가능")은 방향이 올바른 통찰이지만, 현재는 전제 6개가 모두 미실측 상태인 "조기 낙관"이다. 이전 분석에서 정의한 실측 게이트 7종 전부가 미완료이며, 이 중 I²C 무응답(게이트_6)·오염 실채널(게이트_1)·자기정상화 과도구간(게이트_5)·ESD 원인 분리(게이트_7)는 M8의 치명 전제에 직결되어 어느 하나라도 실패하면 M8이 무효화된다. M4~M7은 전부 추론이며, 특히 M5의 "충전기 복귀"는 현상만 실측이고 원인 해석은 추론이다. M9는 데이터시트 기반 합리적 추론이나 보조 안전망 수준이다. M8을 안전하게 채택하려면 반드시 "노터치 게이트 + 비대칭 BETA + I²C 통신관리"를 안전망으로 결합한 하이브리드 구조와 함께 위 게이트를 순차 통과해야 한다.**
