# IQS323 터치 IC 문제 분석 — 공식 회의록

> **TL;DR**: 20인 에이전트 회의(분석 7 → 검증 6 → 토론 4 → 합의 3) 결과, 은수님 M1~M9의 방향성은 전원 조건부 동의했으나 M8 "autoATI + Beta만으로 모든 문제 해결"은 조건 불충분 판정. 최종 합의: ATI Full 복귀 + Reseed 노터치 게이트 + 비대칭 Beta + 런타임 Re-ATI 차단 + I²C 통신관리 5요소 하이브리드. 방전 코드 폐기는 0x30 실측 선행 후 결정.

---

## 1. 회의 개요

### 1.1 목적

2026-06-15, 은수님이 작성한 IQS323 터치 IC 문제 1차 정리(M1~M9)를 검토하고:
- M1~M9에서 옳은 부분과 수정 필요 부분을 정확히 구분하여
- 이전 분석 결론(docs/참고/touch/개선/)과의 정합성을 확인하고
- 구현 착수 가능한 기술 결론과 다음 할 일을 확정한다.

## 2. 은수님 정리에서 정확히 파악한 것 (맞는 부분)

Phase 1·2 전체가 **방향 옳음**으로 동의한 항목이다. 세부 표현 일부를 다듬되 결론 방향은 그대로 유효하다.

### 2.1 M1 — "autoATI는 LTA→카운터 수렴 구조 → 손 떼면 자기정상화"

**판정: 방향 옳음 (수렴 엔진 설명만 수정)**

autoATI 환경에서 LTA IIR(Beta/256 가중 평균)이 noTouch counts를 자유롭게 추적하기 때문에, 손을 떼면 baseline이 수렴해 터치 감도가 자동 회복되는 구조는 데이터시트 §5.6과 일치한다. 모든 에이전트가 이 방향을 지지했다.

> [!NOTE]
> 정확한 메커니즘: "autoATI가 LTA를 수렴시킨다"가 아니라 "autoATI 복귀로 MULT/COMP가 올바르게 설정된 상태에서 **LTA IIR이 자유롭게 noTouch를 추적**하기 때문에 수렴된다." 수렴 엔진은 IIR이고, autoATI는 MULT/COMP 설정 메커니즘이다.

### 2.2 M3 — "Beta 값 조정으로 빠른 수렴 가능"

**판정: 방향 옳음 (비대칭 설계 전제 필수)**

Beta 레지스터 조정이 LTA 추적 속도를 제어하는 것은 데이터시트 §5.6과 정확히 일치한다. B01 검증 결과 "§5.6과 정확히 일치"로 확인됐다.

### 2.3 M4 — "IC 내부 드리프트가 주원인"

**판정: 결론 방향 옳음 (인과 표현만 수정)**

현재 펌웨어가 ATI Mode=Disabled(FIXED)이므로 온도·습도·전극 상태 변화를 IC가 자동 보정할 수 없다. 이것이 드리프트 누적 → 먹통의 직접 원인이다. B02(물리 메커니즘 검증자)가 "은수님의 물리 직관('IC 내부 드리프트 지배')은 유효하다"고 명시적으로 확인했다.

### 2.4 M8 — "autoATI 복귀 방향" (방향 한정)

**판정: 방향 옳음 (단 단독으로는 불충분)**

"FIXED 포기, autoATI 복귀"라는 방향은 이전 분석 권고 B와 동일하다. 드리프트 문제(P4) 해결의 올바른 방향이다. 이 방향성에는 20인 전원이 동의했다.

### 2.5 M9 — "Max Counts 4096보다 크게 하면 더 안정적"

**판정: 기술적으로 합리적 (보조 안전망으로서 유효)**

데이터시트 A.7에서 16383까지 지원 확인(B01). autoATI 복귀 후 noTouch counts가 현재 Max Counts 4095에 근접할 경우 상향 조정은 합리적이다. 단 근본 해결책이 아닌 후속 튜닝 항목이다.

## 3. 은수님 정리에서 수정해야 할 부분

### 3.1 M2 — "터치 중 LTA 업데이트 안 됨 → 터치 해제 대기 코드로 해결"

**수정 등급: 중요 (메커니즘 반전 + 구현 방향 교정 필요)**

**수정 1) 메커니즘 설명 반전**

"frozen 덕분에 수렴한다"는 설명이 데이터시트와 정반대다.
- 실제 메커니즘: 부팅 시 baseline 오염 상태에서 delta≈0 → Touch bit가 set되지 않음 → frozen 자체가 발동 안 됨 → LTA IIR이 **자유롭게(frozen 부재 덕분에)** noTouch를 추적 → 손 뗀 후 수렴

이 반전을 이해하지 못하면 구현 시 `ch0_touch==1 감지 후 대기` 코드를 작성하게 되는데, 부팅 baseline 오염 상태에서는 ch0_touch가 set되지 않아 **대기 조건 자체가 발동하지 않는다**.

**수정 2) 구현 방향 교정**

현행 `s_boot_touch_ignore`(터치 이벤트 사후 차단)와 이전 분석 권고 A(Reseed 노터치 게이트)는 다른 레이어를 지키는 별개 코드다. M2 단독으로는 권고 A를 대체할 수 없다.

| 구분 | `s_boot_touch_ignore` (M2 의도) | Reseed 노터치 게이트 (권고 A) |
|---|---|---|
| 보호 대상 | 상위 레이어 터치 이벤트 출력 | LTA 시딩(baseline) |
| 위치 | READY 전이 이후 | `apply_settings()` 내 Reseed 직전 |
| 경계 조건 | timeout 없이 무한 대기 위험 | timeout fallback 포함 |

은수님의 M2 의도("부팅 시 터치가 baseline을 오염시키지 않도록 한다")는 방향이 옳다. 단 이를 구현하려면 Reseed 직전 `ch0_touch==0` N tick 게이트(권고 A)로 구현해야 하며, 기존 `s_boot_touch_ignore`는 그 사후 보완 역할을 한다.

### 3.2 M4·M5 — "C51 DC 블로킹 캡 때문에 IC 내부 드리프트가 주원인"

**수정 등급: 경미 (인과 연결 표현만 수정, 결론 방향은 유효)**

B02 판정: "C51 때문에 IC 내부 드리프트가 주원인"이라는 인과 연결은 성립하지 않는다. C51(100pF DC 블로킹 캡)은 self-cap 슬라이더 레퍼런스 표준 구성으로 오히려 측정을 가능하게 하는 회로 요소다.

**올바른 인과 표현**: "ATI 보정 부재(FIXED 운용) 때문에 드리프트 주원인이 IC 내부에 있다."

M5("충전기 연결 → 터치 복귀")의 인과도 교정 필요: 충전기 연결 시 복귀의 주효과는 전원 재인가에 따른 POR(Power-On Reset) 메커니즘이지, C51로 인한 전극 측 주원인 배제 증거는 아니다.

### 3.3 M8 — "autoATI + Beta 빠른 수렴만으로 모든 문제 해결 가능 예상"

**수정 등급: 중대 (가장 큰 수정 대상)**

이 명제는 다음 세 가지를 완전히 누락하고 있어 단독 채택 불가 판정이다.

**누락 1: I²C 통신 관리 (B04·B06·B03·A01 전원 동의)**

현 펌웨어가 ATI Disabled(FIXED)를 선택한 근본 이유가 ATI Full 사용 시 발생하는 I²C 무응답 실제 경험이다. ATI Full 재활성 시 `Stuck-Touch → auto Re-ATI → ATI_Active bit set → I²C 무응답` 경로가 열린다. I²C 통신 관리(ATI Active 폴링·ATI Error 핸들러·타임아웃 복구) 없이 ATI Full 복귀는 과거 문제의 재현이다.

**누락 2: Reseed 노터치 게이트 (A07·B03·B04·A01·A02 동의)**

5Why 분석(A07) 결과: P1의 진짜 뿌리는 autoATI 자체가 아니라 `apply_settings()` 내 Reseed가 노터치 여부를 확인하지 않는 것이다. autoATI를 복귀시켜도 Reseed 앞에 노터치 게이트가 없으면 P1이 재현된다. autoATI 복귀와 Reseed 게이트는 서로 다른 문제(뿌리 B vs 뿌리 A)를 해소하는 독립 메커니즘이다.

**누락 3: "autoATI Full 상시" vs "부팅 1회 + 런타임 Disabled" 미구분 (B04·B06)**

은수님 M8은 autoATI를 단일 기능으로 취급하나, IQS323에서 autoATI는 두 동작을 포함한다.

| 구분 | 동작 | 위험 |
|---|---|---|
| 부팅 1회 ATI | 초기 캘리브레이션 | 노터치 게이트 결합 시 안전 |
| 런타임 자율 Re-ATI | Stuck-Touch 감지 시 자동 재보정 | 진동 환경 오인 Re-ATI·I²C hang 유발 |

방전 코드 유지 중 "Full 상시"는 4축 충돌(비트 덮어쓰기·Re-ATI 진동·채널 disable 교란·I²C hang)로 불가하다. 올바른 구조는 "부팅 1회 ATI Full + 런타임 자율 Re-ATI Disabled"다.

**수정 후 M8 표현**:
> "autoATI(부팅 1회 + 런타임 Disabled) + 비대칭 Beta + I²C 통신 관리 + Reseed 노터치 게이트를 결합하면 P1·P4 문제를 해결할 수 있을 것으로 예상한다."

### 3.4 방전 코드 관련 — 근거 없는 VSS 방전 전제

**수정 등급: 중요 (M4·M5·M8의 공통 전제)**

이전 분석이 라이브로 발견한 사실: `discharge_crx0()`의 `0x30 0x02`는 데이터시트 A.5상 "Linearise=1 + Enable=0"일 가능성이 있고, CRX0 핀-VSS 단락은 `0x34` 경로다. 현재 코드가 실제로 VSS 방전을 수행하는지 RTT 실측으로 확인되지 않은 상태다.

방전 코드 효력이 불명확한 상태에서 "방전 폐기"를 결정하는 것은:
- 방전이 Linearise flip이었다면: 폐기해도 실질 변화 없음 (이미 방전 없이 운영 중)
- 방전이 실제 VSS 방전이었다면: 물리 전하 누적 방어를 제거하는 위험 변경

따라서 **방전 폐기는 0x30 실측 선행 후에만 결정 가능**하다.

## 4. 이전 분석과의 정합성

### 4.1 일치 항목 (이전 분석 = 은수님 안)

| 항목 | 이전 분석 | 은수님 안 |
|---|---|---|
| autoATI 복귀 방향 | 권고 B: ATI Full 복귀 | M1·M8: autoATI 복귀 |
| Beta 수렴 방향 | Fast Filter Band 비대칭 설계 권고 | M3: Beta 조정으로 빠른 수렴 |
| IC 내부 드리프트 주원인 | SW 드리프트 주 + 물리 누적 부 가산 모델 | M4: IC 내부 드리프트 주원인 |

은수님 안의 핵심 통찰(자기정상화·autoATI 복귀 방향·비대칭 Beta 아이디어)은 이전 분석 하이브리드 권고의 핵심 두 요소(ATI Full 복귀 + 비대칭 Beta)와 정합한다. 은수님 안이 이 두 요소를 독립적으로 재발견한 것으로 평가된다.

### 4.2 이전 분석이 추가한 항목 (은수님 안에 없는 것)

| 추가 항목 | 이전 분석 출처 | 역할 |
|---|---|---|
| **Reseed 노터치 게이트** | 권고 A: drv.c:1134 Reseed 앞 ch0_touch==0 N tick 게이트 | P1의 진짜 뿌리(Reseed 오염) 해소 |
| **I²C 통신 관리** | 검증 V3: ATI Active 폴링·ATI Error 핸들러 | ATI Full 재활성 시 무응답 재현 방지 |
| **런타임 Re-ATI 차단** | 방전·autoATI 공존 권고: Re-ATI Disabled 고정 | 진동 오인 Re-ATI·방전 충돌 방지 |
| **방전 코드 실측 필요** | 이전 분석 라이브 발굴: 0x30 = Linearise 가능성 | 방전 폐기 전 VSS 효력 확인 |

이 4가지는 은수님 안에 완전히 부재하며, 구현 착수 시 즉각 마주칠 함정이다. (B06 G1~G3 정확히 지적)

### 4.3 충돌 항목 (은수님 안 ≠ 이전 분석)

| 충돌 | 은수님 안 | 이전 분석 | 합의 결과 |
|---|---|---|---|
| M2 vs 권고 A | "터치 해제 대기"가 권고 A를 대체 가능 | 다른 레이어, 둘 다 필요 | **둘 다 필요** (C02 중재, C04 옹호 동의) |
| M8 "autoATI Full 상시" | 상시 전제 | 방전 유지 시 4축 충돌로 불가 | **"부팅 1회 + Re-ATI Disabled"** (합의) |
| 방전 폐기 | M8 함의: 불필요 | 0x30 실측 전 결정 불가 | **실측 선행** (C02 지연형 타협) |

## 5. 회의 최종 합의 (기술 결론)

### 5.1 완전 합의 항목 (20인 전원)

다음 사항은 이의 없이 확정됐다.

**합의_1. 두 뿌리는 독립적이며 각각 해소가 필요하다**

| 뿌리 | 증상 | 해소 방법 |
|---|---|---|
| **뿌리 A**: Reseed 오염 | P1 (터치 중 부팅 → 먹통) | Reseed 앞 노터치 게이트 |
| **뿌리 B**: ATI 보정 부재 | P4 (드리프트 누적 → 먹통) | autoATI 복귀 (ATI Full) |

**합의_2. 타협 불가 최소 요건 3가지**

어떤 구현 경로를 선택하더라도 반드시 포함해야 한다.

```
[필수 1] I²C 통신 관리 선행 구현
          ATI Full 복귀 전: ATI Active 폴링 + ATI Error 핸들러 + I²C 타임아웃 복구

[필수 2] Reseed 노터치 게이트
          drv.c apply_settings() Reseed 직전: ch0_touch==0 N tick 확인 후 Reseed 허용
          timeout fallback + dirty 플래그 포함 (손 안 떼는 극단 케이스 대응)

[필수 3] 비대칭 Beta 설계
          0xB1(일반 LTA Beta) 보수적 + 0xB4(Fast Filter Band) + 0xB2(LTA Fast Beta) 공격적
          단일 LTA Beta 상향 금지 (약터치 흡수 메커니즘 확실)
```

**합의_3. autoATI 구조 확정**

"autoATI Full 상시"는 불가. **"부팅 1회 ATI Full + 런타임 자율 Re-ATI Disabled"** 가 유일한 안전 구조다.

**합의_4. 방전 코드 폐기 여부**

`0x30 0x02` RTT 실측 선행 후 판단. 실측 전 폐기 결정 불가.

**합의_5. 은수님 안 M2 위치**

M2("터치 해제 대기") 의도는 Reseed 노터치 게이트(레이어 1)로 올바르게 구현하고, 기존 `s_boot_touch_ignore`는 사후 이벤트 차단 보완(레이어 2) 역할을 유지한다. 둘은 대체 관계가 아닌 상보 관계다.

### 5.2 합의된 최종 하이브리드 구조

```
[구현 목표 구조]

① ATI Full 복귀 (부팅 1회) + 런타임 Re-ATI Disabled
   → 뿌리 B 해소 (P4 드리프트 누적 먹통)
   → 전제: I²C 통신 관리 선행 구현 필수

② Reseed 노터치 게이트 (drv.c:1134 직전)
   → 뿌리 A 해소 (P1 터치 중 부팅 먹통)
   → ch0_touch==0 N tick 확인 후 Reseed 허용
   → timeout fallback: N초 내 미해제 시 강제 시딩 + dirty_lta 플래그

③ s_boot_touch_ignore (기존 + timeout 강제 해제 추가)
   → 레이어 2 사후 방어

④ 비대칭 Beta 설정 (0xB1 보수 + 0xB2 공격 + 0xB4 Band)
   → 손뗌 후 빠른 수렴 + 약터치 흡수 방지
   → Band 값: RTT 실측(노이즈 delta vs 약터치 delta) 후 결정

⑤ 방전 코드: 실측 선행, 결과에 따라 유지 또는 폐기 결정
   → 유지 시: ATI Active bit 폴링 중 방전 일시 정지 처리 필요
```

### 5.3 중재 결과 요약 (C02 중재자)

| 논쟁 | 은수님 안 | 합의 결론 | 타협 유형 |
|---|---|---|---|
| autoATI+Beta만으로 충분한가 | 충분 (M8) | 충분하지 않고 노터치 게이트 병행 필수 | 가산형 타협 |
| 방전 폐기 가능한가 | M4·M8 함의: 불필요 | 실측 선행 후 결정 | 지연형 타협 |
| M2 = 노터치 게이트인가 | 대체 가능 (M2 전제) | 계층이 달라 둘 다 필요 | 명확화형 타협 |

## 6. 은수님의 다음 할 일 (우선순위 순)

### 할 일_1 — [즉시·당일] 방전 코드 물리효력 RTT 실측

**목적**: 방전 폐기 여부 결정의 전제 조건. 쟁점 3이자 가장 빠른 게이트.

**방법**:
- RTT로 `discharge_crx0()` 전후 레지스터 0x30 값과 CH0 Counts 변화 캡처
- 판별 기준: CRX0 핀 전압·counts가 급감하면 VSS 방전, 변화 없으면 Linearise flip

**결과에 따른 분기**:
- Linearise 확인 → 방전이 실질 효력 없었음 → autoATI 도입 후 방전 루프 제거 가능
- VSS 방전 확인 → ESD 기여도 추가 실측 전까지 방전 유지

### 할 일_2 — [구현 착수 전] I²C 통신 관리 코드 설계 및 구현

**목적**: ATI Full 복귀의 필수 선행 조건. 이것 없이 ATI Full 복귀 코드 작성 금지.

**구현 항목**:
1. RDY 핸드셰이크 강화 (event mode 또는 타임아웃 폴링)
2. ATI_Active bit(bit5) 폴링 — ATI 완료 대기
3. ATI_Error bit(bit6) 핸들러 — 수동 Re-ATI 재트리거
4. I²C 타임아웃 시 강제 복구 시퀀스

### 할 일_3 — [1단계 구현] Reseed 노터치 게이트 구현 및 검증

**목적**: P1(터치 중 부팅 → 먹통) 원천 해소.

**구현 위치**: `drv.c apply_settings()` 내 Reseed 발행(1134행) 직전

**구현 내용**:
```
ch0_touch==0 N tick 연속 확인 → Reseed 허용
N tick 내 미해제 → timeout fallback: 강제 시딩 + dirty_lta 플래그 set
```

`s_boot_touch_ignore`에 timeout 강제 해제 로직 추가.

**검증**: RTT로 "터치된 채 부팅 → 손 뗌 → 정상 인식" 시나리오 확인.

### 할 일_4 — [2단계 구현] ATI Full 복귀 + 런타임 Re-ATI Disabled + 비대칭 Beta

**목적**: P4(드리프트 누적 → 먹통) 해소.

**구현 내용**:
- `ATI_SETUP(0x36)` Mode = Full (부팅 1회)
- ATI 완료 확인 후 Mode = Disabled 고정 (런타임 Re-ATI 차단)
- Beta 레지스터 설정: 0xB1(일반 LTA Beta) 보수적 + 0xB4(Fast Filter Band) + 0xB2(Fast Beta) 공격적

> [!WARNING]
> Beta Fast Filter Band 값은 RTT 실측(정적 노이즈 delta·약터치 delta) 없이 결정 금지.
> Band 값 결정 순서: ① 현행 counts RTT 캡처 → ② 노이즈 delta 측정 → ③ 약터치 delta 측정 → ④ Band = 중간값 시작 → ⑤ 검증

### 할 일_5 — [3단계·후속] Max Counts 조정 검토

**목적**: M9(카운터 최대값) — 보조 안전망.

**방법**: ATI Full 복귀 후 RTT로 noTouch counts 최대값 실측 → 4095에 근접하면 16383으로 조정. §5.4.2 "정상 동작 예상 max counts 위의 가장 작은 값" 원칙 준수.

**시점**: 할 일_3·4 완료 및 안정화 후.
