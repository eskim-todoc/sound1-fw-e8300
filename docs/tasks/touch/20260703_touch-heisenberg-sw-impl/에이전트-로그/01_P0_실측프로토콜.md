# 01 · P0 — RTT 실측 프로토콜

**TL;DR**: fake_func_sleep()(main.c:810~1031) ULP 루프에 신규 로그 2줄(변형 태그·매틱 요약) 삽입 + 기존 로그 재사용으로 status/카운터/타이밍을 남기고, QCC·SPI(NRF)·SYSCLK·read_debug 4개 애그레서를 각각 기존 주석/매크로 토글로 켜고 꺼가며 순차 관찰한다. 코드 직접 확인 결과 **H1은 이 재현경로에서 이미 반증**(§0) — 스윕 예산은 나머지 3개 가설에 집중한다.

---

## 0. 선행 판별 — H1 조기 반증 [확립:코드, 본 세션 직접 확인]

| 확인 대상 | fake_func_sleep() (재현경로) | func_sleep() (진짜 절전, 대조군) |
|---|---|---|
| SYSCLK | **30.72MHz 유지** — `ci_fake_power_sleep()`(main.c:862) → `tdc_Trims_SetOperatingFrequency(SYS_FREQ_30M72)`(ci_power.c:167) | 2.56MHz — `ci_power_sleep()`(main.c:1218) → `SYS_FREQ_2M56`(ci_power.c:181) |
| I2C prescale | **`I2C_MASTER_PRESCALE_240`**(main.c:864, 주석 "본래 노말 모드 설정 그대로") | `I2C_MASTER_PRESCALE_6`(main.c:1222, 의도는 `_21`이었던 기존 [FIXME], 본 P0 범위 밖) |
| 결과 SCL | 30.72MHz÷240 = **128kHz**(driver_i2c.h:17 "128 kHz" 라벨과 정확히 일치, 공식 SCL=SYSCLK/((필드+1)×3), :11) — **노말모드와 동일** | 2.56MHz÷6 ≈ 426.7kHz(기존 문서 인용값, 본 세션 재검증 안 함) |

**결론**: H1이 가정한 조합("SYSCLK 30.72MHz 유지 + 절전용 프리스케일 ÷6 재사용 → SCL 5.12MHz")은 **현재 코드 어디에도 존재하지 않는다.** fake_func_sleep()은 SYSCLK·prescale 둘 다 정상값을 유지(=SCL 정상 128kHz), func_sleep()은 둘 다 절전값(단, 기존 FIXME로 목표보다 빠른 426.7kHz)을 쓴다 — "SYSCLK만 유지하고 prescale은 절전값 재사용"이라는 제3의 조합은 두 함수 어디에도 없다. **H1은 이 재현경로에 대해 [반증]** — §2~3의 스윕 예산은 실측이 필요한 나머지 가설(①지배 애그레서, ③H2, ④재현경로)에 집중한다. (참고: `i2c_set_master_prescale()` 호출은 main.c 전체에 이 2곳뿐 — grep 확인, 다른 경로에서 프리스케일을 바꿔치기할 여지 없음.)

이 반증은 정적 사실이라 실측이 불필요하지만, §2 로그에 1회성 확인 라인(P0-LOG-0)을 넣어 실행 중에도 재확인 가능하게 한다(실측 게이트 아님, 안전핀).

## 1. 재현경로 좌표·재진입 절차

- **범위**: `fake_func_sleep()` 전체(main.c:810~1031). 모든 로그 삽입·토글은 이 함수 내부로 한정 — `func_sleep()`(1164~) 비변경.
- **진입**: BLE General Debug, `packet->data[1]==1` → `gd_handle_op_mode_setting()`(tdc_remote_general_debug.c:160~183) → `tdc_set_fake_op_mode(1)`(:169) → 다음 `func_normal()` 루프 tick에서 main.c:730~735가 `fake_func_sleep()` 호출.
- **재진입 필요**: `s_tdc_fake_op_mode`(main.c:87)는 **RAM 전역변수**(NVM 아님) — ati_error 리부팅(§2 P0-LOG-1의 트리거, main.c:953) 발생 시 리부팅마다 `0`으로 초기화된다. 즉 **매 리부팅 후 BLE 커맨드 재전송이 있어야** 다시 fake_func_sleep()에 진입한다. 스윕 절차(§3)는 이 재진입을 반복 단계로 명시한다.

## 2. 계측 로그 스펙

### 2.1 신규 삽입 (P0-LOG-0, P0-LOG-1)

**P0-LOG-0** — 1회성 변형 태그, 삽입 위치: main.c:868(`ci_timer_init_prescaled(...)`) 직후.

```c
ci_printi("[P0] ENTER variant=%s sysclk=30M72(kept) i2c_prescale=240(128kHz, normal) \r\n", P0_VARIANT_TAG);
```

`P0_VARIANT_TAG`는 §3 변형마다 리터럴 문자열을 직접 고쳐 재빌드(예: `"BASE"`,`"NO_QCC"`) — 신규 빌드 플래그 배관 불필요, RTT 로그만으로 어느 변형 실행 중인지 즉시 식별.

**P0-LOG-1** — 매 틱(100ms) 통합 요약, 삽입 위치: main.c:908~909(`read_status()` 호출) 앞뒤로 타임스탬프 감싸기.

```c
uint32_t t0 = ci_timer_get_tick();
tdc_touch_iqs323_status_t st;
bool ok = tdc_touch_iqs323_read_status(&st);
uint32_t t1 = ci_timer_get_tick();
ci_printd("[P0] t=%lu dt=%lu ok=%d ate=%d ata=%d tch=%d prx=%d aec=%d tc=%d \r\n",
          (unsigned long) t0, (unsigned long) (t1 - t0), ok,
          st.ati_error, st.ati_active, st.pressed, st.prox,
          ati_error_reboot_cnt, touch_cnt);
```

필드: `t0`(ms 절대 타임스탬프)·`dt`(read_status 1회 왕복 소요 ms — I2C/RDY 윈도우 지연의 대리 지표, 애그레서가 버스를 물면 증가 예상)·4-tuple 상태비트·**두 워치독 카운터를 매 틱 값으로**(기존 코드는 상태 전이시에만 로그, 카운터 추이 자체는 비노출이었음). 이 한 줄로 ①③④ 판별에 필요한 최소 데이터가 매 100ms 확보된다.

### 2.2 기존 로그 재사용 (변경 없음)

| 로그 | 위치 | 내용 | 용도 |
|---|---|---|---|
| LTA/CNT/D/THR 라인 | main.c:922~932 (`TDC_TOUCH_DEBUG_PRINT_ENABLE` 게이트) | `read_debug()` 결과 — LTA·Counts·delta·절대임계 | counts→delta 오염 방향 확인(메커니즘_2) |
| ATI 복구/리부팅 | main.c:951, 959 | ati_error 발생마다(연속 아니어도) 매틱 로그 | ①③ 이벤트 발생률 원천 |

## 3. 애그레서 on/off 스윕 절차

4개 변형, 실행 권장 순서는 **위험도 낮은 순**(DBG→QCC→NRF→CLK). 각 변형은 **단독 적용**(동시 토글 금지 — 이분법 판별의 전제).

| 변형 | 대상 | 토글 방법(정확 위치) | 대응 판별 |
|---|---|---|---|
| **BASE** | 기준선 | 무변경(현재 코드 그대로) | 기준 발생률 확립 |
| **DBG** | read_debug 자체 | `tdc_touch_config.h:22` `#define TDC_TOUCH_DEBUG_PRINT_ENABLE 1` → `0` | H2(계측 자체 애그레서) |
| **QCC** | QCC 활성 | main.c:828 주석 해제: `snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);` | ① QCC 후보 |
| **NRF** | SPI(NRF 마스터) | main.c:826 다음 줄에 `ResetNRF(); NRF_Off_Command();` 삽입(func_sleep():1197~1198과 동일 패턴) | ① SPI 후보 |
| **CLK** | SYSCLK | main.c:861~862 주석 스왑: `ci_power_sleep();` 살리고 `ci_fake_power_sleep();` 주석 | ① SYSCLK 후보 |

**변형별 주의(교란 변수)**:
- **DBG**: INV-X-3에 의해 FSM 무영향이 이미 보장된 유일한 변형 — 가장 안전, 최우선 실행 권장.
- **NRF**: `NRF_Off_Command()` 이후에도 루프는 매틱 `bleCommunication(dummy_isd)`(main.c:899)를 계속 호출한다 — NRF 전원차단 후 이 호출의 동작은 **미확인**(에러 반환/타임아웃 가능성, 코드로 확정 못 함). 관찰 중 이 호출이 멈추거나 예외 로그를 내면 즉시 기록하고 세션 재시작.
- **CLK**: main.c:864의 I2C prescale은 그대로 `240`이라 SYSCLK만 2.56MHz로 내려가면 SCL=2.56MHz÷240≈10.67kHz(driver_i2c.h:20~21 자체 언급 수치)로 **함께** 떨어진다 — "SYSCLK 단독 변수"가 아니라 "SYSCLK+I2C속도 동시 변화"임을 결과 해석 시 반드시 인지할 것(단일변수 재분리가 필요하면 후속 CLK-b: prescale도 절전값에 맞춰 별도 조정). 또한 QCC/BLE가 2.56MHz 하에서 정상 동작하는 조합은 **정상/절전 어디에도 기존 실적이 없는 조합**(func_sleep()은 NRF/QCC를 꺼버려 이 조합을 겪지 않음) — 새로운 불안정성 여지, 최후 순위로 실행.

**실행 절차(변형 공통)**:
1. 변형 적용 전 `git status`로 깨끗한 상태 확인 → 적용 → `P0_VARIANT_TAG` 갱신 → 빌드·플래시.
2. 전원 인가 → BLE General Debug `op_mode=1` 전송(§1) → RTT 뷰어로 P0-LOG-0 확인(변형 태그 일치 확인).
3. BASE로 1차 관측해 **기준 재현 소요시간 T_base**(최초 ati_error 리부팅까지 시간, 또는 10분간 §4 이벤트 카운트)를 먼저 확정.
4. 각 변형은 최소 `3×T_base`(또는 BASE와 동일 관측시간) 동안 RTT 로그 채집.
5. 리부팅 발생 시 RTT 재연결 + BLE 커맨드 재전송으로 재진입, 관측 지속.
6. 변형 종료 후 `git diff`로 **완전 원복 확인** 후 다음 변형 진행(동시 토글 방지).

## 7. 리스크 · 실측 게이트

| 항목 | 상태 |
|---|---|
| NRF 변형에서 `bleCommunication()`이 NRF OFF 후 어떻게 동작하는지 | **미확인(실측 게이트)** — 코드상 가드 없음, 실행 중 예외/무한대기 여부 직접 관찰 필요 |
| CLK 변형의 QCC/BLE 안정성(2.56MHz 조합은 기존 실적 없음) | **미확인(실측 게이트)** — 새로운 불안정 유발 가능, 최후 순위 실행 권고 이유 |
| ati_error 리부팅 후 `wait_ati_done_blocking()`(tdc_touch_iqs323.c:328)이 ati_error 미확인 채 진행 — 애그레서 지속 시 재오염 재부팅 루프 가능성(C1 §2.1 기존 지적) | **미확인** — 본 스윕 중 "리부팅 반복 간격이 점점 짧아지는지" 관찰로 부수 확인 가능 |

## 핵심 결론

1. H1(I2C ÷6 재사용 SCL 5배)은 코드 직접 확인으로 **이 재현경로에 대해 이미 반증**됐다 — fake_func_sleep()은 SYSCLK·I2C prescale 둘 다 정상값을 유지한다(§0). 스윕 예산 재배치가 정당하다.
2. 계측은 신규 로그 2줄(P0-LOG-0/1)만 추가하면 되고, 기존 로그(LTA/CNT/D/THR, ATI 이벤트, 터치no-op)는 그대로 재사용 가능 — 최소 침습.
3. 애그레서 스윕 4변형(DBG/QCC/NRF/CLK) 중 3개(DBG/QCC/CLK)는 **기존 코드의 주석/매크로를 그대로 토글**하는 것만으로 구현되어 신규 로직이 거의 없다 — NRF만 2줄 신규 삽입 필요.
4. ④(재현경로 이분법)는 "리부팅 직전 마지막 RTT 줄이 ati_error 리부팅 로그인가"라는 단일 관찰로 판별 가능 — 아니라면 C1이 특성화한 메커니즘과 다른 별도 실패모드 존재 가능성을 즉시 보고해야 한다.
5. C2 불변식은 전부 무영향(INV-X-3만 직접 관련, 정합 확인) — 단 모든 변형은 임시 diagnostic이므로 측정 후 원복이 P1~P5 구현 착수의 전제조건이다.
