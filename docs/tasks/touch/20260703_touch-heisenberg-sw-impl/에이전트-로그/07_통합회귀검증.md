# 07 · 통합/회귀 검증 (P0~P5 fan-in 전 최종 점검)

**TL;DR**: P0~P5 6개 스펙을 코드(main.c·tdc_touch_iqs323.c) 재확인과 함께 통합 점검. 코드충돌 0건이나 P0(임시계측)·P1(구조개편)이 main.c 908~909·917행을 공유해 시간분리 필수. C2 불변식 신규위반 0건, 단 INV-⑦에 4개·INV-④에 2개 레버 누적. fake_func_sleep 반영누락 0건. 권장 롤아웃: P0실측→P2/P4→P1→P3→P0재실측→P5(안전망, 최후).

---

## 0. 검증 방법

지시된 4파일(00 오케스트레이터·01 C1·02 C2·본 노드용 P0~P5 6개)을 전독 후, 교차 접점이 의심되는 실제 소스(main.c:805~1035, tdc_touch_iqs323.c:290~489)를 직접 Read로 재확인했다. **결과: 6개 스펙이 인용한 전체 라인 번호(fake_func_sleep 826/828/861-862/864/868/877-888/908-909/912-943/947-965/1002-1019/1011, tdc_touch_iqs323.c 309-325/316/318/347-398/400-460/447/453/462-472/465/471)가 코드와 1건의 어긋남 없이 정확히 일치**했다 — 6개 스펙의 근거 신뢰도가 높다는 정황이며, 아래 점검은 이 위에서 진행한다.

## 1. (a) 레버 간 충돌·중복

### 1.1 main.c `fake_func_sleep()`(810~1031) — P0/P1/P5 3중 접점

| 레버 | 수정 지점(코드 재확인) | 성격 |
|---|---|---|
| P0 | 868 직후(LOG-0) · 908~909 감싸기(LOG-1) · 826/828/861-862(스윕 토글) | **임시** diagnostic, 측정 후 완전 원복 전제(P0§6 자기명시) |
| P1 | 909(read_status 삭제) + 917(read_debug→combined 치환) | **영구** 구조개편 |
| P5 | 949(임계 `5`→매크로) / 1007(임계→매크로) | 영구 값치환, 조건식 골격 불변 |

- **P0↔P1 직접 겹침(핵심 발견)**: P0-LOG-1이 감싸는 908~909행과 P1이 치환하는 909·917행이 정확히 같은 자리다. P0는 "read_status·read_debug가 분리 호출됨"을 전제로 그 틈에 타임스탬프를 두르는데, P1 적용 후엔 이 두 호출이 `read_combined()` 1회로 합쳐져 애초에 감쌀 두 지점 자체가 사라진다. **동시 병행 불가** — (i) P0 실측을 P1 적용 이전 코드베이스에서 완료·`git diff` 완전원복 후 P1 커밋, 또는 (ii) P1을 먼저 적용한 뒤 P0-LOG-1을 `read_combined()` 호출 앞뒤로 재조정해 재삽입, 둘 중 하나로 시간분리해야 한다. P0 스펙 자체가 (i) 순서(현재 코드 기준 라인 앵커)로 작성돼 있다.
- **P0↔P5 겹침 없음**: LOG-1 대상(908~909)과 P5 대상(949·1007)은 다른 블록. P0§2.2가 재사용하는 기존 로그(951·959·1009)는 P5가 조건식만 바꿔 라인 수 불변이라 그대로 유효 — 안전.
- **P1↔P5 겹침 없음**: P1은 917행 치환 후 "918~943행 포맷/세터 로직 무변경"을 자기 명시하고, P5 대상(947 이하 ati_error 분기·1002 이하 touch_cnt 분기)은 그 하류의 독립 if-블록 — 두 레버는 어떤 순서로 적용해도 코드 레벨 충돌 없음.

### 1.2 tdc_touch_iqs323.c — P1(신규함수)/P3(0xC0 5사이트)/P4(0x31) 3중 접점

| 레버 | 수정 지점(코드 재확인) |
|---|---|
| P1 | 398행("read_debug() 끝, `return true;`") 직후에 신규함수 `read_combined()` 삽입 |
| P3 | 318(0x50→0xD0)·447(0x54→0xD4)·453(0x58→0xD8)·465(0x54→0xD4)·471(0x58→0xD8) |
| P4 | 316(0x05→0x0C, `beta_power_settings()` 내부, 318 바로 앞줄) |

- **P3↔P4**: 316·318은 같은 함수(`beta_power_settings`) 내 바로 인접한 두 줄, 서로 다른 레지스터(0x31 vs 0xC0)라 논리 충돌 없음. 단 인접 hunk라 별도 브랜치 독립작업 시 텍스트 병합충돌 가능 — **한 커밋에서 두 값을 함께 반영** 권장.
- **P1↔P3/P4 라인앵커 이동(신규 확인)**: P1의 신규함수는 398행 직후 삽입돼 P3의 447·453·465·471(398 이후 위치)이 신규함수 길이(read_status+read_debug 바디 이식분, 대략 30~50줄 추정)만큼 전부 뒤로 시프트된다. **로직 충돌이 아니라 "파일:라인" 앵커 실효시점 문제** — 구현 시 라인번호 그대로 patch 적용은 위험하며, `write_register(REG_SYSTEM_CONTROL, ...)` 패턴 grep 재검색으로 사이트를 재확인 후 적용해야 한다(P1을 먼저 넣든 나중에 넣든 동일 원칙).

### 1.3 지시된 3개 교차축 개별 판정

| 축 | 판정 |
|---|---|
| **P3(0xC0 bit7) vs 기존 0xC0 write** | 충돌 아님 — P3가 기존 사이트 자체를 원자적으로 "치환"(5곳 동시커밋 필수, P3§3 이미 명시). 신규 확인: P5가 재시도횟수(5→50)를 늘리면 P3가 값을 바꾼 465행(`re_ati()`) 호출 **빈도**가 비례 증가 — 값 자체는 무관, 새 프로토콜(bit7=Events) 실행 총량만 늘어남. 논리충돌 없음, 인지 필요 |
| **P1(read_debug) vs P0(계측)** | §1.1에서 상술 — 겹침 확인, 시간분리 필수 |
| **P5(카운터) vs P2(prescale)** | 코드 겹침 없음(P2-prescale은 `func_sleep()` 1222행, P5는 `fake_func_sleep()` 949/1007행 — 서로 다른 함수). P2§8 자체가 "prescale은 재현경로 무관"을 명시. P2의 I2C0/SPI1 **드라이브**(부팅1회, 전경로 공유)는 fake_func_sleep에도 적용돼 P5와 상충 없이 시너지(재시도 구간에도 드라이브 하향 효과 유지) |

## 2. (b) C2 불변식 위반 재확인 (통합 상태)

| INV | 관련 P | 개별 판정 | 통합 시 신규 발견 |
|---|---|---|---|
| ①Full ATI | 전체 | 무손상 | 0x36 미접촉 교차확인, 이상 없음 |
| ②최초터치해제 | 전체 | 무손상 | 이상 없음 |
| ③ATI에러 비대칭 | P5 | 주의(의도적 확대) | P3의 465행 호출빈도 증가와 결합해도 게이트 조건 자체 불변 — 이상 없음 |
| **④터치판정** | P2,P4 | 각각 주의(글리치·SNR) | **누적**: 드라이브하향+주파수하향 동시적용 시 통신성공률·감도 변화가 겹쳐 원인분리 곤란 — 단계적 적용 권고(§4) |
| ⑤롱터치 | P3 | 주의(func_sleep 핵심발견) | **잠재 트리거 공유(신규)**: P3§6·P5§8-3 둘 다 "main.c:1011 주석 복원"을 스코프밖 조건으로 남김 — 복원되면 P3의 read-fail 즉시리셋 리스크가 P5의 확장임계(240) 위에서 fake_func_sleep에도 재현됨. 현재 1011 no-op이라 잠재적(§5 위험 표) |
| ⑥절전 진입/기상 | P2,P4 | 무손상/주의(ATI캡) | P4 변환시간 2배가 부팅 Re-ATI 1.25s 캡 여유를 잠식 — P2·P3와 직접결합 없음, 단독 실측 필요 |
| **⑦공통폴링(L1)** | P1,P2,P3,P4 | 각각 핵심적용/주의/급소/주의 | **최다 누적**: 4개 레버 전부가 45ms/20ms 마진에 영향. P0의 "단독변형 원칙"과 동형 문제 — 동시적용 시 마진잠식 원인분리 불가. §4에서 단계적 순서로 대응 |
| ⑧단일채널 | - | 무손상/무관 | 이상 없음 |
| X-①0xC0보존 | P3,P5 | 대상/재사용 | 이상 없음, P3 원자성은 P3 스코프 내에서만 요구됨 재확인 |
| X-②READ_FAIL hold | - | 무손상/무관 | 이상 없음 |
| X-③디버그무해 | P0,P1,P5 | 정합/무손상 | 이상 없음 |

**신규 위반 0건.** 통합 관점 핵심 발견 3가지: (i) INV-⑦에 4개 레버가 몰려 개별로는 "무손상~주의"라도 동시적용 시 마진잠식이 가산적일 수 있음, (ii) INV-④에 2개 레버 누적, (iii) INV-⑤에서 P3·P5가 서로 다른 "스코프 밖" 사유로 같은 잠재 트리거(1011 주석 복원)를 공유함 — 세 가지 모두 개별 스펙 문서엔 명시되지 않았던, 통합 검증에서만 드러난 교차 사실이다.

## 3. (c) fake_func_sleep 반영 누락 체크

| P | 반영 여부 | 근거 |
|---|---|---|
| P0 | 대상 자체 | fake_func_sleep 범위 한정 계측 |
| P1 | 반영(명시) | main.c:909+917 직접 교체 대상(P1§3.2 세번째 행) |
| P2 | 드라이브 반영 / prescale 무관(명시) | I2C0·SPI1은 부팅1회 공유, prescale은 별개 사이트(864행 이미 정상값 240 사용 중, 코드 재확인) |
| P3 | 자동반영(L1 공유) | main.c 무편집, 909·960·983/996이 `func_sleep()`과 동일 심볼 공유 재확인 |
| P4 | 자동반영(부팅1회) | main.c 무편집 |
| P5 | 정의상 전용 | fake_func_sleep 로컬 변수(949·1007)만 대상 |

**누락 0건.** 전 레버가 반영 여부를 명시 확인했고, "무관"(P2-prescale)도 대체 사이트가 이미 정상값임을 코드로 확인한 타당한 판단이다.

## 4. (d) 롤아웃 순서 권장

지시된 "P0 선결·저위험독립 우선" 원칙 + §1~§2 통합 발견을 반영한 6단계.

| 단계 | 내용 | 근거 |
|---|---|---|
| 0 | **P0 실측**(DBG→QCC→NRF→CLK 순, 단독변형) → 완전원복(`git diff` clean) 확인 | P0§3 명시 순서, §1.1의 P0↔P1 시간분리 전제 |
| 1 | **P2-prescale**(main.c:1222)+**P4**(iqs323.c:316) 병행 | 서로 다른 파일, 재현경로 완전독립(prescale)·부팅1회 국소(P4), 즉시가역, 최저위험 |
| 2 | **P2-드라이브**(DIO_PIN_Config.h 13·54) 단독 적용 후 실측(글리치율) | 재현경로 유효적용, INV-④·⑦ "주의" — 단독 실측해야 이후 레버와 원인분리 가능 |
| 3 | **P1**(combined_read, 3파일 호출부) | INV-⑦ 핵심 재구성, 0단계 원복 후 필수. 적용 후 447/453/465/471 라인앵커 재확인(§1.2) |
| 4 | **P3**(0xC0 bit7, 5사이트 원자적 커밋) | P1 위에서 구조 안정화 후 프로토콜 특성 변경 — 순서 필수는 아니나 디버깅 용이성 근거로 권고. 5곳 동시커밋 필수 |
| 5 | **P0 재실측**(권장) | 1~4 누적효과(마진잠식 여부·ati_error 발생률 감소) 검증, BASE 기준선 재확립 |
| 6 | **P5**(카운터 확장, 안전망) — **반드시 최후** | 1~4가 근본원인을 실제로 줄였는지 5단계로 확인하기 **전에** P5를 먼저 넣으면, 재부팅까지의 시간만 늘어나 "좋아진 것처럼" 보이는 **관찰 마스킹** 위험(P5 스펙 자체도 "근본해결 아님" 자인) — 통합 검증 신규 발견 |

핵심 신규 발견은 6번(P5 최후배치의 방법론적 근거 — 관찰마스킹 회피)과 3번(라인앵커 재확인 필요성).

## 5. 종합 판정표

| 점검축 | 결과 |
|---|---|
| 레버 간 코드충돌(diff 겹침, 값 자체 상충) | **0건** |
| 시간순서 제약(동시 병행 불가) | **1건** — P0↔P1(main.c 908~909·917) |
| 라인앵커 재확인 필요 | **1건** — P1 삽입 후 P3 대상 4사이트(447/453/465/471) 오프셋 이동 |
| C2 불변식 신규 위반 | **0건** |
| C2 불변식 누적 주의(개별 무해, 통합 시 재확인 필요) | **2건** — INV-④(P2+P4), INV-⑦(P1+P2+P3+P4) |
| 잠재 미래 트리거 공유(현재 no-op, 조건부 위험) | **1건** — main.c:1011 복원 시 P3⑤주의×P5임계 결합 |
| fake_func_sleep 반영 누락 | **0건** |

**결론**: P0~P5는 fan-in 가능한 상태다. 단, (1) P0와 P1은 반드시 시간분리, (2) INV-④·⑦ 누적구간(P2드라이브·P1·P3·P4)은 §4 순서대로 단계별 실측을 거쳐야 개별 기여도를 분리할 수 있음, (3) P5는 근본완화 레버들의 효과가 확인된 뒤 최후에 적용, (4) main.c:1011 주석 복원 여부는 P3·P5 양쪽에 걸친 별도 의사결정 사항으로 은수님 확인이 선행돼야 한다.
