# 05 · P4 — 변환주파수(Conversion Frequency, 0x31)

**TL;DR**: `tdc_touch_iqs323.c:316` 1줄, Period 5→12(1.00MHz→500kHz)만 바꾼다. 부팅 1회 write(`apply_settings`) 구조라 func_sleep·fake_func_sleep 양쪽 다 코드 변경 0으로 자동 반영된다. 신규 계산 — 389kHz(Period16)는 SYSCLK(30.72MHz)의 정수배(≈79배, 오차 2.8%)에 근접해 회피 대상, 500kHz(Period12)는 44% 이격+데이터시트 §3.4 실측조건 일치로 채택. C2 11개 불변식 무손상 8·주의 3·충돌 0. 메커니즘_3(에일리어싱)에만 약~중 효과, 메커니즘_1 무관·메커니즘_2는 역효과.

---

## 1. 변경 대상 — 정확한 파일:라인

```c
/* tdc_touch_iqs323.c:316, beta_power_settings() 내부 */
ok &= write_register(REG_CONV_FREQ, 0x7F, 0x05);        /* 0x057F = 1MHz (self-cap 상한) */
```
→
```c
ok &= write_register(REG_CONV_FREQ, 0x7F, 0x0C);        /* 0x0C7F = 500kHz (데이터시트 §3.4 실측조건, self-cap 여유) */
```

- `REG_CONV_FREQ`는 `tdc_touch_iqs323.c:21` `#define REG_CONV_FREQ 0x31` — 파일 내 write 사이트는 이 1곳뿐(전수 grep 확인, 중복 없음).
- Fraction(LSB=0x7F=127)은 데이터시트 §6.5 "Fix to 127" 규정 — **불변**. Period(MSB)만 0x05→0x0C.
- 주석도 반드시 동시 갱신 — C2 §7이 지적한 "값 변경 시 주석 미갱신"(β 8→6 사례) 재발 방지.

## 2. Before → After 레지스터 값

| 항목 | Before(현재) | After(P4) |
|---|---|---|
| Period(MSB) | 5 (0x05) | **12 (0x0C)** |
| Fraction(LSB) | 127 (0x7F, 불변) | 127 (0x7F, 불변) |
| 레지스터 전체값 | 0x31 = **0x057F** | 0x31 = **0x0C7F** |
| Fxfer | 1.00 MHz | **500 kHz** |
| write_register 호출 | `(REG_CONV_FREQ, 0x7F, 0x05)` | `(REG_CONV_FREQ, 0x7F, 0x0C)` |
| 자기용량 상한(1MHz) 대비 | 경계(마진 0) | 여유 있음 |

근거: `03_하드웨어설정.md` §6.5 Table A.1(Dead Time Enabled) — Period 12 = 500kHz. 0x33(Dead Time) 미기록(reset 유지 bit6=1=Enabled)이라 Table A.1 적용 확정(S1 §1).

## 3. 후보 비교 — SYSCLK 정수배 근접도 (신규 계산)

e8300 SYSCLK=30.72MHz(`SYS_FREQ_30M72`, `ci_power.c:167` `ci_fake_power_sleep()` 내부 — C2 §11 인용 범위 163~174와 일치)와 Fxfer의 비율이 정수에 가까울수록 두 클럭 위상차가 느리게 표류해(비트 주파수 낮음) 동일 위상 중첩이 오래 지속된다 — 메커니즘_3(에일리어싱/맥놀이)의 최악 조건이다. `SYSCLK ÷ Fxfer`를 계산해 최근접 정수와의 이격도(%)로 정리(계산식: 이격도=min(소수부, 1−소수부)):

| Period | Fxfer | SYSCLK÷Fxfer | 최근접 정수 | 이격도 | 판정 |
|---|---|---|---|---|---|
| 5(현재) | 1.00MHz | 30.72 | 31 | 28.0% | 보통 |
| 7 | 778kHz | 39.49 | 39 | 48.6% | 최대(§3 하단 미채택 사유) |
| **12(채택)** | **500kHz** | **61.44** | 61 | **44.0%** | **양호** |
| 16 | 389kHz | 78.97 | **79** | **2.8%** | **회피 대상 — 최악** |
| 23 | 280kHz | 109.71 | 110 | 28.6% | 보통 |

> [!WARNING]
> **389kHz(Period16)는 채택하지 않는다.** SYSCLK 30.72MHz의 정확히 79배에 오차 2.8%로 근접 — 표에서 가장 낮은 이격도다. "현재(1MHz) 대비 611kHz나 차이 나니 이격이 크다"는 직관과 반대로, 정수비 관점에서는 최악의 근접값이다. 오케스트레이터 편성 지시(00번 노드)도 이를 회피 대상으로 명시했다.

[가설-강] 표기 사유: 위 계산은 (a) Table A.1의 Fxfer 값 자체가 반올림 근사치(예 "389kHz"), (b) IQS323 f_OSC 공차 ±5.5%(S1 §0 인용), (c) SYSCLK 자체 공차 **미확인**(`tdc_Trims_SetOperatingFrequency` 트림 RC로 추정, 크리스탈 여부·ppm 스펙 코드에서 미확인)이 존재해 실제 이격도는 표값에서 이동할 수 있다. 방향성(389kHz 회피·500kHz 양호) 판단 근거로는 충분하나 확정 보장은 아니다.

**Period7(778kHz) 미채택 사유**: 이격도만 보면 48.6%로 최대이나, (a) S1 노드가 이미 후보 검토 범위(S1-1/S1-2)에서 제외했고, (b) 500kHz만이 데이터시트 §3.4 전류표의 실측조건과 정확히 일치하는 독립 근거를 가진다(§7). 실측 스윕(S1-3, P0 프로토콜 대상) 단계에서 추가 후보로 넣을 가치는 있다.

## 4. 적용 시퀀스·조건

1. **코드 변경**: `tdc_touch_iqs323.c:316` 1줄(값)+동행 주석 갱신. 그 외 파일 변경 없음.
2. **호출 체인**(변경 없음, 기존 그대로): `beta_power_settings()`(:309~325) ← `tdc_touch_iqs323_apply_settings()`(:400, 그 안에서 :316 호출) ← `try_finish_init()`(`tdc_touch.c:161`) — auto-ATI 완료 또는 `TDC_TOUCH_INIT_TIMEOUT_MS`(2500ms) 경과 시 **부팅 경로에서 1회만** 실행.
3. **실행 시점**: 최초 전원 인가 부팅 + `SYS_WATCHDOG_RESET()`에 의한 모든 재부팅(ATI 에러 5회·롱터치 2400ms 등) 후에도 동일 경로 재실행 — 매 재부팅마다 500kHz가 재적용(값 잔존 문제 없음, 항상 명시적 write).
4. **순서 종속성 없음**: 0x31은 0xC0(System Control)·0x36(ATI Setup)과 별도 레지스터 — 6개 0xC0 write 사이트(INV-X-1)나 Full ATI 설정과 실행 순서를 바꿀 필요 없음. `beta_power_settings()` 내부에서 다른 write(Beta·Power Mode)보다 먼저/나중 상관없이 동작.
5. **HW 변경 없음** — 순수 상수 1바이트, 재컴파일만 필요.

## 5. fake_func_sleep 경로 반영

- 0x31은 **부팅 1회 write 후 재write 없음** — `func_sleep()`·`fake_func_sleep()` 둘 다 IQS323 레지스터를 별도로 재설정하지 않는다(C2 §7 "절전 IQS323 레지스터는 부팅 시 값과 동일하게 유지", C2 §11 표로 재확인).
- 따라서 **fake_func_sleep()에는 코드 변경이 전혀 필요 없다** — 부팅 시 500kHz로 설정된 레지스터 값이 이후 정상 FSM·`func_sleep()`·`fake_func_sleep()` 어느 경로로 진입하든 그대로 유지된 채 적용된다.
- **IQS323 Fxfer는 e8300 SYSCLK와 완전 비동기**(S1 §0 "완전 비동기·독립 발진") — `fake_func_sleep()`이 `ci_fake_power_sleep()`로 SYSCLK를 30.72MHz로 유지(`func_sleep()`의 2.56MHz 하강과 다름, main.c:861~862 대비)하는 것과 IQS323 Fxfer(500kHz) 사이엔 결합 관계가 없다.
- 단, §3의 SYSCLK 정수배 근접도는 **SYSCLK 값에 따라 경로별로 달라진다** — 본 문서 §3은 fake_func_sleep 재현 조건(SYSCLK 30.72MHz 유지)을 기준으로 계산했다(C1이 지목한 지배 애그레서 후보와 동일 클럭 조건). 참고로 func_sleep() 정상 절전(2.56MHz)에서는 2.56MHz÷500kHz=5.12→최근접 5, 이격도 12%로 별도 계산되나, C1 결론상 하이젠베르크는 "정상 절전에서는 미발생"이 전제이므로 이 경로의 근접도는 문제되지 않는다.

## 6. C2 불변식별 회귀 체크 (S1 §4 매트릭스 인용 + P4 확정치 반영)

| 불변식 | 영향 | 근거 |
|---|---|---|
| INV-①(Full ATI) | 무손상 | 0x31↔0x36(ATI Setup) 별도 레지스터, ATI Target(=400)은 Fxfer 무관 정의 |
| INV-②(최초 터치해제 게이트) | 무손상 | `boot_ignore`/`sleep_ignore`·RESEED 로직 0x31 미접촉 |
| INV-③(ATI 에러 시 Re-ATI 비대칭) | 무손상 | 0xC0 트리거·카운터와 0x31 독립 레지스터 |
| **INV-④(터치판정·임계 계수 상호작용)** | **주의** | 절대임계 공식(계수80×LTA/256)·ATI Target(400) 수식 자체는 레지스터 분리로 Fxfer 무관(이론). 단 Fxfer 변경이 실제 물리 응답(노이즈 플로어·raw delta)을 바꿀 수 있어 SNR≥5·raw≥20counts(적용가이드 §4.4, C2 인용) 재확인 실측 권고 |
| INV-⑤(롱터치 2400ms) | 무손상 | 100ms 폴링·CH0_Touch 비트만 의존, Fxfer는 IC 내부 1회 변환시간만 결정(별개 레이어) |
| INV-⑥(절전 진입/기상) | 무손상, 단 §9 게이트 | write는 부팅 1회뿐(§5) — 클럭다운 전 write 완료 요구와 호환. 단 부팅 Re-ATI 1.25s 블로킹 캡(`wait_ati_done_blocking`) 여유가 줄어들 수 있음 |
| INV-⑦(공통 폴링, 45ms/20ms 타임아웃) | 주의 | 1회 변환 소요시간 증가(§7) — RDY 윈도우 타임아웃과는 여유 추정되나 0x33(Auto Prox Cycle, 미기록·reset=32) 실적용 여부 미확인이라 오차 여지(S1 §4 인용) |
| INV-⑧(단일채널) | 무손상 | CH1/CH2 Conv Freq 레지스터 별도, 미접촉 |
| INV-X-1(0xC0 비트 보존) | 무손상 | 0x31은 0xC0과 별도 레지스터, 6개 write 사이트 미접촉 |
| INV-X-2(READ_FAIL hold) | 무손상 | I2C 프로토콜 레이어 독립, RDY 간접영향은 INV-⑦에 포함 |
| INV-X-3(read_debug 무해) | 무손상 | 0x13/0x14 read 경로와 0x31 무관 |

**요약**: 11개 중 8개 무손상, 3개 주의(INV-④ SNR 재확인·INV-⑥ ATI 캡 여유·INV-⑦ RDY 타이밍 여유), 충돌 0. S1 원 매트릭스(9무손상/2주의)와 표기 차이는 INV-⑥을 "무손상"에서 "무손상, 단 게이트"로 세분한 것뿐 — 신규 충돌 발견 아니다.

## 7. 감도·전류·변환시간 트레이드오프

| 구분 | 1.00MHz(현재) | 500kHz(P4 채택) |
|---|---|---|
| 감도(ATI Target·임계공식) | 기준 | 이론상 동일(레지스터 독립) — SNR 실측 재확인 권고(§6 INV-④) |
| 전류 | 데이터시트 §3.4 표의 실측조건 **아님** | **데이터시트 §3.4 표가 실제 측정에 사용한 조건과 일치**(`01_개요·전기·타이밍.md` §3.4: "Self-cap·Mutual ATI Target=512, Fxfer=500kHz") — 단 그 표는 3채널 기준(본 설계는 CH0 단일)이라 정량 μA 직접 대입 불가 [실측 게이트] |

## 8. 메커니즘별 대응력 — 한계 명시

| 메커니즘 | P4의 대응력 |
|---|---|
| 메커니즘_1(결합임피던스∝f) | **거의 무관** — f는 애그레서(SPI/SYSCLK) 주파수이지 IQS323 Fxfer가 아님(S1 §5) |
| 메커니즘_2(샘플링 윈도우 일치) | **역효과** — Fxfer 하향은 1회 변환 노출창을 2배로 늘려 오히려 불리(S1 §5) |
| 메커니즘_3(에일리어싱/맥놀이) | **약~중** — §3 계산상 500kHz는 SYSCLK 정수비에서 44% 이격(389kHz의 2.8%보다 안전)하나, (a) Table A.1 근사치·IQS323 f_OSC 공차 ±5.5%로 "통계적 이격"이지 "확정 회피" 아님, (b) fake_func_sleep(30.72MHz)·func_sleep(2.56MHz)에서 SYSCLK가 달라 이격도가 다시 갈린다(§5) |

> [!IMPORTANT]
> P4 단독은 **메커니즘_3에 국한된 약~중 수준의 완화**다. 메커니즘_1엔 무관, 메커니즘_2는 오히려 대가를 지불한다(노출창 증가). C1이 지목한 더 강한 근거의 후보(H1 I2C 프리스케일 5배 초과 — P2 담당, H2 read_debug 이중 애그레서 — P1 담당, 둘 다 P4 범위 밖)와 **병행 적용 전제**의 실험적 레버로 자리매김해야 한다. 단독 채택으로 하이젠베르크 해소를 주장할 근거는 아니다.

## 핵심 결론

1. P4는 `tdc_touch_iqs323.c:316` 1줄(Period 5→12, 0x057F→0x0C7F, 1.00MHz→500kHz)만 바꾸는 구현-레디 스펙이며, 부팅 1회 write 구조 덕에 **fake_func_sleep()·func_sleep() 코드 변경 0**으로 자동 반영된다.
2. 신규 계산으로 389kHz(Period16)가 SYSCLK 정수배(≈79배, 오차 2.8%)에 근접한 회피 대상임을 확인했고, 500kHz(Period12)는 44% 이격+데이터시트 §3.4 실측조건 일치라는 이중 근거로 채택했다.
3. C2 11개 불변식 중 8개 무손상·3개 주의(INV-④ SNR·INV-⑥ ATI 캡·INV-⑦ RDY 타이밍), 충돌 0건 — 회귀 위험은 낮으나 재확인 게이트가 남는다.
4. **한계**: 메커니즘_3에만 약~중 효과, 메커니즘_1 무관·메커니즘_2 역효과(노출창 증가) — 단독으로 하이젠베르크 해소를 주장할 근거는 아니며, P0 실측 스윕·P1/P2 등 타 레버와 병행이 전제다.
5. 확정 판단은 실측 게이트(§9) 통과 후 가능 — 특히 SPI 클럭 미확인 상태의 §3 계산은 SYSCLK 단독 근거이므로 방향성 참고로 한정한다.
