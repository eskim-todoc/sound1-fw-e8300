# 03 · P2 — 드라이브·프리스케일 (구현-레디 스펙)

**TL;DR**: S5 후보_1·2·4를 코드 재확인해 구현-레디로 확정했다. I2C0 DIO 드라이브(`DIO_PIN_Config.h:54`, 8X→4X)·SPI1 DIO 드라이브(:13, 2X→1X)·절전 I2C prescale(`main.c:1222`, ÷6→÷21) 3건 모두 매크로·인자 값 1줄 교체이고 런타임 로직 변경은 0줄이다. I2C0가 터치·PMIC·가속도계·연료게이지·ISD 5개 기기의 단일 물리 버스임을 코드로 확정했고, prescale 정정은 `fake_func_sleep()`(재현 경로)와 **무관**함(이미 정상값)을 재확인했다.

## 0. 핵심 변경 3건 — 빠른 참조

| 레버 | 파일:라인 | Before | After | 물리량 변화 |
|---|---|---|---|---|
| I2C0 DIO 드라이브 | `DIO_PIN_Config.h:54` | `DIO_8X_DRIVE\|DIO_LPF_ENABLE\|DIO_NO_PULL` | `DIO_4X_DRIVE\|DIO_LPF_ENABLE\|DIO_NO_PULL` | 드라이브 8X→4X(LPF·PULL 불변) |
| SPI1 DIO 드라이브 | `DIO_PIN_Config.h:13` | `DIO_2X_DRIVE\|DIO_LPF_DISABLE\|DIO_WEAK_PULL_UP` | `DIO_1X_DRIVE\|DIO_LPF_DISABLE\|DIO_WEAK_PULL_UP` | 드라이브 2X→1X(LPF·PULL 불변) |
| 절전 I2C prescale | `main.c:1222` | `I2C_MASTER_PRESCALE_6` | `I2C_MASTER_PRESCALE_21` | SCL 426.7kHz→121.9kHz(≈122kHz) |

3건 모두 부팅 시 1회 적용되는 **정적 설정값**이며, 조건·게이트·FSM 변경이 전혀 없다(P3·P5와 결정적으로 다른 지점).

## 1. I2C0 DIO 드라이브 하향 (8X→4X)

- **적용 사이트**: `ci_dio.c:76` `Sys_I2C_DIOConfig(I2C0, I2C_PIN_CFG_VAL_forDIO, DIO_PIN_INDEX_for_CM3_SCL, DIO_PIN_INDEX_for_CM3_SDA);` — `ci_dio_configure_normal()`(ci_dio.c:40) 내부. 매크로만 바꾸면 이 호출부는 무수정.
- **호출 경로**: `Initialize()`(initialize.c:265) → 부팅 1회. `func_sleep()`/`fake_func_sleep()` 어느 쪽도 I2C0 DIO를 재설정하지 않음(코드 grep 확인, §8 표).
- **활성 브랜치 확인**: `processorDirective.h:10` `#define Board_is_OTE_VER_1_5` — `DIO_PIN_Config.h:6`의 `#ifdef Board_is_OTE_VER_1_5` 분기가 실제 컴파일 대상(§0 값은 이 분기 기준).
- **주의(혼동 방지)**: `DIO_PIN_Config.h:61`의 `CM3_I2C_MASTER_PIN_CFG_VAL(DIO_4X_DRIVE|...|DIO_1K_PULL_UP)`은 코드 전체에서 호출부가 없는 **미사용(dead) 매크로** — 이름이 비슷하나 이번 변경 대상이 아니다. `I2C_PIN_CFG_VAL_forDIO`(:54)만 수정.

## 2. SPI1(QCC/NRF) DIO 드라이브 하향 (2X→1X)

- **적용 사이트**: `driver_SPI.c:256` `Sys_SPI_DIOConfig(SPI1, SPI_SELECT_SLAVE, SPI_DIO_PIN_CFG, NRF_SPI_CLK_PIN, NRF_SPI_CS_PIN, NRF_SPI_MOSI_PIN, NRF_SPI_MISO_PIN);` — `init_cm3_SPI()`(driver_SPI.c:251) 내부.
- **호출 경로**: `initialize.c:506` `init_cm3_SPI();` → 부팅 1회.
- **주의(사석지 오수정 방지)**: `ci_dio.c:83`에 동일 호출의 **주석 처리된 복제본**이 존재 — `//Sys_SPI_DIOConfig(SPI1, ...)`. Dead code이므로 여기를 고쳐도 아무 효과 없음. 반드시 `driver_SPI.c:256`(활성 사이트)만 수정.
- **한계(S5 인용)**: CM3는 `SPI_SELECT_SLAVE`(SPI1 슬레이브) — CLK·CS·MOSI는 QCC/NRF가 구동하는 입력이라 CM3측 드라이브 설정이 실제 엣지에 영향 주는지 자체가 미확인. 확실히 영향받는 것은 CM3가 구동하는 **MISO**뿐일 가능성.

## 3. 절전(func_sleep) I2C prescale 정정 (÷6→÷21)

- **적용 사이트**: `main.c:1222` `i2c_set_master_prescale(I2C_MASTER_PRESCALE_6 /*I2C_MASTER_PRESCALE_21*/);` → 이미 소스에 정정값이 주석으로 명시돼 있어 활성/주석 값만 맞바꾸면 됨(기존 [FIXME] 완성).
- **레지스터**: `I2C0->CFG`의 `MASTER_PRESCALE` 필드. `i2c_set_master_prescale()`(driver_i2c.c:145~160)이 트랜잭션 idle 대기 → 인터페이스 disable → `(cfg & ~I2C_CFG_MASTER_PRESCALE_Mask) | prescale_mask`로 **해당 필드만** 마스킹 교체 → 재enable. 다른 CFG 비트(인터럽트 enable 등)는 그대로 보존되는 함수라 안전.
- **SCL 계산**: `SCL = SYSCLK/((PRESCALE+1)×3)`(driver_i2c.h:11), 매크로 접미사는 이 분모 전체값과 일치(예: `_6`→분모 6, `_21`→분모 21). SYSCLK=2.56MHz(`ci_power_sleep()`, main.c:1218) 기준: `_6`=426.67kHz, `_21`=121.90kHz.
- **시퀀스 불변**: `ci_power_sleep()`(:1218, SYSCLK 30.72M→2.56M) → `i2c_set_master_prescale()`(:1222) 순서는 그대로 유지, **인자값만** 교체. INV-⑥-1(진입 순서 불변) 위반 없음.
- **fake_func_sleep() 확인(필수 지시사항)**: `main.c:864` `i2c_set_master_prescale(I2C_MASTER_PRESCALE_240); /* 본래 노말 모드 설정 그대로 */` — **이미 정상모드와 동일 240(128kHz)**. `main.c:1222`(real `func_sleep()` 전용)와 **완전히 별개 사이트**이며, `fake_func_sleep()`은 `ci_power_sleep()`도 호출하지 않는다(`main.c:861` 주석 처리, 대신 `ci_fake_power_sleep()`이 SYSCLK 30.72MHz 유지). **결론: 이 prescale 정정은 재현 경로(`fake_func_sleep`)를 전혀 지나지 않는다** — §8에서 재확인.

## 4. 오픈컬렉터 제약 — 실제로 무엇이 완만해지는가 (I2C0 한정, 지시사항 반영)

**확립(데이터시트 원문 + 일반 I2C 프로토콜 사실)**: `05_i2c인터페이스.md:140` "Open-drain은 LOW만 능동 구동하고 HIGH는 pull-up 저항에 의존한다." `01_개요·전기·타이밍.md:119` R1~R3(pull-up) 4.7kΩ(SDA·SCL·RDY→VDD, 레퍼런스 회로), `:241` f_SCL 상한 1000kHz. CM3측 `I2C_PIN_CFG_VAL_forDIO`는 `DIO_NO_PULL`(내부 풀업 미사용) — 상승엣지는 **전적으로 보드 외부 저항 RC**가 결정하며 CM3의 `DIO_xX_DRIVE` 설정과 물리적으로 무관하다.

즉 8X→4X 하향이 완만화하는 것은 **CM3(마스터)가 능동으로 파는 하강엣지뿐**이다.

| 신호 | 마스터(CM3)가 구동 → 저감됨 | 슬레이브(IQS323)가 구동 → 저감 안 됨 |
|---|---|---|
| SCL | 모든 비트 사이클의 하강엣지(read·write 공통, 매 클럭) | (SCL은 항상 마스터 소유 — 해당 없음) |
| SDA | 주소+R/W 바이트, write 데이터 바이트, read 시 수신바이트에 대한 ACK/NACK | read 데이터 바이트 자체, write 시 슬레이브 ACK 비트 |
| 상승엣지(SCL·SDA 공통) | — | 외부 pull-up RC가 결정, DIO 드라이브와 무관 |

이 비대칭은 결함이 아니라 오픈컬렉터 토폴로지의 물리적 귀결이다 — **"모든 엣지가 저감된다"고 가정하면 예상 저감폭을 과대평가**하게 되므로 실측 해석 시 반드시 전제할 것(지시사항의 "상승엣지·read 응답엣지 미저감"에 해당).

## 5. I2C0 공유기기 영향 점검 범위 (S5 "미확인"→코드로 확정 승격)

**확립(코드 확인)**: `driver_i2c.c`의 `i2c_startWriteData`/`i2c_startReadData`는 `Sys_I2C_StartWrite(I2C0,...)`로 **버스 인자 없이 I2C0 하나만** 다루는 단일 구현이다. 아래 5개 기기가 전부 이 함수를 그대로 호출해 **동일 물리 버스**를 공유한다.

| 기기 | 슬레이브 주소 | 호출 사이트 |
|---|---|---|
| IQS323(터치) | `0x44`(tdc_touch_iqs323.h:28) | tdc_touch_iqs323.c:70,102 |
| MAX17262(연료게이지) | `0x36`(driver_MAX17262.h:17) | driver_MAX17262.c:31,55 |
| ISL9122(PMIC) | `REN_ISL9122_SlaveAddr` | driver_REN_ISL9122.c:22,53,63 |
| MIS2DH(가속도계) | `MIS2DH_I2C_Addr` | driver_MIS2DH.c:21,52,62 |
| ISD(임플란트, FPGA 경유) | 가변 인자 | dirver_i2c_for_ISD.c:18,66(driver_i2c 얇은 래퍼) |

**점검 범위**: I2C0 드라이브 하향은 이 5개 기기 **전체**의 통신 여유도에 영향(터치 8개 불변식 범위 밖). 특히 ISD는 이번 세션에서 새로 확인된 공유 기기로, S5가 언급하지 않았던 항목 — FPGA/자극 관련 I2C 트랜잭션도 동일 버스·동일 드라이브 설정을 탄다. 실기 검증 시 터치 단독이 아니라 PMIC 전압읽기·가속도계 인터럽트·연료게이지 SOC 읽기·ISD 자극 파라미터 전송까지 포함한 회귀 스윕을 권고.

## 6. 적용 시퀀스·조건

- 3건 모두 **상호 독립**(변수 겹침 없음, S5 §5 인용) — 개별 적용·개별 롤백 가능. FSM/카운터 등 런타임 조건 불요.
- 변경 파일 2개, 라인 3곳: `DIO_PIN_Config.h`(13, 54), `main.c`(1222). 재빌드·재플래시만으로 전체 반영.
- 권장 순서(리스크 관리용, 필수 아님): ① prescale 정정(가장 국소적, real `func_sleep()` 전용이라 재현 경로·타 기기 무관, 안전) → ② I2C0 드라이브 하향(재현 경로 직접 관련, 공유기기 5종 회귀범위) → ③ SPI1 드라이브 하향(BLE/OTA까지 회귀범위 추가 확장).
- 롤백: 매크로/인자 값 되돌리기 각 1줄 — 즉시 가역, 부작용 잔존 없음(레지스터 write 로직 자체는 무변경).
- 타 레버와의 관계: P3(0xC0 bit7)·P5(FSM 라이드스루)·P1(read_debug 로직)과 겹치는 변수 없음(전기적 파라미터 vs 판정 로직 vs 레지스터 비트 — 서로 다른 층위, S5 §5 인용) — 병행 적용 가능.

## 7. C2 불변식별 회귀 체크리스트

| # 기능 | I2C0 드라이브(8X→4X) | SPI1 드라이브(2X→1X) | I2C prescale(÷6→÷21) |
|---|---|---|---|
| ① Full ATI | 무손상 — 0x36·0xC0 write 내용 불변 | 무손상 | 무손상 — 트리거 조건 불변 |
| ② 최초 터치해제 | 무손상 | 무손상 | 무손상 |
| ③ ATI 에러 Re-ATI | 주의 — 통신 마진 실측 필요(§4) | 무손상(터치는 SPI 미사용) | 주의 — 단, §3 계산상 SCL 전환시간은 4바이트 기준 ≈300µs대로 700ms 문턱 대비 무시 가능 수준(이론상 여유 큼) |
| ④ 터치 판정 | 주의 — 글리치(0xEE) 빈도 실측 필요 | 무손상 | 주의(상동 이유, 여유 큼) |
| ⑤ 롱터치 | 무손상 | 무손상 | 무손상 |
| ⑥ 절전 진입/기상 | 무손상(부팅 1회 값, 진입 시퀀스 밖) | 무손상 | 무손상 — **이 레버의 직접 회귀 범위**. 시퀀스(INV-⑥-1) 순서 불변, 값만 교체 |
| ⑦ 공통폴링(L1) | 주의 — force_window_open 45ms/wait_window_closed 20ms(tdc_touch_iqs323.h:32~33) 마진 재확인 필요(INV-⑦-1: 노말·절전 동시적용은 원사양) | 주의(동일, SPI 쪽) | 주의(동일) — real `func_sleep()` 폴링에만 해당 |
| ⑧ 단일채널 | 무손상 | 무손상 | 무손상 |
| INV-X-1(0xC0 비트보존) | 무손상 — 신규 0xC0 write 없음 | 무손상 | 무손상 |
| *(범위 밖)* 공용자원 | PMIC·가속도계·연료게이지·ISD 통신여유도 **[확립: 공유 사실, 실측은 게이트]**(§5) | BLE 매핑/OTA 신뢰성[C2 범위 밖] | 없음(func_sleep 전용, 타 기기 미공유) |

**"충돌" 판정 0건.** ③·④·⑦의 "주의"는 전부 "통신 마진 자체가 실측 검증 전엔 단정 불가"라는 동일 성격 — 코드 재확인이 아니라 벤치 계측(스코프·장시간 0xEE 카운트)으로만 해소된다(S5 결론과 정합).

## 8. fake_func_sleep 경로 반영 여부 (필수 확인 사항)

| 레버 | 재현 경로 반영 | 근거 |
|---|---|---|
| I2C0 드라이브 8X→4X | **반영됨** — 부팅 1회 설정이라 `fake_func_sleep()` 실행 중에도 그대로 유지 | `ci_dio_configure_normal()` 부팅 1회, func_sleep/fake_func_sleep 모두 I2C0 DIO 재설정 없음(grep 확인) |
| SPI1 드라이브 2X→1X | **반영됨** — 상동 | `init_cm3_SPI()` 부팅 1회 |
| I2C prescale ÷6→÷21 | **반영 안 됨(무관)** — `main.c:1222`는 real `func_sleep()` 전용, `fake_func_sleep()`은 `main.c:864`의 별도 사이트에서 이미 `PRESCALE_240`(128kHz) 사용 중 | §3에서 코드 직접 확인, 두 사이트는 서로 다른 함수·서로 다른 값 |

**중요**: P2의 두 드라이브 레버는 실제 재현 경로(`fake_func_sleep`)에 유효하게 적용되지만, prescale 정정은 재현 경로와 **무관한 별개의 기존 FIXME 정정**이다 — "P2 적용=재현 문제 3중 해결"로 오인하지 말 것. prescale 건은 진짜 절전(`func_sleep()`)의 부수 개선일 뿐, 이번 하이젠베르크 재현·완화 효과와는 직접 인과관계가 없다.

## 핵심 결론

1. I2C0 DIO 드라이브(8X→4X, `DIO_PIN_Config.h:54`)·SPI1 DIO 드라이브(2X→1X, `:13`)·절전 I2C prescale(÷6→÷21, `main.c:1222`) 3건 모두 **매크로·인자 값 1줄 교체**로 구현-레디이며, 런타임 로직·FSM 변경은 0줄이다.
2. I2C0는 코드 확인 결과 터치·PMIC·연료게이지·가속도계·ISD **5개 기기가 공유하는 단일 물리 버스**(driver_i2c.c 단일 구현)임을 확정했다 — S5의 "미확인" 항목을 승격, ISD는 이번에 새로 발견된 공유 대상.
3. 오픈컬렉터 토폴로지상 이번 드라이브 하향은 **마스터(CM3)가 능동으로 파는 하강엣지만** 완만화한다 — 상승엣지(외부 pull-up RC)와 read 응답 데이터(IQS323 자체 구동)는 물리적으로 저감되지 않는다(§4, 지시사항 반영 완료).
4. **prescale 정정은 재현 경로(`fake_func_sleep()`)를 지나지 않는다** — `fake_func_sleep()`은 이미 `PRESCALE_240`(128kHz, 정상모드와 동일)을 쓰고 있어 이번 정정과 무관하며, real `func_sleep()`의 별개 기존 FIXME를 해소할 뿐이다. 두 드라이브 레버만 재현 경로에 유효 적용된다(§8).
5. C2 8개 불변식 "충돌" 0건 — ③·④·⑦의 "주의"는 전부 실측(스코프·장시간 글리치 카운트)으로만 해소 가능한 통신 마진 확인 항목이며, 코드 근거상 이론적 여유는 충분한 것으로 추정된다.
