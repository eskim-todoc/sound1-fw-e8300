# 99 · 종합 — 구현 계획 (P0~P5)

**TL;DR**: P0~P5가 모두 구현-레디 스펙(파일:라인·before→after·불변식 회귀·fake_func_sleep 반영)으로 확정됐다. 통합 검증 결과 **논리충돌 0·확정 불변식 위반 0·fake_func_sleep 누락 0**. 롤아웃 6단계와 전제 4건이 도출됐다. **P0 실측이 모든 것의 선결**이며, H1(I2C 5배)은 재현 경로에서 **코드로 반증**돼 애그레서 무게가 H2(read_debug)·물리결합으로 이동했다.

## 1. P0~P5 구현 요약

| P | 변경(핵심) | 파일:라인 | 효과·성격 |
|---|---|---|---|
| **P0** | 4애그레서 스윕(DBG/QCC/NRF/CLK) + RTT 로그. 코드 미수정(측정 후 원복) | main.c fake_func_sleep 로그 삽입 | 지배 애그레서·H2·재현경로 이분 판별(선결) |
| **P1** | 안A `read_combined()` 신규(read_status+read_debug 통합, 레지스터 불변) / 안B `DEBUG_PRINT_ENABLE 1→0` | iqs323.c:398후·호출부 3곳 / config.h:22 | H2 완화(관측 탈침습), 근본 근접 |
| **P2** | I2C0 DIO 8X→4X·SPI1 DIO 2X→1X · prescale ÷6→÷21 | DIO_PIN_Config.h:54·13, main.c:1222 | 결합 저감(중~강, 방향성만 확립). **prescale은 재현경로 무관** |
| **P3** | 0xC0 bit7(0x50→0xD0 등) 5사이트, Streaming→Events | iqs323.c:318·447·453·465·471 | 자가 RDY토글 제거, 조건부(INV-⑤ 실측) |
| **P4** | 0x31 Period5→12(1MHz→500kHz), 389kHz 회피 | iqs323.c:316 (1줄) | 에일리어싱 약~중, 부팅 Re-ATI 캡 여유 2배↓ |
| **P5** | fake 카운터 ×10(5→50·24→240) 카운터기반 | main.c:949·1007, time.h 매크로 추가 | 안전망(근본 아님), touch측은 현재 no-op |

## 2. 핵심 발견

- **H1 재현경로 반증[코드 확립]**: `fake_func_sleep()`은 SYSCLK 30.72MHz 유지 + **I2C prescale 240(128kHz) 유지** → SCL 5배 초과 없음. "÷6→5.12MHz"는 진짜 `func_sleep()`(2.56MHz)의 별건 FIXME. → **재현경로의 애그레서는 I2C 프로토콜 위반이 아니다**. 무게가 **H2(read_debug 자체 애그레서)·물리결합(SPI/SYSCLK/QCC)**로 이동.
- **P2 prescale 정정은 하이젠베르크와 무관**(재현경로 밖 func_sleep FIXME) — 효과 오인 방지 명시.
- **read_debug latch 버그는 양산 빌드에도 잠재**(DEBUG_PRINT_ENABLE=1 기본) — P1의 부수 가치.

## 3. 통합/회귀 검증 (07)

- **논리충돌 0 · 확정 불변식 위반 0 · fake_func_sleep 누락 0** (6개 스펙 인용 라인 전수 코드 재확인 일치).
- **전제 4건** (마스터 계획에 반영):
  1. **P0↔P1 시간분리**: main.c 908~909·917행 공유 → P0 실측·완전원복 후 P1.
  2. **INV-④·⑦ 누적 분리 측정**: P1~P4가 45ms/20ms 타임아웃 마진·SNR에 겹쳐 영향 → 단계별 실측으로 개별 기여 분리.
  3. **P5 최후 배치**: 근본레버(1~4) 효과 확인 전 P5를 넣으면 "재부팅 지연만으로 개선된 듯" 보이는 **관찰 마스킹** 위험.
  4. **main.c:1011 `SYS_WATCHDOG_RESET()` 주석 복원 여부**: P3·P5 양쪽에 걸친 별도 의사결정 → **은수님 확인 선행**.
- **라인앵커 주의**: P1이 iqs323.c에 신규함수 삽입 시 P3 대상 라인 시프트 → 구현 시 `write_register(REG_SYSTEM_CONTROL,...)` grep 재검색으로 사이트 재확인.

## 4. 롤아웃 6단계 (통합 권장)

0. **P0 실측**(DBG→QCC→NRF→CLK 단독변형) → git diff 완전원복.
1. **P2-prescale + P4** 병행(다른 파일, 부팅1회, 최저위험).
2. **P2-드라이브** 단독 적용 후 글리치율 실측(원인분리).
3. **P1**(combined_read) — P0 완전원복 후, 적용 후 P3 라인앵커 재확인.
4. **P3**(0xC0 bit7, 5사이트 원자적 동시커밋) — P1 위 구조 안정화 후.
5. **P0 재실측** — 1~4 누적효과 검증.
6. **P5**(카운터 확장, 안전망) — 반드시 최후.

## 5. 정직한 한계

- 지배 애그레서 미확정 → 레버 효과 대부분 실측 게이트. **P0가 이를 확정**하는 구조.
- P3(Events 모드 전환)·P4(변환시간 2배)는 RDY 윈도우 마진에 영향 → 실측 필수.
- P5는 근본해결 아님. touch측 재부팅은 현재 no-op(main.c:1011 주석).
