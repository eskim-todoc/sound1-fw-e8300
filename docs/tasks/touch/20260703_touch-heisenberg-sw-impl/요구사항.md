# 요구사항 — SW-only 하이젠베르크 회피 구현 계획

**TL;DR**: 선행 조사([`20260703_touch-heisenberg-sw-mitigation`](../20260703_touch-heisenberg-sw-mitigation/))가 "SW-only 회피 가능"으로 결론내고 권고 포트폴리오 P0~P5를 도출했다. 은수님이 **재현 경로=`fake_func_sleep()` 확정**, **전체 계획 수립**을 지시했다. 본 작업은 P0~P5를 **구현-레디 스펙**(정확한 파일·라인·레지스터값·시퀀스·불변식별 회귀체크·롤아웃 순서)으로 구체화한다. 실제 코드 변경(④)은 본 계획 승인 후 착수.

## 1. 입력 (확정 사항)

- **재현 경로 = `fake_func_sleep()`**(main.c:810~1031, BLE 'General Debug' op_mode==1). func_sleep()과 분리된 복제 코드 → **양쪽/해당 경로를 명시 대상**으로.
- 권고 포트폴리오(선행 [`계획.md`](../20260703_touch-heisenberg-sw-mitigation/계획.md)):
  - **P0** RTT 실측 게이트(지배 애그레서·H1·H2·재현경로 확정) — 은수님 환경 실행.
  - **P1** 관측 탈침습: 계측 `read_debug()` latch 버그(문서 39/40) 수정 또는 프로파일링 중 스로틀/비활성.
  - **P2** GPIO 드라이브 하향(I2C0 8X→4X, SPI1 2X→1X) + 절전 I2C 프리스케일 의도값(122kHz) 복귀 검토.
  - **P3** 0xC0 bit7 Interface Selection(IQS323 자가 RDY 토글 제거). **write 사이트 6곳 확정**(tdc_touch_iqs323.c:237 ack·318 base 0x50·447·453·465·471), base 318 `0x50→0xD0`.
  - **P4** 변환주파수(0x31) 조정, 389kHz 최악 근접 회피.
  - **P5** F0-게이팅 라이드스루(**카운터 기반**) — 프로파일링 구간 재부팅 억제.

## 2. 목표

- P0~P5 각각을 **구현-레디 스펙**으로: (a) 정확한 파일·함수·라인, (b) 레지스터/설정 값(before→after), (c) 적용 시퀀스·조건(F0 게이팅 등), (d) **C2 불변식(INV-①~⑧·INV-X)별 회귀 체크**, (e) 리스크·실측 게이트, (f) fake_func_sleep 경로 반영 여부.
- 레버 간 **충돌·중복** 점검(같은 파일 main.c·tdc_touch_iqs323.c 다중 수정).
- **롤아웃 순서**와 각 단계의 검증 방법(빌드·회귀·실측).
- P0 실측 프로토콜(무엇을 RTT로 로깅해 애그레서·H1·H2·재현경로를 이분법 판별하는지).

## 3. 제약

- HW 무수정 · 기존기능 전부 만족(C2 불변식) · mutual 제외 · SW/설정만.
- 본 단계는 **계획 산출만**. 제품 소스 코드 변경은 승인 후 별도 단계(④).
- 데이터시트·현 코드 근거. 미확인은 실측 게이트로 표기. 할루시네이션 금지.
- 특히 **INV-X-1**: 새 0xC0 write는 `Power Mode·CH timeout 비트 동반`(P3에서 bit7 추가 시 기존 `0x50/0x54/0x58, 0x07` 조합 보존).

## 5. 완료 기준

- P0~P5가 각각 구현-레디 스펙(파일·값·시퀀스·불변식 회귀·fake_func_sleep 반영)으로 구체화되고, 레버 간 충돌이 점검되며, 롤아웃 순서·검증법·P0 실측 프로토콜이 `계획.md`에 명시되어 은수님 승인만으로 ④ 구현 착수가 가능한 상태.
