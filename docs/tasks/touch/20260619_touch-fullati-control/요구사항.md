# Full ATI 터치 제어 재설계 — 요구사항

**TL;DR**: 20260618 브레인스토밍이 수렴한 **FullATI 타임아웃 단순안**을 펌웨어로 구현한다. Fixed MULT/COMP·공장 캘리브레이션·CRX1 CalCap 더미채널을 **전부 폐기**하고, **Full ATI**로 전환해 드리프트를 ATI 밴드 이탈 시 Re-ATI로 자동 보정한다. 터치 stuck은 IC 타임아웃이 아닌 **SW 터치 지속시간 카운트(30초)**로 처리한다. 본 문서는 은수님 요구사항 16항목과, 구현 전 결정·정량 분석이 필요한 항목을 정리한다.

---

## 1. 배경

- 누적 분석 9건 + 브레인스토밍(20260618)이 **FullATI 타임아웃 단순안**으로 수렴([`브레인스토밍_FullATI타임아웃단순안.md`](../20260618_touch-review/브레인스토밍_FullATI타임아웃단순안.md)).
- 외부 앱노트 검증(20260619)으로 ATI 2단계·온도 드리프트 정량·SNR≥5·timeout 동작(Reseed) 확인([`적용가이드`](../../../참고/touch/적용가이드/IQS323-제어운영-적용가이드.md)).
- 핵심 전환: **Fixed/공장캘리/CalCap 폐기 → Full ATI 기반 자가 보정**. 단순성·드리프트 자동 커버·human-in-the-loop 복구가 근거.

## 2. 핵심 설계 방향 (확정)

| 방향 | 내용 | 폐기 대상 |
|---|---|---|
| Full ATI 전환 | ATI Mode=Full(자동 Re-ATI 활성) | Fixed MULT/COMP, ATI Disabled |
| 공장 캘리 폐기 | 보드별 절대 노터치 기준 저장 불필요 | 공장 초기화 과정 |
| 단일 채널 | CRX0만 사용 | CRX1 CalCap 더미채널 |
| 드리프트 자동 보정 | LTA가 ATI 밴드 이탈 시 Re-ATI | (수동 드리프트 관리) |
| SW 타임아웃 | 터치 지속시간 SW 카운트(30초) | IC Channel Timeout(ULP 충돌·인지 불가) |

## 3. 은수님 요구사항 (16항목)

| # | 요구사항 | 비고 |
|---|---|---|
| 요구사항_1 | **Full ATI 사용** | ATI Mode=Full |
| 요구사항_2 | ATI 밴드 이탈 시 ATI 에러 발생 → **상태 레지스터 읽어 ATI 에러면 Re-ATI** | System Status bit6 폴링 |
| 요구사항_3 | IC 타임아웃 미사용. **SW에서 터치 유지 시간 체크 → 30초 이상 지속 시 에러 처리** | SW watchdog |
| 요구사항_4 | 약 3초 후 절전 진입 시 **3초 + 이후 터치 유지 시간 체크 방법 필요**. 노말/절전 함수·시퀀스 다름 | 시퀀스 설계 |
| 요구사항_5 | 절전 함수 **초입에서 30초 대기? vs 절전 루프 내 대기?** (Full ATI면 절전 함수 내 센서 재설정 불필요?) | 분석 필요 |
| 요구사항_6 | **내부기 연결·크래들 충전 중엔 터치 미사용**(현재. 향후 사용 가능성) | 게이트 |
| 요구사항_7 | **Beta 설정 분석/계산/검증** — 카운터에 적절히 빠르게 수렴 | 정량 |
| 요구사항_8 | **카운터·스레스홀드 수준 분석/계산/검증** — LTA 밴드는 초과 안 하면서 threshold로 사용 가능한 수준 | 정량 |
| 요구사항_9 | **100ms 측정 조건에서 컨버전 1MHz 적절성 분석/계산/검증** + auto ulp 가능 여부(완전 저전력 진입은 원치 않음) | 정량 |
| 요구사항_10 | 노말 부팅 시 **터치 유지를 노말 메인 루프에서 확인**(초기화서 해제 대기 불필요) | 시퀀스 |
| 요구사항_11 | 노말 부팅 시 **ATI 에러 체크 → 에러면 처음부터 Re-ATI**. 번거로우면 **MCLR로 항상 초기화 후 노말 진입도 OK** | 결정 |
| 요구사항_12 | 노말 루프 내에서도 **ATI 에러 발생 시 Re-ATI** | |
| 요구사항_13 | **ATI로 드리프트 커버** — 드리프트가 LTA 밴드 벗어나면 Re-ATI로 해결 | |
| 요구사항_14 | **Fixed 불필요, 공장초기화 불필요** | 폐기 |
| 요구사항_15 | **CRX0만 사용, CRX1 CalCap 불필요** | 폐기 |
| 요구사항_16 | (빠진 것 있으면 발굴·정리) | → §5 |

## 4. 분석·계산·검증 필요 (정량 — 분석 단계 핵심)

- **검증_Beta**(요구사항_7): 노터치 카운터 수렴 속도 vs 터치 신호 흡수 방지. Beta 값(LTA β, Counts β, Fast Filter Band 비대칭). 100ms 주기·수렴 목표시간 기준 계산.
- **검증_임계**(요구사항_8): ATI Target/Base, ATI Band 폭, Touch Threshold 관계. "LTA 밴드 초과 안 하면서 threshold로 동작" 가능 영역 계산(델타 마진 vs ATI Band 마진). SNR≥5(앱노트) 적용.
- **검증_컨버전전력**(요구사항_9): 컨버전 1MHz + 100ms 폴링 시 ATI 소요시간·전류. auto ULP 가능 여부(단 완전 저전력 진입 불가 — LP까지). 전력모드 설정.
- **검증_절전시퀀스**(요구사항_4·5): 절전 30초 대기 위치(초입 vs 루프). Full ATI 시 절전 함수 내 센서 재설정 필요 여부.

## 5. 추가 검토·결정 필요 (발굴 — 요구사항_16 보완)

> 은수님 요구사항에서 명시되지 않았으나 구현 전 결정·검증이 필요한 항목.

| # | 항목 | 쟁점 |
|---|---|---|
| 검토_1 | **SW 타임아웃 30초 후 "에러 처리"의 구체 동작** | Re-ATI? Reseed? MCLR 재부팅? 사용자 알림? — 정의 필요 |
| 검토_2 | **터치 중 Re-ATI 경계 (급소)** | ATI 에러/밴드이탈 Re-ATI가 터치 판정 중 발동하면 터치를 노터치로 학습. LTA halt가 막아주는가? "터치 중 Re-ATI 보류" 게이트 필요 여부 |
| 검토_3 | **CRX1 폐기 시 ESD 대책** | CRX1이 ESD 더미채널(방전) 역할이었음([이슈해결 CRX1-ESD](../../../참고/touch/이슈해결/2026-06_CRX1-ESD-더미채널.md)). 폐기 시 ESD 내성 — Full ATI Re-ATI 자가복구로 충분한가? 단일채널 정지 이슈 재검토 |
| 검토_4 | **Full ATI의 I²C 무응답 위험** | 과거 Full ATI가 ATI 진행 중 I²C 무응답 유발(현 펌웨어가 끈 이유). 100ms 폴링 시 통신 충돌 → 은수님 가정(실패 시 다음 100ms 재시도, N회 연속 실패 시 고장 판정) 반영 필요 |
| 검토_5 | **Beta 비대칭 (Fast Filter Band)** | 단순 Beta 상향은 약터치 흡수 위험(이전 권고). Fast Filter Band 비대칭이 정답 후보 — 요구사항_7과 통합 검토 |
| 검토_6 | **부팅: ATI 에러 체크 vs MCLR 항상** | 요구사항_11 결정 — 둘 중 택1 또는 조합. MCLR 항상이 단순하나 부팅 ~500ms+ATI 시간 추가 |
| 검토_7 | **Max Counts 포화 안전망** | 큰 물체/전극 이상 시 conversion 정지 → MCLR만 회복(앱노트 확정). SW 타임아웃과 별개 안전망 유지 여부 |
| 검토_8 | **드리프트 Re-ATI burst vs 100ms 폴링** | 환경 급변 시 Re-ATI 빈발 → 통신/전류. 안정화 필요 여부 |
