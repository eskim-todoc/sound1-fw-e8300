# 10 검증 — 회귀 충돌 (adversarial)

**TL;DR**: Full ATI 단순안의 5대 과거 이슈를 코드 ground truth로 재검증했다. ① I²C 무응답·② 단일채널 정지·④ 드리프트 고착은 **[해소]**(CH1 폐기·방전 폐기·자동 Re-ATI 부활). ③ Reseed 오염·⑤ Re-ATI burst는 게이트 설계로 **[잔존위험]**(쿨다운·실측 의존). 그러나 코드 대조에서 **5건의 [신규회귀]를 적출**: (가) `reseed()`가 순수 RESEED가 아니라 절전 감도까지 재적용 — 노드 03 30초 1단계 RESEED 재활용 시 노말에 절전 감도 오염, (나) read 실패 시 NOT_TOUCH 미강제(현 hold-last) — Full ATI burst 빈발로 stuck 롱터치 오발, (다) 부팅 운용 `apply_settings()`에 수동 Re-ATI 없음 — auto-ATI 실패 시 ATI_Error 잔류 영구, (라) `is_auto_ati_done`의 통신실패↔ATI진행 미구분, (마) Threshold(100)>Band 부등식 위반이 Full에서 표면화. 각 신규회귀에 선행 수정 의무를 명시.

---

## 1. 검증 방법·범위

adversarial 검증으로 노드 01~08의 설계 결정이 **(A) 과거 이슈를 진짜 해소하는가, (B) 현 코드 구조와 정합하는가, (C) 새 회귀를 부르는가**를 코드 ground truth로 적출한다. 추측이 아니라 실제 코드 라인·이슈해결 문서·직전분석으로만 판정한다.

검증 대상 5대 과거 이슈 (오케스트레이터 지정):
1. **Full ATI I²C 무응답** (현 펌웨어가 ATI를 끈 이유)
2. **단일채널 정지** (CRX1-ESD 이슈)
3. **Reseed baseline 오염**
4. **드리프트 고착**
5. **Re-ATI burst**

판정 라벨: **[해소]** / **[잔존위험]** / **[신규회귀]**.

> [!NOTE]
> 본 노드는 코드 라인 번호를 직접 확인했다(`tdc_drv_iqs323.c`·`tdc_touch.c`·`main.c`·`tdc_touch_config.h`·`tdc_drv_iqs323.h`). 노드 01~08이 인용한 라인은 대부분 정확했으나, **`apply_settings()` 운용 분기·`reseed()` 부작용·read 실패 경로**에서 노드들이 놓친 정합 충돌을 추가 적출했다.

## 2. 과거 이슈 5종 — 충돌/해소 판정

### 2.1 이슈① Full ATI I²C 무응답 — [해소] + [신규회귀 1건]

#### 판정: 두 원인 중 주원인(B)은 [해소], 그러나 부팅 핸들러에 [신규회귀]

노드 01·02·08이 분석한 대로 과거 무응답의 진짜 원인은 두 갈래다. 코드로 재확인:

| 원인 | 코드 ground truth | Full 단순안 처리 | 판정 |
|---|---|---|---|
| A: ATI 중 RDY 미개방 → `force_window_open()` 45ms timeout | `force_window_open()` [`tdc_drv_iqs323.c:143~172`], `MAX_WAIT_MS_FOR_WINDOW_OPEN`=45ms [`:161`] | N회 재시도 흡수 + ATI_Active 폴링 | [해소] (일시적 read 실패) |
| B: CH1 CalCap 더미 auto-ATI 수렴 실패 → 전역 ATI_Error 영구 | `sensor_setup()` CRX1 DUMMY 분기 [`:479~510`], 이슈해결 §4·§6 | **CH1 폐기**(노드 07) → 수렴 실패원 소멸 | [해소] |

이슈해결 문서 §6 확정: "MCLR 직후 auto-ATI는 `sensor_setup()`보다 **먼저** 돈다. 그 시점 CH1은 reset 기본값(외부 CRx1+C52)이라 ATI 수렴 실패 → 전역 ati_error SET → 운용 모드 re-ATI 없어 영구 잔류". CH1을 폐기하면 이 경로가 원천 소멸한다. **여기까지 노드 01·07 정확.**

#### [신규회귀 1] — 부팅 운용 `apply_settings()`에 수동 Re-ATI가 없다

> [!CAUTION]
> **노드 01·08이 놓친 코드 사실**: 운용 모드 `apply_settings()`(`#else` 분기, [`tdc_drv_iqs323.c:1101~1158`])에는 **`re_ati_trigger()`가 없다.** 수동 Re-ATI는 **덤프 모드**(`#if TDC_DRV_IQS323_ATI_DUMP_ENABLE`, [`:1081`])에만 있고, 운용 부팅 시퀀스는 ACK→sensor_setup→touch/prox/events→`write_ati_compensation()`(FIXED write)→RESEED→CH timeout disable 순서다.

함의: Full 전환 시 노드 01·08이 `write_ati_compensation()`을 제거하면, 운용 부팅 경로에 **게인 캘리 수단이 MCLR 직후 auto-ATI 단 1회**만 남는다. 그런데 이슈해결 §6이 확정한 대로 **auto-ATI는 sensor_setup 이전에 돈다** — 즉 단일 CRX0로 폐기해도, auto-ATI 시점의 보드 기생 부하가 수렴 실패하면 전역 ATI_Error가 set되고, **운용 `apply_settings()`엔 이를 clear할 수동 Re-ATI가 없어** 과거 이슈④(영구 잔류)가 *채널만 바뀐 채* 재현될 수 있다.

- **직전분석 line 116이 같은 함정을 경고**: "ATI_Error set → ATI_Active=0 → read 성공 → 카운터 안 오름 → `(void)` 무시 → 수동 Re-ATI 발행 주체 없음 → 잘못 보정된 IQS323 영구 동작. retry-count·ATI_Active 폴링 둘 다 이 경로를 못 막음 → ATI_Error 전용 핸들러 필수."
- 노드 02가 런타임 ATI_Error 폴링→Re-ATI를 설계했으나, **노드 02의 게이트는 "노터치 AND ATI Active==0"에서만 발행**한다. 부팅 직후 노터치면 첫 폴링 tick에서 처리되지만, **노드 08이 "부팅 ATI_Error 전용 핸들러는 두지 않는다"고 명시**했으므로, 부팅 직후 ~첫 노터치 tick까지의 공백 + boot_touch_ignore 가드 상호작용이 미검증이다.

**선행 수정 의무**: Full 전환 시 운용 `apply_settings()`에서 FIXED write 제거 후, **(ㄱ) 부팅 시 1회 명시 Re-ATI를 넣어 auto-ATI 잔재를 clear하거나, (ㄴ) 노드 02 런타임 핸들러가 READY 직후 첫 노터치 tick에서 ATI_Error를 확실히 처리함을 보장**해야 한다. 노드 08의 "부팅 핸들러 불필요"는 (ㄴ) 보장이 전제다 — 이 전제를 99 종합에서 명시 검증 항목으로 격상 권고.

### 2.2 이슈② 단일채널 정지 (CRX1-ESD) — [해소]

#### 판정: [해소] — 방전 폐기로 정지 조건 원천 소멸

이슈해결 §1 정지 메커니즘: CH0(유일 활성) disable → 활성 채널 0개 → measurement cycle 정지 → RDY 윈도우 안 닫힘 → `WAIT WINDOW CLOSE soft timeout` 무한. 코드로 확인:

- `discharge_crx0()` [`tdc_drv_iqs323.c:951~965`]가 CH0를 `INACTIVE_RXS_CRX0_VSS`로 disable(`:955`) 후 복원(`:960`). 이 disable 순간이 정지 위험.
- `get_state()` [`tdc_touch.c:419~423`]가 `#if TDC_TOUCH_CRX0_DISCHARGE_ENABLE`로 매 폴링 호출.

노드 07이 정확히 적출: "방전을 폐기하면 CH0를 끌 일이 없다 → 활성 채널 항상 1개 → 정지 조건 성립 불가." 코드상 `TDC_TOUCH_CRX0_DISCHARGE_ENABLE=0`(`tdc_touch_config.h:113~114`)으로 두면 `get_state()`의 방전 호출이 컴파일 제거되어 정지 위험이 소멸한다. **[해소] 확정.**

> [!NOTE]
> 단 노드 07의 전제 "방전 폐기 = CalCap 폐기 = 단일채널이 한 묶음"은 옳으나, **방전이 ESD에 실효였는지는 [실측 게이트]**(직전분석 §7). 방전을 폐기하고 ESD 복구를 Full ATI 자동 Re-ATI에 위임하는 것이 실보드에서 통하는지는 미검증 — 이슈②는 정지 회귀만 [해소], ESD 복구 효력은 이슈④로 이관.

### 2.3 이슈③ Reseed baseline 오염 — [잔존위험] + [신규회귀 2건]

#### 판정: 게이트로 1차 방어되나 코드 정합 충돌 2건

노드 02가 "터치 중 Re-ATI가 터치를 노터치로 학습"하는 메커니즘을 정확히 분석했고, 게이트(`CH0 Touch==0 AND ATI Active==0`)를 필수로 결론했다. 이는 [잔존위험]을 관리 가능 수준으로 낮춘다. 그러나 코드 대조에서 두 신규회귀:

#### [신규회귀 2] — `reseed()`는 순수 RESEED가 아니다 (절전 감도 동반)

> [!CAUTION]
> **노드 03이 부분 인지했으나 회귀 심각도를 과소평가**: `tdc_drv_iqs323_reseed()` [`tdc_drv_iqs323.c:931~949`]는 RESEED bit3 발행 전에 **절전 터치 감도**(`touch_settings_impl(SLEEP_TOUCH_THRESHOLD, SLEEP_TOUCH_HYSTERESIS)`, `:934`)와 **절전 Prox Threshold**(`prox_settings(SLEEP_PROX_THRESHOLD)`, `:940`)를 재적용한다. 순수 System Control bit3 RESEED가 아니다.

회귀 경로:
- 노드 03이 30초 stuck 에러처리 **1단계 RESEED에 이 함수를 재활용**하면, **노말 폴링 중에 절전 감도(`SLEEP_TOUCH_THRESHOLD=100`·`SLEEP_PROX_THRESHOLD=100`)가 노말 환경에 잘못 적용**된다. 노말은 `TOUCH_THRESHOLD=100`이라 우연히 같으나, 노드 05가 권고하는 **노말 Threshold 50~80 / 절전 별도 감도**로 분기하는 순간 30초 RESEED가 감도를 절전값으로 덮어쓰는 영구 오염이 발생한다.
- 노드 03 §8.4가 `reseed_only()` 신설을 권고했으나 "권고" 수준 — **이는 권고가 아니라 [신규회귀] 차단 필수**로 격상해야 한다.

**선행 수정 의무**: 30초 에러처리 1단계 RESEED는 반드시 **순수 bit3만 발행하는 신규 API**(`reseed_only()`)로 구현. 기존 `reseed()`(감도 동반)는 절전 진입 전용으로 격리.

#### [신규회귀 3] — 절전 진입 시 감도를 두 번, 다른 값으로 쓴다

> [!WARNING]
> 절전 진입 시퀀스 코드 대조: `apply_sleep_settings()` [`:967~1034`]가 `touch_settings_impl(255, 255)`(`:978`, RTT 튜닝 off일 때)로 **최대 민감도**를 쓴다. 그 직후 `ci_power_sleep()`(클럭강하) → `reseed()` [`main.c:952`]가 다시 `touch_settings_impl(SLEEP_TOUCH_THRESHOLD=100, SLEEP_TOUCH_HYSTERESIS=80)`(`:934`)로 **덮어쓴다**. 즉 255→100 순서로 두 번 쓴다.

이건 Full ATI 전환과 **독립한 기존 코드 모순**이지만, 노드 03이 절전 시퀀스를 "Fixed write만 제거"로 단순화하면서 이 이중 write 모순을 정리 대상에서 누락했다. Full 전환 시 `apply_sleep_settings()`의 FIXED MULT/COMP를 제거할 때 **이 감도 이중 write도 함께 정리**하지 않으면, 어느 감도가 실제 적용인지 불명확한 채 잔존한다. [잔존위험]으로 분류하되 99 종합에서 절전 감도 단일화 명시 권고.

#### 이슈③ 본체 — [잔존위험]

노드 02 게이트가 경로_2(SW 강제 Re-ATI)를 막고, 경로_1(자동 Re-ATI)은 LTA halt(§5.5)에 위임하는 분담은 타당. 단 **미해결_3(Re-ATI가 LTA를 자동 재seed하는지 [자료 미명시])**가 게이트 안전마진을 좌우 — 보수적으로 "재seed한다" 가정한 게이트는 안전 쪽. 실측 전까지 [잔존위험] 유지.

### 2.4 이슈④ 드리프트 고착 — [해소] + [잔존위험]

#### 판정: 자동 Re-ATI 부활로 [해소], 단 약터치 고착·Max Counts는 [잔존위험]

노드 07이 정확히 분석: 현 코드는 ATI Disabled(`ATI_SETUP_LSB=0x08`, `:651`) + CH timeout disable(`0xC0` MSB=0x07, `:1155`)로 **자동 Re-ATI를 이중 봉쇄**했다. 그래서 ESD/드리프트 고착을 SW 방전으로 우회했다. Full 전환(`0x36` LSB 0x08→0x0C)은 이 봉쇄를 풀어 "LTA 밴드 이탈 → 자동 Re-ATI" 경로를 되살린다. 과거 SW RESEED 3회로도 못 풀던 고착(이슈해결 §0)이 자동 재캘리로 풀리는 게 핵심 개선. **드리프트 고착 본체 [해소].**

잔존:
- **약터치 고착**: ESD가 LTA를 밴드 안에서만 밀어 약한 TOUCH로 고착되면 LTA halt(§5.5)로 추종 멈춰 자동 Re-ATI 미발동 → human-in-the-loop 의존(노드 07 §2.3). [잔존위험].
- **Max Counts 포화형**: conversion 정지라 Re-ATI도 못 풀어 MCLR 필수(노드 07 §5). 코드는 `mclr_reset()` [`:288~298`] 보유, 포화 감지 stub만 추가하면 됨. [잔존위험] (감지 stub 미구현).

> [!NOTE]
> CH timeout disable(`0xC0` MSB=0x07)은 Full 전환 후에도 **유지**가 옳다(SW 30초 타임아웃 채택·ULP 충돌 회피, 노드 03·06). 단 주석 [`:1152~1153`]이 "ATI Mode=Disabled(0x08)와 이중 방어"라 명시 — Full 전환 시 **이 주석이 거짓이 되므로 갱신 필수**(이중 방어 중 하나가 사라짐). 코드 동작엔 무해하나 문서 정합 회귀.

### 2.5 이슈⑤ Re-ATI burst — [잔존위험]

#### 판정: 쿨다운·실측 의존 [잔존위험]

노드 02·05·06·07이 공통 인지: Full 전환으로 자동 Re-ATI가 살아나면 ESD·온도 드리프트가 잦을 때 Re-ATI burst → 통신/전류 부담. 코드 정합:

- ATI burst 동안 RDY 미개방 → `force_window_open()` 45ms timeout 반복. 노드 06이 적출한 **force-window 이중 130ms(45+20+45+20)** [직전분석 §138]가 100ms 폴링을 침범.
- 노드 05의 **Threshold<Band 부등식 위반**(2.6 참조)이 Re-ATI 빈도를 직접 악화 — 이게 burst의 근본 트리거 중 하나.

방어: 노드 02 쿨다운(N초) + 노드 05 Band 100 확대(온도 5.6°C마다 Re-ATI) + 노드 03 노터치 RESEED 병행. 모두 [실측 게이트] 의존(burst 실측 시간 = 노드 06 미해결). [잔존위험] 유지.

### 2.6 추가 적출 — [신규회귀 4·5]

#### [신규회귀 4] — read 실패 시 NOT_TOUCH 미강제 (현 hold-last)

> [!CAUTION]
> **코드 ground truth**: `get_state()` [`tdc_touch.c:379~426`]는 read 실패 시 `return false`(`:386`) — 상태를 갱신하지 않는다. `process()` [`:341~373`]는 `got_state==false`면 `proc_long_touch()`를 **호출하지 않는다**(`:369` `got_state &&`). 즉 read 실패 중 **`proc_long_touch()`의 정적 `s_state_old`·`s_tick_first_touch`가 직전 TOUCH로 고정**된다 [`:80~81`].

회귀 메커니즘 (Full 전환으로 **악화**):
- 현 ATI Disabled에선 ATI burst가 거의 없어 read 실패가 드물다(통신 글리치만).
- **Full 전환 후 자동/수동 Re-ATI burst가 빈발**하면 read 실패 구간이 늘어난다. 그동안 `proc_long_touch`의 `s_tick_first_touch`가 갱신 안 된 채, ATI 종료 후 첫 TOUCH가 돌아오면 **누적 tick 차분이 그대로 이어져 stuck 롱터치(2.4초) 오발** → 의도치 않은 절전 트리거.
- 노드 01 §5.3·직전분석 보완_4가 "read 실패 중 NOT_TOUCH 명시 강제"를 경고했으나, **현 코드는 hold-last(미갱신)** 상태다. 노드 01이 "보완 필수"로 명시했어도 코드는 아직 미구현.

**선행 수정 의무**: Full 전환 시 read 실패 처리를 **(ㄱ) NOT_TOUCH 강제 주입(proc_long_touch에 NOT_TOUCH 전달) 또는 (ㄴ) N회 연속 실패 카운터로 명시 분기** 중 하나로 반드시 구현. 단 (ㄱ)은 ATI burst 중 잠깐의 NOT_TOUCH가 **진짜 롱터치를 끊을 수 있으므로**, 노드 01의 N회 카운터(ATI burst 흡수)와 결합 설계 필요. 이 둘은 상충 — 99 종합에서 "read 실패 = NOT_TOUCH로 보되, 롱터치 타이머는 N회까지 hold" 같은 조합 규칙 확정 필요.

#### [신규회귀 5] — `is_auto_ati_done`의 통신실패↔ATI진행 미구분 (부팅)

`is_auto_ati_done_single_read()` [`tdc_drv_iqs323.c:312~331`]는 read 실패(`:319`)와 0xEEEE(`:324`)를 둘 다 `false`(=ATI 미완료)로 반환한다. `try_finish_init()` [`tdc_touch.c:216~229`]가 이를 부팅 ATI 완료 판정에 쓴다.

- 현 ATI Disabled에선 auto-ATI가 짧아 타임아웃(2500ms) 전에 끝난다.
- **Full 전환 후 auto-ATI burst가 길어지면**(직전분석 ~1.5초, 단일채널은 줄 수도) 이 구분 부재가 표면화: 통신 글리치가 ATI 진행과 합산돼 타임아웃까지 강제 대기. 동작상 치명은 아니나(타임아웃 강제 진행) **부팅 시간 예측 불가**. 노드 01 §5.5·직전분석이 "3-상태 구분"을 권고한 그 지점. [잔존위험]으로 분류(먹통 아님, 시간 흔들림).

#### 노드 05 Threshold>Band 위반 — Full에서 표면화 [잔존위험]

노드 05가 정확히 적출: 현 `TOUCH_THRESHOLD=100`(`tdc_drv_iqs323.h:132`) > ATI Band 폭 50(Target 400/8). 부등식 `Threshold<Band` 위반. ATI Disabled라 미표면화됐으나 **Full 자동 Re-ATI 살아나면 터치 진입 전 밴드 이탈 → 경로_1 자동 Re-ATI가 터치 직전 발동** 위험. 노드 05 권고(Base 200→Target 800·Band 100, Threshold 50~80)로 해소 가능하나 [실측 게이트](Base 200 ATI 수렴성). Full 전환과 동시에 임계 재설정 안 하면 [신규회귀]에 준함 → **Full 전환과 임계 재설정은 원자적으로 함께** 적용 의무.

## 5. 설계 함의 (99 종합 입력)

1. **원자적 적용 의무 3쌍**: (Full 전환 ↔ 임계 재설정 노드05), (FIXED 제거 ↔ 부팅 Re-ATI 또는 READY-후 ATI_Error 처리), (방전 폐기 ↔ CH1 폐기). 어느 한쪽만 적용 시 회귀.
2. **신규 API 2종 필수**: `reseed_only()`(순수 bit3, [신규회귀 2] 차단), `re_ati_trigger` 공개화(현 static). 노드 03 "권고"를 "필수"로 격상.
3. **read 실패 처리 규칙 확정**: NOT_TOUCH 강제(stuck 방지)와 N회 카운터(ATI burst 흡수)가 상충 — "read 실패=NOT_TOUCH로 보되 롱터치 타이머는 N회까지 hold" 조합 규칙을 99에서 단일 정의.
4. **부팅 ATI_Error 처리 책임 명시**: 노드 08 "부팅 핸들러 불필요"는 노드 02 런타임 핸들러가 READY 직후 첫 노터치 tick에서 ATI_Error를 확실히 clear함이 전제 — boot_touch_ignore 가드와의 상호작용을 99에서 검증 항목으로 확정.
5. **주석·문서 정합**: CH timeout "이중 방어" 주석(`:1152`)·write_ati_compensation 블록 주석(`:625~648`)이 Full 전환 후 거짓 — 코드 변경과 함께 갱신.
6. **절전 감도 단일화**: `apply_sleep_settings()` 255 ↔ `reseed()` 100 이중 write 정리(Full FIXED 제거와 동시).
