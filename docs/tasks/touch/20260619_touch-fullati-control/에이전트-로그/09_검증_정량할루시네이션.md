# 09 검증 — 정량 할루시네이션 (adversarial)

**TL;DR**: 04(Beta IIR 수렴·약터치 흡수)·05(ATI Target/Band·온도 드리프트)·06(컨버전 1MHz·전류) 세 정량 노드를 데이터시트 01·02·03·06 원문과 1:1 대조했다. **04는 IIR 수렴표·약터치 흡수표를 독립 재계산해 소수점까지 일치 — 전 항목 [확인됨]**. **06은 1MHz 권장·전류표(NP 125/LP 37.5/ULP 4µA @3.3V)가 원문과 일치 — [확인됨], measurement 0.4ms는 노드 스스로 [추정] 라벨로 방어됨**. **05는 ATI Target/Band 공식·온도 −18cnt/°C는 [확인됨]이나, 핵심 부등식의 단위 전제에 [단위오류]가 있다** — Touch Threshold 레지스터값(100)은 raw count가 아니라 `(계수×LTA/256)`의 비율계수이고(데이터시트 A.17·현 코드 주석 확정), ATI Band(raw count)와 직접 비교한 `100>50 위반` 논증은 단위 불일치다. 결론(부등식 방향·Base 상향 권고)은 환산 후에도 유지되나 수치 근거 재서술 필요.

## 4. 05 분석 임계카운터 — 판정 혼합: 공식 [확인됨] / 핵심 부등식 [단위오류]

### 4.1 ATI Target/Base/Band 공식 — [확인됨]

- 05 §2.1: `ATI Target = Base × (Res/16)`. **대조**: [06 A.12] `ATI TARGET = ACTUAL ATI BASE × (Res/16)` **정확 [확인됨]**. Base 100·Res 64 → Target 400 재계산 일치.
- 05 §2.2: ATI Band Large(1/8)=Target/8=50, Small(1/16)=25. **대조**: [06 A.12] bit3 0=Small(1/16) 1=Large(1/8), [02 §5.10] 예시 "Target 800·1/8→100" **정확 [확인됨]**. Base 200→Target 800·Band 100 재계산 일치.
- 05 §2.3: Full 전환 0x0408→0x040C(하위 3비트 000→100), 0x040C가 reset 기본값. **대조**: [06 A.12] 기본값 0x040C=Res 64·Band Large·Mode Full(100) **정확 [확인됨]**.

> [!NOTE]
> 미세 표현 차: [02 §5.9] 본문은 `ATI Target = (divider·multiplier 적용 후 Counts) × (Res/16)`(중간 단계)인데 05는 [06 A.12]의 `ACTUAL ATI BASE × (Res/16)`을 썼다. A.12가 최종 정의이므로 **05 인용이 맞음** — 과실 아님.

### 4.2 온도 드리프트 −18cnt/°C — [확인됨]

- 05 §4.1: −18cnt/°C(센서), 1000cnt 기준 예시. **대조**: [적용가이드 §4.1 = AZD125 §8.2.4] 센서 1000→550 over 25°C. 재계산 (1000−550)/25=**18.0 cnt/°C** 정확 **[확인됨]**. 레퍼런스 −12도 (700−400)/25=12.0 일치. Band 50/18=2.78°C, Band 100/18=5.56°C 재계산 일치 **[확인됨]**. "1000cnt 예시라 Target 800 환산·실측 필요"는 05 §4.1·§7 [실측 게이트]로 정직 처리.

### 4.3 SNR≥5 raw 20cnt — [확인됨]

- 05 §5.1: SNR≥5 → raw 20cnt(노이즈밴드 4cnt). **대조**: [적용가이드 §4.4 = AZD125 §10.1] 임계(터치) ≥5 → 20cnt(전형 25cnt) **정확 [확인됨]**. "노이즈 4cnt는 EV-Kit 가정, 실측" 보류 정직.

### 4.4 핵심 부등식 `Touch Threshold < ATI Band 폭` — [단위오류] (급소)

> [!CAUTION]
> **05 노드 §1.1·§3의 단위 전제가 틀렸다.** 05는 "Touch Threshold·ATI Band·ATI Target·LTA·Counts는 전부 raw count 단위 동일 축"이라 단정하고, 현 Threshold **레지스터값 100을 raw count**로 취급해 "100 > Band 50 → 2배 위반"이라 논증했다. 그러나:
>
> - **[06 A.17] 원문**: `Touch Threshold = (Threshold × LTA) / 256`. 즉 레지스터에 기록하는 8비트 값(Threshold)은 raw count가 아니라 **LTA에 곱해지는 비율계수**이고, IC 내부 절대 판정 임계는 `(계수 × LTA)/256` raw count다.
> - **[현 코드 tdc_drv_iqs323.h:391 주석]**: "self-cap 터치 조건 `(LTA−Counts) > Touch Threshold(절대=계수×LTA/256)`". `read_touch_margin`(c:1224)도 `current=(LTA−Counts)×256/LTA`로 **계수 단위로 역환산**해 비교 → 레지스터 100은 계수임이 코드로 확정.
> - **[적용가이드 §4.4 NOTE]**: "현 펌웨어 Touch Threshold는 raw counts 차이가 아닌 LTA 대비 비율 계수(`delta×256/LTA`)로 동작" — 05의 단위 동일 축 단정과 정면 충돌.
>
> **수치 영향**: 계수 100·LTA 400(현 Target)이면 절대 임계 = 100×400/256 = **156.25 raw cnt**(05가 말한 100도, 50도 아님). 따라서 "Threshold 100 vs Band 50을 raw count로 직접 비교"는 **차원이 다른 두 양의 비교 = [단위오류]**.

**올바른 부등식 재유도**(검증자):

```
절대 임계 < Band 폭
(계수 × LTA)/256  <  Target/8
LTA ≈ Target(노터치 정상) 가정:
(계수 × Target)/256  <  Target/8
계수  <  256/8 = 32
```

즉 raw count 단위로 일관되게 환산하면 **부등식은 "Touch Threshold 계수 < 32"** 가 된다. 현 계수 100은 32의 약 3.1배 초과 → **위반은 사실이나 "2배"가 아니라 "약 3.1배"**, 근거 수치(50·100 raw 비교)가 틀렸다.

> [!IMPORTANT]
> **결론 방향은 살아남는다**: 부등식 위반(터치보다 Re-ATI 먼저)·Base 상향으로 Band 확대·Threshold 하향 권고는 환산 후에도 유효하다. 단 05 §3.2 표("Threshold 100 > Band 50, 2배")와 §6.1 권고표("Touch Threshold 50~80 < Band 100")의 **수치 비교는 계수↔raw 환산을 거쳐 재서술**해야 한다. 권고 계수 50~80도 환산하면 절대 임계 50×800/256≈156 ~ 80×800/256≈250 raw cnt(LTA=Target 800 가정)이고 Band 100과 비교하면 **여전히 절대 임계 > Band** → 05의 raw 권고값(50~80 계수)으로도 부등식이 안 풀린다. **계수를 32 미만(LTA≈Target 기준)으로 낮춰야 부등식 성립** — 05 권고값 자체의 재계산 필요.

### 4.5 Hysteresis 단위 — [단위오류] 연쇄

- 05 §6.4: `(LTA−Counts) > (Threshold − Hysteresis)`, "Hysteresis < Threshold 필수". **대조**: [06 A.17] `Touch Hysteresis = (Touch Hysteresis/256) × Touch Threshold`. Hysteresis도 **Threshold에 곱해지는 비율(4비트 상위필드)**이지 raw count 차감값이 아니다. 05의 "Hysteresis 80 < Threshold 100 차감"식 단순 비교는 [02 §5.7] 판정식과 [06 A.17] 정의가 다른 레이어임을 놓침 → **[단위오류] 연쇄**. 단 "Hysteresis가 과대하면 이탈 임계 붕괴" 정성 방향은 맞음.

> [!NOTE]
> 데이터시트 [06 A.17]은 Hysteresis 필드를 bits15-12(4비트), Threshold를 bits7-0(8비트)로 둔다. 현 코드(tdc_drv_iqs323.h:256·128~133)는 둘 다 8비트 매크로(80·100)로 다루는데, 이는 별도 [실측 게이트] 대상(레지스터 비트폭 vs 코드 매크로 정합) — 05·노드10·종합에서 교차 확인 필요.

## 6. 설계 함의·후속 (검증자 권고)

1. **05 노드 부등식·권고표 재계산 필수**(종합 노드 반영): raw count 단위 일관 시 부등식은 `Touch Threshold 계수 < 256/8 = 32`(LTA≈Target 기준). 현 계수 100·05 권고 50~80 모두 32 초과 → **권고 계수를 32 미만으로 하향**하거나, Band를 Target 상향으로 키워 `계수 < 256/(8×Band배수)` 충족시켜야 함. Base 상향(Target 800) 권고는 Band를 키우지만 Threshold 계수 분모(LTA)도 같이 커져 **계수 기준 부등식은 Base 상향과 무관**(LTA·Target 비례 소거) → Base 상향만으로는 부등식 미해결, **계수 하향이 본질**.
2. **단위 통일 게이트**: 종합 설계에서 "Touch Threshold(계수) vs ATI Band(raw)" 비교 시 반드시 `계수×LTA/256`으로 환산 후 비교하는 static_assert/부팅 검증을 명세. 05 §8의 static_assert 권고는 단위 환산을 포함해 재작성.
3. **04·06은 그대로 채택 가능** — 정량 근거 견고. 04 Beta 레지스터 정수(해석_A/B)·06 measurement 시간은 [실측 게이트]로 이월.
4. **레지스터 비트폭 정합**[실측 게이트]: A.17 Hysteresis 4비트 vs 현 코드 8비트 매크로 — 노드10(회귀)·종합에서 코드 비트필드(tdc_drv_iqs323.h:256) 실제 정의 교차 확인.
