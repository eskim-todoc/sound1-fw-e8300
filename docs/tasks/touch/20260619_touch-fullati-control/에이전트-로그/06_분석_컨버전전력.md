# 06 분석 — 컨버전 주파수·전력 모드 (정량)

**TL;DR**: 컨버전 1MHz(Period=5, self-cap 권장 상한)는 유지가 정답. 1 measurement burst는 µs~ms 단위라 100ms 폴링 주기에 충분히 정합(측정 완료 후 RDY 개방). 전력 모드는 **`Automatic No ULP` 권고** — Channel Timeout을 안 쓰므로 ULP 자체는 가능하나, ULP 단일채널 wake-up 구조가 CRX0 단일 버튼 구성에 이점이 없고 Re-ATI/force-window 폴링과 충돌 위험이 있어 **LP 유지가 목표**에 더 부합. report rate는 NP=무설정(빠름)·LP≈100ms·ULP 미사용 권고. 전류는 self-cap 단일채널 기준 NP 수십~125µA / LP 수십µA 추정.

## 2. 현 코드 사실관계 (출발점)

현 펌웨어는 컨버전 주파수·전력 모드·report rate를 **명시적으로 write하지 않는다** — 전부 IC POR(reset) 기본값에 의존한다.

| 항목 | 레지스터 | 현 코드 | 실효값(POR 기본값) |
|---|---|---|---|
| 컨버전 주파수 | `0x31` Conversion Frequency Setup | write 없음 | `0x057F` = Period **5** = **f_xfer 1.00 MHz** [06 §A.6] |
| Auto Prox Cycle | `0x33` Prox Input and Control | write 없음 | `0x01CF` = **32** conversion/interrupt [06 §A.9] |
| 전력 모드 | `0xC0` System Control bit6:4 Power Mode | write 없음(`0xC0`은 Reseed·CH Timeout만 write) | `000` = **Normal Power 고정** [06 §A.30] |
| Report Rate NP/LP/ULP/Halt | `0xC1`~`0xC4` | write 없음 | 전부 `0x0000` [06 §9] |
| Power Mode Timeout | `0xC5` | write 없음 | `0x0000` → 모드 강하 안 함 [06 §A.30, 02 §5.3] |

> [!IMPORTANT]
> 즉 현 IC는 `Power Mode=000(Normal)` + `Power Mode Timeout=0`이라 **항상 NP 고정**이며 자동 전력 강하가 일어나지 않는다. FullATI 단순안에서 전력을 다루려면 `0xC0` bit6:4(Power Mode)와 `0xC1`~`0xC5`를 **신규 write**해야 한다. (Sound1의 "절전"은 IC ULP가 아니라 CM3 SYSCLK 강하 + RESEED + 200ms 폴링 유지 방식 — 적용가이드 §6, main.c:944~952)

## 3. ATI burst·1 measurement 소요시간 추정 (정량)

### 3.1 공식·가정

- **f_OSC = 14 MHz** (고정) [01 §4.3]
- **f_xfer = 1.00 MHz** (Period=5, Fraction=127, Dead Time enabled) [06 §A.6 Table A.1]
- 1 charge-transfer 사이클 = 1 / f_xfer = **1 / 1MHz = 1 µs** [추정 — 1 사이클 = 1 전하전달 주기 가정]
- 1 measurement(conversion) = LTA/ATI Target counts 도달까지 필요한 전하전달 사이클 수 [02 §5.4]
  - ATI Target ≈ 400 cnt (Base 100 × Resolution 64/16) [02 §5.9 예시, 자료 미명시 — 보드별 실측]

### 3.2 1 measurement 시간

```
1 measurement 시간 ≈ (도달 counts 수) × (1 사이클 시간)
                  ≈ 400 cnt × 1 µs
                  ≈ 400 µs ≈ 0.4 ms          [추정]
```

- 단, 실제 conversion은 settling·dead time·내부 오버헤드가 더해진다 → 0.4ms는 **하한 추정**. 실측 시 수 ms 이내로 예상.
- **Auto Prox Cycle = 32** [06 §A.9] → Auto Mode에서 인터럽트당 32 conversion 묶음 실행. NP 한 report 주기에 묶음 단위로 측정.

> [!NOTE]
> 데이터시트는 "1 conversion = N 사이클"의 N을 명시하지 않는다 [자료 미명시]. counts ≈ N이라는 §5.4 정의(전달 횟수 = counts)를 근거로 ATI Target ≈ counts ≈ 사이클 수로 추정했다.

### 3.3 ATI burst(Full ATI 1회 수렴) 소요시간

ATI는 MULT(거친) → COMP(정밀) 2단계를 채널별로 수렴시키며, 단계마다 여러 measurement를 반복한다 [02 §5.9].

- **직접 근거(실측)**: 직전분석 — "POR auto-ATI ~1.5초가 100ms 기준 약 15회 연속" [20260618 분석 §107·§04노드] [실측 게이트]
- 즉 **부팅 시 IC 전체 auto-ATI burst ≈ 1.5초** (3채널 스캔 + 양산 편차 수렴 포함 worst-case로 추정)
- 단일채널(CRX0만 enable) + Full ATI 런타임 **Re-ATI 1회**는 채널 1개라 이보다 짧을 것으로 추정 — **수백 ms ~ 1초 범위** [추정, 실측 게이트]

> [!IMPORTANT]
> ATI 진행 중에는 **I²C가 disabled** → RDY window 미개방 → 폴링 read가 false 반환 [20260618 §104, DS §8.4]. 이것이 과거 "Full ATI I²C 무응답"의 정체다(01·02 노드 영역). 본 노드는 **타이밍 정합 관점**만 다룬다: ATI burst(수백ms~1.5초) 동안 100ms 폴링은 수 회 연속 실패하므로, **N회 연속 실패를 즉시 고장 판정하면 정상 ATI를 오판**한다(직전분석 "burst 시간상관 함정" §107). FullATI 단순안의 폴링 로직은 ATI_Active(0x10 bit5) 폴링으로 "ATI 진행 중"을 구분해야 한다(01·02 노드 결론에 위임).

## 4. 100ms 폴링 정합 (측정 완료 후 RDY)

### 4.1 현 폴링 주기

- 현 코드 `TDC_TOUCH_POLL_INTERVAL = 200` ms (touch.h:25) — 주석 "100ms"는 오기(직전분석 §68)
- 단순안 목표는 **100ms 폴링** (요구사항_9)

### 4.2 정합 분석

| 항목 | 값 | 정합 판정 |
|---|---|---|
| NP 1 measurement | ≈ 0.4ms ~ 수 ms [추정] | 100ms ≫ 측정시간 → **여유 충분** |
| RDY window 개방 t_Low | ≈ 0.5ms (정상) [20260618 §139·§146] | 측정 완료 후 RDY 개방, 100ms 주기 내 충분히 read 가능 |
| force window 이중 비용 | 최악 130ms (45+20+45+20) [20260618 §138·§145] | **위험 지점**: 폴링 100ms < 130ms면 force가 폴링 주기를 초과할 수 있음 |
| ATI burst | 수백ms~1.5초 | 100ms를 초과 → 그 동안 폴링 실패(정상) → ATI_Active로 구분 필요 |

> [!WARNING]
> **force window 이중 개방 최악 130ms > 폴링 100ms.** 스트리밍 모드 + 폴링 주기 불일치가 원인(직전분석 §138). 측정 자체(수 ms)는 100ms에 무난히 정합하나, **force-window 비용이 폴링 주기를 침범**할 수 있다. 근본 해소는 Event Mode 전환(force 비용 0)이나 단기 우선순위 낮음(적용가이드 §7). FullATI 단순안에서는 폴링 read가 130ms까지 늘어날 수 있음을 main loop tick 기반 카운트(03 노드)에서 감안해야 한다.

**결론(정합)**: 1 measurement(수 ms)와 100ms 폴링은 **정합한다**(측정 완료 후 RDY 개방, 9.6:1 이상 여유). 단 ATI burst 구간과 force-window 비용 130ms는 폴링 주기를 일시 초과하므로 ATI_Active 구분 + tick 기반 시간 카운트로 흡수.

## 5. 전력 모드 — Automatic vs Automatic No ULP vs auto ULP

### 5.1 모드 정의 [02 §5.3, 06 §A.30]

| Power Mode 값 | 의미 |
|---|---|
| `000` Normal | NP 고정 |
| `001` Low / `010` Ultra Low / `011` Halt | 수동 고정 |
| `100` Automatic | Timeout 경과 시 NP→LP→ULP 단계 강하, 이벤트 시 NP 복귀 |
| `101` Automatic No ULP | Automatic과 동일하나 **ULP 절대 진입 안 함** (NP↔LP만) |

### 5.2 auto ULP 가능 여부

> **질문: auto ULP 가능한가? (단 완전 저전력 진입 불가 — LP 유지가 목표)**

- **가능(제약 관점)**: FullATI 단순안은 **IC Channel Timeout을 미사용**한다(설계 방향 §1 — IC 타임아웃 기각, SW 30초 카운트로 대체). 따라서 "Channel Timeout 사용 시 ULP 금지" [02 §5.8 WARNING] **제약이 적용되지 않으므로** 순수 레지스터 관점에서 `Automatic`(ULP 포함)을 쓸 수 있다.
- **그러나 권고하지 않음(LP 유지가 목표)**. 근거 3가지:
  1. **ULP 구조 = 단일 wake-up 채널 고속 + 나머지 저속** [02 §5.2]. Sound1은 **CRX0 단일 채널**(07 노드)이라 "wake-up 채널 1 + 보조 채널들"의 ULP 계층 구조에서 얻을 이점이 없다 — 단일 채널이 곧 wake-up 채널이며 분산 감시 대상이 없다.
  2. **ULP 진입 시 report rate가 160ms로 길어짐** [01 §3.4 표]. 100ms 폴링·force-window 폴링이 ULP의 긴 conversion 주기와 어긋나 RDY window 포착이 더 불안정해진다(force 비용 증가).
  3. **Re-ATI/force-window 폴링 충돌**: 직전 작업 결정에서 "IC Channel Timeout은 ULP 충돌"로 기각된 맥락(설계 방향 §1, 20260618 §6)과 일관되게, 능동 폴링 기반 제어에서 ULP의 deep-sleep성 단일채널 모드는 통신 윈도우 관리를 어렵게 한다.

> [!IMPORTANT]
> **"완전 저전력(ULP/Halt) 진입 불가, LP 유지가 목표"** — 이 목표에 가장 부합하는 설정은 **`Automatic No ULP`(101)**다. NP↔LP만 오가며 ULP/Halt로는 절대 내려가지 않으므로, 통신 윈도우(RDY)가 LP report rate 주기로 안정적으로 열리고 force-window 폴링이 예측 가능하다.

### 5.3 권고: Automatic No ULP

| 비교 | Automatic (100) | **Automatic No ULP (101)** ✅ |
|---|---|---|
| ULP 진입 | 가능(160ms report) | **차단** |
| 통신 윈도우 안정성 | ULP 긴 주기로 불안정 | LP 100ms 주기로 안정 |
| 단일채널 이점 | 없음(분산 감시 무의미) | — |
| LP 유지 목표 정합 | 부분(ULP까지 내려감) | **완전 정합** |
| 이벤트 시 NP 복귀 | 동일 | 동일 |

## 6. 전류 추정 (정량) [01 §3.4 Current Consumption]

### 6.1 데이터시트 측정 조건 주의

데이터시트 표는 **Self-cap 3채널** 기준이며, 측정 조건은 ATI Target=512 / Fxfer=500kHz / **Event mode** [01 §3.4]. Sound1은 **단일채널(CRX0)** + Fxfer=1MHz + 스트리밍이라 절댓값은 다르다 [추정]. 단일채널이면 conversion 부담이 3채널보다 작아 **표값보다 낮을 것**으로 추정.

### 6.2 표값 (Self-capacitive 3ch, @3.3V) [01 §3.4]

| Power mode | Report rate [ms] | 전류 @3.3V [µA] |
|---|---|---|
| **Normal Power** | 16 | **125** |
| **Low Power** | 60 | **37.5** |
| **Ultra Low Power** | 160 | 4.00 |
| Halt | 3000 | 2.00 |

### 6.3 Sound1 추정 (단일채널·Automatic No ULP)

```
NP 구간 (이벤트 직후·터치 중):
  3ch 125µA @report 16ms 기준 → 단일채널·report 100ms면 duty 낮아 더 작음
  추정 ≈ 수십 µA ~ 125µA (worst NP)            [추정]

LP 구간 (Timeout 경과 후, 평상시 노터치 LP 유지):
  3ch 37.5µA @60ms 기준 → 단일채널·report ~100ms면
  추정 ≈ 10~37µA                                [추정]

ULP 미사용 → 4µA 구간은 도달하지 않음 (LP 유지가 목표이므로 의도된 trade-off)
```

> [!NOTE]
> "LP 유지가 목표"이므로 ULP의 4µA를 포기하는 대가로 **LP의 수십µA에서 통신 안정성을 확보**한다. Sound1 실제 평균 전류는 NP/LP 체류 비율(Power Mode Timeout 설정)에 좌우되며 **실측 필요** [실측 게이트].

## 7. 권고 설정 (정량 결론)

### 7.1 컨버전 주파수

| 항목 | 권고 | 근거 |
|---|---|---|
| f_xfer | **1.00 MHz 유지** (Period=5, `0x31`=`0x057F`) | self-cap 권장 상한 = 1MHz [06 §A.6 note]. 현 POR 기본값과 동일 → **명시 write 불요하나 방어적 write 권장** |
| Fraction | 127 고정 | 지터 최소 [03 §6.5] |

> Full ATI에서 conversion frequency > 2MHz면 Compensation 최소화 제약 [02 §5.9]이 걸리나, 1MHz는 2MHz 미만이라 **해당 제약 없음** → Full ATI와 1MHz는 양립.

### 7.2 전력 모드·Report Rate (신규 write 필요)

| 레지스터 | 권고값 | 근거 |
|---|---|---|
| `0xC0` Power Mode (bit6:4) | **`101` Automatic No ULP** | LP 유지 목표·단일채널·통신 안정 (§5.3) |
| `0xC1` NP Report Rate | 작게(예: 10~20ms) 또는 0(기본 빠름) | 이벤트 직후 고속 응답 |
| `0xC2` LP Report Rate | **≈100ms** | 100ms 폴링과 정합(§4) |
| `0xC3` ULP Report Rate | 미사용(write 불요) | ULP 진입 안 함 |
| `0xC5` Power Mode Timeout | **>0** (예: 수 초) | 0이면 강하 안 함 → LP 진입 위해 필수 set [02 §5.3] |

> [!IMPORTANT]
> 현 코드는 `0xC0` bit6:4·`0xC1~C5`를 전혀 write하지 않아 **NP 고정**이다. FullATI 단순안에서 LP를 활용하려면 **`Power Mode=101` + `Power Mode Timeout>0` + `LP Report Rate≈100ms`를 init 시퀀스에 신규 추가**해야 한다. 이 write가 없으면 "LP 유지가 목표"는 달성 불가(NP 고정).

### 7.3 정합 요약

- 1 measurement(수 ms) ↔ 100ms 폴링: **정합** (여유 ≥9.6:1)
- ATI burst(수백ms~1.5초): 100ms 초과 → ATI_Active 폴링으로 구분(01·02 노드)
- force-window 130ms: 폴링 100ms 초과 가능 → tick 기반 카운트로 흡수(03 노드), 근본 해소는 Event Mode

## 9. 설계 함의 (구현)

1. **레지스터 신규 write 3종**: `0xC0`(Power Mode=101) + `0xC5`(Power Mode Timeout>0) + `0xC2`(LP Report≈100ms). 현 코드 미존재 → init 시퀀스 추가.
2. **컨버전 1MHz는 방어적 write 권장**(`0x31`=`0x057F`) — POR 기본값과 동일하나 명시로 의존성 제거.
3. **ULP/Halt 미사용** — `Automatic No ULP` 선택으로 IC가 ULP로 못 내려가게 차단(LP 유지 목표).
4. **폴링 100ms는 measurement에 정합**하나 ATI burst·force-window 구간은 시간 카운트(tick) 기반으로 흡수 — 즉시 고장 판정 금지(01·03 노드 연계).
5. Sound1 "절전"(CM3 SYSCLK 강하)과 IC Power Mode(Automatic No ULP)는 **별개 레이어** — 혼동 금지(03 노드 영역).
