# Full ATI 터치 제어 — 구현 계획

**TL;DR**: 분석 종합(99)의 설계를 **Phase P0~P6 빌드가드 단계**로 구현한다. 회귀 차단 인프라(P0)를 먼저 깔고, 단일채널 폐기(P1) → **Full ATI 전환을 임계 계수 하향과 원자적으로**(P2) → Re-ATI 게이트(P3) → Beta·Power(P4) → SW 타임아웃(P5) → 게이트·절전 정리(P6) 순. 실측 의존 14항목은 **안전 기본값 + RTT 로깅으로 구현 후 은수님 실측 조정** 방식. 각 Phase 독립 빌드가드로 단계 롤백·실측 비교 가능. 코드 변경은 본 계획 승인 후 단계 ④.

---

## 1. 구현 전략

- **빌드가드 단계화**: 각 Phase를 독립 `#define` 가드로 묶어 단계별 on/off·롤백·실측 비교. P2(Full 전환)는 부분 적용 회귀를 막기 위해 **원자적 단일 가드**.
- **회귀 우선**: 검증 10이 적출한 [신규회귀 5건]을 P0에서 선차단(API·상태구분·NOT_TOUCH 규칙). 본체 전환은 그 위에.
- **실측 루프**: 실측 의존 값은 안전 기본값으로 빌드 → 은수님 빌드·플래시·RTT 로깅 → 값 확정·조정. 구현이 실측을 막지 않도록 기본값은 보수적 안전측.

## 2. Phase 상세

| Phase | 목표 | 주요 변경 | 빌드가드 | 검증·실측 |
|---|---|---|---|---|
| **P0 안전망·API 선행** | 회귀 차단 인프라 | `reseed_only()` 신설(순수 0xC0 bit3), `re_ati_trigger` 헤더 공개화, read 실패 NOT_TOUCH+N회 hold 규칙, `is_auto_ati_done` 3-상태(통신실패/ATI진행/ATI_Error) | — (기존 동작 무영향) | 단위: API 시그니처·기존 흐름 무변경 |
| **P1 단일채널 폐기** | CRX1·방전 제거 | `CRX1_DUMMY_ENABLE=0`(0x40/0x44/0x70 reset), `CRX0_DISCHARGE_ENABLE=0`(0x30 방전 토글 제거), 0x43 미수정 유지 | `TDC_TOUCH_CRX1_DUMMY_ENABLE`·`TDC_TOUCH_CRX0_DISCHARGE_ENABLE` | 정지 이슈 미발생, CH0 단독 동작 |
| **P2 Full ATI 전환 (원자적)** | ATI Mode + 임계 동시 | 0x36 `0x0408→0x040C`(3변종 매크로 전부), FIXED MULT/COMP(0x38·0x39) write 폐기, **임계 계수 100→16(32 미만)**, 부팅 Re-ATI 1회 또는 READY-후 ATI_Error clear 보장, `(void)ati_error` 제거 | `TDC_TOUCH_FULL_ATI_ENABLE` (단일 묶음) | **실측: t_ati, 부팅 ATI_Error clear, 계수↔raw LTA** |
| **P3 Re-ATI 게이트 (급소)** | 터치 중 보류 | `tdc_touch_should_re_ati()`(노터치 AND ATI Active==0 AND 쿨다운), 터치 판정 선분기, 자동 Re-ATI는 LTA halt 위임 | — | 터치 중 Re-ATI 미발행 확인 |
| **P4 Beta·Power write** | 필터·전력 | Beta 4종(0xB0/B1/B2/B4) write, Power(0xC0 Automatic No ULP·0xC2 LP Rate·0xC5 Timeout), 0x31 방어 write | `TDC_TOUCH_BETA_INTERP`(해석 A/B 분기) | **실측: Beta 해석 판별(수렴 step), 전류** |
| **P5 SW 타임아웃 30초** | stuck 에스컬레이션 | `proc_stuck_timeout()` 노말 tick 차분 + ULP 웨이크업 카운트(150), 3단계(reseed_only→Re-ATI→MCLR) | `TDC_TOUCH_STUCK_TIMEOUT_MS=30000` | 30초 후 단계 동작, **절전 2.2초 충돌 결정** |
| **P6 게이트·절전 정리** | 미사용 게이트·감도 단일화 | `tdc_touch_is_gated()`(연결·충전·뚜껑), 절전 감도 이중 write 정리, Max Counts 포화 MCLR stub | `TDC_TOUCH_GATE_ENABLE` | 게이트 중 액션 차단·센서 유지 |

## 4. 실측 게이트 처리 전략

> 99 §6의 14항목. 구현은 안전 기본값으로 진행, 실측으로 확정.

| 구분 | 항목 | 구현 기본값 | 확정 방법 |
|---|---|---|---|
| **코드 확정** | Hysteresis 비트폭, Beta 해석 A/B | 코드 정의 확인 후 매크로 | P0/P4서 코드 검증 |
| **실측 필수** | t_ati(N 산정), 계수↔raw LTA, Re-ATI burst, 전류, ESD 복구, 온도 | N=10/N_boot=20, 계수 16, Band 100 | RTT 로깅 → 은수님 측정 |
| **설계 결정** | 절전 30초 vs ULP 2.2초 충돌 | (승인 항목) | §7 질의 |

- **RTT 로깅 훅**: t_ati(ati_active 폴링 횟수), LTA 실측값, Re-ATI 발동·소요, 수렴 step을 RTT로 출력해 은수님이 1회 측정으로 값 확정.

## 5. 검증 계획 (단계 ④-검증)

- 서브에이전트 fan-out 병렬: ① 빌드(컴파일) 가능성, ② 회귀(신규회귀 5건 차단 확인), ③ 원자적 3쌍·신규 API 정합, ④ 레지스터 값·시퀀스 데이터시트 정합, ⑤ 빌드가드 on/off 독립성.
- 전수 PASS까지 루프(상한 3회). 실측 의존 항목은 "코드 정합"까지 검증, 동작 확정은 은수님 실기.

## 6. 리스크·롤백

- 각 Phase 독립 빌드가드 → 문제 Phase만 off로 롤백.
- P2 원자적 묶음이 가장 위험(Full+임계+부팅 Re-ATI 동시) → 단독 가드로 일괄 on/off, 실측 비교.
- 빌드·플래시·실기 동작은 은수님 환경 필수(본 작업은 코드+코드정합 검증까지).
