## 1. LTA (0x14) · Filtered Counts (0x13) — IC 실시간 산출 (read-only)

### 1.1 Counts (0x13)

- **출처**: IC 내부 충전전달(charge-transfer) 엔진이 매 sampling마다 자동 산출. 코드 write 없음 (read-only).
- **물리적 의미**: `Counts ∝ 1/C` — 정전용량이 클수록 counts 감소 (DS §5.4).
- **self-cap 방향**: 터치 시 C_total = C_parasitic + C_finger 증가 → counts 감소 → Delta(= LTA − Counts) 증가.
- **Max Counts 상한**: 0x32 bits[7:6] = 10(기본값) → 최대 4095 (DS A.7).
- **레지스터 정의**: 0x13 = Channel 0 Filtered Counts, 16-bit read-only (DS §9 메모리맵).

### 1.2 LTA (0x14)

- **출처**: IC 내부 IIR(지수이동평균) 필터가 매 IC 측정마다 자동 갱신. read-only.
- **계산식** (DS §5.5 · §5.6 원문 인용):

  ```
  Damping factor = Beta / 256
  LTA_new = LTA_old + (Counts − LTA_old) × (Beta / 256)
  ```

- **동결 조건**: touch 또는 proximity 이벤트 중 LTA 갱신 완전 중단 (DS §5.5 원문: "frozen during touch and proximity events").
- **Beta 종류 구분**:

  | Beta | 레지스터 | 적용 시점 |
  |---|---|---|
  | Counts Beta | 0xB0 (DS A.26) | 각 IC 측정의 raw counts 평활화 → Filtered Counts 산출 |
  | LTA Normal Beta | 0xB1 (DS A.27) | 통상 구간 LTA 환경 드리프트 추적 |
  | LTA Fast Beta | 0xB2 (DS A.28) | Fast Filter Band 조건 만족 시 LTA 급속 복귀 |

- **Fast Filter Band 발동 조건** (DS §5.6 원문):
  > "When counts have drifted from the LTA in the **sensing direction opposite to the normal sensing direction** … by more than the Fast Filter Band, fast filtering is applied."

  self-cap 기준: normal sensing direction = counts 감소(터치 방향). 반대 방향 = counts > LTA.
  즉 `Counts > LTA + Fast Filter Band` 일 때 LTA Fast Beta 적용. (감소 방향인 D>0 구간에서는 Normal Beta만 작동.)

### 1.3 Reseed

- `System Control` bit3 set → 현재 Counts 값을 LTA에 즉시 기록하여 재동기화 (DS §5.5.1).
- 코드: `write_register(REG_SYSTEM_CONTROL, 0x58, 0x07)` (.c:445, .c:463)
  - LSB 0x58 = RESEED(bit3) + Power No ULP(bits[6:4]=101). MSB 0x07 = CH0~2 timeout disable.

## 2. ATI Target · ATI Band · Compensation · Multiplier — Full ATI IC 자동 산출

### 2.1 ATI Mode 설정

코드 write (.c:429):
```c
write_register(REG_SENSOR0_ATI_SETUP, 0x0C, 0x04);
/* 16-bit(little-endian): MSB=0x04, LSB=0x0C → 0x040C */
```

DS A.12 비트 분해 (0x040C = 0000_0100_0000_1100):

| 비트 범위 | 필드 | 0x040C 적용 값 |
|---|---|---|
| [15:4] | ATI Resolution Factor | 0000_0100_0000 = **64** |
| [3] | ATI Band | 1 = **Large** (= 1/8 × ATI Target) |
| [2:0] | ATI Mode | 100 = **Full** |

### 2.2 ATI Target 계산

DS §5.9 공식:
```
ATI Target = ATI Base × (ATI Resolution Factor / 16)
           = 100 × (64 / 16)
           = 400 counts
```

- **ATI Base 출처**: 레지스터 0x37 기본값 = 0x0064 = **100** (DS §9 메모리맵).
  코드에서 0x37을 write하지 않음 → **IC 기본값 그대로 사용** (의도적).
- **ATI Resolution Factor = 64**: 코드 write (0x36 bits[15:4], .c:429).
- **ATI Target ≈ 400 counts**: Full ATI 완료 후 IC가 MULT/COMP를 자동 선택해 noTouch Counts ≈ 400에 수렴.

### 2.3 ATI Band

DS §5.10 · A.12:
```
Large ATI Band = 1/8 × ATI Target = 1/8 × 400 = 50 counts
Re-ATI Boundary = 400 ± 50 = [350, 450] counts
```

- **비교 대상**: Counts(또는 Delta)가 아닌 **LTA**.
  DS §5.10 원문: "re-ATI is triggered when the channel's **LTA** drifts outside of the ATI Band".
- Auto Re-ATI 발동: `LTA > 450` 또는 `LTA < 350` 시 IC가 자동 Re-ATI 실행.

### 2.4 Compensation · Multiplier — IC 자동 산출 (Full ATI)

ATI Mode = Full이므로 코드에서 MULT(0x38)·COMP(0x39)를 write하지 않음. IC가 2단계로 자동 선택:

1. **MULT 단계** (Coarse/Fine Fractional Divider·Multiplier): Counts → ATI Base(100) 근접 (거친 보정).
2. **COMP 단계** (Compensation Value·Divider): Counts → ATI Target(400) 근접 (정밀 보정, DS §5.9).

코드 주석 (.c:11): "MULT/COMP write 폐기(IC 자동 산출)". Full ATI 전환 이후 IC 자동 처리.

### 2.5 ATI Error 및 Re-ATI 경로

- **ATI Error** (DS §5.11): ATI 알고리즘 완료 직후 Counts가 Re-ATI Boundary [350,450] 밖이면 set.
  **자동 복구 없음** — 마스터가 Re-ATI bit 수동 set 필요.
- **SW 게이트**: `tdc_touch_logic_step()` 내 `ati_error=1` 조건으로 Re-ATI 트리거.

### 2.6 부팅 시 ATI 완료 시퀀스 (.c:436~448)

```c
write_register(REG_SYSTEM_CONTROL, 0x54, 0x07);  /* bit2 Re-ATI 트리거 */
wait_ati_done_blocking();                          /* ati_active==0 폴링 (≤1.25s) */
write_register(REG_SYSTEM_CONTROL, 0x58, 0x07);  /* RESEED: LTA ← Counts ≈ 400 */
```

ATI 완료 시점: IC가 MULT/COMP 자동 선택 → Counts ≈ 400. 뒤따른 RESEED로 LTA ≈ 400 동기화.

## 3. Beta (Counts / LTA Normal / LTA Fast) — 코드 설정값

### 3.1 현재 코드 설정 (.c:304~307)

```c
write_register(REG_BETA_COUNTS,      0x02, 0x02); /* 0xB0: Counts Beta NP=2, LP=2 */
write_register(REG_BETA_LTA_NORMAL,  0x06, 0x06); /* 0xB1: LTA Normal Beta NP=6, LP=6 */
write_register(REG_BETA_LTA_FAST,    0x02, 0x02); /* 0xB2: LTA Fast Beta NP=2, LP=2 */
write_register(REG_FAST_FILTER_BAND, 0x0A, 0x00); /* 0xB4: Fast Filter Band = 10 counts */
```

DS A.26~A.28 레지스터 구조: LSB = NP(Normal Power) Beta, MSB = LP(Low Power) Beta.

### 3.2 Beta 역할 분리

| Beta | 레지스터 | 역할 |
|---|---|---|
| Counts Beta = 2 | 0xB0 | 각 IC 측정의 raw counts 평활화 → Filtered Counts 산출. 노이즈 억제. |
| LTA Normal Beta = 6 | 0xB1 | 통상 구간 LTA 환경 드리프트 추적. Prox 미진입 시 이것만 작동. |
| LTA Fast Beta = 2 | 0xB2 | `Counts > LTA + Band(10)` 조건 시 LTA 급속 복귀. Fast Beta < Normal Beta이므로 더 느린 추적. |
| Fast Filter Band = 10 | 0xB4 | Fast Beta 전환 임계(counts). self-cap에서 `Counts > LTA + 10` 일 때 발동. |

### 3.3 Beta 정수값 해석 — 두 공식 비교

DS §5.6 원문: `Damping factor = Beta / 256`
코드 주석 (.c:305): `AZD004 α=1/2^β`

두 해석 수치 비교 (Beta=6, 단일 IC 측정 주기 기준):

| 해석 | 공식 | alpha (Beta=6) | τ (IC 측정 주기 = 200ms 가정) |
|---|---|---|---|
| DS §5.6 | Beta/256 | 6/256 ≈ 2.34% | 1/0.0234 × 200ms ≈ **8.5s** |
| AZD004 | 1/2^Beta | 1/64 ≈ 1.56% | 1/0.0156 × 200ms = **12.8s** |

코드 주석의 "τ≈12.8s"는 **AZD004 공식 + IC 측정 주기 200ms 가정** 값이다 (.c:305 주석 참조).

> [!IMPORTANT]
> **Beta filter 적용 주체와 주기**: Beta filter는 IC 내부에서 각 IC 측정마다 적용된다. SW 폴링 주기(TDC_TOUCH_POLL_INTERVAL_MS = 50ms, tdc_touch_time.h:18)와는 별개다. τ 계산의 "IC 측정 주기"는 IC NP report rate(0xC1 = 0, 기본값 = 즉시)에 의해 결정되며, 정확한 값은 실기 계측 필요.

> [!WARNING]
> **[실측 게이트] Beta 정수값 해석 불일치**
> - DS §5.6(α=Beta/256) vs AZD004(α=1/2^Beta): 공식 출처 불일치.
> - IC 측정 주기 미확정: 0xC1=0(기본값) 조건에서 실제 IC 측정 간격 [실측 미완료].
> - .h:42~43 주석에 "시험 write 1회 판별 후 고정" 명시 → 실측 전 τ 수치 확정 불가.
> - 코드 주석의 τ≈12.8s는 참고용 추정치.

### 3.4 Power Mode 설정 (.c:309~315)

```c
write_register(REG_SYSTEM_CONTROL, 0x50, 0x07);
/* LSB bits[6:4]=101 = Automatic No ULP, MSB=0x07 = CH0~2 timeout disable */
write_register(REG_LP_REPORT_RATE, 0x64, 0x00); /* LP report rate = 100ms */
write_register(REG_PM_TIMEOUT,     0x00, 0x00); /* PM timeout = 0 → 항상 NP 유지 */
```

PM_TIMEOUT=0으로 LP 강하를 원천 차단 → 항상 NP Beta 적용 (LTA Normal=6, Counts=2, LTA Fast=2).
SW 폴링 주기: `TDC_TOUCH_POLL_INTERVAL_MS = 50ms` (tdc_touch_time.h:18).

## 4. Touch Threshold · Hysteresis · Prox Threshold — 코드 설정 계수

### 4.1 Touch Threshold

- **코드 상수**: `TDC_TOUCH_IQS323_THRESHOLD = 80` (.h:46)
- **IC 내부 계산식** (DS A.17 원문):

  ```
  Touch Threshold (절대) = (Threshold × LTA) / 256
  ```

- **SW 계측 코드** (touch.c:286):

  ```c
  uint16_t abs_thr = (uint16_t)(((uint32_t)TDC_TOUCH_IQS323_THRESHOLD * dbg.lta) / 256u);
  ```

- **LTA 연동**: LTA가 바뀔 때마다 절대임계도 실시간 변동.
  - LTA = 400: abs_thr = 80 × 400 / 256 ≈ **125 counts**

- **Touch 진입 조건** (DS §5.7):
  `(LTA − Counts) > Touch Threshold` → `Delta > abs_thr`

- **Touch 이탈 조건** (DS §5.7):
  `Delta > (Touch Threshold − Touch Hysteresis)`

- **레지스터 write** (.c:289):
  ```c
  write_register(REG_CH0_TOUCH, threshold, (uint8_t)((hysteresis & 0x0F) << 4));
  /* 0x62 LSB = 80 (Threshold 계수), MSB = 0x80 (Hysteresis=8 상위 니블) */
  ```

### 4.2 Touch Hysteresis

- **코드 상수**: `TDC_TOUCH_IQS323_HYSTERESIS = 8` (.h:49)
- **레지스터 위치**: 0x62 bits[15:12] (4비트 필드, DS A.17)
- **IC 내부 계산식** (DS A.17 원문):

  ```
  Touch Hysteresis (절대) = (Touch Hysteresis / 256) × Touch Threshold (절대)
  ```

  즉 이중 계수 구조:
  ```
  Hyst_abs = (8/256) × (80 × LTA / 256)
           = (8 × 80 / 65536) × LTA
           = (640 / 65536) × LTA
  ```

  - LTA = 400: Hyst_abs ≈ **3.9 counts**
  - 이탈 절대임계: 125 − 3.9 ≈ **121 counts**

- **LTA 이중 연동**: Hysteresis 절대값은 Touch Threshold를 통해 LTA에 이중으로 연동됨.

### 4.3 Prox Threshold

- **코드 상수**: `TDC_TOUCH_IQS323_PROX_THRESHOLD = 255` (.h:52)
- **write** (.c:415):
  ```c
  write_register(REG_CH0_PROX, TDC_TOUCH_IQS323_PROX_THRESHOLD, 0x00);
  /* 0x61 LSB=255(Prox Threshold), MSB=0x00(Prox Debounce 없음) */
  ```
- **설계 의도**: 255로 prox 사실상 비활성화 → LTA freeze는 touch 이벤트만 담당 (.h:52 주석).

> [!NOTE]
> **코드 주석 불일치 주의**: .c:412 주석 "Prox Threshold = Touch Threshold 동일 계수"는 현재 코드와 불일치(현재 PROX=255, THRESHOLD=80). .h:52가 현재 의도의 정본이다.

#### [실측 게이트] Prox Threshold 단위: 절대 카운트 vs 계수

| 근거 | 내용 |
|---|---|
| DS §5.7 Prox 진입 공식 | `(LTA − Counts) > Prox Threshold` — 직접 비교, 계수 공식 미기술 |
| DS A.16 | "8-bit value" — 변환 공식 없음 |
| DS A.17 (Touch Threshold) | `(Threshold × LTA) / 256` — Touch는 명시적 계수 공식 존재 |
| touch.c:287 (SW 계측) | `pabs_thr = (PROX_THRESHOLD * dbg.lta) / 256u` — **계수로 가정** |
| 255 기준 | 절대(255 counts)이든 계수(≈LTA×1=400 counts)이든 → prox 사실상 비활성화 동등 |

DS §5.7 공식 구조상 Prox Threshold는 Touch Threshold와 달리 **절대 카운트일 가능성이 높다**. 255 설정 시 어느 해석이든 결과적으로 비활성화이므로 현재 운용에는 무영향.

> [!WARNING]
> **[실측 게이트]** 단위 미확정. touch.c:287의 계측 표시값(`PTHR`)은 계수 가정으로 계산되므로 절대 단위일 경우 표시 수치 오차 발생.

## 6. Grounding (대지 결합) 영향과 ATI 보정 범위

### 6.1 Counts/Delta에 대한 영향

self-cap 측정 원리 (DS §5.1 · §5.4):

```
noTouch: C_total = C_parasitic
touch  : C_total = C_parasitic + C_finger
```

대지 결합(접지 도체가 전극 근처): C_finger 증가 → C_total 증가 → Counts 감소 → Delta(= LTA − Counts) 증가.
접지가 양호한 손가락 또는 기기를 잡은 상태일수록 C_finger가 더 크게 반응 → 감도 향상 방향.

### 6.2 ATI가 보정하는 범위 vs 보정하지 않는 범위

| 구분 | ATI 보정 여부 | 이유 |
|---|---|---|
| 기기별 C_parasitic 편차 (양산 편차) | **보정** | Full ATI가 MULT/COMP 자동 선택으로 흡수 |
| 환경 변화에 의한 C_parasitic 드리프트 | **간접 보정** | Auto Re-ATI: LTA가 ATI Band 밖으로 드리프트 시 재실행 (DS §5.10) |
| 터치 순간의 ΔC_finger | **보정 안 함** | 이것이 터치 신호 자체 — Delta 생성이 목적 |
| 영구 grounding 변화 (부착 후 baseline 이동) | **장기 보정** | LTA가 Beta 필터로 천천히 추종 + Auto Re-ATI |
| 순간 grounding 변화 (잡는 동작) | **보정 안 함** | Delta 급증 → 터치 판정 or LTA 동결 → 손 뗀 후 LTA 재수렴 |

> [!NOTE]
> DS §5.9 원문: ATI는 "외부 부품 변경 없이 광범위 센싱 전극 정전·인덕턴스에서 최적 성능"을 제공한다. 그러나 이는 C_parasitic 기준선 정규화이며, 사용 중 발생하는 C_finger(터치 신호)는 ATI 보정 대상이 아니다. Grounding이 C_finger에 미치는 영향(감도 향상)은 ATI 보정 범위 밖이므로 Threshold 계수 조정으로 대응한다.

## 7. 초기화 시퀀스 — 각 값이 결정되는 순서

`tdc_touch_iqs323_apply_settings()` (.c:392~451) 호출 순서:

```
① ack_reset()          → 0xC0(LSB=0x01, MSB=0x00): ACK Reset
② confirm_reset()      → 0x10 폴링: Reset Event clear 확인
③ sensor_setup()       → 0x50=0x0000 (CH2 disable)
                          0x40=0x0000 (CH1 disable)
                          0x30=0x0101 (CH0 enable, CTx0 enable, CRx0 enable)
④ touch_settings()     → 0x62(LSB=80, MSB=0x80): Threshold=80, Hyst=8<<4
⑤ prox write           → 0x61(LSB=255, MSB=0x00): Prox Threshold=255, Debounce=0
⑥ events_enable()      → 0xD3(LSB=0x52, MSB=0x00): ati_error|ati_event|touch_event
⑦ beta_power_settings()→ 0xB0(0x0202)/0xB1(0x0606)/0xB2(0x0202)/0xB4(0x000A)
                          0x31(0x057F, 1MHz)/0xC0(0x0750)/0xC2(0x0064)/0xC5(0x0000)
⑧ ATI Setup write      → 0x36(LSB=0x0C, MSB=0x04)=0x040C: Full Mode, Factor=64, Band=Large
                          [0x37 미기록 → ATI Base=100 (IC 기본값 0x0064)]
⑨ Re-ATI 트리거        → 0xC0(LSB=0x54, MSB=0x07)=0x0754: Re-ATI bit2 + No ULP + CH timeout disable
                          → wait_ati_done_blocking(): IC가 MULT/COMP 자동 선택 → Counts ≈ 400
⑩ RESEED               → 0xC0(LSB=0x58, MSB=0x07)=0x0758: LTA ← Counts ≈ 400 동기화
```

- IC 자동 산출 완료 시점: ⑨ ATI 완료 후.
- 운용 시작점: LTA ≈ Counts ≈ ATI Target(400). Threshold 절대임계 ≈ 80×400/256 = 125 counts.
