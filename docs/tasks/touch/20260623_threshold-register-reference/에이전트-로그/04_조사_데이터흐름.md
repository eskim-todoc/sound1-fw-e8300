# 04 조사 — 데이터 흐름 (raw ADC → touch/prox 판정)

> **TL;DR**: IQS323 self-cap 채널의 측정값이 raw ADC에서 출발해 Counts Beta 필터(0xB0) → Filtered Counts(0x13) → LTA IIR(Normal/Fast Beta 0xB1/0xB2 + Fast Filter Band 0xB4) → LTA(0x14)까지 흐른 뒤, delta(LTA−Counts)가 절대 임계(계수×LTA/256)와 비교되어 CH0_Touch/CH0_Prox 비트가 set되는 전 과정을 단계별로 정리한다. hysteresis·debounce·LTA freeze가 어느 단계에 끼는지, 계측 출력 [T]가 어느 단계를 보여주는지 명시.

## 1. 전체 흐름 개요

```
[HW: 충전전달 측정]
        │ raw ADC 값 (정전용량 반비례)
        ▼
[A단계] Counts IIR 필터 — 0xB0 Beta
        │ Filtered Counts → 0x13 레지스터 (16-bit little-endian)
        ▼
[B단계] LTA IIR 필터 — 0xB1 Normal Beta / 0xB2 Fast Beta + 0xB4 Fast Filter Band
   ├── LTA freeze gate (CH0_Touch|CH0_Prox bit set 동안 갱신 정지)
        │ LTA → 0x14 레지스터 (16-bit little-endian)
        ▼
[C단계] delta 계산
        delta = LTA − Counts  (self-cap: 터치 시 Counts 감소 → delta 양수)
        ▼
[D단계] Touch 판정
   ├── 절대 임계 abs_thr = Touch_Threshold_k × LTA / 256  (레지스터 0x62 bits[7:0])
   ├── delta > abs_thr  → CH0_Touch (System Status 0x10 bit9) SET (진입)
   └── delta < (abs_thr − hysteresis)  → CH0_Touch CLEAR (이탈, 히스테리시스)
        ▼
[E단계] Prox 판정  [실측 게이트: 단위 절대/계수 미확정]
   ├── Prox_Threshold_raw (레지스터 0x61 bits[7:0])
   ├── delta > Prox_Threshold  → CH0_Prox (bit8) SET  (진입, debounce 0=즉시)
   └── delta 조건 미충족  → CH0_Prox CLEAR (이탈)
        │
        └── CH0_Prox SET 시 → B단계 LTA freeze gate 닫힘
```

## 2. A단계 — raw ADC → Filtered Counts (0xB0 → 0x13)

### 물리 원리 (DS §5.4)

IQS323은 충전전달(Charge Transfer) 방식으로 정전용량을 counts로 변환한다.

```
self-cap 터치 시:
  Cx(전극 정전용량) 증가 → 1사이클당 Cs로 이동 전하 증가 → 임계 도달까지 전달 횟수 감소
  → Counts 감소

Counts ∝ 1/C  (정전용량 반비례)
```

### 필터 레지스터 (0xB0, DS A.26)

| 필드 | 비트 | 현재 설정 | 기록처 |
|---|---|---|---|
| NP_COUNTS_FILTER (Normal Power Beta) | bits[7:0] | 0x02 | `tdc_touch_iqs323.c:304` |
| LP_COUNTS_FILTER (Low Power Beta) | bits[15:8] | 0x02 | `tdc_touch_iqs323.c:304` |

코드: `write_register(REG_BETA_COUNTS, 0x02, 0x02)` (`tdc_touch_iqs323.c:304`)

### IIR 수식 (DS §5.6)

```
FilteredCounts_new = FilteredCounts_old + (RawCounts − FilteredCounts_old) × (Beta / 256)
alpha = 2 / 256 ≈ 0.78% / 샘플   (NP, Beta=2)
```

현재 전력 모드는 항상 NP(PM Timeout=0, Automatic No ULP) → NP_COUNTS_FILTER=2 적용 중.

### 출력 레지스터

- **0x13 Channel 0 Filtered Counts** (DS §9 메모리맵, read-only, 16-bit little-endian)
- 코드에서 `buf[0] | (buf[1] << 8)` 로 읽음 (`tdc_touch_iqs323.c:386`)

## 3. B단계 — Filtered Counts → LTA (0xB1/0xB2/0xB4 → 0x14)

### LTA의 역할 (DS §5.5)

LTA(Long-Term Average)는 "아무것도 건드리지 않은 상태"의 Counts 기준선이다.
환경 변화(온도·습도)에 의한 counts 드리프트를 천천히 추적한다.

### LTA Normal Beta 레지스터 (0xB1, DS A.27)

| 필드 | 비트 | 현재 설정 | 기록처 |
|---|---|---|---|
| NP_LTA_FILTER | bits[7:0] | 0x06 | `tdc_touch_iqs323.c:305` |
| LP_LTA_FILTER | bits[15:8] | 0x06 | `tdc_touch_iqs323.c:305` |

코드: `write_register(REG_BETA_LTA_NORMAL, 0x06, 0x06)` (`tdc_touch_iqs323.c:305`)

### LTA Fast Beta 레지스터 (0xB2, DS A.28)

| 필드 | 비트 | 현재 설정 | 기록처 |
|---|---|---|---|
| NP_LTA_FAST_FILTER | bits[7:0] | 0x02 | `tdc_touch_iqs323.c:306` |
| LP_LTA_FAST_FILTER | bits[15:8] | 0x02 | `tdc_touch_iqs323.c:306` |

코드: `write_register(REG_BETA_LTA_FAST, 0x02, 0x02)` (`tdc_touch_iqs323.c:306`)

### Fast Filter Band 레지스터 (0xB4, DS §9 16-bit value)

| 현재 설정 | 단위 | 기록처 |
|---|---|---|
| 10 counts | counts | `tdc_touch_iqs323.c:307` |

코드: `write_register(REG_FAST_FILTER_BAND, 0x0A, 0x00)` (`tdc_touch_iqs323.c:307`)

### LTA IIR 수식과 Fast Filter Band 전환 (DS §5.6)

DS §5.6 원문 인용 (`02_proxfusion동작.md` §5.6):
> "When counts have drifted from the LTA in the **sensing direction opposite to the normal sensing direction** by more than the Fast Filter Band, fast filtering is applied to the LTA."

self-cap에서 **"normal sensing direction" = counts 감소(터치 방향)**이므로,
**"반대 방향" = counts가 LTA보다 위로 올라가는 방향(Counts > LTA)**.

```
조건 판단:
  Counts > LTA + 10  → Fast Beta 적용 (sensing 반대 방향, Band 초과)
  그 외              → Normal Beta 적용

LTA 갱신 수식:
  LTA_new = LTA_old + (Counts − LTA_old) × (Beta / 256)

  Normal Beta 적용 시 (Counts ≤ LTA + 10):
    alpha = 6/256 ≈ 2.3%/샘플  [시정수 ≈ 1/0.023 ≈ 43샘플]

  Fast Beta 적용 시 (Counts > LTA + 10):
    alpha = 2/256 ≈ 0.78%/샘플  (Normal보다 느림 — §11 실측 게이트 참조)
```

> [!NOTE]
> Fast Beta가 Normal Beta보다 숫자가 작다(2 < 6). sensing 반대 방향(noTouch에서 LTA가 Counts보다 높게 남아있는 경우)에서 LTA가 **더 느리게** 수렴하도록 설계된 것이다. 약결합 물체에 의한 LTA 흡수를 방지하는 의도 (`tdc_touch_iqs323.c:299~300` 주석 참조). **[실측 게이트]**: Beta 해석 방향 미확정 — §11 참조.

### LTA freeze gate (DS §5.5 직접 인용)

DS §5.5 원문 (`02_proxfusion동작.md` §5.5):
> "LTA is updated slowly to track environmental changes and is **frozen during touch and proximity events**."

동결 조건: System Status(0x10) 레지스터의 **CH0_Touch(bit9) 또는 CH0_Prox(bit8) 중 하나라도 SET** 시 LTA IIR 갱신 정지.
동결 해제: 두 비트가 모두 CLEAR된 직후 정상 갱신 재개.

이 동결이 없으면 터치 중 LTA가 낮은 Counts 값을 학습해 touch 해제 판정이 불가해진다.

### 출력 레지스터

- **0x14 Channel 0 LTA** (DS §9, read-only, 16-bit little-endian)
- 코드에서 `buf[2] | (buf[3] << 8)` 로 읽음 (`tdc_touch_iqs323.c:387`)
- 0x13과 0x14는 연속 4바이트 read로 1윈도에서 동시 취득 (`tdc_touch_iqs323.c:363~384`)

## 4. C단계 — delta 계산

### 수식 (DS §5.7 판정 기준)

```
delta = LTA − Counts
```

self-cap 물리:
- 노터치: Counts ≈ LTA → delta ≈ 0
- 터치 진입: Counts 감소 → delta 증가 (양수)

IC 내부에서 "delta"라는 용어를 사용하지 않는다. DS §5.7의 판정 공식 `(LTA − Counts)`를 SW에서 delta로 명명한 것이다.

SW 계측 코드 (`tdc_touch.c:285`):
```c
uint16_t delta = (dbg.lta > dbg.counts) ? (uint16_t)(dbg.lta - dbg.counts) : 0;
```

Counts > LTA 시 0으로 클램핑 — SW 계측 표시용이며, IC 내부 판정은 자체 비교 회로로 수행한다.

## 5. D단계 — Touch 판정 (0x62 → 0x10 bit9)

### 레지스터 구조 (DS A.17, 0x62 Touch Settings)

| 비트 | 필드 | 현재 설정 | 기록처 |
|---|---|---|---|
| bits[7:0] | Touch Threshold (계수 k) | 80 | `tdc_touch_iqs323.h:46` (TDC_TOUCH_IQS323_THRESHOLD) |
| bits[15:12] | Touch Hysteresis (4비트 필드값) | 8 | `tdc_touch_iqs323.h:49` (TDC_TOUCH_IQS323_HYSTERESIS) |
| bits[11:8] | (미정의, 0 고정) | 0 | — |

코드 write (`tdc_touch_iqs323.c:289`):
```c
write_register(REG_CH0_TOUCH, threshold, (uint8_t)((hysteresis & 0x0F) << 4));
// LSB=0x50(threshold=80), MSB=0x80(hysteresis 4비트=8을 bits[15:12]에 위치)
```

> [!NOTE]
> `(hysteresis & 0x0F) << 4` 결과가 MSB byte의 상위 니블(bits[15:12])에 Hysteresis 필드를 맞게 위치시킨다. 이전 버전은 `hysteresis` raw를 MSB 전체에 써 bits[11:8](미정의 영역)에 들어가 실효 hysteresis=0이 되던 버그가 있었다 (`tdc_touch_iqs323.c:286~289` 주석 참조).

### 절대 임계 계산 공식 (DS A.17 명확 정의)

DS A.17 원문 (`06_레지스터레퍼런스.md` A.17):
```
Touch Threshold (절대값) = (Threshold × LTA) / 256
```

이 공식의 핵심: 임계가 LTA에 비례하므로, ATI로 LTA가 정규화된 이후에도 동일한 계수 k로 일관된 감도를 유지한다.

현재 k=80, 대표 LTA=399:
```
abs_thr = 80 × 399 / 256 ≈ 124.7 ≈ 125 counts
```

SW 계측 계산 (`tdc_touch.c:286`):
```c
uint16_t abs_thr = (uint16_t)(((uint32_t)TDC_TOUCH_IQS323_THRESHOLD * dbg.lta) / 256u);
```

### Touch 진입/이탈 조건 (DS §5.7)

DS §5.7 원문 (`02_proxfusion동작.md` §5.7):

```
Touch 진입: (LTA − Counts) > Touch_Threshold_absolute
           즉 delta > abs_thr

Touch 이탈: (LTA − Counts) < (Touch_Threshold_absolute − Touch_Hysteresis_absolute)
           즉 delta < (abs_thr − hyst_abs)
```

DS A.17 Hysteresis 공식:
```
Touch Hysteresis (절대값) = (Touch_Hysteresis_field / 256) × Touch_Threshold_absolute
현재: (8/256) × 125 ≈ 3.9 ≈ 4 counts
이탈 조건: delta < (125 − 4) = 121 counts
```

### Touch에 debounce가 있는가?

DS A.17의 0x62 레지스터 정의(`06_레지스터레퍼런스.md` A.17): bits[15:12]=Hysteresis, bits[7:0]=Threshold만 정의되어 있다. bits[11:8]은 미정의다.  
**Touch 판정에는 별도 debounce 필드가 없으며**, 임계 조건을 1샘플 초과 시 즉시 진입한다. Prox에는 Debounce Enter/Exit 필드가 있다(DS A.16).

### 결과 비트 (DS A.2)

- **System Status 0x10 bit9 = CH0_Touch**
- 코드 read (`tdc_touch_iqs323.c:356`): `out->pressed = (msb & (1u << 1)) != 0;`
- MSB bit1 = 전체 word bit9 (16-bit little-endian, MSB = 상위 바이트)

## 6. E단계 — Prox 판정 (0x61 → 0x10 bit8)

### 레지스터 구조 (DS A.16, 0x61 Prox Settings)

| 비트 | 필드 | 현재 설정 | 기록처 |
|---|---|---|---|
| bits[7:0] | Prox Threshold | 255 | `tdc_touch_iqs323.h:52` (TDC_TOUCH_IQS323_PROX_THRESHOLD) |
| bits[11:8] | Prox Debounce Enter | 0 (즉시) | `tdc_touch_iqs323.c:415` (MSB=0x00) |
| bits[15:12] | Prox Debounce Exit | 0 (즉시) | `tdc_touch_iqs323.c:415` (MSB=0x00) |

코드 write (`tdc_touch_iqs323.c:415`):
```c
write_register(REG_CH0_PROX, TDC_TOUCH_IQS323_PROX_THRESHOLD, 0x00);
```

설정 의도 (`tdc_touch_iqs323.h:52` 주석): "255 = prox 사실상 무력화(진입점≈LTA) → LTA freeze는 touch만 담당."

### 판정 조건과 공식 불확실성 [실측 게이트]

DS §5.7 판정 조건 (`02_proxfusion동작.md` §5.7):
```
Proximity 진입: (LTA − Counts) > Prox Threshold
```

DS A.16 (`06_레지스터레퍼런스.md` A.16): Prox Threshold는 단순 "8-bit value"로만 기술되며, Touch Threshold처럼 `(Threshold × LTA) / 256` 공식을 명시하지 않는다.

| 해석 | 공식 | 근거 |
|---|---|---|
| **절대값 (유력)** | delta > Prox_Threshold_raw | DS A.16 "8-bit value", DS §5.7 수식 그대로 |
| 계수 기반 | delta > Prox_Threshold × LTA / 256 | Touch와 동일 구조 가정 |

> [!WARNING]
> **[실측 게이트]**: Prox Threshold 단위(절대 count vs 계수×LTA/256) DS에서 확인 불가. SW 계측 출력의 `PTHR`은 계수 기반으로 계산하고 있으나(`tdc_touch.c:287`), IC 내부 실제 비교 방식과 다를 수 있다. 현재 설정값 255는 두 해석 모두에서 prox 진입을 사실상 차단한다(절대 시 delta>255 필요; 계수 시 임계≈LTA 수준).

### Prox가 LTA freeze에 미치는 영향 (과거 버그 사례)

이전 코드: 0x61 미기록 → IC 기본값 0x0000 → Prox Threshold=0.  
DS §5.7: `(LTA − Counts) > 0` → D>0이면 무조건 prox 진입.  
결과: CH0_Prox=1 → LTA 영구 동결 → D=39 고착 (`51_분석_LTA동작.md` §2 참조).

현재 코드: Prox_Threshold=255 → prox 사실상 비진입 → LTA freeze는 touch만 담당.

### 결과 비트 (DS A.2)

- **System Status 0x10 bit8 = CH0_Prox**
- 코드 read (`tdc_touch_iqs323.c:357`): `out->prox = (msb & (1u << 0)) != 0;`
- 이 비트가 SET되면 B단계의 LTA freeze gate가 닫힌다.

## 7. hysteresis·debounce·LTA freeze의 흐름 내 위치 정리

```
[C단계] delta 계산
   │
   ├─→ [D단계] delta > abs_thr ?
   │       YES → CH0_Touch SET  ──────────────────┐
   │       (Touch debounce 없음, 1샘플 즉시 진입)   │
   │                                              │
   └─→ [E단계] delta > prox_thr ?                │
           YES → CH0_Prox SET  ─────────────────→ 공통 gate
           (Prox Debounce Enter=0 → 즉시 진입)    │
                                                  │
                              ┌───────────────────┘
                              ▼
                   [B단계 gate] LTA freeze
                     CH0_Touch=1 OR CH0_Prox=1
                     → LTA IIR 수식 실행 안 함
                     → delta 현재값 고정 유지

[D단계] CH0_Touch CLEAR 조건 (이탈):
   delta ≤ (abs_thr − hysteresis_abs)   ← 히스테리시스 적용
   hysteresis_abs = (8/256) × abs_thr ≈ (8/256) × 125 ≈ 4 counts
   이탈 임계 ≈ 121 counts
   → 임계보다 4 counts 낮은 지점에서 이탈 (진입/이탈 히스테리시스 4 counts 밴드)

[E단계] CH0_Prox CLEAR 조건 (이탈):
   delta ≤ prox_thr
   Prox Debounce Exit=0 → 즉시 이탈
   현재 prox_thr=255 → 사실상 미진입이라 이탈도 발생 안 함
```

## 8. 계측 출력 [T]가 흐름의 어느 단계를 보여주는가

tdc_touch.c:288의 `ci_printd("[T] ...")`는 다음을 출력한다:

```
[T] LTA=<B단계 출력>  CNT=<A단계 출력>  D=<C단계 계산>  THR=<D단계 절대임계 SW계산>
    (k=<Touch_k>  H=<Hysteresis_field>)  <T or .>   PTHR=<E단계 절대임계 SW계산>
    (pk=<Prox_k>)  <P or .>
```

| 필드 | 읽는 단계 | 값 출처 |
|---|---|---|
| `LTA` | B단계 완료 후 | 0x14 레지스터 (`tdc_touch_iqs323.c:387`) |
| `CNT` | A단계 완료 후 | 0x13 레지스터 (`tdc_touch_iqs323.c:386`) |
| `D` | C단계 SW 계산 | `(LTA > CNT) ? LTA−CNT : 0` (`tdc_touch.c:285`) |
| `THR` | D단계 SW 계산 | `k × LTA / 256` (`tdc_touch.c:286`) |
| `k` | 고정 상수 | TDC_TOUCH_IQS323_THRESHOLD=80 (`tdc_touch_iqs323.h:46`) |
| `H` | 고정 상수 | TDC_TOUCH_IQS323_HYSTERESIS=8 (`tdc_touch_iqs323.h:49`) |
| `T or .` | D단계 IC 판정 | System Status 0x10 bit9 via `read_status()` |
| `PTHR` | E단계 SW 계산 | `Prox_k × LTA / 256` (`tdc_touch.c:287`) ※단위 미확정 |
| `pk` | 고정 상수 | TDC_TOUCH_IQS323_PROX_THRESHOLD=255 (`tdc_touch_iqs323.h:52`) |
| `P or .` | E단계 IC 판정 | System Status 0x10 bit8 via `read_status()` |

> [!IMPORTANT]
> `T or .` 와 `P or .`는 **IC가 판정한 결과**를 read_status()로 읽어 표시한다. 반면 `THR`과 `PTHR`은 **SW가 공식을 이용해 역산한 참고값**이다. IC 내부 판정 기준(특히 Prox)과 완전히 일치하지 않을 수 있다([실측 게이트]).

## 10. 전체 수식 요약

```
A단계 Counts IIR (현재 항상 NP):
  Counts_k = Counts_{k-1} + (Raw_k − Counts_{k-1}) × (2/256)

B단계 LTA IIR (freeze 없을 때):
  if Counts_k > LTA_{k-1} + 10:         [sensing 반대 방향 Band 초과]
    LTA_k = LTA_{k-1} + (Counts_k − LTA_{k-1}) × (2/256)   [Fast Beta]
  else:
    LTA_k = LTA_{k-1} + (Counts_k − LTA_{k-1}) × (6/256)   [Normal Beta]

  if CH0_Touch=1 OR CH0_Prox=1:
    LTA_k = LTA_{k-1}  [FREEZE, 갱신 없음]

C단계 delta (IC 내부 / SW 동일):
  delta_k = LTA_k − Counts_k  (self-cap, non-inverted)

D단계 Touch 판정 (DS A.17, §5.7):
  Touch_Thr_abs = 80 × LTA_k / 256
  Touch_Hyst_abs = (8/256) × Touch_Thr_abs  ≈ 4 counts

  진입: delta_k > Touch_Thr_abs  → CH0_Touch = 1
  이탈: CH0_Touch=1 AND delta_k ≤ (Touch_Thr_abs − Touch_Hyst_abs)  → CH0_Touch = 0

E단계 Prox 판정 (DS A.16, §5.7):
  진입: delta_k > Prox_Threshold  → CH0_Prox = 1
       (Prox_Threshold=255: 절대값 해석 시 delta>255, 계수 해석 시 임계≈LTA — 둘 다 사실상 미진입)
  이탈: delta_k ≤ Prox_Threshold  → CH0_Prox = 0
       [실측 게이트: 단위 미확정]
```

## 11. 불확실(실측 게이트) 항목

1. **Prox Threshold 단위** (0x61 bits[7:0]): DS A.16이 "8-bit value"로만 기술하며 Touch처럼 `× LTA/256` 공식 미명시. 절대값 비교(유력) vs Touch와 동일한 계수 기반 비교. 현재 설정값 255는 두 해석 모두 prox 비활성화로 귀결되어 실기 구분 어려움. 의도적으로 prox를 낮은 임계로 설정 후 P 비트 동작 확인 필요.

2. **Beta 해석 방향** (0xB1/0xB2): DS §5.6 수식 `alpha = Beta/256`으로 기술되어 있으나, 코드 주석에 "비트 시프트 해석_B" 가능성 언급 (`tdc_touch_iqs323.c:299~300`). IC 내부가 `× Beta/256`인지 `>> (8-Beta)`인지 미확정. 기록된 Beta 값 변경 후 수렴 속도 측정으로 판별 가능.

3. **Fast Beta가 더 느린 이유 확인**: 현재 Fast Beta=2 < Normal Beta=6. DS 원문 "fast filtering"이라는 명칭과 반대로 더 느리게 동작. sensing 반대 방향(noTouch에서 LTA가 Counts보다 높게 남아있는 상태)에서 LTA가 의도적으로 느리게 수렴하도록 설계된 것으로 추정. 실기 파형 검증 필요.
