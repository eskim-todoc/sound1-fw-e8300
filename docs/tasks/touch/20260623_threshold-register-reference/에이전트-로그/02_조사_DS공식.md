# 02 조사 — 데이터시트 공식 (페르소나 02: 조사_DS공식)

> **TL;DR**: Touch Threshold·Hysteresis는 LTA 비례 계수(÷256). Prox Threshold 단위(절대 vs 계수)는 DS 명시 없음 [실측 게이트] — 단 255 설정은 어느 해석에서도 prox 무력화. ATI Target=400cnt=Base(100)×ResolutionFactor(64)÷16. Beta 해석 충돌: DS=Beta÷256, AZD004=1÷2^Beta — 코드 τ 계산은 AZD004 기준, DS와 불일치.

근거 파일:
- 데이터시트: `docs/참고/touch/데이터시트/06_레지스터레퍼런스.md` (A.12·A.16·A.17·A.26~A.28), `02_proxfusion동작.md` (§5.5~5.11)
- 코드: `src/2__cm3/Cortex-M3-src/systemControl/tdc_touch_iqs323.h` (L46·L49·L52), `tdc_touch_iqs323.c` (L284-289·L304-315·L429·L439)
- 재검증 대상(맹신 금지): `에이전트-로그/51_분석_LTA동작.md`, `52_분석_ATI동작.md`

## 1. A.17 Touch Settings (0x62) — Touch Threshold · Hysteresis

### 1.1 비트 필드 (DS A.17)

DS `06_레지스터레퍼런스.md` A.17:

| 비트 | 필드 | 값 범위 |
|---|---|---|
| 15-12 | Touch Hysteresis | 4비트 (0~15) |
| 11-8 | (미정의) | 0으로 기입 필요 |
| 7-0 | Touch Threshold | 8비트 (0~255) |

### 1.2 IC 내부 계산 공식 (DS A.17 직접 인용)

```
Touch Threshold_counts = (Touch Threshold_field × LTA) / 256
Touch Hysteresis_counts = (Touch Hysteresis_field / 256) × Touch Threshold_counts
```

- `Touch Threshold_field`: bits[7:0] (0~255)
- `Touch Hysteresis_field`: bits[15:12] (0~15)
- `LTA`: 해당 채널의 런타임 LTA counts (IC가 매 샘플마다 현재 LTA로 재산출)

### 1.3 진입·이탈 조건 (DS §5.7 — Non-inverted + single direction 기준)

DS `02_proxfusion동작.md` §5.7:

```
Touch 진입: (LTA − Counts) > Touch Threshold_counts
Touch 이탈: (LTA − Counts) < (Touch Threshold_counts − Touch Hysteresis_counts)
```

> [!NOTE]
> DS §5.7 이탈 표현은 "Touch Threshold - Touch Hysteresis" 조건 **미충족 시(이탈 임계 미달)**로 기술된다. 이탈 threshold가 진입보다 낮아 delta가 충분히 작아져야 해제 — 전형적 이력현상(hysteresis). Hysteresis_field=8 → 이탈 임계 ≈ 진입 임계의 96.9%.

### 1.4 코드 → 레지스터 write 경로

```c
/* tdc_touch_iqs323.h L46 */
#define TDC_TOUCH_IQS323_THRESHOLD  80   /* 8비트 계수 k. 절대임계 = k×LTA/256 */
/* tdc_touch_iqs323.h L49 */
#define TDC_TOUCH_IQS323_HYSTERESIS  8   /* 4비트 Hyst 필드값. bits[15:12] */

/* tdc_touch_iqs323.c L284-289 touch_settings() */
write_register(REG_CH0_TOUCH,       /* 0x62 */
    threshold,                           /* LSB bits[7:0] = 0x50 = 80 */
    (uint8_t)((hysteresis & 0x0F) << 4) /* MSB 상위 nibble bits[15:12] = (8<<4)=0x80 */
);
/* 16비트 wire value: 0x8050 */
```

**실제 임계 계산 (ATI 완료 후 LTA ≈ 400 기준):**

```
Touch Threshold_counts = 80 × 400 / 256 ≈ 125 counts
Touch Hysteresis_counts = (8 / 256) × 125 ≈ 3.9 counts   (약 4 counts)
Touch 이탈 하한: delta < 125 − 4 = 121 counts
```

> [!NOTE]
> **이전 버그 수정 이력** (`tdc_touch_iqs323.c` L286 주석): 과거 `write_register(0x62, threshold, hysteresis)` 형태로 Hysteresis를 MSB 통째로(bits[11:8])에 기입해 bits[15:12]=0이 되는 버그 존재. 수정 후 `(hysteresis & 0x0F) << 4` 로 bits[15:12]에 정확히 위치. bits[11:8]은 DS A.17에서 미정의 — 항상 0.

## 2. A.16 Prox Settings (0x61) — Prox Threshold · Debounce

### 2.1 비트 필드 (DS A.16)

DS `06_레지스터레퍼런스.md` A.16:

| 비트 | 필드 | 값 범위 |
|---|---|---|
| 15-12 | Prox Debounce Exit | 4비트 (0=disabled, 1~15 = 연속 샘플 수) |
| 11-8 | Prox Debounce Enter | 4비트 (0=disabled, 1~15 = 연속 샘플 수) |
| 7-0 | Prox Threshold | 8비트 "8-bit value" |

### 2.2 진입·이탈 조건 (DS §5.7 직접 인용)

DS `02_proxfusion동작.md` §5.7:

```
Prox 진입: (LTA − Counts) > Prox Threshold    [Debounce Enter 연속 조건]
Prox 이탈: 위 조건 불충족                      [Debounce Exit 연속 조건]
```

### 2.3 Prox Threshold 단위 판정 [실측 게이트]

**데이터시트 기술 비교:**

| 항목 | DS 기술 방식 | 공식 명시 |
|---|---|---|
| Touch Threshold (A.17) | "Touch Threshold = (Threshold × LTA) / 256" | LTA 비례 계수 명시 |
| Prox Threshold (A.16) | "8-bit value" | 공식 없음 |

- A.16에는 A.17의 "×LTA/256" 공식이 없다.
- §5.7 진입식 `(LTA - Counts) > Prox Threshold`도 Prox_Threshold를 delta와 직접 비교 — LTA 분모 없음.
- DS 문면상 Prox Threshold는 **절대 delta counts** 단위로 해석됨이 가장 일관적이다.
- DS가 이를 명시하지 않아 LTA 비례 계수 가능성 완전 배제 불가.
- **판정: 불확실 [실측 게이트]** (`tdc_touch_iqs323.h` L52 주석과 동일 기재)

### 2.4 코드 → 레지스터 write 경로

```c
/* tdc_touch_iqs323.h L52 */
#define TDC_TOUCH_IQS323_PROX_THRESHOLD 255
/* "Prox Threshold 계수. 255 = prox 사실상 무력화(진입점≈LTA) → LTA freeze는 touch만 담당.
 *  [실측 게이트: prox 단위 절대/계수]" */

/* tdc_touch_iqs323.c L415 */
write_register(REG_CH0_PROX, TDC_TOUCH_IQS323_PROX_THRESHOLD, 0x00);
/* → 0x61 LSB=0xFF(255), MSB=0x00(Debounce 없음, 즉시 반응) */
```

**255 설정의 효과 (해석 무관 공통):**

| 해석 | Prox 진입 조건 | 실효 |
|---|---|---|
| 절대 delta 단위 | delta > 255 → LTA≈400에서 Counts < 145 필요 | 사실상 불가 — 무력화 |
| LTA 계수 단위 | 255×400/256≈399 → delta > 399 → 불가능 | 무력화 |

**양 해석 모두 255 = prox 무력화.** LTA freeze는 touch 이벤트만 담당하도록 의도.

> [!NOTE]
> 계측 출력(`tdc_touch.c` L287): `pabs_thr = TDC_TOUCH_IQS323_PROX_THRESHOLD × dbg.lta / 256u` — 코드에서는 Prox Threshold를 계수처럼 변환해 표시한다. 이것은 계측 **표시용** 변환이며, 실제 레지스터에 기입되는 값(0xFF)에는 영향 없다. IC 동작은 0x61에 기입된 원시값(255)으로 결정된다.

## 3. §5.6 Filter Betas — Counts·LTA 필터

### 3.1 레지스터 배치 및 코드 기입값

| 주소 | 이름 | 코드 기입값 | NP 필드 | LP 필드 |
|---|---|---|---|---|
| 0xB0 | Counts Filter Betas | 0x0202 | NP_COUNTS=2 | LP_COUNTS=2 |
| 0xB1 | LTA Normal Filter Betas | 0x0606 | NP_LTA=6 | LP_LTA=6 |
| 0xB2 | LTA Fast Filter Betas | 0x0202 | NP_LTA_FAST=2 | LP_LTA_FAST=2 |
| 0xB4 | Fast Filter Band | 0x000A | 10 counts | — |

코드: `tdc_touch_iqs323.c` L304-307 `beta_power_settings()`.

DS `06_레지스터레퍼런스.md` A.26-A.28: 비트 배치 — bits[15:8]=LP Beta, bits[7:0]=NP Beta.

### 3.2 DS 공식 (§5.6 직접 인용)

DS `02_proxfusion동작.md` §5.6:

```
Damping factor = Beta / 256

IIR 적용(implied):
LTA_new = LTA_old + (Counts − LTA_old) × (Beta / 256)
```

### 3.3 AZD004 해석 충돌 — 두 공식 병기 (실측 판별 필요)

| 해석 출처 | 공식 | Beta=6일 때 alpha | NP 200ms 주기 τ |
|---|---|---|---|
| **DS §5.6** | alpha = Beta / 256 | 6/256 ≈ 2.34% | ≈43 샘플 ≈ 8.6s |
| **AZD004** | alpha = 1 / (2^Beta) | 1/64 ≈ 1.56% | ≈64 샘플 ≈ 12.8s |

**충돌 근거:**
- DS 공식: `02_proxfusion동작.md` §5.6 "Damping factor = Beta / 256"
- AZD004: `tdc_touch_iqs323.c` L305 주석 `"AZD004 α=1/2^β. τ≈12.8s(롱터치 2.4s의 ~5배)..."`

**코드 설계는 AZD004 기준으로 계산됨:**
- 코드 주석 τ≈12.8s = 64 samples × 0.2s/sample → alpha=1/64=1/2^6 → AZD004 공식과 일치
- DS 공식(Beta/256) 적용 시 τ≈8.6s — 코드 주석과 불일치

> [!IMPORTANT]
> DS와 AZD004의 Beta 해석 충돌. IC 실제 동작이 어느 쪽인지 **[실측 게이트]** — Beta=6 상태에서 LTA 수렴 속도 실측 후 τ≈8.6s(DS) vs ≈12.8s(AZD004) 판별. `tdc_touch_iqs323.c` L299 주석: "Beta 정수값과 해석(damping=Beta/256 해석_A vs 시프트 해석_B)은 [실측 게이트]"와 동일 불확실 명시.

### 3.4 Fast Filter Band (0xB4) — 적용 방향 (DS §5.6 직접 인용)

DS `02_proxfusion동작.md` §5.6:

> "When counts have drifted from the LTA in the **sensing direction opposite to the normal sensing direction** by more than the Fast Filter Band, fast filtering is applied to the LTA. When the difference between counts and LTA is less than the fast filter band, normal filtering resumes."

**Self-cap(Sound1) 방향 매핑:**

| 방향 | counts 변화 | delta(LTA-Counts) | Fast Filter Band 조건 |
|---|---|---|---|
| Normal sensing direction (터치) | counts 감소 | delta > 0 | Fast beta 미적용 |
| **Sensing opposite direction** | counts **증가** | **Counts > LTA** (delta < 0) | **Counts > LTA + 10 → Fast Beta 적용** |

**결론**: Fast beta(2)는 노터치 상태에서 외부 간섭 등으로 counts가 LTA보다 10cnt 이상 높아질 때만 활성. 터치 방향(counts < LTA)에서는 Normal beta 유지. 코드 설정 10 counts band(`0xB4=0x000A`).

## 4. §5.9~5.11 ATI — Target·Band·Error

### 4.1 ATI Setup (0x36) 비트 분해

코드 기입: `tdc_touch_iqs323.c` L429: `write_register(REG_SENSOR0_ATI_SETUP, 0x0C, 0x04)` → 16비트 0x040C

```
0x040C = 0000 0100 0000 1100
bits[15:4]  = 0x040 >> 0 = 64   → ATI Resolution Factor = 64
bit[3]      = 1                  → ATI Band = Large (1/8 × ATI Target)
bits[2:0]   = 100 = 4            → ATI Mode = Full (DS A.12)
```

DS `06_레지스터레퍼런스.md` A.12 인용: "ATI TARGET = ACTUAL ATI BASE × (ATI Resolution Factor / 16)"

### 4.2 ATI Target 계산 (DS §5.9 공식)

DS `02_proxfusion동작.md` §5.9:

```
ATI Target = ATI Base × (ATI Resolution Factor / 16)
           = 100 × (64 / 16)
           = 400 counts
```

- ATI Base (0x37): 코드 명시 기입 없음 → DS 기본값 `0x0064 = 100` 적용 (`06_레지스터레퍼런스.md` §9 주소표)
- ATI Resolution Factor (0x36 bits[15:4]): 64

### 4.3 ATI Band 및 Re-ATI 경계 (DS §5.10, A.12)

DS `06_레지스터레퍼런스.md` A.12:

| ATI Band 설정 | 공식 | 값 |
|---|---|---|
| Large (0x36 bit3=1) | 1/8 × ATI Target | 1/8 × 400 = **50 counts** |
| Small (0x36 bit3=0) | 1/16 × ATI Target | 25 counts |

```
Re-ATI Boundary = ATI Target ± ATI Band = 400 ± 50 = [350, 450] counts
```

DS `02_proxfusion동작.md` §5.10 인용:
> "re-ATI is performed when the channel LTA drifts outside of the ATI Band (centred on the ATI Target)"

> [!IMPORTANT]
> **비교 대상은 LTA이고 Counts 또는 delta(D)가 아니다.** `LTA ∉ [350, 450]`일 때만 Automatic Re-ATI 발동. D=39(Counts=355) 같은 delta 값은 ATI Band 판정과 무관.

DS 예시(§5.10): ATI Target=800, Large Band → band=1/8×800=100 → ATI는 LTA>900 또는 LTA<700일 때 실행.

### 4.4 ATI Error 조건 (DS §5.11 직접 인용)

DS `02_proxfusion동작.md` §5.11:

> "After the ATI algorithm has run, error checking is performed. For any channel, if the **counts is outside of the Re-ATI boundary** at the time the ATI algorithm completes, then the ATI Error bit in System Status is set."

```
ATI 완료 시점: Counts ∉ [350, 450] → ATI Error bit set (0x10 bit6)
```

> [!IMPORTANT]
> DS §5.11: "When ATI Error is set, **re-ATI is not automatically triggered**. The master must trigger re-ATI by setting the Re-ATI bit in System Control."
> → ati_error 발생 시 MCU가 `0xC0 bit2`를 수동 set 필요. 코드에서는 `tdc_touch_logic.c`의 Re-ATI 게이트(ati_error 조건)가 이 역할.

### 4.5 Automatic Re-ATI 경로 요약

| 경로 | 트리거 조건 | 자동 여부 | 코드 처리 |
|---|---|---|---|
| Auto Re-ATI (§5.10) | LTA ∉ [350, 450] | IC 자동 | ATI Event bit 폴링 |
| ATI Error → 수동 Re-ATI (§5.11) | ATI 완료 시 Counts ∉ [350, 450] | 마스터 수동 | `tdc_touch_logic` Re-ATI 게이트 |
| 부팅 명시 Re-ATI | 초기화 시퀀스 내 | SW 명시 호출 | `tdc_touch_iqs323.c` L439 `0xC0=0x54` |

## 5. §5.5 LTA — counts 추종·freeze 조건

DS `02_proxfusion동작.md` §5.5 인용:

> "LTA is updated slowly to track environmental changes and is **frozen during touch and proximity events**."

**LTA freeze 발동 조건**: `System Status(0x10)` bit9(CH0_Touch) 또는 bit8(CH0_Prox)이 set된 동안.

**IIR 갱신 공식** (DS §5.6 파생):

```
LTA_new = LTA_old + (Counts − LTA_old) × (Beta / 256)
```

**Reseed** (§5.5.1): `System Control(0xC0) bit3` set → LTA ← 현재 Counts로 즉시 동기화 → IC 자동 clear.

코드: `tdc_touch_iqs323.c` L445: `write_register(REG_SYSTEM_CONTROL, 0x58, 0x07)` (bit3 RESEED + Power No ULP + CH timeout disable 보존).

## 6. 정오 체크: 기존 분석(51·52) 재검증

| 항목 | 51/52 기재값 | DS 공식 일치 여부 | 판정 |
|---|---|---|---|
| Touch Threshold = k×LTA/256 | LTA=394, k=102 → THR≈156 (당시 상수) | DS A.17 공식 그대로 | ✓ 공식 일치 (현재 k=80 → THR≈123) |
| ATI Target = 100×(64/16) = 400 | 400 counts | DS §5.9·A.12 | ✓ 일치 |
| ATI Band [350,450] | LTA 비교 대상 | DS §5.10 | ✓ 일치 |
| LTA freeze during prox | §5.5 원문 근거 | DS §5.5 | ✓ 일치 |
| Fast Filter Band 방향 | sensing opposite = counts > LTA | DS §5.6 | ✓ 일치 |
| Beta alpha=Beta/256 | 51문서 IIR 공식 | DS §5.6 | ✓ DS 일치, 코드 설계는 AZD004 기준으로 불일치 |
| Prox threshold 기본값 0 → LTA freeze | prox thr=0 → D>0 prox 진입 | DS A.16 공식 없음 → 추론 | 기능적 결론 타당, 단위 [실측 게이트] |

> [!NOTE]
> 51/52 분석 당시 LTA Normal Beta = 16 (0xB1=0x1010). 현재 코드는 Beta=6 (0xB1=0x0606)으로 변경됨. τ(AZD004 기준): Beta=16 → 51.2s, Beta=6 → 12.8s. 현재 코드 쪽이 훨씬 빠른 LTA 추종.

## 7. 불확실 항목 (실측 게이트)

1. **Prox Threshold 단위**: DS A.16에 "8-bit value"만 명시. 절대 delta 단위로 읽히나 LTA 비례 계수 가능성 완전 배제 불가. 코드 255 설정은 어느 해석에서도 prox 무력화.
2. **Beta 해석 충돌**: DS §5.6 (Beta/256) vs AZD004 (1/2^Beta). Beta=6에서 alpha≈2.34% vs ≈1.56%, τ≈8.6s vs ≈12.8s. 코드 설계 계산은 AZD004 기준. IC 실제 동작은 실측 판별 필요.
