# 01 조사 — 코드 상수 → 레지스터 매핑 전수

> **TL;DR**: THRESHOLD=80·HYSTERESIS=8·PROX_THRESHOLD=255 는 각각 0x62·0x61 에 write. HYSTERESIS는 `(H & 0x0F) << 4` 변환(bits[15:12] 위치). Beta/Power 는 beta_power_settings()에서 일괄 write. IC가 내부 계산하는 절대임계는 레지스터 계수 × LTA / 256. SW abs_thr 계산은 디버그 표시용 미러링. Prox 단위(절대/계수) 및 Beta IIR 공식(DS vs AZD004)은 [실측 게이트].

## 1. 상수 정의 위치

파일: `tdc_touch_iqs323.h` 줄 45~53

```c
#ifndef TDC_TOUCH_IQS323_THRESHOLD
#define TDC_TOUCH_IQS323_THRESHOLD 80
/* 절대임계 = 계수 x LTA / 256 ≈ 125 @ LTA399. 8비트(0~255) */

#endif
```

## 2. THRESHOLD / HYSTERESIS → 0x62 write 경로

### 2.1 호출 경로

```
tdc_touch_iqs323_apply_settings()          [tdc_touch_iqs323.c:392]
  └─ touch_settings(TDC_TOUCH_IQS323_THRESHOLD, TDC_TOUCH_IQS323_HYSTERESIS)
                                           [tdc_touch_iqs323.c:408]
       └─ write_register(REG_CH0_TOUCH=0x62, threshold, (uint8_t)((hysteresis & 0x0F) << 4))
                                           [tdc_touch_iqs323.c:289]
            └─ i2c_write({0x62, LSB, MSB}) [tdc_touch_iqs323.c:182]
```

### 2.2 실제 전송 바이트

- **buf[0]** = 0x62 (레지스터 주소)
- **buf[1]** = 0x50 (threshold=80=0x50) → 0x62 LSB → DS A.17 bits[7:0] = **Touch Threshold 계수**
- **buf[2]** = (8 & 0x0F) << 4 = **0x80** → 0x62 MSB → DS A.17 bits[15:12] = **Touch Hysteresis 계수**

### 2.3 코드 변환 상세 (`touch_settings()`, tdc_touch_iqs323.c:284~289)

```c
static bool touch_settings(uint8_t threshold, uint8_t hysteresis)
{
    /* 0x62: bits[7:0]=Touch Threshold(LSB), bits[15:12]=Touch Hysteresis(MSB 상위 니블, DS A.17).
     * hysteresis 4비트값을 MSB 상위 니블에 위치시킨다(<<4). 이전엔 MSB 통째로 써 bits[11:8](미정의)에
     * 들어가 실제 hysteresis=0 이었던 버그 수정. */
    return write_register(REG_CH0_TOUCH, threshold, (uint8_t) ((hysteresis & 0x0F) << 4));
}
```

| 인자 | 값 | MSB/LSB | DS 비트 위치 | 분류 |
|---|---|---|---|---|
| `threshold` | 80 (0x50) | **LSB** | bits[7:0] | 레지스터에 그대로 write |
| `hysteresis` | 8 | **MSB**에 `(8 & 0x0F) << 4 = 0x80` | bits[15:12] | **코드 변환** (& 0x0F, << 4) |

> [!IMPORTANT]
> 이전 버그: MSB에 `hysteresis` 원값(8)을 직접 썼을 때 → bits[11:8]에 들어가 IC가 bits[15:12]=0으로 읽음 = hysteresis 실효 0. 현재 코드는 `<< 4`로 수정되어 bits[15:12]에 정확히 위치.

### 2.4 DS A.17이 정의하는 IC 내부 계산 (06_레지스터레퍼런스.md)

```
Touch Threshold (절대) = (Threshold_reg × LTA) / 256
                       = (80 × LTA) / 256          ← IC 내부 계산, SW는 참조만

Touch Hysteresis (절대) = (Hysteresis_reg_4bit / 256) × Touch_Threshold_절대
                        = (8 / 256) × (80 × LTA / 256)
                        ≈ 4 counts @ LTA≈400
```

- 헤더 주석 "≈5cnt"는 LTA≈400 기준 실계산(≈4cnt)과 약 1 cnt 차이. 오차 요인: LTA 정확한 값·정수 반올림.
- IC 내부에서 Touch 진입 조건 (§5.7): `(LTA - Counts) > Touch_Threshold_절대`
- IC 내부에서 Touch 이탈 조건: `(LTA - Counts) > (Touch_Threshold_절대 - Touch_Hysteresis_절대)`

## 3. PROX_THRESHOLD → 0x61 write 경로

### 3.1 호출 경로

```
tdc_touch_iqs323_apply_settings()          [tdc_touch_iqs323.c:415]
  └─ write_register(REG_CH0_PROX=0x61, TDC_TOUCH_IQS323_PROX_THRESHOLD=255, 0x00)
       └─ i2c_write({0x61, 0xFF, 0x00})
```

### 3.2 실제 전송 바이트

- **buf[0]** = 0x61
- **buf[1]** = 0xFF (255) → 0x61 LSB → DS A.16 bits[7:0] = **Prox Threshold**
- **buf[2]** = 0x00 → 0x61 MSB → DS A.16 bits[15:12/11:8] = Prox Debounce Exit/Enter = 0 (즉시)

### 3.3 설계 의도 (tdc_touch_iqs323.c:412~414 주석)

```c
/* Prox Threshold = Touch Threshold 동일 계수 → prox 진입점을 touch 진입점과 일치시킨다.
 * 약결합(터치 미만)은 prox 미진입이라 LTA 자유 수렴(흡수), 진짜 터치 진입 시에만 LTA freeze(보호).
 * 0x61 LSB=Prox Threshold(계수), MSB=Prox Debounce(0=즉시). [실측 게이트: prox 단위 절대/계수 확인] */
```

> [!WARNING]
> **[실측 게이트]**: 0x61 Prox Threshold 단위(절대 vs 계수)는 DS A.16에 "8-bit value"만 명시, 계산 공식 없음. DS A.17(Touch Settings)에서는 `(Threshold × LTA) / 256`으로 명시되지만 A.16(Prox Settings)에는 동등 공식이 없다. 코드 주석도 "실측 게이트" 표시. SW에서 `pabs_thr = (255 × LTA) / 256 ≈ LTA` 로 계산(디버그용)하지만 IC 실제 Prox 판정 단위는 실측으로만 확인 가능.

### 3.4 PROX_THRESHOLD=255 설정 효과

| 해석 | 255의 의미 | 결과 |
|---|---|---|
| **계수 방식** (Touch처럼) | Prox_절대 = 255×LTA/256 ≈ LTA (≈400) | delta > LTA 불가 → prox 사실상 무력화 |
| **절대값 방식** | (LTA-Counts) > 255 | 최대 터치 delta(≈190)로 도달 불가 → 무력화 |

두 해석 모두 prox는 사실상 비활성화. LTA freeze는 Touch 진입 시에만 발생.

## 4. Beta · Power · 기타 레지스터 write 전수

### 4.1 호출 경로

```
tdc_touch_iqs323_apply_settings()
  └─ beta_power_settings()         [tdc_touch_iqs323.c:301~317]
```

### 4.2 write 전수 표

| 레지스터 | 주소 | write 값 | LSB (NP/Low byte) | MSB (LP/High byte) | 분류 |
|---|---|---|---|---|---|
| BETA_COUNTS | 0xB0 | 0x02, 0x02 | NP_COUNTS_FILTER=2 | LP_COUNTS_FILTER=2 | 그대로 |
| BETA_LTA_NORMAL | 0xB1 | 0x06, 0x06 | NP_LTA_FILTER=6 | LP_LTA_FILTER=6 | 그대로 |
| BETA_LTA_FAST | 0xB2 | 0x02, 0x02 | NP_LTA_FAST_FILTER=2 | LP_LTA_FAST_FILTER=2 | 그대로 |
| FAST_FILTER_BAND | 0xB4 | 0x0A, 0x00 | Fast Filter Band=10 counts | — | 그대로 |
| CONV_FREQ | 0x31 | 0x7F, 0x05 | Fraction=127(고정) | Period=5 → 1MHz | 그대로 |
| SYSTEM_CONTROL | 0xC0 | 0x50, 0x07 | bits[6:4]=101=Automatic No ULP | CH0~2 Timeout Disable=0x07 | 그대로 |
| LP_REPORT_RATE | 0xC2 | 0x64, 0x00 | 100ms | — | 그대로 |
| PM_TIMEOUT | 0xC5 | 0x00, 0x00 | 0ms(모드 강하 차단) | — | 그대로 |

> [!NOTE]
> `write_register(addr, lsb, msb)` 프로토콜: i2c_write({addr, lsb, msb}). 레지스터는 little-endian 16bit → LSB=낮은 주소, MSB=높은 주소. A.26~A.28(Beta 레지스터)에서 LSB=NP, MSB=LP.

### 4.3 ATI Setup (0x36)

```
tdc_touch_iqs323_apply_settings()
  └─ write_register(REG_SENSOR0_ATI_SETUP=0x36, 0x0C, 0x04)
```

- **0x36 = 0x040C**: DS A.12 기본값과 동일
  - bits[15:4] = ATI Resolution Factor = `0x040 >> 0` ... 정확히: `0x040C`에서 bits[15:4] = 0x040 = **64**
  - bit3 = ATI Band = **1** (Large = 1/8 × ATI Target)
  - bits[2:0] = ATI Mode = **100 = Full**

ATI Target 계산:
```
ATI Target = ATI Base × (ATI Resolution Factor / 16)
           = 100 × (64 / 16) = 400 counts
```

> [!NOTE]
> ATI Base(0x37)는 코드에서 명시 write 없음 → IC 기본값 0x0064=100 의존. DS §9 기본값 표로 확인되나 리셋 후 실제 보존 여부는 실측 미확인.

### 4.4 apply_settings() 내 Re-ATI / RESEED

```c
// tdc_touch_iqs323.c:439
write_register(REG_SYSTEM_CONTROL, 0x54, 0x07)
// 0xC0 LSB = 0x54 = 0101 0100 → bit2(Re-ATI) + bits[6:4]=101(Automatic No ULP)
// 0xC0 MSB = 0x07 = 0000 0111 → CH0·CH1·CH2 Timeout Disable

// tdc_touch_iqs323.c:445
write_register(REG_SYSTEM_CONTROL, 0x58, 0x07)
// 0xC0 LSB = 0x58 = 0101 1000 → bit3(RESEED) + bits[6:4]=101(Automatic No ULP)
```

두 write 모두 Power Mode 비트(bits[6:4]=101)와 CH Timeout Disable 비트를 동시에 보존하여 단독 0x04/0x08 write가 Power Mode를 Normal(000)로 덮는 문제 방지.

### 4.5 sensor_setup() 레지스터

```c
// tdc_touch_iqs323.c:268~281
write_register(REG_SENSOR2_SETUP=0x50, 0x00, 0x00)  // CH2 disable
write_register(REG_SENSOR1_SETUP=0x40, 0x00, 0x00)  // CH1 disable
write_register(REG_SENSOR0_SETUP=0x30, 0x01, 0x01)
// 0x30 LSB=0x01: bit0=Enable Channel ON
// 0x30 MSB=0x01: bit0=CTx0 ON (self-cap: CRx0/CTx0 동일 핀)
```

### 4.6 events_enable()

```c
// tdc_touch_iqs323.c:295
write_register(REG_EVENTS_ENABLE=0xD3, 0x52, 0x00)
// LSB=0x52 = 0101 0010 → bit6=ATI_error | bit4=ATI_event | bit1=touch_event
// MSB=0x00
```

## 5. SW 계측 계산식 (디버그용)

### 5.1 노말 폴링 (tdc_touch.c:285~288)

```c
uint16_t delta    = (dbg.lta > dbg.counts) ? (uint16_t)(dbg.lta - dbg.counts) : 0;
uint16_t abs_thr  = (uint16_t)(((uint32_t) TDC_TOUCH_IQS323_THRESHOLD * dbg.lta) / 256u);
uint16_t pabs_thr = (uint16_t)(((uint32_t) TDC_TOUCH_IQS323_PROX_THRESHOLD * dbg.lta) / 256u);
```

### 5.2 절전 ULP (main.c:929~932)

동일 공식 반복:
```c
uint16_t abs_thr  = (uint16_t)(((uint32_t) TDC_TOUCH_IQS323_THRESHOLD * dbg.lta) / 256u);
uint16_t pabs_thr = (uint16_t)(((uint32_t) TDC_TOUCH_IQS323_PROX_THRESHOLD * dbg.lta) / 256u);
```

### 5.3 SW 계산식의 위상

이 계산은 **디버그 출력 전용**. IC가 실제 pressed bit를 판정하는 것은 IQS323 하드웨어 내부(0x62 레지스터 기반 IC 내부 로직). SW abs_thr은 DS A.17 공식을 미러링해 RTT 로그에 참조값을 표시하는 용도.

- IC가 판정한 결과 → `st.pressed` (System Status bit9 read)
- SW abs_thr → 로그 출력 및 `s_debug_recent_abs_thr` 저장

## 6. 상수 분류 요약

| 상수 | 값 | 레지스터 write 방식 | IC 내부 처리 |
|---|---|---|---|
| **THRESHOLD** | 80 | 0x62 **LSB** 그대로 | IC 내부: (80 × LTA) / 256 = 절대임계 |
| **HYSTERESIS** | 8 | 0x62 **MSB** = (8 & 0x0F) << 4 = 0x80 **코드 변환** | IC 내부: (8/256) × abs_thr = hysteresis 절대값 |
| **PROX_THRESHOLD** | 255 | 0x61 **LSB** 그대로 | IC 내부 판정: 단위 불확실 [실측 게이트] |
| **Beta NP LTA** | 6 | 0xB1 **LSB** 그대로 | IC 내부: IIR damping factor (공식 DS/AZD004 불일치 [게이트]) |
| **Beta LP LTA** | 6 | 0xB1 **MSB** 그대로 | 동상 |
| **Fast Filter Band** | 10 | 0xB4 LSB 그대로 | IC 내부: Counts가 LTA 대비 sensing 반대방향으로 10cnt 이상 시 Fast Beta 적용 |
| **ATI Resolution Factor** | 64 | 0x36 bits[15:4]=0x040 | IC 내부: ATI Target = 100 × 64/16 = 400 |
| **ATI Mode** | Full | 0x36 bits[2:0]=100 | IC가 MULT/COMP 자동 산출 |

## 7. 이전 분석(51/52)과 현재 코드 비교 — 재검증

| 항목 | 51/52 분석 시점 | 현재 코드 (이번 read) | 판정 |
|---|---|---|---|
| **0x61 Prox Threshold** | write 없음 → IC 기본값 0x00 → D>0이면 prox 상시 진입 → LTA freeze 3중 고착 | 255 명시 write → prox 사실상 무력화 | **변경됨** (버그 수정) |
| **LTA Normal Beta** | 0xB1=0x1010, Beta=16 | 0xB1=0x0606, Beta=6 | **변경됨** (속도 완화) |
| **LTA Fast Beta** | 0xB2=0x0202, Beta=2 | 0xB2=0x0202, Beta=2 | 동일 |
| **Hysteresis write** | 51/52에서 언급 없음 | (H & 0x0F) << 4 으로 bits[15:12] 정확히 위치 | 버그 수정 완료됨 |
| **0x37 ATI Base** | 100 (기본값) | write 없음, 기본값 의존 | 동일 |

> [!WARNING]
> 51/52 분석의 3중 고착(Prox threshold=0·LTA freeze·Channel Timeout 비활성) 중 **Prox threshold 문제는 현재 코드에서 해결됨** (PROX_THRESHOLD=255로 write). 51/52 분석 내용은 구 코드 기준이므로 현재 코드와 1:1 대응 불가.

## 8. 불확실 항목 ([실측 게이트])

1. **Prox Threshold 단위(절대/계수)**: DS A.16에 공식 없음. SW는 (255 × LTA / 256) ≈ LTA로 추정하나 IC 실제 판정 단위 미확인.
2. **Beta IIR 공식 차이**: DS §5.6에 damping = Beta/256. 코드 주석 "AZD004 α=1/2^β" (6/256 ≠ 1/64). IC 실제 구현 공식 실측 미확인.
3. **ATI Base 0x37 = 100 기본값 보존 여부**: 코드에서 명시 write 없음. IC POR 또는 리셋 후 기본값 100이 실제로 유지되는지 레지스터 덤프로 확인 필요.
4. **HYSTERESIS 실효값 ≈4cnt vs 헤더 주석 ≈5cnt**: 오차 1cnt. LTA 변동·정수 절단에 의한 것으로 추정되나 실측으로 확인 필요.
