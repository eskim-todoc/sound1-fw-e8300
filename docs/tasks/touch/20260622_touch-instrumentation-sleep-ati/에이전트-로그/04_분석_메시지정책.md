## 2. 신규 메시지 요구사항 정의

요구사항.md §2 §4 + 00_오케스트레이터-입력.md §메시지 섹션에서 확정된 4종:

## 3. 삽입 지점 결정

### 3-1. 레이어 원칙

- **logic.c**: print 0건 유지 (순수성 위반 불가).
- **tdc_touch_iqs323.c**: read/write 실패만 printe. 상태 해석 로그 추가 금지.
- **tdc_touch.c**: 디스패치 레이어 전담 — 신규 4종 모두 여기에.

### 3-2. ATI 에러 printw — 삽입 지점

**위치**: `tdc_touch.c` `tdc_touch_process()` 안, `tdc_touch_logic_step()` 호출 **전**.

read -> FSM 입력 정규화 블록(tdc_touch.c:141-148) 직후, `in.ati_error`가 참인 시점에 출력한다.

```c
/* tdc_touch.c:148 직후 (logic_step 호출 전) */
if (in.read_ok && in.ati_error)
{
    /* 게이팅: 매 폴링 도배 방지 — ati_active 중이면(ATI 진행 중) 생략 */
    if (!in.ati_active)
    {
        ci_printw("[TOUCH] ATI ERROR: LTA drift detected \r\n");
    }
}
```

**게이팅 근거**:
- `ati_active=true` 이면 IC가 이미 ATI 진행 중이므로 중복 경고 불필요.
- `ati_error=true` + `ati_active=false` 조합은 Re-ATI 게이트 조건(logic.c:140-142)과 동일 → 동반 출력이 자연스럽다.
- ati_error는 드리프트 조건이 해소되기 전 매 폴링 true → 쿨다운이 없으면 200ms마다 반복. **추가 쿨다운 게이팅이 필요한지 검토**: Re-ATI 쿨다운(2000ms=10tick)이 지나야 실제 Re-ATI가 발행되므로, 그 10tick 동안 ATI 에러 printw가 10회 출력될 수 있다. 이는 튜닝 목적(실측)에서 유용하므로 **쿨다운 없이 매 tick 출력**으로 결정. 노이즈가 심하면 별도 작업에서 추가 게이팅.

### 3-3. Re-ATI printi — 삽입 지점 및 원인 구분

**현황**: tdc_touch.c:186 `ci_printi("[TOUCH] RE-ATI (drift/stuck) \r\n")` — 게이트 Re-ATI와 stuck Re-ATI를 하나의 case로 처리.

**분리 필요성 판단**: logic.c FSM 구조상 `TDC_TOUCH_ACT_RE_ATI`는 두 경로에서 발생한다.

- 경로_1 (게이트): logic.c:140-146 — `NOT_TOUCH && !ati_active && ati_error && cooldown 만료`.
- 경로_2 (stuck stage1): logic.c:45-47 `stuck_eval()` — TOUCH 30s 후 stage 1→2.

현재 단일 case에서 두 경로를 구분할 수 없다. 구분 방법:

**옵션_A**: `tdc_touch_out_t`에 `act_reason` 필드 추가(enum: GATE / STUCK) — logic.h 변경 필요.
**옵션_B**: 현행 단일 문구 유지, 단 더 명확한 문구로 조정. 원인은 curr_state로 추론(`NOT_TOUCH`→게이트, `TOUCH`→stuck).

**결정: 옵션_B (최소 변경 원칙)**. 이유:
- logic.h 인터페이스 변경 없이 curr_state 조건 분기로 충분히 구분 가능.
- `out.action == TDC_TOUCH_ACT_RE_ATI` & `out.curr_state == NOT_TOUCH` → 게이트.
- `out.action == TDC_TOUCH_ACT_RE_ATI` & `out.curr_state == TOUCH` → stuck.

**구현 스케치**:

```c
/* tdc_touch.c:184 case TDC_TOUCH_ACT_RE_ATI: 안 */
case TDC_TOUCH_ACT_RE_ATI:
{
    if (out.curr_state == TDC_TOUCH_STATE_NOT_TOUCH)
    {
        ci_printi("[TOUCH] Re-ATI: ATI 에러 감지 → 드리프트 보정 발행 \r\n");
    }
    else
    {
        ci_printi("[TOUCH] Re-ATI: stuck stage1 → Re-ATI 강제 발행 \r\n");
    }
    (void) tdc_touch_iqs323_re_ati();
    break;
}
```

기존 `"[TOUCH] RE-ATI (drift/stuck) \r\n"` 문구는 위 두 문구로 **교체**. 기능 변경 없이 가독성·구분성 향상.

### 3-4. 주기 printd — 페르소나 02와의 통합·경계

페르소나 02(분석_계측설계)가 LTA·Counts·절대임계·Threshold/Hysteresis 원값·밴드초과 여부를 printd로 출력하는 신규 함수(`tdc_touch_iqs323_read_lta_counts()` 류)를 설계한다.

**본 페르소나(04)의 메시지정책 관점**:

- printd 출력은 **tdc_touch.c `tdc_touch_process()` 폴링 tick 안**에서 발행.
- 타이밍: `tdc_touch_logic_step()` 호출 **후**, `out` 기반 로그 블록과 같은 영역.
- read_ok인 tick에만 출력 (LTA/Counts read 추가 성공 전제).
- ATI 에러 printw(§3-2)와 주기 printd는 **같은 폴링 tick에 공존 가능** — 레벨이 달라 혼선 없음.

**소유 경계**:
- LTA/Counts read 함수 설계 → 페르소나 02 소관.
- 그 함수 결과를 tdc_touch.c에서 printd로 포맷 출력 → 본 페르소나 설계 범위.
- 계획 페르소나(11)가 통합.

**printd 포맷 제안**:

```c
/* tdc_touch.c: logic_step 후 로그 블록 안 */
if (in.read_ok)
{
    uint16_t lta    = 0;
    uint16_t counts = 0;
    if (tdc_touch_iqs323_read_lta_counts(&lta, &counts))
    {
        uint32_t abs_threshold = ((uint32_t) TDC_TOUCH_IQS323_THRESHOLD * lta) / 256u;
        bool     over_band     = (counts > abs_threshold);
        ci_printd("[TOUCH] LTA=%u Cnt=%u AbsThr=%u Thr=%u Hyst=%u st=%s %s\r\n",
                  (unsigned) lta,
                  (unsigned) counts,
                  (unsigned) abs_threshold,
                  (unsigned) TDC_TOUCH_IQS323_THRESHOLD,
                  (unsigned) TDC_TOUCH_IQS323_HYSTERESIS,
                  out.curr_state == TDC_TOUCH_STATE_TOUCH ? "TOUCH" : "NOT_TOUCH",
                  over_band ? "!OVER!" : "");
    }
}
```

> [!NOTE]
> `tdc_touch_iqs323_read_lta_counts()` 함수 시그니처·RDY 윈도우 처리는 페르소나 02 산출물에 의존. 본 설계는 해당 함수가 `bool` 반환(성공 여부)·`uint16_t *lta`, `uint16_t *counts` 출력 인자를 가진다고 가정.

## 4. 기존 printe 유지 확인

요구사항.md §4: "기존 치명 실패(I2C/write/read/apply fail)의 `ci_printe`는 디버깅 가치상 유지".

**확인 결과**: tdc_touch_iqs323.c 내 printe 총 13건, 전부 I2C 통신 실패 또는 레지스터 적용 실패 — **전부 유지**.

신규 4종 메시지에는 printe 사용 **없음**.

## 5. 게이팅 패턴 요약

| 메시지 | 게이팅 조건 | 게이팅 없으면 |
|---|---|---|
| ATI 에러 printw | `in.read_ok && in.ati_error && !in.ati_active` | 매 200ms 반복 (의도적 허용, 튜닝에 유용) |
| 게이트 Re-ATI printi | `out.action == RE_ATI && curr==NOT_TOUCH` | Re-ATI 발행 시점만 (FSM이 쿨다운 보장 — 최소 2000ms 간격) |
| stuck Re-ATI printi | `out.action == RE_ATI && curr==TOUCH` | stuck stage1 진입 시만 (30s 간격) |
| 주기 printd | `in.read_ok && lta_counts_read 성공` | 매 200ms (의도적 — 실측 튜닝용) |

## 7. 기존 tdc_touch.c:186 조정 요약

```c
/* 기존 */
ci_printi("[TOUCH] RE-ATI (drift/stuck) \r\n");

/* 신규 (두 분기로 교체) */
if (out.curr_state == TDC_TOUCH_STATE_NOT_TOUCH)
{
    ci_printi("[TOUCH] Re-ATI: ATI 에러 감지 → 드리프트 보정 발행 \r\n");
}
else
{
    ci_printi("[TOUCH] Re-ATI: stuck stage1 → Re-ATI 강제 발행 \r\n");
}
```

이 변경은 기능 변경 없음 (Re-ATI 발행 `tdc_touch_iqs323_re_ati()` 호출은 그대로). 문구·구분성만 개선.

## 8. 불확실·미확정 항목

- **ATI 에러 printw 쿨다운 필요성**: 매 200ms 반복 출력이 RTT 부담/노이즈가 된다면 별도 플래그(ati_error_was_printed 래치)로 에지 1회만 출력 패턴 적용 가능. 실측 후 판단.
- **LTA/Counts read 함수 시그니처**: 페르소나 02 산출물 확정 후 tdc_touch.c printd 포맷 세부 조정 필요.
- **Hysteresis 비트 매핑 불일치**: 요구사항.md §3 "실측 게이트" — printd에 Hysteresis 표시는 계수만, 해석 확정 전 변경 없음.
