# 분석 — 부팅 boot_ignore 해제 400ms 디바운스

**TL;DR**: 현재 logic.c:119-122는 read_ok && NOT_TOUCH 1회로 boot_ignore를 즉시 해제한다. 이를 2폴링(400ms) 연속 NOT_TOUCH로 강화하되, pressed 재발생 시 카운터 리셋, read_ok=false 시 보류(카운터 동결)하는 FSM-순수 설계를 제안한다. 카운트(2회) 방식이 ms 타임스탬프 방식보다 폴링 지터에 더 단순하고 견고하므로 권고한다.

---

## 1. 현재 해제 조건 분석

**근거 파일**: `tdc_touch_logic.c:117-137`

```c
/* --- 부팅 무시 구간 (게이트/stuck/롱터치 전 차단) --- */
if (st->boot_ignore)
{
    if (in->read_ok && curr_state != TDC_TOUCH_STATE_TOUCH)   /* 줄 119-121 */
    {
        st->boot_ignore = false;                /* 해제 (read 실패 시 보류 — 봉합) */
        out->boot_event = TDC_TOUCH_BOOT_RELEASED;
    }
    else if (curr_state == TDC_TOUCH_STATE_TOUCH
             && !st->boot_5s_warned
             && TDC_TOUCH_BOOT_WARN_MS <= (in->now_ms - st->boot_ready_ms))
    {
        st->boot_5s_warned = true;
        out->boot_event    = TDC_TOUCH_BOOT_WARN_5S;
    }
    else
    {
        out->boot_event = TDC_TOUCH_BOOT_IGNORING;
    }
    st->prev_state = curr_state;
    return;
}
```

**현재 동작 요약**:
- `in->read_ok == true` 이고 `curr_state != TOUCH`인 단 1회 tick에서 즉시 `boot_ignore = false`.
- read 실패(read_ok=false) 시에는 이 분기에 진입조차 않으므로 해제가 자동 보류된다. (주석 "read 실패 시 보류 — 봉합"이 이를 설명)
- 디바운스 메커니즘이 없다. 진동·기계적 채터·순간 통신 글리치로 1 tick만 NOT_TOUCH가 뜨면 boot_ignore가 해제된다.

**문제점**: 부팅 직후 손가락이 살짝 들렸다가 다시 눌리는 채터(순간 NOT_TOUCH)에 대응하지 못한다. 그 결과 boot_ignore가 조기 해제되어, 의도치 않은 롱터치→절전 진입이 발생할 수 있다.

## 2. 디바운스 구현안 비교

### 방안_A — 카운트(2회, 폴링 기반)

상태구조체에 `boot_release_cnt` 추가. NOT_TOUCH가 연속 2회(=400ms)면 해제, 중간에 TOUCH 재발생 시 0 리셋.

**장점**:
- 추가 필드 1개(`uint8_t boot_release_cnt`), 연산 단순.
- 폴링 주기(200ms)의 배수로 자연스럽게 정렬 — 지터가 ±수ms여도 카운트 경계를 벗어나지 않는다.
- 폴링 간격이 변경될 경우 `tdc_touch_time.h`의 `TDC_TOUCH_POLL_INTERVAL_MS`만 바꾸면 카운트 파생 매크로(`TDC_TIME_TO_CNT`)로 자동 재계산 가능.

**단점**:
- "정확히 400ms"가 아니라 "2폴링 이상(≥400ms)"이다. 주기 지터가 있으면 실제 400~410ms가 될 수 있다. 요구사항("400ms(=200ms 폴링 2회)")이 이를 명시적으로 허용하므로 문제없음.

### 방안_B — 타임스탬프(400ms ms 차분)

상태구조체에 `boot_release_start_ms` 추가. 첫 NOT_TOUCH 시 타임스탬프 기록, 이후 400ms가 경과한 시점에 해제.

**장점**:
- "400ms" 의미가 ms 단위로 정확하다.

**단점**:
- `uint32_t` 필드 4바이트 추가(카운트보다 3바이트 더 큼).
- NOT_TOUCH가 처음 뜬 시점을 "0으로 초기화되지 않은 상태"와 구별하기 위해 별도의 sentinel(예: 0=미기록) 처리가 필요해 조건문이 복잡해진다.
- 주기가 200ms 고정인 환경에서 타임스탬프 정밀도는 카운트와 사실상 동일하다.

### 권고: **방안_A (카운트 2회)**

폴링 기반 FSM에서 "N 연속 폴링"은 자연 단위다. 필드 크기, 코드 복잡도, 지터 영향 모두 카운트가 우세하며, 요구사항이 "200ms 폴링 2회"라고 직접 지정했으므로 카운트가 ground truth에 더 밀착한다.

## 3. 구체 코드 스케치

### 3-1. `tdc_touch_time.h` — 파생 상수 추가

`tdc_touch_time.h`의 `(A) 노말 모드` 블록에 아래를 추가한다:

```c
/* 부팅 해제 디바운스 — 연속 NOT_TOUCH 횟수 (요구사항: 400ms = 200ms x 2회). */
#define TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_MS  400
#define TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT \
        TDC_TIME_TO_CNT(TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_MS, TDC_TOUCH_POLL_INTERVAL_MS)  /* @200 = 2 */
```

`TDC_TIME_TO_CNT` 매크로(tdc_touch_time.h:15)는 올림 계산이므로 @200ms = 2를 정확히 산출한다.

### 3-2. `tdc_touch_logic.h` — 상태구조체 필드 추가

`tdc_touch_logic_state_t` (logic.h:64-75)에 `boot_release_cnt` 추가:

```c
typedef struct
{
    tdc_touch_state_t prev_state;
    int               read_fail_cnt;
    bool              boot_ignore;
    uint32_t          boot_ready_ms;
    bool              boot_5s_warned;
    uint8_t           boot_release_cnt;              /* 신규: 연속 NOT_TOUCH 카운터 */
    uint32_t          first_touch_ms;
    bool              long_latched;
    uint32_t          re_ati_cooldown_until_ms;
    uint32_t          stuck_anchor_ms;
    uint8_t           stuck_stage;
} tdc_touch_logic_state_t;
```

`uint8_t` 1바이트로 충분 (최댓값 2).

### 3-3. `tdc_touch_logic.c` — init 초기화

`tdc_touch_logic_init()` (logic.c:62-74)에 초기값 추가:

```c

{

    st->boot_ignore              = false;
    st->boot_ready_ms            = now_ms;

    st->first_touch_ms           = now_ms;

}
```

`tdc_touch_logic_set_boot_ignore()` (logic.c:76-81)에도 카운터 리셋 추가:

```c

{
    st->boot_ignore      = true;
    st->boot_ready_ms    = now_ms;
    st->boot_5s_warned   = false;

}
```

### 3-4. `tdc_touch_logic.c` — step() 부팅 무시 구간 교체

현재 logic.c:117-137을 아래로 교체한다:

```c
/* --- 부팅 무시 구간 (게이트/stuck/롱터치 전 차단) --- */
if (st->boot_ignore)
{
    if (!in->read_ok)
    {
        /* read 실패: 카운터 동결(리셋하지 않음), 현 tick 무시. */
        out->boot_event = TDC_TOUCH_BOOT_IGNORING;
    }
    else if (curr_state != TDC_TOUCH_STATE_TOUCH)
    {
        /* NOT_TOUCH 확인: 카운터 증가 */
        st->boot_release_cnt++;
        if (st->boot_release_cnt >= TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT)
        {
            /* 2회 연속 NOT_TOUCH → 진짜 해제 */
            st->boot_ignore      = false;
            st->boot_release_cnt = 0;
            out->boot_event      = TDC_TOUCH_BOOT_RELEASED;
        }
        else
        {
            /* 1회: 아직 보류 중 */
            out->boot_event = TDC_TOUCH_BOOT_IGNORING;
        }
    }
    else
    {
        /* TOUCH 재발생: 카운터 리셋 */
        st->boot_release_cnt = 0;

        if (!st->boot_5s_warned
            && TDC_TOUCH_BOOT_WARN_MS <= (in->now_ms - st->boot_ready_ms))
        {
            st->boot_5s_warned = true;
            out->boot_event    = TDC_TOUCH_BOOT_WARN_5S;
        }
        else
        {
            out->boot_event = TDC_TOUCH_BOOT_IGNORING;
        }
    }

    st->prev_state = curr_state;
    return;
}
```

## 4. 각 케이스별 동작 검증

| 케이스 | 폴링 시퀀스 | 결과 |
|---|---|---|
| 정상 해제 | NOT_TOUCH × 2 | tick1: cnt=1(IGNORING), tick2: cnt=2≥2 → 해제(RELEASED) |
| 채터 방지 | NOT_TOUCH → TOUCH → NOT_TOUCH × 2 | tick1: cnt=1, tick2: TOUCH → cnt=0, tick3: cnt=1, tick4: cnt=2 → 해제 |
| read 실패 보류 | read_fail → NOT_TOUCH × 2 | read_fail: cnt 동결(IGNORING), 이후 정상 2회 → 해제 |
| read 실패 후 채터 | read_fail → NOT_TOUCH → TOUCH → NOT_TOUCH × 2 | 올바르게 채터 재감지 후 2회 연속에서 해제 |
| 5초 경고 | TOUCH 5000ms 이상 지속 | cnt 항상 0(TOUCH 분기에서 리셋), boot_5s_warned=true, WARN_5S 이벤트 정상 발생 |
| 영구 TOUCH | boot_ignore=true + TOUCH 영속 | WARN_5S 후 IGNORING 계속 — 해제 없음(올바름) |

## 5. read_ok=false 처리 상세

현재 구현(logic.c:94-111)에서 read_ok=false인 경우:
- `st->read_fail_cnt++`
- `TDC_TOUCH_READ_FAIL_HOLD_CNT(10회)` 이내이면 `ACT_HOLD`로 early return — boot_ignore 블록에 **도달하지 않는다**.
- 10회 초과 시 `curr_state = NOT_TOUCH`로 강제되어 boot_ignore 블록에 진입하게 된다.

이 점이 설계에 영향을 준다:

- **hold 이내(10회 미만)**: early return으로 boot_ignore 블록 진입 불가 → 카운터 동결이 자동 보장됨.
- **hold 초과(10회=2000ms)**: `read_ok=false`이지만 `curr_state=NOT_TOUCH`로 강제. 이 경우 신규 설계의 `if (!in->read_ok)` 분기에서 카운터를 동결한다.

> [!NOTE]
> hold 초과 시 NOT_TOUCH 강제는 본래 "연결 완전 끊김"을 의미한다. 이 상황에서 boot_ignore를 해제하는 것은 바람직하지 않으므로, read_ok=false 시 카운터 동결이 올바른 처리다. hold 초과 후 IC가 복구되면 read_ok=true가 재개되고 정상 디바운스 경로를 탄다.

## 6. 회귀 무영향 보장

### 6-1. boot_5s 경고 앵커(boot_ready_ms) 영향 없음

`boot_ready_ms`는 `tdc_touch_logic_set_boot_ignore()`(logic.c:76-81)에서만 설정된다. 신규 코드는 이 필드를 읽기만 하고(5초 경고 판정), 쓰지 않는다. 따라서 기존 5초 경고 타이밍은 변경 없음.

### 6-2. 일반 TOUCH↔NOT_TOUCH 천이 무영향

신규 코드는 `if (st->boot_ignore)` 블록 내부에만 존재한다. `boot_ignore=false`인 일반 폴링에는 진입하지 않으므로 일반 터치 천이, Re-ATI 게이트, stuck 에스컬레이션, 롱터치에 전혀 영향 없음.

### 6-3. logic.c 순수성 유지

추가 필드(`uint8_t boot_release_cnt`)와 참조 매크로(`TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT`)는 각각 logic.h와 tdc_touch_time.h에서 선언된다. tdc_touch_logic.c의 include 목록(`tdc_touch_logic.h`, `tdc_touch_time.h`)에서 이미 접근 가능하므로 **신규 include 추가 없음**. HW/timer/printf 접근 0건 유지.

### 6-4. tdc_touch.c 연결층 무변경

`tdc_touch_logic_set_boot_ignore()` 시그니처 불변, `tdc_touch_out_t.boot_event` enum 불변, `TDC_TOUCH_BOOT_RELEASED` 이벤트 경로 불변. 연결층(tdc_touch.c:96-98, 162-178) 변경 없음.

### 6-5. tdc_touch_logic_init() 호출처 무변경

`tdc_touch.c:try_finish_init()` 내에서 호출되는 `tdc_touch_logic_init(&s_logic, now)`(tdc_touch.c:86)는 시그니처 변경 없음. 신규 필드는 init 내부에서 0으로 초기화되므로 외부 호출처 변경 없음.

## 8. 실측 게이트

- `TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT`는 `TDC_TOUCH_POLL_INTERVAL_MS=200`일 때 2이다. 폴링 간격이 바뀌면 상수가 자동 파생되지만, 실기에서 폴링 주기를 RTT로 확인해 200ms 가정이 성립하는지 검증 필요.
- hold 초과(read_ok=false + NOT_TOUCH 강제) 경로는 IC 장시간 응답 없음 케이스이며, 실기에서 발생 빈도가 낮다. 이 경로에서 boot_ignore가 영구 보류되는 현상이 우려되면 hold 초과 후 별도 강제 해제 로직 추가 고려(현재는 미포함, 요구사항에 없음).
