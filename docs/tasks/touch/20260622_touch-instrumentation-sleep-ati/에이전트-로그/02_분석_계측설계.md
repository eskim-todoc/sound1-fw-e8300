# 분석_계측설계 — LTA/Counts read 경로·RDY 윈도우 영향·printd 포맷

**TL;DR**: 기존 `read_status()`는 0x10만 read한다. 0x13(Filtered Counts)·0x14(LTA)를 신규 API(`tdc_touch_iqs323_read_debug`)로 추가하되, 각 레지스터는 개별 force_window_open+I2C 시퀀스 2회를 소비한다. Streaming 모드 특성상 read 추가는 윈도우 손실을 유발하지 않으며, 200ms 폴링 단위에서 3개 레지스터 총 I2C 소요(≈1.5ms)는 허용 범위다. printd 포맷 및 게이팅 제안을 포함한다.

---

## 1. 코드 현황: 기존 read 경로

### 1.1 read_status() 범위

`tdc_touch_iqs323.c:313–332`에서 `tdc_touch_iqs323_read_status()`는 **0x10(System Status) 단 1개만** read한다.

```c
bool tdc_touch_iqs323_read_status(tdc_touch_iqs323_status_t *out)
{
    uint8_t lsb, msb;
    out->ok = out->pressed = out->ati_error = out->ati_active = false;

    if (!read_register(REG_SYSTEM_STATUS, &lsb, &msb))
        return false;
    if (lsb == 0xEE && msb == 0xEE)
        return false;   /* 글리치 */
    out->ok         = true;
    out->ati_active = (lsb & (1u << 5)) != 0;
    out->ati_error  = (lsb & (1u << 6)) != 0;
    out->pressed    = (msb & (1u << 1)) != 0;
    return true;
}
```

LTA(0x14)·Filtered Counts(0x13) read 코드는 **현재 없음** (오케스트레이터 입력 §드라이버 확인). 레지스터 주소 매크로도 헤더에 미노출(모두 `.c` 내부 static `#define`).

### 1.2 read_register() 시퀀스

`tdc_touch_iqs323.c:177–208`의 `read_register(addr, &lsb, &msb)` 1회는:

1. `force_window_open()` — 0xFF Force Comm + RDY LOW 대기 (최대 45ms: `TDC_TOUCH_IQS323_MAX_WAIT_OPEN_MS=45`, tdc_touch_iqs323.h:33)
2. `i2c_write(&addr, 1)` — 주소 쓰기
3. `wait_window_closed(20ms)` — STOP → RDY HIGH 대기
4. `force_window_open()` 재호출 — 데이터 read 전 재오픈
5. `i2c_read(buf, 2)` — 2바이트 read (16-bit little endian)
6. `wait_window_closed(20ms)` — STOP → RDY HIGH 대기

총 force_window_open 2회 + I2C 왕복 2회 = **1개 레지스터 read당 2 comm window 소비**.

## 2. 신규 read 경로 설계

### 2.1 함수 시그니처

```c
/* tdc_touch_iqs323.h 공개 (tdc_ 접두어 준수) */
typedef struct {
    bool     ok;
    uint16_t lta;            /* 0x14 Channel 0 LTA (16-bit) */
    uint16_t counts;         /* 0x13 Channel 0 Filtered Counts (16-bit) */
} tdc_touch_iqs323_debug_t;

bool tdc_touch_iqs323_read_debug(tdc_touch_iqs323_debug_t *out);
```

함수는 `tdc_touch_iqs323.c` 공개 영역에 추가. 헤더에 typedef + 선언 모두 추가.

### 2.2 내부 구현 스케치

```c
/* tdc_touch_iqs323.c — 추가 매크로 (기존 내부 #define 영역 아래) */
#define REG_CH0_COUNTS  0x13   /* Channel 0 Filtered Counts (read-only, 16-bit) */
#define REG_CH0_LTA     0x14   /* Channel 0 LTA (read-only, 16-bit) */

bool tdc_touch_iqs323_read_debug(tdc_touch_iqs323_debug_t *out)
{
    uint8_t lsb, msb;

    out->ok = false;
    out->lta = out->counts = 0;

    /* Counts(0x13) read */
    if (!read_register(REG_CH0_COUNTS, &lsb, &msb))
    {
        ci_printe("[TOUCH] READ_DEBUG: COUNTS FAIL \r\n");
        return false;
    }
    out->counts = (uint16_t)((msb << 8) | lsb);   /* little endian: LSB first */

    /* LTA(0x14) read */
    if (!read_register(REG_CH0_LTA, &lsb, &msb))
    {
        ci_printe("[TOUCH] READ_DEBUG: LTA FAIL \r\n");
        return false;
    }
    out->lta = (uint16_t)((msb << 8) | lsb);

    out->ok = true;
    return true;
}
```

> [!NOTE]
> **little endian 바이트 순서**: 데이터시트 §8.5 — "16-bit data is little endian (LSB first)". `read_register()` 반환 `buf[0]=lsb, buf[1]=msb`이므로 `(msb<<8)|lsb`로 복원.
> 근거: tdc_touch_iqs323.c:100–104의 `p_buf[0]=(uint8_t)(buf[0]&0xFF); p_buf[1]=(uint8_t)(buf[1]&0xFF)`.

## 3. RDY 윈도우(스트리밍 모드) 영향 분석

### 3.1 현 통신 구조 확인

기존 분석(커밋 b689094, `20260618_touch-review/에이전트-로그/v2/11_streaming-window.md`)에서 확인된 사항:

- IQS323은 **Streaming 모드**로 운용 중 (System Control 0xC0 bit[7]=0 전수 확인)
- Report Rate 0x00(기본값 0ms) → IC가 측정 완료 즉시 RDY 토글 (수ms~16ms 추정)
- Transaction Timeout 기본값 200ms = 마스터 **무응답 시 강제 닫힘 상한** (정상 서비스 시 t_Low ≈ 0.4~0.5ms)
- CM3 폴링 주기 200ms로 IC RDY 주기보다 훨씬 길어 **폴링 시점에 윈도우는 이미 닫혀 있음**
- `force_window_open()`이 Force Comm(0xFF)으로 새 윈도우를 강제 요청하는 구조

### 3.2 추가 read 2건의 영향

기존 `read_status()`(0x10, 1 레지스터) → 신규 추가 후 순서:

| 순서 | 동작 | comm window 소비 |
|---|---|---|
| 1 | read_status() — 0x10 System Status | 2회 (force_open × 2) |
| 2 | read_debug() — 0x13 Filtered Counts | 2회 |
| 3 | read_debug() — 0x14 LTA | 2회 |
| 합계 | 200ms 폴링 1회당 | **6회** |

**윈도우 손실 위험 평가**:

Streaming 모드에서 comm window는 IC 측에서 자동으로 계속 열린다. 각 `force_window_open()`은 이전 window가 닫힌 후 **새 window를 강제 요청**하는 방식이다. 연속 read는 순차 시퀀스이므로 병렬 경쟁 없다.

I2C SCL 128kHz 기준 1 레지스터 read(주소 write 1바이트 + 데이터 read 2바이트):
- 주소 write: 약 0.1ms (START + addr + 1byte + ACK + STOP)
- 데이터 read: 약 0.2ms (START + addr + 2byte + NAK + STOP)
- wait_window_closed × 2: ≤20ms 상한이나 정상 RDY 복귀 후 즉시 탈출 (실제 ≈0.2ms 추정)
- force_window_open 대기: 0.1~45ms (RDY 열릴 때까지, 통상 다음 측정 완료까지 ≤수ms)

현실적 1 레지스터 read 소요: **약 0.5ms** (정상 응답 시). 3개 레지스터 = **약 1.5ms** 총 추가.

200ms 폴링 예산에서 1.5ms 추가는 **0.75% 부하 증가**이며 허용 범위.

> [!IMPORTANT]
> **핵심 결론**: Streaming 모드는 IC가 주기적으로 window를 자동 제공하므로, 추가 read는 단순히 force_window_open이 1회씩 더 호출될 뿐이다. "윈도우 놓침"이 문제가 되는 것은 인터럽트 기반 Event Mode에서 단일 window 내에 모든 read를 완료해야 하는 경우다. Streaming + force_window_open 구조에서는 **각 read가 독립 window를 요청**하므로 순서 문제·충돌 없음.

### 3.3 기존 RDY 윈도우 분석 문서 대조

`v2/11_streaming-window.md §4.2`에서 확인:
> "스트리밍 모드에서 200ms 폴링을 쓰는 이상 `force_window_open()`은 구조적 필수 요소"

추가 read도 동일 패턴 적용 — force_window_open으로 각 read를 독립 서비스하면 충분.

## 4. 계측 호출 삽입 지점

`tdc_touch.c`의 `tdc_touch_process()` 폴링 루프 내, read_status() 직후, FSM 입력 정규화 전:

```c
/* tdc_touch.c:141–152 영역 참조 — 아래 패턴으로 삽입 */

/* --- read -> FSM 입력 정규화 (실패 시 status 전부 false 보장) --- */
tdc_touch_iqs323_status_t st;
tdc_touch_in_t            in;
in.read_ok    = tdc_touch_iqs323_read_status(&st);
in.now_ms     = (uint32_t) now;
in.pressed    = st.pressed;
in.ati_error  = st.ati_error;
in.ati_active = st.ati_active;

/* [신규] 계측 read + printd 출력 (read_ok 시만 의미 있음) */
#if (TDC_TOUCH_DEBUG_PRINT_ENABLE)   /* 빌드가드 — tdc_touch_config.h */
{
    tdc_touch_iqs323_debug_t dbg;
    if (in.read_ok && tdc_touch_iqs323_read_debug(&dbg))
    {
        /* 절대임계 = threshold × LTA / 256 (데이터시트 §A.17) */
        uint16_t abs_thr = (uint16_t)(
            ((uint32_t)TDC_TOUCH_IQS323_THRESHOLD * dbg.lta) / 256u);

        ci_printd("[T] LTA=%u CNT=%u THR_ABS=%u(계수=%u) HYST=%u %s %s\r\n",
                  (unsigned)dbg.lta,
                  (unsigned)dbg.counts,
                  (unsigned)abs_thr,
                  (unsigned)TDC_TOUCH_IQS323_THRESHOLD,
                  (unsigned)TDC_TOUCH_IQS323_HYSTERESIS,
                  in.pressed ? "PRESSED" : "NOT",
                  (dbg.counts < abs_thr) ? "BAND_IN" : "BAND_OUT");
    }
}
#endif
```

> [!NOTE]
> 절대임계 공식: `Touch Threshold = (Threshold × LTA) / 256` — 데이터시트 §A.17(06_레지스터레퍼런스.md:398). `TDC_TOUCH_IQS323_THRESHOLD`는 tdc_touch_iqs323.h:46에 16으로 정의.

삽입 위치는 `read_status()` 바로 뒤, `tdc_touch_logic_step()` 호출 전. FSM 순수성 원칙에 따라 (logic.c에는 printf 0건 불변 — tdc_touch_logic.h:8) 연결층인 tdc_touch.c에만 위치.

## 5. printd 한 줄 출력 포맷 제안

### 5.1 포맷 설계

```
[T] LTA=<값> CNT=<값> THR_ABS=<값>(계수=<값>) HYST=<값> <PRESSED/NOT> <BAND_IN/BAND_OUT>
```

각 필드:

| 필드 | 내용 | 예시 |
|---|---|---|
| `LTA=` | 0x14 Channel 0 LTA 16-bit 원값 | `LTA=1200` |
| `CNT=` | 0x13 Filtered Counts 16-bit 원값 | `CNT=1180` |
| `THR_ABS=` | `threshold × LTA / 256` 계산값 | `THR_ABS=75` |
| `(계수=)` | `TDC_TOUCH_IQS323_THRESHOLD` 원값 | `(계수=16)` |
| `HYST=` | `TDC_TOUCH_IQS323_HYSTERESIS` 원값 | `HYST=8` |
| `PRESSED/NOT` | `in.pressed` (0x10 MSB bit1) | `PRESSED` |
| `BAND_IN/BAND_OUT` | `counts < abs_thr` 여부 — 밴드 초과 마커 | `BAND_OUT` |

**밴드 초과 마커 판정 방향**:

Self-cap 터치 시 counts 감소 방향 (데이터시트 §5.1 원문 및 02_proxfusion동작.md:51-51: "터치 시 counts 감소"). 절대임계 판정: `(LTA - Counts) > abs_thr` 이 아니라 IC 내부에서 `Counts < (LTA - abs_thr)`로 동작. 계측 출력에서는 근사 비교로 `counts < abs_thr`를 마커로 제시한다.

> [!NOTE]
> **정확한 IQS323 내부 판정식**: IC 내부 Touch 판정은 `(LTA - Counts) > threshold_abs`이며, threshold_abs = (Threshold × LTA) / 256. 계측에서 `BAND_OUT` 표시는 `(Lta - Counts) > abs_thr`로 정확하게 계산하는 것이 권장된다.

개선된 포맷:

```c
uint16_t delta = (dbg.lta > dbg.counts) ? (dbg.lta - dbg.counts) : 0u;

ci_printd("[T] LTA=%u CNT=%u D=%u THR_ABS=%u(k=%u) H=%u %s %s\r\n",
          (unsigned)dbg.lta,
          (unsigned)dbg.counts,
          (unsigned)delta,
          (unsigned)abs_thr,
          (unsigned)TDC_TOUCH_IQS323_THRESHOLD,
          (unsigned)TDC_TOUCH_IQS323_HYSTERESIS,
          in.pressed ? "P" : ".",
          (delta > abs_thr) ? "**BAND**" : "band_in");
```

`D=delta` 필드를 추가하면 LTA–CNT 차분이 직접 보여 임계 도달 여부를 한눈에 파악 가능.

### 5.2 최종 제안 포맷 (한 줄, 50자 이내)

```
[T] LTA=1200 CNT=1190 D=10 THR=75(k=16) H=8 . band_in
[T] LTA=1200 CNT=1100 D=100 THR=75(k=16) H=8 P **BAND**
```

## 6. 로그 과다·게이팅 분석

### 6.1 200ms 폴링 = 5Hz 출력 평가

200ms마다 1줄 printd = **초당 5줄**. RTT(SEGGER) 버퍼 기본 4KB 기준 줄당 60자 = 약 68줄 버퍼. 충분하나 연속 관찰 시 (10분 = 3000줄) 스크롤이 빠를 수 있다.

**적정 수준 판단**: 실측 튜닝 목적이므로 **5Hz 출력은 허용 수준**이다. 초기 관찰 후 임계 근처 이벤트만 게이팅하는 것이 합리적.

### 6.2 게이팅 옵션

```
옵션_1: 빌드가드 ON/OFF (tdc_touch_config.h)
```

```c
/* tdc_touch_config.h 추가 */
#ifndef TDC_TOUCH_DEBUG_PRINT_ENABLE
#  define TDC_TOUCH_DEBUG_PRINT_ENABLE  1   /* 1=계측 출력 활성, 0=비활성 */
#endif
```

```
옵션_2: 주기 down-sample (N회에 1회만 출력)
```

```c
static int s_debug_sample_cnt = 0;

if (++s_debug_sample_cnt >= TDC_TOUCH_DEBUG_PRINT_EVERY_N)   /* 예: 5 = 1초에 1회 */
{
    s_debug_sample_cnt = 0;
    /* printd 출력 */
}
```

```
옵션_3: 변화 시만 출력 (delta 변화율 임계)
```

변화율 감지 로직이 복잡해지므로 실측 초기에는 옵션_1(빌드가드) + 옵션_2(1초에 1회) 조합을 권장.

**권장**: 기본 `TDC_TOUCH_DEBUG_PRINT_ENABLE=1`, `TDC_TOUCH_DEBUG_PRINT_EVERY_N=1`(200ms마다 출력). 튜닝 완료 후 `ENABLE=0`으로 한 번에 비활성화.

## 7. Hysteresis 비트 매핑 관측 방법

### 7.1 0x62 비트 레이아웃

데이터시트 §A.17 (06_레지스터레퍼런스.md:397–398):

| 비트 | 필드 | 공식 |
|---|---|---|
| `[15:12]` (MSB 상위 4비트) | Touch Hysteresis | `Hysteresis = (Hysteresis_coeff / 256) × Touch_Threshold_abs` |
| `[7:0]` (LSB) | Touch Threshold | `Threshold_abs = (Threshold_coeff × LTA) / 256` |

현재 코드 `apply_settings()` → `touch_settings(TDC_TOUCH_IQS323_THRESHOLD, TDC_TOUCH_IQS323_HYSTERESIS)` = `touch_settings(16, 8)`.

`touch_settings(threshold, hysteresis)` = `write_register(REG_CH0_TOUCH, threshold, hysteresis)` (tdc_touch_iqs323.c:263–265).

`write_register(addr, lsb, msb)` = I2C 순서: [addr, lsb, msb]. 따라서:
- LSB(바이트 1): threshold = 16 = 0x10 → 비트[7:0]
- MSB(바이트 2): hysteresis = 8 = 0x08 → 비트[15:8]

**비트 매핑 불일치 가능성 [실측 게이트]**: 데이터시트 §A.17은 `[15:12]`에 Hysteresis 4비트이지만, 코드는 hysteresis=8을 MSB 전체(8비트)에 쓴다. 0x08은 `00001000`이므로 bit[11]에 1이 있다 → §A.17의 `[15:12]` 필드에는 `0000`이 들어가고 bit[11]=1은 reserved 영역이 된다.

### 7.2 관측 방법

계측 printd에 hysteresis 원값(8)을 그대로 표시하면 read 없이도 write 값을 확인할 수 있다. 실제 IC 내부 동작의 hysteresis 효과는 터치 해제 임계가 터치 진입 임계보다 좁아지는 것으로 나타난다.

**관측 방법**: 터치 진입(BAND_OUT → `D > THR_ABS`) 후 손 때다가 해제되는 delta값을 기록. 해제 시점 delta가 `THR_ABS - (Hysteresis_abs)` 수준이면 hysteresis가 정상 동작 중.

## 8. 설계 결론 요약

| 항목 | 결론 |
|---|---|
| 신규 API | `tdc_touch_iqs323_read_debug()` — 0x13·0x14 각 1회 read_register(). tdc_ 접두어 준수 |
| I2C 시퀀스 | 기존 read_register() 그대로 활용 (force_window_open × 2 per reg) |
| RDY 윈도우 영향 | Streaming + force_window_open 구조에서 추가 read = 독립 window 요청. 충돌 없음 |

| 삽입 위치 | tdc_touch.c 내 read_status() 직후, tdc_touch_logic_step() 전 |
| printd 포맷 | `[T] LTA=%u CNT=%u D=%u THR=%u(k=%u) H=%u <P/.> <**BAND**/band_in>` |
| 빌드가드 | `TDC_TOUCH_DEBUG_PRINT_ENABLE` (tdc_touch_config.h, 기본 1) |
| 게이팅 | 초기 200ms마다 출력. 튜닝 완료 후 `ENABLE=0` |
| Hysteresis 관측 | 해제 delta값 추적으로 실동작 관측. 비트 매핑 정합 [실측 게이트] 유지 |

---

## 9. 미확정·실측 게이트 항목

- **force_window_open 실제 대기 시간**: 코드 상한 45ms이나 정상 응답 시 실측값 미확인. RDY 주기(측정 완료 속도)에 의존.
- **I2C 부하 합산 실측**: 1.5ms 추정은 SCL 128kHz + overhead 기준 추정값. 실기 논리분석기 측정 권장.
- **Hysteresis 비트 매핑 정합**: write 값 8(0x08)이 bits[15:12] vs bits[11:8] 중 어디에 배치되는지 실기 write-back read로 확인 필요. [실측 게이트].
- **self-cap 터치 시 counts 방향**: 감소 방향 가정(데이터시트 §5.1) — 실기 터치 시 counts값 확인으로 검증.
