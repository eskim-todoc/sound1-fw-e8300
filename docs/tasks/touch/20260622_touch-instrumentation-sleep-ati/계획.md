# 계획: 터치 계측·절전 Full ATI 정합 + 부팅 디바운스 + 메시지 정책

**TL;DR**: 6개 소스 파일 최소 변경(P0~P4). ① 절전 `apply_sleep_settings()`의 `0x62=0xFFFF`(threshold 255 무감) 제거 → 운용 임계(16/8) 유지로 절전 중 정상 감지 ② 신규 `tdc_touch_iqs323_read_debug()`로 LTA(0x14)·Counts(0x13) read → 200ms 계측 printd ③ boot_ignore 해제 400ms(2폴링) 디바운스 ④ ATI=printw·Re-ATI=printi 정책. `logic.c` 순수성·공개 API·기존 printe는 회귀 경계로 보호. **검증 적출 4건 반영 완료**.

> [!IMPORTANT]
> 본 계획은 페르소나 7노드(분석4·계획1·검증2) 산출을 종합하고, adversarial/회귀 검증의 치명 3건 + 경계 1건을 반영해 정정한 최종본이다. 단계 ④(구현)는 §6 결정사항 사용자 승인 후 진입한다.

## 2. 단계 순서

- **P0** (선행): `tdc_touch_time.h`·`tdc_touch_config.h` 매크로 추가 → 빌드 확인
- **P1** (P0 병행 가능): `apply_sleep_settings()` `touch_settings(255,255)` 제거 + 주석 갱신 → 빌드
- **P2** (P3 선행): `read_debug()` API — 헤더 typedef/선언 + `.c` 구현(§3 CRIT-01 완화 반영) → 빌드
- **P3** (P0+P2 후): `tdc_touch.c` ATI printw + 계측 printd(#if) + Re-ATI printi 분기 → `ENABLE=0` 조건부 빌드도 확인
- **P4** (P0 후, 독립): `tdc_touch_logic.{h,c}` 디바운스 → 빌드
- **정적 검증** → **실기 검증(RTT)**

## 3. 검증 적출 반영 (치명 3 + 경계 1)

| 적출 | 출처 | 반영 |
|---|---|---|
| 🔴 `over_band` 수식 오류 (`counts > abs_thr`는 항상 true) | adversarial | **`delta=(LTA>Counts)?LTA-Counts:0; over_band=(delta>abs_thr)`** 채택(분석02). self-cap 터치=counts 감소→delta 증가 방향 |
| 🔴 `ci_printe` 기준 13건→**실제 18건** | adversarial | 정적 검증 기준값 `18 + read_debug 2 = 20건`으로 정정 |
| 🔴 CRIT-01: read 3회 직렬 최악 270ms > 200ms 폴링 | 회귀 | **0x13~0x14 연속 auto-increment 1-window read**로 status 외 1 window만 추가(2 window 총량). window 대기 타임아웃 시 계측만 skip(read_ok·FSM 무영향). 실기 RTT 타임스탬프로 폴링 간격 실측 |
| dead code: `if(!read_ok)` 분기 도달 불가 | 회귀 | 디바운스 블록에서 해당 분기 제외(상단 read 실패 return이 선처리) |

> [!NOTE]
> CRIT-01 완화의 핵심: 0x13(Counts)·0x14(LTA)는 인접 주소이므로 IQS323 auto-increment read로 **한 통신 윈도우에 4바이트 연속 read** 가능 여부를 구현 시 데이터시트(§8 I2C)로 확정한다. 가능하면 추가 window는 1회(≈최악 90ms)로 제한된다. 불가 시 fallback은 §6 결정 Q-A 참조.

## 6. 승인 전 결정사항

> [!WARNING]
> 아래 결정 후 단계 ④(코드 변경) 진입. 권장안은 각 항목에 표기.

- **결정_1 (절전 임계, 크리티컬)**: threshold=255 제거 후 **운용 임계 16 그대로**(권장, 분석01·검증 REAL) vs 절전 전용값(예 32) 별도. 후자는 `apply_sleep_settings()`에 절전 threshold write + 복귀 경로 필요.
- **결정_2 (CRIT-01 fallback)**: 연속 auto-increment read가 데이터시트상 불가로 판명될 경우 — (가) 계측 read를 저빈도(예 1초=5폴링)로 분리(권장) vs (나) window 대기 상한을 계측용으로 짧게(예 5ms) 두고 초과 시 skip.
- **결정_3 (Re-ATI 중 ULP touch_cnt 동결)**: 절전 ULP 루프에서 ati_active 구간 롱터치 카운터 리셋 방어를 **이번 분리**(권장, Re-ATI 빈도 미확인·main.c 변경 회피) vs 이번 포함(main.c 변경).
- (정보) 출력 방식: 계측 printd·ATI printw는 **실측 유리하게 매 200ms 출력**으로 진행(튜닝 후 `ENABLE=0`/래치로 축소). 이의 시 알려주십시오.

## 7. 절전 진입 무한 스턱 해소 (후속 — 실측 중 발견)

### 7.1 문제
`func_sleep` 진입 초입(main.c:835~843)의 "터치 해제 대기" 루프가 `st.pressed` 동안 `SYS_WATCHDOG_REFRESH()+delay_ms(100)`로 **무한 대기** → 손을 안 떼거나 임계 오인 시 ULP 루프 진입조차 못 함. ULP 루프(904~)는 이미 "터치 11회 연속(2.2s)→재부팅" 탈출구가 있어 진입만 하면 스턱이 없음.

### 7.2 설계 (ULP 루프 boot_ignore 철학 재설계 — 사용자 승인 2026-06-22 Rev2)
절전 = 노말과 동일 IQS323 설정 사용 → **`apply_sleep_settings()` 제거**(CM3 클럭만 `ci_power_sleep`로 절감, `is_ulp` 플래그는 읽는 곳 0건이라 무관). 진입 release 대기·진입 reseed는 이미 제거(Rev1).

ULP 루프를 부팅 boot_ignore 철학으로 재작성:
- **게이트(`sleep_ignore`)**: 진입 직후 ~ 첫 **400ms(2폴링) 연속 노터치** 확정까지 터치 무시(손 댄 채 진입 대응).
- **노터치 확정 시**: RESEED 1회(절전 노터치 baseline 동기) 후 게이트 해제.
- **무한 스턱 방지**: 노터치가 **10초(50폴링)** 넘게 확정 안 되면(계속 터치/오염) **강제 RESEED**로 현재 상태를 baseline 끌어와 탈출(이후 NOT_TOUCH 유도). 재시도 가능.
- **게이트 해제 후**: **400ms 연속 터치** 시 `SYS_WATCHDOG_RESET()` 재부팅 → 노말 복귀(30/60/90 stuck·기존 2.2s 카운트 불요).
- read 실패: 노터치/터치 카운터 리셋(보류). 단 게이트 지속 시간(10초 기준)은 계속 누적.

### 7.3 회귀 경계
- ULP 루프 롱터치 재부팅 카운트·주기 불변. reseed는 1회만(절전 중 Beta가 LTA 추적).
- 손 떼있으면 첫 NOT_TOUCH에 reseed → 정상. 손 댄 채면 재부팅으로 탈출(reseed 미실행 무방).
- reseed 전 단일 샘플 오판 위험은 NOT_TOUCH 1회만 잡히면 즉시 해소(11회 한참 미만).

### 7.4 검증
- 실기: ① 절전 진입 시 손 안 떼도 스턱 없이 ULP 진입 ② 손 떼면 첫 release에 RESEED 로그·정상 절전 ③ 손 댄 채 2.2s 유지 시 재부팅 ④ 무한 `WAIT TOUCH RELEASE` 도배 소멸.
