# 분석 — CRX1 더미 채널 실측 실패 원인 및 재설계

> **TL;DR**: DUMMY(Internal Reference 방식)+DISCHARGE 실측 결과, 초기화 중 `0x43`에 reserved 위반값(`0x0020`)을 써서 IC 통신이 먹통이 됐고 연쇄로 전 설정 미적용→오감지→자동 절전됐다. Internal Reference는 온도/전류 측정용임이 확정됐고, 올바른 수단은 **내부 CalCap**으로 결정했다.

상세 데이터시트 레퍼런스: [[iqs323-register-map]] (`docs/참고/touch/레퍼런스/IQS323-레지스터-맵.md`)

---

## 1. 실측 환경

- 설정: `TDC_TOUCH_CRX1_DUMMY_ENABLE=1` + `TDC_TOUCH_CRX0_DISCHARGE_ENABLE=1`
- 로그: `tests/CRX1 Dummy, CRX0 Discharge 로그.md`
- 증상(사용자 보고): "초기화를 실패하다가, 그 후에는 터치가 된 것으로 간주되고, 이후 스스로 절전모드에 빠져버렸다."

---

## 2. 실패 원인 체인 (RTT 로그 기반)

| 로그 라인 | 이벤트 | 해석 |
|---|---|---|
| 33 | `WRITE 0x40: LSB=0x01 MSB=0x01` | Sensor1 enable — **성공** |
| 35 | `WRITE 0x43: LSB=0x00 MSB=0x20` | Prox Input에 reserved 위반 값 — i2c 쓰기는 나갔으나… |
| 37-38 | `force_window_open() TIMEOUT (45 MS)` | verify read 단계에서 IC가 RDY 윈도우를 안 엶 |
| 41 | `READ 0x43: WINDOW OPEN FAIL` | write_and_verify 실패 → SENSOR SETUP FAIL |
| 44~94 | TOUCH SETTINGS·EVENTS·ATI·RESEED·DISABLE CH 전부 FAIL | IC busy 지속 → 후속 설정 도미노 실패 |
| 95 | `INIT FINISH DONE ELAPSED=447ms` | 설정 미적용 상태로 초기화 "완료" 선언 |
| 96~99 | `WRITE 0x30: 0x02→0x01` 반복 (timeout 없음) | CH0 discharge는 동작 — IC가 자연 회복 |
| 100→121 | `RESET→NOT_TOUCH→TOUCH` | 손 안 댔는데 오감지 (baseline 엉터리) |
| 151~152 | `LONG TOUCH → POWER BUTTON PUSHED` | 2.8초 오터치 → 전원 버튼 인식 |
| 172-173 | `GO TO SYSTEM OFF / ENTERING SLEEP` | 스스로 절전 진입 |

핵심: **`0x43` 쓰기 한 줄**이 전체 초기화를 무너뜨렸다. `0x40`(Sensor1 enable) 자체는 성공했기에 그 이후 CH0 discharge·터치 감지는 동작했지만, touch threshold·ATI 보정값이 IC 기본값으로 방치되어 baseline이 깨졌다.

## 3. 근본 원인 가설 cross-check (≥3)

| 가설 | 검증 | 결론 |
|---|---|---|
| 가설_1: Internal Reference가 즉시 ATI 재보정을 트리거해 IC busy | §5.10 자동 re-ATI 존재. 측정 비정상 시 발동. 기여 가능 | △ 부분 기여 |
| 가설_2: `0x43`의 reserved 비트(bit7=1, bit1-0=11) 위반으로 IC 동작 미정의 | reset=`0x01CF`인데 `0x0020`은 bit7·bit1-0을 0으로 깸. 데이터시트 "Set to 1/11" 강제 위반 | ✅ **직접 원인** |
| 가설_3: write_and_verify의 verify read가 ATI 윈도우와 충돌 | §(P21) "ATI 중 통신 윈도우 계속 열면 ATI 더 길어짐" | △ 증상 악화 요인 |
| 가설_4: Internal Reference 비트 자체가 더미 채널 기능이 아님 | §5.12.2 — 온도/전류 측정용, 부정확, 대개 비활성 권장 | ✅ 설계 전제 오류 |

→ **직접 원인은 가설_2(reserved 비트 위반)**, 설계 전제 오류는 가설_4. 가설_1·3은 증상을 악화시킨 보조 요인.

---

## 4. 재설계 결정 — CalCap 더미 채널

Internal Reference 방식 폐기. 외부 CRX1 핀(C52 부착)과 무관하게 CH1을 살리는 올바른 수단은 **내부 CalCap을 변환 부하로 사용**하는 것이다(§5.12.1·5.12.3).

근거:
- 외부 핀 무관 — 변환 경로가 IC 내부에서 닫힘 → C52 유무·쇼트와 독립
- 고정 부하 → ATI 수렴 안정적 → `ATI_ERROR` 위험 낮음
- 더미 채널의 목적(활성 채널 존재로 measurement cycle 유지)에 부합

남은 불확실성(실측 확정 필요):
1. CalCap Select(0x43 bit11) 의미가 데이터시트 내 상충 (A.9 vs §5.12.3)
2. CalCap 정식 측정 채널 용법 미보증("debugging용")
3. 외부 CRx와 CalCap Rx 동시 선택 우선순위 미명시

상세는 [[iqs323-register-map]] §9 참조.

---

## 5. 핵심 교훈

> **레지스터 쓰기 값은 reset value를 베이스로 산출하고 바꿀 비트만 조작한다.** 0부터 비트를 쌓으면 reserved 비트를 누락한다. 이번 먹통의 근본 원인이며, CalCap 설계의 모든 값은 이 원칙으로 산출했다.
