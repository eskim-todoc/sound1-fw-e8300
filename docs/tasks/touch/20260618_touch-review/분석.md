## 2. 현재 동작 시퀀스 (코드 확정)

### 부팅·노말
1. `initialize.c:449` `mclr_reset()` 무조건 실행 → 매 (웜)부팅 IC POR (웜부트 상태 보존 없음, B4 반증).
2. `write_ati_compensation()`: ATI Setup `0x36` LSB=`0x08`(bits[2:0]=000 = **ATI Mode Disabled**), FIXED MULT/COMP write (`iqs323.c:651`, `:700~735`). → 자율 auto-ATI 결과는 덮어써져 버려짐.
3. `apply_settings()` 말미 **RESEED 무조건 발행** — `write_register(0xC0, 0x08, 0x00)` (`iqs323.c:1146`). 게이트 없음.
4. `tdc_touch.c` READY 전이 직후 `s_boot_touch_ignore` 가드(`:46`/`:323`/`:352`) — 전이 시점 TOUCH면 플래그 set, 해제까지 폴링 억제 (사전+사후 혼합 방어).
5. 200ms 폴링: `tdc_touch_process()`(`touch.c:422`) 내 `discharge_crx0()` 매 호출 — `0x30`에 `0x02`(CRX0 VSS) write 후 `0x01` 복원 (`iqs323.c:955`/`:960`).

### 절전
- `func_sleep()`: `apply_sleep_settings()`(`main.c:944`) → `ci_power_sleep()` 클럭 강하(`:948`) → `tdc_drv_iqs323_reseed()`(`:952`) → 내부서 SLEEP 감도·Prox Threshold 설정 후 **RESEED 재발행**(`iqs323.c:955~957`).

|---|---|---|
| **A. 진입 baseline 오염** | RESEED 무조건 발행 2곳: `iqs323.c:1146`(노말), `iqs323.c:955`(절전, `main.c:952`서 호출) | 터치 중 부팅/모드전환 시 RESEED가 터치 counts로 LTA를 seed → 손 떼도 delta≈0 → 미인식 |

## 7. 쟁점·실측 의존 (계획에 반영)

- ATI Full 재활성은 **현 펌웨어가 폐기한 I²C 무응답**을 재현할 수 있음 → I²C 통신관리(ATI_Active 폴링·ATI_Error 핸들러·타임아웃 복구) 선행 필수. 현재 `ati_error`는 무시 경로(`crx1-esd-guard` 중단 작업서 도입).
- BETA 부호 세만틱(큰 값=빠른 추적?)·방전 물리 효력·오염 실채널은 **실측 게이트**로만 확정 → 계획은 실측 의존 단계를 명시 분리.
- 방전 코드(`discharge_crx0`)의 `0x30 0x02`가 데이터시트 A.5에서는 Linearise 해석 → 실칩 매핑 실측(실측1) 전 폐기 금지.

## 8. 은수님 retry-and-count 전략 검증 (8 페르소나 오케스트레이션, 2026-06-18)

은수님 제안("ATI Full I2C 실패를 복잡 핸들러 대신 실패=auto-ATI 간주 재시도 + 10회 연속 실패면 고장 판정")을 8 페르소나(분석5·반증2·수렴1)로 검증. 전 노드 `에이전트-로그/v1/01~08` + `인덱스.md`.

### 판정표

| 항목 | 판정 | 근거 |
|---|---|---|
| 가정_1 (auto-ATI 중 I2C 실패) | **타당** | RDY window 미열림, DS §8.4 "I²C disabled during ATI", `force_window_open()` 타임아웃 false (02노드) |
| 가정_2 (터치 중 auto-ATI 미동작) | **조건부** | 정상 터치 인식 후만 성립. 부팅 터치(RESEED 오염 직후)는 미인식→freeze 없음→LTA drift→Re-ATI 발동. **freeze ≠ Re-ATI 트리거**(은수님 혼동 가능) (03노드) |
| 전략 (실패=auto-ATI 간주 재시도) | **구조적 결함** | 현 `is_auto_ati_done_single_read`가 통신실패↔ATI진행을 둘 다 false로 미구분 → 3-상태 확장 필요 (02·05노드) |
| 판별 (10회 연속=고장) | **부분 기각** | burst 시간상관 함정(p¹⁰ 독립가정 오류). POR auto-ATI ~1.5초가 100ms 기준 15회 연속 실패 → 정상 부팅을 고장 오판 (04노드) |

### 핵심 갈림길 — ATI Full 도입 vs FIXED 유지 (06노드 허점_2)

> [!IMPORTANT]
> 7개 노드 전부가 "ATI Full 도입"을 기정사실로 가정했으나, **"FIXED 유지(현 상태)만으로 Sound1 현장에서 충분한가"는 아무도 검증하지 않았다.** FIXED 유지 시 I2C 블로킹 문제는 원천 제거된다(auto-ATI 없음). 이 질문이 retry-count 논의 전체의 **상위 분기**다 — FIXED가 충분하면 Phase 1a·2·retry-count 논의 자체가 불필요.

### ATI_Error 영구먹통 경로 (06노드 허점_3 — 신규 발견)

ATI_Error(0x10 bit6) set → ATI_Active=0(ATI 종료, 단 실패) → RDY window 재개방 → `read_status` 성공(true) → 카운터 안 오름 → 현 `ati_error`는 `(void)` 무시(`touch.c:393`) → 수동 Re-ATI(`0xC0` bit2) 발행 주체 없음 → **잘못 보정된 IQS323 영구 동작**. retry-count·ATI_Active 폴링 **둘 다 이 경로를 막지 못함** → ATI_Error 전용 핸들러 필수.

### retry-and-count 최종 판정: **조건부 채택** (5개 필수 보완 후)

1. **보완_1(최우선)**: ATI_Error 전용 핸들러 — `(void) ati_error` 무시 제거 후 수동 Re-ATI(`0xC0` bit2 / `re_ati_trigger()`) 연결. 영구먹통 차단.
2. **보완_2**: READY 전이 후에만 카운터 시작 (POR auto-ATI 구간 제외) — FM-01(Critical) 차단.
3. **보완_3**: K값을 t_ati 실측 후 `K > ceil(t_ati_max / T_read) + 마진` 산정 (임시 K=7 @200ms).
4. **보완_4**: read 실패 중 **NOT_TOUCH 명시 강제** (묵시적 hold-last는 FM-05 stuck-touch 롱터치 오발 위험).
5. **보완_5**: `is_auto_ati_done_single_read()` 3-상태 확장(통신실패/ATI진행/성공).

> 06노드 "결합 상보성 허위" 비판은 **보완_1 이행 후 무효화** — ATI_Error 핸들러가 있으면 ATI_Active 폴링(1차)+retry-count(안전망) 결합이 ~19줄 비용으로 최적(08노드).

## 9. v2 재검증 — RDY 윈도우·스트리밍·FIXED LTA delta (에이전트-로그 10~17, `Workflow`)

은수님 추가 입력 3건(통신 윈도우 비용·스트리밍·ATI/LTA)을 명제 G~J로 `Workflow` 도구 8 페르소나 재검증(effort high 실제 적용). 전 노드 `에이전트-로그/v2/10~17` + `v2/00_오케스트레이터-입력-v2.md`.

### 명제 G~J 최종 판정

| 명제 | 내용 | 판정 | 근거 |
|---|---|---|---|
| 명제_G | 통신 윈도우 폐쇄·재개방 비용 큼 | **참** | `read_register()` 1회 = `force_window_open()` **2회**(`iqs323.c:233·246`), 최악 130ms. 원인은 "스트리밍+폴링 주기 불일치" |
| 명제_H | 스트리밍 200ms 윈도우 → force 불필요 | **거짓(전부)** | 200ms는 무응답 watchdog 상한(DS §8.8), 정상 t_Low≈0.5ms. RDY 주기(수 ms) vs 폴링(100~200ms) 불일치로 force 구조적 필수 |
| 명제_I | auto-ATI = Re-ATI 동일어 | **조건부 참** | 동일 ATI 알고리즘, 트리거 경로 다름(auto-ATI=POR 강제 1회 / Re-ATI=LTA drift 조건부) |
| 명제_J | FIXED + LTA delta로 threshold 유효 | **조건부 참** | 판정식 `(LTA−Counts) > Threshold`는 ATI 모드 무관(DS §5.7), 정상 counts 범위서 유효. **단 counts 포화(Max Counts 근접) 시 delta<threshold → 침묵 실패** |

### 은수님 질문 직접 답

- **(2-1) 통신 윈도우 비용 큰가**: ✅ **크다**. read 1회마다 `force_window_open` 2회(최악 130ms = 45+20+45+20). 근본 해결 = **Event Mode + 인터럽트 전환**(force 비용 0).
- **(2-2) 스트리밍이면 force 불필요한가**: ❌ **아니오**. 200ms는 무응답 watchdog 상한이지 윈도우 개방 유지 시간(t_Low≈0.5ms)이 아님. 현 폴링 구조에선 force 필수. (Event Mode 전환 시에만 비용 소멸)
- **(3) auto-ATI=Re-ATI인가**: △ 알고리즘은 같으나 트리거 경로 다름. "전원 ON 터치 시 auto-ATI 수행"은 **맞음**(터치 중 수렴 실패=timeout이 정상 처리).
- **(3-1) FIXED LTA delta로 유효한가**: △ **정상 counts 범위에선 유효**(은수님 직관 맞음 — 판정식이 ATI 독립). **단 counts 포화 근접 시 침묵 실패** → Max Counts 실측(실측_V2) + 포화 감지 필요.

### 갈림길·전략 갱신 (계획.md Rev.2 반영)

- **FIXED 유지도 counts 포화 감지 stub(Phase 0) 없으면 불완전** — 실측_V2(Max Counts)를 FIXED 결정 선행 게이트로 추가. 명제_J 신뢰도 "참 → 조건부 참" 격하.
- **Event Mode 우선순위 격상**: 통신 비용(명제_G)의 근본 해법, DS §8.11.2 제품 권장 → Phase 3 우선순위 재검토.
- retry-count v1 5보완 유효 + K 산정에 **force 이중 타임아웃(130ms) 반영**, 절전 클럭 타임아웃 분기 검토, **보완_1(ATI_Error 핸들러) 필수성 강화**(E-2 연쇄 = 사실상 서비스 불능).

## 10. v3 — Fixed+Auto-ATI 하이브리드 아키텍처 (53에이전트 오케스트레이션, 2026-06-19)

은수님 지시(Fixed+Auto-ATI 조합 100% 근접)로 `Workflow` 균형 구조(분석8→계획8→검증8 + adversarial 8×3회 재검증, 53에이전트·553만토큰) 수행. 전체 결론은 [`에이전트-로그/v3/99_최종종합.md`](에이전트-로그/v3/99_최종종합.md).

### 확정 아키텍처 (수렴 — 32 adversarial 노드 기각 0)

> **"공장 절대 기준으로 노터치를 판별하고, 노터치가 확인된 순간에만 Re-ATI를 허용한다."**

5층: ① Fixed 기저(공장 MULT/COMP 매 부팅) → ② 노터치 게이트(공장 noTouch 절대기준으로 RESEED/Re-ATI 판별) → ③ 조건부 Re-ATI(게인+baseline 재보정) → ④ 자기치유(LTA IIR, Beta POR 실측 의존) → ⑤ 크래들 race 소멸. **절전 복귀=재부팅이라 절전/부팅 baseline 통합 처리.**

### 🔴 즉시 실행 버그 2건 (코드 확정 — 현장 영향)

| 버그 | 위치 | 내용 | 수정 |
|---|---|---|---|
| **버그_1** | `iqs323.c:581~623` `wait_re_ati_done()` | 10회 루프 내 `SYS_WATCHDOG_REFRESH()` **0건** → 최악 ~2.3초 blocking 중 **WDT 리셋 위험**. `ATI_CALIB_MODE` 경로(`iqs323.c:860`)서 호출 중 = 잠재 현장버그 | 루프 내 `SYS_WATCHDOG_REFRESH()` 삽입 (WDT timeout 확인_19) |

### Ground Truth 추가 (§4 보강)

- `tdc_drv_iqs323_is_auto_ati_done()` 공개 API `iqs323.c:926` 존재
- CH_TIMEOUT 이중 차단 이유 `iqs323.c:1152~1155` 주석 명시
- `MAX_WAIT_MS_FOR_WINDOW_CLOSE=20ms`(`.h:32`) → `wait_re_ati_done()` 최악 ~2.3초
- `TDC_BOARD_VARIANT`별 MULT/COMP 다중화(`iqs323.c:651~735`), `apply_sleep_settings()` 독립 SLEEP_ATI 경로(`:657~690`)

### 근본 인식 — Cold-Start Ambiguity

부팅 시 미지수 2개(보드 기준·터치 여부)·식 1개 = 불능 → 공장 절대 기준 없이 SW로 근본 해소 불가. **100% 완벽은 cold-start race의 물리 원리상 불가, 다층 방어로 실사용 무시 가능 수준이 목표.**

### ATI 실패 조건 + 환경 민감도 (데이터시트 전수 조회, 2026-06-19)

**ATI_Error 조건 (§5.11)**: ATI 완료 후 어느 채널이든 counts가 `Re-ATI Boundary = ATI Target ± ATI Band` 밖이면 set, **자동 재시도 없음**(수동 `0xC0` bit2). ATI Band = Target/16(Small ±6.25%) 또는 Target/8(Large ±12.5%). Sound1(Target=400, Large) → **350~450 밖이면 실패**.
- MULT/COMP 보정 범위: COMP Value 10-bit(0~1023)+Divider 5-bit(A.14), **MULT 수치 범위는 데이터시트 미명시(AZD004 §4.4)**. 외부 정전용량 한계: Self-cap 권장 max **400pF**(§3.2), 초과 시 ATI 수렴 불가는 논리적이나 정량 미명시.
- **터치 중 ATI**: 터치로 counts 낮아진 상태 → ATI가 Target까지 못 올림 → **하향 이탈 → ATI_Error**(§5.4 counts∝1/C + §5.11 조합). 터치 부팅이 대표 실패 케이스.

**환경 민감도 정량 — 데이터시트에 전혀 없음**:

| 항목 | 데이터시트 |
|---|---|
| 온도계수(counts/°C) | ❌ 미명시 |
| 전압(배터리)→counts | ❌ 미명시 |
| 터치 Δcounts 가이드 | ❌ 미명시 |
| 동작 온도 / VDD 범위 | -40~85°C / 1.71~3.6V (명시) |

> [!IMPORTANT]
> **드리프트 마진의 데이터시트 근거 부재 확정**: 온도·전압·터치 Δ 민감도 정량이 데이터시트에 일절 없다(정량 대신 Reference UI §7.3 + 앱노트 AZD004/AZD125 안내). 따라서 노터치 게이트 윈도우(MARGIN_STRICT/UP)·FACTORY_NOTOUCH_COUNTS는 **반드시 실보드 실측(블로킹_A)으로만** 정해야 한다 — 임의 수치 금지(99 빌드가드 기본값 0 유지). 측정: 온도 범위별 noTouch counts 변동폭 + 배터리 전압별 변동 + 터치 delta 분포.
>
> **추가**: 데이터시트의 온도/습도 드리프트 정공법인 Reference UI(§7.3, 별도 reference 채널로 공통모드 제거)는 **Sound1 CRX1 회로(C52 100nF DC차단)상 사용 불가**(crx1-esd-guard에서 기각) → ATI/LTA 방식이 유일 경로.

**v3 아키텍처 보강 (반증 0)**:
- **D2 노터치 게이트 최강 근거**: AZD004 §12.7("interaction during ATI" → constant errors) + AZD125 §8.1("when the device is not in touch"에서만 자동 추종) — **두 자료가 독립적으로** 노터치 원칙 명시. 블로킹_A 실측 마진 필요성도 그대로 유효(온도 예시는 방향 확정용이지 우리 절댓값 아님).
- **Follow UI 적용불가 확정**: 인터치 중 온도 자동보정 Follow UI [AZD125 §8.2.1]는 별도 레퍼런스 전극 필수 → CRX1 더미채널+C52 DC-block 복합 제약으로 **완전 불가** → 노터치 게이트 조건부 Re-ATI가 유일 능동 보정 수단 재확인.
- **정정(앱노트 정독 노드 자체 오류, 본 문서 무관)**: "수분=카운트 급증" 서술은 자기 커패시턴스 방향과 반대 → **감소**가 정답(adversarial 검증 적출). 본 §10 기존 서술엔 해당 오류 없음("손 뗌 시 counts 급상승"은 올바름).
