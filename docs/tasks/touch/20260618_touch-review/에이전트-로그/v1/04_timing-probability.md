# 04 타이밍·확률 정량 분석 (명제_D 주력)

> **TL;DR**: 명제_D의 확률 논거는 **t_ati(ATI 1회 지속) < read 주기**일 때만 성립한다. 그러나 펌웨어 실측·데이터시트는 **단발 ATI가 1.5초(POR) / 수백 ms~1초(런타임)** 로 read 주기(100~200ms)보다 길다고 가리킨다. ATI가 read 주기보다 길면 **"10회 연속 실패"가 정상 ATI 1회만으로도 발생** → 임계가 정상을 고장으로 오판한다. 즉 "auto-ATI 1회는 짧다"는 전제가 **데이터시트 근거로 뒷받침되지 않으며(미명시 "짧은 시간"), 실측은 오히려 반대**. 다만 현재 펌웨어는 ATI Mode=Disabled로 런타임 Re-ATI 자체를 차단 중이라, 이 임계는 "Phase2에서 ATI Full을 다시 켰을 때"의 가정으로만 의미가 있다. 또한 10회×100ms=**1초 블라인드**는 터치 후 최대 1초 무반응을 의미하며, 롱터치 판정(2.2s)의 45%에 달해 응답성 마진이 얇다.

---

## 0. 검증 명제 (명제_D)

> "100ms 주기로 10회 read 시, 10회 연속 auto-ATI에 걸릴 확률은 낮다 → 10회 연속 실패면 고장."
> (근거_확률: auto-ATI 1회는 짧으므로 1초 동안 매 read가 연속으로 auto-ATI에 걸릴 확률은 낮다.)

**판정 결과: 부분 기각(Conditional Fail).** 확률 논거의 핵심 전제 `t_ati < T_read`가 데이터시트·실측으로 뒷받침되지 않는다. 전제가 깨지면 임계 자체가 붕괴한다.

---

## 1. 입력 파라미터 추정 (근거 + [추정] 표기)

| 기호 | 의미 | 추정값 | 근거 |
|---|---|---|---|
| `T_read` | read 폴링 주기 | **제안 100ms / 실측 200ms** | 제안 전략=100ms(`00_오케스트레이터-입력.md:19`). 실제 펌웨어 `TDC_TOUCH_POLL_INTERVAL=200`ms, "100ms 폴링" 주석은 오류(`분석.md:68`). **둘 다 계산** |
| `t_ati(POR)` | init auto-ATI 1회 지속 | **~1500ms** | 실측 `20260421_init-split/구현계획.md` ("POR → 약 1.5초") |
| `t_ati(Re-ATI)` | 런타임 Re-ATI 1회 지속 | **~100ms ~ 수백ms** [추정] | `20260610_touch-rtt-tuning/계획.md`("wait_re_ati_done ~100ms"), `20260608_sleep-measure-mode/분석.md`("ATI 완료 수백 ms"). 데이터시트는 "짧은 시간"만 명시, 정량 미공개(`02_proxfusion동작.md §5.9`) |
| `t_ati(상한)` | 펌웨어 대기 타임아웃 | **1000ms** | `wait_re_ati_done` 10회×100ms, `wait_auto_ati_done` 20회×50ms = 각 1초(`tdc_drv_iqs323.c`) |
| `T_ati` | Re-ATI 발생 주기(간격) | **이벤트성·비주기적** | LTA가 Re-ATI Boundary(=ATI Target ± Band) 이탈 시에만 발동(`01_datasheet-ati.md`, `02_proxfusion동작.md §5.10`). 정상 환경: 분~시간 단위 희소 [추정]. 온도 급변·근접물 변동 시 빈발 가능 |

> [!IMPORTANT]
> 데이터시트는 ATI 지속시간을 **수치로 명시하지 않는다**("ATI 알고리즘은 짧은 시간에 실행"). "짧다"의 사용자 체감("인지 못 함")과 **I2C 블로킹 ms**는 다른 척도다. 펌웨어가 ATI 완료를 기다리며 두는 타임아웃이 1초인 것 자체가, 설계자가 "ATI 1회 = 최대 1초급"으로 본 증거다.

## 2. 확률 모델

### 2.1 모델 설정

read 1회가 auto-ATI에 "겹친다(실패한다)"는 사건을, ATI가 진행 중인 구간에 read 샘플 시점이 떨어지는 것으로 본다.

- **블라인드 구간 길이** = `t_ati` (이 동안 I2C 차단 → read 실패)
- **단발 read 겹침 확률** `p`: ATI가 진행 중일 때 한 read가 그 안에 떨어질 조건부 확률은, ATI가 read 주기보다 길면 **연속 샘플이 줄줄이 실패**한다.

핵심은 "독립 베르누이"가 아니라 **시간적 상관**이다. ATI는 한 덩어리(burst)라서, 한 번 ATI에 진입하면 그 burst가 끝날 때까지 연속 read가 모두 실패한다.

### 2.2 케이스 A — 명제의 암묵 가정 (t_ati < T_read, 독립 근사)

ATI가 read 주기보다 짧으면, 한 burst는 최대 1~2개 read만 삼킨다. 이때만 "독립적으로 드물게 겹친다"는 명제의 직관이 성립한다.

단발 겹침 확률 `p = t_ati / T_ati` (전체 시간 중 ATI가 차지하는 비율, duty).
10회 연속 실패 확률(독립 근사): `P_10 = p^10`.

| 시나리오 | t_ati | T_ati | p = duty | P_10 = p¹⁰ |
|---|---|---|---|---|
| 낙관(ATI 매우 짧음·희소) | 50ms | 60s | 8.3e-4 | ~1.6e-31 |
| 중간 | 200ms | 10s | 0.02 | ~1.0e-17 |
| 비관(짧지만 빈발) | 200ms | 1s | 0.20 | ~1.0e-7 |

→ **이 케이스에선 명제가 성립**한다. 10회 연속은 사실상 불가능에 가깝고, 그렇다면 "10회 연속 실패=고장" 임계는 타당하다.

### 2.3 케이스 B — 실측/데이터시트가 가리키는 영역 (t_ati ≥ T_read, burst 모델)

ATI 1회 지속이 read 주기보다 **길면** 독립 근사가 깨진다. 한 번 ATI burst에 들어가면, 그 burst 동안의 모든 read가 연속 실패한다. 한 burst가 삼키는 연속 실패 read 개수:

```
N_fail = ceil( t_ati / T_read )
```

| t_ati | T_read=100ms → N_fail | T_read=200ms → N_fail | 10회 임계 도달? |
|---|---|---|---|
| 200ms (런타임 짧은 쪽) | 2 | 1 | 아니오 (안전) |
| 500ms (런타임 중간) | 5 | 3 | 아니오 |
| 1000ms (펌웨어 타임아웃급) | **10** | 5 | **100ms일 때 정확히 임계 붕괴** |
| 1500ms (POR auto-ATI 실측) | **15** | **8** | **둘 다 임계 근접/초과** |

> [!WARNING]
> **임계 붕괴점**: T_read=100ms·t_ati=1000ms이면 단 한 번의 정상 ATI가 10회 연속 실패를 만든다 → 정상을 고장으로 오판. POR auto-ATI(1.5초)는 100ms 기준 15회 연속 실패라 임계를 **명백히 초과**한다. 즉 "초기화 직후 정상 부팅"을 "센서 고장"으로 판정할 수 있다.

### 2.4 두 케이스를 가르는 임계식

명제가 성립할 **필요조건**:

```
t_ati < (임계횟수 K) × T_read = 10 × T_read
T_read=100ms → t_ati < 1000ms (1초)
T_read=200ms → t_ati < 2000ms (2초)
```

- 런타임 Re-ATI(~100~수백ms 추정)만 본다면 → 1초 미만이라 **조건부 통과**.
- POR auto-ATI(1.5초)까지 포함하면 → 100ms 기준 **조건 위반**(15>10).

따라서 명제_D는 "**런타임 Re-ATI에 한정하고, t_ati를 수백 ms 이하로 확정할 수 있을 때만**" 타당하다. POR 경로는 반드시 별도 처리(긴 타임아웃 INIT_TIMEOUT_MS=2500 = 이미 존재) 필요.

## 3. 응답성 영향 정량 (1초 블라인드)

10회×100ms = **1초**, 실측 주기 적용 시 10회×200ms = **2초**가 "실패 누적 중 무반응 윈도우(blind window)"다.

| 항목 | 값 | 평가 |
|---|---|---|
| 블라인드 윈도우(100ms 가정) | **1.0s** | 터치 후 최대 1초 무반응 |
| 블라인드 윈도우(200ms 실측) | **2.0s** | 터치 후 최대 2초 무반응 |
| 롱터치 판정 기준 | 2200ms (`ULP_LONG_TOUCH_MS`) | — |
| 1초 / 롱터치 | **45%** | 100ms 기준이라도 롱터치의 절반 |
| 2초 / 롱터치 | **91%** | 200ms 실측이면 롱터치를 거의 다 잡아먹음 |

> [!CAUTION]
> 실제 폴링이 200ms이므로 "10회"는 사실상 **2초 무반응**을 허용한다. 사용자가 전원 버튼을 누른 순간 ATI burst와 겹치면, 최악 2초간 입력이 무시된다. 롱터치(2.2s) 직전까지 가는 길이라 **단순 탭이 묵살될 위험**. 응답성 관점에서 "10회"는 100ms 전제에서나 1초로 수용 가능하고, 실제 200ms에선 임계를 낮추거나(예: 5회=1초) read 실패와 무관하게 마지막 유효 상태를 유지하는 보강이 필요하다.

## 4. 종합 판정

| 분기 조건 | 명제_D 타당성 |
|---|---|
| `t_ati < T_read` (ATI가 read보다 짧음) | **성립** — P_10 ≈ p¹⁰ 로 사실상 0, 10회 임계 안전 |
| `t_ati ≈ 5×T_read` (수백 ms) | **경계** — N_fail이 임계의 절반, 마진 얇음 |
| `t_ati ≥ 10×T_read` (1초+, POR 1.5초) | **기각** — 정상 ATI 1회가 10회 연속 실패 유발 → 오판 |

**결론**:
1. 명제_D의 확률 직관(p¹⁰≈0)은 **수학적으로 옳지만**, 그 전제 "auto-ATI 1회는 짧다(<read 주기)"가 **데이터시트로 입증되지 않고 실측은 반대**(POR 1.5s, 런타임 수백 ms~1s)다. 시간 상관(burst) 무시한 독립 베르누이 가정이 함정.
2. 안전하게 쓰려면 (a) 대상을 런타임 Re-ATI로 한정하고 t_ati를 수백 ms 이하로 실측 확정, (b) POR auto-ATI는 별도 긴 타임아웃(INIT_TIMEOUT_MS=2500, 이미 존재) 경로로 분리, (c) read 실제 주기(200ms)를 반영해 임계 횟수를 재산정.
3. 현재 펌웨어는 ATI Mode=Disabled로 런타임 Re-ATI를 차단 중 → 이 임계는 Phase2(ATI Full 복귀) 가정에서만 활성 의미.

## 5. 권고 (정량 근거)

- **t_ati 실측 선행**: ATI_Active 비트 set→clear 구간을 RTT로 ms 측정. 이 값이 명제 전체의 분기점.
- **임계 횟수 = ceil(목표_블라인드_상한 / 실제_T_read) + 안전마진**. 목표 1초·실측 200ms이면 5회. 단 t_ati 실측치(예 500ms)보다 충분히 커야 정상 burst를 오판 안 함 → `K > t_ati/T_read + 마진`.
- **POR/Re-ATI 경로 분리**: 초기화 직후 첫 ATI(1.5s)는 고장 판정에서 제외(부팅 시퀀스 INIT_TIMEOUT으로 흡수).
- **응답성 보강**: read 실패 시 "직전 유효 터치 상태 유지(hold-last)"로 블라인드 윈도우 동안 입력 묵살을 완화.
