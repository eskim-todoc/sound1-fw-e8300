# 00 오케스트레이터 입력 — 은수님 retry-and-count I2C 전략 검증

**TL;DR**: ATI Full 시 auto-ATI로 인한 I2C 실패를, 복잡한 ATI_Active 폴링 대신 "실패=auto-ATI 중으로 간주 → 100ms 재시도 + 10회 연속 실패면 고장 판정"이라는 단순 전략으로 대체 가능한지를 8 페르소나(분석5·반증2·수렴1)로 검증한다.

---

## 1. 은수님 가정·제안 (원문 보존 명제화)

- **가정_1**: ATI Full 사용 시 센서가 내부 auto-ATI를 자율 수행하며, 그 동안 CM3의 I2C 통신(터치 상태 read)이 실패할 수 있다.
- **가정_2**: 터치 상태(접촉 중)에서는 auto-ATI가 동작하지 않는다.
- **제안_전략**: 터치 상태를 **100ms 주기**로 read. I2C 실패 시 → auto-ATI 중으로 간주하고 별도 핸들러 없이 **다음 100ms에 재시도**.
- **제안_판별**: **10회 연속 I2C 실패** → auto-ATI 문제가 아니라 센서 자체 고장 상태로 판정.
- **근거_확률**: auto-ATI 1회는 짧으므로, 100ms×10회(=1초) 동안 매 read가 연속으로 auto-ATI에 걸릴 확률은 낮다.

> 핵심 질문: 이 단순 전략이 (제어 재설계·하이브리드 권고가 요구한) ATI_Active 폴링·ATI_Error 핸들러·타임아웃 복구를 대체할 만큼 **정확하고 안전한가?**

---

## 2. 검증 명제

| ID | 명제 | 핵심 |
|---|---|---|
| 명제_A | auto-ATI 중 I2C "실패"의 실제 메커니즘·정의 | 무응답? NACK? RDY low 게이팅? clock-stretch? 실패가 맞나 |
| 명제_B | ATI Full에서 auto-ATI 트리거 조건·빈도·1회 지속시간 | 주기적인가 이벤트성인가, 1회 몇 ms |
| 명제_C | "터치 중 auto-ATI 미동작" 정확성 | frozen(LTA)와 ATI 트리거의 관계, 데이터시트 근거 |
| 명제_D | 100ms×10 연속 실패 확률 정량 + 10회 임계 타당성 | auto-ATI 지속/빈도 대비 정량 모델 |
| 명제_E | retry-and-count vs ATI_Active 폴링 — 복잡도·충분성 | 단순성 이득 실재? 충분한가 |
| 명제_F | failure mode | 오판 양방향(auto-ATI↔고장), 터치 지연·놓침, stale read |
