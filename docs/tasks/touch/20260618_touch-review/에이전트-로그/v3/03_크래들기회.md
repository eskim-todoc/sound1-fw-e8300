# 03_크래들기회 — 뚜껑 닫힘 노터치 구간 ATI/baseline 훅 삽입 분석

**TL;DR**: 뚜껑 닫힘(`func_cradle_lid_closed_loop`) 진입 시점은 노터치 확정+IQS323 폴링 완전 중단 구간이라 Re-ATI 삽입 이상 적지이나, 열림 재부팅은 WDT 리셋→MCLR+Auto-ATI 자동 수행이므로 열림 훅은 불필요. 삽입 가능 지점 2곳(진입 시 Re-ATI, 부팅 시 크래들 판별)을 확인했으며, race 소멸·절대 게이트 불요·드리프트 보정 3가지 고유 이점이 있다. 현재 미구현. 구현 비용은 낮으나 크래들 감지 신호 부팅 시점 가용성 [확정 필요].

---

## 1. 시스템 전제 재확인 (코드 근거)

| 전제 | 코드 위치 | 내용 |
|---|---|---|
| 뚜껑 닫힘 = 터치 폴링 완전 중단 | `main.c:740~744` | `func_cradle_lid_closed_loop()` 호출, `tdc_touch_process()` 루프 탈출 → I2C 통신 없음 |
| 뚜껑 열림 = WDT 리셋 재부팅 | `main.c:854~856` | `SYS_WATCHDOG_RESET()` → MCLR+Auto-ATI 자동 1회 |
| 매 부팅 MCLR+Auto-ATI | `iqs323.c:288`, `initialize.c:449` | `mclr_reset()` 무조건, 이후 Auto-ATI 비블로킹 폴링 |
| Auto-ATI 후 고정값 덮어쓰기 | `iqs323.c:651`, `:700~735` | ATI Mode=Disabled + 사전 측정 MULT/COMP 직접 write → Auto-ATI 결과 폐기 |
| 충전기 연결 시 절전 진입 안 함 | `systemControl.c:162` | 터치 폴링 계속 |
| RESEED = 현재 counts로만 seed | 데이터시트 §5.5.1 | 임의값(공장값 직접 write) 불가 |

> **결정적**: 뚜껑 닫힘 루프(`main.c:807~867`) 내부에는 터치 I2C 통신 코드가 전혀 없다. BLE 수신 루프와 WFI만 존재. IQS323은 물리적으로 idle 상태. 이것이 "노터치 보장"의 실체다.

## 2. 크래들 구간의 고유 이점 (다른 시나리오 대비)

| 이점 | 설명 | 다른 시나리오와 비교 |
|---|---|---|
| **race 사실상 소멸** | 사람이 뚜껑 닫힌 동안 전극에 접촉 불가 → "노터치 판별 ~ ATI 실행" race가 물리적으로 불가능 | 일반 부팅 노터치 게이트: 판별~실행 μs 간격에 race 잔존(저확률) |
| **절대 기준 게이트 불요** | 노터치가 하드웨어(크래들 기구)로 보장되므로 공장 캘리브레이션 기준값 없이도 안전 | 일반 부팅: 공장값 없으면 "현재 counts가 터치인지 노터치인지" 판별 불능 |
| **드리프트 포함 재보정 가능** | 드리프트 후 시점에도 크래들에 넣으면 그 시점 환경의 Re-ATI가 가능 → 환경 적응 | 공장 캘리브레이션 단독: 출하 시점 이후 드리프트 미추적 |
| **사용 패턴과 정렬** | 충전(=크래들) 습관적 → 자연스럽게 주기 재보정 기회 발생 | 별도 캘리브레이션 공정: 의도적 트리거 필요 |

## 3. 훅 삽입 가능 지점 분석

### 지점 A — 뚜껑 닫힘 진입 시 (현재 가장 유력)

```
main.c:740~744 — func_cradle_lid_closed_loop() 호출 직전
  ↓
led_force_fade_off() 완료 후 (현재)
  ↓
[훅 삽입] tdc_drv_iqs323_re_ati() 호출
  → ATI Mode = Full 임시 설정
  → MCLR 생략(또는 RESEED로도 가능, 단 Re-ATI가 우월)
  → ATI 완료 폴링 (노터치 보장 구간이므로 블로킹 허용)
  → 완료 후 ATI Mode = Disabled + 고정값 write (기존 시퀀스 복원)
  ↓
func_cradle_lid_closed_loop() 진입 → 약 절전 루프
```

**장점**:
- 노터치 100% 보장 상태에서 Re-ATI → MULT/COMP + baseline 동시 갱신 (RESEED 단독 대비 우월: 개념정리_터치동작모델.md §3-A 근거)
- ATI 완료 후 즉시 약 절전 루프 진입 → 뚜껑 닫힘 중 보정된 값 유지
- 뚜껑 열림 시 WDT 리셋 → 재부팅 → 부팅 MCLR+Auto-ATI가 보정된 환경 기준에서 다시 실행됨 [추정: Auto-ATI 결과를 어떻게 활용하느냐에 따라 다름]

**주의**:
- 현재 `write_ati_compensation()`이 Auto-ATI 결과를 폐기하고 고정값을 write하는 구조이므로, **지점 A 훅 단독으로는 재부팅 후에도 고정값 덮어쓰기가 일어나 Re-ATI 결과가 살아남지 않는다** [추정]
- 따라서 지점 A는 "뚜껑 닫힘 기간 중 LTA baseline 갱신(RESEED)"으로 제한하거나, 재부팅 시 Re-ATI 결과를 EEPROM에 저장·복원하는 Phase와 결합할 때 완전 효과 발휘

**실용적 최소 구현 (RESEED 버전)**:

```c
/* main.c:742 앞에 삽입 */
/* 뚜껑 닫힘 직전 — 노터치 보장 구간에서 RESEED(LTA 갱신) */
tdc_drv_iqs323_reseed_normal(); /* 절전 감도 적용 없이 순수 RESEED만 */
```

단, RESEED는 MULT/COMP(게인)를 갱신하지 않으므로 드리프트 적응 효과는 LTA baseline 수준으로 제한됨.

**완전 구현 (Re-ATI 버전)** — Phase 2(ATI Full 도입) 이후:

```c
/* ATI Mode를 Full로 임시 전환 → Re-ATI 실행 → 결과 읽기 → EEPROM 저장 → Disabled 복원 */
tdc_drv_iqs323_re_ati_and_store(); /* 신규 함수: ~1.5초 블로킹 허용 */
```

### 지점 B — 부팅 시 크래들 여부 판별 후 (미래 확장)

```
부팅 MCLR+Auto-ATI 완료
  ↓
[판별] 크래들 신호 읽기 → 뚜껑 닫힘 중인가?
  → YES: Auto-ATI 결과 신뢰(노터치 보장) → RESEED/Auto-ATI 결과 유지
  → NO: Auto-ATI 결과 폐기(터치 여부 불확실) → 기존 고정값 write
```

**전제**: 크래들 신호(`tdc_cradle_get_cover_state()`)가 부팅 초기에 가용해야 함. 현재 BLE 패킷 수신 전에는 상태 불확실 → [확정 필요].

**이점**: 크래들 부팅 시 Auto-ATI 결과를 버리지 않고 활용 → MULT/COMP까지 보드 현재 환경에 맞게 갱신.

**위험**: BLE 크래들 신호가 부팅 초기 미가용이면 판별 실패 → 크래들 부팅인데도 Auto-ATI 결과를 폐기하게 됨 [확정 필요].

## 4. 지점별 비교

| | 지점 A (진입 시 Re-ATI/RESEED) | 지점 B (부팅 판별) |
|---|---|---|
| 노터치 보장 | **완전 보장** (기구적) | 보장(뚜껑 닫힘 중이면) |
| 구현 시점 | Phase 1(RESEED) 또는 Phase 2(Re-ATI) | Phase 2+ (크래들 신호 가용성 확인 후) |
| race | 사실상 소멸 | 소멸 |
| MULT/COMP 갱신 | Re-ATI 버전에서 가능(Phase 2 이후) | Auto-ATI 결과 활용으로 가능 |
| 재부팅 후 지속 | EEPROM 저장 없으면 소멸 [추정] | 부팅 시 바로 적용 → 지속 |
| 크래들 신호 의존 | 불필요(진입 시 이미 확인됨) | 부팅 초기 가용성 [확정 필요] |
| 구현 비용 | 낮음(RESEED) / 중간(Re-ATI) | 중간 + 신호 타이밍 검증 필요 |

## 5. 뚜껑 열림 훅 불필요 근거

- 열림 감지 = `SYS_WATCHDOG_RESET()` (`main.c:856`) → **즉시 재부팅**
- 재부팅 = `initialize.c:449` MCLR → Auto-ATI 자동 수행 → 기존 `write_ati_compensation()` 덮어쓰기
- 열림 후 훅 삽입 시점이 존재하지 않음 (WDT 리셋과 재부팅 사이 코드 실행 불가)
- **따라서 열림 후 ATI 훅은 "부팅 시 크래들 판별(지점 B)"로만 구현 가능**

---

## 6. 미구현 현황 및 위험 없음 확인

현재 `func_cradle_lid_closed_loop()` 내부에는 IQS323 관련 I2C 코드가 전혀 없음 (`main.c:807~867` 전문 확인). 삽입은 진입 직전(`main.c:742` 앞)이므로 약 절전 루프 동작에 영향 없음.

RESEED 삽입 시 절전 감도 파라미터 적용 여부에 주의: `tdc_drv_iqs323_reseed()`는 절전용 THRESHOLD/HYSTERESIS를 함께 적용(`iqs323.c:931~948`)하므로, 뚜껑 닫힘 진입 시 호출하면 절전 파라미터가 맞게 적용된다. 그러나 뚜껑 닫힘 루프는 절전(ULP)이 아닌 약 절전이므로 파라미터 적합성 [확정 필요].

## 7. 핵심 결론 (7줄 이내)

1. **뚜껑 닫힘 = 노터치 100% 보장 구간** — 기구적 차단이므로 software race가 소멸하는 유일한 시나리오. 현재 이 구간을 ATI/baseline 갱신에 활용하는 코드는 없다.
2. **삽입 지점 A(진입 시)** — `main.c:742` 앞, `led_force_fade_off()` 직후. RESEED(즉시 가능, Phase 1)로 LTA baseline 갱신, Re-ATI(Phase 2)로 MULT/COMP까지 갱신 가능.
3. **열림 시 훅은 불필요** — WDT 리셋 재부팅이 Auto-ATI를 자동 수행하므로, 열림 후 ATI는 부팅 판별(지점 B)로만 처리.
4. **Re-ATI 결과 지속성은 EEPROM 저장 없이 불가** — 재부팅 시 `write_ati_compensation()`이 고정값을 덮어쓰므로, Phase 2 Re-ATI 결과를 살리려면 Phase 3(EEPROM 저장·복원)와 결합 필요.
5. **최소 구현(Phase 1 적용 가능)** — 진입 시 `tdc_drv_iqs323_reseed()` 삽입. 절전 파라미터 적합성 확인 후 2줄 추가로 LTA 오염 방지 효과 즉시 획득.
6. **부팅 판별(지점 B)은 크래들 신호 부팅 초기 가용성에 의존** [확정 필요] — BLE 수신 전 가용 여부 미확인.
7. **크래들 기회는 다층 방어의 "race 소멸 층"** — 공장 캘리브레이션(절대 기준) + 노터치 게이트 + 크래들 훅이 결합될 때, 크래들은 "game over" 수준의 신뢰도를 제공하는 가장 견고한 층이다.
