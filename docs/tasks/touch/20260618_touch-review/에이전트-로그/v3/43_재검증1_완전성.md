# 43 — 재검증 라운드1: 완전성 adversarial 공격 (30_종합-1차 대상)

**TL;DR**: 30_종합-1차를 완전성 관점에서 공격한 결과, 수렴 선언으로 보이나 실제로는 4개 범주 결정적 누락이 존재한다. ① 절전 진입 RESEED 오염 경로가 부팅 게이트에 미치는 영향 미분석, ② 충전 중 주기 Re-ATI의 트리거 위치·코드 경로 완전 미기술, ③ 실측 게이트 순서 의존 관계가 블로킹 테이블과 Phase 계획 사이에서 불완전하게 연결됨, ④ `write_ati_compensation()` 내부 레지스터 목록 확인이 블로킹_F로 등록됐으나 Phase 1 설계 결론에 실제 반영 없음. 나머지는 수렴 판정.

## 1. 결정적 누락 — 절전 진입 RESEED 오염 경로 미분석

### 1-1. 30_종합-1차의 처리

30_종합-1차 §1-3: "절전 진입 RESEED(`iqs323.c:931~948`)는 ULP 루프 전용 — 복귀 후 baseline에 무관"

### 1-2. 공격

이 주장은 부분 참이나 결정적 케이스를 빠뜨린다.

**놓친 경로**: 롱터치(2400ms)로 절전 진입할 때 사용자가 아직 손을 떼지 않은 상태에서 절전 RESEED(`iqs323.c:955~957`)가 발행된다. 이 시점 LTA ← 터치 counts로 오염된다. 이후 WDT 리셋 재부팅 시 MCLR → Auto-ATI → `write_ati_compensation()` → **노터치 게이트**(Phase 1) 순서로 진입한다.

문제는 절전 진입 오염 RESEED가 **부팅 게이트 직전 LTA 상태**에 영향을 주는가이다. WDT 리셋은 IC POR을 유발하므로(`initialize.c:449` MCLR 무조건) 절전 중 LTA는 MCLR에 의해 초기화된다. 즉 절전 진입 RESEED 오염이 다음 부팅 게이트에 직접 전달되지는 않는다.

**그러나** 30_종합-1차는 이 논리를 전개하지 않고 단순히 "ULP 루프 전용 — 복귀 후 baseline에 무관"이라고만 선언한다. MCLR에 의한 LTA 초기화가 왜 절전 오염을 차단하는지 근거가 없다. 검증8 노드(25_검증_엣지.md §2)는 이 경로를 "치명" 결함으로 발굴했으나, 30_종합-1차에서 "절전 진입 RESEED는 부팅 게이트와 독립"임을 명시 해소하지 않았다.

**결론**: §1-3의 "복귀 후 baseline에 무관" 선언은 MCLR에 의한 LTA 초기화를 묵시 전제하는 미완성 논거다. 아래 한 문장을 추가해야 완결된다: "WDT 리셋 후 MCLR이 IC POR을 강제하므로(`initialize.c:449`) 절전 중 오염 LTA는 다음 부팅 게이트 진입 전 IC 내부에서 이미 초기화된다 — [코드 확인: MCLR이 LTA 레지스터를 POR default로 리셋하는지 데이터시트 §5.5 확인 필요]."

이 확인이 없으면 "절전/부팅 baseline 통합" 전제의 완결 근거가 부재한 채 종합이 선언된다.

## 2. 결정적 누락 — 충전 중 주기 Re-ATI 구현 경로 완전 미기술

### 2-1. 30_종합-1차의 처리

30_종합-1차 §2-1 Phase 계획에 충전 중 Re-ATI(R3_CHARGING)가 Phase 3 선택 항목으로 언급되나, 코드 삽입 위치·타이머 관리·트리거 경로가 전혀 기술되지 않았다. §7 구현 파일 변경 목록에도 `systemControl.c` 또는 `tdc_touch.c` Re-ATI 타이머 항목이 없다.

### 2-2. 공격

검증8(22_검증_회귀.md 결함_10)이 "충전 중 주기 Re-ATI 구현 위치 미기술"을 "중요" 결함으로 발굴했으나, 30_종합-1차 §2·§5·§7 어디에도 이 결함에 대한 해소 또는 명시적 "Phase 3 이후 별도 계획" 위임이 없다.

충전 중 Re-ATI가 미기술인 채 Phase 3을 구현하면 ATI_Error 핸들러와 Re-ATI 트리거는 존재하나 언제 Re-ATI가 실행되는지 구조가 없다. Phase 3 설계 자체가 불완전하다.

**추가 누락**: `systemControl.c:162`에서 충전기 연결(df_Connected) 시 절전 미진입이 코드 확인됐으나, 충전 중 터치가 계속되는 상황에서 주기 Re-ATI가 터치 중에 발동될 때의 노터치 게이트 실패·ATI_Error 연쇄도 30_종합-1차 §4 달성도 표에서 "✅ (Phase 3 완료 후)"로 처리되어 있다. 충전 중 사용자 터치 중 Re-ATI 발동 케이스가 분석 범위 밖이다.

## 3. 결정적 누락 — 블로킹_F(write_ati_compensation 레지스터 목록)가 설계 결론에 미반영

### 3-1. 30_종합-1차의 처리

§5-1 블로킹_F: "`write_ati_compensation()` 내 레지스터 write 전체 목록(L696~) — Phase 1 채택 경로 설계 전"이라고 블로킹으로 등록. 해소 방법: "코드 read (결함_5@22: 스킵 시 운용 설정 누락 가능)"

§2-3 apply_settings() 삽입점 통합 설계: "write_ati_compensation()은 항상 실행 유지"로 결론.

### 3-2. 공격

write_ati_compensation()을 "항상 실행"하기로 결론냈다면 블로킹_F(함수 내부 목록 확인 필요)는 왜 여전히 블로킹으로 남아 있는가? 두 가지 모순이다.

**가능한 해석_A**: "항상 실행"이므로 내부 목록 확인 불필요 → 블로킹_F 해소, 테이블에서 제거해야 한다.

**가능한 해석_B**: 내부 목록 확인 후 "항상 실행" 유지가 올바른지 재검토해야 한다 → 블로킹_F가 §2-3 결론의 전제 조건이어야 한다.

30_종합-1차는 둘 중 어느 것인지 선언하지 않아 블로킹_F가 유령 항목으로 남아 있다. 구현자가 블로킹_F 해소 없이 Phase 1을 착수하면 "내부 목록 확인 전 구현"이라는 22_검증_회귀 결함_5의 위험이 재발한다.

## 4. 결정적 누락 — 실측 게이트 순서의 Phase 계획과 블로킹 테이블 간 불완전 연결

### 4-1. 30_종합-1차의 처리

§5-1 블로킹 테이블: 블로킹_A(noTouch counts 절대값)·블로킹_B(방전 효과) → Phase 1 활성화 전

§2-1 Phase 1: "선행 블로킹: 실측_A(noTouch counts 절대값) + 실측_B(방전 효과) 완료 후 활성화"

### 4-2. 공격

23_검증_실측의존.md §2 위험_C 및 결함_6에서 발굴된 문제: "방전 트랙(실측1) 선행이 노터치 게이트의 전제 조건임에도 Phase 2 의존 관계에 명시되지 않았다."

30_종합-1차 §2-1 Phase 1에서 실측_B(방전 효과)가 Phase 1 활성화 전 블로킹으로 명시된 것은 올바르다. 그러나 §2-1 Phase 0(포화 감지 stub) 설명에는 "블로킹 실측: 실측_E(Max Counts)"만 있다.

**실측_B(방전 효과)와 실측_A(noTouch counts)의 선행 순서 관계가 불명확하다**: 실측_A를 먼저 해야 하는가, 실측_B를 먼저 해야 하는가, 병렬인가. ESD 전하 누적이 심한 보드에서는 실측_A(noTouch counts 측정) 전에 방전이 먼저 이루어져야 계측값이 의미 있다. 즉 **실측_B → 실측_A 순서 의존**이 있으나 30_종합-1차 §5-1 블로킹 테이블이 이를 명시하지 않는다.

**추가 누락**: 블로킹_A 해소 방법 "RTT `tdc_drv_iqs323_check_touch_margin()` Counts 로그 관찰 (노터치 확정 환경)"에서 "노터치 확정 환경"이 어떻게 보장되는지 미기술이다. 실측 환경 자체가 방전 완료·크래들 보장·충전기 분리 등 여러 조건의 교차 집합인데 이 조건 세트가 블로킹 테이블에 없다.

## 5. 경미 누락 — 자기치유 동작 여부 모순의 최종 판정 미완

### 5-1. 30_종합-1차의 처리

§1-1 층위 3: "자기치유는 현재 내장(Beta POR [확정 필요])"

§5-3 설계 통일: "자기치유 동작 여부 — 16(내장) vs 15(Beta=0이면 불가) 모순 → 블로킹_D(Beta POR 실측) 후 재정립"

### 5-2. 공격

블로킹_D가 필수라면 §4 달성도 표의 "환경 드리프트" 항목이 "✅ (Phase 3 + Beta 실측 후)"가 아닌 "블로킹_D 해소 전 판정 보류"여야 한다. 현재 표기는 마치 Beta 실측이 있으면 달성된다는 의미로 읽히지만, Beta POR이 0이 아닌 경우 Phase 2 Beta 설정 계획 전체가 무의미해져 달성 경로 자체가 달라진다. 달성도 표가 두 분기(Beta POR = 0 / ≠ 0)를 통합해 낙관적으로 표기했다.

## 6. 경미 누락 — 충전기 연결 상태에서의 절전 미진입과 게이트 타이밍의 상호작용

### 6-1. 30_종합-1차의 처리

오케스트레이터 입력 §1 전제 4 세부: "충전기 연결(df_Connected): 롱터치해도 절전 진입 안 함(`systemControl.c:162`). 터치 계속 동작."

### 6-2. 공격

충전 중 절전이 없으므로 부팅 게이트(Phase 1)는 충전 중에는 오직 초기 부팅 시에만 1회 실행된다. 충전 연결 후 장시간(수 시간) 동작 시 환경 드리프트가 발생해도 Phase 3 Re-ATI가 실행되지 않으면 (30_종합-1차 §2-1 Phase 3에 충전 중 Re-ATI가 "선택" 항목으로만 있음) 드리프트가 누적된다.

§4 달성도 표에서 "환경 드리프트" → "Phase 3 Re-ATI + LTA IIR 런타임 추적 ✅"이라고 됐으나, Phase 3 충전 중 Re-ATI가 미구현이면 충전 장시간 세션에서는 초기 부팅 1회 ATI 이후 드리프트 대응이 LTA IIR(Beta 실측 선행 필요)에만 의존한다. 이 케이스가 달성도 표에서 누락됐다.

## 8. 신규 약점 발굴 (직전 라운드까지 미등장)

### 8-1. 절전 RESEED 오염이 부팅 게이트와 완전 독립인 이유 미서술 [미검증 주장]

30_종합-1차 §1-3 "복귀 후 baseline에 무관" 선언이 MCLR → LTA POR 초기화를 근거로 해야 하나, 데이터시트 §5.5에서 MCLR 후 LTA POR default 명시 여부가 검증되지 않았다. 25_검증_엣지.md §2는 이를 "치명" 결함으로 발굴했으나 30_종합-1차에서 근거 없이 수렴 처리됐다.

### 8-2. 충전 장시간 세션의 드리프트 대응 경로 미정의 [완전성 공백]

충전 중 Phase 3 Re-ATI가 구현되지 않은 상태에서의 드리프트 대응 경로가 30_종합-1차 §4 달성도 표에 명시되지 않았다. LTA IIR(Beta 실측 선행 필요)만 남는 케이스다.

### 8-3. 블로킹_F가 유령 항목으로 잔존 [내부 모순]

write_ati_compensation() "항상 실행" 결론 이후에도 블로킹_F가 블로킹 테이블에 존재한다. 해소 선언 또는 Phase 1 전 선행 확인 필수로 명시 중 하나를 선택해야 한다.

### 8-4. 실측 선행 순서 (실측_B → 실측_A) 미명시 [시퀀스 누락]

ESD 전하 누적 보드에서 방전 완료 전 noTouch counts 측정은 오염값을 기준값으로 저장하는 위험이 있다. 블로킹 테이블이 실측_B와 실측_A 사이의 의존 관계를 명시하지 않는다.
