# 59 — v3 종합-재검증2 (49_종합-재검증1 + 51~58 통합 정제)

**TL;DR**: 49_종합-재검증1을 8개 adversarial 노드(51~58)로 2차 공격한 결과를 통합 정제. 치명 신규 결함 9건·고위험 7건·중간 5건을 수렴에 반영. 아키텍처 원리("공장 절대 기준 → 노터치 게이트 → Re-ATI")는 재검증2에서도 기각되지 않았으나, 구현 전 해소 필수 블로킹이 7건→11건으로 증가하고 즉시 수정 항목(wait_re_ati_done WDT)이 Phase 0 이전 긴급 항목으로 격상됐다. 수렴도: **부분 수렴 유지** — 아키텍처 원리 확립, 구현 전 해소 항목 대거 잔존.

---

## 1. 아키텍처 원리 재확인 (2차 공격 통과)

> **"공장 절대 기준으로 노터치를 판별하고, 노터치가 확인된 순간에만 Re-ATI를 허용한다."**

재검증2(51~58) 8개 노드를 통해서도 **이 원리 자체는 기각되지 않았다.** 단, 58_대안비교(공격_2)가 "Phase 4 크래들 Re-ATI 결과를 EEPROM에 덮어쓰면 공장 절대 기준이 장기적으로 소실된다"는 잠재 파괴 경로를 지적했다. 이에 따라 층위 구조를 정제한다.

### 1-1. 층위 구조 (재검증2 정제)

| 층위 | 담당 | 재검증2 정제 사항 |
|---|---|---|
| **층위 0 — Fixed 기저** | 공장 MULT/COMP를 매 부팅 적용 | `write_ati_compensation()` 인자 전달 메커니즘 설계 필수 — `s_mult_lsb`·`s_comp_lsb` 신규 정적 변수 또는 인자 추가로 EEPROM 로드값 주입 설계 확정(신규_EEPROM전달) |
| **층위 1 — 노터치 게이트** | 공장 noTouch 절대 기준으로 부팅 판별 | `gate_check()` MARGIN_STRICT > COUNTS 시 uint32 언더플로 가드 추가 필수(신규_A). RTT_TUNING과 동시 활성 `#error` 추가 필수(회귀_A) |
| **층위 2 — 조건부 Re-ATI** | 게인+baseline 전체 재보정 | ATI_Active 비트 API 미존재 확인(블로킹_H 신규). `write_ati_compensation()` 비블로킹 Re-ATI 중 재진입 race 가드 필요(공격_1) |
| **층위 3 — 자기치유** | 손뗌 후 LTA IIR 수렴 | Beta POR=0 시 자기치유 무효 → 사후 검증 설계 조건분기 필요(공격_4). CH_TIMEOUT 재활성이 Beta POR=0 시 유일 복구 경로 가능성(공격_6) |
| **층위 4 — 크래들 race 소멸** | 뚜껑 닫힘 = 노터치 보장 | 크래들 Re-ATI EEPROM 저장 슬롯 정책 결정 필요 — 공장값 슬롯·런타임 슬롯 분리(대안_Z) 또는 공장값 덮어쓰기 금지 정책 명시(공격_2) |

### 1-2. 절전/부팅 통합 정제

- 블로킹_G(MCLR POR) 해소 후 절전 RESEED 게이트화 필요 여부 결정 조건 분기 명시(회귀_D)
- 블로킹_G 대안_Q: 부팅 시 THRESHOLD를 apply_settings()에서 명시 write하면 실측 없이 블로킹_G 해소 가능 — 검토 필요(공격_3)
- 절전 RESEED 오염→ULP 즉시 재부팅 루프가 §8 미해결에 명시 추가 필요(52_race 공격_1)

## 2. 신규 치명 결함 반영 (재검증2 추가 9건)

### 2-1. [긴급·즉시] wait_re_ati_done() 내 WDT 갱신 미삽입 — 현재 ATI_CALIB_MODE 경로 포함 현장 버그 (57_엣지 신규_A)

**발굴**: 57_엣지. `iqs323.c:581~623` 직접 확인 결과 `wait_re_ati_done()` 10회 루프 내 `SYS_WATCHDOG_REFRESH()` 호출이 **단 한 줄도 없다.** 49_종합은 "함수 수정 필수 선행 사항으로 격상"이라 선언했으나 코드 수정이 없는 선언이었다. 현재 `ATI_CALIB_MODE=1` 경로(`iqs323.c:860`)에서 이미 `wait_re_ati_done()`이 호출되므로 잠재 현장 버그 상태다.

**수정 (Phase 0 이전 즉시)**:
```c
/* iqs323.c:581~623 wait_re_ati_done() 루프 본체 내 Sys_Delay 직전 삽입 */
SYS_WATCHDOG_REFRESH();  /* blocking 최악 ~2.3초 — WDT 갱신 필수 */
Sys_Delay(TDC_DRV_IQS323_DEFAULT_DELAY_MS * 100);
```

> [!IMPORTANT]
> ATI_CALIB_MODE 경로(`iqs323.c:860`)에도 동일하게 적용. 독립 함수 수정 1회로 두 경로 모두 커버.

### 2-2. [치명] gate_check() MARGIN_STRICT > COUNTS 시 uint32 언더플로 — 영구 게이트 거부 (51_repro 신규_A)

**발굴**: 51_repro. `lo = (uint32_t)COUNTS - MARGIN_STRICT`에서 MARGIN_STRICT > COUNTS 시 uint32 wrap-around → `lo ≈ 0xFFFF...` → 게이트 영구 거부, 진단 없음. 현재 MARGIN=0이라 잠복 중이나 실측_A 후 값 설정 시 즉시 발현.

**수정**: 빌드가드 추가:
```c
#if (TDC_TOUCH_NOTOUCH_GATE_ENABLE) && \
    (TDC_TOUCH_NOTOUCH_MARGIN_STRICT >= TDC_TOUCH_FACTORY_NOTOUCH_COUNTS)
#error "NOTOUCH_MARGIN_STRICT must be < FACTORY_NOTOUCH_COUNTS (uint32 underflow risk)"
#endif
```

### 2-3. [치명] ATI_SETUP_FULL_LSB 미정의 — Phase 3 구현 불가 할루시 (51_repro 신규_B)

**발굴**: 51_repro. v1·v2·v3 전체 로그를 통해 `ATI_SETUP_FULL_LSB` 값(데이터시트 §5.9 ATI Mode Full bits[2:0])이 단 한 번도 확인되지 않았다. 49_종합 §2-1 코드 스니펫은 이 상수를 사용하면서 `[확정 필요]` 주석만 달았다 — 상수값 없이 코드 컴파일 불가.

**수정**: §2-1 코드 블록의 `ATI_SETUP_FULL_LSB`를 명시:
```c
/* [확정 필요] DS §5.9 bits[2:0] ATI Mode Full 값 — 임의 추정 금지 */
#define TDC_DRV_IQS323_ATI_SETUP_FULL_LSB   0xFFu  /* PLACEHOLDER — 미확정 */
```
블로킹_E(Max Counts)와 같은 수준으로 블로킹_J(신규)에 추가.

### 2-4. [치명] RTT_TUNING × EEPROM 로드 × ATI_FULL_ENABLE 삼중 충돌 — EEPROM 공장값 무효화 (51_repro 신규_E, 55_회귀 회귀_A, 57_엣지 신규_B)

**발굴**: 51·55·57 공통. `write_ati_compensation()` 내부 `#if TDC_TOUCH_RTT_TUNING` 분기가 `s_tdc_normal_tuning.ati_valid=true` 시 MULT/COMP를 런타임 튜닝값으로 덮어쓴다. 49_종합 §2-3이 설계한 EEPROM 로드 경로(`s_mult_lsb = calib.mult_lsb`)가 RTT_TUNING 분기에 의해 무시되어 EEPROM 공장 캘리브값이 완전 무효화된다.

**수정 (Phase 2 착수 전 필수)**:
```c
/* 빌드가드 추가 — §3 빌드가드 세트에 포함 */
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE && TDC_TOUCH_RTT_TUNING
#error "NOTOUCH_GATE와 RTT_TUNING 동시 활성화 불가 — 게이트 기준값 MULT/COMP 불일치"
#endif
#if TDC_TOUCH_FACTORY_CALIB_ENABLE && TDC_TOUCH_RTT_TUNING
#error "FACTORY_CALIB_ENABLE과 RTT_TUNING 동시 활성화 불가 — EEPROM 공장값 무효화"
#endif
```

### 2-5. [치명] EEPROM 로드 경로 인자 전달 메커니즘 미설계 — 사문 코드 (55_회귀 회귀_B, 56_할루시 약점_1, 57_엣지 신규_C)

**발굴**: 55·56·57 공통. `write_ati_compensation(void)`는 인자 없는 `void` 함수이고, `s_mult_lsb`·`s_comp_lsb` 정적 변수가 현재 `iqs323.c`에 존재하지 않는다. 49_종합 §2-3의 "이 값을 사용하도록 전달"이라는 주석은 연결 구조가 없는 환각이다.

**수정 방향 (Phase 2 착수 전 결정 필수)**:
```
선택지_1: write_ati_compensation()에 MULT/COMP 인자를 추가
  → static bool write_ati_compensation(uint8_t mult_lsb, uint8_t mult_msb,
                                       uint8_t comp_lsb, uint8_t comp_msb)
선택지_2: 파일 스코프 정적 변수 s_override_mult_lsb/s_override_comp_lsb 신설
  → 기존 RTT_TUNING 경로(s_tdc_normal_tuning) 패턴과 동일 레이어
  → RTT_TUNING 빌드가드(§2-4)로 상호 배제 보장 후 안전

우선 권고: 선택지_1 (더 명시적, 의존성 추적 용이)
```

### 2-6. [치명] R3_CHARGING 비블로킹 "ATI_Active 확인" API 미존재 (51_repro 신규_C, 54_통신전력 새3)

**발굴**: 51·54 공통. `tdc_drv_iqs323_read_status()`는 ATI_Active 비트를 반환하지 않으며, `is_auto_ati_done_single_read()`는 `static` 부팅 전용 함수다. "다음 폴링에서 ATI_Active 확인"은 현재 구현 불가 설계다.

**수정 (Phase 3 착수 전 필수 — 블로킹_H 신규)**:
```
블로킹_H: tdc_drv_iqs323_is_ati_active() 또는 read_status() ATI_Active 필드 확장
  해소 방법: is_auto_ati_done_single_read() 를 extern 노출하거나
            tdc_drv_iqs323_read_status() 반환 구조체에 ati_active 필드 추가
```

### 2-7. [치명] wait_re_ati_done() 최악 시간 재정정 — ~2.3초 (54_통신전력 새1)

**발굴**: 54_통신전력. `read_register()` 1회당 `wait_rdy_window_closed()` 2회 호출(코드 `:244`, `:261`)이 49_종합의 "~1.9초" 계산에서 누락됐다.

**재산출**:
```
read_register 1회 최악:
  force_window_open × 2 = 45+45 = 90ms
  wait_rdy_window_closed × 2 = 최악 20+20 = 40ms [확정 필요: MAX_WAIT_MS_FOR_WINDOW_CLOSE]
  i2c overhead ≈ 0.5ms
  합계 ≈ 130.5ms

wait_re_ati_done() 10회 최악:
  (130.5ms + 100ms) × 10 ≈ 2.3초
```

> [!IMPORTANT]
> 49_종합의 "~1.9초"는 "~2.3초"로 정정 [확정 필요: MAX_WAIT_MS_FOR_WINDOW_CLOSE 상수]. Phase 3 WDT·FPGA 지연 계산 재수행 필요.

### 2-8. [치명] CH_TIMEOUT 재활성화 — Phase 계획 완전 누락 (53_완전성, 56_할루시, 58_대안비교)

**발굴**: 53·56·58 공통. stuck-touch 방어를 위한 CH_TIMEOUT이 현재 이중 차단된 이유가 어떤 로그에도 없다. `re_ati_trigger()` 호출 시 SYSTEM_CONTROL MSB를 0x00으로 write해 기존 CH_TIMEOUT 비활성화(0x07)를 덮어쓰는 부작용도 미분석(57_엣지 신규_F).

**수정**:
1. CH_TIMEOUT 이중 차단 이유: 커밋 이력 또는 원저자 확인 선행 (확인_12 신규)
2. Phase 0 즉시 실행 또는 Phase 1 착수 시 재활성 여부 결정 — Beta POR=0 시 CH_TIMEOUT이 자기치유 대체 유일 복구 경로
3. `re_ati_trigger()` MSB=0x00 write로 CH_TIMEOUT 0x07 초기화 부작용 분석 필요 (확인_13 신규)

### 2-9. [치명] Phase 0 SATURATE_DETECT_ENABLE=1 + MAX_COUNTS=0 오작동 조합 (53_완전성, 55_회귀 회귀_E)

**발굴**: 53·55. `counts >= SATURATE_MAX_COUNTS`에서 `MAX_COUNTS=0u`이면 부호 없는 비교에서 항상 참 → 매 폴링 포화 경보 범람. 49_종합이 `ENABLE=1u + MAX_COUNTS=0u`를 최종 빌드가드 세트로 유지했으나 이 조합은 실제 오작동을 낳는다.

**수정**: 두 선택지 중 하나 즉시 결정:
```c
/* 선택지_A: ENABLE 기본값 0으로 수정 (실측_E 완료 전 OFF) */
#define TDC_TOUCH_SATURATE_DETECT_ENABLE     0u  /* 실측_E 완료 후 1u로 */
#define TDC_TOUCH_SATURATE_MAX_COUNTS        0u  /* [확정 필요] */

/* 선택지_B: MAX_COUNTS에 데이터시트 추정값 삽입 (12비트 ADC 기준) */
#define TDC_TOUCH_SATURATE_DETECT_ENABLE     1u
#define TDC_TOUCH_SATURATE_MAX_COUNTS     4095u  /* [확정 필요] DS §5.5 실제 최대값 */
```

> [!NOTE]
> 권고: 선택지_A (실측_E 전 안전 OFF). 데이터시트 Max Counts 항목(블로킹_E)이 해소된 후 선택지_B로 전환.

## 3. 정제된 빌드가드 최종 세트 v2 (재검증2 반영)

```c
/* ===== Phase 0: 포화 감지 ===== */
#define TDC_TOUCH_SATURATE_DETECT_ENABLE     0u  /* 실측_E 완료 후 1u로 [재검증2 수정] */
#define TDC_TOUCH_SATURATE_MAX_COUNTS        0u  /* [확정 필요] 블로킹_E 해소 후 */

/* ===== Phase 1: 노터치 게이트 ===== */
#define TDC_TOUCH_NOTOUCH_GATE_ENABLE        0u  /* 블로킹_A+B+D+G+H+I+J 완료 후 1로 */
#define TDC_TOUCH_FACTORY_NOTOUCH_COUNTS     0u  /* [확정 필요] 실측_A 완료 후 */
#define TDC_TOUCH_NOTOUCH_MARGIN_STRICT      0u  /* [확정 필요] 실측 기반만 */
#define TDC_TOUCH_NOTOUCH_MARGIN_UP          0u  /* [확정 필요] */

/* ===== Phase 2: 공장 캘리브레이션 ===== */
#define TDC_TOUCH_FACTORY_CALIB_ENABLE       0u

/* ===== Phase 3: Re-ATI ===== */
#define TDC_TOUCH_REATI_ON_NOTOUCH_ENABLE    0u  /* Phase 2 + Beta POR + 블로킹_H 완료 후 */
#define TDC_TOUCH_ATI_FULL_ENABLE            0u  /* 위와 항상 동일값 */

/* ===== Phase 4: 크래들 Re-ATI ===== */
#define TDC_TOUCH_CRADLE_REATI_ENABLE        0u

/* ===== 컴파일 타임 의존성 강제 (재검증2 확장 세트) ===== */
#if TDC_TOUCH_REATI_ON_NOTOUCH_ENABLE && !TDC_TOUCH_ATI_FULL_ENABLE
#error "REATI_ON_NOTOUCH_ENABLE requires ATI_FULL_ENABLE"
#endif
#if TDC_TOUCH_CRADLE_REATI_ENABLE && !TDC_TOUCH_REATI_ON_NOTOUCH_ENABLE
#error "CRADLE_REATI_ENABLE requires REATI_ON_NOTOUCH_ENABLE"
#endif
#if TDC_TOUCH_REATI_ON_NOTOUCH_ENABLE && !TDC_TOUCH_NOTOUCH_GATE_ENABLE
#error "REATI_ON_NOTOUCH_ENABLE requires NOTOUCH_GATE_ENABLE"
#endif
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE && (TDC_TOUCH_FACTORY_NOTOUCH_COUNTS == 0u)
#error "NOTOUCH_GATE_ENABLE requires FACTORY_NOTOUCH_COUNTS != 0"
#endif
/* 재검증2 신규 추가 */
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE && TDC_TOUCH_RTT_TUNING
#error "NOTOUCH_GATE와 RTT_TUNING 동시 활성 불가 — MULT/COMP 기준 불일치"
#endif
#if TDC_TOUCH_FACTORY_CALIB_ENABLE && TDC_TOUCH_RTT_TUNING
#error "FACTORY_CALIB_ENABLE과 RTT_TUNING 동시 활성 불가 — EEPROM 공장값 무효화"
#endif
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE && \
    (TDC_TOUCH_NOTOUCH_MARGIN_STRICT >= TDC_TOUCH_FACTORY_NOTOUCH_COUNTS)
#error "NOTOUCH_MARGIN_STRICT must be < FACTORY_NOTOUCH_COUNTS (underflow risk)"
#endif
```

## 4. 정제된 Phase 계획 v2 (재검증2 반영)

### Phase −1 (즉시 실행, Phase 0 이전)

1. `wait_re_ati_done()` 내 `SYS_WATCHDOG_REFRESH()` 삽입 — ATI_CALIB_MODE 포함
2. SATURATE_DETECT_ENABLE 기본값 0u로 수정

### Phase 0 — counts 포화 감지 stub

- `SATURATE_DETECT_ENABLE=0u` 기본 유지, 블로킹_E 해소 후 활성
- CH_TIMEOUT 재활성 여부 이중 차단 이유 확인 후 결정 (확인_12 해소 후)

### Phase 1 — 노터치 게이트 + RESEED 조건부

**추가 선행 블로킹**: 블로킹_D·G·H·I·J + RTT_TUNING #error 추가 후.

**gate_check() 정제 (언더플로 가드 포함)**:
```c
static bool tdc_notouch_gate_check(uint16_t counts)
{
    /* 언더플로 가드: 컴파일 타임에 #error로 선차단, 런타임 이중방어 */
    if (TDC_TOUCH_FACTORY_NOTOUCH_COUNTS <= TDC_TOUCH_NOTOUCH_MARGIN_STRICT) {
        return false;  /* 비정상 설정 — RTT 경보 */
    }
    uint32_t lo = (uint32_t)TDC_TOUCH_FACTORY_NOTOUCH_COUNTS
                  - TDC_TOUCH_NOTOUCH_MARGIN_STRICT;
    uint32_t hi = (uint32_t)TDC_TOUCH_FACTORY_NOTOUCH_COUNTS
                  + TDC_TOUCH_NOTOUCH_MARGIN_UP;
    return ((uint32_t)counts >= lo && (uint32_t)counts <= hi);
}
```

**사후 검증 정제 (방향 명확화)**:
```
RESEED 발행 → counts 1회 재읽기
  → counts < lo (터치 중 = counts 감소 방향): 정상 터치 진행 중, RTT 경보 불필요
  → counts > hi (상한 이탈): 이상 상태, RTT 경보 발행 ("race 추정, LTA IIR 자기치유 위임")
  → 재RESEED 없음. Beta POR 확정 후 자기치유에 위임.
```

> [!NOTE]
> 56_할루시 §3-1 정정 반영: 터치 = counts 감소 방향이므로 RESEED 후 counts < lo는 "정상 터치 중"임. "race 가능성 경보"는 counts > hi 방향만 해당.

**`s_boot_touch_ignore` 통합 설계**:
- 노터치 게이트 RESEED 완료 시 `s_boot_touch_ignore` 강제 clear 또는 READY 전이를 1 폴링 지연
- timeout 폴백 RESEED + s_boot_touch_ignore 동시 활성 시 폴링 억제 → LTA IIR 미동작 → 오염 지속 가능성 명시 (확인_10 확장)

**절전 RESEED 게이트화**: 블로킹_G 결과 의존. MCLR 완전 POR이면 불필요, 부분 보존이면 게이트 범위 확장.

**Auto-ATI 완료 직후 counts 1샘플 신뢰도**: 블로킹_I(신규) — 실측_A 수행 시 병행 확인.

### Phase 2 — 공장 캘리브레이션 + EEPROM 저장·로드

**EEPROM 로드 경로 설계 확정 필수 (구현 착수 전)**:
- `write_ati_compensation()` 시그니처 변경(인자 추가) 또는 정적 변수 신설 방법 중 선택
- RTT_TUNING과 FACTORY_CALIB 동시 활성 #error로 상호 배제 보장
- EEPROM 접근 실패 시 RTT 경보 필수 + CFX 초기화 완료 후 접근 순서 보장 + 유효 데이터 마커(magic number) 검증
- 크래들 Re-ATI 결과 EEPROM 저장 슬롯 정책: 공장값 슬롯(불변) + 런타임 슬롯(갱신 가능) 분리 검토 필요(대안_Z, 공격_2)

### Phase 3 — Re-ATI + ATI_Error 핸들러

**R3_CHARGING 비블로킹 3단계 구조 (블로킹_H 해소 후)**:
```
① re_ati_trigger() 발행 → s_ati_in_progress=true (신규 플래그)
② 폴링 중 s_ati_in_progress=true이면 터치 판정 결과 NOT_TOUCH 강제
③ tdc_drv_iqs323_is_ati_active() 확인 → false이면:
   iii-a. 현재 counts로 게이트 재확인 (ATI 중 터치 가능성)
   iii-b. 통과 시 정상 ATI 완료, s_ati_in_progress=false
   iii-c. 이탈 시 ATI 오염 → RTT 경보 + 다음 주기 R3_CHARGING 재시도
```

**ATI_Error 처리**:
- 재시도 상한 N회(제안 3회, [확정 필요]) + 소진 시 Fixed 기저 유지 + RTT 경보
- ATI_Error 후 re_ati_trigger() 재발행 시 30초 타이머 리셋 여부 명시 (확인_13 신규: R3_CHARGING 타이머 리셋 정책)

**`write_ati_compensation()` ATI_SETUP 분기 + 비블로킹 재진입 가드**:
```c
/* re_ati_trigger() 발행 후 s_ati_in_progress=true 구간 중 재호출 차단 */
if (s_ati_in_progress) {
    return;  /* ATI 진행 중 — write_ati_compensation() 재진입 금지 */
}
```

**Beta POR=0 시 사후 검증 조건분기**:
- Beta POR ≠ 0: 현재 설계(RTT 경보 + LTA IIR 자기치유 위임) 유지
- Beta POR = 0: "counts 이탈 시 noTouch 대기 재개" 또는 "폴링 강제 억제(s_boot_touch_ignore 연장)" 대안 선택 → 블로킹_D 해소 후 분기 결정 명시

**R3_CHARGING 게이트 기준**: 공장값(정적) vs 마지막 Re-ATI 후 noTouch counts(동적) 정책 결정 필요 (확인_14 신규, Phase 3 착수 전).

### Phase 4 — 크래들 Re-ATI + EEPROM 저장

- 삽입점: main.c:743 `func_cradle_lid_closed_loop()` 직전 (57_엣지 신규_D: 742+1줄 오차 확인)

## 10. 핵심 10줄

1. **[긴급] wait_re_ati_done() WDT 갱신 즉시 삽입**: 최악 ~2.3초(wait_rdy_window_closed 포함 재계산) blocking 중 WDT 갱신이 0회이며, 현재 ATI_CALIB_MODE 경로에서 이미 호출 중이므로 잠재 현장 버그다. Phase 0 이전 즉시 `iqs323.c:581~623` 수정 필수.

2. **[치명] EEPROM 로드 전달 메커니즘 환각 수정**: `write_ati_compensation(void)`는 인자 없는 함수이고 `s_mult_lsb`·`s_comp_lsb` 변수가 현재 코드에 없다. 49_종합 §2-3 코드 스니펫은 연결 고리가 없는 사문이며, Phase 2 착수 전 함수 시그니처 변경 또는 정적 변수 신설 방법을 확정해야 한다.

3. **[치명] RTT_TUNING 삼중 충돌 즉시 #error 차단**: `TDC_TOUCH_RTT_TUNING=1` + `FACTORY_CALIB_ENABLE=1` 또는 `NOTOUCH_GATE_ENABLE=1` 동시 활성 시 EEPROM 공장값이 런타임 튜닝값으로 무효화된다 — 이 두 조합을 컴파일 타임 `#error`로 즉시 차단해야 게이트 신뢰도가 보장된다.

4. **[치명] gate_check() 언더플로 #error 추가**: MARGIN_STRICT ≥ COUNTS 조합을 컴파일 타임에 차단하지 않으면 실측_A 후 MARGIN 값 설정 시 uint32 wrap-around로 게이트가 영구 거부 상태가 되며 진단 경로가 없다.

5. **[치명] R3_CHARGING 비블로킹 설계 API 선행 필수**: "다음 폴링에서 ATI_Active 확인"이 현재 코드에 존재하지 않는 API를 전제한다. 블로킹_H(`tdc_drv_iqs323_is_ati_active()` 신설)가 Phase 3 착수 전 필수이며, ATI 진행 중 폴링 결과 NOT_TOUCH 강제·ATI 완료 후 게이트 재확인을 포함한 3단계 비블로킹 구조 명세가 있어야 한다.

6. **[치명] SATURATE_DETECT_ENABLE 기본값 수정**: ENABLE=1 + MAX_COUNTS=0 조합은 매 폴링 포화 경보 범람 또는 역방향 무발동을 일으킨다. ENABLE을 0u로 수정(실측_E 완료 전 OFF)하거나 데이터시트 추정 최대값으로 초기화해야 한다.

7. **[고위험] Beta POR=0 시 사후 검증 조건분기 필요**: 블로킹_D 해소 결과가 Beta POR=0이면 "LTA IIR 자기치유 위임"이라는 사후 검증 설계 전체가 무의미해진다 — 블로킹_D 해소 직후 사후 검증 설계를 Beta POR 결과에 따라 revisit하는 명시적 게이트가 Phase 1 계획에 없다.

8. **[고위험] 크래들 EEPROM 슬롯 정책 결정 필수**: Phase 4에서 크래들 Re-ATI 결과를 EEPROM에 덮어쓰면 "공장 절대 기준 MULT/COMP"가 런타임 적응값으로 교체되어 아키텍처 원리가 장기적으로 파괴된다 — 공장값 슬롯·런타임 슬롯 분리(대안_Z) 또는 공장값 보호 정책을 Phase 4 착수 전 결정해야 한다.

9. **[블로킹 증가] Phase 1 착수 전 해소 필수 항목 7건**: 블로킹_A·B·D·G·I + RTT_TUNING #error(즉시) + EEPROM 전달 방법 결정. 이 중 하나라도 미해소이면 Phase 1 착수 불가.

10. **[수렴도] 부분 수렴 유지**: 아키텍처 원리는 2차 공격(16개 adversarial 노드 총계)을 통해서도 기각되지 않았으나, Phase −1 긴급 항목 2건(WDT·SATURATE 수정) + Phase 1 착수 전 블로킹 7건 + Phase 2·3·4 착수 전 블로킹 다수가 잔존한다. 새로운 약점 발굴 수가 감소하지 않아 3차 재검증보다는 블로킹 해소 실측을 우선한 후 구현 착수가 권고된다.
