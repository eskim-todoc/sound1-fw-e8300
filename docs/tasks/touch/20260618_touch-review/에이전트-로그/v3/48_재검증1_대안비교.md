# 48 — 재검증 라운드1 (대안비교 페르소나)

**TL;DR**: 30_종합-1차를 대안비교 관점으로 공격한다. 핵심 공격 대상: ① 크래들 노터치 보장의 암묵적 전제 미검증, ② Re-ATI 대 RESEED 선택의 비용 미평가, ③ 레이어_2·3 제거 결정의 대안 부재, ④ 공장 캘리브레이션 강제화의 규모 과소평가, ⑤ stuck-touch 가드 누락, ⑥ 충전 중 Re-ATI 기회 미언급.

## 0. 공격 방법론

30_종합-1차가 채택한 각 설계 결정을 **"대안 X를 선택했으면 어떻게 됐는가"** 관점에서 공격한다.
- 채택 결정이 충분히 비교·정당화됐는가?
- 비교 대상에서 누락된 대안이 있는가?
- 비교 기준(비용·효과·리스크)이 정량적으로 제시됐는가?

## 1. 공격_1 — 크래들 "노터치 절대 보장" 전제 미검증

### 30_종합-1차의 주장
Phase 4(크래들 Re-ATI)에서 "크래들 = 노터치 절대 보장"을 전제로 race-free 구간이라 서술한다. `func_cradle_lid_closed_loop`(`main.c:807`)에서 터치 폴링 완전 중단 → 뚜껑 열림 시 WDT 리셋 재부팅.

### 공격

**크래들 뚜껑 닫힘 감지 → WDT 리셋까지의 전환 구간이 race-free 인가?**

뚜껑이 닫히는 순간(뚜껑 닫힘 이벤트 감지)부터 실제로 `func_cradle_lid_closed_loop` 루프에 진입해 터치 폴링이 멈추기까지, 또는 반대로 뚜껑이 열리는 순간 WDT 리셋이 발생하기 전까지 짧은 전환 구간이 존재한다.

- **전환 구간 1 (닫힘 진입)**: 뚜껑 닫힘 이벤트 → `func_cradle_lid_closed_loop` 분기 진입 전까지, 정상 터치 폴링이 마지막 1회 실행될 수 있다. 이 시점에 터치 중이면 Phase 4 Re-ATI 계획이 "이미 터치 중인 채" 진입한다.
- **전환 구간 2 (열림 복귀)**: 뚜껑이 열리면 WDT 리셋 재부팅이 발생한다 — 이것은 전제 맞음. 그러나 **Phase 4 Re-ATI를 "뚜껑 닫힘 진입 시점"에 수행**(`main.c:742 앞, led_force_fade_off() 직후`)한다면, 이 시점이 진정한 "노터치 확정 후"인지 코드 레벨에서 미검증이다.
- **대안 미비교**: Phase 4 Re-ATI를 "뚜껑 닫힘 후 N ms 안정 대기 → 노터치 게이트 재확인 → Re-ATI"로 설계하는 대안이 검토되지 않았다. 복잡도 비용은 Phase 1의 노터치 게이트 로직을 재사용하면 ~5줄 추가로 충분하다 [추정].

**판정**: `main.c:807` 루프 진입 시점과 Re-ATI 수행 시점의 선후 관계 코드 확인 [확정 필요]. "크래들 = 절대 노터치"는 뚜껑이 닫힌 *후* 폴링이 중단된 *시점부터*만 참이다. Phase 4 설계에 진입 시점 노터치 재확인 게이트 누락 가능성이 있다.

## 2. 공격_2 — Re-ATI vs RESEED 선택의 비용 편향

### 30_종합-1차의 주장
"노터치 게이트 하 RESEED < Re-ATI: Re-ATI가 게인+comp+baseline 전부 재보정 → 우월." Phase 1은 RESEED 게이트, Phase 3에서 Re-ATI로 전환.

### 공격

**이 비교에서 Re-ATI의 비용이 과소평가됐다.**

| 항목 | RESEED | Re-ATI(노터치 후) |
|---|---|---|
| 소요 시간 | RESEED 레지스터 write 1회, 즉시 | 최대 1초(10×100ms 블로킹, 코드 확정) |
| 부팅 경로 블로킹 | 없음 | 매 부팅 최대 1초 블로킹 추가 |
| WDT 갱신 필요 | 없음 | SYS_WATCHDOG_REFRESH() 명시 필수 |
| ATI_Error 가능성 | 없음 | 있음(§5.11, 핸들러 필수) |
| MULT/COMP 변경 여부 | 없음 | 있음 → 이후 threshold 마진 변경 가능 |
| 공장 캘리브값 의미 | EEPROM 기준값 보존 | Re-ATI로 MULT/COMP 갱신 → 공장값과 괴리 발생 |

**핵심 문제**: Phase 3에서 Re-ATI를 활성화하면 MULT/COMP가 갱신된다. 이때 **공장 캘리브레이션 시점의 MULT/COMP(EEPROM 저장값)와 런타임 Re-ATI 결과가 달라진다.** 다음 부팅에서 `write_ati_compensation()`이 EEPROM의 공장값으로 덮어쓰면, 런타임 Re-ATI의 환경 적응 결과가 소멸된다(30_종합 §2 Phase 4 [!] 항목에서 언급됐으나 이 모순의 체계적 해소 방법이 제시되지 않았다).

**대안 미비교**: "Phase 1에서 Re-ATI 대신 RESEED만 영구 운용(공장 MULT/COMP 고정 + RESEED 게이트)"하는 대안. 이 경우:
- 공장 MULT/COMP가 환경 드리프트로 벗어나는 속도가 실측으로 확인되지 않는 한, Re-ATI의 이점이 검증되지 않음 [추정].
- Re-ATI 도입 비용(1초 블로킹·ATI_Error 핸들러·WDT·Phase 3 구현 규모)이 실측_A(noTouch counts 장기 드리프트)로 정당화되지 않으면 과잉 설계일 수 있다.

**판정**: Re-ATI 채택이 "RESEED < Re-ATI" 단순 비교로만 정당화됐다. Re-ATI 도입 결정은 실측_A(드리프트 폭)의 결과로 게이트화 해야 하나, 30_종합-1차의 Phase 계획에서 이 게이팅이 명시적으로 분리되지 않았다. Phase 3 REATI_ON_NOTOUCH_ENABLE 기본값=0이긴 하나, **왜 Re-ATI를 선택했는가의 정량 근거가 없는 채 아키텍처 원리로 고정**된 점이 약점이다.

## 3. 공격_3 — 레이어_2·3 제거의 대안 부재

### 30_종합-1차의 주장
"N샘플 안정성 확인이 race 창을 오히려 확대." 레이어_2·3 제거, 레이어_1(절대 윈도우) + 사후 검증 1회만 채택.

### 공격

**race 창 확대 주장이 정량 근거 없이 채택됐다.**

레이어_2(N샘플 안정성 확인)는 race 창을 "N×폴링 주기"만큼 연장하는 것이 맞다. 그러나:

- 현재 폴링 주기 200ms 기준, N=3이면 race 창 추가 = 600ms.
- 반면 레이어_2의 실익: 노이즈 1회 값이 게이트를 통과해 RESEED/Re-ATI를 오발하는 경우를 차단.
- **부분 터치(counts가 절대 윈도우 하한에 걸치는 중간값)**: 레이어_1 단독 + MARGIN_STRICT 엄격화가 이를 대응할 수 있는가? MARGIN_STRICT < Threshold/2라는 조건이 제시됐지만, 부분 터치의 counts 분포가 실측되지 않은 상태에서 이 조건이 충분한지 미확정 [확정 필요].

**대안**: 레이어_2 대신 **단일 샘플 + 에지 마스크** 설계. 직전 폴링 주기에 counts가 윈도우 안에 있었고 이번도 안에 있으면 게이트 통과 — N샘플이 아닌 "연속 2샘플" 확인. race 창 추가 = 1×폴링 주기(200ms)만으로 노이즈 오통과를 상당 부분 차단할 수 있다 [추정]. 이 대안이 30_종합-1차에서 검토되지 않았다.

**판정**: 레이어_2·3 제거 결정은 "race 창 확대"라는 단일 논리로 이루어졌다. "연속 2샘플 확인" 같은 중간 대안과의 비교 없이 양극단(N샘플 vs 1샘플)만 비교한 점이 약점이다.

## 4. 공격_4 — 공장 캘리브레이션 강제화의 규모 과소평가

### 30_종합-1차의 주장
Phase 2(공장 캘리브레이션 + EEPROM 저장·로드)가 "전 아키텍처의 공통 선행 조건"이며, Phase 1 활성화 전에 FACTORY_NOTOUCH_COUNTS가 필요하다.

### 공격

**이 전제가 사실상 전체 Phase 계획을 공장 공정 변경 완료 전까지 동결시키는 효과를 낳는다.**

현실 문제:
- `TDC_TOUCH_NOTOUCH_GATE_ENABLE=0` 기본값으로 Phase 1을 미활성화 — 즉 게이트 미동작 = 현재와 동일한 무조건 RESEED.
- Phase 1 활성화 조건: 실측_A + 실측_B + 공장 캘리브 EEPROM 경로 확립. 이 중 하나라도 미완이면 Phase 1은 영구 비활성.
- CFX 파서 크기 확인(블로킹_C)이 Phase 2 선행 — CFX 코드 접근이 불가한 상태에서 블로킹_C 해소 시점이 외부 요인에 달림.

**대안 미비교**: 공장 캘리브레이션 없이 동작하는 **"런타임 자동 기준값 추정"** 대안이 검토되지 않았다.
- 방안: 부팅 후 일정 시간(예: 10초) 동안 counts 분포를 관찰해 최빈값 또는 중앙값을 noTouch 기준으로 잠정 사용. 공장값이 없으면 이 추정값을 사용하고, 공장값이 EEPROM에 존재하면 이를 우선 사용.
- 이 방안은 확률적으로 불완전하지만, **공장 공정 변경 전에도 Phase 1 노터치 게이트를 부분 동작시켜 현재 문제(무조건 RESEED)를 즉시 개선**할 수 있다.
- 30_종합-1차는 이 대안을 "공장값 없으면 어떤 SW도 Cold-Start Ambiguity를 근본 해소할 수 없음"이라는 단일 문장으로 기각했다 — 그러나 "근본 해소"가 목표가 아니라 "현재보다 나은 확률적 개선"이 목표라면 이 대안이 현실적 가치를 가진다.

**판정**: 공장 캘리브레이션을 "전제 조건"으로 절대화함으로써, 공장 공정 확립 전에는 아무것도 동작하지 않는 All-or-Nothing 구조가 됐다. 중간 단계로 동작 가능한 "런타임 추정 기준값" 대안이 명시적으로 기각되지 않은 채 누락됐다.

## 5. 공격_5 — stuck-touch 가드(무한 터치 방어) 누락

### 30_종합-1차의 주장 (부재)
개념정리_터치동작모델.md §5 의문_5에서 "무한 터치(의문5): stuck-touch timeout 재활성이 본질"로 정의됐다. v1/v2 에이전트-로그에서도 `TDC_TOUCH_LONG_TOUCH_MS`(현재 2400ms) 관련 stuck-touch 경로가 언급됐다. 그러나 30_종합-1차의 Phase 0~4 계획에서 **stuck-touch 가드 재활성(CH_TIMEOUT 재활성)이 등장하지 않는다.**

### 공격

현재 코드: `write_register(CH_TIMEOUT, 0x00, 0x07)` — CH_TIMEOUT 비활성(이중 차단 중 하나). 이를 이중 차단한 이유가 30_종합-1차에 설명되지 않았다.

- **무한 터치 시나리오**: 부팅 시 터치 중 RESEED(게이트 미활성 시) → LTA가 터치값으로 오염 → 손 떼도 delta≈0 → 터치 인식 지속. 이 경우 CH_TIMEOUT이 활성화돼 있으면 timeout 후 자동 해제가 가능하다.
- **30_종합-1차 §1-1 층위 구조**: 층위 3(자기치유)에서 "Beta POR 확인 필요"라고 했으나 CH_TIMEOUT에 대한 언급이 없다.
- **대안 비교**: CH_TIMEOUT 재활성(예: 5000ms) + 노터치 게이트 조합 vs 노터치 게이트만. 전자는 게이트 실패 시 자동 복구 경로가 하나 더 생긴다. Phase 0~4 어디에도 이 조합이 검토되지 않았다.

**판정**: 무한 터치 방어(stuck-touch 가드, CH_TIMEOUT 재활성)가 Phase 계획에서 명시적으로 처리되지 않았다. 분석.md §4-7에 "Phase2 이벤트 모드(선택)"으로 언급된 것과 비교하면 CH_TIMEOUT은 더 단순한 방어 수단이다. 누락이 의도적 배제인지 실수인지 확인 필요.

## 6. 공격_6 — 충전 중(df_Connected) Re-ATI 기회 미검토

### 30_종합-1차의 주장 (부재)
전제 4에 "충전기 연결 시 절전 진입 안 함, 터치 계속 동작"이 명시됐다. 그러나 이것이 Re-ATI 기회로 활용되는 방안이 Phase 계획에 없다.

### 공격

충전 중 상태는 다음 특성을 가진다:
- 롱터치해도 절전 진입 안 함 → 사용자가 충전기 연결 후 기기를 내려놓는 시나리오에서 수 분간 노터치 구간이 발생할 가능성이 높다 [추정].
- 크래들 뚜껑과 달리 "노터치 보장"은 아니지만, **노터치 상태가 확인되면(게이트 통과 시) Re-ATI 수행하기에 안전한 구간**이다.
- 크래들 Phase 4와 달리, 충전기 연결은 뚜껑 없이도 발생하는 일상적 시나리오 — 즉 Phase 4 크래들 기회보다 발생 빈도가 높을 수 있다 [추정].

**대안 미비교**: `df_Connected` 상태에서 일정 시간(예: 30초) 연속 노터치 확인 시 Re-ATI 수행하는 "충전 중 기회 Re-ATI" 경로. Phase 4 크래들 Re-ATI와 구조적으로 동일하나 크래들 없이도 동작한다. 이 대안이 30_종합-1차에서 검토되지 않았다.

**판정**: 시스템 전제에 명시된 충전 중 동작 특성이 Re-ATI 기회로 활용되는 경로가 Phase 계획에 없다. 크래들을 보유하지 않은 사용자 환경에서 Phase 4는 작동하지 않으므로, 충전 중 Re-ATI가 더 범용적 대안이 될 수 있다.

## 7. 공격_7 — write_ati_compensation() 내부 레지스터 목록 미확인 전 삽입점 확정

### 30_종합-1차의 주장
"블로킹_F: write_ati_compensation() 내 레지스터 write 전체 목록(L696~) 확인 필요"라고 블로킹으로 지정했으나, Phase 1 삽입점 설계를 **이 확인 이전에 확정**했다.

### 공격

30_종합-1차 §2-3의 삽입점 통합 설계:
```
write_ati_compensation()         ← 항상 실행 유지
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE
  tdc_drv_iqs323_notouch_gate_reseed()
#else
  write_register(0xC0, 0x08, 0x00)
#endif
  write_register(0xC0, 0x00, 0x07)   ← CH_TIMEOUT 항상 실행
```

이 설계의 전제: `write_ati_compensation()`이 RESEED 직전에 반드시 완전 실행돼야 하는 레지스터들을 모두 포함한다. 그런데 **블로킹_F가 미해소**이므로 이 전제가 검증되지 않았다.

- 만약 `write_ati_compensation()` 내부에 RESEED보다 *이후*에 실행해야 할 레지스터가 있다면 삽입점이 틀린다.
- 만약 `write_ati_compensation()` 내부에 게이트 조건(노터치 여부)에 따라 스킵해야 할 레지스터가 있다면 "항상 실행" 원칙이 틀린다.
- 이 두 경우를 배제하는 증거가 30_종합-1차에 없다.

**판정**: 블로킹_F를 블로킹으로 지정하면서도 삽입점 설계를 확정한 것은 모순이다. 30_종합-1차가 "Phase 1 착수 전 확인 필요"로 분류했다면(확인_4) 삽입점 코드 예시를 "임시" 또는 "[확인_4 후 확정]"으로 표기했어야 한다. 현재 서술은 확정 설계처럼 읽힌다.

## 8. 공격_8 — "실측_B 없이 Phase 1 활성화 불가" 강도 과소평가

### 30_종합-1차의 주장
"블로킹_B: 방전 실측(실측1) — ESD 누적 시 counts가 윈도우 이탈 → 게이트 항상 폴백"

### 공격

ESD 누적으로 counts가 공장 기준보다 낮아지는 시나리오에서:
- 부팅 시 counts < 공장 noTouch 기준 윈도우 → 게이트가 "터치 중"으로 판정 → RESEED 보류 → 손 떼길 기다리나 손은 이미 없음 → BOOT_WAIT_MS timeout → **저신뢰 폴백 RESEED + RTT 경보**.
- 이 폴백이 현재 무조건 RESEED보다 **나은가 나쁜가?** ESD 상태에서 무조건 RESEED는 LTA를 ESD-오염된 counts로 seed → 손 뗌 후에도 오작동. 폴백 RESEED도 동일한 오작동이 예상된다.

즉, 실측_B가 해소되지 않으면 ESD 환경에서:
- 현재(게이트 없음): LTA 오염 → 오작동
- Phase 1 활성화 후: 게이트 timeout → 폴백 RESEED → 동일한 LTA 오염 → 동일 오작동

**두 경우의 최종 결과가 같다.** ESD 대응이 실질적으로 개선되지 않는다. 30_종합-1차가 "ESD = 독립 트랙"이라고 분리했지만, 노터치 게이트가 ESD 상태에서 어떻게 거동하는지의 명시적 분석이 없다.

**판정**: ESD 환경에서 Phase 1이 현재보다 나쁜 UX를 만들 가능성(게이트 timeout 대기 후 동일 폴백)이 분석되지 않았다. BOOT_WAIT_MS timeout 값이 [확정 필요]인 점도 이 위험을 가중시킨다.

## 10. 2차 종합에 대한 권고

1. **공격_2(높음)**: Re-ATI 채택 결정을 실측_A(드리프트 폭) 결과로 게이트화해야 한다. "RESEED만 + 공장 MULT/COMP 고정" 대안과 명시적 비교 필요. Re-ATI 도입 시 공장값-런타임 ATI 괴리 해소 방안도 명시 필요.
2. **공격_4(높음)**: "런타임 추정 기준값" 대안을 Phase 1.5(임시 기준값 운용)로 삽입해 공장 공정 완료 전 중간 개선 경로를 확보하는 방안 검토.
3. **공격_8(높음)**: ESD 환경에서 Phase 1 게이트 동작(폴백 시나리오)을 ESD 독립 트랙과 교차 분석해 "게이트 활성이 ESD 환경에서 무해함" 또는 "BOOT_WAIT_MS 설정에 따라 ESD 환경 UX가 달라짐"을 명시.
4. **공격_5(중)**: CH_TIMEOUT 재활성 검토를 Phase 0 또는 Phase 1에 추가(현재 이중 차단 유지 이유 명시 또는 재활성 조건 정의).
5. **공격_7(중)**: 블로킹_F 해소 전까지 삽입점 코드 예시를 "[확인_4 후 확정]"으로 표기 — 현재 확정 설계처럼 읽히는 것 방지.
