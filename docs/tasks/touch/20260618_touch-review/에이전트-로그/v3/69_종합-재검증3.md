# 69 — v3 종합-재검증3 (59_종합-재검증2 + 61~68 통합 정제)

**TL;DR**: 59_종합-재검증2를 8개 adversarial 노드(61~68)로 3차 공격한 결과를 통합 정제. 즉시 코드 확인으로 해소된 거짓 블로킹 3건(블로킹_H·K·확인_12)이 수렴됐고, 신규 치명·고위험 발굴로 블로킹 목록이 재조정됐다. 아키텍처 원리("공장 절대 기준 → 노터치 게이트 → Re-ATI")는 3회 adversarial 공격 누적(24+8=32개 노드)에서도 기각되지 않았다. 수렴도: **부분 수렴 유지(수렴 방향 강화)** — 신규 약점 발굴 수가 2차 9건→3차 주요 7건으로 감소 추세이나, 치명·고위험 잔존으로 수렴 확정 불가.

---

## 1. 아키텍처 원리 재확인 (3차 공격 통과)

> **"공장 절대 기준으로 노터치를 판별하고, 노터치가 확인된 순간에만 Re-ATI를 허용한다."**

재검증3(61~68) 8개 노드를 통해서도 이 원리 자체는 기각되지 않았다. 대안비교(68) 3라운드 누적(48·58·68) 공격에서도 기각 근거가 발굴되지 않아 **아키텍처 원리 수렴 강화**로 판정한다.

단, 재검증3에서 두 가지 중요한 구조적 정제가 확정됐다.

### 1-1. 층위 구조 (재검증3 정제)

| 층위 | 담당 | 재검증3 정제 사항 |
|---|---|---|
| **층위 0 — Fixed 기저** | 공장 MULT/COMP를 매 부팅 적용 | `write_ati_compensation()` 인자 전달: **선택지_2(정적 변수 신설) 권고로 변경** — 선택지_1(인자 추가)은 `s_ati_in_progress` 재진입 가드와 교차 시 인자 소멸 문제 발굴(68_대안비교 공격_1). BOARD_VARIANT별 캘리브 슬롯 분리 정책 및 SLEEP ATI 경로 별도 설계 필수(66_할루시 약점_1·2) |
| **층위 1 — 노터치 게이트** | 공장 noTouch 절대 기준으로 부팅 판별 | `gate_check()` **hi 상한 오버플로 가드 추가 필수**(67_엣지 신규_1, 65_회귀 회귀_P1). 게이트 진행 전 구간 `s_gate_in_progress` 플래그 또는 `s_boot_touch_ignore` 범위 확장으로 억제 필요(61_repro 신규_D). 장기 드리프트 후 공장 기준 게이트 자기 모순 경로를 §8 미해결에 추가 |
| **층위 2 — 조건부 Re-ATI** | 게인+baseline 전체 재보정 | **블로킹_H 해소**: `tdc_drv_iqs323_is_auto_ati_done()` 공개 API가 `iqs323.c:926`에 이미 존재(63_완전성). ati_event vs ati_active 구분은 [확정 필요]로 대체. `re_ati_trigger()` MSB=0x00 → CH_TIMEOUT 덮어쓰기 확정 버그 즉시 수정 필수(63·64·61 공통). 3단계 비블로킹 R3_CHARGING 설계에 apply_settings() 동시 실행 상호 배제·iii-c 재시도 게이트 재확인·롱터치 카운터 freeze 명시 필요(62·67) |
| **층위 3 — 자기치유** | 손뗌 후 LTA IIR 수렴 | counts>hi 경로에서 ESD 방전 후 LTA 상향 수렴 → false touch 위험 경로 추가(62_race 공격_1). ATI_Error N회 소진 후 공장 MULT/COMP를 IC에 명시 재write 필요(확인_16 신규, 67_엣지 신규_3) |
| **층위 4 — 크래들 race 소멸** | 뚜껑 닫힘 = 노터치 보장 | `func_cradle_lid_closed_loop()` 직전 삽입점에서 I2C 윈도우 상태·force_window_open 비용 미분석(66_할루시 약점_3). 확인_8을 블로킹 수준으로 격상 검토 필요 |

### 1-2. 확인_12 즉시 해소 (코드 주석 확인)

`iqs323.c:1152~1155` 주석에서 CH_TIMEOUT 이중 차단 이유가 이미 명시됐음을 63_완전성에서 확인:

> `/* CH0~CH2 stuck-touch timeout 비활성화 → auto-reATI 트리거 경로 차단. ATI Mode=Disabled(0x08)와 이중 방어. */`

**확인_12는 즉시 해소**. CH_TIMEOUT 재활성 검토 시점은 Phase 0·1이 아닌 **Phase 3(ATI Full 활성화 시점)**으로 재이관.

## 3. 신규 치명·고위험 결함 (재검증3 추가)

### 3-1. [치명·즉시] `re_ati_trigger()` CH_TIMEOUT 덮어쓰기 — 확인에서 버그 확정으로 격상 (61·63·64 공통)

**코드 확인** (`iqs323.c:569~579`):
```c
reg.bytes[2] = 0x00;   /* MSB 전체 초기화 → CH_TIMEOUT 비활성화(0x07) 소멸 */
reg.elements.lsb.re_ati = TDC_DRV_IQS323_TRIGGER_RE_ATI;
```

Phase 3에서 `re_ati_trigger()` 호출 시마다 CH_TIMEOUT 이중 방어의 절반이 무효화된다. 이중 차단 이유(§1-2)를 이미 알았으므로, 이 버그는 Phase 3 이전에 수정해야 한다.

**수정 (Phase 3 착수 전 필수)**:
```c
static bool re_ati_trigger(void)
{
    tdc_drv_iqs323_reg_system_control_t reg;

    reg.bytes[0]             = TDC_DRV_IQS323_REG_ADDR_SYSTEM_CONTROL;
    reg.bytes[1]             = 0x00;
    reg.bytes[2]             = 0x07;  /* CH_TIMEOUT 비활성화 유지 (ch0/ch1/ch2_timeout_disable=1) */
    reg.elements.lsb.re_ati  = TDC_DRV_IQS323_TRIGGER_RE_ATI;

    return write_register(reg.bytes[0], reg.bytes[1], reg.bytes[2]);
}
```

> [!IMPORTANT]
> 확인_13("re_ati_trigger MSB=0x00 write 부작용 분석 필요")은 코드 두 라인 대조로 즉시 확정 가능하다. 이것은 확인 항목이 아닌 **즉시 수정 버그**다.

### 3-2. [치명] gate_check() 상한 hi 오버플로 가드 누락 (65_회귀 회귀_P1, 67_엣지 신규_1)

59_종합-재검증2 §2-2에서 lo 언더플로 `#error`를 추가했으나, hi 방향 오버플로 가드가 대칭적으로 누락됐다.

`hi = (uint32_t)FACTORY_NOTOUCH_COUNTS + MARGIN_UP`에서 합이 uint16 범위를 초과하면 wrap-around → `counts <= hi`가 사실상 항상 거짓 → 게이트 영구 거부.

**수정: §3 빌드가드 세트에 추가**:
```c
#if TDC_TOUCH_NOTOUCH_GATE_ENABLE && \
    ((uint32_t)TDC_TOUCH_FACTORY_NOTOUCH_COUNTS + TDC_TOUCH_NOTOUCH_MARGIN_UP > 0xFFFFu)
#error "FACTORY_NOTOUCH_COUNTS + NOTOUCH_MARGIN_UP overflows uint16 range (hi overflow risk)"
#endif
```

### 3-3. [치명] tdc_touch_config.h 신규 define 전무 — 빌드가드 세트 v2 실효 없음 (61_repro 신규_B, 63_완전성 §6)

59 §3의 빌드가드 세트 v2 전체가 현재 `tdc_touch_config.h`에 존재하지 않는다. 현재 define 13개: `TDC_BOARD_VARIANT`, `TDC_DRV_IQS323_ATI_DUMP_ENABLE`, `TDC_TOUCH_ATI_CALIB_MODE` 등. 신규 필요 define 10종+: `TDC_TOUCH_SATURATE_DETECT_ENABLE`, `TDC_TOUCH_NOTOUCH_GATE_ENABLE`, `TDC_TOUCH_RTT_TUNING` 등 전무.

특히 `TDC_TOUCH_RTT_TUNING`은 `iqs323.c` 내부에서 `#if TDC_TOUCH_RTT_TUNING`으로 참조되는데 `tdc_touch_config.h`에 정의가 없어 `#error` 가드가 항상 `#if 0`으로 평가돼 보호 효과가 없다.

**요구 조치**: Phase 1 착수 전 `tdc_touch_config.h`에 신규 define 일괄 추가. 추가 시 기존 13개 define 역할 중복 검토(특히 `TDC_TOUCH_ATI_CALIB_MODE` vs `TDC_TOUCH_FACTORY_CALIB_ENABLE`) 필수.

### 3-4. [치명] WDT 갱신 삽입 보완 — 2차 WDT 공백 및 SLEEP_MEASURE_MODE 누락 (64_통신전력, 65_회귀 회귀_Z2)

Phase-1 수정에서 `Sys_Delay` 직전에만 `SYS_WATCHDOG_REFRESH()`를 삽입하면, `read_register()` 1회당 `force_window_open × 2 + wait_rdy_window_closed × 2 = 최악 130ms` 연속 WDT 미갱신 구간이 잔존한다. WDT timeout < 130ms 시 Phase-1 단순 삽입 후에도 WDT 리셋 발생 가능 [확정 필요: WDT timeout 설정값].

또한 `tdc_drv_iqs323_sleep_measure_dump()` (`iqs323.c:893`)도 `wait_re_ati_done()`을 호출하므로 **3개 경로 모두 WDT 갱신 없이 blocking** — ATI_CALIB_MODE·SLEEP_MEASURE_MODE·미래 Phase 3.

**수정 (Phase-1 보완)**:
```c
/* wait_re_ati_done() 루프 내 read_register 직전에도 삽입 필요 */
SYS_WATCHDOG_REFRESH();  /* 130ms 연속 busy-wait 진입 전 */
if (!read_register(...)) { ... }
SYS_WATCHDOG_REFRESH();  /* Sys_Delay 직전 (기존 Phase-1 위치) */
Sys_Delay(TDC_DRV_IQS323_DEFAULT_DELAY_MS * 100);
```

### 3-5. [치명] BOARD_VARIANT별 MULT/COMP 다중화 및 SLEEP ATI 경로 완전 누락 (66_할루시 약점_1·2)

**약점_1 (BOARD_VARIANT 다중화)**: 현재 `write_ati_compensation()`은 `TDC_BOARD_VARIANT`(0=MINI/1=DEVELOP/2=PACKAGE)마다 컴파일 타임에 다른 MULT/COMP 상수를 선택하는 구조다. 59 종합의 EEPROM 공장 캘리브 설계는 단일 보드 가정이며 다른 변형에 같은 EEPROM 슬롯값이 로드되면 게인 불일치 발생. Phase 2 착수 전 BOARD_VARIANT별 캘리브 슬롯 분리 정책 또는 "캘리브 결과는 해당 보드 전용" 정책 명시 필수.

**약점_2 (SLEEP ATI 경로 누락)**: 코드에 `TDC_DRV_IQS323_SLEEP_ATI_MULT_*` 상수 세트가 별도 존재 (`iqs323.c:657~690`). `apply_sleep_settings()`는 `write_ati_compensation()`과 분리된 독립 경로를 가진다. Phase 2 EEPROM 로드 설계는 `apply_settings()` 경로만 다루고 절전 경로에서 공장 캘리브 결과 미적용 — 구조 공백 확정.

### 3-6. [치명] 게이트 진행 구간 억제 설계 미완 (61_repro 신규_D)

READY 전이 후 노터치 게이트 RESEED 완료 전 구간에 `s_boot_touch_ignore`가 미설정 상태이면 터치 이벤트가 상위 로직에 즉시 전달된다. "RESEED 완료 시 clear" 또는 "1 폴링 지연" 설계 모두 이 구간을 완전히 억제하지 못한다.

**요구 조치**: Phase 1 착수 전 `s_gate_in_progress` 플래그 신설 또는 `s_boot_touch_ignore` 범위 확장(READY 전이 → RESEED 완료까지 전체 구간) 설계 확정. 확인_15를 **블로킹_L**로 격상.

### 3-7. [치명] All-or-Nothing 구조의 대안 기각 3라운드 통과 (63_완전성 §5)

공장 캘리브 미완료 시 Phase 1 착수 불가를 의도적으로 선택한 것인지, 런타임 추정 기준값 대안을 검토하지 않아 결과적으로 그렇게 된 것인지 §8 미해결 또는 §9에 명시돼야 한다. 의도적 선택이라면 "공장 캘리브 완료 전까지 Phase 1 착수 불가 = 전략적 결정"임을 명시.

### 3-8. [고위험] R3_CHARGING 비블로킹 3단계 설계 보완 필요 (62_race, 65_회귀, 67_엣지)

**(a) apply_settings() 동시 실행 상호 배제 미명시** (62 공격_2): 부팅 apply_settings()와 R3_CHARGING 트리거가 동시 활성 시 `s_ati_in_progress` 플래그 상호 배제 구조가 없다.

**(b) iii-c 재시도 게이트 재확인 미명시** (62 공격_2): 재시도 시 게이트 재확인 포함 여부가 §4 Phase 3에 없어 ATI 오염 루프 위험 경로가 열려 있다.

**(c) 롱터치 카운터 freeze 미설계** (67_엣지 신규_4): `s_ati_in_progress=true` 구간 NOT_TOUCH 강제로 롱터치 카운터가 리셋돼 절전 진입 지연 최악 4700ms 또는 롱터치 오인식 발생. 확인_17 신규 — Phase 3 착수 전 필수.

**(d) ATI_Error 소진 후 공장값 재write 미명시** (67_엣지 신규_3): N회 소진 후 "Fixed 기저 유지"가 공장 MULT/COMP를 IC에 명시 재write하는 것인지 IC 내부 오염값 방치인지 불명. 확인_16 신규 — DS §5.11 ATI_Error 시 IC 내부 MULT/COMP 상태 확인 필수.

---

### 3-9. [고위험] Phase 3 ③-a 게이트 재확인 기준 미지정 (65_회귀 회귀_P2, 63_완전성 §4)

Re-ATI 완료 후 IC는 새 MULT/COMP 기준으로 counts를 생성한다. 이 시점 공장 기준 `FACTORY_NOTOUCH_COUNTS`(예: 400)로 게이트 재확인하면 정상 ATI 완료 counts(예: ATI Target 512)가 게이트 이탈로 오판된다. §4 Phase 3의 "현재 counts로 게이트 재확인"에 "어떤 기준값을 쓰는가"가 없다 — 확인_14 의존성을 Phase 3 설계 본문에 명시 연결 필수.

---

### 3-10. [고위험] 절전 RESEED 게이트화를 블로킹_G에 귀속해 즉시 설계 가능 경로를 미룸 (62_race 공격_5)

절전 RESEED 오염→ULP 즉시 재부팅 루프는 MCLR POR 완전성 여부와 무관하게 GATE_ENABLE=0 환경에서 현재 재현 가능하다. Phase 1 노터치 게이트 설계에 "절전 진입 RESEED에도 동일 게이트 적용(FACTORY_NOTOUCH_COUNTS 기준 체크)"을 블로킹_G 대기 없이 포함 가능하며 §4 Phase 1에 명시해야 한다.

## 4. 정제된 빌드가드 최종 세트 v3 (재검증3 반영)

```c
/* ===== Phase 0: 포화 감지 ===== */
#define TDC_TOUCH_SATURATE_DETECT_ENABLE     0u  /* [재검증2 수정] 실측_E 완료 후 1u로 */
#define TDC_TOUCH_SATURATE_MAX_COUNTS        0u  /* [확정 필요] 블로킹_E 해소 후 */

/* ===== Phase 1: 노터치 게이트 ===== */
#define TDC_TOUCH_NOTOUCH_GATE_ENABLE        0u  /* 블로킹_A+B+D+G+L+J 완료 후 1로 */
#define TDC_TOUCH_FACTORY_NOTOUCH_COUNTS     0u  /* [확정 필요] 실측_A 완료 후 */

#define TDC_TOUCH_CRADLE_REATI_ENABLE        0u  /* 대안_Z 슬롯 정책 확정 후 */
```

## 5. 정제된 Phase 계획 v3 (재검증3 반영)

### Phase −1 (즉시 실행, 현재 진행 중)

1. **`wait_re_ati_done()` WDT 갱신 보완**: `Sys_Delay` 직전뿐만 아니라 `read_register()` 직전에도 `SYS_WATCHDOG_REFRESH()` 삽입. ATI_CALIB_MODE·SLEEP_MEASURE_MODE 두 경로 모두 커버. [확정 필요: WDT timeout 값으로 130ms 비교]
2. **`SATURATE_DETECT_ENABLE` 기본값 0u 수정**
3. **`re_ati_trigger()` MSB=0x07 수정** (CH_TIMEOUT 비활성화 유지) — Phase 3 착수 전이 아닌 **즉시** 처리로 격상.
4. **`tdc_touch_config.h` 신규 define 추가** (기존 13개와 역할 중복 검토 후)

### Phase 0 — 단순화 (재검증3 권고)

68_대안비교 공격_2에서 Phase 0(SATURATE=0u 기본 + CH_TIMEOUT 결정 보류)는 실질 동작 없는 빈 단계임이 지적됐다. **대안: Phase 0를 제거하고 블로킹_E 해소 후 Phase 1 착수 시 SATURATE와 CH_TIMEOUT을 함께 활성화** — 단, CH_TIMEOUT 재활성은 Phase 3(ATI Full 활성화) 시점에서만 의미 있으므로 Phase 1에서는 보류.

### Phase 1 — 노터치 게이트 + RESEED 조건부 (보완)

**추가 선행 블로킹**: 블로킹_A·B·D·G·J·L + tdc_touch_config.h 신규 define 추가 완료 후.

**게이트 억제 플래그 설계 (신규)**:
```
노터치 게이트 진행 전 → s_gate_in_progress=true 또는 s_boot_touch_ignore 범위 확장
  → RESEED 완료(또는 timeout 폴백) 후 s_gate_in_progress=false
  → 이 전체 구간 동안 터치 이벤트 상위 전달 차단
```

**gate_check() 정제 v3 (상한 가드 추가)**:
```c
static bool tdc_notouch_gate_check(uint16_t counts)
{
    /* lo 방향 런타임 이중방어 (컴파일 타임 #error 보완) */
    if (TDC_TOUCH_FACTORY_NOTOUCH_COUNTS <= TDC_TOUCH_NOTOUCH_MARGIN_STRICT) {
        return false;  /* 비정상 설정 — 컴파일 타임 가드가 통과됐더라도 방어 */
    }
    uint32_t lo = (uint32_t)TDC_TOUCH_FACTORY_NOTOUCH_COUNTS
                  - TDC_TOUCH_NOTOUCH_MARGIN_STRICT;
    uint32_t hi = (uint32_t)TDC_TOUCH_FACTORY_NOTOUCH_COUNTS
                  + TDC_TOUCH_NOTOUCH_MARGIN_UP;
    /* hi 방향 런타임 이중방어 */
    if (hi > 0xFFFFu) {
        hi = 0xFFFFu;  /* 오버플로 클램프 — 컴파일 타임 #error 보완 */
    }
    return ((uint32_t)counts >= lo && (uint32_t)counts <= hi);
}
```

**사후 검증 3분기 완전 명세** (68_대안비교 공격_6 정상 케이스 추가):
```
RESEED 발행 → counts 1회 재읽기
  → counts < lo  (터치 중 = counts 감소 방향): 정상 터치 진행, RTT 경보 불필요 — 무해
  → counts ∈ [lo, hi] (윈도우 내 유지): 정상 noTouch — Re-ATI 가능 상태 확인
  → counts > hi  (상한 이탈): ESD 방전 또는 이상 상태 추정, RTT 경보 발행
                 (LTA IIR이 증가된 counts를 추적해 false touch 위험 경로 존재 — 블로킹_B 해소 후 방어 설계)
```

**절전 진입 RESEED 게이트화** (블로킹_G 대기 없이 Phase 1에 포함):
```c
/* func_sleep() 내 tdc_drv_iqs323_reseed() 직전 삽입 */
if (TDC_TOUCH_NOTOUCH_GATE_ENABLE) {
    uint16_t counts = tdc_drv_iqs323_read_counts();
    if (!tdc_notouch_gate_check(counts)) {
        /* 절전 RESEED 차단 — RTT 경보 후 RESEED 없이 절전 진행 또는 RESEED 게이트 실패 처리 */
    }
}
```

### Phase 2 — 공장 캘리브레이션 + EEPROM 저장·로드 (보완)

**`write_ati_compensation()` 인자 전달: 선택지_2 권고로 변경** (68_대안비교 공격_1):
```
선택지_2: 정적 변수 신설 — s_override_mult_lsb·s_override_mult_msb·s_override_comp_lsb·s_override_comp_msb
  → 기존 RTT_TUNING 경로(s_tdc_normal_tuning) 패턴과 동일 레이어
  → s_ati_in_progress 재진입 가드에서 return 시 인자 소멸 문제 없음
  → BOARD_VARIANT 다중화: s_override_* 변수를 BOARD_VARIANT별 슬롯에서 로드하는 경로 설계
```

**SLEEP ATI 경로 별도 설계 필수**:
```
apply_sleep_settings() 경로:
  s_override_mult_* 로드 후 SLEEP_ATI_MULT_* 계산 또는 별도 EEPROM 슬롯에서 절전용 캘리브 로드
  [확정 필요: 공장 캘리브 시 SLEEP 환경 별도 측정 필요 여부]
```

### Phase 3 — Re-ATI + ATI_Error 핸들러 (보완)

**`tdc_drv_iqs323_is_auto_ati_done()` 활용** (블로킹_H 해소):

**R3_CHARGING 3단계 비블로킹 완전 명세**:
```
① re_ati_trigger() 발행(CH_TIMEOUT 유지, MSB=0x07) → s_ati_in_progress=true
   선행 체크: apply_settings() 진행 중이면 대기(상호 배제)
② 폴링 중 s_ati_in_progress=true → NOT_TOUCH 강제
   롱터치 카운터: freeze (증가 중단, 리셋 금지) — 확인_17
③ tdc_drv_iqs323_is_auto_ati_done() 확인 [확정 필요: ati_event vs ati_active 의미]
   → 완료 시:
      iii-a. 현재 counts로 게이트 재확인 — 기준값: 확인_14 결과에 따라 공장값 또는 Re-ATI 후 동적값
      iii-b. 통과 시 정상 ATI 완료, s_ati_in_progress=false, 롱터치 카운터 복원
      iii-c. 이탈 시 오염 → 재시도 카운터 증가

      iii-d. 재시도 상한 N회(제안 3회 [확정 필요]) 소진:
              → write_ati_compensation(공장값 s_override_*)으로 IC MULT/COMP 명시 재write

```

### Phase 4 — 크래들 Re-ATI + EEPROM 저장

- 삽입점 직전 I2C 윈도우 상태 확인 및 `force_window_open()` 비용 포함한 타이밍 설계(확인_8) — 확인 항목이 아닌 Phase 4 착수 전 블로킹으로 격상 검토.

## 8. 미해결 / 원리상 해소 불가 (재검증3 추가)

| 항목 | 이유 | 접근 |
|---|---|---|
| 게이트 race 원천 제거 | 원자 블록 불가 | RTT 경보 + Beta POR 실측 후 자기치유 확인 |
| 충전 중 Re-ATI blocking race | 비블로킹 3단계(R3_CHARGING) + DS §8.4 확인 후 | 블로킹_M 해소 후 |

| ESD 방전 후 LTA 상향 수렴 → false touch | counts>hi RTT 경보 후 LTA가 증가값으로 수렴 | 블로킹_B 해소 후 ESD 방전 경로 차단 설계 |
| **SLEEP 환경 공장 캘리브 미반영** | apply_sleep_settings() 경로는 SLEEP_ATI_* 상수 사용 — Phase 2 로드 미적용 | 절전 경로 캘리브 설계 (66_할루시 약점_2) |

| ATI_CALIB_MODE + R3_CHARGING 동시 활성 | Re-ATI 완료 소유권 충돌 | 빌드가드 `#error` 또는 런타임 상호 배제 |

## 10. 핵심 10줄

1. **[즉시 수정] re_ati_trigger() CH_TIMEOUT 덮어쓰기 버그 확정**: `reg.bytes[2]=0x00` 초기화로 Phase 3 Re-ATI 발행마다 `ch0/ch1/ch2_timeout_disable(0x07)` 소멸 — `reg.bytes[2]=0x07`로 즉시 수정 필수. 확인_13은 "확인 항목"이 아닌 **즉시 수정 버그**로 격상.

2. **[즉시 해소] 거짓 블로킹 3건 해소**: 블로킹_H(`tdc_drv_iqs323_is_auto_ati_done()` 공개 API `iqs323.c:926` 존재 확인)·블로킹_K(`MAX_WAIT_MS_FOR_WINDOW_CLOSE=20ms` 헤더 확정 → ~2.3초 수렴)·확인_12(CH_TIMEOUT 이중 차단 이유 코드 주석 확인) — 실측 없이 코드 확인만으로 즉시 해소.

3. **[치명] gate_check() hi 상한 오버플로 가드 추가 필수**: 59 §3 빌드가드 세트에 lo 언더플로 #error만 있고 hi 오버플로 가드가 대칭적으로 누락. MARGIN_UP 큰 값 설정 시 wrap-around로 게이트 영구 거부. 빌드가드·런타임 이중 가드 모두 추가.

4. **[치명] EEPROM 전달: 선택지_2(정적 변수 신설) 최종 권고로 변경**: 선택지_1(인자 추가)은 `s_ati_in_progress` 재진입 가드와 교차 시 인자 소멸 문제가 있고, 선택지_2는 RTT_TUNING 기존 구조와 동일 레이어로 자연스럽게 통합됨. 단, BOARD_VARIANT별 슬롯 분리 및 SLEEP ATI 경로 별도 설계가 Phase 2 착수 전 필수 — 59 설계는 이 두 가지를 완전 누락한 단일 보드·노말 경로 전용 환각이었음.

5. **[치명] tdc_touch_config.h 신규 define 전무 → 빌드가드 세트 v2 실효 없음**: Phase 1 착수 전 신규 define 일괄 추가 및 기존 13개 define 역할 중복 검토(특히 `TDC_TOUCH_RTT_TUNING` 심볼명 일치 grep) 필수. 추가 전까지 59 §3 `#error` 가드 전체가 `#if 0`으로 조용히 무효.

6. **[치명] 게이트 진행 구간 억제·SLEEP ATI 경로 누락**: READY 전이 → RESEED 완료 전 구간 억제 전략(s_gate_in_progress 신설 또는 s_boot_touch_ignore 확장) 미설계(블로킹_L 신규). SLEEP 경로(`apply_sleep_settings()`)에 공장 캘리브 결과 미반영 구조 공백 — Phase 2 착수 전 양측 모두 설계 확정 필수.

7. **[고위험] R3_CHARGING 3단계 설계 3가지 보완 필수**: (a) apply_settings() 동시 실행 상호 배제, (b) iii-c 재시도 시 게이트 재확인 명시, (c) 롱터치 카운터 freeze 설계(확인_17) — 이 세 가지 없이는 Phase 3 구현 착수 불가.

8. **[고위험] 확인_14 장기 자기 모순 경로 §8 추가**: 공장 절대 기준 게이트 + 주기 Re-ATI 조합에서 Re-ATI 반복 후 실제 noTouch counts가 공장값에서 멀어지면 R3_CHARGING 게이트 영구 실패 순환 발생 — 게이트 기준 동적 업데이트 정책(확인_14)이 Phase 3 착수 전 블로킹 수준 항목임을 §8 미해결에 명시.

9. **[Phase-1 보완] WDT 갱신 삽입 위치 확장 + SLEEP_MEASURE_MODE 경로 추가**: Sys_Delay 직전 단독 삽입으로는 read_register 1회당 130ms 연속 WDT 미갱신 구간 잔존. read_register 직전 추가 삽입 필요 [확정 필요: WDT timeout 값]. ATI_CALIB_MODE·SLEEP_MEASURE_MODE 두 경로 모두 포함.

10. **[수렴도] 수렴 방향 강화 — 즉시 해소 가능 블로킹 분리 후 실측 우선 권고**: 아키텍처 원리는 32개 adversarial 노드(3라운드)를 통해 기각되지 않았고, 즉시 해소 가능 항목 3건 처리로 실질 신규 블로킹이 감소 추세. **권고 순서: Phase-1 즉시 수정(WDT 삽입 보완·re_ati_trigger 버그 수정·tdc_touch_config.h define 추가) → 블로킹_J·확인_18(코드/DS 확인) → 블로킹_A·D·G(실측 우선) → Phase 1 착수**.
