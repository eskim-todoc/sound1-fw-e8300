# 56 — 재검증 라운드2: 할루시 페르소나 공격 (49_종합-재검증1 대상)

**TL;DR**: 49_종합-재검증1을 할루시·미검증·놓친 시나리오 관점에서 공격. 치명 3건(EEPROM 로드 경로 내 `write_ati_compensation()` 인자 전달 구조 환각·`wait_re_ati_done()` 최악 시간 ~1.9초 주장의 근거 부재·절전 RESEED 오염 부팅 독립성 선언의 환각 잔존), 고위험 3건(RTT_TUNING 분기 충돌이 블로킹으로 강등·CH_TIMEOUT 이중 차단 유지 이유 미명시·ESD 환경에서 게이트 폴백이 현재와 동작 동치임을 미분석), 중간 1건(Auto-ATI 완료 직후 counts 1샘플 신뢰도 미검증) 등 7개 신규 약점 발굴. 수렴 아님.

## 0. 공격 방법론

49_종합-재검증1이 30_종합-1차 대비 "수정·추가"한 내용을 다음 세 관점으로 공격한다.

- **관점_H (할루시)**: 근거 없이 확정으로 기술하거나 코드·데이터시트 없이 단정한 항목
- **관점_U (미검증 주장)**: `[확정 필요]·[추정]` 태그 없이 사실인 것처럼 서술했으나 실측·데이터시트 확인이 필요한 항목

## 1. 신규 약점 목록

### 약점_1 — EEPROM 로드 → `write_ati_compensation()` 인자 전달 구조 환각 [관점_H, 치명]

**49 종합의 주장 (§2-3)**:

```c
#if TDC_TOUCH_FACTORY_CALIB_ENABLE == 0
  if (tdc_touch_calib_load_eeprom(&calib)) {
    s_mult_lsb = calib.mult_lsb;
    s_comp_lsb = calib.comp_lsb;
    /* write_ati_compensation()이 이 값을 사용하도록 전달 */
  }
#endif
write_ati_compensation();  /* 항상 실행, 위 분기로 인자 결정 */
```

**공격**:

`write_ati_compensation()`은 현재 **인자 없는 `void` 함수** 구조다(`iqs323.c:696`). 내부에서 컴파일 타임 상수(`TDC_DRV_IQS323_ATI_MULT_LSB`, `TDC_DRV_IQS323_ATI_COMP_LSB`)를 직접 참조해 레지스터에 write한다.

49 종합이 제시한 코드는 `s_mult_lsb`, `s_comp_lsb`라는 정적 변수를 설정한 뒤 `write_ati_compensation()`이 "이 값을 사용"한다고 주석 처리한다. 그러나:

1. 현재 `write_ati_compensation()` 시그니처가 인자를 받지 않으므로, 정적 변수를 쓰려면 함수 내부를 수정해야 한다.
2. 함수 수정 방법(전역/정적 변수 참조 추가 vs 인자 추가 vs 래퍼 함수 생성)이 제시된 코드 조각 어디에도 없다.
3. `/* write_ati_compensation()이 이 값을 사용하도록 전달 */` 주석은 이 연결 구조를 "마치 구현된 것처럼" 암시하지만 실제 코드 변경 내용이 없다.

즉 49 종합의 코드 예시는 **EEPROM 로드와 `write_ati_compensation()` 호출 사이의 연결 고리를 주석으로 대체한 환각**이다. "전달" 메커니즘이 없으면 로드된 `calib.mult_lsb` 값은 어디에도 쓰이지 않고 소멸한다.

**영향**: Phase 2 구현 착수 시 이 코드 예시를 참고하면, 로드 경로만 추가하고 `write_ati_compensation()` 내부 연결 수정 없이 빌드하는 오구현이 발생한다. EEPROM 로드 경로 설계의 핵심 절반(전달 메커니즘)이 여전히 미설계다.

**필요 추가**: `write_ati_compensation()`의 시그니처 변경 방법(인자 추가 or 정적 변수 선언 or 함수 분리) 또는 EEPROM 로드값으로 컴파일 타임 상수를 오버라이드하는 구체 코드 패턴을 명시해야 한다.

### 약점_2 — `wait_re_ati_done()` 최악 시간 "~1.9초" 주장의 근거 부재 [관점_H, 치명]

**49 종합의 주장 (§4 Phase 3)**:

> "wait_re_ati_done() 블로킹 시간 정정: Sys_Delay 기준 최대 1초 + force_window_open 포함 최악 **~1.9초** (44_통신전력 발굴). 기존 '1초 확정'은 새로운 환각."

**공격**:

41_repro의 검증(§2.2)에서 `force_window_open()` 1회 최악 45ms + 20ms 딜레이 × 2 = **최악 130ms**라고 분석했다. 그런데 49 종합은 이를 ~1.9초로 처리했다.

1초(Sys_Delay×10회) + 130ms(force_window_open×2)면 최악 **~1.13초**다. ~1.9초가 되려면 force_window_open 비용이 900ms여야 하는데, 41_repro의 45ms+20ms 계산과 맞지 않는다.

44_통신전력 노드를 신뢰하고 ~1.9초를 채택한 것이라면 44 노드의 계산 근거가 중요하다. 그러나 49 종합은 "44_통신전력 발굴"만 언급하고 구체 계산을 제시하지 않는다. "기존 1초 확정은 환각"이라 선언했으나 ~1.9초가 더 정확한 근거도 제시하지 않았다.

두 노드(41, 44)의 수치가 충돌하는 상황에서 49 종합이 44 노드를 선택한 이유가 없다. 이것은 환각 정정을 명분으로 한 **새로운 숫자 환각**이다.

**영향**: Phase 3 R3_CHARGING 비블로킹 설계 근거로 "1초 창 너무 긴 위험"이 사용됐는데, 실제 창이 1.13초인지 1.9초인지가 설계 판단에 직접 영향을 준다. 수치 근거를 코드 실측(force_window_open 최악 반복 수 × ms)으로 확정해야 한다 [확정 필요].

### 약점_3 — 절전 RESEED 부팅 독립성 선언이 여전히 근거 없는 환각으로 잔존 [관점_H, 치명]

**49 종합의 주장 (§1-2)**:

> "절전 복귀 = WDT 리셋 재부팅 → MCLR → Auto-ATI → 노터치 게이트. **단**: MCLR이 IC LTA 레지스터를 포함한 전 레지스터를 POR 초기화하는지 데이터시트 §4.1/§5.5 미확인 → 절전 진입 RESEED 오염이 다음 부팅 게이트와 독립임을 근거 없이 단정 불가. **블로킹_G(신규)로 추가** — Phase 1 착수 전 확인 필수."

**공격**:

43_완전성(§1-2)이 지적한 결정적 누락을 49 종합은 블로킹_G에 통합했다고 주장하지만, 블로킹_G의 내용을 보면:

> "IQS323 MCLR 후 전 레지스터(LTA·THRESHOLD 포함) POR 완전 초기화 여부 — 데이터시트 §3.4/§4.1 확인 + 필요시 MCLR 후 THRESHOLD read 실측"

블로킹_G는 **THRESHOLD 레지스터** 잔존 가능성만 구체적으로 언급하고 있다. 그런데 43_완전성의 핵심 공격은 "절전 진입 RESEED 오염 LTA"가 재부팅 부팅 게이트와 **완전히 독립**인지 여부였다. 즉:

- 절전 진입 시 RESEED(`iqs323.c:955~957`) → IC 내부 LTA = 터치 counts로 오염
- WDT 리셋 → CM3 재부팅 → MCLR 실행
- MCLR이 IC LTA를 POR default로 초기화하면: 절전 오염 LTA가 소멸하므로 부팅 게이트와 독립 ✓
- MCLR 후 LTA가 POR default로 초기화되지 않으면: 오염 LTA가 잔존 → 부팅 게이트 직전 IC의 상태에 영향

49 종합은 §1-2에서 "근거 없이 단정 불가"라 했음에도, §5 블로킹 테이블에서 블로킹_G를 "THRESHOLD 잔존" 관점으로만 표현해 **LTA 잔존 여부**가 블로킹_G에 명시적으로 포함됐는지 불분명하다. 블로킹_G 해소 방법("MCLR 후 THRESHOLD read 실측")이 LTA 초기화 확인을 포괄하는지도 불명확하다.

더 나아가 42_race(공격_3)는 절전 진입 RESEED 오염 LTA가 ULP 루프에서 즉시 터치 감지 → WDT 리셋 재부팅 무한 반복 경로를 제시했는데, 49 종합 §8 미해결 목록이나 어디에도 이 경로에 대한 명시적 처리가 없다.

**영향**: 블로킹_G 해소 범위가 (THRESHOLD 잔존)으로 축소 표기돼 있어, LTA 잔존 여부를 별도로 확인해야 한다는 사실이 구현자에게 전달되지 않는다. 블로킹_G 해소 방법에 "MCLR 후 LTA 레지스터 직독"을 명시해야 완전하다.

### 약점_4 — `TDC_TOUCH_RTT_TUNING` 분기 충돌이 확인 항목으로 격하돼 치명도 과소평가 [관점_N, 고위험]

**45_회귀(회귀_2)의 발굴**: `TDC_TOUCH_RTT_TUNING=1` 빌드에서 `s_tdc_normal_tuning.ati_valid=true`이면 MULT/COMP가 런타임 튜닝값으로 대체 → 공장 캘리브레이션 MULT/COMP 기준 `FACTORY_NOTOUCH_COUNTS`와 다른 게인 환경에서 게이트 비교 → 게이트 윈도우 무의미화. 45_회귀는 이를 "심각" 등급으로 분류했다.

**49 종합의 처리 (§9 잔존 미해결)**:

> "신규_TDC_RTT_TUNING: TDC_TOUCH_RTT_TUNING 분기와 공장값 게이트 신뢰도 충돌 — 고위험"

잔존 미해결 표에 "고위험"으로 기재했지만, **어떤 조치도 §4 Phase 계획이나 §3 빌드가드 세트에 반영되지 않았다.** 특히:

1. `TDC_TOUCH_RTT_TUNING=1` 환경에서 Phase 1(NOTOUCH_GATE_ENABLE=1) 동시 활성화 금지하는 `#error` 가드가 없다.
2. 공장 캘리브레이션 기록 시점과 런타임 게이트 비교 시점의 MULT/COMP 동일성을 보장하는 설계가 없다.
3. "고위험"으로 인식하면서 2차 재검증 대상으로만 미룬 것은 아키텍처 원리("공장 절대 기준이 게이트의 기반")를 훼손하는 상태를 인지하면서 방치하는 것이다.

`TDC_TOUCH_RTT_TUNING` 분기는 코드 내 이미 존재하는 경로이므로, 이 충돌은 실측 의존 없이 코드만으로 확인 가능하다. 블로킹으로 격상하고 `#error` 가드 또는 RTT_TUNING 활성 시 게이트 신뢰도 경고를 즉시 추가해야 한다.

### 약점_5 — CH_TIMEOUT 이중 차단 유지 이유를 "검토 필요"로만 남겨 미결로 잔존 [관점_N, 고위험]

**48_대안비교(공격_5)의 발굴**: stuck-touch 방어용 CH_TIMEOUT이 현재 이중 차단(`write_register(CH_TIMEOUT, 0x00, 0x07)` + 다른 경로)돼 있으며, 이 차단 이유가 종합 어디에도 없고 Phase 계획에도 재활성 검토가 없다.

**49 종합의 처리 (§8 미해결)**:

> "stuck-touch(CH_TIMEOUT) 처리 — CH_TIMEOUT 이중 차단 유지 이유 미명시 — Phase 0 또는 1에서 재활성 여부 검토 추가 필요"

**공격**:

"검토 추가 필요"로만 기재됐고, §4 Phase 계획 어디에도 이 검토가 Phase 게이트로 연결되지 않았다. 즉 아래 둘 중 하나가 지금 결정되지 않은 채 Phase 0~4가 진행될 수 있다:

- CH_TIMEOUT 활성화: 부팅 터치 게이트 실패(timeout) → 폴백 RESEED → LTA 오염 → 손 안 떼면 무한 터치 감지 상태에서 CH_TIMEOUT이 자동 복구. 게이트 실패 시 보조 복구 경로로 기능할 수 있다.
- CH_TIMEOUT 계속 비활성: 게이트 실패 폴백 RESEED 후 LTA 오염 → stuck-touch 발생 시 복구 수단이 Beta POR 실측 선행 자기치유(블로킹_D)밖에 없다.

"이중 차단 이유 미명시"는 이 설계 결정의 역사적 맥락이 없다는 뜻이다 — 즉 CH_TIMEOUT을 비활성화한 **코드 작성자의 의도를 알 수 없는 상태**에서 Phase 계획이 진행되고 있다. 이것은 미검증 전제 위에 설계를 쌓는 것이다.

`분석.md §4-7`에 "Phase2 보조 조정" 수준으로만 언급됐을 뿐 근거 없이 비활성 상태가 기정사실화됐다. CH_TIMEOUT 관련 코드 라인과 비활성화 시점 커밋 이력 확인이 선행돼야 "재활성 여부 검토"가 의미 있다.

### 약점_6 — ESD 환경에서 Phase 1 게이트 폴백이 현재 동작과 동치임을 49 종합이 무시 [관점_N, 고위험]

**48_대안비교(공격_8)의 발굴**: ESD 누적 시 counts가 공장 기준 윈도우 이탈 → 게이트 timeout → 폴백 RESEED = LTA ← ESD-오염 counts. 현재(게이트 없음, 무조건 RESEED)와 결과가 동치이므로 Phase 1이 ESD 환경에서 실질 개선이 없다.

**49 종합의 처리**: 이 공격이 §8 미해결 표는 물론 §7 달성도 표 어디에도 반영되지 않았다. "ESD/물리 전하 누적 — SW 불가, 실측_B → HW 블리더 or 주기 방전"으로만 처리했다.

**공격**:

ESD 대응이 "독립 트랙"이라는 것은 ESD를 완전히 해소하는 것이 독립 과제라는 뜻이지, **ESD 환경에서 Phase 1이 현재보다 나쁜 UX를 만들 가능성이 없다**는 뜻이 아니다.

구체 시나리오:
- 현재(GATE_ENABLE=0): ESD 환경 부팅 → 무조건 RESEED → LTA ← ESD 오염 counts → 사용자 손 뗌 → counts 상승 → LTA IIR 추적(Beta POR 이면 빠름) → 수렴
- Phase 1(GATE_ENABLE=1): ESD 환경 부팅 → counts < 윈도우 하한 → 게이트 실패 → BOOT_WAIT_MS timeout 대기(현재 값 미정[확정 필요]) → 폴백 RESEED → 동일 LTA 오염

두 경로의 차이: **BOOT_WAIT_MS 지연만큼 부팅이 느려진다.** ESD가 심하면 BOOT_WAIT_MS 내내 게이트가 실패하고 폴백 후에도 문제는 동일하다. 즉 Phase 1 활성화가 ESD 환경에서 **부팅 지연만 추가하고 결과는 동일한 퇴행**이 될 수 있다.

49 종합은 §7 달성도 표에 "ESD/물리 전하 누적 → 별도 트랙"으로만 표기해 이 구체 퇴행 경로를 명시하지 않았다. Phase 1 활성화 결정을 내리기 전에 ESD 환경 폴백 동작이 "현재 이상"임을 실측_B로 확인해야 한다.

### 약점_7 — Auto-ATI 완료 직후 counts 1샘플 신뢰도 미검증이 41_repro 발굴임에도 49 종합에서 누락 [관점_U, 중간]

**41_repro(신규_결함_B)의 발굴**: `apply_settings()` 내 게이트 직전 counts 읽기는 MCLR+Auto-ATI 완료 직후 IC 안정화 delay 없는 1샘플이며, force_window_open 최악 130ms 비용도 미계상 — 게이트 판별 신뢰도 근거 없음.

**49 종합의 처리**: §5 블로킹 미지수 표에도, §6 확인 항목에도 이 항목이 없다. 41_repro는 재검증1 8개 노드 중 하나임에도, 49 종합은 재검증1 노드 전체를 반영한다고 선언했으나 이 구체 약점은 누락됐다.

**공격**:

노터치 게이트(Phase 1)의 핵심 판단은 "부팅 시 counts 읽기 → 윈도우 비교"다. 이 counts 값의 신뢰도가 게이트의 정확도를 직접 결정한다. 그런데:

1. MCLR+Auto-ATI 완료 시점에서 IC 내부 counts가 진정한 안정 상태인지 데이터시트에서 확인되지 않았다.
2. force_window_open() 비용(최악 130ms)이 counts 읽기 왕복 시간에 포함되어 그 사이 터치가 발생하면 counts 값이 변화할 수 있다.
3. 현재 레이어_2(N샘플) 제거 결정과 연계되어, 1샘플의 신뢰도 미보장은 게이트 전체 설계의 전제를 훼손한다.

이 항목을 확인_항목으로도 블로킹으로도 등록하지 않은 채 Phase 1 설계가 확정 형태로 유지되는 것은 미확인 전제 위의 설계다.

## 3. 49 종합이 잘못 처리한 항목 정정

### 3-1. §2-2의 사후 검증 설계 — 새로운 모순 도입

49 종합 §2-2에서:

> "RESEED 발행 → counts 1회 재읽기 → 윈도우 이탈(counts < lo): RTT 경보만 발행 ('race 가능성 있음. LTA IIR 자기치유 위임')"

"counts < lo"라는 조건이 **하한 이탈**을 의미한다고 기술했으나, 42_race 공격_1의 핵심 분석은 RESEED 완료 후 counts가 낮은 것(이탈 방향 = 터치 중)이 정상 터치 진행임을 설명한다. 사후 검증의 counts 이탈 방향이 "lo(하한) 이탈 = 터치 방향"인지 "hi(상한) 이탈"인지 명시가 필요하다.

self-cap에서 터치 = counts 감소 → `counts < lo`는 터치 중. RESEED 완료 후 터치 시작 = 정상 동작 = RTT 경보 불필요. 49 종합의 설계가 정상 터치를 "race 가능성 있음"으로 경보 발행하는 오설계로 남아 있을 수 있다.

### 3-2. §4 Phase 3 계획 — `wait_re_ati_done()` 수정 필수성 표기

49 종합 §4 Phase 3에서:

> "`wait_re_ati_done()` 내 SYS_WATCHDOG_REFRESH() 추가 — '명시 필요' 수준이 아닌 **함수 수정 필수 선행 사항**으로 격상."

격상은 맞다. 그러나 41_repro(신규_결함_C)가 지적한 "기존 `tdc_drv_iqs323_calib_re_ati()` 경로(ATI_CALIB_MODE)도 동시에 영향받는다"는 교차 영향이 49 종합에 반영되지 않았다. 공장 캘리브레이션 경로(ATI_CALIB_MODE)에서 `wait_re_ati_done()`을 호출하는 현재 코드도 WDT 위험을 공유한다.

## 5. 핵심 6줄

1. **EEPROM 로드 전달 구조 환각 (약점_1, 치명)**: 49 종합 §2-3 코드 예시는 `s_mult_lsb`·`s_comp_lsb` 설정 후 `write_ati_compensation()`이 "이 값을 사용"한다고 주석으로 대체했으나, 현재 `write_ati_compensation()`은 인자 없는 `void` 함수로 내부에서 컴파일 타임 상수를 직접 참조한다 — 전달 메커니즘 없이 로드값은 소멸하는 사문 코드를 정상 설계처럼 제시한 환각이다.

2. **~1.9초 근거 부재 (약점_2, 치명)**: 41_repro는 force_window_open 최악 130ms + Sys_Delay 1초 = ~1.13초로 계산했으나 49 종합은 "44_통신전력 발굴"만 인용해 ~1.9초를 채택했다 — 두 수치가 충돌하는데 49 종합이 44 노드를 선택한 근거가 없으며, "1초 확정은 환각"을 정정하면서 검증 없는 새 수치를 도입한 2차 환각이다.

3. **절전 RESEED 독립성 블로킹_G 축소 (약점_3, 치명)**: 블로킹_G가 THRESHOLD 잔존으로만 표기되어 LTA 레지스터 잔존 여부가 명시적으로 포함됐는지 불분명하다 — 절전 RESEED 오염 LTA가 MCLR 후 초기화되는지가 부팅 게이트 설계 전체의 독립성 전제이므로, 블로킹_G 해소 방법에 "MCLR 후 LTA 레지스터 직독"을 추가해야 전제가 완결된다.

4. **RTT_TUNING 충돌 격하 (약점_4, 고위험)**: 45_회귀가 "심각"으로 발굴한 `TDC_TOUCH_RTT_TUNING` 분기 충돌이 49 종합의 블로킹·확인 항목 어디에도 없이 "신규_TDC_RTT_TUNING 고위험" 표기만으로 2차 재검증으로 미뤄졌다 — 코드 내 이미 존재하는 분기이므로 실측 없이 즉시 `#error` 가드 또는 설계 결정이 가능한 항목을 블로킹 목록 밖으로 처리한 치명도 격하다.

5. **ESD 폴백 동치 미분석 (약점_6, 고위험)**: ESD 환경에서 Phase 1 게이트 timeout 후 폴백 RESEED = 현재 무조건 RESEED와 최종 결과가 동치이고 부팅 지연만 추가되는 퇴행 경로가 49 종합 §7·§8 어디에도 없다 — Phase 1 활성화 전 ESD 환경 폴백 동작이 "현재 이상"임을 실측_B로 확인하는 조건이 없으면 Phase 1이 ESD 환경에서 무의미한 지연을 도입할 수 있다.

6. **counts 1샘플 신뢰도 누락 (약점_7, 중간)**: 41_repro가 발굴한 "MCLR+Auto-ATI 완료 직후 IC 안정화 delay 없는 1샘플 신뢰도 미확인"이 49 종합 블로킹·확인 항목에서 완전 누락됐다 — 레이어_2 N샘플 제거 결정과 연계되어 게이트 판별의 핵심 입력값 신뢰도가 [확정 필요] 상태로 방치된 채 Phase 1 설계가 확정 형태로 유지된다.
