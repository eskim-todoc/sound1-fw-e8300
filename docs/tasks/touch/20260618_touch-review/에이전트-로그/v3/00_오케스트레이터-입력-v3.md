# 00-v3 오케스트레이터 입력 — Fixed+Auto-ATI 조합 100% 근접안 (균형 구조)

**TL;DR**: 은수님 지시 — 현 시스템 전제 하에서 **Fixed(안정성)와 Auto-ATI(적응성)를 조합**해 부팅 터치 모호성·보드편차·드리프트를 100%에 근접 해결하는 구현안 도출. 브레인스토밍 전체(개념정리·부팅터치모호성·v1·v2)를 입력으로, **분석8→계획8→검증8 1차 도출 + adversarial 8 재검증 3회 + 최종 종합**(균형 구조)으로 진행한다.

---

## 1. 현 시스템 동작 전제 (코드 검증 완료)

| # | 전제 | 검증 | 핵심 함의 |
|---|---|---|---|
| 1 | 전원→CM3 실행 ~500ms+ | 부분사실 (LED 360ms + NVM/FATFS/DMA 로딩) | 부팅 중 Auto-ATI(~1.5초) 수행 시간 확보 가능 |
| 2 | CM3 시작 시 MCLR | **사실** (`initialize.c:449` 무조건, `iqs323.c:288`) | 매 부팅 IC POR + Auto-ATI 1회 |
| 3 | 터치로 절전 진/출입 | 부분사실 — 진입=롱터치(2400ms), **복귀=WDT 리셋 재부팅** | **절전 복귀=재부팅 → 절전/부팅 baseline 문제 통합** |
| 4 | 충전/방전 제외 터치 상시 | 부분사실 — IQS323 전원 항상 ON | 아래 세부 |

### 전제 4 세부 (핵심)

- **충전기 연결(df_Connected)**: 롱터치해도 절전 진입 **안 함**(`systemControl.c:162`). 터치 계속 동작.
- **크래들 뚜껑 닫힘**: `func_cradle_lid_closed_loop`(`main.c:807`)에서 **터치 폴링 완전 중단**(I2C 통신 없음, IQS323 idle) → **노터치 보장 구간**. 뚜껑 열림 시 WDT 리셋 재부팅. **단 이 구간에 noTouch baseline 얻는 코드는 미구현.**
- **배터리 방전(<40%)**: POWER_OFF → 절전 진입. ULP서 IQS323 절전 파라미터로 계속 동작.

### 현 baseline/ATI 시퀀스 (코드 확정)

- **부팅**: MCLR → Auto-ATI 1회(비블로킹 폴링 감지) → 사전 측정 **고정 보상값(MULT/COMP) 직접 write** → ATI Mode=Disabled + CH timeout 비활성(이중 차단) (`iqs323.c:650~694`).
- **절전 진입**: 터치 해제 대기 → 절전 고정 보상값 + threshold 255 → 다운클럭 → **RESEED(LTA←현재 counts)** (`iqs323.c:931~948`, `main.c:944`).
- **절전 복귀**: WDT 리셋 → 처음부터 MCLR+Auto-ATI (이전 LTA 완전 리셋).

> **결정적**: 현 펌웨어는 부팅 Auto-ATI 결과를 버리고 고정값을 쓴다. 그런데 **부팅이 노터치인지 터치인지 구분 없이** 이 시퀀스가 돈다 → 터치 부팅 시 Auto-ATI 게인 왜곡 + RESEED 오염.

## 2. 목표 — Fixed + Auto-ATI 조합 (은수님 지시)

100% 완벽은 원리상 불가(cold-start race)이나, **두 방식의 장점을 조합**해 100%에 근접:

| | Fixed (고정값) | Auto-ATI |
|---|---|---|
| 강점 | 부팅 터치 게인왜곡·ATI_Error 없음, 결정론적 | 보드편차·드리프트 자동 보정 |
| 약점 | 보드편차·드리프트 미보정 | 부팅 터치 시 왜곡/실패, ATI_Error 영구먹통 |

**조합 방향(브레인스토밍 수렴)**: 공장 캘리브레이션(절대 기준) + 노터치 게이트(Auto-ATI/RESEED를 노터치일 때만) + LTA 드리프트 추적 + 크래들 기회 + 사후검증·자기치유 + ESD 별도 트랙.

---

## 3. 브레인스토밍 핵심 (입력 — 페르소나 필독)

- **두 층위**: ATI(counts 절대값 정규화) ↔ 터치판정(delta=LTA−Counts). 연결고리=MULT(게인). ([`개념정리_터치동작모델.md`](../../개념정리_터치동작모델.md))
- **Cold-Start Ambiguity**: 부팅 시 미지수 2개(보드 기준·터치 여부)·식 1개=불능. 미지수 하나를 외부 고정해야. ([`브레인스토밍_부팅터치모호성.md`](../../브레인스토밍_부팅터치모호성.md))
- **RESEED 제약**: 현재 counts로만 seed(임의값 불가, §5.5.1) → 공장값은 "RESEED 게이트 기준"으로.
- **노터치 게이트 하 RESEED < Re-ATI**: Re-ATI가 게인+comp+baseline 전부 재보정 → 우월.
- **게이트 race**: 제거 불가, 치명도 낮음(저확률·자기치유·사후검증·크래들).
- **명제 G~J(v2)**: 통신 윈도우 비용 큼(force×2 130ms)·스트리밍 force 필수·FIXED LTA delta 유효(counts 포화 시 침묵실패)·ATI_Error 자동재시도 없음.

## 4. 페르소나 설계 (균형 구조)

### 1차 도출
**분석 8** (Fixed+ATI 조합 방안 다각도 발산):
1. `분석_부팅ATI게이트` — 부팅 Auto-ATI를 노터치 게이트화
2. `분석_공장캘리` — 공장 캘리브레이션 절대기준 저장·활용(EEPROM)
3. `분석_크래들기회` — 뚜껑 닫힘 노터치 구간 활용(전제4)
4. `분석_절전재부팅통합` — 절전=재부팅 통합 함의
5. `분석_노터치게이트메커` — 노터치 판별·RESEED/Re-ATI 게이트 구현
6. `분석_충전상태활용` — 충전 중 거동·기회
7. `분석_사후검증자기치유` — race 사후검출·복구
8. `분석_FixedATI하이브리드` — 두 방식 결합 핵심 아키텍처

**계획 8**: 위 분석 방안들을 구체 구현 설계(코드 위치·레지스터·시퀀스·빌드가드)로.

**검증 8** (adversarial): 각 설계안의 결함·race·회귀·실측의존 공격.

### 재검증 루프 (3회)
각 루프: 직전 종합을 adversarial 8로 공격(새 약점·놓친 시나리오·할루시네이션) → 종합. 3회 정제.

### 최종 종합
1차+3루프 통합 → **단일 구현 아키텍처 + 단계별 계획 + 실측 게이트 + 분석/계획 반영안**.
