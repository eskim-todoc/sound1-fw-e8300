# 07 분석 — 사후검증·자기치유·ATI_Error 핸들러 결합 설계

**TL;DR**: 게이트 race는 SW로 100% 제거 불가이나, ① RESEED/Re-ATI 실행 직후 counts 재확인·재시도(사후검증), ② 손뗌 시 counts 자연 회복으로 LTA IIR이 baseline을 재수렴(자기치유), ③ `(void) ati_error` 무시 제거 후 `re_ati_trigger()`(`tdc_drv_iqs323.c:569`) 연결(ATI_Error 핸들러) — 세 층을 결합하면 race 체류시간이 수 초 이내로 수렴하고 영구먹통 경로가 차단된다. 현 ATI Mode=Disabled(고정값) 구조에서 ATI_Error는 CH1 더미채널 auto-ATI 잔재로만 발생하므로 핸들러는 미래 ATI Full 전환 대비 설계로 준비한다.

## 1. 게이트 race 구조와 치명도 평가

### 1.1 race 정의

```
공장값 절대 기준으로 noTouch 판별 → [판별~실행 간격: μs~수 ms] → RESEED/Re-ATI 실행
         ↑ 이 구간에 터치가 시작되면 오염된 baseline이 seed됨
```

- **저확률**: 판별~실행 간격이 μs~수 ms, 사람이 정확히 이 순간에 터치를 시작할 확률은 극히 낮음 [추정].
- **자기치유**: race로 오염돼도 손 떼면 counts 자연 상승 → LTA IIR이 수 초 이내 재추적 → 일시 오류, 영구 먹통 아님.
- **사후검증**: RESEED/Re-ATI 실행 직후 counts를 재확인해 오염 감지 → 재시도.
- **치명도 낮음**: 세 완화 장치의 곱셈 효과로 실사용 무시 가능 수준 수렴.

### 1.2 현재 코드의 race 잠재 지점

| 위치 | 현재 동작 | race 가능 여부 |
|---|---|---|
| `iqs323.c:1147` RESEED (노말 부팅) | 게이트 없이 무조건 RESEED | **있음** — noTouch 미확인 후 RESEED |
| `iqs323.c:945` RESEED (절전 진입) | 절전 감도 설정 후 RESEED | **있음** — 단 절전 진입 전 터치 해제 대기(`func_sleep`의 터치 해제 확인 경로) [확정 필요] |
| Re-ATI (`re_ati_trigger()` `iqs323.c:569`) | `wait_re_ati_done()`으로 완료 확인 후 반환 | **있음** — trigger 직전 noTouch 확인 시점과 실행 사이 gap |

## 2. 사후검증 설계 (게이트 race 사후 검출)

### 2.1 개념

RESEED/Re-ATI 실행 **직후** counts를 재확인한다. 오염됐으면 재시도.

```
noTouch 판별 → RESEED/Re-ATI 실행 → [즉시] counts 재확인
                                         ├─ counts ∈ [공장값−허용, 공장값+허용]  → 정상, 완료
                                         └─ counts ≪ 공장값  (터치 의심)
                                              → 재시도 최대 N회 → N회 초과 시 저신뢰 폴백
```

### 2.2 구현 위치 및 코드 윤곽

**대상 함수**: `tdc_drv_iqs323_apply_settings()`(`iqs323.c` RESEED 부분) 또는 별도 `tdc_drv_iqs323_reseed_with_verify()` 래퍼.

```c
/* 예시 윤곽 — 실제 구현은 계획 단계에서 확정 */
static bool reseed_with_post_verify(uint16_t factory_no_touch_counts, uint16_t tolerance)
{
    for (int retry = 0; retry < TDC_RESEED_MAX_RETRY; retry++)
    {
        /* RESEED 발행 */
        if (!write_register(TDC_DRV_IQS323_REG_ADDR_SYSTEM_CONTROL, 0x08, 0x00))
        {
            continue;
        }

        /* 사후 counts 재확인 */
        uint16_t counts_after = read_ch0_filtered_counts(); /* [확정 필요]: 실제 read 함수 */
        if (counts_after == 0xFFFF) { continue; } /* 통신 실패 */

        int32_t diff = (int32_t)factory_no_touch_counts - (int32_t)counts_after;
        if (diff < 0) { diff = -diff; }

        if ((uint16_t)diff <= tolerance)
        {
            return true; /* 사후 검증 통과 */
        }
        /* race 오염 감지 → 재시도 */
        ci_printw("[TOUCH] RESEED RACE DETECTED: counts=%u factory=%u retry=%d\r\n",
                  counts_after, factory_no_touch_counts, retry);
        Sys_Delay(TDC_DRV_IQS323_DEFAULT_DELAY_MS * 10);
    }
    /* N회 실패 → 저신뢰 폴백: RESEED 수행하되 경보만 */
    (void)write_register(TDC_DRV_IQS323_REG_ADDR_SYSTEM_CONTROL, 0x08, 0x00);
    ci_printw("[TOUCH] RESEED FALLBACK: low-trust baseline\r\n");
    return false;
}
```

> [!NOTE]
> **[확정 필요]**: `factory_no_touch_counts` 절대값은 공장 캘리브레이션 실측 또는 보드 변종별 RTT 측정으로 확정해야 한다. `tolerance`는 환경 드리프트 허용 범위(실측_A 결과 기반). 현재는 [추정] 값.

### 2.3 재시도 횟수 및 타임아웃

- `TDC_RESEED_MAX_RETRY`: 3회 권장 [추정]. race 확률이 낮아 3회면 충분.
- 재시도 간 딜레이: 최소 10 ms (LTA IIR 수렴 대기).
- 전체 상한: ~50 ms → 부팅 시퀀스 영향 미미 [추정].

## 3. 자기치유 설계 (손뗌 복구)

### 3.1 메커니즘 (현재 코드 기반)

현재 IQS323 Fixed 운용에서 자기치유는 **이미 내장**돼 있다:

```
race 오염 → LTA = 터치 counts(낮음) → 손 뗌 → counts 상승
  → LTA IIR 매 샘플 추적 → 수 초 내 noTouch counts 재수렴
  → delta ≈ 0 복원 → 정상 동작
```

- **LTA IIR 수렴 속도**: Beta 파라미터(`0xB0~B4` 레지스터, BETA 0건 write → POR default 유지)에 의존 [확정 필요].
- **freeze 해제 조건**: 터치 해제(`CH0_IN_TOUCH = 0`) 시 LTA IIR 재개 (데이터시트 §5.5).

### 3.2 자기치유가 실패하는 조건 (무한 터치 경로)

데이터시트 §5.7·§5.10 의문_5 (`개념정리_터치동작모델.md §5`):

- 조건: `thr < ATI Band` 이면서 LTA가 터치 counts로 고착 → freeze 상태 영구화.
- **현재 차단 수단**: `iqs323.c:1155` CH timeout 비활성(`0x07` to 0xC0 MSB) + ATI Mode=Disabled(이중 방어). `stuck-touch → auto-reATI → ATI_ERROR → I2C 무응답` 경로를 이중 차단.
- **잔여 위험**: `tdc_touch.c:360~364` `s_boot_5s_warned`가 5초 경보만 출력, stuck 상태를 능동 해소하지 않음.

### 3.3 자기치유 보강 — stuck-touch 능동 복구

현재 `s_boot_touch_ignore` 가드는 READY 전이 후 즉시 터치 감지 시 폴링을 억제한다(`tdc_touch.c:352~366`). 5초 경보 후에도 억제 지속(무한 무시). race로 오염된 경우:

- **RESEED 재시도**: `s_boot_5s_warned` 도달 시 RESEED 재발행 + counts 재확인.
- **단**: 현재 ATI Mode=Disabled 구조에서 stuck-touch는 delta≈0(미인식)으로 나타나지 `TOUCH`로 나타나지 않음(LTA가 터치값을 추적하면 delta≈0 → 미인식 → freeze 없음). 따라서 `s_boot_touch_ignore`가 무한 유지되는 것은 **실제 터치(손을 안 뗌)** 경우뿐이다.

> **결론**: 현재 구조에서 자기치유는 손뗌 후 자연 수렴으로 충분하다. stuck-touch 능동 복구는 미래 ATI Full 전환 시 필요.

## 4. ATI_Error 핸들러 설계 (0xC0 bit2 수동 Re-ATI)

### 4.1 현황 — 영구먹통 경로

```
ATI Full 활성(미래) → LTA drift → Re-ATI 발동 → ATI_Error (0x10 bit6) set
  → ATI_Active = 0 (ATI 종료, 단 실패)
  → RDY window 재개방
  → tdc_drv_iqs323_read_status() 성공 반환
  → ati_error bit 수신하지만 tdc_touch.c:393에서 (void) 무시
  → re_ati_trigger() 미발행 → ATI_Error 영구 유지 → 잘못 보정된 MULT/COMP로 동작 지속
```

(v1/06 §3-B, v1/07 FM-09, 분석.md §8 ATI_Error 영구먹통 경로 확정)

### 4.2 현재 무해한 이유

`tdc_touch.c:389~393` 주석 설명:

> "ATI 에러 무시 — 운용 모드는 ATI Disabled + 보드별 고정 보상값을 써서 ATI 기능 자체를 사용하지 않는다. ati_error는 전역 비트(System Status 0x10 bit6)라 CH1 더미 채널의 auto-ATI 잔재까지 합산되지만, 터치 판정(CH0 Touch 비트)은 채널별로 정확해 무관하다."

즉, **현재 ATI Mode=Disabled 구조에서 `(void) ati_error`는 의도적이고 안전**하다. ATI_Error는 CH1 더미채널 auto-ATI 잔재로 발생하며 터치 판정에 영향 없다.

### 4.3 ATI Full 전환 대비 핸들러 설계 (미래 준비)

ATI Full 전환 시 핸들러가 없으면 v1/06 §3-B 영구먹통 경로가 개방된다. 준비 설계:

```c
/* tdc_touch_get_state() 내 ati_error 처리 — ATI Full 전환 시 활성화 */
#if TDC_TOUCH_ATI_FULL_ENABLE  /* 미래 빌드 가드 */
    if (ati_error)
    {
        /* 노터치 확인 후 Re-ATI 발행 (터치 중 Re-ATI = ATI_Error 재발 위험) */
        if (!pressed)
        {
            ci_printw("[TOUCH] ATI_ERROR: triggering Re-ATI\r\n");
            (void)re_ati_trigger(); /* re_ati_trigger(): iqs323.c:569 — 이미 존재 */
            /* Re-ATI 완료 확인은 비동기로 다음 폴링에서 ATI_Event bit 확인 */
        }
        else
        {
            /* 터치 중: Re-ATI 보류. 손 뗌 후 자동 재게이트 */
            ci_printw("[TOUCH] ATI_ERROR: deferred (touch active)\r\n");
        }
    }
#else
    (void) ati_error; /* ATI Disabled 운용: 무해, 의도적 무시 */
#endif
```

> [!IMPORTANT]
> `re_ati_trigger()`는 `tdc_drv_iqs323.c:569`에 이미 구현돼 있다(static). ATI Full 전환 시 extern 노출 또는 래퍼 API 추가만 필요. 구현 비용 ~10줄.

### 4.4 Re-ATI 노터치 선행 조건

Re-ATI는 반드시 **노터치 상태에서** 발행해야 한다. 터치 중 Re-ATI는 게인을 터치 기준으로 선점 → ATI_Error 재발 가능성. 따라서:

1. `ati_error` 감지 → `pressed` 확인.
2. `pressed == false` → `re_ati_trigger()` 즉시 발행.
3. `pressed == true` → 손뗌 대기(다음 폴링에서 재검사). `s_ati_error_pending` 플래그 도입 [추정 필요].

### 5.1 층위별 담당·잔여 위험

| 층위 | 담당 | 잔여 위험 | 심각도 |
|---|---|---|---|
| **게이트** (부팅 noTouch 판별) | race 발생 원인 최소화 | 게이트 자체 race (μs~ms 간격) | 낮음 (저확률) |
| **사후검증** (RESEED 직후 재확인) | race 사후 검출·재시도 | 재시도 중 또 race (곱셈 확률) | 극히 낮음 |
| **자기치유** (손뗌 LTA IIR) | 오염 baseline 자동 복구 | LTA 수렴 지연 (~수 초) 동안 터치 불능 | 낮음 (일시적) |
| **ATI_Error 핸들러** (Re-ATI 재트리거) | ATI Full 전환 시 영구먹통 차단 | 노터치 확인 중 또 race | 낮음 |
| **크래들** (race 소멸) | 크래들 부팅 시 race 원천 제거 | 크래들 없는 부팅 | 해당 없음 |

## 6. 구현 우선순위 및 의존 관계

### 6.1 즉시 구현 가능 (ATI Disabled 현재 상태 유지)

| 항목 | 구현 위치 | 규모 | 근거 |
|---|---|---|---|
| RESEED 사후 검증 (`reseed_with_post_verify`) | `tdc_drv_iqs323.c` | ~30줄 | §2, 게이트 race 사후 검출 |
| `s_boot_5s_warned` 도달 시 RESEED 재시도 | `tdc_touch.c:360` | ~5줄 | §3.3 stuck-touch 보강 |

### 6.2 ATI Full 전환 시 추가 (미래 준비)

| 항목 | 구현 위치 | 규모 | 전제 |
|---|---|---|---|
| ATI_Error 핸들러 (`#if TDC_TOUCH_ATI_FULL_ENABLE`) | `tdc_touch.c:389~393` 대체 | ~15줄 | `re_ati_trigger()` extern 노출 |
| `s_ati_error_pending` 플래그 (터치 중 ATI_Error 지연) | `tdc_touch.c` 파일 상단 | ~3줄 | 핸들러와 함께 |

### 6.3 선행 게이트 (실측 의존)

| 실측 항목 | 결정 내용 | 현재 상태 |
|---|---|---|

## 7. 발견 — 현 코드에서 사후검증 유사 로직

`wait_re_ati_done()`(`iqs323.c:581~623`)은 Re-ATI 완료 후 `ati_error` / `ati_event` bit를 확인한다. 이것이 Re-ATI 전용 사후검증과 유사한 구조다. 단 **counts 절대값을 재확인하지는 않는다** — race 오염 검출 불가. `reseed_with_post_verify`는 RESEED 전용으로 이 구조를 보완한다.

또한 `confirm_reset_event()`(`iqs323.c:385~420`)도 reset 후 10회 폴링으로 상태를 확인하는 사후검증 패턴이다. 본 설계는 이 패턴을 RESEED에 적용한다.

## 8. 종합 판정

1. **게이트 race는 SW로 100% 제거 불가** — 완벽한 해는 없다. 목표는 "충분히 견고". (브레인스토밍 §6-B 확인)
2. **사후검증**이 race를 사후 검출해 재시도한다 — RESEED 직후 counts 재확인, 최대 3회. 현재 `wait_re_ati_done()` 패턴 재활용 가능.
3. **자기치유**는 현재 코드에 이미 내장 — 손뗌 후 LTA IIR이 수 초 내 복구. 추가 구현 불요 (ATI Disabled 구조 한정).
4. **ATI_Error 핸들러**는 현재 `(void) ati_error`가 의도적·안전하므로 즉시 수정 불요 — ATI Full 전환 대비 `TDC_TOUCH_ATI_FULL_ENABLE` 빌드 가드로 준비. `re_ati_trigger()`(`iqs323.c:569`)는 이미 존재.
5. **세 층 결합 효과**: 게이트(race 최소화) × 사후검증(race 검출·재시도) × 자기치유(복구) × ATI_Error 핸들러(영구먹통 차단) = 실사용 무시 가능 수준으로 수렴.
6. **counts 포화 침묵 실패**(`개념정리` 의문_5, v2/15~16)는 본 페르소나 범위 외 — 별도 포화 감지 stub (Phase 0, 계획.md 반영 필요).
