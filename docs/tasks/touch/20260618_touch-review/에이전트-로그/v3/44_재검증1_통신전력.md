# 44_재검증1_통신전력 — adversarial 재검증 라운드 1 (통신전력 관점)

**TL;DR**: 30_종합-1차가 24·28번 결함을 흡수했다고 주장하나, wait_re_ati_done() 최악 시간 수정에 치명적 산술 오류가 있고, Phase 4 크래들 삽입 지점이 FPGA sleep 핀 설정 이후임을 코드로 확인해 "FPGA 절전 지연" 주장이 사실상 무효화됐으나 이를 종합이 언급조차 안 하는 등 통신·전력 관련 3가지 새 약점과 2가지 미검증 주장을 발굴했다. 나머지 항목은 수렴.

## 1. 새 약점 1 — wait_re_ati_done() 최악 시간 수정에 산술 오류 [치명도: 높음]

### 1-1. 종합의 주장

> "wait_re_ati_done() = 최대 1초(10×100ms, 코드 확정): 1.5초 기술은 환각(결함_2@27)" (`30_종합-1차 §2-1 결함_2@27`, `§8.6`)

### 1-2. 코드 실제 값 (tdc_drv_iqs323.c:581~599)

```c
for (int i = 0; i < 10; i++)
{
    // ...
    Sys_Delay(TDC_DRV_IQS323_DEFAULT_DELAY_MS * 100);  // 100ms
    continue;
```

`Sys_Delay(DEFAULT_DELAY_MS × 100)` = `Sys_Delay(SystemCoreClock/1000 × 100)` = 100ms 맞음.
반복 최대 10회이므로 **순수 Sys_Delay 최대 1000ms = 1초** — 여기까지는 종합 주장과 일치.

### 1-3. 공격: force_window_open 비용이 전혀 포함되지 않음

각 루프 반복에서 `read_register(TDC_DRV_IQS323_REG_ADDR_SYSTEM_STATUS, ...)` 호출이 있다 (L590). 이것은 force_window_open(최악 45ms) × 2 = **최악 90ms 추가 비용**이다.

```
루프 1회 실제 최악 비용:
  read_register: force_window_open×2 = 90ms
  I2C 트랜잭션: ~1ms
  Sys_Delay(100ms): 100ms
  합계: ≈ 191ms

10회 최악:
  191ms × 10 = 1910ms ≈ 1.9초
```

**종합이 "1.5초 환각 → 1초로 정정"이라 주장했으나, force_window_open 비용을 포함하면 실제 최악은 ~1.9초다.** "1초 확정"이 새로운 환각이다. 엄밀히는 "순수 Sys_Delay 합산 1초, force_window_open 포함 최악 ~1.9초"로 표현해야 하며, Phase 3의 1초 블로킹 전제로 설계된 WDT 갱신 간격과 FPGA 절전 지연 정량화가 모두 재계산 필요하다.

> [!IMPORTANT]
> 정정: wait_re_ati_done() 블로킹 시간 = Sys_Delay 기준 최대 1초, force_window_open 포함 최악 **~1.9초**. 30_종합 §8.6 "1.5초→1초 정정" 기술이 불완전하다.

## 2. 새 약점 2 — Phase 4 크래들 삽입 지점 코드 불일치, FPGA 절전 지연 주장 무효 [치명도: 중간]

### 2-1. 종합의 주장

> "Phase 4 위치: main.c:742 앞, led_force_fade_off() 직후" (`30_종합-1차 §2-1 Phase 4`)

> [28_검증_전력.md §2]: "크래들 Re-ATI 1.5초 블로킹의 FPGA 절전 진입 지연 [치명도: 중간]" — main.c:827 FPGA sleep 핀 설정 직전이 삽입 지점과 인접

### 2-2. 코드 실제 구조 (main.c:743, main.c:807~827)

```
main.c:743: func_cradle_lid_closed_loop() 호출
main.c:807: static void func_cradle_lid_closed_loop(void) {
main.c:827:     Sys_GPIO_Set_Low(DIO_PIN_INDEX_for_FPGA_SLEEP);  // FPGA sleep 핀
main.c:838:     // 약 절전 루프 진입
```

func_cradle_lid_closed_loop() 내부 순서:
1. FPGA 리셋 (`write_FPGA_reset()`)
2. nRF 리셋
3. **FPGA sleep 핀 LOW** (`main.c:827`) — 여기서 FPGA가 이미 sleep 상태로 전환됨
4. PMIC 끄기
5. LED 끄기
6. 약 절전 루프 진입

**Phase 4 삽입 지점 "main.c:742 앞"은 func_cradle_lid_closed_loop() 호출 전이다.** 즉, Re-ATI 실행 시점에 FPGA는 아직 정상 동작 중이다(FPGA sleep 핀은 함수 내부 827번 줄에서 LOW가 되므로). 28번이 주장한 "Re-ATI 블로킹 1.5초 동안 FPGA 활성 전력 소모"는 사실이지만, 그 이유가 "FPGA sleep 핀 설정 직전에 삽입"이 아니라 단순히 "FPGA sleep 전에 삽입"이라는 점에서 지적이 정확하다.

그런데 30_종합-1차는 이 FPGA 절전 지연 쟁점을 **전혀 다루지 않았다.** 28번 결함_2가 중간 치명도로 발굴됐음에도 §5 블로킹 미지수 목록에 포함되지 않고, §6 미해결 목록에도 없다. **"FPGA 활성 전력 × ~1.9초"는 수렴하지 않은 미해결 항목이다.**

[추정] FPGA 활성 전력 소모 정량화가 없으면 Phase 4의 전력 비용을 정당화할 수 없다. 크래들 진입 직전 배터리 방전 임박 케이스에서 이 비용이 유의미할 수 있다.

## 3. 새 약점 3 — 게이트 timeout 5000ms의 전력 예산 근거 여전히 부재 [치명도: 중간]

### 3-1. 종합의 주장

> "timeout: BOOT_WAIT_MS" (`30_종합-1차 §2-1 Phase 1`)

그런데 `BOOT_WAIT_MS`가 새로 정의된 상수인지, 기존 `TDC_TOUCH_NO_TOUCH_TIMEOUT_MS`(= 5000ms)를 재명명한 것인지 명확하지 않다. §2-2 빌드가드 세트에 `BOOT_WAIT_MS`에 해당하는 define이 보이지 않으며, tdc_touch_config.h 목록에도 없다.

### 3-2. 공격: timeout 설계 근거 없음 + 실제 최악 부팅 지연 미계산

28번과 24번이 공격한 핵심 — **게이트 timeout 동안 실제 경과 시간은 명시값보다 최대 3배 이상 길다** — 은 종합의 §5 확인_5("elapsed_ms를 ci_timer_get_tick() 실시간 계산으로 교체")에 언급됐다. 그러나:

- 교체 후의 timeout 값이 얼마여야 하는지 설계 근거가 없다.
- 현재 부팅 시퀀스 허용 최대 지연이 얼마인지 정의되지 않았다.
- MCLR(~1ms) + boot_wait(50ms) + Auto-ATI 폴링(≤1500ms) + apply_settings + **노터치 게이트 최악**까지 합산한 부팅 초기화 총 지연이 사용 가능한 시스템 타임아웃 내에 있는지 검토되지 않았다.

5000ms timeout이 "설계 근거 없는 임의값"(28번 지적)임은 종합이 인정하지 않는다. 실제 부팅 지연 예산이 얼마인지, 그 안에 게이트 timeout이 맞는지는 여전히 미해결이다.

> 제안: 블로킹 미지수 목록에 **블로킹_G — 부팅 허용 최대 지연 예산(ms)** 항목 추가 필요. ci_timer_get_tick() 교체 후 timeout 재설정의 기준 수치가 없으면 구현 후에도 설계 근거가 부재한 상태로 남는다.

## 4. 미검증 주장 1 — "크래들 Phase 1 RESEED 삽입은 I2C 중단으로 dead code" 정당화 부실 [치명도: 낮음]

### 4-1. 종합의 주장

> "Phase 1 크래들 훅 구현 폐기: 뚜껑 닫힘 기간 I2C 중단으로 실질 이득 없음 (결함_3@22)" (`30_종합-1차 §2-1 Phase 4`)

### 4-2. 공격

크래들 뚜껑 닫힘 기간 I2C 통신이 중단된다는 전제는 "터치 폴링 완전 중단(I2C 통신 없음, IQS323 idle)"(오케스트레이터 입력 §1)에서 온다. 그런데 이 "idle" 상태에서 IQS323이 실제로 I2C 슬레이브로서 어떻게 동작하는지 — CM3가 I2C를 시도하면 NAK를 반환하는가, 아니면 정상 응답하는가 — 는 [확정 필요]다.

만약 크래들 뚜껑 닫힘 상태에서 CM3가 func_cradle_lid_closed_loop() 진입 전(main.c:742 앞) Re-ATI를 시도한다면, 그 시점은 아직 터치 폴링 중단 루프 진입 전이므로 I2C 통신이 가능하다. "dead code"가 되는 것은 뚜껑 닫힘 루프 내부에 삽입할 때이지, 루프 진입 전 삽입은 I2C 가능 구간이다.

Phase 1 크래들 훅 폐기 논리가 "뚜껑 닫힘 기간 I2C 중단"인데, 실제 삽입 지점(main.c:742 앞)은 루프 진입 전이므로 논리적 일관성이 없다. 이 폐기 결정은 재확인이 필요하다 [확정 필요].

## 5. 미검증 주장 2 — LP/ULP Beta 미설정의 절전 LTA 부작용 미반영 [치명도: 낮음]

### 5-1. 종합의 주장

> "Beta POR default 실측이 Phase 3 전 블로킹: 블로킹_D" (`30_종합-1차 §5-1`)

### 5-2. 공격

블로킹_D는 NP 모드 Beta(0xB0~0xB4) POR default를 실측하는 것이다. 그런데 28번 결함_7이 지적한 LP/ULP 모드 Beta 레지스터(0xB1·0xB3 [추정])는 종합 어디에도 언급되지 않는다.

Phase 3에서 NP Beta를 설정하면 절전 진입 시(tdc_drv_iqs323_reseed(), iqs323.c:931~948) Beta 레지스터를 리셋하지 않으므로 ULP 모드에서도 NP Beta가 유지될 수 있다. IQS323 LP/ULP 모드의 LTA IIR 동작 여부와 LP/ULP 전용 Beta가 별도 존재하는지는 데이터시트 §5.6 미확인 항목이다.

"Beta POR default 실측"(블로킹_D)만으로는 절전 중 LTA IIR 부작용을 평가할 수 없다. 블로킹_D에 **"LP/ULP 모드 Beta 레지스터 존재 여부 + 절전 중 LTA IIR 동작 범위"**를 추가해야 한다.

## 8. 핵심 결론 (6줄)

1. **"wait_re_ati_done() = 최대 1초" 수정이 새 환각이다** — 코드(L592/599: Sys_Delay×10=1000ms)에 force_window_open 비용(최악 90ms×10=900ms)이 누락됐으며, 실제 최악은 ~1.9초다. 30_종합 §8.6이 "1.5초→1초 정정"으로 끝났지만 올바른 값은 "Sys_Delay 기준 1초, force_window_open 포함 최악 ~1.9초"다.
2. **Phase 4 FPGA 절전 지연 비용이 종합에서 증발했다** — 28번 결함_2(중간 치명도)가 발굴한 "크래들 Re-ATI 블로킹 동안 FPGA 활성 전력 ~1.9초 추가 소모"는 블로킹 미지수·미해결 목록 어디에도 없다. 블로킹_G 신설이 필요하다.
3. **게이트 timeout의 부팅 지연 예산 근거가 없다** — ci_timer_get_tick() 교체(확인_5)는 방향 지시에 그칠 뿐, 교체 후 timeout을 얼마로 설정해야 하는지 기준 수치가 없어 구현 단계에서 다시 임의값 문제로 귀결된다.
4. **크래들 Phase 1 RESEED 폐기 논리가 삽입 지점과 불일치한다** — "뚜껑 닫힘 기간 I2C 중단"은 루프 내부 논리이고, 삽입 지점(main.c:742 앞)은 루프 진입 전 I2C 가능 구간이다. 폐기 결정 재검토 필요 [확정 필요].
5. **블로킹_D가 LP/ULP Beta 범위를 포함하지 않는다** — NP Beta 설정 후 절전 진입 시 LP/ULP 모드에서 LTA IIR이 의도치 않게 동작할 수 있는 경로가 미분석이며, 블로킹_D 항목에 추가해야 한다.
6. **나머지 통신·전력 항목은 수렴** — elapsed_ms 교체 방향, 사후 검증 재시도 게이트, WDT 삽입 필요, Beta 주소 [추정] 금지 등 24·28번 핵심 지적 5건은 30_종합에 반영됐다.
