# 06 분석 — 충전상태 활용 (캘리브/baseline 기회)

**TL;DR**: 충전기 연결 시 절전 진입 완전 차단(`systemControl.c:162` — `systemOff` 미set·`StartFlag=false`만) → 터치 IQS323 상시 폴링 유지. 이 구간은 ① 사용자 미터치 가능성 높음, ② 환경 안정(실내·정지), ③ 시간 여유 충분 — 세 조건이 겹쳐 **노터치 게이트 통과 후 Re-ATI/RESEED의 최적 기회창**이다. 단 충전 연결 자체는 노터치 보장이 아니므로 반드시 노터치 게이트를 통과한 후에만 실행해야 한다. 크래들 뚜껑 닫힘은 별도 경로로 터치 폴링 완전 중단 — 이 구간에 캘리브 코드는 미구현이며 독립적으로 활용 가능하다.

---

## 1. 코드 확정 — 충전 시 절전 진입 차단 메커니즘

### 1-1. 절전 진입 경로 분석

절전 진입은 `main.c`에서 `systemState.systemOff == true` 시 `break → func_sleep()` 호출로 발생한다.

`systemState.systemOff`가 `true`로 설정되는 경로:
1. `systemControl.c:299` — 배터리 방전(40% 미만) + POWER_OFF burst 완료 후
2. `systemControl.c:367` — 충전기가 연결됐다가 빠진 상태(`df_Disconnected` 분기)
3. `main.c:735` — QCC 배터리 타임아웃 경로

### 1-2. 충전기 연결 분기 (`systemControl.c:162`)

```c
else if (chargerState.chargerConnectorPluggedIn == df_Connected)
{
    systemStatus.BLE_Off    = true;
    systemStatus.enablePMIC = false;
    changePcmOutputMode(PcmBitStream_Mode_FillZero);
    // ...크래들 뚜껑 상태 처리...
    StartFlag = false;
    // ← systemStatus.systemOff = true 없음
}
```

**결론**: `df_Connected` 분기에서 `systemOff`를 `true`로 설정하는 코드가 없다. 따라서 충전기가 연결된 상태에서는 절전 진입 트리거가 발생하지 않는다 (코드 확정).

### 1-3. IQS323 폴링 계속 동작 확인

절전 진입이 없으면 `func_normal` 루프가 계속 돌고, `tdc_touch_process()`(`touch.c:422`)가 200ms 주기로 IQS323 상태를 폴링한다. 충전 중 IQS323 전원은 항상 ON — 터치 판정·방전(`discharge_crx0`)·상태 읽기가 모두 정상 동작한다.

## 2. 충전 구간의 환경 특성 분석

| 특성 | 충전 구간 | 일반 사용 구간 |
|---|---|---|
| 사용자 행동 | 기기를 내려놓거나 크래들/충전기에 연결 중 → 미터치 가능성 높음 [추정] | 착용 중 · 조작 가능 |
| 환경 안정성 | 실내 고정 위치, 온도 안정적 [추정] | 이동·착용 중 온도·습도 변화 |
| 시간 여유 | 충전 시간 = 수십 분 이상 → Re-ATI/RESEED 수행 시간 충분 | 사용 중 window 제한 |
| 노터치 판별 | 게이트 통과 필요 (충전=노터치 자동 보장은 아님) | 동일 |

### 2-1. 충전 ≠ 노터치 자동 보장

충전기 연결 상태에서도 사용자가 기기를 터치할 수 있다. 따라서 충전 구간을 캘리브 기회로 활용할 때 **노터치 게이트(공장 기준값 윈도우 확인 또는 counts 안정성 확인)**는 반드시 통과해야 한다. 충전 연결 사실만으로 RESEED/Re-ATI를 즉시 발행하면 안 된다.

## 3. 크래들과의 관계

### 3-1. 크래들 뚜껑 닫힘 경로 (기존 구현)

`main.c:740` — `systemState.cradleLidClosed && !isd_state.conneded_ISD` → `func_cradle_lid_closed_loop()` 진입.

`func_cradle_lid_closed_loop()` 내부:
- FPGA 리셋, nRF 끄기, FPGA 슬립, PMIC 끄기, LED 끄기
- **터치 폴링 루프(`tdc_touch_process`) 호출 없음** → IQS323 통신 완전 중단
- 뚜껑 열림 BLE 패킷(`df_Connected`) 감지 → `SYS_WATCHDOG_RESET()` → WDT 리셋 재부팅

### 3-2. 크래들 뚜껑 닫힘 구간의 특성

- 노터치 **보장**: 사용자가 기기에 접근 불가 (뚜껑으로 밀폐)
- IQS323 폴링 **완전 중단**: 재부팅 전까지 I2C 통신 없음
- **현재 캘리브 코드 미구현**: 이 구간에서 Re-ATI/RESEED를 수행하는 코드가 없음 (`분석.md §4`, 전제4 세부 참조)
- 재부팅 후 MCLR+Auto-ATI 1회 수행 → 이때가 "노터치 보장 상태에서의 ATI" 기회

### 3-3. 충전 vs 크래들 활용 비교

| | 충전 중 (일반 충전기) | 충전 중 (크래들 뚜껑 열림) | 크래들 뚜껑 닫힘 |
|---|---|---|---|
| 터치 폴링 | 계속 동작 | 계속 동작 | 완전 중단 |
| 노터치 보장 | 아님 (게이트 필요) | 아님 (게이트 필요) | 보장 |
| 재부팅 후 ATI 기회 | 없음 (재부팅 없음) | 뚜껑 닫히면 재부팅 후 기회 | 열림→재부팅 시 기회 |
| SW 활용 가능성 | 노터치 게이트 후 Re-ATI ✅ | 동일 | 미구현, 별도 트랙 필요 |

## 4. 충전 구간 활용 — 구체 방안

### 4-1. 주기적 노터치 Re-ATI 기회창 (권고)

충전 중 터치 폴링 루프 내에서 다음 조건을 주기적으로 평가한다:

```
충전 감지(df_Connected 상태) → 일정 주기(예: 30초)마다:
  → 현재 counts 읽기
  → 공장 기준값 윈도우 확인 (노터치 게이트)
      ├─ 게이트 통과: Re-ATI 또는 RESEED 실행 → 이후 LTA IIR 드리프트 추적
      └─ 게이트 실패(터치 의심): 다음 주기로 보류
```

**이점**: 장기 드리프트 누적 전에 주기적 보정 기회 확보. 일반 사용 구간보다 노터치 확률이 높아 게이트 통과율 높음 [추정].

### 4-2. 충전 진입 시 즉시 1회 시도

충전기 연결 이벤트(`df_Connected` 전이) 감지 → 초기 안정화 대기(예: 2~5초) 후 노터치 게이트 통과 확인 → Re-ATI 1회.

**주의**: 충전 연결 직후 사용자가 기기를 조작할 수 있으므로 대기 후 게이트 통과 필수.

### 4-3. 현재 RESEED 구조와의 정합

현재 `tdc_drv_iqs323_reseed()`(`iqs323.c:931`)는 절전 진입 경로에서만 호출된다. 충전 중 추가 RESEED 호출은 코드 신설이 필요하다 — 단, 노터치 게이트 통과 후에만 호출하면 baseline 오염 없이 현재 counts로 LTA를 정확히 seed할 수 있다(RESEED 제약: 현재 counts로만 seed, 임의값 불가 — §5.5.1).

**노터치 게이트 하에서는 Re-ATI가 RESEED보다 우월**: 게인(MULT/COMP)+baseline 전부 재보정 vs LTA만 갱신 (`브레인스토밍_부팅터치모호성.md §6-B`). 따라서 충전 구간 활용 시 Re-ATI를 우선 고려.

## 6. 결론 요약

1. **충전기 연결 시 절전 진입 완전 차단** — `systemControl.c:162` `systemOff` 미set 코드 확정. IQS323 터치 폴링 상시 유지.
2. **충전 구간 = 노터치 게이트 통과 후 Re-ATI의 최적 기회창** — 미터치 가능성·환경 안정·시간 여유 세 조건 유리 [추정].
3. **충전 ≠ 노터치 자동 보장** — 반드시 노터치 게이트(공장 기준값 윈도우) 통과 후에만 Re-ATI/RESEED 실행.
4. **Re-ATI > RESEED** — 노터치 게이트 하에서 게인+baseline 전부 재보정하는 Re-ATI 우선.
5. **크래들 뚜껑 닫힘 구간은 별도 트랙** — 터치 폴링 완전 중단(I2C 비활성)으로 SW 추가 불가, 재부팅 후 MCLR+ATI가 실질 기회. 현재 미활용.
6. **충전 구간 주기 Re-ATI 구현 시 신설 필요** — 충전 이벤트 구독 인터페이스·노터치 게이트 로직·주기 타이머 [확정 필요].
7. **환경 드리프트 보정 최선 구간** — 일반 사용 중 Re-ATI 기회가 드문 경우 충전 구간이 드리프트 보정의 현실적 대안이 된다.
