# 02_공장캘리 — 공장초기화 캘리브레이션 절대기준 저장·활용 분석

**TL;DR**: 공장초기화(노터치 보장) 시 Auto-ATI로 MULT/COMP를 산출하고 이어서 CH0 Filtered Counts를 noTouch 절대기준으로 함께 EEPROM에 저장한다. 이후 모든 부팅에서 저장 MULT/COMP를 Fixed로 write하고, 저장 noTouch counts를 RESEED 노터치 게이트의 판별 기준으로 사용한다. 기존 `ati-calib-mode`(`tdc_drv_iqs323_calib_read_ati()`)가 MULT/COMP 읽기를 이미 구현했으므로 신규 구현은 EEPROM 저장·로드 경로와 게이트 로직뿐이다.

---

| 구분 | 내용 |

| 목표 | 공장초기화 시 노터치 Auto-ATI로 MULT/COMP + noTouch Counts를 EEPROM에 저장하고, 이후 부팅에서 절대기준으로 활용 |

## 2. 현 코드 근거

### 2-1. MULT/COMP 읽기 경로 (기존 구현 확인됨)

`tdc_drv_iqs323.c:820~840` — `tdc_drv_iqs323_calib_read_ati(uint16_t *p_mult, uint16_t *p_comp)`:
- `TDC_DRV_IQS323_REG_ADDR_SENSOR0_ATI_MULT` + `SENSOR0_ATI_COMP` 레지스터를 `read_register()`로 읽어 16비트 little-endian으로 반환.
- `TDC_TOUCH_ATI_CALIB_MODE` 빌드 플래그 하에서 `tdc_touch.c:try_finish_init()` 내 무한 루프에서 반복 호출됨 (`tdc_touch.c:236~259`).
- **현재 사용처**: `apply_settings()` 후 MULT/COMP를 RTT 또는 LED로 출력하는 개발 도구 — EEPROM 저장은 없음.

### 2-2. noTouch Counts 읽기 경로 (이미 존재)

`tdc_drv_iqs323.c:1208` — `read_register(TDC_DRV_IQS323_REG_ADDR_CH0_FILTERED_COUNTS, &lsb, &msb)`:
- `tdc_drv_iqs323_check_touch_margin()` 내에서 CH0 Filtered Counts(0x13)를 읽는 경로가 존재함.
- Auto-ATI 완료 직후(apply_settings() 이전) 또는 apply_settings() 완료 후 안정화 대기 후에 이 경로로 noTouch counts를 읽을 수 있다.

### 2-3. 읽기 최적 타이밍

`tdc_touch.c:try_finish_init()` 내 흐름:

```
MCLR → Auto-ATI 완료 대기(is_auto_ati_done 폴링, 최대 TDC_TOUCH_INIT_TIMEOUT_MS)
 → apply_settings()  ← ★ 여기서 고정 MULT/COMP write → Auto-ATI 결과 덮어씀
 → (TDC_TOUCH_ATI_CALIB_MODE) 반복 loop
```

공장캘리 목적의 MULT/COMP 읽기는 **Auto-ATI 완료 후, apply_settings() 이전** (`tdc_drv_iqs323.c`의 분석.md §핵심 발견 확인)이 유일한 기회다. noTouch Counts는 apply_settings() 완료 후 안정화(~50ms) 후에 읽는 것이 더 안정적이다. [추정: apply_settings() 후 RESEED까지 완료된 시점의 counts가 실운용 noTouch 기준에 더 근접]

## 3. EEPROM 저장 경로 분석

### 3-1. 현 NVM/EEPROM 구조

Sound1의 NVM은 **CFX(FPGA 측)가 관리하는 Flash EEPROM**으로, CM3는 `cfx_cm3_sharedMemory`를 통해 CFX에 read/write 명령을 전달한다:
- `cfx_cm3_sharedMemory.h:335` — `setReadWriteMapDataFlashCommand()`: CFX에 Flash 명령 전달
- `cfx_cm3_sharedMemory.h:336` — `isReadWriteMapDataFlashCommandDone()`: 완료 폴링
- 현재 저장되는 데이터: ISD info(`ST__CFX_CM3_SharedMemory_ISD_info`), userSettingValue(`mapNum·stimulVolume·audioVolume` 등), mapData

### 3-2. 신규 저장 공간 확보 옵션

| 옵션 | 방법 | 장단점 |
|---|---|---|
| **옵션_A (권장)**: `userSettingValue` 구조체 확장 | `cfx_cm3_sharedMemory.h:89~98` `ST__CFX_CM3_SharedMemory_userSettingValue`에 `touch_mult_16`, `touch_comp_16`, `touch_noTouch_counts_16` 필드 추가 | CFX EEPROM 기존 경로 재사용·공장초기화 트리거 시 기존 `setReadWriteMapDataFlashCommand(flash_Command_Write)` 동일 흐름. 단, CFX 측 저장 스키마 변경 필요. |
| **옵션_B**: CM3 NVM(nvmctrl) 독립 저장 | `ci_boot.h:16` `#include <nvmctrl.h>` 이미 포함 — CM3 자체 Flash의 Data Flash 영역에 24바이트(MULT 2 + COMP 2 + Counts 2 + 매직넘버 2 + 패딩) 직접 쓰기 | CFX 없이 CM3 단독 가능·부팅 즉시 읽기 가능. 단, nvmctrl 직접 write는 고전압 플래시 수명·정렬 제약 검토 필요. [확정 필요] |
| **옵션_C**: 공유 메모리 내 별도 구조체 신설 | `cfx_cm3_sharedMemory.h`에 `ST__CFX_CM3_TouchCalib` 신설 | 가장 명시적이나 구조 변경 범위 가장 큼 |

**권고**: 옵션_A(기존 CFX EEPROM 경로 확장)가 현 아키텍처와 가장 정합적이다. 단, CFX 측 파서가 변경된 구조체 크기를 인식해야 하므로 CFX 코드 연동 확인이 선행 조건이다. [확정 필요 — CFX 측 userSettingValue 파서 위치·크기 제약]

## 4. 저장 트리거 — 공장초기화 진입점

`remoteControl.c:171` 주석 — "수술 위치 3=공장초기화"가 진입 분기로 존재. 또한 `reset_NVM_All_ISD_allData()` (`remoteControl.c:1302`)가 공장초기화 시 호출되는 것으로 확인됨.

**공장캘리 트리거 흐름 (신규)**:

```
공장초기화 수신(BLE 패킷, 수술위치=3)
  → MCLR 리셋 (혹은 전용 공장캘리 커맨드)
  → 노터치 보장 환경 확인 (공장 치구·크래들)
  → Auto-ATI 완료 대기
  → MULT/COMP 읽기 (tdc_drv_iqs323_calib_read_ati())   ← 기존 구현 재활용
  → apply_settings()로 운용 설정 적용
  → 안정화 대기(~50ms)
  → CH0 Filtered Counts 읽기 (= noTouch 절대기준)
  → 3값(MULT·COMP·Counts) EEPROM write (setReadWriteMapDataFlashCommand)
  → 저장 완료 확인 (isReadWriteMapDataFlashCommandDone)
```

> [!NOTE]
> 크래들 뚜껑 닫힘 구간은 현재 `func_cradle_lid_closed_loop`(`main.c:807`)에서 터치 폴링을 완전 중단한다. 이 구간은 노터치가 하드웨어적으로 보장되므로 공장캘리 수행에 최적이나, 현재 이 구간에 캘리브레이션 코드가 없다. 향후 확장 포인트. (전제4 참조)

## 5. 로드 및 활용 경로 — 매 부팅 절대기준 RESEED 게이트

### 5-1. 로드 타이밍

부팅 시 `main.c:355~379` — CFX 시작 후 `CFX_EEPROM_data_is_Loaded=1` 확인 시점에 userSettingValue가 공유 메모리로 로드됨. touch 모듈 초기화는 `tdc_touch_init()`에서 진행되므로, **CFX EEPROM 로드 완료 후 `tdc_touch_init()` 호출** 순서가 보장되면 `tdc_touch.c` 내에서 저장값을 바로 참조 가능하다. [확정 필요: main.c 부팅 순서 상 tdc_touch_init() 호출 위치]

### 5-2. 활용 흐름 — RESEED 노터치 게이트

브레인스토밍(`브레인스토밍_부팅터치모호성.md §6-A`)과 v1/v2 종합에서 수렴한 "공장값 게이트 + Re-ATI(또는 RESEED)" 패턴의 구체화:

```
부팅 → apply_settings() 완료(고정 MULT/COMP write, ATI Disabled)
  → RESEED(현재 구현: iqs323.c:1146 무조건) ← 이 지점을 게이트로 교체
  → 현재 CH0 Filtered Counts 읽기
  → 공장 저장 noTouch Counts 유효성 확인(매직넘버·범위 체크)
  ├─ 공장값 없음(미캘리브레이션): 기존 무조건 RESEED 유지(현 동작 보존)
  └─ 공장값 있음:
      ├─ counts ∈ [factory_noTouch − WINDOW, factory_noTouch + WINDOW]
      │    → 노터치로 판정 → RESEED 허용 ✅
      └─ counts ≪ factory_noTouch (터치 의심: self-cap이므로 터치 시 counts 감소)
           → RESEED 보류 → counts가 윈도우 안으로 회복 대기
           → 회복 시 RESEED ✅ (timeout 시 저신뢰 폴백)
```

**WINDOW 값** [확정 필요 — 실측 의존]: 환경 드리프트 허용범위. 초기 보수값으로 ±50 counts 제안 [추정]. 실측5(장기 drift 관찰) 후 조정 필요.

### 5-3. RESEED vs Re-ATI 선택

브레인스토밍 §6-B에서 확인: 노터치 게이트 하에서 RESEED보다 **Re-ATI가 우월** — MULT/COMP(게인)까지 재보정해 환경 변화를 전범위 흡수. 단, Re-ATI는 ATI Disabled 모드에서 비활성이므로, Re-ATI 활용을 위해서는 ATI Full 복귀(Phase 2)와 연동해야 한다. 현 Phase 1(RESEED 게이트만)은 ATI Disabled 유지 상태에서도 적용 가능하다.

## 6. 저장 데이터 포맷

```c
/* 신규: cfx_cm3_sharedMemory.h ST__CFX_CM3_SharedMemory_userSettingValue에 추가 제안 */
typedef struct {
    uint16_t touch_mult_16;         /* Auto-ATI 결과 MULT (16비트 little-endian) */
    uint16_t touch_comp_16;         /* Auto-ATI 결과 COMP (16비트 little-endian) */
    uint16_t touch_noTouch_counts;  /* noTouch 절대기준 (CH0 Filtered Counts, 16비트) */
    uint16_t touch_calib_magic;     /* 캘리브레이션 완료 매직넘버 = 0xCA1B (유효성 판별) */
} ST__CFX_CM3_TouchCalib;
```

- **매직넘버 0xCA1B**: 미캘리브레이션 보드(POR default 0x0000)와 구분.
- **범위 체크**: `touch_noTouch_counts < 100` 또는 `> 900` [추정: 실제 counts 범위는 실측 필요]이면 무효 처리 → 폴백.

## 9. 핵심 결론 (7줄)

1. **MULT/COMP 읽기는 이미 구현됨** — `tdc_drv_iqs323_calib_read_ati()`(`iqs323.c:820`)가 존재. 신규 구현 불필요.
2. **noTouch Counts 읽기도 경로 존재** — `REG_ADDR_CH0_FILTERED_COUNTS`(0x13) read_register 사용. apply_settings()+RESEED 완료 후 ~50ms 안정화 후 읽기 권장 [추정].
3. **EEPROM 저장 권고 경로** — 기존 CFX EEPROM(`setReadWriteMapDataFlashCommand`) 경로 확장(옵션_A). 저장 데이터: MULT 16b + COMP 16b + noTouch Counts 16b + 매직넘버 0xCA1B.
4. **공장초기화 트리거** — BLE 공장초기화(수술위치=3) 수신 시 전용 캘리브레이션 시퀀스 실행(노터치 보장 전제).
5. **매 부팅 활용** — 저장값 있으면(매직넘버 확인) RESEED 전 게이트 판별: counts∈[factory±WINDOW]이면 RESEED 허용, 아니면 보류→회복 대기.
6. **드리프트는 RESEED 후 LTA IIR이 흡수** — 공장값은 "절대 기준 제공"이지 "영구 LTA 고정"이 아님. RESEED 이후 IIR이 환경 변화를 추적.
7. **WINDOW 허용범위·CFX 파서 확장**은 [확정 필요] — 실측5(drift 관찰) + CFX 코드 리뷰 선행 후 확정.
