# 13_계획_크래들훅 — 크래들 뚜껑 닫힘/열림 baseline 갱신 훅 구현 설계

**TL;DR**: 크래들 뚜껑 닫힘 진입 직전(`main.c:742`)에 RESEED 또는 Re-ATI를 삽입하는 단 1~2줄 훅으로 "race 소멸 구간"을 활용한다. Phase 1은 순수 RESEED(절전 파라미터 제거 주의), Phase 2는 Re-ATI 블로킹 호출이다. 뚜껑 열림은 WDT 리셋 재부팅이 자동 처리하므로 별도 훅이 불필요하다. 크래들 부팅 플래그(지점 B)는 BLE 신호 가용성 [확정 필요] 로 인해 Phase 3 이후로 미룬다.

---

## 1. 삽입 지점 확정 (코드 근거)

### 1-A. 뚜껑 닫힘 진입 시 (Phase 1/2 대상)

```
main.c:739~745 현재 코드:
    if (systemState.cradleLidClosed && !isd_state.conneded_ISD)
    {
        led_force_fade_off();          /* line 742 */
        func_cradle_lid_closed_loop(); /* line 743 */
        /* 도달 불가 */
    }
```

**삽입 위치**: `led_force_fade_off()` 호출 완료 직후, `func_cradle_lid_closed_loop()` 호출 직전.

**이유**: 이 시점부터 `func_cradle_lid_closed_loop()` 내부(`main.c:807~867`)에는 I2C/터치 코드가 전혀 없다. IQS323은 idle 상태이나 아직 전원이 공급 중이므로 I2C 통신이 가능하다. 이 분기는 `!isd_state.conneded_ISD` 가드로 ISD 연결 중에는 진입하지 않는다 — I2C 충돌 없음.

### 1-B. 뚜껑 열림 훅 불필요 확정

`func_cradle_lid_closed_loop()` 내부(`main.c:851~857`):
```c
if (tdc_cradle_get_cover_state() == df_Connected)
{
    ...
    SYS_WATCHDOG_RESET();   /* main.c:856 — 즉시 재부팅 */
}
```

WDT 리셋 발동 후 코드 실행 기회가 없다. 재부팅은 `initialize.c:449` MCLR → Auto-ATI → `iqs323.c:1141` 고정 MULT/COMP write → `iqs323.c:1147` RESEED를 자동 수행한다. **열림 후 별도 훅은 물리적으로 삽입 불가**이며, 부팅 시퀀스가 재보정을 담당한다.

## 2. Phase 1 — RESEED 훅 (즉시 구현 가능)

### 2-1. 목표

- 뚜껑 닫힘 진입 시 노터치 보장 구간에서 LTA를 현재 노터치 counts로 seed한다.
- 약 절전 루프(`func_cradle_lid_closed_loop`) 진입 전 baseline 오염 방지.
- 뚜껑 열림 WDT 리셋 부팅 직전 baseline을 최신 노터치 환경으로 정렬.

### 2-2. 기존 `tdc_drv_iqs323_reseed()` 사용 불가 이유

`tdc_drv_iqs323_reseed()`(`iqs323.c:931~948`)는 절전 전용 함수다:
- `TDC_DRV_IQS323_SLEEP_TOUCH_THRESHOLD` / `TDC_DRV_IQS323_SLEEP_TOUCH_HYSTERESIS` 적용 → 절전 감도로 변경
- `TDC_DRV_IQS323_SLEEP_PROX_THRESHOLD` 적용 → 절전 Prox 설정으로 변경

뚜껑 닫힘 구간은 절전(ULP)이 아닌 약 절전(normal mode)이다. 절전 파라미터를 적용하면 뚜껑 열림 WDT 리셋 부팅 후 처음 폴링에서 감도 불일치가 발생할 수 있다 [추정].

**해결**: 순수 RESEED만 수행하는 신규 함수 `tdc_drv_iqs323_reseed_normal()` 추가 또는 raw `write_register(RESEED)` 직접 호출.

### 2-3. 구현 방안

**방안 A — 신규 API 추가 (권장, 재사용성)**

`tdc_drv_iqs323.c`에 추가:
```c
/* 크래들 뚜껑 닫힘 등 normal 모드 noTouch 보장 구간에서 순수 RESEED 수행.
 * tdc_drv_iqs323_reseed()와 달리 절전 파라미터(THRESHOLD/HYSTERESIS/PROX) 미적용. */
bool tdc_drv_iqs323_reseed_normal(void)
{
    if (!write_register(TDC_DRV_IQS323_REG_ADDR_SYSTEM_CONTROL, 0x08, 0x00))
    {
        ci_printe("[TOUCH] FAIL: CRADLE RESEED\r\n");
        return false;
    }
    ci_printi("[TOUCH] CRADLE RESEED OK\r\n");
    return true;
}
```

`tdc_drv_iqs323.h`에 선언 추가:
```c
bool tdc_drv_iqs323_reseed_normal(void);
```

**방안 B — main.c 인라인 (최소 변경)**

`main.c:742~743` 사이 직접 삽입:
```c
led_force_fade_off();
/* [크래들 훅] 노터치 보장 구간 RESEED — 절전 파라미터 없이 LTA 갱신 */
tdc_drv_iqs323_reseed_normal();
func_cradle_lid_closed_loop();
```

방안 A를 권장한다. `tdc_drv_iqs323.c` 내 캡슐화로 이후 Phase 2(Re-ATI)로 교체 시 `main.c` 수정 없이 함수 구현만 교체 가능.

### 2-4. 변경 파일

| 파일 | 변경 내용 | 규모 |
|---|---|---|
| `tdc_drv_iqs323.c` | `tdc_drv_iqs323_reseed_normal()` 신규 추가 | ~10줄 |
| `tdc_drv_iqs323.h` | 선언 추가 | 1줄 |
| `main.c:742` | `tdc_drv_iqs323_reseed_normal()` 호출 삽입 | 1줄 |

## 3. Phase 2 — Re-ATI 훅 (노터치 게이트 구현 후 적용)

### 3-1. 목표

RESEED(LTA만 갱신)보다 우월한 Re-ATI(MULT/COMP 게인 + baseline 전체 재보정)를 노터치 보장 구간에서 실행한다. 보드편차·드리프트를 가장 완전하게 흡수할 수 있다.

### 3-2. 선행 조건

- `tdc_drv_iqs323.c:569` `re_ati_trigger()` — 이미 `static` 구현 존재.
- `tdc_drv_iqs323.c:581` `wait_re_ati_done()` — 이미 `static` 구현 존재(10회 폴링, 100ms×10=1초 상한).
- Phase 1에서 RESEED 훅 삽입이 완료돼 있어야 교체 지점이 명확하다.
- `TDC_TOUCH_ATI_FULL_ENABLE` 빌드 가드 또는 별도 크래들 전용 가드(`TDC_TOUCH_CRADLE_REATI_ENABLE`) 결정 필요.

### 3-3. 신규 API 설계

`tdc_drv_iqs323.c`:
```c
/* 크래들 뚜껑 닫힘 직후 — 노터치 절대 보장 구간에서 Re-ATI 블로킹 실행.
 * ~1.5초(wait_re_ati_done 10×100ms) 소요. 약 절전 루프 진입 전 호출되므로 블로킹 허용.
 * 완료 후 ATI Mode=Disabled 복원(ATI_SETUP_LSB 0x08 재적용).
 * Re-ATI 실패 시 RESEED 폴백. */
bool tdc_drv_iqs323_cradle_re_ati(void)
{
    ci_printi("[TOUCH] CRADLE Re-ATI START\r\n");

    if (!re_ati_trigger())
    {
        ci_printe("[TOUCH] CRADLE Re-ATI TRIGGER FAIL — RESEED FALLBACK\r\n");
        return tdc_drv_iqs323_reseed_normal();
    }

    if (!wait_re_ati_done())
    {
        ci_printe("[TOUCH] CRADLE Re-ATI WAIT FAIL — RESEED FALLBACK\r\n");
        return tdc_drv_iqs323_reseed_normal();
    }

    /* ATI Mode=Disabled 재적용 (Re-ATI 완료 후 Mode 복원) */
    if (!write_register(TDC_DRV_IQS323_REG_ADDR_SENSOR0_ATI_SETUP,
                        TDC_DRV_IQS323_ATI_SETUP_LSB,
                        TDC_DRV_IQS323_ATI_SETUP_MSB))
    {
        ci_printe("[TOUCH] CRADLE Re-ATI MODE RESTORE FAIL\r\n");
    }

    ci_printi("[TOUCH] CRADLE Re-ATI OK\r\n");
    return true;
}
```

> [!NOTE]
> `re_ati_trigger()`·`wait_re_ati_done()`은 현재 `static`이다. Phase 2 구현 시 `static` 제거 또는 공개 래퍼 API(`tdc_drv_iqs323_re_ati_trigger()`) 추가 필요. `tdc_drv_iqs323_cradle_re_ati()`를 동일 .c 파일 내 배치하면 `static` 유지 가능 — 권장.

### 3-4. main.c 교체 (Phase 2)

```c
led_force_fade_off();
/* Phase 1: tdc_drv_iqs323_reseed_normal() */
/* Phase 2 교체: */
tdc_drv_iqs323_cradle_re_ati();   /* ~1.5초 블로킹 허용(약 절전 루프 진입 전) */
func_cradle_lid_closed_loop();
```

### 3-5. Re-ATI 결과 지속성 한계 [추정]

Re-ATI가 성공해 MULT/COMP가 갱신되더라도, 뚜껑 열림 WDT 리셋 후 부팅 시 `iqs323.c:1141` `write_ati_compensation()`이 **하드코딩 고정값으로 덮어쓴다**. 따라서 Re-ATI 갱신값은 뚜껑 닫힘 구간 동안만 유효하다.

Re-ATI 결과를 재부팅 후에도 유지하려면 Phase 3(EEPROM 저장·로드)가 필요하다 — 본 계획 범위 외.

## 4. Phase 3 — 크래들 부팅 판별 훅 (미래 확장, 지점 B)

### 4-1. 개념

뚜껑 열림 WDT 리셋 재부팅 시 부팅 이유를 크래들 신호로 판별해 Auto-ATI 결과를 버리지 않고 채택한다.

```
부팅 MCLR + Auto-ATI 완료
  → tdc_cradle_get_cover_state() 확인
  ├─ 직전 닫힘 플래그 존재 (크래들 부팅 확인) → Auto-ATI 결과 채택, RESEED 허용
  └─ 일반 부팅                              → 기존 고정값 write (현재 동작 유지)
```

### 4-2. 선행 조건 [확정 필요]

- `tdc_cradle_get_cover_state()`가 부팅 초기(BLE 패킷 수신 전)에 가용한지 확인 필요.
- 현재 `func_cradle_lid_closed_loop()` 내에서 BLE 패킷을 통해 뚜껑 상태를 갱신하므로, 재부팅 직후 BLE 통신이 재초기화되기 전에는 이전 상태가 보존되지 않는다 [추정].
- SoC SRAM retention 또는 EEPROM에 "직전 크래들 닫힘" 플래그를 저장해야 부팅 초기 판별 가능 [확정 필요: 구현 비용 중간].

Phase 3는 Phase 2 완료 + 크래들 신호 가용성 확인 후 착수한다.

## 6. race 분석 — 이 훅의 고유 안전성

| 위험 | 일반 부팅 noTouch 게이트 | 크래들 뚜껑 닫힘 훅 |
|---|---|---|
| 판별~RESEED 사이 race | 존재 (μs~ms, 저확률) | **소멸** — 기구적 차단으로 터치 물리 불가 |
| 공장값 절대 기준 필요 | 필요 (없으면 판별 불능) | **불필요** — 노터치가 하드웨어로 보장 |
| ATI_Error 처리 | 핸들러 없으면 영구먹통 위험 | Phase 1 RESEED는 ATI 비활성화 구조 — 무관 |
| 드리프트 보정 범위 | LTA만 (Phase 1 RESEED) | LTA만 (Phase 1) / MULT+COMP 포함 (Phase 2 Re-ATI) |

**크래들 훅은 race가 소멸하는 유일한 경로**다. 공장 캘리브레이션 없이도 안전하게 RESEED/Re-ATI를 실행할 수 있다는 점에서 다층 방어의 가장 견고한 층이다.

## 7. 핵심 결론 (7줄)

1. **삽입 위치**: `main.c:742` `led_force_fade_off()` 직후, `func_cradle_lid_closed_loop()` 직전 — 노터치가 기구적으로 보장되고 IQS323 I2C 통신이 가능한 유일한 지점.
2. **Phase 1(즉시)**: `tdc_drv_iqs323_reseed_normal()` 신규 추가 — 절전 파라미터 없이 순수 RESEED만 발행, 3파일 ~12줄.
3. **Phase 2(노터치 게이트 후)**: `tdc_drv_iqs323_cradle_re_ati()` 신규 추가 — `re_ati_trigger()`+`wait_re_ati_done()`(이미 존재) 연결, 실패 시 RESEED 폴백, ~1.5초 블로킹 허용.
4. **기존 `tdc_drv_iqs323_reseed()` 사용 금지**: 절전 파라미터(THRESHOLD/HYSTERESIS/PROX)를 적용하므로 크래들 약 절전 구간에 부적합.
5. **열림 훅 불필요**: `SYS_WATCHDOG_RESET()`(`main.c:856`) 이후 코드 실행 불가 — WDT 리셋 재부팅이 MCLR+Auto-ATI+RESEED를 자동 수행.
6. **Re-ATI 결과 재부팅 후 소멸**: `write_ati_compensation()`이 재부팅마다 고정값 덮어쓰기 — Phase 2 Re-ATI 효과는 뚜껑 닫힘 기간 중으로 제한됨, Phase 3 EEPROM 저장과 결합해야 영속.
7. **race 소멸**: 크래들 훅은 공장 기준값 없이도 100% 안전한 RESEED/Re-ATI 실행이 가능한 다층 방어의 race-free 층이며, Phase 1로 즉시 이득을 얻을 수 있다.
