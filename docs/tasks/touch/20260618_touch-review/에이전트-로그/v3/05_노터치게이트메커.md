# 05 — 노터치 게이트 메커니즘 분석 (분석_노터치게이트메커)

**TL;DR**: 노터치 판별은 3레이어(공장 기준 윈도우 → counts 안정 → 손뗌 급증)를 순서대로 통과해야 RESEED/Re-ATI 게이트를 열 수 있다. 게이트 열림~실행 사이 race는 SW로 100% 제거 불가하나, 실행 직후 사후검증+자기치유+크래들 경로 조합으로 치명도를 무시 가능 수준까지 낮출 수 있다.

> [!IMPORTANT]
> 근거: 데이터시트 §5.5(LTA IIR)·§5.7(터치 판정)·§5.9(ATI)·§5.10(Re-ATI)·§5.11(ATI Error)·§5.5.1(RESEED), 코드 `tdc_drv_iqs323.c:931~948`(RESEED), `:569~596`(re_ati_trigger/wait_re_ati_done), `:1141~1158`(write_ati_compensation+RESEED), `main.c:952`(절전 RESEED 경로), `tdc_drv_iqs323.h:132·146`(TOUCH_THRESHOLD=100, PROX_THRESHOLD=120). 추정=[추정], 실측의존=[확정 필요].

## 1. 노터치 판별 3레이어 아키텍처

### 1-1. 레이어 구조 (순서 통과 필수)

```mermaid
flowchart TD
    boot["부팅 완료 (MCLR+Auto-ATI+고정MULT/COMP 완료)"]
    boot --> L1{"레이어_1: 공장 기준 윈도우\ncounts ∈ [factory ± 허용마진]?"}
    L1 -->|실패 — 터치 의심| hold["RESEED/Re-ATI 게이트 닫힘\n손뗌 대기 루프"]
    hold --> spike{"손뗌 급증 감지\n(레이어_3 조기 활용)"}
    spike -->|counts 급상승| L1
    spike -->|timeout| degraded["저신뢰 폴백\n(§4 참조)"]
    L1 -->|통과 (절대값 OK)| L2{"레이어_2: counts 안정성\nN샘플 분산 < σ_thr\n& 평균 ≈ 윈도우 중앙?"}
    L2 -->|불안정 — 진동/과도| hold2["추가 샘플 대기"]
    hold2 --> L2
    L2 -->|통과 (안정)| L3{"레이어_3: 손뗌 급증 확인\n직전 counts 대비\n급격한 상승 없음?"}
    L3 -->|통과 (급증 없음 = 안정 노터치)| gate_open["게이트 열림"]
    L3 -->|급증 있으면 손뗌 직후 과도기| wait_settle["수 샘플 추가 안정화"]
    wait_settle --> L2
    gate_open --> exec["RESEED 또는 Re-ATI 실행\n(게이트 닫힘 → 원자 블록)"]
    exec --> post["사후 검증 (§3)"]
```

### 1-2. 레이어별 판별 기준

| 레이어 | 판별 조건 | 코드/데이터시트 근거 | 추정/확정 |
|---|---|---|---|
| **레이어_1: 공장 기준 윈도우** | `counts ∈ [factory_noTouch ± MARGIN]` | TOUCH_THRESHOLD=100 (`tdc_drv_iqs323.h:132`), RESEED는 현재 counts만 가능(§5.5.1) — 윈도우 설정은 실측 공장값 기반 | [확정 필요]: 공장 noTouch counts 절대값 실측 후 MARGIN 결정 |
| **레이어_2: counts 안정성** | N샘플(N=5~10) 분산 < 임계 AND 평균이 레이어_1 통과값 | 브레인스토밍 방안 E (분산 관찰) + RESEED 제약 | [추정]: N·σ_thr는 실측(Beta·샘플주기) 후 조정 |
| **레이어_3: 손뗌 급증** | 직전 sample 대비 `Δcounts > SPIKE_THR` 감지 후 안정화 대기 | 브레인스토밍 방안 B (counts 급상승 = self-cap 손뗌) | [추정]: SPIKE_THR는 noTouch 정상 변동폭 실측 후 결정 |

> [!NOTE]
> **레이어_1이 핵심 게이트**: 공장 절대 기준이 없으면 레이어_2·3만으로는 "현재 counts가 노터치 기준인지, 터치 상태에서 안정된 것인지" 구분 불가(Cold-Start Ambiguity 본질). 레이어_1이 미지수 ①(보드 noTouch 절대값)를 고정함으로써 닭-달걀을 끊는다.

## 2. RESEED vs Re-ATI 게이트 선택 기준

### 2-1. 게이트 통과 후 실행 선택 기준

| 조건 | 권장 실행 | 이유 |
|---|---|---|
| **부팅 최초 1회** (공장 기준 OK + 안정) | **Re-ATI** (게인+baseline 전체 재보정) | MULT/COMP를 그 순간 환경에 맞춰 게인 최적화. RESEED는 LTA만 — 게인 왜곡 잔존 가능. [추정] |
| **절전 복귀 = 재부팅** | Re-ATI (위와 동일 — 절전 복귀=WDT 리셋 재부팅, 부팅 시퀀스 동일) | `main.c:952` RESEED 경로가 현재 코드이나, Re-ATI가 더 완전한 재보정 |
| **런타임 드리프트 보정** (LTA가 ATI Band 이탈, ATI Full 도입 시) | **Re-ATI** 자동 (§5.10) | LTA drift → counts 절대값 이탈 → MULT/COMP 재조정 필요 |
| **RESEED만 허용하는 경우** (ATI Mode=Disabled 유지 결정 시) | **RESEED** | 현 Fixed 구조 유지 + LTA 오염 방지. 게인 고정 수용. |

### 2-2. 현재 코드의 RESEED 위치와 게이트 부재

현재 코드에서 RESEED는 두 곳에서 **무조건** 실행된다:

- **부팅 RESEED** (`iqs323.c:1147`): `write_register(0xC0, 0x08, 0x00)` — 노터치 여부 확인 없이 바로 실행
- **절전 RESEED** (`iqs323.c:945`, `main.c:952`): 절전 진입 직전 — 터치 해제 대기 후 실행하나, 해제 확인 강도 [확정 필요]

**게이트 부재의 결과**: 부팅 시 터치 중이면 LTA가 터치 counts로 오염 → 뿌리_A(baseline 오염) 그대로 재현.

## 3. 판별~실행 race 최소화 및 원자성

### 3-1. race 발생 경로

```
[판별: 레이어_1~3 통과 → 노터치 확정] ←─ Δt ─→ [실행: RESEED/Re-ATI 발행]
                                          ^
                                  이 사이 터치 시작 가능
                                  (Δt = I2C 1~수 ms, 사람이 터치하는 확률 극히 낮음 [추정])
```

### 3-2. race 완화 전략 (4층)

| 층 | 전략 | 효과 | 코드 근거 |
|---|---|---|---|
| **층_1: 저확률** | 판별~실행 Δt를 I2C 1회 이내로 최소화 | 사람이 정확히 그 순간 터치할 확률 극소 [추정] | force_window_open + write_register 1회 연속 |
| **층_2: 원자 블록** | 레이어_3 직후 즉시 실행 — 중간에 폴링/인터럽트 없이 연속 수행 | 판별과 실행 사이에 다른 코드 삽입 금지 | `iqs323.c:1141~1149` 연속 sequence — 단, RESEED 전 I2C 통신이 게이트 확인보다 먼저면 윈도우 비용 발생 [추정] |
| **층_3: 사후 검증** | RESEED/Re-ATI 실행 *직후* counts를 재확인 — 레이어_1 범위 이탈 시 race 감지 | race를 사후 검출해 재시도 트리거 | `iqs323.c:1189~1228` read_touch_margin이 LTA/Counts 비교 제공 |
| **층_4: 자기 치유** | race로 오염 발생해도 손 떼면 counts 급증 → LTA IIR이 추적 수렴 → 자동 복구 | 영구 먹통 아님, 일시 오류 | §5.5 LTA IIR 추적 메커니즘 |

### 3-3. 크래들 race 소멸 경로

크래들 뚜껑 닫힘 구간(`func_cradle_lid_closed_loop`, `main.c:807`)에서는 터치 폴링 완전 중단 → 뚜껑 열림 시 WDT 리셋 재부팅. 이 구간을 Re-ATI 기회로 활용하면 **race 자체가 소멸**한다(터치 물리적 불가). 단 현재 미구현 (`main.c:807` 내 RESEED/Re-ATI 코드 없음 — [확정 필요]: 뚜껑 닫힘 → 열림 WDT 리셋 부팅 시 레이어_1 통과 가능 여부 확인).

## 4. 저신뢰 폴백 (timeout 시)

레이어_1 통과 실패 + 손뗌 대기 timeout 시:

```
시나리오: 부팅 후 N초(timeout) 내 counts가 공장 윈도우로 복귀 안 함
  원인_가: 실제 손가락이 얹혀 있어 터치 counts 유지 (가장 흔함)
  원인_나: ESD 전하 누적으로 counts가 비정상적으로 낮음
  원인_다: 보드 개체 편차가 공장 윈도우 MARGIN 밖 (캘리브레이션 오류)
```

| 폴백 선택 | 동작 | 적합 상황 |
|---|---|---|
| **폴백_A: 현재 counts로 RESEED 강행** | LTA 오염 감수, 이후 자기치유 기대 | 사용자가 장시간 터치 유지할 경우 무한 대기 방지 |
| **폴백_B: 이전 LTA 유지 (RESEED 보류)** | RESEED 안 하고 이전 LTA로 판정 계속 | 이전 부팅의 올바른 LTA가 있다면 (절전 복귀 시) |
| **폴백_C: 경보 플래그 + 폴백_A** | RTT 경보 출력 후 RESEED 강행 | 개발·디버깅 환경 |

**권고**: 폴백_A + RTT 경보. timeout = `공장 기준 × 2 + 여유` 정도의 값 [확정 필요].

## 5. 실제 구현 시 코드 구조 제안

```c
/* 노터치 게이트 — 레이어_1~3 판별 + 실행 원자 블록 (의사코드) */
bool tdc_notouch_gate_and_reseed(void)
{
    /* [레이어_1] 공장 기준 윈도우 확인 */
    uint16_t counts = read_filtered_counts();  /* 0x13 레지스터 */
    if (counts < FACTORY_NOTOUCH_COUNTS - FACTORY_MARGIN ||
        counts > FACTORY_NOTOUCH_COUNTS + FACTORY_MARGIN)
    {
        return false;  /* 터치 의심 → 게이트 닫힘 */
    }

    /* [레이어_2] N샘플 안정성 확인 */
    if (!is_counts_stable(N_SAMPLES, SIGMA_THR))
    {
        return false;  /* 불안정 → 추가 대기 */
    }

    /* [레이어_3] 직전 delta 확인 (급증 = 방금 손 뗀 과도기) */
    if (counts_delta_from_prev() > SPIKE_THR)
    {
        return false;  /* 과도기 → 안정화 대기 */
    }

    /* ── 원자 블록 시작 (판별~실행 최소화) ── */
    /* RESEED 또는 Re-ATI 즉시 실행 */
    tdc_drv_iqs323_reseed_gate();  /* 현재 counts로 LTA seed */
    /* 또는 re_ati_trigger() + wait_re_ati_done() — ATI Full 도입 시 */

    /* [사후 검증] 실행 직후 counts 재확인 */
    counts = read_filtered_counts();
    if (counts < FACTORY_NOTOUCH_COUNTS - FACTORY_MARGIN ||
        counts > FACTORY_NOTOUCH_COUNTS + FACTORY_MARGIN)
    {
        /* race 감지 — 재시도 또는 경보 */
        ci_printw("[TOUCH] GATE RACE DETECTED: counts=%u\r\n", counts);
        return false;
    }

    return true;  /* 성공 */
}
```

**코드 위치 권고**: `write_ati_compensation()` 직후, `write_register(RESEED)` 대체로 삽입 (`iqs323.c:1141~1149`).

## 6. FACTORY_NOTOUCH_COUNTS 값 설계

### 6-1. 현재 상황

현재 코드에 공장 noTouch counts 절대값 기준 상수가 존재하지 않음 [확정 필요]:
- TOUCH_THRESHOLD = 100 (`tdc_drv_iqs323.h:132`) — delta 판정용, 절대값 기준 아님
- PROX_THRESHOLD = 120 (`.h:146`) — LTA freeze 방지용, 절대값 기준 아님
- ATI Target 기준: `ATI_SETUP_MSB=0x04` → ATI Base=100, ATI Resolution Factor=ATI_SETUP_LSB bits[7:3]... [확정 필요: ATI Target 실제 counts 값 계산]

### 6-2. 취득 방법

| 방법 | 절차 | 정밀도 |
|---|---|---|
| **방법_가: RTT 실측** | 노터치 확정 상태에서 `read_touch_margin` 로그의 `Counts` 값 관찰 → 분포 중앙값 + ±MARGIN 결정 | 가장 정확 [확정 필요] |
| **방법_나: ATI Target 역산** | `ATI_SETUP_LSB=0x08`, `ATI_SETUP_MSB=0x04` 기준 ATI Target = ATI_Base × (ATI_Resolution_Factor/16) 계산 | 데이터시트 §5.9 정량 필요 [확정 필요] |
| **방법_다: MARGIN 기본값** | TOUCH_THRESHOLD=100 → MARGIN=50~80 (threshold의 50~80%) [추정] | 보수적 출발점, 실측 후 조정 |

## 7. 크래들 뚜껑 닫힘 구간 — 미활용 노터치 보장 기회

현 코드 (`main.c:807` `func_cradle_lid_closed_loop`):
- 터치 폴링 완전 중단 → 노터치 물리 보장
- 뚜껑 열림 → WDT 리셋 재부팅 → 레이어_1 통과 가능

이 구간에서 **Re-ATI를 선제 수행**하면 부팅 race 없이 게인+baseline 전체를 재보정할 수 있다. 구현 미완료이며 기회 활용 전략으로 계획에 포함 권고.

## 8. 핵심 결론 (7줄 이내)

1. **노터치 판별 3레이어**: 공장 기준 윈도우(절대값 게이트) → counts 안정성(N샘플 분산) → 손뗌 급증(spike 감지) — 순서대로 모두 통과해야 게이트 열림.
2. **레이어_1(공장 기준 윈도우)이 핵심**: 절대 기준 없이 레이어_2·3만으로는 Cold-Start Ambiguity(터치 vs 노터치 구분 불가) 해소 불가.
3. **게이트 통과 후 Re-ATI > RESEED**: Re-ATI는 게인(MULT/COMP)+baseline 전체 재보정, RESEED는 LTA만 — 노터치 확정 시점에 Re-ATI가 우월.
4. **race 제거 불가, 치명도 낮춤 가능**: 레이어_3 직후 즉시 실행(원자 블록) + 사후검증 + 자기치유(손뗌 시 LTA IIR 수렴) + 크래들 race 소멸 경로 조합.
5. **현재 코드 RESEED 2곳 모두 게이트 없음** (`iqs323.c:1147`, `main.c:952`): 터치 중 부팅 시 baseline 오염 경로 그대로 — 게이트 삽입이 Phase 1 핵심 구현.
6. **FACTORY_NOTOUCH_COUNTS 실측 선행 필수**: RTT 마진 로그(`tdc_drv_iqs323.c:1213~1228`)에서 noTouch Counts 분포 확인 → 윈도우 기준값 결정 후 구현 가능.
7. **크래들 뚜껑 닫힘 구간 Re-ATI**: 노터치 물리 보장 구간이나 현재 미활용 — 부팅 race 소멸 기회로 계획 반영 권고.
