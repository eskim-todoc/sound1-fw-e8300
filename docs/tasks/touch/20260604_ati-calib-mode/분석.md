> **TL;DR**: 기존 `TDC_DRV_IQS323_ATI_DUMP_ENABLE` 플래그 구조 확인. `try_finish_init()` 내 `apply_settings()` 호출 직전이 최적 읽기 포인트. LED 직접 제어 API 사용 가능.

## 현재 코드 구조

### 초기화 흐름

```
tdc_touch.c: try_finish_init()
  ├── tdc_drv_iqs323_is_auto_ati_done() 폴링
  ├── [ATI 완료 또는 2500ms 타임아웃]
  ├── SYS_WATCHDOG_REFRESH()
  └── tdc_drv_iqs323_apply_settings()
        ├── [DUMP MODE] ACK → 센서설정 → Re-ATI → dump_ati_registers()
        └── [운용 모드] ACK → 센서설정 → write_ati_compensation() → RESEED
```

### 핵심 발견: 읽기 포인트

**초기 auto-ATI**는 IQS323이 전원 ON 직후 자체적으로 실행. CM3는 `is_auto_ati_done()` 폴링만 함.
auto-ATI 완료 시점에 IQS323 내부 MULT·COMP 레지스터에는 IC가 결정한 최적값이 저장됨.

이후 `apply_settings()`가 호출되면서 `write_ati_compensation()`이 하드코딩값으로 덮어씀.

**→ `apply_settings()` 호출 전(`try_finish_init()` 내부)이 유일한 읽기 기회.**

### 기존 DUMP 모드와의 차이

| 항목 | `TDC_DRV_IQS323_ATI_DUMP_ENABLE` | 신규 `TDC_TOUCH_ATI_CALIB_MODE` |
|---|---|---|
| 위치 | `apply_settings()` 내부 | `try_finish_init()` 내, `apply_settings()` 앞 |
| 동작 | Re-ATI 재실행 후 시리얼 출력 | 초기 auto-ATI 결과 읽기 후 LED 출력 |
| 출력 | `ci_printi()` (시리얼) | LED N회 점멸 + 빨간 점등 |
| 용도 | 시리얼 연결된 개발 환경 | 조립 완제품 (디버그 포트 없음) |

두 플래그는 **독립적** — 동시 활성화 가능하나 이 작업에서는 별도 플래그로 관리.

### LED API 검토

```c
// LedOutput.c — 직접 GPIO 제어 (arbiter 우선순위 영향 없음)
void turnON_GreenLED(void);   // R=LOW, G=HIGH, B=LOW
void turnON_RedLED(void);     // R=HIGH, G=LOW, B=LOW
void LED_black(void);         // 즉시 OFF (turnOffLED()과 달리 fade 없음)
```

`LED_black()`은 arbiter can_run 여부와 관계없이 즉시 OFF → 블로킹 delay 중 깔끔한 ON/OFF 가능.

### Blocking Delay 패턴 (기존 코드 준용)

```c
// tdc_drv_iqs323.c 라인 673-674 패턴
{
    int t = ci_timer_get_tick();
    while (N > (ci_timer_get_tick() - t)) { SYS_WATCHDOG_REFRESH(); }
}
```

### 거리 계산 방식

COMP 16비트 값 (= `comp_msb * 256 + comp_lsb`) 기준 차이의 제곱 + MULT_MSB 차이의 제곱 × 가중치.
COMP가 정전 용량과 직접 대응하므로 더 중요:

```c
dist = (comp16_actual - comp16_cand)^2 + (mult_msb_actual - mult_msb_cand)^2 * 256
```

(MULT_MSB 1 차이 ≒ COMP_MSB 16 차이 수준으로 가중하여 균형)

### 후보 테이블 (초안)

COMP_MSB 기준 0x48~0xA0 선형 분포, 기존 3개 변형 포함:

| 인덱스 | MULT_LSB | MULT_MSB | COMP_LSB | COMP_MSB | 비고 |
|---|---|---|---|---|---|
| 1 | 0x82 | 0x5C | 0x00 | 0x48 | MINI 이하 |
| 2 | 0x82 | 0x5E | 0xFF | 0x53 | ≈DEVELOP |
| 3 | 0x82 | 0x5A | 0x00 | 0x58 | ≈MINI |
| 4 | 0x82 | 0x5C | 0x00 | 0x60 | |
| 5 | 0x82 | 0x5C | 0x00 | 0x68 | |
| 6 | 0x82 | 0x5C | 0x00 | 0x70 | |
| 7 | 0x82 | 0x5E | 0xFF | 0x73 | ≈PACKAGE |
| 8 | 0x82 | 0x5A | 0x00 | 0x80 | |
| 9 | 0x82 | 0x58 | 0x00 | 0x90 | |
| 10 | 0x82 | 0x56 | 0x00 | 0xA0 | PACKAGE 이상 고용량 |

> [!NOTE]
> 테이블은 초안. 실제 측정 후 은수님이 조정 가능. 숫자는 `const` 배열로 정의하므로 단순 수정.
