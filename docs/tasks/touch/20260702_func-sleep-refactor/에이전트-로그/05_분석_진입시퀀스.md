# 05_분석_진입시퀀스 — while 루프 진입 전 상단부 함수분리 포함 여부

## 결론

**포함하지 않는다.** `func_sleep()`(`main.c:1033~1219`)의 함수 분리 대상은 요구사항 4항 "while(1) ULP 루프 바디"(`main.c:1101~215`, 두 번째 while)에 **한정**하고, 진입부(`main.c:1037~1099`)는 지역변수 최상단 이동(요구 1항)·주석 정리(요구 3항)·`ci_print` 재분류(요구 2항)만 적용한 채 함수 본문에 그대로 남긴다.

## 근거 1 — 요구사항 문구 자체가 특정 루프를 지칭

요구 4항은 "while(1) **ULP** 루프 바디를 이름 있는 정적 함수로 분리"라고 명시한다. `func_sleep()` 내부에는 while(1)이 두 개 있다(`main.c:1062~1069` "CFX ULP mode 진입 대기" 루프, `main.c:1101~215` "ULP loop" — 코드 내 주석 `// ULP loop`가 붙은 것도 후자뿐). "ULP 루프"라는 표현은 후자를 명확히 가리키고, 전자는 CFX 핸드셰이크 대기용 별개 루프다. 즉 사용자가 말한 "while 내에서는 한눈에"는 `main.c:1101`부터 시작하는 루프 본문(터치 상태 읽기, ATI 에러 복구, sleep_ignore 게이트, 재부팅 판단 등 100줄 이상의 중첩 분기)을 뜻하며, 진입부는 범위 밖이다.

## 근거 2 — 진입부는 이미 "한눈에" 파악 가능한 선형 구조

진입부(`main.c:1037~1099`)는 63줄이지만 분기(`if/else`)가 사실상 없다:
- `write_FPGA_reset()` 호출 후 `ret` 출력(`main.c:1049~1050`)
- `ResetNRF()`/`NRF_Off_Command()`/`snd_qcc_set_mode()`/`Sys_GPIO_Set_Low()`/`OnOff_3V_PMIC_CM3_to_CFX(false)`/`turnOffLED()` — 6개 하드웨어 종료 호출을 순서대로 나열(`main.c:1054~1059`)
- CFX ack 대기 while(1) (`main.c:1062~1069`) — 분기 1개뿐, 몸체 3줄
- `ci_power_sleep()` → `i2c_set_master_prescale()` → `ci_timer_init_prescaled()` (`main.c:1077~1085`) — 클럭/타이머 전환 순차 호출

즉 진입부는 이미 "호출 순서를 눈으로 따라가면 되는" 나열형 코드다. 반면 ULP 루프는 게이트 상태(`sleep_ignore`)에 따라 동작이 완전히 갈리고 카운터 3종(`notouch_cnt`, `ignore_elapsed`, `touch_cnt`)이 얽혀 있어 분리 효과가 크다. 요구 4항이 ULP 루프만 지목한 것은 이 복잡도 차이를 정확히 반영한 것으로 보인다.

## 근거 3 — 회귀 위험 최소화 원칙(순수 구조정리)

"동작 100% 동일" 제약 하에서, 이미 분리가 필요 없는 구간까지 함수로 쪼개면 다음 회귀 위험이 새로 생긴다:
- `cfx_cm3_sharedMemoryAll.systemShare.enter_ULP_mode_Command_CM3_to_CFX`를 `1`로 설정(`main.c:1052`)한 직후 그 값을 읽는 대기 루프(`main.c:1064`)가 있어, 두 코드를 별도 함수로 쪼갤 경우 실행 순서·타이밍이 컴파일러 최적화나 함수 경계로 인해 미묘하게 바뀔 여지를 새로 만든다.
- `SYS_WATCHDOG_REFRESH()`가 `main.c:1037`과 `main.c:1087` 두 지점에서 호출되는데, 이 사이 구간을 별 함수로 나누면 워치독 refresh 순서 보존 여부를 별도 검증해야 하는 부담이 생긴다.
- 얻는 이득(가독성)이 근거 2에서 보듯 미미한 반면, 잃는 것(회귀 검증 비용)은 실재한다.

## 선택적 예외 (권장하지 않음, 참고용)

CFX ack 대기 루프(`main.c:1062~1069`)만은 형태상 독립 루프이므로 원한다면 `static void tdc_touch_sleep_wait_cfx_ulp_ack(void)`로 뽑을 수 있다. 다만 3줄짜리 단일 분기 루프라 분리 이득이 거의 없고, 전역 상태(`cfx_cm3_sharedMemoryAll`)를 직접 읽는 구조라 파라미터/리턴값 설계 이슈만 늘어난다. **채택하지 않는 편을 권고**한다.

## 계획 페르소나(11)를 위한 요약

- 함수 분리 대상: **ULP while(1) 루프 바디만**(`main.c:1101~215`).
- 진입부(`main.c:1037~1099`)는 지역변수 5종(`sleep_ignore`, `notouch_cnt`, `ignore_elapsed`, `touch_cnt`, `ulp_state_prev`, `ati_error_reboot_cnt`, `ret`)을 함수 최상단으로 옮기는 것 외에는 구조 변경 없음.
- 이 판단은 "요구 4항 문구 = ULP 루프 한정" + "진입부는 이미 선형 구조라 분리 효과 없음" + "회귀 위험 최소화" 3가지 근거의 교집합이며, 세 근거 모두 같은 결론을 가리킨다.
