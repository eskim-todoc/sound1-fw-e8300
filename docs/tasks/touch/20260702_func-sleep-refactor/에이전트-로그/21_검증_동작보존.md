# 21_검증_동작보존 — `func_sleep()` 리팩토링 계획 adversarial 검증

## 검증 결론 요약

계획의 핵심 골격(포인터 전달, `ok` 게이트, 함수 분리 지점, watchdog 순서)은 **논리적으로 타당**하다. 다만 "로직 문자 그대로 복사"라는 구현 지시가 실제 코딩 단계에서 깨지기 쉬운 지점 3곳과, 계획 문서 자체의 서술 정합성 문제 2곳을 발견했다.

## 발견 1 — [MEDIUM-HIGH] 카운터 리셋용 "else/else-if" companion 분기 누락 위험

`tdc_touch_sleep_handle_ati_error`의 역할 서술("ATI 에러 복구/재부팅 판단")과 `tdc_touch_sleep_handle_touch_reboot`의 역할 서술("게이트 해제 후 터치 재부팅 판단")은 각각 `if` 분기만 지칭하고, 실제로 포함되어야 하는 짝 분기를 언급하지 않는다:
- `else if (ok && !st.ati_error && !st.ati_active) { ati_error_reboot_cnt = 0; }` (110행대)
- `else { touch_cnt = 0; }` (204~206행)

이 두 분기는 "덜 눈에 띄는 else"라서, "로직만 복사, 리네이밍만"이라는 구현 지시에도 불구하고 실제 작업자가 "판단 로직"에만 집중하다 리셋 분기를 누락시키는 전형적 리팩토링 사고 패턴이다. 특히 `ati_error_reboot_cnt` 리셋 조건은 `!st.ati_active`까지 포함한 복합 조건이라, `else { ati_error_reboot_cnt = 0; }`로 단순화하면 ATI burst 진행 중(`ati_active=true`, 에러 없음)에도 카운터가 리셋되어 "5회 초과 시 REBOOT" 임계값의 의미가 바뀐다. `notouch_cnt = 0`(169~172행) 리셋도 동일 범주. **계획의 함수 역할표에 이 3개 리셋 분기를 명시적으로 나열**할 것을 권고한다.

## 발견 2 — [LOW-MEDIUM] `st`/`ok`/`state` "재대입 필수" 문구 불명확

계획 ②는 6종 영속 상태(1회 초기화)와 3종 임시(`st`/`ok`/`state`)를 같은 문장에서 "func_sleep() 최상단에 선언"이라 묶어 서술한다. 영속 상태는 "1회 초기화 후 값 유지"가 맞지만, `st`/`ok`/`state`는 **선언만 최상단으로 옮기고 대입문(`ok = tdc_touch_iqs323_read_status(&st); state = ...`)은 반드시 매 iteration 루프 본문에 남아야** 한다. ⑤의 "상태읽기(인라인 유지)"가 이를 암시하나, ②의 문장 구조상 구현자가 "선언=초기화 위치"로 오독해 대입문까지 루프 밖으로 끌어올리면 두 번째 iteration부터 터치 상태가 영구히 stale해지는 치명적 회귀다. **② 문구에 "대입은 루프 내부 유지, 선언만 이동"임을 명시적으로 분리 기술**할 것을 권고한다.

## 발견 3 — [LOW] "ok 게이트 3곳 보호" 카운트 오류 (실질 버그 없음, 문서 정합성만)

계획 ②는 "ok 게이트가 state/st 소비부 3곳을 전부 보호"라 하나, 실제 소비 지점은 5곳(`log_debug`, `handle_ati_error`, `handle_notouch_gate`, `handle_touch_reboot`, `log_state_transition`)이다. 직접 대조한 결과 5곳 모두 `ok &&`로 정상 게이트되어 있어 **실질적 버그는 없음**을 확인했다. 다만 계획 문서의 자체 검증 카운트가 실제보다 적어, 구현 후 리뷰 시 "3곳만 확인하고 통과" 처리될 위험이 있다. 5곳 전체를 명시적 체크리스트로 갱신 권고.

## 발견 4 — [LOW/정보성] ci_print 매핑표에서 "notouch timeout 10s -> forced RESEED"(현재 printw) 행선지 누락

③은 "최종 printw 2건만 남는다"고 선언하지만, 매핑 서술 어디에도 이 항목의 격하 여부가 없다. 이대로면 printw가 3건(계획의 "2건" 주장과 모순) 남을 수 있다. `ci_printf.h` 확인 결과 `ci_printw`/`ci_printd`는 전부 단순 `SEGGER_RTT_printf` 매크로이고 `CI_PRINT_EABLE_*`는 전부 `1`로 고정, 다른 빌드 설정에서의 override도 없어 **레벨 변경 자체는 로직에 영향 없음**을 확인했다. 순수 문서 누락이므로 동작보존 관점에서는 무해하나, 계획 갱신 시 이 항목의 최종 레벨을 명시할 것.

## 발견 5 — [LOW/정보성] `#if TDC_TOUCH_DEBUG_PRINT_ENABLE` 비활성 빌드에서 파라미터 미사용

`tdc_touch_config.h`는 기본값 1이지만 override 가능한 매크로다. `tdc_touch_sleep_log_debug` 전체를 `#if` 내부로 캡슐화하면 게이트 비활성 시 `ok`/`st`/`state` 파라미터가 미사용이 된다. 현재 `.cproject`에 `-Wall`/`-Wextra`/`-Wunused-parameter`가 설정되어 있지 않아 **오늘 당장 경고가 발생하지는 않음**을 확인했으나, 향후 경고 플래그 강화 시 "경고 0건" 게이트를 깨뜨릴 수 있다. `#else` 분기에 `(void)` 캐스트 추가를 계획에 미리 반영 권고.

## 미검출(정상 확인) 항목

`SYS_WATCHDOG_RESET()` 이후 코드 도달 불가 전제, watchdog refresh 이중 호출(루프 상단 + reboot 분기 내부) 순서, `sleep_ignore` if/else 배타성 유지, gate-open과 동일 iteration 내 touch_reboot 미실행 등은 모두 원본과 동일하게 보존됨을 직접 대조 검증했다 — 문제 없음.
