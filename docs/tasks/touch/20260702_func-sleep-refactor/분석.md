# 분석: func_sleep() 구조 정리

**TL;DR**: 페르소나 5노드([에이전트-로그](에이전트-로그/) 01~05) 분석 결과, `func_sleep()`은 진입부(선형·분기 없음)와 ULP while 루프(중첩 분기·카운터 3종 얽힘)로 뚜렷이 나뉜다. 함수 분리는 ULP 루프에만 적용하고, 변수 최상단 이동·ci_print 재분류·주석 정리는 함수 전체에 적용한다. 상세 원본은 각 노드 파일 참조.

## 1. 변수구조 ([01](에이전트-로그/01_분석_변수구조.md))

- 전체 지역변수 14종: 영속 상태 6종(`sleep_ignore`·`notouch_cnt`·`ignore_elapsed`·`touch_cnt`·`ulp_state_prev`·`ati_error_reboot_cnt`) + 매 iteration 임시 3종(`st`·`ok`·`state`) + `#if` 게이트 전용 4종(`dbg`·`delta`·`abs_thr`·`pabs_thr`) + `ret`.
- 영속 상태 6종은 최상단 이동 시 "루프 진입 전 1회 초기화" 의미가 보존되어 안전. **회귀 위험은 이걸 루프 바디 안으로 착각해 넣는 것**(매 iteration 리셋되면 상태머신 붕괴).
- 임시 3종(`st`/`ok`/`state`)은 **선언만 최상단, 대입문은 루프 내부 유지** 필수 — `ok &&` 게이트가 5곳(21 검증에서 재확인) 모두 stale 값 소비를 막아주므로 안전.
- 게이트 전용 4종은 "게이트를 선언까지 확장"(게이트 안에서 선언)이 권장안 — 비활성 빌드에서 미사용 변수 경고 자체가 발생하지 않음.

## 2. 로직분리 ([02](에이전트-로그/02_분석_로직분리.md))

ULP 루프 바디를 5개 논리블록 → `static`·`tdc_` 접두어 함수로 분해:

| 함수 | 원본 라인(ground truth 기준) | 역할 |
|---|---|---|
| `tdc_touch_sleep_log_debug` | 111~123 | 계측 로그(`#if` 캡슐화) |
| `tdc_touch_sleep_handle_ati_error` | 127~152 | ATI 에러 복구/재부팅 판단 |
| `tdc_touch_sleep_handle_notouch_gate` | 154~181 | sleep_ignore 게이트 유지·해제·강제 RESEED |
| `tdc_touch_sleep_handle_touch_reboot` | 182~206 | 게이트 해제 후 터치 재부팅 판단 |
| `tdc_touch_sleep_log_state_transition` | 208~213 | 상태 천이 로그 |

카운터·게이트는 전부 비-const 포인터로 전달해 `func_sleep()` 소유를 유지(헬퍼 내부 static 은닉 금지). `sleep_ignore` if/else 분기 자체는 `func_sleep()`에 남겨 상태 배타성을 호출부에서 드러낸다.

## 3. ci_print 레벨 ([03](에이전트-로그/03_분석_ci_print레벨.md))

판정 기준: **이 라인 실행 후 `SYS_WATCHDOG_RESET()`으로 칩이 강제 리셋되는가** — 이 축만이 "최대 에러"라는 요구사항에 부합하는 objective한 경계선.

- printw 잔류 2건뿐: "ATI ERROR -> REBOOT", "touch detected -> REBOOT"(현재 printi → 승격).
- 나머지 9건 전부 printd로 흡수(printi 4건, printv 1건 포함).
- 핵심 반전 2건: "ATI ERROR -> RECOVER"(재시도 중, 최종 아님) printw→printd 강등 / "touch detected -> REBOOT" printi→printw 승격.
- 삭제 제안 1건: "FIRST OF ALL..." (바로 다음 줄과 중복).

## 4. 주석정리 ([04](에이전트-로그/04_분석_주석정리.md))

약 30건 전수 판정 — 유지 21 · 삭제 9(죽은 코드 3건 포함) · 축약 2. **최우선 보존 3대장**: 게이트 철학(90-94행), 워치독 refresh 순서(105행), ATI 예외조건(`!ati_active`, 126-127행) — 삭제 시 조건식·설계 의도가 코드만으로 복원 불가능해지는 항목.

## 5. 진입시퀀스 범위 ([05](에이전트-로그/05_분석_진입시퀀스.md))

**함수 분리는 ULP while 루프 바디만.** 진입부(1037~1099)는 이미 분기 없는 선형 나열 구조라 분리 이득이 없고, 오히려 CFX 핸드셰이크 타이밍·워치독 refresh 순서에 새 회귀 위험만 추가한다. 요구사항 문구("while(1) **ULP** 루프")도 이 함수 안의 두 while(1) 중 후자만 지칭. 진입부는 변수 이동·주석·print 정리만 적용.

## 종합 판단

5개 분석 결과는 서로 충돌 없이 일관된 그림을 이룬다 — 함수 경계는 "복잡도가 실제로 있는 곳"(ULP 루프)에만 긋고, 나머지 축(변수·로그·주석)은 함수 전체에 균일 적용. 이 결과를 [계획.md](계획.md)에서 adversarial 검증(21·22) 결과까지 반영해 최종 구현안으로 종합한다.
