# 요구사항: func_sleep() 구조 정리

**TL;DR**: `main.c`의 `func_sleep()`이 절전모드 재부팅 원인 분석([20260701 세션](../../../지침/작업%20규칙.md) 논의)을 거치며 복잡해짐. 동작(로직)은 **100% 동일 유지**한 채, ① 모든 지역변수를 함수 최상단으로 이동 ② `ci_printe` 사용 금지, 최대 에러 상태만 `ci_printw`·나머지는 `ci_printd`로 통일 ③ 주석 정리 ④ while(1) ULP 루프 바디를 이름 있는 정적 함수로 분리해 한눈에 로직 파악 가능하게 한다.

> [!NOTE]
> 은수님 지시(2026-07-02, 대화). 직전 세션에서 절전 재부팅 원인 분석(ATI 에러/터치스턱/I2C hang 3가설, LED 계측 보강안)을 논의한 뒤 이어진 요청. 인터뷰 2문항으로 범위 확정.

## 1. 배경

- `func_sleep()`(`main.c:1033~1219`)은 절전 진입 시퀀스 + ULP(초저전력) 감시 루프를 담당. 최근 ATI 에러 재시도·LED 디버그 계측이 추가되며 while(1) 루프 내부가 복잡해졌다(변수 선언 위치 분산, ci_printi/printw/printv 혼재, 인라인 주석 다수).
- 쌍둥이 함수 `fake_func_sleep()`(무선 테스트용, `main.c:810~1031`)도 거의 동일한 구조지만 **이번 범위에서 제외**(§3).

## 2. 기능 요구사항

### 요구사항_1 — 변수 함수 최상단 배치

- `func_sleep()` 내 모든 지역변수(현재 while 루프 진입 직전 6개: `sleep_ignore`·`notouch_cnt`·`ignore_elapsed`·`touch_cnt`·`ulp_state_prev`·`ati_error_reboot_cnt`, 루프 내부 선언 변수: `st`·`ok`·`state`, `#if TDC_TOUCH_DEBUG_PRINT_ENABLE` 게이트 내부 `dbg`·`delta`·`abs_thr`·`pabs_thr`)를 함수 최상단으로 이동한다.
- 이동 시 매 iteration 재대입/재초기화 안전성을 유지해야 한다(값이 새는 일이 없어야 함).
- 전처리기 게이트(`#if`) 내부에서만 쓰는 변수는, 게이트 비활성 시 미사용 변수 경고가 나지 않도록 처리 방법을 분석에서 판단한다.

### 요구사항_2 — 디버그 메시지 최소화·레벨 통일

- `ci_printe` **사용 금지**(func_sleep() 내 신규·기존 모두).
- **최대 에러 상태**(리부팅이 임박한 시점 등 가장 심각한 케이스)만 `ci_printw`.
- 그 외 **일반적인 메시지는 전부 `ci_printd`**로 통일(현재 혼재된 `ci_printi`·`ci_printv` 포함).
- 메시지 개수 자체도 최소화(중복·과다 로그 정리).

### 요구사항_3 — 주석 정리

- 현재 인라인 주석 중 WHAT(코드가 뭘 하는지 재서술)은 정리하고, WHY(숨은 제약·과거 버그 회피 이유 등 비직관적 근거)만 남긴다.
- 프로젝트 주석 정책([루트 CLAUDE.md](../../../../../CLAUDE.md) 코딩 규칙) 기준.

### 요구사항_4 — 로직 함수 분리

- while(1) ULP 루프 바디를 논리 단위로 나눠 이름 있는 `static` 함수(`tdc_` 접두어)로 추출, `func_sleep()`의 루프 자체는 짧은 호출 시퀀스만 남아 한눈에 흐름 파악이 가능해야 한다.
- 분리된 함수가 필요로 하는 상태(카운터 등)는 `func_sleep()`이 계속 소유하고 **포인터로 전달**한다(요구사항_1과 상충 방지 — 상태가 헬퍼 내부 `static`으로 숨겨지면 안 됨).

## 3. 비목표 (이번 범위 제외)

- **동작(로직) 변경 없음** — 순수 구조 정리. 타이밍·조건·리부팅 트리거 등 기존 동작은 100% 동일해야 한다.
- 직전 세션에서 논의한 **LED 표시 공백**(ATI 재시도 중 LED 없음, 복구 성공 시 LED 미소등 등)은 **이번 범위에서 제외** — 별도 작업으로 분리(은수님 확인, 인터뷰 문항_1).
- `fake_func_sleep()`은 이번 범위에서 제외(은수님 확인, 인터뷰 문항_2). 거의 동일 구조라 향후 동일 패턴 적용 검토 가능.
- I2C 폴링 무한루프(`i2c_write`/`i2c_read` 타임아웃 부재) 등 `func_sleep()` 밖의 구조적 이슈는 별도 과제.

## 5. 제약·근거

- 코드 ground truth = `main.c:1033~1219`(`func_sleep()` 전체, 현재 uncommitted 상태 포함).
- 신규 함수·심볼은 `tdc_` 접두어 필수(루트 CLAUDE.md §7).
- 중괄호는 단일 문이어도 항상 필수.
- 워치독 리프레시(`SYS_WATCHDOG_REFRESH()`)가 루프 매 iteration 최상단에서 무조건 호출되는 현재 순서는 반드시 보존해야 한다(하드웨어 워치독 ~3.28s 타임아웃 대비, 이전 세션 조사 확인 사항).
