# 분석 — SW 운영만으로 하이젠베르크 회피

**TL;DR**: 현 셀프캡·현 HW·기존기능을 유지한 채 SW 운영만으로 절전 프로파일링 클럭/SPI 결합 교란을 회피할 수 있는가 — **답은 "가능"**(회귀안전 레버 다수). 다만 실패의 **실제 재현 경로가 `fake_func_sleep()`**(별도 복제 코드)이고, **지배 애그레서가 미확정**이라 RTT/스코프 실측 게이트가 선결이다. 가장 유력한 저위험 조합은 ①관측 자체의 애그레서 제거(H2 read_debug 수정) ②GPIO 드라이브 하향(S5) ③IQS323 자가 RDY 토글 제거(S8/R7). 상세 매트릭스: [`에이전트-로그/99_종합.md`](에이전트-로그/99_종합.md).

> [!NOTE]
> 워크플로우 18에이전트(특성화 2·레버 8·검증 8). 근거: [`에이전트-로그/`](에이전트-로그/) 01~18. 사실/가설 구분 표기. 선행 [상호용량 검토](../20260703_touch-mutual-cap-review/)는 조건부 No-Go로 종결됨.

## 1. 문제의 정확한 형태 (C1·C2 특성화)

### 1.1 두 재부팅 트리거와 구조적 취약성

- 절전 ULP에 **독립 2트리거**: ① `ati_error && !ati_active` **7연속(~700ms)** → 재부팅, ② 게이트 해제 후 touch bit **24연속(2400ms)** → 재부팅. (`tdc_touch_time.h` 주석의 200ms는 WAKE_MS 100 전환 후 갱신 안 된 낡은 값 — 재계산으로 정정.)
- Normal 모드 FSM은 ati_error 재부팅 카운터가 **아예 없고**(2000ms 쿨다운 무한재시도), TOUCH 스턱은 30/60/90초 사다리. → **같은 크기의 방해도 절전 프로파일링에선 700ms~90초 구간에서 이미 재부팅**되는 비대칭이 코드로 확인됨.
- touch 판정(delta vs 80×LTA/256)과 ATI 판정(Counts vs ATI 밴드)이 **동일 원시 필터 체인 공유** → 하나의 코히런트 방해가 양쪽을 동시 유발 가능. LTA Fast Filter가 방향 비대칭(sensing 반대방향에만)이라 터치-모사 방향 방해는 느린 Beta만 적용돼 오래 흡수 안 됨(+ LTA freeze 자기강화).

### 1.2 ★ 실제 재현 경로 = `fake_func_sleep()`

- C2가 발견: `fake_func_sleep()`(main.c:810~1031)은 BLE 'General Debug' op_mode==1로 진입, `ci_fake_power_sleep()`으로 **SYSCLK 30.72MHz 유지**, 루프서 `bleCommunication()` 상시 서비스, **QCC 셧다운 주석처리**. → 은수님 프로파일링 시나리오(QCC 안 재우고 SPI 위해 30.72MHz 유지)와 **코드 사실 일치**.
- 이 함수는 `func_sleep()`과 **분기된 인라인 복제**이며, 롱터치→재부팅의 실제 `SYS_WATCHDOG_RESET()` 호출이 **주석처리(no-op)**. → **L1(iqs323) 레벨 레버는 자동 적용되나, `func_sleep()`/logic만 고치는 레버는 이 경로에 반영 안 됨.** (은수님 확인 필요 항목.)

### 1.3 두 "자체 애그레서" 후보 (관측이 대상을 흔듦)

- **H2(유력)**: 계측 `read_debug()`가 미해결 latch 버그(문서 39/40)를 보유 — read_status 직후 별도 `force_window_open+0xFF` 발행이 RDY High에서 45ms 타임아웃 반복. `DEBUG_PRINT_ENABLE=1` 기본이라 ULP마다 실행, **CRX0 인접에 추가 0xFF 주입** = 문자 그대로의 하이젠베르크.
- **H1(점검)**: 절전 I2C 프리스케일 ÷6이 30.72MHz 유지 중 재사용 시 SCL≈5.12MHz(상한 5배) → 조용한 비트오류. (S6 검증서 fake 경로엔 반박 — 실측 확정 대상.)

## 2. 해법 레버 8 — 검증 판정

99 종합 §2 매트릭스 참조. 요지:

- **채택 유력(회귀안전·근거 강)**: **S5 GPIO 드라이브 하향**(중~강, 물리 확립), **S8/R7 0xC0 bit7**(IQS323 자가 RDY 토글 제거, 상시 배경교란 제거).
- **조건부 채택**: **S1 변환주파수**(약~중, 389kHz 회피), **S2 필터·Beta·ATI밴드**(중, 전제 [가설-강] 정정·실측 3게이트).
- **H2 완화로 수렴**: **S4**는 'SPI-조건부' 차별성이 반박돼 기각되나, 그 대안인 **무조건 스로틀/비활성 = H2(read_debug) 완화**로 수렴 → 이게 오히려 가장 직접적.
- **안전망(근본해결 아님)**: **S6 FSM 라이드스루** — F0-게이팅으로 프로파일링 구간 재부팅 억제. 단 **S6-4는 카운터 기반 필수**(CFX standby 중 시간원 정지 → Re-ATI 영구중단 회귀).
- **주로 기각**: **S3**(Report Rate만 조건부, Events모드 I2C Lock-Up 에라타), **S7**(후보_3 BLE 레이트리밋만 조건부, 후보_1은 FSM 100× 둔화 회귀로 기각).

## 3. 기존기능 무손상 (제약_2 검증)

- S1·S2·S5·S8은 C2 불변식(INV-①~⑧·INV-X) 위반 **0건**.
- 위반/주의: S6-4(시간원 정지 회귀), S7 후보_1(100× 둔화), S3 Events모드(에라타). → 권고 포트폴리오에서 배제/재설계.
- 공통 규칙: 새 0xC0 write는 `0x50|trigger, 0x07`(INV-X-1) 유지 — 위반 시 Power Mode·CH timeout 비트 되돌아가 즉시 회귀.

## 4. 종합 판정

**SW-only 회피는 가능**하다(mutual No-go와 대조). 회귀안전·SW-only·데이터시트 실현성이 확립된 레버(S5·S8/R7·S1·S2)가 존재하고, 특히 **"관측 자체가 애그레서"인 H2를 제거**하면 근본 원인의 상당 부분이 SW만으로 사라질 가능성이 있다.

**단, 정직한 게이트 2개**:
1. **지배 애그레서 미확정** — 레버 효과 대부분 [가설-강/실측게이트]. RTT/스코프로 확인해야 "확정".
2. **재현 경로 = `fake_func_sleep()`** 가정 — 은수님 확인 필요. 맞다면 이 복제 경로도 대상에 포함해야 함.
