# 요구사항 — SW 운영만으로 하이젠베르크(클럭/스위칭 결합) 회피

**TL;DR**: 현재 셀프캡 터치는 Full ATI + 노말/절전 최초 터치해제 + ATI 에러 시 Re-ATI로 드리프트를 해결한 상태다. 그러나 절전에서 QCC를 깨우고 e8300 클럭을 30.72MHz로 유지한 채 BLE·SPI로 터치 상태를 프로파일링하면 ATI 에러·터치 오인식(→노말 재부팅)이 발생한다("하이젠베르크"=관측/클럭 스위칭이 sub-pF 측정을 교란). **HW 수정 없이, 현 아키텍처·기존 기능을 전부 유지한 채, SW 운영만으로 이 교란을 회피할 방법**을 다분야 전문가로 깊게 탐색한다. mutual 방식은 [선행 검토](../20260703_touch-mutual-cap-review/계획.md)에서 조건부 No-Go로 종결됨 — 본 작업은 그 외 방향을 찾는다.

> [!NOTE]
> 은수님 지시(2026-07-03) 재정의. 선행 상호용량 검토([`20260703_touch-mutual-cap-review`](../20260703_touch-mutual-cap-review/))의 후속. 관측교란 개념은 [`docs/참고/touch/터치 계측 관측 교란/터치 계측 관측 교란.md`](../../../참고/touch/터치%20계측%20관측%20교란/터치%20계측%20관측%20교란.md).

## 1. 배경 (문제 경위)

1. **드리프트 해결(현재 상태)**: 과거 Fixed value + 주기적 CRX0 방전으로 드리프트/스턱을 회피했다가, 지금은 **Full ATI + 노말/절전 최초 터치 해제 감지 + ATI 에러 시 Re-ATI**로 드리프트를 해결한 상태.
2. **정상 절전은 잘 됨**: 절전에서 e8300 메인클럭 2.56MHz로 낮추고 QCC 등 IC를 최대한 off 하면, 노말 모드에서 설정한 threshold/hysteresis 계수로도 잘 동작했다(운이 좋았을 수 있음 — 강건성 미보장).
3. **프로파일링에서 실패(문제)**: QCC를 슬립 안 시키고 SPI 위해 e8300 메인클럭을 30.72MHz로 유지한 채, BLE·SPI로 **절전 상태 터치 정보를 프로파일링**하려 하면 → **ATI 에러 반복 / 터치된 상태로 오인식되어 노말 재부팅**.
4. **원인 가설**: 클럭이 센싱에 영향 + SPI 클럭 dV/dt 전하주입 = 하이젠베르크(관측이 대상을 흔듦). 근거: 관측교란.md 3메커니즘(결합임피던스·샘플링윈도우 일치·에일리어싱)·2경로.

## 2. 목표

- **주 목표**: 현 셀프캡·현 HW·현 아키텍처를 유지한 채, **SW 운영만으로** 절전 프로파일링 구성(QCC on + SPI + 30.72MHz)에서의 클럭/SPI 결합 교란을 **회피/저감**한다.
- **파급**: 절전에서 회피되면 노말 모드에서도 동일하게 강건해진다(은수님 논리) — 즉 "운"이 아닌 "설계된 강건성" 확보.
- **해법 범위(은수님 승인)**: **둘 다 탐색** — ① 센싱을 노이즈에 면역시키는 방향, ② 관측(프로파일링) 방식을 덜 침습적으로 바꾸는 방향. 가장 강건한 조합을 권고.

## 3. 제약 (엄수)

- **제약_1 (HW 무수정)**: 현재 HW를 수정할 수 없다. PCB·소자·배선 변경 불가. **SW/설정(e8300 펌웨어 + IQS323 레지스터)만** 사용.
- **제약_2 (기존 기능 전부 만족)**: 새 방법은 아래 현 기능을 **하나도 훼손하면 안 된다**.
  - 드리프트/스턱 회피(Full ATI 기반)
  - 노말/절전 **최초 터치 해제 감지**
  - **ATI 에러 시 Re-ATI**
  - 정상 터치 판정(CH0 Touch) · **롱터치** 감지
  - 절전 진입/기상 시퀀스 · 노말·절전 공통 폴링 경로
  - 현 단일채널 구성(CalCap 더미 폐기된 FullATI 단순안)
- **제약_3 (mutual 제외)**: 상호용량 전환은 선행 검토에서 종결(조건부 No-Go). 본 작업 범위 밖.
- **제약_4 (근거·검증)**: IQS323 데이터시트·앱노트·현 코드 근거 기반. 핵심 후보는 adversarial-verify로 (a)실제 저감 (b)기존 기능 무손상 (c)진짜 SW-only (d)데이터시트 실현성을 검증 후 확정. 할루시네이션 금지.
