# 16 · V6 — S6(FSM 판정 강건화) 검증

**TL;DR**: 08_S6의 핵심 사실 주장(라인번호·상수 계산·커밋 diff·0xC0 재사용)을 소스코드·`git show`로 전수 재확인한 결과 **전부 정확**했다. 검증 중 자체 발견 2건 — (유리) `fake_func_sleep()`은 실제로 `I2C_MASTER_PRESCALE_240`(30.72MHz÷240=128kHz)을 쓰고 있어 C1의 H1(SCL 5.12MHz 위반) 가설이 **이 확정 경로에 한해 반박**됨(체계적 오염 가능성 축소, S6 전제에 유리). ### 2.3 신규 발견 — S6-4 "동일 패턴 이식"의 잠재적 회귀 (본 검증 최우선 기여)

08_S6 §4 S6-4는 "Normal FSM의 `re_ati_cooldown_until_ms`와 **동일 패턴**"을 `func_sleep()`에 이식한다고 서술한다. Normal의 이 패턴을 추적하면:

- `tdc_touch_logic.c:156~160`: `in->now_ms >= st->re_ati_cooldown_until_ms` 비교 — `now_ms`는 **절대 ms 타임스탬프**(연결층이 주입, `tdc_touch_logic.h:45` 주석 "연결층이 ci_timer 에서 주입").
- `tdc_touch.c:295,306`: 이 주입원은 `ci_timer_get_tick()`.
- `ci_timer.c:143~146`: `ci_timer_get_tick()`은 `g_ci_timer_main_tick`을 반환하고, 이 값은 `ci_timer_increase_tick()`(`ci_timer.c:130`)이 증가시킨다.
- `driver_timmer.c:10~22`: `ci_timer_increase_tick()`은 **`CFX_0_IRQHandler`/`FIFO_5_IRQHandler`에서만** 호출된다 — 즉 이 "ms 시계"는 **CFX(오디오 코프로세서)가 보내는 주기적 인터럽트 전담**이다(파일 주석: "Ezairo7150의 CM3에는 타이머가 들어있지 않다. CFX에서... 인터럽트를 수신하여 타이머처럼 동작").
- `func_sleep()`(main.c:1195~1213) 진입 시퀀스는 `enter_ULP_mode_Command_CM3_to_CFX=1`을 세팅해 CFX를 ULP로 보내고, CFX측(`1__cfx/systemControl/main.c:298~314`)은 `app_configure_interrupts(CFX_INT_STANDBY)` 호출 후 `enter_ULP_mode_Command` 플래그를 클리어하고 `g_interrupt_flags.wake_up` 대기 전용 `while(1)` 루프로 들어간다.

**결론(가설-강, 코드 정황 강력, 실측 미확인)**: CFX가 standby로 전환되면 CM3의 `ci_timer_get_tick()`(=Normal FSM의 `now_ms` 원천)이 **더 이상 갱신되지 않을 개연성이 높다**. 이 클럭을 그대로 재사용해 `func_sleep()`에 "동일 패턴"(절대 ms 비교) 쿨다운을 이식하면, 최초 쿨다운 설정 이후 `now_ms`가 더 이상 증가하지 않아 `now_ms >= cooldown_until_ms` 비교가 **영원히 거짓으로 고정**될 위험이 있다 — 이는 "재시도 억제"가 아니라 **"이후 세션 내내 Re-ATI가 단 한 번만 발행되고 영구 중단"**이라는, 데이터시트가 명시한 "ati_error는 IC가 자동 재시도하지 않는다"(01_C1 §2.1 인용)는 사실과 정면으로 충돌하는 **더 심각한 신규 회귀**다. 08_S6은 이 시간원 문제를 검토하지 않았다.

**안전한 대안**: `func_sleep()`의 ULP 루프는 이미 자체 100.0ms HW 타이머(INV-⑥-3, `TDC_TOUCH_ULP_TIMER_PRESCALE/TIMEOUT_VALUE`, CFX와 무관하게 CM3 로컬)로 정확히 구동되므로, 쿨다운을 "절대 ms 비교"가 아니라 **`ati_error_reboot_cnt`류와 동일한 폴링-반복횟수 카운터**(예: `re_ati_skip_cnt`, 임계 도달 전까지 재발행 skip)로 재구현하면 시간원 문제가 원천적으로 사라진다. 이는 이미 검증된 패턴(S6-1/2/3의 카운터 방식)과 동일 계열이라 추가 위험이 없다.

> [!WARNING]
> 이 발견은 **[가설-강]**이다 — `CFX_INT_STANDBY`가 정확히 어떤 인터럽트를 억제하는지 비트 단위로 추적하지 않았고, `wake_up` 대기 루프 진입 후에도 일부 저전력 틱 소스가 살아있을 가능성을 완전히 배제하지 못했다. **S6-4를 ms-타임스탬프 방식 그대로 채택하기 전 반드시 실측(CFX standby 중 `g_ci_timer_main_tick` 정지 여부 RTT 로그로 확인)이 선행돼야 한다.** 카운터 기반 재설계로 바꾸면 이 실측 게이트 자체가 불필요해진다(권장).

## 6. 실측 게이트

1. **[최우선, 08_S6과 공유]** 아그레서 duty(확률적 vs 체계적) — C1 H1은 fake_func_sleep() 경로에 한해 반박됐으나(§1) H2·SPI/BLE 코히런트 등 타 체계적 후보는 미해소.
2. **[신규, 본 검증 발견]** `func_sleep()` ULP 중 `g_ci_timer_main_tick`(`ci_timer_get_tick()`) 갱신 여부 RTT 실측 — S6-4를 ms-타임스탬프 방식으로 구현하려면 필수 선행, 카운터 방식 채택 시 불필요.
3. S6-1/2/3의 F0 전용 임계값(N_a·N_t·K/J) 구체 수치 — 08_S6과 동일 미확인.
4. S6-2 발동 전제 — `fake_func_sleep()`의 touch-reboot `SYS_WATCHDOG_RESET()` 원복 여부 은수님 확인.
5. S6-4 쿨다운 값 산정 — Re-ATI 1회 소요시간 실측(기존 미해결 게이트와 공유).

## 핵심 결론 (3~5줄)

1. 08_S6의 코드 사실 주장(라인번호·상수 계산·커밋 diff·함수 분리 구조)은 본 검증의 독립 재확인에서 **전부 정확**했다 — 반박 실패.
2. 본 검증의 신규 발견 2건 중 하나는 S6에 **유리**하다: `fake_func_sleep()`이 실제로는 `I2C_MASTER_PRESCALE_240`(128kHz, 안전)를 쓰고 있어 C1의 H1(SCL 5.12MHz 위반) 가설이 이 확정 경로에서 반박되고, 체계적 오염 가능성이 다소 줄어든다.
3. 나머지 하나는 S6-4에 **불리**하다: "Normal과 동일 패턴 이식"이 의존하는 `ci_timer_get_tick()`은 CFX FIFO 인터럽트 전담이고 CFX는 `func_sleep()` 중 standby로 전환되므로, 문자 그대로 이식하면 쿨다운이 영구 고정돼 Re-ATI가 세션 내내 단 한 번만 발행되고 멈추는 **잠재적 신규 회귀**(INV-①의 근본 취지 위반) 위험이 있다 — 카운터 기반 재설계를 조건으로만 채택 권고.
4. S6-1/S6-2/S6-3은 (b)(c) 기준을 그대로 통과하나, S6-2는 대상 트리거가 **현재 코드에서 이미 주석 처리(죽은 코드)**라 구현해도 즉시 효과가 없고, S6-3은 08_S6 스스로도 근거가 약하다고 인정한 대로 실측 전 채택 비권고가 타당하다.
5. **종합: refuted=false, 조건부** — S6 lever family는 구조적으로 타당하고 회귀 위험이 낮은 편이나, "S6-4가 가장 안전하다"는 원 문서의 평가는 시간원 검증 없이는 성립하지 않는다는 점이 이번 검증의 핵심 수정 사항이다.
