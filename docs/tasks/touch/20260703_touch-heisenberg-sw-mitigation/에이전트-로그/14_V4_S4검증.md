# 14 · V4 — S4(e8300 타이밍 협조) 검증

**TL;DR**: S4-1(`fake_func_sleep()` 한정, `get_spi_commu_state()` 스냅샷으로 SPI 활동 시 `read_debug()` 스킵)을 `main.c`·`driver_SPI.c`·`ble_communication.c` 원문과 전수 재대조했다. 구현 사실관계는 대부분 정확하고 C2 8대 불변식은 위반 0건으로 재확인됐으나, 이 후보의 정체성인 "SPI-인지형" 설계 자체가 무조건 스로틀보다 낫다는 근거는 메커니즘_1·2 어느 쪽으로도 재구성하지 못했다. **refuted=true**(구현은 안전, 차별화 근거는 반박됨).

---

## 0. 검증 방법

지시받은 3개 노드(06 S4·01 C1·02 C2) 정독 후, S4-1이 인용한 코드를 신뢰하지 않고 **1차 소스에서 직접 재확인**했다. 확인 파일: `main.c`(`fake_func_sleep()` 전체 810~1031행), `driver_SPI.h`(전체 69행), `driver_SPI.c`(1~260행, ISR·get/set 구현), `ble_communication.c`(220~420행, `bleCommunication()` 스위치문), `tdc_touch_config.h`(전체), `tdc_touch.c`(디버그 getter/setter 51~116행), `tdc_remote_general_debug.c`(77~83행, 소비처).

## (a) 실제 저감 근거 — 반박 시도

### 사실관계 재확인

| S4 노드 주장 | 재확인 결과 |
|---|---|
| `get_spi_commu_state()`는 순수 getter(부작용 없음) | **확인** — `driver_SPI.c:208~211` `return spi_CommuState;` 단일 문 |
| `bleCommunication()`이 FETCH/ERROR 처리 후 `set_spi_commu_state_IDLE()` 호출(인용: 275/365/399행) | **부분 오류** — 275행은 `ble_communication.c:252~276`의 `#if 0` **사장 코드**. 실제 컴파일 경로는 **365행(FETCH)·399행(ERROR)** 뿐. 결론(매 tick 소비 후 IDLE 리셋)은 유효하나 인용 라인 하나가 부정확 |
| `bleCommunication()`은 매 100ms tick 무조건 호출 | **확인** — `main.c:899`, SPI 상태와 무관하게 매번 실행 |
| `driver_SPI.h`가 `main.c`에 이미 include돼 신규 include 불요 | **확인** — `main.c:9` |

### 핵심 반박 — "SPI-인지형"이 무조건 스로틀보다 나은가

S4-1의 정체성은 "SPI 상태를 참고해 **조건부로** 계측을 억제"하는 것이다. 두 후보 메커니즘 중 어느 쪽으로도 이 조건부성 자체가 부가가치를 준다는 근거를 재구성하지 못했다.

- **메커니즘_1(결합임피던스/총 전하) 관점**: 문제는 애그레서의 **총 스위칭 횟수·에너지**이지 SPI와의 시간적 상관이 아니다. `read_debug()` 호출 횟수를 줄이면(C1 §3.2 H2가 참이라는 전제 하) 총량은 줄지만, 이는 **SPI 상태와 무관하게 매 N회 중 1회씩 무조건 스킵**해도 동일하게 달성된다 — "SPI가 바빴을 때만" 스킵할 근거가 이 메커니즘엔 없다.
- **메커니즘_2(샘플링 윈도우 일치) 관점**: 이 메커니즘이 성립하려면 `read_debug()`의 I2C 스위칭과 실제 nRF SPI 엣지가 **실시간으로** 겹치지 않아야 한다. 그러나 `spi_before`는 **과거(직전 최대 100ms) 활동의 스냅샷**이다 — 대상 노드(06) §0가 이미 확인했듯 e8300은 **다음 SPI 트랜잭션이 언제 시작되는지 알 방법이 없다**("그 GPIO 이후 실제 SPI 개시까지 걸리는 시간: 미확인"). `spi_before`가 IDLE이어도 바로 다음 순간 새 SPI 엣지가 시작될 수 있고, non-IDLE이어도 `read_debug()` 실행 순간엔 SPI가 조용할 수 있다 — **과거 시제 정보로 실시간 중첩 문제를 풀려는 구조**라 메커니즘_2를 좁히는 근거가 되지 못한다.
- **자기모순적 이분법**: 프로파일링 세션 자체가 "BLE·SPI로 상태를 계속 내보내는" 구성이다. (i) SPI가 거의 항상 바쁘면 → `spi_before`는 거의 항상 non-IDLE → `read_debug()`는 사실상 **상시 억제**(무조건 끄기와 결과가 같아짐, 더 복잡한 경로로 도달할 뿐)되어 정작 프로파일링이 보려는 순간에 정보가 사라진다(06번 노드도 "역설"로 인지). (ii) SPI가 간헐적이면 → 상관관계가 확정되지 않아 축소 효과가 통계적으로 불확실하다. **어느 쪽이든 "SPI 상태를 본다"는 설계가 "그냥 이따금 끈다"는 설계보다 낫다는 근거가 없다.**
- **원 초점과의 관계**: 06번 노드 §5가 이미 "원 초점(SPI를 윈도우 밖에 스케줄) 불충족"을 인정했다. 본 검증은 그 **재정의된 버전마저 "e8300 타이밍 협조"라는 S4 고유의 차별점을 살리지 못함**을 추가 확인한 것 — S4-1이 실제로 하는 일은 "계측 호출 빈도를 이따금 낮춘다"이며, S4(타이밍 협조)보다 S7(관측 방식 재설계)의 축소판에 더 가깝다.

**바닥선 효과**: C1 §3.2의 H2(계측 자체가 애그레서)가 실재한다면, `read_debug()` 호출 빈도를 **어떤 방식으로든** 줄이는 것 자체는 0이 아닌 완화 효과가 있다(조건부·무조건 구분 없이 동일). 이 바닥선은 인정하나, 이는 S4-1의 **차별화된 기여가 아니라 우연히 딸려오는 효과**다.

## (b) C2 8대 불변식 무손상 — 재확인

`main.c` 810~1031행 전체를 직접 추적, S4 노드의 매트릭스를 신뢰하지 않고 **원 코드로 재확인**했다.

| C2 불변식 | 재확인 | 근거 |
|---|---|---|
| ① Full ATI 드리프트/스턱 회피 | 무손상 | `read_debug()`는 경로_1~4 어디에도 입력 안 됨. `ati_error_reboot_cnt` 로직(947~972행)은 `read_status()`의 `st.ati_error/ati_active`만 참조 |
| ② 최초 터치해제 감지 | 무손상 | `sleep_ignore`/`notouch_cnt`(974~1001행)는 909행 `state`(read_status 결과)만 참조 — `read_debug()` 스킵 여부와 무관 |
| ③ ATI 에러 시 Re-ATI | 무손상 | ①과 동일 근거 |
| ④ 터치 판정 | 무손상 | INV-X-3 재확인 — `dbg` 결과는 `tdc_touch_debug_set_recent_*`로만 흘러가고(934~940행) 판정 변수엔 대입 안 됨 |
| ⑤ 롱터치 | 무손상 | `touch_cnt`(1002~1018행)도 `state` 단일 의존 |
| ⑥ 절전 진입/기상 | 무손상 | 변경 범위는 917행 한 지점뿐, 진입 시퀀스(810~888행)·`SYS_WATCHDOG_RESET` 미접촉. `func_sleep()`(진짜 절전, 1164행~)의 별도 헬퍼 `tdc_touch_sleep_log_debug()`(1037행~)는 미적용 범위임을 재확인 |
| ⑦ 공통 폴링(L1) | 무손상 | `tdc_touch_iqs323_read_status()`(L1) 호출부(909행) 불변. `read_debug()`는 L1과 별도 함수라 이 게이트는 L1 프로토콜 계층에 닿지 않음 |
| ⑧ 단일채널 | 무손상 | 무관 |

**규정된 8개 불변식 위반 0건 — 독립 재확인 결과 S4 노드 판정과 일치.**

### 8개 목록 밖 부수효과 (규정 위반은 아니나 고지 필요)

- **BLE 원격 디버그 텔레메트리 신선도 저하**: `tdc_touch_debug_set_recent_*`(934~940행)는 `tdc_remote_general_debug.c:77~83`이 소비하는 "최근값" 저장소다. `spi_before != IDLE`인 주기엔 이 저장소가 갱신되지 않고 이전 값을 유지한다 — 프로파일링이 이 값을 BLE로 조회하는 용도라면, SPI가 바쁠 때(=프로파일링이 활발할 때) 정확히 조회 대상 데이터가 굳는 역설이 생긴다(06번 노드도 "트레이드오프"로 인지). C2의 8대 목록엔 없는 항목(진단 인프라)이라 `regressionSafe` 판정엔 영향 없음.
- **미사용 변수 경고 가능성**: `spi_before` 스냅샷은 `bleCommunication()` 호출 앞(899행 앞, `#if` 가드 밖)에 있어야 하는데, 사용처(917행)는 `#if (TDC_TOUCH_DEBUG_PRINT_ENABLE)` 블록 안(912~943행)에 있다. 이 값이 0으로 빌드되면 `spi_before`는 선언만 되고 미사용 — 경고(엄격 모드면 빌드 실패) 소지. 구현 시 스냅샷 줄도 같은 `#if`로 가드하거나 `(void)` 캐스트 필요.
- **비휘발성 공유 변수(기존 이슈, 신규 아님)**: `spi_CommuState`(`driver_SPI.c:50`)는 `volatile` 없이 ISR·메인루프 양쪽에서 접근된다. S4-1은 이 변수를 한 번 더 읽는 새 호출 지점을 추가하지만, 기존에도 동일 변수를 동일 방식으로 읽던 코드(`ble_communication.c:238`)가 있어 S4-1이 새로 만든 위험은 아니다. 다만 스냅샷과 `bleCommunication()` 내부 재조회 사이에 ISR이 끼면 값이 미세하게 어긋날 수 있음 — `read_debug()`가 FSM 비입력이라 판정 안전성엔 영향 없고, 게이팅 판단이 가끔 한 박자 어긋나는 수준의 잔여 리스크.

## (c) 진짜 SW-only·HW 무수정인가

**확인**: 제안된 변경은 (1) `main.c`에 로컬 변수 1개, (2) 기존 export 함수 `get_spi_commu_state()` 1회 추가 호출, (3) 기존 `if` 조건 1개뿐이다. IQS323 레지스터 write 없음, PCB·소자·배선 변경 없음, 신규 ISR·전역변수·타이머 없음(공개 getter만 재사용) — S4 노드 주장과 정확히 일치, 코드로 재확인됨. **(c) 완전 충족.**

## 실측 게이트

1. **[신규, 최우선]** S4-1(SPI-조건부 스킵) vs **단순 무조건 스로틀**(예: 매 2회 중 1회 스킵, SPI 무관)을 **동일 조건 A/B 비교** — ATI 에러·오탐 발생률 차이가 없다면 S4-1의 조건부 설계는 근거를 잃는다.
2. C1 §3.2의 H2 가설(`read_debug()` 자체가 39/40 미해결 latch 버그로 애그레서가 됨) 자체를 먼저 실측 확인 — 이것이 거짓이면 S4-1과 그 대안 모두의 전제가 사라진다.
3. nRF SPI 트랜잭션의 실제 시간 패턴(연속적인지 버스트성인지, BLE 연결 간격) — `spi_before`가 "과거 100ms"를 얼마나 잘 대표하는 신호인지는 이 패턴에 좌우되며 현재 미확인.
4. `TDC_TOUCH_DEBUG_PRINT_ENABLE=0` 빌드에서 `spi_before` 미사용 경고 실제 발생 여부 — 구현 시 즉시 확인 가능한 사소한 항목.

## 핵심 결론 (3~5줄)

1. S4-1의 구현 사실관계(API·라인번호·SPI 슬레이브 구조)는 소스코드 직접 재대조로 대부분 정확함을 확인했다 — 유일한 흠은 죽은 코드(`ble_communication.c:275`, `#if 0`)를 살아있는 근거로 인용한 사소한 부정확성이며 결론엔 영향 없다.
2. C2의 8대 불변식은 **전부 무손상으로 독립 재확인**됐다(위반 0건) — `read_debug()`가 FSM 비입력(INV-X-3)이라는 기존 판정이 이 게이팅에도 그대로 유지된다.
3. 그러나 이 후보의 정체성인 "SPI 상태를 참조하는 조건부 억제"가 **무조건(SPI 무관) 스로틀보다 낫다는 근거는 반박됐다** — 메커니즘_1 관점에선 조건부성 자체가 불필요(총량만 중요), 메커니즘_2 관점에선 과거 스냅샷이 미래의 실시간 중첩을 보장 못해(§0의 "SPI 개시 시각 미확인"과 직결) 어느 쪽으로도 차별화된 이득을 재구성하지 못했다.
4. 프로파일링 세션 특유의 "SPI가 거의 항상 바쁨" 상황에서는 이 게이팅이 사실상 상시 억제로 수렴해 정작 관측하려는 순간에 텔레메트리가 굳는 역설(06번 노드도 인지)이 발생한다 — 규정된 8대 기능은 아니지만 실질적 부수효과로 고지 필요.
5. **refuted=true** — 구현은 안전하나(회귀 0건, SW-only 완전 충족) S4가 표방하는 "타이밍 협조"의 차별화된 가치를 입증하지 못했다. 채택하려면 최소한 무조건 스로틀 대안과의 A/B 비교, 그리고 전제인 C1 H2 자체의 실측 확인이 선행돼야 한다.
