# 06 · S4 — e8300 타이밍 협조 (SW-only 후보 생성)

**TL;DR**: 코드 확인 결과 CM3(e8300)는 SPI에서 **슬레이브**(nRF가 마스터)라 SPI 트랜잭션 개시 시각 자체는 스케줄 불가 — 원 초점("SPI를 윈도우 밖에 스케줄")의 핵심 전제가 아키텍처적으로 성립하지 않는다. e8300이 실제로 스케줄 권한을 가진 것은 (a) 자신이 마스터인 IQS323 I2C, (b) SPI "데이터 준비" GPIO 어서션 시각, (c) 계측(read_debug) 호출 여부뿐이다. 이 범위 안에서 `fake_func_sleep()`(실제 프로파일링 경로로 추정, C2 §11) 전용으로 SPI 활동 감지 후 계측 read를 조건부 억제하는 **S4-1**이 가장 근거 있고 안전하다. RDY 인터럽트화(S4-5)는 플랫폼상 이론적으로는 가능하나(2슬롯 DIO 인터럽트 확인) 자원 경합 + 더 큰 재설계 스코프라 보류를 권고한다.

## 0. 선행 재확인 — 원 초점의 핵심 전제 검증 [확립: 코드]

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| CM3가 SPI 마스터/슬레이브 | **슬레이브** — nRF가 CLK·CS 구동 | `driver_SPI.h:17` `SPI_SELECT_SLAVE`, `driver_SPI.c:256` |
| CM3가 SPI 트랜잭션 개시 시점을 아는가 | **아니오** — `SPI_CS_RISE_INT_ENABLE`(완료 후 통지)만 존재, 개시 예고 인터럽트 없음 | `driver_SPI.h:17`, `driver_SPI.c:52~124` |
| 플랫폼이 GPIO 엣지 인터럽트를 지원하는가 | **지원함**(정정 — 최초 가설은 틀림) — `Sys_DIO_IntConfig` 2슬롯(`DIO_0_IRQn`/`DIO_1_IRQn`) 존재 | `ci_dio.c:120~167` |
| 그 2슬롯이 비어있는가 | **아니오** — acc-sensor(DIO_34)·케이스덮개(DIO_28)에 배정(현재 `#if 0`로 비활성, 삭제는 아님) | `ci_dio.c:104~125` |
| RDY(DIO16)가 인터럽트로 배선돼 있는가 | **미배선** — 현재 GPIO busy-wait 폴링만 | `tdc_touch_iqs323.c:128~175` |
| TIMER3(`t3_tick`)와 절전 ULP 타이머가 같은 물리 타이머인가 | **동일**(중요 발견) — `ci_timer_init_prescaled()`가 `OTE_1_5_GEN_TIMER_INSTANCE=TIMER3`를 재구성 | `ci_timer.h:18~19`, `ci_timer.c:153~166` |

> [!IMPORTANT]
> 이 표가 S4 전체 스코프를 바꾼다. "SPI를 윈도우 밖에 스케줄"은 e8300이 SPI 스케줄 주체라는 걸 전제하는데, **SPI 버스의 실제 스위칭 엣지(nRF 클럭)는 e8300 권한 밖**이다. 또한 `func_sleep()`/`fake_func_sleep()` 진입 시 `ci_timer_init_prescaled(PRESCALE_1, 3999)`가 **TIMER3 자체를 100ms 주기로 재구성**하므로, 두 모드 진입 후 `tdc_timer_get_t3_tick()`은 1ms가 아니라 **100ms 해상도**로만 증가한다(SLOWCLK이 정상/`ci_fake_power_sleep`/`ci_power_sleep` 3모드 전부 1.28MHz로 유지되도록 프리스케일이 보정돼 있어 100.0ms 자체는 세 모드 공통으로 정확하다 — `ci_power.c:154,169,183` 확인. 단, 그 결과 t3_tick의 **분해능**이 100ms로 떨어진다는 사실이 중요). 이는 ms 단위의 정밀 SPI-쿨다운 타이머를 새로 만들려는 후보(초기 구상)가 **새 타이머 인프라 없이는 성립하지 않음**을 의미한다 — §3 S4-1을 100ms 단위 설계로 수정한 이유다.

## 1. RDY 윈도우와 "변환 윈도우"의 관계 [확립: RDY 윈도우 타이밍 분석/3_종합결론.md]

RDY **Low**(통신 윈도우 열림) = 측정이 **이미 끝난 후** 호스트 read 대기 구간(t_Low≈0.4~0.5ms). RDY **High**는 대부분 **다음 측정(변환)이 진행 중**인 구간으로 추정(T_주기−t_Low, 실측 미확정). `force_window_open()`이 RDY Low 확인 후에만 I2C를 발행하는 현 프로토콜(`tdc_touch_iqs323.c:145~175`)은 **이미 e8300 자신의 I2C를 추정 변환 활성 구간 밖으로 강제**하고 있다 — 이는 신규 완화책이 아니라 IC Streaming 프로토콜의 기존 보장이다.

**함의**: e8300 자체 I2C가 메커니즘_2의 자기유발 경로일 가능성은 낮다. 남는 진짜 관심사는 **e8300이 통제 못 하는 nRF SPI 엣지**가 이 구간과 우연히 겹치는 경우인데, §0에 의해 이건 스케줄 자체가 불가능하다. 대신 확보 가능한 것은 "e8300이 마스터인 I2C·계측 활동"과 "nRF SPI 활동"의 **시간적 동시발생 빈도를 낮추는 것**뿐 — 이는 메커니즘_1(총 결합 전하)·메커니즘_3(주기적 에너지 총량) 관점의 완화지, 엄밀한 메커니즘_2 윈도우 회피라고 과장하지 않는다.

## 3. SW-only 후보

### S4-1 (권장) — `fake_func_sleep()` 한정, SPI 미처리 상태일 때만 계측(read_debug) 수행

**메커니즘**: `get_spi_commu_state()`(기존 공개 API, `driver_SPI.h`)를 `bleCommunication()` 호출 **이전**에 1회 스냅샷한다. `bleCommunication()`은 내부에서 FETCH 처리 후 `set_spi_commu_state_IDLE()`을 호출하므로(`ble_communication.c:275,365,399`), 스냅샷을 그 호출 앞에서 뜨면 "이번 100ms 주기 동안 SPI로 새 명령이 도착했는가"를 부작용 없이 알 수 있다. 스냅샷이 `SPI_COMM_IDLE`이 아니면(FETCH/ERROR) — 즉 이번 주기에 SPI 스위칭이 있었으면 — 그 주기의 `read_debug()`(C1 §3.2가 이미 확인한 자체 애그레서 I2C 윈도우)만 스킵한다. 목표는 "nRF SPI 스위칭 + e8300 자체 계측 I2C 스위칭"의 **동시(같은 100ms 버킷 내) 발생 총량**을 줄이는 것(§1의 메커니즘_1/3 완화 — 엄밀한 메커니즘_2 주장은 하지 않음).

**필요 변경**:
- `main.c` `fake_func_sleep()` ULP 루프 안, `bleCommunication(dummy_isd)` 호출 **직전**에 `EN__SPI_COMMU_STATE spi_before = get_spi_commu_state();` 추가(신규 로컬 변수 1개, 기존 함수 미변경).
- 같은 루프 안 `#if (TDC_TOUCH_DEBUG_PRINT_ENABLE)` 블록의 `read_debug()` 호출을 `if (spi_before == SPI_COMM_IDLE) { ... }`로 감싼다.
- `func_sleep()`(진짜 절전)은 **미변경** — 그 경로는 NRF가 꺼져 있어(`NRF_Off_Command()`) SPI 활동 자체가 없으므로 이 게이트가 항상 no-op이라 적용 실익이 없다(최소 변경 원칙).
- IQS323 레지스터 변경: **없음**. 새 ISR·새 전역 변수·새 타이머: **없음**(기존 공개 getter만 활용).
- 분해능: §0에 의해 **100ms 버킷 단위**(그 주기에 SPI가 있었는지 여부)만 가능 — ms 단위 세밀 쿨다운은 새 자유주행 타이머 추가가 전제(별도 확장, 본 후보 범위 밖).

**실현성**: 높음(변경 최소, 기존 export API만 사용, FSM 비의존). **트레이드오프**: read_debug은 이 프로파일링 세션이 관측하려는 바로 그 텔레메트리라, SPI 활동 시점(=관측 대상 순간)의 샘플이 정확히 비는 역설이 있다 — "완화 확인용"과 "정밀 관측용" 목적이 상충할 수 있다.

### S4-2 (비권장) — `read_status()` 자체를 SPI 감지 기반으로 지연

**메커니즘**: S4-1과 동일 아이디어를 판정 입력(`read_status`)에도 적용.

**기각/비권장 사유**: `read_status()`는 §C2 INV-⑦-1에 의해 **L1 완전 공유**(노말·절전 동일 함수) — 이 게이트를 절전 루프에만 넣어도, **판정 입력의 실제 샘플링 시각**이 매 주기 가변적으로 밀린다. 절전 ULP 문턱(ati_error 7회≈700ms, touch 24회=2400ms)은 "정확히 100ms 간격"을 전제로 세워진 카운터인데, §0이 확인했듯 세밀한 지연 자체를 구현할 타이머도 없다(TIMER3는 100ms 단위로만 재구성됨). 근거가 약해서가 아니라 **회귀 위험이 이익보다 뚜렷이 커서** 비권장.

### S4-3 (탐색적, 근거 약함) — `enable_ReadCommandForSPI_Master()` 어서션을 RDY 참고해 지연

**메커니즘**: e8300이 "SPI로 보낼 데이터 준비됨" GPIO(`driver_SPI.c:409`) 어서션 시각은 완전히 통제 가능하다. IQS323 RDY 핀을 참고해 이 어서션을 짧게 늦추면, **nRF가 이 신호에 즉시 반응해 SPI를 개시한다는 가정 하에** 간접적으로 SPI 개시 시각에 영향을 줄 수 있다.

**필요 변경**: `writeDataToSpiTxBuff()` 말미, `enable_ReadCommandForSPI_Master()` 호출 전 `Sys_GPIO_Read(TDC_TOUCH_IQS323_RDY_PIN)` 참고 짧은 대기. e8300 SW. IQS323 레지스터 변경 없음.

**근거가 약한 이유**: (1) nRF가 이 GPIO에 실제 얼마나 빨리/어떻게 반응하는지 **완전 미확인**(nRF FW 범위 밖) — 지연시켜도 SPI 개시가 그만큼 밀린다는 보장이 없다. (2) `writeDataToSpiTxBuff()`는 배터리·LED·충전상태 등 다수 BLE 응답 경로의 공용 함수라, 모든 호출자에 지연이 걸려 **터치와 무관한 BLE 응답성**에 영향(C2 목록엔 없는 별도 리스크). (3) 대기 자체가 GPIO 폴링이라 새 자체 스위칭 추가 가능성. 후보로만 제시, 검증 우선순위 낮음.

### S4-4 (기각) — nRF BLE 연결 간격과 IQS323 변환 주기 위상 고정

**기각 사유**: e8300은 nRF BLE 연결 간격을 제어하지 않으며(별도 칩·별도 펌웨어), 양쪽이 완전 비동기 오실레이터라 SW만으로 위상 고정이 성립하지 않는다. "e8300 SW + IQS323 레지스터" 범위를 벗어난다(nRF 펌웨어 변경 필요). 근거 없음.

### S4-5 (이론상 가능, 채택 보류) — RDY(DIO16)를 DIO 인터럽트 슬롯에 배정해 인터럽트 동기화

**메커니즘**: RDY 하강 엣지 인터럽트가 있으면 force_window_open의 45ms busy-wait 폴링을 이벤트 기반으로 대체할 수 있어, 이론적으로는 SPI 처리를 "IQS323이 확실히 유휴 상태"인 시점에 정밀 배치하는 기반이 된다.

**필요 변경**: `ci_dio_configure_sleep()`(또는 별도 초기화)에서 `Sys_DIO_IntConfig(0 또는 1, DIO_INT_SRC_DIO_16 | ..., ...)`로 RDY 핀 배정, 신규 `DIO_x_IRQHandler` 작성, `tdc_touch_iqs323.c`의 폴링 로직을 인터럽트 플래그 기반으로 재작성. IQS323 레지스터 변경 불필요(호스트 수신 방식만 전환).

**보류 사유**: (1) 플랫폼에 **단 2개**뿐인 DIO 인터럽트 슬롯이 이미 acc-sensor·케이스덮개 감지에 배정(현재 `#if 0` 비활성이나 삭제된 기능 아님 — 향후 재활성 계획 여부 **[미확인]**), 자원 경합 소지. (2) INV-⑦-1(L1 완전 공유)에 의해 이 변경은 노말·절전 폴링 방식을 동시에 바꾸는 근본 재설계이며, RDY 종합결론.md §3.3이 이미 "Event Mode + 인터럽트 전환"을 별도의 더 큰 개선 스터디(Phase 3)로 명시 분리해 두었다 — 본 SW 운영 수준 완화의 스코프를 넘어선다. (3) 재작성 범위가 커 "기존 기능 무손상" 제약 하 회귀 검증 부담이 매우 크다. **결론**: 후보 기록·채택 보류, 별도 작업으로 이관 권고.

> [!NOTE]
> **레버 영역 밖 관찰(참고용)**: NP Report Rate(0xC1)를 늘려 RDY 토글 빈도 자체를 낮추는 안은 IQS323 변환 스케줄 자체를 바꾸는 것이라 S1 영역과 중복돼 본 노드는 후보로 세우지 않는다. C1 §3.2가 권고한 "0x10+0x13 통합 combined_read"도 관측 재설계(S7) 영역과 겹쳐 아이디어만 인지한다.

## 핵심 결론 (3~5줄)

1. **원 초점의 핵심 전제가 코드로 반증된다** — CM3(e8300)는 SPI 슬레이브(nRF가 마스터)이므로 "SPI 트랜잭션을 윈도우 밖에 스케줄"은 e8300 SW만으로 문자 그대로 실현 불가능하다. e8300 권한은 자신이 마스터인 IQS323 I2C, SPI "데이터 준비" GPIO 어서션 시각, 계측 호출 여부뿐이다.
2. RDY Low(통신 윈도우)는 이미 측정 종료 후 구간이므로, e8300 자체 I2C는 현 Streaming 프로토콜 자체에 의해 **이미** 추정 변환 활성 구간 밖에서만 발생한다 — 신규 완화책이 아니라 기존 프로토콜의 태생적 보장이다.
3. TIMER3가 `func_sleep()`/`fake_func_sleep()` 진입 시 100ms 주기로 재구성됨을 코드로 확인했다(`ci_timer.h:18~19`) — 이는 ms 단위 정밀 스케줄링 후보(S4-2류)의 실현을 원천적으로 제약하고, 실현 가능한 분해능을 100ms 버킷 단위로 낮춘다.
4. 이 재정의된 권한·분해능 범위 안에서 가장 안전한 후보는 **S4-1**(`fake_func_sleep()` 한정, SPI 미처리 시에만 read_debug 수행) — 기존 export API(`get_spi_commu_state()`)만 재사용해 신규 ISR·타이머·전역변수 없이 구현 가능하고, C2 불변식 8종 전부 무손상~주의 수준이다. 단, 프로파일링 목적 자체와 상충하는 트레이드오프(관측하려는 순간의 샘플 소실)가 있다.
5. RDY 인터럽트화(S4-5)는 플랫폼상 이론적으로 가능함을 확인했으나(2슬롯 DIO 인터럽트 존재) 자원 경합과 재설계 스코프(RDY 종합결론.md가 이미 별도 Phase 3로 분리) 때문에 본 SW 운영 수준 완화의 범위를 벗어나 채택을 보류한다.

## 리스크/불확실성

- T_주기·t_High(변환 사이클 실제 길이) **실측 미확정** — "윈도우 안/밖" 정량 판단 기준 자체가 추정치다.
- S4-1의 "동시발생 저감이 실제로 ATI 에러/오탐을 줄인다"는 것은 본 노드의 **추론**(가설-불확실)이며, C1이 명시적으로 검증한 인과관계는 아니다 — stage2 검증에서 반증 가능성 열어둠.
- nRF가 `GPIO_PIN_ReadCommandForSPI_Master`에 실제로 어떻게/얼마나 빨리 반응하는지(S4-3의 전제)는 nRF 펌웨어 소스가 범위 밖이라 **완전 미확인**.
- acc-sensor·케이스덮개 DIO 인터럽트(S4-5가 자원 경합을 우려하는 대상)가 `#if 0`로 비활성인 이유(임시 비활성인지 폐기된 기능인지)는 **미확인** — 재활성 계획이 있다면 S4-5의 슬롯 경합 우려가 더 강해진다.
- S4-1은 `fake_func_sleep()`이 실제 프로파일링 경로라는 C2 §11의 **강한 정황 추정**(100% 확정 아님)을 전제로 스코프를 좁혔다 — 만약 실제 재현이 `func_sleep()` 경로라면(은수님 확인 필요), S4-1은 대상을 잘못 짚은 것이 되고 §3 "func_sleep 미적용" 판단도 재검토해야 한다.
