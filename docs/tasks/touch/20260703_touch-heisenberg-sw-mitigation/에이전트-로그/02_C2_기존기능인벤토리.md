## 2. ① 드리프트/스턱 회피 (Full ATI)

**정의**: IC 자체 Full ATI(자동 게인 산출·자동 Re-ATI) + SW가 보조하는 드리프트/스턱 복구 3경로.

| 경로 | 트리거 | 함수 | 레지스터 |
|---|---|---|---|
| 경로_1 IC 자동 | LTA가 ATI Band 이탈 [확립:문서, 레지스터-맵.md §5.10] | (IC 내부, SW 미개입) | 0x36 Full 모드가 전제 |
| 경로_2 SW 드리프트 게이트 | `NOT_TOUCH && !ati_active && ati_error && 쿨다운경과` | `tdc_touch_logic_step` :154~161 | 0xC0 bit2 write |
| 경로_3 stuck 3단계 | TOUCH 지속 30000ms(`TDC_TOUCH_STUCK_TIMEOUT_MS`)마다 승급 | `stuck_eval` (logic.c:17~60) | 0xC0 bit3→bit2→CM3 reboot |
| 경로_4(절전 전용) | `ati_error && !ati_active` 5회 초과 | `tdc_touch_sleep_handle_ati_error` (main.c:1062~1092) | 0xC0 bit2, 5회 후 `SYS_WATCHDOG_RESET` |

**부팅 1회 시퀀스**([확립:코드] `tdc_touch_iqs323_apply_settings`, .c:400~460): ACK reset→sensor_setup→touch/prox 임계→events_enable→beta/power(0xB0/B1/B2/B4·0x31·0xC0·0xC2·0xC5)→**0x36=0x040C(Full ATI)**→**0xC0=0x54,0x07(부팅 Re-ATI, `wait_ati_done_blocking` 블로킹 대기)**→**0xC0=0x58,0x07(부팅 RESEED)**.

**INV-①-1**: 0x36(Sensor0 ATI Setup)은 부팅 시 Full 모드(`0x040C`)로 유지 — Disabled/Full 이외 모드 전환·MULT/COMP 수동 write 재도입은 훼손(경로_1 소멸).
**INV-①-2**: 경로_2 게이트 3조건(`NOT_TOUCH ∧ !ati_active ∧ 쿨다운경과`)은 전부 유지 — 하나라도 제거·완화(예: TOUCH 중에도 발행)는 "터치 중 Re-ATI로 실터치를 노터치로 학습" 회귀.
**INV-①-3**: stuck 3단계 순서(RESEED→RE_ATI→MCLR, 각 30000ms)와 "TOUCH 지속 중에만 카운트, 해제 시 리셋" 로직(:21~32) 불변.
**INV-①-4**: 경로_2/③ 쿨다운(`re_ati_cooldown_until_ms`, 절대ms) 로직은 read-fail-hold 카운터(`read_fail_cnt`)와 별개 변수 — 통합/치환 시 두 독립 타이머의 의미가 섞여 회귀 위험.
**확립(데이터시트, 레지스터-맵.md §5.11)**: ati_error는 IC가 **자동으로 재시도하지 않는다** — SW가 명시적으로 0xC0 bit2를 써야 클리어된다. 즉 경로_2를 없애면 한번 난 drift가 영구화될 수 있음(완화책이 "게이트를 더 막는" 방향일 때 반드시 확인).

## 3. ② 노말/절전 최초 터치 해제 감지

**정의**: 부팅/절전진입 직후 "손이 이미 닿아있는" 상태를 무시하고, **디바운스된 해제 확인** 후에만 정상 판정을 재개하는 게이트. 두 모드가 각각 별도 상태변수로 구현.

| 항목 | 노말(`boot_ignore`) | 절전(`sleep_ignore`) |
|---|---|---|
| 진입 조건 | READY 전이 시 `pressed==true` (`try_finish_init`, tdc_touch.c:171~177) | `func_sleep()` 진입 시 무조건 `true` 시작(main.c:1172) |
| 해제 조건 | 연속 not-pressed **3폴링**(`TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT`=ceil(300/100)=3) — logic.c:118~152 | 연속 NOT_TOUCH **3샘플**(`TDC_TOUCH_ULP_NOTOUCH_DEBOUNCE_CNT`=3) — main.c:1095~1112 |
| 해제 시 부수효과 | 없음(그냥 게이트 해제 + 로그) | **RESEED 1회 발행**(`tdc_touch_iqs323_reseed`) — 절전 baseline 동기 |
| 무한대기 방지 | `TDC_TOUCH_INIT_TIMEOUT_MS`=2500ms 지나면 auto-ATI 강제완료 처리(별개 메커니즘, try_finish_init) | `TDC_TOUCH_ULP_FORCE_RESEED_MS`=10000ms 미확정 시 강제 RESEED(게이트 유지, 재시도) — main.c:1114~1121 |
| 부가 경고 | 5000ms(`BOOT_WARN_MS`) 지속 시 1회 경고 로그+LED(게이트는 안 풀림) | 없음 |

**INV-②-1**: 두 게이트 모두 **디바운스 카운트 ≥1** 유지 — "1샘플만 보고 즉시 해제 확정" 완화는 채터링 시 오해제 회귀.
**INV-②-2**: 절전 게이트 해제 시 RESEED가 반드시 동반(해제=baseline 동기 시점, 분리 불가). RESEED 없이 게이트만 풀면 절전 진입 시점 환경(클럭다운·QCC off) LTA 미반영 상태로 판정 시작 — 오탐 회귀.
**INV-②-3**: 강제 타임아웃(10000ms) 경로는 게이트를 **열지 않고** RESEED만 반복 — "타임아웃 시 게이트도 강제로 연다"로 바꾸면 손이 계속 닿아있는 채로 판정 시작(오염된 상태에서 touch_reboot 카운트 시작) 회귀.
**확립(코드)**: 두 게이트는 **완전히 독립된 상태 저장소**(logic.c의 `tdc_touch_logic_state_t.boot_ignore` vs main.c 지역변수 `sleep_ignore`) — 한쪽을 수정해도 다른 쪽에 자동 반영 안 됨. 통합 리팩토링 시 반드시 둘 다 명시 수정.

## 4. ③ ATI 에러 시 Re-ATI — 노말/절전 비대칭 주의

**정의**: `ati_error` 비트(System Status bit6, [확립:문서] 전역·채널비구분)를 감지해 Re-ATI(0xC0 bit2)를 발행하는 복구 경로. **노말과 절전이 서로 다른 게이트 조건을 쓴다** — 이는 기존에도 존재하던 비대칭이며, 하이젠베르크 완화책이 이 비대칭을 더 벌리면 안 된다.

| | 노말 (`tdc_touch_logic_step`) | 절전 (`tdc_touch_sleep_handle_ati_error`) |
|---|---|---|
| 발행 조건 | `NOT_TOUCH` 상태일 때**만** (§2 INV-①-2) | **터치 상태 무관** — `ati_error && !ati_active`이면 무조건 (main.c:1064) |
| 재시도 제한 | 쿨다운(절대ms 2000) 후 재평가만, 무한 허용 | **5회** 초과 시 CM3 리부팅으로 승격(main.c:1066~1080) |
| 실패 시 최종수단 | stuck stage2(TOUCH 30000ms×2 지속 시)에서만 MCLR급 리부팅 | ati_error 카운트 초과 시 즉시 `SYS_WATCHDOG_RESET` |

**INV-③-1**: 노말 경로의 "TOUCH 중엔 Re-ATI 금지" 게이트는 **절전 경로엔 이미 없다**(현재도 절전은 터치 상태와 무관하게 Re-ATI를 쏠 수 있음) — 이는 기존 동작이므로 "훼손"은 아니지만, 완화책이 이 비대칭을 인지하지 못한 채 절전쪽에도 "터치 중 금지"를 새로 추가하면 그 자체가 **동작 변경**(기존 사양 아님, 별도 검토 필요)이 된다. 반대로 이 비대칭이 프로파일링 실패(§11)의 실제 인자일 가능성은 C1의 몫.
**INV-③-2**: 절전 5회 카운터는 `ati_active`가 true인 동안(ATI 진행 중) 증가도 리셋도 안 됨(main.c:1064,1088 조건 배타) — "ATI 진행 중에도 카운트 계속 증가"로 바꾸면 정상 ATI burst 시간이 김에도 조기에 리부팅 승격되는 회귀.
**INV-③-3**: 0xC0 write는 **항상 Power Mode(0x50)·CH timeout(0x07) 비트를 동반**(§10 교차불변식 INV-X-1) — 새 Re-ATI 트리거 코드를 추가할 때 이 비트를 빠뜨리면 Power Mode가 Normal로 되돌아가는 조용한 회귀.

## 5. ④ 터치 판정 (CH0 Touch)

**정의**: System Status(0x10) 4-tuple read → CH0 눌림 여부·ATI 상태 판정. 노말·절전·프로파일링 전부 이 판정 결과에 의존.

| 필드 | 비트 | 의미 | 근거 |
|---|---|---|---|
| pressed | MSB bit1 (전체 bit9) | CH0 Touch | [확립:코드] iqs323.c:364 |
| prox | MSB bit0 (전체 bit8) | CH0 Prox (FSM 미사용, 계측 전용) | iqs323.c:365 |
| ati_active | LSB bit5 | ATI burst 진행 중 | iqs323.c:362 |
| ati_error | LSB bit6 | ATI 실패(전역) | iqs323.c:363, [확립:문서] 레지스터-맵.md §5.11 |
| 글리치 | lsb==msb==0xEE | 통신 실패로 간주, `ok=false` | iqs323.c:357~360 |

**임계**: 0x62 Touch Threshold=**80**(계수), Hysteresis=**8**(4비트, 상위니블<<4). 절대임계 = 계수×LTA/256(코드 주석 iqs323.c:288, iqs323.h:46~49 — 실측 LTA≈399에서 절대임계≈125). **이 값은 노말·절전 공용**(`apply_settings()`가 부팅 1회만 write, 절전 진입 시 재write 없음 — iqs323.c:497~499 명시) — 과거 문서(§0, RESEED.md)의 "절전 전용 30/30" 서술은 낡았다. **주의**: 과거 문서(20260619 종합)의 "계수<32 필수" 가설은 **현재 코드(80)로 이미 초과 상태** — 이는 이후 실측 튜닝으로 대체된 것으로 보이며(§0 문서 신선도), 현재 코드의 80이 실제 기준값이다. 새 계수 변경 시 이 실측 근거(터치 D 160~190 대비 78%)와 비교해야 함.
Prox Threshold=255(사실상 비활성화, LTA freeze는 touch에만 연동, iqs323.c:420~422).

**INV-④-1**: System Status 비트 매핑(bit5/6/8/9) 불변 — 레지스터 재해석 금지.
**INV-④-2**: 0xEEEE 글리치 판정 불변 — 이 패턴을 "유효 데이터"로 오인하면 안 됨.
**INV-④-3**: 임계 공식(절대임계=계수×LTA/256)은 IC 하드웨어 사양 — 계수를 조정하는 완화책(S2 레버 등)은 이 공식으로 절대 raw count를 역산해 SNR≥5(raw≥20cnt, [확립:문서] 적용가이드 §4.4) 여부를 확인해야 함.
**INV-④-4**: `public_touch_settings()`(iqs323.c:292)는 현재 유일한 외부 호출부가 `#if 0`(main.c:850~859, 죽은 코드)뿐 — 살아있는 기능 아님. 완화책이 "런타임 임계 전환"을 새로 쓰려면 이 함수를 **활성화**하는 것 자체가 신규 기능 추가이지, 기존기능 재사용이 아님(별도 검증 필요).

## 6. ⑤ 롱터치 (2400ms 지속 — 절전⇄노말 대칭 트리거)

**정의**: 동일한 2400ms(`TDC_TOUCH_LONG_TOUCH_MS`/`TDC_TOUCH_ULP_REBOOT_TOUCH_MS`) 상수를 노말→절전, 절전→노말 양방향에 대칭 사용하는 "전원 버튼처럼 동작하는" UX. **구현은 완전히 별도**(공유 함수 없음).

| 방향 | 함수 | 발동 조건 | 결과 |
|---|---|---|---|
| 노말→절전 | `tdc_touch_logic_step` 롱터치 블록(:172~190) | TOUCH 진입 엣지 기록 후 2400ms 지속, **1회 래치**(`long_latched`) | `tdc_touch_process()`가 `true` 반환 → `powerButtonPushed` → `systemControl()`(main.c:452,492~499) → 절전 진입 판단은 systemControl.c 소관(터치 모듈 범위 밖) |
| 절전→노말 | `tdc_touch_sleep_handle_touch_reboot`(main.c:1125~1153) | `sleep_ignore` 게이트 해제 **이후**만 카운트 시작, 연속 TOUCH 2400ms(24샘플) | `SYS_WATCHDOG_RESET()` 직접 호출(CM3 재부팅→노말 재시작) |

**INV-⑤-1**: 노말 쪽은 "1회 래치"(`long_latched`, 재진입 전까지 재발동 안 됨) — 절전 쪽은 카운터라 게이트 열린 채 반복 터치 시 매번 재평가(래치 없음, 손 떼면 `touch_cnt=0` 리셋). 두 구현이 다르다는 것 자체가 기존 사양이므로, 완화책이 "동일 로직으로 통합"하려면 이 차이(래치 유무)를 의식적으로 결정해야 함.
**INV-⑤-2**: 절전 쪽 카운트는 **게이트(§3 sleep_ignore) 해제 후에만** 시작 — 게이트 열리기 전 터치는 절대 reboot 카운트에 반영되지 않음(main.c:974,1002 if/else 배타).
**INV-⑤-3**: `tdc_touch_process()`의 `true` 반환은 `main.c`의 `powerButtonPushed` 계약 — 반환 시점·조건(2400ms 1회 엣지)을 바꾸면 `systemControl()` 하류 로직(범위 밖, 검증 안 함)에 파급.

## 7. ⑥ 절전 진입/기상 시퀀스

**정의**: `func_sleep()`(main.c:1164~1252) 진입부(HW 셧다운)→클럭 다운→ULP 루프. **기상은 별도 FSM 없이 CM3 재부팅**(WDT reset) 후 부팅 시퀀스 전체 재실행.

**진입 순서**([확립:코드] main.c:1189~1226):
1. FPGA reset write, CFX에 ULP 진입 커맨드, NRF 리셋+off, QCC `SND_QCC_MODE_SHUTDOWN`, FPGA_SLEEP핀 Low, PMIC 3.3V/1.2V off, LED off
2. CFX가 ULP 진입 확인할 때까지 대기(공유메모리 폴링)
3. `ci_power_sleep()`: SYSCLK 30.72M→**2.56M**, SLOWCLK 유지
4. `i2c_set_master_prescale(I2C_MASTER_PRESCALE_6)` — **[FIXME] 미해결**: 헤더 설계 의도는 `_21`(≈122kHz 유지)인데 실제는 `_6`→2.56MHz/6≈**426.7kHz**로 가동 중(20260702 작업 검증 확정, driver_i2c.h 공식 `SCL=SYSCLK/((PRESCALE+1)×3)`으로 본 세션에서 재확인). **이 SCL 426.7kHz는 노말(30.72MHz÷240 프리스케일)보다 절전에서 오히려 I2C 엣지가 상대적으로 빨라지는 지점 — 관측교란.md 메커니즘_1(결합임피던스)과 직결되는 기존 미해결 이슈**. 완화책이 이 값을 건드릴 경우 "신규 도입"이 아니라 "기존 미해결 FIXME 해결"로 문서화할 것.
5. `ci_timer_init_prescaled(PRESCALE_1, 3999)` — ULP 하드웨어 타이머 정확히 100.0ms(SLOWCLK 40kHz 가정)
6. ULP 루프(SYS_WAIT_FOR_INTERRUPT 100ms 간격) — §2·§3·§4·§6의 에러/게이트/롱터치 핸들러 호출

**기상**: 런타임 FSM 없음 — `SYS_WATCHDOG_RESET()`(ati_error 5회 초과, 또는 touch_reboot 2400ms)로 CM3 하드 리부팅, 이후 `Initialize()`부터 전체 재시작(`tdc_touch_init_begin()`→MCLR→apply_settings). **절전 IQS323 레지스터는 부팅 시 값과 동일하게 유지**(전용 sleep 설정 없음, 코드 주석 iqs323.c:497~499 명시).

**INV-⑥-1**: 진입 순서(HW 셧다운 → 클럭다운 → I2C prescale → ULP 타이머 init) 불변 — 특히 IQS323 레지스터 write는 전부 클럭다운 **이전**(정상속도 I2C 보장)에 끝나 있어야 함(현재는 부팅 시에만 쓰고 절전 진입 시엔 재write 없음 자체가 이 제약을 자동 만족).
**INV-⑥-2**: 기상 경로가 "리부팅뿐"이라는 사실 자체가 불변식 — 완화책이 "절전 중 문제 시 그냥 무시하고 계속 절전 유지"로 바꾸면 스턱 회복 수단이 사라짐.
**INV-⑥-3**: ULP 웨이크 주기(100ms, HW 타이머)와 `TDC_TOUCH_ULP_WAKE_MS`(100, SW 상수) 정합 — 이 값을 어긋나게 바꾸면(SW만 변경) 카운트형 판정(§3·§6 CNT 매크로) 전부 실제 시간과 괴리.

## 8. ⑦ 노말·절전 공통 폴링 경로

**정의**: 노말(`tdc_touch_process`)과 절전(`func_sleep` ULP 루프)은 **판정 로직은 분리**돼 있지만, **L1 read 함수 하나(`tdc_touch_iqs323_read_status`)를 물리적으로 공유**한다. I2C 트랜잭션·RDY 윈도우 프로토콜은 두 모드에서 동일 코드.

**공유 스택**(호출 시 매번 동일):
```
read_status() → read_register(0x10) → force_window_open() (0xFF write, RDY Low 대기 45ms)
                                     → i2c_write/i2c_read (I2C 원시)
                                     → wait_window_closed() (RDY High 대기 20ms)
```

**INV-⑦-1**: 이 L1 계층(`tdc_touch_iqs323.c`)에 손대는 완화책(예: force_window_open 타이밍 조정, RDY 핀 슬루/드라이브 강도 재설정 — `TDC_TOUCH_IQS323_RDY_PIN_CFG_OUTPUT/INPUT` 매크로, iqs323.h:38~39)은 **노말·절전 양쪽에 동시 적용**된다 — 한쪽만 고치는 것이 원천적으로 불가능(장점: 레버 하나로 양쪽 커버 / 위험: 노말 쪽 회귀 가능성도 항상 동반 검토 필요).
**INV-⑦-2**: `MAX_WAIT_OPEN_MS`(45)·`MAX_WAIT_CLOSE_MS`(20) 타임아웃 값은 두 모드 공통 — 프로파일링 전용으로 다르게 하려면 파라미터화가 **신규** 필요(현재 상수 고정).
**INV-⑦-3**: 폴링 **주기**는 공유 아님(노말=SW tick 차분 100ms, 절전=HW 타이머 인터럽트 100ms) — L1 자체 호출 빈도는 두 모드에서 독립적으로 결정됨. 레버가 "폴링 주기를 애그레서 비트와 이격"시키려면 두 스케줄러(SW 게이팅 vs HW 타이머)를 각각 건드려야 함.

## 9. ⑧ 단일채널(FullATI 단순안) 구성

**정의**: CRX0만 활성, CRX1/CH1·CH2 전부 disable. CalCap 더미채널·주기적 방전 없음(과거 스턱 이슈 원인 제거).

**부팅 1회**(`sensor_setup`, iqs323.c:266~282): 0x50(Sensor2)=0,0 → 0x40(Sensor1)=0,0 → 0x30(Sensor0)=0x01,0x01(enable+ctx0). 재설정 없음(런타임 CH 토글 코드 전무).

**INV-⑧-1**: CH1(0x40)·CH2(0x50)는 계속 disable 유지 — 어떤 레버가 "레퍼런스 채널로 노이즈 상쇄"를 시도하면 이 항목을 위반(= mutual/differential 영역, 요구사항 제약_3으로 이미 범위 밖).
**INV-⑧-2**: `ati_error`가 전역 비트([확립:문서] §5.11)이므로, 단일채널 한정 사실이 "ati_error=CH0 ATI 문제"라는 **암묵적 등가**를 만들어준다 — 어떤 완화책이 채널을 늘리면 이 등가가 깨져 ③의 게이트 조건 해석이 틀어짐(회귀).

## 10. 교차-커팅 불변식

**INV-X-1 (0xC0 비트 보존)**: `SYSTEM_CONTROL`(0xC0) write는 트리거 비트(ack=bit0, RESEED=bit3, Re-ATI=bit2)만 단독으로 쓰면 **Power Mode(bits[6:4]) 및 MSB CH timeout(bits[2:0])이 되돌아간다** — 현재 코드는 모든 런타임 write에 `0x50|trigger, 0x07`을 동반(iqs323.c:447,453,465,471)해 이를 방지한다. 새 0xC0 write를 추가하는 모든 레버(S3 전력모드, S6 등)는 이 조합을 반드시 이어받아야 함.
**INV-X-2 (READ_FAIL 처리)**: read 실패는 hold(≤20폴링≈2000ms, 상태 동결) 후 `NOT_TOUCH` 강제(logic.c:97~113) — hold 카운트를 0으로 낮추면 스턱/롱터치가 매 통신 글리치마다 리셋되는 회귀, 반대로 과도히 높이면 진짜 해제를 오래 못 봄.
**INV-X-3 (디버그 계측 경로 무해)**: `TDC_TOUCH_DEBUG_PRINT_ENABLE`(config.h)로 게이팅된 LTA/Counts read(`tdc_touch_iqs323_read_debug`, 0x13+0x14 4바이트)는 판정에 **입력되지 않음**(FSM 입력 아님, 실패해도 `ok=false`만 반환하고 무시) — 단, 이 read 자체가 **추가 I2C 윈도우 1회**를 매 폴링 소모(노말 100ms, 절전 100ms 마다) — 하이젠베르크 원인 후보(추가 SPI/I2C 트래픽)로서 C1이 검토할 만하나, 끄면(`=0`) 판정 로직 자체는 변하지 않음(계측 전용이므로 완화책 후보 중 "부작용 없는" 옵션에 해당).

## 11. [중요 발견] `fake_func_sleep()` — 실제 프로파일링 경로일 가능성

지시받은 4파일 + `func_sleep()` 범위 **밖**이지만, 은수님의 문제 서술과 코드가 거의 정확히 일치해 반드시 보고한다.

| 사실 | 근거 |
|---|---|
| BLE 원격 "General Debug" 커맨드로 진입(`op_mode==1`) | `tdc_remote_general_debug.c:160~183` `gd_handle_op_mode_setting` → `tdc_set_fake_op_mode(1)` |
| 진입 시 `func_normal()` 루프 안에서 조건부 호출 | `main.c:730~735`: `if (tdc_get_fake_op_mode()==1) fake_func_sleep();` |
| **SYSCLK을 낮추지 않음** — 30.72MHz 유지 | `ci_fake_power_sleep()`(`ci_power.c:163~174`) 내부 `tdc_Trims_SetOperatingFrequency(SYS_FREQ_30M72)` — 이름은 "sleep"이지만 실제로는 클럭을 **30.72MHz로 (재)설정** |
| 루프 안에서 **BLE 통신을 계속 서비스** | `main.c:899` `bleCommunication(dummy_isd)` 매 t3 tick 호출 — QCC/SPI·BLE 트래픽 지속 |
| QCC 셧다운은 **주석 처리되어 미실행** | `main.c:828` `// snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);` |
| 터치 판정은 `func_sleep()`과 **동일 L1 API**를 호출하되, **인라인 복제 코드**(2026-07-02 리팩토링 미적용) | `main.c:889~1028`, 5개 static 헬퍼로 분리된 `func_sleep()`과 달리 통짜 인라인 — 20260702 작업 이력이 "적용범위: func_sleep()만, fake_func_sleep() 제외"를 명시 확정 |
| **롱터치→재부팅 경로가 사실상 no-op** | `main.c:1007~1013`: 카운트 도달 시 로그만 찍고 `SYS_WATCHDOG_RESET()`가 **주석 처리**됨(`// SYS_WATCHDOG_RESET();`) — `func_sleep()`의 대응 코드(main.c:1130~1146)는 이 호출이 살아있음. **이 한 가지는 이미 두 경로가 갈라졌다는 확정 증거**(가설 아님, 코드 diff로 확인 가능) |

**의미(가설, C1/오케스트레이터 교차검증 필요)**: 은수님이 설명한 "QCC를 슬립 안 시키고 SPI 위해 30.72MHz 유지한 채 BLE·SPI로 프로파일링"은 `fake_func_sleep()`의 정의 자체와 매우 근접한다. **만약 실제 재현이 이 경로를 타는 것이라면**, S1~S8 레버 후보가 `tdc_touch_logic.c`/`tdc_touch.c`/`func_sleep()`만 고쳐서는 재현 경로에 반영되지 않을 수 있다(단, ④·⑦의 L1 공유 덕분에 L1 계층 레버는 자동으로 이 경로에도 적용됨 — §8 INV-⑦-1). 이 발견은 확정 원인지목이 아니라 **코드 사실**이며, 최종 해법은 (a) `func_sleep()`류 정식 경로 대비, (b) `fake_func_sleep()` 프로파일링 경로 대비를 모두 검토하거나 최소한 어느 쪽인지 은수님께 확인이 필요하다.

## 핵심 결론

1. 8개 기존기능은 전부 코드에서 구체적 함수·레지스터·타이밍으로 특정됐고, 각각 검증 가능한 INV-①~⑧ 목록으로 정리했다(§2~9) — 이후 S1~S8은 이 표를 그대로 회귀 체크리스트로 인용 가능.
2. **노말과 절전은 판정 로직이 완전히 분리**(별도 게이트·상태변수)돼 있으나 **L1 read/윈도우 프로토콜은 완전히 공유**(INV-⑦-1) — L1 레벨 완화책은 적용 범위가 넓은 대신 항상 양쪽 회귀를 함께 검토해야 한다.
3. **비대칭 발견**: 노말의 "터치 중 Re-ATI 금지" 게이트가 절전 ATI-에러 복구에는 이미 없다(§4 INV-③-1) — 기존 사양이지 이번에 깨지는 게 아니지만, 완화책 설계 시 이 비대칭을 인지하지 못하면 "고친 줄 알았는데 절전은 원래도 달랐다"는 혼선이 생긴다.
4. **가장 중요한 발견**은 `fake_func_sleep()`이 사용자가 설명한 프로파일링 시나리오(클럭 유지+BLE 지속)와 거의 정확히 일치하는 별도의, 부분적으로 낡은 코드 경로라는 점(§11) — 이는 전체 작업의 범위(어느 파일을 고쳐야 실제로 재현 경로에 반영되는지)에 영향을 줄 수 있어 오케스트레이터/C1에 우선 전달이 필요하다.
5. 절전 I2C SCL이 설계 의도(122kHz)와 달리 실제로는 426.7kHz로 가동 중인 기존 [FIXME]는(§7) 메커니즘_1(결합 임피던스)과 직결되는, 이미 존재하던 미해결 이슈다 — S4/S5 레버의 유력 후보 지점.

## 리스크 · 불확실성

- 0x36=0x040C의 세부 비트 해석("Large Band, Res=64")은 본 세션에서 데이터시트 PDF로 직접 재검증하지 않았고, 과거 작업(20260619 종합 §2.1)의 인용을 그대로 전달했다 — [문서 근거, 1차 재검증 아님]으로 표기함.
- `fake_func_sleep()`이 실제로 은수님이 프로파일링에 쓰는 경로가 맞는지는 코드 사실로부터의 **강한 정황 추정**이며, 100% 확정은 아니다(§11 "가설" 표기). C1 또는 은수님 확인 필요.
- I2C 실제 SCL 426.7kHz 수치는 2026-07-02 작업 이력의 검증 결과를 재인용했고, 본 세션에서 오실로스코프 등 실측으로 재확인한 것은 아니다(코드/헤더 공식 기반 재계산만 수행).
- Beta 레지스터(0xB0/B1/B2/B4) 정수값의 "damping=값/256" 해석은 과거 문서의 [실측 게이트] 미해결 항목이 그대로 남아있다 — 본 인벤토리는 현재 write값(0x02/0x06/0x02/0x0A)만 사실로 기록하고 해석 확정은 보류한다.
