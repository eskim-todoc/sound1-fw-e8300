# 18 · V8 — S8 검증 (조합·시스템 전략, 적대적 검증)

**TL;DR**: S8의 핵심 진단(fake_func_sleep 대 func_sleep 차이, I2C SCL 128k/426.7k, busy-poll, C1 H1 반증)은 코드·데이터시트 직접 재확인으로 **거의 전부 확립** — 드물게 탄탄하다. 1~3단계 최소패키지(R1~R8)는 C2 8대 불변식 위반 0건·SW-only 확정·인용 레지스터(0xC0 bit7·0xC1·0x31·0x61) 전부 실재. 다만 R7 "0xC0 write 5곳" 인용사슬 단절(S3="4곳" 오류·S8 자체 §3.1 미존재, 코드실측=6곳 중 ack_reset 제외 5곳), R4의 계측가시성 트레이드오프 미명시, Phase 3 오인용 등 3건의 정밀성 결함을 발견 — **기각 아닌 조건부 채택**을 권고한다.

## 3. 핵심 발견 — R7 "0xC0 write 5곳" 인용사슬 단절 [신규 발견, 코드로 확정]

코드 전수 grep(`write_register(REG_SYSTEM_CONTROL, ...)`, `tdc_touch_iqs323.c` 전체 + `REG_SYSTEM_CONTROL`/`0xC0` 전체 src 트리) 결과, 실제 write 사이트는 **6곳**:

| # | 위치 | 값 | 비고 |
|---|---|---|---|
| 1 | `ack_reset()` :237 | 0x01,0x00 | bit7=0(미포함), 직후 다른 write로 즉시 덮임 |
| 2 | `beta_power_settings()` :318 | 0x50,0x07 | 부팅 1회 |
| 3 | `apply_settings()` boot Re-ATI :447 | 0x54,0x07 | 부팅 1회 |
| 4 | `apply_settings()` boot RESEED :453 | 0x58,0x07 | 부팅 1회 |
| 5 | `tdc_touch_iqs323_re_ati()` :465 | 0x54,0x07 | **런타임 반복 호출** |
| 6 | `tdc_touch_iqs323_reseed()` :471 | 0x58,0x07 | **런타임 반복 호출** |

원 출처 05_S3(§5, 후보_3)는 "**4곳**"이라 서술하며 목록에 "공개 `re_ati()`/`reseed()`"를 **한 항목으로 묶어** 사실상 5번째 사이트를 통계에서 누락시켰다(리스트는 4개 이름이지만 마지막 이름이 실제로는 2개 함수). S8은 이를 "**5곳**"으로 인용하며 "§3.1 상세"를 근거로 들었으나, **S8 자신의 문서에는 §3.1이라는 하위섹션이 존재하지 않는다**(실제 §1.1/1.2/1.3만 있음). 즉 S3(4)→S8(5)→코드실측(6, ack_reset 제외 시 5) 사이에 숫자가 두 번 바뀌었고 그 경로 중 어느 것도 명시적으로 재검증되지 않았다.

**재확인**: ack_reset()의 bit7 누락은 기능적으로 무해할 개연성이 높다(리셋 직후 즉시 다른 write들이 그 값을 덮어써 Full ATI/터치 판정이 실질 개시되기 전에 이미 정정됨) — 따라서 "5곳(ack_reset 제외)"이 실질적으로 맞는 답일 가능성이 크다. 그러나 이는 **본 검증에서 처음 명시적으로 재확인한 것**이며, S8·S3 어느 문서도 이 근거를 문장으로 남기지 않았다. **INV-X-1이 정확히 경고하는 "하나라도 누락 시 조용한 회귀"의 재발 경로가 인용 단계에서 이미 한 번 발생했다**(4→5 사이의 재계산 근거 미기재) — 이는 R7 개념 자체를 반증하지 않으나, **구현 착수 전 전체 파일 grep으로 사이트를 직접 재확인하라**는 실측 게이트를 하나 추가해야 한다.

## 4. (c) SW-only·HW 무수정 검증

R1~R13 전 항목을 `write_register`/`i2c_set_master_prescale`/`ci_power_sleep` 계열 호출 재확인 결과, **PCB·부품·배선을 요구하는 항목 0건** — 전부 e8300 C 코드 변경 또는 IQS323 I2C 레지스터 값 변경으로 실현 가능함을 확인. R1이 `func_sleep()`(실제 절전) 코드까지 건드리는 유일한 항목이라는 서술도 코드로 확인(다른 레버는 `fake_func_sleep()` 전용 지역 코드 또는 `apply_settings()`/`beta_power_settings()`의 레지스터 값만 변경). **swOnlyConfirmed = true.**

| "제어 재설계 분석·권고.md Phase 3" (S8 §5 실측게이트2 인용) | R7 실측게이트 | 원문 §3 로드맵의 "Phase 3"은 **RDY edge ISR 이벤트모드(폴링 폐지)·DIO16 파워버튼 통합** 항목 — S8이 의도한 "Event mode 전류측정"은 실제로는 같은 문서 **§4 실측게이트 #2**("Event mode 실보드 NP/LP 전류")임. 두 항목은 관련은 있으나(RDY·이벤트 개념 공유) 서로 다른 층위(CM3 ISR 처리 vs IQS323 자체 인터페이스 모드) | **경미 오인용 — 게이트 대상 자체는 실재, 인용 번호만 정정 필요** |

**종합**: 인용된 모든 레지스터·비트는 실재하며 서술과 정확히 일치 — **레지스터 차원의 "할루시네이션"은 0건**. 유일한 결함은 §3(사이트 개수)·§5(문서 내 항목번호) 두 곳의 **인용 정밀도** 문제이며, 둘 다 "존재하지 않는 것을 존재한다고 서술"이 아니라 "존재하는 것을 잘못된 라벨/개수로 가리킴"에 해당한다.

## 핵심 결론 (3~5줄)

1. S8이 자신의 근거로 삼은 코드 사실들(`fake_func_sleep()` vs `func_sleep()`의 SYSCLK·I2C·QCC·NRF·리부팅 경로 차이, C1 H1 반증, busy-poll 구조, 타이밍 상수 12.5~37.5배)은 본 검증에서 소스 직접 재확인으로 **전부 재현**됐다 — 표본 검증 범위에서 반증된 항목이 없다는 것 자체가 이례적으로 강한 신뢰도다.
2. 1~3단계 최소패키지(R1~R8)는 C2 8대 불변식을 명시적으로 위반하지 않으며, 인용된 IQS323 레지스터(0xC0 bit7·0xC1·0x31·0x61)는 전부 데이터시트에 실재해 "확정처럼 쓴 미확인"은 발견되지 않았다.
3. 유일하게 실질적인 결함은 **R7의 "0xC0 write 5곳" 수치가 근거 문서(S3=4곳, 인용처=존재하지 않는 §3.1)와 어긋난 채 그대로 통과됐다**는 점이다 — INV-X-1이 경고하는 "하나라도 누락하면 조용한 회귀"가 인용 단계에서 이미 발생할 뻔했다(본 검증에서 6곳/ack_reset 제외 5곳으로 직접 확정).
4. R4(ATI 버스트 중 계측 생략)는 판정 로직엔 무해하나 "가장 보고 싶은 순간의 관측을 줄인다"는 연성 트레이드오프가 있고, S8 §5의 "Phase 3" 인용은 원문서의 다른 항목(§4 실측게이트#2)을 가리켜야 한다 — 둘 다 기각 사유는 아니나 구현 전 정정 대상이다.
5. 지배 애그레서 자체는 S8도 인정하듯 여전히 미확정이며, R1~R8은 "무엇이 원인이든 유효한" 보험적 포트폴리오다 — 배포 후 실측으로 효과를 확인하기 전까지는 "저감될 것"이 아니라 "저감될 가능성이 높고 위험은 낮다"로 읽어야 한다.
