# 11 · V1 — S1(변환주파수) 검증

**TL;DR**: S1 후보(0x31 Period 5→12, 1.00MHz→500kHz)의 핵심 사실 주장을 소스코드(`tdc_touch_iqs323.c` 전체)·데이터시트 원문 3편과 전수 대조 검증했다. 레지스터 주소·비트·기본값·Table A.1 수치·write_register 바이트 순서·라인번호(316) **전부 정확**, 조작 가능성·회귀 위험 새로 발견 없음. 단 (1) "500kHz가 데이터시트 typical값"이라는 프레이밍은 다소 과장(공용 측정조건일 뿐), (2) Auto Prox Cycle Select 미확인 리스크는 Power Mode 이름("Automatic No ULP") 자체가 이미 관련성을 시사해 격상 필요. **refuted=false, 조건부 채택**(실측 스윕 선행) 권고.

---

## 0. 검증 방법

지시받은 4개 노드(00·01·02·03) 정독 후, S1이 인용한 **1차 근거를 직접 재확인**했다 — 소스: `tdc_touch_iqs323.c`(전체 500행)·`tdc_touch_iqs323.h`·`tdc_touch_logic.c`(발췌)·`main.c`(발췌, grep). 데이터시트: `03_하드웨어설정.md §6.4·6.5`·`06_레지스터레퍼런스.md §9+A.6+A.9+A.12+A.30`·`01_개요·전기·타이밍.md §2·§3.4·§4.3`. 인용 아닌 부분(02_proxfusion동작.md 등 ATI 내부 알고리즘 세부)은 본 검증 범위 밖으로 별도 표기.

## (a) 실제 저감 근거 — 재반박 시도

| 메커니즘 | S1 자체 평가 | 본 검증 재확인 | 판정 |
|---|---|---|---|
| 메커니즘_1(결합임피던스) | "거의 무관"(자기비판) | 관측교란.md §4 원문 직접 재확인: "f(**애그레서** 주파수)가 높을수록 Z_결합↓" — f는 명시적으로 애그레서(SPI/SYSCLK) 정의, IQS323 자신의 Fxfer가 아님. S1의 자기비판은 원문 정의와 **정확히 일치** — 과장 아니라 정확한 재평가 | **반박 불가**(S1 스스로 이미 정확히 인정) |
| 메커니즘_2(윈도우 노출) | "역방향 트레이드오프"(하향 시 불리) | 재검토: 애그레서(수십 MHz)가 IQS323 Fxfer(수백 kHz)보다 훨씬 빠르므로, 윈도우 내 "충돌 여부"가 아니라 "**누적 주입 전하**"가 문제 — 창이 길어질수록(Fxfer↓) 같은 연속 애그레서에 노출되는 총 시간이 늘어 누적 주입량 증가. 애초 논리보다 더 강한 근거로 **동일 결론(하향=불리) 재확인** | **반박 불가, 오히려 근거 보강** |
| 메커니즘_3(에일리어싱) | "부합하나 근사치"(SPI 미확인·공차±5.5%) | 확인된 두 상수(SYSCLK 30.72MHz, Table A.1 주파수값)만으로 정수배 근접도 계산: 30.72MHz/1.00MHz=30.72(정수거리 0.28) vs /500kHz=61.44(거리 0.44, **현재보다 양호**) vs /389kHz=78.97(거리 **0.03, 정수에 매우 근접 — 최악**) vs /280kHz=109.71(거리 0.29, 현재와 대동소이). **[본 검증자 도출, 미확인 가정 포함]**: SYSCLK가 유일/지배 애그레서라는 전제하의 근사 지표일 뿐, 실제 지배 애그레서는 C1이 SPI(미확인 주파수)일 가능성도 병기함 — 확정 아님 | **반박 불가. 추가로 S1-2 후보 중 Period=16(389kHz)은 SYSCLK 대비 최악 근접값이라는 신규 주의사항 발견** — S1-3 실측 스윕에서 389kHz는 우선순위 하향 권고 |

**종합**: (a)를 반박하는 데 실패했다. S1은 이미 스스로 메커니즘_1 무관·메커니즘_2 역효과를 정직하게 인정했고, 메커니즘_3만 남는데 이는 "확정 저감"이 아니라 "통계적으로 이격, 근거는 약함"이라는 S1 자신의 결론과 일치한다. 새로 발견한 것은 반박이 아니라 **정밀화**(389kHz 후순위화) 뿐이다.

> [!NOTE]
> 부가 확인: §3.4 원문 "측정 조건: ... Self-cap·Mutual ATI Target=**512**, Fxfer=500kHz"를 직접 대조했다. S1의 "데이터시트 자체가 typical로 삼는 값"이라는 인용은 **문자 그대로는 정확**하나(원문 그대로), 이 조건은 self-cap 전용이 아니라 **self-cap+mutual 공용 단일 측정 조건**이며 ATI Target도 실제 코드값(400)과 다른 512다. "그러므로 임의성이 줄어든다"는 해석은 **다소 과장** — 사실 인용은 맞지만 수사적 비중이 근거 강도보다 크다. 채택 여부에 영향 없는 표현 수위 문제로만 기록한다.

## (b) C2 불변식 무손상 — 가장 중요, 전수 재확인

`tdc_touch_iqs323.c` 전체(500행)를 직접 읽어 0x31(`REG_CONV_FREQ`) 관련 **모든** 코드 경로를 확인했다.

|---|---|
| 0x31 write는 `beta_power_settings()` **단 1곳**(:316), 부팅 1회만 호출 | 코드 전체 grep 결과 write_register(REG_CONV_FREQ,...) 호출부 1건뿐 |
| 0x36(ATI Setup)·0xC0(System Control/Re-ATI/RESEED)·0x62(Touch threshold)·0x33(미기록)은 **전부 별도 주소, 별도 함수**(`apply_settings` 내 순차 호출이지만 변수·조건 공유 없음) | :437(0x36), :447/453/465/471(0xC0), :289(0x62 via touch_settings) |

## (c) 진짜 SW-only·HW 무수정인가

**확인**: 변경은 `write_register(REG_CONV_FREQ, 0x7F, 0x05)` → `write_register(REG_CONV_FREQ, 0x7F, 0x0C)` I2C write **값** 변경 1건뿐(:316). PCB·소자·배선·핀 배정 전혀 불변. write_register 시그니처(`addr, lsb, msb`)·i2c_write 바이트 순서(addr→lsb→msb)를 직접 추적해, 제안된 0x0C가 MSB(=A.6 bits 15-8=Period 필드)에 정확히 대응함을 재확인 — 코드 변경 기술 자체에 오류 없음. **(c) 완전 충족**.

## 실측 게이트 (배포 전 필수)

1. **[신규 격상]** Power Mode="Automatic No ULP" 상태에서 Auto Prox Cycle Select(0x33, reset=32)가 CH0 read_status 경로에 실제 적용되는지 — RDY 윈도우 실측(오실로스코프 또는 RTT 타임스탬프)으로 §6 소요시간 추정치(~0.4~1.43ms)를 최대 32배까지 재검증. 45ms/20ms 타임아웃·1.25s ATI 블로킹 캡과의 여유를 확인하기 전에는 500kHz든 현행 1MHz든 **소요시간 가정 자체가 불확실**.
2. SNR 실측 재확인(raw≥20counts, AZD125 §10.1 규칙) — Fxfer 변경 후 노이즈 플로어 변화 확인.
3. S1-3 실측 스윕(Period 7/12/16/23) 수행 시 **389kHz(Period 16)는 SYSCLK(30.72MHz) 정수배 근접도가 최악**(본 검증 신규 발견)이므로 우선순위 최하위로 재조정 권고 — 500kHz(Period 12)·280kHz(Period 23)를 우선.
4. 정확한 SPI(NRF 마스터 구동) 클럭 주파수 확인 — 메커니즘_3 정량 판단의 최종 병목(C1·S1 공통 지적, 본 검증도 동일 결론).
5. 부팅 Re-ATI 총소요시간(1.25s 캡) 여유 실측 — Fxfer 하향 시 IC 내부 ATI 탐색이 비례 지연될 가능성(본 검증에서 물리적으로 타당함을 재확인, §6 트레이드오프 표 그대로 유효).

## 핵심 결론 (3~5줄)

1. S1-1(0x31 Period 5→12, `tdc_touch_iqs323.c:316` 1바이트 변경)의 모든 사실 주장(레지스터 주소·비트·기본값·Table A.1 수치·write_register 바이트순서·라인번호)을 소스코드와 데이터시트 원문에 직접 대조해 **전부 정확함을 확인**했다 — 반증 시도는 실패했다.
2. C2 11대 불변식 중 코드 경로 직접 추적으로 **9개 무손상을 재확인**했고 위반은 0건이다. 2개 주의 항목 중 INV-⑦(공통 폴링 타임아웃 여유)은 Power Mode 레지스터 값("Automatic No ULP")과 Auto Prox Cycle Select 필드명("Auto Mode")의 문자적 일치를 근거로 **실측 우선순위를 격상**해야 한다는 것이 본 검증의 신규 기여다.
3. (a) 실제 저감 근거는 메커니즘_1엔 무관(S1 스스로 정확히 인정, 본 검증도 원문 정의 재확인으로 동의), 메커니즘_2엔 역효과(하향 시 노출 누적 증가, 더 강한 논거로 재확인), 메커니즘_3에만 근사 부합 — "확정 저감"이 아니라 "낮은 위험의 실험적 완화"라는 S1의 자체 평가가 본 검증에서 **정확했음이 확인**됐다.
4. 신규 발견(반박은 아니고 정밀화): SYSCLK(30.72MHz)와의 정수배 근접도를 직접 계산하면 S1-1(500kHz)은 현재값(1MHz)보다 오히려 근접도가 낮아(양호) 근거가 소폭 보강되는 반면, S1-2의 389kHz(Period 16) 옵션은 근접도가 최악이라 S1-3 실측 스윕에서 우선순위를 낮춰야 한다.
5. **refuted=false, 조건부 채택 권고** — HW 무수정·SW-only 완전 충족, 회귀 위험 없음(위반 0건), 근거는 약~중 수준. 실측 게이트(특히 Auto Prox Cycle Select 실경로 적용 여부) 통과를 전제로 낮은 리스크의 시험 적용 가치가 있다.

## 리스크·불확실성

| 항목 | 상태 |
|---|---|
| Auto Prox Cycle Select 실제 적용 여부 | **미확인** — 본 검증에서 개연성을 "가능"→"유력"으로 격상했으나 확정 아님. 최우선 실측 권고 |
| 지배 애그레서(SPI 클럭) 정확한 주파수 | **미확인** — C1·S1과 동일한 병목, 본 검증도 해소 못함 |
| SYSCLK 정수배 근접도 산술(§(a) 표)의 물리적 타당성 | **[본 검증자 도출]** — 애그레서가 SYSCLK 단독이라는 가정 위에서만 유효한 근사 지표, SPI가 지배적이면 이 계산은 무의미해질 수 있음 |
| ATI_TARGET Fxfer 무관성의 "이론적" 근거 | 본 검증의 물리 추론(사이클수 개념)이며, IC 내부 ATI 알고리즘 원문(02_proxfusion동작.md)으로 직접 재확인하지는 않음 — 결론 방향은 S1과 일치하나 근거의 최종 출처는 [추론]으로 표기 |
| 500kHz 프레이밍("데이터시트 typical값")의 수사적 과장 | 사실관계는 정확(원문 인용 일치), 해석적 비중만 과장 — 채택 판정에는 영향 없음 |
