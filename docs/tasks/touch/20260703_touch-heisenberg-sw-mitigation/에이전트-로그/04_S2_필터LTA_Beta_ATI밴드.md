# 04 · S2 — 필터·LTA·Beta·ATI밴드 (SW-only 후보 생성)

**TL;DR**: 레지스터 상수 튜닝만으로 두 갈래 효과가 나뉜다 — Counts Beta(0xB0)·LTA Normal Beta(0xB1) 상향은 "터치 오인식" 경로(필터를 통과하는 delta 판정)에 직접 유효하나, "ATI 에러 반복"은 ATI 알고리즘 자체가 필터를 우회해 소비하는 원시값으로 판정되므로 간접 효과만 있다(C1 §5 근거). Re-ATI 밴드는 레지스터상 이미 최대(Large 1/8)라 확장 여지가 없고, 우회 경로(ATI Target 상향)는 근거가 약해 비권장이다. Threshold/Hysteresis 상향은 실측 마진이 얇아 대폭 변경은 위험하다. 권고 우선순위: ① Counts Beta·LTA Normal Beta 소폭 상향(병행 실측) → ② Threshold 미세조정(SNR 재확인 후에만) → ③ ATI Band/Target·Hysteresis는 보류.

---

## 1. 이 레버 계열의 스코프·강점

- **전역 적용**: 본 절의 모든 후보는 `tdc_touch_iqs323_apply_settings()`(부팅 1회) 안의 상수 인자 값만 바꾸는 변경이다. IQS323은 노말·절전·프로파일링이 **완전히 동일한 레지스터 상태**를 공유한다(C2 §12 "절전 전용 settings 는 제거됨"). 따라서 이 레버는 `func_sleep()` 경로든 C2 §11이 발견한 `fake_func_sleep()` 경로든 **어느 쪽이 실제 프로파일링 경로인지와 무관하게 자동 적용**된다 — C2가 제기한 경로 불확실성에 영향받지 않는 몇 안 되는 레버 계열이다.
- **아그레서 비특정(agnostic)**: C1은 지배 애그레서(SYSCLK 12배·SPI·QCC·I2C 프리스케일 위반·`read_debug()` 자체 등)를 코드만으로 확정하지 못했다([미확인], C1 §3). 본 절의 후보는 "무엇이 찌르는가"를 몰라도 "얼마나 세게 반응하는가"만 조정하는 헤드룸 전략이라, 지배 애그레서가 무엇으로 밝혀지든 동일하게 작동한다는 것이 장점이다. 반대로 이는 근본 원인을 없애지 못하고 증상만 완화한다는 한계이기도 하다(§10 참조).
- **전역 적용의 대가**: 선택적으로 "프로파일링 중에만" 적용할 수 없다 — 정상 절전(현재 무증상)에도 동일하게 적용되므로, **정상 절전 회귀 검증이 모든 후보의 필수 게이트**다(§8·§9).

---

## 2. 선행 판단 — ATI는 필터를 우회한다 (모든 후보의 적용 범위를 가른다)

C1 §5 오염 사슬 다이어그램은 "터치 판정"과 "ATI 판정"이 **같은 원시 charge-transfer 변환**에서 출발하되 이후 갈라진다고 명시한다.

| 경로 | 흐름 | 본 절 레버 적용 여부 |
|---|---|---|
| 터치 판정(delta) | 원시 → Filtered Counts(0x13, **Counts Beta 통과**) → LTA(0x14, **LTA Beta 통과**) → delta → CH0_Touch | **직접 적용됨** — Beta가 그대로 이 경로에 있다 |
| ATI 판정(ati_error) | 원시 → **ATI 알고리즘(MULT/COMP 자동산출, Beta 우회)** → 완료 시점 counts가 Boundary 밖이면 SET | **직접 적용 안 됨** — ATI는 Counts/LTA Beta 필터링 이전의 원시값을 자체 알고리즘으로 소비 |

**함의**: 본 절 후보(Beta 상향)는 "터치 오인식" 증상에는 근거가 강하지만, "ATI 에러 반복"(700ms/7회 watchdog) 증상 자체 — 특히 C1이 지적한 "재시도해도 매번 같은 창에서 또 오염되는" 급성 현상 — 에는 **직접 효과가 없다**. 단, LTA Beta 상향은 IC의 **자동 Re-ATI 진입 빈도**(§5.10, LTA가 Band를 벗어나 자동 트리거되는 빈도)를 줄여 "애초에 위험한 재보정 구간에 덜 들어가게" 하는 **간접·예방적 효과**는 있다(§4). "이미 시작된 ATI 버스트 자체가 매번 오염되는" 급성 실패 자체를 고치는 것은 S1(변환주파수)·S4(타이밍 협조)·S6(FSM 라이드스루)의 몫이다 — 이는 억지로 여기서 해결한다고 주장하지 않는다.

## 3. 후보 1 — Counts Beta 상향 (0xB0)

| 항목 | 내용 |
|---|---|
| 현재 | `write_register(0xB0, 0x02, 0x02)` — NP/LP 공통 β=2 (`tdc_touch_iqs323.c:312`) |
| 제안 | `write_register(0xB0, 0x03, 0x03)` 또는 `0x04, 0x04` — AZD004 문서화 범위(§5.2, β=0~4) 안에서 단계적 상향 |
| 메커니즘 | Filtered Counts는 delta 판정의 직접 입력(§2). β를 올리면(α=1/2^β, AZD004 해석) 원시 샘플의 가중치가 줄어 단발성 코히런트 주입(메커니즘_1: 결합임피던스 증가로 인한 순간 전하 주입)이 delta에 반영되는 폭이 줄어든다. **단, 주입이 매 폴링 동일 위상으로 "항상" 겹치는 진짜 체계적 바이어스(메커니즘_2)라면 저역통과 필터는 이를 걸러내지 못한다**(상수 바이어스는 필터를 통과해도 그대로 남는다) — IQS323 자체 오실레이터·NRF SPI 클럭·CM3 SYSCLK가 서로 독립·비동기 클럭이므로([확립] 관측교란.md §5, "IQS323 내부 오실레이터: 자체(비동기)") 완전한 위상 고정은 물리적으로 유지되기 어렵다는 점에서, 겉보기엔 "매 폴링 급성"으로 보이는 현상도 미세 시간축에서는 위상이 서서히 흘러(사실상 메커니즘_3에 가까움) 필터가 부분적으로라도 감쇠시킬 가능성이 있다 — [가설-강, 물리적 추론], 확정 아님. |
| 트레이드오프 | 정착 시간 증가(응답 지연) — 다만 IQS323 NP 모드 내부 실제 report/scan 주기가 100ms SW 폴링보다 훨씬 빠른지 여부가 **미확인**(본 참고자료 범위에는 LP report rate=100ms만 문서화되어 있고 NP 주기는 없음) — 이 값에 따라 β=4가 100ms 폴링 내 충분히 정착하는지가 갈린다. **[실측 게이트]**: NP 내부 report 주기 확인 + β 단계별 실터치 정착시간 스코프 계측. |
| 리스크 | 낮음(코드 변경 폭 1줄, 기존에 명시적 근거로 방어된 값이 아니어서 — β=6 LTA처럼 "왜 6인가" 주석이 따로 없음 — 재조정 마찰이 적다) |

## 4. 후보 2 — LTA Normal Beta 상향 (0xB1)

| 항목 | 내용 |
|---|---|
| 현재 | `write_register(0xB1, 0x06, 0x06)` — β=6, τ≈12.8s (`tdc_touch_iqs323.c:313` 주석 근거) |
| 제안 | β=7(τ≈25.6s, **미검증 중간값** — 기존 주석은 4/6/8 세 값만 평가, 7은 아직 시도되지 않음) 우선 시험. β=8(τ≈51s)은 기존 주석에 "느림"으로 **이미 기각된 이력**이 있어 재채택 시 그 판단을 다시 여는 것임을 인지해야 함. |
| 메커니즘 | LTA는 mechanism_3(에일리어싱/맥놀이, 시간에 따라 값이 변하는 느린 beat)의 1차 피해자다(관측교란.md §4 메커니즘_3, "LTA가 못 쫓거나 잘못된 방향으로 쫓는다"). LTA Beta를 올리면 저역통과 컷오프가 낮아져 beat 주파수가 컷오프보다 낮을 때 그 진폭을 더 강하게 감쇠한다 — **시간에 따라 변하는 간섭(메커니즘_3)에는 유효**하나, §2에서 확인했듯 **ATI 자체의 급성 재오염(§2.1의 700ms/7회 현상)에는 미적용**. 부가로, LTA가 노이즈에 덜 흔들리면 §5.10 자동 Re-ATI 진입 빈도(즉 "위험 구간"에 들어가는 횟수) 자체가 줄어드는 간접 예방 효과가 있다. |
| 트레이드오프 | 기존 주석이 밝힌 트레이드오프가 그대로 적용된다 — 너무 느리면 "약결합 흡수" 지연(정상 환경 드리프트 재수렴 지연), 너무 빠르면(현 6도 이미 이 방향으론 여유 없음) 터치 흡수 위험. β=7은 미평가 지점이라 실측 없이는 "적당한 중간"이라는 것도 가설일 뿐이다. |
| 리스크 | 중간 — 이미 한 번 튜닝된 값을 다시 여는 것이므로, 회귀 시험(정상 절전 시나리오에서 기존처럼 잘 동작하는지)이 특히 중요하다. |

## 5. 후보 3 — Re-ATI 밴드 확대 (0x36 bit3) 및 ATI Target 상향 — 근거 약함, 비권장

**직접 레버(ATI Band bit)**: 레지스터-맵.md §4(A.12)에 따르면 ATI Band는 **1비트 이진 선택**(0=Small 1/16, 1=Large 1/8)뿐이다. 현재 코드는 이미 `0x36=0x040C`로 **Large(1/8)를 선택 중**이다(터치 임계·계수 레지스터 동작.md §6.3, [확립: 코드+데이터시트]). 즉 **오케스트레이터가 제시한 "Re-ATI 밴드를 넓힌다"는 방향의 레지스터 옵션은 이미 소진되어 있다** — 더 넓힐 선택지가 존재하지 않는다.

**우회 경로(ATI Target 상향 — Resolution Factor 0x36[15:4] 또는 ATI Base 0x37)**: Re-ATI Boundary = Target ± (1/8 × Target)이므로 Target 자체를 키우면 절대 카운트 폭은 넓어진다. 그러나:

1. **스케일 불변성 가설 [가설-강, 물리적 추론]**: Full ATI는 Mult/Comp를 자동 산출해 baseline counts를 Target에 맞춘다(터치 임계·계수 레지스터 동작.md §6.3). 이 Mult/Comp는 해당 채널의 **전체 아날로그 프런트엔드 이득**을 조정하는 것으로 보이며, 이 경우 전극에 물리적으로 주입되는 코히런트 간섭 전하(Q=C기생×ΔV, 관측교란.md §2)도 **같은 이득 체인을 통과**해 Target과 함께 비례 확대된다. 즉 Target을 2배로 올리면 실터치 delta도 약 2배, 간섭에 의한 카운트 편차도 약 2배로 늘어날 가능성이 높아 **상대적 여유(마진 비율)는 그대로**일 수 있다 — 이는 IC 내부 Mult/Comp 구현이 순수 이득(gain)인지 오프셋(offset) 위주인지에 대한 확증 없이 도출한 추론이며, **[미확인: IC 내부 ATI 알고리즘 세부 구현]**이 남아있다.
2. **구현 리스크**: 현재 코드는 0x37(ATI Base)을 **한 번도 write한 적이 없다**(POR 기본값 100에 의존, 그 보존 여부조차 [실측 게이트] 미해결, 터치 임계·계수 레지스터 동작.md §6.3). 신규 write를 추가하는 것은 검증 이력이 전무한 레지스터를 새로 건드리는 것이라, Resolution Factor(이미 write 중인 0x36 필드) 조정보다도 리스크가 크다.

**결론**: 이 방향은 "넓힌다"는 직관적 기대와 달리 근거가 약하고 구현 리스크도 있다 — **현행(Large 1/8) 유지를 권고**하며, 추가 헤드룸은 §3·§4(필터 Beta)에서 확보하는 것이 합리적이다.

## 6. 후보 4·5 — Threshold(k)·Hysteresis — 약한 후보

**Threshold 계수(0x62 LSB, 현재 k=80, 절대임계≈125 @LTA400)**: k를 올리면 delta가 더 커야 터치로 판정되어 간섭에 대한 여유가 생기지만, 이미 실측 마진이 얇다 — 코드 주석상 실측 최소 실터치 delta는 **160**이고, 현 절대임계 125는 그 78%다. 잔여 마진은 **35counts(160 대비 약 22%)뿐**이며, 이 마진은 실터치 검출력과 정확히 상충한다. 더구나 이 값(80)은 "158에서 수렴 실패 → 80으로 하향"이라는 **이미 한 번 실패를 겪고 되돌린 이력**이 있다(`tdc_touch_iqs323.h:46` 주석). k=84~86(절대≈131~134) 정도의 최소 침습적 미세조정만 방어 가능하며, 대폭 상향(예: k=100→156)은 실터치 마진을 거의 소진해 **비권장**이다. 이 후보를 쓰려면 INV-④-3이 요구하는 SNR≥5/raw≥20cnt 재확인이 선행되어야 한다.

**Hysteresis(0x62 MSB 상위 니블, 현재 H=8)**: 4비트 필드라 최댓값(15)에서도 실제 hyst는 절대임계의 **5.9%뿐**인 구조적 상한이 있다(터치 임계·계수 레지스터 동작.md §4). H=8→15로 올려도 실제 hyst는 약 3.9→7.3counts로 3~4counts 차이에 불과하다. 간섭이 threshold 부근에서 단속적으로(끊겼다 이어졌다) 나타난다면 아주 미미하게 "조기 release로 인한 카운터 리셋" 가능성을 넓히지만, 지속적(coherent, 안 끊기는) 간섭에는 hysteresis가 전혀 관여하지 않는다(release 판정에만 쓰이고 최초 트리거에는 무관). **효과가 작아 근거가 약한 후보**다.

## 7. 참고 — LTA Fast Beta(0xB2)·Fast Filter Band(0xB4) — 이 실패모드엔 접점 약함

C1 §2.2가 이미 지적했듯, Fast Filter Band(현재 10)는 **"sensing 반대 방향"(터치 방향과 반대, 즉 counts 증가/release 방향)으로만** Fast Beta(β=2, 빠름) 전환을 트리거한다(§5.6, [확립: 데이터시트 인용]). 이 비대칭은 버그가 아니라 **구조적으로 불가피**하다 — 만약 IC가 "터치 방향"으로도 빠르게 LTA를 따라가게 하면, 실제 터치 자체가 LTA에 흡수되어 버려 터치 판정 기능 자체가 무력화된다(실터치와 코히런트 간섭은 이 방향에서 LTA 입장에서 구분 불가능하다). 즉 "터치 오인식"(counts 감소 방향 간섭)에 대해 Fast Beta/Fast Filter Band 계열 레지스터로 대응하는 것은 **기능 정의상 불가능**하며, 이는 새로 지어낼 후보가 아니라 명시적으로 기각해야 하는 방향이다. Fast Filter Band를 넓히는 것은 release 방향 드리프트 회복 속도에만 영향을 주므로 본 실패모드의 주 레버가 아니다(부차적, 약함).

## 9. 정적 적용 vs 동적 전환 — 참고(S8 연계)

본 절 후보는 모두 **전역 상수를 한 번 바꾸는 정적 튜닝**이다. "프로파일링 중에만 더 둔감하게" 같은 **동적 전환**은 기술적으로 `public_touch_settings()`(현재 dead code, `#if 0`) 활성화로 가능해 보이지만, C2 INV-④-4가 명시하듯 이는 "기존 기능 재사용"이 아니라 **신규 기능 추가**로 분류된다 — 되돌리기(restore) 실패 시 잘못 튜닝된 상태가 영구화되는 새로운 리스크 표면이 생긴다. 본 절은 이 방향을 권고하지 않으며, 필요하다면 S8(조합·시스템 전략)에서 별도로 다뤄야 한다.

## 핵심 결론 (3~5줄)

1. Counts Beta(0xB0)·LTA Normal Beta(0xB1) 상향은 "터치 오인식" 증상(delta 판정 경로)에 근거가 있는 후보이나, "ATI 에러 반복" 증상에는 ATI 알고리즘이 이 필터들을 우회해 원시값을 직접 소비하므로(C1 §5) 직접 효과가 없고 자동 Re-ATI 진입 빈도를 낮추는 간접·예방 효과만 있다.
2. "Re-ATI 밴드를 넓힌다"는 오케스트레이터의 관심사는 레지스터상 **이미 최댓값(Large 1/8)이 선택되어 있어 확장 여지가 없다** — 우회 경로(ATI Target 상향)는 스케일 불변성 가설(신호와 간섭이 같은 이득 체인을 공유)로 실효가 의문시되고 구현 리스크도 커 비권장이다.
3. Threshold·Hysteresis는 구조적으로 마진이 얇다(Threshold 잔여 마진 약 22%, Hysteresis 최대치도 절대임계의 5.9%뿐) — 대폭 변경은 실터치 검출력을 잠식할 위험이 커 미세조정 이상은 권하지 않는다.
4. 본 절 모든 후보는 부팅 1회 상수 변경이라 절전 진입 시퀀스(INV-⑥)·L1 프로토콜(INV-⑦ 구조)·채널 구성(INV-⑧)·0xC0 비트 보존(INV-X-1)에는 **무손상**이지만, 노말·절전·프로파일링·`fake_func_sleep()` 전부가 같은 레지스터를 공유하므로 **선택 적용이 불가능**하고 정상 절전 회귀 검증이 모든 후보의 공통 필수 게이트다.
5. 이 레버 계열은 지배 애그레서가 무엇으로 밝혀지든(C1 §3, 4개 후보 미확정) 동일하게 작동하는 아그레서-비특정 헤드룸 전략이라는 것이 강점이며, 동시에 근본 원인을 없애지 못하고 증상만 완화한다는 한계를 함께 지닌다.
