# 15 · V5 — S5(GPIO 드라이브·슬루·주파수계획) 검증

**TL;DR**: S5 후보_1(I2C0 DIO 드라이브 8X→4X)·후보_2(SPI1 2X→1X)·후보_3(RDY 2X→1X) 전부 코드 재확인 + 벤더 데이터시트(Ezairo 8300 SDK, 로컬 설치본) 직접 대조를 통과했다 — **불기각(refuted=false)**. 단, 데이터시트 신규 확인 결과 I2C0/I2C1 DIO 모드가 "open collector"로 명시돼 있어 후보_1의 저감 범위가 SCL(상시 CM3 구동)·SDA 쓰기방향에 국한되고 상승엣지·IQS323 발신 read 응답엣지는 이 레버로 저감되지 않는다는 **중요한 신규 제약**을 발견했다. 조건부 채택 권고.

---

## 0. 검증 방법

지시된 4개 노드(00·01·07·02) 정독 후, 07(S5)이 인용한 모든 코드 경로를 **직접 재확인**했고, 07이 "본 저장소에 미포함"이라 밝힌 벤더 SDK(`sk5_hw_cid101.h`)와 공식 HW Reference 문서가 이 머신에 로컬 설치돼 있음을 확인해(`/mnt/c/Program Files (x86)/ON Semiconductor/Ezairo 8300 SDK/`) **1차 데이터시트로 교차 대조**했다. Sound1 저장소 안에는 없는 자료이므로 "본 저장소 미포함"이라는 07의 서술 자체는 정확하나, 이 세션에서는 접근 가능해 실현성 검증에 사용했다.

## 1. (a) 실제 저감 검증 — 부분 확증 + 중요 신규 제약

### 확인된 사실 [확립, 벤더 데이터시트 직접 인용]

| 확인 항목 | 출처 | 내용 |
|---|---|---|
| DIO 드라이브 필드 실재·순서 | `sk5_hw_cid101.h:12613~12616`, `hwref_IO_Pad_DIO_CFG.htm` | `DIO_CFG[13:12] DRIVE`, 값 0x0=1X/0x1=2X/0x2=4X/0x3=8X. "Nx drive strength" 표기로 순서 확정 — 07의 "[미확인이나 명명규칙상 확실]"을 [확립]으로 격상 |
| **I2C0/I2C1 DIO 모드는 오픈컬렉터** | `hwref_Interfaces_I2C.htm` "IMPORTANT" 단락, `hwref_IO_Pad_DIO_CFG.htm` IO_MODE 표 | "I2C interfaces are defined using **open-collector** pads... rely on the bus's pull-up resistors." `DIO_MODE_I2C0_SCL/SDA` 둘 다 "(open collector)" 명기. **07·C1·C2 어디에도 없던 신규 확인** |
| SPI는 오픈컬렉터 아님(push-pull) | 동일 IO_MODE 표 | I2C0/I2C1/I3C0/I3C1만 "(open collector)" 표기, SPI0/1_IO0~3·CS·CLK은 표기 없음 → 표준 push-pull |
| SPI 슬레이브 모드 CLK/CS 방향 | `hwref_Interfaces_SPI.htm` §SPI*_CLK·§SPI*_CS | "In slave mode, the SPI*_CLK signal is **sourced from a remote SPI master device**", "SPI*_CS pad is an **input** sourced from a remote SPI master device" — 07의 "SPI 클럭 주파수 선택 기각"을 코드 추론에서 **1차 데이터시트 확정**으로 격상 |
| MISO(CM3 유일 출력) | 동일 문서 §SPI*_IO[0:3], `DIO_MODE_SPI1_IO1`="slave SERO" | 슬레이브 모드에서 CM3가 구동하는 유일한 출력 데이터핀 = IO1("slave SERO") — 07의 "MISO만 CM3가 구동" 주장을 명칭 수준까지 확정 |

### 파생 결론 — 후보_1(I2C0)의 저감 범위는 07이 서술한 것보다 좁다

I2C0 SCL/SDA가 오픈컬렉터이고 `I2C_PIN_CFG_VAL_forDIO`가 `DIO_NO_PULL`(내부 풀업 없음)을 쓰므로, 이 버스의 **상승엣지는 전적으로 외부 풀업 저항의 RC 특성**에 의해 결정되며 **어떤 기기의 DIO 드라이브 설정과도 무관**하다. CM3의 드라이브 강도(8X→4X)가 실제로 저감하는 것은:

- **SCL 하강엣지**: CM3가 I2C0 마스터(`CM3_I2C_CFG_VAL_AsMaster`)이므로 SCL은 항상 CM3가 생성 → **전 구간 저감 적용**.
- **SDA 하강엣지 중 CM3가 쓰는 비트만**(주소·`force_window_open()`의 0xFF write 등) → 저감 적용.
- **SDA 하강엣지 중 IQS323이 응답하는 비트(read 페이로드, 즉 `read_status()`/`read_debug()`의 실제 데이터 바이트 대부분)**: IQS323 자신의 출력단이 구동 → **CM3 드라이브 설정과 무관, 저감 안 됨**(07 §1이 이미 "IQS323 쪽엔 드라이브 SW 레지스터 없음"이라 밝힌 사실과 정확히 같은 한계가 여기서도 재확인됨).

**결론**: 후보_1의 메커니즘_1 저감은 실재하나 "I2C0 버스 결합을 전반적으로 줄인다"가 아니라 "SCL 전체 + SDA 쓰기 방향만 줄인다"가 더 정확한 서술이다. `read_status()`는 읽기 위주 트랜잭션이라 SDA 데이터 바이트의 상당 부분이 이 레버로 저감되지 않는 잔여 애그레서로 남는다. 반대로 **후보_2(SPI1 MISO)는 push-pull이라 이런 제약이 없다** — 2X→1X는 MISO의 상승·하강 양쪽 엣지 모두에 완전 적용된다(07은 SPI1을 "효과 제한적 2순위"로 낮게 평가했으나, 그 사유는 BLE/OTA 공용 부담 때문이지 엣지 메커니즘 결함 때문이 아니었고, 엣지 메커니즘만 보면 오히려 후보_1보다 "완전하다"는 것이 이번에 새로 확인된 사실).

**RDY(후보_3)**: 표준 `DIO_MODE_GPIO_OUT`(push-pull), 오픈컬렉터 제약 없음 — 07의 "MCLR 시퀀스에만 잠깐 쓰이고 상시 애그레서 아님, 효과 미미" 평가는 그대로 유효.

### 판정: PLAUSIBLE(불기각) — 단, 정량 효과는 여전히 미확인이며 범위는 07 서술보다 좁음

물리 메커니즘 자체(`Z=1/2πfC`, 느린 엣지→고주파 성분 감소)는 확립된 사실이고 07의 코드 인용은 전부 정확했다. 다만 "이 버스의 결합을 낮춘다"는 표현은 이번 검증으로 "SCL과 CM3발 SDA만" 낮춘다로 정밀화되어야 하며, 이는 채택 여부를 뒤집는 반증이 아니라 **기대치 보정**이다.

## 2. (b) 기존기능 무손상 검증 — C2 8개 불변식 재점검

07 §4 매트릭스를 코드 직접 재추적으로 독립 재현했다. 추가로 확인한 사실:

| 확인 사실 | 근거 |
|---|---|
| DIO 드라이브 설정은 부팅 1회만 적용, 런타임 재설정 경로 0건 | `initialize.c:265`(`ci_dio_configure_normal()`, I2C0 8X 설정) / `:506`(`init_cm3_SPI()`, SPI1 2X 설정) — 둘 다 `Initialize()` 내부, `func_sleep()`·`fake_func_sleep()`(main.c 전체) grep 결과 `ci_dio_configure_*`·`init_cm3_SPI`·`Sys_I2C_DIOConfig`·`Sys_SPI_DIOConfig` 재호출 **0건** |
| `ci_dio_configure_sleep()`은 별개 함수(딥 셧다운용), 폴링 경로와 무관 | `initialize.c:206`, `Uninitialize()` 내부(main.c:848 `fake_func_sleep()`에서도 **주석 처리되어 미호출**, main.c 어디서도 능동 호출 없음) — I2C/SPI 핀을 `DIO_MODE_DISABLE`로 tri-state하는 별도 시퀀스라 100ms 폴링 중 절대 끼어들지 않음 확인 |
| 드라이브 강도 레지스터(`DIO_CFG`)와 SCL 주파수 레지스터(`I2C0->CFG` PRESCALE 필드)는 물리적으로 별개 레지스터 | `driver_i2c.c:145~159`(`i2c_set_master_prescale()`는 `I2C0->CFG`의 PRESCALE 필드만 RMW) — 드라이브 변경이 SCL 주파수·타이밍에 부수효과를 줄 경로 없음 |
| I2C0가 터치 외 최소 2~4개 기기와 공유(07 서술보다 넓음) | `grep i2c_startWriteData/ReadData` → `driver_MIS2DH.c`(가속도계)·`driver_REN_ISL9122.c`(PMIC)·`driver_MAX17262.c`(연료게이지 추정)·`dirver_i2c_for_ISD.c` 전부 동일 `driver_i2c.c`(I2C0 하드코딩) 경유 — 07은 PMIC+가속도계 2건만 언급했으나 실제로는 더 많은 파일이 동일 버스·동일 DIO 드라이브 설정을 공유 |

### 8개 불변식 재확인 결과 (독립 재현)

| # | 불변식 | 재확인 결과 |
|---|---|---|
| ① Full ATI 드리프트회피 | 무손상 — 0x36/0xC0 write 페이로드는 DIO 드라이브와 무관한 별도 레지스터(`tdc_touch_iqs323.c` 재확인) |
| ② 최초 터치해제 감지 | 무손상 — 순수 SW 카운터(`main.c` sleep_ignore/notouch_cnt), 전기 레이어와 무관 |
| ③ ATI 에러 시 Re-ATI | **주의**(07과 동일) — 통신 글리치율 변화는 기존 0xEE 처리(INV-④-2)로 흡수, 신규 실패모드 아님 |
| ④ 터치 판정 | **주의**(07과 동일) — 상동 |
| ⑤ 롱터치 | 무손상 — 카운터/래치 로직 불변 |
| ⑥ 절전 진입/기상 | 무손상 — 진입 순서(HW셧다운→클럭다운→I2C prescale→ULP타이머) 안에 DIO 재설정 단계 자체가 없음(부팅 1회 고정이 이 순서 밖에서 이미 끝나 있음) 재확인 |
| ⑦ 공통 폴링 경로(L1) | **주의**(07과 동일) — 45ms/20ms 타임아웃 마진은 실측 필요, 구조적 훼손 아님 |
| ⑧ 단일채널 구성 | 무손상 — CH enable 여부와 무관 |

**"충돌" 0건 — 독립 재확인으로도 동일 결론.** ③④⑦의 "주의"는 전부 "통신 글리치율이 오르면 어떻게 되는가"라는 동일 질문으로 수렴하고, 그 답은 기존 INV-X-2(read-fail-hold→NOT_TOUCH 강제)가 이미 처리하도록 설계돼 있어 **구조적 신규 위반이 아니라 확률적 마진 문제**다.

### 판정: regressionSafe = true (구조/로직 차원). 단, 배포 전 실측 게이트는 선택이 아니라 필수.

추가로, I2C0 공유 기기가 07 서술보다 넓다는 점(위 표)은 C2의 8개 터치 불변식 범위 **밖**이라 `regressionSafe` 판정 자체는 바꾸지 않으나, 배포 전 점검 목록에 반드시 포함시켜야 할 항목으로 격상해 리스크 표에 반영한다.

## 3. (c) SW-only·HW 무수정 검증 — 완전 확증

- 변경은 `DIO_PIN_Config.h`의 매크로 상수 값(비트 조합) 교체 1건뿐(`I2C_PIN_CFG_VAL_forDIO`: `DIO_8X_DRIVE`→`DIO_4X_DRIVE`). PCB·부품·배선·풋프린트 변경 전무.
- `DIO_4X_DRIVE`는 이미 코드베이스에 존재하는(단, 다른 매크로 `CM3_I2C_MASTER_PIN_CFG_VAL`에서 미사용 상태로 정의만 돼 있는) 실제 값 — 신규 심볼 추가 없음. grep으로 `CM3_I2C_MASTER_PIN_CFG_VAL` 사용처 0건 확인(07의 "dead code" 주장 확증).
- SPI1(후보_2)·RDY(후보_3)도 동일하게 매크로 값 교체뿐.

### 판정: swOnlyConfirmed = true

**refuted = false.** 세 후보(I2C0 8X→4X 1순위, SPI1 2X→1X 2순위, RDY 2X→1X 부차) 모두 반증되지 않았고, 오히려 이번 데이터시트 교차대조로 07이 스스로 [미확인]이라 낮춰 잡았던 여러 항목(SPI 슬레이브 확정, MISO 단독구동, 드라이브 순서)이 1차 사양으로 격상됐다. 유일하게 새로 발견된 제약(오픈컬렉터)은 채택을 막는 반증이 아니라 **기대 효과 범위를 정밀화하는 정보**이며, 오히려 SPI1(후보_2)이 메커니즘상 07 평가보다 "더 완전하게" 작동함을 보여준다.

## 핵심 결론 (3~5줄)

1. S5 후보 3종 전부 **불기각(refuted=false)** — 코드 인용 100% 정확, 벤더 데이터시트(로컬 설치본) 직접 대조로 SPI 슬레이브·MISO단독구동·드라이브 순서 등 다수 항목이 [확립]으로 격상됐다.
2. **신규 발견**: I2C0/I2C1 DIO 모드는 데이터시트상 "open collector"(내부 무풀업 설정과 결합) — 후보_1(I2C0 8X→4X)의 실제 저감 범위는 "SCL 전체 + SDA 쓰기방향"에 국한되고 "SDA 읽기방향(IQS323 발신)·모든 상승엣지"는 이 레버로 저감되지 않는다. 반증은 아니고 기대치 정밀화다.
3. 반대로 **SPI1(후보_2) MISO는 push-pull**이라 이런 제약이 없어 07의 낮은 평가("효과 제한적")와 달리 엣지 메커니즘만 보면 오히려 더 완전하게 작동한다(단, BLE/OTA 공유 리스크는 07 평가대로 유효, 확인 결과 공유 파일 수가 07 언급보다 더 많음).
4. C2 8개 불변식은 독립 재확인으로도 "충돌 0건" — 구조적으로 regressionSafe=true. 단 ③④⑦의 "주의"(통신 마진)는 실측 게이트 통과가 배포의 필요조건이며, 이는 07도 이미 명시한 사항이라 신규 리스크가 아니다.
5. I2C0가 터치 외 PMIC·가속도계·(추정)연료게이지까지 공유한다는 사실이 07 서술(2건)보다 넓게(최대 4건) 확인돼, 배포 전 점검 범위를 그만큼 넓혀야 한다.
