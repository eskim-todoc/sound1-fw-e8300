# 00 · 오케스트레이터 입력 (fan-out 설계)

**TL;DR**: 현 셀프캡·현 HW·현 아키텍처 유지, SW 운영만으로 절전 프로파일링(QCC on+SPI+30.72MHz) 클럭/SPI 결합 교란을 회피하는 법 탐색. ① 특성화 2노드(실패 메커니즘·기존기능 인벤토리) 병렬 → 배리어 → ② 해법 레버 8노드를 pipeline: 각 레버가 SW-only 후보를 생성(노드 기록)하면 곧바로 adversarial 검증(기존기능 무손상·실제저감·SW-only·데이터시트 실현성)이 이어짐 → ③ 오케스트레이터가 종합·권고로 fan-in.

## 문제 정의 (한 줄)

> 현 셀프캡(CRX0 단일, Full ATI + 최초 터치해제 + Re-ATI)을 그대로 두고, HW 수정 없이 SW 운영만으로 절전 프로파일링 구성의 클럭/SPI 결합(하이젠베르크) 교란을 회피할 수 있는가? 있다면 어떤 조합이 기존 기능을 전부 만족하며 가장 강건한가?

## 공통 컨텍스트 (모든 노드 전제)

- **하이젠베르크 3메커니즘**(관측교란.md): ① 결합임피던스 `Z=1/(2πfC기생)`(고주파일수록 결합↑), ② 샘플링 윈도우 일치(애그레서 엣지가 변환 윈도우 안이면 counts 오염), ③ 에일리어싱/맥놀이(애그레서 f가 샘플레이트 배수 근처면 느린 드리프트). 2경로 — 경로_1 접지, 경로_2 스위칭.
- **실패 조건**: 정상 절전(2.56MHz·QCC off)은 노말 계수로 OK. **프로파일링(QCC on·30.72MHz·BLE+SPI)에서만 ATI 에러·터치 오인식→노말 재부팅**. 즉 애그레서(고클럭·SPI 버스트)가 늘어난 구성에서 깨짐.
- **현 IQS323 설정(근거 확인 대상)**: 변환 0x31=0x057F(1MHz), ATI 0x36 Full, Beta 0xB0/B1/B2/B4, Power 0xC0계열, Events 0xD3, 폴링 200ms/롱터치 등. 단일채널 CH0.
- **제약**: HW 무수정 · 기존 기능(드리프트회피·Full ATI·최초 터치해제·Re-ATI·터치/롱터치·절전 진입/기상) 전부 만족 · mutual 제외 · SW/설정(e8300 FW + IQS323 레지스터)만.

## 검증 주장(레버별 stage2 공통 틀)

각 후보에 대해: (a) 하이젠베르크(경로_2/해당 메커니즘) 실제 저감 근거 있나? (b) 제약_2 기존 기능 **전부** 만족하나(하나라도 훼손 시 실격)? (c) 진짜 SW-only·HW 무수정인가? (d) IQS323 데이터시트·e8300으로 실현 가능한가? → refuted 여부·잔여 불확실성·실측 게이트 반환.
