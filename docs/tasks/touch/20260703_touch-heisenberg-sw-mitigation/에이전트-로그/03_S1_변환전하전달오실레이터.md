# 03 · S1 — 변환·전하전달·오실레이터

**TL;DR**: IQS323에서 실제 조정 가능한 레버는 변환주파수(Conversion Frequency, 0x31 MSB) 단 하나다 — 전하전달 주파수는 동일 레지스터의 동의어이고, 오실레이터는 SW 조정 레지스터·외부 동기 핀 자체가 없다(확인). 현재 1.00MHz(자기용량 권장 상한, 마진 0)를 데이터시트 자체 기준값인 500kHz로 하향하는 안을 주 후보로 제시한다. C2 8대 불변식은 전부 무손상이나 2건 주의, 정확한 SPI 클럭 미확인으로 효과는 실측 검증에 달려 있다.

---

## 0. 범위 정리 — 3개 키워드가 사실은 레버 1개

| 키워드(과업 지시) | 확인 결과 | 근거 |
|---|---|---|
| 변환주파수(Conversion Frequency) | 0x31 MSB(Period), **유일한 실질 레버** | 03_하드웨어설정.md §6.5 |
| 전하전달 주파수(Charge Transfer Freq) | 변환주파수와 **동일 개념**("charge transfer frequency(Fxfer, conversion frequency라고도 함)") — 별도 레버 아님 | 03_하드웨어설정.md §6.5 원문 |
| 오실레이터 설정 | SW 조정 레지스터 **없음**. f_OSC=14MHz(공차 13.23~14.77MHz) 내부 발진, 사용자 트림 레지스터가 메모리맵(0x00~0xE1) 전체에 없음 | 01_개요·전기·타이밍.md §4.3, 06_레지스터레퍼런스.md §9 |
| 외부 동기 여부 | **없음** — 3종 패키지(WLCSP11/DFN12/QFN20) 핀맵에 클럭 입력 핀 없음, 메모리맵에 sync 트리거 필드 없음 | 01_개요·전기·타이밍.md §2 Pin Diagrams, 06_레지스터레퍼런스.md §9 전체 |

**결론**: e8300 SYSCLK/SPI와 IQS323 Fxfer는 **완전 비동기**(독립 발진, 위상관계가 시간에 따라 계속 표류) — "SW로 동기시킨다"는 옵션 자체가 존재하지 않는다. f_OSC가 크리스탈이 아니라 내부 RC로 추정되는 근거는 핀맵에 크리스탈 핀이 없고 공차(±5.5%)가 RC 특성 범위이기 때문이나, 데이터시트가 발진기 종류를 명시하지 않으므로 **[가설]**로 표기한다.

## 3. 후보

### 후보 S1-1 (권고) — Period 5→12, 1.00MHz→500kHz

- **메커니즘**: 현재 값은 자기용량 상한 경계(마진 0)에 있다. 500kHz는 데이터시트 §3.4가 자기용량 전류 특성 측정에 실제로 사용한 기준값 — "데이터시트가 스스로 typical로 삼는 지점"으로 이동해 임의성을 줄이고, 30.72MHz 계열 및 그 하모닉과의 산술적 관계를 현재값(1MHz)에서 바꾼다.
- **필요 변경**: `tdc_touch_iqs323.c:316` 한 줄만 `write_register(REG_CONV_FREQ, 0x7F, 0x05)` → `write_register(REG_CONV_FREQ, 0x7F, 0x0C)`. Fraction(0x7F) 불변. 그 외 코드 변경 없음.
- **C2 불변식 영향**: §4 매트릭스 참조 — 전부 무손상, 2건 주의.
- **실현성**: 긍정(코드 변경 최소, 데이터시트 부합). 단 "효과"는 실측 필요(§6 리스크).

### 후보 S1-2 (보수적 대안, 조건부) — Period 5→16 또는 23, 389/280kHz

- **메커니즘**: 아그레서(SYSCLK 30.72MHz 계열, 미확인 SPI 클럭)에서 주파수상 최대한 멀리 이격 — 통계적으로 우연한 정수배 근접 확률을 낮추는 방향.
- **트레이드오프**: §5에서 논하듯 변환 1회 소요시간이 늘어나 노출창이 커지는 역효과 동반 — S1-1보다 근거는 약하고 대가는 크다. S1-1로 불충분할 때의 2차 시도로 제시.
- **실현성**: 조건부 — S1-1 실측 후에만 판단.

### 후보 S1-3 (방법론) — 실측 스윕

- **메커니즘**: 정확한 애그레서 주파수(특히 NRF 구동 SPI 클럭)가 미확인이므로 분석적으로 "최적값"을 계산할 수 없다. Table A.1의 여유 옵션(7/12/16/23) 각각을 실제 프로파일링 하네스(QCC on·30.72MHz 유지·BLE+SPI) 하에서 순차 적용해 ATI 에러·오탐 발생률을 실측 비교하는 것이 데이터에 부합하는 접근.
- **실현성**: 긍정 — 별도 코드 불필요, 상수 1바이트 스윕 + 기존 RTT 로그 관찰만으로 가능.

## 4. C2 8대 불변식 영향 매트릭스 (S1-1/S1-2 공통 — Period 값만 다르고 write 경로는 동일)

| 불변식 | 영향 | 근거 |
|---|---|---|
| INV-①(Full ATI 드리프트회피) | **무손상** | 0x31은 0x36(ATI Setup)·Re-ATI 게이트 로직과 별도 레지스터, 상호 미접촉. ATI_TARGET(=BASE×Factor/16=400)은 Fxfer와 무관하게 정의(A.12) |
| INV-②(최초 터치해제 게이트) | **무손상** | `boot_ignore`/`sleep_ignore` 게이트·RESEED 동반 로직 모두 0x31 미접촉 |
| INV-③(ATI 에러 시 Re-ATI, 노말/절전 비대칭) | **무손상** | 0xC0 트리거·카운터 로직과 0x31은 독립 레지스터 |
| INV-④(터치판정 CH0) | **주의** | 비트맵(bit5/6/8/9)·임계공식(계수×LTA/256)은 불변(이론상 Fxfer 무관). 단 SNR≥5·raw≥20counts 규칙(AZD125 §10.1) 재확인 실측 권고 — Fxfer 변경이 노이즈 플로어를 바꿀 수 있음 |
| INV-⑤(롱터치 2400ms) | **무손상** | 100ms 폴링주기·CH0_Touch 비트에만 의존. 폴링 주기는 SW tick/HW 타이머가 결정하고 Fxfer는 IQS323 내부 1회 변환 소요시간만 결정 — 별개 레이어 |
| INV-⑥(절전 진입/기상 시퀀스) | **무손상** | 0x31 write는 `apply_settings()` 부팅 1회뿐(절전 진입 시 재write 없음, §11 기존 설계) — 클럭다운 이전 write 완료 요구사항과 완전 호환. 진입 순서·기상=리부팅뿐이라는 성격 불변 |
| INV-⑦(공통 폴링경로, 45ms/20ms 타임아웃) | **주의** | Fxfer 하향 시 IQS323 내부 1회 변환 소요시간이 늘어난다(§5). RDY 윈도우 open/close 타임아웃(45ms/20ms)과 개별 변환 시간이 근접할 가능성은 낮으나(추정치 최대 ~1.4ms, §5), Auto Prox Cycle Select(0x33, 미기록·reset=32)가 실경로 적용되는지 **미확인**이라 시간 추정에 최대 32배 오차 여지 — 실측 확인 권고 |
| INV-⑧(단일채널 구성) | **무손상** | CH1(0x41)/CH2(0x51) 자체 Conv Freq 레지스터는 미접촉, 두 채널 모두 Enable Channel=0 유지(disable) — 채널 수·전역 ati_error 등가 관계 불변 |
| INV-X-1(0xC0 비트 보존) | **무손상** | 0x31은 System Control(0xC0)과 별도 레지스터, 트리거 write 로직 미접촉 |
| INV-X-2(READ_FAIL hold 처리) | **무손상** | I2C 통신 프로토콜(레이어 분리) 자체는 Fxfer와 독립. RDY 타이밍 간접 영향은 INV-⑦에서 이미 다룸 |
| INV-X-3(디버그계측 read_debug 무해) | **무손상** | 0x13/0x14 read 경로와 0x31(변환주파수)은 무관 |

**요약**: 8개 기존기능 + 3개 교차불변식 **전체 11개 중 9개 무손상, 2개 주의(SNR 재확인·RDY 타이밍 여유), 0개 충돌**.

## 5. 하이젠베르크 3메커니즘 대응력 — 정직한 재평가

오케스트레이터 입력은 S1이 메커니즘_1·3을 회피한다고 프레이밍했으나, 근거를 직접 따라가면 다음과 같이 갈린다.

| 메커니즘 | S1의 실제 대응력 | 근거 |
|---|---|---|
| **메커니즘_1**(결합임피던스 Z=1/(2πfC기생)) | **거의 무관** — f는 **애그레서**(SPI·SYSCLK파생)의 주파수이지 IQS323 자신의 Fxfer가 아니다. Fxfer를 아무리 조정해도 애그레서 자체의 결합 임피던스는 바뀌지 않는다. [근거 약함 — 오케스트레이터 프레임과 배치되는 재평가] | 관측교란.md §4 메커니즘_1 정의 자체("f=애그레서 주파수") |
| **메커니즘_2**(샘플링 윈도우 일치) | **양날의 검, 순방향 여유 소진** — Fxfer는 1회 변환의 실제 노출시간을 정한다. 하향 조정(S1-1/S1-2)은 노출창을 **늘려 오히려 불리**해진다. 상향(창 단축, 유리)은 현재 이미 자기용량 상한이라 여유가 없다 | 03_하드웨어설정.md §6.5(RC 정착조건), §2 카운트=사이클수 개념 |
| **메커니즘_3**(에일리어싱/맥놀이) | **가장 부합하나 근사치 한계** — Fxfer를 애그레서 정수배 근처에서 이격시키는 것이 S1 본연의 취지. 단 (a) 정확한 애그레서 주파수(특히 SPI) 미확인, (b) IQS323 f_OSC 공차 ±5.5%로 소자·온도별 정밀 회피 보장 불가 — "통계적으로 멀어짐"이지 "확정 회피"가 아니다 | 01_개요·전기·타이밍.md §4.3 f_OSC 공차 |

## 핵심 결론 (3~5줄)

1. S1의 실질 레버는 **0x31 Conversion Frequency Period 단 하나**다 — "전하전달 주파수"는 동의어, "오실레이터 설정"·"외부 동기"는 애초에 SW로 조정할 여지가 존재하지 않음을 데이터시트로 확인했다(§0).
2. 주 후보(S1-1)는 현재 자기용량 상한(1MHz, 마진 0)을 데이터시트 자체 기준값(500kHz)으로 낮추는 것이며, 코드 변경은 1바이트 상수 1곳(`tdc_touch_iqs323.c:316`)뿐이다. C2 11개 불변식 중 9개 무손상·2개 주의·0개 충돌로, 기존 기능을 훼손할 위험은 낮다.
3. 다만 메커니즘별 대응력은 불균등하다 — 메커니즘_3(에일리어싱)에는 부합하나 근사치 수준(정확한 SPI 클럭 미확인 + IQS323 자체 공차 ±5.5%), 메커니즘_1(결합임피던스)에는 사실상 무관, 메커니즘_2(윈도우노출)는 하향 조정 시 오히려 노출창이 늘어나는 **역방향 트레이드오프**를 동반한다.
4. 따라서 S1 단독으로 "교란 제거"를 주장할 근거는 약하다 — "낮은 리스크의 실험적 완화 + 실측 스윕(S1-3)을 통한 데이터 기반 선택"이 정직한 결론이며, C1이 지목한 I2C 프리스케일 5배 초과 의심(H1)·`read_debug()` 이중 애그레서(H2) 같은 더 강한 근거의 후보들과 병행 검토를 권고한다.
5. 부팅 Re-ATI 블로킹 대기(1.25s 캡) 여유가 저주파 옵션일수록 줄어드는 부수 리스크가 있으나, 실패 시 경고 로그만 남기고 진행하도록 이미 설계되어 있어(코드 주석 "터치 중이면 정상") 기능 정지로 이어지지는 않는다.

## 리스크/불확실성

| 항목 | 상태 |
|---|---|
| 정확한 SPI 마스터(NRF 구동) 클럭 주파수 | **미확인** — 이것이 없으면 메커니즘_3 정수배 회피 계산이 근본적으로 불가능. 최우선 확인 권고 |
| IQS323 f_OSC가 내부 RC라는 추정 | [가설] — 데이터시트가 발진기 종류를 명시하지 않음, 핀맵 부재+공차범위로 추정 |
| Fxfer 변경 시 1회 변환 실제 소요시간 | **미확인** — 데이터시트에 사이클수 명시 공식 없음, §6 수치는 400count 가정 기반 추정치 |
| Auto Prox Cycle Select(0x33, reset=32)가 CH0 read_status 경로에 실제 적용되는지 | **미확인** — 적용된다면 §6 시간추정치가 최대 32배 과소평가일 수 있음. 04_부가기능·UI.md 추가 확인 필요(본 노드 1차 근거 범위 밖) |
| S1-1(500kHz)이 실제로 ATI 에러·오탐 발생률을 낮추는지 | **미확인** — 실측 게이트. 정확한 애그레서 주파수 부재로 분석적 사전 확정 불가 |
| 메커니즘_1에 대한 "거의 무관" 재평가 | 오케스트레이터 입력(00번 노드)의 프레이밍과 배치 — 본 노드가 근거를 좇아 하향 조정한 결론이며, 다른 레버(S1 외)의 프레이밍까지 부정하는 것은 아님 |
