# 계획 — SW-only 하이젠베르크 회피 권고

**TL;DR**: SW-only 회피는 **가능**하다. 지배 애그레서가 미확정이라 **P0 실측 게이트를 선결**하고, 회귀안전이 확인된 저위험 레버를 우선순으로 포트폴리오 적용한다: **P1 관측 탈침습(H2 read_debug 수정) → P2 드라이브 하향(S5) → P3 IQS323 자가 RDY토글 제거(S8/R7) → P4 변환주파수(S1) → P5 FSM 라이드스루 안전망(S6)**. 본 계획은 방향 결정 + 다음 단계 산출물이며, 제품 코드 변경(④)은 은수님 승인 후 별도 착수한다.

> [!IMPORTANT]
> 본 단계는 타당성 검토·계획이다. 아래 P1~P5의 실제 코드 구현은 **은수님 승인 후 별도 신규 작업(4단계)**으로 진행한다. 승인 전엔 tasks 문서만 존재.

## 1. 결론

- 셀프캡·현 HW·기존기능(드리프트회피·Full ATI·최초터치해제·Re-ATI·터치/롱터치·절전 진입/기상)을 **유지한 채 SW 운영만으로** 절전 프로파일링 교란을 회피할 **회귀안전 레버가 존재**한다. (상호용량 No-go와 대조 — "정말 없으면 포기"의 그 지점은 아니다.)
- 다만 **지배 애그레서(SPI/QCC/SYSCLK 중)가 미확정**이라, 어느 레버가 실제로 듣는지는 **실측(RTT/스코프)으로 확정**해야 한다. 미확정 상태로 배포하면 효과가 "개연성"에 머문다.
- 상세: [`분석.md`](분석.md) · [`에이전트-로그/99_종합.md`](에이전트-로그/99_종합.md).

## 2. 권고 포트폴리오 (우선순)

| 단계 | 조치 | 근거 레버 | 회귀 | 성격 |
|---|---|---|---|---|
| **P0** | RTT 로그로 ① 재현이 `fake_func_sleep()` 경로인지 ② 지배 애그레서 식별 ③ H1(I2C 5배)·H2(read_debug 자체 애그레서) 참 여부 확인 | C1·C2 | — | **선결 실측 게이트** |
| **P1** | 계측 `read_debug()` latch 버그 수정(combined_read 적용) 또는 프로파일링 중 스로틀/비활성 — "관측이 대상을 흔드는" 부분 제거 | H2, S4 | 안전 | 근본(관측 탈침습) |
| **P2** | GPIO 드라이브 하향(I2C0 8X→4X, SPI1 2X→1X) + 절전 I2C 프리스케일 의도값(122kHz) 복귀 검토 | S5 | 안전(게이트) | 물리 결합 저감(중~강) |
| **P3** | 0xC0 bit7 Interface Selection로 IQS323 자가 RDY 토글 제거 (0xC0 write 사이트 재grep + INV-X-1 준수 선결) | S8/R7 | 안전 | 배경 교란 제거 |
| **P4** | 변환주파수 조정(389kHz 최악 근접 회피) | S1 | 안전 | 샘플링 이격(약~중, 시험) |
| **P5** | F0-게이팅 라이드스루(**카운터 기반**)로 프로파일링 구간 재부팅 억제 | S6 | 조건부(카운터화) | 안전망(근본해결 아님) |

- **기각/보류**: S3 Events모드(I2C Lock-Up 에라타), S7 후보_1(FSM 100× 둔화 회귀). S2(필터·Beta)는 전제 [가설-강]·실측 3게이트 통과 시 조건부.

## 3. 왜 이 순서인가

- **P0 우선**: 애그레서·재현경로·H1/H2를 모르면 나머지는 "짐작 사격". RTT 한 번으로 이분법 판별 가능(저비용·고정보).
- **P1이 근본에 가장 가까움**: H2가 참이면 "관측 자체가 애그레서" — 이걸 제거하면 프로파일링이 대상을 안 흔든다(하이젠베르크의 정의 그 자체 해소). S4의 결론도 여기로 수렴.
- **P2·P3는 애그레서 무관 보험**: 무엇이 주범이든 결합·배경교란을 낮춤. 물리·데이터시트로 확립.
- **P5는 완충**: 근본 저감이 부족해도 짧은 ULP 문턱(700ms/2400ms)을 프로파일링 구간에 한해 늘려 재부팅을 막음. 단 기존 기능 훼손 없게 F0-게이팅+카운터 기반.

## 4. 은수님 결정 요청

1. **결론 수용**: "SW-only 회피 가능, 단 P0 실측 선결" 방향에 동의하시는지.
2. **재현 경로 확인(핵심)**: 절전 프로파일링이 실제로 `fake_func_sleep()`(BLE General Debug op_mode==1) 경로가 맞는지 — 이건 은수님 실험 구성만 아는 사실입니다. 맞다면 이 복제 경로도 대상에 포함합니다.
3. **어디까지 진행**:
   - (A) **P0 실측만 먼저** — RTT 로그로 애그레서·H1/H2 확정 후 재논의
   - (B) **P0 + P1(관측 탈침습)** 까지 착수
   - (C) **권고 포트폴리오 전체 구현 계획**(P1~P5)을 별도 작업으로 수립
   - (D) 특정 레버만 지정
4. **부수 정정**(선택): `tdc_touch_time.h` 재부팅 카운트 낡은 주석, IQS323-RESEED.md·적용가이드 문서 세대 불일치 경고 표기.

승인/선택 후, 고르신 범위를 별도 신규 작업(4단계)으로 착수하겠습니다. 실측(P0)은 은수님 환경 실행이 필요할 수 있어, 필요한 RTT 계측 항목을 정리해 드리겠습니다.
