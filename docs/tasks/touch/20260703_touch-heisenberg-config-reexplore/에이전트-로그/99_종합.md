# 99 · 종합 평결 — config/channel/measurement 재탐색

**TL;DR**: 제어 3거동만 불변·설정/채널/측정 자유로 넓혀 재탐색했으나, **fact-verified 결론은 "config/channel/measurement 레벨에 코히런트 AC(클럭/SPI) 노이즈 상쇄 해법이 없다"**. 은수님 1순위였던 **reference tracking은 데이터시트로 기각**(DC 드리프트만·touch 상태 게이팅), SW 차동(C-DUAL)은 **순차측정 확정으로 공통모드 전제 붕괴**. 완전성 비평(V6)이 IQS323 전체 레지스터맵+Azoteq 앱노트를 훑어 "상쇄 기능 전무, Azoteq도 SNR 마진만 제시"를 확정. 할루시네이션 감사 통과(단 **참고문서 오류 3건** 별도 발견). 검증이 "아닌 것"을 사실로 밝혀 엄한 고생을 막은 결과.

## 1. 후보 5종 판정 (전부 검증 통과 후 기각/약함)

| 후보 | AC 상쇄 | 판정 근거(사실) |
|---|---|---|
| **C-RT** reference tracking | **없음** | §7.3(p.26) 상쇄 대상=count drift/온습도뿐, clock/SPI/noise 어휘 전무. 상쇄가 "primary touch/prox 상태"에서만 작동(정의 게이팅) → idle 오인식에 원리적 무관. LTA만 조정·raw Counts 비교 무관(V1 신규 논거). **반증 4갈래 전부 실패, 할루시네이션 0** |
| **C-DUAL** SW 차동 | **약함→기각** | 데이터시트 원문(p.15·21)으로 **CH0-CH1 순차(시분할) 측정 확정** → "동일 순간 공통노출" 전제 붕괴. CRX0/CRX1 비매칭 라우팅·비대칭 배치(공통모드 미지지). D패드 동심구조 co-touch veto 위험 |
| **C-MEAS** 측정모드 | 약함~없음 | 평균화는 **코히런트 바이어스에 원리적 무력**(N샘플 동일 유입→평균 무효). 오버샘플(Auto Prox Cycle) 이미 최댓값. 변환주파수는 방향 예측 불가 |
| **C-FILT** 공격적 필터/ATI | 약함 | Threshold(계수)만 판정식 직접 개입(원리 생존)하나 과거 실패 이력(k=100·102 도달난)으로 **헤드룸 k≈80→85 거의 소진**. 나머지 레버 기각/무관 |
| **C-SYNC** 센서 동기 | 없음 | 외부 동기 불가(자유구동 오실레이터). Report Rate=duty 게이팅 가설 근거 미약. Events모드 I2C Lock-Up 에라타 위험 |

## 2. 완전성 비평 (V6) — 결정적

> **IQS323 전체 레지스터맵(A.1~A.37)·AZD004·AZD125 재탐색 결과, 코히런트 AC 클럭/SPI 노이즈를 직접 상쇄하는 register·기능은 전무.** 존재하는 SW 레버는 (1) 통계적 마진 확대(디바운스/베타/임계 — 노이즈 제거가 아니라 문턱 상향) 또는 (2) 변환주파수 재선택(약함)뿐. **Azoteq 노이즈 앱노트(AZD125 §10)조차 "상쇄"가 아닌 "SNR 마진 확보"만 제시** — 제조사 문서 자체가 이 범주 기능을 안 준다는 게 가장 강한 정황.

→ "config/channel/measurement 레벨로는 코히런트 AC 상쇄 불가. 남는 SW 레버는 타이밍(약함)+물리완화(자매 프로젝트 소관)." 할루시네이션 0.

## 3. 근본 이유

- 노이즈가 **코히런트(클럭 유래)**라 랜덤 평균화·필터로 안 지워짐(관측교란.md §4 메커니즘_3와 정합).
- IQS323는 **차동/참조 상쇄 회로를 AC용으로 제공하지 않음**(reference tracking은 DC-LTA 전용, mutual은 HW·기하로 No-go).
- 채널을 둘 써도(C-DUAL) **순차측정+비대칭결합**이라 상쇄 불성립.

## 4. 검증 품질·부수 발견

- **하드 할루시네이션 0건** — 후보들이 인용한 레지스터·비트·reset값·데이터시트 페이지 전수 원문 일치(V1·V3·V6).
- **참고 문서 오류 3건 발견(별도 정정 권고)**:
  1. `데이터시트/02_proxfusion동작.md §5.6 NOTE` "Beta 4비트(0~15)" — **사실오류**, 실제 NP/LP 각 8비트(0~255, A.26~28).
  2. 동 `§5.7 NOTE` "Touch Debounce 필드" — 원문엔 Touch debounce 없음(Prox만).
  3. C-FILT의 "k=158 시도" 서술 — 계수(k)와 절대임계(THR=k×LTA/256) 혼동(실제 k=102가 THR 158, k=158 시도 없음).
  - 부수: `main.c` TIMER3 주석 "≈200ms" vs "100.0ms" 자기모순.

## 5. 남는 길 (config-level 아님)

config/channel/measurement로는 상쇄 불가 → **실효 SW-only는 선행 조사·구현계획의 물리완화·타이밍 포트폴리오뿐**:
- **P0 실측**(지배 애그레서·H2 확정) → **P1 자체 애그레서 제거(read_debug)** → **P2 결합 저감(드라이브 하향)** → **P5 FSM 라이드스루** (모두 [`20260703_touch-heisenberg-sw-impl`](../../20260703_touch-heisenberg-sw-impl/) 계획).
- 이들은 "노이즈 상쇄"가 아니라 **애그레서 제거 + SNR 마진 확보 + 재부팅 완충** — Azoteq 권고 방향과 정합.
- C-FILT Threshold(C)는 헤드룸 소진이라 **추천 안 함**(과거 실패 재현 위험).
