# 06 · C-MEAS — 측정모드 재구성 (변환구조·오버샘플/다중변환)

**TL;DR**: "측정모드 재구성으로 코히런트 노이즈 저감" 가설을 하위후보 3개(M1 다중변환·M2 변환주파수·M3 레지스터 명시화)로 분해해 검증한 결과, 전부 근거가 약하거나 실체가 없다. M1은 평균화 근거가 데이터시트에 0건이고 이미 최댓값이라 SW 액션 자체가 없다. M2는 방향을 사전 예측 못하는 실측 전제 후보에 그친다. M3은 노이즈 저감이 아닌 방어적 하드닝일 뿐이다. 3불변식은 셋 다 보존된다.

---

## 0. 결론 먼저 — 판정표

| 하위후보 | 메커니즘 | AC 노이즈 저감 근거강도 | SW 실체 존재 | 3불변식 | 판정 |
|---|---|---|---|---|---|
| **M1** Auto Prox Cycle Select 상향(다중변환) | 인터럽트당 4/8/16/32회 변환 | **근거 없음**(평균화 언급 DS 0건) + ULP 전용 의심(§8.11.1) | **없음**(이미 reset 기본값이 최댓값 32) | 무관(미접촉) | **기각(실체 없음)** |
| **M2** Conversion Frequency Period 재튜닝 | 에일리어싱/윈도우 재정렬(관측교란.md §4) | **약함**(방향 예측 불가, 실측 스윕 전제) | 있음(레지스터 값 교체) | 보존 | **조건부 생존**(실측 게이트) |
| **M3** §6 하드웨어설정 레지스터 명시화(0x32/33/34) | 없음 — 이미 최적 기본값 고정 | 해당 없음(노이즈 개선 주장 아님) | 있음(write 3개 추가) | 보존 | **채택**(하드닝 목적, 노이즈 무관) |

## 1. 공통 이론적 제약 — 오버샘플/평균화가 코히런트 노이즈엔 근본적으로 약한 이유

평균화(N회 측정 평균)는 **매 샘플마다 값이 달라지는 무작위·비상관 성분**을 1/√N로 줄이는 도구다. 하지만 아군-어그레서 관계가 **매 샘플에 동일하게 실리는 성분**(체계적 바이어스)에는 원리적으로 무력하다 — N개 샘플 모두에 같은 바이어스가 더해지면 평균에도 그 바이어스가 그대로 남는다(통계학 일반 원리, IQS323 고유 사실 아님).

기존 프로젝트 참고자료가 이미 이 구분을 명시한다: `터치 계측 관측 교란.md §4`(핵심 구분 콜아웃) — "랜덤 광대역 노이즈는 평균화되어 노이즈 플로어만 약간 올린다. 진짜 문제를 일으키는 건 주기적·코히런트(clock 유래) 간섭 — 체계적 offset·드리프트·발산의 주범." fake_func_sleep()은 SPI/SYSCLK/QCC를 **상시** 유지하는 조건(오케스트레이터 배경, G3 §4)이라 순간적 글리치가 아니라 **지속적** 교란에 가깝다 — 지속적 바이어스일수록 오버샘플/평균화의 효과는 더 줄어든다. 이하 M1·M2는 이 제약을 깔고 평가한다.

**단, 완전한 무력은 아니다**: `터치 계측 관측 교란.md §4 메커니즘_3`(에일리어싱/맥놀이)은 애그레서 주파수와 센서 샘플레이트가 정수배에 가까우면 그 위상관계가 **느리게 회전**(beat)한다고 설명한다 — 이 경우 바이어스는 완전히 고정된 DC가 아니라 **느린 AC 성분**을 갖는다. IQS323 내부 오실레이터(fOSC, 14MHz, 공차 13.23~14.77MHz — `iqs323_datasheet.pdf` Table 4.3 "Master CLK frequency tolerance", p.12)가 SYSCLK(30.72MHz)와 공유 레퍼런스 없는 자유구동이라는 사실은, 전체 핀 목록(Table 2.4 Signal Descriptions, p.7 — CRx0~2/CTx0~2/Bias·TxA·OutA·RDY/MCLR·SDA·SCL·VDD·VREG·VSS 11종 전부)에 **외부 클럭 입력 핀 자체가 없음**으로 확인된다(WLCSP11/DFN12/QFN20 세 패키지 핀맵 전부 동일 신호 집합, p.6-7 원문 대조). 두 클럭 사이 위상이 고정되지 않고 표류함을 뒷받침하는 근거다. 이 AC 성분에 한해서는 M2(변환주파수 변경, 아래 §3)가 부분적 효과를 가질 **가능성**이 있으나, 방향은 예측 불가다.

## 2. M1 — Auto Prox Cycle Select (다중변환수 조정)

### 2.1 메커니즘(원문)
`Prox Input and Control`(0x33/43/53) bits[3:2] `Auto Prox Cycle Select`, 원문(`iqs323_datasheet.pdf` p.54, Appendix A.9): "Number of conversions before each interrupt is generated in Auto Mode" — 00=4·01=8·10=16·11=32.

### 2.2 근거강도 판정 — 두 가지 반증
1. **평균화 근거 0건**: 데이터시트 전문(68페이지, `pdftotext`로 전체 추출 후 검색, 본 세션)에서 "average"/"averaging"/"averaged" 계열 어휘는 "Long Term Average"(LTA) 명칭 외 **단 한 번도 등장하지 않는다**. "다회 변환을 평균해 raw counts를 보고한다"는 서술 자체가 없다 — 이 필드가 실제로 하는 일은 "인터럽트 생성 전 변환 횟수"일 뿐, 그 결과가 평균되는지 마지막 값만 보고되는지 데이터시트가 규정하지 않는다(**근거 없음**, G2 §3 "미확인" 판정과 일치).
2. **ULP 전용 의심**: 이 필드의 유일한 정량적 사용처는 `iqs323_datasheet.pdf` p.32 §8.11.1 원문 "In ULP power mode the report rate is: (Auto Prox Cycle Select × Ultra Low Power Report Rate)ms"뿐이다. NP/LP/Automatic No ULP에서 이 필드가 어떤 효과를 갖는지 명시하는 문장은 리뷰 범위(§5·§6·§8·부록 A) 전체에서 발견되지 않았다. Sound1은 `REG_SYSTEM_CONTROL`=0x50/0x54/0x58 write로 Power Mode를 **Automatic No ULP**(bits[6:4]=101)로 고정하고 `REG_PM_TIMEOUT`=0(자동 강하 차단, `tdc_touch_iqs323.c:320`)이라 **ULP에 진입하지 않는다** — 이 필드가 실제 운용 모드에서 기능하는지 자체가 **미확인**.

### 2.3 현재 상태 — 이미 최댓값, 액션 자체가 없음
`tdc_touch_iqs323.c` 전체(499줄) grep 확인: `REG_` 정의 목록(17~34행)에 0x33/0x43/0x53 계열 매크로가 아예 없고, `write_register(` 호출 전수(전체 파일)에도 해당 주소가 등장하지 않는다 — **0x33은 부팅마다 reset 기본값 0x01CF에 머문다**. 이 값의 bits[3:2]를 직접 재계산하면(0x01CF = `0000 0001 1100 1111`) bit3=1·bit2=1 → **이미 "11"=32(최댓값)**이다. 즉 "다중변환수를 늘린다"는 이 후보의 전제 자체가 **성립하지 않는다** — 늘릴 여지가 없고, 늘릴 근거도 없다.

**판정**: 기각. 근거 부재 + 여유 부재가 겹쳐 이 하위후보는 SW 변경 항목으로 존재하지 않는다.

## 3. M2 — Conversion Frequency Period 재튜닝

### 3.1 현재 상태·메커니즘
`REG_CONV_FREQ`(0x31) 현재 write(`tdc_touch_iqs323.c:316`): `write_register(REG_CONV_FREQ, 0x7F, 0x05)` → 0x057F = Fraction 127(고정) + Period 5 → f_xfer **1.00MHz**(자기용량 권장 상한, `iqs323_datasheet.pdf` p.52 Table A.1 "maximum recommended conversion frequency for self-capacitive sensing is 1 MHz"). 참고로 이 값은 **reset 기본값과 동일**(0x31 reset = 0x057F, `06_레지스터레퍼런스.md` §9 표) — 현재 explicit write는 실질적으로 reset값을 재확인할 뿐, Period를 낮추는 것이 이 레지스터를 **최초로 기능적 변경**하는 지점이 된다.

메커니즘은 §1에서 이미 정리한 대로 **관측교란.md §4 메커니즘_2(샘플링 윈도우 일치)·메커니즘_3(에일리어싱/맥놀이)**다 — f_xfer(및 이에 연동되는 총 변환 소요시간)를 바꾸면 애그레서 고정주파수(SYSCLK 30.72MHz 등)와의 정수배 근접도·윈도우 폭이 달라져 결과적 비트(맥놀이)주파수·중첩 확률이 바뀐다.

### 3.2 방향 예측 불가 — 이 후보의 핵심 한계
- 애그레서의 정확한 지배 주파수 성분(SPI 실제 비트레이트 등)이 본 재탐색 근거자료 범위에서 **미확인**(G3도 "애그레서 무게=물리결합(SPI/SYSCLK/QCC)"로만 명시, 정확한 Hz값 없음).
- f_xfer 자체가 IQS323 내부 자유구동 오실레이터 fOSC(14MHz, 공차 13.23~14.77MHz, Table 4.3, p.12)에서 파생("derived from fOSC", 동 표) — 개별 칩·온도마다 공차가 흔들려 **정밀한 Hz 단위 회피 튜닝이 애초에 불가능**하다.
- 따라서 이 후보는 "이 값이 낫다"는 분석적 결론이 아니라 **실측 스윕 대상 후보 목록**이다.

### 3.3 레지스터/시퀀스
Fraction(LSB)은 `iqs323_datasheet.pdf` p.22(§6.5) 권고대로 **0x7F 불변**, MSB(Period)만 Table A.1(p.52, 자기용량·Dead Time ON) 옵션 중 1MHz **이하**로 교체:

| Period(MSB) | f_xfer | 비고 |
|---|---|---|
| 5(현재) | 1.00 MHz | 자기용량 권장 상한(이미 사용 중) |
| 7 | 778 kHz | 후보 |
| 12 | 500 kHz | 후보(Azoteq 자체 전류특성표 p.11 §3.4 기준 동작점과 동일) |
| 16 | 389 kHz | 후보 |
| 23 | 280 kHz | 후보(가장 보수적) |

자기용량 권장 상한이 이미 1MHz이므로 **상향(더 높은 주파수)은 권장범위 이탈** — 방향은 하향만 유효.

### 3.4 3불변식 보존
- INV-CTRL-1(Full ATI): `REG_SENSOR0_ATI_SETUP`(0x36)·`REG_SYSTEM_CONTROL`(0xC0) 어느 것도 이 변경으로 접촉되지 않는다. ATI Target 계산식(§5.9, p.18 "ATI TARGET = ACTUAL ATI BASE × (ATI Resolution Factor / 16)")이 f_xfer와 무관하게 counts를 재정규화하도록 설계되어 있어, Full ATI 자체의 정상 동작 전제는 유지된다. 코드 순서상으로도 `REG_CONV_FREQ` write(316행, `beta_power_settings()` 내부)가 0x36 Full-ATI write(437행)·Re-ATI 트리거(447행)보다 **먼저** 실행되므로 순서 변경 없이 값만 교체하면 된다.
- INV-CTRL-2(ATI 에러 처리): 로직 미접촉. 단 f_xfer 변경 직후 ATI가 새 정상범위로 재수렴하는 데 (특히 Period=23의 극단값에서) 실측 전 보장 안 되는 지연이 있을 수 있음 — 이미 INV-CTRL-2가 안전망으로 존재하므로 치명적이지 않음(**미확인**, 실측 필요).
- INV-CTRL-3(첫 터치 해제): `boot_ignore`/`sleep_ignore` 경로와 무관한 레지스터 — 완전 보존.

### 3.5 감도·전류·응답 트레이드오프
- **감도**: Full ATI가 f_xfer와 무관하게 ATI Target으로 재정규화하므로 명목 threshold 계수 기준 감도는 보존 추정. 다만 count당 실제 물리량(ΔC) 스케일이 달라져 미세한 양자화 차이가 있을 수 있음(**미확인**).
- **전류**: 스위칭 활동(charge-transfer 사이클 빈도) 감소 → 소비 전류 감소 방향으로 추정. 단 이는 스위치드커패시터 회로 일반 원리에 따른 **유도(추론)**이며, IQS323 고유 수치 근거는 없다 — 데이터시트 §3.4(p.11) 전류표는 자기용량 특성치를 500kHz **한 동작점**만 제시하고 주파수 스윕표 자체가 없다(**근거 약함**).
- **응답**: §6.5(p.22) "고저항 센서는 Fxfer를 낮춰야 할 수 있다"는 정성적 서술과 일관되게, 낮은 f_xfer는 변환 1회 소요시간을 늘려 report 지연이 소폭 증가할 가능성(**정량 미확인**).

### 3.6 한계·리스크
방향(개선/악화)을 사전에 확정할 수 없는 **실측 전제 후보**다. 비용은 낮다(레지스터 값 1바이트 교체 + 재빌드 + 실측 스윕). 잘못된 Period 선택 시 개선은커녕 새로운 비트주파수 대역에서 악화될 위험도 동등하게 존재한다.

## 4. M3 — §6 하드웨어설정 레지스터 명시적 하드닝 (노이즈 저감 주장 아님)

### 4.1 발견 (코드 확인)
`tdc_touch_iqs323.c` 전체 grep 결과, `0x32`(Prox Control)·`0x33`(Prox Input and Control)·`0x34`(Pattern Definitions) 세 레지스터(및 대응 0x42/43/44, 0x52/53/54)는 **단 한 번도 write되지 않는다**. 매 MCLR 리셋(부팅마다, `tdc_touch_init_begin()`)마다 reset 기본값에 의존한다. 세 값을 직접 재계산해 §6 권고와 대조하면 **전부 우연히 이미 권고값과 일치**한다:

| 레지스터 | reset 값 | 관련 필드 | §6 권고 | 일치 여부 |
|---|---|---|---|---|
| 0x32 | 0x1290 | 0v5 Discharge=0 | "대부분 응용은 완전방전(0v5 off) 권장"(p.21) | 일치 |
| 0x32 | 0x1290 | Cs Size=1(80pF) | "대부분 응용은 80pF 적절"(p.21) | 일치 |
| 0x33 | 0x01CF | Dead Time Enable=1 | "정전용량은 항상 enable"(§6.4) | 일치 |
| 0x34 | 0x030A | Inactive Rxs=0x0A(VSS) | "최적 noise rejection 위해 VSS 권장"(§6.1) | 일치 |
| 0x34 | 0x030A | Wav Pattern0=0x3 | Table 5.2 자기용량 권장값 | 일치 |

(bit 단위 재계산은 본 문서 작성자가 직접 수행해 `06_레지스터레퍼런스.md`의 기존 A.7/A.9/A.10 표와 교차 대조·전항 일치 확인.)

### 4.2 평가 — 왜 이건 "노이즈 저감 후보"가 아닌가
이 발견은 **개선 여지가 있다는 뜻이 아니라 개선 여지가 없다는 뜻**이다 — 이미 데이터시트가 권장하는 값 그대로다. 유일한 잔여 리스크는 이 상태가 **암묵적**(reset 의존)이라는 점 — 향후 다이 리비전 차이(A.8 경고: IQS3ed는 bit11 read-only 강제, p.53)나 예기치 못한 레지스터 오염 시 방어벽이 없다.

### 4.3 레지스터/시퀀스 (하드닝안, 참고용)
`sensor_setup()` 내부에 현재값 그대로 명시적 write 3개 추가: `write_register(0x32, 0x90, 0x12)` · `write_register(0x33, 0xCF, 0x01)` · `write_register(0x34, 0x0A, 0x03)`. 값 변화가 없으므로 동작 변화·리스크도 없다 — **노이즈 저감 효과를 주장하면 과장**이며, 순수 회귀 방지 목적으로만 유효하다.

## 6. WF2 사실 대조 목록 (factsToVerify)

1. "Auto Prox Cycle Select"가 raw counts를 실제 평균화하는지 vs 단순 인터럽트 주기 배수인지 — 본 세션 전문 검색("average" 0건) 재현·반증 필요.
2. Auto Prox Cycle Select 효과가 정말 ULP 전용인지(§8.11.1, p.32가 유일 근거) — NP/Automatic No ULP에서도 적용되는지 Azoteq 직접 확인 또는 실측 필요.
3. `tdc_touch_iqs323.c`가 0x32/0x33/0x34를 정말 전혀 write하지 않는지(본 세션 grep, 499줄 전수 확인) — 독립 재확인 권고.
4. 핀 목록(Table 2.4, p.7)에 외부 클럭 입력이 없다는 사실 자체는 확인됨(본 세션). 단 이로부터 "SYSCLK와 완전 무관·표류"까지 단정하는 추론이 보드 레벨 간접 결합(전원 레일 변조 등) 가능성까지 배제하는지는 별개 — 실측(두 클럭 위상차 장시간 관측)으로 재확인 권고.
5. §1의 "코히런트 바이어스엔 평균화 무력" 이론이 fake_func_sleep() 실제 증상(지속형 vs 순간형)에 맞는지 — 오실로스코프/장시간 Counts 로그 실측 필요.
6. Conversion Frequency Period 하향(특히 Period=23, 280kHz)이 실제 ATI 재수렴에 지장 없는지 — 코드·데이터시트 어느 쪽도 보장하지 않음, 실측 필요.
7. 본 문서 §4의 0x32/0x33/0x34 비트 재계산(0x1290/0x01CF/0x030A 분해)이 `06_레지스터레퍼런스.md` 기존 표와 정확히 일치하는지 — 독립 재계산 재검증 권고.
