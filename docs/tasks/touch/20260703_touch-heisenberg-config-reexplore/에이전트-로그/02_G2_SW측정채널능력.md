# 02 · G2 — IQS323 SW-only 측정·채널 변경 능력 전수

**TL;DR**: IQS323 SW-only(레지스터) 측정·채널 변경 능력 전수. 채널모드 3종(Independent/Follower/Reference)은 LTA 드리프트 보정만 담당(확립). CH0+CH1 raw counts FW 병행 읽기·차감은 항상 가능(확립). 오버샘플 레버는 존재하나 동기는 근거 없음. CH1 실채널화는 물리 핀 라우팅(SW 가능)과 터치 전극 노출(HW 필요, 미확인)을 층위 분리해야 함.

---

## 1. 채널 모드 3종 — Independent / Follower / Reference

**확립** 근거: 02_proxfusion동작.md §5.1, 04_부가기능·UI.md §7.3(원문 p.24 Table 7.1/7.2), 06_레지스터레퍼런스.md A.15/A.18.

`Channel Setup`(0x60/0x70/0x80) bits[3:0] `Channel Mode`로 채널마다 독립 설정:

| 모드 | 값 | 의미 | 관련 필드 |
|---|---|---|---|
| **Independent** | 00 | 다른 채널과 무관하게 자체 LTA·threshold로만 판정 | — (현재 Sound1 CH0 상태) |
| **Follower** | 01 | 지정된 Reference 채널의 LTA 변화량을 자신의 LTA에서 차감 | `Reference Sensor ID`(bits7-4)=참조할 채널 번호, `Follower Weight`(0x63/73/83, 16bit)=Weight/4096 |
| **Reference** | 10 | 다른 채널(Follower)의 기준 역할. 자신은 threshold 판정 대상 아님 | `Follower Event Mask`(bits15-8)=Follower의 Prox/Touch bit를 마스크해 자신의 ATI를 차단하는 인터록 |

**동작 원리(확립, 04_부가기능·UI.md §7.3.1 NOTE)**: 온도·습도 등 공통 드리프트는 Follower·Reference 채널 LTA를 동시에 같은 방향으로 이동시킨다. `follower LTA 보정량 = reference LTA 변화량 × (Follower Weight/4096)`을 follower LTA에서 차감해 공통 모드 드리프트를 제거하는 방식 — **LTA(기준선) 레벨의 연산이며 raw Counts 자체를 건드리지 않는다.**

**제약(확립)**: single reference는 multiple follower 가능하나 follower는 multiple reference 불가(1개만)(04 §7.3). Reference 채널은 사용자가 접촉할 수 없어야 하고 sensing 채널과 동일 환경에 노출되어야 함(04 §7.3 도입부).

**3불변식과의 상호작용(G3 상세, 여기선 개요만)**: `Follower Event Mask`는 "Follower가 Prox/Touch 상태일 때 Reference의 ATI를 차단"하는 인터록이다 — 이는 INV-CTRL-1(Full ATI 사용)·INV-CTRL-2(ATI 에러 Re-ATI)와 직접 얽힌다. Reference 채널도 ATI 대상이면 그 자신의 ATI 실패가 전역 `ati_error`(A.2, 채널 무관 단일 비트)를 세울 수 있음(레지스터-맵.md §2, 이슈해결 문서 §4 실제 사례로 확인됨).

## 2. Dual-channel 활용 가능성 — CH0+CH1 동시 self-cap

### 2.1 IC 내장 메커니즘(§1의 Follower/Reference) — LTA만

위 §1 그대로. **AC 노이즈(클럭/SPI 스위칭 순간 전하 주입)를 상쇄한다는 근거는 데이터시트 어디에도 없다** — Reference UI 도입부(04 §7.3)와 예시(§7.3.2)는 모두 "온도·습도"(수초~수분 시간축의 느린 변화) 맥락으로만 서술되어 있고, IIR 기반 LTA 자체가 §5.6에서 명시하듯 "천천히 변하는 신호만 통과"시키는 저역통과 필터다. 이 판정은 G1(reference tracking 실능력) 소관이므로 본 문서는 결론을 내리지 않고 사실만 전달한다.

### 2.2 FW 레벨 독립 병행 측정 — Channel Mode 무관, 항상 가능(확립)

`Channel 0 Filtered Counts`(0x13)·`Channel 0 LTA`(0x14)·`Channel 1 Filtered Counts`(0x15)·`Channel 1 LTA`(0x16)는 **읽기 전용 레지스터**로, Channel Mode 설정(Independent/Follower/Reference 무엇이든)과 **무관하게** 항상 I²C로 개별 read 가능(06_레지스터레퍼런스.md §9 Read Only 표). 즉:

- CH0·CH1을 둘 다 **Independent**로 두고, FW가 매 폴링마다 두 채널의 raw counts(또는 LTA)를 각각 읽어 **임의의 차감·비교 연산**(IC 내장 Follower 공식과 무관한 자체 알고리즘)을 적용하는 것은 순수 SW 로직으로 가능하다 — IC의 도움 없이 FW 자신이 "차동"을 구현하는 방식.
- 이는 §2.1의 IC 내장 Follower(LTA끼리, 고정 공식)와 **다른 층위**다: FW 레벨 방식은 raw Counts 단위에서 임의 시점(예: 애그레서 이벤트 직후)에 즉시 비교할 수 있어 원리적으로 더 빠른 시상수 대응이 가능하나, IC 내부 ATI/Threshold 판정 자체는 여전히 CH0 자신의 LTA만 기준으로 이뤄지므로(§5.7 공식) FW가 별도로 읽은 CH1 값을 터치 판정에 반영하려면 **CH0의 최종 Touch bit 판정과는 별개의 추가 FW 로직**이 필요하다(현재 코드는 `ch0_touch` bit만 읽으며 CH1 raw 비교 로직 없음 — tdc_touch_iqs323.c 전체에 REG_CH1 계열 정의 자체가 없음).
- **미확인**: 두 채널이 서로 다른 물리 CRx 핀(CRx0 vs CRx1)에서 동시에(같은 conversion cycle에) 측정되는지, 아니면 항상 순차(time-multiplexed) 측정인지는 리뷰 범위(§5, §9) 내 명시 없음 — 순차라면 CH0·CH1 사이 수 십~수백 µs 시간차가 존재해 "동시성"을 전제한 차동 상쇄는 그만큼 약화될 수 있음(가설, 미확인).

## 3. 노이즈 강건 관련 SW 설정 — 오버샘플·다중변환·동기·리포트레이트

| 레버 | 레지스터 | 값·범위 | 근거 | 상태 |
|---|---|---|---|---|
| **Auto Prox Cycle Select** | Prox Input and Control(0x33/43/53) bits[3:2] | 00=4·01=8·10=16·11=32 (Auto Mode에서 인터럽트당 conversion 수) | 06_레지스터레퍼런스.md A.9 | 확립(존재)·효과(평균화 여부) 미확인 |
| **Report Rate** ×4 | 0xC1(NP)·0xC2(LP)·0xC3(ULP)·0xC4(Halt) | 0~3000ms | 06_레지스터레퍼런스.md §9 | 확립 |
| **Conversion Frequency Period** | Conversion Frequency Setup(0x31/41/51) bits[15:8] | Table A.1(Dead Time ON, self-cap): Period 2→1.75MHz ~ 23→280kHz | 03_하드웨어설정.md §6.5, 06 A.6 | 확립 |
| **Fraction** | 동 레지스터 bits[7:0] | 127 고정 권장(변경 시 지터 유발) | 03_하드웨어설정.md §6.5 | 확립 |
| **외부 이벤트 동기(SPI/SYSCLK 스위칭 시점 회피)** | — | — | — | **근거 없음** — 리뷰한 §5~9(02·03·04·05·06)에 IQS323 conversion을 외부 클럭/이벤트에 위상 동기시키는 핀·레지스터 기술 없음. IQS323은 자체 내부 발진기(§6.5 f_OSC 14MHz 파생) 기반 자유구동(free-running)만 확인됨 |
| **Filter Beta(Counts/LTA/LTA Fast)** | 0xB0~B2 | Beta/256 = damping | 02_proxfusion동작.md §5.6 | 확립(존재) — 상세 튜닝은 C-FILT 후보 소관, 본 문서는 존재만 표기 |

**Auto Prox Cycle Select의 미확인 지점**: "인터럽트당 conversion 수"라는 원문 문구(A.9)만 확인되며, 그 4/8/16/32회 conversion 결과가 **평균되어 하나의 Counts로 보고되는지, 단순 보고 주기 배수로만 쓰이는지**는 리뷰 범위 내 명시 없음(§8.11.1의 ULP report rate 공식 `Auto Prox Cycle Select × ULP Report Rate`는 "주기 배수" 해석을 뒷받침하나 "평균화"를 확언하진 않음) — 실측 또는 추가 확인 필요.

**결론**: "동기"(위상 정렬) 레버는 존재하지 않음, "오버샘플"에 가장 가까운 후보는 Auto Prox Cycle Select이나 그 정확한 신호처리 효과는 미확인, "다중변환"·"리포트레이트"는 확립된 SW 레버.

## 4. CH1 실채널화 — SW-only 가능성 경계

### 4.1 현황 재확인(확립, 코드·회로 원본 직접 대조)

- **코드**: `tdc_touch_iqs323.c:272` — `write_register(REG_SENSOR1_SETUP, 0x00, 0x00)` (`REG_SENSOR1_SETUP=0x40`). 주석(265행): "단일채널: CRX0 단독 활성, CH1/CH2 Floating disable. **CalCap 더미/방전 없음**." → 과거 이슈해결 문서(2026-06_CRX1-ESD-더미채널.md)의 CalCap 더미 채널 방식은 **현재 코드에 없음** — 완전 단일채널로 되돌아간 상태(현재 코드가 최종 근거, 문서보다 우선).
- **CH1 레지스터 조작 전무**: 파일 전체에 `REG_CH1_*`·`REG_SENSOR1_ATI*`·0x70대 정의 자체가 없음(grep 확인) — CH1은 boot 시 1회 disable 외 어떤 SW도 손대지 않음.
- **회로**: CRX1(A1) → C52(100nF, 직렬) → R32(0Ω) → J4(SCS05-065-10, J3와 동일 규격). "**HW 배선은 완료, 전극 연결은 미사용**"(회로 구성·분석.md §7.2) — J4 커넥터 자체는 존재하나 그 반대편에 실제 사용자 접촉 가능한 전극 패드가 물려 있는지는 본 문서가 확보한 자료로 **확인 불가**.

### 4.2 확립 — Sensor 블록↔물리 CRx/CTx 핀은 SW 설정으로 자유 매핑된다

`Prox Input and Control`(CRx0/1/2 선택)과 `Sensor Setup`(CTx0/1/2 선택)은 **Sensor 0/1/2 각 블록이 독립적으로 보유**하며, "Sensor 1"이라는 이름이 "물리 CRX1 핀"을 강제하지 않는다. 근거(이중 확인):

1. §5.12.1 원문(02_proxfusion동작.md): self-cap은 "동일 CRx·CTx 핀 번호"를 짝지어 set — CRx0/CTx0을 예시로 들 뿐, 특정 Sensor 블록에 묶는 서술 없음.
2. **Azoteq 공식 EV-KIT 예제 3종 전부**(03_EV_KIT설정·레지스터.md §3.1~3.2)에서 `S0_RX_SELECT=0x02`(bit1=CRx1 선택) + `S1_RX_SELECT=0x01`(bit0=CRx0 선택) — **Sensor 0 블록이 물리 CRx1을, Sensor 1 블록이 물리 CRx0을 사용하도록 3개 예제 전부 동일하게 프로그램**되어 있음. Sensor 블록 번호와 물리 핀 번호가 뒤바뀐 배치가 Azoteq 자신의 레퍼런스 펌웨어에 실재한다는 것이 매핑 자유도의 직접 증거.

→ **결론(확립)**: CH1(Sensor1 블록, 0x40대)을 물리 CRX1 핀(C52 쪽)에 연결하려면 `Prox Input and Control`(0x43) bit9=1(CRx1) + `Sensor Setup`(0x40) bit9=1(CTx1)을 **명시적으로 SW에서 기록**하면 된다 — 이 라우팅 자체는 순수 레지스터 조작으로 HW 무수정 달성 가능.

### 4.3 미확인 — CH1 reset 기본값이 실제로 어느 물리 핀을 향하는지

- `Prox Input and Control`(0x43) reset값은 0x01CF로 **모든 Sensor 블록에 동일**하며 표기상 "CRx0 bit set"(06_레지스터레퍼런스.md A.9) — 문자 그대로 읽으면 Sensor1도 reset 상태에서 물리 **CRx0**(=CH0과 같은 핀)를 향한다.
- 그러나 기존 프로젝트 문서(이슈해결/2026-06_CRX1-ESD-더미채널.md §6)는 "그 시점 CH1은 아직 reset 기본값(0x0101=enable, ATI Full, **외부 CRx1**)"이라 서술 — 물리 CRx1로 명시.
- 두 근거가 상충한다. 본 문서가 확보한 자료로는 **어느 쪽이 맞는지 판정 불가**(미확인, 실측 필요) — 가능한 두 가설을 병기한다:
  - 가설_A(레지스터 표 문자대로): Sensor1 reset은 물리 CRx0을 향함 → 과거 ATI 수렴 실패는 CH0(활성, 실전극)과 CH1(reset, 동일 CRx0 대상)의 **물리 핀 경합**이 원인일 수 있음.
  - 가설_B(기존 프로젝트 문서대로): Sensor1 reset은 물리 CRx1(C52 부하)을 향함 → 과거 ATI 수렴 실패는 C52 부하값이 ATI Target과 안 맞았기 때문.
  - 어느 가설이든 **결론(§4.2)에는 영향 없음** — 어차피 SW가 CRx1/CTx1 bit를 명시적으로 기록하면 reset 기본값과 무관하게 물리 CRx1로 확정할 수 있기 때문.

### 4.4 "실채널화"의 3층위 구분 — 여기가 핵심

| 층위 | 내용 | SW-only 가능? | 근거 |
|---|---|---|---|
| **(a) 물리 핀 라우팅** | Sensor1을 CRx1/CTx1로 명시 설정 | **가능** | §4.2 확립 |
| **(b) 실제 터치(사용자 손가락) 감지용 전극 노출** | J4 반대편에 사용자가 접촉 가능한 도전성 패드가 실재해야 함 | **HW 요구 — SW로 대체 불가** | 회로 구성·분석.md §7.2 "전극 연결은 미사용"만 확인, 패드 실재 여부 **미확인** |
| **(c) 더미/보조 활성 채널(터치 감지 목적 아님, 측정 사이클 유지용)** | 전극 없이도 "활성 채널 1개 이상" 요건 충족 목적 | **SW 시도 가능하나 과거 실패 이력** | §4.5 참조 |

**(b)에 대한 물리적 보충 근거(유도·가설, 데이터시트 인용 아님)**: C52(100nF, 직렬)의 리액턴스는 $X_C = 1/(2\pi f C)$로, 현재 CH0 conversion frequency(1MHz, `REG_CONV_FREQ`=0x057F 실측값)를 그대로 적용하면 $X_C ≈ 1/(2\pi \times 10^6 \times 100\times10^{-9}) ≈ 1.6\,\Omega$ — 손가락 정전용량(수 pF, 1MHz에서 리액턴스 수십 kΩ)과 비교하면 무시할 수준으로 작다. 즉 **C52 자체가 실제 전극이 있을 경우 손가락 신호를 가로막는 요소는 아닐 가능성이 높다**(계산상 유도, 미확인 — 실제 부품 공차·기생 성분 영향은 실측 필요). 다만 이는 "전극이 있다면 C52가 방해하지 않는다"는 것이지 "전극이 있다"를 증명하지 않는다 — (b)의 핵심 미확인은 여전히 유효.

### 4.5 (c) 더미/보조 채널로서의 재검토 — 과거 실패, 현재는 전제가 달라짐

과거(이슈해결/2026-06 문서) 외부 CRx1(C52 부하) 경로는 실제로 시도되지 않고 **CalCap(내부) 경로로 대체**됐다 — 정확히는, MCLR 직후 auto-ATI가 sensor_setup() 적용 전에 reset 기본값으로 먼저 도는 타이밍 문제 때문에 CH1이 무엇으로 설정되든(CalCap이든 외부 CRx1이든) 초기 auto-ATI 수렴에 실패하면 전역 `ati_error`가 SET됐고, 당시 FW는 `ati_error → CAL_ERROR` 단락 로직이 있어 터치 인식 자체가 막혔다.

**현재 코드는 이 CalCap 더미 채널 자체를 쓰지 않는 단일채널 구조로 되돌아갔다**(§4.1). 다만 `ati_error` 필드는 여전히 읽히지만(`tdc_touch_iqs323.c:363`) **터치 판정(pressed)에 사용되지 않음**(CAL_ERROR 단락 로직이 현재 파일에 grep 0건) — 즉 이슈해결 문서가 기록한 "ati_error 무시" 사상이 이 파일 어딘가(get_state 경로)에 계승된 것으로 보인다(정확한 소스는 본 파일 351~365행 범위, `pressed` 산출 로직 자체는 본 read 범위 밖).

→ **미확인(가설)**: 만약 `ati_error`가 이미 판정에서 배제된 아키텍처가 맞다면, CH1을 외부 CRx1(전극 없이 C52만)로 활성화해 auto-ATI가 실패하더라도 — 과거처럼 CAL_ERROR로 이어지지 않고 "그냥 실패한 채 방치된 활성 채널"로 남을 가능성이 있다. 이것이 (c) 더미 목적(전극 없이 활성 채널 수만 채우기)에 실사용 가능한지는 **실측 검증 없이는 확정 불가** — 특히 실패한 채널이 매 cycle 반복 재시도되며 I²C 트래픽·전력에 어떤 영향을 주는지는 근거 없음.

## 6. 미확인·추가확인 필요 목록

1. CH1(Sensor1) reset 기본값이 물리 CRx0/CTx0을 향하는지 CRx1/CTx1을 향하는지 — §4.3 가설_A/B 상충, 실측(레지스터 dump 또는 오실로스코프) 필요.
2. J4 반대편에 실제 사용자 접촉 가능 전극 패드가 존재하는지 — 회로도·제품 PCB 실물 확인 필요.
3. Auto Prox Cycle Select의 4/8/16/32 conversion이 평균화되는지 단순 주기 배수인지 — 데이터시트 재검색 또는 실측 필요.
4. CH0·CH1이 물리적으로 동시 측정되는지 순차(time-multiplexed) 측정인지 — §9 Timing 세부 챕터(미리뷰) 또는 실측 필요.
5. 현재 코드의 `ati_error` 무시가 정확히 어느 함수·라인에서 이뤄지는지(본 리뷰 범위 351~370행 밖 가능) — 코드 재확인 시 정확한 라인 인용 필요.
6. C52의 실제 설계 의도(DC 차단·노이즈 흡수 추정, 확정 아님) — 회로 설계자 확인 또는 원 설계 문서 필요.
