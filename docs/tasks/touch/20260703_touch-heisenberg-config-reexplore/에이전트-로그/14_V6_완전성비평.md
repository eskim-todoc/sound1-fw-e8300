# 14 · V6 — 완전성 비평 (놓친 SW-only 레버 탐색)

**TL;DR**: 5후보 원문 전체 + IQS323 데이터시트 06장 전부(§1,3,5,6 신규 확인분 포함, 완전 레지스터맵 A.1~A.37) + AZD004/AZD125(신규: 노이즈·온도·접지 3개 장) + 코드(REG_ 정의 전수)를 재탐색했으나, **코히런트 AC 클럭/SPI 노이즈를 직접 상쇄하는 SW-only 레지스터·기능은 발견되지 않았다**(근거 없음, 확립). "노이즈 검출 플래그"는 전체 레지스터맵에 실재 자체가 없고(확인 완료), 후보들이 이미 찾아둔 두 항목(Inactive Rxs=VSS, Interface Selection)은 검증 결과 이미 각각 C-MEAS·C-SYNC가 정확히 다뤘으며 둘 다 무관/한계 판정이 옳다. 결론(정직 보고): **config/channel/measurement 레벨로는 코히런트 AC 상쇄 불가 — 남는 SW 레버는 타이밍(약함·방향불명)과 물리완화(범위 밖, 자매 프로젝트 소관)뿐**이라는 5후보의 집단적 자평이 완전성 관점에서 그대로 확정된다.

## 0. 결론 먼저

| 질문 | 판정 |
|---|---|
| 5후보가 놓친 코히런트 AC 상쇄 SW 레버가 있는가 | **없음** — 데이터시트 전반 재탐색 결과 확인 |
| "노이즈 검출 플래그 기반 적응" 가능한가 | **불가** — System/Gesture/Movement Status(A.2~A.4) 전체에 노이즈 관련 비트 자체가 부재 |

| 채널 조합의 다른 활용이 있는가 | **없음** — Follower/Reference(DC 전용, G1 기각)·FW 차동(C-DUAL, 미검증 가설)·guard channel(AZD125, 액체감지 전용) 전부 검토, 새 조합 없음 |

| 남는 레버 | 타이밍(주파수 선택, 방향 예측 불가) + 물리완화(자체 애그레서 제거·드라이브 하향, IQS323 설정 범위 밖) |

- **5후보 원문 전체**: 04(C-RT)·05(C-DUAL)·06(C-MEAS)·07(C-FILT)·08(C-SYNC) — 요약이 아닌 **본문 전체**를 직접 대조(후보가 "이미 다룬 것"을 정확히 판정하기 위한 필수 절차)

## 2. 후보가 이미 다룬 항목 재확인 — 신규 주장 방지

본 세션에서 "미검토 레지스터"로 처음 포착했던 2건을 5후보 원문과 대조한 결과, **둘 다 이미 정확히 다뤄져 있었다**. 신규 발견으로 잘못 보고하지 않기 위해 명시한다.

| 항목 | 레지스터 | 본 세션 최초 인상 | 원문 대조 결과 |
|---|---|---|---|
| **Inactive Rxs=VSS** | Pattern Definitions(0x34/44/54) bits[3:0], §6.1 "최적 noise rejection 권장" | G2 §3 노이즈 레버 표에 누락 → 미검토처럼 보임 | **C-MEAS §4(M3)가 이미 발견·평가함**. reset 기본값이 이미 VSS(코드 write 0건, 본 세션도 독립 재확인). C-MEAS 판정: "개선 여지가 있다는 뜻이 아니라 없다는 뜻 — 이미 최적값. 노이즈 저감 효과를 주장하면 과장" — 정확한 판정. 또한 이 필드는 **미사용 CRx1/2 핀의 부유 안테나 효과 차단**이 목적이라 CH0 자신의 활성 전극에 직접 결합하는 SYSCLK/SPI 애그레서(주된 위협)와는 다른(부차적) 경로를 막을 뿐 |
| **Interface Selection(Streaming↔Event)** | System Control(0xC0) bit7 | G2가 명명하지 않음 → 미검토처럼 보임 | **C-SYNC §1·§2(C-SYNC-3)가 이미 정확히 다룸**. 판정: "약(주 애그레서 무관)" — SPI/SYSCLK 자체와 무관, RDY 핀 부수 애그레서만 겨냥. 게다가 I²C Lock-Up 에라타(부록C, 본 세션 원문 재대조 완료 — 인용 정확) 트리거 빈도 증가 위험까지 지적 |

**결론**: 두 항목 모두 "5후보가 놓친 새 레버"가 **아니다**. 오히려 C-MEAS·C-SYNC의 완결성이 본 세션의 독립 재탐색으로 교차검증된 셈이다.

## 3. 신규 탐색 — 후보 원문에 없는 자료에서 확인한 것

### 3-1. AZD125 §8 Follow UI (G1이 "미열람"으로 남긴 자료, 본 세션 신규 전체 통독)

IQS323 Channel Mode=Reference/Follower와 **동일 메커니즘**을 앱노트 레벨에서 재서술한 것으로 확인됨. Follow Weight 결정법이 **통제된 온도 스윕 시험**(T_ref=25℃→T_max/min, 식 (2) W_f=|ΔN_s|/|ΔN_r|×100)으로 명시되어 있어, G1의 "DC 드리프트 전용" 판정을 **독립 자료로 재확증**한다. "clock"·"switching"·"AC" 언급 없음(전문 대조). C-RT 기각을 흔들 근거 없음 — 오히려 보강.

### 3-2. AZD125 §9 방수/습도 — guard channel (신규 개념, 검토 후 배제)

큰 도전체(액체 풀) 검출용으로 별도 채널을 "guard channel"로 쓰는 기법이 언급됨(§9, "guard channel을 사용해 큰 물체를 검출"). 이는 **IQS323의 정식 채널 모드가 아니라** Independent 채널 + FW 자체 판단 조합이므로, 메커니즘상 **C-DUAL(SW 차동)의 하위 변형**일 뿐 새 채널-조합 클래스가 아니다. 또한 목적이 "큰 도전체(액체) 감지 후 터치 비활성화"이지 "코히런트 AC 노이즈 상쇄"가 아니어서 이번 문제에 직접 적용 안 됨.

### 3-3. AZD125 §10 노이즈/SNR — 공식 SW 튜닝 체크리스트 (핵심 대조)

Azoteq 자신의 "노이즈 내성 개선" SW 체크리스트 원문 전부를 이미 나온 5후보 테마와 1:1 대조:

| AZD125 §10 SW 체크리스트 항목 | 대응 후보 |
|---|---|
| Mutual 사용 시 변환주파수 ≥1MHz | 해당없음(self-cap 고정, 제약상 범위 외) |
| activation·release debounce 최적화 | **C-FILT**(레버 A) |
| count filter beta 최적화 | **C-FILT**(레버 B) |
| threshold 최적화(오검출 저감) | **C-FILT**(레버 C) |
| SNR≥3(비핵심)·≥5(핵심), 노이즈밴드×3/×5 | **C-FILT**(임계 설정 정량 기준, 이미 적용가이드 §4.4에 반영됨) |

**중요 판정**: Azoteq 공식 앱노트의 "노이즈 내성" 절 전체가 "코히런트 노이즈를 상쇄/제거한다"가 아니라 "신호와 노이즈를 구분할 마진을 벌린다(SNR 확보)"는 **통계적 여유 확대** 프레임에만 머문다. 즉 **Azoteq 자신도 config/channel/measurement 레벨에서 "적응형 코히런트 노이즈 캔슬링" 기능을 제시하지 않는다** — 이는 IQS323·AZD004·AZD125 3개 문서 전체에 그런 기능이 없다는 정황을 가장 강하게 뒷받침하는 근거다(제조사 자신의 권장 절차가 이 범주를 벗어나지 않음).

### 3-4. 명시적으로 검토 후 배제한 나머지 §7 UI 기능

| 기능 | 배제 사유 |
|---|---|
| **Release UI**(§7.4, Activation LTA) | 장기터치 **해제** 오검출 완화용 — 문제는 idle 상태 **진입(entry)** 오검출이라 목적 자체가 반대. Reference UI와 동일하게 touch/prox 상태를 전제하는 구조 |

| **Slider/Gesture**(§7.2) | 다채널 위치보간·제스처용. Sound1은 단일 버튼(슬라이더 미사용) — 적용 대상 자체 없음. Debounce 기반 false-trigger 방지 원리는 이미 C-FILT가 흡수 |
| **OutA**(§7.1) | 범용 출력/이벤트 인디케이터. 노이즈 상쇄 기능 아님 |

### 3-5. 명시적 안티레버(오히려 역효과) 확인

| 레지스터 | 내용 | 판정 |
|---|---|---|
| **Dual Direction**(Sensor Setup bit2) | 양방향(증가/감소 모두) 판정 활성 | **역효과**: 현재 단방향(감소=touch)만 트립 조건인데 양방향으로 열면 노이즈가 반대 방향으로 튀는 경우까지 트립 조건이 추가돼 오검출 **표면적 확대**. 채택 불가 |
| **0v5 Discharge**(Prox Control bit14) | Cs 0.5V 방전 | 데이터시트 원문 "this can introduce some noise" — **노이즈 증가** 명시. 기본 OFF 유지가 곧 최선(C-MEAS/M3 확인) |

| **Cs Size**(Prox Control bit12, 40/80pF) | 게인(count당 fF 감도) 조정 | C-FILT 레버 G(ATI Target/Resolution Factor)와 **동일 물리 한계** — 노이즈가 게인에 비례 증폭되면 상대 SNR 불변. 신호·노이즈 스케일이 같이 커지므로 "다른 conversion 방식"이 아니라 이미 식별된 게인-스케일링 논리의 반복일 뿐 |

## 4. 물리 판정 재확인 — 코히런트 vs 인코히런트 (독립 교차검증)

C-MEAS §1이 이미 정립한 논리를 본 세션에서 별도 자료(관측교란.md §4, AZD125 §10)로 **독립적으로 재확인**했다:

- 평균화(오버샘플)는 **매 샘플 무작위·비상관 성분**만 1/√N로 줄인다(통계학 일반 원리). fake_func_sleep()의 SPI/SYSCLK/QCC는 **상시 유지**(오케스트레이터 배경) — 순간 글리치가 아니라 지속적 애그레서에 가까워 평균화에 원리적으로 약하다.
- 예외 조건(관측교란.md 메커니즘_3, C-MEAS §1이 이미 지목): IQS323 내부 오실레이터(f_OSC 자유구동)와 SYSCLK가 위상 무관계이면 **느린 맥놀이**가 생겨 완전 고정 DC는 아니게 된다 — 그러나 이 AC 성분에 유효한 레버는 "노이즈 캔슬링"이 아니라 **변환주파수 재선택(C-MEAS/M2=C-SYNC-1)**뿐이며, 그마저 방향(개선/악화) 예측이 **불가능**(양 후보 공통 결론)하다.
- AZD125 §10 자체가 "노이즈 밴드 식별 → 그 배수로 임계 설정"이라는 **사후 마진 확보** 절차만 제시하고 "노이즈 원인을 상쇄한다"는 절차는 제시하지 않는다 — 제조사 공식 문서가 코히런트 캔슬링을 아예 다루지 않는다는 것 자체가, 이 재탐색이 데이터시트 범위에서 그런 기능을 못 찾은 것이 탐색 미비가 아니라 **기능이 실재하지 않기 때문**이라는 정황을 강화한다.

## 5. 최종 결론 — 은수님 보고용 핵심 문구

> **config·channel·measurement 레벨의 SW-only 레지스터로는 fake_func_sleep()의 코히런트 AC 클럭/SPI 노이즈를 상쇄할 수 없다.** IQS323 전체 레지스터맵(A.1~A.37)에 노이즈 검출 플래그가 없고, 채널 모드 3종(Independent/Follower/Reference)은 전부 LTA(저역통과) 레벨의 DC 드리프트 전용이며 touch/prox 상태 게이팅까지 걸려 idle 오검출과 무관하다. Azoteq 자신의 노이즈 대응 앱노트(AZD125 §10)조차 "상쇄"가 아닌 "임계 마진 확대"만 제시한다. 5후보가 이미 찾아낸 레버 중 살아있는 것은 (a) **디바운스/베타/임계 등 통계적 마진 확대**(C-FILT, 노이즈를 없애는 게 아니라 넘지 못하게 문턱을 높이는 것) (b) **변환주파수 재선택**(C-MEAS/C-SYNC-1, 방향 예측 불가·약한 근거)뿐이다. 이 범주 밖의 진짜 근본 대응은 애그레서 자체를 줄이는 물리완화(자체 애그레서 제거·드라이브 하향)와 타이밍 이격이며, 이는 IQS323 설정이 아니라 CM3/FPGA/QCC 쪽 조치라 본 프로젝트(config-reexplore) 범위 밖 — 자매 프로젝트(`20260703_touch-heisenberg-sw-mitigation`)가 이미 별도로 다루고 있다(C-SYNC §근거에서 확인).

**살아날 여지(조건부, 신규 아님)**: 노이즈가 실측상 "지속적 코히런트"가 아니라 "간헐적 버스트성"으로 밝혀지면 C-FILT의 디바운스/베타가 실효를 가지며, 특정 변환주파수가 우연히 애그레서와 나쁜 정수배 관계를 피하면 C-MEAS/C-SYNC-1이 부분 개선을 줄 수 있다 — 그러나 이는 **이미 식별된 레버의 실측 결과**일 뿐 본 완전성 비평이 발견한 새 회피 경로가 아니다. 이 판정 자체가 C-FILT §7의 게이팅 질문(지속성 vs 버스트성, 미확인)에 걸려 있다.
