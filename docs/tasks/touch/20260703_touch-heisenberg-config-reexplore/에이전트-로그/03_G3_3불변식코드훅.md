# 03 · G3 — 3불변식 코드훅

**TL;DR**: INV-CTRL-1(Full ATI)은 `apply_settings()`(iqs323.c:400~460) 단일 함수로 부팅마다 재적용. INV-CTRL-2(ATI에러 Re-ATI)·INV-CTRL-3(첫 터치 해제)은 노말·func_sleep()·fake_func_sleep() 3곳에 독립 구현(fake는 인라인 복제) — 한 곳만 고치면 재현경로(fake_func_sleep)에 미반영될 수 있다. 그 외 레지스터·채널·측정방식은 전부 자유.

## 0. 결론 먼저 — 최소 계약

| 불변식 | 지켜야 할 것 (계약) | 안 지키면 |
|---|---|---|
| INV-CTRL-1 | 0x36(REG_SENSOR0_ATI_SETUP) 필드가 상시 **Full 모드** 유지 + 부팅마다 Re-ATI 트리거·완료대기 시퀀스 실행 | IC 자동 게인/드리프트 복구(경로_1) 소멸 |
| INV-CTRL-2 | `ati_error && !ati_active` 감지 시 **어느 경로에서든** `tdc_touch_iqs323_re_ati()` 발행 | drift 영구화(IC가 자동 재시도 안 함, C2 §2 인용) |
| INV-CTRL-3 | 부팅/절전진입 직후 "이미 눌려있음" 무시 게이트 + **디바운스 해제 확정 + 동반 RESEED** | 오염된 baseline으로 판정 시작 → 오탐 |

그 외(레지스터값·채널수·CH1 활성화·측정모드·필터·리포트레이트 등)는 위 계약을 깨지 않는 한 후보가 자유롭게 바꿀 수 있다.

## 1. INV-CTRL-1 — Full ATI

**정의**: IC가 자동으로 게인을 산출·재조정하는 Full ATI 모드를 상시 유지, 부팅마다 명시 Re-ATI 트리거 후 완료를 확인한다.

| 항목 | 위치 | 내용 |
|---|---|---|
| Full 모드 write | `tdc_touch_iqs323.c:437` | `write_register(REG_SENSOR0_ATI_SETUP=0x36, 0x0C, 0x04)` → 0x040C. **런타임 재write 1건뿐**(코드 전체에 0x36 write 이 자리 유일) |
| 부팅 Re-ATI 트리거 | `tdc_touch_iqs323.c:447` | `write_register(REG_SYSTEM_CONTROL=0xC0, 0x54, 0x07)` — bit2 Re-ATI + Power No ULP(bits[6:4]=101) + CH timeout disable(0x07) |
| 완료 블로킹 대기 | `tdc_touch_iqs323.c:328~342` (`wait_ati_done_blocking`), 호출 `:451` | REG_SYSTEM_STATUS(0x10) 폴링, `ati_active`(bit5)==0 확인, 최대 25회×50배수 딜레이(약 1.25s). **코드 전체 유일한 블로킹 ATI 대기**(주석 :327 "운용 폴링은 논블로킹") |
| 컨테이너 함수 | `tdc_touch_iqs323_apply_settings()` (iqs323.c:400~460) | ack_reset→confirm_reset→sensor_setup→touch_settings→prox→events_enable→beta_power_settings→**0x36 Full**→**Re-ATI 트리거**→**wait 대기**→RESEED(453) 순서 고정 |

**호출 체인(부팅마다 1회)**:
```
main.c:373 Initialize()
  → initialize.c:448 tdc_touch_init_begin()  (MCLR, tdc_touch.c:180~189)
  → main.c:452 tdc_touch_process() 매 폴링
      → tdc_touch.c:282~286 (state==INIT_MCLR_DONE) → try_finish_init() (tdc_touch.c:149~178)
          → :151 tdc_touch_iqs323_is_ati_done() true 이거나 2500ms(TDC_TOUCH_INIT_TIMEOUT_MS) 타임아웃
          → :161 tdc_touch_iqs323_apply_settings()  ← INV-CTRL-1 본체
```
**중요**: `func_sleep()`/`fake_func_sleep()` 둘 다 기상 = `SYS_WATCHDOG_RESET()`(하드 리부팅)이지 소프트 레주메가 아니다 — 즉 위 체인이 **절전 기상마다 처음부터 재실행**된다(전용 절전 설정 없음, iqs323.c:497~499 / main.c:1215~1216 / main.c:845~846 3곳 모두 "절전도 노말과 동일 설정" 명시). 따라서 INV-CTRL-1은 "최초 1회"가 아니라 **"매 부팅 사이클마다"**가 정확한 표현.

**자유/불변 경계**: 0x36과 그 도달 시퀀스(437·447·451) 자체는 불변. `sensor_setup()`(266~282, CH0/1/2 enable 조합)·`touch_settings()`(284~290)·`beta_power_settings()`(309~325)는 전부 별개 레지스터라 자유 변경 가능 — INV-CTRL-1을 안 건드림.
**미확인**: CH1(0x40)을 실채널화할 때 CH1 전용 ATI 모드 레지스터가 IQS323에 별도 존재하는지(0x30/0x40/0x50처럼 REG_SENSORx_ATI_SETUP 패턴 유추 가능하나 코드엔 0x36 하나뿐) — 데이터시트 재확인 필요(G1/G2 소관, 본 노드 범위 밖). CH1 활성화 후보(C-RT/C-DUAL)는 이 갭을 반드시 메워야 함.

## 2. INV-CTRL-2 — ATI 에러 처리(Re-ATI)

**정의**: System Status bit6(`ati_error`)이 서고 ATI burst 중(`ati_active`)이 아니면 Re-ATI(0xC0 bit2)를 발행해 복구한다. IC는 ati_error를 자동 재시도하지 않는다(C2 §2 인용, 레지스터-맵.md §5.11 — 본 세션 데이터시트 원문 재대조는 안 함, 문서 인용으로 표기).

**3개 독립 구현 사이트** (공유 코드 없음, 각자 완결):

| 사이트 | 게이트 조건 | Re-ATI 발행 | 재시도 상한 |
|---|---|---|---|
| 노말 FSM | `tdc_touch_logic.c:154~161`: `NOT_TOUCH && !ati_active && ati_error && 쿨다운(2000ms, `TDC_TOUCH_RE_ATI_COOLDOWN_MS` time.h:25) 경과` | `tdc_touch.c:380~393`(switch) → `:391 tdc_touch_iqs323_re_ati()` | 무제한(쿨다운마다 재평가), 최종수단은 별개 stuck 경로 |
| `func_sleep()` | `main.c:1062~1092 tdc_touch_sleep_handle_ati_error()`, 조건 `:1064 ok&&ati_error&&!ati_active` (터치상태 무관) | `:1084 tdc_touch_iqs323_re_ati()` | **5회**(`:1066 5 < cnt`) 초과 시 `:1078 SYS_WATCHDOG_RESET()` |
| `fake_func_sleep()` | `main.c:945~972` **인라인 복제**(별도 함수 아님), 조건 `:947` — func_sleep 헬퍼와 논리 100% 동형 | `:960 tdc_touch_iqs323_re_ati()` | 5회(`:949`) 초과 시 `:953 SYS_WATCHDOG_RESET()` — **주석처리 안 됨, 살아있음** |

저수준 공통: `tdc_touch_iqs323_re_ati()` = `iqs323.c:462~466`, `write_register(0xC0, 0x54, 0x07)` — Power Mode·CH timeout 비트(INV-X-1, C2 §10 인용) 동반 필수. 새 트리거를 추가하는 어떤 후보든 이 조합을 이어받아야 함(단독 0x04만 쓰면 Power Mode가 Normal로 되돌아감).

**비대칭 유의**(기존 사양, 이번 작업이 만든 게 아님): 노말은 `NOT_TOUCH`일 때만 발행, 절전 2곳은 터치 상태 무관 무조건 발행 — 후보가 "통합"하려면 의식적 결정 필요.

**자유/불변 경계**: 재시도 횟수(5)·쿨다운(2000ms)·비대칭 자체는 자유 레버. 불변은 "3개 사이트 각각 `ati_error&&!ati_active` 감지 시 반드시 `tdc_touch_iqs323_re_ati()`가 발행된다"는 사실 하나. **채널을 늘리는 후보 유의**: ati_error가 전역 비트(채널 비구분, C2 §9 INV-⑧-2 인용)라서 CH1을 켜면 "CH0 에러/CH1 에러"를 이 로직이 구분 못 함 — 선택적 재-ATI(CH0만/CH1만)는 현재 레지스터 구조로 불가능해 보이나 데이터시트 재확인 필요(미확인).

## 3. INV-CTRL-3 — 첫(최초) 터치 해제 감지

**정의**: 부팅 READY 전이 직후 또는 절전 진입 직후 "이미 손이 닿아있는" 상태를 무시하고, 디바운스된 연속 노터치 확정 후에만 정상 판정을 재개하는 게이트.

**3개 독립 구현 사이트**:

| 사이트 | 상태변수 | 진입 조건 | 해제(디바운스) | 해제 시 부수효과 |
|---|---|---|---|---|
| 노말 `boot_ignore` | `tdc_touch_logic_state_t.boot_ignore`(logic.h:67) | READY 직후 첫 read `pressed==true`일 때만 — `tdc_touch.c:172~177` → `tdc_touch_logic_set_boot_ignore()`(logic.c:77~83) 호출 | 연속 not-pressed **3폴링**(`TDC_TOUCH_BOOT_RELEASE_DEBOUNCE_CNT`=ceil(300/100), time.h:27,33~34) — 게이트 로직 `logic.c:119~152`, 해제 판정 `:127~131` | 없음(로그만, `TDC_TOUCH_BOOT_RELEASED`) |
| `func_sleep()` `sleep_ignore` | main.c 지역변수, 진입마다 재초기화 | `func_sleep()` 진입 시 **무조건** true(`:1172`) | 연속 NOT_TOUCH **3샘플**(`TDC_TOUCH_ULP_NOTOUCH_DEBOUNCE_CNT`=3, time.h:40,44~45) — 헬퍼 `main.c:1095~1122`, 해제 `:1102~1107` | **RESEED 발행**(`:1104 tdc_touch_iqs323_reseed()`) |
| `fake_func_sleep()` | main.c 지역변수(`:877`), 동일 초기값 | 진입 시 무조건 true | 헬퍼와 100% 동형 **인라인 복제** `main.c:974~1001`, 해제 `:981~986` | **RESEED 발행**(`:983`) |

공통 안전장치: 게이트가 오래 안 풀리면(오염 지속) 강제 RESEED — 노말은 5000ms 경고만(`TDC_TOUCH_BOOT_WARN_MS`, logic.c:137~144, 게이트 안 풂), 절전 2곳은 10000ms(`TDC_TOUCH_ULP_FORCE_RESEED_CNT`=50, time.h:41,46~47)마다 RESEED만 반복 발행(게이트 유지) — `main.c:1115~1121` / `:993~1000`.

**불변**: (a) 디바운스 카운트 ≥1 유지(1샘플 즉시확정 금지), (b) 절전 2곳은 **해제 확정 시 RESEED가 반드시 동반**(C2 INV-②-2 — RESEED 없이 게이트만 풀면 절전 진입 시점 LTA 미동기 상태로 오탐 회귀), (c) 강제타임아웃 경로는 게이트를 열지 않고 RESEED만 반복.
**자유**: 디바운스 숫자(현재 3)·타임아웃 숫자(현재 50)·판정 입력 신호원(현재 CH0 `pressed` 단일 비트) 자체는 자유 — CH1 참조채널 도입 후보(C-RT/C-DUAL)가 "노터치"를 CH0-CH1 차감 결과로 바꾸는 것도 이 3박자(무시→디바운스 해제→RESEED 동반) 구조만 유지하면 허용.

## 4. 교차 컷팅 — 왜 "한 곳만 고치면 안 되는가"

INV-CTRL-2·3은 노말/`func_sleep()`/`fake_func_sleep()` **3중 독립 구현**이다(INV-CTRL-1은 `apply_settings()` 단일 함수이나 매 부팅 재실행이라 실질 3경로 모두 자동 적용됨 — 유일하게 "한 곳 수정으로 3경로 커버"가 보장되는 불변식).

| 불변식 | 노말 | func_sleep() | fake_func_sleep() | 3곳 동형? |
|---|---|---|---|---|
| INV-CTRL-1 | `apply_settings()` 1회(재부팅마다 자동 재적용) | 재실행 없음(부팅값 유지) | 좌동 | 사실상 공유(재부팅 경유) |
| INV-CTRL-2 | logic.c:154~161 + tdc_touch.c:391 | main.c:1062~1092(헬퍼 함수) | main.c:945~972(**인라인 복제**) | 논리 동형, 코드는 별도 |
| INV-CTRL-3 | logic.c:119~152(`boot_ignore`) | main.c:1095~1122(헬퍼 함수) | main.c:974~1001(**인라인 복제**) | 논리 동형, 코드는 별도 |

**배경과 연결되는 핵심 사실**: 은수님이 서술한 재현 시나리오(SYSCLK 30.72MHz 유지·QCC on·BLE/SPI 상시)는 `fake_func_sleep()`의 정의와 정확히 일치(C2 §11 인용 — 이 노드에서 직접 재확인: `ci_fake_power_sleep()`이 클럭을 낮추지 않고 30.72MHz 유지, QCC 셧다운은 `main.c:828`에서 주석처리, BLE는 `:899`에서 매 tick 서비스). **후보가 `tdc_touch_logic.c`나 `func_sleep()` 헬퍼(main.c:1062~1153)만 고치고 `fake_func_sleep()`의 인라인 복제(945~1001)를 빠뜨리면, 실제 재현 경로에는 그 변경이 반영되지 않는다** — 이는 C2 §11이 이미 지적한 "2026-07-02 리팩토링이 `func_sleep()`에만 적용, `fake_func_sleep()` 제외"와 동일한 함정.

참고(INV-CTRL 범위 밖이나 혼동 주의): `fake_func_sleep()`의 **롱터치→재부팅**(`main.c:1011 // SYS_WATCHDOG_RESET()`)은 주석처리된 no-op — 이는 C2 분류 기능⑤(롱터치)이지 INV-CTRL-3(첫 터치 해제)이 아니다. INV-CTRL-2(ATI에러 리부팅, `:953`)는 살아있음과 대비해서 헷갈리지 않도록 명시.

## 5. 자유 변수 목록 (요구사항 재확인용)

INV-CTRL-1~3의 코드훅(§1~3에 나열된 라인)을 건드리지 않는 한 아래는 전부 자유:

- **레지스터값**: 0x30/0x40/0x50(채널 enable 구성, CH1 현재 disable `iqs323.c:272`), 0x61/0x62(prox/touch 임계·히스테리시스), 0xB0/B1/B2/B4(베타필터), 0x31(컨버전 주파수), 0xC2/0xC5(LP리포트레이트/PM타임아웃), 0xD3(이벤트enable).
- **채널 수**: CH1을 disable→enable로 바꾸는 것 자체는 INV-CTRL-1~3 코드가 참조하는 필드(System Status의 CH0 전용 pressed=bit9·ati_error=bit6 전역)와 직접 충돌 안 함(§1 미확인·§2 전역비트 유의사항 예외).
- **측정 방식**: self-cap 유지 전제 하 reference tracking(Channel Mode=Reference) 포함 자유 — 단 **Channel Mode 레지스터 자체가 현재 코드에 없음**(`sensor_setup()`은 enable_channel+ctx0 비트만 write, iqs323.c:277) — 그 레지스터의 존재·주소·비트는 G1/G2·데이터시트 소관, 본 노드는 "현재 코드가 그 레지스터를 아예 건드리지 않는다"는 사실만 확인.

## 6. 리스크·미확인

- 0x36이 CH0 전용인지 전 채널 공용 ATI 모드 레지스터인지, CH1 전용 ATI 레지스터 존재 여부 — **미확인(데이터시트 확인 필요)**. 코드엔 `REG_SENSOR0_ATI_SETUP` 하나만 존재.
- `ati_error` 비트가 "전역(채널 비구분)"이라는 서술은 C2 인벤토리 인용(원출처 레지스터-맵.md §5.11)이며, 본 세션에서 데이터시트 PDF 원문을 재대조하지 않았다 — 코드 자체가 확인해주는 것은 "채널별 ati_error 구분 로직이 전무하다"는 사실(코드 근거)뿐, "전역"이라는 명명은 문서 인용.
- `wait_ati_done_blocking()`의 상한 25×50배수 딜레이가 실제로 약 몇 ms인지는 `TDC_TOUCH_IQS323_DEFAULT_DELAY_MS = SystemCoreClock/1000`(iqs323.h:36) 값에 의존 — 본 세션에서 `SystemCoreClock` 실제값을 재확인하지 않아 "약 1.25s"는 코드 주석(iqs323.c:332) 인용이지 재계산 검증치가 아님.
- 본 노드는 지정 4파일(iqs323.c/logic.c/touch.c/main.c) 범위의 **코드훅 특정**에 한정 — 각 불변식이 실제로 "왜" 필요한지(물리적 근거)는 C2·G1(reference tracking 실능력) 소관.
