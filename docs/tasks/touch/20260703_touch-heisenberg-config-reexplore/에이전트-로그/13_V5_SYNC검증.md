# 13 · V5 — C-SYNC(센서 동기·리포트) 검증

**TL;DR**: C-SYNC 3서브후보(변환주파수·Report Rate·Events모드) 재확인 결과 "기각/약함" 자평은 **정당**(killConfirmed=true). 진짜 AC 노이즈 **상쇄** 메커니즘은 0건 — 전부 확률적 노출회피뿐이다. 신규 발견: (1) C-SYNC-2 핵심 근거("Report Rate가 duty를 게이팅")가 실은 원문이 아니라 2차 참조문서의 해설이 인용사슬에서 "원문 확인"으로 격상된 인용팽창, (2) TIMER3 "100ms"가 코드 주석 내부에서 자체모순(≈200ms/100.0ms 병존), (3) Force Comm(Fig 8.2)이 "SCL없는 SDA토글"이 아니라 통상 클럭 I2C임을 원문 이미지로 재확인(에라타 우려는 약화 아니라 강화). 살아날 여지: 노이즈-상쇄 관점에서 없음.

## 판정 요약

| (3) Events모드 I2C Lock-Up 에라타 | **트리거 개연성 실재, 보드버전은 코드상 계측 자체 불가** | PDF 부록C(p.67) 원문일치 + 0xE1 read 0건 신규확인 |

## 1. Report Rate 자기맥놀이 — 개념 유효, "100ms" 수치는 미확정

- SW 폴링: `TDC_TOUCH_POLL_INTERVAL_MS = 100`(`tdc_touch_time.h:18`) — **확인, 정확**.
- TIMER3(ULP 웨이크): `main.c:868`(fake_func_sleep 경로) 주석 "≈200ms 주기" vs `main.c:1224`(func_sleep, 실 `ci_power_sleep()` 호출부) 주석 "100.0ms 정확" — **동일 매크로**(`TDC_TOUCH_ULP_TIMER_PRESCALE=TIMER_PRESCALE_1`, `TIMEOUT_VALUE=3999`, `tdc_touch_time.h:55-56`) 호출인데 코드 주석 자체가 상호모순. `ci_timer.h:61` 공식 "T=2^prescale×(tick+1)/40kHz(SLOWCLK=1.28MHz 기준)"도 "40kHz"와 "1.28MHz"가 32배 어긋나 그 자체로 모호하다.
- `ci_power.c:154,169,183` 직접 대조 결과 SLOWCLK가 정상(`SLOWCLK_PRESCALE_24`)·fake_func_sleep(동일 24)·func_sleep(`SLOWCLK_PRESCALE_2`, SYSCLK 12배 하강과 정확히 상쇄) **3모드 전부 1.28MHz로 고정**되는 것은 **확인·정확**(06_S4 인용 그대로 재확인, 계산 직접 검산). 그러나 이 사실이 "고정 SLOWCLK → 100ms 확정"까지 보장하지는 않는다 — prescale_field 실제 인코딩(2^1 vs 2^0)에 따라 100ms·200ms 두 갈래가 남고 코드 주석 자체가 양쪽을 모두 주장해 **자체모순 미해소**.
- **결론**: "SW 100ms ↔ TIMER3 100ms 근접"이라는 전제는 코드가 100% 확정해주지 않는다(미확인·실측 게이트). 다만 이는 위험을 없애지 않고 오히려 넓힌다 — TIMER3가 100ms든 200ms든 두 개의 독립 발진기(CM3 SLOWCLK계열 vs IQS323 자체 f_OSC)가 정수배·근접값을 취하면 표류하는 저속 맥놀이가 생긴다는 물리 원리(관측교란.md §4 메커니즘_3)는 그대로 유효 — "100ms류 값을 피하라"는 08_C-SYNC의 권고는 정확한 수치 확정 여부와 무관하게 **방향은 유효**하다.

## 2. "Report Rate=0"의 의미 — 원문 미명시, 정확히 확인됨

`iqs323_datasheet.pdf` p.32 §8.11.1 원문: "In I²C streaming mode data is constantly reported at the relevant power mode report rate...(ms) by the ... registers." §8.11.2도 이벤트 유무만 다룰 뿐 "0"의 정의 문장이 없다. **1차 소스(PDF) 직접 대조로 재확인** — 08_C-SYNC·V3·`3_종합결론.md` 전부 "미확인"으로 정직하게 표기한 것은 **과장이 아니라 근거 있는 겸손**이다.

## 3. Events 모드(0xC0 bit7) → I2C Lock-Up 에라타

- 0xC0 write 지점 코드 재실측(`tdc_touch_iqs323.c` 1-499행 전체 통독): **237(ack_reset, 0x01/0x00)·318(0x50/0x07)·447(0x54/0x07)·453(0x58/0x07)·465(0x54/0x07)·471(0x58/0x07) = 정확히 6곳**, 전부 bit7=0(Streaming) — 08_C-SYNC의 "6곳 중 5곳 수정(237 제외)" 주장은 **라인·값 전부 일치, 정확**(자매 검증 V3의 "5곳"보다 완전한 카운트).
- 부록C 원문(p.67): "IQS323-00x v1.3 and below · IQS323-A0x v1.4 and below... higher likelihood... when using force communications (§8.13)... read one byte from a register that does not exist. If not 0xEE, hard reset" — **`08_개정이력·이슈.md` 인용과 원문이 정확히 일치**.
- **신규 확인(본 노드)**: Figure 8.2(p.33) 원문 이미지를 직접 재대조한 결과 SCL 트레이스에 **클럭 펄스가 실재**하며 "Setup to write 0x44+ACK"→"0xFF+ACK" 라벨이 붙어 있다 — 이는 참조문서(`05_i2c인터페이스.md`) NOTE박스의 "SCL 없이 SDA 토글"이라는 서술과 **불일치**(참조문서 자체의 부정확한 각색이며 08_C-SYNC가 만든 오류는 아님). 실제로는 **표준 클럭 I2C로 주소(0x44)+데이터(0xFF) 쓰기**이며, 이는 `force_window_open()`의 `i2c_write(&force_comm,1)`(0xFF write 실제 위치는 `tdc_touch_iqs323.c:155`)과 **메커니즘이 사실상 동일**하다 — 08_C-SYNC가 "미확인"으로 남긴 질문을 본 노드가 원문 이미지로 해소하며, 답은 "예, 같은 메커니즘"이다. **이는 에라타 우려를 약화가 아니라 강화**한다.
- 보드 IC 버전: `tdc_touch_iqs323.c` 전체에 `0xE1`(Hardware ID)·`0x00~0x09`(Version) read 코드 **0건**(본 노드 재확인) — 즉 "미확인"이 아니라 **현재 코드로는 확인 자체가 불가능**(신규 `read_register(0xE1,...)` 추가 없이는 실측 불가). 08_C-SYNC의 "미확인" 표기는 사실이나 이 심각도(계측 자체 부재)까지는 명시하지 않았다 — 본 노드가 정밀화.
- **인용 정밀도**: 08_C-SYNC는 이 사실을 `force_window_open()(iqs323.c:145-152)`로 인용했는데, 실제 0xFF write문은 154-155행이고 145-152는 함수 시작+조기반환 검사부뿐이다 — 근사 인용(함수 전체 범위 145-175 안에는 있음), 결론에는 영향 없음.
- **판정**: 에라타 트리거 개연성 주장은 원문·코드 전부와 정합해 **신뢰도 높음**(V3의 독자 발견을 본 노드가 재확인). IC 버전 미확인 상태에서 "저위험"으로 채택하는 것은 부당 — V3·08_C-SYNC 공통 결론("보류") 지지.

## 7. 종합 — AC 노이즈 실제 저감 근거

C-SYNC 3서브후보 전부 **"상쇄(cancel)" 메커니즘 없음** — C-SYNC-1은 노출창 시간만 바꾸고 역효과까지 확인됨(S1/V1), C-SYNC-2는 duty 조절 가설이나 1차 근거 미확인(위 §6), C-SYNC-3은 SPI·SYSCLK 애그레서와 애초 무관(08_C-SYNC 자인, 본 노드 확인)하고 부수 애그레서(RDY 핀)만 다루며 신규 리스크(에라타)까지 동반한다. 원 재탐색의 make-or-break 질문("AC 클럭/스위칭도 상쇄하나")에 **셋 다 "아니오"**로 답이 확정된다.

**killConfirmed = true.** "기각/약함" 자평은 사실과 대조해 **정당함이 확인**됐다. 노이즈-상쇄 관점에서 살아날 여지는 없다. 단 C-SYNC-1(500kHz)은 이미 별도 트랙(S1/V1)에서 "무회귀 실험적 값 변경"으로 조건부 생존해 있으나, 이는 본 검증 대상인 C-SYNC 고유 기여가 아니라 상속된 결론이다.
