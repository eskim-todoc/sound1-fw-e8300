# 08 · C-SYNC — 센서 동기·리포트 (후보 생성)

**TL;DR**: IQS323엔 위상동기 핀·레지스터가 **부재**(교차확인) — "동기"는 위상고정이 아닌 자유구동 파라미터 선택으로 애그레서와 통계적 겹침만 줄인다. 3후보: C-SYNC-1(변환주파수, 근거 약, 선행검증완료)·C-SYNC-2(Report Rate, 근거 중·조건부)·C-SYNC-3(Events모드, 주애그레서 무관+Lock-Up위험, 근거 약). 전부 3불변식과 레지스터 분리되나 0xC0 공유 리스크는 있음.

---

## 0. 전제 정정 — "동기"는 위상동기가 아니다

데이터시트 3종 패키지 핀맵(01_개요·전기·타이밍.md §2, 원문 p.6-9) + 메모리맵 전체(06_레지스터레퍼런스.md §9+부록A, 원문 p.35-37/49-64) 양쪽에서 외부 클럭 입력·동기 트리거 핀/필드가 **부재**함을 이미 2개 노드가 독립 확인했다(G2 §3 `데이터시트/06_레지스터레퍼런스.md §9 전체`, `03_S1_변환전하전달오실레이터.md` §0). 본 노드도 반증 시도했으나 재확인 실패 — IQS323은 내부 발진기(f_OSC≈14MHz, 공차 ±5.5%, `01_개요·전기·타이밍.md` §4.3) 기반 **완전 자유구동**이다. 따라서 이하 "센서레벨 동기"는 **의도적 위상 고정이 아니라, 자유구동 파라미터를 골라 애그레서와의 겹침 확률/시간을 줄이는 확률적 회피**를 의미한다 — e8300측(S4, 선행 노드)이 "SPI를 스케줄"하려던 것과 대칭적으로, 센서측도 실제로는 "스케줄"이 아니라 "선택"만 가능하다.

## 1. 작동 메커니즘 (3후보)

| 후보 | 레버 | 메커니즘 (관측교란.md §4 3메커니즘 기준) |
|---|---|---|
| **C-SYNC-1** | Conversion Frequency Period(0x31 MSB, A.6) | 1회 변환 소요시간(노출창) 자체를 바꿈 — 메커니즘_2(창 길이)·메커니즘_3(SYSCLK 정수배 이격) 대상. **선행 노드(S1/V1, 20260703_touch-heisenberg-sw-mitigation) 이미 상세 검증 완료** — 본 노드는 요지만 재인용 |
| **C-SYNC-2** | NP Report Rate(0xC1, 신규) | 변환 사이클 사이 **idle(비활성) 구간**을 만들어 총 노출시간(duty cycle) 자체를 줄임 — 메커니즘_2의 "창 밖 시간 비중"을 늘리는 접근. 현재 0xC1은 코드에 아예 정의·write가 없어 reset값(0x0000) 그대로 |
| **C-SYNC-3** | Interface Selection(0xC0 bit7, A.30) | Streaming→Events 전환 시 RDY 핀 자체의 주기적 토글(부수 애그레서 후보)이 idle 구간에 사라짐 — **SPI/SYSCLK 자체와는 무관**, RDY(DIO16)라는 별도 소스만 겨냥 |

## 2. AC 노이즈 실제 저감 여부 (근거강도)

| 후보 | 메커니즘_1(결합임피던스) | 메커니즘_2(창 노출) | 메커니즘_3(에일리어싱) | **종합 근거강도** |
|---|---|---|---|---|
| C-SYNC-1 | 거의 무관(f=애그레서 주파수, Fxfer 아님) — S1 자인정+V1 재확인, 반박 실패 | **역방향**: 하향 시 노출창↑ 불리(V1이 "누적 주입 전하" 논리로 보강 재확인) | 근사 부합하나 근사치(SPI 정확 주파수 미확인 + f_OSC 공차±5.5%) | **약** (S1/V1 결론 그대로 인용) |
| C-SYNC-2 | 무관(Report Rate는 대역/주파수가 아니라 duty cycle 변수) | **정방향 가능성**: `02_proxfusion동작.md` §5.2 원문("NP: 매 Report Rate마다 모든 채널 전체 conversion"·"LP: Report Rate 간격↑ → 아날로그 블록 off 시간↑") — Report Rate가 실제 아날로그 duty를 게이팅한다는 근거는 **LP행에서 확인**, NP 행 적용은 유추(미확인) | 값이 SW 100ms 폴링·SLOWCLK 등 다른 자유구동 주기와 우연히 근접하면 **자기 맥놀이 재도입 위험**(V3 §2 신규위험2 — 아래 §5) | **중(조건부)** — "노이즈 상쇄"가 아니라 "노출시간 비중 감소"가 정확한 표현, 정량 효과는 실측 필요 |
| C-SYNC-3 | 무관 | RDY(DIO16) 핀 스위칭 제거뿐 — **CRx0 대비 실제 PCB 인접도 미확인**(S3 §9 인정), 유효해도 부수효과 | 무관(위상 관계 자체가 안 바뀜) | **약(주 애그레서 무관, 부수 애그레서 한정)** — 오케스트레이터가 지정한 "SPI·SYSCLK 비트에서 이격"에는 직접 대응하지 않음을 명시해야 함 |

> [!WARNING]
> C-SYNC-3은 명칭("Interface Selection")과 달리 **SPI·SYSCLK 애그레서를 전혀 다루지 않는다** — 이 사실을 후보 목록에 넣는 이유는 오케스트레이터가 "센서 자체 변환 타이밍/리포트레이트/**동기 설정**"이라 명명한 범주에 데이터시트상 대응하는 유일한 "통신 스케줄" 레지스터이기 때문이며, 실효는 별개 문제임을 조기에 못박는다.

|---|---|---|---|---|
| C-SYNC-1 | Conversion Frequency Setup(0x31 MSB=Period, A.6) | `tdc_touch_iqs323.c:316` `0x057F`(Period=5→1.00MHz, self-cap 상한 마진 0) | Period=12(500kHz, 자기용량 예시 기준점) — S1-1 그대로 | 상세 시퀀스·트레이드오프는 `03_S1_변환전하전달오실레이터.md`·`11_V1_S1검증.md` 참조, 본 노드 재도출 없음 |

## 4. 3불변식(INV-CTRL-1~3) 보존

| 불변식 | C-SYNC-1 | C-SYNC-2 | C-SYNC-3 |
|---|---|---|---|
| INV-CTRL-1(Full ATI, 0x36 + 부팅 Re-ATI 트리거+대기) | **무손상** — 0x31·0x36 별도 레지스터(G3 §1 자유변수 목록과 일치), 순서상 0x31 write가 0x36보다 먼저라 안전(V1 (b) 확인) | **주의(미확인)** — Report Rate가 ATI burst 내부 반복주기에도 적용되는지 원문 명시 없음(V3 §2 신규위험1). 적용된다면 `wait_ati_done_blocking()`(iqs323.c:328, 25×50ms≈1.25s 상한) 여유 잠식 가능 — 단 타임아웃 시 코드는 경고만 남기고 진행(비파괴) | **무손상(값 자체는)** — bit7은 0x36과 별도 필드. 단 **트리거 시퀀스 위험**: 5개 write 사이트 중 하나라도 bit7 누락 시 그 write 이후 Streaming 회귀(값 손상은 아니나 "설정 유지"라는 계약이 깨짐) |
| INV-CTRL-2(ati_error→Re-ATI, 3사이트 공유 `tdc_touch_iqs323_re_ati()`) | 무손상 — 0x31 write는 부팅 1회, 절전 재write 없음(iqs323.c:497-499 확인) | 무손상(레지스터 분리) — 단 위 ATI 타이밍 리스크가 간접 파급 가능 | **주의** — `re_ati()`(iqs323.c:465)가 유일한 저수준 진입점이라 **1곳만 고치면 3사이트(노말/func_sleep/fake_func_sleep) 전부 커버**(G3 §4 "유일하게 3경로 자동 적용" 성격과 유사) — 단 그 1곳을 놓치면 3사이트 전부 동시에 회귀 |
| INV-CTRL-3(첫 터치 해제, RESEED 동반) | 무손상 | 무손상 | 상동 — `reseed()`(iqs323.c:471) 1곳 수정으로 3사이트 커버, 누락 시 3사이트 동시 회귀 |

**종합**: 3후보 모두 레지스터 자체는 INV-CTRL 코드훅(0x36/0xC0 트리거비트/게이트로직)과 값 수준에서 충돌하지 않는다(G3 §5 자유변수 목록에 0x31·0xC1·0xC0 bit7 모두 해당 사항 없음 = 자유). 유일한 실질 리스크는 **C-SYNC-3이 0xC0을 공유**해 트리거 로직과 같은 레지스터에 값을 얹는다는 점 — 다만 저수준 함수가 중앙화되어 있어(`tdc_touch_iqs323_re_ati()`/`reseed()`) 수정 지점 자체는 5곳(모두 `iqs323.c` 내부)으로 유한하다.

## 5. 한계·리스크

1. **C-SYNC-2 자기모순 위험(V3 §2 신규위험2, 본 노드도 재확인)**: 제안값이 SW 폴링주기(100ms, `TDC_TOUCH_POLL_INTERVAL`) 또는 절전 진입 시 TIMER3 재구성 주기(100ms, `06_S4_e8300타이밍협조.md` 인용 `ci_timer_init_prescaled(PRESCALE_1,3999)`)와 근접/일치하면, IQS323 자체 발진기와 CM3 SLOWCLK라는 **서로 다른 두 자유구동 오실레이터가 새 맥놀이(느린 위상 표류)** 를 만들 수 있다 — 애그레서 회피책이 같은 성격의 문제를 재도입하는 역설. 100ms류 "깔끔한" 값을 피하고 의도적으로 이격된 값을 골라야 한다.
2. **C-SYNC-2 "0" 의미 미확인**: Report Rate=0이 "지연없이 최대속도 연속변환"이라는 해석은 `RDY 윈도우 타이밍 분석/3_종합결론.md`의 **추정**(원문에 "0"을 명문 정의하는 문장은 미확인)이며, 본 노드가 원문에서 직접 재확인하지 못했다 — 실측(RTT/오실로스코프) 또는 Azoteq 문의 선행 권고.
3. **C-SYNC-3 I²C Lock-Up 에라타(본 노드 직접 확인, `08_개정이력·이슈.md` 부록C)**: "IQS323-00x v1.3 이하·A0x v1.4 이하에서 §8.13 force communications 사용 시 I²C read가 상수값 반환 상태에 빠질 가능성 증가"(원문 인용). 현 코드 `force_window_open()`(iqs323.c:145-152)은 RDY가 이미 열려있지 않으면 0xFF write로 강제 오픈한다 — Events 전환 시 idle(무이벤트) 구간엔 RDY가 계속 닫혀 있으므로(§8.11.2 원문 확인) **100ms마다 이 강제-오픈 경로가 상시화**되어 에라타 트리거 빈도가 오히려 **높아질 개연성**. 단, `force_window_open()`의 0xFF write(표준 I²C 바이트 write)가 §8.13 Figure 8.2가 기술하는 "SCL 없는 SDA 토글 패턴"과 동일 메커니즘인지는 **본 노드가 직접 대조하지 못함(미확인, WF2 확인 항목)** — 다르다면 에라타 적용 여부 자체가 달라질 수 있다. 현재 보드 실장 IQS323 버전(Hardware ID 0xE1)도 **미확인**.
4. **C-SYNC-3 아키텍처 전제 불일치**: Events 모드의 "CPU 부하 낮음" 이점(§8.11.2)은 **RDY 인터럽트 기반 폴링**을 전제한다. 현 코드는 100ms GPIO busy-wait 폴링(RDY 종합결론.md §3.3)이라 이 전제가 성립하지 않고, 오히려 강제-오픈 빈도 증가(§5-3)로 이어진다 — bit7만 뒤집는 것은 데이터시트가 상정한 사용법이 아니다.
5. **C-SYNC-1은 이미 별도 노드(S1/V1)가 상세 검증 완료** — 본 노드가 중복 재도출하지 않은 이유이며, 채택 판단은 그 문서를 1차 근거로 한다(경계선상 근거: "약").
6. **CH1 교차영향 미검토**: 오케스트레이터 스코프는 CH1 병용도 자유변수로 허용하나, CH1이 활성화되면 자신의 Conversion Frequency(0x41)·Report Rate 영향(공용 0xC1)을 받는 채널이 하나 늘어 C-SYNC-1/2 효과 계산이 복잡해진다 — 이는 C-RT/C-DUAL 후보의 영역이라 본 노드는 존재만 표기.

## 6. WF2 사실대조 체크리스트

- [ ] 0xC1(NP Report Rate) 주소·range(0-3000ms)·reset값(0x0000) — `06_레지스터레퍼런스.md` §9 원문(및 가능하면 PDF p.35-37) 재대조.
- [ ] 코드에 0xC1 write/매크로가 정말 0건인지 — `tdc_touch_iqs323.c` 전체 재grep(본 노드는 REG_ 정의+리터럴 병행 확인함).
- [ ] `02_proxfusion동작.md` §5.2 "NP: 매 Report Rate마다 모든 채널 전체 conversion" 원문이 실제로 이 문구인지, "NP 행에도 duty-gating이 적용"이라는 본 노드의 유추가 과도한 해석이 아닌지.
- [ ] Report Rate가 ATI burst 내부 주기에도 적용되는지 — 원문(§5.9-5.11, 02_proxfusion동작.md 전체범위 p.15-20 내)에 명시 문장이 정말 없는지 반증 시도(본 노드는 절 제목만 확인, 절별 정확 페이지는 미확인).
- [ ] 0xC0(A.30) bit7=Interface Selection, bits[6:4]=Power Mode 비트 위치 — 원문 재대조(본 노드는 06_레지스터레퍼런스.md만 근거, PDF 직접 대조 안 함).
- [ ] `tdc_touch_iqs323.c`의 0xC0 write 사이트가 정확히 6곳(:237,318,447,453,465,471)인지, ack_reset 1곳 제외 로직이 타당한지 코드 재확인.
