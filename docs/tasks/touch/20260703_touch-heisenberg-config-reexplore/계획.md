# 계획 — 재탐색 후 권고

**TL;DR**: 넓힌 스코프(설정·채널·측정 자유) 재탐색의 fact-verified 결론은 **"config/channel/measurement 레벨로는 코히런트 AC 클럭/SPI 노이즈 상쇄 불가"**. reference tracking·SW 차동 모두 데이터시트로 기각됐다. 따라서 실효 SW-only 경로는 **상쇄가 아닌 완화** — 선행 구현계획([`20260703_touch-heisenberg-sw-impl`](../20260703_touch-heisenberg-sw-impl/))의 물리완화·타이밍 포트폴리오(P0 실측→P1 read_debug 제거→P2 드라이브 하향→P5 라이드스루)로 수렴한다. 본 계획은 방향 결정이며 코드 변경은 승인 후.

> [!IMPORTANT]
> 제품 소스 변경 0(계획 단계). 아래는 방향 결정. 실제 구현은 승인한 경로를 별도 작업(④)으로.

## 1. 결론 (fact-verified)

- 은수님이 열어주신 넓힌 스코프에서 **가장 기대했던 reference tracking을 포함해, 설정·채널·측정 레벨의 어떤 SW 레버도 코히런트 AC 노이즈를 상쇄하지 못한다** — IQS323 전체 레지스터맵+Azoteq 앱노트로 확정, Azoteq 자신도 "SNR 마진 확보"만 제시.
- 검증이 이를 **사실로 차단**(reference tracking·SW 차동 기각, 할루시네이션 0) → 이 방향으로 구현에 들어갔다면 헛수고였을 것.
- 상세: [`분석.md`](분석.md)·[`에이전트-로그/99_종합.md`](에이전트-로그/99_종합.md).

## 2. 그럼 남는 것 — 완화 포트폴리오 (상쇄 아님)

config-level 상쇄가 불가하므로, 실효 SW-only는 **애그레서 제거 + 결합 저감 + 재부팅 완충 + SNR 마진**뿐이며, 이는 이미 구현-레디로 정리돼 있음([`20260703_touch-heisenberg-sw-impl/계획.md`](../20260703_touch-heisenberg-sw-impl/계획.md)):

| 단계 | 조치 | 성격 |
|---|---|---|
| **P0** | RTT 실측으로 지배 애그레서·H2(read_debug 자체 애그레서) 확정 | 선결 |
| **P1** | 계측 read_debug latch 버그 제거/스로틀 — **관측이 대상을 흔드는 부분 제거** | 근본 근접 |
| **P2** | GPIO 드라이브 하향(I2C0·SPI1) — 결합 dV/dt 저감 | 물리 완화 |
| **P5** | fake_func_sleep 재부팅 문턱 확장(카운터) — 완충 | 안전망 |

- **C-FILT Threshold는 비권고**(헤드룸 소진, 과거 실패 재현 위험).
- 참고문서 오류 3건(Beta 4비트 등) 정정은 선택.

## 3. 정직한 한계 ("정말 없으면 포기" 지점 관련)

- **"클럭 노이즈를 상쇄한다"는 형태의 해법은 이 IC·보드에서 SW로 존재하지 않는다** — mutual(HW), reference tracking·SW차동(config)까지 전부 사실로 배제됨.
- 남는 완화 포트폴리오는 **노이즈를 없애는 게 아니라 견디게/줄이게** 하는 것이며, "충분한가"는 **P0 실측으로만** 판정된다.
- 만약 완화 포트폴리오로도 프로파일링 안정이 불충분하면, 선택지는 (a) 관측을 덜 침습적으로(선행 S7/P1 방향: 절전 RAM 버퍼링·기상 후 덤프), (b) 프로파일링 구성 자체를 완화, (c) 해당 프로파일링 시나리오의 한계를 수용 — 이 지점이 은수님이 말씀하신 "정말 없으면 포기" 판단 영역.

## 4. 은수님 결정 요청

1. **재탐색 결론 수용**: config/channel/measurement 상쇄 해법 없음(reference tracking 기각)을 확인하시는지.
2. **완화 포트폴리오로 진행**: 선행 구현계획(P0→P1→P2→P5)을 실효 경로로 채택하고, **P0 실측부터** 착수할지.
3. **참고문서 오류 3건 정정** 여부(Beta 4비트 등).
4. (해당 시) 완화로도 부족할 경우의 대안(관측 덜 침습적 재설계 vs 시나리오 한계 수용) 선호.

승인 후, 선택한 경로를 별도 작업(④)으로 착수하겠습니다. P0 실측 항목은 [`20260703_touch-heisenberg-sw-impl/에이전트-로그/01_P0_실측프로토콜.md`]에 구현-레디로 준비돼 있습니다.
