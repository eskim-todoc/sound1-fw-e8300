# service 모드 RTT 디버그 콘솔 — 이력

**TL;DR**: 2026-05-07 요구사항 작성 시작 ~ 2026-05-08 검증·머지 완료. 부트로더 UART 디버그 모드(`tdc_boot_debug_mode` 등 4 함수, ~140 줄) 폐기 + storage init 시퀀스를 `tdc_boot_storage_init()` 헬퍼로 추출 + service 모드에 RTT 디버그 콘솔 신설. 출력 형식은 외부 도구 [`sound1-fw-extractor`](../../../../../sound1-fw-extractor) 명세 준수 — `dump` 단일 명령으로 4 파일 (`MANIFEST.TXT` + `APP000~002.FEZ`) 일괄 hex 덤프 → fw.txt 캡처 → Python 도구가 4 바이너리 자동 추출. RTT up 채널은 service 모드 한정 BLOCK_IF_FIFO_FULL 전환 (drop 0 보장). 사용자 extractor 추출 통과 (`MANIFEST.TXT` 45 B + `APP000~002.FEZ` 178336/9476/1280 B + 경고 0).

작업 슬러그: `bootloader/service-rtt-debug-console`
브랜치: `claude_feature_service-rtt-debug-console` (base: `claude_develop`)
기간: 2026-05-07 (요구사항 작성) ~ 2026-05-08 (검증·머지)
상태: **완료** (사용자 검증 통과)

## 3. 주요 설계 결정

| ID | 결정 | 근거 |
|---|---|---|
| 결정_1 | 부트로더 UART 디버그 모드 코드 폐기 | 사용자 미사용. 사이즈 절약 (~-300 B) |
| 결정_2 | `bootloader_boot()` storage init 부분 (NVMInit ~ NVMSync) 을 `tdc_boot_storage_init()` 헬퍼로 추출, 부트로더·service 양쪽 호출 | 사이즈 우선, 1 벌만 존재. service 가 NVM/FATFS init 누락 해소 |
| 결정_3 | service LED 8 색 순회 루프 폐기. 디버그 명령 처리 루프 안에서 백그라운드 tick (380 iter ≈ 380 ms) | 정밀 무관, 단순 카운트로 코드 사이즈 최소 |
| 결정_4 | 헬퍼 책임 = NVM/FATFS init 만. `snd_boot_*` / `tdc_boot_print_boot_file` (OTA DFU 이미지 슬롯 선택) 은 부트로더만 호출 (service 미해당). `tdc_boot_get_ohdl()` getter 로 service 의 `_print_fw_file` 이 부트로더 정적 변수 `ohdl` 재사용 (별도 fp 변수 폐기) | service 는 슬롯 처리 자체 불필요. 사이즈 절약 |
| 결정_5 | 출력 형식 = [`sound1-fw-extractor` 명세](../../../../../sound1-fw-extractor/docs/사용방법/Sound1%20측%20fw.txt%20출력%20명세.md) 준수. 5 명령 → 단일 `dump` (4 파일 일괄). 마커 = 데이터 영역 (`========== FW DUMP BEGIN/END ==========`) + 파일 (`:::FILE:<NAME>:BEGIN/END:::`). 데이터 라인 = `%02X ` × 16 B + `\n`. 데이터 영역 안 LF only | 외부 Python 도구 자동 파싱 → 4 바이너리 자동 추출. 명령 5 → 2 통합으로 사이즈 절약 |
| 결정_6 | service 모드 한정 RTT up 채널 0 모드 = `SEGGER_RTT_MODE_BLOCK_IF_FIFO_FULL` (`SEGGER_RTT_SetFlagsUpBuffer(0, ...)` 진입 첫 줄). 부트로더 본체 무관 | 기본 NO_BLOCK_SKIP 은 1024 B buffer 가득 시 호출 통째 drop. dump (~52 B / 16 B 청크) 가 host (auto-rtt-viewer 10 ms polling, ~100 B/ms drain) 보다 빨리 누적 → drop. BLOCK 모드는 자동 backpressure (인터랙티브 콘솔이라 stall 허용) |

`reboot` 동작: `[SERVICE] reboot requested. Resetting in 500ms...` 출력 → 500 ms LED tick + watchdog refresh 유지 (RTT flush 보장) → `SYS_WATCHDOG_RESET()` 직접 호출 → 즉시 HW reset → `main()` 재진입.

## 4. 외부 도구 협업 패턴 (학습)

- **검증 자동화**: extractor 가 `[경고]` 메시지로 마커 짝맞춤 / 누락 파일 자동 검증 → 사용자가 `python src/main.py` 한 번으로 수용_2 통과 확인
- **줄바꿈 정책 분리**: 데이터 영역 안 LF only (extractor 정규식 호환) / 데이터 영역 밖 CRLF (viewer 가독성) — 영역별 분리 정책으로 양쪽 모두 만족

### 5.1 현상

Step 1~3 commit 후 사용자 빌드: 빌드 에러. 사용자 진단:

### 5.2 원인

[`bootloader.c:1404`](../../../../src/0__bootloader/source/bootloader.c) doxygen 주석 안에:

```c
/**
 * ...
 * 책임 외: LED 가드, app_name 결정, OTA 슬롯 선택(snd_boot_*/tdc_boot_print_boot_file),
 *                                                            ^^^
 *                                          이 '*/' 가 주석을 일찍 닫음
 * ...
 */
```

`snd_boot_*/tdc_boot_print_boot_file` 의 **`*/` 시퀀스가 주석 종료 토큰** 으로 해석 → 이후 한글 + 함수 시그니처가 모두 코드로 파싱 → 줄줄이 syntax error.

### 5.3 fix

`*` 와 `/` 사이 공백 1 칸 삽입: `snd_boot_* / tdc_boot_print_boot_file`. 가독성 동일, 컴파일러 토큰 분리.

부수 fix: `ci_boot.h` 의 `<bootloader_internal.h>` include → `struct _bootloader_boot_information;` forward declaration 으로 대체. transitive 헤더 의존 단순화 — ci_boot.c / service.c 다른 컴파일 단위에서 aes.h / bootloader_application_file.h 등 부수 의존 충돌 회피.

## 6. RTT NO_BLOCK_SKIP drop 동작 (학습)

큰 파일 dump 중 데이터 누락 우려 → SEGGER RTT 동작 정밀 분석 결과:

- **NO_BLOCK_SKIP 모드 (기본)**: buffer 가득 시 **write 호출 통째 drop** ([`SEGGER_RTT.c:1144~1148`](../../../../src/0__bootloader/source/segger_rtt/SEGGER_RTT.c) `Avail < NumBytes → Status = 0`). 부분 drop 아님
- **버퍼 1024 B**, **호출당 최대 64 B** (vsnprintf), **호스트 polling 10 ms** (auto-rtt-viewer)
- 청크 당 194 B (64 hex) 또는 52 B (16 hex) 가 polling 사이 누적 → buffer 임계값 초과 시 drop

**대안 비교**:

| 옵션 | 평가 |
|---|---|
| chunk 당 5 ms delay | 출력 시간 ~1.6 s 증가 (10 KB 기준), 마진 60% |
| **선택**: BLOCK_IF_FIFO_FULL 전환 | drop 자체 원천 차단 (CPU stall 자동 backpressure). 코드 1 줄. 부트로더 본체 무관 |
| 전역 BLOCK 모드 | 부트로더 본체 RTT 출력도 stall — 부팅 시간 영향 우려 → 반려 |

`SEGGER_RTT_SetFlagsUpBuffer(0, SEGGER_RTT_MODE_BLOCK_IF_FIFO_FULL)` 한 줄로 service 모드 한정 적용. 사용자 검증 통과.

## 7. 호출자 영향

| 위치 | 영향 |
|---|---|
| `bootloader_main()` → `bootloader_boot()` | storage init 부분이 `tdc_boot_storage_init(&boot_info)` 호출로 단순화. app_name 결정 / LED 가드 / OTA 슬롯 선택 (`snd_boot_*` + `tdc_boot_print_boot_file`) 은 그대로 부트로더에 남음. 동작 동일 |
| `bootloader_main()` 직전 `tdc_boot_debug_mode()` 호출 1 줄 | 삭제. `CI_BOOT_COUNT_DOWN_SEC=0` 이라 카운트다운 즉시 통과 + `\n` 미입력 시 디버그 모드 미진입 → 기존에도 사실상 미사용. 영향 없음 |
| `service_main()` | LED 8 색 순회 루프 폐기 → RTT BLOCK 모드 전환 + `tdc_boot_storage_init(NULL)` + RTT 콘솔 + LED tick 으로 전체 재작성 |

| 부트로더 부팅 시퀀스 (CFX/CM3 boot, FATFS, NVM) | 영향 없음 — 코드 이동만 (수용_5 통과) |
