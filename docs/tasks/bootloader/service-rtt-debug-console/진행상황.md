- (사용자 피드백 2026-05-07 4차) 결정_8: 결정_7 수정 — service 는 슬롯 처리 자체 불필요라 `snd_boot_set_fp` / `snd_boot_handle_file` / `tdc_boot_print_boot_file` 모두 호출 안 함. `tdc_boot_get_ohdl()` getter 는 service 의 `_print_fw_file` 이 부트로더 정적 변수 `ohdl` 을 재사용용 (별도 `s_tdc_service_fp` 변수 폐기, 사이즈 절약). 부트로더는 같은 파일 내 정적 변수라 `&ohdl` 직접 사용 (분석.md §2.2)
- (구현 단계 2026-05-07) 구현_1: Step 1 (storage init 헬퍼 추출 + ohdl getter), Step 2 (UART 디버그 모드 4 함수 폐기), Step 3 (service.c RTT 디버그 콘솔) commit. LED 가드 위치가 `bootloader_load_manu_table` 직후 → `NVMSync` + app_name 결정 후로 ~수십 ms 늦춰짐 (LED/bootloader-power-on-indicator AC-1 측정 검증 필요)
- (fix 단계 2026-05-07) 구현_2: 빌드 에러 fix — bootloader.c L1404 doxygen 주석 안 `snd_boot_*/...` 의 `*/` 가 주석을 일찍 닫음. `*` 와 `/` 사이 공백 1 칸 추가. + ci_boot.h 의 `<bootloader_internal.h>` include 를 `struct _bootloader_boot_information;` forward declaration 으로 대체 (transitive 헤더 의존 단순화). 회고 [`docs/회고/코딩.md`](../../../../../docs/회고/코딩.md) "doxygen 주석 안 `*/` 시퀀스 금지" 추가
- (사용자 승인 2026-05-08) 결정_9: service 모드 한정 RTT up 채널 0 모드를 `SEGGER_RTT_MODE_BLOCK_IF_FIFO_FULL` 로 전환. 근거 — 기본 `NO_BLOCK_SKIP` 은 buffer (1024 B) 가득 시 write 호출 통째 drop. 파일 hex 덤프 (`%02X ` × 64 + `\r\n` = 194 B / 64 B 청크) 가 host drain (auto-rtt-viewer 10 ms polling, 약 100 B/ms) 보다 빨라 chunk 누락 가능. BLOCK 모드는 CPU stall 로 자동 backpressure (인터랙티브 콘솔이라 stall 허용). 적용 위치 = `service_main()` 진입 첫 줄 (LED init 전). 부트로더 본체는 service_main 진입 안 하므로 영향 없음. delay 추가 방식 대비 코드 단순 + drop 자체 원천 차단
- (사용자 검증 2026-05-08) 검증_1: 결정_9 BLOCK 모드 동작 정상 확인 — "블록 방식으로 동작 잘 하는거 같아"
- (사용자 검증 2026-05-08) 검증_2: 결정_10/11 출력 형식 + sound1-fw-extractor 추출 정상 확인 — `dump` 명령 → fw.txt 캡처 → extractor 실행 결과 4 파일 정상 추출 (`MANIFEST.TXT` 45 B, `APP000.FEZ` 178336 B, `APP001.FEZ` 9476 B, `APP002.FEZ` 1280 B), `[완료] 4개 파일 추출.` 메시지 출력, `[경고]` 0. 수용_1·수용_2·수용_8 통과
- (사용자 확정 2026-05-08) 결정_10: 파일 출력 방식 변경 — 4 파일 (MANIFEST.TXT + APP000~002.FEZ) 단일 명령 일괄 출력. 형식 = [`sound1-fw-extractor` 명세](../../../../../sound1-fw-extractor/docs/사용방법/Sound1%20측%20fw.txt%20출력%20명세.md) 준수: 데이터 영역 마커 `========== FW DUMP BEGIN/END ==========`, 파일 마커 `:::FILE:<NAME>:BEGIN/END:::`, 데이터 영역 안 줄바꿈 LF only. 외부 프로그램 (sound1-fw-extractor Python 도구) 자동 파싱 → 4 바이너리 추출
- (사용자 승인 2026-05-08) 결정_11: 결정_10 세부 — 명령어 이름 `dump` (단어 한 개, 명세 §10 예시 부합), 데이터 라인 길이 16 B (명세 §6 권장), `[SERVICE] dump done.\r\n` 메시지 출력 (END 마커 후 데이터 영역 밖). 5 명령 (`manifest`/`app0~2`/`reboot`) → 2 명령 (`dump`/`reboot`) 으로 축소
