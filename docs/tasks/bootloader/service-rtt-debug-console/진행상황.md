# 진행상황: service 모드 RTT 디버그 콘솔

**TL;DR**: 단계 ① 요구사항 ~ ③ 구현계획 산출물 Rev.4 갱신 (사용자 피드백 4차 반영 — service 는 OTA 슬롯 처리 자체 불필요라 `snd_boot_*`/`tdc_boot_print_boot_file` 호출 안 함. `tdc_boot_get_ohdl()` getter 는 service 의 `_print_fw_file` 이 부트로더 `ohdl` 재사용용으로만 사용 — 별도 `s_tdc_service_fp` 변수 폐기. 부트로더는 `&ohdl` 직접 사용). 사용자 재검토 대기.

## 결정 누적

- (사용자 승인) 결정_1: 부트로더 UART 디버그 모드 코드 폐기. service에서만 RTT 디버그 콘솔 운영
- (사용자 승인) 결정_2: 코드 사이즈 우선 — `bootloader_boot()`의 storage init 부분을 헬퍼로 추출, 부트로더·service 양쪽이 호출
- (자동) 결정_3: `tdc_boot_print_boot_file()`은 storage init 헬퍼 안에 포함 (양쪽 자동 출력)
- (사용자 피드백 2026-05-07 1차) 결정_4: 명령어 이름 `--quit`/`--print=mf`/`--print=a0~2` → `reboot`/`manifest`/`app0~2`로 변경 (요구사항.md §4 수용_1~3)
- (사용자 피드백 2026-05-07 2차) 결정_5: `reboot` 명령 후 동작 = `SYS_WATCHDOG_RESET()` 직접 호출 + 500 ms 사전 delay (RTT 출력 버퍼 flush 보장 — 출력 중이던 hex 덤프 메시지 손실 방지) (분석.md §2.5)
- (사용자 확정 2026-05-07 2차) 결정_6: auto-rtt-viewer `write.line_terminator` = `\n` 확정 → 위험_2 해소 (분석.md §2.7)
- (사용자 피드백 2026-05-07 3차) 결정_7: 헬퍼 함수 책임 축소. `snd_boot_set_fp` / `snd_boot_handle_file` / `tdc_boot_print_boot_file` 은 OTA DFU 이미지 슬롯 선택 영역이라 `tdc_boot_storage_init()` 외부에서 호출 (`bootloader_boot()` 은 `bootloader_load_app_file()` 직전, `service.c` 는 storage init 직후). ohdl 접근은 신규 `tdc_boot_get_ohdl()` getter 경유 (분석.md §2.2)
- (사용자 피드백 2026-05-07 4차) 결정_8: 결정_7 수정 — service 는 슬롯 처리 자체 불필요라 `snd_boot_set_fp` / `snd_boot_handle_file` / `tdc_boot_print_boot_file` 모두 호출 안 함. `tdc_boot_get_ohdl()` getter 는 service 의 `_print_fw_file` 이 부트로더 정적 변수 `ohdl` 을 재사용용 (별도 `s_tdc_service_fp` 변수 폐기, 사이즈 절약). 부트로더는 같은 파일 내 정적 변수라 `&ohdl` 직접 사용 (분석.md §2.2)
