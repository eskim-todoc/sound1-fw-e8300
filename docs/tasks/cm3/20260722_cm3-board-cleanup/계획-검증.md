## 4. 잔여 결함

| ID | 결함 | 완화 |
|---|---|---|
| 잔여_1 | **단계_1 커밋 시점의 중간 상태**에서 선택자가 존재하지 않는 파일을 `#elif` 로 가리킨다 | **무해함이 논증된다** — C 전처리기는 비활성 분기의 `#include` 를 **해석하지 않는다**(조건부 포함, C11 §6.10.1). 따라서 단계_1 단독 상태에서도 빌드는 성공한다. 그럼에도 단계_1·2 를 **한 게이트로 묶어** 중간 상태를 `claude_develop` 에 노출시키지 않는다 |

## 5. 반증 시도 — 단계 순서를 바꾸면 나은가

| 대안 | 평가 |
|---|---|
| 단계_2(선택자) 먼저 | ❌ 선택자를 먼저 좁히면 그 순간 나머지 파일이 "선택자에서 참조되지 않는 파일"이 되어, 삭제의 근거를 **삭제 행위 자체가 만들어내는** 순환이 된다. 현행 순서는 "원래부터 도달 불가"를 근거로 삼아 논리가 곧다 |
| 한 커밋에 통합 | ❌ 회귀 시 삭제/편집 중 원인 특정 불가. 결함_1(④)의 완화책이 무력화 |
| 현행 1→2 | ✅ 각 커밋이 독립적으로 빌드 가능하고, 롤백 지점이 유의미하다 |
