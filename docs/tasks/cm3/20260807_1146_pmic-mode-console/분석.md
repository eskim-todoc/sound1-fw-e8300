# 분석

**TL;DR**: 은수님 이해는 **절반만 맞다** - «입력이 낮아지면 승압» 은 맞고 «입력이 높으면 바이패스» 는 틀렸다(그때는 **강압**한다). 바꿀 것은 `CONV_CFG(0x12)` 의 **2비트(`FMODE[3:2]`)뿐**이고, 나머지 6비트가 같은 레지스터에 살고 있어 **읽고-고쳐-쓰기가 필수**다.

## 1. 요구_1 검토 결과

상세 근거는 [`참고/pmic-isl99122a/README.md §2`](../../../참고/pmic-isl99122a/README.md) 에 정리했다. 결론만 옮긴다.

| 은수님 진술 | 판정 | 근거 |
|---|---|---|
| 입력이 낮아지면 **부스트로 승압** | **맞다** | §5.6 - `VIN < VOUT` 이면 순수 Boost |
| 입력이 출력보다 크면 **입력을 출력으로 바이패스** | **아니다** | §5.6·§5.7 - `VIN > VOUT` 이면 **순수 Buck 으로 강압**해 `VOUT` 을 `VSET` 으로 유지한다 |
| 그 둘을 **«바이패스 모드»** 하나가 한다 | **아니다** | Bypass 는 `VIN ≈ VOUT` **±1%** 구간의 자동 전이 상태다 (p.9 `VIN_BYP`) |

### 1.1 왜 헷갈리기 쉬운가

데이터시트가 **«bypass» 를 두 뜻으로 쓴다.**

| 용어 | 정체 | 제어 |
|---|---|---|
| **Auto Bypass** | `VIN ≈ VOUT` 일 때 Buck↔Boost 전이를 매끄럽게 하려고 자동으로 지나가는 **상태** | **별도 비트 없음.** Normal(`FMODE=0x0`)에 내장 |
| **Forced Bypass** | 스위칭을 **끄고** 입력을 출력으로 직결하는 **모드** | `FMODE = 0x3` |

특징란의 *"Selectable Forced and Auto Bypass power saving modes"* 가 «둘 다 켜고 끌 수 있다» 처럼 읽히지만, 실제로는 **`FMODE` 로 넷 중 하나를 고르는 것**이 전부다. 레지스터 맵 전체를 훑어도 Auto Bypass 를 끄는 비트는 없다.

### 1.2 은수님이 원하는 거동이 필요하다면

«배터리가 충분히 높으면 그대로 쓰고, 낮아지면 승압» 은 **IC 가 스스로 하지 않는다.** 하려면 **펌웨어가 배터리 전압을 보고 `FMODE` 를 토글**해야 한다.

| 항목 | 판단 |
|---|---|
| 가능한가 | 가능하다. `Forced Bypass` ↔ `Normal` 토글 |
| **권할 만한가** | **아니다.** Forced Bypass 는 **과전류 보호가 없고**(§5.10) 이 레일은 **자극 출력**이다 |
| 이번 작업 범위인가 | **아니다.** 은수님이 요청한 것은 «확인·변경 명령» 이다. 정책은 별건 |

## 2. 현재 코드

| 항목 | 현재 |
|---|---|
| 드라이버 | `drv/tdc_drv_isl9122.c` - `write_register` · `read_register` · `reset` 3함수 |
| I2C 경로 | `tdc_hal_i2c_*` 로 CM3 가 **직접** 붙는다 |
| 콘솔 | `tests/tdc_test_tx_pmic.c` - `+N` `-N` `=N` `r` `?` + 방향키 |
| 현재 `CONV_CFG` | **`0x81`** → `FMODE = 0x0` (Normal) |
| 진입 | `main.c:471` - **은수님이 지금 주석을 풀어 둔 상태**(미커밋) |

> [!NOTE]
> `isd/tdc_isd_fpga.c` 의 `tdc_isd_fpga_read_tx_power_level()` · `..._write_change_tx_power_level()` 은 **이름과 달리 FPGA 를 거치지 않는다.** `tdc_drv_isl9122_*_register()` 를 그대로 부르고 실패 디바운스만 얹은 얇은 래퍼다. **모드 함수는 그 파일이 아니라 드라이버에 둔다** — PMIC 레지스터는 PMIC 드라이버의 소관이다.

### 2.1 콘솔 입력기의 제약 (놓치면 명령이 안 먹는다)

`tdc_tx_pmic_read_input()` 은 **`w`·`s`·`a`·`d`(대소문자 무관)를 엔터 없이 즉시 소비**한다(방향키 대체). 따라서 **새 명령 문자열에 이 넷을 쓰면 안 된다.**

`mode` 라고 치면 `m`·`o` 는 쌓이지만 **`d` 에서 «+10 단계» 로 빠져나간다.** 명령을 **`m`·`c` 와 숫자로만** 구성해야 하는 이유다.

## 3. HW 레지스터 5게이트

### 게이트_1 - 대상 식별

| 항목 | 값 |
|---|---|
| 디바이스 | ISL9122A, I2C 7비트 주소 **`0x18`** |
| 레지스터 | **`CONV_CFG` = `0x12`** |
| 비트 | **`FMODE[3:2]`** — 마스크 `0x0C` |
| 그 외 | `EN_AND[7]` · `DISCH[6]` · `DVSRATE[5:4]` · `CONV_RSVD[1]` · `TYPE1[0]` — **건드리지 않는다** |

### 게이트_2 - 근거 확인

데이터시트 **Table 5 (Register Address 0x12: CONV_CFG), p.25**.

| `FMODE` | 정의 | 쓸 수 있나 |
|---|---|---|
| `0x0` | Normal operation with automatic mode transitions | **가능** (리셋 기본값) |
| `0x1` | **RESERVED. DO NOT USE this combination** | **금지** |
| `0x2` | Forced PWM mode with no PFM operation | 가능 |
| `0x3` | Forced bypass. Disables switching. | 가능 (**단서 있음** — 게이트_4) |

### 게이트_3 - 전후 시뮬레이션

현재값 `0x81 = 0b1000_0001` 기준. **읽고-고쳐-쓰기**로 `FMODE` 만 바꾼다.

```
new = (old & ~0x0C) | ((mode & 0x03) << 2)
```

| 명령 | 전 | 후 | 바뀐 비트 | 보존 확인 |
|---|---|---|---|---|
| `m0` Normal | `0x81` | **`0x81`** | 없음 | 전부 보존 |
| `m2` Forced PWM | `0x81` | **`0x89`** | `[3:2]` `00`→`10` | `EN_AND=1`·`DISCH=0`·`DVSRATE=00`·`TYPE1=1` |
| `m3` Forced Bypass | `0x81` | **`0x8D`** | `[3:2]` `00`→`11` | 동 |
| `m1` RESERVED | `0x81` | **쓰지 않음** | — | — |

되돌리기는 `m0` 이고, `r`(PMIC 리셋)도 `CONV_CFG` 에 `0x81` 을 다시 써서 **Normal 로 복귀시킨다.**

### 게이트_4 - 부작용

| # | 부작용 | 크기 | 조치 |
|---|---|---|---|
| 1 | **Forced Bypass 에 과전류 보호가 없다** (§5.10 Note) | **높음** — 자극 출력 레일이다 | 진입 시 **경고 출력**. 콘솔은 자극을 돌리지 않아 사실상 무부하지만 0 은 아니다 |
| 2 | **Forced Bypass 는 승압하지 않는다** | 중 | `VOUT` 이 `VIN`(배터리)까지 떨어진다. 경고에 명시 |
| 3 | **모드 전환을 연달아 하면 오동작** (§5.10 - 1ms 규칙) | 중 | 쓰기 뒤 **2ms 지연** |
| 4 | `EN_AND=0` 으로 꺼도 Forced Bypass 유지 (Table 5) | 낮음 | 콘솔은 IC 를 끄지 않는다. 문서에 기록 |
| 5 | `TYPE1=1`(Type II) × `OC_FAULT_MODE=0x2/0x3` 금지 조합 | **없음** | 펌웨어가 `INTFLG_MASK` 를 쓰지 않아 리셋값 `0x0`(Hiccup) 유지. **조합에 걸리지 않는다** |
| 6 | 드라이버에 함수가 늘어 `.text` 증가·`__LINE__` 밀림 | 낮음 | 콘솔은 테스트 전용. 정상 경로 로직은 안 바뀐다 |
| 7 | 콘솔 파일 수정이 정상 동작에 영향 | **없음** | `main.c` 의 호출 한 줄이 주석일 때는 링커가 살려 두어도 실행되지 않는다 |

### 게이트_5 - 불확실성

| # | 모르는 것 | 어떻게 다루나 |
|---|---|---|
| 1 | Forced Bypass 에서 실제 `VOUT` 이 몇 V 인가 | **측정해야 안다.** 데이터시트는 «입력 직결» 이라고만 한다. 실기 항목으로 등재 |
| 2 | Forced PWM 에서 입력 전류가 얼마나 느는가 | 데이터시트에 수치 없음(«increased input current» 서술뿐). 측정 대상 |
| 3 | 무부하 상태의 Bypass 가 정말 안전한가 | 자극을 안 돌리므로 큰 전류가 흐를 경로가 없다고 **판단**했으나 실측 전에는 단정하지 않는다 |
| 4 | 모드 전환 과도 구간에서 `VOUT` 이 튀는가 | 오실로스코프로 봐야 한다. 실기 항목 |

> [!IMPORTANT]
> **추측으로 레지스터를 쓰지 않는다.** 바꾸는 비트 2개는 데이터시트 표에 값과 뜻이 그대로 적혀 있고, 나머지 6비트는 **읽어서 그대로 되돌려 쓴다.** 불확실성 4건은 전부 «바꾼 뒤 무슨 일이 일어나는가» 이지 «무엇을 써야 하는가» 가 아니다.

## 4. 설계 선택

### 선택_1 - 모드 함수를 드라이버에 둔다

`tests/` 안에서 `write_register(0x12, ...)` 를 직접 부르면 **비트 조작이 테스트 코드에 흩어진다.** 마스크·시프트·RESERVED 거부·되읽기를 드라이버가 갖는다.

### 선택_2 - 모드 이름 표도 드라이버에 둔다

`tdc_drv_isl9122_mode_name()` 을 열거형 바로 옆에 둔다. 콘솔에 두면 **열거형과 이름이 따로 놀 수 있다.**

### 선택_3 - 명령 문자는 `m` 과 `c`

| 명령 | 뜻 |
|---|---|
| `m` | 현재 모드 조회 |
| `m0` · `m2` · `m3` | 모드 설정 |
| `m1` | **거부** (RESERVED) |
| `c` | `CONV_CFG` 원시값 + 비트 해독 |

`w`·`s`·`a`·`d` 를 피했다(§2.1). `c` 를 넣는 이유는 «모드 확인» 의 실체가 `CONV_CFG` 이고, **다른 비트가 보존됐는지 눈으로 확인**할 수단이 필요하기 때문이다 — 게이트_3 의 예측을 실기에서 대조할 수 있다.

### 선택_4 - 넣지 않는 것

| 후보 | 왜 안 넣나 |
|---|---|
| `INTFLG_REG(0x03)` 조회 | 유용하지만 **요청 범위 밖**이다. 넣으려면 «읽으면 지워진다» 는 성질까지 다뤄야 해 별건이 맞다 |
| 배터리 연동 자동 토글 | §1.2 — 정책이고, 과전류 보호 부재 때문에 권하지 않는다 |
| `VSET` 과 모드의 연동 | 요청에 없다 |
