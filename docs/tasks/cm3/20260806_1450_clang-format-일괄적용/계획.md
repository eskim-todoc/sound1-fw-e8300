# 계획

**TL;DR**: 커밋을 **셋으로 쪼갠다** - ① 개행 정규화 ② `.clang-format` 갱신 ③ 일괄 적용. 검증의 주력은 **심볼 크기 표 대조**다 - 순수 포맷이면 `__LINE__` 운반체를 품은 함수 말고는 **바이트 크기가 같아야 한다.**

## 1. 최종 설정

현행 `src/.clang-format` 에서 **세 줄만 바뀐다.**

```yaml
ColumnLimit: 160          # 320 에서 낮춤 - 조건_6 을 도구가 지키게 한다

InsertBraces: true        # 신규 - 조건_2 (제어문에 모두 {})
KeepEmptyLines:           # 신규 - 조건_5 ({ 다음 빈 줄 금지)
  AtStartOfBlock: false
LineEnding: LF            # 신규 - .gitattributes 와 일치시킨다
```

**넣지 않는 것**: `AlignArrayOfStructures`(본보기와 어긋남 - 분석 §5) · `KeepEmptyLinesAtTheStartOfBlocks`(v22 에 없는 이름 - 분석 §3.1)

## 2. 커밋 분리 (제약_2)

| # | 커밋 | 내용 | 왜 나누나 |
|---|---|---|---|
| **①** | `.clang-format` + 문서 | 설정 4줄 · README 갱신 | 코드 변경이 없어 되돌리기 쉽다 |
| **②** | **일괄 적용** | 149파일 포맷 | 문제 시 **이 하나만** 되돌리면 된다 |

> [!NOTE]
> **개행 정규화는 커밋이 되지 않았다.** 작업 트리 4파일을 LF 로 되돌렸으나 저장소 blob 이 원래 LF 였으므로 git 에게는 무변경이다(분석 §9). 포맷 전에 되돌린 것 자체는 필요했다 — 안 그러면 clang-format 이 8,234줄을 더 건드린다.

## 3. 절차

| 단계 | 내용 | 검증 |
|---|---|---|
| 1 | **현재 `.elf` 를 기준본으로 보관** | `nm -S` · `size` 추출 |
| 2 | 개행 4파일 LF 정규화 → 커밋 ① | ARM 빌드 · 크기 **완전 불변** |
| 3 | `.clang-format` 갱신 → 커밋 ② | 코드 무변경 |
| 4 | `--dry-run -Werror` 로 대상 확정 | 149파일 중 113 변경 예상 |
| 5 | **일괄 적용** (`-i`) | |
| 6 | 인코딩 검사 | UTF-8 유효 · U+FFFD 0 · 한글 수 보존 · CP949 손실문자 0 |
| 7 | ARM 빌드 | 에러 0 · 경고 0 |
| 8 | **심볼 크기 표 대조** | §4 |
| 9 | 호스트 회귀 | 514 PASS |
| 10 | `example.c` 재생성 | `main.c` 와 바이트 동일 |
| 11 | `--dry-run -Werror` 재확인 | 무경고(멱등) |

> [!IMPORTANT]
> **1단계를 건너뛰면 안 된다.** 포맷 후에는 기준본을 다시 만들 수 없다. `Copy-Item` 은 타임스탬프를 보존하므로(자산_9) 되돌려 빌드할 때 `LastWriteTime` 을 갱신해야 한다.

## 4. 검증의 주력 - 심볼 크기 표

구조 지표는 못 쓴다(`InsertBraces` 가 `{}` 를 늘린다). 줄 수도 못 쓴다. **함수별 바이트 크기를 쓴다.**

```sh
arm-none-eabi-nm -S --defined-only 2__cm3.elf | sort -k3
```

| 판정 | 의미 |
|---|---|
| 크기가 같은 함수 | **코드 생성이 완전히 동일** |
| 크기가 다른 함수 | **반드시 `__LINE__` 운반체를 품고 있어야 한다** |
| 심볼이 사라지거나 생김 | **즉시 실패** |

`__LINE__` 이 `movs`(2바이트)에서 `movw`/`mov.w`(4바이트)로 넘어가면 함수가 2바이트 커진다. 그것 말고 크기가 변할 이유가 없다.

**운반체 판정**: 해당 함수의 소스에 `TDC_PRINTF_E` 또는 명시 `__LINE__` 이 있는가(자산_1 정정본).

## 5. 예측

| 항목 | 예측 |
|---|---|
| 변경 파일 | **113 / 149** |
| 변경 줄 | **4,027** |
| `InsertBraces` 로 늘어나는 `{}` | 52쌍 (104줄), 4파일 |
| `data` · `bss` | **완전 불변** |
| `.text` | **바뀐다** - 밀린 `__LINE__` 즉치의 인코딩 폭 변화만큼 |
| 크기가 변한 함수 | **전부 `__LINE__` 운반체 보유** |
| 심볼 증감 | **0** |
| 호스트 | **514 PASS** |
| ARM | 에러 0 · 경고 0 |
| 실기 대기 | **12건** (+1, 포맷 일괄 적용) |

> [!CAUTION]
> **실기 대기가 1건 는다.** 앞선 죽은 코드 제거는 «살아 있는 줄 동일 + `.text` 바이트 등가» 로 대기를 안 늘렸지만, 이번엔 `InsertBraces` 가 실제로 소스를 바꾸고 `.text` 도 바뀐다. 등가를 주장할 수 없다.

## 6. 위험

| 위험 | 완화 |
|---|---|
| `InsertBraces` 가 전처리기를 가로질러 삽입 | 분석 §8 전량 검토 - 삭제 0 · 조건부 가로지름 0. 추가로 ARM 빌드 |
| 매크로 본문이 제어문인 곳에 오삽입 | 심볼 크기 표가 잡는다(크기가 변하는데 운반체가 없으면 실패) |
| 한글 주석 인코딩 손상 | 6단계 - U+FFFD·한글 수·CP949 손실문자 3중 검사 |
| 개행 뒤집힘 | `LineEnding: LF` 고정 + 커밋 ① 로 선행 정규화 |
| 되돌릴 수 없게 됨 | 커밋 분리 - ③ 만 `git revert` 하면 원상 복구 |
| `example.c` 가 `main.c` 와 어긋남 | 10단계에서 재생성 후 `diff` 0 확인 |
