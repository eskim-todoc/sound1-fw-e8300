# 구현 검증

**TL;DR**: 완료 조건 8개 전부 충족. **149파일 중 113파일 4,000줄을 다시 포맷했는데 심볼 1,423개 중 크기가 바뀐 것은 단 1개**이고, 그 −4바이트를 «어느 줄이 어디로 밀려 어떤 인코딩이 됐는지» 까지 명령어로 설명했다.

## 3. 검증의 핵심 - 심볼 크기 표

```
심볼 수        before 1,423 / after 1,423
사라진 이름    0
새로 생긴 이름 0
크기 바뀐 이름 1
바이트 총합    before 173,071 / after 173,067   (-4)
```

| 심볼 | 전 | 후 | 차 |
|---|---|---|---|
| `tdc_isd_fpga_read_backtel_config` | 164 | 160 | **−4** |

**나머지 1,422개는 바이트 단위로 완전히 동일하다.**

### 3.1 그 −4바이트를 끝까지 파고들었다

원인은 **한 줄에 `__LINE__` 이 두 개** 있는 곳이었다.

`TDC_ISD_DEBOUNCE_FAIL`(`isd/tdc_isd_fpga.h:18~30`)이 매크로 안에 둘을 품는다.

```c
TDC_PRINTF_E(...);                                  // -> tdc_printf_file_func_line(..., __LINE__)
tdc_sys_error_update((_maj), (_det), __LINE__);     // -> 두 번째
```

이 매크로 호출이 **257줄에서 250줄로 내려오며 255 경계를 넘었다.**

| | 전 (257줄) | 후 (250줄) |
|---|---|---|
| 인코딩 | `f240 1201  movw r2, #257` | `22fa  movs r2, #250` |
| 폭 | **4바이트** | **2바이트** |
| 개수 | 2 | 2 |

**2 × 2 = 4바이트 감소.** 함수 크기 변화(−4)와 `.text` 전체 변화(186,524 → 186,520)가 정확히 일치한다.

> [!IMPORTANT]
> **자산_1 을 다시 늘려야 한다.** 직전 세션에서 «운반체는 명시 `__LINE__` 과 `TDC_PRINTF_E` 뿐» 으로 정정했는데, **프로젝트 매크로가 그 둘을 감싸면 그것도 운반체**이고 **한 호출이 운반체를 두 개 실을 수 있다.**
>
> `grep -c "TDC_PRINTF_E"` 로만 세면 `TDC_ISD_DEBOUNCE_FAIL` 같은 래퍼를 놓친다.

### 3.2 왜 4,000줄을 밀었는데 4바이트뿐인가

`__LINE__` 즉치는 **값이 바뀌어도 인코딩 폭이 그대로면 함수 크기가 안 변한다.** `movs`(0~255) 안에서 움직이거나 `movw`(0~65535) 안에서 움직이면 폭이 같다.

**폭이 바뀌는 것은 255 경계를 넘을 때뿐**이고, 이번 포맷은 줄을 대부분 **줄이는** 방향이라 경계를 넘은 곳이 한 군데였다.

심볼 크기 표는 «값이 바뀐 것» 은 못 보고 «폭이 바뀐 것» 만 본다. **그것으로 충분하다** - 값 변화는 오류 보고의 줄 번호일 뿐이고, 코드 생성이 달라졌다면 폭이 아니라 **명령어 구성**이 바뀌어 크기가 크게 튄다.

## 5. 고정점에 올리는 데 두 가지가 필요했다

1차 적용 후 `--dry-run -Werror` 가 **3파일에서 계속 위반을 보고**했다. clang-format 자신의 출력이 자기 기준에 안 맞는 상태다.

### 5.1 `ReflowComments` 가 진동을 만들었다

| 패스 | `tdc_ble_protocol.h` 차이 |
|---|---|
| 1 → 2 | 12줄 |
| 2 → 3 | **96줄** (더 나빠진다) |

긴 한글 후행 주석을 계속 다시 흘려 쓰면서 **수렴하지 않는다.** `ReflowComments: Never` 로 바꾸니 세 파일 모두 2패스 안에 고정점에 도달했다.

**손으로 배치한 주석을 도구가 다시 흘려 쓰지 않는 것이 맞기도 하다.** 조건_7 의 «주석 시작 위치를 코드와 맞춤» 은 정렬(`AlignTrailingComments`)이지 재배치가 아니다.

### 5.2 한 패스로는 부족하다

`ReflowComments: Never` 로도 2파일이 1패스에서 안 끝났다.

| 패스 | 차이 |
|---|---|
| 1 → 2 | 7줄 |
| **2 → 3** | **0** |
| 3 → 4 | 0 |

**2패스를 돌리고 나서야 149파일 전부 미준수 0 이 됐다.**

> [!IMPORTANT]
> **일괄 적용은 «한 번 돌리고 끝» 이 아니다.** `--dry-run -Werror` 가 0 이 될 때까지 돌린 뒤 그 상태를 커밋한다. 안 그러면 다음 사람이 파일을 만질 때마다 무관한 줄이 따라 바뀐다.

### 5.3 남은 흠 - `tdc_drv_isl9122.h`

고정점이 예쁘지는 않다.

```c
#define TDC_DRV_PMIC_MAX_VOLTAGE_CONTROL_VALUE                    \
    214  // 0.025*214=5.35V
         //  #define ... 190     // 0.025*200=4.75V
```

후행 주석 뒤에 **주석 처리된 옛 `#define` 이 이어 붙어** 논리적 한 줄이 160을 넘는다. 도구는 `#define` 을 역슬래시로 잘라 맞춘다.

**동작은 같다**(역슬래시 연속은 유효하다). 고치려면 그 주석 줄을 옮겨야 하는데 그건 내용 변경이라 **순수 포맷 커밋에 섞지 않는다.** 다음에 그 파일을 만질 때 정리하면 된다.

## 6. 실기

**대기가 1건 는다.** 앞선 죽은 코드 제거처럼 «바이트 등가» 를 주장할 수 없다 - `InsertBraces` 가 소스를 바꾸고 `.text` 도 −4바이트 바뀌었다.

다만 **근거가 이례적으로 강하다.**

| 근거 | 값 |
|---|---|
| 크기가 바뀐 함수 | **1 / 1,423** |
| 그 변화의 설명 | **명령어 단위로 완결** |
| 심볼 증감 | 0 |
| `data` · `bss` | 불변 |
| 호스트 | 514 PASS |

따라서 확인 항목을 **«전반 동작에서 에러 로그 없을 것»** 하나로 얕게 잡는다. 특정 경로를 겨냥할 근거가 없다.
