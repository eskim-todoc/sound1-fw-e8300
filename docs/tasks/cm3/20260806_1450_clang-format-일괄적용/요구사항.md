# 요구사항

**TL;DR**: 은수님 지시 *"clang-format에 대해서 정리하고 `.clang-format`에도 업데이트 하고, 내가 어떤 스타일을 원하는건지 분석좀 해보고, 그에 맞는 포맷으로 다듬어서 전체 소스에 일괄 적용"*. 범위는 **`src/2__cm3/source/` (벤더 `lib/` 제외) 149파일**, 줄 폭은 **160** - 둘 다 은수님이 선택했다.

## 1. 지시 원문

> clang-format에 대해서 네가 정리하고 .clang-format에도 업데이트 하고. 그 다음 적당히 네가, 내가 어떤 스타일을 원하는건지 분석좀 해보고. 그에 맞는 포맷으로 좀 다듬어봐. 그다음 전체 소스에 그 포맷을 일괄 적용하고 싶어. (2026-08-06)

## 2. 요구 분해

| # | 요구 | 판정 기준 |
|---|---|---|
| 요구_1 | clang-format 관련 사항을 **정리** | `docs/참고/clang-format/README.md` 가 v22 기준으로 갱신되고, 자동/수동 구분이 실측과 맞는다 |
| 요구_2 | **`.clang-format` 갱신** | 조건 11개 중 도구로 강제 가능한 것이 전부 설정에 들어간다 |
| 요구_3 | **은수님 스타일 분석** | 본보기 `main.c` 를 근거로 «무엇을 원하는가» 를 수치로 제시 |
| 요구_4 | 그에 맞게 **다듬기** | 분석 결과가 설정에 반영된다 |
| 요구_5 | **전체 소스 일괄 적용** | 대상 전 파일이 `clang-format --dry-run` 무경고 |

## 3. 은수님이 선택한 것 (2026-08-06 질의)

| 항목 | 선택 | 대안 |
|---|---|---|
| **줄 폭** | **`ColumnLimit: 160`** | 320 유지 · 140 |
| **범위** | **`2__cm3` 만** (벤더 `lib/` 제외) | +부트로더·캘리브레이션 · `src/` 전체 |

**줄 폭을 낮춘 이유**: 현행 320 은 사실상 «줄을 절대 나누지 않는다» 라서 **조건_6(인자 많으면 각 인자를 새 줄에)을 도구가 지킬 수 없다.** 오히려 손으로 나눠 둔 호출을 도로 한 줄로 붙인다.

**범위를 좁힌 이유**: ARM 빌드와 호스트 테스트로 회귀를 잡을 수 있는 것이 `2__cm3` 뿐이다. `1__cfx` 는 chess 컴파일러라 여기서 빌드가 안 되고, `3__hear/microcode.c` 는 도구 생성 코드라 재생성하면 포맷이 되돌아온다.

## 4. 제약

| # | 제약 | 근거 |
|---|---|---|
| 제약_1 | **동작을 바꾸지 않는다** | 순수 포맷이다. `.text` 차이는 `__LINE__` 즉치뿐이어야 한다 |
| 제약_2 | **포맷을 다른 변경과 섞지 않는다** | 실기 대기 11건 위에 올리는 변경이라, 문제 시 통째로 되돌릴 수 있어야 한다 |
| 제약_3 | **CP949 손실 문자를 만들지 않는다** | [`CLAUDE.md` §소스 인코딩 규칙](../../../../CLAUDE.md). CLI 로 직접 돌리므로 Eclipse 플러그인 경로는 타지 않지만 결과는 검사한다 |
| 제약_4 | 벤더 코드 제외 | `lib/SEGGER_RTT` · `lib/tiny-AES-c` 는 상류가 따로 있다 |
| 제약_5 | **`example.c` 는 `main.c` 와 바이트 동일을 유지** | 본보기의 정의다 |
