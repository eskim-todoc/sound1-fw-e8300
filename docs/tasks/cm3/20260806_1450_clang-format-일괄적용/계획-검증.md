## 축_2 - 논리 정합성

### 정합_1 - 심볼 크기 표가 정말 자가 되는가

된다. **순수 포맷은 코드 생성을 바꾸지 않으므로 함수 바이트 크기가 같아야 한다.**

크기가 변할 수 있는 유일한 경로는 `__LINE__` 즉치의 인코딩 폭이다.

| 인코딩 | 폭 | 값 범위 |
|---|---|---|
| `movs Rd, #imm8` | 2바이트 | 0~255 |
| `mov.w Rd, #imm` | 4바이트 | modified immediate |
| `movw Rd, #imm16` | 4바이트 | 0~65535 |

줄 번호가 255를 넘나들면 2↔4바이트가 오간다. **그 외에 함수 크기가 변할 이유가 없다.**

따라서 판정은 이렇게 갈린다.

| 관측 | 판정 |
|---|---|
| 크기 다른 함수가 **운반체를 품음** | 정상 |
| 크기 다른 함수가 **운반체가 없음** | **실패 - 코드 생성이 바뀌었다** |
| 심볼 증감 | **실패** |

### 정합_2 - 왜 명령어 단위 디스어셈블 diff 를 주력으로 안 쓰는가

`.text` 크기가 바뀌면 **뒤따르는 모든 주소가 밀려** 단순 diff 가 전량 불일치로 나온다. 4,027줄 규모 변경에서는 밀림이 확실하다.

심볼 크기 표는 **주소 이동에 영향받지 않는다.** 함수 단위로 보기 때문이다. 디스어셈블 diff 는 크기 표가 이상을 지목한 함수에만 **국소적으로** 쓴다.

### 정합_3 - 커밋 3분할이 과한가

과하지 않다. 세 변경의 **되돌리는 이유가 서로 다르다.**

| 커밋 | 되돌릴 상황 |
|---|---|
| ① 개행 | 되돌릴 일 없음 (`.gitattributes` 와 일치시키는 것) |
| ② 설정 | 폭 160 이 마음에 안 들 때 |
| ③ 적용 | **실기에서 문제가 났을 때** |

③ 만 되돌려야 하는 상황이 실제로 가능하므로 분리가 정당하다.

### 정합_4 - 「실기 대기 +1」이 맞는가

맞다. 앞선 죽은 코드 제거는 «살아 있는 줄 동일 + `.text` 바이트 등가» 라는 3단 사슬로 대기를 안 늘렸다. **이번엔 두 근거가 다 성립하지 않는다** - `InsertBraces` 가 소스를 바꾸고 `.text` 도 바뀐다.

정직하게 1건 늘린다. 다만 **확인 항목은 «전반 동작에서 에러 로그 없을 것»** 정도로 얕다 - 순수 포맷이라 특정 경로를 겨냥할 근거가 없다.
