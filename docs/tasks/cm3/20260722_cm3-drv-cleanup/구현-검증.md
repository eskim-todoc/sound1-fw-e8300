# ⑧ 구현-검증 — drv 사장 드라이버 제거

**TL;DR**: `drv/` 10 → **2파일**(`isl9122` 만). 죽은 보드 분기 8체인 정리. **[코드동등성]** 실측 통과 — `__FILE__` 경로 정규화 후 **잔존 68개 오브젝트의 text/data/bss 가 완전 동일**하고, 총 감소 1,871B 가 삭제 드라이버 코드량과 정확히 일치한다. 자극 제어 코드(`isd/`)를 건드렸음에도 **기계어가 한 바이트도 바뀌지 않았다**.

## 4. 축 3 — 구현 중 검출 사항

| ID | 사항 | 처리 |
|---|---|---|
| 검출_1 | **소스 grep 이 오판.** `mis2dh_configure_click_mode` 가 호출된다고 보고했으나 `#if 0` 안이었다. `isl91128`·`isl98608` 호출부도 전부 죽은 보드 분기 안 | 판정 기준을 **링크 레벨 미정의 참조**로 전환 |
| 검출_2 | **전처리 diff 가 "차이 25건" 보고.** 실제로는 (a) 삭제 드라이버의 선언·enum 소멸 (b) 분기 접기로 인한 `__LINE__` 시프트 두 종류 | 텍스트 비교의 한계로 판단하고 **심볼·코드 크기 대조**로 승격 |
| 검출_3 | **코드 크기 대조에서 무관한 21개 파일이 일률적으로 48B 감소.** 제가 건드리지 않은 `pwr_clock.c`·`fs_fft.c` 까지 포함돼 심각한 이상으로 보였다 | 디스어셈블 결과 `.rodata` 만 0x30 감소 → **`__FILE__` 이 박는 소스 경로 문자열** 차이였다. 워크트리 경로가 정확히 **48자** 더 길다. `-fmacro-prefix-map` 으로 정규화 후 **차이 0** |

> [!NOTE]
> **학습**: 두 트리를 다른 경로에 두고 산출물을 비교하면 `__FILE__`·`__BASE_FILE__` 이 경로 길이만큼 `.rodata` 를 부풀린다. 로그 매크로가 `__FILE__` 을 쓰는 코드베이스에서는 **`-fmacro-prefix-map` 정규화가 필수**다. 이번엔 "일률적으로 같은 크기(48B)"라는 패턴이 단서였다 — **무관한 파일까지 균일하게 변하면 코드 변경이 아니라 빌드 환경 차이를 의심해야 한다.**

## 7. 결론

**⑦ 구현 완료로 판정한다.** `drv/` 가 10 → 2파일로 줄었고, 사장 드라이버 4종과 죽은 보드 분기 8체인이 사라졌다. 동작 보존은 **잔존 68개 오브젝트의 기계어 완전 동일**로 확정됐다 — 코드 크기 감소분 1,871B 가 삭제 드라이버 코드량과 정확히 일치한다.
