# ③ 분석 — 링크 레벨로 판정한 사장 드라이버

**TL;DR**: 은수님 지적대로 `drv/` 5개 중 **`isl9122`(PMIC) 하나만 살아 있다.** 소스 grep 은 `#if 0`·비활성 분기 때문에 오판하므로 **실제 컴파일 후 미정의 참조(`nm -u`)** 로 확정했다. `isl91128`·`isl98608` 은 삭제된 보드 가드 때문에 **빈 오브젝트**였고, `max17262`·`mis2dh` 는 코드는 생성되나 **호출자가 0**이다.

## 1. 왜 소스 grep 으로는 안 되는가

초기 소스 스캔은 `mis2dh_configure_click_mode` 가 `sys/tdc_sys_init.c` 에서 호출된다고 보고했다. 실제로는 `#if 0` 블록 안이었다. 마찬가지로 `isd/tdc_isd_fpga.c` 는 `isl91128`·`isl98608` 함수를 호출하지만 전부 죽은 보드 분기 안이다.

→ **판정 기준을 "텍스트 등장"이 아니라 "링크 시 미정의 참조"로 바꿨다.**

## 2. 판정 방법 (3중)

| 단계 | 방법 | 얻는 것 |
|---|---|---|
| 1 | SDK 툴체인으로 **전 소스 72개 컴파일**(실패 0) | 실제 컴파일 대상 확정 |
| 2 | `nm -u` 로 각 오브젝트의 **미정의 참조** 수집 | 누가 무엇을 부르는지 |
| 3 | `nm --defined-only` 로 각 드라이버가 **제공하는 전역 심볼** | 무엇이 살아 있는지 |

## 3. 결과

| 드라이버 | 제공 전역 심볼 | 호출자 | 판정 |
|---|---|---|---|
| **`isl9122`** (PMIC) | 3 (`read_register`·`write_register`·`reset`) | `tdc_isd_fpga` · `tdc_isd_init_fpga` | ✅ **생존** |
| `isl91128` (PMIC) | **0** | 0 | ❌ 사장 |
| `isl98608` (PMIC) | **0** | 0 | ❌ 사장 |
| `max17262` (배터리 게이지) | 2 | **0** | ❌ 사장 |
| `mis2dh` (가속도 센서) | 6 | **0** | ❌ 사장 |

## 4. 근본 원인 — 보드 가드

세 PMIC 드라이버는 **헤더·소스 전체가 보드 조건으로 감싸여** 있다.

| 드라이버 | 감싸는 조건 | 상태 |
|---|---|---|
| `isl91128` | `#if defined(Board_is_OTE_VER_1_2)` | **직전 board 정리에서 삭제한 보드 → 영구 사장** |
| `isl98608` | `#if defined(Board_is_OTE_VER_1_3)` | 동 |
| `isl9122` | `TD_DEV_1_4 \|\| OTE_1_4 \|\| **OTE_1_5**` | 활성 |

`isl91128.c`(122줄) · `isl98608.c`(270줄) 가 **전역 심볼 0개짜리 빈 오브젝트**로 컴파일되던 이유다. 보드가 사라졌으므로 어떤 `#define` 으로도 되살릴 수 없다.

`max17262` · `mis2dh` 는 보드 가드가 없어 코드는 생성되지만 아무도 부르지 않는다. `tdc_sys_init.c` 의 유일한 `mis2dh` 호출부에는 **`// 더 이상 가속도 센서 사용하지 않음`** 주석과 함께 `#if 0` 이 걸려 있었다 — 의도적 퇴역이다.

## 5. 숨은 의존성 — `TDC_DRV_PMIC_*` 중복 정의

세 PMIC 헤더가 **같은 이름의 매크로를 서로 다른 값으로** 정의하고, `isd/` · `sys/` 가 실제로 사용한다.

| 매크로 | isl91128 | **isl9122 (활성)** | isl98608 |
|---|---|---|---|
| `MAX_VOLTAGE_CONTROL_VALUE` | `0x3F` | **`214`** | `40` |
| `MIN_VOLTAGE_CONTROL_VALUE` | `0x2B` | (없음) | `3` |
| `VOLTAGE_CONTROL_STEP` | `2` | **`5`** | `1` |
| `MIN_TX_POWER_VALUE` | `0x3E` | **`164`** | `(MAX-1)` |
| `RESET_VOLTAGE_SET_VALUE` | (`CONTROL_VALUE` 명) | **`75`** | `MIN_VOLTAGE...` |

**보드 가드가 배타적이므로 현재 빌드에서는 `isl9122.h` 것만 정의된다.** 따라서 나머지 둘을 삭제해도 값이 바뀌지 않으며, 오히려 중복이 사라져 안전해진다. 이것이 본 작업에서 가장 위험했던 지점이며, 실측(§7)으로 무변경을 확인했다.

## 6. 부수 정리 대상 — 죽은 보드 분기

삭제된 보드를 참조하는 전처리 체인이 `drv/` 밖에 18건 남아 있다.

| 파일 | 체인 |
|---|---|
| `isd/tdc_isd_fpga.c` | 3 (include 1 + 함수 정의 2) |
| `isd/tdc_isd.c` · `isd/tdc_isd_init_fpga.c` · `sys/tdc_sys_init.c` | 각 1 |
| `drv/tdc_drv_isl9122.h` · `.c` | 각 1 (자신의 조건도 항상 참) |

전부 `#if OTE_1_2 / #elif (…‖OTE_1_5) / #elif OTE_1_3 / [#else #error] / #endif` 형태로 **가운데가 활성**이다. 활성 분기 본문만 남기고 접는다.

> [!CAUTION]
> `isd/` 는 자극 제어 코드다(G7-2 에서 구조 변경을 보류한 영역). 분기 접기는 **중첩 조건까지 인식하는 파서**로 수행하고, 활성 본문은 한 글자도 바꾸지 않는다.
