# 00 — 오케스트레이터 입력

**TL;DR**: ③ 분석 단계의 전수 조사를 10노드 병렬 fan-out 으로 위임했다. 은수님 지시로 **동시 실행 10개 상한**. 각 노드는 담당 범위의 사장 후보를 `파일:라인` 근거와 함께 조사해 자기 로그 파일에 직접 Write 하고, 압축 요약만 반환한다.

## 은수님 원 지시 (2026-07-23)

> 우선 작업을 위해 브랜치를 새로 만들어. CM3 코드 리팩토링 2차 느낌으로 만들어. (...) 그 다음 FS_MEM_UART를 cfx_link 쪽으로 분리 이관해. 그리고 uart 관련 항목을 다 제거할거야. 깔끔하게. UART 아예 안 쓸거야 앞으로도. 에러 안나게 검증을 잘 하는게 가장 중요해. 그리고 UART같이 지금 코드 + 파일은 존재하는데, 실제로 사용되지 않는 항목들이 있을거란 말이야. 이걸 전수 조사해서. 어떻게 간추리고 제거할지 계획을 세워야해. 일단 넓은 범위에서 검색 및 분석 활동을 하는거니까, 네가 적절히 서브에이전트들을 활용하도록 해봐. 너무 많이는 아니고 토큰 때문에 최대 10개 제한으로 잘 활용해봐. 동시에 돌리는게 10개라는 거고, 총 개수가 10개는 아니야.

## 위임 설계

| 판단 | 결정 |
|---|---|
| 트리거 | *"서브에이전트들을 활용"*, *"넓은 범위에서 검색 및 분석"* -> 오케스트레이션 트리거 성립 |
| 방식 | `Workflow` 단일 phase 병렬 fan-out (10노드). 종합·저술은 오케스트레이터가 직접 |
| 모델 | 전 노드 `sonnet`, effort 미지정(세션 상속) - 루트 지침 §5 |
| 분할 기준 | 도메인 폴더를 파일 수 기준으로 5묶음 + 횡단 관심사 5노드 |
| 반환 | 압축 요약만 (상세는 각자 로그 파일에 Write) - 오케스트레이터 컨텍스트 보호 |
