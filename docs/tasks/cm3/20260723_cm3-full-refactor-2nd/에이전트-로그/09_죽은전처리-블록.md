# 09_죽은전처리-블록

**TL;DR**: `source/` 전역(153파일)에서 `#if 0`/`#if 1` 130여 곳을 전수 확인. 사장 후보 55건 도출(안전 18 · 주의 20 · 위험 17). 최대 발견은 `tdc_isd_fpga.c` 의 완전 사장 함수 2개(호출부도 죽은 블록 안), `processorDirective.h` 의 무consumer 매크로 13개, `FPGA_ver2_7_0.h` 의 현장실패 이력이 담긴 백텔 캘리브레이션 값, BLE 패스키 인증 영구비활성(보안 특이사항).

## 1. 조사 범위와 방법

- 범위: `E:/workspace/projects/sound1-fw-e8300/src/2__cm3/source` 전역 153파일.
- 1차: `grep -n "#if 0"` / `grep -n "#if 1"` 로 전 위치 수집 (35개 파일에서 `#if 0` 100여 건, 다수 파일에서 `#if 1` 60여 건).
- 2차: 각 위치를 `Read` 로 열어 (a) 매칭되는 `#else`/`#endif` 확인, (b) 죽은 분기의 실제 크기, (c) 살아있는 분기와의 관계(구현 교체/디버그/보드분기)를 판정.
- 3차: `#if defined(MACRO)` 형태로 조건화된 분기는 해당 `MACRO` 가 `board/processorDirective.h` 등에서 정의되는지 전역 `grep` 으로 재확인 → "설정매크로 → 죽은분기" 쌍 확정.
- 4차: 완전 사장 함수로 보이는 것은 전역에서 호출부를 재검색하고, 호출부 자체가 또 다른 죽은 블록 안에 있는지 재확인 (지침 3번 "grep 함정" 대응).
- 5차: `isd/tdc_isd_map_*` (ecap/impedance/live/specific_stim/test_stim/data, 6파일) 은 지침 4번 불가침 목록에 해당 - 죽은 블록을 발견해도 제거 후보에서 제외하고 사유를 명기.

## 4. 판단 보류 · 추가 확인 필요

1. **후보_08 `pwr_clock.c:169-243` 완전절전 SDK 시퀀스**: 왜 채택되지 않았는지(배터리 소모 실측 결과? 특정 레지스터 부작용?) 이력을 찾지 못함. 은수님 확인 필요.
2. **후보_28 `TDC_TOUCH_DEBUG_PRINT_ENABLE`**: `#ifndef` 가드가 있어 빌드 옵션으로 재정의 가능한 구조 - "소스에서 고정되어 절대 참이 될 수 없는" 기준에 엄밀히는 부합하지 않음. 실제 빌드 스크립트(Eclipse 프로젝트 설정)에서 `-D` 오버라이드 여부는 조사 범위(순수 소스) 밖이라 확인 못함.
3. **후보_42 `fs_map.c` CRC+AES128 미적용 legacy read/write 8곳**: 순수 코드 관점에선 죽은 `#else` 이지만, 매핑데이터 포맷(암호화/CRC 유무)과 관련된 것이라 calibration 도구 등 다른 프로젝트가 이 "구 포맷"을 읽어야 할 가능성을 배제 못함 - 은수님 확인 필요.
4. **후보_51 `ble_remote.c:816-938`(123줄)**: 이 조사에서는 정적 분석만 수행했고, 무선 프로토콜 문서(v4.0.2 등 타 파일에서 언급)와 대조해 해당 커맨드가 실제로 폐기되었는지까지는 확인하지 못함.
5. **`isd/tdc_isd_map_*` 6개 FSM 내부 dead 블록 20여 곳(후보_20~24)**: 지침에 따라 제거 후보에서 일괄 제외했으나, 낱개로는 안전해 보이는 것(단순 디버그 프린트 등)도 섞여 있어 추후 FSM 전담 조사에서 재분류가 필요할 수 있음.

## 5. 특이사항

- **BLE 리모콘 패스키 인증 영구 비활성(후보_07)**: `ble/tdc_ble_remote.c:724-741` 에서 `remocon_passkey_Match` 를 먼저 `true` 로 고정한 뒤, 실제 4바이트 비교 루프를 `#if 0 // IMPORTANT: 패스키 인증을 더 이상 사용하지 않는다` 로 비활성화하고 `TDC_PRINTF_W("[PASSKEY] ALWAYS PATH OPENED.")` 로 로그까지 남기고 있다. 죽은 코드 자체는 "사장"이 맞지만, 그 죽음이 **의도적 보안기능 비활성화**라는 점에서 단순 삭제 대상이 아니라 은수님 확인이 필요한 사안으로 판단해 별도 표기했다.
- **`ble_mapping.c:840-848` 살아있는 코드의 명시적 버그**: `#if 1 // 1세대에서 사용되던 코드 (min_T_uA가 1800으로 유지되는 버그 있음)` - 이 블록은 죽은 코드가 아니라 **현재도 컴파일되는 살아있는 코드**이며, 주석에 알려진 버그가 명시되어 있다. 본 조사의 주제(사장 코드)와는 다르지만, `#if 1` 전수 조사 과정에서 발견되어 반드시 보고할 가치가 있다고 판단해 기록한다. 바로 아래(L851-864) 정상 재계산 로직이 있어 실제 영향은 제한적일 수 있으나 코드 검증은 하지 않았다(추정).
- **`board/FPGA_ver2_7_0.h:117-131` 백텔 캘리브레이션 실험 이력**: 살아있는 값 `0x2D` 를 중심으로 위아래 7개 값(0x39~0x19)이 주석으로, 그중 2개는 "백텔 안들어옴 - 개체번호 목록" 형태의 현장 실패 기록을 달고 있다. 코드 정리 시 이 이력 주석을 삭제하지 말고 별도 문서로 이관하는 것을 권장한다(존치 또는 이관, 삭제 금지).
- **작성자 본인이 "삭제할 것"이라 명시한 두 항목**: 후보_44(`fs_map.c:743-763`)와 후보_29 인접의 후보_29 는 아니고 `fs_map.c:549` 의 "NofM 테스트를 위한 코드. 테스트 후 삭제할 것"(이 항목은 `#if 1` 무조건 실행 코드라 사장 코드 목록에는 넣지 않았고, 살아있는 채로 잔존한 기술부채로 별도 언급함) - 이런 항목은 원 저자의 의도가 코드에 남아있어 판단이 쉬운 사례다.
- 전체적으로 `isd/` 도메인에서 "구현 초기의 수동 I2C/PCM 레지스터 비트연산 → 헬퍼함수 호출로 대체"라는 동일한 리팩토링 패턴이 최소 6개 파일(tdc_isd.c 포함)에 20회 이상 반복 발견됨. 이는 과거 어느 시점에 "헬퍼 함수화" 리팩토링이 있었으나 죽은 구코드를 정리하지 않고 남겨둔 것으로 보인다.
