## 주요 결정

| # | 결정 | 근거 |
|---|---|---|
| 결정_1 | `FS_MEM_UART` 이관을 UART 제거보다 **선행**한다 | UART 헤더를 먼저 지우면 CM3↔CFX 채널이 끊긴다. 이관 → 검증 → 제거 순서가 안전 |
| 결정_2 | 사장 판정은 **링크 레벨**로 확정한다 | 1차 drv 정리 노하우_1. grep 은 `#if 0` 내부 호출을 "사용 중"으로 오판 |
| 결정_3 | 판정 도구를 `nm -u` 가 아닌 **`--print-gc-sections`** 로 격상 | CM3 빌드에 `-ffunction-sections`·`--gc-sections` 가 이미 켜져 있어 링커가 폐기 섹션을 직접 알려준다. 연쇄 사장까지 자동 포착 |
| 결정_4 | UART 제거 범위는 **CM3 한정** (은수님 확정) | 부트로더는 DIO32 판정으로 OTA·부팅 로그를 실사용 중. 현장 디버깅 수단 유지 |
| 결정_5 | 적용은 **위험도별 단계 게이트** (은수님 확정) | 안전 → 주의 → 위험 순. 각 단계 전처리 diff · 기계어 대조 후 실기 확인 |

## 신규 검증 노하우 (다음 작업 자산)

| # | 노하우 |
|---|---|
| 신규_1 | **`--print-gc-sections` 가 사장 판정의 최종 심판이다.** `-ffunction-sections -fdata-sections` + `--gc-sections` 가 켜진 빌드라면 링커가 폐기 섹션을 전부 출력한다. grep·`nm -u` 보다 강하고 연쇄 사장까지 잡는다. 단 매크로·타입·미사용 `static inline` 헤더 함수는 못 잡는다 |
| 신규_2 | **사장 판정 전 반드시 대상 브랜치로 클린 재빌드하라.** `.o` 는 git 미추적이라 브랜치 전환에 따라오지 않는다. 실험 브랜치 산출물이 남아 있으면 판정이 통째로 왜곡된다 |
| 신규_3 | **이 프로젝트에서 `make` 는 `cmd.exe` 셸로 돌려야 한다.** Git Bash 의 `sh` 는 `-Dchess_storage(a)=` 에서 죽는다 |
| 신규_4 | **`__LINE__` 오염** — 줄을 삭제하면 그 아래 코드의 `__LINE__` 값이 밀려 바이너리가 달라진다. `util/tdc_printf.h:39-41` 의 `TDC_PRINTF_E` 가 `__LINE__` 을 쓴다. 실측: 줄 삭제본은 `.text` 9바이트 차이(전부 즉시값 1 감소), **빈 줄 치환으로 라인 수 보존 시 md5 완전 일치**. 노하우_3(`__FILE__`)의 같은 계열 |
| 신규_5 | **계획을 임시 트리에서 미리 실행해 검증할 수 있다.** 소스 트리를 temp 로 복사해 변경을 적용하고 동일 조건 빌드 후 `size`·`nm`·`.text` md5 를 대조하면, 작업 트리를 건드리지 않고 계획의 타당성을 실증할 수 있다 |
