# 05 — 링크 레벨 사장 판정 결과

**TL;DR**: CM3 빌드에 `--gc-sections` 가 이미 켜져 있어 **링커에게 사장 코드를 직접 물어볼 수 있었다**(`--print-gc-sections`). 자체 코드에서 **사장 함수 70개 · 사장 데이터 심볼 24개**가 확정됐다. 첫 시도는 이전 실험 브랜치의 stale `.o` 때문에 261건으로 부풀려졌고, 현재 브랜치 클린 재빌드 후 168건(자체 125건)으로 교정됐다. 노하우_4(도구를 먼저 의심하라)의 새 사례다.

## 1. 판정 방법 — 노하우_1 의 상위 호환

1차 drv 정리에서 확립한 `nm -u` 방식보다 **직접적이고 완전한 방법**을 찾았다.

CM3 빌드는 이미 다음 플래그를 쓴다(`Debug/source/*/subdir.mk`, `Debug/makefile`).

| 플래그 | 효과 |
|---|---|
| `-ffunction-sections -fdata-sections` | 함수·데이터마다 개별 섹션 생성 |
| `-Xlinker --gc-sections` | 어디서도 도달하지 않는 섹션을 링커가 폐기 |

여기에 **`--print-gc-sections` 하나만 추가**하면 링커가 폐기한 섹션을 전부 출력한다.

```sh
arm-none-eabi-gcc -mcpu=cortex-m3 -mthumb -O0 -fsigned-char \
  -ffunction-sections -fdata-sections \
  -T <프로젝트>/sections.ld -nostartfiles \
  -Xlinker --gc-sections -Xlinker --print-gc-sections \
  -L<SDK>/lib/cm3 --specs=nano.specs -o gc.elf \
  $(find source -name '*.o') -lcmsis -lfatfs -lnvmlib -lHAL 2> gcsections.txt
```

> [!IMPORTANT]
> **이 판정은 "최종 바이너리에 존재하지 않음"을 뜻하므로 grep 보다 강하다.** 연쇄 사장(사장 함수만이 호출하는 함수)까지 자동으로 잡아낸다. 다만 다음은 잡히지 않으므로 별도 조사가 필요하다.
>
> - 헤더의 매크로 · 타입 · enum (컴파일 후 흔적이 없음)
> - 미사용 `static inline` 헤더 함수 (`.o` 에 아예 들어가지 않음)
> - 링커스크립트 `KEEP()` 으로 보호된 섹션 (벡터 테이블 등 - 사장이어도 남음)

## 2. 함정 — stale `.o` 가 판정을 오염시킨다 (노하우_4 신규 사례)

첫 실행에서 261건이 나왔다. 그런데 `.o` 타임스탬프가 09:06 이고 당시 체크아웃돼 있던 브랜치는 `claude_hw_test_qcc_1.8v_current`(QCC 1.8V 전류 측정용 실험 브랜치)였다.

그 브랜치의 커밋 `ea27707 Test(cm3): FPGA·터치·ISD 시퀀스 제한` 은 `isd/tdc_isd.c` 에서 초기화 호출을 주석 처리한다.

```diff
 case en__isdStatus_PowerIC_Reset:
-    tdc_isd_init_tx_power_ic(s_isd_control_state_chaged_flag);
+    // tdc_isd_init_tx_power_ic(s_isd_control_state_chaged_flag);
+    tdc_isd_change_state(en__isdStatus_PowerIC_OK);  // for QCC 1.8V 테스트
```

그 결과 하위 호출 사슬 전체가 거짓 사장으로 잡혔다.

| 도메인 | 오염본(stale `.o`) | 클린 재빌드 | 차이 |
|---|---|---|---|
| `isd` | 81 | **19** | -62 |
| `touch` | 37 | **8** | -29 |
| `drv` | 1 | **0** | -1 |
| `cfx_link` | 11 | **10** | -1 |
| 그 외 12개 도메인 | 변화 없음 | | |
| **합계** | **261** | **168** | **-93** |

> [!CAUTION]
> **사장 판정 전에는 반드시 대상 브랜치로 클린 재빌드하라.** `.o` 는 git 미추적이라 브랜치 전환으로 갱신되지 않는다.

### 재빌드 시 주의 — `make` 는 `cmd.exe` 로 돌려야 한다

Git Bash 에서 `make` 를 돌리면 `/usr/bin/sh` 가 셸이 되어 컴파일 플래그 `-Dchess_storage(a)=` 의 괄호에서 `syntax error near unexpected token '('` 로 실패한다. **PowerShell 등 `sh` 가 PATH 에 없는 환경에서 실행**하면 `make` 가 `cmd.exe` 를 쓰므로 Eclipse 와 동일하게 빌드된다.

```powershell
$env:PATH = "C:\Program Files (x86)\ON Semiconductor\Ezairo 8300 SDK\arm_tools\bin;" + $env:PATH
Set-Location "<프로젝트>\Debug"; & make all -j8
```

## 6. 교차 검증 사례 — grep 과 링커가 엇갈릴 때

`tdc_pwr_lsad_*` 는 소스 grep 상 **5곳에서 호출**되지만 링커는 사장으로 판정했다. 확인 결과 링커가 옳았다.

| 호출처 | 실상 |
|---|---|
| `sys/tdc_sys_init.c:480` · `:488` · `:491` | **`#if 0` 블록 내부**(`:476~493`) |
| `sys/tdc_sys_init.c:363` | 주석 처리됨 (`// tdc_pwr_lsad_init();`) |
| `cfx_link/tdc_shm.c:157` | 호출자 `tdc_shm_read_battery_level_from_cfx()` **자신이 사장** (연쇄) |

**LSAD 모듈은 통째로 사장이다.**

같은 방식으로 `tdc_sys_uninit()` 도 정의(`sys/tdc_sys_init.c:150`)와 선언(`sys/tdc_sys_init.h:20`)만 있고 호출이 0건이다. 이 함수 안에 UART 종료 호출(`:193 tdc_hal_uart_uninit()`)이 들어 있었으므로, **UART 정리 코드는 애초에 실행된 적이 없다.** UART 제거 시 대체 처리가 불필요하다는 근거가 된다.
