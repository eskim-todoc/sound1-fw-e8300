# 06 — 자극 전하량 초과 안전 검사 분석

**TL;DR**: **`KKK` 는 오타가 아니라 원저자의 의도적 비활성화다**(git 이력상 처음부터 `KKK` 가 붙어 있고, 접미사 없는 버전이 존재한 적 없다). 그리고 **이 검사를 지금 켜는 것은 권장하지 않는다** — 초과 감지 시 실행되는 `else` 블록이 `configurationError = false` 로 두고 함수가 **`true`(성공)를 반환**하기 때문에, 켜면 오히려 **DAC 파라미터가 미설정인 채로 정상 진행**하는 더 위험한 상태가 된다. 실질 방어선은 `isd/tdc_isd_map_*` 3곳에 살아 있다.

> [!NOTE]
> 앞선 보고에서 이 건을 "매크로명 불일치로 안전 검사가 무력화됐다"고 전해 드렸다. 사실 관계는 맞으나 **"실수로 꺼졌다"는 뉘앙스는 정확하지 않다.** 아래가 정정된 분석이다.

## 1. `KKK` 는 의도적 비활성화다

| 확인 | 결과 |
|---|---|
| 정의 | `board/processorDirective.h:112` — `#define Df_MaxDeliveryChargeLimitationKKK 1` |
| 사용 | `stim/tdc_stim_para_cal.c:216` — `#ifdef Df_MaxDeliveryChargeLimitation` (접미사 없음) |
| git 이력 (`-S` 추적) | `Df_MaxDeliveryChargeLimitationKKK` 는 디렉토리 재편(`a1ac22e`) 이전부터 존재. **접미사 없는 버전은 이력에 단 한 번도 없다** |
| 1차 리팩토링 | `분석-데이터/08_보류-동결-목록.md:37` 에 **동결 심볼로 등재** |

C 에서 매크로를 임시로 끄는 흔한 방식이 **이름 뒤에 아무 문자나 붙이는 것**이다. `KKK` 는 그 전형이고, 처음부터 그 상태로 커밋됐다. 위치도 `// ble chip 관련` 섹션 아래라 원래부터 임시 삽입 성격으로 보인다.

**결론: 리팩토링 과정에서 생긴 오타가 아니다. 되돌려야 할 회귀가 아니다.**

## 2. 검사 로직 자체는 정합하다

```c
// stim/tdc_stim_para_cal.c:218-219
deliveryCharge_pico = maxStimul_uA * pulseWidth;
if (deliveryCharge_pico > df_MaxDeliveryCharge_pC)
```

| 항목 | 값 | 판정 |
|---|---|---|
| 단위 | `uA` x `us` = (10^-6 A) x (10^-6 s) = 10^-12 C = **1 pC** | **정합** |
| 임계값 | `df_MaxDeliveryCharge_pC = 75000` (`stim/tdc_stim_definitions.h:91`) = **75 nC** | 인공와우 자극 전하량 한계로 통상적인 값 |
| 대상 | `maxStimul_uA` = 전 채널 중 최대 C-level | phase 당 최대 전하량 기준. 타당 |

## 3. 그런데 켜면 더 위험하다 — 초과 시 처리가 잘못돼 있다

```c
// stim/tdc_stim_para_cal.c
192:  bool MaxDeliveryChargeOver = false;
...
216:  #ifdef Df_MaxDeliveryChargeLimitation      // <- 현재 항상 거짓
218:      deliveryCharge_pico = maxStimul_uA * pulseWidth;
219:      if (deliveryCharge_pico > df_MaxDeliveryCharge_pC)
220:          MaxDeliveryChargeOver = true;
222:  #else
224:      MaxDeliveryChargeOver = false;           // <- 현재 채택
225:  #endif

227:  if (!MaxDeliveryChargeOver)
228:  {
          ... DAC slope / offset 선택 + C_level_255[] · T_level_255[] 계산 (약 320줄) ...
554:  }
555:  else
556:  {
557:      configurationError = false;              // <- 에러가 아니라고 설정
558:      tdc_sys_error_update(en__dataProcessing_ERROR, en__MaxChargeOver_mapdata, __LINE__);
559:  }

561:  if (configurationError)
563:      return false;
565:  else
567:      return true;                             // <- 항상 성공 반환
```

**검사를 켰을 때 전하량이 초과되면:**

| 단계 | 실제 동작 | 문제 |
|---|---|---|
| 1 | `MaxDeliveryChargeOver = true` | 정상 |
| 2 | `if (!true)` → DAC 파라미터 계산 블록 **전체를 건너뜀** | `C_level_255[]` · `T_level_255[]` · `stimulationDAC_para` 가 **미설정 상태로 남음** |
| 3 | `configurationError = false` (`:557`) | **에러를 에러가 아니라고 표시** |
| 4 | `return true` (`:567`) | 호출자는 **파라미터 계산이 성공했다고 판단** |

> [!CAUTION]
> `:557` 의 `configurationError = false` 는 **`true` 여야 할 자리로 보인다.** 지금 상태로 검사를 켜면, 전하량 초과 시 자극 파라미터가 미설정(이전 값 또는 초기화되지 않은 값)인 채로 "정상"이 반환된다. **검사가 꺼져 있는 현재보다 위험하다.**

## 4. 실질 방어선은 다른 곳에 살아 있다

같은 검사가 **자극이 실제로 나가는 매핑 경로 3곳**에서 활성 상태로 동작한다.

| 위치 | 대상 | 초과 시 동작 |
|---|---|---|
| `isd/tdc_isd_map_impedance.c:169` | 임피던스 측정 | `TDC_PRINTF_E` 로그 + `tdc_sys_error_send_to_app(en__MaxChargeOver)` + `tdc_ble_mapping_clear_command()` |
| `isd/tdc_isd_map_ecap.c:221` | eCAP 측정 (마스커) | `tdc_sys_error_send_to_app` + `tdc_ble_mapping_clear_command()` |
| `isd/tdc_isd_map_specific_stim.c:103` | 특정 전극 자극 | `tdc_sys_error_send_to_app` + `tdc_ble_mapping_clear_command()` |
| `isd/tdc_isd_map_test_stim.c:178` | 테스트 자극 | **비활성** (`RELEASE` 매크로로 파일 전체 사장) |

이 3곳은 **앱에 에러를 보내고 매핑 커맨드를 리셋**한다. 커맨드 리셋으로 후속 시퀀스가 중단되므로 실효적인 차단 역할을 한다.

> [!WARNING]
> 다만 이 3곳도 **초과를 감지한 뒤 `break`/`return` 없이 아래 자극 파라미터 계산을 계속 진행한다.** 커맨드 리셋에 의존하는 구조다. 완전한 조기 차단은 아니다 — 별도 검토 대상이다.

## 5. 결론과 권고

| # | 판정 |
|---|---|
| 판정_1 | `KKK` 는 **오타가 아니라 의도적 비활성화**다. 리팩토링이 만든 회귀가 아니므로 **되돌릴 대상이 아니다** |
| 판정_2 | 검사 수식·단위·임계값은 **정합하다** (uA x us = pC, 75 nC) |
| 판정_3 | **현 상태로 켜면 안 된다.** `:557 configurationError = false` 때문에 초과 시 미설정 파라미터로 "성공"이 반환된다 |
| 판정_4 | 실질 방어선은 `isd/tdc_isd_map_*` 3곳에 살아 있다. 안전 검사가 통째로 사라진 상태는 **아니다** |

**권고**

1. **이번 리팩토링에서는 건드리지 않는다.** `tdc_stim_para_cal.c:216-225` 블록과 `KKK` 매크로 모두 **현행 유지**
2. 별도 작업으로 다룰 것 (본 리팩토링 범위 밖):
   - `:557` 의 `configurationError = false` → `true` 가 맞는지 판정. 맞다면 상위 호출자가 `false` 반환을 어떻게 처리하는지 확인 후 수정
   - `isd/tdc_isd_map_*` 3곳의 초과 감지 후 **조기 차단(`break`/`return`) 추가** 여부 검토
   - 위 둘이 정리된 뒤에야 `Df_MaxDeliveryChargeLimitation` 활성화를 논할 수 있다
