# ① 요구사항 — 2__cm3 2차 리팩토링 (UART 제거 · 사장 코드 정리)

**TL;DR**: 2차 리팩토링은 세 축이다. ㉮ `FS_MEM_UART`(이름만 UART 인 CM3↔CFX 공유메모리)를 `cfx_link/` 로 분리 이관, ㉯ 그 뒤 UART 관련 항목을 CM3 에서 전면 제거(앞으로도 미사용 확정), ㉰ UART 처럼 "파일·코드는 있으나 실제로 쓰이지 않는" 항목을 전수 조사해 정리 계획을 세운다. **검증 실패(빌드 깨짐·동작 변화) 무발생이 최우선 제약이다.**

## 1. 배경

1차 리팩토링(2026-07-20~22)으로 `src/2__cm3` 는 `source/` 단일 루트 · 16 도메인 · flat include 로 정리됐다. 그 과정에서 **사장 코드 45건이 이월**됐고(`docs/tasks/cm3/작업 목록.md` §이월 항목), drv 정리에서 **링크 레벨 사장 판정법**(노하우_1)이 확립됐다.

2026-07-23 UART 사용처 조사에서 다음이 확인됐다 — 본 작업의 직접 발단이다.

| 심볼 | 위치 | 판정 |
|---|---|---|
| `tdc_hal_uart_printf()` | `hal/tdc_hal_uart.c:34` | **사장.** 호출 0건. `util/tdc_printf.h:21` 이 `TDC_PRINTF_INTERFACE_SEGGER_RTT` 로 고정돼 UART 분기(`:35`)가 전처리에서 소멸 |
| `tdc_hal_uart_uninit()` | `hal/tdc_hal_uart.c:9` | 호출 1건 (`sys/tdc_sys_init.c:193`, 슬립 진입). CM3 는 UART 를 **켜지 않는다**(`Sys_UART_Config`·`UART_ENABLE` 전무) |
| `FS_MEM_UART` | `hal/tdc_hal_uart.h:138` | **활성 — 이름만 UART.** `DSP_PRAM1_REMAP_BASE` 에 얹은 CM3↔CFX 공유메모리 |

> [!CAUTION]
> `FS_MEM_UART` 는 `cfx_cm3_sharedMemoryAll` 과 동급의 **공유 ABI** 다. CFX(`1__cfx/OTE_1_5_gen/OTE_1_5_gen_UART.h:19-24`)가 `{ int state; int flag[32]; int buffer[512]; }` 동일 레이아웃 사본을 `D_DSP_PRAM1_BASE` 에 갖는다. 살아있는 경로는 CM3 `cfx_link/tdc_shm.c:283`(`flag[0]=1`) → CFX `signalProcessing/nonlinearMapping.c:465`(읽고 `buffer[]` 채운 뒤 `flag[0]=2`). **UART 파일과 함께 지우면 이 채널이 끊긴다.**

## 2. 요구사항

### 요구사항_1 — `FS_MEM_UART` 를 `cfx_link/` 로 분리 이관

- `hal/tdc_hal_uart.h` 에 있는 `FS_MEM_UART_T` · `FS_MEM_UART` · 관련 `FS_MEM_*` 매크로를 `cfx_link/` 아래 전용 헤더로 옮긴다
- 옮긴 헤더 상단에 **공유 ABI 경고 주석**을 단다 (`cfx_link/tdc_shm.h` 선례 준수)
- CFX 사본(`OTE_1_5_gen_UART.h`)과의 **레이아웃 정합을 증거로 남긴다**
- 네이밍은 `tdc_` 규약을 따르되, **필드명·구조체 크기는 절대 변경 금지**(ABI)

### 요구사항_2 — CM3 UART 관련 항목 전면 제거

- 대상: `hal/tdc_hal_uart.c/.h`, `TDC_HAL_UART_*` 매크로, UART DIO 정의(`DIO_PIN_INDEX_forUART_*`), `TDC_PRINTF_INTERFACE_UART` 분기, 무의미해진 `#include <tdc_hal_uart.h>` 8건
- **UART 는 CM3 에서 앞으로도 사용하지 않는다** (은수님 확정)
- 단, `tdc_hal_uart_uninit()` 는 부트로더가 UART 를 켠 채 앱으로 점프하는 경로(`0__bootloader/main.c:61-63`, `tdc_uart_uninit` 부재)가 있으므로 **제거 시 UART 잔존 상태 처리 방안을 분석에서 판단한다**

> [!IMPORTANT]
> **`0__bootloader` 의 UART 는 실사용 중이다** — DIO32 풀업 판정으로 OTA·부팅 로그를 출력한다(`main.c:61-63`, `bootloader.c:1617`). 본 요구사항의 제거 범위에 부트로더가 포함되는지는 **은수님 확인 사항**(§4 미결_1).

### 요구사항_3 — 사장 항목 전수 조사 및 정리 계획 수립

"파일·코드는 존재하나 실제로 사용되지 않는" 모든 항목을 CM3 전역에서 조사한다.

| 범주 | 예 |
|---|---|
| 사장 함수 | 정의만 있고 호출 0건, 또는 죽은 전처리 분기에서만 호출 |
| 사장 파일 | 어디서도 include·컴파일되지 않는 `.c/.h` |
| 사장 매크로·타입·전역 | 정의만 있고 참조 0건 |
| 죽은 전처리 블록 | `#if 0` · 항상 거짓인 조건 · 대량 주석 코드 |
| 이월분 재판정 | 1차 이월 45건 (G5 LED/touch 11 · G7 FPGA 15 · G8 cfx_link 19) |

산출은 **제거 대상 목록 + 근거(`파일:라인`) + 위험도 + 제거 순서**를 담은 계획이다.

### 요구사항_4 — 검증 (최우선 제약)

- **사장 판정은 소스 grep 이 아닌 링크 레벨**(`arm-none-eabi-nm -u` / `--defined-only`)로 확정한다 — 노하우_1
- 동작 보존은 **전처리 diff → `.o` 심볼·크기 대조** 2단으로 실증한다 — 노하우_2
- 산출물 비교 시 `__FILE__` 경로 오염을 `-fmacro-prefix-map` 으로 차단한다 — 노하우_3
- 자동 검증이 이상을 보고하면 **먼저 검증 도구를 의심**하고, 예상 건수와 실제 건수를 대조한다 — 노하우_4
- 파일 삭제·`.cproject` 변경 후 은수님께 **Clean / F5 Refresh / Index Rebuild 필요 여부를 명시**해 드린다 — 노하우_5

## 4. 결정 사항 (2026-07-23 은수님 확정)

| # | 질문 | **답변** | 반영 |
|---|---|---|---|
| 결정_1 | UART 전면 제거에 `0__bootloader` 가 포함되는가? | **CM3 만 제거.** 부트로더 UART 는 존치 | 부트로더는 DIO32 풀업 판정으로 OTA·부팅 로그를 실사용 중(`main.c:61-63` · `bootloader.c:1617`). 현장 디버깅 수단을 유지한다 |
| 결정_2 | 사장 코드 조사 범위 | **`src/2__cm3` 한정** | 153파일 39,790줄. 타 프로젝트는 참조만 |
| 결정_3 | 제거 적용 방식 | **위험도별 단계 게이트** | 안전 → 주의 → 위험 순으로 나눠 각 단계마다 전처리 diff · 기계어 대조 후 은수님 실기 확인. 1차 G0~G8 방식과 동일 |

> [!NOTE]
> **결정_1 의 파생 과제**: 부트로더가 UART 를 켠 채 앱으로 점프하는 경로가 존치되므로, CM3 에서 `tdc_hal_uart_uninit()` 을 제거할 때 **UART 페리페럴·DIO 가 켜진 상태로 남는 시나리오**를 반드시 검토해야 한다(슬립 전류·핀 레벨 영향). 분석 단계에서 판정한다.

## 5. 완료 기준

1. `FS_MEM_UART` 가 `cfx_link/` 에서 관리되고 CFX 와의 채널이 실기에서 동작한다
2. CM3 에 UART 관련 심볼·파일·매크로가 **0건**이다 (`FS_MEM_UART` 제외)
3. 사장 항목 전수 목록과 제거 계획이 문서로 남는다
4. 각 게이트에서 **전처리 diff 0 또는 설명 가능한 차이만** 남고, 은수님 실기 확인을 통과한다
