# ⑥ 계획 검증 — 2__cm3 2차 리팩토링

**TL;DR**: `계획.md` 의 6게이트 구조를 검증했다. **검증 기준(`.elf` 비트 일치)이 실제로 성립함을 G1+G2 로 실증**했으므로 계획의 근간이 검증됐다. 게이트 순서·커밋 단위·되돌리기 경로가 모두 정합하며, 은수님 체크 반영과 위험 등급 재검증 절차를 §4 에 추가했다. **구현 착수 준비 완료.**

## 1. 지침 준수 축

| 지침 | 준수 |
|---|---|
| 위험도 계층 분해 (`밸리데이션 계층화.md`) | **준수** — G1(이관)→G2(UART)→G3(함수)→G5(매크로)→G4(모듈)→G6(변수). 안전→위험 순 |
| 테스트 순서 명시 ("A는 B 통과 전제") | **준수** — G1 선행 필수, G4 최후. 각 게이트 전제 표기 |
| 단계별 커밋 + `--no-ff` 병합, 사용자 승인 후 | **준수** — 게이트별 독립 커밋, `claude_develop` 병합은 전 게이트 통과+승인 시 |
| 실기 확인 포인트 명시 | **준수** — 각 게이트 Eclipse 조작(Refresh/Clean/Index Rebuild)·확인 동작 명시 |
| AI 표시 금지 | **준수** — 커밋 메시지에 AI 라인 없음 |

## 2. 논리 정합 축

| 검증 | 결과 |
|---|---|
| "`.elf` 일치를 합격 기준으로" 가 실현 가능한가 | **실증됨** — G1+G2 로 md5 완전 일치 확인. 계획의 핵심 전제가 검증됨 |
| G4 만 `.elf` 불일치인 이유 | **정합** — `*_IRQHandler` 는 벡터 테이블 결속으로 링커가 못 지움. 모듈 제거 시 벡터 변화 불가피 |
| `__LINE__` 오염 대응 | **정합** — 라인 보존 대조본 절차(§7.1)로 diff 원인 분리. 실측으로 검증됨 |
| 되돌리기 경로 | **정합** — 게이트별 독립 커밋 → `git revert` 개별 가능 |

## 5. 종합 판정

계획은 **구현 착수 가능**하다. 핵심 검증 기준이 실증됐고, 게이트 순서·되돌리기·실기 확인 절차가 모두 정합하며, 은수님 체크와 위험 재검증 절차가 반영됐다.

**착수 순서**: G1(`FS_MEM_UART` 이관) → G2(UART) → G3(함수·변수) → G5(매크로·죽은블록·유령선언) → G4(모듈, 은수님 확인) → G6(선택).
