# ② 요구사항 검증 — 2__cm3 2차 리팩토링

> [!NOTE]
> **이 문서는 작업 종료 시점(2026-07-27)에 뒤늦게 작성됐다.** 8단계 산출물 중 ② 단계를 빠뜨린 채 ③ 분석으로 넘어갔고, 종료 점검에서 누락이 드러나 보완했다. 따라서 통상의 "착수 전 검증"이 아니라 **요구사항이 실제 결과와 어긋나지 않았는지를 사후 대조**하는 성격이다. 절차상 결함이므로 그대로 남긴다.

**TL;DR**: 요구사항 4건은 전부 충족됐고 완료 기준 4개도 통과했다. 다만 요구사항 작성 시점의 **전제 하나가 틀렸고**(§3 근거_2), 범위도 실제로는 **넓어졌다**(§3 논리_2). 둘 다 진행 중 발견해 문서에 반영했으나, 요구사항 단계에서 잡았어야 할 것이다.

## 1. 지침 준수 축

| 지침 | 준수 |
|---|---|
| 모호하면 질문 (`명령 해석 규칙`) | **준수** — 미결 3건을 선택지로 제시해 은수님 확정을 받고 §4에 기록 |
| 범위·불가침 명시 (`코딩/작업 규칙`) | **준수** — §3에 포함/참조만/불가침/제외를 구분 |
| 추측 섞이면 변경 금지 | **준수** — 코드로 판단 불가한 항목을 미결로 분리 |
| 검증 방법을 요구사항에 명시 | **준수** — 요구사항_4에 링크 레벨 판정·`__FILE__` 오염 차단 등 1차 노하우를 명시적 제약으로 넣음 |
| 8단계 산출물 | **위반** — 본 문서(②)를 제때 작성하지 않았다 |

## 2. 완료 기준 대조

| # | 완료 기준 | 결과 |
|---|---|---|
| 1 | `FS_MEM_UART` 가 `cfx_link/` 에서 관리되고 CFX 채널이 실기 동작 | **충족** — `cfx_link/tdc_shm_debug.h` 이관, G1 `.elf` 바이트 동일, 실기 통과 |
| 2 | CM3 에 UART 심볼·파일·매크로 **0건** | **충족** — 잔여 1건은 이관 헤더의 설명 주석 1줄뿐 |
| 3 | 사장 항목 전수 목록과 제거 계획이 문서로 남음 | **충족** — 체크리스트 4종(336항목) + `G5-잔여`(80) + `G6-목록`(117) |
| 4 | 각 게이트에서 전처리 diff 0 또는 **설명 가능한 차이만**, 실기 통과 | **충족** — 바이너리 변화 7개 지점 전부 원인 규명([`구현-검증.md §3`](구현-검증.md)), 실기 통과 |

## 3. 논리 정합·근거 축 — 어긋난 지점

요구사항이 실제와 맞았는지 항목별로 대조했다. **틀린 것 2건, 좁게 잡은 것 1건**이 나왔다.

| # | 요구사항 서술 | 실제 | 평가 |
|---|---|---|---|
| 근거_1 | `tdc_hal_uart_printf()` 사장 · `tdc_hal_uart_uninit()` 호출 1건 | 맞음 | ○ |
| **근거_2** | **"`uninit` 은 부트로더가 UART 를 켠 채 넘어오는 경로의 유일한 차단 지점"** | **틀림.** 호출자 `tdc_sys_uninit()` 자체가 호출 0건이라 **정리 코드가 실행된 적이 없다** | **✗** — 요구사항 §4 NOTE 에 "파생 과제"로 적었으나, 조사했다면 착수 전에 확정할 수 있었다. 결과적으로 UART 제거가 예상보다 안전했다 |
| 근거_3 | `FS_MEM_UART` 는 CFX 와 3필드 정합 | 맞음 (G1에서 실증) | ○ |
| **논리_2** | 요구사항_3 "사장 항목 전수 조사 **및 정리 계획 수립**" | 계획 수립을 넘어 **G3~G6 실제 제거까지** 수행 | **범위 확대** — 은수님이 단계마다 승인해 문제는 없었으나, 요구사항은 "계획까지"로 읽힌다 |
| 논리_3 | 요구사항_4 검증 제약에 1차 노하우 4건 인용 | 실제로는 **신규 노하우 5건이 더 필요**했다(`--print-gc-sections`·라인보존 대조본·`__LINE__` 크기 변화 등) | 미흡하나 예견 불가 |

### 3.1 요구사항이 놓친 것

착수 시점에 예상하지 못해 진행 중 드러난 항목들이다. 요구사항 단계에서 잡혔다면 계획이 더 정확했을 것이다.

| 항목 | 발견 시점 |
|---|---|
| BLE 프로토콜 정의는 미참조여도 제거 금지 | G5 (은수님 지시로 규약 명문화) |
| `static const` 상수 폴딩 트랩 (`devFwVer`) | G3 착수 직전 |
| 비활성 블록이 참조하는 변수 (`pabs_thr`) | G6 (일괄 제거 롤백) |
| `#if 0` 로 출력만 막아 계산이 고아가 된 구조 | G6 (은수님 지적) |
| 잠재 버그 2건 (PCM 모드 복원 누락 · 전하량 검사) | 분석·G6 |

## 4. 종합 판정

요구사항 자체는 **범위·불가침·검증 제약을 갖춘 실행 가능한 문서**였고, 완료 기준 4개가 모두 통과됐다.

다만 두 가지가 아쉽다.

1. **근거_2의 오판** — "UART 정리 코드가 실행 중"이라는 전제로 위험을 높게 잡았다. 착수 전 호출 사슬을 한 단계만 더 따라갔으면 알 수 있었다. 다행히 안전한 방향의 오판이었다.
2. **본 문서(②)의 누락** — 절차 위반이다. ① 직후 이 검증을 했다면 근거_2를 그 자리에서 잡았을 가능성이 있다. **다음 작업에서는 ② 를 건너뛰지 않는다.**
