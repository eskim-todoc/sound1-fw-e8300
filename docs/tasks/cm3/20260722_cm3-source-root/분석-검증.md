# ④ 분석-검증

**TL;DR**: 인과 판정(단일 원인 → 3파생)과 flat include 전제 3건이 실측으로 뒷받침된다. **결함 3건 검출** — `Debug/` 잔재 처리 절차 누락, `.settings/` 인코딩 설정 영향 미검토, `99_includeBoard` 내부 하위 폴더 여부 미확인. 계획에 반영.

## 1. 축 1 — 지침 준수

| 지침 | 검증 | 결과 |
|---|---|---|
| 리팩터링은 유닛→모듈→시스템 계층 분해 (루트 §7) | 로직 변경이 없어 유닛 계층 부재임을 명시하고 [구조검사]→[빌드]→[통합테스트] 로 대체 | ✅ 근거 있는 대체 |
| 의존성은 테스트 순서로 표현 | `분석.md §7` 에 "A는 B 통과 전제" 형식 명시 | ✅ |
| 회귀 위험 시 근본원인 가설 cross-check | `§6 위험 분석` 6건 각각 완화책 대응 | ✅ |
| Mermaid 사용 (ASCII 다이어그램 금지, §6) | 인과도를 Mermaid 로 작성 | ✅ |

## 2. 축 2 — 논리 정합

| 검증 | 결과 |

| "단일 원인 → 3파생" 인과가 성립하는가 | ✅ 소스 루트가 있으면 (a)`Debug/` 는 `Debug/source/` 한 갈래 (b)`-I` 는 `source/` 기준 (c)루트 잔여 헤더는 `board/` 귀속 — 3파생 모두 해소됨이 연역됨 |

## 4. 검출 결함

| ID | 결함 | 조치 |
|---|---|---|
| 결함_1 | **기존 `Debug/` 잔재 처리 절차가 분석에 없음.** 이동 후에도 구 경로 오브젝트 폴더(`Debug/hal` 등 20개)가 디스크에 남는다. Clean 만으로 빈 폴더가 지워지지 않을 수 있어, 은수님이 여전히 "혼재"를 보게 될 위험 | ⑤ 계획에 **`Debug/` 통째 삭제** 절차 추가 (git 미추적이라 안전) |
| 결함_2 | **`.settings/org.eclipse.core.resources.prefs` 의 인코딩 설정이 경로 기준일 가능성 미검토.** 폴더별 UTF-8 고정 항목이 있으면 이동 후 무효화되어 CP949 손상 방어가 뚫린다 (프로젝트 `CLAUDE.md` §소스 인코딩 규칙) | ⑤ 계획에 **`.settings` 실사 + 필요 시 경로 갱신** 단계 추가 |
| 결함_3 | **`99_includeBoard/` 내부에 하위 폴더가 있는지 미확인.** 있다면 `-I` 추가 등록이 필요한데 `§5 결속 지점`이 이를 다루지 않음 | ⑤ 계획 착수 시 실사, 하위 폴더 발견 시 `-I` 등록 |

## 5. 반증 시도 — flat include 유지가 정말 옳은가

경로 명시형(`<hal/tdc_hal_i2c.h>`)의 이점을 의도적으로 검토했다.

| 경로 명시형의 이점 | 이 프로젝트에서의 성립 여부 |
|---|---|
| 파일명 충돌 해소 | ❌ 충돌 0건 — 해소할 대상이 없음 |
| 공개 API 경계 표시 | ❌ 단일 바이너리, 외부 소비자 없음 |
| `-I` 1개로 축소 | ⭕ 성립. 다만 **요구_4 가 이를 명시적으로 배제** |
| 헤더 소속 가시화 | ⭕ 성립. 다만 `tdc_<도메인>_` 접두어가 이미 소속을 표기 (`tdc_hal_*` → hal) |

→ 성립하는 이점 2건 중 하나는 은수님이 명시 배제했고, 다른 하나는 **접두어 체계가 이미 대체**하고 있다. **flat 유지가 이 프로젝트에서 합리적**이라는 분석 결론을 유지한다.

## 6. 결론

분석은 **⑤ 계획 수립에 충분**하다. 결함 3건은 계획 단계 절차로 흡수한다.
