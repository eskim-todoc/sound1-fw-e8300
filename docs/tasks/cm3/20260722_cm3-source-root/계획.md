# ⑤ 계획 — 3단계 · 단일 게이트

**TL;DR**: 단계_1(폴더 이동) → 단계_2(include `<>` 통일) → 단계_3(Eclipse 설정 갱신)을 **한 커밋씩** 쌓고, 마지막에 은수님 빌드·실기 게이트 **1회**로 폐쇄한다. 로직 변경이 0이므로 게이트를 쪼갤 실익이 없다. 롤백은 커밋 단위.

## 1. 목표 구조

```
2__cm3/
├── .cproject  .project  .settings/  .gitignore
├── sections.ld                     링커 -T 대상 (루트 유지 - 불가침)
├── Debug/                          빌드 산출물 → Debug/source/ 한 갈래
└── source/
    ├── main.c   main.h             ← Cortex-M3-src/ 소멸
    ├── board/                      ← 99_includeBoard/ 27 + 루트 헤더 2
    ├── lib/
    │   ├── SEGGER_RTT/             ← Gen1_5/SEGGER_RTT
    │   └── tiny-AES-c/             ← Gen1_5/tiny-AES-c
    ├── hal/  drv/                  하드웨어
    ├── pwr/  fs/  util/            플랫폼 서비스
    ├── led/  touch/  ui/           사용자 인터페이스
    ├── ble/  qcc/  dfu/  boot/  cfx_link/   통신·부팅
    └── isd/  stim/  sys/           내부기·자극·시스템
```

`tdc_convention.md` 는 `docs/참고/cm3-소스-트리-규약.md` 로 이관한다(결함_2 조치) — 소스 트리에 문서를 두지 않는다.

## 2. 단계_1 — 폴더 이동 (커밋 1)

| 순번 | 작업 | 명령 |
|---|---|---|
| 1-1 | `source/` 생성 | `mkdir source` |
| 1-2 | 도메인 16개 이동 | `git mv <d> source/<d>` × 16 |
| 1-3 | main 승격 | `git mv Cortex-M3-src/main.c source/` · `main.h` 동. 빈 폴더 소멸 |
| 1-4 | 라이브러리 격리 | `mkdir source/lib` → `git mv Gen1_5/SEGGER_RTT source/lib/` · `Gen1_5/tiny-AES-c source/lib/` |
| 1-5 | 보드 정의 통합 | `git mv 99_includeBoard source/board` → `git mv 99_eeprom_address.h processorDirective.h source/board/` |
| 1-6 | 규약 문서 이관 | `git mv tdc_convention.md ../../docs/참고/cm3-소스-트리-규약.md` |

> [!CAUTION]
> `sections.ld` 는 **절대 이동하지 않는다.** `Debug/makefile:77` 이 절대경로로 `-T` 참조 중이며, `.cproject:105` 도 `${ProjName}/sections.ld` 를 가리킨다. 직전 `.cproject` 정리에서 이 파일을 잘못 제거한 전례가 있다.

**검증_구조_1**: 이동 후 프로젝트 루트에 `source/` `Debug/` `sections.ld` + Eclipse 메타만 남는지 확인. `source/` 하위 파일 수 = **180** 대조.

## 3. 단계_2 — include `<>` 통일 (커밋 2)

`#include "x.h"` → `#include <x.h>` 전면 치환. **81파일 / 419건**.

| 항목 | 방침 |
|---|---|
| 치환 정규식 | `^\s*#\s*include\s*"([^"]+)"` → `#include <\1>` — **`#include` 로 시작하는 라인에만** 적용. 문자열 리터럴 오염 차단 |
| 대상 | `source/` 전체 (`lib/` 포함 — SEGGER_RTT·tiny-AES-c 도 내부 include 는 통일) |
| 제외 | `Debug/` (산출물) |
| 경로 접두어 | **생성하지 않음** — 요구_4. 파일명만 유지 |

**검증_구조_2**: `#include "` 잔존 **0건** · 치환 후 `#include <` 총계 = 987(568+419) · 경로 접두어(`/` 포함) include **0건**.

> [!NOTE]
> `lib/` 의 외부 라이브러리 파일 내부 include 도 통일 대상에 포함한다. `SEGGER_RTT.c` 등이 `"SEGGER_RTT.h"` 를 참조하는데, 해당 폴더가 `-I` 에 등록돼 있어 `<>` 로도 동일하게 해소된다. 라이브러리 **원본 심볼**은 건드리지 않으므로 G0 라이브러리 예외와 충돌하지 않는다.

## 4. 단계_3 — Eclipse 설정 갱신 (커밋 3)

### 4.1 `-I` 목록 (`.cproject` line 59~81)

| 조치 | 대상 |
|---|---|
| **경로 갱신** | 도메인 16 + `Gen1_5/SEGGER_RTT`→`source/lib/SEGGER_RTT` + `Gen1_5/tiny-AES-c`→`source/lib/tiny-AES-c` + `99_includeBoard`→`source/board` + `Cortex-M3-src`→`source` |
| **제거** | `${ProjName}/linked/include` (사장 - `linked/` 미존재) · `${ProjName}` (루트 헤더 2개가 `board/` 로 이동해 불필요) · `${ProjName}/Gen1_5` (폴더 소멸) |
| **무변경** | `${eclipse_home}` SDK 경로 3건 · 링커 `-T ${ProjName}/sections.ld` |

결과 `-I` **20건** (도메인 16 + `source` + `source/board` + `source/lib/SEGGER_RTT` + `source/lib/tiny-AES-c`). 24 → 20 으로 축소.

### 4.2 `sourceEntries` (`.cproject` line 131~136)

```xml
<sourceEntries>
    <entry flags="VALUE_WORKSPACE_PATH|RESOLVED" kind="sourcePath" name="source"/>
</sourceEntries>
```

기존의 `name=""` + `excluding=...` + 개별 3건(계 4 entry)을 **단일 entry** 로 대체한다. `Debug/` 는 CDT 가 빌드 출력으로 자동 제외한다.

### 4.3 손대지 않는 것

| 항목 | 사유 |
|---|---|
| `.settings/org.eclipse.core.resources.prefs` | `encoding/<project>=UTF-8` — **프로젝트 전역** 설정이라 경로 의존 없음 (결함_2 해소) |
| `.settings/language.settings.xml` | `GCCBuiltinSpecsDetector` = 툴체인 빌트인 경로 자동 탐지. 이것이 은수님이 보신 "자동 include 경로"의 정체이며, **정상 동작이라 유지**한다 |
| `Debug/makefile` 등 | CDT 가 재생성 |

**검증_구조_3**: `.cproject` XML well-formed · `-I` 20건 **전부 실존 폴더** 대조 · `sourceEntries` 단일 entry · `sections.ld` 참조 2개소 보존.

## 5. 단계_4 — 잔재 정리 · 규약 명문화 (커밋 3 동봉)

| 작업 | 내용 |
|---|---|
| `Debug/` 통째 삭제 | 구 경로 오브젝트 폴더 20개 잔존 방지 (결함_1). **git 미추적**이라 안전 |
| 규약 명문화 | `docs/참고/cm3-소스-트리-규약.md` 에 추가: ① 소스는 `source/` 아래에만 ② include 는 `<파일명.h>` — 경로·따옴표 금지 ③ **새 폴더 생성 시 `.cproject` `-I` 등록 필수** ④ `sections.ld` 루트 불가침 |

## 6. 게이트 · 검증 라벨

| 라벨 | 계층 | 방법 | 담당 |
|---|---|---|---|
| **검증_구조_1** | 구조 | 루트 잔여 정합 · `source/` 180항목 | Claude |
| **검증_구조_2** | 구조 | `#include "` 잔존 0 · 경로 접두어 0 | Claude |
| **검증_구조_3** | 구조 | `.cproject` XML valid · `-I` 20건 실존 · sourceEntries 단일 | Claude |
| **검증_구조_4** | 구조 | 헤더 basename 중복 0 재확인 (flat 전제 유지) | Claude |
| **검증_빌드** | 빌드 | Eclipse **Clean → Build** | 은수님 |
| **검증_통합** | 시스템 | 실기 — 부팅 · BLE · 자극 · EEPROM · 터치 · LED | 은수님 |

의존: 검증_빌드는 검증_구조_1~4 통과 전제, 검증_통합은 검증_빌드 통과 전제.

> [!IMPORTANT]
> **게이트 진입 전 은수님 조작 필수**: ① Eclipse **Project → Clean** ② **Refresh(F5)** ③ **Index → Rebuild**. 셋 다 하지 않으면 구 경로 잔재로 오탐이 발생한다.

## 7. 롤백

단계별 커밋이 분리돼 있어 `git revert <커밋>` 으로 단계 단위 되돌림이 가능하다. 전면 롤백은 `git reset --hard claude_develop` (은수님 승인 필요).

## 8. 범위 밖 재확인

형제 프로젝트 개편 · 사장 코드 제거 · 3프로젝트 ABI 동기화 · 도메인 재분류 · `Debug/` 프로젝트 외부 이전은 본 작업에 포함하지 않는다.
