# ② 요구사항-검증

**TL;DR**: 요구 6건이 확정 결정으로 빠짐없이 매핑됐고, flat include 의 전제(헤더명 전역 유일)가 실측 0건 중복으로 입증됐다. **결함 2건 검출** — `linked/include` 사장 경로 누락, `tdc_convention.md` 거취 미정. 요구사항에 반영 완료.

## 1. 축 1 — 지침 준수

| 지침 | 검증 | 결과 |
|---|---|---|
| 모호 시 질문 (루트 §2) | 소스 루트 이름·include 표기·적용 범위를 선택지로 제시해 확정 | ✅ 추측 진행 없음 |
| 8단계 프로세스 (§3) | ①~⑥ 후 승인, ⑦ 구현 | ✅ 본 문서가 ② |
| 동작 보존 (밸리데이션 계층화 §7.2) | 비기능_1 로 명시 | ✅ |
| `tdc_` 접두어 (§7) | 신규 심볼 없음 — 이동·표기 변경만 | ✅ 해당 없음 |
| 문서 메타 | frontmatter + TL;DR | ✅ |

## 2. 축 2 — 논리 정합

| 검증 | 결과 |
|---|---|
| 요구_1~6 이 확정 결정에 전부 매핑되는가 | ✅ 요구_1→기능_1, 요구_2→기능_5, 요구_3→기능_4, 요구_4→"flat 유지", 요구_5→범위, 요구_6→`분석.md §2` |
| 요구_3(`<>`)과 요구_4(flat)가 서로 충돌하는가 | ✅ **충돌 없음**. `<>` 는 탐색 대상을 `-I` 로 한정할 뿐 경로 표기를 강제하지 않는다 |
| flat include 가 폴더 계층(`source/lib/SEGGER_RTT`)과 양립하는가 | ✅ 양립. 컴파일러는 `-I` 목록을 순차 탐색할 뿐 계층을 해석하지 않음 |
| 수용 기준이 측정 가능한가 | ✅ 전부 grep/파일 존재로 판정 가능 (잔존 0건·diff 0 등) |

## 3. 축 3 — 근거 검증

| 주장 | 검증 방법 | 결과 |
|---|---|---|
| "헤더 basename 전역 중복 0" — flat include 전제 | `find -name '*.h' -printf '%f\n' \| sort \| uniq -d` | ✅ **0건**. 전제 성립 |
| "`<>` 가 이미 우세" | 표기별 grep 카운트 | ✅ `<>` 568 · `""` 419 |
| "경로 접두어 include 잔존 없음" | `#include` 중 `/` 포함 패턴 grep | ✅ **0건** (G7 에서 `<isdExecution/driver_PCM.h>` 정리 완료) |
| "`sections.ld` 는 makefile 이 절대경로 참조" | `Debug/makefile` 의 `-T` 인자 확인 | ✅ 확인. 루트 유지 필요(비기능_3) |
| "Debug/ 가 소스 트리를 미러링" | `ls Debug/` | ✅ 소스 폴더 20개 동일 이름 복제 확인 |

## 4. 검출 결함

| ID | 결함 | 조치 |
|---|---|---|
| 결함_1 | `.cproject` 의 `-I` 목록에 **`${ProjName}/linked/include` 가 있으나 `linked/` 폴더는 실존하지 않음**. `.project` 에 linked resource 도 0건 — 완전한 사장 경로. 직전 `.cproject` 정리(`201cd46`)에서 "폴더가 아닌 항목은 보존" 판단으로 남겨둔 것 | **기능_5 수용 기준에 제거 명시** (반영 완료) |
| 결함_2 | `tdc_convention.md` 가 프로젝트 루트에 있는데 거취가 미정. 기능_1 은 "루트에 남는 것"에 이 파일을 넣지 않음 | ⑤ 계획에서 확정 — **`docs/` 로 이관**하여 소스 트리에서 분리 (`계획.md §2`) |

## 5. 결론

요구사항은 **⑦ 구현 진입에 충분**하다. 결함 2건은 요구사항·계획에 반영했다. 다음 단계 ③ 분석에서 업계 구조 비교 근거와 이동 대상 전수를 확정한다.
