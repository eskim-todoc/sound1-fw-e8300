# ⑧ 구현-검증 — 2__cm3 전면 리팩토링

### 3.1 ABI 동결 근거

`cfx_cm3_sharedMemoryAll` 참조 232건이 전 트리에 남아 있다 — **이것이 정상**이다. CFX(`1__cfx`)·calibration(`5__calibration`)이 동일 레이아웃 사본을 갖고 `.shared_memory` 섹션 주소로 정합하므로, 인스턴스명·구조체 타입·필드는 리팩토링 대상에서 제외했다(G0 결정, `tdc_shm.h` 상단 경고 주석으로 고정).

## 4. 축 3 — 근거 검증 (본 검증에서 추가 검출)

게이트별 `검증_공통_1`은 **각 게이트 범위 심볼**만 대조했기 때문에, 앞 게이트에서 흘러나온 잔존을 놓쳤다. 전 트리 재스캔으로 아래를 검출·정정했다.

| 잔존 | 건수 | 성격 | 정정 |
|---|---|---|---|
| `ci_fatfs_get_fp` | 5 | **실코드** — fs 공개 함수. 헤더 스캔에서 유일한 미정합 | → `tdc_fs_get_fp` |
| `snd_boot_status_t` | 13 | **실코드** — boot/dfu 공유 타입 | → `tdc_boot_status_t` |
| `ci_aes_init`/`encrypt`/`decrypt` | 10 | **실코드** — tiny-AES-c 파일 안에 있으나 원본 API(`AES_ECB_*`)가 아닌 **자작 래퍼**라 라이브러리 예외 미적용 | → `tdc_aes_*` |
| `ci_strcasecmp` | 30 | **실코드** — static. 지침상 무접두어 | → `str_casecmp` |
| `@file`·주석 오기 6종 | — | `ci_system_mode.h`·`ci_from_cfx_eeprom_recover`·`ci_filesystem`·`ci_timer`·`ci_file_system_get_fp`·`isd_interface_StimulationStandAlone.c` | 현행명으로 갱신 |

계 **22파일 / 58건**. 정정 후 재스캔 잔존은 `ci_fake_power_sleep` 3건뿐이며, 이는 **제거 이력을 남긴 주석**이라 옛 이름이 정확하다(존치가 맞음).

> [!NOTE]
> **학습**: 게이트 범위로 좁힌 잔존 검사는 게이트 경계를 넘는 심볼을 구조적으로 놓친다. 다게이트 리팩토링에서는 **매 게이트마다 전 트리 재스캔**을 병행해야 한다. 라이브러리 예외도 "파일 단위"가 아니라 **"원본 API 심볼 단위"**로 판정해야 한다(`ci_aes_*` 사례).

## 6. 결론

**⑦ 구현 완료로 판정한다.** 지시된 3대 요구(전 심볼 `tdc_` 정합 · 공유 구조체 보존 · 코드 일관성)를 충족했고, 8회 실기 게이트로 동작 보존을 실증했다. 본 검증에서 검출된 잔존 58건은 정정 완료. 사장 코드 제거는 **의도적으로 보류**해 별도 작업으로 넘긴다 — 리팩토링(동작 보존)과 기능 삭제(동작 변경)를 같은 커밋에 섞지 않기 위함이다.
