# 요구사항 — 2__cm3 전면 리팩토링

**TL;DR**: 2__cm3 약 174파일/43,000줄을 **전 심볼 rename(도메인 구분 체계) + 폴더 구조 재편 + 유닛/모듈 밸리데이션 계층 + FSM·파일처리 패턴 일관화 + Sullivan 사장 코드 발굴**로 전면 리팩토링한다. 불가침 3종: 공유 메모리 구조체 항목 존치 · `SEGGER_RTT_*` 제외 · 관측 가능 동작 엄격 보존. 진행은 전수 분석 1회 + 모듈별 구현(모듈마다 빌드 게이트).

---

## 1. 배경

지시 원문과 구속 조건 5개는 [`이력 및 결과.md §지시 원문`](이력%20및%20결과.md) 참조. 착수 시 스코프 질의 4건에 대한 은수님 답변(2026-07-20):

| 질의 | 답변 |
|---|---|
| systemControl FSM 분해(승인 대기) 처리 | **전면 리팩토링에 흡수** — 통일 FSM 표준 정의 후 그 표준으로 분해. 기존 분석 산출물(dead 3개 · 초기값 2000 등) 재활용 |
| `tdc_` 적용 범위 | **전체** (아래 원문) |
| 진행 단위 | **전수 분석 1회 + 모듈별 구현** (모듈마다 빌드 확인 후 다음 진행) |
| 동작 보존 수준 | **엄격 보존** (관측 가능 동작·부수효과 유지, 동작 변경 필요 시 별도 작업 분리) |

### `tdc_` 범위 답변 원문 (구속 조건)

> 전체 내용이야. 함수/변수 이름까지 전부. 단, `SEGGER_RTT_` 접두어는 SEGGER_RTT 라이브러리라 제외. `ci_` 도 내가 만든거라 수정해도 돼. `sdk_ci_` 도 마찬가지. `driver_` 가 붙은 것도 레거시 코드인데 변경을 원하긴 해. `isd_`, `ble_` 등도 다 원래 레거시 코드 내용이라 변경을 원하긴 하는데, 이름에서 알 수 있듯이 특정 목적들을 위한 코드라 잘 구분할 수 있게 정리해야해. 예를 들면 `tdc_isd_` 로 가던지, 아니면 더 좋은 방향을 제시해. 폴더 이름도 변경해도 되고, 구조를 바꿔도 돼. 지금 구조도 마음에 안드는게 사실이야.

핵심 해석:

- **전 심볼**(함수 · 변수 · 타입 · 매크로 · 파일명 · 폴더명) rename 대상. 유일한 라이브러리 예외 = `SEGGER_RTT_*`
- `ci_` / `sdk_ci_` / `driver_` / `isd_` / `ble_` 등 기존 접두어는 전부 은수님 자작 레거시 — 변경 가능하되 **도메인이 이름에서 구분**되어야 함 (`tdc_isd_` 같은 계층 접두어 또는 더 나은 안을 ⑤에서 제시)
- **폴더 구조 재편 허용·희망** — 현 구조에 불만 명시

## 2. 요구사항

### 요구사항_1 — 네이밍 전면 통일 (도메인 계층 체계)

전 심볼과 파일 · 폴더명을 단일 컨벤션으로 통일한다. 컨벤션은 `tdc_<도메인>_<역할>` 계층을 기본안으로 하되, ⑤ 계획에서 대안 비교 후 확정한다(은수님 "더 좋은 방향" 요청).

**수용 기준**: 확정 컨벤션 문서 1건 + 모듈별 rename 완료 시 구 접두어 심볼 잔존 0 (예외 목록 제외).

### 요구사항_2 — 폴더 구조 재편

도메인 기반 폴더 구조를 설계해 흩어진 잔여물(루트 `systemControl/` · `isdExecution/` · `signalProcessing/` · 루트 직속 헤더 3종)을 정리한다.

**수용 기준**: 재편안(현행 → 신규 매핑표) 승인 후 적용. Eclipse `.cproject` 소스 경로 · include 경로 · `sections.ld` 정합 유지.

### 요구사항_3 — 유닛/모듈 밸리데이션 계층 적용

루트 지침 [`코딩/밸리데이션 계층화.md`] 방법론(유닛→모듈→시스템, 의존성은 테스트 순서)을 전 모듈에 적용한다. 선례: `signalProcessing/20260626_i2s-beamforming-modularize` 의 유닛-모듈-테스트맵.

**수용 기준**: 모듈별 유닛-모듈-테스트맵 산출. 유닛 경계와 `[UNIT]`/`[MODULE]` 식별이 코드에 반영.

### 요구사항_4 — FSM 패턴 일관화

표준 FSM 패턴 1개를 정의하고, FSM 성격의 제어 코드를 전수 목록화해 그 패턴으로 전환한다. **승인 대기였던 `main/20260715_systemcontrol-fsm-decompose` 를 본 작업에 흡수** — systemControl 도 표준 패턴으로 분해하며, 기존 분석 산출물(dead static 3개 · `ISD_Disconnection_counter` 초기값 2000 · 1-tick 지연 문서화)을 재활용한다.

**수용 기준**: FSM 표준 정의 문서 + FSM 인스턴스 전수 목록 + 전환 완료. 상태 · 전이 · 부수효과가 전환 전후 등가(요구사항_8).

### 요구사항_5 — 파일 처리(FS/EEPROM) 패턴 일관화

파일시스템 · EEPROM 접근 코드를 전수 목록화하고 단일 패턴으로 통일한다. 참조 선례: `ci_stim_mute` 패턴, `touch/20260701_touch-setting-file-persist` 설계(magic+version+size+crc, all-or-nothing).

**수용 기준**: 파일 처리 표준 정의 + 인스턴스 전수 목록 + 통일 완료.

### 요구사항_6 — Sullivan 사장 코드 발굴 · 제거

호출 경로 전수 조사로 사장 코드를 찾아 제거한다. **단 `cfx_cm3_sharedMemoryAll` 구조체 항목은 미사용이어도 존치**(조건_1).

**수용 기준**: 제거 대상마다 "소비자 0" 근거(`파일:라인`). 선례: Sullivan GPIO 체인(3b966a7) · fake sleep(cc5e4e5).

### 요구사항_7 — 루트 노출 헤더 정리

`99_eeprom_address.h` · `99_errorCode.h` · `processorDirective.h` · `99_includeBoard/`(27파일) 및 루트 잔여 디렉토리를 조사해 통합/삭제/이동 + 명명을 결정한다.

**수용 기준**: 헤더별 처분안(근거 포함) 승인 후 적용.

### 요구사항_8 — 엄격 동작 보존 (불변식)

관측 가능한 동작 · 부수효과(LED · 로그 · 통신 · 타이밍)를 유지한다. rename 은 동작 무영향이 원칙이나, FSM · 파일처리 전환은 경로별 등가 대조를 정적으로 수행한다. 동작 변경이 필요해지면 별도 작업으로 분리해 승인받는다.

### 요구사항_9 — 모듈별 빌드 게이트

구현은 모듈 단위로 쪼개고, **매 모듈 은수님 Eclipse 빌드 + 실기 확인 후** 다음 모듈로 진행한다.

## 3. 불가침 · 예외 목록

| 항목 | 내용 | 근거 |
|---|---|---|
| 공유 메모리 구조체 **항목** | `cfx_cm3_sharedMemoryAll` 필드 제거 금지 (미사용 존치) | 조건_1 (지시 원문) |

## 5. 성공 판정

1. 확정 컨벤션(네이밍 · 폴더 · FSM · 파일처리) 문서화 + 전 모듈 적용.
2. 구 접두어 심볼 잔존 0 (예외 목록 제외).
3. 사장 코드 제거 전건 "소비자 0" 근거 보유. 공유 구조체 항목 존치 확인.
4. 모듈별 유닛-모듈-테스트맵 존재.
5. 전 모듈 빌드 게이트(은수님 Eclipse + 실기) 통과.
