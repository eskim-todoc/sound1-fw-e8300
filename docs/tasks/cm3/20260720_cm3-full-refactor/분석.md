# 분석 — 2__cm3 전면 리팩토링

**TL;DR**: 전수 census(스크립트, 원본 데이터 [`분석-데이터/`](분석-데이터/)) 결과 — rename 대상 **심볼 약 1,800개 · 파일 163개**, 실질 대형 FSM **10여 개**(mapping 계열 5대가 최대), FS/EEPROM 접근 **28파일**, 사장 후보 **정제 후 약 70개**(자동 105 중 오탐 35 제외), **공유 인터페이스는 타입 19 + 필드 105 전부 복제 존재 → rename 보류 확정**. 로그 태그 55종은 도메인 기반이라 rename 과 대부분 독립. 파일명 오타(`dirver_*`) 3건, 포함 0 헤더(`99_errorCode.h`) 1건 발견.

## 4. FSM 인스턴스 (후보 79 → 실질 대형 목록)

검출 기준: 함수 본문 내 `static` 상태 보유 또는 `switch`+state 어휘. 전체는 데이터 파일, 실질 대형(상태 3개 이상 + 제어 성격)은:

| 함수 | static 수 | 위치 | 도메인 |
|---|---|---|---|
| `impedanceMeasurement` | 16 | `isd_interface_mapping_impedanceMeasurement.c` | ISD 매핑 |
| `testStimulation` | 15 | `isd_interface_mapping_testStimulation.c` | ISD 매핑 |
| `specificStimulation` | 15 | `isd_interface_mapping_SepcificStimulation.c` | ISD 매핑 |
| `eCapMeasurement_masking` | 15 | `isd_interface_mapping_eCAP_Measurement.c` | ISD 매핑 |
| `liveStimulation` | 14 | `isd_interface_mapping_Live.c` | ISD 매핑 |
| `init_ISD` | 9 | `isd_interface_init_FPGA.c` | ISD 초기화 |
| `settingStimulPara_*` (2벌) | 8+6 | `isd_interface_stimulationParaSetting.c` | 자극 파라미터 |
| `systemControl` | 7 | `systemControl.c` | 시스템 (흡수된 선행 분석 보유) |
| `update_isd_LinkConnection_*` (2벌) | 6+3 | `isd_interface.c` | ISD 링크 |
| `mappingControl` / `remoteControl` | 5 / 3 | BleCommunication | BLE 명령 |
| `isd_path_Open` · `init_FPGA` · `enableStimul_10v` | 4 · 3 · 3 | ISD 초기화 | |
| touch 계열 (`tdc_touch_process` 등) | — | `tdc_touch*.c` | 이미 명시 FSM 에 가까움 (최근 정비) |

**시사점**: FSM 이 가장 밀집한 곳은 **ISD 매핑 5대 함수**다(각 14~16개 static, 사실상 동일 패턴의 복제 5벌). 여기가 FSM 표준화의 최대 수혜처이자 최대 위험처(자극 제어 = 의료 기능)다. 표준 패턴은 흡수된 `systemcontrol-fsm-decompose` 의 설계(명시 state + ctx struct + 단계 핸들러)를 기반으로 ⑤에서 확정한다.

## 5. 파일 처리 인스턴스 (28파일)

계층이 이미 존재하나 소비 패턴이 제각각이다:

| 계층 | 파일 | 상태 |
|---|---|---|
| FS 코어 | `Gen1_5/FS/ci_filesystem.c` | 래퍼 (fatfs 흔적: `snd_fatfs_remount_twice`) |
| 소비자 (정형) | `ci_stim_mute.c` (magic+crc, all-or-nothing) | **최신 패턴 — 표준 후보** (선례: touch-setting-file-persist 설계) |
| 소비자 (비정형) | `ci_map.c` · `ci_event_log.c` · `ci_boot.c`(`_open_status_file` 계열) · `ci_ota.c` | 각자 방식 |
| EEPROM 원격 | `Gen1_5/fn_fromCFX/fn_from_cfx_eeprom_{read,write,erase,recover}.c` | CFX 명령 기반 — 공유 메모리 프로토콜과 결합 |
| 앱측 대량 소비 | `isd_interface_mapping_readWrtieMapData.c`(오타 포함) 등 | 맵데이터 read/write |

**시사점**: "일관된 파일 처리"의 실체는 ①`ci_filesystem` 위에 ②표준 레코드 규약(magic+version+size+crc)과 ③접근 API 계층(`tdc_fs_*`)을 세우고 소비자를 이관하는 것. `fn_fromCFX` 는 공유 메모리 프로토콜과 얽혀 있어 **마지막 순서**로 미룬다.

## 7. 공유 인터페이스 — rename 보류 목록 확정

`cfx_cm3_sharedMemory.h` 의 **타입 19개 전부 + 필드 105개 전부**가 CFX(`1__cfx/environment/shared_memory.h`) 및 calibration(`5__calibration/include/cfx_cm3_sharedMemory.h`) 복제본에 존재한다 (`06_공유-인터페이스.md`, spot-check: `grep -c ST__CFX_CM3_SharedMemory` → CFX 27 / cal 26).

**결정**: 이 심볼들은 **2__cm3 단독 rename 금지**. 3헤더 동시 rename 은 타 프로젝트 범위라 별도 작업으로 분리한다. 헤더에 "공유 ABI — 단독 rename 금지" 주석을 명시해 재발을 막는다.

추가 교차 결합 (파일명 복제, `05_헤더-위상.md`): `processorDirective.h` · `definitionsForAlgorithm.h` 도 calibration/CFX 에 복제본 존재 — **내용 rename 시 복제본과의 drift 를 ⑤에서 처리 방침 확정** (동기화 대상 목록화).
`ci_boot.h` · `sdk_ci_boot.h` 는 0__bootloader 와 공유 계보 — bootloader 는 범위 밖이므로 2__cm3 쪽 rename 시 계보 단절을 감수할지 ⑤ 판단.

## 8. 로그 태그 (55종) — 결함_1 해소

상위: `[TOUCH]` 40 · `[FPGA]` 32 · `[ISD]` 26 · `[MUTE]` 25 · `[INFO]` 18 ... — **전부 도메인/기능 명칭이지 심볼명이 아니다**. 따라서:

**정책 제안**: 태그 문자열은 **유지**(rename 과 독립), 로그 본문에 심볼명을 인용한 경우만 추종 갱신. 외부 로그 파서 호환도 자동 보존된다. ⑤에서 확정.
