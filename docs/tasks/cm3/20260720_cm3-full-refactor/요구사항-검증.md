## 축_2 — 논리 정합성

### 결함_1 (발견 · ⑤ 위임) — rename ↔ 로그 문자열 보존 충돌

요구사항_8 은 "로그 등 부수효과 유지"를 요구하는데, 요구사항_1 의 전 심볼 rename 은 **로그 문자열에 박힌 심볼명**(명시 문자열 · `__func__` 매크로)을 바꿀 수 있다. 예: `ci_printw("[GD] ...")` 태그, 함수명 인용 로그.

**방침**: 로그는 디버그 채널이므로 **심볼명 추종 갱신을 허용**하는 것이 합리적이나, 외부 파서(로그 수집 도구)가 태그에 의존할 가능성은 은수님만 안다. ⑤ 계획에서 "로그 태그 정책"(유지 목록 vs 추종 갱신)을 확정 항목으로 올린다.

### 결함_2 (발견 · ⑤ 위임) — 공유 헤더 rename ↔ 모듈 게이트 충돌

요구사항_9 는 모듈 단위 구현 · 빌드 게이트를 요구하나, `processorDirective.h` · `cfx_cm3_sharedMemory.h` 같은 **전역 공유 헤더의 rename 은 전 모듈에 동시 파급**된다 — 모듈 하나만 바꾸고 빌드를 통과시킬 수 없다.

**방침**: 모듈 분할 설계 시 **기반(foundation) 단계를 선두에 배치** — 공유 헤더 · 공통 타입 · 루트 노출 헤더 정리를 1개 게이트로 먼저 통과시킨 뒤, 도메인 모듈들을 순차 진행한다. ⑤ 의 모듈 순서 설계 요건으로 명시.

### 결함_3 (발견 · 즉시 조치) — 흡수된 작업의 상태 갱신 누락

요구사항_4 가 `main/20260715_systemcontrol-fsm-decompose` 를 흡수한다고 선언했으나, **그 작업 폴더의 상태를 갱신하는 조치가 없다**. 방치하면 "승인 대기" 상태로 영원히 남는다.

**조치**: 해당 작업 `이력 및 결과.md` 에 흡수 종결 기록을 추가한다 (본 검증 직후 수행).
