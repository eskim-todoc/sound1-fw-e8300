# 분석 - 조치안 선택과 배치

**TL;DR**: 결함 자체의 분석은 [`상시 점검 대장.md` §2.6](../../../상시%20점검%20대장.md) 에 끝나 있다. **이 문서는 «어떻게 고칠 것인가» 만 다룬다.** 결론은 **안 나(공통 함수) + 안 다(루프 가드) 동시 적용**이고, 공통 함수를 **`ble/` 아래 새 파일**로 떼는 것이 핵심이다 — 그래야 순수 함수라 호스트가 단독 링크한다.

## 1. 조치안 비교

대장 §2.6 이 제시한 세 안이다.

| 안 | 내용 | 검증 가능성 | 중복 |
|---|---|---|---|
| **가** | 리모콘에 매핑 앱 검사를 복제 | 호스트 (remote 스위트) | **늘어난다** |
| **나** | 공통 함수로 빼서 양쪽 호출 | 호스트 (+ 신규 스위트) | **줄어든다** |
| **다** | 배열 접근 루프에 상한 이중가드 | **불가** (`isd/` 미컴파일) | - |

### 1.1 「가」 를 배제하는 이유

이 결함의 구조적 원인이 **«같은 로직이 두 경로에 복사돼 한쪽만 갱신됐다»** 이다. 복제를 늘리면 같은 결함을 다시 만든다.

이식 문서도 같은 진단을 한다.

> **구조적 원인**: 바이폴라 기능이 추가되면서 전극번호를 변환하는 코드가 여러 경로에 **복사되어 퍼졌고**, 원본에 있던 `!= 99` 체크가 일부 경로에서 누락됐다.

### 1.2 「다」 만으로 부족한 이유

루프 가드는 **배열을 넘지 않게** 할 뿐, 이상값이 플래시에 기록되는 것 자체는 막지 못한다. `numFrequencyBand = 200` 이 저장되면 밴드 수가 32로 잘려 **자극 구성이 조용히 달라진다.**

### 1.3 「나 + 다」 를 함께 적용한다

이식 문서 §5 체크리스트가 입력 검증(4·5번)과 루프 가드(7번)를 **별개 항목**으로 요구한다. 방어 깊이가 다르다.

| 층 | 막는 것 |
|---|---|
| 입력 검증 (나) | **앞으로** 들어올 이상값 |
| 루프 가드 (다) | **이미 플래시에 있는** 이상값 · 미래의 새 쓰기 경로 |

> [!IMPORTANT]
> **둘째 층이 실질적이다.** 이 펌웨어를 올리는 기기의 플래시에 이미 이상값이 있으면 입력 검증은 아무것도 못 한다.

## 2. 공통 함수를 어디에 둘 것인가

### 2.1 제약 - 호스트가 링크할 수 있어야 한다

`isd/` 는 `run.sh` 의 `TEST_TARGETS` 에 없어 호스트가 컴파일하지 않는다. `ble/mapping/` 이나 `ble/remote/` 의 기존 `.c` 안에 두면 **그 파일 전체를 링크**해야 해서 다른 스위트가 무거워진다.

### 2.2 결론 - `ble/` 아래 새 파일

```
src/2__cm3/source/ble/tdc_ble_map_field_range.c / .h
```

**선례가 있다.** `ble/tdc_ble_reply.c` 는 매핑·리모콘이 공유하는 모듈이고 `run.sh` 의 `COMMON_SRC` 에 **스텁이 아니라 실물로** 들어가 있다. 같은 자리에 같은 방식으로 둔다.

> [!NOTE]
> **이것이 [isd 분해 분석](../../isd/20260806_0834_isd-대형함수-분해-분석/분석.md) §6.2 가 예측한 «호스트 게이트를 여는 통로» 의 첫 실행이다.**
>
> 그 문서는 «순수 함수를 새 파일로 떼면 `isd/` 의 의존 사슬(shm · i2c · FPGA)에 닿지 않아 호스트가 단독 링크한다» 고 적었다. 이번 함수는 `int` 를 받아 `bool` 을 내므로 정확히 그 조건을 만족한다.

### 2.3 함수 분할

| 함수 | 대상 |
|---|---|
| `tdc_ble_map_field_stimul_para_in_range(field_index, value)` | 하위명령 1 의 12필드 |
| `tdc_ble_map_field_electrode_in_range(value)` | 하위명령 2~7 (전극 · 기준전극 · 밴드순서) |
| `tdc_ble_map_field_level_uA_in_range(value)` | 하위명령 8~15 및 자극 알람 크기 |

첫째만 인덱스를 받는다. 필드마다 범위가 달라 `switch` 가 필요하고, **그 `switch` 가 곧 «저장소 인덱스 = 구조체 필드» 대응표**라 한 곳에 모을 값이 있다.

나머지 둘은 인덱스가 필요 없다 - 같은 범위를 반복 적용할 뿐이다. **과분해 금지** 원칙에 따라 인자를 늘리지 않는다.

## 3. 경계값의 출처

새 값을 만들지 않는다. 기존 값을 옮기되 **1차 정의를 주석으로 남긴다**(`tdc_ble_map_measure.c` 선례).

| 필드 | 범위 | 1차 정의 |
|---|---|---|
| 자극 기법 | 1~3 | - (프로토콜) |
| 선행 펄스 위상 | 0~1 | - |
| 자극 모드 | 1~6 | `EN___STIMULATION_MODE` 에서 `en__referenceNA`(0) 제외 (`tdc_shm.h:67~76`) |
| 펄스 위상 폭 | 13~255 | `FPGA_pulsePhaseWidth_minimum` (`board/FPGA_ver2_7_0.h:133`) |
| 주파수 밴드 수 | 1~32 | **`df_MaxNumOfElectrode`** (`stim/tdc_stim_definitions.h:68`) |
| 알람 채널 | 1~32 | 동 |
| 전극번호 계열 | 1~100 | 99(미사용 센티널) 통과용 여유. 최종 1~32 는 `stim_para_setting.c:492` |
| T·C 레벨 | 0~1800 | 프로토콜 상한 (0x65 파싱과 동일) |

> [!IMPORTANT]
> **`df_MaxNumOfElectrode` 만 매크로로 참조하고 나머지는 값을 둔다.** 두 호출부가 이미 `tdc_stim_definitions.h` 를 include 하므로 **새 의존이 0**이다. `FPGA_ver2_7_0.h` 를 끌어오면 `remote.c` 에 없던 의존이 생기고, 순수 함수 파일이 무거워져 §2.1 조건이 깨진다.

## 4. 루프 가드 대상 전수

`numFrequencyBand` 를 상한으로 쓰는 루프를 전수로 찾았다.

| 위치 | 인덱싱 대상 | 조치 |
|---|---|---|
| `isd/tdc_isd_stim_para_setting.c:465` | `usableStimulationElectrodIndex[32]` · `usableReferenceElectrodIndex[32]` | **가드 추가** |
| `ble/mapping/tdc_ble_cmd_0x66_live.c:698` | `T_level_uA[32]` | **가드 추가** |
| `isd/tdc_isd_stim_para_setting.c:515` | - | **불필요** - 상한이 이미 `df_MaxNumOfElectrode` |

> [!CAUTION]
> **자산_5 를 적용했다.** 「기계 추출은 패턴에 맞는 것만 처리한다」 - `grep "numFrequencyBand"` 전수로 3곳을 찾고 각각 인덱싱 대상을 확인했다. 세 번째는 이미 안전해 건드리지 않는다.

## 5. 매핑 앱 경로 전환의 회귀 위험

공통화는 **동작하는 코드를 건드린다.** 완화는 둘이다.

| 수단 | 내용 |
|---|---|
| 경계값 1:1 대조 | §3 표. 8개 경계를 옮기며 한 칸도 바꾸지 않는다 |
| 호스트 테스트 | `map_flash` 스위트 **75 PASS** 가 회귀를 잡는다 |

**호스트 테스트가 없었다면 공통화 대신 복제(안 가)를 골랐어야 한다.**
