# 요구사항 검증

**TL;DR**: 3축 통과. 다만 **요구사항_2(복제 금지)와 요구사항_5(동작 불변)가 긴장 관계**임을 명시하지 않아 보완했다 — 공통화는 매핑 앱 경로를 건드리므로 회귀 위험이 생긴다. 완화 수단(호스트 테스트 75건)을 근거로 남긴다.

## 축_1 - 지침 준수

| 항목 | 판정 |
|---|---|
| 8단계 | 통과 - ① 요구사항 → ② 이 문서 |
| 작업 폴더 (날짜 + 시각 prefix) | 통과 - `20260806_0942_` |
| 한글 라벨 | 통과 - `요구사항_N`·`제약_N` |
| **코드 전 승인** | **확보** - 2026-08-06 은수님 *"조치해줘"*. 조치안 3종(가/나/다)은 대장 §2.6 에 제시돼 있었다 |
| HW 5게이트 | **해당 없음** - 레지스터·타이밍을 건드리지 않는다. 입력 검증과 루프 상한만 다룬다 |

## 축_2 - 논리 정합성

### 정합_1 - 요구사항_2 와 요구사항_5 의 긴장

> [!WARNING]
> **초안이 놓쳤다.** «복제하지 말라»(요구사항_2)를 지키려면 매핑 앱 경로를 공통 함수로 **바꿔야** 한다. 그런데 요구사항_5 는 그 경로의 동작이 바뀌지 않기를 요구한다. **바꾸면서 안 바뀌어야** 한다.

**해소**: 이 긴장은 «리팩터링» 의 정의 그 자체다. 관건은 **불변임을 무엇으로 입증하는가**이고, 여기서는 근거가 있다.

| 근거 | 값 |
|---|---|
| `map_flash` 호스트 테스트 | **75 PASS** (`run.sh` 의 `TEST_TARGETS[map_flash]`) |
| 경계값 대조 | 옮긴 8개 경계를 1:1 표로 확인 (계획 §3) |

**호스트 테스트가 없었다면 요구사항_2 를 포기하고 복제했어야 한다.** 있으므로 공통화가 정당하다.

### 정합_2 - 요구사항_3(루프 가드)이 요구사항_1 로 충분해지지 않는가

충분해지지 않는다. 입력 검증은 **앞으로 들어올 값**만 막는다.

| 남는 경로 | 이유 |
|---|---|
| 이미 플래시에 기록된 맵 | 이 조치 이전에 리모콘으로 쓴 값이 남아 있을 수 있다 |
| 펌웨어 자체 오류 | `tdc_fs_map.c` 등이 값을 세운다 |
| 미래의 새 쓰기 경로 | 검사를 빠뜨리면 다시 뚫린다 |

**첫째가 실질적이다.** 이 펌웨어를 올리는 기기의 플래시에 이미 이상값이 있으면 입력 검증은 아무것도 못 한다. 루프 가드만이 막는다.

### 정합_3 - 요구사항_4(호스트 검증)가 달성 가능한가

가능하다. 검사 로직은 **정수 하나를 받아 `bool` 을 내는 순수 함수**로 만들 수 있어 `isd/` 의 의존 사슬에 닿지 않는다. `ble/tdc_ble_reply.c` 가 이미 `COMMON_SRC` 에 있는 선례다.
