# 구현 검증

**TL;DR**: 완료 조건 6개 전부 충족. 호스트 **431 → 483 PASS**(신규 52), ARM **에러 0 · 경고 0**, `text` **+428B** · `data`·`bss` **불변**. 계획이 예측한 «수백 바이트» 범위 안이다.

## 1. 완료 조건 대조

| # | 조건 | 결과 |
|---|---|---|
| 1 | 리모콘 0x4D 가 매핑 앱과 같은 필드를 막는다 | **충족** - `dataRangeError` 지점 2 → **12** |
| 2 | 두 경로가 **같은 함수**를 호출한다 | **충족** - `tdc_ble_map_field_*` 3함수 |
| 3 | `numFrequencyBand` 상한 루프 전수 가드 | **충족** - 2곳 (세 번째는 이미 안전) |
| 4 | 호스트 테스트가 경계값을 고정 | **충족** - 신규 **52 케이스** |
| 5 | ARM 에러 0 · 경고 증가 0 | **충족** - `error:` 0건 · `warning:` 0건 |
| 6 | 기존 431건 통과 (무회귀) | **충족** |

## 2. 호스트 테스트

| 스위트 | 이전 | 이후 |
|---|---|---|
| **map_field_range** (신규) | - | **52** |
| map_measure | 125 | 125 |
| map_flash | 75 | **75** |
| map_stim | 174 | 174 |
| remote | 57 | 57 |
| **합계** | **431** | **483** |

> [!IMPORTANT]
> **`map_flash` 75 유지가 이 작업의 핵심 검증이다.** 매핑 앱 경로를 인라인 검사에서 공통 함수 호출로 바꿨는데 결과가 같다 = 경계값이 한 칸도 안 옮겨졌다.

## 3. ARM 빌드

| 항목 | 이전 | 이후 | 판정 |
|---|---|---|---|
| `error:` | 0 | **0** | 통과 |
| `warning:` | 0 | **0** | 통과 |
| `text` | 186,172 | **186,600** | **+428B** |
| `data` | 4,664 | **4,664** | **불변** (계획대로) |
| `bss` | 21,804 | **21,804** | **불변** (계획대로) |

신규 심볼 3개가 링크됐다.

```
0002d8cc T tdc_ble_map_field_stimul_para_in_range
0002d9c8 T tdc_ble_map_field_electrode_in_range
0002d9f2 T tdc_ble_map_field_level_uA_in_range
```

### 3.1 `text` 증가폭이 정합적인가

계획-검증 §정합_3 이 «수백 바이트면 정합, 수 KB 면 무언가 잘못» 이라는 기준을 세웠다. **+428B 는 범위 안이다.**

내역 추정: 신규 함수 3개(`switch` 6분기 + 비교 2개) · 리모콘 검사 12지점 · 루프 가드 2곳이 늘고, 매핑 앱의 인라인 비교 6블록이 호출로 줄었다.

### 3.2 빌드가 bash 에서 깨진 것

Eclipse makefile 의 `-Dchess_storage(a)=` 를 `/usr/bin/sh` 가 파싱하지 못한다. **`make all SHELL=cmd.exe`** 로 통과했다. 다음 세션이 같은 곳에서 막히지 않도록 기록한다.

## 5. 기계 치환의 예외 점검 (자산_5)

치환 스크립트가 건수를 계획과 대조하고 어긋나면 중단하도록 만들었다. 실제 결과다.

| 대상 | 계획 | 실제 |
|---|---|---|
| 리모콘 전극 계열 | 6 | **6** |
| 리모콘 T/C | 2 | **2** |
| 매핑 앱 12필드 `switch` | 1 | **1** |
| 매핑 앱 전극 계열 | 6 | **6** |
| 매핑 앱 T/C | 2 | **2** |
| 매핑 앱 알람 크기 | 1 | **1** |

**전부 일치.** 다만 한 번 실패했다 — 첫 시도에서 치환 블록의 **들여쓰기를 24칸으로 넣어 28칸 문맥과 어긋났다.** 스크립트는 건수만 보고 들여쓰기는 안 봐서 통과시켰고, 눈으로 결과를 확인해 잡았다.

> [!CAUTION]
> **자산_5 의 새 국면이다.** 지금까지는 «패턴에 안 맞는 항목이 빠진다» 였는데, 이번엔 «건수는 맞는데 결과가 어긋났다». **건수 대조는 필요조건일 뿐 결과를 눈으로 봐야 한다.**

## 6. 코드 포맷 조건 적용

[`참고/clang-format/README.md`](../../../참고/clang-format/README.md) 의 수동 7개를 신규 코드에 적용했다.

| 조건 | 적용 |
|---|---|
| 2 - 모든 제어문에 `{}` | 적용 |
| 3 - `case` 를 `{}` 안에, `break` 와 다음 `case` 사이 공백 줄 | **적용** - `tdc_ble_map_field_range.c` 의 `switch` |
| 5 - `{` 다음 빈 줄 없음 | 적용 |
| 7·8 - 주석 형태 | 적용 - 여러 줄은 `/* */`, 중첩 없음 |
| 10·11 - 제어문 앞 공백 줄 | 적용 |

CP949 비호환 문자(`—` `–` `≈` `µ` `►`)는 쓰지 않았다.
