## 자산 (다음 세션이 알아야 할 것)

### 자산_A - ARM 빌드는 `SHELL=cmd.exe` 가 필요하다

Eclipse makefile 의 `-Dchess_storage(a)=` 를 `/usr/bin/sh` 가 파싱하지 못해 bash `make` 는 **전부 실패**한다.

```powershell
$env:PATH = "C:\Program Files (x86)\ON Semiconductor\Ezairo 8300 SDK\arm_tools\bin;" + $env:PATH
Set-Location "...\src\2__cm3\Debug"
make all SHELL=cmd.exe
```

### 자산_B - 자산_5 의 새 국면: 건수는 맞는데 결과가 틀릴 수 있다

치환 스크립트가 «6건 치환» 을 확인하고 통과시켰지만 **들여쓰기가 24칸/28칸으로 어긋났다.** 지금까지 자산_5 는 «패턴에 안 맞는 항목이 빠진다» 였는데 이번은 다르다.

**건수 대조는 필요조건일 뿐이다. 결과를 눈으로 봐야 한다.**

### 자산_C - 신규 소스는 Eclipse 새로고침이 **반드시** 필요하다

`Debug/source/<폴더>/subdir.mk` 는 Eclipse 자동 생성물이고, **`Debug/` 는 `.gitignore` 대상이라 커밋되지 않는다.**

> [!CAUTION]
> **내가 등록한 것은 내 로컬에만 있다.** 은수님 환경에는 신규 소스가 빌드 목록에 없어, 새로고침 없이 빌드하면 `tdc_ble_map_field_*` 3개가 **undefined reference** 로 링크 실패한다.
>
> **Eclipse 에서 프로젝트 우클릭 → Refresh(F5) 후 빌드.**

`src/` 에 신규 `.c` 를 추가할 때마다 해당한다. 앞으로 신규 파일을 만들면 보고에 이 항목을 반드시 넣는다.

### 자산_D - 호스트 게이트를 여는 방법이 실증됐다

[isd 분해 분석](../../isd/20260806_0834_isd-대형함수-분해-분석/분석.md) §6.2 가 «순수 함수를 새 파일로 떼면 `isd/` 의 의존 사슬에 닿지 않아 호스트가 단독 링크한다» 고 예측한 것을 이번에 실행했다. **성립한다.**

`isd/` 를 통째로 호스트에 올리는 대신, **검증하고 싶은 로직만 순수 함수로 떼어내는 것**이 현실적인 경로다.
