# 요구사항 - 맵 쓰기 범위 검사 대칭화

**TL;DR**: 매핑 앱과 리모콘이 **같은 저장소에 맵 데이터를 쓰는데 검사는 한쪽에만 있다.** 특히 `numFrequencyBand` 는 하류에 2차 방어가 없고 루프 상한으로 쓰여 32칸 배열을 넘게 한다. **검사를 양쪽이 공유하게 하고, 배열 접근에는 루프 상한 가드를 함께 건다.**

## 2. 요구사항

### 요구사항_1 - 리모콘 0x4D 에 범위 검사를 넣는다

`tdc_ble_cmd_0x4D_parse_write_mapdata()` 가 `dataRangeError` 를 세우는 것은 `slot_index`·`map_index` 둘뿐이다. 매핑 앱이 검사하는 **모든 필드**를 같이 막는다.

### 요구사항_2 - 검사를 복제하지 않는다

> [!CAUTION]
> **단순 복사는 안 된다.** 이 결함 자체가 «같은 로직이 두 경로에 나뉘어 한쪽만 갱신됐다» 는 구조에서 나왔다. 복제를 늘리면 다음에 또 갈라진다.

### 요구사항_3 - 배열 접근에 루프 상한 이중가드

입력 검증만으로는 부족하다. 이식 문서 §5-7 이 **둘 다** 두라고 한다.

```c
for (i = 0; (i < 앱값) && (i < 배열크기); i++)
```

### 요구사항_4 - 호스트로 검증 가능해야 한다

`isd/` 는 호스트 러너가 컴파일하지 않는다. **검사 로직을 호스트가 링크할 수 있는 자리에 둔다.**

### 요구사항_5 - 매핑 앱 경로의 동작은 바뀌지 않는다

기존 경계값을 한 칸도 옮기지 않는다.

## 3. 범위

| 포함 | 제외 |
|---|---|
| 리모콘 0x4D 하위명령 1~15 검사 | 리모콘 0x4C 슬롯 데이터 (별건) |
| 매핑 앱 경로를 공통 검사로 전환 | 경계값 자체의 재검토 |
| `numFrequencyBand` 를 상한으로 쓰는 루프 가드 | `isd/` 대형 함수 분해 (별 작업) |
| 호스트 테스트 신설 | 실기 (은수님 원격) |

## 4. 제약

| # | 제약 | 출처 |
|---|---|---|
| 제약_1 | 경계값 불변 (요구사항_5) | 회귀 방지 |
| 제약_2 | 새 의존 최소화 | 배터리 상수화 선례 |
| 제약_3 | 코드 포맷은 [`참고/clang-format/README.md`](../../../참고/clang-format/README.md) 조건 11개 | 2026-08-06 은수님 지시 |
| 제약_4 | `.c`/`.h` 주석에 CP949 비호환 문자 금지 | 프로젝트 `CLAUDE.md` |
| 제약_5 | **실기 대기가 6건이 된다** | 대장 §1 알림_2 |

## 5. 완료 조건

- [ ] 리모콘 0x4D 가 매핑 앱과 같은 필드를 막는다
- [ ] 두 경로가 **같은 함수**를 호출한다
- [ ] `numFrequencyBand` 를 상한으로 쓰는 루프 전수에 이중가드
- [ ] 호스트 테스트가 경계값을 고정한다
- [ ] ARM 빌드 에러 0 · **경고 증가 0**
- [ ] 기존 호스트 테스트 431건 전부 통과 (매핑 앱 경로 무회귀)
