# 이력 및 결과 - 이월_F 자극 채널 경계 상수화

**TL;DR**: 라이브(0x66)·특정자극(0x65) 양쪽에 똑같이 박혀 있던 `for (i = 24; i < 32; i++)` 를 `for (i = df_MaxNumTransferableChannel; i < df_MaxNumOfElectrode; i++)` 로 바꿨다. **값은 동일**(24·32)하고 `text`·`data`·`bss` 도 완전 동일하다. 바이트 차이는 `__LINE__` 즉치 하나뿐이며 디스어셈블리로 그 한 곳임을 실증했다.

## 배경

이월_F 는 이월_D(바이폴라 99 방어) 작업의 «분석-검증 결함_1» 에서 등록됐다. 당시 `case 5`(0~23)와 `case 7`(24~31)이 32원소를 빈틈·겹침 없이 덮는다는 것을 **`df_MaxNumTransferableChannel` = 24 를 실측해서** 확인했는데, 정작 코드에는 그 관계가 리터럴로만 있었다.

> `24 + 8 = 32` 라는 관계가 코드 어디에도 적혀 있지 않다. `df_MaxNumTransferableChannel` 이 바뀌면 `case 7` 의 `24` 가 조용히 어긋난다.

## 변경

**양쪽 동시**에 고쳤다. 한쪽만 하면 대칭이 깨져 다음 사람이 두 곳을 비교해야 한다(불가침 «방어 위치 대칭» 과 같은 취지).

| 경로 | 파일 | 위치 |
|---|---|---|
| 특정자극 0x65 | `isd/tdc_isd_map_specific_stim.c` | `case 7` |
| 라이브 0x66 | `isd/tdc_isd_stim_para_setting.c` | `case 10` |

```c
// 시작값이 df_MaxNumTransferableChannel 인 것은 case 5 가 0 ~ (그 값 - 1) 을 이미 채웠기 때문이다.
// 즉 case 5 와 이 루프가 이어 붙어 df_MaxNumOfElectrode 전체를 빈틈·겹침 없이 덮는다.
for (i = df_MaxNumTransferableChannel; i < df_MaxNumOfElectrode; i++)
```

**선행 `case`(0~23)는 이미 `df_MaxNumTransferableChannel` 을 쓰고 있었다.** 즉 절반만 상수화된 상태였고, 이번에 나머지 절반을 맞췄다.

### 바이트 차이가 `__LINE__` 하나뿐임을 실증

주석 2줄을 넣었기 때문에 `tdc_isd_map_specific_stim.c` 의 `__LINE__`(원래 `:440`)이 `:442` 로 밀렸다. 디스어셈블리로 확인했다.

```
   1db88:  f44f 73dd   mov.w  r3, #442  ; 0x1ba
   1db92:  f7f5 fa49   bl     13028 <tdc_sys_error_send_to_app>
```

- 함수: `tdc_isd_map_specific_stim_step`
- `r3` 은 `tdc_sys_error_send_to_app()` 의 **4번째 인자 = `__LINE__`**
- `#442` 는 전체 디스어셈블리에 **정확히 1회**만 등장

`tdc_isd_stim_para_setting.c` 의 `__LINE__` 3건(`:111`·`:132`·`:143`)은 전부 편집 지점(`:597`)보다 **앞**이라 밀리지 않았다.

> [!NOTE]
> **`__LINE__` 이동은 이 프로젝트에서 계약 위반이 아니다.** 단계_4(`20260729_ble-live-state-contract`)가 *"`lineNumber` 는 어떤 설계든 값이 바뀐다 - 계약이 아님"* 을 근거 3건(`stub_ble.h` 명시 · 단계_1b 에서 이미 전량 변경 · 카탈로그도 라인 참조 폐기)으로 확정했다.
>
> 그래서 **주석 2줄을 포기하고 바이트 동일을 지키는 선택은 하지 않았다.** 암묵 관계를 코드에 적는 것이 이 작업의 목적 자체다.

## 판단 기록

### 판단_1 - 불변량을 «바이트 동일» 이 아니라 «크기 동일» 로 잡았다

직전 매크로 상수화 작업은 `.elf` 바이트 동일이 성립했다(주석을 추가하지 않았고 `__LINE__` 이 편집 지점보다 앞이었다). 이번에는 **설명 주석이 산출물의 본질**이라 줄이 늘고, 결과적으로 뒤쪽 `__LINE__` 이 밀린다.

| 선택지 | 판정 |
|---|---|
| 주석 없이 치환만 → 바이트 동일 유지 | **기각.** 리터럴을 상수로 바꾸기만 하면 «왜 그 시작값인가» 는 여전히 안 보인다 |
| **주석 포함 → 크기 동일 + 차이 1곳 실증 (채택)** | 목적 달성. 차이가 `__LINE__` 임을 디스어셈블리로 못 박으면 검증 강도가 실질적으로 유지된다 |

**교훈**: 바이트 동일이 깨질 때는 «깨졌다» 로 끝내지 말고 **깨진 지점을 특정해 설명**해야 한다. 그러면 크기 동일 + 원인 규명이 바이트 동일에 준하는 근거가 된다.

### 잔여

| # | 내용 |
|---|---|
| 잔여_1 | 두 파일의 기존 주석 "24~32번" 은 0-based 인덱스로는 24~31 이다. 값 무변경 원칙상 이번엔 손대지 않았다 |
