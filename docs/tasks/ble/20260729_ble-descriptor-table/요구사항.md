# 요구사항 - BLE 패킷 디스크립터 테이블 (단계_3)

**TL;DR**: `tdc_ble_map_stim_live_all_parameter()` 의 데이터 인덱스 1~15 분기(409줄)를 **디스크립터 테이블 + 단일 순회 루프**로 흡수한다. 동작은 100% 보존한다. 착수 전 은수님이 확정한 3건(**범위=0x66 하위 1 만 · 타입 정합=디스크립터에 필드 폭 명시 · 테스트 선행 추가**)이 요구사항의 골격이다.

## 1. 배경

[`재구조화 설계안.md §3 단계_3`](../../../참고/ble/재구조화/재구조화%20설계안.md) 의 실행이다. 설계 원칙 원칙_2("데이터 인덱스 분기는 제거가 아니라 흡수")를 코드로 구현한다.

단계_1a·1b·2 로 `tdc_ble_mapping.c` 는 2,196 -> 662줄이 됐으나, **분해된 개별 함수 안의 분기 밀도는 그대로다.** 대상 함수가 그 대표다.

| 항목 | 값 | 근거 |
|---|---|---|
| 대상 함수 | `tdc_ble_map_stim_live_all_parameter()` | `tdc_ble_map_stim.c:117~525` |
| 함수 길이 | **409줄** | 동 |
| `tdc_ble_map_stim.c` 전체 | 845줄 | `wc -l` |
| 데이터 인덱스 분기 | `case 1` ~ `case 15` + `default` | `:149~476` (328줄) |
| 범위 검사 대입 | 파일 전체 34건 중 **대상 함수 내 24건** | `awk` 범위 계수 (`case 1` 9건 · `case 2~15`+`default` 15건) |

## 2. 대상 구조 실측

데이터 인덱스는 **3가지 유형**으로 완전히 분류된다. 이 균일성이 테이블 흡수의 근거다.

| 유형 | 인덱스 | 내용 | 필드 폭 | 범위 |
|---|---|---|---|---|
| 유형_A 스칼라 묶음 | 1 | 9개 필드 (볼륨·알림·기법·모드·위상·밴드) | u8 x 8 + **u16 x 1** | 필드마다 다름 |
| 유형_B 배열 청크 (u8) | 2~7 | 3개 배열 x 2청크 (`[0..16]` 17개 · `[17..31]` 15개) | u8 | 전부 1~100 |
| 유형_C 배열 청크 (u16) | 8~15 | 2개 배열 x 4청크 (8개씩) | u16 | 전부 0~1800 |

유형_B 대상 배열: `usableStimulationElectrodIndex` · `usableReferenceElectrodIndex` · `CIS_FreqBandOrder`
유형_C 대상 배열: `T_level_uA` (8~11) · `C_level_uA` (12~15)

> [!NOTE]
> 유형_B·C 가 인덱스 2~15 의 **14개 case 전부**를 차지한다. 코드 줄수는 `:231~475` 의 **245줄** — 함수 409줄의 **59.9%**, `switch` 본문 328줄의 **74.7%** 다(실측). 이 14개 case 는 배열 포인터·시작/끝 인덱스·폭·범위 6개 값만 다르고 **본문 구조가 완전히 동일**하다.

## 3. 요구사항

### 요구사항_1 - 데이터 인덱스 분기의 테이블 흡수

`case 1` ~ `case 15` 의 파싱·범위 검사를 **디스크립터 테이블 선언 + 이를 순회하는 단일 루프**로 대체한다.

- 테이블은 "데이터 인덱스 N 에는 이 필드들이 이 순서·이 폭·이 범위로 온다"를 데이터로 선언한다
- 파싱 코드에서 인덱스별 `case` 분기가 사라진다 (`default` 의 범위 밖 거부는 테이블 조회 실패로 대체)

### 요구사항_2 - 동작 100% 보존

다음이 전부 기존과 **바이트 단위로 동일**해야 한다.

| # | 보존 대상 |
|---|---|
| 보존_1 | 파싱 결과 구조체 `ST__MAPPINGPAYLOAD_LIVE_STIMULATION` 의 전 필드 값 |
| 보존_2 | 범위 검사 판정 결과 (경계값 포함 - `<1`/`>32` 등 각 필드 고유 경계) |
| 보존_3 | 에러 전송 여부·인자 (`en__DATA_Order` · `en__mapping_live_stimulation` · `en__EN__BLE_PROTOCOL_ERROR`) |
| 보존_4 | 데이터 인덱스 연속성 검사와 `seq_index` 갱신·리셋 시점 |
| 보존_5 | 응답 바이트열 (loop-back 3바이트: 명령 · `en__allParameter` · 인덱스 번호) |
| 보존_6 | 인덱스 15 수신 완료 시의 부수 처리 (`audio_input_x_mim/max` 32개 초기화 · `subCommand = en__allParameter` · 로그 문구) |

> [!CAUTION]
> **범위 검사의 "모든 필드를 끝까지 검사한다"는 성질도 보존 대상이다.** 현재 코드는 첫 위반에서 `break` 하지 않고 `dataRangeError = true` 만 세운 뒤 계속 파싱한다. 조기 종료로 바꾸면 **구조체에 남는 값이 달라진다.**

### 요구사항_3 - 타입 정합 (은수님 확정)

디스크립터 엔트리에 **대상 필드의 폭**을 명시하고, 기록 시 그 폭으로 쓴다.

- 근거: [`이력 및 결과.md §발견_1`](이력%20및%20결과.md) - `stimulationMode` 는 `EN___STIMULATION_MODE` 이고 ARM EABI 기본 `-fshort-enums` 로 **1바이트**다(실측 `sizeof`=1). `int *` 로 4바이트를 쓰면 정의되지 않은 동작이다
- **구조체 정의와 공유 메모리 ABI 는 변경하지 않는다** (불가침_3)

### 요구사항_4 - 테스트 선행 확장 (은수님 확정)

리팩토링 **착수 전에** 데이터 인덱스 2~15 의 파싱 테스트를 `tests/unit/test_map_stim.c` 에 추가하고, **기존 코드로 통과시킨다.**

- 근거: 현재 테스트 186 케이스 중 0x66 하위 1 커버는 **데이터 인덱스 1 뿐**이다. 인덱스 2~15 의 14개 case 245줄(함수의 59.9%)이 안전망 밖이다
- 확장 후 테스트는 "기존 코드 통과 -> 테이블 전환 후에도 통과" 라는 **동작 보존의 직접 증거**가 된다

### 요구사항_5 - 프로토콜 문서와의 1:1 대응

테이블 엔트리는 [`명령 카탈로그.md`](../../../참고/ble/프로토콜/명령%20카탈로그.md) 및 0x66 페이로드 정의와 **눈으로 대조 가능한 형태**여야 한다. 각 엔트리에 데이터 인덱스 번호를 주석으로 명시한다.

- 근거: 설계안 §3 "가독성 대응" - 테이블 주도는 흐름 추적이 어려워지므로 문서 대응이 보완책이다

### 요구사항_6 - 불가침 준수

| # | 항목 | 출처 |
|---|---|---|
| 불가침_1 | `tdc_ble_protocol.h` 전체 · 명령 코드 값 · 페이로드 레이아웃 · 응답 바이트 순서 | 설계안 §5 |
| 불가침_2 | `cfx_cm3_sharedMemoryAll` 필드 배치 · `EN___STIMULATION_MODE` 정의 | 동 |
| 불가침_3 | `tdc_ble_reply_*` 의 stateless 계약 (인덱스는 호출자 소유) | 2026-07-28 인수인계 §3 |
| 불가침_4 | `tests/unit/` 의 `src/` 무변경 원칙 - **테스트를 통과시키려고 프로덕션 코드를 고치지 않는다** | 동 |
| 불가침_5 | `prev_subCommandData_Num_index` 접근자 (`tdc_ble_mapping_get/set_seq_index`) | 동 |

## 4. 범위 밖 (은수님 확정)

| # | 제외 항목 | 사유 |
|---|---|---|
| 제외_1 | `tdc_ble_map_flash.c` 의 배열 청크 파싱 (for 루프 16곳) | 청크 폭이 불균일(18/14/12/8)하고 슬롯·맵 인덱스 상태가 얽혀 회귀 원인 규명이 어려움. 되돌릴 수 있는 크기 유지(원칙_6) |
| 제외_2 | 0x66 의 다른 하위 명령 (Start·Stop·볼륨·마이크 감도·알림·이퀄라이저·상태 읽기) | 데이터 인덱스 분기가 없거나 짧아 테이블 실익이 낮음 |
| 제외_3 | 0x65 특정 자극 파싱 | 인덱스 분할이 없는 단일 패킷 |
| 제외_4 | 구조체 필드 타입 변경 | 공유 ABI 저촉 위험 (요구사항_3) |
| 제외_5 | `isd/` 응답 조립 21곳 | 단계_2 부터의 이월_1. 단계_5 이후 재검토 |

## 5. 완료 기준

| # | 기준 | 측정 방법 |
|---|---|---|
| 기준_1 | 확장된 호스트 테스트 전량 통과 | `bash tests/unit/run.sh` - 기존 186 + 신규 케이스 |
| 기준_2 | 신규 테스트가 **전환 전 기존 코드에서도 통과**했음이 기록됨 | 요구사항_4 의 2단계 실행 로그 |
| 기준_3 | ARM 빌드 에러 0 · 경고 0 | CLI 빌드 (`make SHELL=cmd all`) |
| 기준_4 | 파싱 대상 필드·경계 상수 집합이 전환 전후 동일 | 소스 대조표 (경계 상수 전수 열거) |
| 기준_5 | 대상 함수 줄수 유의미 감소 | `wc -l` 및 함수 범위 실측 |
| 기준_6 | 실기 게이트 통과 | 은수님 확인 (라이브 전체 파라미터 15단계 수신 -> 자극 정상) |

> [!IMPORTANT]
> **기준_4 가 "조건 분기 총수 `+0`" 을 대체한다.** 단계_1b·2 에서 쓴 분기 총수 보존 지표는 **이번 단계에 쓸 수 없다.** 테이블 주도 전환은 분기를 루프로 접는 것이 목적이므로 분기 수가 줄어드는 것이 정상이다. 대신 **무엇을 파싱하고 어떤 경계로 검사하는지의 집합**이 불변량이 된다.
