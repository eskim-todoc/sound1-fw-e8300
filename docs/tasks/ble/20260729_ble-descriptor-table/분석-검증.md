# 분석 검증 - BLE 패킷 디스크립터 테이블 (단계_3)

**TL;DR**: 3축 검증 **통과**. 인용 라인 33개를 자동 대조해 **전부 일치**를 확인했다. 다만 **분석이 놓친 사실 1건을 발견**했다 - `default:` 는 죽은 코드가 아니라 **실제 도달 가능한 방어 코드**다(`seq_index` 가 `map_flash` 와 공유되고 flash 는 데이터 인덱스를 **34** 까지 쓴다). 테이블 인덱싱 전 상한 검사가 선택이 아니라 **필수**임이 확정됐다.

## 검증 축 3 - 근거 검증

### 3.1 인용 라인 자동 대조 - 전부 일치

분석 §1.1~1.3 이 인용한 라인을 원본에서 직접 출력해 대조했다.

| 대조 대상 | 건수 | 결과 |
|---|---|---|
| 유형_A 파싱 라인 (`:153`·`:154`·`:155`·`:156`·`:158`·`:160`~`:164`) | 10 | **전부 일치** - 각 라인이 표에 적힌 필드를 정확히 대입 |
| 유형_A 검사 라인 (`:167`·`:174`·`:181`·`:188`·`:195`·`:202`·`:209`·`:216`·`:223`) | 9 | **전부 일치** |
| 유형_B·C 청크 루프 시작 라인과 구간 | 14 | **전부 일치** - `for (i = 0; i < 17)` x3 · `(i = 17; i < 32)` x3 · `(i = 0/8/16/24; i < 8/16/24/32)` x8 |

특히 유형_C 의 구간 `[0..7]`·`[8..15]`·`[16..23]`·`[24..31]` 이 T·C 각각에 대해 정확히 반복됨을 확인했다(`:330`·`:348`·`:366`·`:384` / `:402`·`:420`·`:438`·`:456`).

### 3.2 발견_2 - `default:` 는 도달 가능한 방어 코드다

> [!CAUTION]
> **분석 §3.2 는 데이터 인덱스가 "1~15 로 조밀"하다고만 적었으나, 실제로는 16 이상이 이 함수에 도달할 수 있다.** 테이블 인덱싱 전에 상한을 검사하지 않으면 **`.rodata` 범위 밖을 읽어 임의 오프셋에 쓰기**를 하게 된다.

**기전**: 데이터 인덱스 연속성 카운터가 `map_stim` 전용이 아니라 **`map_flash` 와 공유**된다.

| 사실 | 근거 |
|---|---|
| 카운터는 접근자로 공유되는 단일 상태 | `tdc_ble_mapping.c:35`·`:40` (2026-07-28 세션에서 3그룹 공유로 접근자화) |
| `map_flash` 가 같은 카운터를 설정 | `tdc_ble_map_flash.c:68`·`:280`·`:553` — `set_seq_index(subCommandData_Num_index)` |
| **`map_flash` 의 데이터 인덱스는 34 까지 간다** | `tdc_ble_map_flash.c` 의 `case` 최대값 = **34** |
| `map_stim` 진입 조건은 `idx == seq + 1` | `tdc_ble_map_stim.c:138` |

따라서 flash 명령이 카운터를 15~34 로 올려 둔 상태에서 0x66 하위 1 이 그 다음 번호로 도착하면 **`switch` 에 16~35 가 들어온다.** 현재 코드는 `default:` 가 이를 받아 `dataRangeError = true` 로 처리한다(`:471~475`).

**도달 가능 인덱스 범위: 1~35** (하한은 `idx == 0` 이 `0 != seq+1` 에서 항상 걸러지므로 1).

**조치**: 분석 §5 위험_3 의 대응을 다음으로 확정한다.

```c
/* 테이블 인덱싱 전 - 생략 불가 */
if (subCommandData_Num_index < 1 || Live_AllParameter_payloadNum < subCommandData_Num_index)
{
    dataRangeError = true;   /* 기존 default: 와 동일 동작 */
}
else
{
    /* 테이블 순회 */
}
```

> [!NOTE]
> 이 발견은 2026-07-28 세션의 **불가침 항목("`prev_subCommandData_Num_index` 접근자는 3그룹이 공유한다")이 실제로 어떤 결과를 낳는지**를 구체화한 것이다. 공유 상태는 "파일 경계를 넘기 위한 접근자" 문제로만 기록돼 있었으나, **파싱 유효 범위에까지 영향을 준다.**
