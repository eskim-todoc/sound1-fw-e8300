# 계획 - BLE 패킷 디스크립터 테이블 (단계_3)

**TL;DR**: **4개 커밋**으로 진행한다. 커밋_1 은 **테스트를 먼저 늘려 기존 코드로 통과**시키고(안전망 확보), 커밋_2·3 이 전환, 커밋_4 가 문서다. 디스크립터 23개는 `offsetof`·`sizeof` 매크로로 생성해 **플랫폼별 필드 폭 차이를 컴파일러가 흡수**하게 한다. 테이블 인덱싱 전 **상한 검사는 생략 불가**(발견_2).

## 1. 커밋 분해

> [!IMPORTANT]
> **커밋_1 이 커밋_2 보다 먼저여야 한다.** 신규 테스트가 **기존 코드에서 통과한 사실**이 기록돼야 "전환 후에도 통과 = 동작 보존"이 성립한다(분석 검증_3). 순서를 뒤집으면 테스트가 새 구현에 맞춰 쓰였을 가능성을 배제할 수 없다.

## 2. 확정 자료구조

### 2.1 디스크립터 타입

```c
// 패킷 한 필드(또는 연속 원소 묶음)의 파싱 규칙.
//
// dst_size 는 손으로 적지 않는다. 아래 매크로가 sizeof 로 산출한다.
// EN___STIMULATION_MODE 는 ARM(-fshort-enums 기본)에서 1바이트, 호스트에서 4바이트라
// 상수로 적으면 한쪽에서만 맞는다.
typedef struct
{
    uint16_t dst_offset;  // 페이로드 구조체 기준 바이트 오프셋
    int16_t  min;         // 범위 검사 하한 (이 값 미만이면 에러)
    int16_t  max;         // 범위 검사 상한 (이 값 초과면 에러)
    uint8_t  dst_size;    // 대상 필드 폭 - 1 또는 4
    uint8_t  src_width;   // 패킷에서 읽을 폭 - 1 또는 2 (2는 상위 바이트 먼저)
    uint8_t  count;       // 연속 원소 수 - 스칼라 1, 배열 청크 8/15/17
} tdc_ble_field_desc_t;
```

필드 순서는 2바이트 3개 + 1바이트 3개로 배치해 패딩을 1바이트로 줄였다(총 **10바이트**).

> [!NOTE]
> 타입명 `tdc_ble_field_desc_t` 는 프로젝트에 이미 있는 소문자 `_t` 관행(`tdc_hal_spi_comm_state_t`·`tdc_fs_gain_setting_t`·`tdc_boot_status_t`)을 따른다. `tdc_` 접두어 규칙도 충족한다.

## 3. 순회 함수

```c
// 디스크립터 목록대로 패킷을 파싱해 dst_base 에 적재한다.
//
// 범위를 벗어난 값도 일단 적재한다(기존 동작). 위반이 있어도 중단하지 않고
// 끝까지 돌며 플래그만 세운다 - 조기 종료하면 구조체 잔류값이 달라진다.
//
// 반환: 범위 위반이 하나라도 있으면 true
static bool tdc_ble_desc_parse(void                       *dst_base,
                               const tdc_ble_field_desc_t *desc,
                               int                         desc_count,
                               const uint8_t              *packet,
                               int                         index)
{
    bool rangeError = false;
    int  d;
    int  e;

    for (d = 0; d < desc_count; d++)
    {
        const tdc_ble_field_desc_t *f = &desc[d];

        for (e = 0; e < f->count; e++)
        {
            int      value;
            uint8_t *dst = (uint8_t *) dst_base + f->dst_offset + (e * f->dst_size);

            if (f->src_width == 2)
            {
                value = packet[index++] << 8;
                value = value | packet[index++];
            }
            else
            {
                value = packet[index++];
            }

            if (f->dst_size == 1)
            {
                *dst = (uint8_t) value;
            }
            else
            {
                *(int *) dst = value;
            }

            if ((value < f->min) || (f->max < value))
            {
                rangeError = true;
            }
        }
    }

    return rangeError;
}
```

### 3.1 범위 검사 등가성 논증

기존 코드는 **구조체에 적재한 뒤 그 필드를 읽어** 검사한다. 신규는 **읽은 값으로** 검사한다. 두 방식이 등가임을 확인했다.

| 대상 | 근거 |
|---|---|
| `int` 필드 (22개 엔트리) | 적재 후 읽어도 값이 그대로다. 자명하게 등가 |
| `stimulationMode` (1바이트 enum) | `src_width`=1 이라 값이 0~255, 필드도 1바이트라 **절단이 없다.** 또한 `EN___STIMULATION_MODE` 는 **unsigned** 임을 실측 확인 (`(EN___STIMULATION_MODE)200 == 200` 이 컴파일 타임에 참) -> 적재 후 읽어도 0~255 그대로 |

> [!NOTE]
> **실측 명령**: 프로젝트 헤더를 ARM 툴체인으로 컴파일해 `((int)(EN___STIMULATION_MODE)200 == 200)` 을 배열 크기로 판정. 결과 참. 따라서 부호 확장으로 인한 판정 차이가 발생하지 않는다.

### 7.1 경계 상수 다중집합 비교 방법

전환 전 `git show` 로 원본을 꺼내 범위 검사 상수를 전수 추출하고, 전환 후 테이블의 `min`/`max` 를 추출해 정렬 비교한다. 예상 다중집합은 다음과 같다(분석 §1 기준).

| 상수 | 등장 횟수 |
|---|---|
| `1`(하한) | 자극볼륨·오디오볼륨·알림채널·기법·모드·밴드 + 유형_B 6개 = 12 |
| `0`(하한) | 알림크기·선행위상 + 유형_C 8개 = 10 |
| `13`(하한) | 1 |
| `4`·`10`·`3`·`6`·`1`(상한) | 각 1 |
| `32`(상한) | 알림채널·밴드 = 2 |

# 13. 재설계 (2026-07-29, 1차 구현 후)

> [!IMPORTANT]
> **§1~11 의 디스크립터 테이블 설계는 구현 후 은수님 검토에서 기각됐다.** 커밋 `516861b`·`d6da48d` 는 `05c3a81` 로 되돌렸다. 아래가 확정 설계다.

## 13.1 무엇이 문제였나

지표는 좋았다(`text` -1,276B, 대상 함수 409 -> 101줄). 그러나 **읽는 사람 기준으로 나쁜 코드**였다.

```c
TDC_BLE_DESC_ARRAY(usableStimulationElectrodIndex, 0, 17, 1, 1, 100)
```

숫자 다섯 개가 나열돼 있고 각각이 시작 첨자인지 개수인지 폭인지 범위인지 알려면 **매크로 정의를 찾아가 봐야 한다.**

구조적으로도 **이중 관리**였다. 필드 23개가 평면 배열이고 슬롯이 `{first, count}` 로 구간을 가리켜서, 인덱스 1 에 필드 하나만 추가해도

| 고칠 곳 | 내용 |
|---|---|
| `s_live_all_param_fields` | 엔트리 1줄 삽입 |
| `s_live_all_param_slots` | **뒤따르는 14줄의 `first` 가 전부 +1 씩 밀림** |
| `_Static_assert` | `== 23` -> `== 24` 수동 수정 |

**"그 자리만 찾아가서 바꾸면 되는" 구조가 아니었다.**

## 13.2 확정 설계 - 프로토콜 계층을 이름에 드러낸다

은수님 제안. 명령별 · 하위 옵션별로 자리를 정해 두면 프로토콜이 바뀔 때 그 자리만 찾아가면 된다.

| 계층 | 이름 규칙 | 예 |
|---|---|---|
| 명령 | `tdc_ble_cmd_0xNN_<이름>` | `tdc_ble_cmd_0x66_live` |
| 하위 명령 | `tdc_ble_cmd_0xNN_subMM_<이름>` | `tdc_ble_cmd_0x66_sub03_volume_adjust` |
| 데이터 인덱스 | `tdc_ble_cmd_0xNN_subMM_idxKK_<이름>` | `tdc_ble_cmd_0x66_sub01_idx02_stim_electrode_0_16` |

파일도 명령 단위로 나눈다 - `tdc_ble_cmd_0x66_live.c/.h`.

**본문은 원본 `for` 루프를 그대로 둔다.** 헬퍼로 위임해 인자를 숫자로 넘기면 다시 "숫자 나열을 해독해야 하는" 코드가 된다. 숫자가 문맥 안에 있어야 한다.

`p_mappingPacket->tdc_isd_map_live_step.` 이 반복되던 자리는 `live->` 로 줄여 각 줄이 무엇을 읽는지가 앞에 오게 한다.

### 이 설계가 새 구조가 아닌 이유

0x66 의 하위 명령 8개는 **2026-07-28 단계_1b 에서 이미 함수로 분리돼 있었다.**

| 하위 명령 | 분리 전 |
|---|---|
| 2 Start · 7 상태읽기 · 8 Stop | 각 6줄 |
| 3 볼륨 · 4 마이크 | 31 · 28줄 |
| 5 알림 · 6 이퀄라이저 | 89 · 54줄 |
| **1 전체 파라미터** | **409줄** |

**하위 1 만 비대칭으로 남아 15갈래를 안에 품고 있었다.** 이번 작업은 같은 원칙을 한 계층 더 내린 것이다.

## 13.3 적용 범위 (은수님 확정)

**0x66 먼저 시범 후 확대.** 0x65 는 `tdc_ble_map_stim.c` 에 남겨 두고 확대 단계에서 옮긴다.

## 13.4 검증 방법 변경

테이블 설계에서 쓰려던 `.rodata` 덤프 대조는 해당 없다. 대신 **함수 추출 리팩토링의 표준 지표**를 쓴다.

| # | 검증 | 근거 |
|---|---|---|
| 재검증_1 | **조건 분기 총수 보존** (`if`·`else`·`for`·`case`·`switch`·에러 대입) | 함수 추출은 분기를 만들지도 없애지도 않는다. 2026-07-28 단계_1b 에서 확립한 지표 |
| 재검증_2 | **범위 검사 상수 다중집합 일치** | 파싱 규칙 불변 |
| 재검증_3 | 호스트 테스트 275 PASS | 커밋_1 의 안전망 |
| 재검증_4 | ARM 빌드 에러 0 · 경고 0 | |
| 재검증_5 | 실기 게이트 | 은수님 |

크기는 **증가를 예상**한다. 함수 15개 분리는 `-O0` 에서 호출 오버헤드를 그대로 더한다. 지표가 아니라 기록 대상이다.
