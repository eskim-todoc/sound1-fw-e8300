### 보완 지시_1 - 요구사항_5 의 완료 기준 누락

요구사항_5 는 "테이블 엔트리를 `명령 카탈로그.md` 와 대조 가능하게" 요구하나, §5 완료 기준 기준_1~6 중 이를 측정하는 항목이 없다. **단계 ⑤ 계획에서 검증 가능한 형태로 구체화**할 것 (예: 테이블 엔트리 수 = 데이터 인덱스 수 x 필드 수 대조표를 산출물로 남긴다).

## 검증 축 3 - 근거 검증

### 3.1 정정한 오류

> [!CAUTION]
> **초안의 수치 인용 2건이 실측과 달랐다.** 둘 다 검증 없이 눈대중으로 적은 값이다. 2026-07-28 세션의 노하우_5("설계안과 자기 분석을 모두 의심한다")가 다시 적중했다.

| # | 초안 서술 | 실측 | 조치 |
|---|---|---|---|
| 오류_1 | 대상 함수 내 범위 검사 대입 **23건** | **24건** (`case 1` 9 + `case 2~15`·`default` 15) | 정정 완료 |
| 오류_2 | 인덱스 2~15 가 "409줄 중 약 340줄(**83%**)" | **245줄** = 함수의 **59.9%**, `switch` 본문의 **74.7%** | 정정 완료 |

**오류_2 의 원인**: `switch` 본문 대비 비중과 함수 전체 대비 비중을 혼동했다. 함수에는 `switch` 밖의 전처리(`:119~148`)와 후처리(`:478~524`)가 **81줄** 있는데 이를 빼지 않고 어림했다.

**영향 평가**: 요구사항의 **결론은 바뀌지 않는다.** 인덱스 2~15 는 여전히 테스트 커버리지가 0 이고 14개 case 245줄이며, 테이블 흡수 대상으로서의 균일성 판단도 그대로다. 다만 은수님께 질문할 때 "83%" 로 말씀드렸으므로 **정정 보고 대상**이다.

### 3.3 패킷 폭 정합 교차 검증

각 데이터 인덱스가 `BLE_DataPacketSize`(20) 를 넘지 않는지 확인했다. 페이로드는 인덱스 3 부터 시작한다(0=명령, 1=하위명령, 2=데이터 인덱스).

| 유형 | 최대 소비 | 종료 위치 | 판정 |
|---|---|---|---|
| 유형_A (`case 1`) | 10바이트 (u8 x 8 + u16 x 1) | 3+10 = 13 | 여유 |
| 유형_B 17개 청크 | 17바이트 | 3+17 = **20** | 경계 정확히 사용 |
| 유형_B 15개 청크 | 15바이트 | 3+15 = 18 | 여유 |
| 유형_C 8개 청크 | 16바이트 | 3+16 = 19 | 여유 |

> [!IMPORTANT]
> **유형_B 의 17개 청크가 20바이트 경계를 정확히 채운다.** 테이블 순회 루프가 오프셋을 하나라도 잘못 계산하면 즉시 버퍼 경계를 넘는다. 단계 ③ 분석에서 인덱스 산술의 상한을 명시하고, 단계 ⑤ 계획에 경계 검사 또는 컴파일 타임 단언을 넣을지 결정할 것.

### 3.4 부수 발견 - 명령 카탈로그의 라인 참조가 stale

[`명령 카탈로그.md:78`](../../../참고/ble/프로토콜/명령%20카탈로그.md) 의 0x66 항목은 `tdc_ble_mapping.c:309`·`:1953`·범위검사 9곳(`:331,355,694,763,791,815,864,904,912`) 을 가리키나, 이는 **단계_1a·1b 이전(2,196줄 시절)의 라인이다.** 현재 해당 코드는 `tdc_ble_map_stim.c` 로 이동했다.

요구사항_5 가 이 문서와의 1:1 대응을 요구하므로 **단계 ⑦ 구현 시 카탈로그의 라인 참조도 함께 갱신**해야 한다. 작업 범위에 포함할지는 단계 ⑤ 계획에서 결정한다.
