### 2.3 반증 시도

분석의 주요 결론을 스스로 반박해 봤다.

| # | 반증 시도 | 결과 |
|---|---|---|
| 반증_1 | "함수 분해 부재가 근인_1 인데, 함수를 쪼개면 정말 나아지는가? 데이터 인덱스 분기는 그대로 남는다" | **부분 성립.** 함수 분해는 가독성을 올리지만 분기 총량은 그대로다. 다만 근인_1 의 주장은 "분기가 사라진다"가 아니라 "1,724줄 단일 함수가 이해·수정·검증을 불가능하게 만든다"이므로 유효. ⑤ 계획에서 **분해만으로는 부족하고 테이블화가 필요**함을 명시할 것 |
| 반증_2 | "상태 4층이 정말 문제인가? 층이 나뉜 것 자체는 정상 설계일 수 있다" | **성립하지 않음.** 문제는 층의 존재가 아니라 **층간 관계가 코드 어디에도 명시돼 있지 않다**는 점이다. §5.1 이 이를 기술하고 있으나 표현이 약해 정정_3 으로 보강 |

## 축_3 - 근거 검증

### 3.1 근거 등급 오표기 (중요)

§1 에서 내가 정의한 등급 규칙은 다음과 같다.
- `확정` = 노드 2개 이상 독립 도달 **또는** 오케스트레이터 재검증 완료
- `채택` = 단일 노드 발견이나 근거 라인 명시
- `미확인` = 근거 미확보

이 규칙에 비추어 분석.md 를 점검한 결과 **오표기 3건**을 발견했다.

| # | 위치 | 표기 | 실제 | 조치 |
|---|---|---|---|---|
| 오표기_1 | §4.1 정량 검증 표 (58.6% · 48.1%) | "확정" | **노드 03 단독 산출**. 교차 확인도 재검증도 없음 | `채택(노드 03)` 으로 강등 |
| 오표기_2 | §4.2 보조_1 순환 복잡도 227 | "확정" 표 안에 배치 | 노드 03 단독 + **본인이 "도구 미검증 추정치"라 명시** | `추정(노드 03)` 으로 강등 |
| 오표기_3 | §6.1 모듈별 호출 수 (sys 57 등) | 등급 미표기 | 노드 07 단독 | `채택(노드 07)` 명시 |

> [!CAUTION]
> **58.6% 는 이 분석의 핵심 수치**(은수님 가설 검증의 근거)인데 단일 노드 산출이다. 결론 자체를 뒤집을 정도는 아니다 - `fetch_packet` 1,724줄 중 데이터 인덱스 분기가 지배적이라는 정성적 사실은 오케스트레이터도 코드에서 직접 확인했다. 다만 **소수점 한 자리까지 제시된 수치의 정밀도는 보증되지 않는다.** ⑤ 계획에서 이 수치에 의존하는 결정을 내리지 않도록 한다.

### 3.3 미확인 사항의 정직성 점검

§9 에 6건을 `미확인` 으로 명시했다. 추측을 사실로 포장한 곳이 있는지 재점검한 결과 **발견되지 않았다.** 특히 결함_4 의 위험 창 길이, 결함_9 의 하드폴트 실제 발생 여부를 단정하지 않은 것은 적절하다.
