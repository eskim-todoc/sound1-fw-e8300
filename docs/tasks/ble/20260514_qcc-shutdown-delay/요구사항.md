# QCC OTA 후 셧다운 진입 딜레이 — 요구사항 (Rev.1)

**TL;DR**: BLE 의 **OTA DFU 기능으로 펌웨어 업데이트 후 Ezairo(CFX) 를 재부팅하기 전에 QCC 를 절전 모드로 진입 시킨 후 재부팅**하기 위한 변경. `ci_ble_control_boot.c` 의 `_fetch_packet_boot_select()` 함수 (부팅 슬롯 선택 패킷 처리·재부팅 트리거) 에서 응답 패킷 송신 후 → 20 ms 대기 → `snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN)` 호출 → 2.2 초 (2200×1 ms, 워치독 리프레시 포함) 대기 → `SYS_WATCHDOG_RESET()` 재부팅. 사용자(다) 본인 작업분, 본 task = 변경 의미 정리 + 코드 commit.

## 1. 배경

- **트리거**: [`signalProcessing/20260514_nofm-merge`](../../signalProcessing/20260514_nofm-merge/) 분석 ([`분석.md §6.1`](../../signalProcessing/20260514_nofm-merge/분석.md)) 에서 다니엘 작성 NofM 코드와 함께 묶여 있던 CM3 측 변경 1 건 (`ci_ble_control_boot.c`) 이 NofM 무관임을 분별 → 사용자(다) 명시 별도 task 분리.
- **사용자(다) 명시 설명**: "ble의 OTA DFU 기능으로 펌웨어 업데이트 후 Ezairo를 재부팅 하기 전에 QCC를 절전 모드로 진입 시킨 후 재부팅하기 위한 내용이야. 이대로 내가 한 작업 상황을 정리하라는 거야".
- **변경 사이즈**: +15/-15. `ci_ble_control_boot.c` 의 `_fetch_packet_boot_select()` 함수 내부 (응답 송신 직후 ~ 재부팅 직전 시퀀스).

## 2. 목적·범위

### 2.1 대상

- **파일**: `src/2__cm3/Cortex-M3-src/BleCommunication/ci_ble_control_boot.c`
- **함수**: `_fetch_packet_boot_select()` — OTA DFU 후 부팅 슬롯 선택 패킷 (BLE) 을 받아 boot status 갱신 + 응답 송신 + 재부팅.
- **신규 의존**: `<snd_qcc.h>` (QCC 칩 제어 API 헤더, `snd_qcc_set_mode` / `SND_QCC_MODE_SHUTDOWN`).

### 2.2 변경 본질

OTA DFU 흐름의 마지막 단계 (펌웨어 업데이트 완료 → 부팅 슬롯 선택 → Ezairo 재부팅) 직전에 **QCC 절전 모드 진입 시퀀스 삽입**:

1. 응답 패킷 송신 후 20 ms 대기 (워치독 리프레시) — 응답 송신 완료 시간 확보.
2. `snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN)` 호출 — QCC_CTRL 핀 0 유지로 QCC 절전 진입.
3. 2.2 초 (2200×1 ms, 워치독 리프레시 매회) 대기 — QCC 가 안정적으로 절전 진입할 시간 (코드 주석: "2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다").
4. `SYS_WATCHDOG_RESET()` — Ezairo 재부팅.

### 2.3 모듈 분류

`ble` (BleCommunication/ 하위, OTA DFU 흐름).
