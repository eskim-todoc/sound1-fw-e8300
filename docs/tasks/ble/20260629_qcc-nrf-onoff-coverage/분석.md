# 분석 — QCC가 NRF_On_OFF 역할을 전부 커버하는가

**TL;DR**: NRF_On_OFF()의 5개 BLE off 조건 중 QCC는 covered 1·partial 2·uncovered 1·정책반전 1. 그러나 **NRF 출력부 자체가 이미 死코드**였으므로 이 전환은 기능 이전이 아닌 **아키텍처 패러다임 교체**(CM3 중앙 결정 → QCC 자율 판단). 실질 gap은 **조건_4(Mapping_BLE_Off 매핑 일시 off)** 단 1건 — QCC로 전달할 경로가 소스 전체에 없음. 다페르소나 8노드(분석5·통합1·검증2), 할루시네이션 0건, 반증 생존.

---

## 1. 결론 먼저

> [!IMPORTANT]
> **판정: `architecture_shift` (아키텍처 패러다임 교체)** — "전부 커버"도 "전혀 커버 못함"도 아니다.
>
> 1. NRF 시대에도 BLE 출력은 이미 **死코드**였다 (실제 제어 안 됨).
> 2. QCC 전환은 결정 주체를 **E8300(CM3) → QCC 내부 펌웨어**로 옮긴 구조 변화다.
> 3. 단 하나의 실질 미구현 gap = **조건_4 (Mapping_BLE_Off)**.

### 핵심 사실 (검증 confirmed)

- `NRF_Off_Command()`·`NRF_On_Command()` 본문의 GPIO 구문이 **전부 주석 처리**되어 있다 (systemControl.c:37~45). 게다가 `NRF_On_OFF()` 말미의 호출부(:104, :108)도 주석. → NRF 시대에도 BLE를 실제로 켜고 끈 적이 없는 **완전 死코드**.
- `NRF_On_OFF()`는 main.c:660에서 매 cycle 호출되어 조건 연산은 수행하지만, 결과(`BLE_OFF` 플래그)가 하드웨어에 반영되지 않는다.
- QCC 측 `snd_qcc_set_isd`/`set_mode`는 **결정 로직 없는 단순 GPIO 출력**이다 (snd_qcc.c:21~91). 두 핀만 조작: `ISD_CHECK`(DIO13), `QCC_CTRL`(DIO24).

## 3. 조건별 커버리지 표 (최종)

| NRF 조건 | 원래 로직 | QCC 대응 경로 | 판정 |
|---|---|---|---|
| **조건_1** 연결 이력 후 끊김 0.6초(640 tick) → off | systemControl.c:64~73 | isd_interface.c:255/268 → `set_isd(DISCONNECTED)` 즉시 (지연 없음) | 🟡 **partial** |
| **조건_2** ISD 미연결 초기 → off | systemControl.c:79~82 | `snd_qcc_init()`:17 ISD_CHECK=LOW + isd_interface.c:268 매 cycle DISCONNECTED | 🟢 **covered** |
| **조건_3** mappingConnection → 강제 유지(on) | systemControl.c:85~88 (ISD 무관) | isd_interface.c:245~255: mappingConnection이어도 ISD<10V면 DISCONNECTED | 🟡 **partial** |
| **조건_4** Mapping_BLE_Off → 일시 off | systemControl.c:91~94 | **없음** — BLE_Off_Command가 QCC 함수 어디에도 연결 안 됨 | 🔴 **uncovered** |
| **조건_5** global_BLE_Off(충전기) → off | systemControl.c:97~100, :165 | main.c:800 SHUTDOWN 의도적 주석, 충전 중 QCC NORMAL 유지 | 🔵 **정책 반전** |

### 판정 근거 상세

- **조건_1 (partial)**: ISD 끊김 이벤트는 `set_isd(DISCONNECTED)`로 전달되나, E8300 레벨의 0.6초 지연이 사라졌다. QCC 펌웨어 내부 debounce 여부는 소스가 없어 단정 불가(추정).
- **조건_2 (covered)**: 부팅 초기(init)·런타임 미연결 모두 DISCONNECTED를 확실히 전달. isd_interface.c:260이 매 cycle `stimulationParameterSettingIsDone`을 평가해 미완료 시 :268 DISCONNECTED를 보내므로 동적 미연결도 커버 (노드 02의 partial 주장은 재확인 결과 기각).
- **조건_3 (partial)**: NRF는 mappingConnection 단독으로 BLE 강제 유지(ISD 무관). QCC는 mappingConnection **+ ISD≥10V_Ok 이중 조건**. 매핑 중 ISD가 일시 10V 미달이면 동작이 갈린다 (반증 confirmed).
- **조건_4 (uncovered)** ⚠️ **유일한 실질 gap**: `BLE_Off_Command`는 ble_communication.c:433~452에서 세팅되지만, main.c:660의 `NRF_On_OFF`(死코드)로만 전달되고 `set_isd`/`set_mode` 어떤 호출처에도 입력되지 않는다 (grep 전수 확인). "매핑 앱 최초 내부기 이름 설정 시 BLE 일시 off" 시나리오가 QCC에서 어떻게 처리되는지 **확인 필요**.
- **조건_5 (정책 반전)**: "충전 시 BLE off"가 **의도적으로 뒤집혀** "충전 중 QCC NORMAL 유지 → BLE SPI 패킷으로 뚜껑 열림 감지"로 바뀜 (main.c:799~800 주석, :823~824 충전 루프 내 `bleCommunication()`). 미커버가 아니라 **요구사항 변경**.

## 4. NRF에 없던 QCC 고유 동작 (신규)

| 동작 | QCC 경로 | NRF 대응 |
|---|---|---|
| 절전 진입 시 BLE off | main.c:871 `set_mode(SHUTDOWN)` (live) | NRF_Off_Command 死코드 — 실효 없었음 |
| OTA 재부팅 시 BLE off + 2.2초 대기 | ci_ble_control_boot.c:117~123 (2초+ QCC 전원 차단 필수) | 해당 타이밍 요건 없었음 |
| 크래들 뚜껑 열림 후 재부팅 전 off | main.c:829 `set_mode(SHUTDOWN)` | 없음 |

## 5. 검증 결과 (adversarial)

- **할루시네이션 검증(07)**: 통합 평결의 22개 인용 라인 전수 직접 Read/grep 대조 → 분석 시점 기준 **할루시네이션 0건**(잘못 귀속·존재하지 않는 인용 없음).
- **단계_4 후속 정정**: resume 전후 `isd_interface.c`가 외부 편집되어 라인이 2~5줄 시프트됨(분석 당시 `:248/253/261/266` → 현재 `:250/255/263/268`, set_isd 호출 기준). 본 최종본은 **현재 파일 기준으로 정정 완료**(조건_1·2·3). 코드 의미·평결은 불변.
- **반증(08)**: 8개 공격 축 결과
  - refuted(평결 방어 성공): 死코드 무의미론, QCC 실효 없음론, SHUTDOWN=광고off 동치론, 조건_5 미커버론, "전부 커버"·"전혀 커버 못함" 양극단.
  - confirmed(gap 실재): 조건_3 mappingConnection override 부재, 조건_4 Mapping_BLE_Off 경로 부재.

> [!NOTE]
> **set_mode(SHUTDOWN) ≠ NRF 광고 off** (반증 (b)): NRF는 "BLE 광고 일시 정지(재부팅 없음)", QCC는 "칩 전원 완전 차단 + 재부팅 시퀀스"(ci_ble_control_boot.c:119~123). 같은 수준의 off가 아니다.

## 6. 발견된 정리 대상 (부수)

- `systemControl.c:35` `#define BLE_OffTimeAfterISD_Disconnected 1000` 매크로가 **미사용 dead macro** — NRF_On_OFF는 리터럴 `640`을 사용(:66). (본 분석 무관, 정리 권고)
- main.c:508 `snd_qcc_set_isd(CONNECTED)`는 `#if 1 … #else` 구조의 **死코드** 블록(전처리 제외). 실 호출은 isd_interface.c 4곳.
