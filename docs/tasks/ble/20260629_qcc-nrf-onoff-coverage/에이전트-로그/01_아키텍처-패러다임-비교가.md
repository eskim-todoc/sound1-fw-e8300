# 아키텍처 패러다임 비교가

**TL;DR**: NRF 시대는 E8300(CM3)이 5개 조건을 평가해 BLE on/off를 직접 명령하는 "중앙집중형 BLE 결정자" 구조였다. QCC 시대는 E8300이 ISD 상태·전원 모드 두 핀만 보내고, BLE 광고 판단은 QCC 펌웨어가 자율 결정하는 "결정 위임형" 구조로 전환되었다. 두 아키텍처는 명령 방식·책임 주체·제어 의미 모두 본질적으로 다르다.

---

## 1. NRF 시대 — E8300이 BLE 결정 두뇌

### 1.1 구조 요약

`systemControl/systemControl.c:50~110` `NRF_On_OFF()` 함수가 5개 조건을 순차 평가해 `BLE_OFF` 불리언을 산출한 뒤, `NRF_Off_Command()` / `NRF_On_Command()`로 NRF 모듈에 명령.

```
E8300 CM3
  ├─ isd_state        ─┐
  ├─ global_BLE_Off   ─┤  NRF_On_OFF()  →  NRF_Off_Command() / NRF_On_Command()
  ├─ mappingConnection─┤  (결정 로직 전부 E8300 내)    │
  └─ Mapping_BLE_Off  ─┘                              ↓
                                                NRF 모듈 (BLE 광고 on/off)
```

### 1.2 5개 결정 조건 (systemControl.c:55~109)

| 조건 번호 | 내용 | 코드 |
|-----------|------|------|
| 조건_1 | ISD 연결 이력 있고 끊어진 후 640 tick(≈0.6초) 경과 → BLE_OFF=true | :64~72 |
| 조건_2 | ISD 연결 이력 없음(초기 또는 충분히 끊어진 후) → BLE_OFF=true | :79~82 |
| 조건_3 | mappingConnection=true → BLE_OFF=false (강제 유지, 상위 조건 덮어씀) | :85~88 |
| 조건_4 | Mapping_BLE_Off=true → BLE_OFF=true (매핑 일시 BLE 끄기, 조건_3 이후 적용) | :91~94 |
| 조건_5 | global_BLE_Off=true → BLE_OFF=true (충전기 연결 시 — systemControl.c:165) | :97~100 |

### 1.3 실효성 (사실)

`NRF_Off_Command()` (systemControl.c:37~40)와 `NRF_On_Command()` (:42~44) 양쪽 모두 내부 GPIO 구문이 주석 처리 → **이미 死코드**. 결정 로직은 실행되지만 출력 명령이 없어 NRF 모듈에 실제로 아무 신호도 가지 않는다.

## 2. QCC 시대 — 결정 위임형, E8300은 상태 보고자

### 2.1 구조 요약

```
E8300 CM3
  ├─ ISD_CHECK (DIO13) ─── snd_qcc_set_isd()  ─→  QCC 핀 입력
  └─ QCC_CTRL  (DIO24) ─── snd_qcc_set_mode() ─→  QCC 핀 입력
                                                        │
                                                  QCC 펌웨어가
                                                  BLE 광고 여부 자율 결정
```

E8300은 두 가지 상태만 GPIO로 전달한다. BLE 광고 on/off 결정 자체는 QCC 내부 펌웨어 소관.

### 2.2 ISD_CHECK 핀 (DIO13) — "ISD가 준비되었는가"

| 값 | 의미 | 설정처 |
|----|------|--------|
| HIGH (CONNECTED) | ISD 연결 완료 + 자극 파라미터 설정 완료 | isd_interface.c:248 (매핑 경로), :261 (standalone 경로), main.c:508 (디버그 강제) |
| LOW (DISCONNECTED) | ISD 미연결 또는 파라미터 미완료 | isd_interface.c:253, :266, snd_qcc_init()(:17) |

- snd_qcc.c:41~54: CONNECTED/DISCONNECTED 외 나머지 상태는 전부 LOW로 처리 ("확실한 연결 상태가 아니면 사실상 의미 없음" 주석).

### 2.3 QCC_CTRL 핀 (DIO24) — "전원 모드"

| 값 | 의미 | 설정처 |
|----|------|--------|
| HIGH (NORMAL) | QCC 정상 동작 허용 | initialize.c:511 (부팅 완료 후) |
| LOW (SHUTDOWN) | QCC 전원 차단 | main.c:829 (충전 중 뚜껑 열림), main.c:871 (절전), ci_ble_control_boot.c:117 (OTA 후 재부팅) |

- ci_ble_control_boot.c:116 주석 확인: "2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다" → SHUTDOWN은 BLE 광고 중지가 아닌 **모듈 전원 차단**.
- main.c:800은 **주석 처리**된 SHUTDOWN 호출. 주석 내용: "충전기 연결 시 QCC는 절전 미진입, SPI 패킷 수신 유지" → 충전 중 QCC는 **의도적으로 NORMAL 유지** (뚜껑 열림 BLE 패킷 감지 목적).

## 3. 핵심 패러다임 차이

### 3.1 결정 주체 이전

| 항목 | NRF 시대 | QCC 시대 |
|------|----------|----------|
| BLE 광고 결정 주체 | E8300 CM3 (`NRF_On_OFF` 로직) | QCC 내부 펌웨어 |
| E8300 역할 | 5개 조건 평가 + 명령 발행 | 상태 신호(ISD/전원) 2종 전달만 |
| 명령 방식 | 직접 GPIO on/off 명령 (NRF_On/Off_Command) | 상태 힌트 GPIO 2핀 (ISD_CHECK, QCC_CTRL) |
| 제어 단위 | "BLE 광고 on/off" | "ISD 연결 여부" + "전원 허용 여부" |

### 3.2 "BLE 광고만 off" vs "QCC 전원 자체 off"

- NRF 의도: `NRF_Off_Command()`는 NRF 모듈이 살아있는 상태에서 BLE 광고만 중단시키는 명령이었을 것 (핀 이름 `DIO_NUM_NRF_ON_OFF_COMMAND`).
- QCC SHUTDOWN: 모듈 자체 전원 차단 (2초 LOW 유지 필요). BLE 광고 off보다 훨씬 큰 단위.
- **의미가 다르다**: NRF off = 광고 중단, QCC SHUTDOWN = 모듈 전원 off.

### 3.3 ISD_CHECK 핀의 역할 (추정 포함)

ISD_CHECK는 QCC에 "지금 내부기(ISD)가 연결되어 있음/없음"을 알리는 힌트 핀이다. QCC 펌웨어가 이 신호를 읽고 BLE 광고 정책(예: ISD 연결 시 광고 중단, 미연결 시 광고 재개)을 내부적으로 결정하는 것으로 추정된다. 단, **QCC 내부 펌웨어 소스가 없으므로 단정 불가** — 핀 의미상 추정.

## 4. NRF 5개 조건 → QCC 커버리지 매핑

| 조건 | NRF 동작 | QCC 대응 | 상태 |
|------|----------|----------|------|
| 조건_1: ISD 끊김 0.6초 → off | 640 tick 타이머 → BLE_OFF | isd_interface.c:253/266 DISCONNECTED 즉시 전달, 지연 없음 | DELEGATED — 지연 로직이 QCC 펌웨어로 이관됐을 가능성, 확인 불가 |
| 조건_2: ISD 미연결 초기 → off | BLE_OFF=true | snd_qcc_init()에서 ISD_CHECK=LOW, QCC_CTRL=SHUTDOWN으로 시작 | COVERED |
| 조건_3: mappingConnection → BLE 강제 유지 | BLE_OFF=false 덮어씀 | isd_interface.c:243~254: mappingConnection=true여도 ISD < 10V_Ok이면 DISCONNECTED 전달 | PARTIAL — 매핑 중 ISD 미연결 상태에서의 "강제 on" 의미는 QCC에 없음 |
| 조건_4: Mapping_BLE_Off → 일시 off | BLE_Off_Command 경유 NRF_On_OFF 4번째 인자 | QCC 경로 없음 — BLE_Off_Command가 snd_qcc_set_isd/set_mode로 연결되지 않음 | UNCOVERED |
| 조건_5: global_BLE_Off(충전기) → off | systemControl.c:165 → NRF_On_OFF | main.c:800 SHUTDOWN 호출이 주석 처리됨; 충전 중 QCC는 NORMAL 유지(의도적) | UNCOVERED (의도적 설계 변경 — 충전 중 BLE 통신 유지 필요) |

## 5. 종합 판정

### 5.1 기능 추가인가, 동등 대체인가, 축소인가?

**동등 대체가 아니다.** 아키텍처 패러다임 자체가 달라졌다:

- NRF_On_OFF는 이미 死코드였다 (NRF_Off/On_Command GPIO 주석 처리). 따라서 QCC 전환은 "기능 이전"이 아니라 **처음부터 제대로 구현된 첫 BLE 제어 경로**다.
- NRF 시대 5개 조건 중 조건_4(Mapping_BLE_Off)와 조건_5(global_BLE_Off)는 QCC에 직접 대응이 없다. 단, 조건_5는 의도적 설계 변경(충전 중 BLE 유지로 뚜껑 열림 감지).
- QCC 시대는 "E8300이 ISD 상태 + 전원 상태를 알려주면 QCC가 알아서 BLE를 관리"하는 위임 구조로, NRF 시대의 "E8300이 BLE on/off를 직접 결정"과 근본적으로 다르다.

### 5.2 커버하지 못하는 영역

1. **Mapping_BLE_Off 일시 off**: 매핑 앱이 최초 내부기 이름 설정 시 BLE를 잠깐 끄는 로직. QCC에서 이 신호가 전달되는 경로 없음.
2. **global_BLE_Off(충전기) → QCC off**: 의도적으로 제거됨. 충전 중 QCC를 살려 BLE 패킷으로 뚜껑 열림을 감지하는 설계로 변경.
3. **0.6초 지연 off (조건_1)**: E8300 레벨에서는 사라짐. QCC 펌웨어가 내부 구현했을 가능성이 있으나 확인 불가.
