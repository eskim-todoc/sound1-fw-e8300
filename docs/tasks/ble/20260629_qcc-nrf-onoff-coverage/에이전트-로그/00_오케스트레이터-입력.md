# 오케스트레이터 입력

**TL;DR**: 모든 fan-out 노드 공통 컨텍스트. 라인 좌표는 직접 Read로 검증할 것(인용 환각 금지). repo 루트: `/mnt/e/Claude/projects/Sound1`. 분석 대상은 `src/2__cm3/Cortex-M3-src/` (factory 사본 `2__cm3_factory`는 제외).

## 분석 미션

폐기 예정인 nRF 시대의 `NRF_On_OFF()` 함수가 담당하던 **BLE on/off 결정 로직**을, 현재 QCC 전환 후 `snd_qcc.c`의 함수들이 **기능적으로 전부 커버**하는지 판정한다.

## Ground Truth 좌표 (직접 Read로 검증)

### NRF 측
- `systemControl/systemControl.c:50~110` — `NRF_On_OFF(ST__ISD_STATUS isd_state, bool global_BLE_Off, bool mappingConnection, bool Mapping_BLE_Off)` 본체.
  - 입력 4개. 내부 `ISD_ConnectionHistory` static, `deaylCounter`(0.6초=640 tick) 지연.
  - 조건: ① ISD 연결 이력 후 끊김 0.6초 → off, ② ISD 미연결 초기 → off, ③ mappingConnection → 강제 유지(on), ④ Mapping_BLE_Off → off, ⑤ global_BLE_Off → off.
  - **출력 `NRF_Off_Command()`(systemControl.c:37)·`NRF_On_Command()`(:42) 본문 전부 주석 처리 = 死코드**.
- `systemControl/systemControl.c:165` `systemStatus.BLE_Off = true`(충전기 연결 시), `:204` `= false`(충전기 미연결).
- `main.c:660` — 메인 루프 매 cycle 호출: `NRF_On_OFF(isd_state, systemState.BLE_Off, BLE_communicationState.mappingConnection, BLE_communicationState.BLE_Off_Command)`.
- `BleCommunication/ble_communication.c:433~456` — `BLE_Off_Command` 세팅(매핑/리모컨 BLE_Off에서). `mappingConnection` 세팅(:456).

### QCC 측
- `QCC/snd_qcc.c` 전체 — `snd_qcc_init`(:12), `snd_qcc_set_isd`(:21, 핀 `ISD_CHECK`=DIO13), `snd_qcc_set_mode`(:57, 핀 `QCC_CTRL`=DIO24). 단순 GPIO 출력, 결정 로직 없음.
- `QCC/snd_qcc.h` — `snd_qcc_mode_t`(SHUTDOWN=0/NORMAL), `snd_qcc_isd_t`(DISCONNECTED=0/CONNECTED).
- 호출처(전수):
  - `snd_qcc_set_isd`: `main.c:508`(CONNECTED), `internalDevice/isd_interface.c:248`(매핑연결+10V Ok→CONNECTED)/`:253`(DISCONNECTED)/`:261`(standalone 파라설정완료→CONNECTED)/`:266`(DISCONNECTED).
  - `snd_qcc_set_mode`: `systemControl/initialize.c:511`(NORMAL, 부팅), `main.c:829`(SHUTDOWN), `main.c:871`(SHUTDOWN, 절전), `BleCommunication/ci_ble_control_boot.c:117`(SHUTDOWN, OTA 후), `main.c:800`(SHUTDOWN, 주석).

## 핵심 분석 질문

1. NRF_On_OFF의 5개 결정 조건 각각이 QCC 경로 어디서 대응되는가? (1:1 매핑)
2. QCC 전환의 아키텍처 의미: BLE on/off 판단 주체가 E8300→QCC 펌웨어로 위임되었는가? `ISD_CHECK` 핀의 역할은?
3. NRF가 끄던 조건 중 QCC가 **놓치는** 것이 있는가? (예: 매핑 연결 유지, Mapping_BLE_Off 일시 off, global_BLE_Off 충전기 off, 0.6초 지연 off)
4. `set_mode(SHUTDOWN)`은 QCC 전원 자체를 끄는 것 — NRF의 "BLE 광고만 off"와 의미가 같은가 다른가?
5. NRF_On_OFF가 死코드인 점을 감안하면, QCC 전환은 기능 추가인가 동등 대체인가 축소인가?
