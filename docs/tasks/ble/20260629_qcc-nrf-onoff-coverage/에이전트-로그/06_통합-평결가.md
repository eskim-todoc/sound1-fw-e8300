# 통합 평결: NRF_On_OFF → QCC 커버리지

**TL;DR**: NRF_On_OFF() 5개 조건 중 covered 1개·partial 2개·uncovered 2개. 단, NRF 출력 함수 자체가 死코드였으므로 이 전환은 기능 이전이 아닌 아키텍처 패러다임 교체(CM3 중앙 결정 → QCC 자율 판단)로 판정한다. 조건_4(매핑 일시 off)는 QCC 경로에도 전달 수단이 없는 실질적 설계 gap이다.

## 전체 평결

### 판정: **architecture_shift**

NRF_On_OFF() 5개 조건의 커버리지 수치만 보면 covered 1·partial 2·uncovered 2로 partially_covered에 가깝다. 그러나 이 판정은 전제가 틀렸다.

**핵심 사실**: NRF_Off_Command()/NRF_On_Command() 본문은 이미 전부 주석 처리(systemControl.c:37-44, :104-108)되어 NRF 시대에도 GPIO 출력이 전혀 없는 完全 死코드였다. NRF_On_OFF()는 매 cycle(main.c:660) 조건 연산은 수행했지만 그 결과가 하드웨어에 반영된 적이 없다. 따라서 이 전환은 **작동하던 BLE 제어 기능을 이전한 것이 아니라**, 빈 자리에 전혀 다른 아키텍처를 올린 것이다.

**아키텍처 패러다임 교체의 3가지 근거**:

1. **결정 주체 이전**: NRF 시대는 E8300(CM3)이 5개 조건을 직접 평가해 모듈에 명령 의도였으나, QCC 시대는 ISD_CHECK(DIO13) 단방향 힌트 핀만 전달하고 BLE 광고 on/off 결정은 QCC 내부 펌웨어가 자율 수행하는 구조다. E8300 측에 결정 로직이 없다(snd_qcc.c:21-91 전체 단순 GPIO).

2. **제어 단위 상이**: NRF_Off_Command는 의도상 BLE 광고 soft-disable이었으나, set_mode(SHUTDOWN)은 QCC 칩 전원을 2초 이상 LOW 유지해야 성립하는 하드웨어 전원 차단이다(ci_ble_control_boot.c:116). 같은 수준의 off 개념이 아니다.

3. **조건_5 정책 반전**: 충전기 연결 시 BLE를 끄던 NRF 정책을 의도적으로 뒤집어(main.c:800 주석), 충전 중에도 QCC를 NORMAL로 유지해 BLE SPI 패킷으로 뚜껑 열림을 감지하는 설계로 전환됐다(main.c:823-824). 이는 조건 미커버가 아닌 요구사항 변경이다.

### 잔존 주의 항목

**조건_4(Mapping_BLE_Off)**는 유일하게 설계 의도 근거가 불명확한 gap이다. BLE_Off_Command는 ble_communication.c:433-452에서 세팅되고 main.c:660의 NRF_On_OFF(死코드)에만 전달되며 QCC 경로가 전혀 없다. 매핑 앱에서 최초 내부기 이름 설정 시 BLE를 일시 off하는 시나리오(주석 "매핑에서 BLE를 잠시 껐다가 켜는 경우")가 QCC에서 어떻게 처리되는지 확인 필요하다. QCC 내부 펌웨어가 자율 처리할 가능성은 있으나 E8300 측 전달 경로 자체가 없어 현재로선 미구현으로 봐야 한다.

## 5개 분석 노드 모순 정리

5개 노드 간 판정 차이가 있었던 조건_2에 대해 재확인한다. 노드 [02]는 "초기화 시점만 커버(runtime 미연결 재판단 경로 없음)"로 partial 판정했으나, 노드 [03][04][05]는 covered로 판정했다. 직접 Read 결과: isd_interface.c:265-266에서 stimulationParameterSettingIsDone=false 조건이 매 cycle 평가되므로 런타임 동적 미연결 상태에서도 매 cycle DISCONNECTED를 전달한다. **covered 판정이 옳다.**

조건_1의 타이밍 판정: 노드 [05]는 uncovered, 나머지는 partial로 분류했다. 이벤트(ISD 끊김)는 전달되므로 partial이 더 적합하다. uncovered는 경로 자체가 없는 조건_4/조건_5에 한정한다.
