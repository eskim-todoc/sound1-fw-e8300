# 검증·반증 에이전트 (08)

**TL;DR**: 통합 평결 `architecture_shift`의 핵심 주장 8개를 양방향으로 공격. 死코드 무의미론·set_mode 의미 동치론 모두 refuted. 조건_4(Mapping_BLE_Off) gap과 mappingConnection override 부재는 confirmed. 조건_5(global_BLE_Off)는 uncovered 아닌 의도적 정책 반전으로 refuted.

## 역할

반증가(adversarial). 통합 평결이 옳다고 주장하는 쪽과 틀리다고 주장하는 쪽, 양방향을 모두 깨려 시도한다. 특히 오케스트레이터가 지정한 세 공격 축:

- **(a)** 死코드라 NRF 자체가 실효 없으니 커버 논의가 무의미한가
- **(b)** set_mode(SHUTDOWN) = QCC 전원 off 가 NRF의 "광고만 off"와 의미가 같은가
- **(c)** mappingConnection / Mapping_BLE_Off / global_BLE_Off 조건이 QCC 경로에 정말 없는가

## 반증 시도 결과

### (a)-1 "死코드이므로 커버 논의 무의미" → **반박됨(refuted)**

- **공격 주장**: NRF_On_OFF() 출력부(systemControl.c:104,108)가 주석이고 NRF_Off_Command() 본문도 주석(systemControl.c:39)이므로, NRF 시대에도 BLE가 실제로 제어되지 않았다. 따라서 QCC가 커버하든 안 하든 무의미하다.
- **반박 근거**: 주석화는 *출력부 한정*. 판정 로직(systemControl.c:50-100) 자체는 활성 C코드로 매 cycle 실행된다. 설계 의도(언제 BLE를 끌 것인가)는 이 로직에 인코딩되어 있다. 반면 QCC snd_qcc_set_isd/set_mode는 실효 있는 GPIO 출력(snd_qcc.c:44,48,80,84 — Sys_GPIO_Set_High/Low 활성). 死코드 논거는 NRF 출력부에만 적용되며, QCC 전환 후 동등 의도가 구현됐는지는 독립적으로 평가 가능하다. 무의미론 성립 안 됨.

### (a)-2 "QCC도 어차피 NRF처럼 실효 없을 것" → **반박됨(refuted)**

- **공격 주장**: NRF가 死코드였듯 QCC GPIO도 실제 QCC 칩 동작을 보장하지 않을 수 있다.
- **반박 근거**: snd_qcc.c:44,48 ISD_CHECK(DIO13) High/Low 및 snd_qcc.c:80,84 QCC_CTRL(DIO24) High/Low — 이 핀들은 QCC 칩의 하드웨어 인터페이스 핀이다. ci_ble_control_boot.c:116 주석 "2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다"는 칩 동작을 전제한 실측 기반 구현이다. NRF_Off_Command()의 Sys_GPIO_Set_Low가 주석화된 것과 달리, QCC 경로 GPIO는 주석 없이 활성이다.

### (b) "set_mode(SHUTDOWN)이 NRF 광고 off와 동등하다" → **반박됨(refuted)**

- **공격 주장**: NRF_Off_Command()가 BLE 광고를 끄는 것이고 snd_qcc_set_mode(SHUTDOWN)이 QCC BLE를 끄는 것이므로, 둘은 기능상 동등하다. 따라서 set_mode를 호출하는 경로가 있으면 커버된다.
- **반박 근거**:
  - NRF_Off_Command()는 GPIO one-shot(systemControl.c:39 주석화 전 원형: Sys_GPIO_Set_Low 단발). BLE 광고 soft-disable 의도.
  - set_mode(SHUTDOWN)은 ci_ble_control_boot.c:119-123: 2200ms 딜레이 루프 후 watchdog reset으로 시스템 재부팅까지 포함한 QCC 칩 전원 완전 차단 시퀀스.
  - 제어 단위: NRF는 "BLE 광고 일시 정지(재부팅 없음)", QCC는 "칩 전원 차단 + 재부팅". 동치로 볼 수 없음. 커버 여부 판정에서 set_mode 호출 존재 자체를 NRF 광고 off와 1:1로 대입하면 오판.

### (c)-1 "mappingConnection 강제 override가 QCC 경로에 없다"(gap 주장) → **확인됨(confirmed)**

- **공격 주장(평결 측)**: QCC 경로에서 mappingConnection이 ISD 10V 여부와 이중 조건으로 처리되어, NRF의 단독 강제 override가 없다.
- **반박 시도**: isd_interface.c:243-248에서 mappingConnection=true + ISD >= 10V → CONNECTED를 전달하므로, 매핑 연결 중 정상 ISD 상태에서는 동등하게 동작한다고 볼 수 있지 않은가?
- **반박 실패(confirmed)**: NRF systemControl.c:85-88은 ISD 상태 무관(코드 순서상 조건_1,2 판정 이후 override). QCC isd_interface.c:250-253은 mappingConnection=true여도 ISD < stimul_10V_Ok이면 DISCONNECTED를 전달한다. 매핑 연결 중 ISD가 일시적으로 10V 미달이 되는 순간 동작 차이가 발생한다. override 로직 부재 confirmed.

### (c)-2 "BLE_Off_Command(Mapping_BLE_Off)가 QCC 경로에 없다"(gap 주장) → **확인됨(confirmed)**

- **공격 주장(평결 측)**: ble_communication.c:433-452에서 세팅된 BLE_Off_Command가 QCC 제어 함수로 연결되는 경로가 없다.
- **반박 시도**: BLE_Off_Command가 main.c:660 → NRF_On_OFF() 내부에서 systemControl.c:91-94로 처리되므로, NRF_On_OFF() 자체가 QCC 제어를 담당하는 구조로 재해석 가능하지 않은가?
- **반박 실패(confirmed)**: NRF_On_OFF()의 출력부(systemControl.c:102-109)가 주석화되어 있고, 내부에 snd_qcc_set_isd/set_mode 호출이 없다. BLE_Off_Command는 NRF_On_OFF() 로직에서 BLE_OFF=true로만 설정되고 실제 GPIO 출력이 없다. snd_qcc_set_isd/set_mode 전체 호출처(main.c:508, isd_interface.c:248/253/261/266, initialize.c:511, main.c:829/871, ci_ble_control_boot.c:117) 어디에도 BLE_Off_Command를 입력으로 받는 경로 없음. gap confirmed.

### (c)-3 "global_BLE_Off(충전기 연결)가 QCC에서 uncovered"(gap 주장) → **반박됨(refuted — 정책 반전)**

- **공격 주장(평결 측)**: systemControl.c:165 BLE_Off=true → QCC 제어 경로 없음으로 uncovered.
- **반박 시도**: main.c:800 주석 처리된 snd_qcc_set_mode(SHUTDOWN)은 단순히 구현이 빠진 것이 아닌가?
- **반박 성공(refuted)**: main.c:799 주석 "QCC는 절전 미진입, SPI 패킷 수신 유지"와 main.c:823 "BLE 통신: 충전 중 QCC는 SPI 패킷 계속 수신 가능"은 의도적 설계 변경을 명시한다. main.c:819-824 충전 루프에서 bleCommunication()을 매 iteration 호출하여 뚜껑 열림 BLE 패킷을 감지한다(main.c:827-832). '충전 시 BLE off'라는 NRF 시대 정책이 '충전 중 BLE on 유지 + SPI 패킷으로 뚜껑 열림 감지'로 요구사항 자체가 바뀐 것. uncovered 아닌 의도적 정책 반전. 다만 공식 요구사항 변경 문서가 없다는 점은 별도 리스크.

### "QCC가 전부 커버한다"(완전 대체 주장) → **반박됨(refuted)**

- **공격 대상**: architecture_shift 판정 대신 "QCC가 NRF의 5개 조건을 전부 대체했다"는 낙관론.
- **반박 근거**: 조건_4(Mapping_BLE_Off) — BLE_Off_Command를 QCC에 전달하는 경로가 소스 전체에 없음(ble_communication.c:433-452 세팅 → main.c:660 死코드 전달이 전부). 전부 커버 불성립.

### "QCC가 전혀 커버 못한다"(완전 미대체 주장) → **반박됨(refuted)**

- **공격 대상**: "아키텍처가 바뀌어서 NRF 기능이 전혀 QCC에 없다"는 비관론.
- **반박 근거**: isd_interface.c:265-266 매 cycle snd_qcc_set_isd(DISCONNECTED) + :261 CONNECTED — ISD 연결/미연결 상태가 QCC에 실시간 전달됨(조건_2 확실히 covered). snd_qcc_init():17 부팅 초기 DISCONNECTED 설정. 적어도 ISD 상태 기반 BLE 제어는 동작한다.

**결론**: 통합 평결의 `architecture_shift` 판정과 `조건_4 gap` 지적은 반증에서 살아남는다. `조건_5 uncovered` 표현은 `의도적 정책 반전`으로 수정이 적절하다. 死코드 무의미론 및 SHUTDOWN 동치론은 모두 반박된다.
