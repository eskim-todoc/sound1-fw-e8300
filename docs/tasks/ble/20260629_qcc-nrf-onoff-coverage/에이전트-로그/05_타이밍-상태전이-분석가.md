# 타이밍·상태전이 분석가

**TL;DR**: QCC 경로는 NRF의 0.6초 지연-off를 계승하지 않는다. ISD_CHECK는 즉시 반영, QCC_CTRL은 절전·OTA 트리거 시점에만 LOW로 내려가며 OTA 경로에만 2초 고정 유지 요건이 존재한다. 부팅 시 QCC는 Initialize() 말미에서 즉시 NORMAL로 올라온다.

---

## 1. NRF_On_OFF() 0.6초 지연 로직 (사실)

`systemControl/systemControl.c:50~110`

```
static int deaylCounter = 0;
bool       ISD_ConnectionHistory = false;   // :47 (static 아님)

// ISD가 10V_Ok 이상 → 이력 플래그 세팅
if (isd_state.isd_controlState >= en__isdStatus_stimul_10V_Ok)
    ISD_ConnectionHistory = true;

// 이력 있는데 끊어짐 → tick 마다 카운트
if (ISD_ConnectionHistory && isd_state.isd_controlState < en__isdStatus_stimul_10V_Ok)
{
    if (deaylCounter > 640)   // 0.6초 후 off (:66)
    {
        BLE_OFF = true;
        ISD_ConnectionHistory = false;
    }
    deaylCounter++;
}
```

- `#define BLE_OffTimeAfterISD_Disconnected 1000` (:35) 이 정의되어 있지만 로직은 하드코드 640을 사용 — 인용 불일치.
- 매 main cycle 호출(`main.c:660`). tick rate에 따라 640 tick ≈ 0.6초.
- **결론**: NRF 경로는 ISD 끊김 후 0.6초 누적 후 BLE_OFF=true. 단, `NRF_Off_Command()` 본문이 주석(`:39`)이므로 실제 핀 변화 없음(死코드).

## 2. QCC 경로별 타이밍 전이

### 2-1. 부팅 (NORMAL 진입)

`systemControl/initialize.c:506~511`

```c
// SPI 초기화
init_cm3_SPI();         // :507

// 이제 QCC를 깨우고 배터리 정보를 얻을 수 있도록 한다.
snd_qcc_set_mode(SND_QCC_MODE_NORMAL);   // :511
```

- Initialize() 전체 시퀀스 말미. I2C·터치·SPI init 완료 직후 즉시 HIGH.
- 딜레이 없음. NRF가 부팅 직후부터 광고하던 것과 동등 — 단, NRF는 자체 모듈 부팅 시간이 있었으나 QCC도 마찬가지로 모듈 자체 초기화 시간이 있음(핀 의미상 추정).
- **타이밍**: Initialize() 완료 즉시. 사전 지연 없음.

### 2-2. ISD 상태 변화 → ISD_CHECK 핀

`internalDevice/isd_interface.c:248/253/261/266`

```c
// mappingConnection && 10V_Ok 이상 → CONNECTED
snd_qcc_set_isd(SND_QCC_ISD_CONNECTED);   // :248

// 그 외 → DISCONNECTED
snd_qcc_set_isd(SND_QCC_ISD_DISCONNECTED); // :253, :266
```

- `isd_interface()` 내부에서 ISD 상태 판정 즉시 → `snd_qcc_set_isd()` 호출.
- `isd_interface()`는 매 main cycle에 `main.c:492`에서 호출됨.
- **타이밍**: ISD 상태 변화 시 동일 tick 내 즉시 GPIO 반영. 0.6초 지연 없음.
- **NRF 대비 차이**: NRF는 `deaylCounter > 640` 지연 후 BLE_OFF. QCC는 ISD_CHECK만 즉시 바뀌며, QCC_CTRL(NORMAL/SHUTDOWN)은 변하지 않는다.

### 2-3. 정상 절전 진입 (SHUTDOWN)

`main.c:845~892` — `func_sleep()`:

```c
ResetNRF();                                      // :869
NRF_Off_Command();                               // :870  (死코드)
snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);         // :871  — QCC CTRL LOW 즉시
Sys_GPIO_Set_Low(DIO_PIN_INDEX_for_FPGA_SLEEP);  // :872
OnOff_3V_PMIC_CM3_to_CFX(false);                // :873
turnOffLED();                                    // :874
```

- `func_sleep()`는 `main.c:311`의 `while(1) { func_normal(); func_sleep(); }` 에서 `func_normal()` 내 `break`(`:768`) 직후 호출됨.
- `break` 직전 가드(`main.c:754~758`): mappingConnection·pair·OTA 중이면 `systemState.systemOff = false` 리셋 후 재평가. 해당 없을 때만 `func_sleep()` 진입.
- **타이밍**: 절전 트리거 발생 → (매핑·페어·OTA 없음 확인) → break → 즉시 QCC_CTRL LOW.
- NRF 0.6초 지연과 다른 개념: NRF는 ISD 연결 끊김에 대한 광고 off 지연이었고, QCC_CTRL SHUTDOWN은 모듈 전원 자체 차단으로 다른 레이어.

### 2-4. OTA 후 재부팅 (SHUTDOWN + 2초 유지)

`BleCommunication/ci_ble_control_boot.c:112~126`:

```c
/* 응답 패킷 송신까지 일정 시간 딜레이 */
SYS_WATCHDOG_REFRESH();
_DELAY_MS(20);                                           // :114 — 패킷 드레인

/* 2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다. */
snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);                 // :117 — LOW 세팅

for (volatile int i = 0; i < 2200; i++)
{
    SYS_WATCHDOG_REFRESH();
    _DELAY_MS(1);                                        // :120~123 — 2.2초 하드 대기
}

SYS_WATCHDOG_RESET();                                    // :126 — 워치독 리셋으로 재부팅
```

- 명시 주석: "2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다."
- 이는 QCC IC 고유 전원-off 보증 시간이며 NRF에는 이에 해당하는 요건이 없었다.
- **타이밍 요약**: 응답 패킷 20ms 드레인 → QCC_CTRL LOW → 2.2초 대기 → 워치독 리셋.

### 2-5. 크래들 뚜껑 닫힘 (약 절전, light sleep)

`main.c:783~843` — `func_cradle_lid_closed_loop()`:

```c
ResetNRF();           // :796
NRF_Off_Command();    // :797  (死코드)

// snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);   // :800 — 주석 처리됨
```

루프 중 뚜껑 열림 패킷 수신 시:
```c
snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN);  // :829 — 재부팅 직전
_DELAY_MS(20);                            // 로그 드레인
SYS_WATCHDOG_RESET();                     // 워치독 리셋
```

- **약 절전 진입 시 QCC_CTRL은 HIGH 유지** (line 800 주석). 충전 중 QCC는 BLE SPI 패킷을 계속 수신 가능 상태.
- NRF_Off_Command는 line 797에서 호출되지만 死코드이므로 실효 없음.
- 뚜껑 열림 → 재부팅 직전 QCC_CTRL LOW + 20ms → 워치독 리셋.

## 3. 타이밍 비교 요약

| 시나리오 | NRF 타이밍 | QCC 타이밍 | 차이 |
|---|---|---|---|
| ISD 끊김 → BLE off | 0.6초 누적(640 tick) 후 BLE_OFF=true | 同 tick 내 ISD_CHECK LOW; QCC_CTRL 변화 없음 | 지연 없음. QCC는 ISD_CHECK 핀만 즉시 변경. QCC가 자율 판단(추정) |
| ISD 미연결 초기 | ISD_ConnectionHistory=false → 즉시 BLE_OFF | snd_qcc_init()에서 ISD_CHECK=LOW 초기화 | 동등 (초기 DISCONNECTED 상태) |
| 정상 절전 진입 | NRF_Off_Command() 즉시(死코드) | snd_qcc_set_mode(SHUTDOWN) 즉시 | 구조 동등. QCC는 실제 핀 변화 O |
| OTA 후 재부팅 | 없음 (NRF는 워치독 리셋만) | SHUTDOWN 후 2.2초 대기 → 워치독 리셋 | QCC 전원-off 보증 2초 유지 요건 — NRF에 없던 추가 타이밍 |
| 크래들 약 절전 | NRF_Off_Command() 즉시(死코드) | QCC_CTRL HIGH 유지(주석) — 뚜껑 열림 시 SHUTDOWN+20ms | NRF 약 절전 off 의도 → QCC는 의도적으로 NORMAL 유지 |
| 부팅 | NRF 자체 모듈 초기화 후 광고 시작 | Initialize() 말미에 NORMAL 즉시 | 동등 수준. 딜레이 없음 |

## 4. 핵심 발견

### 4-1. 0.6초 지연 off는 QCC 경로에 계승되지 않음 (사실)

NRF의 `deaylCounter > 640` 로직(`systemControl.c:66`)은 QCC 경로 어디에도 대응되지 않는다. `snd_qcc_set_isd()`는 즉시 GPIO 반영이며, QCC_CTRL(모드 핀)은 ISD 상태에 연동되지 않는다.

이 지연의 원래 목적은 ISD 일시 끊김 후 BLE를 계속 유지해 재연결을 지원하는 것으로 추정. QCC 전환 후 해당 로직이 QCC 자체 펌웨어로 흡수되었는지 여부는 QCC 내부 펌웨어를 알 수 없어 단정 불가.

### 4-2. QCC_CTRL 핀과 ISD_CHECK 핀의 역할 분리 (사실)

- `ISD_CHECK`(DIO13): ISD 연결 상태 알림 — isd_interface.c에서 매 tick 갱신, 즉시 반영.
- `QCC_CTRL`(DIO24): QCC 전원·모드 제어 — 절전 진입·OTA·재부팅 시점에만 LOW.

NRF의 단일 ON/OFF 핀이 "BLE 광고 on/off"였다면, QCC 경로는 두 핀의 역할을 분리: ISD 상태는 ISD_CHECK로 지속 알리고, 모드는 QCC_CTRL로 전원 수준에서만 제어.

### 4-3. OTA 경로의 2초 대기는 QCC 고유 타이밍 제약 (사실)

`ci_ble_control_boot.c:116~123` — 명시 주석 "2초 이상 QCC_CTRL을 0으로 유지해야 QCC가 꺼진다." NRF에는 이에 대응하는 타이밍 요건이 없었다. QCC 모듈 전원-off 보증을 위한 하드웨어 요구사항으로 판단.

### 4-4. 크래들 약 절전 시 QCC 유지는 의도적 (사실 + 추정)

`func_cradle_lid_closed_loop()` 내 `snd_qcc_set_mode(SND_QCC_MODE_SHUTDOWN)` 주석(`:800`)과 "충전 중 QCC는 SPI 패킷 계속 수신 가능"(`:823` 주석)은 의도적 설계 결정임을 나타낸다. 충전 중 BLE 통신 유지가 목적으로 추정.

## 5. NRF 0.6초 지연 미계승의 리스크 평가 (추론)

NRF의 0.6초 지연은 "ISD 잠깐 끊김 → BLE 광고 off → 재연결 어려움" 문제를 완충하는 로직이었다. QCC 경로에서:
- ISD 끊김 시 `ISD_CHECK=LOW`가 즉시 QCC에 전달됨.
- QCC가 ISD_CHECK LOW를 받고 내부에서 어떻게 동작하는지(광고 유지·중단 결정)는 QCC 내부 펌웨어에 달려 있어 단정 불가.
- 만약 QCC 내부에 동등한 debounce/holdoff 로직이 없다면, ISD 순간 끊김에 QCC가 즉시 반응해 BLE 광고를 중단할 수 있음.

---

## 6. 결론

1. NRF의 **0.6초 지연 off**는 QCC E8300 경로에서 **직접 계승되지 않는다**. ISD_CHECK는 즉시 반영, QCC_CTRL은 절전/OTA 이벤트에만 LOW.
2. **QCC_CTRL** 핀의 SHUTDOWN 전이는 세 지점: `func_sleep()`(즉시), `ci_ble_control_boot.c`(2.2초 딜레이 후), `func_cradle_lid_closed_loop()`의 뚜껑 열림 직전.
3. **OTA 경로의 2.2초 대기**는 QCC 고유 전원-off 보증 타이밍이며 NRF에는 없던 추가 요건.
4. **크래들 약 절전**에서 QCC는 의도적으로 NORMAL 유지(BLE SPI 통신 지속).
5. NRF_On_OFF()의 5개 결정 조건 중 타이밍 측면의 "0.6초 지연" 은 **미계승(uncovered)**이며, QCC 내부가 자율 처리하는지 여부는 외부에서 검증 불가.
