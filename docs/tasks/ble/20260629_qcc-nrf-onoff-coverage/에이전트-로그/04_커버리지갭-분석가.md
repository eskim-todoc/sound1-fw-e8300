# 커버리지 갭 분석

**TL;DR**: NRF_On_OFF() 5개 조건 중 2개(조건 4·5)는 QCC 경로에 전달 수단이 전무(uncovered), 1개(조건 2)는 ISD_CHECK 핀 초기화로 QCC에 위임(delegated), 2개(조건 1·3)는 부분 대응(partial). 아키텍처 변화의 핵심은 "CM3가 BLE 광고를 직접 결정"에서 "ISD_CHECK 핀으로 QCC에 힌트 전달 후 QCC 자율 결정"으로 책임 위임.

## 1. NRF_On_OFF() 구조 재확인

```c
// systemControl/systemControl.c:50~110
void NRF_On_OFF(ST__ISD_STATUS isd_state, bool global_BLE_Off, bool mappingConnection, bool Mapping_BLE_Off)
{
    static int deaylCounter = 0;
    bool       BLE_OFF      = false;

    // [조건1] ISD 연결 이력 후 끊김 → 0.6초(640 tick) 후 off
    if (isd_state.isd_controlState >= en__isdStatus_stimul_10V_Ok) { ISD_ConnectionHistory = true; }
    if (ISD_ConnectionHistory) {
        if (isd_state.isd_controlState < en__isdStatus_stimul_10V_Ok) {
            if (deaylCounter > 640) { BLE_OFF = true; ISD_ConnectionHistory = false; }
            deaylCounter++;
        } else { deaylCounter = 0; }
    }
    // [조건2] ISD 미연결 초기 → off
    else { BLE_OFF = true; }

    // [조건3] mappingConnection → 강제 유지(on)
    if (mappingConnection) { BLE_OFF = false; }

    // [조건4] Mapping_BLE_Off → off
    if (Mapping_BLE_Off) { BLE_OFF = true; }

    // [조건5] global_BLE_Off(충전기 연결) → off
    if (global_BLE_Off) { BLE_OFF = true; }

    // 출력: 전부 주석 = 死코드
    if (BLE_OFF) { /* NRF_Off_Command(); */ }
    else         { /* NRF_On_Command();  */ }
}
```

> [!IMPORTANT]
> NRF_Off_Command()·NRF_On_Command() 본문이 이미 주석이므로 NRF_On_OFF() 자체가 NRF 시대에도 실효 없었음. QCC 전환 전부터 BLE on/off 제어는 사실상 공백이었다.

## 2. QCC 아키텍처 이해

QCC 제어 채널은 두 핀뿐이다:

| 핀 | 함수 | 값 | 의미 |
|---|---|---|---|
| `QCC_CTRL` (DIO24) | `snd_qcc_set_mode()` | HIGH(NORMAL) / LOW(SHUTDOWN) | QCC 전원·동작 on/off |
| `ISD_CHECK` (DIO13) | `snd_qcc_set_isd()` | HIGH(CONNECTED) / LOW(DISCONNECTED) | ISD 연결 상태 힌트 |

**핵심 아키텍처 변화**: NRF 시대에는 CM3가 BLE 광고 on/off를 직접 지시(비록 死코드였지만). QCC 시대에는 CM3가 `ISD_CHECK` 핀 하나로 ISD 연결 상태만 알려주고, **BLE 광고 on/off 결정은 QCC 펌웨어 내부에 위임**된다(추정 — QCC 내부 펌웨어 미확인).

`set_mode(SHUTDOWN)` = QCC 전원 자체 차단. NRF의 "BLE 광고만 off"보다 훨씬 강한 동작이며 의미가 다름.

## 3. 조건별 1:1 매핑 및 갭 판정

### 조건 1: ISD 연결 이력 후 끊김 0.6초 지연 → BLE off

**NRF 경로**: `systemControl.c:60~78` — `ISD_ConnectionHistory=true` 상태에서 ISD 끊기면 `deaylCounter > 640`(≈0.6초) 후에만 BLE_OFF=true

**QCC 경로**: `isd_interface.c:252~253` (매핑 연결 분기) 또는 `:265~266` (standalone 분기) — ISD 상태가 10V_Ok 미만이면 **즉시** `snd_qcc_set_isd(DISCONNECTED)`

**갭**:
- 0.6초 지연 로직이 QCC 경로에 없음 — ISD 끊김 즉시 DISCONNECTED 신호 전달
- QCC 펌웨어가 ISD_CHECK=LOW 수신 후 내부적으로 지연을 구현할 수도 있으나 미확인(추정)

**status**: `partial` — 이벤트 전달 자체는 되나 지연 로직이 E8300 측에서 누락

---

### 조건 2: ISD 미연결 초기 → BLE off

**NRF 경로**: `systemControl.c:79~82` — `ISD_ConnectionHistory=false` 초기 상태에서 BLE_OFF=true

**QCC 경로**:
- `snd_qcc.c:17` — `snd_qcc_init()`에서 `snd_qcc_set_isd(SND_QCC_ISD_DISCONNECTED)` 초기화
- `isd_interface.c:265~266` — `stimulationParameterSettingIsDone == false`이면 DISCONNECTED

**갭**: 없음. 초기 DISCONNECTED 신호를 QCC에 전달하며, QCC 펌웨어가 이를 받아 BLE 광고 억제를 처리한다고 추정.

**status**: `delegated` — ISD_CHECK=LOW 초기화로 QCC에 위임

---

### 조건 3: mappingConnection → 강제 유지(on)

**NRF 경로**: `systemControl.c:84~88` — ISD 상태와 무관하게 `mappingConnection=true`이면 BLE_OFF=false 강제 override

**QCC 경로**: `isd_interface.c:243~254`
```c
if (mappingConnection) {
    if (s_isd_state.isd_controlState >= en__isdStatus_stimul_10V_Ok) {
        snd_qcc_set_isd(SND_QCC_ISD_CONNECTED);   // :248
    } else {
        snd_qcc_set_isd(SND_QCC_ISD_DISCONNECTED); // :253  ← NRF와 다름
    }
}
```

**갭**:
- NRF에서는 `mappingConnection` 시 ISD 상태 무관하게 BLE ON 강제
- QCC에서는 `mappingConnection`이더라도 ISD가 10V_Ok 미만이면 DISCONNECTED 신호 → QCC에게 "ISD 없음"으로 알림
- "매핑 연결 중에는 BLE를 반드시 유지" 강제 override 경로가 QCC 측에 없음
- 단, QCC가 이미 BLE 연결을 유지하고 있는 상태(매핑 중)라면 ISD_CHECK 변화만으로 BLE 광고를 끊지 않을 수 있음(QCC 내부 로직 미확인)

**status**: `partial` — 명시적 강제 override 경로 없이 QCC 내부 로직에 의존

---

### 조건 4: Mapping_BLE_Off(매핑 일시 BLE off) → BLE off

**NRF 경로**: `systemControl.c:90~94` — `BLE_communicationState.BLE_Off_Command=true`이면 BLE_OFF=true  
설정처: `ble_communication.c:433~452` — 매핑/리모컨 BLE_Off → `BLE_Off_Command=true`

**QCC 경로**: **없음**
- `BLE_Off_Command`를 `snd_qcc_set_isd()` 또는 `snd_qcc_set_mode()`로 전달하는 경로 전무
- `main.c:660`에서 `NRF_On_OFF()`에 `BLE_Off_Command`를 전달하지만 이는 死코드
- `isd_interface.c`는 `mappingConnection`·`enable_ISD`·`stimulationParameterSettingIsDone`만 참조, `BLE_Off_Command` 인자 없음

**갭**: 완전 누락. "최초 내부기 이름 설정 시 BLE 일시 off" 동작이 QCC에 전달되지 않음.

**status**: `uncovered` — QCC 전달 경로 전무

---

### 조건 5: global_BLE_Off(충전기 연결) → BLE off

**NRF 경로**: `systemControl.c:96~100` — `global_BLE_Off=true`이면 BLE_OFF=true  
설정처: `systemControl.c:165` — 충전기 연결 시 `systemStatus.BLE_Off=true`

**QCC 경로**: **없음 (의도적 설계 변경)**
- 충전기 연결 시 QCC를 SHUTDOWN하는 코드(`main.c:800`)가 **주석 처리됨**
- 주석: "충전기 연결 시 QCC는 절전 미진입, SPI 패킷 수신 유지"
- 충전기 연결 후 light sleep 루프(`main.c:785~843`)에서 QCC는 NORMAL 유지하며 SPI 패킷 수신 계속
- `systemStatus.BLE_Off`는 `NRF_On_OFF()` 死코드에만 전달되고 QCC 경로엔 연결 없음

**갭**: 충전기 연결 시 NRF를 꺼야 했던 조건이 QCC에서는 의도적으로 QCC를 켜둔 상태로 역전. 설계 의도 변경으로 추정되나 명시적 문서화 없음.

**status**: `uncovered` — 의도적 주석 처리로 충전기 연결 시 QCC BLE off 없음

## 5. 아키텍처 의미 해석

**NRF_On_OFF() 死코드의 함의**: `NRF_Off_Command()`·`NRF_On_Command()` 본문이 이미 주석 처리된 상태라, QCC 전환 이전에도 E8300은 BLE on/off를 실제로 제어하지 않았다. 즉 QCC 전환은 "기존에 작동하던 기능의 대체"가 아니라 **사실상 아무것도 없던 자리에 새 아키텍처를 올린 것**이다.

**ISD_CHECK 핀의 역할(추정)**: QCC 펌웨어가 ISD_CHECK 핀을 모니터링하여 ISD 연결 상태에 따라 BLE 광고 시작/중지를 자율 결정하는 것으로 추정된다. CM3 → QCC로의 책임 위임이 이 핀 하나로 이루어진다(QCC 내부 펌웨어 확인 불가, 추정).

**`set_mode(SHUTDOWN)` vs NRF "광고만 off"**: SHUTDOWN은 QCC 전원 차단으로 절전/재부팅 전용. NRF의 단순 광고 on/off와 의미·용도가 다르다. 런타임 BLE 광고 제어는 ISD_CHECK 핀이 담당하는 구조로 추정.

## 6. 핵심 위험 항목

1. **조건 4 uncovered**: 매핑 프로그램이 "최초 내부기 이름 설정 시 BLE 일시 off" 요청(`BLE_Off_Command`)을 보내도 QCC는 이를 받지 못함. QCC가 독립적으로 같은 타이밍에 BLE를 끄는 로직이 없다면 기능 누락.

2. **조건 5 uncovered (의도적?)**: 충전기 연결 시 QCC를 NORMAL 유지하는 것이 의도적 설계 변경이라면 문서화 필요. NRF 시대에는 충전기 연결 시 BLE off가 요구사항이었으나 QCC 시대에는 이 제약이 해제된 것인지 확인 필요.

3. **조건 1 partial**: 0.6초 지연이 QCC 펌웨어 내부에 구현되지 않았다면 ISD 순간적 끊김에도 즉시 BLE 광고 중단 위험.
