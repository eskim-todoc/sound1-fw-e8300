## 핵심 발견 (사전 조사 단계)

- `NRF_On_OFF`는 결정 로직은 온전하나 실제 출력(`NRF_Off_Command`/`NRF_On_Command`)이 **전부 주석 처리된 死코드** — 현재 BLE를 실제로 켜고 끄지 못함. main.c:660에서 매 cycle 호출되나 부수효과 없음.
- QCC 제어는 핀 2개 미러링: `QCC_CTRL`(전원 NORMAL/SHUTDOWN), `ISD_CHECK`(ISD 연결 상태). 결정 로직 없이 GPIO 출력만.
- **아키텍처 전환 가설**: NRF=E8300이 BLE on/off를 직접 GPIO 명령 / QCC=E8300은 ISD 연결 상태·전원 모드만 핀으로 알려주고 BLE 광고 on/off 판단은 QCC 펌웨어가 자율 수행.

## 완료 요약

**결론: `architecture_shift`** — QCC는 NRF_On_OFF의 역할을 "전부 커버"한 것이 아니라 **아키텍처 자체를 교체**했다.

- NRF 시대에도 BLE 출력은 **死코드**(GPIO 전부 주석)였다 → 작동하던 기능 이전이 아님.
- 결정 주체가 **E8300(CM3) → QCC 내부 펌웨어**로 위임. E8300은 ISD_CHECK/QCC_CTRL 핀으로 상태만 전달.
- 5조건 판정: 조건_2 covered / 조건_1·3 partial / **조건_4(Mapping_BLE_Off) uncovered = 유일한 실질 gap** / 조건_5 의도적 정책 반전(충전 중 BLE 유지→뚜껑 감지).
- QCC 고유 신규 동작 3종(절전·OTA·뚜껑 시 SHUTDOWN).
