# 요구사항 — QCC가 NRF_On_OFF 역할을 전부 커버하는가

**TL;DR**: nRF 시대의 `NRF_On_OFF(isd_state, global_BLE_Off, mappingConnection, Mapping_BLE_Off)`가 담당하던 BLE on/off 결정 로직을, 현재 QCC 전환 후 `snd_qcc.c`의 함수들(`set_isd`·`set_mode`)이 **기능적으로 전부 커버**하는지 다페르소나로 비교 분석한다. 코드 변경 없는 순수 분석.

## 배경

Sound1은 더 이상 nRF(Nordic) BLE 모듈을 쓰지 않고 QCC(Qualcomm) 모듈로 전환했다. nRF 시대에는 `NRF_On_OFF()` 함수가 4개 입력(ISD 연결 상태·global_BLE_Off·mappingConnection·Mapping_BLE_Off)으로 BLE를 켜고 끌지 판정했다. 현재는 `snd_qcc.c`의 `snd_qcc_set_isd()`·`snd_qcc_set_mode()`가 QCC를 제어한다.

## 요구사항 목록

- **요구사항_1**: `NRF_On_OFF`의 BLE on/off 결정 로직을 입력·조건·출력 단위로 완전 해부한다.
- **요구사항_2**: 현재 QCC 제어 경로(`snd_qcc_*` 전 호출처 + 호출 조건)를 전수 추적한다.
- **요구사항_3**: NRF 로직의 각 결정 조건이 QCC 경로에서 **어디서 어떻게 커버되는지(또는 누락되는지)** 1:1 매핑한다.
- **요구사항_4**: 미커버·반쪽 커버·아키텍처 위임(QCC 펌웨어 자율 판단) 항목을 구분해 식별한다.
- **요구사항_5**: 결론을 할루시네이션 검증(라인 인용 진위) + 반증(adversarial) 노드로 교차검증한다.

## 비범위 (Out of scope)

- 코드 변경(수정·리팩토링)은 하지 않는다. 분석·문서화만.
- QCC 칩 내부 펌웨어 동작은 추론 한계 내에서만 다루고, 단정은 회피한다.

## 완료 기준

- `분석.md`에 NRF↔QCC 조건 매핑표 + 커버리지 평결(커버/부분/미커버/위임) 작성.
- 검증 노드 전수 통과(할루시네이션 0, 반증 결과 반영).
