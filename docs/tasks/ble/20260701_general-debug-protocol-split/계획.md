# 계획 — 범용 디버깅 프로토콜 파일 분리

**TL;DR**: `tdc_remote_general_debug.h`(공개 API 1개)·`tdc_remote_general_debug.c`(진입 함수 + option 1/2/3 static 헬퍼)를 생성하고, `remoteControl.c`의 case 블록(1339~1446)을 3줄 호출로 축약한다. 동작 동일 리팩토링이며, 응답 바이트 포맷을 분리 전후 1:1 대조로 검증한다.

## 산출물

| 파일 | 조치 | 내용 |
|---|---|---|
| `tdc_remote_general_debug.h` | 신규 | 헤더가드 + `int tdc_remote_general_debug_handle(int *tx_buf, int tx_index);` 선언 |
| `tdc_remote_general_debug.c` | 신규 | 진입 함수 + option 1/2/3 static 헬퍼 3개 + 필요한 include |
| `remoteControl.c` | 수정 | case 블록 축약 + `#include "tdc_remote_general_debug.h"` 추가 |

## 세부 설계

### 단계_1: `tdc_remote_general_debug.h`

```c
#ifndef TDC_REMOTE_GENERAL_DEBUG_H_
#define TDC_REMOTE_GENERAL_DEBUG_H_

/*
 * tdc_remote_general_debug.h
 *
 * 범용 디버깅 프로토콜(EN__SND_BT_CMD_GENERAL_DEBUG, 0x8F) 처리.
 * remoteControl.c의 case 블록에서 분리(2026-07-01).
 * remoteDataPacket.data[0]=option 으로 서브 프로토콜 분기.
 */

/*
 * 범용 디버깅 프로토콜을 처리하고 응답을 tx_buf에 채운다.
 *  - tx_buf   : SPI 송신 버퍼(호출부 지역 배열) 포인터
 *  - tx_index : 현재 쓰기 오프셋(진입 시점)
 *  - 반환값   : 응답을 채운 뒤의 tx_index
 */
int tdc_remote_general_debug_handle(int *tx_buf, int tx_index);

#endif /* TDC_REMOTE_GENERAL_DEBUG_H_ */
```

### 단계_2: `tdc_remote_general_debug.c`

- include: 자체 헤더 → 표준 → `remoteControl.h`(remoteDataPacket 타입/extern), 그리고 기존 case가 쓰던 헤더(`tdc_touch.h`, `ci_ble_control_ota.h`, `ci_map.h`, `ci_printf.h`, 워치독 매크로 헤더 등) — 조사에서 확인된 심볼 출처를 그대로 이관.
- `extern ST__REMOTECONTROL_PACKET remoteDataPacket;` (remoteControl.c에 정의된 전역 접근).
- 구조:
  ```c
  static int gd_handle_touch_debug(int *tx_buf, int tx_index);    // option 1
  static int gd_handle_no_backtel (int *tx_buf, int tx_index);    // option 2
  static int gd_handle_map_init   (int *tx_buf, int tx_index);    // option 3

  int tdc_remote_general_debug_handle(int *tx_buf, int tx_index)
  {
      int option = remoteDataPacket.data[0];
      ci_printd("[GD] opt: %d \r\n", option);
      switch (option)
      {
          case 1:  tx_index = gd_handle_touch_debug(tx_buf, tx_index); break;
          case 2:  tx_index = gd_handle_no_backtel (tx_buf, tx_index); break;
          case 3:  tx_index = gd_handle_map_init   (tx_buf, tx_index); break;
          default: tx_buf[tx_index++] = remoteDataPacket.command;      break;  // command loop-back
      }
      return tx_index;
  }
  ```
- 각 static 함수는 현재 case의 option별 본문을 **그대로** 옮기고, `bufferForSPI_tx`→`tx_buf`, `tx_index`는 지역으로 받아 누적 후 반환. `option`/`command` loop-back 바이트 순서·값은 원본과 동일하게 유지.
  - 주의: 원본 option 1/2/3은 각자 블록 서두에서 `command` loop-back을 먼저 쓴다 → static 함수 안에서 동일 위치에 유지(포맷 불변).

### 단계_3: `remoteControl.c` case 축약

- 1339~1446 블록을 요구사항_4의 목표 형태로 교체(`#if 1/#endif` 처리 방침은 구현 시 원본 스타일 존중 — 유지 or 제거는 diff 최소화 기준).
- 파일 상단 include 그룹에 `#include "tdc_remote_general_debug.h"` 추가.

## 검증 (단계_4, 서브에이전트 fan-out 병렬)

1. **회귀(동작 동일)**: 분리 전 원본 블록 vs 새 static 함수의 응답 바이트 시퀀스를 option별 1:1 대조 — command/option/데이터 순서·마스킹·인덱스 증가가 완전 일치하는지.
2. **심볼 해결**: 새 .c가 참조하는 모든 심볼(함수·매크로·타입)의 include 경로가 실제 존재하는지 grep 검증(미해결 심볼 0).
3. **스타일**: 헤더가드·include 순서·snake_case·Allman·한글 주석 컨벤션 준수.
4. **빌드 통합**: `.cproject` 폴더 등록 확인(수정 불필요), case 잔류 관용구(`writeDataToSpiTxBuff`/`clearRemoteColtrolCommand`) 정상 여부.

전수 PASS까지 루프(실패 시 단계_3 재진입, 상한 3회). 빌드는 Eclipse 환경이 필요하므로 실제 컴파일은 은수님 확인 항목으로 명시(에이전트는 정적 검증까지).
