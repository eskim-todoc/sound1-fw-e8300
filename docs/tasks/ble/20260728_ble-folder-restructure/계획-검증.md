# 계획 검증 - ble 폴더 개편

## 2. 검증 축_2 - 논리적 정합성

### 2.1 검증 절차의 성립성

| 확인 | 결과 |
|---|---|
| 1a-1 의 플래그 값(`../source/ble/=`)이 이동 후 `tdc_ble_communication.c` 에도 유효한가 | **유효**. 이 파일은 루트 유지라 경로가 그대로이므로 1a-1·1a-5 양쪽에서 같은 플래그가 걸린다 |
| `-I` 3개 추가가 `.elf` 에 영향을 주는가 | **주지 않는다**. `-I` 는 전처리 탐색 경로일 뿐 바이너리에 박히지 않는다. `__FILE__` 은 **확장 시점의 번역 단위(.c) 경로**이므로 헤더 위치와 무관 |
| 동명 헤더가 없으므로 탐색 순서 변화가 무해한가 | **무해**. 분석 §3.6 에서 `tdc_ble_map_*` 미사용 확인. 단 이동하는 헤더 5개(`tdc_ble_remote.h` 등)도 프로젝트 내 유일함이 확인됨 |
| clean 빌드 3회(1a-1·1a-5·1a-6)가 과한가 | 과하지 않다. 1a-1/1a-5 는 **정규화 대조쌍**, 1a-6 은 **정식 산출물**. 각각 목적이 다르다 |
| 단계_1a 에서 실기를 생략하는 것이 타당한가 | **타당**. 바이트 동일이 확증되면 실행 코드가 물리적으로 같다. 다만 정식 빌드(플래그 없음)는 `__FILE__` 만 다르므로 **로그 문구의 파일명 표시가 바뀌지 않음**을 확인해야 한다 - **결함_4** |

### 2.2 커밋 분할의 타당성

| 확인 | 결과 |
|---|---|
| measure -> flash -> stim 순서가 위험도 오름차순인가 | **맞다**. measure 는 공유 static 0건, flash 는 15곳, stim 은 6곳이나 646줄 단일 case 를 8분해 |
| 1b-1 에서 "패턴 확립" 후 적용한다는 전략이 유효한가 | 유효. 92줄 3명령으로 시그니처·계약표 형식을 굳힌 뒤 확대 |
| 1b-4(정리)를 별도 커밋으로 두는 실익 | 있다. 앞 3커밋은 "추출", 마지막은 "잔류 정돈"으로 성격이 다르다 |

### 2.3 정합성 문제

| 확인 | 결과 |
|---|---|
| 수용_1b_2(디스어셈블 대조)의 **PASS 기준**이 정의됐는가 | **미정의** - **결함_1** |

## 4. 발견 결함

### 결함_1 (중대) - 디스어셈블 대조의 PASS 기준이 없다

수용_1b_2 는 "니모닉·호출 시퀀스·분기 구조를 함수 단위 비교"라고만 적었다. 그러나 **함수를 추출하면 구조는 반드시 달라진다** - 새 함수의 프롤로그/에필로그, `bl` 호출 추가, 레지스터 할당 변경이 정상적으로 발생한다. "비교"만으로는 무엇이 정상이고 무엇이 회귀인지 갈리지 않는다.

**보완 - 판정 기준을 다음으로 확정한다**

| # | 확인 항목 | PASS 조건 |
|---|---|---|
| 기준_1 | 조건 분기 개수 | 추출 전 case 블록의 조건 분기(`b<cc>`) 총수 == 추출 후 함수 내 총수 |
| 기준_2 | 외부 함수 호출 | 호출 대상 심볼의 **종류와 순서**가 동일 (신규 `bl <추출함수>`·접근자 호출은 예외로 열거) |
| 기준_3 | 상수 리터럴 | 비교·대입에 쓰인 즉치값 집합이 동일 |
| 기준_4 | 설명 불가 차이 | **0건** - 차이는 전부 "추출로 인한 예상 변화"로 분류 가능해야 한다 |

`Debug/**/*.o.lst`(이미 생성됨)를 쓰면 소스 라인과 어셈블리가 병기돼 대조가 쉽다.

### 결함_2 (경미) - 실기 게이트 1회의 근거가 미기술

1b 커밋 3개를 묶어 게이트_2 한 번으로 검증한다. 커밋마다 실기하면 회귀 지점이 즉시 갈리지만 은수님 부담이 3배가 된다.

**보완**: 트레이드오프를 명시하고, **중단_3(이분 탐색)이 그 대가**임을 계획에 기록한다. 커밋을 되돌릴 수 있도록 각 커밋이 독립 빌드 가능함을 보장한다(이미 §3.3~3.6 이 그렇게 설계됨).

### 결함_3 (경미) - `Debug/` 갱신 스크립트 위치 미지정

`Debug/` 는 gitignore 라 스크립트를 repo 에 두면 산출물과 분리된다.

**보완**: 스크립트는 **세션 임시 영역**(`$CLAUDE_JOB_DIR/tmp`)에 두고 커밋하지 않는다. 갱신 내용 자체는 `.cproject` 에 정본이 있으므로 재현 가능하다. `구현-검증.md` 에 스크립트 전문을 첨부해 추적성을 남긴다.

### 결함_4 (경미) - 로그 문구의 파일명 표시 변화 미확인

`TDC_PRINTF_E` 는 `__SHORT_FILE__`(basename)을 출력하므로 폴더가 바뀌어도 **표시는 `tdc_ble_mapping.c` 로 동일**할 것이 논리적으로 명확하다(`strrchr` 로 마지막 구분자 뒤를 취함). 다만 계획에 확인 항목으로 없다.

**보완**: 게이트_2 의 확인 항목에 "로그의 파일명 표시가 이전과 동일" 을 추가한다. 로그 7종 대조에 자연히 포함되나 명시하는 편이 안전하다.

### 결함_5 (경미) - `.cproject` 커밋 시 무관 변경 혼입 가능성

Eclipse 가 `.cproject` 를 자동 갱신하므로 이전 세션 잔여 변경이 섞일 수 있다.

**보완**: 1a-7 커밋 전 `git diff .cproject` 로 **추가된 `-I` 3줄 외 변경이 없음**을 확인한다.

## 5. 잔여 위험 (승인 시 은수님께 전달)

| # | 위험 | 성격 |

| 잔여_1 | 정식 빌드 크기가 `__FILE__` 문자열분만큼 증가 | **불가피**. 예상 15~30바이트 수준. 동작 무영향 |
| 잔여_2 | `en__allParameter` 401줄 함수가 남음 | 판단_1 의 의도적 선택. 근인_1 완전 해소는 설계안 단계_3 소관 |
