## 4. 발견 결함

### 결함_1 (중대) - `.elf` 바이트 동일의 성립 가능성이 검증되지 않았다

수용_1a_2 는 설계안 §3 단계_1a 의 "**`.elf` 바이트 동일**" 을 그대로 옮겼다. 그러나 `.elf` 에는 **DWARF 디버그 섹션이 포함**되고, 디버그 정보에는 컴파일 단위의 소스 경로(`DW_AT_name`·`DW_AT_comp_dir`)가 문자열로 박힌다. 폴더가 `ble/` -> `ble/mapping/` 으로 바뀌면 **이 문자열이 바뀌므로 `.elf` 는 바이트 동일이 될 수 없다.**

| 비교 대상 | 경로 변경 영향 | 적합성 |
|---|---|---|
| `.elf` 전체 | 디버그 섹션 경로 문자열 변동 | **부적합 가능성 높음** |
| `.text`/`.data`/`.rodata` 섹션 덤프 | 영향 없음(`__FILE__` 미사용 전제) | **적합** |
| `objcopy -O binary` 산출 `.bin` | 동 | **적합** |
| `arm-none-eabi-size` 수치 | 동 | 보조 지표 |

**조치**: ③ 분석에서 (가) 현 빌드의 디버그 정보 포함 여부, (나) `__FILE__`/`__BASE_FILE__` 사용 여부, (다) 적합한 비교 대상을 확정하고 수용_1a_2 를 재정의한다. 미결_6 을 이 내용으로 확장한다.

### 결함_2 (경미) - 목표_1·3·4 에 대응하는 정량 수용 기준이 없다

목표_3 은 "유의미하게 감소"라는 모호한 표현을 쓴다. ⑤ 계획에서 정량 기준(예: 단일 함수 최대 300줄 이하, 파일당 최대 900줄 이하)을 확정한다.

### 결함_3 (경미) - 미결_2 에 헤더명 전역 유일 확인이 빠졌다

단계_1b 는 신규 헤더 3개(`tdc_ble_map_flash.h`·`tdc_ble_map_measure.h`·`tdc_ble_map_stim.h`)를 만든다. 제약_5 에 규칙은 있으나 미결 항목으로 등록되지 않아 ③ 분석에서 누락될 수 있다. 미결_2 에 편입한다.
