# 분석 - ble 폴더 개편

**TL;DR**: 미결 6건을 전부 실측으로 해소했다. **핵심은 세 가지** — ① 설계안의 "`.elf` 바이트 동일"은 **그대로는 성립하지 않는다**(경로가 `__FILE__` 로 바이너리에 박힘, 실측 +8바이트). 단 **`-ffile-prefix-map` 으로 완전 중화되어 md5 가 일치**함을 실증했다. ② `system/` 폴더에 넣을 파일이 **없다**(0x30~0x36 은 `tdc_ble_communication.c` 내부). ③ 설계안의 `mapping/` 3분할 분류는 **명령 5개(0x6B·0x6E·0x6F·0x70·0x71)를 누락**해 재분류가 필요하다.

## 1. 검증 체계 분석 (최우선)

### 1.1 빌드 재현성 - 성립

CLI 빌드는 `make SHELL=cmd all` 로 성립한다(`-Dchess_storage(a)=` 의 괄호를 sh 가 파싱하지 못해 `SHELL=cmd` 가 필수).

| 항목 | 값 |
|---|---|
| 툴체인 | GNU Arm Embedded 10-2020-q4-major (gcc 10.2.1) |
| make | `<SDK>\arm_tools\bin\make.exe` |
| 베이스라인 크기 | text 184,144 / data 4,668 / bss 21,804 (인수인계 §1 과 일치) |
| `.elf` md5 (빌드 1) | `72025FA766AFDDF7E21F0EC29D3CAE64` |
| `.elf` md5 (clean 후 빌드 2) | `72025FA766AFDDF7E21F0EC29D3CAE64` |

**동일 소스를 clean 후 재빌드해도 `.elf` 가 바이트 동일**하다. 타임스탬프·빌드 ID 가 박히지 않는다는 뜻이며, 바이트 동일 비교의 **전제 조건이 성립**한다.

### 1.2 경로가 바이너리에 박힌다 - 요구사항 결함_1 확정

`util/tdc_printf.h:28` 이 `__FILE__` 을 쓴다.

```c
#define __SHORT_FILE__ (strrchr(__FILE__, '/') ? ... : __FILE__)
```

이것이 `TDC_PRINTF_E`(`tdc_printf.h:36`)에서 확장되고, `TDC_PRINTF_INTERFACE == SEGGER_RTT`·`TDC_PRINTF_ENABLE_ERROR == 1` 이라 **활성 상태**다. 런타임에 `strrchr` 로 basename 만 뽑아 쓰지만, **`__FILE__` 문자열 전체가 `.rodata` 에 박힌다.**

이동 대상 파일의 `TDC_PRINTF_E` 사용:

| 파일 | 건수 | 이동 여부 | `__FILE__` 영향 |
|---|---|---|---|
| `tdc_ble_mapping.c` | 2 | `mapping/` 으로 이동 | **있음** |
| `tdc_ble_remote.c` | 7 | `remote/` 로 이동 | **있음** |
| `tdc_ble_communication.c` | 1 | 루트 유지 | 없음 |
| `tdc_ble_gain_control.c` | 0 | `sound1/` 로 이동 | 없음 |
| `tdc_ble_general_debug.c` | 0 | `sound1/` 로 이동 | 없음 |
| `tdc_ble_remote_sp_para.c` | 0 | `remote/` 로 이동 | 없음 |

### 1.3 실증 - 경로 변경의 영향과 중화

`tdc_ble_mapping.c` 를 임시 하위 폴더(`ble/probe/`)에 복사해 네 조건으로 컴파일하고 오브젝트를 대조했다(실험 후 폴더 삭제 완료).

| 조건 | 경로 | `-ffile-prefix-map` | md5 | 크기 |
|---|---|---|---|---|
| A | `../source/ble/` | 없음 | `897D60B292A310444C4CB8F139512A17` | 20,904 |
| B | `../source/ble/probe/` | 없음 | `1576A2BA02BBB4EACD77C0768B8490B6` | 20,912 |
| C | `../source/ble/` | `=../source/ble/=` | `0454F23F183841FAD699190E87A40489` | 20,888 |
| D | `../source/ble/probe/` | `=../source/ble/probe/=` | `0454F23F183841FAD699190E87A40489` | 20,888 |

**판정 3건**

| # | 판정 | 근거 |
|---|---|---|
| 판정_1 | **경로가 바뀌면 오브젝트가 달라진다** | A != B, 크기 +8바이트 |
| 판정_2 | **`-ffile-prefix-map` 으로 완전히 중화된다** | C == D (md5·크기 모두 동일) |
| 판정_3 | 플래그는 오히려 산출물을 줄인다 | C(20,888) < A(20,904). 경로 접두어가 사라진 만큼 |

> [!IMPORTANT]
> **`-ffile-prefix-map` 은 GCC 8+ 옵션이고 툴체인이 10.2.1 이라 사용 가능**하다(`--help=common` 으로 지원 확인). `-fdebug-prefix-map`(디버그 정보)과 `-fmacro-prefix-map`(`__FILE__`)을 동시에 적용하므로 `.elf` 전체 바이트 동일 비교에 적합하다.

### 1.4 검증 전략 확정

수용_1a_2 를 다음으로 **재정의**한다.

| 구분 | 방법 | 목적 |
|---|---|---|
| **주 검증** | 이동 전/후 빌드에 **각 폴더별 `-ffile-prefix-map` 을 걸어** 경로를 basename 으로 정규화한 뒤 `.elf` md5 비교 | **바이트 동일 확증** |
| 부 검증 | 플래그 없는 정식 빌드끼리 `arm-none-eabi-size` 비교 | 예상 증가분과 실제 증가분 대조 |
| 보조 | `arm-none-eabi-nm -n -S` 심볼 배치 대조 | 배치 변동 확인 |

**예상 부작용**: 플래그 없는 정식 빌드에서는 `__FILE__` 문자열이 길어져 `.rodata` 가 **소폭 증가**한다(`mapping/` 8자 + `remote/` 7자 + 정렬). 이는 이동의 **불가피한 귀결**이며 동작에는 영향이 없다. 실측치는 ⑦ 구현에서 확정한다.

> [!NOTE]
> `-ffile-prefix-map` 을 **상시 적용**하면 `.rodata` 가 오히려 줄어드는 부수 이득이 있으나(판정_3), 로그 출력 내용이 바뀌지 않음을 별도 확인해야 하고 범위 밖이므로 **이번 작업에서는 검증 전용으로만 쓴다.**

## 2. 빌드 설정 분석

### 2.1 include 규약 - 미결_3 해소

프로젝트 전체가 **flat include** 규약이다. `ble` 헤더 참조 47건 전부가 경로 없는 `#include <파일명.h>` 형태다.

| 예 | 위치 |
|---|---|
| `#include <tdc_ble_mapping.h>` | `hal/tdc_hal_spi.c:7`·`isd/tdc_isd.c:18`·`main.c:18`·`sys/tdc_sys_init.c:31` |
| `#include <tdc_ble_protocol.h>` | `cfx_link/tdc_shm.c:5`·`dfu/tdc_dfu_ble_boot.h:15` |

**결론**: 파일을 하위 폴더로 옮겨도 **소스의 include 문은 한 줄도 고칠 필요가 없다.** `-I` 에 새 폴더만 등록하면 된다. 이는 `.elf` 바이트 동일 검증에 유리한 조건이다(소스 무변경).

### 2.2 `.cproject` - 미결_4 해소

| 대상 | 위치 | 현황 | 조치 |
|---|---|---|---|
| C 컴파일러 `-I` | `.cproject:60-83` (22개 항목) | `source/ble` 는 `:69` | **신규 폴더 3개 추가 필요** |
| 어셈블러 `-I` | `.cproject:48-50` (1개 항목) | `source/lib/SEGGER_RTT` **만** 등록 | **불필요** |

> [!IMPORTANT]
> **함정_1(어셈블러 `-I` 등록)은 이번 작업에 해당하지 않는다.** 어셈블러 include 목록에 `ble` 가 애초에 없고, 어셈블리 소스는 SEGGER_RTT 계열뿐이라 `ble` 헤더를 참조하지 않는다. 2026-07-22 선례는 다른 폴더 사례다. **단 판단 근거를 기록으로 남기고, 빌드 실패 시 최우선 의심 대상으로 유지한다.**

### 2.3 `Debug/` 빌드 산출물 - 중요 제약

| 사실 | 함의 |
|---|---|
| `Debug/` 전체가 gitignore (`src/2__cm3/.gitignore:2`) | **`subdir.mk` 수정분은 커밋되지 않는다** |
| `subdir.mk` 20개 **전부**가 `-I "...\source\ble"` 를 하드코딩 | 신규 폴더 3개 x 20파일 = **60곳 추가** 필요 |
| `Debug/makefile` 이 `-include source/<폴더>/subdir.mk` 를 나열 | 신규 3줄 추가 필요 |
| `Debug/sources.mk` 의 `SUBDIRS` 목록 | 신규 3줄 추가 필요 |
| 모든 파일 머리에 "Automatically-generated file. Do not edit!" | Eclipse 가 `.cproject` 기준으로 재생성 |

**결론**: CLI 검증을 위해서는 `Debug/` 하위 파일을 **스크립트로 일괄 갱신**해야 한다. 이는 **로컬 검증 전용**이고, 정본은 `.cproject` 다. 은수님이 Eclipse 에서 Clean+Build 하면 `.cproject` 기준으로 재생성된다.

| 명령 | 처리 위치 |

### 3.5 파일 경계를 넘는 상태 - 미결_5 해소 (**최대 난점**)

파일 스코프 static 2개 외에 **`fetch_packet` 함수 지역 static 4개**가 더 있다. 함수를 분할하면 이들이 파일 경계를 넘는다.

| 심볼 | 선언 | 종류 | 사용 그룹 | 분할 시 대응 |
|---|---|---|---|---|
| `mappingPacket` | `:24` | 파일 static | **전 그룹** | 접근자 `tdc_ble_mapping_get_packet()`(`:45`) **기존재** |
| `writingStartSlot_index` | `:50` | 파일 static | flash (`:1743`·`:1752` = 0x70·0x71) | `map_flash.c` 로 **이관** |
| **`prev_subCommandData_Num_index`** | `:58` | 함수 static | **잔류·stim·flash 3그룹** | **접근자 신설 필요** |
| `max_C_uA` / `min_T_uA` | `:61` | 함수 static | stim 전용 (`:828`~`:862`, 0x66 내부) | `map_stim.c` 로 이관 |
| `stimulPara_index` | `:72` | 함수 static | flash 전용 (`:984`·`:1180`·`:1459`~`:1509`) | `map_flash.c` 로 이관 |

**`prev_subCommandData_Num_index` 사용 분포 (전수 23곳)**

| 그룹 | 라인 | 건수 |
|---|---|---|
| 잔류(0x60) | 119 | 1 (리셋만) |
| stim(0x66) | 349·352·356·360·695·712 | 6 |
| flash | 975·978·983·988·1122·1171·1174·1179·1184·1376·1429·1432·1436·1440·1692 | 15 |

성격은 **"데이터 인덱스 연속성 검사 카운터"** 다(`:352` `if (subCommandData_Num_index != prev_subCommandData_Num_index + 1)`). 여러 패킷에 걸쳐 도착하는 데이터 인덱스가 1씩 증가하는지 검사하고, 어긋나면 0 으로 리셋한다.

> [!CAUTION]
> **이 심볼이 단계_1b 의 최대 난점이다.** 3개 그룹이 공유하는 **가변 상태**이므로 파일을 나누면 반드시 노출해야 한다. 값 하나라도 타이밍이 어긋나면 **멀티 패킷 명령(0x66 하위 1, 0x68, 0x6C, 0x6D)이 조용히 깨진다** - 컴파일러가 잡아주지 않는 종류의 회귀다.

**대응 후보**

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| 안_가 | `mappingPacket` 과 같이 **접근자 함수** 신설 (`tdc_ble_mapping_get/set_seq_index()`) | 기존 패턴 재사용, 캡슐화 유지 | 호출 오버헤드 |
| 안_나 | 파일 static 을 non-static 전역 + `extern` | 단순 | 링키지 변경, 전역 노출 |
| 안_다 | 파싱 컨텍스트 구조체로 묶어 포인터 전달 | 가장 깨끗 | 시그니처 대폭 변경, 이 단계에는 과함 |

**안_가 를 권고**한다 - `tdc_ble_mapping_get_packet()` 으로 이미 확립된 패턴이고, 설계안 원칙_6(되돌릴 수 있는 크기)에 맞는다.

> [!NOTE]
> 설계안 §3 단계_1b 위험 표는 "전역 `mappingPacket` 이 파일 경계를 넘음 -> `extern` 유지"라고 적었으나, **실제로는 `static`(파일 지역)이라 `extern` 이 애초에 성립하지 않는다.** 또한 설계안은 **함수 지역 static 4개의 존재를 인지하지 못했다.** 실제 난도는 설계안 서술보다 높다.

### 3.6 헤더명 전역 유일 - 요구사항 결함_3 해소

신규 헤더 3개(`tdc_ble_map_flash.h`·`tdc_ble_map_measure.h`·`tdc_ble_map_stim.h`)와 충돌하는 파일은 **없다**. 프로젝트 내 `map` 포함 헤더는 `electrodeMapping.h`·`tdc_ble_mapping.h`·`tdc_fs_map.h`·`tdc_isd_map_{data,ecap,impedance,live,specific_stim}.h` 이며, `tdc_ble_map_*` 는 미사용 이름이다.

> [!NOTE]
> `tdc_isd_map_*` 와 이름이 유사하다. 혼동 방지를 위해 `ble` 접두를 유지한 `tdc_ble_map_*` 로 확정한다.
