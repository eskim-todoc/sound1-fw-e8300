## 2. 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| 결정_1 | **`system/` 폴더를 만들지 않는다** | 0x30~0x36 처리가 전부 `tdc_ble_communication.c`(루트 유지) 안에 있어 넣을 파일이 없음. 분석 §3.1 |
| 결정_2 | **설계안의 `mapping/` 3분할 분류를 재분류** - 0x6B·0x6E·0x6F·0x70·0x71 를 flash 그룹에 추가 | 설계안 §3 단계_1b 목록이 명령 5개를 누락. 분석 §3.2 |
| 결정_3 | **`-ffile-prefix-map` 을 검증 전용으로 사용** (상시 적용은 범위 밖) | 경로가 `__FILE__` 로 바이너리에 박혀 바이트 동일이 깨지는 것을 중화. 분석 §1.3 |
| 결정_4 | 0x66 은 **하위 명령 8개까지만** 함수 추출, 데이터 인덱스 재분해는 이월 | 3단 분해는 라이브 상태 로직에 근접해 위험. 계획 판단_1 |
| 결정_5 | `prev_subCommandData_Num_index` 는 **접근자 함수**로 노출 | `tdc_ble_mapping_get_packet()` 로 확립된 기존 패턴. 계획 판단_4 |

## 3. 이슈

| # | 이슈 | 처리 |
|---|---|---|
| 이슈_1 | CLI 빌드가 sh 에서 `-Dchess_storage(a)=` 괄호 파싱 실패 | `make SHELL=cmd all` 로 해결. 인수인계 §4 보조에 추가 예정 |
| 이슈_2 | 설계안이 **함수 지역 static 4개의 존재를 인지하지 못함** | 분석 §3.5 에서 전수 조사해 반영. `prev_subCommandData_Num_index` 가 3그룹 공유 - 단계_1b 최대 난점 |
| 이슈_3 | 설계안의 "`.elf` 바이트 동일"이 그대로는 불성립 | 결정_3 으로 해소 |
| 이슈_4 | 1a 첫 대조 FAIL (크기 동일, md5 불일치) | 원인은 **링크 순서**. 폴더 분할로 오브젝트 나열이 바뀌어 섹션 배치가 밀렸다. 순서를 맞추자 바이트 동일 성립 |
| 이슈_5 | **`__LINE__` 이 에러 응답으로 앱에 전송된다**(`tdc_sys_error.c:168-169`) | 함수 추출로 값이 바뀐다. 에러 분류는 major/minor 가 담당하고 라인은 위치 표시용이라 수용. 실기 대조 시 해당 2바이트 제외 |
| 이슈_6 | 1b-3b 어셈블리 대조가 무효였음 | PowerShell `Copy-Item` 이 타임스탬프를 보존해 `make` 가 재컴파일을 스킵. 섹션 수(2 vs 10)로 발각하고 `.o` 삭제 + `touch` 후 재측정 |
