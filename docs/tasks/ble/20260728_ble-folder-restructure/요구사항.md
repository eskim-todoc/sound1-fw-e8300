# 요구사항 - ble 폴더 개편

**TL;DR**: `src/2__cm3/source/ble/` 13파일(5,071줄)을 **프로토콜 헤더 그룹별 하위 폴더로 개편**하고(단계_1a, `.elf` 바이트 동일로 검증), 이어서 **`fetch_packet`(1,724줄)의 case 블록을 명령별 static 함수로 추출**해 `mapping/` 을 기능별 3파일로 분할한다(단계_1b, 4중 검증). **동작 보존이 절대 기준**이며 프로토콜 규약·`isd/` 역결합은 건드리지 않는다.

## 1. 배경

2026-07-27 BLE 프로토콜 구조 분석([`20260727_ble-protocol-restructure`](../20260727_ble-protocol-restructure/))이 복잡도 근인 3건을 규명하고 6단계 로드맵을 설계했다. 그중 **단계_0(결함 트랙)은 2026-07-28 에 3건 수정으로 처리**됐고([`20260727_ble-8bit-packet-redesign`](../20260727_ble-8bit-packet-redesign/) 병합 `d624ffe`), 다음 순위가 단계_1a·1b 다.

근인 3건 중 이 작업이 겨냥하는 것은 **근인_1 "함수 분해 부재"** 다.

| 근인 | 실태 | 이 작업의 소관 |
|---|---|---|
| 근인_1 함수 분해 부재 | `tdc_ble_mapping.c` 함수 6개, `fetch_packet` 1,724줄(78%) | **소관 (단계_1b)** |
| 근인_2 라이브 상태 4층 분산 | 층간 관계가 코드에 미명시 | 소관 밖 (단계_4) |
| 근인_3 파서가 자극 FSM tick 겸함 | `tdc_ble_mapping_step()` 이 `isd/` 4종 직접 구동 | 소관 밖 (단계_5) |

## 2. 목표

| # | 목표 | 측정 |
|---|---|---|
| 목표_1 | `ble/` 파일을 프로토콜 헤더 그룹별 폴더로 정리 | 목표 구조(§3.1)와 실제 트리 일치 |
| 목표_2 | 파일 이동이 **바이너리에 아무 영향을 주지 않음**을 확증 | `.elf` 바이트 동일(md5) |

## 3. 범위

### 3.1 단계_1a - 파일 이동 (In Scope)

목표 구조 (설계안 §3 단계_1a 원본):

```
src/2__cm3/source/ble/
├── tdc_ble_communication.c/.h      디스패치 (루트 유지)
├── tdc_ble_protocol.h              프로토콜 정의 (루트 유지, 불가침)
├── system/                         Ezairo_BT_30 (0x30~0x36)
├── remote/                         통신 프로토콜_40 (0x40~0x59)
│   ├── tdc_ble_remote.c/.h
│   └── tdc_ble_remote_sp_para.c/.h
├── mapping/                        매핑 프로토콜_60 (0x60~0x72, 0x91)
│   └── tdc_ble_mapping.c/.h
└── sound1/                         SOUND1_80 (0x8C·0x8F)
    ├── tdc_ble_gain_control.c/.h
    └── tdc_ble_general_debug.c/.h
```

> [!NOTE]
> **`system/` 에 넣을 파일이 설계안에 명시돼 있지 않다.** 0x30~0x36 처리 위치를 단계 ③ 분석에서 확인해 (가) 해당 파일을 옮기거나 (나) 빈 폴더를 만들지 않거나를 결정한다. — 미결_1

## 5. 수용 기준

### 5.1 단계_1a

| # | 기준 | 방법 |
|---|---|---|
| 수용_1a_1 | 빌드 에러 0 · 경고 0 | `make all` |
| 수용_1a_2 | **`.elf` 바이트 동일** | 이동 전후 md5 비교 (라인 보존 대조본 기법) |
| 수용_1a_3 | 파일 히스토리 보존 | `git log --follow` 로 확인 |
| 수용_1a_4 | Eclipse 빌드도 성립 | 은수님 게이트 |

> [!IMPORTANT]
> **`.elf` 바이트 동일이 성립하려면 파일 내용이 1바이트도 바뀌면 안 된다.** include 경로 수정이 필요해지면 그 자체가 내용 변경이므로, flat include 규약 덕에 수정이 불필요함을 ③ 분석에서 먼저 확증해야 한다. — 미결_3

### 5.2 단계_1b

| # | 기준 | 방법 |
|---|---|---|
| 수용_1b_1 | 빌드 에러 0 · 경고 0 | `make all` |
| 수용_1b_2 | **디스어셈블 대조** - 니모닉·호출 시퀀스·분기 구조 함수 단위 비교 | `arm-none-eabi-objdump` |
| 수용_1b_3 | **추출 함수 입출력 계약 표** 작성 후 누락 확인 | 문서 산출 |
| 수용_1b_4 | 브레이스 균형·전처리 깊이 검산 | 스크립트 검산 |
| 수용_1b_5 | **로그 7종 전 시나리오 재현** - 응답 바이트열·로그 문구 완전 일치 | 은수님 실기 게이트 |
| 수용_1b_6 | 크기 회귀 없음 (text/data/bss) | `arm-none-eabi-size` |

> [!CAUTION]
> **단계_1b 는 `.elf` 바이트 동일이 성립하지 않는다.** 함수 추출은 인라인 여부·레지스터 할당·호출 규약을 바꾼다. 크기 증감만으로 판단해서는 안 되며(`__LINE__` 이동만으로도 명령 길이가 바뀐다), 디스어셈블 구조 대조가 필요하다.
