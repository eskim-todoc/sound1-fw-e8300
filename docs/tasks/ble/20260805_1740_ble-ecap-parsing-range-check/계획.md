# 계획 - 0x63·0x64 eCAP 파싱 범위 검사

**TL;DR**: 3커밋(0x63 → 0x64 → 문서). 코드는 0x65 의 **평탄 플래그 방식**을 이식하고, 검증은 «정상 경로 불변 + 예측된 분기만 증가» 불변량으로 **`if` +19 · `||` +15 · `else` +2 · `&&` 불변 · `return` 불변 · `fetched_command=` 불변** 6지표를 사전에 못 박는다. 실기가 불가하므로 **호스트 테스트가 유일한 과잉 차단 검출 수단**이다.

## 1. 커밋 분해

| # | 커밋 | 내용 | 자족성 |
|---|---|---|---|
| 커밋_1 | `Fix(ble): 0x63 eCAP 마스킹 파싱 범위 검사 추가 (위험_1)` | `_ecap_masking()` 9블록 + 테스트 | 빌드·테스트 통과 |
| 커밋_2 | `Fix(ble): 0x64 eCAP 교대 파싱 범위 검사 추가 (위험_2)` | `_ecap_alternative()` 6블록 + 테스트 | 동 |
| 커밋_3 | `Docs(ble): eCAP 범위 검사 반영 - 대장·카탈로그·헤더 주석` | 문서 4종 | 문서만 |

> [!NOTE]
> **테스트 선행 커밋을 두지 않는다.** 단계_3 은 «기존 코드로 통과하는 안전망» 을 먼저 깔 수 있었지만, 이번 테스트는 **신설 동작을 단언**하므로 코드 없이는 통과할 수 없다. 대신 커밋마다 코드와 테스트를 함께 넣어 각 커밋이 자족하게 한다.

## 2. 코드 형태

### 2.1 0x65 평탄 방식 이식 (분석 §5)

```c
    bool dataRangeError = false;

    // <필드 한글 이름>
    if ((p_mappingPacket->eCapMeasurement.<필드> < <하한>)      // <하한> 미만
        || (<상한> < p_mappingPacket->eCapMeasurement.<필드>))  // <상한> 초과 시 에러
    {
        dataRangeError = true;
    }
    ...
    if (dataRangeError)
    {
        // 데이터 범위를 벗어남
        tdc_sys_error_send_to_app(en__mapping_eCAP_Measurement_masking, en__EN__BLE_PROTOCOL_ERROR, en__OutOfDataRange, __LINE__);
    }
    else
    {
        p_mappingPacket->fetched_command = en__mapping_eCAP_Measurement_masking;
    }
```

바이폴라 기준전극만 0x65 `:83~90` 의 **99 예외 형태**를 그대로 쓴다(제약_7).

### 2.2 의도적으로 따르지 않는 것

| 0x65 의 것 | 이번 처리 | 이유 |
|---|---|---|
| `:45` 의 `dataRangeError = false;` 재대입 | **생략** | `:30` 선언 시 초기화와 중복. 군더더기를 복제하지 않는다 |
| 공통 헬퍼 함수 추출 | **하지 않음** | 은수님이 0x65 의 8블록을 *"필드 하나 + 한글 주석으로 이미 읽힌다"* 며 유지 결정. 같은 기준을 적용 |
| 상수명(`FPGA_pulsePhaseWidth_minimum`) 사용 | **리터럴 13** | 파싱 계층이 보드 헤더에 의존하게 된다. 근거는 주석으로 남긴다 (분석-검증 승격_1) |

### 2.3 include

`<stdbool.h>` 를 명시 추가한다. 현재는 `tdc_ble_mapping.h:4` 를 통해 전이적으로만 들어온다.

## 3. 검사 블록 확정

### 3.1 0x63 `_ecap_masking()` - 9블록

| 순서 | 필드 | 조건 | 주석 |
|---|---|---|---|
| 1 | `iterationNum` | `< 1 \|\| 255 <` | 측정 반복 횟수 |
| 2 | `pulseWidth` | `< 13 \|\| 255 <` | 펄스 위상 폭 (13 = FPGA 최소 펄스폭) |
| 3 | `firstPulsePhase` | `< 0 \|\| 1 <` | 선행 펄스 위상 |
| 4 | `stimulatonMode` | `< 1 \|\| 6 <` | 자극 모드 |
| 5 | `stimulationElectrodeNum` | `< 1 \|\| 32 <` | 자극 전극 번호 |
| 6 | `bipolarReferenceElectrodeNum` | `< 1 \|\| 32 <` + `!= 99` 예외 | 바이폴라 기준전극 |
| 7 | `measurementElectrodeNum` | `< 1 \|\| 32 <` | 측정 전극 번호 |
| 8 | `adcSamplingFreq` | `< 0 \|\| 7 <` | ADC 샘플링 주파수 (레지스터 3비트) |
| 9 | `adcMeasurementDelay` | `< 0 \|\| 15 <` | 측정 딜레이 (레지스터 4비트) |

### 3.2 0x64 `_ecap_alternative()` - 6블록

순서 1·2·4·5·6·7 과 동일 (0x64 는 `firstPulsePhase`·adc\* 를 파싱하지 않음).

## 4. 테스트 설계

### 4.1 헬퍼 신설

0x62 의 `make_impedance_ok()` 패턴에 맞춰 `make_ecap_masking_ok()` · `make_ecap_alternative_ok()` 를 만든다. 기존 인라인 패킷 조립(`test_map_measure.c:161~177`)을 헬퍼로 옮긴다.

### 4.2 기존 테스트 값 감사 (수용_2b)

| 필드 | 기존 값 | 신설 범위 | 판정 |
|---|---|---|---|
| `adcSamplingFreq` | **12** (`:175`) | 0~7 | **무효 → 5 로 정정** |
| `adcMeasurementDelay` | 13 (`:176`) | 0~15 | 유효 |
| `stimulatonMode` | 2 (`:165`) | 1~6 | 유효 |
| `pulseWidth` | 25 (`:163`) | 13~255 | 유효 |
| 나머지 0x63 필드 | - | - | 유효 |
| 0x64 전 7필드 | - | - | **전부 유효 — 정정 없음** |

**정정 1건.** 이 값은 스펙이 아니라 필드 구분용 순번(11·12·13·14)이었다.

### 4.3 경계 케이스

| 필드 | 케이스 |
|---|---|
| `iterationNum` | 0 거부 / 1 통과 / 255 통과 |
| `pulseWidth` | 12 거부 / 13 통과 / 255 통과 |
| `firstPulsePhase` | 0 통과 / 1 통과 / 2 거부 |
| `stimulatonMode` | 0 거부 / 1 통과 / 6 통과 / 7 거부 |
| `stimulationElectrodeNum` | 0 거부 / 1 통과 / 32 통과 / 33 거부 |
| `bipolarReferenceElectrodeNum` | 0 거부 / 1 통과 / 32 통과 / 33 거부 / **98 거부** / **99 통과** |
| `measurementElectrodeNum` | 0 거부 / 1 통과 / 32 통과 / 33 거부 |
| `adcSamplingFreq` | 0 통과 / 7 통과 / 8 거부 |
| `adcMeasurementDelay` | 0 통과 / 15 통과 / 16 거부 |

> [!NOTE]
> **`uint8_t` 라 시험 불가한 경계가 있다.** 상한 255 필드는 «상한+1» 을 패킷에 실을 수 없고, 하한 0 필드는 «하한-1» 을 실을 수 없다. 해당 케이스는 설계에서 제외하고 그 사실을 `구현-검증.md` 에 남긴다 (은폐 금지).

### 4.4 OOB 차단 전용 케이스

**255 는 위험_1 의 대표 입력이다.** 두 전극 필드에 255 를 넣어 거부되는지 각각 확인한다 — `electrodeMap[254]` 가 `s_manu_table` 을 침범하던 경로다.

### 4.5 거부 시 부작용 없음

거부된 패킷이 `fetched_command` 를 설정하지 않는지 확인한다. **이것이 `isd/` 도달을 막는 실제 기전**(분석 §1)이므로 반드시 단언한다.

## 5. 검증 지표 예측 (노하우_1 - 방어 추가 불변량)

**기준선** (`tdc_ble_map_measure.c`, 앵커 패턴 실측):

| 지표 | 기준선 | 예측 증분 | 예측값 |
|---|---|---|---|
| `^\s*if \(` | 5 | **+19** (0x63 11 · 0x64 8) | **24** |
| `^\s*else` | 0 | **+2** | **2** |
| `\|\|` (주석행 제외) | 1 | **+15** (0x63 9 · 0x64 6) | **16** |
| `&&` (주석행 제외) | 5 | **0** | **5** |
| `^\s*return` | 1 | **0** | **1** |
| `fetched_command *=` | 3 | **0** | **3** |

**증분 산식**:

| 구성 | `if` | `\|\|` | `else` |
|---|---|---|---|
| 단순 블록 1개 | 1 | 1 | 0 |
| 바이폴라 블록 1개 | 2 | 1 | 0 |
| 말미 판정 1개 | 1 | 0 | 1 |
| **0x63** = 단순 8 + 바이폴라 1 + 말미 1 | **11** | **9** | **1** |
| **0x64** = 단순 5 + 바이폴라 1 + 말미 1 | **8** | **6** | **1** |

> [!IMPORTANT]
> **`&&` 불변 · `return` 불변 · `fetched_command=` 불변이 «0x62 무변경» 의 증거다.** 0x62 는 `&&` 5개와 조기 `return` 1개를 갖는 유일한 함수이므로, 이 셋이 흔들리면 손대지 말아야 할 곳을 건드렸다는 신호다.

> [!CAUTION]
> **지표는 반드시 행 앵커(`^[[:space:]]*`)와 주석행 제외로 측정한다.** 이월_D 에서 `grep -o "case "` 가 주석 속 단어를 세어 거짓 FAIL 을 냈다(노하우_2). 이번 작업은 블록마다 한글 주석을 다는 형태라 같은 함정에 그대로 노출된다.
