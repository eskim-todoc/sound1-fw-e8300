# 계획 검증 - 0x63·0x64 eCAP 파싱 범위 검사

**TL;DR**: 지표 예측 산식을 블록 단위로 재계산해 **`if` 24 · `||` 16 · `else` 2** 를 재확인했다. **결함 1건** — 분석 §4 가 `test_map_measure.c:222~225` 를 «0x63 값 잔류를 고정한 테스트» 로 인용했으나, `stub_reset()` 이 패킷 전체를 0 으로 밀기 때문에 **그 테스트는 잔류를 증명하지 않는다**. 분석을 정정했다. 그 외 죽은 검사 3건은 0x65 대칭을 위해 **의도적으로 유지**한다.

### 보완_1 - 병합 절차 누락

계획 §1 이 커밋 3건만 다루고 병합을 적지 않았다. **커밋 후 `claude_develop` 로 `--no-ff` 병합, 은수님 승인 필수** 를 명시한다. 이번 작업은 실기 게이트가 없으므로 «호스트 테스트 통과 + 지표 일치» 가 승인 근거가 된다.

## 2. 논리 정합

### 결함_3 (해소) - 분석 §4 의 테스트 인용이 틀렸다

**분석 원문**: *"직전 0x63 의 값이 남으며 이는 현재 동작으로 테스트에 고정돼 있다(`test_map_measure.c:222~225`)"*

**반증**: `stub_reset()` 이 매핑 패킷을 통째로 민다.

```c
// tests/unit/stub_ble.c:38~40
void stub_reset(void)
{
    memset(&g_packet, 0, sizeof(g_packet));
```

`make_packet()`(`test_map_measure.c:22`)이 매 케이스마다 이를 호출하므로, `:224` 의 `firstPulsePhase == 0` 은 **0x63 잔류가 아니라 초기화 결과**다. 테스트 주석(`:222~223`) 자체가 *"직전 0x63 의 값이 남는 것이 현재 동작"* 이라 적었으나 실제로 그것을 시험하지 않는다.

| 항목 | 판정 |
|---|---|
| «0x64 는 그 필드들을 파싱하지 않는다» | **참** — `tdc_ble_map_measure.c:93~113` |
| «실기에서 직전 값이 잔류한다» | **참** (전역 구조체, 초기화 없음) |
| «그 잔류를 테스트가 고정한다» | **거짓** — 스텁이 초기화하므로 잔류 상황이 만들어지지 않는다 |

**조치**: 분석 §4 문구를 정정했다. 계획에는 영향 없다 — 0x64 검사 대상을 «파싱하는 7필드» 로 한정한 판단의 근거는 파싱 코드 자체이지 그 테스트가 아니다.

> [!NOTE]
> **기존 테스트 주석의 오류는 이번 범위에서 고치지 않는다.** 테스트 파일을 만지긴 하지만 이 주석 정정은 별건이고, 섞으면 커밋의 의도가 흐려진다. `구현-검증.md` 에 잔여로 남긴다.

### 확인_1 - 죽은 검사 3건을 유지하는 판단

`firstPulsePhase < 0` · `adcSamplingFreq < 0` · `adcMeasurementDelay < 0` 은 **절대 참이 될 수 없다.** 필드는 `int` 이나 대입원이 `uint8_t` 이기 때문이다.

| 선택지 | 판정 |
|---|---|
| 하한 검사 생략 | 0x65 `:62` 가 `firstPulsePhase < 0` 을 갖고 있어 **형태가 어긋난다** |
| **유지 (채택)** | 0x65 와 형태 일치. 필드 폭이 바뀌어도 검사가 살아 있다. 컴파일 경고 없음(`int` 비교) |

블록을 «필드 하나당 하한·상한 한 쌍» 이라는 **한 가지 형태**로 통일하는 것이 눈으로 훑을 때의 이점이고, 그것이 이 프로젝트가 테이블 주도를 기각하며 택한 기준이다.

### 확인_3 - 앵커 패턴이 신규 코드를 정확히 세는가

| 패턴 | 신규 코드에서의 거동 |
|---|---|
| `^[[:space:]]*if \(` | `if ((p_mapping...` 를 잡는다. 중첩 `if` 도 자기 행 선두라 잡힌다 |
| `^[[:space:]]*else` | `else` 단독 행. `} else {` 형태를 쓰지 않으므로 안전 |
| `\|\|` 주석행 제외 | 조건 2행째가 `\|\| (32 < ...)` 로 시작 — 주석행이 아니라 계수됨. 행말 한글 주석에는 `\|\|` 없음 |

**주석 오염 위험 재점검**: 블록마다 한글 주석(`// 1 미만`)을 다는데, 그 안에 `if` · `else` · `||` 가 들어가지 않는다. 다만 **주석에 «if» 를 한글 설명으로 쓰지 않도록** 구현 시 주의한다.

### 확인_4 - 커밋 분해의 자족성

| 커밋 | 빌드 | 호스트 테스트 | 판정 |
|---|---|---|---|
| 커밋_1 (0x63) | 통과 | 통과 (0x63 케이스 신설, 0x64 는 기존 그대로) | 자족 |
| 커밋_2 (0x64) | 통과 | 통과 | 자족 |
| 커밋_3 (문서 + 헤더 주석) | 통과 (주석만) | 통과 | 자족 |

**커밋_1 시점에 0x64 테스트가 깨지지 않는가?** 깨지지 않는다 — 0x64 파싱은 커밋_2 까지 무변경이고, 기존 0x64 단언은 필드 적재만 본다.
