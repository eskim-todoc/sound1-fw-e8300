# 분석 검증 - 0x63·0x64 eCAP 파싱 범위 검사

**TL;DR**: 범위표 14행을 전수 재확인했다. **근거 승격 2건** — `pulseWidth` 하한 13 과 `stimulatonMode` 1~6 은 0x65 에서 «빌려온 리터럴» 이 아니라 **1차 정의에 직접 귀속**된다(`FPGA_pulsePhaseWidth_minimum` 상수 · `EN___STIMULATION_MODE` enum). 판정 오류는 없었고, 전제 1건(`electrodeMap` 32원소)의 직접 근거를 보강했다.

## 1. 지침 준수

| 항목 | 판정 |
|---|---|
| 사실은 `파일:라인` 귀속, 추측 금지 | PASS — 범위표 전 행이 귀속됨. 귀속 불가 5건은 **검사 제외**로 처리 |
| Mermaid 사용 (ASCII 다이어그램 금지) | PASS — §1 흐름도 |
| 한글 라벨 | PASS — `발견_N` · `잔여_N` |
| HW 레지스터 5게이트 | §4 에서 별도 판정 |
| 리팩터링 계층 분해 | 해당 없음 (결함 수정) |

## 2. 논리 정합

| 확인 | 결과 |
|---|---|
| «OOB 벡터 2개» 와 «검사 9블록» 의 불일치가 정당한가 | **정당.** OOB 차단이 목표_1, 비트폭·의미 검증이 목표_2. 9블록 중 2개가 OOB, 7개가 목표_2·형태 일치 |
| 발견_1(bipolar 은 OOB 아님)이 «그래도 검사한다» 와 모순되는가 | **모순 아님.** 검사 이유가 메모리 안전이 아니라 **필드 의미 통일 + 조용한 폴백 방지**임을 명시했다 |
| 발견_2(interval 은 isd 검사 존재)와 제약_3 이 일치하는가 | 일치. 상한이 런타임 값 `numFramePerChannel` 의존이라 파싱 시점 판정 불가 |
| 0x63 9블록 · 0x64 6블록 산술 | **일치.** 0x63 14필드 - 잔여 5 = 9. 0x64 7필드 - 잔여 1 = 6 |
| 0x64 가 파싱 안 하는 필드에 검사를 넣지 않는가 | **넣지 않음.** §4 표가 파싱 7필드로 한정 |
| 차단 기전이 신규가 아닌가 | 신규 아님. `mapping.c:269` 게이트는 0x62·0x65 가 이미 쓰는 것 |

## 3. 근거 검증 - 범위표 전수 재확인

| 필드 | 분석의 근거 | 재확인 | 판정 |
|---|---|---|---|
| `iterationNum` 1~255 | 0x62 `:27~28` | 직접 확인 | PASS |
| `pulseWidth` 13~255 | 0x65 `:55~56` | **근거 승격** → 승격_1 | **개선** |
| `firstPulsePhase` 0~1 | 0x65 `:62~63` | 직접 확인. `isd:905`·`:1129` 가 시프트 피연산자로만 사용 | PASS |
| `stimulatonMode` 1~6 | 0x65 `:69~70` | **근거 승격** → 승격_2 | **개선** |
| `stimulationElectrodeNum` 1~32 | 0x65 `:76~77` + `df_MaxNumOfElectrode` | **전제 보강** → 보강_1 | **개선** |
| `bipolarReferenceElectrodeNum` 1~32/99 | 0x65 `:83~90` | 직접 확인 | PASS |
| `measurementElectrodeNum` 1~32 | `electrodeMap[32]` | 보강_1 | **개선** |
| `adcSamplingFreq` 0~7 | `isd:730~733`·`:764~767` | **두 곳 모두 `<< 3` 확인** | PASS |
| `adcMeasurementDelay` 0~15 | `isd:680~681` | 직접 확인 (`<< 4` + 주석 `[3:0]`) | PASS |
| 잔여 5건 | 근거 없음 | 재확인 — 여전히 없음 | PASS |

### 승격_1 - `pulseWidth` 하한 13 은 상수로 정의돼 있다

분석은 0x65 의 리터럴 `13` 을 차용했으나, **eCAP 자신이 그 상수를 직접 쓴다**.

```c
// board/FPGA_ver2_7_0.h:133
#define FPGA_pulsePhaseWidth_minimum         13 // 최소 펄스폭 크기.

// isd/tdc_isd_map_ecap.c:935 · :1160
w_FPGA_registerValue = (mappingPacket->eCapMeasurement.pulseWidth - FPGA_pulsePhaseWidth_minimum);
```

**13 미만이면 이 뺄셈이 음수**가 되어 FPGA 레지스터 값이 언더플로한다. 즉 하한 13 은 0x65 관례가 아니라 **eCAP 경로 자체의 요구**다.

> [!NOTE]
> 검사식에는 상수명을 쓰지 않고 **0x65 와 동일하게 리터럴 `13`** 을 쓴다. `tdc_ble_map_measure.c` 가 `FPGA_ver2_7_0.h` 를 include 하지 않으므로 상수를 쓰려면 헤더 의존이 새로 생긴다. 파싱 계층이 보드 헤더에 의존하는 것은 결합도 악화다. **근거는 상수, 표현은 리터럴** — 이 관계를 코드 주석에 남긴다.

### 승격_2 - `stimulatonMode` 1~6 은 enum 전체 범위다

```c
// cfx_link/tdc_shm.h:67~76
typedef enum {
    en__referenceNA = 0, en__monopolr_body, en__monopolr_rod,
    en__monopolr_BothRodBody, en__bipolar, en__commonground, en__semi_simultaneously
} EN___STIMULATION_MODE;
```

**1~6 = `en__referenceNA`(0) 를 뺀 실제 모드 전체**다. 0x65 의 `1 <= mode <= 6` 이 이 뜻이었음이 확정된다.

**eCAP 가 6까지 다루는지도 확인했다** — `isd:858~875` 는 모노폴라 3종을 `case` 로 처리하고, `:873` `default` 주석이 *"바이폴라, 공통접지, 동시 자극의 경우는 접지를 끊는다"* 로 **5·6 을 명시적으로 의도**한다. 과잉 차단 위험 없음.

### 보강_1 - `electrodeMap` 32원소의 직접 근거

분석은 `df_MaxNumOfElectrode`(32)를 근거로 들었으나 배열 선언 자체를 인용하지 않았다.

```c
// board/electrodeMapping.c:3
int electrodeMap[32]={31,12,11,9, 7,5,3,1, 0,2,4,6, 8,10,13,15, 17,18,20,22, 24,26,28,30, 14,29,27,25, 23,21,19,16};
```

**원소값이 전부 0~31** 이라는 부수 확인도 얻었다 — 유효 인덱스에서 나온 값은 5비트에 들어가므로, 파싱에서 1~32 를 강제하면 `isd/` 의 `0x1F` 마스크 부재가 **무해해진다**(위험_1 의 «마스크 0건» 지적이 함께 해소된다).

## 4. HW 레지스터 5게이트

레지스터 조합에 쓰이는 값의 범위를 바꾸므로 게이트를 적용한다.

| 게이트 | 판정 |
|---|---|
| ① 대상 식별 | ISD `0x8`(측정 채널) · `0x9`(측정 설정) · `0xA`(딜레이) · `0xB/0xC`(preamp) 와 PCM 몰드의 전극 인덱스 필드 |
| ② 근거 확인 | §3 범위표. 비트폭은 시프트 폭으로 도출, 전극 범위는 배열 선언으로 확정 |
| ③ 전후 시뮬레이션 | **유효 입력에서 레지스터 값 완전 동일** — 검사는 통과만 시키고 값을 변형하지 않는다. 무효 입력은 `isd/` 도달 자체가 없어짐 |
| ④ 부작용 | 무효 입력이 «조용한 오염» 에서 «명시적 에러 응답» 으로 바뀐다. 앱이 0x63 을 안 보내므로 현행 트래픽에 영향 없음 |
| ⑤ 불확실성 | 3건 — 아래 분류 |

### 불확실성 분류 (노하우_4 - «변경 금지 사유인가»)

| 불확실 | 성격 | 변경 금지? |
|---|---|---|
| `adcPreampGain` 의 실제 비트폭 | **변경의 충분성** — 이 필드를 덮을지 말지 | **그렇다** → 검사 제외로 회피. 남은 9블록의 정당성에는 영향 없음 |
| masker·probe 자극 크기 상한 | 동 | 동 → 제외로 회피 |
| 앱이 장차 0x63 을 쓸 것인가 | 결함 발현 빈도 | 아니다 |

**«변경의 충분성» 불확실 2건을 검사 제외로 처리**했으므로, 남은 9블록에는 미확정 요소가 없다. 게이트 통과.
