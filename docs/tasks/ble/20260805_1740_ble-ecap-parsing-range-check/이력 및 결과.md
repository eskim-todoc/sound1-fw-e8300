# 이력 및 결과 - 0x63·0x64 eCAP 파싱 범위 검사

**TL;DR**: [`상시 점검 대장.md §2`](../../../상시%20점검%20대장.md) 의 **위험_1(중)·위험_2(낮음)** 조치. 0x63·0x64 파싱에 범위 검사가 0건이라 `electrodeMap[32]` 를 무검증 `uint8_t` 로 인덱싱하는 경로가 살아 있다. **은수님 선택으로 `isd/` 가 아니라 파싱에 넣는다** — `isd/` 는 호스트 테스트가 닿지 않고 앱이 0x63 을 보내지 않아 실기도 불가하므로, 파싱이 유일하게 검증 가능한 위치다.

## 판단 기록

### 판단_1 - 조치 위치를 `isd/` 에서 파싱으로 바꿨다

인수인계 §4.2 원안은 *"0x65 와 동일 방식"*(= `isd/` 차단)이었다. 불가침 «방어 위치 대칭» 을 따른 것이다. **이를 뒤집었다.**

| 근거 | 내용 |
|---|---|
| 검증 불가 | `isd/` 는 호스트 러너가 컴파일하지 않고(`tests/unit/run.sh:119~121`), 0x63 은 앱이 안 보내(`tdc_ble_protocol.h:91`) 실기도 불가 → **두 게이트 모두 닫힌다** |
| 대칭의 실제 축 | 대칭은 «자극 계열»(0x65·0x66) 규칙이다. **측정 계열은 0x62 가 이미 파싱 차단**(`tdc_ble_map_measure.c:27~53`) — 0x63 을 파싱에서 막아야 측정 계열 3개가 통일된다 |
| 헤더의 자기 기록 | `tdc_ble_protocol.h` 의 매핑 명령이 대부분 `// 확인 완료: ... 범위 외에는 ... 처리` 를 달고 있는데 **0x63·0x64 만 없다** — 누락이 설계가 아님을 헤더가 증언 |
| 테스트의 자기 기록 | `test_map_measure.c:196` 이 `CHECK_EQ("범위 검사가 없어 에러 없음", stub_error_count(), 0)` 로 **현재의 부재를 고정**해 뒀다. 이 줄을 뒤집는 것이 곧 조치의 검증 |
