# 요구사항 - 0x63·0x64 eCAP 파싱 범위 검사

**TL;DR**: 0x63(eCAP 마스킹)·0x64(eCAP 교대) 파싱에 범위 검사를 넣어 `electrodeMap[32]` 범위 밖 접근 경로를 차단한다. **위치는 파싱**(`tdc_ble_map_measure.c`) — `isd/` 는 호스트 테스트·실기 둘 다 닿지 않아 검증할 수 없기 때문이다. 근거가 확실한 필드만 검사하고, 불확실한 필드는 넣지 않고 잔여로 남긴다.

## 1. 배경

[`상시 점검 대장.md §2.2`](../../../상시%20점검%20대장.md) 의 **위험_1(중)** 과 **§2.3 위험_2(낮음)** 이 조사만 되고 미조치 상태다.

`tdc_ble_map_measure_ecap_masking()`(`tdc_ble_map_measure.c:59~91`)과 `tdc_ble_map_measure_ecap_alternative()`(`:93~113`)는 필드를 읽고 곧바로 `fetched_command` 를 설정한다. **범위 검사가 단 한 건도 없다.** 그 값이 `isd/tdc_isd_map_ecap.c` 에서 `electrodeMap[... - 1]` 로 쓰인다.

`Rx_dataPacket[]` 은 `uint8_t` 이므로 **0~255 전 구간**이 그대로 들어온다. 2026-07-30 에 해소한 바이폴라 99 결함(이월_D)은 99 라는 **특정 값**이 통로였으나, 이쪽은 **전 구간**이 통로다.

## 2. 목표

| # | 목표 |
|---|---|
| 목표_1 | 0x63·0x64 파싱에서 **배열 인덱스로 쓰이는 전극번호 필드**를 검사해 범위 밖 접근 경로를 끊는다 |
| 목표_2 | **레지스터 비트폭을 초과하는 필드**를 검사해 인접 비트 오염을 막는다 (바이폴라 99 결함의 뒷단과 같은 실패 유형) |
| 목표_3 | 범위 위반 시 매핑 명령 공통 규약대로 `en__EN__BLE_PROTOCOL_ERROR` · `en__OutOfDataRange` 로 응답하고 `fetched_command` 를 설정하지 않는다 |
| 목표_4 | 조치 결과를 **호스트 테스트로 검증**한다 (실기 불가를 대체) |
| 목표_5 | 상시 점검 대장 §2 에서 위험_1·위험_2 를 «해소» 로 이관한다 |

## 3. 범위

### 3.1 포함

| 대상 | 내용 |
|---|---|
| `tdc_ble_map_measure.c` | `_ecap_masking()` · `_ecap_alternative()` 에 범위 검사 추가 |
| `tests/unit/test_map_measure.c` | 정상 입력 통과 · 경계값 · 위반값 케이스 추가. **`:196` 의 «범위 검사가 없어 에러 없음» 단언을 뒤집는다** |
| 문서 | 상시 점검 대장 · 명령 카탈로그 · `tdc_ble_protocol.h` 주석 · 작업 목록 |

### 3.2 제외

| 대상 | 이유 |
|---|---|
| `isd/tdc_isd_map_ecap.c` | 파싱에서 막으면 `isd/` 는 이미 안전한 값만 받는다. 손대면 검증 불가 구간이 늘어난다 |
| `mapping.c:389` 실행부 주석 처리 | 기능 제거에 해당 — 은수님이 «파싱에 범위 검사» 를 선택했으므로 범위 밖 |
| `mapping.c:403`(0x64 실행부 주석) | 현 상태 유지. 되살리는 것은 별건 |
| 0x62 impedance | 이미 검사 있음. 위험_3(마스크 비대칭)은 별건 |
| 근거가 불확실한 필드 | §4 제약_2 |

## 4. 제약

| # | 제약 |
|---|---|
| 제약_1 | **정상 입력의 동작을 바꾸지 않는다.** 유효 범위 안 값은 검사 추가 전후로 파싱 결과가 동일해야 한다 |
| 제약_2 | **근거 없는 범위를 만들지 않는다.** 상한·하한은 ① 형제 명령(0x62·0x65)의 기존 검사 ② `isd/` 레지스터 비트폭 ③ 상수 정의 중 하나에 `파일:라인` 으로 귀속돼야 한다. 귀속 불가 필드는 **검사하지 않고 잔여로 문서화** |
| 제약_3 | `isd/` 에 **이미 검사가 있는 필드**는 중복해 넣지 않는다 |
| 제약_4 | 기존 매핑 명령의 에러 응답 규약(`tdc_sys_error_send_to_app(..., __LINE__)`)을 따른다 |
| 제약_5 | 소스 주석에 CP949 비호환 문자 금지 (`—` `–` `≈` `µ` `►`) |
| 제약_6 | `src/2__cm3/source/sys/tdc_sys_control.c` 는 건드리지 않는다 (은수님 미커밋 임시 변경 유지 중) |
| 제약_7 | `bipolarReferenceElectrodeNum` 은 0x65 의 검사 형태를 **그대로** 이식한다 — **99 예외 포함**. 같은 이름·같은 의미의 필드를 한쪽만 거부하면 앱이 0x65 관례로 보낼 때 과잉 차단이 된다 ([`요구사항-검증.md` 결함_2](요구사항-검증.md)) |

## 5. 수용 기준

| # | 기준 | 확인 방법 |
|---|---|---|
| 수용_1 | `electrodeMap[]` 인덱스로 쓰이는 필드가 전부 `1 <= n <= 32` 로 제한된다 | 코드 대조 + 호스트 테스트 |
| 수용_2 | **유효 범위 안** 값의 파싱 결과가 검사 추가 전후로 동일하다 | 필드 적재 단언(`test_map_measure.c:181~195`)이 값 정정 후 그대로 통과 |
| 수용_2b | 기존 테스트 패킷의 값이 신설 범위에 유효한지 **전수 감사**하고, 무효 값은 유효 값으로 정정한 뒤 정정 사실을 기록한다 | `구현-검증.md`. **`adcSamplingFreq = 12` 가 이미 무효**임이 확인됨 ([`요구사항-검증.md` 결함_1](요구사항-검증.md)) |
| 수용_3 | 범위 위반 패킷은 `fetched_command` 가 설정되지 않고 에러가 1건 발생한다 | 신규 테스트 |
| 수용_4 | 경계값(하한-1 · 하한 · 상한 · 상한+1)이 전부 의도대로 갈린다 | 신규 테스트 |
| 수용_5 | 호스트 테스트 전체 통과, ARM 빌드 에러 0 · 경고 0 | `bash tests/unit/run.sh` · `make` |
| 수용_6 | 검사 대상 각 필드의 범위 근거가 `파일:라인` 으로 제시된다 | `분석.md` 범위표 |

## 6. 검증 게이트의 특수성

> [!CAUTION]
> **이 작업은 실기로 검증할 수 없다.** `tdc_ble_protocol.h:91~92` 대로 앱이 0x63·0x64 를 보내지 않는다.
>
> 노하우_5 는 *"방어 추가의 실패 모드는 누락이 아니라 **과잉 차단**이고, 정적 지표로는 못 잡으므로 실기 항목에 «정상 입력에서 방어가 걸리지 않을 것» 을 넣어야 덮인다"* 고 못 박았다. **그 항목을 실기에 넣을 수 없으므로 호스트 테스트가 대신해야 한다** — 수용_2·수용_4 가 그 대체물이다.
>
> 이것이 조치 위치를 파싱으로 정한 결정적 이유다. `isd/` 에 넣으면 호스트 테스트도 닿지 않아 **과잉 차단을 검출할 수단이 0 이 된다.**
