# 계획 검증 - 바이폴라 기준전극 99 · 0x65 경로 방어

**TL;DR**: 검증 3축 **전부 PASS**. 편집 전문의 분기 증가분을 **손으로 세어 예측(`if (`+1 · `else`+1 · `||`+3)과 일치**함을 확인했다. CP949 금지 문자 사전 검사에서 **이식 원문의 `→` 1건을 발견**해 ASCII 로 치환하도록 계획에 반영돼 있음을 확인했다. 실기 요청서가 "정상 경로에서 로그가 뜨지 않아야 한다"는 **거짓 양성 검출 항목**을 포함한 것이 적절하다.

## 1. 축_1 - 지침 준수

| 항목 | 판정 | 근거 |
|---|---|---|
| 되돌릴 수 있는 크기 (원칙_6) | **PASS** | 한 파일 3곳. 롤백은 브랜치 되돌리기로 충분 |
| 커밋을 더 쪼개지 않는 근거 제시 | **PASS** | 계획 §1 - 범위 검사만 넣고 마스크를 빼면 무방비 중간 상태가 남는다 |
| 실기 요청서 구체성 | **PASS** | Refresh 필요 여부 · 확인 동작 · **기대 로그** · 대상 작업 구분 |
| 소스 주석 CP949 | **PASS** | §3.3 |
| 라이브 경로 무변경 명시 | **PASS** | 검증_10 |

## 2. 축_2 - 논리 정합성

### 정합_1 - 분기 증가분 예측이 편집 전문과 맞는가

계획 §2.1 의 변경 후 코드를 손으로 센다.

| 지표 | 추가된 것 | 증가 |
|---|---|---|
| `if (` | 범위 검사 `if (` **1개** | **+1** |
| `else` | `else` **1개** | **+1** |
| `\|\|` | 조건 4개를 잇는 `\|\|` **3개** | **+3** |
| `case ` | 없음 | **0** |
| `for (` | 없음 | **0** |
| `&&` | 없음 | **0** |

`case 5` · `case 7` 마스크는 `(0x1F & ...)` 로 **연산자 `&` 1개씩** 추가되나 `&&` 가 아니므로 `&&` 카운트에 잡히지 않는다.

> [!CAUTION]
> **`grep -o "&&"` 가 `0x1F & bipolar...` 를 잡지 않는지 확인이 필요하다.** 단일 `&` 두 개가 인접해야 `&&` 가 되는데, 마스크는 `& ` (뒤에 공백)이라 안전하다. 다만 **검증 시 `&` 단독 카운트도 함께 보면** 마스크 적용을 교차 확인할 수 있다 -> 검증_4 에 보강 권고.

**예측이 편집 전문과 일치한다.**

### 정합_2 - 검증이 완료 기준을 전부 덮는가

| 완료 기준 (요구사항 §5) | 덮는 검증 |
|---|---|
| 기준_1 (마스크 2곳) | 검증_4 |
| 기준_2 (범위 검사 + 대입 건너뜀) | 검증_2 (분기) + 코드 리뷰 |
| 기준_3 (정상 경로 동작 불변) | 검증_1 + 검증_2·3 |
| 기준_4 (라이브와 구조 대칭) | 검증_5 |
| 기준_5 (301 PASS) | 검증_7 |
| 기준_6 (빌드) | 검증_8 |
| 기준_7 (실기) | 검증_11 |

**전부 덮인다.** 추가로 검증_6(크기 증가) · 검증_9(CP949) · 검증_10(라이브 무변경)이 보강이다.

### 정합_3 - 실기 요청서가 거짓 양성을 잡는가

방어 추가에서 가장 위험한 실패는 **과잉 차단**(정상 입력을 거부)이다. 크기·분기 지표로는 잡히지 않는다.

| 실패 유형 | 잡는 항목 |
|---|---|
| 방어가 안 걸림 (누락) | 실기 3번 각주 - 바이폴라+99 에서 로그가 떠야 함 |
| **방어가 과하게 걸림 (거짓 양성)** | **실기 3번 - 정상 바이폴라에서 `OUT OF RANGE` 가 뜨면 안 됨** |
| 정상 경로 회귀 | 실기 2·4·5번 |

**거짓 양성 검출 항목이 명시된 것이 적절하다.** 예: 조건에 `<=` 를 잘못 쓰면 전극번호 32 가 거부되는데, 이는 로그로만 드러난다.

### 정합_4 - 크기 "증가" 를 지표로 쓰는 것이 유효한가

| 관점 | 판단 |
|---|---|
| 필요조건 | **성립** - 방어 코드를 넣으면 반드시 증가한다 |
| 충분조건 | **불성립** - 증가했다고 옳은 방어라는 보장은 없다 |
| 역방향 검출력 | **유효** - **감소하면 뭔가 지워진 것**이므로 사고 신호 |

약한 지표지만 **"감소 = 사고"** 라는 한 방향 검출력이 있어 유지가 정당하다. 주 판정은 검증_2(분기 증가분 정확 일치)가 맡는다.

## 3. 축_3 - 근거 검증

### 3.1 편집 전문의 인용 정확성

| 계획이 인용한 것 | 확인 |
|---|---|
| `para_setting.c:486` 을 이식 원본으로 | 확인 - 범위 검사 블록 시작 |
| `para_setting.c:576` · `:604` 마스크 주석 문구 | 확인 - "비트 [4:0] 범위, 범위 초과한 값 입력시 FIFO 클리어 발생 → 이후 백텔 카운트 0 에러 발생할 수 있음" |

| `df_MaxNumOfElectrode` 를 검사 상한으로 | 확인 - 32, 라이브도 동일 상수 사용 |

### 3.2 "264바이트" 재검산

주석이 *"32원소 배열의 범위를 264바이트 벗어나"* 라고 쓴다.

| 항목 | 값 |
|---|---|
| `electrodeMap[98]` 오프셋 | 98 x 4 = **392바이트** |
| 배열 크기 | 32 x 4 = **128바이트** |
| 초과분 | 392 - 128 = **264바이트** |

**일치.** 주석 수치가 정확하다.

### 3.3 CP949 금지 문자 사전 검사

계획 §2 의 신규 주석·코드에 대해 금지 5종(`—` `–` `≈` `µ` `►`)을 검사했다.

| 항목 | 결과 |
|---|---|
| 신규 주석 (범위 검사 · 마스크) | 금지 문자 **0건** |
| 사용된 비ASCII | 한글 · `[4:0]`(ASCII) | 안전 |
| **이식 원문의 `→`** | **발견** - `para_setting.c:576` 원문에 있다. `→`(U+2192)는 CLAUDE.md 안전 목록에 있으나, 계획이 **ASCII `->` 로 치환**하도록 명시 -> 더 보수적, 적절 |

> [!NOTE]
> `→` 는 CP949 에 존재해 안전하지만, 계획이 ASCII 로 낮춘 것은 **원문과의 문구 동일성**을 약간 희생하는 선택이다. 계획 §2.3 각주가 *"원문의 `→` 만 ASCII `->` 로 바꾼다"* 고 명시해 의도적임을 밝혔으므로 정합적이다.
