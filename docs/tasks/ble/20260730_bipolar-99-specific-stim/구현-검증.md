# 구현 검증 - 바이폴라 기준전극 99 · 0x65 경로 방어

**TL;DR**: 검증_1~10 **전부 PASS**. 분기 증가분이 예측(`if`+1 · `else`+1 · `||`+3, 그 외 불변)과 **6개 지표 정확히 일치**. 크기 **184,908 -> 185,072 (+164B)** 로 예상대로 증가했다. **검증 중 지표 오염을 발견해 측정 방법을 교정**했다 - `grep -o "case "` 가 주석 안의 "case" 언급까지 세어 거짓 FAIL 을 냈다. 실기(검증_11)만 남았다.

### 1.1 분기 증가분 - 앵커 패턴 실측

| 지표 | 패턴 | 기준선 | 현재 | 증가 | 기대 |
|---|---|---|---|---|---|
| `case` 레이블 | `^\s*case ` | 17 | 17 | **0** | 0 |
| `if` 문 | `^\s*if \(` | 21 | 22 | **+1** | +1 |
| `else` | `^\s*else` | 7 | 8 | **+1** | +1 |
| `for` 문 | `^\s*for \(` | 12 | 12 | **0** | 0 |
| `\|\|` (코드 라인) | `\|\|` | 0 | 3 | **+3** | +3 |
| `&&` (코드 라인) | `&&` | 0 | 0 | **0** | 0 |

**6개 전부 예측과 일치.** "정상 경로 불변 + 예측된 분기만 증가" 불변량이 성립했다.

파일 줄 수 **594 -> 627** (+33) - 주석 20줄 + 검사 블록 13줄.

## 2. 발견 - 검증 지표가 주석에 오염됐다

> [!CAUTION]
> **`grep -o "case "` 로 잰 첫 측정이 19 -> 21 로 나와 거짓 FAIL 을 냈다.**

### 2.1 원인

| 위치 | 내용 |
|---|---|
| `:210` (기존) | `// 1 + 6 = 7; case 7로 강제 설정한 뒤,` |
| `:456` (기존) | `// ... 별도의 case 문` |
| **`:238` (신규)** | `* (case 5 - case 7 의 마스크 주석 참조).` <- **2건 추가** |

기준선 "19" 자체가 **실제 `case` 레이블 17 + 주석 언급 2** 였다. 내 주석이 2건을 더해 21 이 됐다.

### 2.2 교정

| 항목 | 잘못된 패턴 | 교정된 패턴 | 결과 |
|---|---|---|---|
| `case` | `grep -o "case "` | `grep -cE "^[[:space:]]*case "` | 17 -> 17 **불변** |
| `if` | `grep -o "if ("` | `grep -cE "^[[:space:]]*if \("` | 21 -> 22 |
| `else` | `grep -o "else"` | `grep -cE "^[[:space:]]*else"` | 7 -> 8 |
| `\|\|` `&&` | 전체 라인 | 주석 라인(`^\s*[/*]`) 제외 | 0 -> 3, 0 -> 0 |

> [!IMPORTANT]
> **주석을 많이 쓰는 변경일수록 문자열 카운트 지표가 오염된다.** 이 프로젝트는 방어 코드에 경위를 길게 남기는 관례가 있어(라이브 경로 `:475~485` 11줄) 특히 취약하다. **구조 지표는 반드시 행 앵커(`^\s*`)로 재야 하고, 연산자는 주석 라인을 제외해야 한다.**
>
> 이전 작업들의 "조건 분기 총수 보존" 검증도 같은 취약점을 가진다 - 다만 그 작업들은 **주석 증감이 없어** 오염이 상쇄됐을 뿐이다. 앞으로 앵커 패턴을 기본으로 쓴다.

### 2.3 계획-검증 결함 2건 처리

| # | 결함 | 처리 |
|---|---|---|
| 결함_1 | 검증_4 가 `0x1F` 문자열만 세어 엉뚱한 위치도 통과 | **보강 적용** - `(0x1F & bipolarReferenceElectrodeNum[i])` **정확 문자열 2건** + 마스크 없는 잔존 `\| bipolarReferenceElectrodeNum[i];` **0건** 을 함께 확인 |
| 결함_2 | 검증_1 판정이 코드 리뷰뿐이라 주관적 | **명시** - 정적 대리 지표는 검증_2·3, **실증은 실기 3번**(정상 바이폴라에서 `OUT OF RANGE` 로그가 뜨지 않을 것) |

## 3. 변경 내용

### 3.1 `case 3` 범위 검사 (신규)

```c
if ((... stimulationElectrodeNum < 1)
    || (df_MaxNumOfElectrode < ... stimulationElectrodeNum)
    || (... bipolarReferenceElectrodeNum < 1)
    || (df_MaxNumOfElectrode < ... bipolarReferenceElectrodeNum))
{
    TDC_PRINTF_I("[SPEC] STIM ELEC NUM : %d, REF ELEC NUM : %d, OUT OF RANGE - USE DUMMY \r\n", ...);
}
else
{
    bipolarReferenceElectrodeNum[electrodeMap[... stimulationElectrodeNum - 1]] =
        electrodeMap[... bipolarReferenceElectrodeNum - 1];
}
```

경위 주석 20줄을 붙였다 - 라이브 경로(11줄)보다 긴 이유는 **침범 대상(`s_tdc_table`)과 실기 로그값 대조**라는 이번에 새로 확정된 근거를 담았기 때문이다.

### 3.2 `case 5` · `case 7` 마스크 (2곳)

```c
// 바이폴러 레퍼런스 전극 번호는 비트 [4:0] 범위, 범위 초과한 값 입력시 FIFO 클리어 발생 -> 이후 백텔 카운트 0 에러 발생할 수 있음
w_isd_registerValue = w_isd_registerValue | (0x1F & bipolarReferenceElectrodeNum[i]);
```

주석 문구는 라이브 경로(`para_setting.c:576` · `:604`)와 **글자까지 동일**하다(원문 `→` 만 ASCII `->`). 두 경로를 대조할 때 차이가 없어야 하기 때문이다.

### 실기가 확증한 것 - 거짓 양성 배제

방어 추가에서 정적 지표로 **잡히지 않는 실패**는 **과잉 차단**이다. 조건 부등호를 잘못 쓰면(`<` 대신 `<=` 등) 정상 전극번호가 거부되는데, 크기·분기 지표는 전부 통과한다.

| 실패 유형 | 정적 검증 | 실기 |
|---|---|---|
| 방어 누락 | 검증_2·4 가 부분 검출 | - |
| **방어 과잉(거짓 양성)** | **못 잡는다** | **항목 3 - 정상 바이폴라에서 `OUT OF RANGE` 없이 자극 정상** |
| 정상 경로 회귀 | 검증_2·3 이 대리 지표 | 항목 2·4·5 |

**항목 3 통과가 검증_1(정상 경로 불변)의 실증**이다. 계획-검증 결함_2 가 *"검증_1 판정이 코드 리뷰뿐이라 주관적"* 이라 지적한 것이 이로써 해소됐다.

> [!NOTE]
> 바이폴라 + 기준전극 **99** 조합(방어가 실제로 걸리는 경우)은 매핑 앱에서 만들 수 없어 확인하지 않았다. 방어 발동 경로는 **미실증**이며, 호스트 테스트도 이 경로를 덮지 않는다(`isd/` 는 테스트 대상 밖). **정상 경로 무영향만 확증된 상태**다 - 이것이 이번 실기의 정확한 범위다.
