# 계획 - 바이폴라 기준전극 99 · 0x65 경로 방어 (이월_D)

**TL;DR**: **2커밋** - 커밋_1 방어 3곳(범위 검사 1 + 마스크 2), 커밋_2 문서. 불변량은 **"정상 경로 불변 + 예측된 분기만 증가"**(`if (` +1 · `else` +1 · `||` +3, 그 외 전부 불변). 편집 전문을 아래에 확정한다.

## 1. 커밋 분해

| # | 커밋 | 내용 |
|---|---|---|
| 커밋_1 | 방어 추가 | `tdc_isd_map_specific_stim.c` - `case 3` 범위 검사 + `case 5`·`case 7` 마스크 |
| 커밋_2 | 문서 | 8단계 산출물 · 이월 갱신 · 카탈로그 주의 문구 정리 |

한 파일 3곳이고 서로 짝을 이루는 방어라 **커밋을 더 쪼개지 않는다.** 범위 검사만 넣고 마스크를 빼면 다른 경로의 범위 밖 값에 무방비이므로, 중간 상태를 남길 이유가 없다.

## 2. 편집 전문

### 2.1 `case 3` 범위 검사 (`:224` 앞)

**현재**

```c
            bipolarReferenceElectrodeNum[electrodeMap[mappingPacket->tdc_isd_map_specific_stim_step.stimulationElectrodeNum - 1]] =  // 코드 길어서 line wrapping
                electrodeMap[mappingPacket->tdc_isd_map_specific_stim_step.bipolarReferenceElectrodeNum - 1];
```

**변경 후**

```c
            /* 전극번호 범위 방어 (2026-07-30 추가).
             * 라이브 경로 tdc_isd_stim_para_setting.c:486 의 방어를 이식한 것이다.
             * 그쪽은 2026-07-27 에 막혔는데 이 경로는 남아 있었다.
             *
             * 매핑 앱은 모노폴라 기준전극을 99 로 보낸다. 0x65 파싱
             * (tdc_ble_cmd_0x65_specific.c:86)이 이를 stimulatonMode 와 무관하게
             * 통과시키므로, 바이폴라 + 99 조합이 여기까지 도달한다.
             * 거르지 않고 electrodeMap[99 - 1] 을 읽으면 32원소 배열의 범위를
             * 264바이트 벗어나 인접 전역(s_tdc_table, ui/tdc_ui_command.c:120)의
             * 포인터 값을 집어온다. 실기 로그의 "REF ELEC NUM : 99 (PCB : 70378)"
             * 이 그 미정의 동작이며 70378 = 0x112EA 는 .text 범위 안 주소다.
             *
             * 그 값이 기준전극으로 레지스터에 실리면 비트 [4:0] 을 넘어 ISD 내부
             * FIFO 클리어를 유발하고 백텔 카운트 0 에러로 이어진다
             * (case 5 - case 7 의 마스크 주석 참조).
             *
             * 바로 위 루프에서 전 원소가 unusedReferenceElectrode_DummyNum(31) 로
             * 초기화되므로, 여기서 건너뛰면 그 더미값이 그대로 유지된다.
             * 자극 전극번호도 함께 검사한다 - 좌변 첨자라 범위 밖이면 쓰기가 된다. */
            if ((mappingPacket->tdc_isd_map_specific_stim_step.stimulationElectrodeNum < 1)                             //
                || (df_MaxNumOfElectrode < mappingPacket->tdc_isd_map_specific_stim_step.stimulationElectrodeNum)       //
                || (mappingPacket->tdc_isd_map_specific_stim_step.bipolarReferenceElectrodeNum < 1)                     //
                || (df_MaxNumOfElectrode < mappingPacket->tdc_isd_map_specific_stim_step.bipolarReferenceElectrodeNum))
            {
                TDC_PRINTF_I("[SPEC] STIM ELEC NUM : %d, REF ELEC NUM : %d, OUT OF RANGE - USE DUMMY \r\n",  //
                          mappingPacket->tdc_isd_map_specific_stim_step.stimulationElectrodeNum,
                          mappingPacket->tdc_isd_map_specific_stim_step.bipolarReferenceElectrodeNum);
            }
            else
            {
                bipolarReferenceElectrodeNum[electrodeMap[mappingPacket->tdc_isd_map_specific_stim_step.stimulationElectrodeNum - 1]] =  // 코드 길어서 line wrapping
                    electrodeMap[mappingPacket->tdc_isd_map_specific_stim_step.bipolarReferenceElectrodeNum - 1];
            }
```

### 2.2 `case 5` 마스크 (`:258`)

```c
// 현재
                w_isd_registerValue = w_isd_registerValue | bipolarReferenceElectrodeNum[i];

// 변경 후
                // 바이폴러 레퍼런스 전극 번호는 비트 [4:0] 범위, 범위 초과한 값 입력시 FIFO 클리어 발생 -> 이후 백텔 카운트 0 에러 발생할 수 있음
                w_isd_registerValue = w_isd_registerValue | (0x1F & bipolarReferenceElectrodeNum[i]);
```

### 2.3 `case 7` 마스크 (`:284`)

`case 5` 와 **동일**하게 적용.

> [!NOTE]
> 마스크 주석은 라이브 경로(`para_setting.c:576` · `:604`)의 문구를 **그대로** 쓴다. 같은 사실을 다른 말로 적으면 다음 사람이 두 경로를 대조할 때 차이가 있는 줄 안다. 원문의 `→` 만 ASCII `->` 로 바꾼다.

## 3. 검증 절차

| # | 검증 | 기대 |
|---|---|---|
| 검증_1 | **정상 경로 불변** (주 불변량) | 0~31 입력에서 `0x1F & v == v`, 범위 검사 통과 -> 비트 단위 등가 (코드 리뷰로 판정) |
| 검증_2 | **분기 증가분이 예측과 정확히 일치** | `if (` 21 -> **22** · `else` 11 -> **12** · `\|\|` 0 -> **3** |
| 검증_3 | 그 외 구조 지표 불변 | `case ` **19 불변** · `for (` **12 불변** · `&&` **0 불변** |
| 검증_4 | 마스크 적용 수 | `grep -c "0x1F"` = **2** |
| 검증_5 | 라이브 경로와 구조 대칭 | `case 5`/`case 7` 이 `case 8`/`case 10` 과 동일 형태 |
| 검증_6 | `text` **증가** | 방어 코드만큼. **감소하면 뭔가 지워진 것** |
| 검증_7 | 호스트 테스트 | **301 PASS / 0 FAIL** |
| 검증_8 | ARM 빌드 | 에러 0 · 경고 0 |
| 검증_9 | CP949 금지 문자 | 신규 주석에 **0건** |
| 검증_10 | 라이브 경로 무변경 | `para_setting.c` **손대지 않음** |
| 검증_11 | 실기 게이트 | §4 |

> [!IMPORTANT]
> **검증_2 가 이 작업의 핵심이다.** 개명 작업의 "크기 완전 동일"에 대응하는 지표다. 증가분이 예측(`+1`/`+1`/`+3`)과 다르면 의도 밖 편집이 섞였다는 뜻이다. `||` 3개는 검사 조건 4개(`A || B || C || D`)에서 나온다.

## 4. 실기 요청서 (은수님)

0x65 개명(직전 작업)과 **함께 확인**한다. Eclipse F5 Refresh 는 개명 때문에 필요하다.

| # | 항목 | 기대 | 대상 |
|---|---|---|---|
| 1 | **F5 Refresh -> Clean -> Build** | 에러 0 · 경고 0. **크기는 184,908 보다 약간 증가**(방어 코드분) | 공통 |
| 2 | 0x65 특정 자극 - **모노폴라** | 정상 자극 (기존과 동일) | 개명 |
| 3 | 0x65 특정 자극 - **바이폴라, 기준전극 정상(1~32)** | 정상 자극, 기준전극 반영. **RTT 로그에 OUT OF RANGE 가 뜨지 않아야 한다** | **이월_D** |
| 4 | 0x65 **범위 외 값** (예: 자극 크기 2000uA) | 범위 외 에러 응답 | 개명 |
| 5 | 라이브 0x66 회귀 | 15단계 전송 + 자극 시작 정상 | 개명 |

**3번이 이월_D 의 핵심이다.** 정상 바이폴라에서 `OUT OF RANGE` 로그가 뜨면 방어가 과하게 걸린 것이므로 즉시 알려 주십시오.

> [!NOTE]
> **바이폴라 + 기준전극 99 를 일부러 보낼 수 있으면** 로그에 `[SPEC] STIM ELEC NUM : n, REF ELEC NUM : 99, OUT OF RANGE - USE DUMMY` 가 뜨고 자극이 더미 기준전극으로 나가는 것이 정상입니다. 매핑 앱에서 그 조합을 만들 수 없으면 건너뛰어 주십시오 - 정상 경로만 확인해도 회귀는 잡힙니다.
