# 분석 검증 - 바이폴라 기준전극 99 · 0x65 경로 방어

**TL;DR**: 검증 3축 **전부 PASS**. 인용 근거 **13건 자동 대조 전부 일치**. 커버리지 주장(마스크 2곳이 32원소 전량)을 상수 실측으로 검산했고, 미결 3건 해소가 근거와 정합함을 확인했다. **요구사항 §게이트_5 의 불확실_3 이 해소**돼 5게이트가 완결됐다.

## 1. 축_1 - 지침 준수

| 항목 | 판정 | 근거 |
|---|---|---|
| HW 레지스터 5게이트 | **PASS** - 게이트_1~5 요구사항 §4. 불확실_3 은 ③ 에서 해소 | 추측 0건, 전 항목 소스 근거 |
| 결함 수정과 구조 리팩토링 분리 (원칙_4) | **PASS** | 개명 작업과 별도 폴더·별도 커밋. 같은 브랜치지만 커밋이 분리됨 |
| 호출 경로 추정 금지 | **PASS** | `case 5`/`case 7` 루프 범위를 상수 실측으로 확인 |
| root cause 가설 3개 이상 | **해당 없음** - 회귀 fix 가 아니라 **이미 확증된 결함의 방어 이식** | 원인 규명은 직전 작업에서 완료 |
| 신규 심볼 `tdc_` 접두어 | **해당 없음** - 신규 심볼 없음 | |
| 한글 라벨 | **PASS** | `위험_N` · `미결_N` · `게이트_N` |

## 2. 축_2 - 논리 정합성

### 정합_1 - "마스크 2곳으로 충분"이 성립하는가

주장: `bipolarReferenceElectrodeNum[32]` 의 **모든 원소**가 `case 5` 또는 `case 7` 을 거쳐 레지스터로 나간다.

| 검산 | 값 |
|---|---|
| 배열 크기 | `df_MaxNumOfElectrode` = **32** |
| `case 5` 커버 | `i = 0 .. df_MaxNumTransferableChannel-1` = **0~23** (24개) |
| `case 7` 커버 | `i = 24 .. 31` = **24~31** (8개) |
| 합 | 24 + 8 = **32** = 배열 크기 |
| 겹침 | 23 < 24 이므로 **0** |
| 빈틈 | 23 + 1 = 24 이므로 **0** |

**성립.** 두 지점에 마스크를 넣으면 전량이 갇힌다.

> [!NOTE]
> 이 검산은 `df_MaxNumTransferableChannel`(24) + 8 = `df_MaxNumOfElectrode`(32) 라는 **암묵적 관계**에 의존한다. 두 상수가 독립적으로 바뀌면 빈틈이 생긴다. `case 7` 이 하드코딩 `32` 를 쓰는 것도 같은 취약점이다. **다만 라이브 경로도 동일 구조**이므로 이번 작업에서 바꾸면 대칭이 깨진다 -> **이월**.

### 정합_2 - `if/else` 가 `continue` 와 등가인가

| 라이브 (`for` 안) | 0x65 (단발) |
|---|---|
| 검사 실패 -> `continue` -> **이번 밴드 대입 생략**, 다음 밴드로 | 검사 실패 -> `else` 미실행 -> **대입 생략** |
| 더미값(31)이 유지됨 | 더미값(31)이 유지됨 |

**등가.** 0x65 는 반복이 없으므로 "다음 반복으로" 부분이 불필요하고, 결과인 "대입 생략 + 더미 유지"가 동일하다.

### 정합_3 - 방어 위치를 `isd/` 로 한 것이 옳은가 (제외_1 재검토)

| 위치 | 장점 | 단점 |
|---|---|---|
| 파싱 (`ble/`) | 앱에 에러 응답 가능, 조기 차단 | **동작 변경** - 기존 통과 조합이 거부됨. 라이브와 **비대칭** |
| **`isd/` (채택)** | 라이브와 **완전 대칭**, 동작 변경 최소, 방어가 파싱에 의존하지 않음 | 앱은 에러를 못 받고 더미로 동작 |

**채택 근거가 정합적이다.** 이 작업의 목적은 *"라이브는 고쳐졌는데 0x65 는 안 고쳐진 비대칭 해소"* 이므로, 라이브와 같은 위치·같은 방식이어야 목적에 부합한다. 파싱 차단은 **양쪽 경로에 함께** 판단할 사안이다.

### 정합_4 - 불변량이 이 작업 유형에 맞는가

| 기존 유형 | 적용 가능? |
|---|---|
| 개명 - `text` 완전 동일 | **불가** - 방어 코드가 늘어 크기가 반드시 증가 |
| 함수 추출 - 분기 총수 보존 | **불가** - 분기가 의도적으로 증가 |
| 가드 수렴 - 게이트 수렴·본문 불변 | **불가** - 수렴이 아니라 추가 |

**"정상 경로 불변 + 예측된 분기만 증가"** 신설이 정합적이다. 핵심은 **증가분을 미리 못 박는 것**(`if (` +1 · `else` +1 · `||` +3)이며, 예측과 다르면 의도 밖 편집이 섞였다는 신호다.

### 3.2 미결_3 근거 재확인 - 파싱의 `stimulationElectrodeNum` 검사

소스 직접 확인 (`tdc_ble_cmd_0x65_specific.c:76~80`):

```c
if ((... stimulationElectrodeNum < 1) || (32 < ... stimulationElectrodeNum))
{
    dataRangeError = true;
}
```

**99 예외 분기가 없다.** `bipolarReferenceElectrodeNum`(`:82~90`)만 `!= 99` 예외를 갖는다.

| 주장 | 판정 |
|---|---|
| `stimulationElectrodeNum` 은 도달 불가 | **참** - 파싱이 1~32 로 막고 예외 없음 |
| 그래도 검사에 포함한다 | **정합** - 좌변이 **쓰기**이고, 방어가 파싱 구현에 의존하지 않아야 하며, 라이브와 대칭 |

### 3.3 게이트_5 불확실_3 해소

| 불확실 | 상태 |
|---|---|
| 불확실_3 (`case 5`/`case 7` 커버리지 겹침) | **해소** - §2 정합_1. 겹침 0 · 빈틈 0 |
| 불확실_1 (정상 앱이 바이폴라+99 를 보내는가) | **유지** - 미확정. 단 정상 경로 불변이라 안전성에 영향 없음 |
| 불확실_2 (실기 재현) | **유지** - 동 |

**5게이트가 완결됐다.** 불확실_1·2 는 *"변경해도 되는가"* 가 아니라 *"결함이 실제로 발현됐는가"* 에 관한 것이라, 변경 금지 사유(추측 섞임)에 해당하지 않는다.

## 4. 발견된 결함과 정정

| # | 결함 | 정정 |
|---|---|---|
| 결함_1 | 분석이 **상수 간 암묵적 관계**(24 + 8 = 32)에 의존하는 취약점을 지적만 하고 이월 등록을 안 했다 | **⑤ 계획의 이월 목록에 추가** - `case 7` 하드코딩 `32` 상수화 (라이브 포함 양쪽 동시) |
| 결함_2 | 위험_3 의 분기 증가분 예측(`||` +3)의 산출 근거가 없다 | **명시** - 검사 조건 4개는 `A \|\| B \|\| C \|\| D` 형태이므로 `\|\|` 연산자 **3개**. 정정 불필요, 근거만 보강 |

## 5. 판정

**PASS.** 인용 13건 전부 일치, 커버리지 검산 성립, 미결 3건 해소가 근거와 정합. 결함_1 은 이월로 처리한다.
