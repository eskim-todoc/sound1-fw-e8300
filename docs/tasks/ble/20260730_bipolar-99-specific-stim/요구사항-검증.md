# 요구사항 검증 - 바이폴라 기준전극 99 · 0x65 경로 방어

**TL;DR**: 검증 3축 **PASS**, 단 **HW 5게이트가 미완결**이다 - 게이트_5 의 **불확실_3(커버리지 겹침)이 미해소**라 ③ 분석으로 이월한다. 나머지 근거는 전부 소스에서 확인됐고 추측이 섞인 항목은 없다. 제외 범위 5건이 요구사항과 충돌하지 않음을 확인했다.

> [!IMPORTANT]
> **불확실_3 이 남은 채로는 ⑦ 구현에 들어가면 안 된다.** 루트 지침 §7 - *"추측 섞이면 변경 금지(미확인 남은 채 실기 금지)"*. 커버리지가 확정되지 않으면 "마스크 2곳으로 충분한가"에 답할 수 없다.

## 2. 축_2 - 논리 정합성

### 정합_1 - 요구사항과 제외가 충돌하지 않는가

| 요구사항 | 관련 제외 | 판정 |
|---|---|---|
| 요구사항_1 (범위 검사) | 제외_1 (파싱 변경 금지) | **정합** - 방어 위치가 `isd/` 로 서로 배타적. 같은 결함을 두 곳에서 막지 않는다 |
| 요구사항_1 (범위 밖이면 대입 생략) | 제외_2 (에러 응답 추가 금지) | **정합** - 조용히 더미값 사용이 라이브 경로와 동일 동작 |
| 요구사항_5 (`stimulationElectrodeNum` 도 검사) | 제외_1 | **정합** - 파싱이 이미 막지만 `isd/` 에서 이중 방어. 파싱을 *바꾸는* 것이 아니다 |
| 요구사항_2·3 (마스크) | - | 충돌 없음 |

### 정합_2 - "이식"이라는 전제가 성립하는가

요구사항이 모든 항목에 **이식 원본**을 명시했다. 이것이 성립하려면 두 경로가 대응해야 한다.

| 요구사항 | 이식 원본 | 대응 확인 |
|---|---|---|
| 요구사항_1 | `para_setting.c:486~496` | 같은 배열(`bipolarReferenceElectrodeNum`) · 같은 더미값 · 같은 상수(`df_MaxNumOfElectrode`) |
| 요구사항_2 | `:577` | 같은 레지스터 · 같은 루프 구조 |
| 요구사항_3 | `:605` | 동 |
| 요구사항_4 | `:475~485` | 주석 관례 동일 |

**성립.** 다만 **형태 차이가 있을 수 있다** - 라이브는 `for` 루프 안이고 0x65 는 단발일 가능성. ③ 분석에서 확인 대상으로 올린다.

### 정합_3 - 완료 기준이 요구사항을 덮는가

| 요구사항 | 덮는 기준 |
|---|---|
| 요구사항_1 (범위 검사) | 기준_2 |
| 요구사항_2·3 (마스크 2곳) | 기준_1 |
| 요구사항_4 (주석) | **기준 없음** -> §4 결함_1 |
| 요구사항_5 (`stimulationElectrodeNum`) | 기준_2 에 포함 (검사 조건의 일부) |
| 정상 경로 불변 | 기준_3 |
| 대칭성 | 기준_4 |

### 정합_4 - 불확실_1·2 가 "변경 금지" 사유인가

루트 지침 §7 은 *"추측 섞이면 변경 금지"* 다. 남은 불확실이 그에 해당하는지 판별했다.

| 불확실 | 성격 | 변경 금지 사유인가 |
|---|---|---|
| 불확실_1 (정상 앱이 바이폴라+99 를 보내는가) | **결함 발현 빈도**에 관한 것 | **아니다** - 안 보내도 방어는 무해하다(정상 경로 비트 등가). 변경의 옳고 그름과 무관 |
| 불확실_2 (실기 재현 여부) | **과거 사고의 인과**에 관한 것 | **아니다** - 동 |
| **불확실_3 (커버리지 겹침)** | **변경의 충분성**에 관한 것 | **그렇다** - 마스크 2곳이 전량을 덮는지 모르면 방어가 불완전할 수 있다 |

**불확실_3 만이 진짜 게이트다.** ③ 분석에서 해소해야 ⑤ 계획·⑦ 구현으로 갈 수 있다.

## 3. 축_3 - 근거 검증

### 3.1 요구사항이 인용한 사실

| 인용 | 확인 |
|---|---|
| 라이브 범위 검사 `para_setting.c:486~496` | 확인 |
| 라이브 마스크 `:577` · `:605` | 확인 |
| 0x65 마스크 없는 OR `specific_stim.c:258` · `:284` | 확인 |
| 레지스터 주소 상수 `isd_ver1_1_2.h:17` = `0x04` | 확인 |
| 더미값 `isd_ver1_1_2.h:42` = 31 | 확인 |

**추측 0건.** 게이트_2 요건 충족.

### 3.2 게이트_3 시뮬레이션 검산

`0x1F & 0x112EA` 를 손으로 검산한다.

```
0x112EA = 0001 0001 0010 1110 1010
0x0001F = 0000 0000 0000 0001 1111
    AND = 0000 0000 0000 0000 1010 = 0x0A
```

요구사항 기재값 **0x0A 와 일치.**

정상값 검산: `0x1F & 31` = `0b11111 & 0b11111` = **31**. 일치.
`0x1F & 0` = **0**. 하한도 통과(전극번호 0 은 범위 검사가 따로 막는다).

### 3.3 게이트_5 판정 - **미완결**

| 불확실 | 상태 | 처리 |
|---|---|---|
| 불확실_1 | 미확정 | **수용** - §2 정합_4 |
| 불확실_2 | 미확정 | **수용** - 동 |
| **불확실_3** | **미해소** | **③ 분석 필수 과제로 이월.** `df_MaxNumTransferableChannel` 값 실측 + `case 5`/`case 7` 인덱스 범위 대조 |

> [!CAUTION]
> **5게이트 미완결 상태다.** ③ 분석에서 불확실_3 을 해소하고 ④ 에서 재판정해야 ⑦ 로 갈 수 있다.

| # | 결함 | 정정 |

## 5. 판정

**조건부 PASS.** 요구사항의 실체·제외 범위·근거는 정합하나, **HW 5게이트가 게이트_5(불확실_3)에서 미완결**이다.

**③ 분석의 필수 과제**: 불확실_3(커버리지) 해소, 미결_1~3 해소, 이식 형태(루프 vs 단발) 확인.
