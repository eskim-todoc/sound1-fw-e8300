# 분석 - 바이폴라 기준전극 99 · 0x65 경로 방어 (이월_D)

**TL;DR**: 두 경로는 `case` 번호만 다르고 **구조가 1:1 대응**한다. 다만 라이브는 `for` 루프 안이라 `continue` 를, 0x65 는 **단발 대입이라 `if/else`** 를 써야 한다 - 이식의 유일한 형태 차이다. `df_MaxNumTransferableChannel` = **24** 실측으로 `case 5`(0~23) + `case 7`(24~31)이 **32원소를 빈틈없이 덮음**을 확인해, 마스크 2곳이 전량을 커버함이 확정됐다.

## 1. 두 경로의 구조 대조

| 단계 | 라이브 0x66 (`tdc_isd_stim_para_setting.c`) | 특정자극 0x65 (`tdc_isd_map_specific_stim.c`) |
|---|---|---|
| 배열 선언 | `:407` `static int bipolarReferenceElectrodeNum[32]` | `:65` **동일** |
| 더미 초기화 | `:460` `= unusedReferenceElectrode_DummyNum` | `:221` **동일** |
| **범위 검사** | `:486~496` **있음** (`continue`) | **없음** |
| 대입 | `:498~499` | `:224~225` **동일 형태** |
| 레지스터 0~23 | `case 8` `:577` `(0x1F & ...)` | `case 5` `:258` **마스크 없음** |
| 레지스터 24~31 | `case 10` `:605` `(0x1F & ...)` | `case 7` `:284` **마스크 없음** |

**차이는 방어 3곳뿐이다.** 나머지는 문자 단위로 같은 패턴이다.

### 1.1 이식의 유일한 형태 차이 - `continue` vs `if/else`

| 경로 | 문맥 | 건너뛰기 수단 |
|---|---|---|
| 라이브 | `for (i = 0; i < numFrequencyBand; i++)` **루프 안** - 밴드마다 반복 | **`continue`** |
| **0x65** | **단발 대입** - 자극 전극이 하나뿐 | **`if/else`** (또는 조기 `if` 후 대입) |

0x65 는 특정 자극이라 전극 조합이 **하나**다. 반복이 없으므로 `continue` 를 쓸 수 없다. **`if/else` 로 대입을 감싸는 것이 등가 형태**다.

## 2. 커버리지 검증 - 마스크 2곳이면 충분한가

`bipolarReferenceElectrodeNum[32]` 의 **모든 원소**가 레지스터로 나가야 방어가 완결된다.

| 상수 | 값 | 출처 |
|---|---|---|
| `df_MaxNumTransferableChannel` | **24** | `stim/tdc_stim_definitions.h:61` |
| `df_MaxNumOfElectrode` | **32** | `stim/tdc_stim_definitions.h:68` |

| 위치 | 루프 | 커버 인덱스 |
|---|---|---|
| `case 5` `:251` | `for (i = 0; i < df_MaxNumTransferableChannel; i++)` | **0 ~ 23** |
| `case 7` `:277` | `for (i = 24; i < 32; i++)` | **24 ~ 31** |
| **합** | | **0 ~ 31 (32개, 겹침 0, 빈틈 0)** |

**마스크 2곳으로 전량 커버가 확정됐다.** 라이브도 동일 구조(`case 8` 0~23 · `case 10` 24~31)다.

> [!NOTE]
> `case 7` 의 상한이 `df_MaxNumOfElectrode`(32) 가 아니라 **하드코딩 `32`** 다. 라이브(`:597`)도 같다. 상수화는 이번 범위 밖이나 **일관돼 있어 위험은 없다.**

## 3. 미결 해소

### 미결_1 - 인덱스 커버리지

**해소** - §2. `case 5` + `case 7` = 0~31 전량.

### 미결_2 - 범위 검사에 로그를 남길지

| 항목 | 실측 |
|---|---|
| 라이브 경로 | `:491` `TDC_PRINTF_I(... UNUSED)` - **`#if` 없이 그대로** |
| `TDC_PRINTF_I` 정의 | `util/tdc_printf.h:49` - SEGGER_RTT 인터페이스일 때 실체, 아니면 `:51` 빈 매크로 |
| `specific_stim.c` 의 `case 3` 위치 | `:217~246` - `#if` 블록(`:175~197` · `:374~381` · `:422~462`) **밖** |

**해소 - 로그를 남긴다.** `case 3` 이 `#if` 밖이라 무조건 컴파일되며, 라이브와 대칭이다. 이 결함은 **조용히 잘못 동작하는 것이 최악**이었으므로(실기 로그에 "PCB : 70378" 이 찍혀서야 발견됐다) 방어가 걸렸을 때 로그가 남아야 한다.

### 미결_3 - `stimulationElectrodeNum` 도 검사할 근거

| 관점 | 판단 |
|---|---|
| 도달 가능성 | **낮다** - 파싱(`tdc_ble_cmd_0x65_specific.c:76~80`)이 1~32 로 검사하고 **99 예외가 없다** |
| 위험도 | **높다** - 좌변 `bipolarReferenceElectrodeNum[electrodeMap[stimElec - 1]]` 은 **쓰기**다. 읽기보다 위험 |
| 대칭성 | 라이브(`:486~489`)가 **양쪽 다 검사**한다 |
| 비용 | 조건 2개 추가 |

**해소 - 포함한다.** 도달 불가라도 (가) 좌변이 쓰기라 사고 시 피해가 크고, (나) 라이브와 대칭이며, (다) 파싱이 바뀌면 전제가 무너진다. 방어 위치가 파싱에 의존하지 않는 것이 옳다.

## 5. 위험 분석

| # | 위험 | 판정·대응 |
|---|---|---|
| 위험_1 | 정상 자극 동작이 바뀐다 | **없음** - 0~31 에서 `0x1F & v == v`, 범위 검사도 통과. 비트 단위 등가 |
| 위험_2 | 더미값 31 이 마스크에 걸린다 | **없음** - `0x1F & 31 = 31` |
| 위험_3 | `else` 추가로 분기 구조가 바뀐다 | 조건 분기 **`if (` +1 · `else` +1 · `||` +3** 이 예상 증가분. 그 외 불변이어야 한다 -> 검증 지표 |
| 위험_4 | 크기 증가로 링크 실패 | **없음** - 수십 바이트, `sections.ld` 여유 충분 |
| 위험_5 | 실기 타이밍 변화 | **없음** - `case` 수·PCM 전송 수 불변 |
| 위험_6 | 주석에 CP949 금지 문자 | 작성 시 ASCII `->` 사용, 커밋 전 검사 |

## 6. 불변량 - 이 작업의 유형

**결함 수정(방어 추가)**은 개명·가드 수렴과 또 다른 유형이다.

| 지표 | 기대 |
|---|---|
| `text` 크기 | **증가** (방어 코드만큼) - 개명과 반대. 감소하면 뭔가 지워진 것 |
| 조건 분기 | **정확히 예측한 만큼만 증가** (`if (` +1 · `else` +1 · `||` +3) |
| `case` 수 | **불변 19** - 단계를 추가하지 않는다 |
| `for (` 수 | **불변 12** - 루프를 추가하지 않는다 |
| 정상 경로 동작 | **불변** - 0~31 에서 비트 단위 등가 |

**"정상 경로 불변 + 예측된 분기만 증가"** 가 이 유형의 불변량이다.
