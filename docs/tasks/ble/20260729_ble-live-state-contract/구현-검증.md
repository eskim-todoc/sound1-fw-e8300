# 구현 검증 - BLE 라이브 상태 계약 명시 (단계_4)

**TL;DR**: 계획의 검증_1~5 **전부 통과**. 게이트 4곳이 가드 1개로 수렴하면서 `en__HoldOn` 비교 · `en__Command_Order` 전송이 각각 **5 -> 1**, `else` **14 -> 10** 이 됐고, **본문 지표(`if (` 45 · `for (` 18 · `en__OutOfDataRange` 7)는 전부 불변**이다. **남은 것은 실기 게이트뿐이다.**

## 1. 커밋

| 커밋 | 해시 | 내용 |
|---|---|---|
| 커밋_1 | `5a7b32b` | 선행 상태 계약 테스트 26 케이스 추가 (기존 코드로 통과) |
| 커밋_2 | `4cd72d1` | 가드 수렴 + 조기 반환 전환 + 수락 조건 주석 9개 |

## 3. 게이트 수렴 대조 (검증_3)

계획-검증 보완 지시_1 이 정한 기준 - **"게이트 관련은 수렴, 본문은 불변"** 으로 대조했다.

| 지표 | 전환 전 | 전환 후 | 기대 | 판정 |
|---|---|---|---|---|
| `subCommand == en__HoldOn` | 5 | **1** | 수렴 | PASS |
| `en__Command_Order` | 5 | **1** | 수렴 | PASS |
| `subCommand = en__Standby` | 14 | **10** | -4 (게이트 else) | PASS |
| `else` | 14 | **10** | -4 | PASS |
| **`if (`** | 45 | **45** | **불변** | PASS |
| **`en__OutOfDataRange`** | 7 | **7** | **불변** | PASS |
| **`for (`** | 18 | **18** | **불변** | PASS |

> [!NOTE]
> **`if (` 가 45 로 불변인 것이 이 전환의 성격을 보여준다.** 게이트 4개와 가드 1개(총 5개)가 사라지고, 가드 내부 `if` 1개와 호출부 `if (!...)` 4개(총 5개)가 생겨 정확히 상쇄됐다. 분기를 **없앤 것이 아니라 이름 있는 자리로 옮긴 것**이다.
>
> 전환 전 카운트가 4가 아니라 5인 이유는, 대조 기준 파일이 가드 함수를 이미 추가한 시점이기 때문이다(게이트 4 + 가드 1).

## 4. 무엇이 달라졌나

### 4.1 전제가 함수 이름으로 올라왔다

```c
// 수락 조건 : 라이브 자극 유지 중(en__HoldOn)에만.
static void tdc_ble_cmd_0x66_sub03_volume_adjust(const uint8_t *Rx_dataPacket, int index)
{
    ...
    if (!tdc_ble_cmd_0x66_require_hold_on(p_mappingPacket, __LINE__))
    {
        return;
    }

    value = Rx_dataPacket[index++];   /* 본문이 한 단계 왼쪽으로 */
```

### 4.2 9종의 수락 조건이 각 함수 자리에 전부 적혔다

테이블을 만들지 않고도 조건이 한눈에 보인다. 조건 없는 명령도 "없음"이라고 적어, **조건이 없는 것과 가드를 빠뜨린 것이 구분**된다.

| 하위 | 주석 |
|---|---|
| 1 | 없음. 다만 데이터 인덱스는 1씩 증가해야 한다 |
| 2 · 7 | 없음. 어느 상태에서도 수락한다 |
| **3 · 4 · 5 · 6** | **라이브 자극 유지 중(en__HoldOn)에만** |
| 8 | 없음. 다만 `fetch_packet` 의 재진입 가드에서 먼저 걸릴 수 있다 |
| 9 | 앱이 보낼 수 없는 내부 상태값. `default` 로 낙하 (진입점에 명시) |

### 4.3 테스트가 4곳을 한 번에 보증한다

게이트가 한 함수로 수렴했으므로 그 함수가 틀리면 4개 명령이 동시에 깨진다. 커밋_1 의 26 케이스가 그 위험을 덮는다.

| 그룹 | 케이스 | 역할 |
|---|---|---|
| 거부 | 12 | 하위 3·4·5·6 이 Standby 에서 거부 · minor · Standby 유지 |
| 통과 | 4 | HoldOn 이면 게이트 통과 (하위 5 는 스텁 맵데이터 0 때문에 minor 로 판정) |
| **무조건** | **6** | **하위 2·7·8 이 Standby 에서도 수락** - 가드 오부착 검출 |
| 값 보존 | 4 | 거부된 명령이 기존 값을 덮지 않음 |

## 5. 남은 것 - 실기 게이트

> **단계_3 실기 확인이 아직이며, 단계_4 가 그 위에 쌓였다.** 두 단계가 함께 실기를 기다린다.
