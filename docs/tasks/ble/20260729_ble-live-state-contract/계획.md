# 계획 - BLE 라이브 상태 계약 명시 (단계_4)

**TL;DR**: **2개 커밋**. 커밋_1 이 게이트 테스트를 먼저 늘려 기존 코드로 통과시키고(안전망), 커밋_2 가 가드 추출과 수락 조건 주석을 넣는다. 게이트가 한 함수로 수렴하므로 **테스트 선행이 단계_3 보다 더 중요하다** - 가드가 틀리면 4개 명령이 동시에 깨진다.

## 1. 커밋 분해

| # | 커밋 | 내용 | 검증 |
|---|---|---|---|
| 커밋_1 | `Test(ble)` | 하위 3·4·5·6 게이트 전수 + 조건 없는 2·7·8 무조건 수락 테스트 추가 | `run.sh` 통과 (**기존 코드 그대로**) |
| 커밋_2 | `Refactor(ble)` | `tdc_ble_cmd_0x66_require_hold_on()` 추출 + 4곳 조기 반환 전환 + 9개 하위 명령에 수락 조건 주석 | `run.sh` + ARM 빌드 + 분기 총수 대조 |

## 2. 확정 코드

### 2.1 가드 함수

`tdc_ble_cmd_0x66_live.c` 의 하위 명령 함수들 **앞**에 배치한다(`sub01_all_param` 위).

```c
// 라이브 자극 유지 중(en__HoldOn)에만 수락되는 명령인지 확인한다.
//
// 하위 명령 3(자극 볼륨) · 4(마이크 감도) · 5(알림 자극) · 6(이퀄라이저 읽기)가
// 이 전제를 공유한다. 거부할 때는 앱에 명령 순서 에러를 보내고 서브커맨드를
// Standby 로 되돌린다.
//
// lineNumber 를 인자로 받는 이유 : 여기서 __LINE__ 을 쓰면 네 명령이 전부 같은
// 값을 보내 로그에서 구분되지 않는다. 호출 지점 값을 그대로 실어 보낸다.
//
// 반환 : 수락 가능하면 true
static bool tdc_ble_cmd_0x66_require_hold_on(ST__MAPPING_PACKET *p_mappingPacket, int lineNumber)
{
    if (p_mappingPacket->tdc_isd_map_live_step.subCommand == en__HoldOn)
    {
        return true;
    }

    // 라이브 자극 중에만 컨트롤 되는 명령어
    tdc_sys_error_send_to_app(en__mapping_live_stimulation, en__EN__BLE_PROTOCOL_ERROR, en__Command_Order, lineNumber);
    p_mappingPacket->tdc_isd_map_live_step.subCommand = en__Standby;

    return false;
}
```

### 2.2 호출부 전환 (4곳)

```c
// 하위 명령 3 - 자극 볼륨 조절 (en__StimulationVolumeAdjust)
// 수락 조건 : 라이브 자극 유지 중(en__HoldOn)에만.
static void tdc_ble_cmd_0x66_sub03_volume_adjust(const uint8_t *Rx_dataPacket, int index)
{
    ST__MAPPING_PACKET *p_mappingPacket = tdc_ble_mapping_get_packet();

    int value;

    if (!tdc_ble_cmd_0x66_require_hold_on(p_mappingPacket, __LINE__))
    {
        return;
    }

    value = Rx_dataPacket[index++];

    /* 이하 기존 본문을 그대로 왼쪽으로 한 단계 당긴다 */
}
```

`sub04` · `sub05` · `sub06` 도 동일하다. **본문은 들여쓰기만 바뀌고 내용은 손대지 않는다.**

> [!CAUTION]
> **본문 안의 `subCommand = en__Standby` 는 건드리지 않는다.** `sub05`(`:635`·`:684`)와 `sub06`(`:729`·`:737`)에는 **범위 검사 실패용** 복귀가 따로 있다. 가드가 담당하는 것은 게이트 실패뿐이다(분석 위험_5).

### 2.3 수락 조건 주석 (9개 하위 명령 전부)

테이블을 만들지 않고도 수락 조건이 한자리에 모이도록, 각 함수 머리에 한 줄씩 적는다.

| 함수 | 주석 |
|---|---|
| `sub01_all_param` | `// 수락 조건 : 없음. 단 데이터 인덱스는 1씩 증가해야 한다.` |
| `sub02_start` | `// 수락 조건 : 없음. 어느 상태에서도 수락한다.` |
| `sub03_volume_adjust` | `// 수락 조건 : 라이브 자극 유지 중(en__HoldOn)에만.` |
| `sub04_mic_sensitivity` | 동 |
| `sub05_indicator` | 동 |
| `sub06_read_equalizer` | 동 |
| `sub07_read_device_status` | `// 수락 조건 : 없음. 어느 상태에서도 수락한다.` |
| `sub08_stop` | `// 수락 조건 : 없음. 다만 fetch_packet 의 재진입 가드에서 먼저 걸릴 수 있다.` |
| (하위 9) | 진입점 `switch` 의 `default` 주석에 명시 |

## 3. 테스트 설계 (커밋_1)

`tests/unit/test_map_stim.c` 에 추가한다. 기존 케이스는 수정하지 않는다.

| 그룹 | 내용 | 케이스 |
|---|---|---|
| 그룹_1 | 하위 3·4·5·6 각각 - `en__Standby` 상태에서 **거부** + `minor == en__Command_Order` + `subCommand == en__Standby` 유지 | 12 |
| 그룹_2 | 하위 3·4·5·6 각각 - `en__HoldOn` 상태에서 **수락**(에러 0) | 4 |
| 그룹_3 | 하위 2·7·8 이 `en__Standby` 에서도 **수락**되는지 (가드 오부착 방지) | 6 |
| 그룹_4 | 거부된 볼륨 명령이 `stimulVolume` 을 바꾸지 않는지 | 2 |

**그룹_3 이 핵심 안전장치다.** 가드를 실수로 조건 없는 명령에 붙이면 정상 명령이 거부되는데, 현재 테스트에는 이를 잡을 케이스가 없다.

> [!NOTE]
> 하위 5(알림 자극)는 `tdc_shm_get_pointer_current_map_data()` 의 `numFrequencyBand` 와 T/C 레벨을 참조한다. 스텁이 0 으로 초기화하므로 **게이트 통과 후 범위 검사에서 걸릴 수 있다.** 그룹_2 는 "게이트를 통과했는가"만 보므로, 판정을 `en__Command_Order` 가 **아닌지**로 한다(에러 0 이 아니라).
