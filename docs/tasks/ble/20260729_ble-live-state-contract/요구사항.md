# 요구사항 - BLE 라이브 상태 계약 명시 (단계_4)

**TL;DR**: 라이브 자극(0x66)의 층간 규칙 - 특히 **"볼륨 · 마이크 감도 · 알림 자극 · 이퀄라이저 읽기는 `en__HoldOn` 일 때만 수락된다"** - 이 각 함수 안 조건문으로만 존재하는 것을 **이름 있는 가드로 승격**한다. 설계안이 제안한 테이블은 쓰지 않는다.

## 1. 배경

[`상태머신 사양.md §1`](../../../참고/ble/라이브모드/상태머신%20사양.md) 이 규명한 문제다.

> **문제는 층이 4개라는 것이 아니다.** 진짜 문제는 **층간 관계가 코드 어디에도 명시돼 있지 않다**는 점이다.

단계_3 에서 0x66 을 명령 · 하위 명령 · 데이터 인덱스 계층으로 분해했다. 그 결과 **각 하위 명령이 자기 함수를 갖게 됐고**, 이제 각 함수가 자기 전제를 선언할 자리가 생겼다.

## 2. 대상 실측

### 2.1 층_2(`subCommand`) 접근 지점 - 43곳

| 파일 | 건수 | 역할 |
|---|---|---|
| `ble/mapping/tdc_ble_cmd_0x66_live.c` | 22 | 게이트 검사(읽기) · 전이 설정(쓰기) |
| `ble/mapping/tdc_ble_mapping.c` | 2 | 재진입 가드(읽기) |
| `isd/tdc_isd_map_live.c` | 19 | 실행 완료 후 전이 설정(쓰기) |

**`ble/` 가 읽고 `isd/` 가 쓴다.** 한 상태 변수를 두 폴더가 공유하며, 어느 쪽이 소유자인지 코드에 없다.

### 2.2 `en__HoldOn` 게이트 - 4곳

[`상태머신 사양.md §2`](../../../참고/ble/라이브모드/상태머신%20사양.md) 전수표 기준.

| 하위 명령 | 함수 (단계_3 이후) | 수락 조건 |
|---|---|---|
| 1 전체 파라미터 | `tdc_ble_cmd_0x66_sub01_all_param` | 조건 없음 (인덱스 순서만 강제) |
| 2 시작 | `tdc_ble_cmd_0x66_sub02_start` | 조건 없음 |
| **3 자극 볼륨** | `tdc_ble_cmd_0x66_sub03_volume_adjust` | **`en__HoldOn` 일 때만** |
| **4 마이크 감도** | `tdc_ble_cmd_0x66_sub04_mic_sensitivity` | **`en__HoldOn` 일 때만** |
| **5 알림 자극** | `tdc_ble_cmd_0x66_sub05_indicator` | **`en__HoldOn` 일 때만** |
| **6 이퀄라이저 읽기** | `tdc_ble_cmd_0x66_sub06_read_equalizer` | **`en__HoldOn` 일 때만** |
| 7 장치 상태 읽기 | `tdc_ble_cmd_0x66_sub07_read_device_status` | 조건 없음 |
| 8 종료 | `tdc_ble_cmd_0x66_sub08_stop` | 조건 없음 (재진입 가드는 별도) |
| 9 HoldOn | (없음) | 앱이 보낼 수 없음. `default` 로 낙하 |

### 2.3 반복되는 게이트 코드

4개 함수가 동일한 구조를 각자 품고 있다.

```c
if (p_mappingPacket->tdc_isd_map_live_step.subCommand == en__HoldOn)
{
    /* 본문 전체가 이 안에 들여쓰기된다 */
}
else
{
    tdc_sys_error_send_to_app(en__mapping_live_stimulation, en__EN__BLE_PROTOCOL_ERROR, en__Command_Order, __LINE__);
    p_mappingPacket->tdc_isd_map_live_step.subCommand = en__Standby;
}
```

## 3. 요구사항

### 요구사항_1 - 수락 조건을 이름으로 선언

`en__HoldOn` 게이트를 **이름 있는 가드 함수**로 추출하고, 4개 하위 명령이 그것을 호출한다.

- 함수 이름이 "이 명령은 라이브 자극 중에만 받는다"를 말해야 한다
- 본문이 `if` 안에 들여쓰기되지 않고 **조기 반환**으로 평탄해져야 한다

### 요구사항_2 - 층_2 소유권 명시

`subCommand` 를 직접 읽고 쓰는 대신 **접근자를 경유**한다.

- 근거: 43곳이 두 폴더에 흩어져 있고 소유자가 불명확하다
- 2026-07-28 세션이 `prev_subCommandData_Num_index` 에 대해 이미 같은 처방을 했다(접근자 2개로 노출)

> [!CAUTION]
> **`isd/` 쪽 19곳까지 한 번에 바꾸지 않는다.** `ble/`-`isd/` 역결합 해소는 설계안 단계_5(고위험, 별도 판단) 영역이다. 이번 범위는 **`ble/` 쪽 24곳**이다.

### 요구사항_3 - 동작 100% 보존

| # | 보존 대상 |
|---|---|
| 보존_1 | 게이트 판정 결과 (수락 · 거부) |
| 보존_2 | 거부 시 에러 인자 - `en__mapping_live_stimulation` · `en__EN__BLE_PROTOCOL_ERROR` · `en__Command_Order` |
| 보존_3 | **거부 시 에러의 `lineNumber`** - 공통 함수로 빼면 전부 같은 값이 되므로 호출 지점의 `__LINE__` 을 넘겨야 한다 |
| 보존_4 | 거부 시 `subCommand = en__Standby` 되돌림 |
| 보존_5 | 수락 시 본문 동작 전부 |
| 보존_6 | 재진입 가드(`tdc_ble_mapping.c`)의 판정 |

### 요구사항_4 - 설계안 제안의 재해석 (핵심)

설계안 §3 단계_4 의 "**서브커맨드별 허용 선행 상태 테이블**" 은 **채택하지 않는다.**

- 근거: 2026-07-29 단계_3 에서 같은 성격의 디스크립터 테이블이 **가독성 문제로 기각**됐다. 지표(크기 -1,276B, 함수 409->101줄)가 전부 우수했음에도, 매크로 인자의 숫자 나열을 해독해야 한다는 이유였다
- 대신 **계층 네이밍 철학**을 이어간다 - 전제를 함수 이름으로 드러내고, 각 함수만 보면 자기 조건을 알 수 있게 한다

## 4. 범위 밖

| # | 제외 | 사유 |
|---|---|---|
| 제외_1 | `isd/tdc_isd_map_live.c` 의 19곳 | `ble/`-`isd/` 역결합 해소는 단계_5 |
