# 계획 - ble 응답 조립 공통화

**TL;DR**: **stateless 빌더 3함수**(`header`/`u8`/`u16`)를 `ble/tdc_ble_reply.c/.h` 에 신설하고, `ble/` 의 조립 지점 33곳을 **4커밋**으로 전환한다(빌더 신설 -> mapping 9 -> communication 5 -> remote 19). 인덱스는 호출자가 계속 소유하므로 **기존 흐름이 그대로 보존**된다. 검증은 직전 작업에서 확립한 어셈블리 대조 절차를 그대로 쓴다.

## 1. 판단 확정

| # | 판단 | **확정** | 근거 |
|---|---|---|---|
| 판단_1 | `tdc_ble_reply_send` 도입 | **미도입** | `tdc_hal_spi_write_tx_buffer` 의 얇은 래퍼일 뿐 추상화를 더하지 않는다. 호출 스택만 깊어진다 |
| 판단_2 | 커밋 분할 | **4커밋** (빌더 신설 -> mapping -> communication -> remote) | 위험 오름차순. `remote.c` 18곳이 최대라 마지막 |
| 판단_3 | 크기 증가 허용 상한 | **+300B** | 직전 작업(함수 추출)이 +736B. 이번은 반복 흡수라 더 작아야 한다. 초과 시 원인 규명 |
| 판단_4 | 16비트 표기 4변형의 등가성 | **등가 확정** | §2.2 |
| 판단_5 | `tdc_ble_reply_bytes` API | **제외** (분석-검증 결함_2) | 배열 복사가 **3곳**뿐. `for` 루프에서 `reply_u8` 을 부르면 된다 |

## 2. 빌더 API 확정

### 2.1 시그니처

```c
/* tdc_ble_reply.h */
#ifndef __tdc_ble_reply_h__
#define __tdc_ble_reply_h__

#include <stdint.h>

// BLE 응답 조립 빌더.
//
// 버퍼와 현재 인덱스를 주입받고 갱신된 인덱스를 반환한다.
// 인덱스는 호출자가 소유하므로 기존 조립 흐름(함수 진입 시 0, 이후 누적)이
// 그대로 유지된다. tdc_ble_general_debug.c 에서 확립된 계약과 같다.

int tdc_ble_reply_header(uint8_t *tx_buf, int tx_index, int command);  // 헤더 에코
int tdc_ble_reply_u8(uint8_t *tx_buf, int tx_index, int value);        // 8비트
int tdc_ble_reply_u16(uint8_t *tx_buf, int tx_index, int value);       // 16비트 (상위 -> 하위)

#endif  // __tdc_ble_reply_h__
```

`tdc_ble_reply_header` 는 `tdc_ble_reply_u8` 에 위임한다. 별도로 두는 이유는 **응답의 첫 바이트가 명령 에코라는 프로토콜 규약을 코드에 드러내기** 위함이다.

### 2.2 16비트 등가성 (판단_4 근거)

현행 표기 4변형과 빌더 구현의 등가를 확정했다.

| 변형 | 표기 | 위치 |
|---|---|---|
| 변형_1 | `0xff & (v >> 8)` / `0xff & v` | `mapping.c:592-593` |
| 변형_2 | `(char)((v >> 8) & 0xFF)` / `(char)(v & 0xFF)` | `remote_sp_para.c:63,121` |
| 변형_3 | **`v >> 8`** (마스크 없음) / `v & 0xFF` | `remote_sp_para.c:188,209,230,251` |
| 변형_4 | `(v >> 8) & 0x00FF` / `v & 0x00FF` | `general_debug.c:87~93` |

빌더 구현: `tx_buf[i++] = (value >> 8) & 0xFF; tx_buf[i++] = value & 0xFF;`

**등가 근거**: 대상이 `uint8_t` 배열이므로 대입 시 하위 8비트만 남는다. 마스크 유무·`(char)` 캐스팅·마스크 폭(`0xFF`/`0x00FF`)은 결과를 바꾸지 못한다. **값이 음수여도 동일**하다 - `-1 >> 8` 은 산술 시프트로 `-1`, 하위 8비트는 `0xFF` 이고, 마스크를 씌워도 `0xFF` 다.

대상 값(`adc_inputMax`·`isd_id`·`stimulationLevel_uA`)은 전부 `int` 이나 프로토콜상 양수이며, 음수여도 위 근거로 동작이 같다.

> [!IMPORTANT]
> **전 지점이 상위 바이트 먼저**임을 실측 확인했다(분석-검증 §3 근거_5). 순서를 뒤집는 지점은 없다.

## 3. 전환 절차

### 3.1 커밋 1 - 빌더 신설 (코드 변경 0)

| 항목 | 내용 |
|---|---|
| 신규 | `ble/tdc_ble_reply.c/.h` |
| 등록 | `.cproject` 불필요(`ble/` 루트는 이미 `-I` 등록됨) · `Debug/source/ble/subdir.mk` 갱신 |
| 검증 | 빌드 통과. **크기 무변동**(`--gc-sections` 가 미사용 함수 제거) **또는 빌더 3함수 크기만큼 증가** - 둘 다 정상 |

> [!NOTE]
> 어느 쪽이든 그 자체가 정보다. 무변동이면 링커가 미사용 함수를 걷어낸 것이고, 증가하면 그 값이 빌더의 순수 코드 크기다. 후자면 이후 커밋의 증감을 해석할 기준선이 된다.

### 3.2 커밋 2 - mapping 그룹 (9곳)

| 파일 | 조립 지점 |
|---|---|
| `mapping/tdc_ble_mapping.c` | 5 |
| `mapping/tdc_ble_map_flash.c` | 3 |
| `mapping/tdc_ble_map_stim.c` | 1 |

직전 작업으로 함수가 잘게 나뉘어 있어 **가장 안전**하다. 여기서 전환 패턴을 확립한다.

### 3.3 커밋 3 - communication (5곳)

`ble/tdc_ble_communication.c`. 0x30~0x36 대역 응답. 디스패치 파일이라 다른 성격의 조립이 섞여 있을 수 있으므로 별도 커밋.

### 3.4 커밋 4a·4b - remote 그룹 (19곳, 2분할)

최대 규모라 **명령 대역으로 나눈다** (계획-검증 결함_2). 한 커밋에 18곳을 몰면 실패 시 이분 탐색 해상도가 없다.

| 커밋 | 대상 |
|---|---|
| **4a** | `remote/tdc_ble_remote_sp_para.c` (1곳, **16비트 변형 2·3 이 몰린 6곳 포함**) + `remote.c` 의 0x40~0x4F 대역 |
| **4b** | `remote.c` 의 0x50~0x59 대역 |

`remote_sp_para.c` 를 먼저 처리하는 이유는 16비트 변형이 집중돼 있어 **등가성 판단(§2.2)이 실제로 성립하는지 가장 빨리 드러나기** 때문이다. 대역 경계는 착수 시 case 라벨로 확정한다.

### 3.5 전환 규칙

| 현행 | 전환 후 |
|---|---|
| `buf[idx++] = <명령>;` | `idx = tdc_ble_reply_header(buf, idx, <명령>);` |
| `buf[idx++] = <값>;` | `idx = tdc_ble_reply_u8(buf, idx, <값>);` |
| `buf[idx++] = (v >> 8) & 0xFF;`<br/>`buf[idx++] = v & 0xFF;` | `idx = tdc_ble_reply_u16(buf, idx, v);` |
| `tdc_hal_spi_write_tx_buffer(buf, idx);` | **그대로** (판단_1) |

**금지 사항**

- 인덱스 초기화 위치를 옮기지 않는다 (분석 §1.2)
- 조립 순서를 바꾸지 않는다
- 배열 복사 `for` 루프의 구조를 바꾸지 않는다 (내부 대입만 `reply_u8` 로)

## 4. 수용 판정

| # | 기준 | 방법 |
|---|---|---|
| 수용_1 | 빌드 에러 0 · 경고 0 | 커밋마다 `make SHELL=cmd all` |
| 수용_2 | **조건 분기 총수 보존** | 커밋마다 어셈블리 대조. 빌더 전환은 분기를 만들지 않으므로 **`+0` 이어야 한다** |
| 수용_3 | **호출 대상 집합** | 추가는 `tdc_ble_reply_*` 뿐. 기존 호출 대상·빈도 불변 |
| 수용_4 | **상수 보존** | 특히 `0xFF`/`0x00FF` 가 빌더 내부로 이동한 만큼만 감소 |
| 수용_5 | 전환 누락 0 | 파일별 전환 전후 `buf[idx++]` 직접 기술 건수 대조 |
| 수용_6 | 크기 | **+300B 이내** (판단_3) |
| 수용_7 | 응답 바이트열 완전 동일 | **은수님 실기 게이트** |

> [!IMPORTANT]
> **수용_2 가 이번 작업의 핵심 지표다.** 빌더 전환은 조건 분기를 추가하지도 제거하지도 않는다. `+0` 이 아니면 조립 로직이 바뀐 것이므로 즉시 중단한다.
