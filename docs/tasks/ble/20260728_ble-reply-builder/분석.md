# 분석 - ble 응답 조립 공통화

**TL;DR**: 미결 6건을 해소했다. **핵심은 API 형태 결정** - 응답 인덱스(`tx_index`)가 함수 진입 시 한 번만 0 이 되고 각 응답 후 리셋되지 않는 구조라, **빌더가 인덱스를 소유하면(컨텍스트 구조체) 리셋 시점을 새로 정해야 해 동작 변경 위험이 생긴다.** 호출자가 인덱스를 계속 관리하는 **stateless API 를 택하면 이 위험이 원천적으로 없다.** 적용 범위는 `ble/` 33곳으로 한정하고 `isd/`(21곳)는 제외한다.

## 1. 응답 조립 실태

### 1.1 두 지표의 차이 (요구사항 결함_2 해소)

| 지표 | `ble/` | `isd/` | `dfu/` | `sys/`·`hal/` | 계 |
|---|---|---|---|---|---|
| 송신 호출 | **33** | 21 | 2 | 2 | **58** |
| 버퍼 선언 | 12 | 14 | 2 | 2 | 29 |

두 수치가 다른 이유는 **한 함수 안에 여러 case 가 각자 조립**하기 때문이다. `tdc_ble_remote.c` 는 버퍼 선언 2곳(`:55`·`:645`)에 송신 18곳이다.

**전환 작업량의 척도는 송신 지점(33곳)** 이다.

| 파일 | 송신 |
|---|---|
| `ble/remote/tdc_ble_remote.c` | 18 |
| `ble/tdc_ble_communication.c` | 5 |
| `ble/mapping/tdc_ble_mapping.c` | 5 |
| `ble/mapping/tdc_ble_map_flash.c` | 3 |
| `ble/mapping/tdc_ble_map_stim.c` | 1 |
| `ble/remote/tdc_ble_remote_sp_para.c` | 1 |

### 1.2 인덱스 생명주기 - **가장 중요한 발견**

`tdc_ble_remote.c:647` 은 `int tx_index = 0;` 을 **함수 진입 시 한 번만** 실행하고, 그 뒤 16개 송신 지점 어디에서도 리셋하지 않는다(`grep "tx_index *= *0"` 결과가 선언 2곳뿐).

동작이 성립하는 이유는 **switch 의 각 case 가 배타적**이라 한 호출에서 한 경로만 실행되기 때문이다.

"같은 case 안에 송신 2회 이상"으로 의심된 4곳을 전수 확인한 결과 **전부 배타적 분기**였다.

| 지점 | 실태 |
|---|---|
| `tdc_ble_remote.c:849` | `if (value == 1)` / `else if (value == 2)` - 배타 |
| `tdc_ble_communication.c:144` | 내부 `switch` 의 case 와 바깥 `else if` 체인이 섞여 오탐. 실제 배타 |
| `tdc_ble_mapping.c:225` | 송신이 다음 `default:` case 안에 있어 오탐 |

> [!CAUTION]
> **이 구조가 API 설계를 결정한다.** 인덱스가 "한 번 0, 이후 누적"이므로, **빌더가 인덱스를 소유하면 어디서 0 으로 되돌릴지를 새로 정해야 한다.** 판단이 한 곳이라도 틀리면 응답 바이트열이 어긋나고, 컴파일러는 잡아주지 않는다.

### 1.3 조립 패턴 유형

| 유형 | 형태 | 예 |
|---|---|---|
| 유형_1 헤더 에코 | `buf[idx++] = <명령>;` | 거의 모든 응답의 첫 바이트. 코드 패턴 기준 **58곳** |
| 유형_2 8비트 값 | `buf[idx++] = <값>;` | 최다 |
| 유형_3 16비트 분해 | `buf[idx++] = (v >> 8) & 0xFF; buf[idx++] = v & 0xFF;` | **21곳** |
| 유형_4 배열 복사 | `for (...) buf[idx++] = arr[k];` | 맵 스탬프·전극 배열 등 |
| 유형_5 송신 | `tdc_hal_spi_write_tx_buffer(buf, idx);` | 58곳 |

> [!NOTE]
> **유형_3 의 마스크 표기가 통일돼 있지 않다.** `& 0x00FF`(`general_debug`)와 `& 0xFF`(그 외)가 섞여 있으나 결과는 같다. 빌더로 흡수하면 표기 차이가 사라진다.

### 1.4 확립된 선례 (`tdc_ble_general_debug.c`)

```c
int tdc_ble_general_debug_handle(const ST__REMOTECONTROL_PACKET *packet, uint8_t *tx_buf, int tx_index);
```

**버퍼와 인덱스를 주입받고 갱신된 인덱스를 반환**한다(`:35`·`:59`). 8비트 전환이 이미 반영돼 `uint8_t*` 다. 이 작업은 이 계약을 **원시 연산 단위로 낮추는** 것이다.

## 2. API 형태 결정 (미결_1)

### 2.1 두 안 비교

| | 안_가 stateless | 안_나 컨텍스트 구조체 |
|---|---|---|
| 형태 | `int tdc_ble_reply_u8(uint8_t *buf, int idx, int v)` | `void tdc_ble_reply_u8(tdc_ble_reply_t *r, int v)` |
| 인덱스 소유 | **호출자** | 빌더 |
| 기존 인덱스 생명주기 | **그대로 유지** | **리셋 시점을 새로 정해야 함** |
| 버퍼 선언 통합 | 안 됨(29곳 유지) | 됨 |
| 전환 시 위험 | **낮음** - 인덱스 흐름 무변경 | **높음** - §1.2 참조 |
| 설계안 스케치 | 일치 | - |
| `general_debug` 패턴 | 일치 | 불일치 |

### 2.2 결정 - **안_가 (stateless)**

근거 셋:

1. **§1.2 의 인덱스 생명주기를 건드리지 않는다.** 호출자가 `tx_index` 를 그대로 쓰므로 누적이든 리셋이든 기존 흐름이 보존된다. 이 작업의 최대 위험이 원천 제거된다.
2. **설계안 스케치·`general_debug` 선례와 일치**한다. 새 규약을 발명하지 않는다.
3. **점진 전환이 가능**하다. 한 조립 지점만 바꿔도 나머지가 영향받지 않는다.

안_나 의 유일한 이점(버퍼 선언 통합)은 **스택 사용량을 줄이지 못한다** - 어차피 호출자 프레임에 버퍼가 있어야 한다.

### 2.3 API 초안

```c
/* tdc_ble_reply.h - 확정 시그니처는 계획에서 */
int  tdc_ble_reply_header(uint8_t *tx_buf, int tx_index, int command);   /* 헤더 에코 */
int  tdc_ble_reply_u8(uint8_t *tx_buf, int tx_index, int value);         /* 8비트 */
int  tdc_ble_reply_u16(uint8_t *tx_buf, int tx_index, int value);        /* 16비트 상위->하위 */
int  tdc_ble_reply_bytes(uint8_t *tx_buf, int tx_index, const uint8_t *src, int len);
void tdc_ble_reply_send(const uint8_t *tx_buf, int tx_index);            /* 송신 */
```

`tdc_ble_reply_header` 와 `tdc_ble_reply_u8` 은 구현이 같다(헤더도 결국 1바이트). **의도를 드러내기 위해 분리**하되 내부는 위임한다.

> [!NOTE]
> `tdc_ble_reply_send` 는 `tdc_hal_spi_write_tx_buffer` 의 얇은 래퍼가 된다. 실익은 "응답 API 하나로 모인다"는 것뿐이라 **도입 여부를 계획에서 재검토**한다 - 판단_1.

## 3. 적용 범위 결정 (미결_2)

### 3.1 결정 - **`ble/` 33곳만**

| 대상 | 판정 | 근거 |
|---|---|---|
| `ble/` (33) | **포함** | 이 작업의 본체 |
| `isd/` (21) | **제외** | 설계안 원칙_5 - `isd/`-`ble/` 역결합은 단계_5 소관. 빌더 헤더를 `isd/` 가 include 하면 **결합이 한 방향 더 늘어난다** |
| `dfu/` (2) | **제외** | 2곳뿐이라 실익이 작고, OTA 실기가 별도 시나리오(이월_1)라 검증 비용이 크다 |
| `sys/tdc_sys_error.c` (1) | **제외** (미결_5) | 이미 공통 함수이며 6바이트 고정 형식이다. 내부를 빌더로 바꿔도 호출부는 그대로라 실익이 없다 |
| `hal/tdc_hal_spi.c` (1) | **제외** | 송신 계층 자체 |

> [!IMPORTANT]
> **`isd/` 제외는 실익을 포기하는 선택이다.** `isd/tdc_isd_map_data.c` 10곳이 그대로 남는다. 그러나 지금 넣으면 `isd/` -> `ble/` 참조가 늘어 단계_5(FSM 분리)를 더 어렵게 만든다. **빌더를 `ble/` 밖으로 승격하는 것은 단계_5 에서 계층이 정리된 뒤가 옳다.**
