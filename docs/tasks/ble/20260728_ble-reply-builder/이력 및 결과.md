## 2. 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| 결정_1 | **stateless API** (`buf`·`idx` 주입, `idx` 반환) | 인덱스가 함수 진입 시 한 번만 0 이 되고 이후 리셋되지 않는다. 빌더가 인덱스를 소유하면 리셋 시점을 새로 정해야 해 동작 변경 위험. 호출자가 계속 소유하면 이 위험이 원천 제거된다 |
| 결정_2 | 범위를 **`ble/` 33곳**으로 한정, `isd/` 21곳 제외 | 빌더 헤더를 `isd/` 가 include 하면 역결합이 한 방향 더 늘어 단계_5 를 어렵게 만든다 (원칙_5) |
| 결정_3 | `tdc_ble_reply_send` **미도입** | `tdc_hal_spi_write_tx_buffer` 의 얇은 래퍼일 뿐 추상화를 더하지 않는다 |
| 결정_4 | `tdc_ble_reply_bytes` **제외** | 배열 복사가 3곳뿐. `for` 루프에서 `reply_u8` 호출로 충분 |
| 결정_5 | 오버플로 방어 **미포함** | 방어 추가는 동작 변경이라 원칙_3 저촉. 별도 조사 항목으로만 기록 |

## 3. 이슈

| # | 이슈 | 처리 |
|---|---|---|
| 이슈_1 | "같은 case 안 송신 2회 이상" 의심 4곳 | 전수 확인 결과 **전부 배타적 분기**(if/else if) 또는 스크립트 오탐. 누적 송신 경로 없음 |
| 이슈_2 | 16비트 분해 표기가 **4가지**로 갈림 | `uint8_t` 대입의 하위 8비트 절단으로 **전부 등가**임을 확정(음수 포함). 빌더 하나로 흡수 가능 |
| 이슈_3 | **32비트 분해를 분석에서 놓침** | `>> 8` 만 grep 한 탓. 커밋 2 착수 중 발견해 전수 재조사(3곳) 후 `reply_u32` 추가. `remote_sp_para.c:63,121` 을 16비트로 오분류한 것도 정정 |
| 이슈_4 | **`sound1/` 25곳이 범위에서 빠짐** | 범위를 송신 호출 지점으로 셌는데 `sound1/` 은 자체 송신 없이 인덱스를 반환하는 구조라 누락. 전환 완료 후 잔존 대입을 훑다가 발견해 커밋 5 로 처리 |
