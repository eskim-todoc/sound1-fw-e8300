## 4. 발견 결함

### 결함_1 (경미) - 헤더 에코 계수 기준이 혼재

"62곳"은 `loop-back` **주석** 기준이고, 실제 코드 패턴(`buf[idx++] = ...command`)은 **58곳**이다. 두 집합은 완전히 겹치지 않는다(주석만 있고 형태가 다른 경우, 주석 없이 에코하는 경우).

**조치**: ③ 분석에서 **코드 패턴 기준으로 전수 분류**하고, 주석 기준 수치는 참고로만 둔다.

### 결함_2 (경미) - "`isd/` 가 `ble/` 보다 많다"는 지표에 따라 뒤집힌다

| 지표 | `ble/` | `isd/` |
|---|---|---|
| 버퍼 선언 | 12 | **14** |
| **송신 호출** | **33** | 21 |

`isd/tdc_isd_map_data.c` 는 버퍼 10개에 송신 10회(1:1)인 반면, `ble/remote/tdc_ble_remote.c` 는 **버퍼 2개로 송신 18회**다. 즉 **한 버퍼를 여러 응답이 돌려쓴다.**

**함의**: 전환 작업량의 척도는 **송신 지점(58)** 이지 버퍼 선언(29)이 아니다. 그리고 `ble/` 가 `isd/` 보다 전환 대상이 많다.

**조치**: ③ 분석에서 두 지표를 분리해 제시하고, `remote.c` 의 "버퍼 재사용" 구조가 빌더 전환에 제약이 되는지 확인한다(버퍼를 돌려쓰면 인덱스 리셋 시점이 중요하다).

### 결함_3 (경미) - 수용_4 의 "크기 감소 기대"에 근거가 없다

`-O0` 에서 반복 코드를 함수로 접으면 **호출 오버헤드가 추가**되므로 감소를 단정할 수 없다. 직전 작업에서 함수 추출이 +736B 였던 것과 같은 이유다.

**조치**: "감소 기대"를 **"증감을 실측하고 증가 시 원인을 설명한다"** 로 완화한다. ⑤ 계획에서 허용 상한을 정한다.

### 결함_4 (경미) - 제외_6(dfu) 정량 근거 보강

dfu 는 **2곳뿐**이다. 실익이 작고 OTA 실기가 별도 시나리오(이월_1)라는 점을 함께 대면 제외 근거가 명확해진다.
