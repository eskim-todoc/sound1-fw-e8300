# 구현 검증 - ble 응답 조립 공통화

**TL;DR**: 코드 6커밋 전부 **빌드 에러 0 · 경고 0**. 핵심 지표인 **조건 분기 총수가 5개 전환 커밋 모두 `+0`** 이었고, 추가된 호출은 빌더뿐이며 범위 검사 상수는 전 구간 불변이다. `ble/` 의 응답 조립 대입 **112줄이 빌더 호출 112개**로 바뀌었고, **크기는 568바이트 줄었다**(계획 상한이 +300B 였는데 반대 방향). **남은 것은 은수님의 실기 게이트 1회다.**

**누적 184,880 -> 184,312 = -568B.** 계획 판단_3 의 허용 상한은 `+300B` 였으므로 반대 방향으로 크게 벗어났다 - 반복 대입을 호출로 접은 절감이 `-O0` 의 호출 오버헤드를 넘어섰다.

> [!NOTE]
> 커밋 1 은 크기가 **무변동**이었다. `--gc-sections` 가 아직 아무도 호출하지 않는 빌더를 전부 걷어냈다는 뜻이다. 커밋 2 의 `+60B` 는 빌더 4함수 본체가 처음 링크에 포함된 몫이 크다. 이후 커밋은 전부 감소했다.

## 4. 조사 누락과 정정

정직하게 기록한다. 두 건 모두 **전환 중 실물을 보고 발견**했다.

### 발견_1 - 32비트 분해를 놓쳤다

분석 §1.3 은 16비트 분해만 유형으로 잡았다. 커밋 2 착수 중 `tdc_ble_mapping.c:590-593` 이 내부기 ID 를 4바이트로 분해하는 것을 보고 전수 재조사했다.

| 위치 | 값 |
|---|---|
| `tdc_ble_mapping.c:590-593` | `tdc_isd_read_connected_id()` |
| `remote_sp_para.c:61-64` | `adc_inputMax` |
| `remote_sp_para.c:119-122` | `isd_id` |

**분석의 오분류도 정정한다**: `remote_sp_para.c:63`·`:121` 을 16비트로 셌으나, 그 두 줄은 32비트 블록의 뒤쪽 2바이트였다. 남은 `>> 12` 4곳은 응답 조립이 아니라 DAC 기울기 계산이라 대상 밖이다.

**원인**: `>> 8` 만 grep 했다. 시프트 폭을 전수로 세었어야 했다.

### 발견_2 - `sound1/` 25곳이 범위에서 빠졌다

범위를 **송신 호출 지점**으로 셌는데, `sound1/` 2파일은 자체 송신을 하지 않고 `tx_index` 를 반환해 호출자가 송신하는 구조라 집계에 잡히지 않았다.

역설적으로 **이 두 파일이 빌더의 원형**이다. "버퍼 주입 + 인덱스 반환" 패턴이 여기서 확립됐고(2026-07-01) 빌더는 그것을 원시 연산 단위로 낮춘 것이다. 원형만 옛 방식으로 남기면 `ble/` 안에 두 방식이 공존하므로 커밋 5 로 마저 전환했다.

**원인**: "응답 조립"을 "송신하는 곳"과 동일시했다. 조립과 송신이 분리된 구조를 고려하지 못했다.

## 7. 노하우 추가

### 노하우_1 - "조건 분기 총수 `+0`" 은 조립 리팩토링의 강한 지표다

직전 작업(함수 추출)에서는 분기가 파일 간 **이동**했으나, 이번 빌더 전환은 분기가 **생기지도 사라지지도 않는다**. 따라서 `+0` 은 필요조건이자 사실상 충분조건에 가깝다. 5개 커밋 모두 `+0` 이었다.

### 노하우_2 - 범위를 "송신 지점"으로 세면 조립 전용 파일을 놓친다

조립과 송신이 분리된 구조(`sound1/`)가 있으면 송신 기준 집계에서 빠진다. **대입 패턴(`buf[idx++] =`)으로 세는 편이 안전**하다. 다만 버퍼 이름이 파일마다 다르므로(`bufferForSPI_tx`·`Tx_dataBuff`·`tx_buf`) 이름을 먼저 수집해야 한다.

### 노하우_3 - 시프트 폭은 전수로 센다

`>> 8` 만 찾으면 32비트 분해의 앞 2바이트를 놓치고, 뒤 2바이트를 16비트로 오분류한다. `grep -o ">> *[0-9]*" | sort | uniq -c` 로 폭 분포를 먼저 본다.

### 노하우_4 - `uint8_t` 대입은 표기 차이를 흡수한다

마스크 유무·`(char)` 캐스팅·마스크 폭(`0xFF`/`0x00FF`)이 달라도 `uint8_t` 배열에 대입하면 하위 8비트만 남는다. **음수여도 같다**. 덕분에 4가지 표기를 빌더 하나로 안전하게 통일할 수 있었다.
