# 요구사항 - ble 응답 조립 공통화

**TL;DR**: 에러 응답은 `tdc_sys_error_send_to_app()` 하나로 공통화돼 있으나 **정상 응답은 명령마다 손으로 조립**한다 - 버퍼 선언 29곳 · 헤더 에코 62곳 · 16비트 분해 21곳 · 송신 호출 58곳. `tdc_ble_general_debug.c` 에서 확립된 "버퍼 주입 + 인덱스 반환" 패턴을 **응답 빌더로 승격**해 이 반복을 흡수한다. **동작 보존이 절대 기준**이며 응답 바이트열은 1비트도 바뀌면 안 된다.

## 1. 배경

2026-07-28 폴더 개편(단계_1a·1b)으로 명령별 파싱 함수 23개가 분리됐다. 그 과정에서 **각 함수가 응답 버퍼를 따로 선언하고 손으로 채우는 구조**가 드러났다 - 추출한 `map_flash.c` 만 해도 버퍼 선언이 3곳이다.

설계안 §3 단계_2 가 지목한 문제가 이것이며, 폴더 개편으로 **적용 지점이 함수 단위로 명확해져** 지금이 착수 시점이다.

### 1.1 확립된 선례

`tdc_ble_general_debug.c`(2026-07-01 분리 작업)가 이미 패턴을 갖고 있고 `tdc_ble_gain_control.c` 가 재사용 중이다.

```c
int tdc_ble_general_debug_handle(const ST__REMOTECONTROL_PACKET *packet, uint8_t *tx_buf, int tx_index);
```

**버퍼와 인덱스를 주입받고 갱신된 인덱스를 반환**한다. 이 작업은 이 패턴을 **원시 연산 단위로 낮춰** 전 명령에 적용하는 것이다.

## 2. 현황 실측

| 항목 | 건수 | 비고 |
|---|---|---|
| 응답 송신 호출 (`tdc_hal_spi_write_tx_buffer`) | **58** | |
| 응답 버퍼 선언 (`uint8_t ...[BLE_DataPacketSize]`) | **29** | 함수마다 스택에 21바이트 |
| 헤더 에코 (`command loop-back` 주석 기준) | **62** | 거의 모든 응답의 첫 바이트 |
| 16비트 상·하위 분해 | **21** | `(v >> 8) & 0xFF` + `v & 0xFF` 쌍 |

### 2.1 폴더별 분포 (버퍼 선언 기준)

| 폴더 | 건수 | 파일 |
|---|---|---|
| `isd/` | **14** | `map_data` 10 · `specific_stim`·`live`·`impedance`·`ecap` 각 1 |
| `ble/` | **12** | `map_flash` 3 · `remote`·`mapping`·`map_stim` 각 2 · `communication`·`remote_sp_para` 각 1 |
| `dfu/` | 2 | |
| `sys/`·`hal/` | 2 | `tdc_sys_error.c` 는 이미 공통 함수 |

> [!IMPORTANT]
> **`isd/` 가 `ble/` 보다 응답 조립이 많다.** 자극 FSM 이 진행 상황을 앱에 직접 보고하기 때문이다. 이는 설계안이 지적한 `isd/`-`ble/` 역결합의 또 다른 단면이며, **범위를 어디까지 잡을지가 이 작업의 첫 판단**이다. - 미결_2

## 3. 목표

| # | 목표 | 측정 |
|---|---|---|
| 목표_1 | 응답 조립의 반복을 빌더로 흡수 | 헤더 에코·16비트 분해의 직접 기술 건수 감소 |
| 목표_2 | 16비트 분해의 시프트·마스크 실수 여지 제거 | `>> 8` 직접 기술이 빌더 내부로 국한 |

| 목표_4 | 이후 단계_3(디스크립터 테이블)의 기반 마련 | 테이블 주도 코드가 쓸 응답 API 확보 |

## 6. 수용 기준

| # | 기준 | 방법 |
|---|---|---|
| 수용_1 | 빌드 에러 0 · 경고 0 | `make SHELL=cmd all` |
| 수용_2 | **어셈블리 대조** - 조건 분기 총수 보존 · 호출 대상 집합 설명 가능 · 상수 보존 | 직전 작업에서 확립한 절차 |
| 수용_3 | **응답 바이트열 완전 동일** | 은수님 실기 로그 7종 대조 |
| 수용_4 | 크기 회귀 없음 | `arm-none-eabi-size`. 빌더 도입으로 **감소 기대** |
| 수용_5 | 전환 누락 0 | 전환 대상 목록을 만들고 1:1 대조 |

> [!NOTE]
> **이번에는 크기가 줄어들 가능성이 있다.** 폴더 개편은 함수 추출이라 호출 오버헤드가 늘었지만(+736B), 응답 빌더는 **반복 코드를 함수 하나로 접는** 방향이라 `-O0` 에서도 절감이 기대된다. 다만 확언할 수 없으므로 실측으로 확인한다.

## 7. 미결 사항 (③ 분석에서 해소)

| # | 미결 | 선택지 |
|---|---|---|
| 미결_1 | **빌더 API 형태** | (가) stateless - `(uint8_t *buf, int idx, ...)` -> `int` (설계안 스케치, `general_debug` 패턴과 동일) / (나) 컨텍스트 구조체 - `tdc_ble_reply_t` 에 버퍼와 인덱스를 담아 포인터 전달 |
| 미결_2 | **적용 범위** | (가) `ble/` 만(12곳) / (나) `ble/` + `isd/`(26곳) |
| 미결_3 | 오버플로 방어 포함 여부 | 현재 방어가 없다. 넣으면 **동작 변경**이므로 원칙_3 저촉 가능 |

| 미결_6 | 빌더 파일 위치 | `ble/` 루트 vs 신규 `common/` |
