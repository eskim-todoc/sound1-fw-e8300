# 계획 검증 - ble 응답 조립 공통화

**TL;DR**: 3축 검증 PASS. 계획의 강점은 **수용_2(조건 분기 `+0`)를 핵심 지표로 세운 것** - 빌더 전환은 분기를 만들지 않으므로 `+0` 이 아니면 곧 로직 변경이며, 이 지표 하나로 회귀를 즉시 잡는다. 다만 **결함 2건**을 보완해야 한다 - ① 커밋 1(빌더 신설)의 "크기 무변동" 기대가 `--gc-sections` 동작에 대한 가정이고, ② `remote.c` 18곳을 한 커밋에 묶는 것이 중단_4(이분 탐색)의 해상도를 떨어뜨린다.

## 2. 검증 축_2 - 논리적 정합성

| 확인 | 결과 |
|---|---|
| 수용_2(분기 `+0`)가 이번 작업에 타당한 지표인가 | **타당하고 강력하다.** 직전 작업(함수 추출)은 분기가 파일 간 이동했으나, 빌더 전환은 **분기 자체가 생기지 않는다**. `+0` 은 필요조건이자 사실상 충분조건에 가깝다 |
| 판단_1(`reply_send` 미도입)이 목표_4(단계_3 기반)와 충돌하는가 | 충돌 없음. 테이블 주도 코드도 조립은 빌더로, 송신은 기존 API 로 하면 된다 |
| 판단_5(`reply_bytes` 제외) 근거 | 배열 복사 3곳. `for` 루프 안에서 `reply_u8` 호출로 대체 가능하므로 타당 |
| 커밋 순서(mapping -> communication -> remote)가 위험 오름차순인가 | **맞다**. mapping 은 직전 작업으로 함수가 잘게 나뉘어 있고, remote 는 18곳에 16비트 변형 2·3 이 몰려 있다 |
| §3.5 "금지 사항"이 §2.2 등가성과 모순되는가 | 모순 없음. 등가성은 **표기**에 대한 것이고, 금지 사항은 **순서와 위치**에 대한 것이다 |
| 커밋 1 의 "크기 무변동" 기대 | **가정에 의존** - **결함_1** |
| 중단_4(이분 탐색)의 실효성 | remote 19곳이 한 커밋이라 해상도가 낮다 - **결함_2** |

**축_2 판정: 조건부 PASS**

## 4. 발견 결함

### 결함_1 (경미) - 커밋 1 의 "크기 무변동" 은 `--gc-sections` 가정에 의존한다

§3.1 은 "기존 코드가 아직 쓰지 않으므로 `--gc-sections` 로 빌더가 제거돼 크기 무변동이어야 한다"고 적었다. 링커 옵션에 `-Xlinker --gc-sections` 가 있고 `-ffunction-sections` 도 켜져 있으므로 **성립할 가능성이 높지만**, 정적 함수가 아닌 외부 링키지 함수가 항상 제거되는지는 확인이 필요하다.

**보완**: 커밋 1 에서 크기가 **늘어도 실패가 아니다.** 늘어난 양이 빌더 3함수의 코드 크기와 맞으면 정상이다. 판정 문구를 "무변동 또는 빌더 함수 크기만큼 증가"로 완화한다.

### 결함_2 (경미) - `remote.c` 18곳을 한 커밋에 묶으면 이분 탐색 해상도가 낮다

중단_4 는 "커밋 단위 이분 탐색"인데, remote 커밋이 실패하면 18곳 중 어디인지 좁힐 수 없다.

**보완**: 커밋 4 를 **명령 대역으로 2분할**한다.

| 커밋 | 대상 |
|---|---|
| 4a | `remote/tdc_ble_remote_sp_para.c` (1곳) + `remote.c` 의 **0x40~0x4F** 대역 |
| 4b | `remote.c` 의 **0x50~0x59** 대역 |

`remote_sp_para.c` 는 16비트 변형 2·3 이 몰려 있어(6곳) 먼저 확인하는 편이 낫다. 실제 대역 경계는 착수 시 case 라벨로 확정한다.
