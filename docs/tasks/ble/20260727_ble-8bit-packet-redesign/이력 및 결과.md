# 이력 및 결과 - BLE 패킷 버퍼 8비트 전환 및 구조 재설계

**TL;DR**: 2026-07-27 착수. 은수님 제안(DMA 워드 크기를 32→8비트로 바꿔 `uint8_t` 패킷 버퍼 사용)의 타당성을 5게이트로 검증하고, 프로토콜 추가·수정이 쉽고 유닛/모듈 단위 테스트가 가능한 재설계안을 산출한다. **코드 무변경.** 브랜치 `claude_feature_ble-8bit-packet-redesign`.

## 완료 요약

**2026-07-28 완료.** 8비트 전환 5단계 + 결함 수정 2건. 전 단계 빌드 무결·실기 정상 확인.

### 결과

| # | 결론 |
|---|---|
| 결론_1 | **은수님 구상이 옳았다.** SPI1 은 이미 8비트 워드인데 DMA 만 32비트로 퍼 담아 버퍼가 `int[]` 이 됐다. 프로토콜 요구가 아니라 설정 문제였다 |
| 결론_2 | **변경 지점이 예상보다 훨씬 적었다.** DMA 매크로 2곳 + 버퍼 타입. `transferLength`(21)·주소 증가 설정은 손댈 필요가 없었다. 부트로더의 `dma_len_mul` 실증으로 "워드 개수" 임을 확정한 것이 결정적이었다 |
| 결론_3 | **최초 실측 게이트는 불필요했다.** 니블 재배치 서술이 `If byte ordering is enabled` 조건부이고 현 설정이 `DMA_LITTLE_ENDIAN`(0)이라 발동 불가. 은수님 반문으로 재검증해 게이트를 폐지했다 |
| 결론_4 | **전환 중 기존 결함 2건이 드러났다.** 바이폴라 `electrodeMap` 범위 밖 읽기, EEPROM 슬롯 0 허용. 둘 다 전환과 무관한 잠복 결함이며 `nm` 실측·구버전 대조로 확정했다 |
