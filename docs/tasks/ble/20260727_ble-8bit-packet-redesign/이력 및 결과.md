# 이력 및 결과 - BLE 패킷 버퍼 8비트 전환 및 구조 재설계

**TL;DR**: 2026-07-27 착수. 은수님 제안(DMA 워드 크기를 32→8비트로 바꿔 `uint8_t` 패킷 버퍼 사용)의 타당성을 5게이트로 검증하고, 프로토콜 추가·수정이 쉽고 유닛/모듈 단위 테스트가 가능한 재설계안을 산출한다. **코드 무변경.** 브랜치 `claude_feature_ble-8bit-packet-redesign`.

## 시계열 로그

### 2026-07-27

| 시점 | 단계 | 내용 |
|---|---|---|
| 착수 | - | 은수님 제안 접수 - `WORD_SIZE_32BITS_TO_32BITS` 가 패킷 버퍼를 `int[]` 로 강제해 접근 구조를 복잡하게 만든다. 8비트 전환 가능 여부 + 전체 재설계 계획안 요청 |
| 사전 확인 | - | **핵심 사실 5건 확보**: ① SPI 주변장치는 **이미 8비트 워드**(`tdc_hal_spi.h:17` `SPI_WORD_SIZE_8`) ② 32비트는 **DMA 설정**(`tdc_hal_dma.h:7`·`:13`) ③ **`WORD_SIZE_8BITS_TO_8BITS` 가 CM3 SDK 에 실재**(`sk5_hw_cid101.h:10983`, `0x12`) ④ CMSIS 드라이버에도 동일 정의(`Driver_DMA.h:149`) ⑤ **같은 저장소 부트로더에 8비트 워드 DMA 선례 존재**(`bootloader.c:314`·`:326`·`:438`) |
| 브랜치 | - | `claude_feature_ble-8bit-packet-redesign` 생성 |

| ① | 요구사항 | [`요구사항.md`](요구사항.md) 작성 - 요구사항 12건(8비트 전환 7 + 재설계 5) · 제약 6건 |
| ② | 요구사항-검증 | [`요구사항-검증.md`](요구사항-검증.md) - 결함 0 · 보완 1(선행 로드맵 갱신). **사실_3 검증 경로 중요**: 최초 grep 은 `include/cfx/`(LPDSP32용)만 걸렸고, CM3 용 `include/cm3/` 에서 재확인한 뒤에야 확정 |
| ③ | 분석 | 4노드 fan-out 완료 -> [`분석.md`](분석.md) 종합. **판정: 조건부 가능**(미확인 5건, 실기 전 필수 2건) |
| ④ | 분석-검증 | [`분석-검증.md`](분석-검증.md) - **최중요 판정을 부트로더 코드로 직접 재검증.** `dma_len_mul` 이 32비트일 때 0, 8비트일 때 2(×4) -> `transferLength` 는 **소스 워드 크기 기준 개수** 확정. `TRANS_LENGTH_SEL` 이 양쪽 모두 **메모리 기준**이라는 독립 근거 추가 확보 |
| ⑤ | 계획 | [`계획.md`](계획.md) - **7단계 통합 로드맵**(실측게이트 -> 8비트전환 -> 유닛추출 -> 응답공통화 -> 디스크립터테이블 -> 상태계약 -> FSM분리). 유닛 6 · 모듈 3 · 테스트 순서 10단계 |
| ⑥ | 계획-검증 | [`계획-검증.md`](계획-검증.md) - **누락 1건 자체 적발**(밸리데이션 계층화 체크리스트의 의존성 그래프가 계획서에 없었음) + 반증에서 **어댑터를 캐스팅으로 구현하면 즉시 깨진다**는 정정 도출 |
| **미확인 해소** | - | **은수님 지적으로 실측 게이트 폐지.** "SPI 8비트를 32비트에 저장하고 하위 8비트만 꺼내 쓰는 게 명확한데 니블을 따질 필요가 있나" -> 원문 재검증 결과 니블 재배치는 **"If byte ordering is enabled"** 조건부이고 `BYTE_ORDER` 는 1비트(`LITTLE`=0 / `BIG`=1), 현 설정이 `DMA_LITTLE_ENDIAN`(0)이라 **발동 불가**. 정렬 논쟁은 `aligned(4)` 로 우회. **판정 조건부 가능 -> 가능** |
| 승인 | - | **B1 진행 승인** (2026-07-27 은수님). 단 "자료형 변환 주의 구간을 전부 목록화 후 진행" 조건 |
