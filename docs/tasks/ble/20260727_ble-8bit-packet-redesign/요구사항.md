# ① 요구사항 - BLE 패킷 버퍼 8비트 전환 및 구조 재설계

**TL;DR**: 은수님 제안 - SPI+DMA 의 `WORD_SIZE_32BITS_TO_32BITS` 가 패킷 버퍼를 `int[]` 로 강제해 접근 구조를 복잡하게 만든다. 이를 `8BITS_TO_8BITS` 로 바꿔 `uint8_t` 버퍼를 쓰면 훨씬 단순해진다는 구상이다. **착수 즉시 SDK 에서 `WORD_SIZE_8BITS_TO_8BITS` 실재를 확인했다.** 이번 작업은 ① 그 전환의 **5게이트 검증 자료**를 갖추고 ② **프로토콜 추가·수정이 쉽고 유닛/모듈 단위로 테스트 가능한** 전체 재설계안을 산출한다. **코드는 변경하지 않는다.**

## 1. 배경

[`20260727_ble-protocol-restructure`](../20260727_ble-protocol-restructure/) 구조 분석에서 복잡도의 근인 3건(함수 분해 부재 · 라이브 상태 4층 분산 · 파서가 자극 FSM 구동)을 규명하고 6단계 로드맵을 제시했다. 그 설계안은 **패킷 버퍼가 `int[]` 라는 전제 위에서** 수립됐다.

은수님이 그 전제 자체를 지적했다. 패킷 버퍼가 `int[20]`(`tdc_hal_spi.c:22`)인 이유는 프로토콜이 32비트를 요구해서가 아니라 **DMA 워드 크기 설정 때문**이며, 이것이 바이트 단위 프로토콜을 다루는 코드를 불필요하게 복잡하게 만든다는 것이다.

### 착수 시점 확인 사실

| # | 사실 | 근거 |
|---|---|---|
| 사실_1 | **SPI 주변장치는 이미 8비트 워드로 동작 중이다** | `tdc_hal_spi.h:17` `TDC_HAL_SPI_CONFIG` 에 `SPI_WORD_SIZE_8` 포함 |
| 사실_2 | 32비트는 **DMA 설정**이다. RX·TX 양쪽 모두 | `tdc_hal_dma.h:7`(DMA0) · `:13`(DMA1) `WORD_SIZE_32BITS_TO_32BITS` |
| 사실_3 | **`WORD_SIZE_8BITS_TO_8BITS` 가 CM3 용 SDK 에 실재한다** | `<SDK>/include/cm3/sk5_hw_cid101.h:10983` - `((uint32_t)(0x12U << DMA_CFG0_SRC_DEST_WORD_SIZE_Pos))` |
| 사실_4 | CMSIS 드라이버에도 동일 정의가 있고 의미가 명시돼 있다 | `<SDK>/include/cm3/cmsis_drivers/Driver_DMA.h:149` - "Source data uses 8-bit word and destination data uses 8-bit word" |
| 사실_5 | 같은 저장소에 **8비트 워드 DMA 사용 선례가 있다** | `0__bootloader/source/bootloader.c:314`·`:326` `WORD_SIZE_8BITS_TO_24BITS`, `:438` `WORD_SIZE_8BITS_TO_32BITS` |

> [!NOTE]
> 사실_3~5 로 **"가능한가"는 이미 긍정적으로 답이 나왔다.** 이번 작업의 실질은 "**어떻게 바꾸며 무엇이 깨지는가**"를 5게이트로 규명하는 것이다.

## 2. 요구사항

### 2.1 SPI+DMA 8비트 전환 (은수님 요청 1)

| # | 요구사항 | 수용 기준 |
|---|---|---|
| 요구사항_1 | **5게이트 검증 자료 완비** | [`레지스터·하드웨어 설정 검증.md`](../../../../../rules/지침/코딩/레지스터·하드웨어%20설정%20검증.md) 의 ① 대상 식별 ② 근거 확인(**원문 인용**) ③ 전후 시뮬레이션 ④ 부작용 ⑤ 불확실성 명시를 전부 채운다 |
| 요구사항_2 | 변경 대상 비트 필드 특정 | `DMA_CFG0` 의 `SRC_DEST_WORD_SIZE` 필드 위치·폭·현재값·목표값. **같은 레지스터의 다른 비트**가 의도대로 유지되는지 |
| 요구사항_3 | **`transferLength` 의미 확정** | 현재 `TDC_HAL_SPI_COMM_PACKET_SIZE`(21)를 넘긴다. 이 값이 **워드 수인지 바이트 수인지** 원문 근거로 확정. 워드 크기 변경 시 재계산이 필요한지 |
| 요구사항_4 | **주소 증가 단위 확정** | `DMA_DEST_ADDR_INCR_1` / `DMA_SRC_ADDR_INCR_1` 이 8비트 모드에서 몇 바이트씩 증가하는지 |
| 요구사항_5 | SPI 데이터 레지스터 접근 확정 | 현재 하드코딩된 `0x40000E10`(RX) · `0x40000E0C`(TX) 가 8비트 모드에서도 유효한지. 정렬·엔디안 영향 |
| 요구사항_6 | 부작용 전수 확인 | DMA0/DMA1 채널을 공유하는 다른 기능, 저전력 모드 시 설정 유지, `SPI_CMMM_ERROR` 복구 경로 영향 |
| 요구사항_7 | 선례 대조 | `bootloader.c` 의 8비트 워드 DMA 사용 코드를 읽고, 설정 조합·주의점을 이번 전환에 대입 |

### 2.2 전체 구조 재설계 (은수님 요청 2)

| # | 요구사항 | 수용 기준 |
|---|---|---|
| 요구사항_8 | **프로토콜 추가·수정이 쉬운 구조** | 신규 명령 1개를 추가할 때 손대야 할 파일·함수를 **최소화**하는 설계. "이 명령을 추가하려면 여기 한 줄"이 되도록. 추가 절차를 문서화 |
| 요구사항_9 | **유닛/모듈 분해** | [`밸리데이션 계층화.md`](../../../../../rules/지침/코딩/밸리데이션%20계층화.md) 를 따른다. 유닛 후보(독립·결정론 입출력) 도출 + 모듈 후보 + **의존성 그래프**(Mermaid) |
| 요구사항_10 | **테스트 가능 구조** | 각 유닛·모듈에 검증 방법 라벨(**[유닛테스트]** / **[통합테스트]** / **[로직설명]**) 부여. 테스트 순서("A는 B 통과 전제") 명시 |
| 요구사항_11 | 8비트 전환과 재설계의 **연계 순서** | 두 작업의 선후 의존을 명시. 어느 쪽을 먼저 해야 다른 쪽이 쉬워지는지 |
| 요구사항_12 | 단계별 구현 계획 | 각 단계에 동작 보존 위험도와 검증 방법. 되돌릴 수 있는 크기로 분할 |

## 3. 제약 조건

| # | 제약 | 근거 |
|---|---|---|
| 제약_1 | **소스 코드를 변경하지 않는다** | 이번 작업은 분석·계획까지 (은수님 요청 문구 "분석해줄래" · "계획안을 줘봐") |
| 제약_2 | **프로토콜 규약 불변** - 명령 코드·페이로드 레이아웃·응답 바이트 순서 | 앱·리모콘과 공유. [`cm3-소스-트리-규약.md §2.1`](../../../참고/cm3-소스-트리-규약.md) |
| 제약_3 | **추측이 섞이면 변경 금지.** 미확인은 미확인으로 명시 | 5게이트 §2.2·§2.5 |
| 제약_4 | **단순·특화 원칙.** 과도한 추상화·범용화·테스트용 군더더기 금지 | 밸리데이션 계층화 §6 |
| 제약_5 | 동작 보존이 기본값. 동작 변경은 별도 표시 후 승인 | 자극 계통 안전 |
| 제약_6 | 신규 심볼은 `tdc_` 접두어 | 루트 지침 §7 |

## 4. 범위

**포함**
- `hal/tdc_hal_spi.c/.h` · `hal/tdc_hal_dma.h` · SDK DMA 정의

- `0__bootloader` 의 8비트 DMA 선례 (읽기 전용 참조)
- 프로토콜 계층 재설계 (디스크립터 테이블 · 유닛/모듈 경계 · 테스트 구조)

**제외**
- 실제 코드 수정·빌드·실기 검증 (후속)
- CFX(`1__cfx`) 측 DMA 설정 (별도 프로세서)
- 프로토콜 규약 자체의 변경
