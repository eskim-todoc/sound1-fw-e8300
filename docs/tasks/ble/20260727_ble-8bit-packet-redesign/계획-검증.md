### 2.3 반증 시도

| # | 반증 | 결과 |
|---|---|---|
| 반증_1 | "단계_B 를 원자적이라 했는데 §3.3 은 3단계로 나눈다. 모순 아닌가" | **모순 아님.** §3.3 이 "원자적이라 함은 DMA 설정과 HAL 버퍼를 함께 바꾼다는 뜻이지 57개 호출부를 한 번에 고친다는 뜻이 아니다"라고 명시적으로 구분한다. 순서_1 만으로 동작이 완결되고 순서_2·3 은 타입 정합 정리다 |
| 반증_2 | "어댑터로 `int*` 를 계속 노출하면 순서_1 시점에 버퍼는 `uint8_t` 인데 `int*` 로 넘기게 된다. 이거 위험하지 않나" | **성립.** 어댑터는 단순 캐스팅이 아니라 **변환 복사**여야 한다(`uint8_t` 버퍼 -> 임시 `int` 배열). 캐스팅으로 구현하면 즉시 깨진다. -> 정정_2 로 명시 |
| 반증_3 | "테스트 순서 10단계 중 1~5 가 전부 '전제 없음' 인데 정말 독립적인가" | **타당.** 유닛_1~5 는 순수 함수이고 서로 호출하지 않는다. 유닛_6 만 유닛_2 에 의존한다(응답 조립 시 16비트 분해 사용) |
| 반증_4 | "단계_A 에서 니블 재배치가 발동하면 전체 계획이 무산되는데, 그때의 대안이 한 줄뿐이다" | **부분 성립.** §2.3 이 대안을 제시하나 얕다. 다만 **실측 결과를 보기 전에 대안을 정교화하는 것은 낭비**다. 무산 시 재계획하는 것이 합리적 -> 현행 유지 |
