# ⑧ 구현 검증

**TL;DR**: B1~B3c 5단계 전환과 그 과정에서 발견된 결함 2건 수정을 검증했다. **전 단계 빌드 에러 0·경고 0, 실기 정상 동작 확인.** 계획 대비 실제 변경이 일치하며, 잔여 `int` 조립 버퍼와 전환용 어댑터가 **0건**임을 grep 으로 확증했다. 계획에 없던 결함 수정 2건이 추가됐는데, 이는 전환 중 실기에서 드러난 것으로 **범위 확대가 아니라 필수 대응**이었다.

## 축_2 - 논리적 정합성

### 2.1 계획 대비 실제

| 단계 | 계획 | 실제 | 판정 |
|---|---|---|---|
| B1 | DMA 매크로 2곳 + HAL 버퍼 + 어댑터 (2파일) | 3파일 (`tdc_ble_communication.c` 의 범위 밖 로그 정리 추가) | **초과.** 전환으로 노출 값이 달라지는 지점이라 함께 처리한 것이 타당 |
| B2 | RX 경로 (2파일) | 11파일 | **초과.** 시그니처 연쇄가 계획 예상보다 컸다(fetch 6 + dfu 내부 7). 컴파일러가 3단계로 전부 검출 |
| B3a | `ble/` 5파일 | 8파일 | **초과.** `general_debug`·`gain_control` 의 `tx_buf` 인자 연쇄 |
| B3b | `isd/` 6파일 | 5파일 | 축소. 실제 대상이 5파일이었다 |
| B3c | `dfu/`·`sys/` 3파일 + 어댑터 제거 | 14파일 | **초과.** 이름 정리(`_u8` 제거) 57곳이 전 파일에 걸침 |

> [!NOTE]
> 파일 수 초과는 **계획 오류가 아니라 컴파일러 주도 전환의 정상 결과**다. 포인터 타입 불일치는 컴파일 단계에서 드러나므로 누락이 불가능하고, 실제 연쇄 범위는 착수 전에 정확히 셀 수 없었다. ② 검증에서 예상한 "연쇄 시그니처 15개" 와 실제(13개)가 근사했다.

### 2.2 계획에 없던 작업 2건

| # | 작업 | 정당성 |
|---|---|---|
| 추가_1 | 바이폴라 `electrodeMap` 범위 밖 읽기 수정 (`d46d448`) | **필수.** B3a 실기 검증 중 드러났다. 방치하면 이후 단계의 실기 검증이 불가능했다 |
| 추가_2 | EEPROM 슬롯 0 심층 방어 (`daa44f8`) | **필수.** 추가_1 조사 과정에서 같은 유형(경계 검사 누락)으로 발견. 은수님 승인 후 진행 |

두 건 모두 **전환 자체와 무관한 기존 결함**이며, 근거를 `nm` 실측과 구버전 대조로 확정했다. 상세는 [`참고/ble/재구조화/바이폴라 전극번호 경계 결함.md`](../../../참고/ble/재구조화/바이폴라%20전극번호%20경계%20결함.md).

### 2.3 동작 보존 논증

| 경로 | 근거 |
|---|---|
| 송신 | SPI1 이 `SPI_WORD_SIZE_8` 이라 **전환 전에도 상위 24비트는 송신되지 않고 버려졌다.** 잘림 지점이 하드웨어에서 소프트웨어로 앞당겨졌을 뿐 전송 바이트가 같다 |
| 수신 | `uint8_t -> int` 확대 변환이라 값 손실이 없다. 16비트 조립(`packet[i] << 8 \| packet[i+1]`)도 정수 승격으로 `int` 계산이라 결과가 같다 |
| 부호 확장 | `impedanceValue`(`char` 배열)의 `(int)` 캐스팅은 하위 8비트를 보존하므로 결과 바이트 동일. 코드 주석으로 근거를 남겼다 |
| 전송 길이 | `transferLength`(21)는 **워드 개수**라 워드가 8비트로 줄어도 그대로. `TRANSFER_WORD_CNT_SHORT` 검사(`tdc_hal_spi.c:71`)도 21 비교를 유지 |

## 축_3 - 근거 검증

### 3.1 전환 완결 확증 (grep)

| # | 확인 | 결과 |
|---|---|---|
| 3-1 | 잔여 `int` 조립 버퍼 | **0건** |
| 3-2 | 잔여 `_u8` 접미사 | **0건** |
| 3-3 | 잔여 구 API 호출 | **0건** |
| 3-4 | HAL 버퍼 타입 | 3개 전부 `uint8_t` (`SPI_Rx_Buffer`·`SPI_Tx_Buffer` 는 `aligned(4)`) |
| 3-5 | 공개 API 시그니처 | `uint8_t *get_rx_packet_addr(void)` · `void write_tx_buffer(const uint8_t*, int)` |

### 3.2 빌드·크기 실측

| 단계 | text | data | bss | 비고 |
|---|---|---|---|---|
| B1 이전 | 185,592 | 4,668 | 21,864 | 기준선 |
| B1 | 185,592 | 4,668 | 21,864 | 버퍼 84->21 x2 |
| B2 | 185,772 | 4,668 | 21,804 | `Rx_DataPacket` 80->20 |
| B3a | 183,920 | 4,668 | 21,804 | `uint8_t` 접근이 짧은 명령으로 |
| B3b | 184,236 | 4,668 | 21,804 | |
| **B3c (최종)** | **184,144** | 4,668 | **21,804** | 어댑터 제거 |

**전 단계 에러 0 · 경고 0.** `-Wconversion` 정밀 검사에서도 버퍼 관련 경고 0건.

정적 메모리는 SPI 버퍼 3개 기준 **248 -> 62 바이트(186 절감)**, 코드는 **1,448 바이트 감소**.

## 이 작업에서 얻은 방법론 교훈

| # | 교훈 |
|---|---|
| 교훈_1 | **포인터 타입 전환은 컴파일러를 도구로 쓸 수 있다.** `int*` -> `uint8_t*` 는 컴파일 에러라 누락이 원천 불가능하다. 반면 **배열 원소 대입은 조용히 잘리므로** `-Wconversion` 이 필요하다. 성격이 다른 두 위험을 구분해 대응했다 |
| 교훈_2 | **전환 기간용 어댑터로 파일 단위 이행이 가능하다.** 신규 API 를 병행 도입하고 마지막에 구 API 를 제거하면, 57개 호출부를 한 커밋에 몰지 않고도 매 단계 빌드·동작이 유지된다. 단 어댑터는 **캐스팅이 아니라 변환 복사**여야 한다 |
| 교훈_3 | **하드웨어 문서의 조건절을 놓치지 말 것.** "니블 재배치" 서술은 `If byte ordering is enabled` 조건부였는데 이를 놓쳐 불필요한 실측 게이트를 계획에 넣었다. 은수님의 상식적 반문("크기 변환이 없는데 재배치할 것이 무엇인가")이 재검증을 촉발했다 |
| 교훈_4 | **메모리 배치 변경 가설은 `nm` 으로 실측해 검증할 것.** "내 변경이 `.data` 배치를 바꿔 결함을 발현시켰다" 는 추정을 세웠으나, 두 빌드의 심볼 상대 거리를 대조해 **기각**했다. 추정으로 원인을 단정했다면 엉뚱한 방향으로 갔을 것이다 |
