# 자료형 전환 체크리스트 - SPI 패킷 버퍼 int -> uint8_t

**TL;DR**: `tdc_hal_spi_get_rx_packet_addr()` 1개소·`tdc_hal_spi_write_tx_buffer()` 57개소(12파일)·로컬 조립 버퍼 27곳을 전수 조사했다. 16비트를 쪼개지 않고 원본을 그대로 넣는 사례는 0건이었다. 실질 위험은 `char`(부호 있음, `-fsigned-char` 확정) 경유 부호확장 2곳, printf 마스킹 비대칭 1곳, 이미 알려진 RX 로그 경계 밖 접근 1곳으로 좁혀지며, **버퍼 타입과 DMA 워드 크기(`tdc_hal_dma.h:7,13`)는 반드시 같은 커밋에서 동시에 바꿔야 한다.**

> [!IMPORTANT]
> 이 문서는 같은 작업 폴더의 [`분석.md §3`](분석.md)·[`계획.md §3`](계획.md)·[`에이전트-로그/02_타입전환-영향범위.md`](에이전트-로그/02_타입전환-영향범위.md), 그리고 [`docs/참고/ble/재구조화/알려진 결함 목록.md`](../../../참고/ble/재구조화/알려진%20결함%20목록.md)가 이미 수행한 선행 분석을 **전제로 삼아 교차 검증**했다. 선행 문서는 파일 단위 요약(위험_1~12, 결함_1~13)이고, 이 문서는 요청받은 8개 목록 형식으로 **모든 항목에 파일:라인을 단** 실무 체크리스트다.
>
> **조사 방법**: `src/`는 읽기 전용으로만 열람했다. 대용량 파일(`tdc_ble_remote.c` 1389줄, `tdc_ble_mapping.c` 2196줄, `tdc_isd_map_ecap.c`+`tdc_isd_map_data.c` 2483줄, `tdc_isd_map_specific_stim.c`+`tdc_isd_map_impedance.c`+`tdc_isd_map_live.c` 2060줄)는 4개 병렬 조사 에이전트에 파일 단위로 분담해 전문을 정독시켰고, 나머지 파일(`hal/`·`tdc_ble_communication.c`·`tdc_ble_remote_sp_para.c`·`tdc_sys_error.c`·`dfu/` 2개·`tdc_ble_protocol.h`)은 직접 정독했다. 병렬 조사자들이 남긴 "미확인" 항목 다수를 이후 상수·구조체 정의를 교차 grep 하여 이 문서에서 추가로 해소했다(예: `df_maxStimulationVloumeLevel=4`, `MaxNumMap=4`, `char`의 부호성, `stimulationPulsePhaseWidth`의 13~255 검증 등). 남은 미확인은 정직하게 "미확인"으로 표기했다.
>
> **한계 고지**: `tdc_ble_mapping.c`(2196줄, 최대 파일)의 448~1687행 구간(자극 파라미터 read/write 루프, RX 방향 - 공유메모리 `int*`로 대입)은 다른 파일들만큼 줄 단위로 전수 확인하지 못했다. 다만 이 구간은 패턴상 목록_6의 "구조체/배열 int 필드 대입(정수 승격 안전)" 일반 원칙에 해당하고, 이 값들이 TX로 재전송되는 지점은 별도 파일(`tdc_isd_map_data.c:451-532`, 이미 목록_3에서 확인 완료)이므로 실질 위험은 낮게 평가하나 **줄 단위 재확인은 구현 착수 전 권고**한다.

> [!CAUTION]
> **DMA 워드 크기와 버퍼 타입은 반드시 같은 커밋에서 함께 바꿔야 한다.** `tdc_hal_dma.h:7`(DMA0/RX)·`:13`(DMA1/TX)이 현재 `WORD_SIZE_32BITS_TO_32BITS`다. SPI 주변장치 자체는 이미 `SPI_WORD_SIZE_8`(`tdc_hal_spi.h:17`)이지만, **DMA가 메모리 쪽을 32비트 워드 21개(=84바이트)로 퍼담고 있어 버퍼가 `int[21]`이 될 수밖에 없는 구조**다(분석.md §2.2 "SPI 워드 크기를 함께 바꿔야 하는가 - 불필요, SPI는 이미 SPI_WORD_SIZE_8"). `transferLength`(21)는 "소스 워드 크기 기준 개수"라 워드 크기가 8비트가 되어도 **21 그대로 유지**하면 된다(분석.md §2.2 실증표). **버퍼만 `uint8_t`로 바꾸고 DMA를 그대로 두면 21바이트 버퍼에 84바이트가 쓰여 인접 메모리를 파괴한다.** 정렬(`__attribute__((aligned(4)))`)·니블 재배치 미확인 2건은 분석.md §2.3에서 이미 해소되어 별도 실측 게이트가 불필요하다.

## 3. 목록_3 - 축소 변환 위험 (가장 중요)

### 3.1 안심 근거 - 16비트 미분할 대입 0건

## 10. 위험도 3등급 분류

### 기계적 (타입만 바꾸면 되는 것)

- `write_tx_buffer` 57곳 중 약 50곳(헤더 echo, enum 상수, 0~255 확정값, 이미 `>>8`/`&0xFF` 분할된 16비트 값)
- RX 소비 함수 6개 중 `fetch_readDataForBleSetting`·`tdc_dfu_ble_fetch_boot`·`tdc_dfu_ble_fetch_ota`(내부가 이미 바이트 단위 설계)
- 페이로드 구조체(`ST__MAPPING_PACKET`·`ST__REMOTECONTROL_PACKET`) - 필드를 `int`로 유지해도 안전(정수 승격)
- `tdc_dfu_ble_ota.c:59`/`tdc_dfu_ble_boot.c:26` - 오히려 중간 `int` 변환이 사라져 단순해짐
- `tdc_hal_spi.c` 내부 for 루프 4곳(목록_4) - 로직 불변
- 목록_2의 23개 스택 로컬 버퍼 선언 자체

### 판단 필요 (값 범위를 확인해야 하는 것)

- `tdc_ble_mapping.c` 448~1687행(자극 파라미터 read/write 루프) - 이 문서에서 줄 단위 전수를 완료하지 못한 유일한 구간
- `tdc_ble_remote_sp_para.c:71,79,85,93,99,105,110`(DAC 기울기/오프셋 레지스터 상수) - 정의 파일 미확인
- `tdc_ble_remote_sp_para.c:188-189,209-210,230-231,251-252`(`stimulationLevel_uA>>8`, 상위바이트 마스킹 없음) - 16비트 초과 가능성 이론상 존재
- `tdc_ble_remote.c:806`(`p_mapStemp`), `:840-842`(led/telecoil/stimul indicator on-off getter), `tdc_isd_map_data.c:286,297,303`(패스키·맵스탬프)
- `tdc_sys_error.c:165`의 `minorError` - 특히 `tdc_isd_map_ecap.c:1267`·`tdc_isd_map_impedance.c:577`의 "FPGA 값 그대로 전달" 2곳
- `tdc_ble_communication.c:107`의 `0xFF` 배터리 미준비 센티널 - 정상값 255와 표현이 겹치는지 소비 측 확인
- `tdc_isd_map_ecap.c:1297,1476-1477`(2차원 배열 인덱스 상한), `tdc_isd_map_impedance.c:637-641`(배열 크기)
- **왜 위험한가**: 이 값들은 현재 `int` 배열에 담겨 있어 256 이상의 값이 들어와도 조용히 동작해 왔다. `uint8_t`로 바뀌는 순간 그 여유가 사라지므로, 지금까지 드러나지 않은 상한 초과가 있었다면 전환 시점에 비로소 자극 파라미터 왜곡으로 나타난다.

### 위험 (잘못 바꾸면 동작이 달라지는 것)

- **DMA 워드사이즈(`tdc_hal_dma.h:7,13`)와 버퍼 타입은 반드시 원자적으로 함께 바꿔야 한다.** 버퍼만 바꾸면 21바이트에 84바이트가 쓰여 메모리 오버런, DMA만 바꾸면 63바이트가 쓰레기로 남는다 - **이 문서에서 가장 심각한 항목**
- `char`(부호 있음, `-fsigned-char` 확정) 경유 2곳(`tdc_ble_remote_sp_para.c:61-64,119-122`, `tdc_isd_map_impedance.c:544-561,637-641`) - 결과는 우연히 보존되나 회귀 테스트 없이는 확신 불가
- `tdc_hal_spi_write_tx_buffer`의 `dataSize` 상한 미검증(목록_8) - 향후 호출부 실수 시 버퍼 오버플로우를 막을 안전망이 없음
- `tdc_dfu_ble_ota.c:147-149`의 `<<24` 조립 - 최상위 바이트가 0x80 이상이면 부호 있는 정수 좌시프트 오버플로우(정의되지 않는 동작), 전환과 무관한 기존 결함이나 손대는 김에 정리 권고
- **왜 위험한가**: 이들은 타입만 바꾸면 되는 수준이 아니라 전환과 동시에 로직·설정을 함께 고쳐야 값과 메모리 안전이 유지된다.
