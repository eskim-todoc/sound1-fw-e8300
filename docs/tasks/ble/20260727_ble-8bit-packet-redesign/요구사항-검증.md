# ② 요구사항 검증

**TL;DR**: [`요구사항.md`](요구사항.md) 를 3축 검증했다. **결함 0건, 보완 1건**. 착수 시점 확인 사실 5건은 전부 `파일:라인` 또는 SDK 원문으로 대조를 마쳤다. 이번 작업은 **HW 설정 변경**이 걸려 있어 5게이트 지침이 강제 적용되며, 요구사항이 이를 명시적으로 수용하고 있는지가 검증의 초점이다.

## 축_2 - 논리적 정합성

| # | 점검 | 결과 |
|---|---|---|
| 2-1 | 요구사항 12건이 은수님 요청 2건을 덮는가 | 요청1(DMA 설정 방법 분석) -> 요구사항_1~7 / 요청2(전체 개선 계획안) -> 요구사항_8~12. **누락 없음** |
| 2-2 | 은수님이 명시한 3개 부가 조건 반영 | "프로토콜 추가·수정 용이" -> 요구사항_8 / "유닛·모듈 개념" -> 요구사항_9 / "테스트 가능" -> 요구사항_10. 전부 반영 |
| 2-3 | 요구사항 간 모순 | 없음. 제약_1(코드 무변경)과 요구사항_12(구현 계획)는 상충하지 않는다 - 계획은 문서다 |
| 2-4 | 선행 작업과의 관계 | [`20260727_ble-protocol-restructure`](../20260727_ble-protocol-restructure/) 의 6단계 로드맵은 `int[]` 전제 위에 세워졌다. 이번 작업이 그 전제를 재검토하므로 **로드맵 갱신이 필요할 수 있음**을 §1 이 시사하나 명시하지 않음 -> 보완_1 |
| 2-5 | 완료 조건의 검증 가능성 | 조건 1~4 모두 문서 대조로 판정 가능 |

> [!NOTE]
> **보완_1**: 이번 분석 결과에 따라 **선행 작업의 6단계 로드맵을 갱신해야 할 수 있다.** 8비트 전환이 성립하면 로드맵의 단계_1b(함수 추출)·단계_3(디스크립터 테이블)의 전제와 난이도가 달라진다. ⑤ 계획에서 **로드맵 통합**을 산출물로 포함한다.

## 축_3 - 근거 검증

착수 시점에 사실로 기재한 5건을 전수 재확인했다.

| # | 주장 | 재확인 |
|---|---|---|
| 3-1 | SPI 주변장치가 이미 8비트 워드 | 확인. `tdc_hal_spi.h:17` `TDC_HAL_SPI_CONFIG` 에 `SPI_WORD_SIZE_8` |
| 3-2 | 32비트는 DMA 설정 | 확인. `tdc_hal_dma.h:7`(DMA0 RX) · `:13`(DMA1 TX) |
| 3-3 | `WORD_SIZE_8BITS_TO_8BITS` 가 **CM3 용** SDK 에 실재 | 확인. `<SDK>/include/cm3/sk5_hw_cid101.h:10983`. **CFX 용(`include/cfx/`)과 별개로 CM3 용 경로에서 확인**한 점이 중요 |
| 3-4 | CMSIS 드라이버 정의 | 확인. `<SDK>/include/cm3/cmsis_drivers/Driver_DMA.h:149` |
| 3-5 | 부트로더에 8비트 워드 DMA 선례 | 확인. `bootloader.c:314`·`:326`(`8BITS_TO_24BITS`) · `:438`(`8BITS_TO_32BITS`) |

> [!IMPORTANT]
> **사실_3 의 검증 경로가 중요하다.** 최초 grep 은 `include/cfx/`(LPDSP32 용) 헤더만 걸렸다. CM3 와 CFX 는 별개 프로세서이므로 **CFX 헤더에 있다고 CM3 에서 쓸 수 있는 것이 아니다.** `include/cm3/` 경로에서 재확인한 뒤에야 사실로 확정했다.
