# 요구사항 - 이월_2 리모콘 0x40~0x59 분해

**TL;DR**: `ble/remote/` 는 `ble/` 에 남은 최대 부채다. **착수 즉시 전제가 반전됐다** - 이월_2 는 «1,340줄 단일 함수» 로 적혀 있었으나 실제로는 `fetch_packet()` 570줄(파싱) + `step()` 752줄(실행) **두 함수**다. 단계_1b 가 매핑 쪽에 한 것과 같은 방식(명령별 추출 + 계층 네이밍)을 적용하되, 최대 위험은 **함수 지역 `static` 5개**의 호출 간 상태 유지다. **안전망을 먼저 깔았다** - shim 3개 + `stub_remote.c` 로 호스트 컴파일을 열고 57 케이스를 기존 코드로 통과시켰다(전체 **431 PASS**).

## 1. 배경

이월_2 는 단계_3(`20260729_ble-descriptor-table`)의 **발견_3** 에서 등록됐다. 명령 카탈로그를 함수 기준으로 재작성하자 미분해 그룹이 드러났다.

> 리모콘 0x40~0x59 는 전부 `tdc_ble_remote_fetch_packet()`(약 1,340줄) 안, Ezairo 0x33~0x36 은 전부 `setting_nrf_ble_adv_info()`(183줄) 안 - **다음 분해 후보**.

매핑 쪽은 단계_1a·1b 로 `tdc_ble_mapping.c` 2,196 → 664줄, `fetch_packet` 1,724줄 → 디스패치만 남는 상태가 됐다. **리모콘은 그 처리를 받지 않았다.**

## 2. 현황 실측 (2026-08-05)

> [!CAUTION]
> **착수 즉시 이월_2 의 전제가 반전됐다.** 이월_2 는 *"`tdc_ble_remote_fetch_packet()`(약 1,340줄)"* 로 적혀 있었으나 **실제로는 두 함수**다.
>
> | 함수 | 범위 | 줄수 | 역할 |
> |---|---|---|---|
> | `tdc_ble_remote_fetch_packet()` | `:51`~`:620` | **570** | 파싱만 |
> | `tdc_ble_remote_step()` | `:639`~`:1390` | **752** | 실행·응답 |
>
> 처음 측정에서 놓친 것은 `step()` 의 시그니처 줄에 행말 주석이 붙어 있어 함수 추출 정규식에 걸리지 않았기 때문이다. **함수 목록은 «여는 중괄호가 다음 줄» 패턴으로 다시 세야 한다.**
>
> **의미가 크다 — 파서와 실행이 이미 갈려 있다.** 단계_5(파서-FSM 분리)가 매핑 쪽 과제인데 리모콘은 그 구조를 이미 갖췄다. 따라서 이월_2 는 «한 덩어리를 쪼개기» 가 아니라 **«두 함수를 각각 명령별로 분해하기»** 다. (이월_1 때도 같은 일이 있었다 - 착수 후 전제가 뒤집혔다.)

| 항목 | 값 |
|---|---|
| `tdc_ble_remote.c` | **1,390줄** (67,231 B) |
| `tdc_ble_remote_fetch_packet()` | `:51`~`:620` = **570줄** (파싱) |
| `tdc_ble_remote_step()` | `:639`~`:1390` = **752줄** (실행) |
| 나머지 함수 4개 | `:29`~`:50` = 22줄 (passkey 3 + clear_command 1) |
| `switch` | **9개** (최대 4중 중첩) |
| `case` (행 앵커) | **65개** |
| `if` / `else` / `for` | 56 / 40 / 17 |
| `break` | 66 |
| **함수 지역 `static`** | **5개** |
| `__LINE__` | 24곳 |
| `tdc_ble_reply_*` 호출 | 50곳 |

### 2.1 구조 - 이중 switch

```mermaid
flowchart TD
    A["tdc_ble_remote_fetch_packet()"] --> B["switch #1 :80 tempCommand"]
    B -->|"플래시 계열 8건"| C["0x4A · 0x4C · 0x4B · 0x4D<br/>erase 3종 · recover"]
    B -->|"default :610"| D["패킷 파싱 + 타임아웃 처리<br/>:610~:780 약 171줄"]
    D --> E["switch #2 :781 remoteDataPacket.command"]
    E --> F["일반 명령 16건<br/>0x40~0x49 · 0x59 · 0x8F 등"]
```

**바깥 switch 는 «플래시 접근이 필요한 명령» 을 먼저 걸러내고, 나머지를 `default` 에서 파싱한 뒤 두 번째 switch 로 보낸다.** 같은 명령(0x4A~0x4D 등)이 **양쪽 switch 에 모두 등장**한다(두 번째는 응답·에러 처리용으로 보인다 - 분석에서 확정).

### 2.2 최대 위험 - 함수 지역 `static` 5개

| 위치 | 변수 | 사용 | 성격 |
|---|---|---|---|
| `:53` | `prev_subCommandData_Num_index` | 11회 | 데이터 인덱스 연속성 |
| `:54` | `stimulPara_index` | 16회 | 자극 파라미터 누적 인덱스 |
| `:641` | `noCommandTime_counter` | - | 무명령 타임아웃 |
| `:642` | `prev_remotegCommand` | 3회 | 직전 명령 |
| `:643` | `disconnectionCounter` | - | 연결 해제 카운터 |

파일 수준에도 `:49` `writingStartSlot_index`(3회)가 있다.

> [!CAUTION]
> **단계_1b 가 똑같은 함정에 빠질 뻔했다.** 당시 설계안이 함수 지역 `static` 4개를 인지하지 못했고, `prev_subCommandData_Num_index` 가 3그룹 23곳에 공유돼 있었다. **접근자 2개로 노출하고 읽기/쓰기 분류표를 어셈블리 호출 수와 1:1 대조**해서 해결했다.
>
> 리모콘은 그때보다 `static` 이 **더 많다**(4 → 5+1). 같은 방식이 필요하며, 분해로 함수가 갈리는 순간 이 상태들이 **각 함수의 지역 static 으로 쪼개지면 동작이 깨진다.**

## 7. 검증 게이트의 특수성

> [!NOTE]
> **2026-08-05 해소 - 안전망을 먼저 깔았다.** 은수님 판단으로 «테스트 선행 후 분해» 를 택했고, `tests/unit/` 에 shim 헤더 3개와 `stub_remote.c` 를 두어 `ble/remote/` 를 호스트에서 컴파일 가능하게 만든 뒤 **57 케이스**를 기존 코드로 통과시켰다(전체 374 -> **431 PASS**). 아래는 착수 시점의 기록이다.

> [!IMPORTANT]
> **리모콘은 호스트 테스트 커버리지가 0 이었다.** `tests/unit/run.sh` 가 컴파일하는 `src/` 파일 4개는 전부 `ble/mapping/` 과 `ble/tdc_ble_reply.c` 이며 `ble/remote/` 는 없다.
>
> 따라서 이 작업은 **정적 지표 + 실기**로 검증해야 한다. 0x63 eCAP 과 반대 상황이다 - 그쪽은 앱이 안 보내 실기가 불가했고, 이쪽은 **실사용 기능이라 실기가 가능하다.**
>
> 단계_3 이 «테스트 선행» 으로 안전망을 깐 것처럼, **리모콘 파싱 테스트를 먼저 추가할지**를 계획에서 판단한다. 1,340줄을 테스트 없이 분해하는 것은 단계_3 이 명시적으로 권하지 않은 방식이다.
