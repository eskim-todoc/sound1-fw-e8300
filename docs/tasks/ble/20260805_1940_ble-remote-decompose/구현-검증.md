# 구현 검증 - 이월_2 리모콘 분해

**TL;DR**: **조건 분기 총수 8지표가 전부 불변**이다. `fetch_packet` 570→70줄, `step` 752→284줄, 함수 6→26개. 커밋_1(static 승격)은 **`.text`·`.data` 바이트 동일**로 등가를 확증했고, 커밋_2·3 은 431 PASS 로 회귀 없음을 확인했다. text +476B 는 `-O0` 호출 오버헤드다.

## 1. 커밋

| # | 해시 | 내용 | 불변량 |
|---|---|---|---|
| 커밋_1 | `76c883f` | 공유 static 2개 파일 수준 승격 | **`.text`·`.data` 바이트 동일** |
| 커밋_2 | `5013fe7` | 파싱 계층 9함수 추출 | 8지표 불변 |
| 커밋_3 | `27e76d1` | 실행 계층 11함수 추출 | 8지표 불변 |
| 커밋_4 | (이 문서 포함) | 문서 | - |

## 2. 8지표 - 전부 불변

| 지표 | 기준선 | 커밋_2 후 | 커밋_3 후 | 판정 |
|---|---|---|---|---|
| `case` | 65 | 65 | **65** | 불변 |
| `switch` | 9 | 9 | **9** | 불변 |
| `if` | 56 | 56 | **56** | 불변 |
| `else` | 40 | 40 | **40** | 불변 |
| `for` | 17 | 17 | **17** | 불변 |
| `\|\|` | 15 | 15 | **15** | 불변 |
| `&&` | 6 | 6 | **6** | 불변 |
| `tdc_ble_reply_*` 호출 | 49 | 49 | **49** | 불변 |

전부 **행 앵커 + 주석행 제외**로 측정했다(이월_I 대응). `reply` 는 `tdc_ble_reply_[a-z0-9]*(` 로 세어 `#include` 줄을 배제했다 — 계획에서 «50» 을 49 로 정정한 이유다.

> [!IMPORTANT]
> **함수 추출은 분기를 만들지도 없애지도 않는다.** 8지표 불변이 그 필요조건이며, 431 PASS 가 충분조건 쪽을 덮는다.

## 3. 규모 변화

| 항목 | 전 | 후 |
|---|---|---|
| `tdc_ble_remote_fetch_packet()` | **570줄** | **70줄** (디스패치만) |
| `tdc_ble_remote_step()` | **752줄** | **284줄** |
| 파일 전체 | 1,390줄 | 1,590줄 |
| 함수 개수 | **6** | **26** (기존 6 + 파싱 9 + 실행 11) |

파일이 200줄 늘어난 것은 함수 시그니처·중괄호·설명 주석 때문이다. **본문은 그대로 옮겨졌다.**

## 4. 커밋_1 - 불변량 정정 기록

계획은 «`.elf` 바이트 동일» 을 걸었으나 **md5 가 달라졌다**(`2fa66722…` → `4c8bedfd…`). 계획 §7 의 중단 조건에 해당해 원인을 규명했다.

원본을 재빌드해 심볼을 대조했다.

```
이전:  2000baa4  prev_subCommandData_Num_index.5
       2000baa8  stimulPara_index.4
이후:  2000baa4  prev_subCommandData_Num_index
       2000baa8  stimulPara_index
```

**`.bss` 주소가 완전히 같다.** 달라진 것은 맹글링 접미사(`.5`·`.4`)뿐이며 이는 `.symtab`/`.strtab` 의 이름 문자열이다. 로드 섹션을 직접 뽑아 확인했다.

| 섹션 | md5 | 판정 |
|---|---|---|
| `.text` | `a5fdf2d61e020c5075f99e6c88ed4749` | **전후 동일** |
| `.data` | `b101315763be1f99c0817e8ab46f677e` | **전후 동일** |

> [!IMPORTANT]
> **순수 승격·개명 유형의 진짜 불변량은 «`.elf` md5» 가 아니라 «로드 섹션 바이트 동일» 이다.** md5 는 심볼 이름 변경에 민감해 **과잉 검출**한다. 이월_1(개명)이 `text` 크기만 봤던 것을 섹션 내용 비교까지 끌어올렸다.

## 5. 3축 검증

### 5.1 지침 준수

| 항목 | 판정 |

| 계층 네이밍 (`tdc_ble_cmd_0xNN_...`) | PASS — 20함수 전부 |

### 5.2 논리 정합

| 확인 | 결과 |

| 추출 함수 인자 최소성 | 파싱은 `(Rx_dataPacket, index)` 또는 `+command`, 실행은 **전부 `(void)`** |
| 미추출 판단 일관성 | 플래시 6건·0x8F·게인제어·빈 case. 이들이 쓰는 `bufferForSPI_tx`·`tx_index` 만 `step()` 에 남음 |
| 계획 대비 이탈 | **1건 — 0x40 누락 → 보강 완료** (§6) |

## 6. 계획 대비 이탈

| # | 이탈 | 처리 |
|---|---|---|
| 이탈_1 | 커밋_3 에서 **0x40 추출 누락**. 계획 §4.2 에 있었으나 case 가 아니라 게이트 밖 `if` 블록이라 추출 스크립트가 잡지 못했다 | **같은 커밋 안에서 보강 완료** (`tdc_ble_cmd_0x40_step_check_passkey()`) |
| 이탈_2 | 계획 §4.3 의 **0x59 하위 분해(`_sub01`·`_sub02`)를 하지 않았다.** 151줄을 한 함수로 뺐고 내부 4중 중첩은 그대로다 | **미이행.** 하위 분해는 «case 본문 이동» 이 아니라 «중첩 `if`/`switch` 를 쪼개기» 라 기계 추출이 안 되고 판단이 들어간다. 구조 변경 위험이 다른 종류라 별도 작업으로 남긴다 |

이월_F 때도 계획 대비 누락(0x64 경계 케이스 4건)이 있었다. **스크립트로 기계 처리할 때 «패턴에 안 맞는 예외» 가 조용히 빠진다** 는 것이 두 번 반복됐다 — 계획 목록과 결과물을 항목 단위로 대조하는 절차가 필요하다.

## 7. 빌드·테스트

| 항목 | 결과 |
|---|---|
| 호스트 테스트 | **431 PASS / 0 FAIL** (매 커밋) |
| ARM 빌드 | 에러 **0** |
| `src/` 경고 | 37건 — **증가 없음** |
| text | 185,444 → **185,920** (+476B) |
| data / bss | 4,668 / 21,804 — **불변** |

`data`·`bss` 불변은 **새 상태를 만들지 않았다**는 뜻이다. 추출 함수는 전부 지역 변수만 쓴다.

## 8. 실기 대기

계획 §5 의 8항목이 그대로다. **실기_6·7(맵/슬롯 데이터 순차 전송)이 핵심** — 승격한 static 2개의 단일 인스턴스 여부는 여러 패킷에 걸친 전송으로만 확인된다.
