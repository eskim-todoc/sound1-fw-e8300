# 계획 검증 - 이월_2 리모콘 분해

**TL;DR**: 커밋 분해와 지표 예측을 재점검했다. **결함 1건** — 커밋_1(static 승격)의 «`.elf` 바이트 동일» 은 **성립하지 않을 수 있다**. 승격 자체는 등가지만 선언을 옮기면 `fetch_packet` 의 줄 수가 줄어 뒤쪽 `__LINE__` 이 밀린다. 불변량을 «크기 동일 + 차이는 `__LINE__` 뿐» 로 고쳤다(이월_F 에서 확립한 방식).

### 보완_1 - 병합 절차

계획이 커밋 4건만 다루고 병합을 적지 않았다. **커밋 후 `claude_develop` 로 `--no-ff` 병합, 은수님 승인 필수**. 이번 작업은 **실기 게이트가 있으므로** 실기 통과가 병합 승인의 근거가 된다(직전 eCAP 작업과 다른 점).

또한 이 브랜치에는 이미 **인프라 2커밋**(`a3fbc70` 요구사항 · `d34fe39` 테스트 인프라)이 있다. 병합 시 함께 올라간다.

## 2. 논리 정합

### 결함_1 (해소) - 커밋_1 의 바이트 동일은 성립하지 않는다

계획은 static 승격을 *"생성 코드가 1비트도 바뀌지 않아야 한다"* 로 적었다. **생성 코드는 맞지만 `.elf` 는 아니다.**

`prev_subCommandData_Num_index`·`stimulPara_index` 선언 2줄을 `fetch_packet`(`:53`~`:54`) 밖으로 옮기면 **그 뒤 모든 줄이 위로 밀린다.** `tdc_ble_remote.c` 에는 `__LINE__` 이 **24곳**이고 대부분 `:53` 뒤에 있다.

| 항목 | 예상 |
|---|---|
| `text`·`data`·`bss` | **동일** (즉치 폭이 안 바뀐다) |
| md5 | **달라진다** — `__LINE__` 24곳 중 이동한 만큼 |

**조치**: 커밋_1 불변량을 **«크기 3종 동일 + 바이트 차이는 `__LINE__` 뿐»** 으로 고친다. 이월_F(`20260805_1925_carry-f-channel-constant`)에서 확립한 방식 그대로다 — 깨진 지점을 디스어셈블리로 특정하면 크기 동일이 바이트 동일에 준하는 근거가 된다.

다만 24곳은 이월_F 의 1곳보다 많아 디스어셈블리 전수 대조가 번거롭다. **대안**: 선언을 옮기되 **빈 줄 2개를 남겨 줄 수를 보존**하면 `__LINE__` 이 전혀 밀리지 않아 **바이트 동일이 성립**한다.

| 방안 | 판정 |
|---|---|
| 줄 수 보존 (빈 줄 2개 남김) | **채택.** 바이트 동일이 성립해 검증이 한 줄로 끝난다. 빈 줄은 커밋_2 에서 자연히 없어진다 |
| 줄 수 변화 허용 + `__LINE__` 24곳 대조 | 기각. 검증 비용이 이득보다 크다 |

### 확인_1 - 지표 «불변» 예측이 옳은가

함수 추출이 분기를 바꾸지 않는다는 것은 단계_1b 에서 *"조건 분기 총수 보존(265/254/143/112 전부 `+0`)"* 으로 실증됐다. 다만 **주의점**이 있다.

| 위험 | 대응 |
|---|---|
| 추출 함수마다 `if` 가 새로 생기지 않는가 | 생기지 않는다. case 본문을 그대로 옮긴다 |
| 함수 선언·정의가 `case`·`if` 로 세지는가 | 세지 않는다. 행 앵커가 `if (`·`case ` 를 요구한다 |
| **주석에 «case»·«if» 를 쓰면 오염되는가** | **오염된다.** 이월_D 의 거짓 FAIL 원인. 추출 함수 주석에 이 단어를 쓰지 않도록 통제 |

### 확인_2 - 커밋 순서가 위험을 옳게 나누는가

| 커밋 | 실패 시 진단 |
|---|---|
| 커밋_1 | 바이트 동일이 깨지면 **승격이 등가가 아니다** → 즉시 되돌림 |
| 커밋_2 | 지표가 틀어지면 **파싱 추출 문제** (static 은 이미 무죄) |
| 커밋_3 | 지표가 틀어지면 **실행 추출 문제** (파싱은 이미 무죄) |

**원인 후보가 커밋마다 좁혀진다.** 설계 의도대로다.
