# 요구사항 검증 - 이월_2 리모콘 분해

**TL;DR**: 전제 반전(단일 1,340줄 → 570 + 752 두 함수)을 반영한 요구사항을 재검증했다. **결함 2건** — ① 목표_1·수용_1 이 `fetch_packet` 만 말하고 `step()` 을 빠뜨렸다. ② 수용_6 이 «리모콘 커버리지 0» 을 전제로 쓰였으나 그사이 57 케이스가 생겨 기준을 올려야 한다. 둘 다 수정했다.

## 2. 논리 정합

### 결함_1 (해소) - 목표·수용 기준이 `step()` 을 빠뜨렸다

전제 반전 전에 쓴 문구가 남아 있었다.

| 위치 | 원문 | 문제 |
|---|---|---|
| 목표_1 | *"`tdc_ble_remote_fetch_packet()` 을 명령별 함수로 분해"* | `step()` 752줄이 범위에서 빠진다 |
| 수용_1 | *"`fetch_packet()` 이 디스패치만 남는다"* | 동 |

**분해 대상이 둘이고 성격이 다르다** — `fetch_packet` 은 파싱(패킷 → 구조체), `step` 은 실행(구조체 → 레지스터·응답). 두 함수를 각각 명령별로 쪼개야 하며, 수용 기준도 각각 필요하다.

### 결함_2 (해소) - 수용_6 의 전제가 그사이 바뀌었다

원문은 *"호스트 테스트 회귀 없음 (현재 리모콘 커버리지 0)"* 이었다. 요구사항 작성 시점에는 맞았으나, **은수님 판단으로 테스트 선행을 택해 57 케이스가 생겼다**(전체 431 PASS). 회귀 없음이 아니라 **57 케이스 전량 통과**가 기준이 돼야 한다.

| 제외 항목(패스키·0x51/53/58)이 목표를 훼손하는가 | 훼손 없음. 코드를 옮기되 로직 무변경 |
| 목표_3(`static` 접근자화)이 항상 필요한가 | **아니다** — §3 근거_1 참조. 요구사항을 조건부로 수정 |

## 3. 근거 검증

### 근거_1 - `static` 5개 중 실제 위험은 2개다

요구사항 §2.2 는 5개를 같은 무게로 다뤘다. 사용 위치를 실측하니 **성격이 갈린다.**

| 변수 | 선언 | 사용 위치 | `switch` 안? | 분해 위험 |
|---|---|---|---|---|
| `prev_subCommandData_Num_index` | `:53` | `:110`·`:114`·`:119`·`:125`·`:325`·`:381`·`:384`·`:390`·`:396`·`:558` | **안 (0x4A·0x4C·0x4D)** | **높음** |
| `stimulPara_index` | `:54` | `:120`·`:414`~`:559` (13곳) | **안 (0x4C·0x4D)** | **높음** |
| `writingStartSlot_index` | `:49` (파일 수준) | `:596`·`:605` | 안 (0x50·0x57) | 낮음 — 이미 파일 수준 |
| `noCommandTime_counter` | `:641` | `:774`·`:778` | **밖** (switch 는 `:781`) | **없음** |
| `prev_remotegCommand` | `:642` | `:682`·`:691` | **밖** | **없음** |
| `disconnectionCounter` | `:643` | `:670`·`:671`·`:674`·`:679` | **밖** | **없음** |

> [!IMPORTANT]
> **`step()` 의 static 3개는 전부 `switch` 밖, 즉 디스패치 이전 구간에서만 쓰인다.** 명령별로 case 를 함수로 빼도 이 셋은 `step()` 본체에 그대로 남는다. **접근자가 필요 없다.**
>
> 실제 위험은 `fetch_packet` 의 **함수 지역 static 2개**뿐이며, 이 둘은 0x4A·0x4C·0x4D 세 명령에 걸쳐 공유된다. 단계_1b 의 `prev_subCommandData_Num_index` 와 **같은 이름·같은 구조**다.

**요구사항 §2.2 의 «리모콘은 그때보다 static 이 더 많다(4 → 5+1)» 는 과대평가였다.** 실질 위험은 단계_1b(3그룹 23곳 공유)보다 **작다**.

### 근거_2 - 접근자가 필요한 조건

| 분해 방식 | `static` 처리 |
|---|---|
| **같은 파일 안에서 함수만 추출** | 함수 지역 static 2개를 **파일 수준으로 올리면 끝.** 추출된 함수가 그대로 접근한다. 접근자 불필요 |
| 파일 분할까지 | 파일 경계를 넘으므로 **접근자 필요** (단계_1b 패턴) |

단계_1b 가 접근자를 만든 것은 **파일을 분할했기 때문**이지 함수를 추출했기 때문이 아니다. 요구사항 목표_3 을 «파일 분할 시」 조건부로 고쳐야 한다.
