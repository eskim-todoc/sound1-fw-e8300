# 계획 - 이월_2 리모콘 분해

**TL;DR**: 4커밋. **커밋_1(static 승격)을 먼저 떼어 `.elf` 바이트 동일로 검증**한 뒤, 커밋_2(`fetch_packet`)·커밋_3(`step`)에서 실제 추출을 한다. 지표는 **함수별로 나눠** 재측정한다(분석-검증 결함_1). 매 커밋마다 431 PASS + ARM 에러 0 을 게이트로 둔다.

## 1. 커밋 분해

| # | 커밋 | 내용 | 불변량 |
|---|---|---|---|
| 커밋_1 | `Refactor(ble): 리모콘 공유 static 2개를 파일 수준으로 승격` | `prev_subCommandData_Num_index`·`stimulPara_index` 를 `fetch_packet` 밖으로. **선언 자리에 빈 줄을 남겨 줄 수를 보존** | **`.elf` 바이트 동일** |
| 커밋_2 | `Refactor(ble): 리모콘 파싱 계층 명령별 분해 (fetch_packet)` | 8 case + default 추출 | 함수별 분기 총수 보존 |
| 커밋_3 | `Refactor(ble): 리모콘 실행 계층 명령별 분해 (step)` | 11 함수 + 0x59 하위 2 | 동 |
| 커밋_4 | `Docs(ble): 리모콘 분해 반영 - 카탈로그·작업 목록` | 문서 | - |

> [!IMPORTANT]
> **커밋_1 을 떼는 이유.** static 승격은 저장 수명·초기값·가시성이 모두 같아 **생성 코드가 1비트도 바뀌지 않아야 한다**(분석 발견_2). 이를 독립 커밋으로 두면 «승격이 안전했다» 가 md5 한 줄로 증명되고, 이후 커밋에서 지표가 틀어졌을 때 **원인 후보에서 static 을 제외**할 수 있다. 단계_1a 가 파일 이동을 떼어 바이트 동일로 검증한 것과 같은 설계다.
>
> **줄 수를 보존하는 이유.** 선언 2줄을 그냥 옮기면 뒤 줄이 밀려 `__LINE__` 24곳이 함께 이동하고 md5 가 깨진다. 그러면 이월_F 처럼 «차이가 `__LINE__` 뿐» 임을 디스어셈블리로 증명해야 하는데, 24곳은 전수 대조 비용이 이득보다 크다. **선언 자리에 빈 줄을 남기면 `__LINE__` 이 하나도 안 밀려 바이트 동일이 그냥 성립한다.** 빈 줄은 커밋_2 에서 자연히 사라진다 ([`계획-검증.md` 결함_1](계획-검증.md)).

## 2. 추출 시그니처

분석-검증 §3 에서 경계를 넘는 상태가 거의 없음을 확인했다.

### 2.1 `fetch_packet` 계열

```c
static void tdc_ble_cmd_0x4A_parse_read_slot(const uint8_t *Rx_dataPacket, int index);
```

- `index` 는 **값 전달**. `switch` 직후 함수가 끝나 되돌릴 필요가 없다(확인_1)
- 나머지 지역은 각 함수의 스크래치가 된다
- 공유 `static` 2개는 커밋_1 에서 파일 수준으로 올라가 그대로 보인다

### 2.2 `step` 계열

```c
static void tdc_ble_cmd_0x45_step_adjust_stim_volume(void);
```

- **인자가 없다.** 입력은 전역 `remoteDataPacket`, 출력은 SPI 송신과 공유메모리다
- `RemoteControlState` 는 `switch` 안에서 미사용이라 넘기지 않는다(확인_2)
- 각 함수가 `uint8_t bufferForSPI_tx[BLE_DataPacketSize]` 와 `int tx_index = 0` 을 지역으로 둔다. **switch 배타성으로 등가**(확인_3, 단계_2 근거)

플래시 6건은 `remoteCommandStartFlag` 를 쓰므로 추출 대상이 아니다(확인_4).

## 3. 함수별 지표 기준선 (분석-검증 결함_1 조치)

| 지표 | `fetch_packet`<br/>(`:51`~`:620`) | `step`<br/>(`:639`~`:1390`) | 합계 | 파일 전체 |
|---|---|---|---|---|
| `case` | 36 | 29 | 65 | **65** |
| `switch` | 5 | 4 | 9 | **9** |
| `if` | 24 | 32 | 56 | **56** |
| `else` | 17 | 23 | 40 | **40** |
| `for` | 15 | 2 | 17 | **17** |
| `\|\|` | 9 | 6 | 15 | **15** |
| `&&` | 6 | 0 | 6 | **6** |
| `tdc_ble_reply_*` 호출 | 4 | 45 | 49 | **49** |

**합계가 파일 전체와 8지표 모두 일치**한다 — 구간 분할이 정확하다는 뜻이다.

> [!NOTE]
> **요구사항 수용_4 의 «50곳» 을 49 로 정정한다.** `grep -c "tdc_ble_reply"` 는 `:21` 의 `#include <tdc_ble_reply.h>` 까지 세어 50 이 나온다. 호출만 세면(`tdc_ble_reply_[a-z0-9]*(`) **49** 다. 이월_I(앵커 패턴 통일)가 지적한 것과 같은 유형의 오염이다.

### 3.1 분해 후 예측

함수 추출은 분기를 만들지도 없애지도 않는다. **8지표 전부 불변**이어야 한다.

| 지표 | 예측 |
|---|---|
| `case`·`switch`·`if`·`else`·`for`·`\|\|`·`&&` | **파일 전체 값 불변** |
| `tdc_ble_reply_*` 호출 | **49 불변** |
| `static` 선언 위치 | 함수 지역 2개 → 파일 수준 (커밋_1) |
| 함수 개수 | 6 → 6 + 9(파싱) + 13(실행) = **28** |

**함수별 값은 이동한다** — 추출된 함수로 옮겨가므로 «`fetch_packet` 안의 `case` 36» 은 「`fetch_packet` + 추출된 9함수」 합으로 봐야 한다. 커밋마다 그 구간 합으로 대조한다.

## 5. 실기 항목 (은수님)

> [!IMPORTANT]
> **리모콘은 실사용 기능이라 실기가 가능하다.** 0x63 eCAP 과 반대다.

| # | 확인 | 근거 |
|---|---|---|
| 실기_1 | 리모콘 **연결·패스키 통과** | 0x40 이 게이트 밖 별도 경로라 분해 영향을 별도로 봐야 한다 |
| 실기_2 | **자극 볼륨 증가·감소** (상하한 포함) | 0x45. 호스트 테스트가 덮지만 실제 자극 반영은 실기만 확인 가능 |
| 실기_3 | **마이크 볼륨 증가·감소** | 0x46 |
| 실기_4 | **텔레코일·자극 인디케이터·LED On/Off** | 0x47·0x48·0x49 |
| 실기_5 | **맵 번호 변경** | 0x44. 사용 가능 맵 탐색 루프가 84줄로 가장 복잡 |
| 실기_6 | **맵 데이터 읽기/쓰기** | 0x4B·0x4D. `stimulPara_index` 연속성이 걸린 경로 |
| 실기_7 | **슬롯 데이터 읽기/쓰기** | 0x4A·0x4C. `prev_subCommandData_Num_index` 연속성 |
| 실기_8 | 정상 동작에서 **에러 로그가 뜨지 않을 것** | 과잉 차단 검출(노하우_5) |

**실기_6·7 이 핵심이다** — 승격한 static 2개가 실제로 단일 인스턴스로 동작하는지는 «여러 패킷에 걸친 순차 전송» 으로만 확인된다.

## 7. 중단 지점

한 커밋이 검증에 실패하면 **그 커밋에서 멈추고 원인을 규명한다.** 특히 커밋_1 의 `.elf` 바이트 동일이 깨지면 승격이 등가가 아니라는 뜻이므로 **되돌리고 재설계**한다.
