# 계획 - BLE 0x65 계층 네이밍 개명

**TL;DR**: **3커밋으로 분해**한다 - 커밋_1 `git mv` 만(내용 무변경, rename 확실 기록) -> 커밋_2 심볼·참조 개명 -> 커밋_3 문서. 검증은 **`text` 완전 동일**이 주 지표이고 보조 3종이 상수 오타를 덮는다. 주석 줄 수를 유지해 **`__LINE__` 까지 불변**으로 만든다.

## 1. 커밋 분해

| # | 커밋 | 내용 | 검증 |
|---|---|---|---|
| 커밋_1 | `git mv` **만** | `tdc_ble_map_stim.c/.h` -> `tdc_ble_cmd_0x65_specific.c/.h`. **파일 내용 1바이트도 안 건드린다** | `git show --stat` 에 `rename` 100% 표시 |
| 커밋_2 | 심볼·참조 개명 | 함수명 · 헤더 가드 · 헤더 주석 · include 2곳 · 호출 12곳 · `run.sh` | 기준_2~7 |
| 커밋_3 | 문서 | `명령 카탈로그.md:96` + 8단계 산출물 + 인덱스 | 기준_9·10 |

> [!IMPORTANT]
> **커밋_1 을 내용 무변경으로 두는 것이 핵심이다** (분석-검증 결함_3). `git mv` 와 내용 수정을 한 커밋에 담으면 유사도 임계에 걸려 rename 이 아니라 **삭제 + 신규 추가**로 기록될 수 있다. 분리하면 rename 이 100% 유사도로 확실히 남는다.
>
> **커밋_1 직후에는 빌드가 깨진다** - `tdc_ble_mapping.c:25` 가 사라진 `tdc_ble_map_stim.h` 를 include 한다. 의도된 중간 상태이며 커밋_2 에서 해소된다. 커밋_1 단독 checkout 은 하지 않는다.

### 2.2 헤더 주석 - 줄 수 보존

현재 12~14 (3줄):

```
// 0x66(라이브 자극)은 tdc_ble_cmd_0x66_live.c 로 분리됐다. 명령 단위로
// 파일을 나누고 함수 이름에 명령 코드를 넣는 체계를 그쪽에서 시범
// 적용 중이며, 0x65 도 확대 단계에서 같은 규칙으로 옮긴다.
```

신규 (**정확히 3줄**):

```
// 명령 단위로 파일을 나누고 함수 이름에 명령 코드를 넣는 계층 네이밍
// 체계를 따른다. 0x66(라이브 자극)은 tdc_ble_cmd_0x66_live.c 에 있다.
// 0x65 는 하위 명령·데이터 인덱스가 없어 subNN_idxKK 세그먼트가 없다.
```

> [!NOTE]
> **줄 수를 3 으로 유지하면 `.c` 의 `__LINE__`(`:109`)이 영향받지 않는다** - `.h` 와 `.c` 는 별개 파일이라 원래 무관하지만, `.c` 상단 주석도 손대지 않으므로 `__LINE__` 은 **완전 불변**이다. 미결_2 가 "기록만"에서 **"불변 확인"으로 강화**된다.

### 2.3 `tdc_ble_cmd_0x65_specific.c`

| 줄 | 편집 |

**그 외 전부 무변경.** 특히 `:20-22` 주석, `:28~114` 본문(파싱 8줄 · 범위 검사 8블록 · 에러 처리)에 손대지 않는다. **줄 수 116 유지.**

### 2.4 `tdc_ble_mapping.c`

| 줄 | 편집 |
|---|---|
| 25 | `#include <tdc_ble_map_stim.h>` -> `#include <tdc_ble_cmd_0x65_specific.h>` |
| 151 | `tdc_ble_map_stim_specific(Rx_dataPacket);` -> `tdc_ble_cmd_0x65_specific_stim(Rx_dataPacket);` |

> [!NOTE]
> **include 위치는 `:25` 그대로 둔다 - 이동 불필요.** 이 블록은 알파벳 순이 아니라 **모듈 그룹 순**(isd -> 외부 -> sys -> ble)이며 그룹 안에서도 알파벳이 아니다(`measure` -> `flash` -> `stim`). `:25` 를 유지하면 `tdc_ble_cmd_0x65_specific.h`(`:25`) -> `tdc_ble_cmd_0x66_live.h`(`:26`) 로 **계층 네이밍 두 파일이 명령 코드 순으로 인접**해 오히려 자연스럽다.
>
> clang-format 재정렬 위험도 없다 - `.clang-format:35` 이 **`SortIncludes: false`** 다 (계획-검증 §3.3).

## 4. 실기 요청서 (은수님)

> [!CAUTION]
> **Eclipse F5 Refresh 후 Clean 재빌드가 필수다.** 파일 **1개가 사라지고 1개가 새로 생긴다**(`tdc_ble_map_stim.c/.h` -> `tdc_ble_cmd_0x65_specific.c/.h`). Refresh 없이 빌드하면 사라진 파일을 찾다 실패하거나, 새 파일이 빌드에서 빠진다.

| # | 항목 | 기대 |
|---|---|---|
| 1 | **Eclipse F5 Refresh -> Clean -> Build** | 에러 0 · 경고 0, text **184,908** (단계_3·4 와 **같은 값** - 개명은 크기를 바꾸지 않는다) |
| 2 | 매핑 프로그램으로 **0x65 특정 자극 실행** | 자극 정상 출력 (전극 · 자극 크기 · 유지 시간 반영) |
| 3 | **범위를 벗어난 값**으로 0x65 전송 (예: 자극 크기 2000uA) | 범위 외 에러 응답 (`en__OutOfDataRange`) |
| 4 | 라이브 자극(0x66) **회귀 확인** | 같은 폴더를 건드렸으므로 15단계 전송 + 자극 시작이 여전히 정상 |

**2번과 3번이 짝**이다 - 정상 경로와 거부 경로를 모두 봐야 파싱이 살아 있음이 확증된다. **4번은 회귀 확인**으로, 0x66 은 이번에 손대지 않았으나 같은 폴더·같은 디스패치를 공유한다.

**text 184,908 이 그대로여야 한다는 점이 이번 작업의 특징**이다. 값이 다르면 개명 외의 변경이 섞인 것이므로 2번 이후를 진행하지 말고 알려 주십시오.
