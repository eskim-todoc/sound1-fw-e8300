### 정합_3 - 불변량 선택이 작업 유형에 맞는가

인수인계 §5 노하우_2 의 유형별 불변량 표에 **개명이 없다.** 기존 유형을 그대로 쓸 수 있는지 검토했다.

| 기존 유형 | 이 작업에 적용 가능? | 판정 |
|---|---|---|
| 파일 이동 - `.elf` 바이트 동일 | **부분** - 파일이 이동하지 않고 *개명*된다. 심볼명도 바뀌어 `.symtab`·`.debug_*` 는 반드시 달라진다 | 바이트 동일은 **과한 기준** |
| 함수 추출 - 조건 분기 총수 보존 | **필요조건이나 불충분** - 개명은 분기를 건드릴 이유가 없어 너무 약하다 | 기준_3 으로 채택(보조) |
| 테이블 주도 - 파싱 필드·경계 상수 집합 | **필요조건이나 불충분** | 기준_4·5 로 채택(보조) |
| 가드 수렴 - 게이트 수렴·본문 불변 | **무관** - 게이트가 없다 | 미적용 |

**따라서 `text` 크기 완전 동일을 주 불변량으로 신설**했다(기준_2). 근거는 [`이력 및 결과.md §발견_2`](이력%20및%20결과.md) 의 5개 실측이며, "로드 섹션에 파일명·심볼명이 기여하지 않는다"가 성립하기 때문이다. **논리 정합 확인**: 로드 섹션 기여가 0 이면 개명이 크기를 바꿀 경로가 없고, 바뀌었다면 본문이 변했다는 뜻이므로 요구사항_5 위반을 검출한다. 필요충분에 가깝다.

### 경계 상수 17개 손검산 대조

정규식 원시 추출은 **18개**다. 필드별 손검산과 대조해 **오탐 1건**을 특정했다.

| 값 | 손검산 출처 | 개수 |
|---|---|---|
| 0 | `firstPulsePhase < 0` · `stimulationLevel_uA < 0` | 2 |
| 1 | `usableElectrodeNum` · `stimulatonMode` · `stimulationElectrodeNum` · `bipolarReferenceElectrodeNum` · `stimulationTime_100msec` 의 하한 5건 + `firstPulsePhase` 상한 `1 <` 1건 | 6 |
| 6 | `stimulatonMode` 상한 | 1 |
| 13 | `pulseWidth` 하한 | 1 |
| 32 | `usableElectrodeNum` · `stimulationElectrodeNum` · `bipolarReferenceElectrodeNum` 상한 | 3 |
| 99 | `bipolarReferenceElectrodeNum` 모노폴라 예외 | 1 |
| 255 | `pulseWidth` · `stimulationTime_100msec` 상한 | 2 |
| 1800 | `stimulationLevel_uA` 상한 | 1 |
| **합** | | **17** |

**오탐 1건 = `value = Rx_dataPacket[index++] << 8;`(`:39`) 의 `8`.** 정규식 `(< [0-9]+)` 이 `<< 8` 의 뒷부분을 잡는다. 비트 시프트이므로 경계 상수가 아니다. **18 - 1 = 17 로 손검산과 일치.**

> [!NOTE]
> **이 오탐을 기준_4 의 판정 절차에 명시해야 한다.** 개명 후 같은 정규식을 돌리면 또 18개가 나오는데, 그것이 정상이다. 절차에 "원시 18개 중 시프트 1건 배제"를 적어 두지 않으면 다음 검증자가 불일치로 오판한다. -> ⑤ 계획에 반영.

### 파싱 필드 8개

`stimulationTime_100msec` 는 첫 추출에서 `stimulationTime_` 로 잘렸다 - 정규식 `[a-zA-Z_]+` 가 숫자 `100` 에서 멈춘 것이다. 소스 `:42` 직접 확인으로 전체 이름을 확정했다. **필드 수 8개는 변동 없다.**
