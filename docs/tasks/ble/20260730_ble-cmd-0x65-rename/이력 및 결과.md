# 이력 및 결과 - BLE 0x65 계층 네이밍 개명 (이월_1)

**상태**: **완료** - 구현 · 정적 검증 · 실기 확인 전부 통과 (2026-07-30).

**TL;DR**: 단계_3 에서 0x66 에 시범 적용한 계층 네이밍을 0x65(특정 자극)로 확대한다. **착수 즉시 이월_1 의 전제가 실측과 다름을 확인했다** - 0x65 는 `subCommand` 참조 0건 · 데이터 인덱스 참조 0건으로 **분해할 계층이 없다.** 따라서 작업은 **개명 1건**으로 축소되며, 범위 검사 8블록(58줄)은 손대지 않는다.

> [!IMPORTANT]
> **이 작업의 불변량은 `text` 크기 완전 동일이다.** `.rodata` 가 별도 섹션이 아니고(`.text` 병합), 파일명·심볼명 문자열이 `.debug_*`·`.symtab` 에만 존재해 **로드 섹션에 영향이 없다**는 것을 실측으로 확정했다. 개명으로 크기가 1바이트라도 바뀌면 순수 개명이 아니라는 신호다.

### 이 작업에서 배운 것

> [!IMPORTANT]
> **개명은 `text` 완전 동일이 불변량인 새 리팩토링 유형이다.** 파일명이 18자 -> 27자, 함수명이 25자 -> 29자로 길어졌는데도 크기가 1바이트도 안 변했다. `.rodata` 가 별도 섹션이 아니고(`.text` 병합) 파일명·심볼명 문자열이 `.debug_*`·`.strtab` 에만 있기 때문이며, 이를 `objdump`·`nm` 으로 사전에 확정한 뒤 예측대로 나왔다.
>
> **`grep -rn` 이 아니라 `git grep` 을 쓸 것.** 이 프로젝트는 Eclipse 워크스페이스가 `src/` 안에 있어 `grep -rn` 이 `src/.metadata/` 를 훑고 **203건 오탐**을 냈다. `git grep` 은 gitignore 를 자동 제외해 정확히 0건이 나왔다.
>
> **개명 작업에서 `grep` 일괄 치환은 금물이다.** `docs/` 의 구 이름 57건 중 갱신 대상은 기준표 1건뿐이고, 나머지 56건은 과거 작업 기록이라 고치면 역사가 거짓이 된다. 게다가 **자기 문서가 구 이름을 인용하므로 총계가 문서를 쓰는 동안 움직인다**(77 -> 91 실측). 집계 기준을 자기 폴더 제외로 고정해야 한다.

### 발견_4 - 바이폴라 기준전극 99 결함이 0x65 경로에 무방비 (2026-07-30, 은수님 지적)

> [!CAUTION]
> **라이브(0x66) 경로는 2026-07-27 에 2중 방어됐는데 0x65 경로는 0중이다.** 같은 결함, 같은 전역, 한쪽만 고쳐진 비대칭이 남아 있었다.

| 방어 | 라이브 0x66 (`tdc_isd_stim_para_setting.c`) | **특정자극 0x65 (`tdc_isd_map_specific_stim.c`)** |
|---|---|---|
| 전극번호 범위 검사 | **있음** `:486~496` | **없음** |
| 레지스터 `0x1F` 마스크 | **있음** `:577` · `:605` | **없음** `:258` · `:284` |

**발현 조건**: `stimulatonMode == en__bipolar` **AND** `bipolarReferenceElectrodeNum == 99`. 모노폴라면 `:206` 이 `flowCounter += 6` 으로 `case 3` 을 건너뛰어 안전하다.

**통로**: 0x65 파싱(`tdc_ble_cmd_0x65_specific.c:86`)이 99 를 `stimulatonMode` **무관하게** 허용한다. 주석은 *"99인 경우 예외 (for 모노폴라)"* 인데 **모노폴라인지 검사하지 않는다.**

**침범 대상 특정 (실측)**:

| 항목 | 값 |
|---|---|
| `electrodeMap` | `0x200080d0`, 128바이트 (32 x 4) |
| `electrodeMap[98]` | `0x20008258` - 배열 끝 **+264바이트 초과** |
| 그 주소의 심볼 | **`s_tdc_table`** `0x200081d0`, 384바이트 |
| 정체 | `ui/tdc_ui_command.c:120` - `command_entry_t[32]`, 원소가 **포인터 3개**(12 x 32 = 384 일치) |

**실기 로그 교차 검증으로 인과 한 축 확정**: `para_setting.c:479` 가 기록한 관측값 *"REF ELEC NUM : 99 (PCB : 70378)"* 에서 **70378 = 0x112EA** 이고, 이는 `.text` 범위(`0x10000~0x3d244`) **안**이다. 쓰레기값이 `s_tdc_table` 의 포인터임이 수치로 확인된다. `para_setting.c:471~473` 의 TODO 가 미확정이라 한 것 중 **쓰레기값의 출처**가 이로써 확정됐다.

**마스크 부재가 증폭한다**: `0x112EA` 급 값이 마스크 없이 OR 되면 전극번호 필드(하위 5비트)를 넘어 **레지스터 주소·명령 필드까지 오염**된다. 라이브 경로는 `0x1F &` 로 최악에도 0~31 에 갇힌다.

**안전 지점(오탐 배제)**: `:224` 좌변 · `:455` · `:534` 는 `stimulationElectrodeNum`(1~32 검사, 99 예외 없음)이라 무해하다. **위험 지점은 `:225` 단 한 곳.**

**조치**: 이번 범위 밖(요구사항 제외_4 · 원칙_4). 섞으면 `text` 불변량이 깨져 개명 검증이 무효가 된다. **이월_D 로 등록**하고 라이브 경로 방어를 그대로 이식하는 것이 대응이다.

## 발견

### 발견_1 - 0x65 에는 분해할 계층이 없다 (2026-07-30)

> [!CAUTION]
> **이월_1 의 문구를 그대로 따르면 존재하지 않는 계층을 만들려 하게 된다.**

계층 네이밍 체계는 `tdc_ble_cmd_0xNN_sub`**MM**`_idx`**KK**`_<이름>` 이다. 0x65 에는 `subMM`·`idxKK` 가 붙을 자리가 없다.

| 항목 | 0x66 (단계_3 대상) | **0x65** |
|---|---|---|
| `subCommand` 참조 | **27건** (`tdc_ble_cmd_0x66_live.c`) | **0건** |
| 데이터 인덱스 참조 (`seq_index`·`subCommandData_Num`) | 있음 (선언 1~15, 실도달 1~35) | **0건** |
| 구조 | 하위 명령 9개 x 데이터 인덱스 15개 | **단일 패킷 8필드** |
| 규모 | 894줄 | **92줄** (`tdc_ble_map_stim.c:24~115`) |

**이월_1 이 이렇게 적힌 경위**: 단계_3 착수 시점에 0x65 와 0x66 이 같은 `tdc_ble_map_stim.c`(845줄) 안에 있었다. 0x66 이 `tdc_ble_cmd_0x66_live.c` 로 떠난 뒤 남은 것은 92줄짜리 단일 함수다. `tdc_ble_map_stim.h:12-14` 의 주석이 *"0x65 도 확대 단계에서 같은 규칙으로 옮긴다"* 로 이 작업을 예고해 뒀다.

**내부 구성도 분해에 적합하지 않다.** 92줄 중 파싱이 8줄, **범위 검사 8블록이 58줄**이다. 블록마다 필드 하나를 검사하고 한글 주석이 붙어 이미 읽힌다. 테이블로 만들면 단계_3 에서 기각된 방식이고, 함수로 뽑으면 3줄짜리 함수 8개가 되어 과분해다.
