# 요구사항 - BLE 0x65 계층 네이밍 개명 (이월_1)

**TL;DR**: 0x65(특정 자극)의 함수·파일 이름을 계층 네이밍 체계(`tdc_ble_cmd_0x65_*`)로 옮겨 `mapping/` 폴더의 명령 단위 파일 규칙을 완결한다. **동작·본문은 일절 바꾸지 않는다** - 불변량은 `text` 크기 완전 동일. 범위 검사 8블록과 `stimulatonMode` 오타는 명시적 제외.

## 1. 배경

단계_3 에서 0x66 에 계층 네이밍(`tdc_ble_cmd_0x66_subNN_idxKK_<이름>`)과 명령 단위 파일(`tdc_ble_cmd_0x66_live.c`)을 시범 적용해 실기까지 통과했다(2026-07-30). `tdc_ble_map_stim.h:12-14` 주석이 0x65 확대를 예고해 뒀다.

착수 실측에서 **0x65 에는 분해할 계층이 없음**을 확인했다([`이력 및 결과.md §발견_1`](이력%20및%20결과.md)) - `subCommand` 0건 · 데이터 인덱스 0건. 은수님 판단으로 **범위를 개명으로 한정**한다.

## 3. 제외 범위 (명시)

| # | 제외 항목 | 사유 |
|---|---|---|
| 제외_1 | **범위 검사 8블록(58줄) 구조 변경** | 블록마다 필드 하나 + 한글 주석으로 이미 읽힌다. 테이블은 기각된 방식, 함수 추출은 3줄 x 8개로 과분해. 은수님 확정 |
| 제외_2 | **`stimulatonMode` 오타 26곳 정정** | 필드명 변경이라 `isd/` 2파일까지 걸친다. 개명 두 종류가 뒤섞이면 검증 축이 흐려진다. **별도 작업으로 분리** |
| 제외_3 | 테스트 파일 `test_map_stim.c` 개명·분할 | `run.sh:121` 의 `[map_stim]` 타깃이 0x65 와 0x66 을 **함께** 컴파일한다(174 PASS 그룹). 분할은 별도 판단 |
| 제외_4 | `bipolarReferenceElectrodeNum != 99` 결함 | 알려진 미결 결함(이월). 원칙_4 - 결함 수정과 구조 리팩토링을 섞지 않는다 |
| 제외_5 | 신규 테스트 추가 | 0x65 는 이미 커버돼 있다(호출 11곳). 개명은 커버리지를 넓히는 작업이 아니다 |

## 5. 기준선 실측값 (2026-07-30, 개명 전)

**경계 상수 다중집합** (17개) - `<< 8` 의 `8` 은 비트 시프트이므로 제외한 값:

```
0 0 1 1 1 1 1 1 6 13 32 32 32 99 255 255 1800
```

| 필드 | 하한 | 상한 | 예외 |
|---|---|---|---|
| `usableElectrodeNum` | 1 | 32 | - |
| `pulseWidth` | 13 | 255 | - |
| `firstPulsePhase` | 0 | 1 | - |
| `stimulatonMode` | 1 | 6 | - |
| `stimulationElectrodeNum` | 1 | 32 | - |
| `bipolarReferenceElectrodeNum` | 1 | 32 | `!= 99` (모노폴라) |
| `stimulationLevel_uA` | 0 | 1800 | - |
| `stimulationTime_100msec` | 1 | 255 | - |

**파싱 대입 필드 순서** (8개, 패킷 인덱스 1 부터):

```
usableElectrodeNum, pulseWidth, firstPulsePhase, stimulatonMode,
```
