# 분석 - BLE 0x65 계층 네이밍 개명

**TL;DR**: 개명은 **소스 20곳 + 문서 1곳**으로 끝난다. `docs/` 의 구 심볼 참조 **57건(이번 작업 문서 제외) 중 56건은 과거 기록이므로 갱신하면 역사가 왜곡된다** - 갱신 대상은 `명령 카탈로그.md:96` **1건뿐**이다. 불변량 `text` 완전 동일이 성립하는 근거를 섹션 배치로 확정했고, 위험은 `subdir.mk`(gitignore) 와 `__LINE__` 두 건으로 한정된다.

### 1.1 명명 근거 - 0x66 과의 대칭

| 명령 | 함수 | 파일 |
|---|---|---|
| 0x66 (라이브 자극) | `tdc_ble_cmd_0x66_live()` + 하위 `_subNN_idxKK_*` | `tdc_ble_cmd_0x66_live.c` |
| **0x65 (특정 자극)** | **`tdc_ble_cmd_0x65_specific_stim()`** | **`tdc_ble_cmd_0x65_specific.c`** |

파일명은 **명령 성격 1단어**(`live` / `specific`), 함수명은 **동작을 드러내는 2단어**(`live` / `specific_stim`)로 맞춘다. 0x65 는 하위 계층이 없어 `_subNN_idxKK_` 세그먼트가 없다.

### 1.2 헤더명 전역 유일성 확인

`tdc_ble_cmd_0x65_specific.h` 와 충돌하는 헤더가 있는지 조사했다. 프로젝트의 `tdc_ble_cmd_*` 헤더는 `tdc_ble_cmd_0x66_live.h` **하나뿐**이며, `0x65` 를 포함하는 헤더는 **없다**. 충돌 없음.

## 3. 불변량 `text` 완전 동일의 성립 근거

### 3.1 섹션 배치 실측

| 실측 | 결과 | 개명이 영향을 주는가 |
|---|---|---|
| `objdump -h` 로드 섹션 | `.text` **0x2d244** 만. `.rodata` 별도 섹션 **없음**(`.text` 병합) | - |
| `objdump -j .rodata -s \| grep map_stim` | **0건** | 파일명이 로드 섹션에 **없다** |
| `strings \| grep tdc_ble_map_stim` | 2건 (`.c` 파일명 · 심볼명) | 둘 다 `.debug_*` / `.strtab` -> **로드 안 됨** |
| `nm \| grep map_stim` | `0002bf9a T tdc_ble_map_stim_specific` | 심볼 이름 문자열은 `.strtab` -> **로드 안 됨** |
| `grep TDC_PRINTF` (대상 파일) | **0건** | `__SHORT_FILE__`(`tdc_printf.h:28`)이 `__FILE__` 을 `.text` 로 끌어올 경로가 **없다** |

**따라서 개명이 `text`/`data`/`bss` 를 바꿀 경로가 존재하지 않는다.** 크기가 바뀌면 본문이 변했다는 뜻이므로, 이 불변량은 요구사항_5(본문 무변경) 위반을 **검출**한다.

### 3.2 필요충분 여부

| 성질 | 판정 |
|---|---|
| 필요조건 | **성립** - 본문이 안 바뀌면 크기는 반드시 같다 |
| 충분조건 | **거의 성립** - 크기를 유지하면서 본문을 바꾸는 것은 가능하나(예: 상수 값 변경), 개명 작업에서 그런 편집이 우발적으로 일어날 경로가 없다. 보조 지표 3종(분기·상수·필드)으로 그 틈을 덮는다 |

### 3.3 `__LINE__` - 유일한 허용 변동

`:109` 의 `tdc_sys_error_send_to_app(..., __LINE__)` 은 헤더 주석(요구사항_6) 길이가 바뀌면 값이 변한다.

| 항목 | 판단 |
|---|---|
| 크기 영향 | **없음** - immediate 상수 인코딩. 100 근방에서 `movs`/`mov` 명령 길이 불변 |
| 계약 여부 | **계약 아님** - 단계_4 에서 근거 3건으로 확정(`stub_ble.h` 명시 · 단계_1b 전량 변경 · 카탈로그 라인 참조 폐기) |
| 조치 | ⑧ 검증에 **값 변화를 기록**하되 판정 기준으로 쓰지 않는다 |

> [!NOTE]
> **주석 줄 수를 유지하면 `__LINE__` 도 불변으로 만들 수 있다.** 요구사항_6 의 예고 문구 갱신을 **같은 줄 수**로 하면 `:109` 가 그대로 남는다. 이렇게 하면 불변량이 더 강해진다 -> ⑤ 계획에서 채택.

## 5. 부수 발견

### 부수_1 - `알려진 결함 목록.md` 결함_14 의 소스 참조가 이중으로 stale

`결함_14` 는 `tdc_ble_map_stim_live()` 진입점의 미사용 지역 변수 11개를 지적하며 `tdc_ble_map_stim.c:759-772` 를 인용한다.

| 문제 | 실태 |
|---|---|
| 함수명 | `tdc_ble_map_stim_live()` 는 단계_3 에서 **`tdc_ble_cmd_0x66_live()` 로 개명**됐다 |
| 파일·라인 | `tdc_ble_map_stim.c` 는 현재 **116줄**이라 `:759-772` 가 **존재하지 않는다** |

**이번 작업(0x65)과 무관한 별개 stale 이다.** 0x66 개명 + 파일 이동으로 이미 무효화돼 있었다. 카탈로그는 함수 기준으로 전환했으나 **결함 목록은 전환 대상에서 빠졌다.**

**조치**: 범위 밖으로 둔다(제외_4 의 취지 - 결함 트랙과 구조 리팩토링 분리). **이월 항목으로 기록**한다.

### 부수_2 - 개명 후 `mapping/` 폴더의 명령 단위 파일 규칙 완결도

| 파일 | 담당 | 계층 네이밍 |

| `tdc_ble_mapping.c` | 디스패치 | 해당 없음 (진입점) |
| `tdc_ble_cmd_0x65_specific.c` | 0x65 | **적용** (이번) |
