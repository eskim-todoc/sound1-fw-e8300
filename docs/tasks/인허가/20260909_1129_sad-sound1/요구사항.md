# Sound1 소프트웨어 아키텍쳐 기술서 - 요구사항

**TL;DR**: 1.5세대 `SAD-FW-TD20B` 를 뼈대로 Sound1 판 소프트웨어 아키텍쳐 기술서를 **Word 로** 작성한다. 핵심은 «내용»이며 문서번호·RID 같은 **식별자는 향후 일괄 갱신 대상**이라 자리만 정확히 잡는다. 범위는 **CFX·HEAR·CM3 + 부트로더/OTA**이고, **QCC5181 은 구조적으로만 포함**한다. 문서는 «QCC 펌웨어 내용을 나중에 붙일 수 있고, 부트로더/OTA 를 나중에 뗄 수 있는» 착탈 구조로 설계한다.

---

## 1. 배경

Sound1 의 소프트웨어 밸리데이션 문서 8종(SAD·SDDD·SIP·SUVC·SUVR·SITC·SITR·SSTC)을 작성해야 한다. 1.5세대 산출물이 `docs/참고/인허가/1.5세대/` 에 있고, 그중 **[01] SAD(소프트웨어 아키텍쳐 기술서)가 이번 작업 대상**이다.

> [!NOTE]
> 1.5세대 기준서 계보의 한계는 이미 기록돼 있다 - `rules/기억/sound1/필수성능시험.md §2`. 1.5세대 문서 자체가 설리번 차용이라 **«왜 이 항목인가»가 재검토된 적이 없을 수 있다**. 실제로 1.5세대 SAD 본문에는 *"소프트웨어는 Ezairo 7150 시스템에서 동작"* 이라는 **세대가 어긋난 문장**이 남아 있다(P043). 승계할 때 그대로 옮기지 않는다.

## 2. 인터뷰 기록

### 은수님 제공 - 주의사항 (필독) 문서

`docs/참고/인허가/1.5세대/주의사항 (필독).md` 요지.

| 구분 | 1.5세대 | Sound1 |
|---|---|---|
| 메인 칩셋 | Ezairo8300 | 동일 |
| 무선 칩셋 | nRF51822 (BLE) | **QCC5181 (블루투스 콤보)** |
| FPGA | 있음 | 동일 |
| TX PMIC | 있음 | 동일 |
| 사용자 입력 | 가속도 센서 (더블 클릭) | **터치 센서 (롱 터치)** |
| 배터리 측정 | Ezairo8300 이 수행 | **QCC 가 수행 -> SPI 로 EZ 에 통보** |
| 충전기 상태 | - | **QCC -> EZ SPI 통보** |
| 제거 | - | **이어피스 연결 · USB 충전** |

은수님 단서: *"이 외에 추가된 기능이나 제거된 기능도 있긴 할 건데, 다 기억나는 상황은 아니라 직접 분석할 필요도 있어."* -> **소스 조사로 델타를 보강한다**(`계획.md §2`).

### 질문_1 - 3절에 넣을 실행체 범위

**답변**: CFX·HEAR·CM3 **필수**, **부트로더/OTA 포함**, 캘리브레이션 제외.

> 은수님: *"아키텍처에 QCC5181이 포함은 되어야 해. 해당 펌웨어는 별개이지만, 전체 시스템에서는 포함되어 있으니 구조적으로 포함된 것으로는 표현해야 해. 그리고 향후 외부기 자체에 대한 소프트웨어 아키텍처 문서로 승격이 되는 경우 이 문서에 QCC5181에 대한 펌웨어 내용이 추가 될 수도 있어. 그래서 추가가 가능할 수 있는 구성으로 문서 작성이 필요해. 반대로 부트로더와 OTA는 향후 뺄 수도 있으니, 뺄 수 있는 구성으로 문서 작성이 필요해."*

**해석 - 이 답변이 문서 구조를 결정한다.**

| 대상 | 지금 | 앞으로 | 설계 요구 |
|---|---|---|---|
| CFX·HEAR·CM3 | 본문 | 유지 | 고정 |
| **QCC5181** | **구조만** (하드웨어 플랫폼·블록도·인터페이스에 등장, 펌웨어 내부는 «범위 밖» 명시) | 펌웨어 내용이 **추가**될 수 있음 | **빈 자리를 미리 만든다** - 절을 지금 만들고 내용만 «본 문서 범위 밖»으로 채운다 |
| **부트로더/OTA** | 본문 | **삭제**될 수 있음 | **통째로 잘라내도 나머지가 안 깨지게** 한다 |
| 캘리브레이션 | 제외 | - | 언급만 (범위 밖) |

### 질문_2 - 요구사항 추적성 표

**답변**: **68항 승계 + 변경 표기**. 번호를 그대로 두고 각 항에 유지/변경/삭제 판정과 사유를 달고, 신규는 RID-69 부터 잇는다.

### 질문_3 - 블록도

**답변**: **PNG 로 새로 그려 삽입**. 1.5세대 그림은 nRF·가속도 센서 기준이라 재사용 불가.

### 은수님 선행 지시 (본 세션)

> *"내용이 중요하며, ID 같은 번호는 향후에 모든 내용이 확정되면 일괄 업데이트할 수도 있어. 그런 관점으로 진행해보자."*

-> 문서번호·개정번호·일자·RID 는 **정확한 값보다 «일괄 치환이 쉬운 형태»가 우선**이다.

## 3. 요구사항

| 라벨 | 내용 | 수용 기준 |
|---|---|---|
| **요구사항_1** | 1.5세대 SAD 의 **절 구성을 승계**한다 (1 서론 / 2 하드웨어 플랫폼 / 3 소프트웨어 아키텍쳐 / 4 요구사항 추적성 / 5 아키텍쳐 검증) | 5개 절이 같은 순서·같은 의미로 존재 |
| **요구사항_2** | 내용은 **Sound1 실제 구현 기준**으로 다시 쓴다. 1.5세대 문장을 검증 없이 옮기지 않는다 | 본문의 사실 주장마다 소스 `파일:라인` 근거가 `계획.md` 에 있다 |
| **요구사항_3** | **QCC5181 을 구조적으로 포함**하되 펌웨어 내부는 범위 밖으로 명시하고, **나중에 내용을 채울 절**을 미리 둔다 | 3절에 QCC 하위절이 존재하고 «범위 밖» 사유가 적혀 있다 |
| **요구사항_4** | **부트로더/OTA 절은 착탈 가능**하게 쓴다 | 해당 절을 삭제해도 다른 절의 문장·표가 깨지지 않는다 (상호참조 0건) |
| **요구사항_5** | 4절 추적성 표는 **RID-1~68 승계 + 유지/변경/삭제 판정 + 신규 RID-69~** 구조 | 68항 전부에 판정이 있고, 변경·삭제에는 사유가 있다 |
| **요구사항_6** | 2절·3절 **블록도 2점을 Sound1 구성으로 새로 그려** 삽입 | 그림에 nRF·가속도 센서·USB·이어피스가 없다 |
| **요구사항_7** | 산출물은 **Word(.docx)** 이며 A4 인쇄 가능 | 표 폭이 본문 폭을 넘지 않는다 |
| **요구사항_8** | 문서번호·일자·개정번호·RID 는 **일괄 치환이 쉬운 형태** | 치환 대상이 `계획.md` 에 목록으로 정리돼 있다 |

## 4. 범위 밖

- QCC5181 펌웨어의 내부 아키텍쳐 (구조적 언급만)
- 캘리브레이션 실행체(`5__calibration/`)
- 나머지 7종 문서(SDDD·SIP·SUVC·SUVR·SITC·SITR·SSTC)
- 소스 코드 변경 - **본 작업은 문서 작성이며 펌웨어를 고치지 않는다**
