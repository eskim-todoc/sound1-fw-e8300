# Sound1 소프트웨어 아키텍쳐 기술서 - 계획

**TL;DR**: 1.5세대 SAD 는 «코어별 모듈 -> 항목» 2단 분해 + RID 68항 추적성 + 3문답 검증으로 되어 있다. Sound1 은 여기에 **무선 칩셋 교체(nRF -> QCC)·사용자 입력 교체(가속도 -> 터치)·배터리 주체 이동(EZ -> QCC)·이어피스/USB 제거**가 겹치고, 소스 조사로 **크래들 뚜껑 상태 수신 · 빔포밍 · I2S 브리지 · 부트로더/OTA · NofM** 5건이 추가로 드러났다. 문서는 **QCC 절을 빈 자리로 미리 만들고 부트로더/OTA 절을 상호참조 0으로 격리**해 착탈 가능하게 쓴다.

### 1.2. 3절의 분해 방식 - «모듈 -> 항목» 2단

각 코어를 **모듈(Module)** 로 나누고 그 아래 **항목(Item)** 을 둔다. 이 2단 구조가 4절 추적성 표의 `Software Module` 열과 짝을 이룬다.

| 코어 | 모듈 |
|---|---|
| CFX | 시스템 제어 / 신호처리 / 내부 자극 장치 실행 |
| Hear | (Function Chain 하나로 서술 - 모듈 분해 없음) |
| CM3 | 시스템 제어 / 신호처리 / 내부 자극 장치 실행 / 블루투스 통신 |
| NRF | 시스템 제어 / 블루투스 통신 |

> [!CAUTION]
> **원본의 결함 2건을 승계하지 않는다.**
>
> 1. P043 *"소프트웨어는 Ezairo 7150 시스템에서 동작하게 된다"* - 1.5세대는 **8300** 이다. 설리번(7150) 문장이 그대로 남았다.
> 2. 3.3 CM3 / 3.4 NRF 아래 «시스템 제어 모듈»이 **Heading 2 로 잘못 지정**돼 있어 목차상 코어와 같은 레벨로 뜬다(P080·P101). Sound1 판에서는 Heading 3 으로 바로잡는다.

## 3. 문서 구조 설계 - 착탈 가능성이 핵심

은수님 요구는 «QCC 는 나중에 **붙이고**, 부트로더/OTA 는 나중에 **뗀다**»이다. 이를 문서 구조로 푼다.

### 3.1. 절 배치

```
1. 서론
2. 하드웨어 플랫폼            <- 그림 1 (QCC5181 포함)
3. 소프트웨어 아키텍쳐        <- 그림 2
   3.1 CFX Core
   3.2 HEAR Core
   3.3 Cortex-M3 (CM3)
   3.4 부트로더               <- [착탈 대상 A]
   3.5 QCC5181               <- [확장 대상 B] 본문은 «범위 밖» 선언 + 인터페이스만
4. 프로세서 간 인터페이스     <- QCC 와의 경계를 여기 모은다
5. 소프트웨어 요구사항 추적성
6. 소프트웨어 아키텍쳐 검증
```

### 3.2. 착탈이 성립하는 이유

| 요구 | 설계 |
|---|---|
| **부트로더/OTA 를 뗄 수 있다** | 3.4 를 **끝에서 두 번째 코어 절**로 두고, 다른 절이 3.4 를 참조하지 않는다. OTA 관련 RID 는 추적성 표에서 **연속 구간(신규 RID 끝)** 에 모아 통째로 지운다. 3.4 를 지우면 3.5 가 3.4 로 밀릴 뿐 본문 문장은 안 깨진다 |
| **QCC 내용을 붙일 수 있다** | 3.5 를 **지금 만들어 두고** 내부를 «본 문서 범위 밖» + 이유 + «추가 시 여기에 기술한다» 로 채운다. 승격 시 이 절만 열어 모듈·항목을 채우면 되고 **번호·목차·추적성 표 구조가 그대로**다 |
| **번호는 나중에 일괄 갱신** | 절 번호는 Word 자동 번호가 아니라 **본문 텍스트 상호참조를 쓰지 않는 방식**으로 쓴다. 즉 *"3.4 절 참조"* 같은 문장을 **한 건도 넣지 않는다** |

> [!IMPORTANT]
> **4절 «프로세서 간 인터페이스»를 신설하는 이유**: 1.5세대는 NRF 를 3.4 절에서 내부 아키텍쳐까지 서술했다. Sound1 의 QCC 는 내부를 쓸 수 없으므로, **«우리가 아는 것»(SPI·I2S 로 무엇을 주고받는가)을 별도 절로 분리**해야 QCC 절을 비워 둔 채로도 문서가 완결된다. 이것이 착탈 구조의 핵심이다.

### 3.3. 일괄 치환 대상 (은수님 «ID 는 향후 일괄 업데이트» 지시 반영)
