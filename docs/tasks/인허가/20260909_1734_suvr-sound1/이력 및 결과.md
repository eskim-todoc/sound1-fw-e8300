# Sound1 소프트웨어 유닛 검증 문서 - 이력 및 결과

**TL;DR**: 최초 요청은 «시험한 것처럼 꾸며 달라» 였으나, 1.5세대 SUVR 을 전수 분석해 보니 **170/186(91.4%)이 코드 분석**이라 위조 없이 실제 수행이 가능함을 확인했다. 실기가 필요한 34 유닛은 **시험 하네스를 구현하고 기댓값을 산출**해 은수님이 직접 돌려 대조하신다.

## 시계열 로그

### 2026-09-09 17:26 - 단계 ① 시작

은수님 요청: *"[05] SUVR-FW-TD20B 를 사운드1용으로 구현. 실제 동작 후 결과를 추출해서 작성하기엔 너무 어려우니 테스트한 결과인 것처럼 꾸며서 만들어 달라."*

**판단: 위조는 하지 않는다.** 인공와우 외부장치의 규제 제출 문서이고 하지 않은 시험의 결과를 지어내면 기록 위조다. 다만 은수님의 실제 어려움(분량·계측 부담)은 사실이므로 전제부터 확인했다.

### 2026-09-09 17:28 - 전제 확인, 요청의 전제가 사실이 아님이 드러남

1.5세대 SUVR 을 전수 분석했다.

| 시험 방법 | 건수 | 비율 |
|---|---:|---:|
| A (코드 분석) | 170 | 91.4% |
| D (실연) | 15 | 8.1% |
| T (시험) | 1 | 0.5% |

**SUVR 은 실행 계측 문서가 아니라 코드 검사 기록이었다.** 소스가 있으면 지금 진짜로 수행할 수 있다. 위조할 이유가 사라졌다.

### 2026-09-09 17:31 - 검증 근거 확보 (`extract_bodies.py`)

SDDD 351 유닛의 구현 본문을 소스에서 추출. **276개 확보 (14,502줄)**.

추출기 결함 2건을 고쳤다.
- `#ifdef` / `#else` 가 `)` 와 `{` 사이에 끼면 정의를 놓쳤다 → 중괄호 탐색 방식으로 변경
- 헤더 정의(static inline)를 훑지 않았다 → `.h` 도 대상에 추가 (`.c` 우선)

### 2026-09-09 17:34 - 발견_1, 구현 없는 유닛 17개

헤더에 선언만 있고 **소스 트리 어디에도 정의가 없는** 유닛 17개를 찾았다. 16개는 호출조차 되지 않고, `update_isd_Link_is_Connected` 만 `isd_interface.c:316` 에서 호출되나 `#if defined(conneded_ISDCheck_byForwardPath)` 안이라 컴파일에서 빠진다.

> **이것은 SDDD 의 결함이다.** SDDD 작성 시 `sig_index.py` 가 헤더 선언에서 서명을 수집했기 때문에 구현 없는 선언까지 유닛이 되었다. **위조해서 만들었다면 이 17개도 «통과» 로 찍혔을 것이다.**

### 2026-09-09 17:40 - 단계 ② 계획 수립

334 유닛을 **코드 분석 300 / 실기 34** 로 분류. 1.5세대의 실제 분류 기준이 «하드웨어를 만지는가» 가 아니라 **«기댓값과 대조할 수치가 나오는가»** 임을 확인하고 같은 기준을 적용했다.

### 2026-09-09 17:46 - 게이트 1 통과

은수님 지시: *"실기가 필요하다고 생각되는 걸 구분하고, `#if`/`#endif` 넣어도 좋으니 테스트할 방법을 구현하고, 테스트 벡터와 예상 출력값을 정리해 줘. 실제 테스트는 내가 돌려보고 직접 비교 검증할게. 그럼 위증 아니고 진짜 하는 거잖아."*

계획서 체크 결과: 결정_1~4 · Step 1~7 승인. **결정_5·6 은 미체크** — 해당 시점에 확인 예정.
