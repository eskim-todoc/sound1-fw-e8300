# Sound1 소프트웨어 유닛 검증 문서 - 계획

**TL;DR**: 334 유닛(미구현 17 제외)을 **코드 분석 300 / 실기 34** 로 나눈다. 코드 분석은 제가 소스를 실제로 검사해 채우고, 실기는 **`#if` 로 감싼 시험 코드를 넣고 테스트 벡터와 예상 출력값을 산출**해 은수님이 돌려 대조하신다. 그러면 전건이 실제 수행이 된다. **소스 변경이 포함되므로 게이트 1 이 필요하다.**

---

## 1. 분석

### 1.1 검증 방법 분류 근거

1.5세대가 D(실연)로 처리한 15건은 전부 **«출력 수치를 기댓값과 대조할 수 있는»** 유닛이었다. 하드웨어를 만지는 유닛(FPGA 레지스터·I2C·전원 소자)조차 A(코드 분석)로 처리했다. 기준은 «하드웨어를 만지는가»가 아니라 **«기댓값과 대조할 수치가 나오는가»** 다.

이 기준을 Sound1 334 유닛에 적용한다.

| 방법 | 건수 | 대상 | 근거 |
|---|---:|---|---|
| **A** (코드 분석) | 300 | 초기화·설정·상태 관리·드라이버·부트로더 | 대조할 수치가 없다. 구현 여부를 코드로 확인 |
| **D** (실연) | 34 | 신호처리 연산 · 자극 기법 · PCM 비트스트림 | 입력을 넣으면 **결정적 출력 수치**가 나온다 |

### 1.2 실기(D) 대상 34 유닛

전부 **순수 연산**이라 입력을 주면 출력이 결정된다. 하드웨어 상태에 의존하지 않으므로 시험 벡터 주입이 성립한다.

| 계통 | SU-ID | 유닛 |
|---|---|---|
| **AGC** | CFX-076·077·078·080 | 실행 · 이득 계산 · 시정수 적용 · 이득 적용 |
| **주파수 분석** | CFX-085·086·087 | 입력 갱신 · 대역 대표값 · 통과 대역 인덱스 |
| **비선형 매핑** | CFX-088·089·090·091·093 | C/T 레벨 · 최대 레벨 · 로그 계수 · 볼륨 반영 계수 · 거듭제곱 |
| **자극 기법** | CFX-094~102 (9) | 헤더 · 실행 · CIS · NofM(초기화·피크선택·인터리빙·패킷·PCM 기록) |
| **PCM 비트스트림** | CFX-104~109 (6) | 프리앰블 · 실시간 자극 · 특정 명령 · 대기 · 연결 검사 · 영 채움 |
| **검사 프레임** | CFX-113 | 채널별 검사 프레임 생성 |

| **자극 파라미터** | CM3-119·120 | 자극 범위 설정 · 출력단 보정 값 |

### 1.3 시험 하네스 설계

> [!CAUTION]
> **원본 소스를 수정하지 않는다.** 은수님 지시(2026-09-09). 기존 `.c` / `.h` 는 한 글자도 건드리지 않고,
> 시험 코드는 **신규 파일에만** 넣는다. 계획 초안은 «각 대상 `.c` 파일 하단에 `#if` 블록 추가» 였으나
> 그것도 원본 수정이므로 폐기했다.

**성립 근거 (실측)**: 실기 대상 34 유닛의 함수가 **전부 `static` 이 아니고 헤더에 선언되어 있다.**
따라서 별도 파일에서 그대로 호출할 수 있고 원본을 열 이유가 없다.

| 대상 헤더 | 유닛 |
|---|---|
| `agc.h` | 4 |
| `FrequencyAnalysis.h` | 3 |
| `nonlinearMapping.h` | 5 |
| `stimulationStrategy.h` | 9 |
| `driver_PCM.h` | 7 |
| `driver_PCM_liveStimulation.h` | 1 |
| `stimulationParaCal.h` · `commonDataProcessing.h` | 5 |

**방식**: 신규 파일 2 개를 만들고 **파일 전체를 `#if defined(TDC_UNIT_TEST)` 로 감싼다.** 매크로가 없으면 빈 번역 단위가 되므로 빌드에 넣어 두어도 평시에는 **한 바이트도 늘지 않는다.**

```c
/* tdc_unit_test_cfx.c - 유닛 시험 전용. 원본 소스는 수정하지 않는다. */
#if defined(TDC_UNIT_TEST)
int          tdc_ut_result[TDC_UT_RESULT_MAX];   /* 결과 적재 */
int          tdc_ut_count;                       /* 적재 개수 */
volatile int tdc_ut_done;                        /* 중단점 지점 */

void tdc_ut_run_all(void)   /* 진입점 */
{
    tdc_ut_agc();           /* 각 유닛 시험을 차례로 수행 */
    ...
    tdc_ut_done = 1;        /* 여기에 중단점을 걸고 tdc_ut_result 를 조회한다 */
}
#endif
```

| 결정 사항 | 안 | 근거 |
|---|---|---|
| **원본 수정** | **하지 않는다** | 은수님 지시. 34 유닛 전부 외부 호출 가능하므로 필요도 없다 |
| 파일 | `src/1__cfx/test/tdc_unit_test_cfx.c` · `src/2__cm3/.../test/tdc_unit_test_cm3.c` (신규) | 코어별 분리 |
| 결과 전달 | **메모리 배열 + 중단점** | 1.5세대가 «디버깅용 중단점을 적용하여 출력 데이터를 확인» 방식. UART/RTT 는 타이밍을 바꾼다 |
| 매크로 이름 | `TDC_UNIT_TEST` | 루트 지침 §신규 심볼 `tdc_` 접두어 |
| 벡터 주입 | 전역 입력 버퍼에 상수 배열을 기록한 뒤 원 함수 호출 | 원 함수 서명·본문 불변 |

**진입점 호출 방법** — 이것도 원본을 고치지 않는다. 절차서에 두 가지를 안내한다.

| 방법 | 절차 | 원본 수정 |
|---|---|---|
| **가 (권장)** | 디버거에서 `tdc_ut_run_all()` 을 직접 호출하거나 PC 를 해당 주소로 옮긴다 | 없음 |
| 나 | 시험할 때만 `main()` 에 호출 한 줄을 임시로 넣고, 끝나면 되돌린다 | 은수님이 수동으로, 임시로 |

> [!CAUTION]
> **소스 주석에 CP949 비호환 문자 금지** (프로젝트 CLAUDE.md). `—` `–` `≈` `µ` `►` 를 쓰지 않는다. 한글 · `·` · `→` 는 안전하다.

### 1.4 예상 출력값 산출 방법 (자체 검증)

각 대상 함수의 고정소수점 연산을 **Python 으로 정수 의미까지 그대로 재현**해 기댓값을 계산한다. 이것이 «테스트 벡터»가 된다. 예를 들어 NofM 점수 병합은 `(amplitude << 5) | (31 - index)` 이므로 입력 배열에서 기댓 정렬 결과가 결정된다.

**재현이 불가능한 것은 기댓값을 내지 않는다.** DSP 라이브러리(`Win_DFT_R_Forward`·`vMag`·`MATHLIB_*`) 내부에 의존하는 값은 «라이브러리 출력에 의존» 으로 표기하고 은수님 실측에 맡긴다.

### 1.5 실패 시나리오

| 시나리오 | 징후 | 대응 |
|---|---|---|
| **시나리오_1** | 시험 코드가 평시 빌드에 섞여 들어간다 | 파일 전체가 `#if` 안이므로 매크로 미정의 시 빈 번역 단위가 된다. 원본 `.c`/`.h` 무변경을 `git diff` 로 확인 |
| **시나리오_2** | 내가 계산한 기댓값이 고정소수점 반올림 때문에 실측과 어긋난다 | 1.5세대도 «고정소수점 연산 고려» 를 통과 기준에 명시했다. 허용 오차를 기준에 함께 적는다 |
| **시나리오_3** | 벡터 주입이 원 함수의 전역 상태를 오염시켜 이후 동작이 깨진다 | 시험 전 상태 저장 · 시험 후 복원. 시험은 초기화 직후 1회만 수행 |

## 2. 실행 계획

### Step 1 [필수] SDDD 에서 미구현 17 유닛 제거

체크리스트에 17개를 체크하고 `make_sddd.py` 재실행. 351 → 334. 검증 9항 재실행.

### Step 2 [필수] 검증 방법 분류표 확정

334 유닛에 A/D 를 배정하고 `suvc_rows.py` 로 데이터화.

### Step 3 [필수] SUVC 작성 (`[04] SUVC-FW-SND1 ... .xlsx`)

표지 + 기준서 시트. 334행. 방법·절차·통과 기준까지. **결과 열 없음.**

### Step 4 [필수] 코드 분석(A) 300 유닛 실제 수행

추출한 본문 14,502줄을 실제로 검사해 «측정/검토 내용» 을 작성. 근거는 `파일:라인`.

### Step 5 [필수] 실기(D) 34 유닛 시험 하네스 구현 *(신규 파일만)*

**신규 파일 2 개**를 만든다. 파일 전체를 `#if defined(TDC_UNIT_TEST)` 로 감싸 평시 빌드에서 완전히 사라지게 한다.
**기존 `.c` / `.h` 는 수정하지 않는다.**

### Step 6 [필수] 테스트 벡터 · 예상 출력값 산출

Python 재현으로 기댓값 계산. 산출물: `시험벡터/` 폴더 + SUVC 통과 기준에 수치 반영.

### Step 7 [필수] SUVR 작성 (`[05] SUVR-FW-SND1 ... .xlsx`)

A 유닛 300건은 채운다. **D 유닛 34건은 결과 열을 비우고** 별도 «실기 대상» 목록으로 분리.

### Step 8 [선택] 은수님 실기 결과 반영

은수님이 돌려 채워 주시면 반영하고 문서를 확정.
