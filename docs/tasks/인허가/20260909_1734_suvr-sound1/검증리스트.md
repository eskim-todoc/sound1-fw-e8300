## 2. 은수님 확인 (써 봐야 아는 것)

| 라벨 | 항목 | 어떻게 확인하나 | 은수님 |
|---|---|---|:---:|
| **확인_1** | **문서를 열어 읽을 만한가** | `[04]`, `[05]` xlsx 를 열어 열 폭·줄바꿈·인쇄 상태를 본다 | ⬜ |
| **확인_2** | **측정/검토 내용의 서술 밀도가 적절한가** | 몇 유닛을 골라 읽어 본다. 너무 얕거나 장황하지 않은지 | ⬜ |
| **확인_3** | 시험 대상 소프트웨어 이름과 버전이 맞는가 | 표지와 머리말의 `OTE_SND1` / `1.0.0` 확인 | ⬜ |
| **확인_4** | 동작 하드웨어 표기가 맞는가 | `인공달팽이관 외부장치 Sound1 시제품` 확인 | ⬜ |
| **확인_5** | 장비 및 지그 목록이 실제와 맞는가 | 7개 항목. 빠지거나 없는 장비가 있는지 | ⬜ |
| **확인_6** | **하네스가 빌드되는가** | `TDC_UNIT_TEST` 정의하고 빌드 | ⬜ |
| **확인_7** | **평시 빌드에 시험 코드가 안 들어가는가** | 매크로 없이 빌드 후 `tdc_ut_` 심볼 0건 확인 | ⬜ |
| **확인_8** | **실기 시험이 돌아가는가** | 절차서대로 진입점 호출, 결과 배열 조회 | ⬜ |
| **확인_9** | **기댓값이 실측과 맞는가** | 절차서 §2·§3 표와 대조 | ⬜ |
| **확인_10** | 실기 대상 33 유닛 선정이 타당한가 | 계획서 §1.2 목록. 빠지거나 넣지 말아야 할 것이 있는지 | ⬜ |
| **확인_11** | **발견된 코드 결함을 어떻게 할지** | 이력 문서 §위조했다면 묻혔을 것들. 고칠지, 문서에만 남길지 | ⬜ |

> [!IMPORTANT]
> **확인_9 가 어긋나면 그것부터 봅니다.** 제가 계산한 기댓값이 틀렸을 수도, 코드가 의도와 다를 수도 있습니다. 어느 쪽이든 그때 함께 보시죠.
>
> **확인_11 은 이 작업 범위 밖입니다.** 본 작업은 문서 작성이고 소스 수정은 별도 작업입니다. 다만 결함 목록은 남겨 두었습니다.
