### 예상 테스트 입출력 문서화 (완료)

현재 유닛 115개와 공통 검사/감사기록 시험을 대상으로 입력 조건, 초기 상태, 실행 동작, 예상 값/동작/로그를 정리한다. 수치 배열과 벡터를 생략하지 않고, PC 대체 환경과 실제 장치 확인을 구분한다. 현재 제품 불일치와 판정이 정의되지 않은 관찰값을 통과 결과로 바꾸지 않는다. 실제 보드 시험은 수행하지 않는다.

- 산출 위치: `docs/참고/인허가/사운드1/DHF/04_설계 검증/SW/펌웨어/예상 테스트 입출력`.
- 주 작업은 공통 안내/감사기록/전체 대응 및 검증, CFX 계산/분석, CFX IO/HEAR, CM3 계산/상태, CM3 IO, BOOT는 ID별로 쓰기 범위를 나눠 병행한다.
- 완료 조건: 115개 ID 누락 없음, 구현된 모든 벡터/관찰 항목과 사전 기대값 대응, 알려진 실패 분리, 내부 링크와 소스 보존 확인. 기존 Word/Excel, 제품/시험 코드, 작성자 전용 문서와 필수성능 기준서는 그대로 둔다.
- 추가 요청: RTT는 표/요약만이 아니라 접두어, C 번호, A 배열 전량, 줄 나눔, PASS 요약까지 실제 출력과 바로 대조할 수 있는 전문을 제공한다. 기존 로그 포매터를 문서용으로 사용하며 제품 시험은 실행하지 않는다. 실행마다 달라지는 관찰값은 범위와 변동 사유를 따로 표시한다.

#### 문서화 결과와 확인

- [전체 목록](../../../참고/인허가/사운드1/DHF/04_설계%20검증/SW/펌웨어/예상%20테스트%20입출력/README.md)에서 CFX 42, HEAR 2, CM3 51, BOOT 20개 입력/초기 상태/실행/예상 결과를 찾는다. [로그 전문](../../../참고/인허가/사운드1/DHF/04_설계%20검증/SW/펌웨어/예상%20테스트%20입출력/예상%20로그/README.md)은 설명과 분리해 배열 전체를 바로 대조하도록 구성했다. 공통 시험 도구의 고정 캡처도 13조건/283정수/156줄을 별도 수록했다.
- 문서용 도구는 사전 기대배열을 변경하지 않은 `tdc_ut_log.c`에 전달해 줄 나눔을 만들었다. 제품 함수를 호출하지 않았으며, 실제 RTT 수집도 아니다. 생성 문자열에서 배열 인덱스/정수/최종 상태/실패 개수를 다시 해석하고 CRLF 포함 60바이트를 확인했다. HEAR 시간 초과 2조건은 FAIL, 영 입력 원시 관찰 2조건은 OBSERVED로 출력하며 PASS로 바꾸지 않았다.
- PC는 실제 출력 형식을 따른다. CFX_EXTRA는 repeat 0/1의 전체 JSON, CM3 보충은 시나리오별 RECORD, BOOT는 STATUS/ACTUAL/EXPECTED로 작성했다. CM3 IO는 배열을 stdout에 출력하지 않으므로 실제 요약 33종만 싣고 숫자별 기대값은 유닛 문서에 남겼다. 정상 계약 모드와 알려진 실패 재현 모드를 구분했다.
- 코어별 검사기는 문서/사전 기대값/현재 소스 근거/입력 배열과 링크를 대조했다. 독립 DFT와 고정소수점 계산, expected와 actual의 혼용 방지, 잘못된 기대값 거부도 확인했다. 이 검사 성공은 제품 시험 통과를 뜻하지 않는다.
- 독립 검토의 보완 사항: BOOT 이미지 구획의 선행 읽기 길이 설명, 인코딩 검사의 실제 범위, CFX 수치 구간/오류 주입 누락을 수정했다. CM3-051은 타깃 RAM 시험에서 첫 응답 후 두 번째 응답까지 SPI busy가 해제되지 않아 대기할 수 있음을 확인했다. PC의 `__WFE` 대체 함수는 이를 해제하므로 PC 완료를 타깃 완료로 간주하지 않는다. 유닛 문서/로그/전체 목록에 경고만 반영하고 코드는 그대로 두었다.
- 최종 근거: [전체 출판 검사](qa/expected-io/publication-checks.json), [로그 검증](qa/expected-io/full-logs-checks.json), [413개 보존 확인](qa/expected-io/preservation.json), 같은 폴더의 코어별 manifest/로그 export. 내부 링크, 표 열 개수, 코드 블록 닫힘, 유닛 등록 중복/누락 모두 이상 없음. QCC 추가 위치도 중앙 목록에 연결했다.
- 이번 단계에서는 제품/시험 코드, 기존 Word/Excel, 필수성능 기준서, 작성자 전용 파일을 수정하지 않았다. 장치 실행/다운로드/커밋/병합도 하지 않았다. 앞 단계의 33항 회귀 성공은 이전 이력이며 이번 문서화에서 다시 수행한 결과가 아니다.

### 제품 소스 보존 조건의 추가 보완

은수님이 제품 원 소스 수정 없이 시험 코드를 최대한 보완하고, 제품 오류 처리 내용을 정리하도록 요청했다. 보드 시험은 보류한다. 이번 작업 시작 시 소스/헤더/링커/프로젝트 설정 299개 파일의 SHA256을 `tmp/unit-tests/source-preservation/before.json`에 기록했다. 기존 제품 파일과 사용자 변경은 그대로 유지한다. 쓰기 범위는 시험 전용 파일, 검사기, 관련 작업 기록이다. 제품 함수는 실제 구현을 실행하되 외부 의존만 기존 시험 경계 또는 호스트 fixture에서 대체한다.

- CM3 I/O/명령, CM3 순수 제어, CFX, BOOT의 시험 파일을 담당자별로 나눈다. 공통 실행기/전체 대응표/오류 정리와 최종 검증은 주 작업이 맡는다.
- 정상/오류 입력, 반환과 상태, 반복 및 복원을 함께 확인한다. 현재 구현의 잘못된 결과를 기대값으로 바꾸지 않는다.
- 원 소스에 새 경계가 필요해야만 가능한 타깃 자동 실행은 강제로 추가하지 않는다. 가능한 PC 입력을 먼저 확장하고 타깃 잔여는 구체적인 이유로 남긴다.

아래 중간 검증은 이전 단계의 이력이다. 78개 실행/과거 불일치/기준서 이전 해시 등은 위 최종 현황으로 대체해 읽는다. 미완료 조건은 현황 문서에서 그대로 관리한다.

- 은수님이 전체 시험 코드 추가와 필요한 수정을 승인했다. 현재 기준서의 CFX 42, HEAR 2, CM3 51, BOOT 20개를 기준으로 한다. 방법 분류는 I 1/A 31/D 34/T 49이며 과거 집계와 구분한다.

은수님이 추가 에이전트 사용을 허용한 뒤 실제 파일 수정 범위를 나눴다. 입력 기준은 위 현행 기준서와 현재 소스이며 기존 사용자 변경은 보존한다. 공통 코드/작업 기록은 주 작업만 수정한다.

| 담당 | 소유 범위 | 완료 판단 |
|---|---|---|
| 주 작업 | CFX 계산 벡터, 공통 60바이트 로그, CM3 RTT 전달, 전체 수렴 | 실제 함수 호출/상태 복원/출력 재시도 검사 |

### 중간 검증

- `tests/unit/check_cfx_vectors.py`: 실제 C 함수의 계산 벡터 17개를 두 번씩 호출하고 관련 RAM/초기 I2S 상태 복원을 대조했다. DSP 라이브러리 경계는 호스트에서 대체하므로 라이브러리 근사/CFX ABI의 실기 검증과 구분한다.
- `tests/unit/tdc_ut_cfx_io_check.py`: CFX 12개 실행 중 15의 복사 완료 플래그(실제 0/기대 1), 40의 명령 프레임 수(실제 24/기대 3)가 불일치다. 이 두 항목을 기댓값 수정으로 통과시키지 않았다. HEAR는 실제 연산을 수행하지 않은 호스트에서 TARGET_REQUIRED를 반환한다.
- `tests/unit/tdc_ut_cm3_run.py`: 18개 ID의 준비한 벡터를 두 번씩 실행했고 값/상태 복원 검사에서 차이가 없었다. 13/21/22/29는 부분 벡터이므로 전체 유닛 합격이 아니다.
- `tests/unit/tdc_ut_boot_check.py`: 실제 AES/이미지/파일 처리 함수 16개 ID, 116개 비교. 제조 정보 검사 반환값 무시(7/C6), 선언 구획 누락 허용(11/C6)을 재현했다. 호스트 파일은 임시 폴더에 격리하며 타깃 자동 쓰기/리셋은 하지 않는다.
- 공통 로그와 전달의 호스트 검사에서 CRLF 포함 60바이트, INT32 경계, 배열 256개 전량, 버퍼 가득 참/부분 쓰기 재시도, 메타데이터 오류, 명시적 취소와 24비트 부호 복원을 확인했다. 기대값 없는 관찰은 OBSERVED로만 기록한다.

### CM3 잔여 입력 연결과 독립 검토

- 기본값이 수동 관찰뿐이었던 CM3 4/6/30에 안전 RAM 입력을 연결했다. 4는 실제 기동 함수의 허용 대입을 사용하고 대기/하드웨어 초기화만 입력 경계로 바꾼 부분 시험이다. 6은 실제 맵 변경/재계산 요청과 파일 경계 입력, 30은 실제 내부기 상태 설정/변경 플래그 해제다.
- CM3-030을 맡은 Nash의 반영 파일과 독립 검사 결과를 확인하고 주 작업의 실제 runner/RTT 경로에 연결했다. 새 채팅 fork 여부와 무관하게 해당 파일/API를 다시 빌드하고 시험한다. 에이전트 답변만으로 완료 처리하지 않는다.
- CM3-006 동일 맵 재적재에서 정확히 5개 값이 다르고, CM3-030 같은 상태 플래그에서 1개 값이 다르다. 기댓값 수정이나 정상 로직 수정으로 숨기지 않았다. 같은 상태의 플래그는 기준에 값이 명시되지 않아 해석 검토 대상이다.
- 입력 전 공유/private 상태와 경계 callback을 보관하고 복원한다. 부족한 공간/겹치는 배열은 변경 전에 거부하며, 이전 RTT 결과 배출 전 재호출은 BUSY다. CM3 21개 벡터를 비기본 상태에서 2회씩 실행하고 정확한 불일치 위치와 복원을 검사했다.
- RTT 취소 중 부분 줄이 남으면 CRLF 배출을 마친 뒤 다음 시험을 시작하도록 보완했다. 취소 직후 재시작에서 줄이 60바이트를 넘던 사례의 공통/CM3/BOOT 회귀를 추가했다. 관찰 준비 기록의 case 0은 로그 범위에 맞게 90으로 수정했다.
- SDK 경로와 호스트 경로의 include 차이로 CM3 추가 헤더의 첫 링크가 실패했다. 소스 파일 기준 상대 경로로 고친 뒤 전체 회귀/여섯 링크를 다시 실행한다. 기존 Eclipse Debug 산출물은 덮어쓰지 않는다.
- Kepler의 읽기 전용 독립 검토에서 count 포인터와 결과 배열이 겹치면 레코드가 길이를 덮어써 범위 밖 쓰기로 이어지는 P2를 찾았다. 코어 기동/맵 시험과 같은 형태의 상태 시험 모두 쓰기 전 겹침을 거부하도록 수정했다. 실제/기대 배열의 모든 결과 원소에 count를 겹치게 한 입력, 한쪽 배열이 NULL인 입력, 비기본 상태 보존을 회귀로 추가했다. 나머지 지정 범위에서는 추가 blocker/P1이 보고되지 않았다.
