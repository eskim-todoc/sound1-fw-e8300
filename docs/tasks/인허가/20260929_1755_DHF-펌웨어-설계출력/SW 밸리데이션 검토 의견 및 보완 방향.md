# Sound1 SW 밸리데이션 검토 의견 및 보완 방향

기존 115개 유닛과 문서 형식을 유지하면서, 요구사항과 맞지 않는 시험 및 판정이 부족한 부분을 보완한다. 유닛 시험은 개별 처리의 정확성을 확인하고, 시스템 시험은 유닛 시험 통과 후 제품 전체 기능을 동작시켜 확인하는 방식으로 정리한다.

이 문서는 2026-10-02의 검토 의견과 은수님의 후속 방침을 다른 SW 밸리데이션 문서 작업 채팅에 전달하기 위한 자료다. 아래의 사용자 방침, 확인된 사실, 보완 의견을 구분해서 적용한다. 이 문서 작성만으로 Word/Excel 기준서나 제품 코드가 변경된 것은 아니다.

## 1. 은수님이 정한 적용 방침

### 1.1 유닛 시험과 시스템 시험의 역할

- 시스템 시험은 유닛 시험이 모두 통과된 후 전체적인 기능을 동작시켜 확인하는 시험이다. 시스템 시험에 개별 유닛의 내부 계산과 모든 분기 시험을 다시 나열하지 않는다.
- 유닛 시험에서는 필요한 정상값, 경계값, 오류 처리와 상태 변화를 확인한다. 통합시험에서는 유닛/모듈 사이의 전달과 실행 순서를 확인한다. 시스템 시험에서는 사용자 조작과 실제 장치 연결에 따른 최종 기능을 확인한다.
- 시스템 시험은 이러한 목적에 맞는 방법이면 된다. 동작 확인은 D, 수치 허용 범위가 있는 항목은 T 등으로 정하며, 모든 항목을 정량 측정이나 오실로스코프 시험으로 바꾸지 않는다.
- 요구사항과 시험 기준이 서로 다른 기능이나 조건을 설명하는 부분은 대조 후 수정한다. 단순히 기존 번호가 연결되어 있다는 이유만으로 같은 시험이라고 판단하지 않는다.

### 1.2 처리 주기는 1ms에 허용 오차를 명시

은수님은 실제 시험에서 +/-5%를 허용하는 취지에 맞춰, 기준을 `1ms (허용 오차 +/-5%)`처럼 명시하는 방향을 제시했다.

| 항목 | 반영 방향 |
|---|---|
| 기준값 | 1.00ms |
| 허용 오차 | +/-5% |
| 수치상 허용 범위 | 0.95~1.05ms |
| 함께 확인할 요구사항 | SW-FW-RID-12, SW-FW-RID-58 및 해당 상위 시스템 요구사항 |
| 함께 확인할 시험 | 시스템 시험 ID-12/58 및 같은 주기를 판정하는 관련 시험 |

상위 요구사항에 `1ms 이하`를 그대로 남긴 채 시험에서 1.05ms를 통과시키면 조건이 다르다. 요구사항을 관리하는 문서에서도 같은 의도로 표현을 맞추고, 설계 입력과 출력의 공통 시험 기준을 함께 맞춘다. 이 문서는 상위 원본을 임의로 수정하라는 지시가 아니라, 문서 작업에서 함께 정리해야 할 차이를 알려주는 자료다.

또한 1ms가 무엇의 주기인지 구분한다. 1ms마다 처리/전송하는 주기와 입력부터 출력까지 걸리는 시간은 같은 값이 아닐 수 있다. 시험에는 대상 동작과 측정 시작/끝을 적는다. 위 범위는 허용 오차를 수치로 풀어 쓴 것이며 실측 결과가 아니다.

### 1.3 QCC 자료는 별도로 추가

- QCC 내부 설계와 내부 검증 자료는 은수님이 별도로 추가할 예정이다. 지금 자료가 없다는 이유로 QCC 내부 내용을 추정하거나 시험 통과로 작성하지 않는다.
- 현재 E8300에서 확인 가능한 SPI/I2S/GPIO 연계는 유지한다. 이 연계 시험을 QCC 내부 인증이나 보안 검증의 대체 증거로 사용하지 않는다.
- QCC 단독 요구사항 47/48/49/52/71/72/76, E8300/QCC 연계 44/45/69/70, 양측 확인 15의 구분을 유지한다.
- QCC 자료 반영 위치는 기존 [QCC 자료 추가 위치 관리](../../../참고/인허가/사운드1/QCC%20자료%20추가%20위치%20관리.md)를 사용한다. 관련 문서를 수정하면서 위치나 ID가 바뀌면 같은 작업에서 목록도 갱신한다.

## 2. 현재 문서의 연결 상태

현행 소프트웨어 요구사항 사양서, 아키텍쳐 기술서, 상세 설계서와 유닛/통합/시스템 시험 기준서를 대조했다. Word의 삭제 추적 내용과 Excel 변경 비교 시트의 이전 행은 현재 기준으로 사용하지 않았다.

| 확인 항목 | 확인 결과 |
|---|---|
| 시스템 요구사항 SYS-RID-FW-1~50 | 소프트웨어 요구사항 사양서에서 모두 추적 가능 |
| 소프트웨어 요구사항 SW-FW-RID-1~81 | 아키텍쳐 기술서의 추적 표에 모두 존재 |
| 상세 설계서 등록 유닛과 유닛 시험 | 115개 유닛에 115개 시험 대응 |
| 시험 ID/유닛 ID | 중복 및 미정의 유닛 참조 없음 |
| 입력/시험 절차/예상 결과 | 빈 항목 없음 |

번호 연결은 잘 되어 있다. 다만 이는 시험 내용이 충분하거나 실제 시험이 모두 통과했다는 의미가 아니다. 특히 유닛 기준서는 모듈과 유닛을 통해 요구사항에 연결되므로, 보완 시 각 요구사항의 어느 부분을 어떤 유닛 또는 후속 시험에서 판정하는지 확인한다. 모든 요구사항에 유닛 시험을 1:1로 새로 만들 필요는 없다.

## 3. 유지할 검증 방식

코드 분석과 고정 입력의 실제 함수 실행, 처리 후 RTT 결과 비교를 중심으로 하는 방향은 적절하다. RTT는 결과를 확인하는 수단이며, RTT로 수치/배열/횟수를 기대값과 정량 비교하는 시험은 T로 분류할 수 있다.

1. 입력과 초기 상태를 정한다. 플래그는 용도와 0/1의 의미를 설명한다.
2. 실제 처리 함수를 실행한다. 파일이나 주변장치 응답을 대신 넣는 경우에는 무엇을 대신했는지 구분한다.
3. 반환값, 처리한 값, 변경된 상태를 독립적으로 산출한 기대값과 비교한다.
4. 코드 분석, PC 실행, 실제 CFX/HEAR 실행, 장치 측정의 확인 범위를 구분한다.
5. 반복 실행이나 초기화 후 재실행이 중요한 유닛은 이전 시험의 상태가 다음 결과에 섞이지 않는지 확인한다.

시험 대상 함수의 결과를 기대값에 복사하거나, 같은 잘못된 계산을 양쪽에서 반복해 일치시키지 않는다. 수식, 프로토콜 또는 라이브러리 사양에서 기대값을 산출하고, 근사 연산은 허용 오차와 산출 근거를 적는다. 일부 중간값을 고정한 시험은 그 이후 처리의 검증이며 전체 계산 경로의 검증과 구분한다.

각 유닛에 모든 종류의 오류를 억지로 추가할 필요는 없다. 안전 영향, 계산 범위, 상태 전환과 실제 인터페이스를 기준으로 필요한 조건을 선택한다. 외부 입력의 유효성 검사를 상위 유닛이 담당하면 그 책임을 연결한다.

일반적인 방법 검토에는 [FDA General Principles of Software Validation](https://www.fda.gov/media/73141/download)의 정적/동적 검증, 정의된 입력과 기대 결과, 위험에 따른 시험 깊이를 참고했다. 이 검토가 IEC 62304 전체 조항의 적합성이나 인허가 완료를 판정한 것은 아니다.

### 4.1 전하량 제한과 계산 실패

CM3-028/029의 현재 정상 입력은 펄스폭 25us, T/C 전류 100/300uA다. 이는 정상 전류 변환을 확인하지만 전하량 제한 초과를 판정하는 입력은 아니다. 예상 결과에 적힌 DAC 지원 상한 초과도 전하량 제한 시험을 대신하지 못한다.

전하량은 전류와 펄스폭의 곱으로 계산한다. 제한값과 가능한 입력 범위를 설계에서 확인한 뒤, 제한에 못 미치는 입력, 제한과 같은 입력, 제한을 넘는 입력을 구성한다. 실패 후 기존 값을 유지할지, 안전한 값으로 바꿀지 등은 설계에서 정한 처리와 연결한다. 단순히 실패를 반환했는지만 확인하지 않는다.

### 4.2 감사기록, 저장소와 보안

현재 CM3-042의 저장 후 재읽기는 자료 보존과 A/B 경로 구분을 확인한다. CM3-046의 명령 허용 상태는 명령 처리 여부를 확인한다. 다음 사항은 별도 판정이 필요하다.

- 감사기록 생성 여부, 생성 실패 정보, 시간 정보: SW-FW-RID-50/73/74.
- 설정파일의 무결성 확인과 손상 시 공장초기화: SW-FW-RID-51/80.
- 오류 메시지의 보안 정보 노출 방지: SW-FW-RID-75.
- 내부기 제조번호/사용자 이니셜의 암호화 저장: SW-FW-RID-77.
- 감사기록의 인가자 접근과 외부 전송 보호: SW-FW-RID-79.

부트 이미지의 AES/CRC 검증이 개인정보 저장이나 감사기록 보호의 검증까지 대신하지는 않는다. 유닛에서는 담당 처리의 정확성을 확인하고, 시스템 시험에서는 전체 기능을 통한 생성/접근/복구 등의 동작을 확인한다. QCC에 해당하는 부분은 별도 자료로 보완한다.

### 4.3 수치 정확도와 관찰 시점

HEAR-002의 현재 시험은 0 입력과 FFT bin 32/64의 순음을 사용한다. 올바른 bin에 양수 최대값이 있다는 조건만으로는 크기가 잘못 계산되어도 통과할 수 있다. 창과 스케일을 포함한 대표 출력의 기대값, 허용 오차를 추가한다. 처음부터 모든 bin을 비트 단위로 일치시키는 시험을 강제하지는 않는다.

HEAR-001은 절대값 연산 후 첫 칸이 0이지만, 최대값 연산까지 완료하면 첫 칸이 100으로 바뀐다. 완료 후 배열만 출력하여 두 시점의 결과를 모두 관찰했다고 쓰지 않는다. 중간 관찰을 추가하거나 중간 처리는 분석, 최종 결과는 실행 비교로 나눈다.

CFX의 중간 계산값 고정은 경계 분기를 분리해서 확인하는 좋은 방법이다. 다만 실제 입력부터 전체 수치 계산을 확인하는 대표 벡터도 필요하다. PC 시험에서 DSP 라이브러리 경계를 대신한 경우에는 실제 SDK 연산과 CFX 고정소수점 처리까지 검증했다고 쓰지 않는다.

## 5. 요구사항과 시스템 시험에서 함께 정리할 차이

| 대상 | 현재 차이 | 반영 방향 |
|---|---|---|

## 6. 문서 보완과 분리해서 판단할 코드 사항

다음은 코드 검토에서 발견한 사항이다. 문서가 부족한 부분과 제품 코드가 설계와 다른 부분을 구분하고, 현재 동작에 맞춰 기대값을 낮춰 통과시키지 않는다.

- [processorDirective.h](../../../../src/2__cm3/processorDirective.h)의 정의는 `Df_MaxDeliveryChargeLimitationKKK`이고, [stimulationParaCal.c](../../../../src/2__cm3/Cortex-M3-src/signalProcessing/stimulationParaCal.c)의 `setting_stimulationRange()` 조건은 `Df_MaxDeliveryChargeLimitation`이다. 확인한 정상 CM3 빌드에서는 이 조건 분기가 활성화되지 않는다. 다른 자극 경로의 보호까지 없다고 단정하지 않으며, 설계 의도와 적용 범위를 확인한 후 별도로 판단한다.
- `calculationStimulParaN_cfxShare()`에는 전류 계산 성공 여부와 무관하게 공유 배열을 복사하는 경로가 있다. 실패 시 공유/완료 처리의 계약과 실제 호출 경로를 함께 확인한다.
- CFX-015의 복사 완료 플래그, CFX-040의 전송 길이, CM3-050의 DFU 상태는 현행 기대 결과와 구현의 관계를 정리해야 한다. 구현 오류인지 시험의 입력/책임 구분 오류인지 먼저 판단한다.
- 이전 시험 코드 검토에는 BOOT-007의 제조 정보 검사 실패 반환 처리, BOOT-011의 선언 구획 누락 처리 등도 기록되어 있다. 이런 불일치를 기준 완화로 해소하지 않는다.

이 전달 문서는 제품 코드 수정, Git 커밋/병합 또는 장치 다운로드를 승인하는 문서가 아니다. 해당 조치가 필요하면 문서 보완과 구분해서 진행한다.

## 7. 다음 문서 작업의 권장 순서

1. 요구사항과 시험이 다른 기능/조건을 설명하는 항목부터 정리한다. 처리 주기는 사용자 방침인 1ms +/-5%로 표현을 맞추고, 자극 볼륨과 오디오 볼륨을 구분한다.
2. 전하량 제한과 계산 실패 후 상태를 상세 설계에 맞춰 구체화한다. 설계에 처리 방침이 없는 경우에는 시험 기준만 임의로 만들지 않는다.
3. 유닛 기준서의 수치/패킷/상태 시험을 보강하고 필요한 시험 벡터와 연결한다. 현재 115개 구성과 번호는 가능한 한 유지한다.
4. 유닛/통합/시스템 시험의 담당 범위를 확인한다. 시스템 시험은 유닛 시험 통과를 선행 조건으로 두고 전체 기능을 확인하도록 정리한다.
5. 설계 입력과 출력에 공통인 시험은 입력부터 수정하고 출력도 맞춘다. 기존 Excel의 변경 비교 방식과 Word의 실제 변경 추적을 유지한다.
6. 보고서에는 실제로 확인한 범위만 결과로 작성한다. 예상 RTT 출력은 실제 출력과 구분하고, 자료 대기 중인 QCC 항목은 보류 상태로 남긴다.

기존 문서의 필드, 순서, 문체를 가능한 한 유지하며 불필요한 설명이나 신규 항목을 늘리지 않는다. `[작성자 전용]` 문서는 수정하지 않고, 필수성능시험 기준서는 앞선 제외 지시를 유지한다. 사용자 편집 내용도 보존한다.
