# Sound1 통합 시험 범위 검토

2026-10-08에 현재 통합시험 보고서의 17개 시험/106조건을 소프트웨어 아키텍쳐 기술서, 소프트웨어 상세 설계서, 소프트웨어 통합 계획서 및 관련 코드와 대조했다. Word는 변경추적의 삽입 내용을 포함하고 삭제 내용을 제외한 현재 본문을 읽었다.

## 판단

**주요 연결 경로는 반영됐지만, 모든 중요한 모듈/유닛의 연결을 빠짐없이 확인했다고 단정하기에는 보완이 필요하다.**

통합 시험은 유닛마다 시험 하나를 만들거나 모든 유닛 쌍을 시험하는 것이 아니다. 실제로 데이터를 주고받는 경로, 처리 순서, 완료 통보, 모드 전환과 오류 전달을 확인하는 것이다. 유닛 자체의 계산/동작 시험이나 완제품의 성능 시험과도 구분한다.

은수님이 확인한 기존 17개 시험의 통과 판정은 변경하지 않았다. 아래 보완점은 시험 범위의 충분성에 대한 검토이며 새 실패 판정이나 보드 시험 실행 결과가 아니다. 다른 단계의 기준/보고서에 같은 확인이 있다면 해당 시험의 조건과 결과를 명확하게 연결하여 중복 시험을 줄일 수 있다.

## 보완이 필요한 연결

| 연결 | 현재 문서의 한계 | 보완 방향 |
|---|---|---|
| 같은 오디오 입력 → AGC → FFT/대역 → 매핑 → 최종 PCM | 005는 혼합 입력, 별도 FFT 입력, 매핑 이후 고정 크기를 나누어 확인하고 015도 매핑 이후 값을 고정한다. 처리 순서 확인은 있지만 같은 입력에 대한 전 구간 수치 연결이 충분히 드러나지 않는다. | 한 고정 입력에서 주요 단계 값과 최종 PCM을 연결하여 자료의 단위/배율/버퍼 전달이 일관된지 확인한다. 개별 연산의 모든 유닛 시험을 다시 반복할 필요는 없다. |
| CM3 채널별 T/C → 공유 자료 → CFX 채널별 적용 | 009 조건3은 32개 채널 모두 T=0/C=127이어서 채널 순서가 바뀌어도 같은 값으로 보인다. | 채널마다 구분 가능한 서로 다른 T/C를 사용하여 전극/대역 인덱스가 유지되는지 확인한다. |
| 맵/사용자 설정 명령 → 비휘발성 저장 → 재읽기/복원 | 006의 RAM 반영과 017의 OTA 파일 저장만으로 맵/설정 저장 경로를 확인할 수 없다. 상세 설계의 CM3-042/043 연결에 직접 대응하는 조건이 없다. | 설정 기록 후 같은 값의 재읽기/재기동 복원, 저장 실패 응답, 선택 맵/내부기/전체 삭제 범위의 보존을 확인한다. |
| 터치 센서 오류 → 복구 → 전원 이벤트 | 002/007은 초기화와 정상 터치 복귀다. 읽기 실패/고착 시 재보정과 길게 누름 판정이 어떻게 연결되는지는 없다. | CM3-009/010의 오류 입력, 복구 조치와 전원 이벤트 전달을 같은 조건에서 연결한다. |
| 배터리/충전/뚜껑/LED 요청 → 실제 시스템 동작 | 012는 수신값 저장/조회/응답을 확인한다. 후속 LED 우선순위, 출력 차단/절전 및 알림 실행까지의 기준은 충분하지 않다. 자극 알림의 공유 상태/크기가 CFX 매핑 결과를 바꾸고 PCM으로 나가는 연결도 명시적 기준이 없다. | CM3-013/014/024/044를 포함하여 상태 입력 후 표시/전원/알림의 적용 결과를 확인한다. 자극 알림은 알림 전/중/후의 최종 PCM을 연결한다. 완제품 시스템 시험에서 이미 확인했다면 그 조건을 참조 연결한다. |
| PMIC/FPGA 오류 → 상위 상태/모드 | 008의 정상/무응답/오류 조건을 묶은 상태 갱신 기록과 설정 전달만으로 오류 종류별 결과를 구분하기 어렵다. | 전력 단계 설정/조회와 실패 시 상위 오류 응답 및 Live 진입 여부를 구분한다. |
| OTA 완성 이미지 수신/저장 → 재기동 → 같은 이미지 적재/실행 | 017의 2바이트 파일 기록과 016의 별도 정상 이미지 적재는 각각 확인한다. 같은 완성 이미지가 두 단계를 통과하는 연결은 명시돼 있지 않다. | 유효 완성 이미지 한 개로 수신/저장/선택/재기동/검사/실행을 연결하고, 수신 순서 오류 및 불완전 갱신의 기동 금지도 확인한다. |
| 서비스 모드 점검 → 결과 표시 → 재기동 | 016 조건7은 CAL 입력에 따른 분기까지만 확인한다. | BOOT-017/018의 점검 성공/실패가 표시 및 다음 기동으로 전달되는지 확인한다. |
| 맵/볼륨 변경, 연결 해제 및 절전 요청의 겹침 | 006의 동시 설정 변경과 011의 변경 중 종료가 있다. 통합 계획에 있는 연결 해제까지 겹치는 조건은 명확하지 않다. | 새 설정의 적용 완료 전 해제/절전 시 이전 완료 상태로 Live가 진행되지 않는지 확인한다. |

## 현재 코드와 시험 조건을 다시 연결할 부분

아래는 문서 표기 오류와 별개다. 시험 당시 버전, 시험용 입력 경계와 현재 제품 코드가 어떤 조건으로 대응되는지를 확인해야 한다. 이번 작업에서는 코드나 결과/판정을 바꾸지 않았다.

| 보고서 위치 | 현재 소스에서 확인한 내용 | 확인할 사항 |
|---|---|---|
| 009 조건5, M71/N71 | 매핑 Live 호출자는 계산 결과가 성공인지 분기하기 전에 CFX 계산 완료 플래그를 게시한다. | 결과의 ‘계산 실패 시 완료 게시=0’이 어느 시험 경로/버전에서 확인됐는지 연결한다. |
| 009 조건6, M72/N72 | 자극 계산 함수는 `Df_MaxDeliveryChargeLimitation`이 있을 때 전하량을 검사한다. 현재 헤더의 정의는 `Df_MaxDeliveryChargeLimitationKKK`다. | 전하량 75300pC 거부 결과의 시험 빌드에서 활성 조건을 확인한다. |
| 014 조건4, M101/N101 | 매핑 연결 상태는 일반 연결의 자극 파라미터 설정 완료 플래그가 아니라 내부기 전원 준비 상태를 기준으로 통보한다. | ‘준비 완료’가 어떤 상태인지 구분하고 일반 연결과 같은 완료 조건으로 오해하지 않도록 한다. |
| 003 조건5, M36/N36 및 013 조건6, M97/N97 | CFX 정상 루프의 `I2S_handle()` 호출이 주석 처리돼 있다. | 함수 단독의 완만한 전환과 실제 정상 입력 경로의 시작/중단 결과가 어떤 시험 경계에서 대응되는지 구분한다. |

유닛 ID가 참조된 것만으로 통합 확인을 인정하지 않았다. F열에는 115개 중 102개 유닛 ID가 있으며 없는 13개는 BOOT-002/004/017/018, CFX-020, CM3-010/014/021/024/035/042/043/044다. 이는 **번호 인용 현황이지 통합 시험 충족률이 아니다.** 단순 대기/표시 보조 유닛처럼 상위 경로에서 확인할 수 있는 것도 있고, 저장/복구처럼 실제 연결 보완이 필요한 것도 있다.

QCC는 현재 E8300의 SPI/I2S/제어 핀 경계를 확인하는 범위다. QCC 내부 모듈/유닛 통합까지 완료됐다는 뜻은 아니다. 향후 추가 위치는 [QCC 자료 추가 위치 관리](E:/workspace/projects/sound1-fw-e8300-backup/docs/참고/인허가/사운드1/QCC%20자료%20추가%20위치%20관리.md)의 통합 기준서/보고서 항목으로 관리한다.
