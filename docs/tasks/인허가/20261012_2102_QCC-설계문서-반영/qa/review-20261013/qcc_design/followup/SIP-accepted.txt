[33 P] 서론
[34 P] 개요
[35 P] 본 문서는 TD24A-A-EXT 제품의 소프트웨어 개발 절차로서 소프트웨어 통합 계획을 수립한다.
[36 P] 
[37 P] 목적
[38 P] 인공달팽이관 외부장치 소프트웨어 모듈들의 통합 과정을 계획하여, 소프트웨어 개발 절차에 따라 각 모듈이 안전하고 일관되게 동작하도록 하는 것을 목적으로 한다.
[39 P] 
[40 P] 대상
[41 P] TD24A-A-EXT 제품의 펌웨어 개발 프로젝트에 참여하는 모든 구성원은 이 문서를 참고하도록 한다.

[53 P] 소프트웨어 모듈 구현 및 통합 계획 
[54 P] 인공달팽이관 외부장치 소프트웨어의 기능 모듈과 코어별 역할은 <그림 1.>과 같이 구성한다.
[55 P] 
[56 P] 
[57 P] 
[58 P] 
[59 P] 
[60 P] <그림 1. 인공와우 소프트웨어 아키텍쳐 블록도>
[61 P] [QCC 자료 입력] QCC 4모듈/14유닛의 실제 소스/빌드/라이브러리 설정과 유닛/통합 실행 및 측정 결과가 필요하다. DMIC2 입력 연결은 확인되었으며 이 안내는 구현/시험 근거의 확인 상태를 나타낸다.
[62 P] 
[63 P] 이를 참고하여 소프트웨어 모듈 구현 및 통합 순서를 다음과 같이 계획한다.
[64 P] 
[65 P] 
[66 P] 소프트웨어 구현 
[67 P] 소프트웨어 모듈의 구현 과정에서 아직 준비되지 않은 상대 기능은 테스트 코드로 대신할 수 있다.
[68 P] 소프트웨어 구현 순서는 다음과 같다.
[69 P] CFX 코어 소프트웨어
[70 P] System Control Module
[71 P] 부트로더의 기초 하드웨어 설정과 이미지 적재를 바탕으로 CFX의 인터럽트, 공유 상태 및 반복 실행 제어를 먼저 구현한다. 이후 HEAR, 마이크, PCM과 I2S 경로를 준비한다.
[72 P] 다른 모듈의 상태에 따라 시스템을 제어하는 항목은 Signal Processing Module, Internal Stimulation Device Execution Module의 구현 및 검증이 완료된 이후에 최종적으로 구현한다.
[73 P] 그 외의 모듈
[74 P] System Control Module의 반복실행 기능이 동작되는 상태에서 다른 모듈을 구현한다.
[75 P] Signal Processing Module과 Internal Stimulation Device Execution Module은 독립적으로 구현할 수 있다. 다만 신호처리 결과를 자극 패킷으로 전달하는 단계에서는 맵, T/C 값과 프레임 조건을 함께 준비한다.
[76 P] 
[77 P] Hear 코어 소프트웨어
[78 P] System Control Module
[79 P] HEAR의 실행 준비와 함수체인 호출, 완료 이벤트 처리는 CFX의 System Control Module에서 구현한다.
[80 P] Signal Processing Module
[81 P] CFX의 반복 실행과 입력 버퍼가 준비된 상태에서 절대값 최대값 연산과 창 적용 FFT/크기 연산을 구현한다. CFX의 AGC, 분석 입력 갱신과 대역 대표값 처리에 연결한다.
[82 P] 
[83 P] CM3 코어 소프트웨어
[84 P] System Control Module
[85 P] CM3 주변장치와 공유 메모리, 터치 센서 및 QCC 제어 핀을 먼저 준비한다. CFX의 기동 상태를 확인하고 공유 자료를 설정한 뒤 CFX의 반복 실행을 허가하도록 구현한다.
[86 P] 시스템을 제어하는 항목은 Signal Processing Module, Internal Stimulation Device Execution Module, Bluetooth Communication Module의 구현 및 검증이 완료된 이후에 최종적으로 구현한다.
[87 P] 그 외의 모듈
[88 P] Signal Processing Module, Internal Stimulation Device Execution Module과 Bluetooth Communication Module은 독립적으로 구현할 수 있다. 맵 읽기와 변경 요청, 자극 파라미터 계산, 내부기 설정 및 명령 응답의 연결은 통합 단계에서 확인한다.
[89 P] 
[90 P] QCC 소프트웨어
[91 P] System Control Module
[92 P] E8300 측에서는 CM3의 SPI 명령/응답과 제어 핀, CFX의 I2S 입력 경로를 구현한다. QCC 내부 모듈의 구현과 구분한다.
[93 P] 
[94 P] PIO/Power/NVM을 먼저 준비하고 보안 키 읽기/파생/인증 계산을 연결한다. 초기화와 상태 처리에는 E8300의 준비/종료 신호 및 내부기 연결 정보를 반영한다. 하위 기능이 준비된 후 Bluetooth 검색/연결과 SPI 중계를 연결한다.
[95 P] Bluetooth Communication Module
[96 P] 
[97 P] 
[98 P] 
[99 P] E8300에서는 리모콘과 매핑 명령의 수신, 처리 및 응답 경로를 구현한다.
[100 P] 
[101 P] Classic, BLE, AUTH service와 BLE Data를 단계적으로 연결한다. AUTH service는 보안 처리/툴박스/보안 NVM을 사용하고 인증된 BLE 데이터는 시스템 상태 유닛을 통해 SPI로 중계한다. Classic 수신 오디오는 I2S로 E8300에 전달하며 통화 상향은 DMIC2→QCC→통화 상대 경로로 연결한다.
[102 P] 
[103 P] 구현은 HW 접근과 시스템/무선/보안 기능의 의존 순서를 따른다. QCC의 4모듈/14유닛과 E8300의 실행 경로는 아래의 준비 조건 및 통합 단계에 연결한다.

[107 P] [QCC 자료 입력] 실제 QCC 소스/빌드·ADK/BSP 버전과 단위 실행 로그를 제출해야 한다. 아래 단계는 통합 계획이며 구현/단위시험이 완료된 것으로 가정하지 않는다.
[108 P] 
[109 P] 
[110 P] 부트로더 소프트웨어
[111 P] 기초 하드웨어 설정, 저장장치 준비, 이미지 헤더/구획 검사와 메모리 적재를 먼저 구현한다. 이후 응용 코어 기동, 서비스 모드, 기본/대체 슬롯 선택과 복구 처리를 연결한다. 갱신 데이터 수신/저장은 CM3 응용 프로그램에서 구현한다.
[112 P] 소프트웨어 통합 
[113 P] 각 코어의 모듈을 먼저 통합한 뒤 공유 메모리와 완료 이벤트를 사용하는 코어 간 경로를 연결한다. 실행 순서는 부트로더의 이미지 적재, 응용 코어 준비, 맵/내부기 설정, 실시간 자극의 순서로 확인한다.
[114 P] 상대 코어의 기능이 준비되지 않은 단계에서는 테스트 코드로 입력과 응답을 대신할 수 있다. 최종 통합에서는 실제 코어와 장치를 연결하여 같은 데이터와 완료 상태가 전달되는지 확인한다.
[115 P] 각 통합 단계의 입력, 전달 결과와 상태 전환을 확인한 뒤 다음 단계로 진행한다. 결과가 설계와 다르면 해당 유닛과 연결 부분을 수정하고 같은 조건으로 다시 확인한다.
[116 P] CFX 코어 소프트웨어 통합
[117 P] 병렬 통합 단계
[118 P] CFX의 System Control Module을 기준으로 신호처리와 내부기 실행 모듈을 각각 통합한다. 상대 모듈의 입력은 준비된 맵 자료나 테스트 코드로 제공할 수 있다.
[119 P] Signal Processing Module + System Control Module
[120 P] 맵의 방향/마이크 수와 입력 상태에 따라 단일 입력, 두 마이크 빔포밍 또는 I2S 혼합 경로가 선택되는지 확인한다. 오디오/자극 볼륨을 변경하여 AGC 이득, C 상한과 매핑 계수의 반영을 확인한다.
[121 P] Internal Stimulation Device Execution Module + System Control Module
[122 P] CM3의 내부기 연결 상태, PCM 실행 모드와 지정 명령이 CFX의 출력 경로에 반영되는지 확인한다. 명령 요청과 전송 완료를 구분하고 대기/초기화, 연결 검사 및 실시간 자극 모드를 각각 확인한다.
[123 P] 
[124 P] 누적 통합 단계
[125 P] 신호처리와 내부기 실행 경로를 연결하고 설정 변경이 두 모듈에 반영된 뒤 자극 데이터를 출력하도록 통합한다.
[126 P] Signal Processing Module + internal Stimulation Device Execution Module + System Control Module
[127 P] 입력 혼합, HEAR 최대값 연산, AGC, FFT/크기 연산, 대역 대표값/매핑과 PCM 출력을 순서대로 연결한다. 선택한 맵의 디지털 T/C, 전극과 프레임 조건이 자극 패킷에 반영되는지 확인한다.
[128 P] CIS는 맵의 펄스폭에서 계산한 프레임 수와 전송량을 사용한다. NofM은 대역 수 16 이상인 맵에서 16개 대역 선택, 교차 배치와 시작점 조정 후 자극당 3프레임, 1ms당 8개씩 두 구간으로 출력하는지 확인한다.
[129 P] 
[130 P] Hear 코어 소프트웨어 통합
[131 P] HEAR 통합은 CFX 신호처리 통합에 포함한다. 혼합된 16표본의 절대값 최대값 연산이 끝나면 Event 0으로 CFX의 AGC와 FFT 입력 갱신을 진행하고, 512표본 FFT/크기 연산이 끝나면 Event 1으로 후속 대역 처리와 PCM 출력을 진행하는지 확인한다.
[132 P] Event 0 전에는 최대값 결과를, Event 1 전에는 FFT/크기 결과를 사용하지 않는지 확인한다. CM3가 읽는 maxAudioInput은 혼합 후 AGC 전의 최근 16표본 절대값 최대이며, RMS나 장시간 누적 최대값과 구분한다.
[133 P] 
[134 P] CM3코어 소프트웨어 통합
[135 P] 병렬 통합 단계
[136 P] CM3의 System Control Module을 기준으로 신호처리, 내부기 실행과 블루투스 통신 모듈을 각각 통합한다. 이 단계에서는 상대 모듈의 상태와 응답을 준비하여 개별 연결을 확인한다.
[137 P] Signal Processing Module + System Control Module
[138 P] 맵의 펄스폭, 채널 수와 T/C 전류로 DAC 범위, 디지털 T/C 및 전송량이 계산되는지 확인한다. 선택한 내부기 파라미터와 계산 결과가 공유 메모리의 동일한 맵 자료에 대응하는지 확인한다.
[139 P] 
[140 P] Internal Stimulation Device Execution Module + System Control Module
[141 P] 내부기 연결 요청에 따라 FPGA/송신 전원 설정과 연결 확인이 진행되는지 확인한다. CM3의 명령 요청, CFX의 PCM 전송과 완료 통보, FPGA의 응답 처리를 연결하고 해제/재연결 시 상태 갱신도 확인한다.
[142 P] 
[143 P] Bluetooth Communication Module + System Control Module
[144 P] 리모콘의 연결 확인과 일반 명령 허용 상태를 구분하여 처리/응답을 확인한다. 매핑 연결/종료, 게인 변경, 배터리/충전/크래들 뚜껑 및 LED 요청이 해당 시스템 상태에 반영되는지 확인한다.
[145 P] 
[146 P] 누적 통합 단계
[147 P] 먼저 맵 처리와 내부기 실행을 시스템 제어에 연결하고, 그 다음 블루투스 명령과 상태 전달을 추가한다.
[148 P] Signal Processing Module + internal Stimulation Device Execution Module + System Control Module
[149 P] CM3의 맵 변경 요청, CFX의 맵 반영 완료, CM3의 자극 파라미터 계산과 CFX의 결과 적용을 순서대로 확인한다. 내부기 설정과 준비 상태를 확인한 뒤 Live PCM 모드로 전환되는지 확인한다.
[150 P] Signal Processing Module + internal Stimulation Device Execution Module + Bluetooth Communication Module + System Control Module
[151 P] 입력 상태 수집 후 시스템 제어, 맵 갱신, 내부기 실행과 블루투스 통신 처리가 순서대로 연결되는지 확인한다. 맵/볼륨 변경, 연결 해제와 절전 요청이 겹치는 조건도 확인하고, 절전 시 CFX 정지 확인 후 CM3 대기로 전환되며 터치 입력으로 재시작되는지 확인한다.
[152 P] 
[153 P] QCC와 E8300 소프트웨어 통합
[154 P]

[165 P] SPI 연계: E8300의 수신 정의는 0x34(data[0] 배터리 %, data[1] 충전기 미연결 0 / 연결 1, data[2] 뚜껑 열림 1 / 닫힘 2), 0x35(data[0] LED 상태, OTA_EZAIRO=4일 때 갱신 연결 1), 0x36(data[0] 오디오 미연결 0 / 연결 1, data[1] 종류 미상 0 / 크래들 1 / 기타 2)이다. 응답은 각각 명령값과 성공값 1이다. 0x36은 연결 1·종류 1일 때만 크래들 오디오 상태를 설정한다.
[166 P] 메시지 경계: QCC BLE Data 메시지는 type 1바이트와 data 0~19바이트로 총 1~20바이트이다. E8300 SPI 전송 프레임은 별도 길이 1바이트를 포함한 21바이트이다. 무선 메시지와 물리 SPI 프레임을 같은 계층의 길이로 취급하지 않는다.
[167 P] 제어 핀: E8300 QCC_CTRL(DIO24)은 High=정상 동작 요청, Low=종료 요청이며 초기값은 Low이다. ISD_CHECK(DIO13)는 High=내부기 연결, Low=미연결이며 초기값은 Low이다. CFX I2S_FLAG(DIO29)는 Low=입력 유효이다. QCC의 shutdown_ind 또는 I2S enable이라는 논리 이름만으로 물리 핀 극성을 변경하지 않는다.
[168 P] 
[169 P] 오디오 입력은 DMIC1/DMIC2→E8300의 마이크 경로와 QCC→E8300의 I2S 경로로 구분한다. DMIC2는 QCC에도 연결되며 전화 통화 시 QCC가 수음한 음성을 통화 상대에게 송신한다. QCC의 Classic 수신 오디오는 I2S 24bit/16kHz로 CFX에 전달한다. E8300 PCM1은 slave, 24bit, MSB 우선/정렬, 상승 에지, 2word 설정이며 16표본 블록을 처리한다. 16kHz 표본율과 0~8kHz 오디오 대역은 구분한다. CFX는 일반 I2S 게인 1과 마이크 Gain A, 크래들 I2S Gain B와 마이크 Gain A, 매핑 연결 중 두 게인 1을 적용하며 혼합 후 2로 나누지 않는다.

[176 P] 시험 기록: 유닛 시험은 15그룹(SW-FW-UnitTest-QCC-ID-1~15)이 14설계유닛에 대응한다. Bluetooth activation 그룹은 SU-ID-QCC-004가 주담당이고008/009가 연계된다. 통합과 시스템 시험은 상위 요구 기능을 함께 적고 준비 조건·입력·구체 예상 메시지/값·절차·통과 기준을 본문 행에 둔다. 보고서는 기준서의 공통 열·행/병합 구조를 그대로 유지하면서 같은 입력 조건 옆에 실제 시험/측정 내용과 판정을 추가한다.
[177 P] 신규 통합시험의 ID는 SW-FW-IntegrationTest-ID-018 전원 상태/SPI, 019 연결·종료 신호, 020 AUTH 패턴 중계, 021 실제 CRA와 제어 게이트/시간 제한, 022 Classic/I2S 오디오, 023 BLE 편이·양이 데이터, 024 보안 NVM/키 생성/CRA 계산이다. AUTH 패턴 중계 시험을 실제 CRA 통과로 확대하지 않으며, 각 단계를 해당 기준서·보고서의 같은 입력 조건과 연결한다.
