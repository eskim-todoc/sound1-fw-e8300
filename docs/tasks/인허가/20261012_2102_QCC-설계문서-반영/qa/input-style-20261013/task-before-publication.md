## 목표와 범위

QCC 담당자가 제공한 설계 입력/출력 5개 문서를 실제로 읽고 외부기 펌웨어 요구사항, 설계, 시험 문서에 반영한다. 기존 `[E8300]` 파일과 `서석일_작성/QCC_` 원문은 보존하고 같은 단계의 `SW/외부기`에 `[E8300-QCC]` 사본을 만든다. 제공 자료만으로 확정되지 않는 설계와 검증은 구체적인 미비 사항으로 남긴다.

기본 순서는 SRS → SAD → SSTC/SSTR → SDDD → SUVC/SUVR → SIP → SITC/SITR다. 뒤 문서에서 발견한 상충과 누락은 관련 요구사항부터 되돌려 수정한다. 설계 입력 SR/SGR에도 실제 변경 영향이 있으면 같은 복사 방식으로 반영한다. 펌웨어와 시험 코드, 참고 원문, 기존 승인/서명, 온라인 매트릭스 및 Git 이력은 이번 문서 편집 권한으로 변경하지 않는다.

## 수용 기준

1. QCC 원문 5개의 본문과 표를 직접 확인하고 기능/조건/인터페이스를 기존 요구사항과 연결한다. 원문 식별자 중복과 오기는 위치와 기능 내용으로 구분한다.
2. E8300와 QCC 원본의 시작/종료 SHA256이 같고 새 문서만 지정된 경로와 접두어로 저장된다.
3. 요구사항, 아키텍처, 상세설계, 통합계획, 세 단계 시험이 같은 기능/담당/입력/출력/조건을 설명한다. 충돌의 처리 근거와 남은 미비를 연결한다.
4. 기준서와 보고서는 같은 시험 행과 공통 열, 순서, 병합 구조를 사용한다. 같은 입력의 구체 예상값과 결과를 같은 행에서 비교하고 보고서만의 조건 행은 만들지 않는다.
5. 제공된 설계 자료, 코드 분석, 시험자 확인 기록, 실제 수집 결과를 구분한다. 신규 QCC 시험의 미실행과 기존 알려진 불일치를 판정에 유지한다. 원본의 과거 승인 사실을 신규 승인으로 복사하지 않는다.
6. Word는 기존 서식과 실제 변경 추적을 보존하고 변경 수락/거부 구조를 확인한다. Excel은 기존 그림/수식/병합/인쇄 설정을 보존하고 수정 구간의 표시를 확인한다.
7. 새 미비 안내의 담당 접두어, 기본+2pt, 색상과 밑줄을 확인하고 중앙 QCC 목록의 저장 문서 본문 위치와 확인일을 갱신한다.
8. 2026-10-13 후속 요청에 따라 SV 약칭을 사용하고, Excel7개의 원래 시트에는 적용 내용만 남긴다. 변경 전후의 `[-]`/`[+]` 문구는 같은 셀 구조의 `<원래 시트명>_비교` 시트에 보존한다. 본문과 비교의 최종 내용, 수식·추적 ID·미비 표시·예상값/실제 결과·메모·그림·인쇄 설정을 확인한다.

## 근거와 실행 계획

- 산출물 위치는 프로젝트 [AGENTS.md](../../../../AGENTS.md)의 G드라이브 단계별 경로를 따른다. 경로 접근과 실제 파일 존재를 확인했다.
- 기존 E8300 설계 입력/출력 작업 기록은 작성 당시 이력을 유지한다. 이번 요청은 QCC 자료를 포함한 새 문서군이므로 별도 작업으로 관리한다.
- 시스템 구조의 원본은 [Sound1 시스템 구조](../../../참고/시스템/Sound1%20시스템%20구조.md), 미비 위치의 원본은 [QCC 자료 추가 위치 관리](../../../참고/인허가/사운드1/QCC%20자료%20추가%20위치%20관리.md)다. 구조 사실과 세부 미비 목록을 여기에 중복 복제하지 않는다.
- 독립 담당은 QCC SRS와 요구사항 대응(SRS/SR/SGR 사본), QCC SAD/SDDD/SIP와 E8300 연계 계약(설계 3개 사본), QCC SUVC와 시험 문서 대응(기준/보고서 6개 사본)으로 나눈다. 원문은 모두 읽기 전용이며 최종 통합 판단과 공통 MD 편집은 주 작업이 맡는다.
- 원본 해시와 사본을 확인한 뒤 필요한 내용만 편집한다. 새 파일이 이미 있으면 확인 없이 덮어쓰지 않는다. 문서군의 내용 대조와 Word/Excel 저장/렌더 확인 뒤 최종본을 저장한다.

## 검증과 결과

2026-10-12 당시 문서 반영과 정합·저장·표시 검증을 완료했다. 아래 결과는 당시 기준의 이력이다. 2026-10-13 정정된 원칙의 검사 통과로 소급하지 않으며, 산출물 작업을 재개할 때 실제 현재본을 다시 확인한다. 문서 생성과 제품 시험 통과를 구분한다.

- 요구사항은 기존 1~81의 ID/상위 연결을 보존하고 82 마이크 Bluetooth 송신, 83 사용자 설명서 안전·사용·문제 해결을 추가했다. 83의 미제공 상위 연결은 임의 ID 대신 실제 미비로 표시한다.
- QCC SUVC의 15그룹/38조건을 본문 예상값과 시험 조건으로 옮겼다. 유닛 전체130개, 통합24개, 시스템83개 ID가 있으며 신규 결과는 모두 미실행/판정 대기다. 변경 기준에 맞지 않는 과거 관찰은 현재 판정에서 보존·구분한다.
- 세 시험 단계의 공통 셀 값과 병합 구조는 저장본 대조에서 일치했다. 구조 기준의 72개 소스와 QCC 원문 5개를 확인했고 실제 코드/실기 검증을 QCC 제공 설계로 대신하지 않았다.
- Word 필드/목차와 페이지를 갱신하기 전후의 본문 변경 추적 서명(종류·작성자·일시·텍스트)이 일치했다. 기존 미수락 삽입 안에 새 삭제가 들어가는 38개 사례는 원본 삽입 서명과 일치하며 신규 삽입의 잘못된 중첩이 아니다. 현재 삭제행/목차를 제외한 본문 위치를 중앙 목록에 수집했다.
- 번들 렌더러 실패 후 격리된 숨김 Office의 읽기 전용 수락 미리보기로 Word 전체 페이지와 Excel 수정 구간을 PDF/PNG로 확인했다. 실제 산출물의 변경 추적이나 시험 결과는 이 미리보기에서 바꾸지 않았다. 발견한 표시 문제의 수정과 재확인 결과는 아래 최종 기록에 남겼다.

## 결정 이력

- 2026-10-13: 은수님이 산출물 수정을 보류하고, 기존 원칙의 1/6/7번 정정과 29번 Word 작성 형식을 지침으로 정리하도록 요청했다. SW 밸리데이션 문서 작업에는 별도 언급 없이 원칙 준수를 검사하도록 온디맨드 연결을 지정했다. 지침의 상세 원본은 [SW 밸리데이션 문서 작성·검증 지침](../../../참고/인허가/사운드1/SW%20밸리데이션%20문서%20작성·검증%20지침.md)이며 이 작업은 지침/진입점만 수정한다.
- 2026-10-12: 은수님이 기존 E8300 원본을 보존하고 E8300-QCC 사본에 QCC 자료를 반영하도록 요청했다. 문서 순서와 앞뒤 반복 검토를 포함한다.

- 2026-10-12: 번들 Word 렌더러는 실행했으나 LibreOffice 부재로 실패했다. 같은 호출을 반복하지 않고 별도 숨김 Word COM의 읽기 전용 미리보기에서만 추적을 수락해 PDF를 내보낸 뒤 번들 PDFium으로 페이지를 확인한다. 산출물의 실제 변경 추적은 유지한다.

### 재개 후 검사에서 발견한 오류와 수정 반복

- 실제 온라인 설계 입출력 검증 매트릭스를 읽기 전용으로 확인하고 [보존한 읽기 자료](qa/review-20261013/qcc_requirements/matrix-readonly.xlsx)와 요구사항 사양서 첫 문구를 대조했다. 기존 상위 추적이 있는 50항목(사용 설명서 포함)은 같은 문구를 사용한다. 기존 상위 추적이 비어 있던 32개 파생 요구에 임의 상위 ID를 추가하지 않는다.
- Bluetooth 마이크 송신의 중복 RID82 및 100~8000Hz 하드웨어 상위 연결을 RID69 / SYS-RID-SP-FW-15로 바로잡았다. 시험ID82는 별도 통화 상향 송신 시험으로 유지하며 수신 시험의 과거 통과를 송신 완료로 사용하지 않는다. 현재 요구는 1..81 및83의82개다. 사용 설명서의 실제 상위 요구 ACDOC17/18/20을 연결했다.
- E8300과 다른 QCC 전용 설명 틀·목적/원문 추적 표를 실제 기능 설명과 같은 I/O·구현 표 구조로 정리했다. 시험에서 확인한 지원 요구 누락은 설계 추적을 다시 보완하여 양방향으로 대조했다.
- 준비 조건에 들어간 호출·입력 변경·측정 수행은 절차로 옮겼다. 정확한 배열/응답 바이트를 비교하는 시험의 D/T 구분도 기준서와 보고서에 함께 수정 중이다. 같은 공통 열·행·병합과 기존 실제 관찰 범위를 유지한다.
- Word 스타일의 basedOn ID가 대상 문서의 Normal Table과 충돌해 기본 본문 간격이 사라진 오류를 찾았다. 실제 DOTX의 지원 기반 스타일을 비충돌 ID로 내장해 본문/표 기반을 복구했다. 새 수정 추적의 잘못된 run 배치로 SR이 실제 Word에서 열리지 않던 문제도 복구 후보의 readonly Open으로 확인 후 수정했다. 오류본은 최종본으로 승인하지 않았다.
- SRS의 전체 인쇄 범위는 B3:I107이다. 초기 C6:I94 출력은 부분 검사 자료이며 전체 검사가 아니다. 90~92/95행의 적용 분류와 96~107행 규제 요구를 보존했다. 실제 전체 출력에서 첫 줄이 잘린 분할 셀은 내용·병합·폰트를 유지하며 높이를 보완했다.
- 필드 갱신 비교에서 SEQ 그림 번호의 계산 결과가 revision 밖으로 이동하는 Word 정규화를 확인했다. 계산 필드는 본문 수락·거부 및 revision 텍스트 검사에서 동일한 범위로 제외하며, 일반 텍스트·그림·작성자/일시·미비 안내 검사는 엄격히 유지한다. 오래된 삭제 paragraph-mark의 작은 폰트는 현재 빈 문단과 구분한다.

## 2026-10-13 후속 정리: 아키텍처의 QCC 모듈 이름

은수님 요청에 따라 SAD의 3.4.3~3.4.6 모듈 제목4곳과 같은 목차4곳에서 SI-ID-QCC-001~004 접두어만 제거했다. 시스템 관리/HW 인터페이스/블루투스/보안 모듈의 이름과 역할 설명은 보존했다. 모듈 ID는 상세설계에서 부여하고 아키텍처의 상세설계 추적표에서 관련 모듈/유닛을 연결한다는 원칙을 SV 지침3번에도 반영했다. 상세설계 추적 테이블을 포함한 모든 표의 원전 XML과 실제 Word 수락 후 표 내용을 대조했고 모듈/유닛 ID는 그대로다.

qcc_design은 현재 SAD와 E8300 동종 제목을 조사하고 8개 표기를 수정하는 스크립트 초안을 준비했다. 주 작업은 스크립트를 보완·실행하여 후보와 증거를 생성하고 실제 Word 검증, 표시 검토, G 저장과 공통 기록을 맡았다. 일반 역할 설명이나 실행 구조, 그림, 상세설계 및 시험 문서는 수정하지 않았다. 새 변경의 XML 거부 복원, 기존 이력/스타일/번호/그림/필드 보존을 확인했다. 과거 이력을 수락한 검증용 문단에서 새 변경의 실제 Word 수락/거부도 확인했으며 기존 이력이 포함된 납품 문서의 선택적 COM 거부가 검증됐다고 확대하지 않는다.

Windows 번들에는 LibreOffice가 없어 packaged render_docx.py는 실패했다. 설치된 LibreOffice로 대체하지 않고 실제 Microsoft Word의 읽기 전용 수락 보기에서 전후 전체 PDF를 출력해 모든 쪽을 렌더했다. 이전 검증본과 동일한 페이지는 픽셀 동일성을 대조하고 달라진 페이지는 원본 크기로 열어 글자/목차/제목/페이지 배치를 확인했다. 판정과 실제 페이지 번호는 아래 표시 검사에 기록했다. 전역 Word 사용자 설정은 변경하지 않았다.

검증한 후보와 같은 SHA256으로 G의 SAD 현재본만 저장했다. 다른 통합 문서11개와 보호 원본23개는 불변이다. 중앙 QCC 위치를 저장본에서 다시 수집하고 현재 산출물 목록을 갱신했다. 기존 제품 시험 대기/미비 상태와 사용설명서 초안 검사 범위는 그대로다.
