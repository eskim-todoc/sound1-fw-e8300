서론
개요
본 문서는 TD24A-A-ACC 제품의 스마트 케이스 펌웨어를 개발하기 위한 소프트웨어 아키텍처를 설계하고 기술한다.

목적
스마트 케이스 펌웨어의 요구사항을 구현하기 위한 소프트웨어의 아키텍처를 설계함으로써 소프트웨어 개발 절차에 따라 안전한하고 일관성 및 정확성을 보장하는 소프트웨어의 개발이 보장되는 것을 목적으로 한다.

대상
TD24B-A-EXT 펌웨어 개발 프로젝트에 참여하는 모든 구성원은 이 문서를 참고하도록 한다.

하드웨어 플랫폼

외부장치 소프트웨어가 동작할 하드웨어 플랫폼은 아래 <그림 1.>과 같으며, 이를 참고하여 소프트웨어 아키텍처를 설계한다.






















<그림 1. 외부장치 블록도>


소프트웨어 아키텍처 – 블루투스
2절의 하드웨어 플랫폼을 기반으로 동작하는 외부장치 시스템의 블루투스 소프트웨어의 아키텍처는 <그림 2.>와 같이 설계되었으며,






















































<그림 2. 외부장치 블루투스 소프트웨어 아키텍처 블록도>
블루투스 펌웨어는 크게 외부장치 Application과 MCU 제조사인 Qualcomm에서 제공하는 Built-in library와 system software가 있다. 제조사에서 제공하는 부분은 Application을 구현하는데 바탕이 되며, 별도의 수정 없이 제공되는 API만을 사용하므로, 여기서는 외부 Application만을 설명한다.

외부장치 Application의 각 모듈들이 담당하는 기능들은 다음과 같다.

시스템 관리 모듈 (System management module)
외부장치 시스템의 전체적인 동작을 제어하는 모듈이다. 다른 모듈의 상태 값을 확인하여 해당 모듈의 동작을 결정한다.
시스템 초기화와 설정 유닛
시스템과 application의 초기화를 수행하고, 각 유닛과 모듈들의 초기 상태와 설정 수행하고 확인하다. 특히, 사용되는 시스템과 built-in library의 각 부분을 설정과 초기화를 수행한다.
시스템 상태 유닛
시스템의 일반적인 상태와 사운드 처리기의 상태를 처리하고, 다른 모듈들에게 전달하거나 모듈들의 처리를 수행한다. 그리고, 사운드 처리기와 SPI 통신을 처리한다.
장치 상태 유닛
장치가 블루투스 단독형(Standalone, 편이)인지 무선 스테레오형(TWS(True Wireless Stereo), 양이) 인지를 확인하고 이에 따라 관련된 모듈들의 상태 및 데이터 처리를 관리한다.
블루투스 상태 유닛
시스템 상태에 따라 Bluetooth Classic과 BLE의 상태를 확인하고 관련된 모듈들의 상태 및 데이터 처리를 관리한다.
하드웨어 인터페이스 모듈 (Hardware interface module)
MCU와 연결된 여러 HW 모듈들을 제어하고, 외부장치 전원관 배터리, 충전을 관리하고 제어한다.
PIO 포트 유닛
MCU와 연결된 PORT IO들들 설정하고 제어한다.
Power 제어 유닛
외부장치의 배터리와 충전을 관리하고 관련된 정보를 사운드처리기와 블루투스를 통해 외부기기에 전달한다.
시스템 상태에 따라 저전압 모드에 진입하고 wake-up을 수행한다.
NVM 처리 유닛
칩의 NVM(Non-Volatile Memory, Flash memory)의 접근을 관리하고, 저장되는 데이터를 정의하고 읽고 쓰는 부분에 대한 인터페이스를 제공한다.
블루투스 모듈 (Bluetooth module)
외부장치의 블루투스 통신을 제어한다. 이 모듈은 크게 Audio 전송을 위한 Bluetooth Classic과 데이터 통신을 위한 BLE로 나누어진다.
Bluetooth Classic 유닛
Classic 연결을 위한 설정과 통신 관련 부분을 설정하고 제어한다.
Audio 연결과 통신을 설정하고 제어한다.
BLE 유닛
BLE Advertising의 설정하고 연결을 관리한다.
BLE 데이터를 송수신하기 위한 BLE 정보와 통신 관련 부분을 설정하고 제어한다.
AUTH service 처리 유닛
자체 보안 인증에 사용되는 AUTH service를 정의하고 관련된 characteristic의 접근과 데이터 처리를 관리한다.
BLE Data 처리 유닛
BLE data를 정의된 메시지 형태로 구성하고, 처리한다.
상대 BLE 장치로 데이터를 전송하고, 수신된 데이터를 처리하여 시스템에 전달한다.
보안 모듈 (Security module)
인증 처리 유닛
BLE 데이터 통신에 필요한 인증을 정의하고 절차를 처리 및 관리한다.
보안 툴박스 유닛
보안 모듈에서 사용하는 각종 암호화 알고리즘과 키 생성 방식에 대한 처리를 수행한다.
보안 NVM 처리 유닛
NVM에 저장된 보안 데이터를 읽을 때와 쓸 때 각각 필요한 보안 절차를 수행한다.






시스템 동작 흐름도
시스템의 동작흐름을 3. 절의 소프트웨어 아키텍처에서 기술한 모듈들이 조합하여 시스템의 동작흐름을 간략히 설명하면 <그림 3.>과 같다.

























<그림 3. 외부장치 블루투스 시스템 동작 흐름도>

<그림 3>을 요약하여 설명하면 다음과 같다:
System management module은 외부장치의 블루투스 시스템의 전체적인 동작을 관리한다. 전원이 들어오면 내부 시스템과 built-in library의 설정을 관리하고 시스템의 각 부분을 초기화 한다. 구동 중에는 배터리 상태와 사운드 처리기의 신호를 받아 필요하면 저전압 모드에 진입할 수 있도록 하고 블루투스의 활성화를 제어한다.
HW interface module은 충전이나 배터리 상태같은 Power 상태를 관리하며 필요하면 저전압 모드에 진입한다. 그리고, 주변 장치들의 상태와 사운드 처리기의 신호를 확인하고 상태를 전달한다. 또한, 비활성화 메모리에 대한 접근의 인터페이스를 제공한다.
Bluetooth module은 전반적인 블루투스 기능 (연결과 통신, 오디오 스트리밍 등)을 관리하여, 하나의 전체적인 블루투스 시스템을 구성한다. 또한, 일반 데이터와 오디오 데이터의 송수신을 처리한다.
Security module은 BLE 연결과 접근에 대한 설정 및 관리를 수행하고, 보안 데이터에 대한 읽기 쓰기를 관리한다.


소프트웨어 안전 등급
소프트웨어 일반 요구사항(TD-AE-SGR-01)에서 사운드원 인공 와우의 안전 심각도는 중(Class B or Moderate)로 분류되었다. 이 문서 3절에서 설계한 소프트웨어 아키텍처의 모든 소프트웨어 항목은 시스템의 안전 심각도를 동일하게 상속받는다. 따라서 사운드원의 인공 와우의 모든 소프트웨어 항목의 안전 심각도는 중(Class B or Moderate)로 분류한다.
