# Sound1 소프트웨어 상세 설계서 - 계획

**TL;DR**: 1.5세대 SDDD 는 «SI 항목 -> SU 유닛» 카탈로그다. Sound1 은 **부트로더가 하드웨어 브링업을 가져가면서 CFX 초기화가 크게 가벼워졌고**, I2S·빔포밍이 들어오면서 오디오 입력부가 두꺼워졌다. 유닛의 입력·반환 파라미터는 헤더 서명에서 기계적으로 뽑고, 이미 있는 **14 유닛 / 6 모듈 분해 자산에 U/M 라벨로 교차참조**를 건다. CFX 장을 먼저 완성한다.

---

## 1. 원본 해부 - 1.5세대 SDDD-FW-TD20B

### 1.1. 장 구성

| 장 | 내용 |
|---|---|
| 1 | 서론 (개요·목적·대상·관련문서) |
| 2 | 하드웨어 구조 (그림 1) |
| 3 | **MCU 간 제어 인터페이스** - 모듈별 다이어그램 4점 |
| 4 | **CFX 소프트웨어 상세 설계** - SI 6 · SU 61 |
| 5 | **CM3 소프트웨어 상세 설계** - SI 5 · SU 107 |
| 6 | **NRF 소프트웨어 상세 설계** - SI 3 · SU 18 |
| 7 | 소프트웨어 상세 설계 검증 (2문답) |

### 1.2. 유닛 서술 서식 (그대로 승계)

```
SU-ID-<CORE>-<NNN>, <유닛 이름>
    입력 파라미터 : ...
    반환 파라미터 : ...
    수정 파라미터 : ...
    기능 및 동작 :
    - ...
```

`SI-ID` 는 항목(Item), `SU-ID` 는 유닛(Unit)이다. **번호는 코어별로 1부터 연속**이며 모듈이 바뀌어도 이어진다.

## 2. Sound1 구조 델타 - 소스 근거

### 2.1. 가장 큰 변화 - 하드웨어 브링업이 부트로더로 이동했다

1.5세대 CFX 는 `SU-ID-CFX-001~023` 이 전부 초기화였다 - DIO 1차/2차/3차 설정, 타이머 중지, 클럭 설정, FIFO 초기화, IOC 설정, ADC/DAC 설정, **CM3·HEAR 코어 시작**까지 CFX 가 했다.

Sound1 의 `1__cfx/systemControl/main.c:13` 의 `main()` 은 **saturation 모드 설정과 인터럽트 설정 두 줄 뒤 바로 대기 루프**로 들어간다. 코어 기동과 메모리 배치는 `0__bootloader/source/bootloader_boot_cores.c` 가 담당한다.

| 1.5세대 CFX 가 하던 일 | Sound1 에서는 |
|---|---|
| DIO 1~3차 설정, 클럭 설정, 메모리 초기화 | **부트로더** |
| CM3·HEAR 코어 시작 | **부트로더** (`bootloader_boot_cores.c`) |
| FIFO·IOC·ADC 설정 | CFX `normal_init()` 에 축약 (`tdc_configure_audio_path_all`) |

> [!IMPORTANT]
> **이 이동을 문서에 반영하지 않으면 CFX 장이 통째로 사실과 어긋난다.** 1.5세대 SU-ID-CFX-001~023 을 그대로 옮겨 적으면 안 된다.

### 2.2. 부트로더가 SAD 기술보다 하는 일이 많다

SAD 3.4 절에 «무결성(CRC) 검증 · 코어 기동 · OTA 갱신» 으로 적었으나, 소스를 보면 그 이상이다.

| 기능 | 근거 |
|---|---|
| **AES 복호화** - 암호화된 이미지를 복호화한다 | `bootloader.c:56` `bootloader_initialize_aes_ctx` · `:76` `bootloader_decrypt_data` · `:741` `bootloader_get_application_key` |
| **PRAM 잠금** | `bootloader.c:106` `bootloader_lock_pram` |
| **파일 시스템 기반 로딩** - FatFs(`ff.h`) 로 이미지 파일을 읽는다 | `bootloader.c:263,852,975` |
| **매니페스트 처리** - 다중 파일 갱신 | `bootloader.c:999,1108` |
| 헤더 CRC 검증 | `bootloader.c:746` `bootloader_check_header_crc` |

> [!CAUTION]
> **SAD 3.4 절 보완이 필요하다.** 「복호화」와 「매니페스트」가 빠져 있다. SDDD 부트로더 장을 쓸 때 SAD 도 함께 고쳐야 두 문서가 어긋나지 않는다. 은수님 확인 사항으로 올린다.

### 2.3. 오디오 입력부가 두꺼워졌다

1.5세대 CFX 신호처리는 텔레코일 입력이 앞에 있었고(`SU-ID-CFX-048,049`) 마이크는 1개였다. Sound1 은 텔레코일이 **현재 버전 비활성**(`remoteControl.c:293`)이고, 대신 **2-DMIC 빔포밍 · I2S 브리지 · 게인 변환 테이블**이 들어왔다.

## 3. 유닛 도출 규칙

**규칙_1 - 파라미터는 서명에서 뽑는다.** 헤더 선언을 파싱해 반환형·인자를 그대로 쓴다. 지어내지 않는다. (`스크립트/extract_units.py`)

**규칙_2 - 다음은 유닛으로 올리지 않는다.**

| 제외 대상 | 이유 |
|---|---|
| 단순 getter/setter 쌍 | 짝을 하나의 «상태 읽기/쓰기 유닛» 으로 묶는다 |
| `[DEAD]` 표시 함수 | `lib_i2s.h:I2S_update_state` - 미사용 명시 |
| 디버그 전용 (`ci_print*`, RTT, 테스트 트리거) | 제품 기능이 아니다 |
| SDK·서드파티 (`SEGGER_RTT`, `tiny-AES-c`, FatFs) | SOUP 로 취급 |
| 같은 일을 채널 수만큼 반복하는 함수군 | `frame_1~4_perChannel` 은 1개 유닛으로 묶는다 |

**규칙_3 - 기존 분해 자산을 승계한다.** `20260626_i2s-beamforming-modularize/유닛-모듈-테스트맵.md` 의 U1~U14 / M1~M6 은 이미 «검증 라벨·의존성·테스트벡터 지점» 까지 정의된 밸리데이션 산출물이고, **소스의 `[UNIT]`/`[MODULE]` 배너와 1:1 정합**이다. 새 ID 로 덮어쓰지 않고 **SU-ID 에 «(U1, M1)» 형태로 교차참조**를 단다.

| 맵 라벨 | 함수 | SDDD 에서 |
|---|---|---|
| U1 | `tdc_audio_mix_2_buffers_for_beamforming` | 지향성 믹싱 유닛 |
| U2 | `tdc_audio_mix_1_buffer` | 단일 버퍼 믹싱 유닛 |
| U3 | `tdc_audio_mix_2_buffers` | 독립 2버퍼 믹싱 유닛 |
| U4 | `tdc_audio_set/get_front_mic` | 전방 마이크 상태 유닛 |
| U5 | `tdc_get_enabled_DMIC_count` | DMIC 사용 개수 유닛 |
| U6 | `I2S_isStreaming` / `tdc_i2s_set_streaming_state` | I2S 스트리밍 상태 유닛 |
| U7·U8 | I2S fade-in / fade-out | I2S 페이드 유닛 |
| U9 | `tdc_copy_DMIC_buffers` | DMIC 링버퍼 시프트 유닛 |
| U10 | `tdc_enable_1_DMIC` / `tdc_enable_2_DMICs` | DMIC 수 전환 유닛 |
| U11 | `tdc_configure_audio_path_all` | 오디오 경로 설정 유닛 |
| U12 | `Normal_PowerMode_event_mapChange` 의 L/R 블록 | 전방 마이크 및 HW 지연 설정 유닛 |
| U13 | `tdc_audio_gain_lookup_q8_16` | 게인 변환 테이블 유닛 |
| U14 | `tdc_audio_mix_2_buffers_with_gain` | 게인 적용 믹싱 유닛 |

## 4. 장 구성 - 착탈 구조 유지

```
1. 서론
2. 하드웨어 구조                    <- SAD 그림 1 재사용
3. 프로세서 간 제어 인터페이스        <- SAD 4장과 대응 (모듈별)
4. CFX 소프트웨어 상세 설계          <- 이번 단계
5. CM3 소프트웨어 상세 설계          <- 다음 단계
6. 부트로더 소프트웨어 상세 설계      <- [착탈 A]
7. QCC5181 소프트웨어 상세 설계      <- [확장 B] 범위 밖 선언
8. 소프트웨어 상세 설계 검증
```

SAD 와 같은 규칙을 적용한다 - **본문에 장·절 번호 상호참조를 쓰지 않는다.** 6장을 지워도 다른 장의 문장이 깨지지 않는다.

## 7. 실패 시나리오

| 라벨 | 시나리오 | 방지 |
|---|---|---|
| **실패_1** | 1.5세대 CFX 초기화 유닛(001~023)을 그대로 옮겨 적어, **부트로더가 하는 일을 CFX 가 한다고 기술**한다 | 2.1절 대조표를 근거로 초기화 유닛을 새로 도출. 검증 단계에서 `main.c` 실제 호출과 대조 |
| **실패_2** | 파라미터를 기억으로 적어 서명과 어긋난다 | **서명 파싱으로만 채운다.** 검증 단계에서 문서의 파라미터와 헤더를 재대조 |
| **실패_3** | 기존 `유닛-모듈-테스트맵.md` 와 SU-ID 가 따로 놀아, 밸리데이션 추적성이 두 갈래로 갈라진다 | U/M 라벨 교차참조 필수(규칙_3). 14건 전부 매핑됐는지 검증 |
| **실패_4** | SU-ID 번호가 중간에 끊기거나 중복되어 SUVC 가 참조하지 못한다 | 검증 단계에서 코어별 연속성 확인 |
| **실패_5** | SAD 의 부트로더 기술(«CRC·기동·OTA»)과 SDDD 의 부트로더 장(복호화·매니페스트 포함)이 어긋난다 | **SAD 3.4 절 보완을 은수님께 올린다** (2.2절). 확인 전에는 SDDD 를 사실대로 쓰고 불일치를 기록 |

## 8. 핵심 결정 (게이트 1)

| 결정 | 권장안 | 근거 |
|---|---|---|
| **결정_1** - CFX 초기화 유닛 도출 | **Sound1 소스 기준으로 새로 도출** | 1.5세대 것을 옮기면 부트로더 이동을 놓친다 (실패_1) |
| **결정_2** - 기존 U/M 라벨 처리 | **SU-ID 에 교차참조로 병기** | 이미 있는 밸리데이션 자산을 버리지 않는다 |
| **결정_3** - SAD 부트로더 절 보완 | **보완 제안 후 은수님 확인** | 두 문서가 어긋나면 심사에서 잡힌다 |
| **결정_4** - 텔레코일 유닛 | **기술하지 않음** | 현재 버전 비활성. 프로토콜에만 남아 있다 |
