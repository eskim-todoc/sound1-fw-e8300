## 2. 논리 정합성

- **매트릭스 완전성**: I2S 유무 × (Streaming/CRADLE) 3상태가 상호 배타·전체 포괄. I2S 없음 상태에서 classic_type은 미사용이므로 모순 없음. ✅
- **Gain_A 적용 대상**: 다이어그램(빔포밍 합산)과 현행 코드(I2S 시 DMIC1 단일)의 차이를 §1에 명시하고 "현행 유지"로 확정(은수님 답변) — 요구사항 내 상충 없음. ✅
- **응답 패킷**: Read/Write 모두 5바이트 응답으로 통일, 실패 조건 열거(요구사항_4). Gain type=0(Invalid)이 프로토콜에 존재하므로 Failed 처리 규정 타당. ✅
- **인덱스 유효 범위**: 1바이트 필드라 0~255 전 값이 테이블 범위 내 → 인덱스 자체의 범위 오류는 구조적으로 불가(index 0=뮤트는 유효값). ✅
- **미확정 항목**: 기본 인덱스 값 1건만 미정, ⑤계획 제안 + 승인 게이트 확정으로 명시(요구사항_3). ✅

# 2차 요구(§4-2 ISD별 영속화) 검증 — 2026-07-20 추가

## 5. 논리 정합성

- **1차 요구와의 관계**: 요구사항_3(컴파일 타임 기본값)은 폐기되지 않는다. 저장값이 없거나 손상된 경우의 fallback으로 **역할이 재정의**될 뿐이며, 요구사항_11이 이를 명시한다. 모순 없음. ✅
- **Read 일관성(요구사항_10)**: 0x8C Read는 이미 공유메모리 현재값을 반환하도록 구현되어 있다(`tdc_remote_gain_control.c` `gc_read_index()`). 따라서 **요구사항_8(연결 시 공유메모리에 반영)이 충족되면 요구사항_10은 자동 충족**된다 — 별도 코드 불필요. ✅
- **은수님의 사용 시나리오 재구성**: ① 앱에서 게인 조정(0x8C Write) → 저장(요구사항_9) → ② 전원 재인가 → ③ ISD 연결 확인 → 저장값 로드(요구사항_8) → ④ 폰 연결 후 앱이 Read → 이전 설정 표시(요구사항_10). 각 단계가 요구사항으로 빠짐없이 덮인다. ✅
- **ISD별 분리의 타당성**: 게인은 착용자의 청력·착용 환경에 종속되므로 ISD(사용자)별 값이 자연스럽다. 기존 사용자 설정(볼륨 등)이 이미 ISD별인 것과 일관. ✅ (단, 실제 저장 구조가 ISD별인지는 ③분석에서 근거 확인 — 조사 진행 중)
- **미확정 항목**: 저장 위치(기존 설정 파일 확장 vs 전용 파일), 포맷 호환성, 쓰기 빈도 — 셋 다 요구사항 §4-2 말미에 "③분석·⑤계획에서 확정"으로 명시. 임의 가정 없음. ✅
