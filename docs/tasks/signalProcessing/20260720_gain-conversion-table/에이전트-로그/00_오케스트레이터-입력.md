# 오케스트레이터 입력 — 게인 설정 ISD별 영속화 조사

**TL;DR**: 은수님 추가 요구(게인 값을 ISD별 파일로 저장 → ISD 연결 시 자동 로드)를 설계하기 위해, 기존 ISD별 설정 저장·로드 경로와 소규모 설정 영속화 선례를 Explore 2노드로 병렬 조사했다. 코드 수정 없는 조사 전용 위임.

## 1. 오케스트레이터 입력 (은수님 지시 원문)

> 좀 더 추가하고 싶은게 있어. cm3에서는 지금 isd가 최대 4개까지 저장되잖아. 그래서 나도 이 gain control 값을 isd 별로 파일로 저장한 다음, isd가 연결된게 확인될 때 해당하는 isd의 gain control 값을 설정하게하고 싶어. 그래서 폰이 연결되고나서 단순히 설정 읽기만 해도 이전 설정이 유지될 수 있게. 이게 사용자 측면에서는 당연한 이야기 같거든?

## 2. 위임 설계

| 노드 | 역할 | 산출 로그 | 모델 |
|---|---|---|---|
| 01 | ISD별 설정 저장·로드 경로 조사(슬롯 모델·저장 포맷·연결 감지 시점·저장 트리거·필드 추가 영향) | `01_ISD별-설정-저장-경로.md` | sonnet |
| 02 | 소규모 설정 영속화 선례·FS API 계층 조사(ci_stim_mute 패턴·API·다른 사례·쓰기 안전성·초기화 순서) | `02_설정-영속화-선례.md` | sonnet |

**분할 근거**: 두 조사는 대상 파일군이 거의 겹치지 않고(01 = ISD/맵/공유메모리 계통, 02 = FS 래퍼/영속화 모듈 계통) 결과 의존도 없음 → 병렬 fan-out 실익 있음. 광범위 파일 탐색이라 세션 컨텍스트 절약 효과도 큼.

**공통 제약(양 노드 프롬프트에 명시)**: 코드 수정 금지(조사 전용) · 모든 사실 주장에 `파일:라인` 근거 · 추측은 "추정" 명시 · 근거 미발견은 "확인 실패"로 남기고 날조 금지 · **결과를 지정 경로에 직접 Write** · 한국어 작성 · frontmatter + TL;DR.

## 3. 프롬프트 원문

프롬프트 전문은 세션 기록에 있으며, 위 §2의 조사 항목 5종(노드별)과 공통 제약이 그대로 전달되었다. 산출물 경로는 각 노드 프롬프트에 절대경로로 지정했다.

## 4. 후속

두 로그 수신 후 오케스트레이터(세션)가 요구사항 확장 → 분석 → 계획 → 승인 → 구현으로 이어간다. 조사 결과의 사실 검증(파일:라인 재확인)은 세션이 분석-검증 단계에서 수행한다.
