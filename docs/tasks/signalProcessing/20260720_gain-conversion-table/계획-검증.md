## 3. 논리 정합성

- **순서 의존성**: Step 4는 Step 1(함수)·2(필드)·3(값)에 의존 — 계획의 Step 번호 순서가 곧 컴파일 가능 순서. 커밋 분할(§4)도 커밋 1→2→3 순으로 각 시점에 빌드 가능(커밋 1 시점의 신규 함수는 미호출 상태이나 컴파일 유효). ✅
- **U3 잔존 판단**: 라이브 호출부만 교체하고 U3 정의를 남기는 이유가 "DEAD `I2S_handle()`이 참조"로 명시됨 — 삭제 시 컴파일 에러라는 근거 타당(`main.c:381`·`:409`). ✅
- **Streaming 무게인 = 유니티 곱**: `x * 65536 >> 16 == x`(x는 정수, 산술 시프트) — 음수 포함 항등. 단 이는 **합산 전 각 항이 아니라 합산 후 시프트**인 계획 수식에서도 성립(`(a*65536 + b*65536) >> 16 = a + b`). ✅
- **기본값 유니티 = 현행 비트 동일**: 현행 U3는 `(mic>>5) + (i2s>>5)`, 신규는 `(65536*(mic>>5) + 65536*(i2s>>5)) >> 16` = 동일. 단 **포화 클램프가 추가**되므로, 현행에서 24비트를 넘겨 랩어라운드하던 극단 입력에서는 동작이 달라진다(포화). 이는 개선이며 agc 관행과 일치 — **의도된 차이로 기록**. ✅
- **실패 시 응답 index 에코**: 앱이 거부 원인을 식별할 수 있어 합리적. 프로토콜 문서가 실패 시 필드 값을 규정하지 않으므로 설계 재량 — 계획에 명시됨. ✅
- **cradle 플래그 잔존**: 클래식 DISCONN 시 0으로 갱신되고, 0x36 미수신 상태에서도 I2S_FLAG 비활성이면 바이패스라 무해([`분석.md §2.3`](분석.md)). ✅

## 8. 논리 정합성 (2차)

- **정렬 불변식 재계산**: 데이터 8바이트 → `8 % 16 = 8`, `8 + 4(CRC) + 4(padding) = 16` ✅. 맵 스탬프(`24 % 16 = 8`, 동일하게 `8+4+4`)와 **같은 잔여값**이므로 검증된 경로를 그대로 탄다.
- **Step 8 삽입 위치**: `if (0 < isd_num)` 블록 안이며 `connected_ISD_num = isd_num`(`:350`) 대입 **이전**이다. 이 순서가 문제되지 않는 이유 — `tdc_gain_storage_load()`는 `isd_num`을 **인자로 직접 받으므로** 공유메모리의 `connected_ISD_num`에 의존하지 않는다. ✅
- **Step 9의 슬롯 판정 시점**: 0x8C Write는 ISD 연결이 이미 끝난 런타임에 도착하므로 `read_connected_ISD_Num()`이 유효값을 준다. 미연결 상황은 결정_5 가드로 처리. ✅
- **로드와 저장의 대칭**: 로드는 `isd_num` 인자, 저장은 `read_connected_ISD_Num()` 조회 — 비대칭으로 보이나, 로드는 "연결 중인 ISD를 확정하는 과정"이라 아직 공유메모리에 반영 전이고, 저장은 "이미 확정된 상태"라서 조회가 자연스럽다. 의도된 비대칭. ✅
- **부팅 초기화 생략의 안전성**: ISD 연결 전 구간은 `tdc_remote_gain_control_init()`(1차 구현)이 유니티를 보장하고, 연결되면 Step 8이 덮어쓴다. 게인이 미정의 값으로 쓰이는 구간이 없다. ✅
- **결정_5의 부작용 점검**: 미연결 상태에서 Write → 공유메모리만 갱신 → 이후 ISD 연결 시 Step 8이 **저장값으로 덮어쓴다**. 즉 미연결 중 조정한 값은 연결 시 사라진다. 이는 "게인은 ISD별 설정"이라는 요구 자체에서 따라오는 자연스러운 귀결이며, 사용자 시나리오(앱은 ISD 연결 후 사용)에서 발생 가능성이 낮다. ⚠️ **은수님 확인 대상**으로 승인 항목에 포함.
