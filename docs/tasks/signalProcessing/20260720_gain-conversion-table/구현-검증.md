# Gain Conversion Table — 구현 검증 (⑧)

**TL;DR**: 계획 6단계 전부 구현 완료(11파일, +566/-5). 게인 테이블 256엔트리 문서 대조 **불일치 0건**, 공유메모리 미러 필드 35/35 순서 일치, 정적 검증(브레이스·금지문자·심볼) 전수 PASS. 빌드·실기는 은수님 Eclipse 환경 몫이며 **미수행**.

## 2. 검증 라벨별 결과

### 유닛_게인테이블 — PASS

- 스크립트로 `audioMixer.c`의 `m_tdc_gain_table_q8_16[]` 초기화자를 파싱해 `Gain Table.md` 256엔트리와 대조: **엔트리 256/256, 불일치 0건**.
- 스팟 확인: `[0]=0`(뮤트) · `[128]=65536`(유니티) · `[255]=512211`(+17.8594 dB).
- 결정_4(확장성) 준수: 인덱스별 1줄 + `// [nnn] ±d.dddd dB` 주석 형태로 나열 — 임의 인덱스만 다른 값으로 교체 가능. 런타임 수식 계산 없음.
- 범위 밖 인덱스 방어: `tdc_audio_gain_lookup_q8_16()`(`audioMixer.c:282`)가 음수·256 이상이면 유니티 반환.

### 유닛_게인믹서 — PASS

`tdc_audio_mix_2_buffers_with_gain()`(`audioMixer.c:328`) 손계산 검증:

| 케이스 | 입력 | 기대 | 코드 결과 |
|---|---|---|---|
| 유니티 항등 | gain_a=gain_b=65536 | `(mic>>5)+(i2s>>5)` (기존 U3와 동일) | `(65536·a + 65536·b) >> 16 = a + b` ✅ |
| 뮤트 | gain_a=0 | 마이크 성분 0 | `0·a = 0` ✅ |
| 최대 게인 | gain=512211, 입력 최대 2^18 | 오버플로 없음 | 곱 ≈2^37, 2항 합 ≈2^38 < long 48비트 ✅ |
| 상단 초과 | 합이 +8,388,607 초과 | 절삭 | `INT24_MAX` 클램프(`:346~348`) ✅ |
| 하단 초과 | 합이 -8,388,608 미만 | 절삭 | `INT24_MIN` 클램프(`:350~352`) ✅ |

- **결정_3(절삭)** 준수: 랩어라운드 없음. `apply_agc_gain()`(`agc.c:324~331`)과 동일 관행.
- 두 곱을 합산한 뒤 **1회만** `>> 16` — 항별 시프트 대비 반올림 오차 작음(계획대로).
- `INT24_MAX/MIN`은 `definitionsForAlgorithm.h:39~40` 정의, `audioMixer.h:16` include 체인으로 가용.

> [!NOTE]
> **의도된 동작 차이**: 기존 U3에는 포화 클램프가 없어 24비트 초과 시 랩어라운드했다. U5는 절삭한다. 은수님 지시(결정_3)에 따른 **의도된 변경**이며, 극단 입력에서만 나타난다.

### 유닛_공유메모리레이아웃 — PASS

- 스크립트로 두 헤더의 `ST__CFX_CM3_SharedMemory_ALL` 멤버를 순서대로 추출: **cm3 35개 / cfx 35개, 순서 일치**.
- 신규 3필드가 양쪽 모두 **맨 끝** 동일 순서(`gain_table_index_a` → `gain_table_index_b` → `is_i2s_source_cradle`) — 선행 필드 오프셋 불변.
- 유일한 표기 차이는 `cfx_ISD_info[MaxNumUser]`(cm3) vs `[MAX_NUM_USER]`(cfx)로 **본 작업 이전부터 존재**하며, 두 매크로 모두 값 4(`processorDirective.h:169`, `definitionsForAlgorithm.h:65`)라 레이아웃 영향 없음.

### 유닛_기본값초기화 — PASS

- `tdc_remote_gain_control_init()` 호출을 `initialize.c:344`(`CFX_EEPROM_data_is_Loaded = 1`) 직후에 배치 — `enable_CFX_trigger_for_iteration()`(`:452 → 현 :456`)보다 **앞**. 분석-검증 정정_1 반영 확인.
- 기본값 128/128(유니티) + cradle 0. 상수는 `tdc_remote_gain_control.h`에 단일 정의.

### 유닛_0x8C핸들러 — PASS

분기 전수 검토(`tdc_remote_gain_control.c`):

| Control type | Gain type | index | 동작 | rsp_code | 응답 index |
|---|---|---|---|---|---|
| 0 Read | 1 A / 2 B | (무시) | 현재값 조회 | 1 | 저장된 값 |
| 1 Write | 1 A / 2 B | 0~255 | 저장 후 조회 | 1 | 저장된 값 |
| 1 Write | 1 A / 2 B | 범위 밖 | 거부 | 0 | 수신값 에코 |
| 0/1 | 0 Invalid 또는 3+ | — | 거부 | 0 | 수신값 에코 |
| 2+ | — | — | 거부 | 0 | 수신값 에코 |

- 응답 5워드 순서 = 프로토콜 문서(`[0]=0x8C`, `rsp_code`, `Control type`, `Gain type`, `index`) 일치.
- Read 명령은 인덱스 필드를 쓰지 않으므로 범위 검사 제외(`gc_is_valid_request()` 내 조건) — 앱이 index 필드를 0으로 채워 보내도 정상 Read.
- 페이로드 도착 경로 확인: 0x8C는 `fetch_remoteControlPacket()`의 `default:`(`remoteControl.c:619~624`)로 복사되어 `data[0..2]`에 안착 — 0x8F와 동일.

## 6. 검증 라벨별 결과

### 유닛_게인파일IO — PASS

| 항목 | 결과 |
|---|---|
| 구조체 크기 | `uint32_t(4) + ST__TDC_GAIN_SETTING(8) × 4 + uint32_t(4) = 40바이트` (ARM Cortex-M3 `int`=4) |

| **컴파일 타임 검사** | `typedef char tdc_gain_file_alignment_check[...]`로 조건 위반 시 **컴파일 에러**. 구조체를 나중에 확장하다 조건이 깨지는 사고를 원천 차단 |

| 슬롯 범위 방어 | `(isd_num < 1) \|\| (MaxNumUser < isd_num)` — 배열 인덱스 `isd_num - 1` 음수 접근 차단 |

| 파일 상태 | 처리 | 재기록 |

### 모듈_연결시로드 — PASS

- 삽입 위치: `cfx_cm3_sharedMemory.c` `changeConnected_isd_num_CFX()`의 `if (0 < isd_num)` 블록, `fn_copy_userSettingParameters_toCM3()` 직후.
- `connected_ISD_num = isd_num` 대입(블록 밖)보다 **앞**이지만, `tdc_gain_storage_load()`가 `isd_num`을 **인자로 받으므로** 공유메모리 값에 의존하지 않는다. 문제 없음.
- 로드 실패해도 `p_out`에 기본값이 채워져 반환되므로, 호출부는 반환값을 보지 않고도 항상 유효한 값을 공유메모리에 넣는다.

### 모듈_부팅검사 — PASS (설계 변경분)

- `initialize.c`에 `tdc_gain_storage_init()` 추가. 위치는 `CFX_EEPROM_data_is_Loaded = 1` 직후, `tdc_remote_gain_control_init()` **직전**.
- **선행 조건 충족**: FS 마운트(`:261`)·부트 드라이브 왕복(`:313~316`)보다 뒤이므로 파일시스템 사용 가능. `enable_CFX_trigger_for_iteration()`보다 앞이므로 CFX 오디오 개시 전.
- 순서 의도: 파일을 먼저 정상화 → 공유메모리 기본값 설정 → (이후 ISD 연결 시) 저장값으로 덮어쓰기.
- 반환값 미검사 = 기존 `ci_map`·`ci_stim_mute` 초기화와 동일한 fail-soft 관행(계획대로).
