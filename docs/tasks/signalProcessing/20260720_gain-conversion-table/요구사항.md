# Gain Conversion Table 기능 — 요구사항

**TL;DR**: 256엔트리 Q8.16 게인 테이블을 cfx `audioMixer.c`에 구현. I2S 소스에 따라 마이크 경로에 Gain_A, 크래들 마이크(I2S) 경로에 Gain_B를 적용하고, I2S 미사용 시 게인 없이 바이패스(현행 유지). 게인 인덱스는 컴파일 타임 기본값 + 앱 0x8C(Gain control) 패킷으로 런타임 Read/Write. CRADLE 판별은 cm3 CLASSIC_STATE(0x36)의 classic_type을 cfx로 전달해 해결한다. **2차 요구(§4-2)**: 게인 설정을 ISD별 파일로 영속화해 ISD 연결 시 자동 복원한다.

---

## 1. 배경

- 은수님이 게인 적용 정책을 [`Gain Table.md`](../../../참고/Gain%20Conversion%20Table/Gain%20Table.md)(256엔트리 변환 테이블)로 정의함.
  - Q8.16 고정소수점: index 128 = 0 dB = 65,536(=1.0), 스텝 0.140625 dB, 범위 약 ±17.86 dB, **index 0 = 뮤트(0)**.
- 오디오 경로·게인 배치는 [`Audio path & Gain setting.png`](../../../참고/Gain%20Conversion%20Table/Audio%20path%20&%20Gain%20setting.png) 기준:
  - **Gain_A** = 마이크(빔포밍 합산) 경로 게인. 단, I2S 활성 시 현행 코드는 DMIC1 단일 버퍼를 섞으므로(`main.c:440`) **현행 유지 + 그 신호에 Gain_A** (은수님 확정 2026-07-20).
  - **Gain_B** = I2S로 들어오는 **크래들(충전 포트) 마이크** 신호 게인.
  - AGC 앞 합산 지점 이전에 적용.
- I2S 입력의 두 소스: QCC 블루투스 클래식 **Streaming**(스마트폰 볼륨으로 제어) vs **Mic (Case)**(크래들 마이크).
  - 구분 신호: cm3 `ble_communication.c:198` `EN__SND_BT_CMD_SYSTEM_INFO_CLASSIC_STATE`(0x36)의 `classic_type == 1`(CRADLE). 현재 로그만 찍고 있으며 cfx 전달 경로 없음(`ble_communication.c:216` "향후 크래들과 I2S 게인 테이블 적용" 주석).
- 게인 인덱스 런타임 설정 프로토콜: [`Gain control protocol packet.png`](../../../참고/Gain%20Conversion%20Table/Gain%20control%20protocol%20packet.png) — 헤더 **0x8C**.

## 2. 게인 적용 매트릭스 (확정)

| 상황 | 판별 | 마이크 경로 | I2S 경로 |
|---|---|---|---|
| I2S 입력 없음 | I2S_FLAG 비활성 | **바이패스** (게인 미적용, 현행 동작 유지) | (없음) |
| I2S = Streaming | I2S_FLAG 활성 + classic_type ≠ CRADLE | **Gain_A** | 게인 없음 (스마트폰 볼륨) |
| I2S = Mic (Case) | I2S_FLAG 활성 + classic_type == 1(CRADLE) | **Gain_A** | **Gain_B** |

## 3. 0x8C Gain control 패킷 (앱 → QCC → E8300)

**앱 명령 (4바이트)**: `[0]=0x8C` · `[1]=Control type`(0 Read / 1 Write) · `[2]=Gain type`(0 Invalid / 1 Gain_A(외부기 mic) / 2 Gain_B(크래들 mic)) · `[3]=Gain table index`(0~255)

**기기 응답 (5바이트)**: `[0]=0x8C` · `[1]=rsp_code`(0 Failed / 1 Success) · `[2]=Control type` · `[3]=Gain type` · `[4]=Gain table index`

## 4. 요구사항 목록

- [ ] **요구사항_1 (테이블)**: `Gain Table.md`의 Q8.16 256엔트리를 cfx `audioMixer.c`에 상수 테이블로 구현한다.
- [ ] **요구사항_2 (게인 적용)**: §2 매트릭스대로 믹싱 시점에 Gain_A/Gain_B를 곱셈 적용한다. I2S 미사용 경로(단일/빔포밍 믹서)는 동작 보존.
- [ ] **요구사항_3 (기본값)**: 컴파일 타임 기본 인덱스를 정의한다(값은 ⑤계획에서 제안, 승인 게이트에서 확정).
- [ ] **요구사항_4 (런타임 설정)**: cm3가 0x8C 패킷을 수신·해석해 Write 시 해당 게인 인덱스를 갱신하고, Read/Write 모두 §3 응답 패킷을 회신한다. 유효성 위반(Gain type 0/범위 밖, Control type 범위 밖)은 rsp_code=0(Failed).
- [ ] **요구사항_5 (cm3→cfx 전달)**: 게인 인덱스(A/B)와 I2S 소스 종류(classic_type의 CRADLE 여부)를 cm3에서 cfx로 전달한다(기존 cm3↔cfx 공유메모리 관행 준수).
- [ ] **요구사항_6 (CRADLE 판별 연동)**: 0x36 CLASSIC_STATE 수신 시 classic_type을 cfx 전달 값에 반영한다.

## 4-2. 2차 요구 — ISD별 게인 설정 영속화 (2026-07-20 추가)

**배경**: 1차 구현에서 게인 인덱스는 전원 재인가 시 기본값(유니티)으로 돌아간다(§6 범위 밖 항목이었음). 은수님 지시로 이를 범위 안으로 끌어온다.

> 사용자 관점에서는 "폰이 연결되고 나서 단순히 설정을 읽기만 해도 이전 설정이 유지"되는 것이 당연하다.

cm3는 ISD(내부기)를 최대 4개까지 저장하므로, 게인 설정도 **ISD별로 분리 저장**한다.

- [ ] **요구사항_7 (영속화)**: Gain_A·Gain_B 인덱스를 **ISD별로** 파일시스템에 저장한다.
- [ ] **요구사항_8 (자동 적용)**: ISD 연결이 확인되면 해당 ISD의 저장값을 읽어 공유메모리에 반영한다(앱 개입 없이).
- [ ] **요구사항_9 (쓰기 시점)**: 0x8C Write 수신으로 값이 바뀌면 저장한다.
- [ ] **요구사항_10 (Read 일관성)**: 0x8C Read는 현재 적용 중인(= 연결된 ISD의) 값을 반환한다. 앱이 Read만 해도 이전 설정이 보여야 한다.
- [ ] **요구사항_11 (안전한 기본값)**: 저장 파일이 없거나 손상되었으면 기본값(유니티 128)으로 동작하고, 무음(인덱스 0)으로 빠지지 않는다.

**설계 방향 결정 사항**(③분석·⑤계획에서 근거와 함께 확정):
- 저장 위치 — 기존 ISD별 사용자 설정 파일에 필드를 추가할지, 게인 전용 파일을 새로 둘지.
- 기존 저장 파일과의 호환성(포맷 변경 시 마이그레이션 필요 여부).
- 쓰기 빈도와 플래시 수명(0x8C Write마다 즉시 기록할지, 지연·병합 기록할지).
