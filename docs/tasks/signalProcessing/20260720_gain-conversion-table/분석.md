# Gain Conversion Table 기능 — 분석 (③)

**TL;DR**: 살아있는 I2S 믹싱 호출부는 `main.c:440` 한 곳(`I2S_handle()`은 DEAD). CFX에는 Q8.16 + `long` 누산 + `>>16` + INT24 포화 관행이 agc.c에 이미 확립되어 있어 게인 곱은 동일 패턴으로 구현 가능. cm3 0x8C는 기존 명령 범위와 충돌 없는 빈 값이고, 0x8F(tdc_remote_general_debug) 분리 파일 관행을 그대로 미러링하면 된다. cm3→cfx 전달은 이중 미러 공유메모리 구조체 끝에 3필드 append + `Initialize()`에서 기본값 기록(CFX iteration 개방 전이라 순서 보장).

## 1. cfx 오디오 경로 현행 구조

### 1.1 믹싱 유닛 (audioMixer.c)

| 유닛 | 함수 | 역할 | 게인 관련성 |
|---|---|---|---|
| U1 | `tdc_audio_mix_2_buffers_for_beamforming` (`audioMixer.c:99`) | 2-DMIC DAS 빔포밍 | I2S 없음 경로 — **바이패스 유지, 미수정** |
| U2 | `tdc_audio_mix_1_buffer` (`audioMixer.c:17`) | 단일 DMIC | I2S 없음 경로 — **바이패스 유지, 미수정** |
| U3 | `tdc_audio_mix_2_buffers` (`audioMixer.c:30`) | mic + I2S 단순 합산(÷2 없음) | **게인 적용 대상 경로** |

- 공통 규약: 각 입력 `>> AUDIO_INPUT_RSHIFT`(=5, `definitionsForAlgorithm.h:103`) 후 합산, 출력은 `HEAR_ADDR_AUDIO_MIX[16]`.
- 믹스 출력은 `CALL_FUNCTION_CHAIN(HEAR_FC_agc_preprocessing)`(`main.c:486`)로 AGC에 전달 — 요구 다이어그램의 "합산 → AGC" 지점과 일치.

### 1.2 디스패치 (M6, `PCM_LiveStimulation_Mode`, main.c:429~487)

- `I2S_isStreaming()`(`main.c:433`) 분기: 활성 시 `tdc_audio_mix_2_buffers(DMIC1 현재블록, I2S 버퍼)`(`main.c:440`), 비활성 시 DMIC 수·front mic에 따라 U1/U2.
- **U3의 살아있는 호출부는 `main.c:440` 단 한 곳**. `main.c:381`·`:409`의 호출은 `I2S_handle()` 내부인데 이 함수는 DEAD(호출부 없음, `main.c:357~358` 주석 명시). → 게인 적용 지점은 M6 디스패치 1곳만 수정하면 됨.

### 1.3 Q8.16 고정소수점 연산 관행 (agc.c — 그대로 재사용할 패턴)

- Q8.16 상수 테이블 정례: `int chess_storage(XMEM) m_amplify_region_ybias_db_Q8_16[10]`(`agc.c:24`) — 256엔트리 게인 테이블도 동일 형식으로 배치 가능.
- 곱셈 정례: `long_acc = ((long) coeff_Q8_16) * value; long_acc >>= 16;`(`agc.c:127~129`) — CFX `long`(48비트) 누산.
- 샘플에 게인 적용 + 포화 정례: `apply_agc_gain()`(`agc.c:307~336`) — `(long)gain * p_mix[i] >> 12` 후 `INT24_MAX/INT24_MIN` 클램프. INT24 상수는 `definitionsForAlgorithm.h:39~40`(audioMixer.h가 include하는 헤더에서 가용).
- 샘플은 Q24.0(24비트 int) — 클램프 사용으로 확인.

### 1.4 오버플로 여유 (수치 검증)

- 입력: `|sample >> 5|` ≤ 2^18. 게인 최대 512,211(≈2^19). 곱 ≈ 2^37, 두 항 합 ≈ 2^38 — `long`(48비트) 내 안전.
- `>> 16` 후 최대 ≈ 2^22 — INT24 범위(±2^23) 내. 포화는 이론상 거의 미발동이나 방어적으로 유지(agc 관행 동일).
- 유니티 게인(65,536) 곱은 `x * 2^16 >> 16 = x` — **비트 정확**(Streaming 시 I2S 무게인 요구를 게인 경로 통일로 충족 가능).

## 2. cm3 패킷 인프라

### 2.1 0x8C 값 충돌 검사 (전수)

`ble_commonProtocol.h` 기준: 리모컨 0x40~0x5A(`:51~81`), 매핑 0x60~0x72 연속(`:88~110`) + 0x90·0x91(`:111~112`), SND 시스템 0x33~0x36(`:42~45`), GENERAL_DEBUG 0x8F(`:117`), OTA/BOOT 0xC0~0xC3. → **0x8C는 미할당, 충돌 없음**. `ble_communication.c`의 라우팅 분기들(리모컨 `0x40≤x<0x60`, 매핑 `0x60≤x≤0x72`·0x90·0x91, SND `0x33~0x36`, 0x8F 개별 else-if)도 0x8C를 삼키지 않음 — 신규 else-if 필요.

### 2.2 0x8F 선례 (그대로 미러링할 파이프라인)

1. **라우팅**: `ble_communication.c:357~360` `else if (p_Rx_dataPacket[0] == EN__SND_BT_CMD_GENERAL_DEBUG)` → `fetch_remoteControlPacket(p_Rx_dataPacket)`.
2. **복사**: `fetch_remoteControlPacket()`의 `default:` 분기(`remoteControl.c:619~624`)가 헤더→`remoteDataPacket.command`, 페이로드 19워드→`remoteDataPacket.data[]` 복사. → 0x8C 페이로드는 `data[0]=Control type`, `data[1]=Gain type`, `data[2]=index`로 도착.
3. **처리**: `remoteControl()`의 `case EN__SND_BT_CMD_GENERAL_DEBUG`(`remoteControl.c:1345~1352`) → `tx_index = tdc_remote_general_debug_handle(&remoteDataPacket, bufferForSPI_tx, tx_index)` → `writeDataToSpiTxBuff()` → `clearRemoteColtrolCommand()`. 별도 파일 `tdc_remote_general_debug.c/.h` 분리 선례([`ble/20260701_general-debug-protocol-split`](../../ble/20260701_general-debug-protocol-split/)).
4. **응답 인프라**: `bufferForSPI_tx`(지역 int[20])·`tx_index`·`writeDataToSpiTxBuff()` — 0x59 케이스(`remoteControl.c:1360~`)는 5워드 응답 + 공유메모리 직접 읽기/쓰기 선례(`cfx_cm3_sharedMemoryAll.is_enabled_mute_stimulation_under_t_level`, `:1372~1373`).

### 2.3 CLASSIC_STATE(0x36) 핸들러

- `ble_communication.c:198~223`: `classic_state`(0 DISCONN/1 CONN), `classic_type`(0 UNKNOWN/1 CRADLE/2 OTHER) 수신, 현재 로그만 출력. `:216`에 "향후 크래들과 I2S 게인 테이블 적용" 주석 — 이 지점에서 공유메모리 cradle 플래그 기록이 자연스러움.
- 시맨틱: cradle = (`classic_state==1` AND `classic_type==1`). DISCONN이면 0. 0x36 미수신 상태에서 I2S가 노는 경우는 I2S_FLAG 비활성 → 바이패스이므로 플래그 잔존 무해.

## 3. cm3→cfx 공유메모리

### 3.1 구조

- **이중 미러 헤더**: cm3 `cfx_cm3_sharedMemory.h:187~241`(`ST__CFX_CM3_SharedMemory_ALL`) ↔ cfx `environment/shared_memory.h:177~219`. **필드 순서·구성이 바이트 단위로 일치해야 함**(cfx는 IOMEM 0x28000 고정 매핑, `shared_memory.h:223`; cm3는 `.shared_memory` 섹션 → PRAM5, `cfx_cm3_sharedMemory.h:401`).
- **끝에 append가 안전**: 선행 필드 오프셋 불변. 선례: `is_enabled_mute_stimulation_under_t_level`(2026-01-20 append), `is_pcm_specific_command_reading`(2026-02-24 append).

### 3.2 소비 패턴 (cfx)

- 사용자 설정 소비 선례: `system_control.c:193` `m_audio_volume = Addr_SharedMem->userSettingValue.audioVolume - 1`(변경 감지 폴링). 게인은 매 블록 직접 읽기(`Addr_SharedMem->필드`)로 충분 — agc.c도 블록마다 공유메모리 접근(`agc.c:105`).

### 3.3 초기화 순서 보장 (기본값 0 = 뮤트 함정 회피)

- 부팅 핸드셰이크: CFX가 `is_CFX_started=1` 설정(`1__cfx/main.c:47`) 후 `is_enabled_CFX_iteration==1` 대기(`1__cfx/main.c:49`). cm3는 `tdc_normal_boot_sequence()`(`2__cm3/main.c:591~604`)에서 `Initialize()` **완료 후에야** `is_enabled_CFX_iteration=1`(`:597`, **유일한 설정 지점**).
- → **`Initialize()` 내부에서 게인 인덱스 기본값·cradle=0을 기록하면 CFX 오디오 루프 시작 전 유효값 보장**. 공유메모리 섹션의 전원 직후 값(제로 미보장 가능성)에 의존하지 않게 됨. index 0(뮤트)이 유효값이라 "0=미설정" 관례를 쓸 수 없는 문제도 함께 해소.

## 5-2. 2차 요구(ISD별 영속화) 분석 — 2026-07-20 추가

조사 위임 결과: [`에이전트-로그/02_설정-영속화-선례.md`](에이전트-로그/02_설정-영속화-선례.md) (+ 세션 직접 확인분).

### 5-2.1 기존 ISD별 사용자 설정 저장 구조

- 파일명 규칙 `/ISD*_USER_SETTING`(`*`는 ISD 번호 1~4로 런타임 치환) — `ci_map.h:66~69`·`:82`·`:86`, 치환 코드 `ci_map.c:23~24`·`:83~84`.
- 읽기/쓰기 = `ci_map_read_user_setting_value(isd_num)` / `ci_map_write_user_setting_value(isd_num)`(`ci_map.c:20`·`:80`) — `ST__CFX_CM3_SharedMemory_userSettingValue` **구조체 통째로** + CRC16-CCITT(AES 없음)로 기록.
- 저장 버퍼는 PRAM3의 전역 맵 이미지 `g_ci_filesystem_ptr_entire_map->map[isd_num-1].user_setting_value`(`ci_filesystem.h:69~71`·`:114`).

### 5-2.2 기존 구조체 확장이 위험한 이유 (핵심 판단)

`userSettingValue`에 게인 2필드를 얹는 방안은 **세 가지 이유로 기각**한다.

| # | 문제 | 근거 |
|---|---|---|
| 기각_1 | **공유메모리 레이아웃 대이동** — `userSettingValue`는 미러 구조체 **중간**에 위치(`shared_memory.h:187`)하므로 필드 추가 시 그 뒤 모든 필드의 오프셋이 밀린다. 1차 구현이 "끝에 append"를 택한 이유와 정면 충돌 | `shared_memory.h:187~218`, `cfx_cm3_sharedMemory.h:204~240` |
| 기각_2 | **기존 저장 파일 무효화** — 파일은 고정 크기(28바이트)로 저장되고 `ci_filesystem_read`는 **크기 불일치 시 실패**한다. 구조체가 36바이트가 되면 기존 파일 전부 읽기 실패 → 볼륨·LED·텔레코일 등 **기존 사용자 설정이 초기화될 위험** | `ci_filesystem.h:69~71`(28바이트 주석), `ci_filesystem.c:822~860`(크기 검사) |
| 기각_3 | **PRAM3 여유 부족 우려** — 전역 맵 이미지는 4048워드로 PRAM3 4096워드의 **98.83%를 이미 사용**(주석 명시). ISD당 2워드 추가 = 8워드로 산술상 들어가지만 여유가 40워드로 줄어 다음 확장을 막는다 | `ci_filesystem.h:86~101` |

> [!IMPORTANT]
> **결론: 게인 전용 파일을 신설한다.** 기존 파일·구조체·공유메모리 레이아웃을 일절 건드리지 않으므로 기각_1~3이 모두 회피된다. 이는 `ci_stim_mute`가 자기 설정을 별도 파일(`STIM_MUTE.TXT`)로 갖는 선례와 동일한 접근이다.

### 5-2.3 참고 템플릿 — `ci_stim_mute` 패턴

- 구조: 매직넘버(begin/end) + 값 + 범위 검증, 무효 시 **기본값으로 재기록**하는 자기수복 방식(`ci_stim_mute.c:4~131`).
- 갱신: 사용자 조작 시점에만 파일 전체 덮어쓰기 + `f_sync`(`ci_stim_mute.c:133~201`).
- **답습하지 말 것**(조사 노드 지적): `FA_OPEN_APPEND` 오용(`:166`), 초기화 실패 반환값 미검사.

### 5-2.4 쓰기 빈도 — 기존 관행이 이미 "즉시 기록"

- 볼륨·LED·텔레코일 변경 시 `changeAudioVolume()` 등이 **매번** `ci_map_write_user_setting_value()`를 호출한다(`cfx_cm3_sharedMemory.c:451`·`481`·`496`·`512`·`527`·`542`).
- 즉 **0x8C Write마다 즉시 기록해도 기존 관행과 동일**하다. 위험_7(플래시 수명)은 신규 위험이 아니라 기존 시스템이 이미 안고 있는 특성이며, 코드베이스에 마모 완화 로직은 없다(조사 노드: 관련 검색 0건).
- 다만 앱 슬라이더 연속 드래그 시나리오는 볼륨 조작과 동일한 부하이므로 **동일 취급**한다. 별도 지연·병합은 도입하지 않는다(과도 설계 회피, 기존 일관성 우선).

### 5-2.5 쓰기 안전성 현황

- 원자적 쓰기(임시파일·rename·이중버퍼) 장치는 코드베이스에 **전무**(조사 노드 검색 0건). 모든 쓰기는 in-place 덮어쓰기.
- 보호는 "사후 감지 후 기본값 복구" 전략 — 게인 파일도 동일하게 매직넘버 + 범위 검증으로 손상을 감지해 기본값으로 떨어뜨린다(요구사항_11 충족).

### 5-2.6 초기화·로드 시점

- `Initialize()` 내 순서: FS 마운트(`initialize.c:261`, 실패 시 fail-fast) → 부트 드라이브 왕복(`:313~316`) → `ci_map_init_map_data_all()`(`:321`) → `ci_fft`·`ci_stim_mute`·`ci_event_log` 초기화(`:326`~`:337`) → ISD 정보 공유메모리 복사(`:344`) → **`tdc_remote_gain_control_init()`(`:347~350`, 1차 구현)** → CFX iteration 개방(`:458`).
- 개별 설정 파일 초기화는 반환값을 검사하지 않는 **fail-soft** 관행(`:321`·`:326`·`:330`·`:334`·`:337`) — 게인도 동일하게 fail-soft로 두고 내부에서 기본값으로 흡수한다.

### 5-2.7 ISD 연결 감지 → 로드 훅 (조사 노드 01)

호출 체인(근거: [`01_ISD별-설정-저장-경로.md §3`](에이전트-로그/01_ISD별-설정-저장-경로.md)):

1. `isd_path_Open()` 상태머신이 내부기 칩 ID를 읽어 등록 슬롯 4개와 대조해 슬롯 번호를 확정(`isd_interface_init_ISD.c:389~397`).
2. 패스키 검증 통과 시 **`changeConnected_isd_num_CFX(isd_id_match_num)`** 호출(`isd_interface_init_ISD.c:675~677`). **매핑(청각사) 모드에서는 로드 없이 번호만 임시 대입**(`:681`).
3. `changeConnected_isd_num_CFX()`(`cfx_cm3_sharedMemory.c:319~351`)가 `if (0 < isd_num)` 블록에서 ISD 정보·사용자 설정·맵 스탬프·맵 4종을 파일에서 읽고(`:337~343`), `fn_copy_userSettingParameters_toCM3()`로 공유메모리에 반영(`:346`)한 뒤 `connected_ISD_num`을 확정(`:350`).

> [!IMPORTANT]
> **로드 훅 = `changeConnected_isd_num_CFX()`의 `if (0 < isd_num)` 블록**(`cfx_cm3_sharedMemory.c:335~347`). 기존 사용자 설정이 로드되는 바로 그 지점이므로 게인도 같은 자리에서 읽으면 **시점 정합이 자동 보장**된다(위험_8 해소). 부팅 1회가 아니라 ISD가 바뀔 때마다 호출되므로 런타임 ISD 교체도 자동 대응된다.

### 5-2.8 저장 훅과 슬롯 판정

- 기존 관행: `change*()` 함수들이 공유메모리 갱신 직후 **`system_opMode == en__normalMode`일 때만** `fn_write_userSettingParameters(connected_ISD_num)`로 즉시 동기 기록(`cfx_cm3_sharedMemory.c:475~483`·`490~498`·`505~514`·`521~529`·`536~544`).
- `normalMode` 가드의 의미: 매핑 모드에서는 슬롯 번호가 임시 대입 상태(`isd_interface_init_ISD.c:681`)라 **엉뚱한 슬롯에 쓸 위험**이 있다. 게인도 동일 가드를 채택한다(위험_9 부분 해소).
- 슬롯 획득은 `read_connected_ISD_Num()`(`cfx_cm3_sharedMemory.c:353~356`). **0이면 미연결**이므로 파일 저장 대상이 없다 → 배열 인덱스 `isd_num - 1`이 음수가 되는 것을 막기 위해 **`1 <= isd_num` 가드 필수**.

### 5-2.9 파일 포맷 제약 — 16바이트 블록 정렬 불변식 (세션 직접 확인)

`ci_filesystem_write_with_crc_and_aes128()`는 AES 사용 여부와 **무관하게** 다음을 강제한다(`ci_filesystem.c:518~524`, 직접 확인):

```
(data_size % 16) + 4 + aes128_padding_size == 16
```

위반 시 파일에 **아무것도 쓰지 않고 즉시 실패 반환**한다. 신규 게인 파일 설계에 그대로 적용하면:

| 후보 데이터 | `%16` | + CRC 4 | 필요 padding | 판정 |
|---|---|---|---|---|
| `int` 2개 = **8바이트** (Gain_A·Gain_B) | 8 | 12 | **4** | ✅ 성립 |
| `int` 3개 = 12바이트 | 12 | 16 | 0 | ✅ 성립(확장 여지) |
| `int` 4개 = 16바이트 | 0 | 4 | 12 | 성립하나 패딩 과다 |

**선례 일치**: 맵 스탬프 파일이 정확히 같은 구성(24바이트 데이터 → `24%16=8`, padding 4, `enable_aes=false`)으로 동작 중이다(`ci_map.c:104`). 게인 파일도 **데이터 8바이트 + CRC 4 + padding 4 = 16바이트**로 두면 검증된 패턴을 그대로 따른다.

### 5-2.10 RAM 버퍼 위치

`ci_filesystem_*_with_crc_and_aes128()`는 데이터·CRC·패딩 포인터를 **인자로 받으므로** 버퍼가 PRAM3 전역 맵(`g_ci_filesystem_ptr_entire_map`)일 필요가 없다. PRAM3는 이미 98.83% 사용 중(`ci_filesystem.h:86~101`)이므로, 게인은 **cm3 SRAM의 static 버퍼**를 쓴다. 이러면 `CI_FILESYSTEM_MAP_T` 레이아웃도 건드리지 않는다.

### 5-2.11 부팅 시 파일 부재 처리

- 기존 4종 파일은 `ci_map_init_map_data_all()`(`initialize.c:321`)이 부팅 시 슬롯 전체를 훑어 없으면 기본값으로 생성한다(`ci_map.c:498~509`).
- 게인은 **별도 부팅 초기화를 두지 않는다**. 연결 시 로드에서 읽기 실패·범위 위반이면 기본값(유니티)을 적용하고 그 자리에서 파일을 생성하면 충분하다(자기수복). 부팅 시점의 `tdc_remote_gain_control_init()`(1차 구현)은 ISD 연결 이전 구간의 기본값 보장 역할로 **그대로 유지**한다.

## 6. 설계 방향 (⑤ 계획으로 이월)

1. **cfx**: `audioMixer.c`에 Q8.16 테이블 + 룩업 게터 + 신규 U4 `tdc_audio_mix_2_buffers_with_gain(p_mic, p_i2s, gain_a, gain_b)`(agc 포화 관행). M6 디스패치에서 공유메모리 읽어 게인 결정, Streaming 시 gain_b=유니티(경로 통일, 비트 정확).
2. **공유메모리**: 양쪽 구조체 끝에 3필드 append(`게인 인덱스 A/B`, `I2S 소스 cradle 플래그`).
3. **cm3**: `Initialize()`에 기본값 기록, 0x36 핸들러에 cradle 플래그 기록, 0x8C enum + 라우팅 else-if + `tdc_remote_gain_control.c/.h` 핸들러(0x8F 파이프라인 미러).
4. U3(`tdc_audio_mix_2_buffers`)는 정의 유지, 라이브 호출부만 U4로 대체 — 유닛-모듈-테스트맵 갱신.
