# Gain Conversion Table 기능 — 분석 (③)

**TL;DR**: 살아있는 I2S 믹싱 호출부는 `main.c:440` 한 곳(`I2S_handle()`은 DEAD). CFX에는 Q8.16 + `long` 누산 + `>>16` + INT24 포화 관행이 agc.c에 이미 확립되어 있어 게인 곱은 동일 패턴으로 구현 가능. cm3 0x8C는 기존 명령 범위와 충돌 없는 빈 값이고, 0x8F(tdc_remote_general_debug) 분리 파일 관행을 그대로 미러링하면 된다. cm3→cfx 전달은 이중 미러 공유메모리 구조체 끝에 3필드 append + `Initialize()`에서 기본값 기록(CFX iteration 개방 전이라 순서 보장).

---

## 1. cfx 오디오 경로 현행 구조

### 1.1 믹싱 유닛 (audioMixer.c)

| 유닛 | 함수 | 역할 | 게인 관련성 |
|---|---|---|---|
| U1 | `tdc_audio_mix_2_buffers_for_beamforming` (`audioMixer.c:99`) | 2-DMIC DAS 빔포밍 | I2S 없음 경로 — **바이패스 유지, 미수정** |
| U2 | `tdc_audio_mix_1_buffer` (`audioMixer.c:17`) | 단일 DMIC | I2S 없음 경로 — **바이패스 유지, 미수정** |
| U3 | `tdc_audio_mix_2_buffers` (`audioMixer.c:30`) | mic + I2S 단순 합산(÷2 없음) | **게인 적용 대상 경로** |

- 공통 규약: 각 입력 `>> AUDIO_INPUT_RSHIFT`(=5, `definitionsForAlgorithm.h:103`) 후 합산, 출력은 `HEAR_ADDR_AUDIO_MIX[16]`.
- 믹스 출력은 `CALL_FUNCTION_CHAIN(HEAR_FC_agc_preprocessing)`(`main.c:486`)로 AGC에 전달 — 요구 다이어그램의 "합산 → AGC" 지점과 일치.

### 1.2 디스패치 (M6, `PCM_LiveStimulation_Mode`, main.c:429~487)

- `I2S_isStreaming()`(`main.c:433`) 분기: 활성 시 `tdc_audio_mix_2_buffers(DMIC1 현재블록, I2S 버퍼)`(`main.c:440`), 비활성 시 DMIC 수·front mic에 따라 U1/U2.
- **U3의 살아있는 호출부는 `main.c:440` 단 한 곳**. `main.c:381`·`:409`의 호출은 `I2S_handle()` 내부인데 이 함수는 DEAD(호출부 없음, `main.c:357~358` 주석 명시). → 게인 적용 지점은 M6 디스패치 1곳만 수정하면 됨.

### 1.3 Q8.16 고정소수점 연산 관행 (agc.c — 그대로 재사용할 패턴)

- Q8.16 상수 테이블 정례: `int chess_storage(XMEM) m_amplify_region_ybias_db_Q8_16[10]`(`agc.c:24`) — 256엔트리 게인 테이블도 동일 형식으로 배치 가능.
- 곱셈 정례: `long_acc = ((long) coeff_Q8_16) * value; long_acc >>= 16;`(`agc.c:127~129`) — CFX `long`(48비트) 누산.
- 샘플에 게인 적용 + 포화 정례: `apply_agc_gain()`(`agc.c:307~336`) — `(long)gain * p_mix[i] >> 12` 후 `INT24_MAX/INT24_MIN` 클램프. INT24 상수는 `definitionsForAlgorithm.h:39~40`(audioMixer.h가 include하는 헤더에서 가용).
- 샘플은 Q24.0(24비트 int) — 클램프 사용으로 확인.

### 1.4 오버플로 여유 (수치 검증)

- 입력: `|sample >> 5|` ≤ 2^18. 게인 최대 512,211(≈2^19). 곱 ≈ 2^37, 두 항 합 ≈ 2^38 — `long`(48비트) 내 안전.
- `>> 16` 후 최대 ≈ 2^22 — INT24 범위(±2^23) 내. 포화는 이론상 거의 미발동이나 방어적으로 유지(agc 관행 동일).
- 유니티 게인(65,536) 곱은 `x * 2^16 >> 16 = x` — **비트 정확**(Streaming 시 I2S 무게인 요구를 게인 경로 통일로 충족 가능).

## 2. cm3 패킷 인프라

### 2.1 0x8C 값 충돌 검사 (전수)

`ble_commonProtocol.h` 기준: 리모컨 0x40~0x5A(`:51~81`), 매핑 0x60~0x72 연속(`:88~110`) + 0x90·0x91(`:111~112`), SND 시스템 0x33~0x36(`:42~45`), GENERAL_DEBUG 0x8F(`:117`), OTA/BOOT 0xC0~0xC3. → **0x8C는 미할당, 충돌 없음**. `ble_communication.c`의 라우팅 분기들(리모컨 `0x40≤x<0x60`, 매핑 `0x60≤x≤0x72`·0x90·0x91, SND `0x33~0x36`, 0x8F 개별 else-if)도 0x8C를 삼키지 않음 — 신규 else-if 필요.

### 2.2 0x8F 선례 (그대로 미러링할 파이프라인)

1. **라우팅**: `ble_communication.c:357~360` `else if (p_Rx_dataPacket[0] == EN__SND_BT_CMD_GENERAL_DEBUG)` → `fetch_remoteControlPacket(p_Rx_dataPacket)`.
2. **복사**: `fetch_remoteControlPacket()`의 `default:` 분기(`remoteControl.c:619~624`)가 헤더→`remoteDataPacket.command`, 페이로드 19워드→`remoteDataPacket.data[]` 복사. → 0x8C 페이로드는 `data[0]=Control type`, `data[1]=Gain type`, `data[2]=index`로 도착.
3. **처리**: `remoteControl()`의 `case EN__SND_BT_CMD_GENERAL_DEBUG`(`remoteControl.c:1345~1352`) → `tx_index = tdc_remote_general_debug_handle(&remoteDataPacket, bufferForSPI_tx, tx_index)` → `writeDataToSpiTxBuff()` → `clearRemoteColtrolCommand()`. 별도 파일 `tdc_remote_general_debug.c/.h` 분리 선례([`ble/20260701_general-debug-protocol-split`](../../ble/20260701_general-debug-protocol-split/)).
4. **응답 인프라**: `bufferForSPI_tx`(지역 int[20])·`tx_index`·`writeDataToSpiTxBuff()` — 0x59 케이스(`remoteControl.c:1360~`)는 5워드 응답 + 공유메모리 직접 읽기/쓰기 선례(`cfx_cm3_sharedMemoryAll.is_enabled_mute_stimulation_under_t_level`, `:1372~1373`).

### 2.3 CLASSIC_STATE(0x36) 핸들러

- `ble_communication.c:198~223`: `classic_state`(0 DISCONN/1 CONN), `classic_type`(0 UNKNOWN/1 CRADLE/2 OTHER) 수신, 현재 로그만 출력. `:216`에 "향후 크래들과 I2S 게인 테이블 적용" 주석 — 이 지점에서 공유메모리 cradle 플래그 기록이 자연스러움.
- 시맨틱: cradle = (`classic_state==1` AND `classic_type==1`). DISCONN이면 0. 0x36 미수신 상태에서 I2S가 노는 경우는 I2S_FLAG 비활성 → 바이패스이므로 플래그 잔존 무해.

## 3. cm3→cfx 공유메모리

### 3.1 구조

- **이중 미러 헤더**: cm3 `cfx_cm3_sharedMemory.h:187~241`(`ST__CFX_CM3_SharedMemory_ALL`) ↔ cfx `environment/shared_memory.h:177~219`. **필드 순서·구성이 바이트 단위로 일치해야 함**(cfx는 IOMEM 0x28000 고정 매핑, `shared_memory.h:223`; cm3는 `.shared_memory` 섹션 → PRAM5, `cfx_cm3_sharedMemory.h:401`).
- **끝에 append가 안전**: 선행 필드 오프셋 불변. 선례: `is_enabled_mute_stimulation_under_t_level`(2026-01-20 append), `is_pcm_specific_command_reading`(2026-02-24 append).

### 3.2 소비 패턴 (cfx)

- 사용자 설정 소비 선례: `system_control.c:193` `m_audio_volume = Addr_SharedMem->userSettingValue.audioVolume - 1`(변경 감지 폴링). 게인은 매 블록 직접 읽기(`Addr_SharedMem->필드`)로 충분 — agc.c도 블록마다 공유메모리 접근(`agc.c:105`).

### 3.3 초기화 순서 보장 (기본값 0 = 뮤트 함정 회피)

- 부팅 핸드셰이크: CFX가 `is_CFX_started=1` 설정(`1__cfx/main.c:47`) 후 `is_enabled_CFX_iteration==1` 대기(`1__cfx/main.c:49`). cm3는 `tdc_normal_boot_sequence()`(`2__cm3/main.c:591~604`)에서 `Initialize()` **완료 후에야** `is_enabled_CFX_iteration=1`(`:597`, **유일한 설정 지점**).
- → **`Initialize()` 내부에서 게인 인덱스 기본값·cradle=0을 기록하면 CFX 오디오 루프 시작 전 유효값 보장**. 공유메모리 섹션의 전원 직후 값(제로 미보장 가능성)에 의존하지 않게 됨. index 0(뮤트)이 유효값이라 "0=미설정" 관례를 쓸 수 없는 문제도 함께 해소.

## 6. 설계 방향 (⑤ 계획으로 이월)

1. **cfx**: `audioMixer.c`에 Q8.16 테이블 + 룩업 게터 + 신규 U4 `tdc_audio_mix_2_buffers_with_gain(p_mic, p_i2s, gain_a, gain_b)`(agc 포화 관행). M6 디스패치에서 공유메모리 읽어 게인 결정, Streaming 시 gain_b=유니티(경로 통일, 비트 정확).
2. **공유메모리**: 양쪽 구조체 끝에 3필드 append(`게인 인덱스 A/B`, `I2S 소스 cradle 플래그`).
3. **cm3**: `Initialize()`에 기본값 기록, 0x36 핸들러에 cradle 플래그 기록, 0x8C enum + 라우팅 else-if + `tdc_remote_gain_control.c/.h` 핸들러(0x8F 파이프라인 미러).
4. U3(`tdc_audio_mix_2_buffers`)는 정의 유지, 라이브 호출부만 U4로 대체 — 유닛-모듈-테스트맵 갱신.
