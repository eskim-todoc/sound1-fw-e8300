- **2026-07-20 (2차 ③④)**: 조사 2노드 산출 수신·로그 저장. **핵심 발견**: ① `ci_filesystem_write_with_crc_and_aes128()`가 `(data%16)+4+padding==16` **정렬 불변식을 강제**(`ci_filesystem.c:518~524`, 세션 직접 확인) — 기존 `userSettingValue`(28B)에 `int` 하나만 더해도 쓰기가 즉시 실패. ② 게다가 미러 구조체 **중간** 필드라 공유메모리 전체 오프셋이 밀리고, 기존 저장 파일이 무효화되어 **사용자 볼륨 설정이 초기화될 위험**. ③ PRAM3 전역 맵은 이미 98.83% 사용. → **게인 전용 파일 신설로 결정**. 로드 훅은 기존 설정이 로드되는 `changeConnected_isd_num_CFX()`(`cfx_cm3_sharedMemory.c:319~351`)로 확정. 조사 인용 전수 재확인, **할루시네이션 0**.
- **2026-07-20 (2차 피드백 반영)**: 은수님 의견 3건 반영 — ① **단일 파일로 전환**(ISD별 4파일이면 4KB×4=16KB 점유, 게인 데이터가 작으니 파일 1개로 전체 슬롯 관리). 구조 `매직(4) + 4슬롯×8 + 매직(4) = 40바이트`, 정렬 `40%16=8, 8+4+4=16` ✅ ② **ISD 미연결 시 앱 접근 자체가 없음**(QCC가 BLE 미활성) → 해당 분기는 이상 상황이므로 Failed 응답 + 방어 가드만 유지 ③ **쓰기 실패 무시 관행은 답습하지 않기로** — 코드베이스에 이미 올바른 선례(`EN__DATA_LOGGING_ERROR` + `errorCodeUpdate()`, "사이버 보안 고려" 주석) 확인, 권고안(write-verify + 1회 재시도 + rsp_code 반영 + 에러코드 기록) 제시하고 승인 대기.
- **2026-07-20 (2차 승인)**: 은수님 결정 — 쓰기 실패는 **반환값으로 바로 판정**(write-verify·재시도 없음), 근거는 "손상되면 다음 회차 읽기에서 드러나고 `Initialize()`에서 자동 초기화됨". **에러 enum 신설 안 함**(리팩터링 준비 중). ⚠️ 이 근거를 코드와 맞추기 위해 **설계 변경**: 직전 계획은 부팅 초기화를 두지 않고 ISD 연결 시에만 자기수복하는 구조였으나, 은수님 인식대로 `Initialize()`에 검사·복구 훅을 추가(결정_9).
