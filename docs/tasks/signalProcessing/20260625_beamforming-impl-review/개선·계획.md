# 개선·후속 계획

**TL;DR**: 구현은 **기능적으로 정확하므로 기능 재작성은 불필요**. 개선은 ① 안정성·정확성(게인 경로 통일·버퍼 가정 명문화·전환 글리치 완화), ② 일관성(HW fractional 재적용·QCC 통화 AND 조건), ③ 코드 품질(데드코드·낡은 주석·믹서 루프화), ④ 검증(전후비 정량) 순. **코드 변경은 본 리뷰 범위 밖** — 항목별 후속 작업·승인 대상.

> [!IMPORTANT]
> 본 작업은 **분석·리뷰**까지. 아래는 변경 권고이며 실제 제품 코드 수정은 별도 4단계·승인이 필요하다.

---

## 0. 총평

- 검증 **refuted 0 / confirmed 3 / uncertain 2** — 빔포밍 방향·지연량·L/R 조향 모두 정확. **하이브리드(SW 1샘플 + HW FRAC=6) 설계는 우리 논의(22mm는 1.026샘플 > 레지스터 최대 0.9958이라 하이브리드 필요)와 정합.**
- critical 3건은 모두 **버퍼 인덱스 가정**이 근원이며 검증 결과 "참" → **버그 아님, fragility(미문서화)**.
- "이론 FRAC=14 ≠ 구현 FRAC=6" 보고는 **오탐**(2cm-all-HW vs 22mm-하이브리드 시나리오 혼동). 구현 FRAC=6이 정답.

> [!NOTE]
> **2026-06-25 은수님 검토 반영**: T1-1 **철회**, T2-1/T2-4 **다운그레이드**, T3-4 **현행 유지로 결론**. 아래 표에 반영.

## 5. 후속 작업 제안

1. **후속_1 (Tier 1)**: 게인 경로 통일 + 버퍼 가정 명문화 + 전환 mute — 별도 task, 4단계·승인.
2. **후속_2 (Tier 2)**: fractional 재적용·QCC AND 조건·웜업.
3. **후속_3 (Tier 3)**: 코드 정리(데드코드·주석·루프화) — 단순 수정 묶음.
4. **후속_4 (Tier 4)**: 전후비 정량 측정(벤치) — 문서/시험방법.

## 6. 한 줄 결론

> **구현은 우리 논의를 충실히 반영해 기능적으로 정확하다. 재작성 불필요.** 은수님 검토로 게인 경로(T1-1)·fractional 재적용(T2-1/T2-4)·저장 시 시프트(T3-4)는 **현 설계가 타당함이 확인**되어 철회·다운그레이드됨. 잔존 가치 항목은 **① 버퍼 인덱스 가정 한 줄 주석(미래 보험), ② 전환 글리치 mute(전환 클릭/null 붕괴 방지), ③ 전후비 정량 측정(설계 효과 확인)** 정도이며, 모두 현 동작에는 문제 없어 점진 반영 가능하다.
