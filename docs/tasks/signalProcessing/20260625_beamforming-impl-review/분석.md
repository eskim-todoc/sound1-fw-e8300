# 구현 분석 종합 (12 페르소나)

**TL;DR**: 은수님 구현은 **기능적으로 정확**하다 — 동일 패리티(ch0/ch2)·SEL 엣지 정합·하이브리드 지연(SW 1샘플+HW FRAC=6=1.025샘플, 22mm 이상값 1.026과 오차 0.08µs)·L/R 재조향·QCC 폴백 모두 코드로 검증됨. 다만 **암묵적 가정(버퍼 인덱스 0=최신)이 load-bearing인데 미문서화**(critical 3건은 전부 이 가정의 "확인됐으나 무근거" 성격), **게인 경로 비일관(빔포밍 ÷2 vs I2S 경로 비÷2 → +6dB)**, **런타임 전환 글리치(mute 부재)**, **데드코드·낡은 주석**이 개선 대상.

> [!NOTE]
> 페르소나 원본: [`에이전트-로그/인덱스.md`](에이전트-로그/인덱스.md) 01~12. 사실: [`조사_구현-그라운딩.md`](조사_구현-그라운딩.md).

## 1. 정확성 — 핵심은 모두 맞음 ✅

| 항목 | 판정 | 근거 |
|---|---|---|
| 채널 패리티 ch0/ch2(짝수) → 스큐 0 | ✅ | `lib_audio_in.h:89` 활성 매크로 |
| SEL↔엣지 (U7 GND↔RE, U9 VDD↔FE) | ✅ | 회로도 확인 + `lib_audio_in.c:152` |
| IOC IN0→FA0_0, IN2→FA0_1 | ✅ | `lib_audio_in.h:58`, `main.c:333/346` |
| 하이브리드 지연 = 1.025샘플 | ✅ | SW 1(믹서 i+1) + HW FRAC=6(0.025) |
| L/R 재조향 (front mic 지연) | ✅ | `main.c` LEFT→dmic2·RIGHT→dmic1 지연 |
| 지연 방향 (front mic이 실제 지연) | ✅ | 버퍼 0=최신 + i+1=older = 1샘플 지연 |

## 2. 지연 분해 정밀 (지연 분해 분석가)

- SW 1.000 + HW 0.025 = **1.025샘플 = 64.06µs**. 22mm/343 = 64.14µs = 1.0262샘플. **오차 0.0012샘플(0.077µs, 공간 0.027mm)** — 사실상 최적점.
- 실온 20°C(c=343.21) 기준 타깃 1.0256 → 오차 0.0006샘플(38ns). FRAC 1스텝 = 1/240샘플 = 0.089mm 해상도.
- 체온(37°C, c=353) 타깃은 0.997샘플 → 현재 1.025는 +0.028샘플 과지연이나, 2-mic 22mm 지향성(수 dB)에선 주 열화 요인 아님. 필요 시 FRAC=5로 온도 보정 여지.

## 3. 이론 정합 — "FRAC=14 vs FRAC=6"는 오탐 (중요 정정)

> [!IMPORTANT]
> 한 페르소나가 "이론 FRAC=14 ≠ 구현 FRAC=6"를 major 이탈로 보고했으나 **시나리오 혼동에 의한 오탐**이다.
> - **FRAC=14(0.058샘플)**: 2cm·**all-HW**(INT=7+FRAC=14=0.933샘플) 시나리오 값.
> - **FRAC=6(0.025샘플)**: 22mm·**하이브리드**(SW 1.0 + HW 0.025 = 1.025) 시나리오 값.
> 구현은 22mm 하이브리드를 채택했으므로 **FRAC=6이 정답**. 두 값은 다른 설계점이며 모순 아님. → 구현 정합.

## 4. 데이터흐름 — load-bearing 가정 (버퍼·믹서 분석가)

- 버퍼: `[mic][0]`=최신 블록, `[1]`=직전 (`tdc_copy_DMIC_buffers` 시프트 후 신규 저장으로 확정).
- 블록 내 **index 0=최신 … 15=오래됨** — 믹서 경계 `p_mix[15]=delay_buf1[0]`이 시간 연속이려면 이 순서여야 하고, 버퍼 채움 로직과 정합하므로 **참**(검증 confirmed).
- i+1 오프셋 = 1샘플 older = **지연 채널 1샘플 지연** → 방향 정확.
- **그러나** 이 인덱스 순서를 코드에 명시한 주석/assert가 **전무** → FIFO 읽기 순서를 바꾸면 빔포밍이 조용히 역전/붕괴(critical 3건의 실체 = "맞지만 무방비").

## 5. 게인 스테이징 (게인 분석가) — 경로 비일관

- 빔포밍 믹서: `(no_delay[i] + delay[i+1]) >> 1` → 상관(front) +6dB를 ÷2 = **0dB**(단일 마이크와 정합) ✓.
- 그러나 **I2S 경로 `audio_mix_2_buffers`는 `>>1` 제거**(의도적 주석) → 동일 2-입력 합산인데 +6dB(상관)/+3dB(비상관). → **I2S↔비-I2S 전환 시 최대 +6dB 불연속**, AGC 입력 기준 레벨이 경로별로 달라짐(major).
- `>>5 후 합산 후 >>1`은 양자화를 2회 truncate — 합산 후 1회 시프트로 줄일 여지(오버플로 확인 전제).

## 6. 런타임 전환·글리치 (글리치 분석가)

- 맵변경 시 `SYS_SET_ADC_DEC_CTRL`(fractional) **live 변경 → 위상 점프** → 전환 직후 1~수 블록 빔 null 붕괴.
- `enable_1/2_DMIC`의 **DIO10 클럭 토글** → 클럭 on/off 순간 글리치.
- **mute 절차 부재**(DAC auto-mute만 의존) → 클릭 가능. 권장 순서: ADC mute → 클럭 전환 → FIFO clear → DEC_CTRL write → 안정화 → unmute.

## 7. 초기화·적용 시점 (초기화 분석가)

- HW fractional은 **맵변경 switch에서만** 설정. `configure_audio_path_all` init은 ch0/ch2 모두 delay 0.
- `normal_loop`의 I2S↔2-DMIC 전환(`enable_2_DMICs`)은 **fractional 재적용 없음** → I2S 복귀 후 다음 맵변경 전까지 fractional 0(−0.025샘플, 효과는 미미하나 일관성 결함).
- soft wake 경로 활성화 시 stale `s_lib_audio_front_mic` 위험 → init에서 NONE 명시 권고.

## 8. QCC 공유 (QCC 분석가)

- I2S_FLAG로 통화 시 1-DMIC 폴백은 동작하나, **QCC 통화 종료↔FLAG 해제 타이밍 결합이 코드로 미검증** → FLAG 늦게 해제되면 DMIC2 클럭 경합 가능(major). 공유메모리 통화 상태 플래그 AND 조건 권고.
- `enable_2_DMICs` 직후 DMIC2 웜업 전 빔포밍 진입 가능 → 워밍업 중간 상태(N프레임 대기) 권고.

## 9. 성능·지향성 (성능 분석가)

- 2-mic 22mm delay-and-sum 지향성은 **이론상 수 dB(전후비)** 수준 — 구현 문제 아닌 배열 한계.
- white-noise L/R 음량차 관측은 **동작 방증**이나 정량 아님 → 전후비/DI를 **정면·후면 음원 SPL 비교**로 측정 권고.

## 10. 코드 품질 (코드 분석가)

- 데드 매크로 `LIB_ADC_DEC_CTRL_VAL_0_9958`(미사용), 믹서 **16줄 하드코딩 + 매직 i+1**, 버퍼 순서 가정 무주석, 낡은 주석 2건(`lib_audio_in.h:55` IN1→IN0, `main.c:88` ADC1/DMIC1→ADC2/DMIC2), `LIB_AUDIO_IN_BUF_MAX_CNT=2` 다중 의존.
