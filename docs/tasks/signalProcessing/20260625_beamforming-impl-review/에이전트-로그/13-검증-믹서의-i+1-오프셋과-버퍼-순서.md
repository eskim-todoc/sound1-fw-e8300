# [검증 13] 믹서의 i+1 오프셋과 버퍼 순서(index0=최신) 가정 하에서, 지연 채널(=front mic)이 실제로 1샘플 지연되어 forward 빔이 형성된다

**판정**: `CONFIRMED`

## 근거
세 가지 독립 근거가 모두 주장을 지지한다.

1. 블록 인덱스 순서 — tdc_copy_DMIC_buffers(main.c:321-348)에서 `[mic][1][i] = [mic][0][i]` 후 `[mic][0][i] = FIFO[i]`로 확정: 블록 인덱스 0=최신, 1=직전.

2. 샘플 인덱스 순서(index 0=최신) — 블록 경계 처리(audioMixer.c:74)가 유일한 내부 근거. `i=14`에서 `delay_buf0[15]`(현재 블록 oldest), `i=15`에서 `delay_buf1[0]`(직전 블록 newest)을 사용한다. index 0=oldest(표준 FIFO 순서)라면 이 두 샘플 간격은 16샘플 이상의 시간 불연속(gap)이 되어 빔포밍 지연이 붕괴된다. index 0=newest라면 `delay_buf0[15]`와 `delay_buf1[0]`이 시간상 인접(1샘플 간격)하여 경계가 완벽히 연속된다. 경계 처리 로직은 index 0=newest일 때만 의미 있으므로, 이 가정이 코드 설계 의도로 확정된다.

3. 지연 방향과 빔 형성 — index 0=newest 하에서 `delay_buf0[i+1]`은 출력 위치 i에서 no_delay[i]보다 1샘플 더 오래된(earlier in time) 데이터를 참조한다. 즉 delay 채널의 기여는 no_delay 채널 대비 1샘플 시간상 뒤처진(retarded) 상태로 합산된다. front mic 신호는 22mm 거리만큼 먼저 도달하므로 1.025샘플(SW 1샘플 + HW FRAC=6, 합계 64.06µs)만큼 지연시켜 rear mic 도달 시각에 정렬하면 forward end-fire 방향에서 건설적 합산이 발생한다. 수치 오차는 22mm 이상값 1.0262샘플 대비 0.0012샘플(0.08µs)로 무시 가능 수준이다.

미결 한계: 샘플 인덱스 순서는 HW 데이터시트(Ezairo8300 FIFO 충전 방향) 직접 인용이 아닌 코드 내부 정합성으로만 검증됨. RTT 덤프 또는 HW 레퍼런스 매뉴얼으로 외부 검증 권고.
