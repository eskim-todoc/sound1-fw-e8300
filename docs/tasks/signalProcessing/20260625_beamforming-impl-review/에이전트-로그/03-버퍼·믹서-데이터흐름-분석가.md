# [분석 03] 버퍼·믹서 데이터흐름 분석가

**신뢰도**: high

## 결론
audioMixer.c의 i+1 오프셋은 FIFO 인덱스 순서(0=최신 vs 0=오래됨)가 확정되어야만 지연 방향이 검증된다. 블록 경계 delay_buf1[0]의 시간 연속성도 동일 전제에 의존하며, 인덱스 0=최신 가정이 참이면 연속·정합, 거짓이면 중복(gap) 위험이 발생한다. 현재 코드 내에 DMIC FIFO 인덱스 방향을 직접 명시하는 근거가 없어 이 가정의 검증이 전체 분석의 핵심 미결 항목이다.

## 발견(severity·근거)
- **[info]** tdc_copy_DMIC_buffers의 버퍼 롤링 방향은 [0]=최신, [1]=직전임이 코드로 확인된다
  - 근거: main.c L327~333: 내부 루프 j=0 (BUF_MAX_CNT-1=1일 때) → g_lib_dmic_in_buffers[0][1][i] = g_lib_dmic_in_buffers[0][0][i] 먼저 실행, 그 다음 L333: g_lib_dmic_in_buffers[0][0][i] = HCT_A0_0[i]. 즉 [block=0] = 신규 FIFO, [block=1] = 이전 블록. LIB_AUDIO_IN_BUF_MAX_CNT=2 (lib_audio_in.h L31). 블록 축 방향은 [0]=최신/현재, [1]=직전/과거로 확정.
- **[info]** 믹서 호출 시 p_delay_buf0=현재블록, p_delay_buf1=직전블록 인수가 정합하게 전달된다
  - 근거: main.c L454 (LEFT 분기): audio_mix_2_buffers_for_beamforming(g_lib_dmic_in_buffers[1][LIB_AUDIO_IN_BUF_MAX_CNT-2][0], g_lib_dmic_in_buffers[1][LIB_AUDIO_IN_BUF_MAX_CNT-1][0], g_lib_dmic_in_buffers[0][0][0]). LIB_AUDIO_IN_BUF_MAX_CNT=2이므로 BUF_MAX_CNT-2=0(현재블록), BUF_MAX_CNT-1=1(직전블록). 함수 시그니처(audioMixer.h L26)의 p_delay_buf0=현재, p_delay_buf1=직전 의미와 일치. RIGHT 분기(L461)도 동일 패턴.
- **[major]** i+1 오프셋의 지연 방향(1샘플 지연 여부)은 FIFO 블록 내 인덱스 순서에 완전 의존하며, 현재 코드에 DMIC FIFO의 인덱스 방향을 직접 명시한 근거가 없다
  - 근거: audioMixer.c L59: p_mix[0] = no_delay[0] + delay_buf0[1]. 이것이 1샘플 지연이 되려면 delay_buf0[1]이 delay_buf0[0]보다 1샘플 오래된 것이어야 한다. 즉 블록 내 [0]=최신...[15]=가장 오래됨 순서여야 한다. 그러나 lib_audio_in.c L13~17의 버퍼 인덱스 주석('buffer0 / [0:15] : 16 samples')은 방향을 기재하지 않는다. configure_audio_path_all(L106~156)이나 tdc_copy_DMIC_buffers도 블록 내부 인덱스 방향을 명시하지 않는다. 확정을 위해서는 Ezairo8300 FIFO HW 문서 또는 오실로스코프 측정이 필요하다.
- **[critical]** 인덱스 0=최신 가정이 참이면 i+1 오프셋은 지연 채널을 1샘플 늦게(오래된 샘플 방향으로) 읽어 지연 효과가 맞으나, 가정이 거짓(0=오래됨)이면 오프셋이 역방향이 되어 지연이 아니라 반대로 미래 샘플을 읽는 형태가 된다
  - 근거: audioMixer.c L59~73: p_mix[i] = no_delay[i] + delay_buf0[i+1]. [0]=최신이면 [i+1]은 [i]보다 1샘플 오래됨 → delay_buf에서 1샘플 과거를 참조 → 지연 성립. [0]=오래됨이면 [i+1]은 [i]보다 1샘플 최신 → delay_buf에서 1샘플 미래를 참조 → 지연 반전(빔포밍 방향 180도 오류). 그라운딩 데이터 내에서 방향 확정 불가.
- **[critical]** 블록 경계 p_mix[15]=delay_buf1[0]의 시간 연속성은 인덱스 0=최신 가정이 참일 때만 성립하며, 그 경우 갭·중복 없이 연속이다
  - 근거: audioMixer.c L73~74: p_mix[14] = no_delay[14] + delay_buf0[15], p_mix[15] = no_delay[15] + delay_buf1[0]. [0]=최신 가정: delay_buf0[15]는 현재 블록에서 가장 오래된 샘플(t-15), delay_buf1[0]은 직전 블록에서 가장 최신 샘플(t-16). t-16과 t-15는 인접하여 연속. 반면 [0]=오래됨 가정: delay_buf0[15]는 현재 블록 가장 최신(t-1), delay_buf1[0]은 직전 블록 가장 오래됨(t-32). t-32 → t-1 경계는 16샘플 불연속(갭 또는 중복) 발생.
- **[minor]** HW fractional delay(0.025샘플)는 맵변경 이벤트(Normal_PowerMode_event_mapChange)에서만 설정되며, init(configure_audio_path_all)에서는 두 채널 모두 delay=0으로 초기화된다
  - 근거: lib_audio_in.c L141~142: configure_audio_path_all 내 SYS_SET_ADC_DEC_CTRL(AUDIO, 0, LIB_ADC_DEC_CTRL_VAL) / SYS_SET_ADC_DEC_CTRL(AUDIO, 2, LIB_ADC_DEC_CTRL_VAL) — 두 채널 모두 LIB_ADC_DEC_CTRL_VAL(fractional=0). system_control.c L87~94: mapChange 이벤트에서만 Left_Ear→ch2에 _0_0250, Right_Ear→ch0에 _0_0250 설정. 따라서 ISD가 연결되기 전 또는 맵변경 이벤트 발생 전 상태에서는 HW fractional delay가 0이며, 빔포밍 지연은 SW 1샘플만 작동한다.
- **[info]** LIB_ADC_DEC_CTRL_VAL_0_9958(INT=7/FRAC=29)은 정의만 있고 어느 호출 지점에서도 사용되지 않는 데드코드다
  - 근거: lib_audio_in.h L110: LIB_ADC_DEC_CTRL_VAL_0_9958 정의. 코드 내 grep 결과 해당 매크로를 SYS_SET_ADC_DEC_CTRL에 전달하는 호출 없음. system_control.c L87~99에서 사용되는 매크로는 LIB_ADC_DEC_CTRL_VAL 및 LIB_ADC_DEC_CTRL_VAL_0_0250 뿐.
- **[info]** FIFO 블록 내 인덱스 방향을 간접적으로 시사하는 코드 단서가 존재하지만 DMIC FIFO에 직접 적용할 수 없다
  - 근거: main.c L368: I2S 버퍼 디버그 출력에서 p_buffer[15-i] 역순 읽기. 이는 I2S 버퍼(lib_g_i2s_buffers)가 [0]=오래됨, [15]=최신 순서이거나, 출력 목적으로 역순 정렬한 것임을 시사. 그러나 이 버퍼는 DMIC FIFO(HCT_A0_0/HCT_A0_1)와 별개이며, DMIC FIFO의 인덱스 방향에 대한 직접 근거가 되지 않는다.

## 개선 제안
- FIFO 블록 내 인덱스 방향 확정: Ezairo8300 HW 레퍼런스 매뉴얼에서 FIFO 출력 순서(index 0 = oldest vs newest)를 확인하거나, RTT 디버그 로그로 오디오 임펄스 입력 시 HCT_A0_0[0]과 HCT_A0_0[15] 중 어느 쪽에 먼저 나타나는지 측정. 이것이 전체 빔포밍 지연 방향의 전제 조건이므로 최우선 검증 항목.
- lib_audio_in.c 또는 audioMixer.c에 블록 내 인덱스 순서 주석 명시: '// index 0 = newest sample (captured last in this block), index 15 = oldest' 형태로 추가하여 이후 유지보수 시 방향 혼동 방지.
- LIB_ADC_DEC_CTRL_VAL_0_9958 제거 또는 TODO 주석 처리: lib_audio_in.h L110의 데드 매크로는 혼란 유발. 22mm 지연(1.026샘플)에 대한 INT+FRAC 하이브리드 구현 계획이 있다면 관련 TODO로 전환, 없으면 삭제.
- HW fractional delay의 초기화 시점 보완 검토: configure_audio_path_all에서는 delay=0으로 시작하므로, ISD 미연결 상태로 2-DMIC 빔포밍이 시작될 경우 SW 1샘플만 작동. 이 동작이 의도적이라면 주석으로 명시, 의도적이지 않다면 초기값에도 front_mic 상태 기반 fractional 설정 적용 필요.
- audio_mix_2_buffers_for_beamforming의 16줄 언롤 하드코딩을 루프로 전환하고 블록 경계 처리(i==15 분기)를 한 지점에서 관리: 현재 audioMixer.c L59~74의 구조는 경계 조건이 마지막 1줄로 분리되어 있어 블록 크기(16) 변경 시 취약. df_inputADC_DataBuffLength 상수 기반 루프 + 경계 조건 명시가 유지보수에 유리.
