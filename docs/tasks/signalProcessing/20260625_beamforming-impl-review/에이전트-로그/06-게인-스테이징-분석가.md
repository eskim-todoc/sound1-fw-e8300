# [분석 06] 게인 스테이징 분석가

**신뢰도**: high

## 결론
audioMixer.c의 >>5(AUDIO_INPUT_RSHIFT) 후 합산 구조에서 네 가지 핵심 게인 스테이징 특성을 파일·라인 근거로 도출했다. 빔포밍 경로(>>1 있음)와 I2S 경로(>>1 없음)의 절대 레벨 불일치, 1mic↔2mic 전환 시 잠재적 음량 불연속, 그리고 개별 >>5 2회 적용에 의한 양자화 손실 중복이 핵심 발견이다.

## 발견(severity·근거)
- **[info]** 빔포밍 경로 >>1은 상관(정면) 신호 진폭을 보존하고 비상관 잡음을 -3dB 억제한다 (SNR +3dB)
  - 근거: audioMixer.c:59-74. p_mix[i] = (no_delay[i]>>5 + delay_buf0[i+1]>>5) >> 1. 두 채널이 동위상 상관 신호이면 합 = 2A → >>1 = A (진폭 불변, 0dB). 비상관 잡음 σ는 RMS 합산 sqrt(2)σ → >>1 = σ/sqrt(2) = -3dB. 결과적으로 SNR이 +3dB 향상된다. >>1은 클리핑 방지가 1차 목적이나 통계적 SNR 개선 효과를 동반한다.
- **[major]** I2S 경로(audio_mix_2_buffers)는 >>1이 의도적으로 제거되어 있어 단일 마이크 대비 상관 신호 +6dB, 비상관 신호 +3dB 출력 레벨 차이가 발생한다
  - 근거: audioMixer.c:51. p_mix[i] = ((p_buf1[i] >> AUDIO_INPUT_RSHIFT) + (p_buf2[i] >> AUDIO_INPUT_RSHIFT)); // >> 1; 주석으로 halvning이 의도적으로 비활성화됨. 두 채널 동등 상관 신호 기준 진폭 2배 = +6dB. 비상관 RMS 기준 sqrt(2)배 = +3dB. audio_mix_1_buffer(audioMixer.c:39)는 단순 >>5 단일 채널이므로 I2S 경로와 절대 레벨 불일치가 구조적으로 존재한다.
- **[major]** 1mic(NONE/I2S) ↔ 2mic(빔포밍) 전환 시 이상적 상관 음원 기준은 0dB 연속이나, I2S↔비-I2S 전환은 최대 +6dB 불연속이 발생할 수 있다
  - 근거: main.c:440-443(1mic → audio_mix_1_buffer, 출력 A), main.c:454-461(2mic → audio_mix_2_buffers_for_beamforming, 상관 음원 출력 ≈ A). 순수 mic 1↔2 전환은 이상적으로 0dB 연속. 그러나 I2S 스트리밍 분기(main.c:423 audio_mix_2_buffers, 비-halving)는 진폭 2A를 출력하므로 I2S 활성→비활성 전환 시 최대 6dB 음량 급변 가능. normal_loop(main.c:171-192)에서 enable_1_DMIC()/enable_2_DMICs() 전환은 즉각적이며 페이드 처리 없음.
- **[minor]** >>5 양자화는 합산 전 각 채널에 독립 적용되어 2회 손실이 발생한다; 합산 후 단일 >>5 적용 시보다 SNR 이론상 최대 ~0.5dB 열화가 있다
  - 근거: audioMixer.c:59-74. (no_delay[i]>>5) + (delay_buf0[i+1]>>5) 순서로 각 채널 독립 truncation 후 합산. 합산 전 각 >>5의 최대 truncation 오차는 31(2^5-1 LSB). 2회 독립 truncation의 오차 분산은 2배 → RMS 오차 sqrt(2)배. 합산 후 >>5 1회 적용이라면 오차 분산 1회. 실용 SNR 차이는 약 0.5dB 이내로 minor하나, 구조적 비최적성은 사실이다. 단, 이 플랫폼 AUDIO_INPUT_RSHIFT=5는 lib_audio_in.h:107에서 LIB_ADC_DEC_CTRL_VAL 게인 인자 1092와 함께 설계된 값이므로 변경 시 클리핑 위험 검토 필요.
- **[info]** 버퍼 인덱스 [mic][0]=최신, [mic][1]=직전 가정이 코드로 검증되었으며, 빔포밍 SW 1샘플 지연 구현이 정확하다
  - 근거: main.c:324-347 tdc_copy_DMIC_buffers: j 루프에서 [0][1]←[0][0] shift 후 [0][0]←FIFO 신규 할당. LIB_AUDIO_IN_BUF_MAX_CNT=2(lib_audio_in.h:31). PCM_LiveStimulation_Mode(main.c:454): delay_buf0=[1][LIB_AUDIO_IN_BUF_MAX_CNT-2]=[1][0](최신), delay_buf1=[1][1](직전). audioMixer.c:59: delay_buf0[i+1] = 최신 블록의 i+1번째 = 1샘플 오래된 데이터 → SW 1샘플 지연 ✓. 블록 경계 처리(audioMixer.c:74): delay_buf1[0] = 직전 블록의 index 0 = 이전 블록의 최신 샘플로 연속성 유지.
- **[major]** audio_mix_2_buffers의 >>1 비활성화 주석은 의도를 기록했으나, AGC 입력 레벨 기준이 경로별로 달라지는 부작용이 구조적으로 잠재한다
  - 근거: audioMixer.c:50-51 주석: '두 값을 믹싱 했으므로 반으로 줄여준다. -> 반으로 줄이지 않음'. I2S 경로는 합산 레벨 그대로 AGC(main.c:474 CALL_FUNCTION_CHAIN(HEAR_FC_agc_preprocessing))에 진입. 빔포밍 경로는 >>1 후 AGC 진입. 동일한 입력 음압이라도 경로에 따라 AGC 입력 레벨이 최대 6dB 달라지므로 AGC 응답 특성(attack/release 게인 m_prev_agc_10db_gain_Q8_16, system_control.c:263)이 경로 전환 시 transient를 유발할 수 있다.

## 개선 제안
- I2S 경로(audio_mix_2_buffers)에 >>1을 복원하거나, 대신 AGC 기준 레벨을 경로별로 오프셋 보정하여 경로 간 레벨 불일치를 해소할 것 (audioMixer.c:51)
- 1mic↔2mic 전환(enable_1_DMIC/enable_2_DMICs) 시 짧은 페이드 인/아웃(예: 16샘플 램프)을 삽입하여 +6dB 급변을 억제할 것 (main.c:171-192 분기)
- 양자화 순서를 (no_delay[i] + delay_buf0[i+1]) >> AUDIO_INPUT_RSHIFT >> 1 로 변경하면 truncation을 1회로 줄일 수 있으나, 중간 합산 시 오버플로우 여부를 워드 폭으로 사전 검증할 것 (audioMixer.c:59-74)
- LIB_AUDIO_IN_BUF_MAX_CNT=2 하드코딩이 tdc_copy_DMIC_buffers의 일반 루프와 PCM_LiveStimulation_Mode의 [BUF_MAX_CNT-2]/[BUF_MAX_CNT-1] 인덱스에 모두 의존하므로, 이 값을 변경할 경우 빔포밍 SW 지연 샘플 수가 암묵적으로 변한다. 상수 변경 시 audioMixer.c의 지연 인덱스를 함께 검토할 것
