# [분석 11] 초기화·적용시점 분석가

**신뢰도**: high

## 결론
HW fractional delay(0.025샘플)는 `Normal_PowerMode_event_mapChange()` 내 switch 블록에서만 `SYS_SET_ADC_DEC_CTRL`로 기록되고, `configure_audio_path_all()`(normal_init에서 호출)은 ch0·ch2 모두 delay=0으로 초기화한다. 전체 전원 전환 경로(ULP)는 풀 칩 리셋으로 C 전역 변수까지 재초기화되므로 실제 운용에서 HW frac 탈동기 창은 존재하지 않는다. 맵변경 전/직후 구간은 `fn_PcmBitStream_Mode_NopStandby()`가 HW frac 레지스터 기록 이전에 출력을 뮤트하고, `tdc_copy_DMIC_buffers` → `LB_Normal_PowerMode` 순서로 인해 HW frac 변경 효과는 다음 블록(1ms 후)부터 반영되나, 그 1ms 역시 NopStandby 창 내부에 있어 가청 아티팩트가 없다. 단, 소프트 standby/wake 경로(CM3_1_ISR)가 활성화될 경우 `s_lib_audio_front_mic` 상태는 stale한 LEFT/RIGHT로 잔존하면서 HW frac는 0으로 리셋되는 불일치가 발생할 수 있는 잠재 결함이 있다.

## 발견(severity·근거)
- **[info]** init(configure_audio_path_all)은 ch0·ch2를 delay=0으로 초기화하며, s_lib_audio_front_mic는 NONE으로 C 전역 초기화된다. 따라서 부팅 직후 ~ 첫 mapChange 전 구간은 front_mic==NONE 분기가 audio_mix_1_buffer를 호출하여 빔포밍이 실행되지 않는다.
  - 근거: lib_audio_in.c:8 `volatile int s_lib_audio_front_mic = LIB_AUDIO_FRONT_MIC_NONE;`, lib_audio_in.c:141-142 `SYS_SET_ADC_DEC_CTRL(AUDIO, 0/2, LIB_ADC_DEC_CTRL_VAL)` (FRAC=0), main.c:89 `configure_audio_path_all()`, main.c:467 `audio_mix_1_buffer` (NONE 분기)
- **[info]** 맵변경 스위치(Left/Right/default) 내에서 lib_audio_set_front_mic()와 SYS_SET_ADC_DEC_CTRL(_0_0250)이 동일 case 블록에서 연속 기록된다. SW front_mic 상태와 HW frac는 항상 동기 갱신되어 split-update 레이스가 없다.
  - 근거: system_control.c:85-102: Left_Ear case에서 lib_audio_set_front_mic(LEFT) + SYS_SET_ADC_DEC_CTRL(ch2, _0_0250) 연속 실행; Right_Ear case에서 lib_audio_set_front_mic(RIGHT) + SYS_SET_ADC_DEC_CTRL(ch0, _0_0250) 연속 실행
- **[info]** 맵변경 직전 fn_PcmBitStream_Mode_NopStandby()가 PCM 출력을 뮤트한다. HW frac 레지스터 변경 효과는 1블록(1ms) 뒤 FIFO에 반영되나, 그 동안 PCM 모드가 NopStandby이므로 빔포밍 출력이 자극으로 전달되지 않는다.
  - 근거: system_control.c:65 `fn_PcmBitStream_Mode_NopStandby()` → lines 70-100 enable DMIC + switch(HW frac write); main.c:209 `tdc_copy_DMIC_buffers()` → 210 `LB_Normal_PowerMode()` 순서(버퍼 복사 후 mapChange 처리)로 인해 frac 변경은 N+1번째 블록부터 유효
- **[info]** Mapping Live 모드(mapNum<0) 분기에서는 enable_1_DMIC()만 호출되고 front_mic·HW frac 기록이 없다. 이전 맵변경에서 설정된 front_mic(LEFT/RIGHT) 값이 잔존하지만, s_enabled_dmic_cnt==1이므로 PCM_LiveStimulation_Mode가 audio_mix_1_buffer 경로를 타 빔포밍이 호출되지 않는다.
  - 근거: system_control.c:106-114 else 분기: `copy_MappingData_without_mappingDate()` + `enable_1_DMIC()` only; main.c:440 `if(get_enabled_DMIC_count()==1)` → audio_mix_1_buffer
- **[info]** I2S 스트리밍 활성 → 비활성 전환 시 normal_loop에서 enable_2_DMICs()가 호출되어 s_enabled_dmic_cnt=2로 복원된다. 이 시점 HW frac와 front_mic는 마지막 mapChange 값이 레지스터/변수에 그대로 유지되어 올바른 상태로 빔포밍이 재개된다.
  - 근거: main.c:189-192: `if((!I2S_isStreaming()) && (get_enabled_DMIC_count()==1)) enable_2_DMICs()`; HW frac 레지스터는 configure_audio_path_all 이후 mapChange에서만 덮어쓰며, I2S 전환 시 재초기화되지 않음
- **[minor]** 소프트 standby/wake 경로(CFX standby() → CM3_1_ISR 웨이크업)가 활성화될 경우, normal_init()의 configure_audio_path_all()이 HW frac를 0으로 리셋하지만 s_lib_audio_front_mic는 NONE으로 재초기화되지 않아 stale LEFT/RIGHT가 잔존한다. s_enabled_dmic_cnt는 normal_init의 enable_2_DMICs()로 2가 되어, 다음 mapChange 전까지 front_mic=LEFT·HW frac=0 상태로 빔포밍이 실행된다(SW 1샘플 지연만 유효, HW 0.025샘플 누락).
  - 근거: lib_audio_in.c:8 초기화는 C startup에만 실행; normal_init(main.c:69-115)에서 configure_audio_path_all() 호출 후 s_lib_audio_front_mic 재설정 없음; main.c:97 enable_2_DMICs()로 s_enabled_dmic_cnt=2 확정; 현재 CM3 코드(initialize.c:143 `//NVIC_EnableIRQ(CFX_1_IRQn)` 주석처리)로 이 경로는 비활성 상태
- **[info]** ULP(진짜 절전) 복귀는 SYS_WATCHDOG_RESET() 풀 칩 리셋으로 처리되므로 C 전역 변수와 HW 레지스터가 모두 재초기화되고, 이후 반드시 mapChange가 발생하여 HW frac를 재설정한다. 전원/모드 전환의 실질적 운용 경로에서 HW frac 누락 구간은 없다.
  - 근거: CM3 main.c:984-990: `if(touch_cnt >= TDC_TOUCH_ULP_REBOOT_TOUCH_CNT) SYS_WATCHDOG_RESET()`; func_sleep 이후 ULP loop에서 복귀 경로가 watchdog reset 뿐; CM3 main.c:366: `cfx_cm3_sharedMemoryAll.is_enabled_CFX_iteration = 1` — 부팅 초기화 구문에만 존재
- **[info]** audioMixer.c의 블록 경계 처리(p_mix[15] = no_delay[15] + delay_buf1[0])가 올바르다. tdc_copy_DMIC_buffers의 버퍼 시프트 구조상 buf[0]=최신 블록·buf[1]=1블록 이전이며, delay_buf0[i+1]은 동일 블록 내 1샘플 이전(시간상 더 오래된) 데이터를 참조하여 SW 1샘플 지연을 구현한다.
  - 근거: main.c:330: `g_lib_dmic_in_buffers[0][1][i] = g_lib_dmic_in_buffers[0][0][i]`(시프트) → `g_lib_dmic_in_buffers[0][0][i] = FIFO`(신규); audioMixer.c:59-74: i=0..14는 delay_buf0[i+1], i=15는 delay_buf1[0]으로 블록 경계 완전 처리

## 개선 제안
- normal_init() 또는 configure_audio_path_all() 내에서 lib_audio_set_front_mic(LIB_AUDIO_FRONT_MIC_NONE)을 명시 호출하여, 소프트 wake 경로가 활성화될 때 stale front_mic 문제를 방어할 것 (system_control.c에 의존하지 않고 lib_audio_in.c 자체에서 일관성 보장)
- Normal_PowerMode_event_mapChange()의 I2S 스트리밍 분기(line 70-73)에서도 switch(isd_location_RL) 블록을 실행하여 HW frac를 기록하고 있다. 이 경우 DMIC_cnt=1이므로 빔포밍 경로가 도달하지 않으나, HW frac 레지스터가 불필요하게 기록된다. 향후 동작 변경 시 혼란을 줄이기 위해 I2S 분기에서 HW frac 기록을 생략하거나 별도 주석으로 의도를 명시할 것
- 소프트 standby/wake 경로(CM3_1_ISR)를 활성화할 계획이 있다면, standby() 진입 전에 lib_audio_set_front_mic(NONE) + SYS_SET_ADC_DEC_CTRL(ch0/ch2, LIB_ADC_DEC_CTRL_VAL) 쌍을 명시적으로 초기화하여 wake 후 mapChange 전 구간의 잘못된 빔포밍을 방지할 것
