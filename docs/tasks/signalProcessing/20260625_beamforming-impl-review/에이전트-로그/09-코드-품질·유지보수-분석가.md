# [분석 09] 코드 품질·유지보수 분석가

**신뢰도**: high

## 결론
4개 파일(lib_audio_in.h, audioMixer.c, main.c, system_control.c)에서 총 6개 품질 문제 확인. 데드 매크로 1건, 믹서 언롤 하드코딩 1건, 버퍼 순서 암묵 가정 1건, tdc_ 접두어 혼용 1건, 주석 불일치 1건, audio_mix_2_buffers 정규화 비일관성 1건. 현재 동작에 영향을 주는 regression 위험은 버퍼 순서 가정과 정규화 비일관성이 가장 크고, 나머지는 유지보수성 문제다.

## 발견(severity·근거)
- **[minor]** LIB_ADC_DEC_CTRL_VAL_0_9958 — 정의만 존재, 호출 0건인 데드 매크로
  - 근거: lib_audio_in.h:110에서 정의(INT=7, FRAC=29 → 7.9958샘플 지연). 전체 src/ grep 결과 .h 외 사용처 없음. 22mm 물리 지연(1.0262샘플)이 HW 레지스터 최대값(0.9958샘플)을 초과하므로 구조적으로 단독 사용 불가 — 실험 중 폐기된 값으로 추정. 코드베이스에 혼선을 줄 수 있어 삭제 또는 `/* UNUSED: 22mm gap requires hybrid delay; max HW frac=0.9958 < 1.026 */` 주석 명시가 필요.
- **[major]** audio_mix_2_buffers_for_beamforming — 16줄 수동 언롤, 블록 크기 16 매직넘버 암묵 고정
  - 근거: audioMixer.c:59-74에서 p_mix[0]~p_mix[15]를 16개 독립 구문으로 작성. p_delay_buf0[1]~[15] 오프셋과 p_delay_buf1[0]은 블록 크기=16을 전제로 수동 계산됨. df_inputADC_DataBuffLength 매크로가 다른 믹서 함수에서 루프 상한으로 사용되나(audioMixer.c:12, 24, 36, 47) 이 함수에서만 미사용. 블록 크기가 변경되면 16줄을 손으로 수정해야 하고, 실수 1건(예: p_mix[14]에 p_delay_buf0[15] 대신 p_delay_buf0[16] 오기)이 OOB 접근으로 이어짐. chess_loop_range로 언롤 힌트 제공이 가능한 플랫폼임을 다른 함수가 증명한다.
- **[major]** 버퍼 샘플 인덱스 순서(index 0 = 최신) — 코드 내 어디에도 assert/static_assert/명시 주석 없음
  - 근거: tdc_copy_DMIC_buffers(main.c:321-348) 루프: j=0일 때 [BUF_MAX_CNT-1][i] = [BUF_MAX_CNT-2][i] → 이후 [0][i] = FIFO. 즉 [0]=최신, [1]=직전 블록. 이 방향이 올바른 이유는 audioMixer.c:74의 경계 처리(i=15에서 p_delay_buf1[0] 참조)가 '직전 블록 index 0 = 직전 블록의 최신 샘플'임에 의존하기 때문. 그러나 lib_audio_in.c:12-17 주석은 순서 정보가 없고('buffer0 / [0:15]: 16 samples' 라벨만), main.c 어디에도 assert가 없다. FIFO 하드웨어가 push 순서를 바꾸거나 copy 루프가 리팩터링되면 지향성이 반전되어도 컴파일 에러 없이 무음 regression이 발생한다.
- **[minor]** tdc_ 접두어 컨벤션 혼용 — main.c 내 신규 심볼은 tdc_이지만, 동일 파일의 기존 심볼(normal, standby, PCM_LiveStimulation_Mode 등)은 미적용
  - 근거: main.h:195-204: normal_init, normal_loop, normal, standby, PCM_LiveStimulation_Mode, HEAR_LiveStimulation_Mode는 tdc_ 없음. tdc_copy_DMIC_buffers(main.h:204)만 tdc_ 적용. CLAUDE.md 코딩 지침 '신규 심볼·모듈은 tdc_ 접두어'에서 '신규'의 범위가 모호하여 파일 내 일관성이 깨진 상태. 단, 기존 심볼 일괄 rename은 다른 파일 참조 다수에 영향을 주므로 별도 리팩터링 작업이 필요하다.
- **[minor]** main.c 인라인 주석 오기 — [0][0][0] 접근에 'buffer1 sample0' 표기
  - 근거: main.c:423 `audio_mix_2_buffers(...g_lib_dmic_in_buffers[0][0][0]...)  // dmic1 buffer1 sample0`, main.c:443 동일 패턴. [0][0][0]은 mic0 / block-index0 / sample0 = 'dmic1 buffer0 sample0'. 반면 main.c:467은 동일 접근에 'dmic1 buffer0 sample0'으로 올바르게 표기. 불일치 주석이 버퍼 인덱스 이해를 방해하며 리뷰 시 혼선 유발.
- **[major]** audio_mix_2_buffers와 audio_mix_2_buffers_for_beamforming 간 정규화(>>1) 비일관성 — 동일 2-mic 합산 경로에서 한쪽만 나누기 2
  - 근거: audioMixer.c:51: audio_mix_2_buffers는 `(buf1>>5) + (buf2>>5)` — >>1 주석 처리됨('두 값을 믹싱 했으므로 반으로 줄여준다 → 반으로 줄이지 않음'). audioMixer.c:59-74: audio_mix_2_buffers_for_beamforming은 `((no_delay>>5) + (delay>>5)) >> 1` — 매 샘플 >>1 적용. 두 함수가 2-mic 합산이라는 동일 목적임에도 출력 스케일이 2배 차이남. beamforming 경로는 올바르게 평균을 내고, 비-beamforming 2-mix 경로는 레벨이 2배 높음. I2S+mic 믹스(PCM_LiveStimulation_Mode:423)에서 audio_mix_2_buffers를 사용하므로 두 경로 간 청각 레벨 차이가 발생한다.

## 개선 제안
- LIB_ADC_DEC_CTRL_VAL_0_9958 매크로를 lib_audio_in.h:110에서 삭제하거나, '22mm gap이 1.026샘플로 HW 최대값(0.9958)을 초과하므로 하이브리드(HW frac + SW 1샘플) 방식으로 대체됨' 주석을 달아 의도적 보존임을 명시한다.
- audio_mix_2_buffers_for_beamforming을 df_inputADC_DataBuffLength 기반 루프(chess_loop_range 힌트 포함)로 전환하고, 블록 경계 처리(i=BLK_LEN-1일 때 p_delay_buf1[0] 참조)를 루프 내 조건으로 명시한다. 이를 통해 블록 크기 변경 시 단일 매크로 수정으로 전파된다.
- lib_audio_in.h 또는 lib_audio_in.c 상단에 버퍼 인덱스 규약을 명문화한다: '블록 인덱스 0 = 최신(현재 인터럽트에서 수신된 블록), 1 = 직전 블록; 샘플 인덱스 0 = 블록 내 가장 최근 샘플'. 선택적으로 tdc_copy_DMIC_buffers 직후 정적 검증 주석(또는 런타임 guard)을 추가한다.
- audio_mix_2_buffers의 >>1 생략 의도(레벨 보존)와 audio_mix_2_buffers_for_beamforming의 >>1 의도(평균화)를 각 함수 Doxygen 주석에 명시하거나, 두 경로의 출력 레벨을 의도적으로 통일시킨다. I2S+mic 경로(main.c:423)의 레벨이 beamforming 경로 대비 2배 높은 현상이 의도인지 버그인지를 먼저 확인한다.
- main.c:423, 443의 인라인 주석 'dmic1 buffer1 sample0'을 'dmic1 buffer0(최신 블록) sample0'으로 수정하여 main.c:467의 올바른 표기와 일관성을 맞춘다.
- tdc_copy_DMIC_buffers처럼 새로 추가되는 CFX 심볼은 tdc_ 접두어를 유지하되, 기존 non-tdc_ 함수(normal, standby, PCM_LiveStimulation_Mode 등)의 일괄 rename은 별도 리팩터링 작업으로 분리하고 작업 목록에 등록하여 점진적으로 적용한다.
