# [검증 17] 빔포밍 믹서의 >>1(÷2)이 front 상관신호를 단일 마이크와 동일 레벨로 정규화하여 1↔2 DMIC 전환 시 음량 연속성을 준다

**판정**: `UNCERTAIN`

## 근거
주장은 두 부분으로 분해된다.

[부분 1 — 정규화 수학: confirmed]
audioMixer.c:59-74에서 audio_mix_2_buffers_for_beamforming의 연산은 `(no_delay[i]>>5 + delay_buf0[i+1]>>5) >> 1`이다. 이상적 정면 상관 신호(두 채널 동일 진폭 A)를 대입하면 `(A/32 + A/32)/2 = A/32`이며, audio_mix_1_buffer(audioMixer.c:39)의 `p_buf1[i]>>5 = A/32`와 동일하다. 수학적으로 >>1이 정면 상관 신호를 단일 마이크 레벨로 정규화하는 것은 맞다.

[부분 2 — 1↔2 DMIC 전환 시 음량 연속성: 조건부·불확실]
실제 전환 경로를 코드 기반으로 추적하면 세 가지 케이스가 존재한다.

케이스 A (NONE↔LEFT/RIGHT, 빔포밍 ON/OFF): PCM_LiveStimulation_Mode(main.c:450-468)에서 front_mic==NONE이면 audio_mix_1_buffer, LEFT/RIGHT이면 audio_mix_2_buffers_for_beamforming. 정면 완전 상관 신호에서는 레벨 연속. 그러나 비상관 잡음이 지배하는 경우 빔포밍 경로 출력이 -3dB 낮아져 오히려 음량이 줄어든다(√2·A/32/2 < A/32). 실제 환경에서 신호 상관도가 1이 아닌 한 연속성은 보장되지 않는다.

케이스 B (I2S 스트리밍 종료 → 2-DMIC 복귀): normal_loop(main.c:188-193)에서 enable_2_DMICs()가 호출되고 PCM_LiveStimulation_Mode 내 경로가 I2S 분기(audio_mix_2_buffers, >>1 없음, audioMixer.c:51)에서 2-DMIC 빔포밍 분기로 전환된다. audio_mix_2_buffers는 주석에서 의도적으로 >>1을 제거했으므로("반으로 줄이지 않음"), 이 전환에서는 동일 신호 기준 레벨이 2배→1배로 급락하는 불연속이 발생한다. 이 경우 >>1은 연속성을 주는 것이 아니라 오히려 불연속의 원인이 된다.

케이스 C (QCC I2S_FLAG 기반 DMIC 수 전환): 이 경로에서 믹서 함수 선택은 I2S 상태와 DMIC 카운트의 조합으로 결정되며, I2S 비스트리밍·1-DMIC → 2-DMIC 전환 시 audio_mix_1_buffer에서 audio_mix_2_buffers_for_beamforming으로 바뀐다. front_mic가 NONE이 아닌 경우 케이스 A와 동일 분석이 적용된다.

결론: 주장의 전제(이상적 정면 상관 신호 한정)에서는 수학이 성립하지만, "음량 연속성"이 모든 1↔2 DMIC 전환 경로에서 보장된다는 주장은 반증된다. I2S 경로의 audio_mix_2_buffers가 의도적으로 >>1을 제거(audioMixer.c:51 주석 "반으로 줄이지 않음")했기 때문에 해당 전환 경로에서 >>1의 연속성 역할이 성립하지 않으며, 비상관 잡음 환경에서도 레벨 불연속이 발생한다. 전체 주장은 조건부(이상적 신호·특정 전환 경로 한정)로만 지지되므로 uncertain 판정.
