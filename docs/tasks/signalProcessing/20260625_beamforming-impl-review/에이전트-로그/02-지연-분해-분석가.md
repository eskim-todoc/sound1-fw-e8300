# [분석 02] 지연 분해 분석가 — E8300 CFX 빔포밍 실구현 기반, 그라운딩 사실 및 소스 파일 직접 인용

**신뢰도**: high

## 결론
SW 1샘플 + HW FRAC=6(0.025샘플) = 1.025샘플(64.0625µs)은 22mm 이상값 1.02624샘플(64.1399µs)에 대해 절대 오차 0.00124샘플(0.077µs, 0.027mm)로 정합. 실온(20°C) 기준으로는 오차 0.00061샘플(38ns)로 사실상 최적점. 온도 산포(20→37°C)는 타깃을 -0.0285샘플만큼 당겨 내리며, HW FRAC 1스텝(1/240=0.0042샘플, 0.089mm) 단위의 미세조정 여지가 존재. 단, 버퍼 인덱스 순서(index 0=최신)는 코드에서 직접 도출되며, 이것이 SW 1샘플 지연의 핵심 전제다.

## 발견(severity·근거)
- **[info]** 1.025샘플 합계와 22mm 이상값의 정합: 오차 0.077µs(0.121%)
  - 근거: 수치 계산: SW=1.000샘플(62.500µs) + HW FRAC=6/240=0.025샘플(1.563µs) = 1.025샘플(64.063µs). 22mm/343m/s=64.140µs=1.02624샘플. 오차=0.00124샘플=0.077µs. 실온 20°C(c=343.21m/s) 기준 타깃=1.02561샘플, 오차=0.00061샘플(38ns)로 더욱 정밀. HW macro: lib_audio_in.h L112-113: LIB_ADC_FRACTIONAL_DELAY_6=(6<<AUDIO_ADC_DEC_CTRL_DELAY_FRACTIONAL_Pos), LIB_ADC_DEC_CTRL_VAL_0_0250 (INT=0, FRAC=6).
- **[info]** 버퍼 인덱스 순서: index 0=최신, index 15=오래됨 — 직접 코드에서 확인됨
  - 근거: main.c L322-347 tdc_copy_DMIC_buffers: 내부 루프 j=0..BUF_MAX_CNT-2=0에서 buf[mic][1][i]=buf[mic][0][i] (이전 보존), 이후 buf[mic][0][i]=FIFO(신규). 즉 [0]=최신, [1]=직전. audioMixer.c L74: p_mix[15]=delay_buf0[15]+delay_buf1[0]의 블록 경계에서 delay_buf0[15](현재 블록의 가장 오래된 샘플)와 delay_buf1[0](직전 블록의 가장 새로운 샘플)이 시계열상 인접 — index 0=최신 전제와 완전 정합. 이 가정이 틀리면 SW 1샘플 지연이 성립하지 않음.
- **[minor]** 온도 산포(20→37°C)에 대한 오차 여유: FRAC 미세조정 범위 이내
  - 근거: 음속: 20°C=343.21m/s, 37°C=353.03m/s. 22mm 타깃: 20°C=1.02561샘플, 37°C=0.99710샘플. 17°C 온도차로 타깃이 -0.0285샘플 이동. 현재 고정 지연 1.025샘플은 37°C 타깃(0.997)보다 +0.028샘플 초과 — 즉 체온 환경에서는 약간 과지연 상태. HW FRAC 1스텝=1/240=0.00417샘플=0.089mm 공간해상도이므로, 온도 변화량 0.0285샘플은 FRAC 약 6.8스텝에 해당. 2-mic 22mm 구성의 수 dB 수준 지향성을 고려하면 온도 오차는 주 열화 요인이 되지 않음.
- **[info]** HW FRAC 미세조정 여지: FRAC=5/6/7 선택으로 ±0.089mm 브라켓 가능
  - 근거: lib_audio_in.h L112-113에서 FRAC=6이 하드코딩. 계산: FRAC=5→1.02083샘플=21.884mm(오차+0.116mm), FRAC=6→1.02500샘플=21.973mm(오차+0.027mm), FRAC=7→1.02917샘플=22.063mm(오차-0.063mm). 20°C 기준 최소오차는 FRAC=6. 온도 보상이 필요하다면 FRAC=5(더 따뜻한 환경)로 조정 가능. 단 현재 LIB_ADC_DEC_CTRL_VAL_0_0250 매크로만 정의되어 있어 FRAC=5/7을 쓰려면 신규 매크로 추가 필요(lib_audio_in.h L109-113 패턴 반복).
- **[minor]** LIB_ADC_DEC_CTRL_VAL_0_9958(INT=7/FRAC=29) 미사용 데드코드 — 22mm 타깃과 무관한 값
  - 근거: lib_audio_in.h L109-110: LIB_ADC_DEC_CTRL_VAL_0_9958=(INT=7, FRAC=29)=7+29/240=7.12083샘플=445µs=152mm. 정의만 있고 system_control.c, lib_audio_in.c 어디에도 호출 없음. 22mm 빔포밍과 완전 무관한 값(전혀 다른 지연 규모). 코드 정리 시 제거 또는 목적 주석 추가 권고.
- **[info]** SW 1샘플 지연은 순수 HW INT=1, FRAC=6으로 수치적으로 대체 가능하지만 구조적으로 현재 방식이 채택된 배경이 있음
  - 근거: Pure HW: INT=1, FRAC=6=1.025샘플 — 현재 하이브리드(SW1+FRAC6)와 수치 동일. 그러나 현재 SW 1샘플은 audioMixer.c의 언롤 16줄(L59-74) 인덱스 i+1 참조로 구현되어 있고, HW decimation filter가 콘텐츠 지연(FIFO 인터럽트 동기 내)이라는 논의 결론(그라운딩 사실)을 활용. 순수 HW INT=1로 바꿔도 delay=1.025샘플로 동일하나, INT 필드가 decimation filter 내부 지연이므로 동작 검증 없이 구조 변경은 리스크.
- **[minor]** HW fractional 설정이 map 변경 이벤트(Normal_PowerMode_event_mapChange)에서만 적용됨 — init 경로에서는 지연 0
  - 근거: lib_audio_in.c L141-142: configure_audio_path_all에서 ch0/ch2 모두 LIB_ADC_DEC_CTRL_VAL(delay=0) 설정. system_control.c L87-94: Normal_PowerMode_event_mapChange의 Left_Ear/Right_Ear case에서만 LIB_ADC_DEC_CTRL_VAL_0_0250 적용. 따라서 ISD가 연결되어 맵 변경 이벤트가 발생하기 전(초기 상태 또는 front_mic=NONE)에는 HW fractional이 0이고 SW 1샘플만 작동. 이는 의도된 설계이나, 초기화 후 첫 맵 변경 전 구간에서 HW 지연이 0임을 인지해야 함.

## 개선 제안
- FRAC 값을 런타임 파라미터로 추출하여 온도 또는 교정 기반 미세조정 경로 마련 — 현재 LIB_ADC_DEC_CTRL_VAL_0_0250 하드코딩(lib_audio_in.h L113)을 FRAC 필드 분리 매크로로 리팩터링
- LIB_ADC_DEC_CTRL_VAL_0_9958(lib_audio_in.h L110) 데드코드 제거 또는 '미래 8샘플 이상 지연 실험용' 주석 명시
- tdc_copy_DMIC_buffers 및 audioMixer.c 상단에 '버퍼 index 0=최신, index 15=오래됨' 순서를 명시하는 주석 추가 — SW 1샘플 지연 동작의 전제 조건
- configure_audio_path_all(초기화)에서도 front_mic 상태에 따라 HW fractional을 즉시 설정하거나, 맵 변경 전 구간의 FRAC=0 상태를 시스템 로그/디버그로 명시화
