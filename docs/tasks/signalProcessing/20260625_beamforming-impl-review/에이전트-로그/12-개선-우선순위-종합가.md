# [분석 12] 개선 우선순위 종합가 — CFX 빔포밍 실구현 코드 리뷰 (파일 직접 판독 근거)

**신뢰도**: high

## 결론
src/1__cfx 의 DMIC 빔포밍 구현을 6개 관점(정확성/안정성/게인/코드품질/성능/테스트)에서 분석. 가장 긴급한 항목은 audio_mix_2_buffers 의 정규화 누락(게인 2배 불균형)과, configure_audio_path_all 의 HW 소수 지연 미적용(init 시 ch0/ch2 둘 다 지연=0)이며, 이후 데드코드 제거·루프 변환·버퍼 인덱스 문서화 등이 중간 우선순위다.

## 발견(severity·근거)
- **[major]** audio_mix_2_buffers 에서 두 채널 합산 후 >>1 정규화를 하지 않아 빔포밍 경로 대비 출력 게인이 2배 차이남
  - 근거: audioMixer.c:51 — p_mix[i] = ((p_buf1[i]>>AUDIO_INPUT_RSHIFT) + (p_buf2[i]>>AUDIO_INPUT_RSHIFT));  // >> 1; 로 주석 처리. 반면 audio_mix_2_buffers_for_beamforming(line 59-74)은 끝에 >>1 적용. I2S+DMIC 믹싱(main.c:423)은 비-빔포밍 코드이므로 >>1 없이 합산되어 HEAR_ADDR_AUDIO_MIX 진입 레벨이 빔포밍 경로 대비 2x 높음.
- **[major]** configure_audio_path_all 초기화 시 ch0·ch2 모두 소수 지연 0으로 설정되며, 맵변경(Normal_PowerMode_event_mapChange) 경로에서만 HW 소수 지연이 부여됨. ISD 미연결 상태로 첫 루프 진입 시 지연 미적용 상태로 빔포밍 연산이 수행될 수 있음
  - 근거: lib_audio_in.c:141-142 — configure_audio_path_all #elif 2 DMIC 분기에서 SYS_SET_ADC_DEC_CTRL(AUDIO,0,LIB_ADC_DEC_CTRL_VAL) / SYS_SET_ADC_DEC_CTRL(AUDIO,2,LIB_ADC_DEC_CTRL_VAL) 둘 다 지연=0 매크로 사용. system_control.c:87-93 에서만 Left_Ear→ch2에 _0_0250, Right_Ear→ch0에 _0_0250 적용. ISD 연결 전(m_current_isd==0) 구간에는 Normal_PowerMode_isdConnected가 호출되지 않으므로 HW 소수 지연이 0인 채로 2-DMIC 경로 진입 가능.
- **[minor]** LIB_ADC_DEC_CTRL_VAL_0_9958 매크로가 정의만 있고 실 코드에서 전혀 사용되지 않는 데드코드임
  - 근거: lib_audio_in.h:110 — #define LIB_ADC_DEC_CTRL_VAL_0_9958 (BAND_SELECT_ADC_0K_8K | ADC_INTEGER_DELAY_7 | LIB_ADC_FRACTIONAL_DELAY_29 | ...). lib_audio_in.c 및 system_control.c 전체에서 이 매크로를 참조하는 코드 없음. 그라운딩 문서에서도 '정의만 있고 호출 없음'으로 확인.
- **[minor]** audio_mix_2_buffers_for_beamforming 가 16줄 하드코딩 언롤로 구현되어 있어 블록 길이(df_inputADC_DataBuffLength) 변경 시 버그 발생 위험이 있음
  - 근거: audioMixer.c:59-74 — p_mix[0]~p_mix[15] 를 16개 독립 구문으로 작성. audio_mix_1_buffer(line 36-41)와 audio_mix_2_buffers(line 47-52)는 for 루프+chess_loop_range 패턴을 사용하는 것과 대조적. 블록 경계 처리(p_mix[15]=delay_buf1[0]) 로직이 루프로 일반화되지 않아 향후 블록 크기 변경 시 수동 수정 필요.
- **[minor]** tdc_copy_DMIC_buffers 에서 buffer 인덱스 0이 '최신 블록'임을 코드 내 어디에도 명시하지 않아 PCM_LiveStimulation_Mode 의 LIB_AUDIO_IN_BUF_MAX_CNT-2/BUF_MAX_CNT-1 참조 의미가 불명확함
  - 근거: main.c:322-347 — g_lib_dmic_in_buffers[mic][0][i] = FIFO 신규값, [BUF_MAX_CNT-1] = 가장 오래된 값으로 이동. main.c:454 — audio_mix_2_buffers_for_beamforming에서 p_delay_buf0=dmic[1][BUF_MAX_CNT-2], p_delay_buf1=dmic[1][BUF_MAX_CNT-1] 로 호출. lib_audio_in.h:31 — LIB_AUDIO_IN_BUF_MAX_CNT=2 이므로 BUF_MAX_CNT-2=0(최신), BUF_MAX_CNT-1=1(직전) 과 같으나, 주석이 없으면 BUF_MAX_CNT 값 변경 시 의미 역전 위험.
- **[major]** normal_loop 의 I2S 스트리밍 전환 로직에서 enable_1_DMIC/enable_2_DMICs 호출 시 HW 소수 지연 레지스터 재적용이 없어, I2S→비-I2S 전환 후 빔포밍 지연이 소거되지 않고 이전 상태 유지됨
  - 근거: main.c:172-173 — I2S 스트리밍+2-DMIC 상태이면 enable_1_DMIC() 호출. main.c:189-191 — 비-I2S+1-DMIC 상태이면 enable_2_DMICs() 호출. 두 함수(lib_audio_in.c:173-184)는 DIO CLK 설정만 수행하고 SYS_SET_ADC_DEC_CTRL 은 호출하지 않음. HW 소수 지연 복구는 다음 mapChangeFlag 이벤트를 기다려야 하므로 전환 직후 구간에 지연 불일치 잠재.
- **[info]** PCM_LiveStimulation_Mode 내 get_enabled_DMIC_count()==2 분기에서 LIB_AUDIO_FRONT_MIC_NONE 이면 audio_mix_1_buffer(dmic1 고정)를 사용하는데, 이 상태에서도 2개 DMIC CLK이 모두 활성화되어 불필요한 전력 소모가 발생할 수 있음
  - 근거: main.c:465-468 — front_mic==NONE이면 audio_mix_1_buffer(dmic1 buffer0). lib_audio_in.c:181-184 — enable_2_DMICs()는 DIO22·DIO10 양쪽 CLK을 ADCCLK 모드로 활성화. NONE 상태에서 dmic2(ch2)를 읽지 않더라도 CLK이 살아있어 QCC와의 CLK 공유 주의.
- **[minor]** 비-I2S·2-DMIC 경로(PCM_LiveStimulation_Mode)와 I2S 경로(I2S_handle)에서 audio_mix_2_buffers 호출이 혼재하며 이 두 경로의 믹싱 정규화 정책이 일관되지 않음
  - 근거: main.c:423 — I2S+dmic1 믹싱: audio_mix_2_buffers(>>1 없음, 게인 2배). main.c:372, 400 — I2S_handle 내 audio_mix_2_buffers 동일 함수 사용. audioMixer.c:51 의 주석 '// >> 1;'이 의도적 결정인지 임시 비활성화인지 불명확.

## 개선 제안
- [우선순위 1 — 게인/정확성] audio_mix_2_buffers 에서 주석 처리된 >>1 의도 확인 후, I2S+DMIC 믹싱과 단독 DMIC 경로 간 출력 레벨 정합. 필요 시 I2S 경로 전용 믹서 함수 분리(구현비용: 저)
- [우선순위 2 — 안정성] enable_1_DMIC / enable_2_DMICs 함수 내부 또는 호출 직후 SYS_SET_ADC_DEC_CTRL 재적용 로직 추가. I2S↔비-I2S 전환 시 HW 소수 지연이 올바른 채널에 유지되도록 보장(구현비용: 저~중)
- [우선순위 3 — 정확성] configure_audio_path_all 에서 초기화 시 front_mic 상태(s_lib_audio_front_mic)를 보고 ch0/ch2 중 front 채널에 _0_0250 선 적용하거나, 최초 ISD 연결 전에는 2-DMIC 빔포밍 경로를 진입 금지하는 가드 추가(구현비용: 저)
- [우선순위 4 — 코드품질] LIB_ADC_DEC_CTRL_VAL_0_9958 매크로 및 관련 주석 삭제. 오해 방지(구현비용: 극저)
- [우선순위 5 — 코드품질] audio_mix_2_buffers_for_beamforming 을 for 루프+chess_loop_range 패턴으로 리팩터링. 블록 경계(index 15 → delay_buf1[0]) 처리는 루프 바깥 단일 구문으로 유지(구현비용: 저)
- [우선순위 6 — 코드품질] g_lib_dmic_in_buffers[mic][buf][sample] 의 buf 인덱스 규칙(0=최신, BUF_MAX_CNT-1=최오래됨)을 lib_audio_in.h 또는 헤더 블록 주석으로 명문화. 현재 lib_audio_in.c:9-16 주석은 buffer0/buffer1 이 최신/직전임을 표기하지 않음(구현비용: 극저)
