# [분석 04] L/R 재조향 로직 분석가

**신뢰도**: high

## 결론
CFX 빔포밍 L/R 재조향 로직의 4개 과제를 코드 근거 기반으로 분석한 결과, front_mic LEFT/RIGHT 스왑은 forward end-fire 정렬을 올바르게 구현하나, HW fractional 채널 할당과 SW 지연 채널 사이에 구조적 불일치(minor)가 존재한다. ISD location 소스는 EEPROM 파일시스템 경유이나 기본값 하드코딩 위험이 있고, NONE 폴백은 기능적으로 타당하다.

## 발견(severity·근거)
- **[info]** front_mic LEFT/RIGHT 스왑이 forward end-fire 정렬을 올바르게 구현한다
  - 근거: main.c L454: LEFT → delay=dmic2[1], no_delay=dmic1[0]. dmic2=ch2=DMIC2(U9/DIO17, FE), dmic1=ch0=DMIC0(U7/DIO23, RE). system_control.c L85-89: Left_Ear → lib_audio_set_front_mic(LEFT) + SYS_SET_ADC_DEC_CTRL(AUDIO,2,_0_0250)로 ch2(QCC/뒤쪽)에 frac 지연. L91-94: Right_Ear → SYS_SET_ADC_DEC_CTRL(AUDIO,0,_0_0250)로 ch0(EZ/앞쪽)에 frac 지연. 즉 LEFT 착용 시 뒤쪽(ch2)을 지연하여 앞쪽(ch0)에 위상 정렬 → forward end-fire. RIGHT 착용 시 뒤쪽(ch0)을 지연하여 앞쪽(ch2)에 정렬 → 동일 방향성. 기기 착용 귀에 따라 전후 물리적 위치가 뒤집히므로 스왑은 의도적이고 정확하다.
- **[info]** HW fractional 지연 채널과 SW 지연 채널이 일치한다
  - 근거: LEFT 케이스: system_control.c L88에서 ch2(ADC2=DMIC2=dmic2 버퍼 인덱스 [1])에 _0_0250 부여. main.c L454에서 delay 인자 = g_lib_dmic_in_buffers[1][LIB_AUDIO_IN_BUF_MAX_CNT-2][0] 즉 dmic2의 현재 블록. RIGHT 케이스: L93에서 ch0(ADC0=DMIC0=dmic1 버퍼 인덱스 [0])에 _0_0250 부여. main.c L461에서 delay 인자 = g_lib_dmic_in_buffers[0][LIB_AUDIO_IN_BUF_MAX_CNT-2][0] 즉 dmic1. HW fractional이 붙은 채널과 SW i+1 지연을 받는 채널이 정확히 일치한다. 총 지연 = HW 0.025샘플 + SW 1샘플 = 1.025샘플 = 64.06µs. 22mm 음향 지연 이론값 1.0262샘플과 오차 0.0012샘플(0.08µs).
- **[info]** 버퍼 인덱스 순서(index 0=최신, 1=직전)가 tdc_copy_DMIC_buffers 구현에서 검증된다
  - 근거: main.c L321-348: tdc_copy_DMIC_buffers 내부 이중 루프에서 j=0부터 LIB_AUDIO_IN_BUF_MAX_CNT-2까지 역방향 시프트: [BUF_MAX-1-j][i] = [BUF_MAX-2-j][i]. 이후 [0][i] = FIFO 신규 데이터. LIB_AUDIO_IN_BUF_MAX_CNT=2이므로 [1][i]=[0][i](직전 보존) → [0][i]=FIFO(신규). 따라서 [0]=최신, [1]=직전 확인. audioMixer.c L74: p_mix[15]=(no_delay[15]>>5 + delay_buf1[0]>>5)>>1, delay_buf1=dmic_buffers[mic][LIB_AUDIO_IN_BUF_MAX_CNT-1]=[mic][1]=직전 블록의 index 0으로 블록 경계 처리 일관성 확인.
- **[minor]** HW fractional 지연(0.025샘플)이 init 시 리셋되고 맵변경 이벤트에서만 재설정되는 타이밍 갭이 존재한다
  - 근거: lib_audio_in.c L141-142: configure_audio_path_all()에서 ch0, ch2 모두 LIB_ADC_DEC_CTRL_VAL(frac=0)으로 초기화. system_control.c L87-94: HW frac _0_0250 설정은 Normal_PowerMode_event_mapChange() 내 mapChangeFlag.cm3Command_mapChange==1 분기에서만 수행. 즉 ISD 연결 직후 맵변경 이벤트 수신 전까지는 양 채널 모두 frac=0으로 동작. 이 기간 동안 빔포밍이 활성화되면 HW frac 없이 SW 1샘플만 적용되어 1.025샘플 대신 1.000샘플 지연이 적용된다.
- **[minor]** ISD location 소스(cfx_ISD_info[].isd_location_RL)는 파일시스템 EEPROM 경유이나, 미초기화 시 하드코딩 기본값에 의존한다
  - 근거: cfx_cm3_sharedMemory.c L409: get 함수는 cfx_cm3_sharedMemoryAll.cfx_ISD_info[connected_ISD_Num-1].isd_location_RL 반환. fn_from_cfx_eeprom_read.c L16: 부팅 시 EEPROM FS에서 cfx_ISD_info[i] 전체 구조체 복사로 신뢰성 경로 존재. 단, ci_map.c L348-375: EEPROM 검증 실패(validate_isd_info < 0) 또는 force_init 시 기본값으로 isd_num==1이면 L364에서 isd_location_RL=2(Right_Ear), isd_num==2이면 L374에서 =1(Left_Ear)로 하드코딩. fn_from_cfx_eeprom_erase.c L57: 소거 시 isd_location_RL=3(NA). 따라서 EEPROM이 유효하면 신뢰 가능하나, 초기화/소거 후에는 하드코딩 기본값 또는 NA(=default 폴백)로 귀결.
- **[info]** NONE 폴백(audio_mix_1_buffer(dmic1))은 기능적으로 타당하다
  - 근거: main.c L466-468: front_mic==NONE 또는 EEPROM isd_location_RL 미매핑(default 분기) 시 audio_mix_1_buffer(g_lib_dmic_in_buffers[0][0][0]) 즉 dmic1(EZ 내장 마이크, ch0)만 사용. system_control.c L97-101: default 분기에서 lib_audio_set_front_mic(NONE) + 양 채널 frac=0. QCC 점유/1-DMIC 상태에서도 동일 dmic1 사용(main.c L443). ISD 미연결·Mapping Live 모드·QCC I2S 활성화 등 모든 비정상 경로가 동일 단일 채널 경로로 수렴하므로 폴백으로 일관성 있음. 다만 NONE 상태에서 enable_2_DMICs()가 활성화되어 있으면 dmic2는 FIFO에 데이터를 채우지만 믹서에서 무시됨 — 낭비이나 오동작 없음.
- **[info]** 데드코드 LIB_ADC_DEC_CTRL_VAL_0_9958이 정의되어 있으나 어디서도 호출되지 않는다
  - 근거: lib_audio_in.h L109-110: LIB_ADC_DEC_CTRL_VAL_0_9958 (INT=7, FRAC=29 → 7+29/240=7.1208샘플)이 define됨. grep 결과 system_control.c와 모든 CFX 소스에서 이 매크로 사용처 없음. 22mm 이론값 1.0262샘플은 ADC decimation 레지스터 최대 단일 채널 정수+분수 조합 범위를 초과(INT 최대 7이면 7.025이상도 가능하나 실제 의도는 0.xx샘플 수준 지연)하므로 0.9958 정의 자체가 실험적 잔재로 보임.

## 개선 제안
- HW fractional 지연을 configure_audio_path_all() 또는 ISD 연결 직후 즉시 설정하도록 변경하여, 맵변경 이벤트 수신 전 frac=0 구간을 제거할 것 (system_control.c Normal_PowerMode_isdConnected의 최초 진입 시점에 isd_location_RL 기반 ADC_DEC_CTRL 설정 추가)
- isd_location_RL 기본값 하드코딩(ci_map.c L360/364/374)에 대해, 임상 환경에서 EEPROM 미초기화 기기가 배포되는 경우 잘못된 방향성이 적용될 수 있으므로 기본값을 NONE(=3)으로 통일하거나 CLI 명령으로 강제 설정 경로를 제공할 것
- 데드코드 LIB_ADC_DEC_CTRL_VAL_0_9958을 제거하거나 주석으로 이력 설명을 추가하여 코드 혼란 방지
- NONE 상태에서 2-DMIC 활성화 시 dmic2 FIFO 점유가 불필요하게 발생하므로, NONE 설정 시 enable_1_DMIC()로 전환하는 경로를 고려할 것 (QCC 공유 맥락과 충돌하지 않는지 검증 필요)
