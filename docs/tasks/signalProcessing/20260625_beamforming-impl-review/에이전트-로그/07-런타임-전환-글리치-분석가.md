# [분석 07] 런타임 전환 글리치 분석가 — E8300 CFX 빔포밍 실구현 코드 기반 (추측 없음, 파일/라인 근거만)

**신뢰도**: high

## 결론
맵변경 시 Normal_PowerMode_event_mapChange(system_control.c:57) 내 세 가지 전환 글리치 지점이 확인됨. (1) SYS_SET_ADC_DEC_CTRL live 쓰기로 인한 decimation 필터 위상 점프, (2) enable_1/2_DMIC의 DIO CLK 토글 글리치로 QCC DMIC 데이터 오염, (3) audio DAC 출력 뮤트 없이 PCM NOP만 사용하는 오디오 경로 전환. 세 문제 모두 mute/flush 없이 실행되는 공통 구조적 결함을 공유하며, 특히 ADC_DEC_CTRL 위상 점프는 빔포밍 지향성 붕괴를 유발한다.

## 발견(severity·근거)
- **[major]** SYS_SET_ADC_DEC_CTRL live 쓰기 — 소수 지연(FRAC=0→6 또는 6→0) 순간 변경으로 decimation 필터 내부 상태(파이프라인 탭)가 불연속되어 위상 점프 발생
  - 근거: system_control.c:87-100: Left_Ear 분기에서 ch0→LIB_ADC_DEC_CTRL_VAL(FRAC=0), ch2→LIB_ADC_DEC_CTRL_VAL_0_0250(FRAC=6)을 오디오 스트림이 흐르는 도중 live로 쓴다. fn_PcmBitStream_Mode_NopStandby(system_control.c:65)는 PCM 출력 FIFO(HEAR_ADDR_FIFO_PCM_WRITING)에 NOP 패턴을 기록할 뿐(driver_PCM.c:110-121), ADC decimation 필터 파이프라인을 flush하거나 ADC를 disable하지 않는다. configure_audio_path_all(lib_audio_in.c:141-142)는 ch0/ch2 모두 LIB_ADC_DEC_CTRL_VAL(FRAC=0)으로 init하므로, 맵변경 시 처음으로 FRAC 값이 달라진다. Ezairo 8300 HW는 DEC_CTRL 레지스터 쓰기가 즉시 적용되므로, 이전 블록 끝~신규 블록 시작 사이에 fractional delay 파이프라인 탭이 리셋되거나 잘못 연장되어 최소 1블록(16샘플=1ms) 이상 출력 위상이 불연속됨.
- **[major]** 위상 점프가 빔포밍 null 방향 붕괴를 유발함 — 전환 직후 1~수 블록간 두 채널 위상차가 설계값(1.025샘플)과 달라져 지향성 패턴 소멸
  - 근거: audio_mix_2_buffers_for_beamforming(audioMixer.c:55-75)은 p_delay_buf0[i+1]을 읽는 1샘플 SW 지연과 FRAC=6 HW 지연을 합산해 1.025샘플 정렬을 가정한다. FRAC가 전환 순간 내부 파이프라인 상태 없이 새 값으로 쓰이면 ch2(또는 ch0)의 출력이 수 샘플 동안 부정확한 위상을 가지므로, 그 기간의 믹스 출력은 front 방향 빔 대신 무작위 위상 합산이 된다. tdc_copy_DMIC_buffers(main.c:321-348)가 FIFO→g_lib_dmic_in_buffers[mic][0]으로 매 블록 복사할 때 이미 오염된 샘플이 [0]과 [1] 모두에 순차적으로 채워지므로, 최악의 경우 2블록(2ms)간 beamforming 출력이 오염됨.
- **[major]** enable_1_DMIC / enable_2_DMICs의 DIO10(DMIC_CLK2) 토글 — CLK가 ADCCLK→DISABLE(또는 역방향)로 전환되는 순간 QCC(U9) DMIC는 CLK 엣지를 받지 못해 PDM 데이터 라인(DIO17)에 미정의 비트를 출력하고, 이 쓰레기 샘플이 ADC FIFO로 진입함
  - 근거: enable_1_DMIC(lib_audio_in.c:173-178): DIO10을 DIO_MODE_ADCCLK→DIO_MODE_DISABLE로 즉시 전환(Sys_DIO_Config 1회 호출). enable_2_DMICs(lib_audio_in.c:180-184): DIO10을 DISABLE→ADCCLK로 즉시 전환. 어느 방향이든 전환 순간 CLK는 DMIC(U9)가 요구하는 클럭 주기 중간에 멈추거나 갑자기 시작될 수 있다. U9의 DIO17(DMIC_DATA_FE, falling edge 샘플링)은 CLK 공급이 불규칙한 구간에 PDM 비트를 보내거나 보내지 않을 수 있으며, ADC ch2는 이 구간의 FIFO 데이터를 정상 샘플로 취급한다. tdc_copy_DMIC_buffers(main.c:340-347)은 HCT_A0_1(ch2)을 매 블록 g_lib_dmic_in_buffers[1][0]으로 복사하므로, 오염된 샘플이 그대로 beamforming 입력으로 쓰인다. 전환 후 QCC DMIC 스타트업 특성(IQS323 등과 유사하게 수 ms 안정화 시간 필요)도 동일하게 적용됨.
- **[major]** 맵변경 시 DAC/오디오 출력 경로에 mute 절차 없음 — fn_PcmBitStream_Mode_NopStandby는 PCM 자극 출력만 보호하며, 오디오 믹서 출력(DAC0/DAC1 FA0_2/FA0_3)은 전환 중에도 이전 블록 잔류 데이터 또는 전환 직후 오염 데이터로 출력됨
  - 근거: Normal_PowerMode_event_mapChange(system_control.c:57-131): fn_PcmBitStream_Mode_NopStandby(PCM FIFO 보호) 호출 후 즉시 enable_1/2_DMIC → SYS_SET_ADC_DEC_CTRL 순서로 진행. SYS_SET_OUTPUT_CTRL이나 SYS_SET_DAC_GF_CTRL을 0으로 설정(DAC mute)하는 코드가 없다. FIFO_A0_2/A0_3에 SYS_FIFO_AUTOMUTE(lib_audio_in.c:57-58)가 설정돼 있으나, auto mute는 FIFO가 비거나 언더런 시 자동 무음화이지, 능동적 전환 뮤트가 아니다. 따라서 beamforming 전환 구간(최소 1~2블록)에 오디오 출력 경로로 위상 오염 샘플이 그대로 전달됨. 인공와우 적용 맥락상 이는 클릭/과도 자극 노이즈로 직결된다.
- **[minor]** g_lib_dmic_in_buffers[mic][1](직전 블록)이 전환 시 flush되지 않아 LEFT↔RIGHT 방향 전환 시 첫 믹스 블록에 구 방향 지연 샘플이 혼입됨
  - 근거: audio_mix_2_buffers_for_beamforming(audioMixer.c:74): p_mix[15]=(no_delay[15]+p_delay_buf1[0])>>1 에서 p_delay_buf1은 g_lib_dmic_in_buffers[mic][LIB_AUDIO_IN_BUF_MAX_CNT-1]([1] 슬롯). 방향 전환(Left→Right) 시 delay 채널이 dmic2→dmic1으로 바뀌는데, [1] 슬롯에는 직전 블록 데이터(이전 방향의 dmic2 샘플)가 남아있다(tdc_copy_DMIC_buffers에서 [1]=[이전 [0]]으로만 갱신됨, system_control.c·main.c 어디에도 전환 시 [1] 슬롯 클리어 없음). 전환 직후 첫 블록의 p_mix[15]는 새 방향 no_delay 채널과 구 방향 delay 채널의 합산이 된다.
- **[info]** LIB_ADC_DEC_CTRL_VAL_0_9958(INT=7, FRAC=29)은 정의만 있고 호출 경로가 전혀 없어 데드코드 상태 — 향후 이 값을 사용하는 코드 경로 추가 시 위험
  - 근거: lib_audio_in.h:110: LIB_ADC_DEC_CTRL_VAL_0_9958 정의. 전체 1__cfx/ 트리에서 SYS_SET_ADC_DEC_CTRL와 함께 호출되는 곳 없음(grep 결과 system_control.c:87-100, lib_audio_in.c:96,124,141-142만 존재, 0_9958은 해당 없음). INTEGER_DELAY_7 설정은 ADC 파이프라인에 7샘플 정수 지연을 추가하므로 만약 live로 쓰이면 위상 점프가 7샘플(437µs) 규모로 확대됨.

## 개선 제안
- 완화_1 (위상 점프): SYS_SET_ADC_DEC_CTRL 쓰기 전 ADC ch0/ch2를 ADC_MUTE 비트로 뮤트(LIB_ADC_DEC_CTRL_VAL 시리즈에서 ADC_UNMUTE를 ADC_MUTE로 교체한 임시 값 작성) → DEC_CTRL 레지스터 갱신 → 1블록 대기 또는 다음 FIFO 인터럽트 후 UNMUTE 복원. 뮤트 구간 동안 g_lib_dmic_in_buffers[mic][0] 초기화(0 fill)도 함께 수행.
- 완화_2 (DIO CLK 글리치): enable_1_DMIC/enable_2_DMICs 호출 전 FIFO_A0_1(ch2 FIFO)을 clear_FIFO(HCT_A0_1, HCT_FIFO_A0_1_LENGTH)로 플러시하고, 전환 후 최소 1블록 인터럽트 대기 후 g_lib_dmic_in_buffers[1][*] 전체를 0 fill하여 스타트업 오염 샘플 격리.
- 완화_3 (전환 시 beamforming 입력 버퍼 flush): Normal_PowerMode_event_mapChange의 lib_audio_set_front_mic 호출 직후 g_lib_dmic_in_buffers[0][1] 및 [1][1](LIB_AUDIO_IN_BUF_MAX_CNT-1 슬롯)을 0으로 초기화하여 구 방향 잔류 샘플이 첫 믹스 블록의 p_mix[15]에 혼입되는 것을 방지.
- 완화_4 (오디오 출력 뮤트): DAC auto mute만 의존하는 현 구조 대신, mapChange 진입 시 SYS_SET_DAC_GF_CTRL(AUDIO, 0)으로 DAC 게인을 0으로 낮추거나 SYS_SET_OUTPUT_CTRL로 OD 출력을 일시 disable → 전환 완료 후 복원. PCM NopStandby는 자극 채널 보호이므로 오디오 출력 채널(FA0_2/FA0_3)은 별도 조치 필요.
- 완화_5 (순서 정리): Normal_PowerMode_event_mapChange 내 권장 순서 — ① ADC ch0/ch2 MUTE write → ② DIO CLK 전환(enable_1/2) → ③ FIFO clear(A0_0/A0_1) → ④ ADC DEC_CTRL 갱신 → ⑤ buffer[*][1] 0 fill → ⑥ ADC ch0/ch2 UNMUTE write. fn_PcmBitStream_Mode_NopStandby는 현재 위치(①이전)를 유지.
