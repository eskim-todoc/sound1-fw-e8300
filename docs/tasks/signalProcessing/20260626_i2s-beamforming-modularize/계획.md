# 모듈화 계획 (③ — 승인 게이트)

**TL;DR**: 코드가 이미 유닛에 거의 대응하므로, **새 추상화 없이 "경계를 명시"**하는 경량 구조화를 제안 — ① 유닛/모듈 **배너 주석**(유닛명·책임·검증라벨·의존성"A는 B 전제"·테스트벡터 지점), ② **유닛/모듈/테스트 맵 문서**(밸리데이션 산출물), ③ 모듈 응집 위한 **경량 그룹화**(섹션·선택적 파일), ④ dead code 정리(선택). 모두 **동작 보존**. 테스트 코드는 미삽입(구조만). **승인 후** ④구현 → 검증.

> [!IMPORTANT]
> 승인 전 제품 코드 변경 금지. 본 작업은 전체 시스템 리팩토링의 **템플릿** — 여기서 정한 패턴을 이후 동일 적용.

---

## 1. 설계 원칙 (방법론)
- **현 체계 특화·단순**. 과도 추상화·범용화·테스트용 군더더기 금지. "2-버퍼만 운용" 자명.
- **독립성 기준 자연 분해** — 유닛=함수, 모듈=테스트 그룹(물리 분리 강제 아님), 의존성=테스트 순서.
- **동작 보존**. 단순 glue 하드코딩 유지.

## 2. 확정 구조 (분석 수렴) — 밸리데이션 산출물

[`분석.md`](분석.md) §2·§3의 **12 유닛 → 6 모듈 → 시스템** + 테스트 순서 DAG를 본 작업의 **공식 유닛/모듈 맵**으로 채택. (M1 믹싱연산·M2 마이크라우팅·M3 HW경로·M4 DMIC수집·M5 I2S·M6 디스패치, 순서 ①M1+M2→②M3→③M4+M5→④M6→⑤시스템.)

## 3. 구현 항목 (④, 동작 보존)

| # | 항목 | 내용 | 비고 |
|---|---|---|---|
| C1 | **유닛 배너 주석** | 각 유닛 함수 위에: `[UNIT] 이름 / 책임 / 검증=unit·integration·logic / 의존=A는 B 전제 / 테스트벡터 지점` | 코드 의미 불변 |
| C2 | **모듈 배너 주석** | 각 모듈의 대표 위치(또는 파일 헤더)에 모듈 구성 유닛·전제 모듈 명시 | |
| C3 | **유닛/모듈/테스트 맵 문서** | `유닛-모듈-테스트맵.md` 신설 — 표·DAG·각 유닛 테스트벡터 케이스(예: U1 i=0..14, i=15 경계) | 밸리데이션 추적성 |
| C4 | **경량 그룹화** | 파일 내 함수를 모듈 단위로 인접 배치(섹션 구분). 물리 이동 최소 | 동작 무관 |
| C5 (선택) | **dead code 정리** | `audio_mix_internal/external_mic_only`(미호출), `I2S_update_state`(미사용), `I2S_handle`(주석) 제거/표기 | 승인 시만 |
| C6 (선택) | **2-버퍼 자명화** | 링버퍼 2-블록·U1 경계 주석/상수 강화 | |

> **테스트 코드는 삽입하지 않는다.** C1·C3에 "향후 이 지점에 테스트 벡터 하드코딩" 위치만 표기(구조 준비).

## 4. 승인 필요 — 결정 사항
- **결정_A (구조화 강도)**: 경량(배너+맵+섹션, 권장) vs 모듈별 파일 신설(이동 큼).
- **결정_B (dead code C5)**: 포함 vs 제외.
- **결정_C (tdc_ 네이밍)**: 신규/손댄 심볼 tdc_ 적용 vs 보류(이전 작업과 일관되게 보류 가능).

## 5. ④ 검증 계획 (단계_4)
- 동작 보존(주석/그룹화는 토큰 불변, dead 제거는 미참조 확인) — 기계 검증 + 페르소나.
- 맵 문서 ↔ 코드 배너 **정합**(유닛명·위치·의존성 일치) — 할루시네이션 0.
- 빌드는 은수님 Eclipse.

## 6. 적용 순서
C3(맵 문서) → C1·C2(배너) → C4(그룹화) → (승인 시) C5·C6 → 검증.
