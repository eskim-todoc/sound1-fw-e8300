# [분석 01] 책임·데이터흐름 매핑가

## 결론
대상 6개 파일(audioMixer.c/h, lib_audio_in.c/h, main.c/h, system_control.c, lib_i2s.c/h) 전체 함수를 표준 방법론으로 분해. 데이터 흐름: DMIC FIFO(HCT_A0_0/A0_1) → g_lib_dmic_in_buffers[2][2][16] 링버퍼 → audio_mix_2_buffers_for_beamforming(DAS) → HEAR_ADDR_AUDIO_MIX → HEAR FC → PCM 출력. 병렬 흐름: I2S FIFO(HCT_A0_5/FA0_5) → lib_g_i2s_buffers[8][16] 링버퍼 → fade 처리 → audio_mix_2_buffers(DMIC1 + I2S) → HEAR_ADDR_AUDIO_MIX. front mic 방향(L/R)에 따라 SW 1샘플(i+1 인덱스) + HW 0.025샘플(FRAC=6) = 총 1.025샘플 지연을 front 채널에만 인가하여 end-fire 정면 빔 정렬. I2S 스트리밍 감지 시 2-DMIC→1-DMIC 자동 전환. 17개 유닛, 7개 모듈로 분해.

## 노트
- 데이터 흐름 전체 경로(DMIC): DMIC1(U7,DIO22/23) → HCT_A0_0(FIFO FA0_0) --[dmic_fifo_ring_copy]--> g_lib_dmic_in_buffers[0][0..1][0..15] → audio_mix_2_buffers_for_beamforming → HEAR_ADDR_AUDIO_MIX → CALL_FUNCTION_CHAIN(agc_preprocessing) → pcmDataOut(). DMIC2(U9,DIO10/17) → HCT_A0_1(FA0_1) --[dmic_fifo_ring_copy]--> g_lib_dmic_in_buffers[1][0..1][0..15] (빔포밍 반대 채널).
- 데이터 흐름 전체 경로(I2S): I2S_MISO(DIO14) → PCM1→IOC1→HCT_A0_5(FIFO FA0_5) --[normal_loop_i2s_monitor/lib_i2s_copy_data_from_fifo]--> lib_g_i2s_buffers[0..7][16](순환 링버퍼) --[I2S_get_buffer_with_fade_in/out]--> faded buffer --[audio_mix_2_buffers(DMIC1[0][0]+I2S_buf)]--> HEAR_ADDR_AUDIO_MIX. 동시에 lib_audio_loopback → HCT_A0_3(DAC1 FIFO).
- 빔포밍 지연 합성: SW 지연 = audio_mix_2_buffers_for_beamforming 내 delay[i+1] 인덱스 (1.000샘플). HW 지연 = ADC dec ctrl FRAC=6 (6/240=0.025샘플, front 채널에만, system_control.c:88-96에서 설정). 합계 1.025샘플 ≈ 64µs ≈ 22mm/343m·s. front mic 미지정(NONE) 시 두 지연 모두 미적용.
- I2S 스트리밍 판단 이중 경로: (현재 활성) normal_loop가 FLAG GPIO + interrupt_flag 직접 폴링 → tdc_i2s_set_streaming_state() 호출. (미사용/주석) I2S_update_state() 상태기계(카운터 기반 10회 확인)는 현재 호출 미사용(main.c:419 주석). 두 경로 혼용 금지 — 리팩토링 시 단일화 필요.
- 2-버퍼 운용 자명성: g_lib_dmic_in_buffers[mic][2][16]에서 BUF_MAX_CNT=2이므로 inner j 루프는 1회만 동작(block[1]←block[0], 이후 block[0]←FIFO). 추가 블록 필요 시 BUF_MAX_CNT 변경으로 자동 확장되나 audio_mix_2_buffers_for_beamforming의 p_delay_buf1 참조는 [BUF_MAX_CNT-1]=1 하드코딩 의존.
- I2S 링버퍼 크기: lib_g_i2s_buffers[FULL_READY_CNT=8][16]. UNDERRUN_CNT=4. INIT/UNDERRUN → 8프레임 누적 시 READY. READY 상태에서 copy_cnt(== 소비 잔량)가 UNDERRUN_CNT(=4) 도달 시 UNDERRUN 전이 + FADE_OUT 시작. normal_loop의 in_pos는 0/1 토글(2-슬롯 동작), lib_i2s_copy_data_from_fifo의 in_pos는 0~7 순환(8-슬롯 동작) — 두 경로가 동시 사용되지 않도록 주의.
- Mapping 연결 상태(live mode)에서는 enable_1_DMIC() 강제 고정(system_control.c:115). ISD 미연결 시 front_mic_hw_delay_config 미수행 → lib_audio_get_front_mic()=NONE → DUAL 상태여도 audio_mix_1_buffer 폴백(pcm_live_stim_dispatch의 else 분기).
