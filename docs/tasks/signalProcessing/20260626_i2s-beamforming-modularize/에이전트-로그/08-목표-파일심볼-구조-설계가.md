# [분석 08] 목표 파일/심볼 구조 설계가

## 결론
6개 파일을 읽어 실재 심볼/라인을 기준으로 분석. 빔포밍·I2S·DMIC·믹서 도메인을 16개 유닛→5개 모듈로 분해. 신규 파일 불필요 — 기존 audioMixer.c/h, lib_audio_in.c/h, lib_i2s.c/h 경계가 이미 도메인과 일치. 유일한 이동 대상: main.c:326의 tdc_copy_DMIC_buffers → lib_audio_in.c (DMIC 버퍼 책임 귀속). tdc_beamforming_hw_delay는 system_control.c의 Normal_PowerMode_event_mapChange 내 L/R switch 블록(L83-105)에 유지. 오디오 입력 선택 디스패처(PCM_LiveStimulation_Mode + normal_loop I2S-DMIC 전환)는 main.c에 유지.

## 노트
- 파일 이동 1건: tdc_copy_DMIC_buffers(main.c:326-353) → lib_audio_in.c로 이동, lib_audio_in.h에 선언 추가, main.h:204 extern 선언 제거. DMIC 버퍼 관리 책임이 lib_audio_in 모듈에 응집됨.
- 신규 파일 불필요: audioMixer.c/h(믹서), lib_audio_in.c/h(DMIC), lib_i2s.c/h(I2S) 경계가 이미 도메인 분리와 일치. system_control.c의 L/R 분기(tdc_beamforming_hw_delay)와 main.c의 디스패처(tdc_audio_input_router)는 각자 파일에 유지.
- tdc_ 접두어: tdc_copy_DMIC_buffers(main.c:326), tdc_i2s_set_streaming_state(lib_i2s.c:174)은 이미 tdc_ 적용. 기존 심볼(audio_mix_2_buffers_for_beamforming, I2S_isStreaming 등)은 behavior-preserving 원칙으로 rename 없음.
- 빔포밍 1.025샘플 지연 구성: SW 1샘플(audioMixer.c:113-128 i+1 오프셋) + HW 0.025샘플(lib_audio_in.h:121-122 LIB_ADC_FRACTIONAL_DELAY_6, LIB_ADC_DEC_CTRL_VAL_0_0250). 두 상수의 의존관계를 각 헤더 주석으로 교차 참조 유지 권장.
- 블록경계 하드코딩 위험: audioMixer.c:128 p_mix[15]=delay_buf1[0]은 LIB_AUDIO_IN_BUF_MAX_CNT=2(lib_audio_in.h:41)에 묵시 의존. BUF_MAX_CNT 변경 시 함께 수정 필요 — 주석으로 명시 권장.
- tdc_i2s_dmic_switcher(main.c:166-189)는 tdc_audio_input_router(main.c:421-474)와 같은 normal_loop 내에서 분리 실행됨: 전환 판정이 믹서 호출보다 한 블록 앞서 발생. 현 동작 유지 목적이므로 구조 변경 없이 '전환→디스패치 1블록 지연' 주석 경고 추가.
- AUDIO_INPUT_RSHIFT(audioMixer.h에서 정의 없음 — definitionsForAlgorithm.h 또는 shared_memory.h 경유 추정): 믹서 4개 유닛 모두 공통 의존. 헤더 포함 경로 확인 후 audioMixer.h 내 include 목록에 명시 권장.
