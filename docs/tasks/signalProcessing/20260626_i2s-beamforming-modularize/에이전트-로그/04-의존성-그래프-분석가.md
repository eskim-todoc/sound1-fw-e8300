# [분석 04] 의존성 그래프 분석가

## 결론
대상 5개 파일을 실독(Read)하여 14개 유닛과 5개 모듈로 분해. 핵심 의존 축은 "오디오 입력 설정 → DMIC 버퍼 수집 / I2S 수신 → 믹서/빔포밍 → 모드 전환 디스패치" 4단 직렬이며, 빔포밍 믹서는 DMIC 버퍼 수집 + front mic 상태 + HW FRAC=6 설정 세 선행 조건을 모두 요구한다.

## 노트
- 테스트 순서(선행 관계): (1) audio-path-init → (2) i2s-init + dmic-enable-control 병렬 → (3) dmic-buffer-copy + i2s-fifo-copy 병렬 → (4) i2s-fade-in/out + front-mic-hw-delay-config 병렬 → (5) beamforming-mix → (6) pcm-livestim-dispatch
- beamforming-mix는 dmic-buffer-copy(g_lib_dmic_in_buffers 유효) + front-mic-state(LEFT/RIGHT 결정) + front-mic-hw-delay-config(HW FRAC=6 부여) 세 선행 조건이 모두 통과되어야 정면 정렬(1.025샘플)이 보장된다.
- i2s-fifo-copy는 lib_g_i2s_buffer_copy_cnt가 FULL_READY_CNT(=8, I2S_BUFFER_FULL_READY_CNT=I2S_BUFFER_UNDERRUN_CNT*2=4*2)에 도달해야 READY 상태로 전이한다. i2s-fade-in/out은 READY 진입 후에만 유효한 출력을 낸다.
- i2s-dmic-switch는 I2S 스트리밍 활성화 시 enable_1_DMIC()로 DMIC 수를 1개로 축소하고, 비활성 시 enable_2_DMICs()로 복원하는 대칭 전환이다. 이 전환이 완료된 시점에서야 pcm-livestim-dispatch의 get_enabled_DMIC_count() 분기가 올바르게 동작한다.
- audio-mix-2-buffers(독립 소스)와 audio-mix-2-buffers-for-beamforming(상관 소스)의 ÷2 유무는 의도적 차이다: 독립 음원은 합산 그대로, 동일 음원 2경로는 >>1(÷2)로 단일 마이크 레벨 정합.
- 블록 경계 처리: beamforming-mix의 p_mix[15]에서 delay_buf1[0](직전 블록 최신 샘플) 사용. 이는 LIB_AUDIO_IN_BUF_MAX_CNT=2 고정에 의존하며, dmic-buffer-copy의 2-버퍼 shift 설계와 직접 결합되어 있다.
- front-mic-hw-delay-config에서 Left_Ear 시 ch2(QCC/DMIC2)에 FRAC=6, Right_Ear 시 ch0(EZ/DMIC1)에 FRAC=6을 적용한다. 이때 lib_audio_set_front_mic()와 SYS_SET_ADC_DEC_CTRL()이 동일 귀 방향으로 일치해야 SW i+1 오프셋과 HW 지연이 같은 채널(front mic)에 누적된다. 불일치 시 빔 방향이 반전된다.
- system_control.c Normal_PowerMode_event_mapChange(L.70)에서 I2S_isStreaming() 조건을 확인하여 맵 변경 시점에도 DMIC 수를 올바르게 설정한다. 즉 i2s-streaming-state는 모드 전환 디스패치 모듈뿐 아니라 이 이벤트 핸들러에도 직접 참조된다.
