## 노트
- 온타깃 테스트 벡터 주입 지점 — 코드 작성은 아님, 함수 시작부 하드코딩 위치 제안만:
- [주입점 1] DAS_산술 — audioMixer.c:111 (p_mix 포인터 선언 직후). p_delay_buf0/buf1/no_delay_buf0 세 배열을 알려진 패턴(예: 동일 상수 시퀀스)으로 채우고 함수 호출 → HEAR_ADDR_AUDIO_MIX[0..15] 읽어 (no_delay[i]+delay[i+1])>>RSHIFT>>1 계산값과 비교. 경계(i=15)에서 delay_buf1[0] 사용 여부 별도 확인.
- [주입점 2] DMIC_링버퍼_복사 — main.c:328 (DMIC1 루프 시작 전). (int _XMEM*)HCT_A0_0 / HCT_A0_1에 알려진 16샘플 기록 후 함수 호출 → g_lib_dmic_in_buffers[0][0]/[1][0] 최신 블록 값 확인, [0][1]/[1][1] 직전 블록 shift 확인.
- [주입점 3] I2S_페이드_처리 — lib_i2s.c:327 (p_src=0 초기화 직후). lib_g_i2s_buffers[out_pos] 배열을 알려진 값으로, lib_g_i2s_buffer_sub_state를 FADE_IN_STEP_0로, lib_g_i2s_buffer_out_pos를 0으로 하드코딩 후 호출 → 반환 포인터[15-i]에 (src[15-i]*coeff[i])>>16 Q24 클리핑 결과 확인.
- [주입점 4] 빔포밍_디스패치 — main.c:420 (함수 진입 직후). I2S_isStreaming()=0, get_enabled_DMIC_count()=2, lib_audio_get_front_mic()=LIB_AUDIO_FRONT_MIC_LEFT 상태 하드코딩 후 호출 → HEAR_ADDR_AUDIO_MIX 결과가 DAS 산술 출력과 일치하는지 확인. Right귀 / I2S 스트리밍 / 폴백 경로를 상태 조합 변경으로 각각 검증.
- 순서 제약: DAS_산술 unit-test 통과 → 빔포밍_디스패치 integration-test 순으로 진행. DMIC_링버퍼_복사는 DAS_산술보다 먼저 또는 독립적으로 수행 가능.
- DMIC_링버퍼_복사의 j 루프(main.c:332-336)는 순수 배열 이동 로직이지만 FIFO 읽기와 묶여 분리 없이 integration-test로 분류. 향후 shift 로직만 별도 함수로 추출하면 unit-test 격상 가능.
- HW_FRAC_지연_설정(LIB_ADC_DEC_CTRL_VAL_0_0250 = FRAC=6/240=0.025샘플)은 SYS_SET_ADC_DEC_CTRL HW 레지스터 직접 설정이라 온타깃 integration-test만 가능. 결과 확인은 실제 마이크 신호 상관 측정 또는 RTT 로그로 대체.
- BUF_MAX_CNT=2 상수(lib_audio_in.h:41)가 변경되면 tdc_copy_DMIC_buffers의 j 루프 반복 횟수 및 DAS 블록 경계 인덱스(p_delay_buf1[0]=직전 블록 [BUF_MAX_CNT-1])가 자동 연동됨. 테스트 벡터 설계 시 이 상수를 기준으로 할 것.
