# 오케스트레이터 입력 — ②분석 (유닛/모듈 분해)

**TL;DR**: [`SW 밸리데이션 계층화 방법론`](../../../../지침/SW%20밸리데이션%20계층화%20방법론.md) 적용. 범위 코드를 실파일 정독으로 유닛/모듈 분해, 의존성 그래프·검증방법 라벨 도출. 할루시네이션 검증 + 방법론 정합 검증.

## 대상 파일 (범위: 빔포밍+I2S+입력설정+모드전환)
- `src/1__cfx/systemControl/audioMixer.{c,h}` (믹서들)
- `src/1__cfx/lib_cfx/lib_audio_in.{c,h}` (입력설정·DMIC enable·front_mic·버퍼)
- `src/1__cfx/systemControl/main.c` (tdc_copy_DMIC_buffers·normal_loop I2S/DMIC 분기·PCM_LiveStimulation_Mode 디스패치·I2S_handle)
- `src/1__cfx/systemControl/system_control.c` (Normal_PowerMode_event_mapChange L/R·HW 지연)
- `src/1__cfx/lib_cfx/lib_i2s.{c,h}` (I2S 상태·버퍼)

## 방법론 핵심 (페르소나 공통 입력)
- 유닛=최소 독립 테스트 단위(결정론 입출력 우선). 유닛이 유닛 사용해도 자동 모듈 승격 아님.
- 모듈=유닛 묶음. 통합테스트=모듈 내 전 유닛 동시 활성화 시 각 유닛 정상 확인.
- 합성: 유닛+유닛=모듈, 모듈+모듈=더 큰 모듈, 전체=시스템. 의존성="A는 B 통과 전제".
- 테스트: 온타깃 CFX(향후 함수 시작점 테스트벡터 하드코딩), 지금은 구조만. 단순은 로직설명.
- 설계: 현 체계 특화·단순(과도 추상화 금지), "2-버퍼 자명". 독립성 기준 자연 분해.

## 분석 페르소나 (10)
1. 책임·데이터흐름 매핑가 — 범위 함수별 책임·입출력·부작용(HW/전역) 표
2. 유닛 식별가(순수로직) — 결정론 입출력 유닛 후보(믹싱 수식·지연정렬·버퍼시프트·I2S 블록복사 등)
3. 모듈 식별가 — 유닛 묶음(오디오입력·빔포밍·I2S·모드전환 모듈 후보)
4. 의존성 그래프 분석가 — 유닛/모듈 간 의존·테스트 순서("A는 B 전제")
5. 검증방법 라벨링가 — 각 요소 [유닛테스트]/[통합테스트]/[로직설명] + 온타깃 테스트벡터 주입 지점
6. HW결합·CFX제약 분석가 — _XMEM·레지스터·FIFO·HEAR_ADDR·chess_loop 결합 → 순수유닛 불가 항목
7. 단순·특화 균형 검토가 — 과도추상화·테스트용 군더더기 위험, "2-버퍼 자명" 유지
8. 목표 파일/심볼 구조 설계가 — 파일 조직·tdc_ 네이밍·무엇을 어디에
9. 동작보존 위험 감별가 — 재구조화의 동작변경 위험
10. 밸리데이션 계층 종합가 — 유닛→모듈→시스템 계층 + 테스트 순서 조립

## 검증 페르소나 (2, adversarial)
1. 할루시네이션 검증 — 분해가 인용한 file:line·심볼이 실재하는지
2. 방법론 정합 검증 — 분해가 방법론(유닛/모듈 정의·자동승격 금지·통합테스트 정의·단순특화)에 맞는지
