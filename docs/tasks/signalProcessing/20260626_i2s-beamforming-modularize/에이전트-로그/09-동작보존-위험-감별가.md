## 노트
- [HIGH-1 보류 권고] das_mixer 언롤 폼 변경 금지 — audioMixer.c:109-129. audio_mix_2_buffers_for_beamforming은 16샘플을 수동 언롤(chess_loop_range 없음). p_mix[0]~[14]는 p_delay_buf0[i+1], p_mix[15]만 p_delay_buf1[0](직전 블록 경계 접합). 루프로 묶으면 (a) 경계 조건을 if 분기로 처리해야 하고 (b) chess_loop_range 힌트 미삽입 시 HW loop-stack 오버플로 가능. 16-샘플 블록 크기를 전제하는 언롤 구조 그대로 유지 권고.
- [HIGH-2 보류 권고] normal_loop 인라인 I2S 복사와 lib_i2s_copy_data_from_fifo의 in_pos 충돌 — main.c:154-160 vs lib_i2s.c:294-298. 수동 복사는 lib_g_i2s_buffer_in_pos를 0↔1 toggle(2-슬롯). lib_i2s_copy_data_from_fifo는 동일 변수를 0→(I2S_BUFFER_FULL_READY_CNT=8)-1 mod 증가. 두 경로는 같은 전역 lib_g_i2s_buffer_in_pos를 다른 방식으로 관리한다. 수동 복사를 lib_i2s_copy_data_from_fifo로 대체하면 lib_g_i2s_buffer_out_pos(main.c:434-440: 0↔1 toggle)와 in_pos 범위가 어긋나 잘못된 버퍼 슬롯 참조. 통일 전 out_pos 토글 로직도 함께 mod-8로 변경해야 안전.
- [HIGH-3 보류 권고] front_mic SW 값 + HW DEC_CTRL 원자성 — system_control.c:87-103. lib_audio_set_front_mic(LEFT/RIGHT)와 SYS_SET_ADC_DEC_CTRL(AUDIO, 0, ...), SYS_SET_ADC_DEC_CTRL(AUDIO, 2, ...)는 동일 switch-case 블록 안에서 연속 실행. 분리하면 그 사이 PCM 인터럽트가 끼어들어 SW front_mic=LEFT인데 HW 지연=RIGHT 설정인 1프레임 창이 생겨 빔포밍 방향 순간 반전. 반드시 동일 블록 내 원자 유지.
- [MEDIUM-4] tdc_copy_DMIC_buffers 시프트→FIFO 쓰기 순서 보존 — main.c:329-352. 각 샘플 i에 대해 j-루프(block[1]=block[0])가 완료된 뒤 FIFO→block[0] 쓰기. 선 FIFO 읽기·후 시프트로 순서 역전 시 block[0] 직전 데이터가 block[1]로 복사되지 않아 빔포밍 p_delay_buf1[0] 접합이 깨짐. chess_loop_range(LIB_AUDIO_IN_BUF_MAX_CNT-1, LIB_AUDIO_IN_BUF_MAX_CNT-1)=(1,1) 고정도 유지 필수.
- [MEDIUM-5] PCM_LiveStimulation_Mode 내 CALL_FUNCTION_CHAIN 누락 위험 — main.c:474. CALL_FUNCTION_CHAIN(HEAR_FC_agc_preprocessing)는 I2S·DUAL·SINGLE·NONE 모든 분기 후 함수 말미 단 1회. 믹서 dispatch를 별도 함수로 추출 시 이 호출을 새 함수 안에 두면 호출부에서 중복 기동 위험, 누락하면 HEAR_LiveStimulation_Mode의 g_interrupt_flags.function_chain0가 영원히 0이 되어 무한 대기. 추출 함수는 믹서 선택만, CALL_FUNCTION_CHAIN은 호출부(PCM_LiveStimulation_Mode)에 잔류 권고.
- [MEDIUM-6] I2S 상태 즉각 전환 vs I2S_update_state() 디바운스 — main.c:163/178 vs lib_i2s.c:184-261. 현재는 FLAG 핀+인터럽트 확인 즉시 tdc_i2s_set_streaming_state로 상태 전환(디바운스 없음). 주석 처리된 I2S_update_state()(main.c:419)는 LIB_I2S_ENABLE_CHECK_CNT=10회 확인 지연을 거친다. 상태 관리를 I2S_update_state()로 일원화하면 DMIC 전환 타이밍이 최대 10프레임 늦어져 전환 구간 빔포밍/단일 믹스 불일치 창이 발생.
- [LOW-7] I2S_get_buffer_with_fade_out_process 내 out_pos 랩 하드코딩 — lib_i2s.c:386. `if (lib_g_i2s_buffer_out_pos == 4)` 리터럴 4. fade-in 경로(L333)는 I2S_BUFFER_FULL_READY_CNT(=8)로 wrap. I2S_BUFFER_UNDERRUN_CNT=4 현재 값에서는 우연히 동작하지만, UNDERRUN_CNT 변경 시 fade-out 경로만 오동작. 상수화 권고: I2S_BUFFER_FULL_READY_CNT 또는 I2S_BUFFER_UNDERRUN_CNT로 교체.
- [LOW-8] fifo_fill_zero 언롤 블록 크기 하드코딩 — main.c:113-124. chess_unroll_loop(*) + px(8개)+py(8개) 두 포인터로 16개 병렬 기입. df_inputADC_DataBuffLength=16 묵시적 전제. 함수 이동만이라면 안전; 블록 크기 변경 시 포인터 분할 재계산 필요.
- [INFO] I2S_handle 이중 lib_i2s_copy_data_from_fifo 호출 현재 비활성 — main.c:359/414. 함수 시작(L359)·종료(L414)에 각 1회씩 FIFO 복사하는 인터럽트-안전 이중 읽기 패턴. 현재 I2S_handle 호출부(main.c:422)가 주석처리. 재활성화 시 한 번만 호출로 단순화하면 인터럽트 경쟁 창에서 FIFO 데이터 유실 가능. 이중 호출 의도를 코드 주석으로 문서화 권고.
