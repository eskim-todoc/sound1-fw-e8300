## 노트
- --- 2-버퍼 가시성 확인 ---
- DMIC: g_lib_dmic_in_buffers[LIB_AUDIO_IN_DMIC_ENABLE_COUNT][LIB_AUDIO_IN_BUF_MAX_CNT=2][16] (lib_audio_in.h:150, lib_audio_in.c:19). tdc_copy_DMIC_buffers의 시프트 로직과 audio_mix_2_buffers_for_beamforming의 3-인수 시그니처(p_delay_buf0=block[0], p_delay_buf1=block[1], p_no_delay_buf0)에서 2-버퍼 운용이 한눈에 자명. 양호.
- I2S: lib_g_i2s_buffers[I2S_BUFFER_FULL_READY_CNT=8][16] (lib_i2s.c:19, lib_i2s.h:43). 2-버퍼가 아니라 8-슬롯 링버퍼 — 이는 underrun 복구(FADE IN/OUT 각 UNDERRUN_CNT=4 프레임 확보) 목적의 의도된 설계. 이상 없음.
- --- 과분해 경고 (5건) ---
- [경고1] I2S_handle(main.c:355-415): 현재 main.c:423에서 주석 처리(`// I2S_handle();`)되어 dead code. 내부에 audio_mix_2_buffers·lib_audio_loopback·I2S_get_buffer_with_fade_in/out_process 호출 포함. 이를 새 유닛으로 명세하거나 분해하는 것은 불필요 — dead code 확인 후 제거 또는 부활 여부만 결정하면 됨.
- [경고2] tdc_copy_DMIC_buffers 내 j-루프(main.c:332-336): BUF_MAX_CNT=2이므로 j=0 단 1회 실행 — 실질적으로 `block[1]=block[0]` 단 1줄. `shift_block()` 헬퍼 함수로 추출하거나 루프를 전개하는 것은 과분해/과전개 모두 불필요. 현행 유지.
- [경고3] PCM_LiveStimulation_Mode의 L/R 대칭 분기(main.c:454-468): Left·Right case가 대칭이라 `dispatch_beamforming(front_mic, rear_mic)` 같은 추상 헬퍼로 분리하려는 유혹이 있으나 인수 2개짜리 호출 래퍼를 만드는 것은 과분해. 지금처럼 인라인 `if/else if` 유지가 적절.
- [경고4] lib_g_i2s_buffer·lib_g_i2s_buffer_prev1·lib_g_i2s_buffer_prev2(lib_i2s.c:13-15): 선언은 있으나 현재 활성 코드 경로에서 사용 없음(I2S_handle dead code와 연관). 이를 위한 별도 유닛 명세 불필요 — 삭제 검토 대상.
- [경고5] audio_mix_internal_mic_only·audio_mix_external_mic_only(audioMixer.c:7-30): HCT_A0_0·HCT_A0_1을 직접 읽어 HEAR_ADDR_AUDIO_MIX에 쓰는 함수이나, 현재 main.c·system_control.c의 활성 호출 경로에서 참조 없음. 유닛 명세에서 제외. 레거시 여부 확인 후 삭제 또는 주석 처리 권고.
- --- PCM_LiveStimulation_Mode 인덱스 명확성 ---
- main.c:457·462에서 `[LIB_AUDIO_IN_BUF_MAX_CNT - 2]`(=0, 현재블록)·`[LIB_AUDIO_IN_BUF_MAX_CNT - 1]`(=1, 직전블록) 표기 사용. 값은 정확하나 독자 입장에서 `[0]`·`[1]` 또는 `LIB_AUDIO_BUF_CURRENT`·`LIB_AUDIO_BUF_PREV` 같은 named constant가 더 직관적. 기능 변경 없는 가독성 개선 사항 — 본 분석 범위 메모로 기록.
