# I2S·빔포밍 모듈화 — 요구사항

**TL;DR**: 기능 검증된 I2S·빔포밍 코드를 **현 체계에 특화**(예: 빔포밍은 버퍼 2개만 운용하는 구조가 한눈에 보이게)하면서, 동시에 **의료기기 SW 밸리데이션 관점의 독립 유닛/모듈 + 유닛별 테스트 가능 구조**로 정리한다. 과도한 확장성·빙빙 도는 함수 분리는 지양. 전체 시스템 리팩토링의 **출발 템플릿**이므로 시작이 중요. 다중 페르소나, 할루시네이션 0, 문서화.

---

## 1. 배경·목표
- 은수님 I2S·빔포밍 구현은 기능 정확성 검증 완료([`20260625_beamforming-impl-review`](../20260625_beamforming-impl-review/)) + 상수화/주석 리팩토링 완료([`20260625_beamforming-refactor`](../20260625_beamforming-refactor/)).
- 이번 작업 = **구조(아키텍처) 재정리**:
  - **특화·단순**: 현 2-DMIC/2-버퍼/단일 I2S 구조에 맞춰 "딱 이렇게 하려는 로직이구나" 하고 보이게. 간단한 건 하드코딩, 불필요한 함수 추출·추상화 배제.
  - **밸리데이션 친화**: 유닛/모듈을 명확히 세분화하고 각 유닛이 **독립적·이해 쉽고·테스트 가능**하게.
- **범위 = I2S + 빔포밍 우선**. 괜찮으면 전체 시스템으로 순차 확대 → **본 작업이 패턴 정의**.

## 2. 목표 (요구사항)
- [ ] **요구사항_1**: 현 I2S·빔포밍 코드의 책임/의존성/데이터흐름을 분석해 **유닛/모듈 경계 후보** 도출.
- [ ] **요구사항_2**: "특화·단순"과 "테스트 가능 유닛 분리"의 **균형 잡힌 목표 구조** 설계(과도 추상화 없이).
- [ ] **요구사항_3**: 각 유닛/모듈의 **단위 테스트 전략**(밸리데이션 관점) 정의.
- [ ] **요구사항_4**: 동작 보존을 전제로 한 **단계적 적용 계획** + 전체 시스템 확대 시 재사용할 **패턴 정의**.

## 3. 제약
- **동작 보존**(behavior-preserving) 전제. 기능 변경 아님.
- 4단계: ①요구사항→②분석→③계획→**승인**→④구현+검증. 승인 전 제품 코드 변경 금지.
- 신규 심볼 `tdc_` 접두어 검토. CFX 제약(`_XMEM`/`chess_loop`/HW 레지스터) 고려.
- 다중 페르소나(분석·검증) + 할루시네이션 검증 노드. 실코드 정독 기반.

## 4. 확정된 설계 방향 (인터뷰 결과 2026-06-26)

- **결정_1 (범위)** ✅: **빔포밍 코어 + I2S + 오디오 입력설정(`configure_audio_path_all`·`enable_1/2_DMIC`) + 모드전환(`normal_loop` I2S/DMIC 분기·`PCM_LiveStimulation_Mode` 믹싱 디스패치)** = 자족적 서브시스템. (입력/믹싱 전체·ADC 경로는 후속 시스템 확대.)
- **결정_2 (테스트 모델)** ✅: **온타깃 CFX 테스트**가 최종 형태 — 향후 **유닛 함수 시작점에 테스트 벡터를 하드코딩**해 자극-응답 검증. **단, 지금은 테스트 코드 미삽입** — "테스트 가능한 구조"만 준비. **테스트만을 위한 불필요 로직 추가 금지.** 단순한 유닛은 **로직 설명(문서)**으로 검증 대체 가능.
- **결정_3 (계층화)** ✅: **SW 밸리데이션 생명주기**로 계층화 —
  `유닛 구현 → 유닛 테스트 → 통합 계획 → 통합(유닛→모듈) → 통합 테스트 → 시스템 테스트`.
  - **유닛** = 독립적·자족적(단독 자극-응답 검증 가능). 순수 로직(믹싱 수식·지연 정렬·버퍼 시프트 등).
  - **모듈/통합** = 서로 의존하거나 HW에 결합된 것(FIFO/레지스터/디스패치). → **통합 테스트** 수준에서 검증.
  - "단순·특화"와 "테스트 유닛"의 균형 = **독립성 기준 자연 분해**(테스트 위한 과도 추상화 아님). 단순 glue는 하드코딩, "2-버퍼만 운용" 자명하게.

> [!IMPORTANT]
> 본 작업은 [`docs/지침/SW 밸리데이션 계층화 방법론.md`](../../../지침/SW%20밸리데이션%20계층화%20방법론.md)를 **표준 방법론으로 적용**한다(은수님 정의). 핵심: 유닛이 유닛을 써도 자동 모듈 승격 아님(의존성=테스트 순서 "A는 B 통과 전제"), 통합 테스트=모듈 내 전 유닛 동시 활성화 시 각 유닛 정상 확인, 합성 유닛→모듈→시스템. 향후 전체 시스템 확대 시에도 동일 적용.
