# 오케스트레이터 입력 — 빔포밍 3단계 페르소나

**TL;DR**: 데이터시트 그라운딩(`조사_데이터시트-그라운딩.md`)을 공통 입력으로, 단계1 분석(12) → 단계2 토론(10) → 단계3 검증(12) 페르소나를 fan-out. 각 노드는 결론만 구조화 반환, 본 폴더 `01~NN-<페르소나>.md`로 기록.

---

## 공통 입력 (모든 페르소나)
- `조사_데이터시트-그라운딩.md` 전문 (사실 베이스, 페이지 인용 포함).
- 분석 목표: (1) 채널 간 고유 지연 유무, (2) HW 내부 샘플링 지연 가능 여부, (3) 필요 상대 지연 정량, (4) 2-DMIC 전환 방향.

## 단계 1 — 분석 페르소나 (12)
1. DMIC HW 인터페이스 분석가 — 클럭/엣지/pad 라우팅, RE·FE 반주기 스큐
2. Decimation 필터 체인 분석가 — WDF 5/7/11차, group delay, band select
3. 채널 스큐 분석가 — (0,2) vs (1,3) 1/8 샘플 시분할 스큐 부호·크기
4. 샘플링 지연 레지스터 분석가 — DELAY_INTEGER/FRACTIONAL 의미·범위·해상도
5. 빔포밍 이론 분석가 — delay-and-sum, end-fire, steering, null
6. 음향 기하 분석가 — 마이크 배치(각 귀 front mic), 착용 방향, 타깃 음원
7. IOC/FIFO 경로 분석가 — IN→FIFO, double-access, 인터럽트
8. 타이밍 산술 분석가 — 16kHz, 62.5µs, 2.14cm, 0.933 샘플, fractional 해상도
9. 현재 펌웨어 구성 분석가 — 1-DMIC 현황, 2-DMIC 분기 차이
10. Filter Engine 대안경로 분석가 — low-group-delay/undecimated 경로
11. 전력·자원 영향 분석가 — 2nd DMIC/ADC/decimation 활성화 비용
12. QCC 공유 마이크 제약 분석가 — DMIC2 공유, SPI 프로토콜, 10ms 대기

## 단계 2 — 토론 페르소나 (10)
단계1 종합을 입력으로 쟁점별 찬반·교차검토:
1. 지연 부여 방식 논쟁 — HW DEC delay vs SW 버퍼 시프트
2. 정밀도 논쟁 — 정수 1샘플 근사 vs fractional 0.933 정밀
3. 스큐 보정 논쟁 — 고유 1/8 스큐를 예산에 포함/상쇄
4. RE/FE 통일 논쟁 — 반주기 스큐 유의미성
5. 어느 마이크 지연 논쟁 — Left/Right front 역할·타깃 방향
6. 채널 배치 논쟁 — DMIC을 어느 입력채널(1/2)에 둘지 재배치 여부
7. 빔 형상 논쟁 — end-fire vs broadside, 2cm에서 지향성 한계
8. 대안경로 논쟁 — Filter Engine vs decimation 경로
9. 운용 제약 논쟁 — QCC 공유, 전화통화 시나리오
10. 종합 합의 도출자 — 쟁점 수렴, 잔여 불확실성 정리

## 단계 3 — 검증 페르소나 (12, adversarial)
각자 핵심 주장 1개를 **반증 시도**(데이터시트 근거로 refute, 불확실하면 refuted):
1. "채널쌍 1/8 스큐 존재" 반증
2. "DELAY_INTEGER가 1/8 샘플 단위" 반증
3. "DELAY_FRACTIONAL 0~SFCR, 서브-1/8 해상도" 반증
4. "DMIC도 fractional delay 지원" 반증
5. "필요 지연 0.933 샘플" 산술 반증
6. "SW 버퍼 불요, HW만으로 충분" 반증
7. "16kHz 1샘플=2.14cm" 반증
8. "RE/FE 스큐는 출력샘플 대비 무시 가능" 반증
9. "짝수 채널(0,2)이 먼저 도착" 부호 방향 반증
10. "2-DMIC 활성화로 빔포밍 데이터 경로 성립" 반증
11. "decimation 절대 group delay는 동일대역 상쇄" 반증
12. "QCC 공유가 상시 빔포밍을 제약" 반증

## 산출 규칙
- 각 노드 → `01~NN-<페르소나>.md` (결론·근거·페이지·불확실성).
- `인덱스.md` 행 추가.
- 단계 종합 → `분석.md`/`토론.md`/`검증.md`.
