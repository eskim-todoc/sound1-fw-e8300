# [단계1·분석 06] 음향 기하 분석가 — E8300 DMIC 빔포밍 타이밍 전문

**신뢰도**: medium

## 결론
착용 시 정면 음원 기준, Left ear front mic(U9/DMIC2/ch2)가 Right ear front mic(U7/DMIC1/ch1)보다 먼저 노출된다. 따라서 Right(ch1)를 지연시켜야 정합되며, HW 고유 스큐(ch2가 ch1보다 1/8 샘플 선행)를 반영하면 DELAY_INTEGER=6, DELAY_FRACTIONAL=14로 ch1에만 설정하면 SW 버퍼 없이 0.8079 샘플(≈50.5µs) 보정이 가능하다. 이 결론은 착용 기하가 "앞=Left"임이 확인된 경우에만 성립하며, 반대 기하(앞=Right)라면 필요 지연이 1.058샘플로 DELAY_INTEGER 최대(7/8=0.875) 초과이므로 SW 1샘플 오프셋이 추가로 필요하다.

## 발견(근거)
- **착용 시 정면 음원에 먼저 노출되는 마이크는 Left ear front mic(U9/DMIC2)다.**
  - 근거: 이미지 '착용 시 앞 방향 마이크 위치 정보.png' 및 '현재 상태 정리 및 복기.md'에 'Left인 경우를 예로 들면 DMIC2[1]==DMIC1[0]' 기술 — DMIC2(Left)가 1샘플 선행함을 명시. 착용 그림에서 Left ear 기기가 정면(앞)에 위치. 따라서 정면 음원 → Left mic이 먼저 수음. (착용 시 앞 방향 마이크 위치 정보.png; 현재 상태 정리 및 복기.md)
- **빔포밍 정합을 위해 지연시켜야 할 채널은 Right(ch1, DMIC1, U7)다.**
  - 근거: Left(DMIC2)가 먼저 도달 → 늦게 도달하는 Right를 기하 지연만큼 추가 지연시켜야 두 채널이 동일 음원의 동일 위상에 정렬됨. end-fire 최대 지연 = d/c = 0.02m/343m/s = 58.31µs = 0.9329 샘플 (사실 F). (사실 F (HW 기하 산술))
- **HW 채널 고유 스큐: DMIC2(Left/ch2)가 DMIC1(Right/ch1)보다 1/8 샘플(7.81µs) 먼저 IOC에 도착한다.**
  - 근거: 사실 A(HW p.222): ADC0·ADC2 데이터가 ADC1·ADC3보다 1/8 샘플 period ahead. 사실 B(HW p.445 §14.4): 짝수 채널(0,2)이 홀수 채널(1,3)보다 먼저 출력. 현재 매핑: DMIC2=ch2(짝수), DMIC1=ch1(홀수) → ch2가 ch1보다 1/8 샘플 선행. (HW p.222 (사실 A), HW p.445 §14.4 (사실 B))
- **ch1(Right)에 설정해야 할 DEC 지연값: DELAY_INTEGER=6, DELAY_FRACTIONAL=14 (결과 0.8083 샘플, 50.5µs).**
  - 근거: 필요 순수 기하 지연 0.9329 샘플 - 고유 스큐 보정 0.125 샘플 = 0.8079 샘플. DELAY_INTEGER=6 → 6/8=0.75 샘플(46.88µs). 나머지 0.0579 샘플을 DELAY_FRACTIONAL로: SFCR=29(16kHz/3.84MHz, 사실 D), 1/8 샘플 내부 30분할 → 0.0579×(29+1)×8≈13.9 → DELAY_FRACTIONAL=14. 합산 0.75+14/(8×30)=0.8083 샘플(50.52µs). DELAY_INTEGER 범위(0~7) 내, 단일 HW 설정으로 완결. (사실 D (HW p.450-451), 사실 E (HW §18.2 p.563))
- **고유 스큐를 무시하고 ch1에 단순 DELAY_INTEGER=7(0.875샘플)만 적용하면 오차 57.8µs - 고유스큐 보정 없음 → 실제 보정량은 기하 필요값 대비 약 0.058 샘플(3.6µs) 부족하다.**
  - 근거: 7/8=0.875 샘플(54.69µs) < 필요 0.9329 샘플(58.31µs). 잔차 0.058 샘플=3.62µs는 DELAY_FRACTIONAL≈14로 해결 가능. 단 고유 스큐 1/8 샘플(7.81µs)을 무시하면 과보정: 실질 보정량 0.875+0.125(스큐)=1.0 샘플로 기하 필요값 0.9329를 초과. (사실 A/B, 사실 D, 사실 G)
- **DMIC FE(DMIC2) vs RE(DMIC1) 에지 오프셋은 오버샘플링 클럭 반주기(≈0.13µs = 0.002 샘플)로, CIC 필터 후 무시 가능한 수준이다.**
  - 근거: ADCCLK=3.84MHz → 반주기=1/(3.84M)/2=0.13µs. 16kHz 샘플주기 62.5µs 대비 0.21%. 6th order CIC 필터(사실 E, HW §18.2 p.563)가 수십~수백 클럭 윈도우로 적분하므로 단일 클럭 오프셋은 출력 샘플 타이밍에 실질 영향 없음. (사실 E (HW §18.2 p.563))
- **만약 앞 방향이 Right(DMIC1/ch1)라면, 필요 DEC 지연이 1.058 샘플로 DELAY_INTEGER 최대(7/8=0.875 샘플)를 초과하여 HW 단독 설정 불가 — SW 1샘플 오프셋이 추가로 필요하다.**
  - 근거: 시나리오_2: 기하 지연 0.9329 + 고유 스큐 0.125 = 1.0579 샘플 필요. DELAY_INTEGER 최대=7/8=0.875(사실 D, 사실 G). 초과분 0.183 샘플은 HW 레지스터 범위 밖 → SW FIFO 시프트(1샘플 정수부) + 나머지 HW DELAY_FRACTIONAL 조합 필요. (사실 D (HW p.450-451), 사실 G)

## 미해결 질문
- 착용 기하 확정 필요: 이미지와 '현재 상태 정리 및 복기.md'는 Left=앞임을 강하게 시사하지만, 실기기 착용 방향(Left 기기가 실제로 얼굴 전방에 오는지)을 물리적으로 재확인해야 모든 부호가 확정된다.
- DMIC2(ch2) 활성화 시 QCC와의 DMIC2 공유 충돌 해소 방안: SPI 프로토콜 10ms 대기 및 QCC 전화 통화 중 빔포밍 비활성화 정책이 선행 확정되어야 한다.
- decimation 절대 group delay(ch1과 ch2 각각의 군지연)가 동일 대역(0K_8K) 설정에서 정확히 상쇄되는지 실측 또는 데이터시트 추가 확인 필요 — 상쇄되어야 사실 A/B의 상대 스큐만이 유효하다.
- DMIC2 FE 캡처와 DMIC1 RE 캡처의 에지 오프셋(0.13µs)이 CIC 필터 구현상 실제로 상쇄되는지 시뮬레이션 또는 데이터시트 명시 확인 필요 (현재는 무시 가능 추정).
- DELAY_INTEGER=6, DELAY_FRACTIONAL=14 설정이 DMIC 채널(ADC가 아닌 DMIC 경로)에서도 동일하게 적용되는지 사실 E의 'ADC와 동일 fractional delay 지원' 주장을 펌웨어 레지스터 매크로(SYS_SET_ADC_DEC_CTRL)로 DMIC 채널에 직접 적용 가능한지 코드 레벨 확인 필요.
