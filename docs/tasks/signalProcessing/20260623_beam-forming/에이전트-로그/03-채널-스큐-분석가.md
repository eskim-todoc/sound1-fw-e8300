# [단계1·분석 03] 채널 스큐 분석가 — E8300 decimation 시분할 고유 스큐 정밀 규명

**신뢰도**: high

## 결론
사실 A·B의 결론은 동일: ch2(DMIC2, Left)가 ch1(DMIC1, Right)보다 1/8 샘플(=7.8µs) 먼저 FIFO에 도착하는 고유 스큐가 존재한다. 빔포밍에 필요한 총 상대 지연은 0.933 샘플이며, 이 고유 스큐(+1/8)를 소거하고 음향 지연 0.933을 얹으려면 ch1에 1/8 + 0.933 ≈ 1.058 샘플이 필요하나 HW 최대가 7/8이므로 "고유 스큐를 지연 예산에 흡수"하는 방향(ch2를 7/8+fractional로 지연)이 현실적이다.

## 발견(근거)
- **사실 A·B의 (0,2) vs (1,3) 1/8 샘플 스큐 — 부호: 짝수 채널(0,2)이 홀수 채널(1,3)보다 먼저 도착. 크기: 정확히 1/8 샘플(=62.5µs/8=7.8µs).**
  - 근거: 사실 A(HW p.222): 'ADC0·ADC2 데이터가 ADC1·ADC3보다 1/8 sample period ahead 도착.' 사실 B(HW p.445 §14.4): 'time multiplexed into two pairs (0,1)·(2,3), resulting in longer processing delays for channels 1,3.' 두 사실이 동일 현상을 서로 다른 관점(Filter Engine 입력 vs decimation WDF 시분할)에서 기술한 것이므로 부호와 크기는 동일하게 수렴: 짝수 선도(先到), 홀수 후도(後到), 차이=1/8 샘플. (HW p.222(사실 A), HW p.445 §14.4(사실 B))
- **현재 매핑에서 DMIC2(ch2, Left ear front)가 DMIC1(ch1, Right ear front)보다 1/8 샘플 먼저 FIFO에 도착한다.**
  - 근거: 채널 매핑(그라운딩 문서 §1): AUDIO_MUX 소스 순서 = (ch3=ADC3 | ch2=DMIC2/FE | ch1=DMIC1/RE | ch0=ADC0). ch2=짝수, ch1=홀수. 사실 B에 의해 짝수(ch2)가 홀수(ch1)보다 1/8 샘플 먼저 출력. IOC→FIFO 매핑(IN1→FA0_0(MIC0)=DMIC1, IN2→FA0_1(MIC1)=DMIC2)에도 동일하게 적용. (그라운딩 문서 §1(lib_audio_in.h 인용), HW p.445(사실 B))
- **빔포밍에 필요한 음향 상대 지연은 정확히 0.933 샘플(58.3µs). '1샘플'은 근사이며, 7/8+fractional로 HW에서 정밀 구현 가능.**
  - 근거: 사실 F: d=2cm, c=343m/s → end-fire 최대 지연=58.3µs. 16kHz 샘플주기=62.5µs → 필요 지연=58.3/62.5=0.933 샘플. 사실 G: DELAY_INTEGER 최대=7/8=0.875 샘플(54.7µs). 0.933-0.875=0.058 샘플=3.6µs를 DELAY_FRACTIONAL로 보정. SFCR≈29이므로 해상도≈1/(8×30)≈0.26µs → 3.6µs는 ~14 fractional steps로 도달 가능. (사실 D(HW p.450-451), 사실 F, 사실 G)
- **고유 스큐(ch2가 1/8 먼저)를 빔포밍 지연 예산에 포함할 때, 나중 도착 채널(ch1=DMIC1=Right)에 총 (0.933+1/8)=1.058 샘플을 가산해야 하나 HW 최대 7/8=0.875이므로 단방향 ch1 지연 단독 적용은 불가. 대신 ch2(DMIC2=Left)에 (0.933-1/8)=0.808 샘플을 지연시키는 방향이 현실적.**
  - 근거: 사실 D: DELAY_INTEGER 최대=ADC_INTEGER_DELAY_7=7/8 샘플. 사실 G: 단일 DEC delay로 1.0 샘플 이상 불가. 지연 방향 산술: 음원이 Left(DMIC2)에 먼저 닿는 end-fire 기준, Right(DMIC1)를 지연시켜야 한다. 그러나 ch2 고유 스큐(+1/8 선도)가 이미 Left를 추가로 앞당긴다. 필요 순방향 설계: DMIC2(Left)를 0.808 샘플(=0.933-0.125) 지연 → ch2에 DELAY_INTEGER=6(=6/8=0.75) + DELAY_FRACTIONAL≈(0.058샘플≈14 steps) 적용. 이 방법은 HW 한계 내에 있음(0.808 < 7/8=0.875 미만은 아니므로 재산출 필요 — openQuestions 참조). (사실 D(HW p.450-451), 사실 G, 사실 B(HW p.445))
- **DMIC의 RE/FE 엣지 차이(DMIC1=RE, DMIC2=FE)는 오버샘플링 클럭(3.84MHz) 반주기=130ns의 추가 스큐를 유발하나, 출력 샘플 단위(62.5µs)에 비해 2000배 작아 빔포밍 오차에서 무시 가능.**
  - 근거: 사실 E(HW §18.2 p.563): DMIC_RE=rising edge 캡처, FE=falling edge 캡처. 클럭 공유(DIO22, 3.84MHz) → FE는 RE보다 1/(2×3.84MHz)=130ns 늦게 캡처. 16kHz 샘플주기=62.5µs 대비 130ns=0.002 샘플 수준 → 빔포밍 지연 예산(목표 정밀도 ~0.26µs=1 fractional step)에서 무시 가능 범위. 단, 이론적으로 ch2의 고유 스큐를 1/8 샘플(7.8µs) + 130ns로 봐야 하나 실용적으로 130ns는 absorb. (사실 E(HW §18.2 p.563), 사실 D(HW p.450-451))
- **현재 DELAY_INTEGER=0, DELAY_FRACTIONAL=0 설정은 고유 1/8 샘플 스큐를 그대로 방치한 상태. 2-DMIC 빔포밍 전환 시 반드시 보정 필요.**
  - 근거: 그라운딩 문서 §1: 현재 설정 ADC_INTEGER_DELAY_0, LIB_SAMPLE_FRACTIONAL_DELAY=0 (lib_audio_in.h:96-98). 사실 B에 의해 ch2(DMIC2)가 ch1(DMIC1)보다 1/8 샘플 선도 상태가 보정 없이 유지됨. 현재 1-DMIC(ch1만) 구성에서는 무관하나 2채널 사용 시 스큐가 빔포밍 지향 오차로 직결. (그라운딩 문서 §1(lib_audio_in.h:96-98 인용), HW p.445(사실 B))

## 미해결 질문
- ch2에 0.808 샘플 지연 적용 재산출 필요: 0.808 샘플 = DELAY_INTEGER=6(=6/8=0.750) + DELAY_FRACTIONAL=(0.808-0.750)×(SFCR+1)=(0.058×30)≈1.74 → round=2 steps(단, SFCR=29 확인 필요). 0.808 < 7/8=0.875이므로 HW 내 구현 가능하나, 음원 방향(Left vs Right end-fire 기준) 확정 후 ch1/ch2 어느 쪽을 지연할지 방향 결정이 선행돼야 함.
- 음원이 Right(DMIC1) 쪽에 먼저 닿는 end-fire 방향도 고려해야 한다. 이 경우 ch2(Left)를 지연할 필요가 없고 오히려 ch1(Right)에 지연을 주어야 하는데, 고유 스큐(ch2 선도 1/8)와 방향이 반대가 되어 보정 스큐(1/8)를 추가로 가산해야 한다 → ch1에 0.933+0.125=1.058 샘플 필요, HW 불가. 실제 착용 시 음원 방향별 지연 방향 사전 결정 필요.
- decimation 절대 group delay의 채널별 동일성 확인 필요: 사실 B에서 두 쌍(0,1)·(2,3)이 동일 대역이면 절대 group delay는 같고 상대 1/8 스큐만 남는다는 가정이 성립하는지 — HW p.445 §14.4의 원문에서 'longer processing delays for channels 1,3'이 absolute latency 차이인지 relative skew인지 명확히 재확인 필요.
- DMIC2(FE) ch2의 고유 1/8 스큐가 오버샘플링 단계(ADC 입력 동기화 후)에서 발생하는 것인지, 아니면 CIC pre-decimation 필터 자체의 시분할 스큐인지 구분 필요. 사실 E에서 DMIC가 ADC와 동일 decimation 메커니즘을 쓴다고만 기술되어 있어, DMIC ch2(짝수)도 정확히 ADC ch2와 동일한 1/8 선도 스큐를 갖는지 데이터시트 직접 확인 권고.
- 2-DMIC 활성화 시 QCC의 DMIC2 동시 사용 충돌 회피를 위한 SPI 프로토콜·10ms 대기 운용 절차가 확정돼야 실제 구현 가능. 이 제약이 해소되지 않으면 빔포밍 HW 지연 설계 이론이 성립해도 실사용 불가(현재 상태 정리 및 복기.md 참조).
