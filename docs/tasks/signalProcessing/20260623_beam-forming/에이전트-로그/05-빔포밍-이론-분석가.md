# [단계1·분석 05] 빔포밍 이론 분석가 — delay-and-sum end-fire 원리 전문가. 모든 주장은 제공된 그라운딩 사실(사실 A~G)에 근거하며, 추측은 openQuestions로 분리.

**신뢰도**: high

## 결론
2cm 간격·16kHz에서 end-fire delay-and-sum에 필요한 최대 상대 지연은 정확히 0.933 샘플(58.3µs)이며, DELAY_INTEGER=7(0.875 샘플)에 DELAY_FRACTIONAL 보정을 더하면 SW 버퍼 없이 HW에서 목표값에 도달 가능하다. 다만 ch2(DMIC2/Left)가 ch1(DMIC1/Right)보다 1/8 샘플 먼저 도착하는 고유 스큐(사실 B)가 이미 존재하므로, 지연 예산 계산 시 이 0.125 샘플 오프셋을 반드시 차감해야 하고, broadside 대비 end-fire는 간격이 d=λ/2(≈1.07cm) 미만이라 주엽 폭이 넓지만 착용 기하에서 정면 방향 선택에 유일하게 유효하다.

## 발견(근거)
- **end-fire 최대 필요 지연은 정확히 0.933 샘플(58.3µs)이며, '1샘플'은 7% 과다 근사다.**
  - 근거: 사실 F: d/c = 0.02m / 343m/s = 58.3µs. 16kHz 샘플주기 62.5µs. 58.3/62.5 = 0.933 샘플. 정수 1샘플 지연은 1.07배 과다 — 등가 음속 이동 거리 2.14cm > 실제 간격 2cm. (사실 F)
- **DELAY_INTEGER=7(0.875 샘플) + DELAY_FRACTIONAL 보정으로 0.933 샘플에 HW에서 도달 가능하다.**
  - 근거: 사실 D: DELAY_INTEGER 최대 = 7(= 7/8 = 0.875 샘플). 사실 G: 단일 필드로 정수 1샘플 불가(최대 7/8). 사실 D: DELAY_FRACTIONAL 해상도 ≈ 0.26µs(= 1/(8×30) 샘플). 0.933 - 0.875 = 0.058 샘플 = 3.6µs → DELAY_FRACTIONAL로 보정 가능(해상도 0.26µs 이내). (사실 D, 사실 G)
- **ch2(DMIC2/Left)는 ch1(DMIC1/Right)보다 1/8 샘플(0.125 샘플 = 7.8µs) 먼저 도착하는 고유 스큐가 존재한다.**
  - 근거: 사실 A(HW p.222): ADC0·ADC2 데이터가 ADC1·ADC3보다 1/8 샘플 앞서 도착. 사실 B(HW p.445 §14.4): decimation 필터 시분할로 채널쌍 (0,1)·(2,3) → 짝수(0,2)가 홀수(1,3)보다 1/8 샘플 먼저 출력. 현재 매핑: ch2=DMIC2(Left), ch1=DMIC1(Right) → Left가 Right보다 1/8 샘플 먼저 도착. (사실 A (HW p.222), 사실 B (HW p.445 §14.4))
- **실효 필요 추가 지연량은 고유 스큐 차감 후 0.808 샘플(=0.933 - 0.125)이다.**
  - 근거: 사실 F에서 목표 지연 0.933 샘플. 사실 A·B에서 DMIC2(Left/ch2)가 이미 1/8=0.125 샘플 앞서 있으므로, SW가 ch2를 지연 기준으로 삼을 경우 ch2에 (0.933 - 0.125) = 0.808 샘플을 추가 지연하거나, ch1에 0.125 샘플을 추가하는 등 방향을 정해야 한다. 어느 마이크가 '앞'인지에 따라 부호가 결정됨(openQuestions 참조). (사실 A (HW p.222), 사실 B (HW p.445 §14.4), 사실 F)
- **DELAY_FRACTIONAL 유효 해상도는 약 0.26µs(≈ 1/(8×30) 샘플)이며 16kHz·3.84MHz 조건에서 SFCR≈29다.**
  - 근거: 사실 D: SFCR = round(f_adcclk/8/f_sample)-1 = round(3.84MHz/8/16kHz)-1 = round(30)-1 = 29. 해상도 = (1/8 샘플)/30 = 0.0042 샘플 = 62.5µs/8/30 ≈ 0.26µs. 필요 보정량 3.6µs는 해상도 0.26µs × ~14 스텝으로 충분히 도달 가능. (사실 D (HW p.450-451))
- **end-fire는 broadside 대비, 이 기하(d=2cm, λ/2≈1.07cm)에서 주엽이 넓지만 착용 방향 선택에는 유일한 유효 모드다.**
  - 근거: 사실 F: 1샘플=2.14cm > d=2cm → d < λ/2(≈1.07cm at 16kHz 가청 상한이 아닌 음원 주파수 의존). 16kHz에서 λ=343/16000=2.14cm, λ/2=1.07cm. d=2cm > λ/2=1.07cm이므로 16kHz 단일 주파수 기준 배엽(grating lobe) 발생 가능. broadside 빔포밍(지연=0)은 두 귀 간 수직 방향 집음이라 착용 시 앞/뒤 구분 불가. end-fire(지연≈0.933 샘플)는 마이크 축선 방향(앞 또는 뒤) 선택 가능 — 착용 기하에서 정면 선택에 end-fire만 유효. (사실 F, 사실 G)
- **현재 DEC delay 설정(DELAY_INTEGER=0, DELAY_FRACTIONAL=0)은 빔포밍을 전혀 적용하지 않은 상태(omnidirectional)다.**
  - 근거: 사실 D(현재 설정): DELAY_INTEGER=ADC_INTEGER_DELAY_0=0, LIB_SAMPLE_FRACTIONAL_DELAY=0. 두 채널 모두 추가 지연 없음 → 채널 간 상대 지연은 오직 고유 스큐 1/8 샘플만 존재. 0.125 샘플로는 빔 방향이 정의되지 않음(목표 0.933 샘플과 크게 이탈). (사실 D (현재 설정값))
- **널(null) 방향은 end-fire 반대 축선 방향(뒤쪽)이며, 완전 널은 음원이 d·cos(θ)=c/f_s일 때 구조적으로 형성된다.**
  - 근거: 사실 F: delay-and-sum에서 지연 τ=d·cos(θ)/c를 보정하면 해당 방향 신호가 정합·강화됨. 반대로 보정 방향의 역방향(θ=180°)에서는 d·cos(180°)=-d/c = -0.933 샘플 → 상쇄. 정확한 널 위치는 인가된 지연값과 기하의 합으로 결정되며, 2소자 어레이에서는 정면(end-fire 방향)과 후면(널)만 1차적으로 구분된다. (사실 F)
- **DMIC2(FE)가 DMIC1(RE)보다 DMIC 클럭 반주기 먼저 캡처되는 추가 스큐가 존재하나, 출력 샘플 레이트 대비 미미하다.**
  - 근거: 사실 E: DMIC*_DATA_RE=rising, *_FE=falling. 본 보드는 pad 분리+클럭 공유 → DMIC2(FE)는 DMIC1(RE)보다 DMIC 클럭 반주기만큼 먼저 캡처. ADCCLK=3.84MHz → 반주기=130ns. 출력 샘플 주기 62.5µs 대비 0.002 샘플(<0.4%) → 6th order CIC 필터링 후 추가 스큐는 사실상 무시 가능 수준이나, 엄밀 보정 시 고려 대상. (사실 E (HW §18.2 p.563))
- **DMIC에도 fractional delay 메커니즘이 동일하게 적용되므로 ADC 채널과 동일한 HW 지연 제어가 가능하다.**
  - 근거: 사실 E: 'DMIC pre-decimation 필터도 ADC와 동일하게 fractional delay 지원.' 사실 D의 AUDIO_ADC_DEC_CTRL 레지스터 메커니즘이 DMIC 채널에도 적용 → DMIC1(ch1)·DMIC2(ch2)에 각각 다른 DELAY_INTEGER+DELAY_FRACTIONAL 설정 가능. (사실 E (HW §18.2 p.563), 사실 D (HW p.450-451))

## 미해결 질문
- 어느 마이크(Right/DMIC1 또는 Left/DMIC2)가 착용 시 '앞 방향' 음원에 더 가까운가? — 이미지 파일(Sound1 마이크 위치.png, 착용 시 앞 방향 마이크 위치 정보.png)을 직접 분석하지 않아 지연 부호(어느 채널을 지연시킬지)를 확정할 수 없음. 현재 상태 문서에는 '앞 방향 마이크 샘플이 1개 느려져야 한다'고 명시되어 있으나, Left/Right 중 어느 쪽이 앞인지는 착용 방향에 따라 결정됨.
- 배엽(grating lobe) 영향 범위: d=2cm, λ/2=1.07cm → d > λ/2 조건에서 고주파(특히 4kHz 이상)에서 배엽 발생 가능. 실용적 빔포밍 주파수 범위를 얼마로 제한할지 미정.
- 고유 1/8 샘플 스큐(사실 A·B)가 decimation 필터 절대 group delay 이후에도 상대 스큐로 보존되는지, 아니면 후단 필터에서 정렬되는지 — HW 명세에서 사실 A·B는 '필터 출력 도착 시점'으로 기술하므로 보존 가능성이 높으나 Filter Engine 이후 경로에서의 동기화 여부 추가 확인 필요.
- DELAY_INTEGER 네이밍 혼동: 필드명은 'INTEGER'이지만 물리 의미는 1/8 샘플 단위(0~7/8). 펌웨어 코드에서 이 필드를 '1샘플 단위'로 잘못 해석할 경우 7배 과소 지연 설정 버그 발생 가능 — 코드 구현 단계에서 반드시 재확인.
- RE/FE 혼용(DMIC1=RE, DMIC2=FE)을 의도적으로 유지해야 하는지, 아니면 두 채널 모두 RE로 통일 가능한지 — 본 보드는 pad 분리이므로 이론상 둘 다 RE 설정 가능하나, QCC 측 DMIC2 공유 시 FE 고정 여부 확인 필요.
- 전화 통화 중 QCC가 DMIC2를 사용하는 상황에서 E8300이 DMIC2를 동시에 빔포밍에 사용할 경우의 충돌 처리 — 10ms SPI 대기 포함 운용 시나리오 미정.
