# [단계2·토론 22] E8300 DMIC 2채널 빔포밍 타당성 분석 — 종합 합의

## 찬
## 찬성 입장 (HW 단독 빔포밍 구현 가능)

**1. 기하 타이밍 산술 확정**
- end-fire 필요 지연 = d/c = 0.02m/343m/s = 58.309µs = **0.9329 샘플** (정확값).
- "1샘플" 근사는 7.4% 과다 — 정밀 구현 필수.

**2. HW 레지스터로 목표값 달성 가능**
- `DELAY_INTEGER=7` (7/8 = 0.875 샘플) + `DELAY_FRACTIONAL=14` (14/240 = 0.0583 샘플) = **0.9333 샘플(58.33µs)**, 양자화 오차 +0.0243µs (0.093 FRAC LSB) — SW 버퍼 없이 HW에서 완결.
- SFCR=29(정확값, round(3.84MHz/8/16kHz)-1=29.000), 해상도 = 0.2604µs/step (1/240 샘플).
- 최대 지연 범위 0.9958 샘플 — 목표 0.9329 샘플은 범위 내.

**3. 채널 간 고유 스큐 — 방향과 크기 모두 확정**
- 사실 A(p.222) + 사실 B(p.445 §14.4): ch2(짝수, DMIC2/Left)가 ch1(홀수, DMIC1/Right)보다 **1/8 샘플(7.8125µs) 먼저** IOC/FIFO에 도착 — 두 사실이 동일 방향으로 수렴.
- 이 고유 스큐는 decimation WDF 시분할(짝수 레인 우선)에서 기인하며, 양 채널이 동일 BAND_SELECT(0K_8K)이므로 WDF 절대 group delay는 완전 상쇄 → **상대 스큐 1/8 샘플만 잔존**.
- FIFO까지 보존되며 CFX DSP에 그대로 전달됨.

**4. 음향 기하 — 착용 방향 시사**
- 이미지 및 복기 문서: "Left(DMIC2) 샘플이 Right(DMIC1)보다 1개 앞서야 한다" → **Left가 정면에 더 가까운 기하**.
- 고유 스큐(ch2 선행 1/8)가 빔포밍 방향과 동일 부호 → **지연 예산을 줄이는 방향으로 작용**.

**5. 실효 ch1(Right) DEC 설정값 도출 (착용 기하: Left=앞 가정)**
- 필요 HW 추가 지연 = 0.9329 - 0.125(고유 스큐) = **0.8079 샘플**
- `DELAY_INTEGER=6` (6/8=0.75) + `DELAY_FRACTIONAL=14` (14/240≈0.0583) = 0.8083 샘플(50.52µs), 오차 +0.0243µs.
- DELAY_INTEGER=6 < 최대 7 → HW 범위 내 달성 가능.

**6. RE/FE 에지 오프셋 무시 가능**
- DMIC2(FE)의 오버샘플링 반주기 추가 스큐 = 0.1302µs = 0.002 샘플 — CIC 필터 후 사실상 흡수됨. 빔포밍 양자화 해상도(0.2604µs)의 절반 수준.

**7. 2-DMIC 전환 코드 변경 최소화**
- `LIB_AUDIO_IN_DMIC_ENABLE_COUNT` 1→2 단 1행 변경으로 3개 함수 분기 전환.
- FIFO FA0_1, CFX 인터럽트 INT_A0_1, double-access 설정은 현재 1-DMIC에서도 이미 적용 완료.
- main.c:182 mic1 조건 주석 해제 추가 필요.

## 반
## 반대 입장 (미해결 리스크 — 구현 전 해소 필수)

**1. QCC/DMIC2 공유 충돌 — 가장 큰 차단 리스크**
- 전화통화 시 QCC가 DMIC2(U9) 사용: DIO10(CLK2) 마스터가 QCC인지 E8300인지 미확인. 충돌 시 HW 버스 다툼 발생.
- I2S_FLAG(DIO29)만으로는 전화통화/미디어/크래들 구분 불가 → 현행 신호만으로 빔포밍 ON/OFF 전환 기준 없음.
- SPI 프로토콜에 "QCC DMIC2 점유 시작/종료" 명령 부재 → 새 패킷 정의 + QCC 펌웨어 협의 필요.
- DIO17이 QCC에 물리적으로 연결되어 있는지 회로도 미확인.

**2. 착용 기하 미최종 확정**
- 이미지와 복기 문서는 Left=앞을 강하게 시사하나, 실기기 착용 방향 물리 재확인 미완료.
- 만약 Right=앞이면 총 필요 지연 = 0.9329 + 0.125(스큐 반전) = **1.058 샘플** → DELAY_INTEGER 최대(7/8=0.875) 초과 → HW 단독 불가, SW 1샘플 버퍼 시프트 병행 필요.

**3. DELAY_INTEGER 필드명 혼동 리스크**
- 필드명 'INTEGER'이지만 물리 단위는 1/8 샘플 — 구현 시 "1샘플=DELAY_INTEGER=1" 오해 시 7배 과소 지연 버그 발생 가능.

**4. 음속 온도 의존성 — 고정 레지스터 오차**
- 0°C→40°C 범위에서 필요 지연 변동 4.12µs = 15.8 FRAC LSB — 양자화 오차(0.0243µs)의 169배.
- 온도 센서 없이 고정값 사용 시 최악 온도에서 빔 방향 편이 발생.

**5. 사실 C(p.219) 부작용 미검증**
- "fractional delay 변경이 ADC 입력 간 동기화에 영향" — ch1에만 DEC delay를 적용할 때 ch2 동작에 의도치 않은 부작용이 있는지 HW 상세 미확인.

**6. CFX DSP 사이클 예산 미확인**
- delay-and-sum 알고리즘을 CFX 마이크로코드에 추가할 사이클 여유가 있는지 미측정.
- MIC1(FA0_1) FIFO 인터럽트 설정은 완료지만 CFX가 실제로 MIC1 데이터를 소비하는 연산 경로 미확인.

**7. decimation 절대 group delay 상쇄 데이터시트 명시 부재**
- 동일 BAND_SELECT이면 상쇄된다는 이론적 추론은 타당하나, HW Reference에서 채널별 절대 group delay 수치표 확인 미완료.

**8. DMIC2 FE 오버샘플링 스큐 CIC 흡수 여부 정량화 미완료**
- 0.002 샘플로 무시 가능 추정이나 CIC 필터 내부에서 증폭되는지 데이터시트 명시 없음.

### 레지스터 설정 — 착용 기하 조건별

**조건 A: Left(DMIC2/ch2)가 정면에 더 가까운 경우 (현재 이미지·복기 문서 시사, 신뢰도 medium)**
- ch2(DMIC2, Left): `DELAY_INTEGER=0`, `DELAY_FRACTIONAL=0` (기준, 지연 없음)
- ch1(DMIC1, Right): `DELAY_INTEGER=6`, `DELAY_FRACTIONAL=14` → 0.8083 샘플(50.52µs) 지연
- 고유 스큐(1/8 샘플 ch2 선행)가 이미 0.125 샘플을 기여 → 총 상대 지연 = 0.125 + 0.8083 = **0.9333 샘플 ≈ 목표 0.9329** (오차 +0.0243µs)

**조건 B: Right(DMIC1/ch1)가 정면에 더 가까운 경우 (가능성 낮으나 기하 확정 전 배제 불가)**
- 총 필요 HW 지연 = 0.9329 + 0.125(고유 스큐 반전) = 1.058 샘플 → DELAY_INTEGER 최대 초과
- SW FIFO 1샘플 시프트 + `DELAY_INTEGER=1`, `DELAY_FRACTIONAL=14` 병행 필요

### 잔여 불확실성 (구현 착수 전 해소 필수 목록)

**[차단급 — 미해소 시 구현 불가]**
1. **착용 기하 물리 확정**: Left vs Right 정면 마이크 — 이미지 재확인 또는 실기기 측정. 조건 A/B 분기 확정에 직결.
2. **QCC DMIC2 CLK 마스터십**: DIO10이 현재 QCC 주도인지 E8300 주도인지 — 2-DMIC 활성화 전 회로도·QCC 펌웨어 확인 필수. 충돌 시 HW 손상 가능.
3. **SPI 프로토콜 신규 패킷 정의**: QCC 전화통화 DMIC2 점유 시작/종료 통보 명령 부재 — QCC 팀과 협의 없이 상시 빔포밍 운용 불가.

**[정밀도·견고성 — 구현 초기에 해소]**
4. **사실 C(p.219) 부작용 검증**: ch1 단독 DEC delay 변경 시 ch2 동기화 영향 여부.
5. **decimation 절대 group delay 수치 확인**: HW §14 표에서 채널별 절대 group delay 명시 페이지 직접 검토.
6. **DMIC 채널 레지스터 매핑 확인**: `SYS_SET_ADC_DEC_CTRL`이 DMIC ch1/ch2에도 동일하게 적용되는지 레지스터 주소 레벨 재확인.
7. **CFX 사이클 예산**: delay-and-sum 알고리즘 추가 가능 여부.

**[운용·품질 — 구현 후 개선 가능]**
8. **온도 보상**: 0→40°C 범위 4.12µs(15.8 FRAC LSB) 변동 — 허용 빔 각도 편이 정의 후 보상 전략 결정.
9. **DELAY_INTEGER 단위 혼동 방지**: 구현 시 1/8 샘플 단위임을 코드 주석으로 명기 필수.

### 결론 요약

E8300 DMIC 2채널 end-fire delay-and-sum 빔포밍은 **HW 레지스터(`DELAY_INTEGER=6`, `DELAY_FRACTIONAL=14` ch1 단독 설정) 단독으로 이론적 구현이 완전히 가능**하며, SW 버퍼 시프트가 불필요하다. 이는 요구사항_1~4 모두를 데이터시트 근거로 충족한다. 단 구현 착수 전 QCC DMIC2 공유 충돌 해소(차단급 리스크)와 착용 기하 물리 확정이 선행되어야 한다.
