# [단계1·분석 09] 현재 펌웨어 구성 분析가

**신뢰도**: high

## 결론
현재 펌웨어는 LIB_AUDIO_IN_DMIC_ENABLE_COUNT==1 단일 매크로로 3개 함수(configure_audio_path_all, enable_DMIC, disable_DMIC)의 #if/#elif 분기를 동시 제어한다. 2-DMIC 활성화는 이 매크로를 2로 변경하는 것이 유일한 CFX 레이어 변경이며, 코드상 2-DMIC 경로는 이미 구현 완료 상태다. 단, QCC가 DIO10/DIO17을 사용 중인지 여부가 확인되지 않아 HW 충돌 리스크가 남아 있다.

## 발견(근거)
- **2-DMIC 활성화에 필요한 CFX 코드 변경은 단 1개 항목: LIB_AUDIO_IN_DMIC_ENABLE_COUNT를 1→2로 변경**
  - 근거: lib_audio_in.h:24 `#define LIB_AUDIO_IN_DMIC_ENABLE_COUNT 1`. 이 매크로가 configure_audio_path_all()/enable_DMIC()/disable_DMIC() 세 함수의 #if(COUNT==1)/#elif(COUNT==2) 분기를 모두 제어. 2-DMIC 경로 코드는 이미 구현 완료. (lib_audio_in.h:24, lib_audio_in.c:106-142, 150-157, 165-171)
- **1-DMIC(현재)와 2-DMIC 분기의 차이 항목 1 — ADC 채널 설정: 채널 1만 vs 채널 1+2 동시 설정**
  - 근거: 1-DMIC: `SYS_SET_ADC_CFG(AUDIO, 1, ...)` + `SYS_SET_ADC_DEC_CTRL(AUDIO, 1, ...)` 만 호출. 2-DMIC: 채널 1에 더해 `SYS_SET_ADC_CFG(AUDIO, 2, ...)` + `SYS_SET_ADC_DEC_CTRL(AUDIO, 2, ...)` 추가 호출 (decimation 필터 ch2 활성화). 이는 사실B(p.445) 채널 쌍 (ch1, ch2)에 대응. (lib_audio_in.c:107-111 vs 124-129)
- **1-DMIC와 2-DMIC 분기 차이 항목 2 — DIO10/DIO17 패드 설정: DISABLE vs WEAK_PULL_UP+INPUT**
  - 근거: 1-DMIC: `Sys_DIO_Config(DIO10, DIO_MODE_DISABLE)`, `Sys_DIO_Config(DIO17, DIO_MODE_DISABLE)`. 2-DMIC: `Sys_DIO_Config(DIO10, DIO_WEAK_PULL_UP|DIO_MODE_INPUT)`, `Sys_DIO_Config(DIO17, DIO_WEAK_PULL_UP|DIO_MODE_INPUT)`. DIO10=DMIC_CLK2(QCC), DIO17=DMIC_OUT2(QCC). (lib_audio_in.c:116-117 vs 134-135)
- **1-DMIC와 2-DMIC 분기 차이 항목 3 — SRC_DMIC_DATA 레지스터: DMIC1 전용 vs DMIC1+DMIC2 OR 연결**
  - 근거: 1-DMIC: `DIO->SRC_DMIC_DATA = DMIC1_DATA_SRC_DIO_23`. 2-DMIC: `DIO->SRC_DMIC_DATA = DMIC1_DATA_SRC_DIO_23 | DMIC2_DATA_SRC_DIO_17`. 사실E(HW §18.2 p.563)에서 DMIC2_DATA_FE(DIO17)가 falling edge 캡처로 오버샘플 클럭 반주기 늦게 처리됨. (lib_audio_in.c:121 vs 139)
- **1-DMIC와 2-DMIC 분기 차이 항목 4 — enable_DMIC(): DIO22(CLK1) 단독 vs DIO22+DIO10(CLK2) 동시 ADCCLK 출력**
  - 근거: 1-DMIC: `Sys_DIO_Config(DIO22, DIO_MODE_ADCCLK)` 만. 2-DMIC: 추가로 `Sys_DIO_Config(DIO10, DIO_MODE_ADCCLK)`. 두 클럭은 동일 소스 ADCCLK(3.84MHz, 사실B). 그러나 코드 주석 '클럭은 1개만 설정 가능'은 SRC_DMIC_CLK 레지스터 단일 지정을 의미하며, DIO 출력 핀은 2개 동시 구동 가능. (lib_audio_in.c:150-154 vs 152-154, lib_audio_in.h:119 주석)
- **1-DMIC와 2-DMIC 분기 차이 항목 5 — disable_DMIC(): DIO22 단독 DISABLE vs DIO22+DIO10 동시 DISABLE**
  - 근거: 1-DMIC: `Sys_DIO_Config(DIO22, DIO_MODE_DISABLE)`. 2-DMIC: 추가 `Sys_DIO_Config(DIO10, DIO_MODE_DISABLE)`. DIO17은 configure 단계에서 INPUT으로 설정되므로 disable 분기에 별도 처리 없음. (lib_audio_in.c:165-169)
- **2-DMIC 활성화 시 CFX 루프 조건도 변경 필요: mic1 인터럽트 플래그 조건 주석 해제**
  - 근거: main.c:182 `if ((g_interrupt_flags.pcm_out==1) && (g_interrupt_flags.mic0==1))  // && (g_interrupt_flags.mic1==1))`. 주석 처리된 mic1 조건과 :186 `// g_interrupt_flags.mic1 = 0;` 도 2-DMIC 동작 시 활성화 대상. interrupt_service_routine.c:88에서 mic1 ISR 핸들러는 이미 구현 완료. (main.c:181-186, interrupt_service_routine.c:88)
- **AUDIO_MUX ch2 소스는 DMIC2_DATA_FE로 이미 1-DMIC에서도 설정됨 — 분기 무관 공통 설정**
  - 근거: LIB_DMIC_AUDIO_MUX_CFG_INPUT_CH_SRC = `ADC3_OUT | DMIC2_DATA_FE | DMIC1_DATA_RE | ADC0_OUT` 은 COUNT==1/2 무관하게 configure_audio_path_all() 공통부에서 적용. ch2 MUX 소스는 이미 DMIC2_FE로 고정. 단 ch2 decimation 필터가 COUNT==1에서는 비활성화 상태. (lib_audio_in.h:79-84, lib_audio_in.c:101)
- **채널 간 타이밍 오프셋 보정값은 현재 설정 없음 — 빔포밍 적용 시 추가 설정 필요 항목**
  - 근거: LIB_SAMPLE_FRACTIONAL_DELAY=0, ADC_INTEGER_DELAY_0 → 두 채널 모두 delay=0. 사실B(p.445)에서 ch2(DMIC2/Left)가 ch1(DMIC1/Right)보다 1/8샘플 먼저 출력. 사실E에서 DMIC2_FE가 오버샘플 클럭 반주기 추가 지연. 빔포밍 활성화 시 ch별 DELAY_INTEGER/DELAY_FRACTIONAL 설정이 별도 항목으로 필요하나, 이는 2-DMIC 기본 활성화와는 독립 항목. (lib_audio_in.h:96-98, 사실B(p.445), 사실D(p.450-451), 사실E(p.563))

## 미해결 질문
- DIO10(DMIC_CLK2)이 현재 QCC 쪽에서 다른 용도로 사용 중인지 여부가 불확실함 — Board_OTE_ver1_5.h에서 DIO10은 PCM_SERO/PCM_FR로 정의되어 있어, 현재 시스템에서 QCC가 DIO10을 PCM 클럭으로 능동 구동 중인지 확인 필요. 충돌 시 2-DMIC 활성화 전 QCC 측 DIO10 해제 협의 필요.
- DIO17(DMIC_OUT2)도 Board_OTE_ver1_5.h에서 UART_TX로 정의된 변종이 존재 — 실제 양산 보드(v1.5)에서 DIO17이 어떤 기능으로 사용 중인지, QCC가 실제로 DMIC_OUT2 신호를 DIO17로 출력하는지 확인 필요.
- QCC가 DMIC2(Left ear front mic/U9)를 현재 사용 중인지 여부 — 코드 주석에 'QCC 담당'으로 명시되어 있으나, 2-DMIC 활성화 시 EZ가 DMIC_CLK2를 구동하면 QCC 쪽 DMIC 처리 경로와 충돌 가능성 있음. QCC 펌웨어 레벨 협의 필요.
- FIFO double-access mode: LIB_IOC_FIFO_ACCESS_VALUE에 FIFO_A0_1_DBL_ACC_EN이 포함되어 있음 — 2-DMIC에서 MIC1 FIFO(FA0_1)에 IN2 단일 소스만 연결되므로 double-access 유지가 맞으나, 실제 동작 검증 필요(HW 주석: 단일 소스는 double-access 권장).
- 2-DMIC 활성화 후 CFX 루프의 mic1 인터럽트 조건 추가 시, PCM 출력과 두 마이크 인터럽트의 타이밍 동기화가 실제로 보장되는지 — 현재 mic0만 대기하는 구조에서 mic1을 추가하면 루프 레이턴시 변화 가능성 있음.
