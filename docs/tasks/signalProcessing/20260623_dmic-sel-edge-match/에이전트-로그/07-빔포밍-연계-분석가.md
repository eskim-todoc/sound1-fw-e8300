# [분석 07] 빔포밍 연계 분석가 — DATA선 분리 구성에서 both-RE 통일 가능성 및 HW 비용 전문 분석

**신뢰도**: high

## 결론
DATA선 분리 구성(U7=DIO23, U9=DIO17)에서는 멀티플렉싱 충돌이 없으므로 두 마이크를 both-RE(둘 다 SEL=GND)로 통일하는 것이 HW상 허용된다. 통일 시 RE/FE 반주기 스큐(0.1302µs = 0.002083 샘플)를 원천 제거하는 이점이 있으나, 이 스큐는 DELAY_FRACTIONAL 1 LSB(0.2604µs)의 0.5배로 HW 보정 불가 수준이며 빔포밍 목표 지연(58.31µs)의 0.22%에 불과해 실질 영향이 없다. HW 비용(U9 SEL 재스트랩)은 실존하며, U9의 현재 SEL 스트랩이 VDD인지 GND인지 회로도 확인 없이 판단 불가한 상태다.

## 발견(근거)
- **DATA선 분리 구성에서 both-RE 통일은 HW 충돌 없이 허용된다**
  - 근거: 본 보드는 U7=DIO23, U9=DIO17로 DATA 라인이 분리되어 있고 CLK만 DIO22 공유한다. SPH0641 타이밍도(§6, p.7)의 High-Z 반주기 충돌 문제는 1 DATA 라인 공유(멀티플렉싱) 구성에서만 발생한다. 라인이 독립적이므로 두 마이크가 동일 반주기(LOW 구간)에 동시 출력해도 전기적 충돌이 없다. 따라서 둘 다 SEL=GND + 둘 다 DMIC*_DATA_RE 설정이 허용된다 (조사_SEL엣지-그라운딩.md §5). (조사_SEL엣지-그라운딩.md §5; SPH0641 데이터시트 §6 p.7(타이밍도))
- **both-RE 통일의 빔포밍 이점은 원칙적으로 존재하나 실질 크기는 무의미하다**
  - 근거: 현재 DMIC1=_RE, DMIC2=_FE 혼용 시 반주기 스큐 = 0.5 / 3.84MHz = 0.1302µs = 0.002083 샘플(출력 샘플 주기 62.5µs 기준). 빔포밍 목표 지연(58.31µs) 대비 0.22%, DELAY_FRACTIONAL 1 LSB(0.2604µs)의 0.5배로 HW 레지스터 보정조차 불가한 크기. CIC 6차 30클럭 적분 윈도우(7.8µs) 내에서 위상적으로 흡수되는 것으로 판단됨. 빔포밍 오차 예산을 지배하는 항목은 decimation 시분할 스큐(7.81µs, 목표 지연의 13.4%)이며 RE/FE 스큐는 그 1/60 규모다 (검증 페르소나 30, 토론 페르소나 16 수렴 결론). (에이전트-로그/30-검증-DMIC2(FE)DMIC1(RE)-반주기-스큐는-출력-.md; 에이전트-로그/16-REFE-통일-.md §수렴 결론)
- **both-RE 통일을 위한 HW 비용: U9 SEL 재스트랩이 필요할 수 있다**
  - 근거: 올바른 조합 규칙(SEL=GND ↔ _RE, SEL=VDD ↔ _FE)에 따르면 현재 DMIC2_DATA_FE 설정은 U9 SEL=VDD를 강제한다. both-RE 통일 시에는 U9 SEL도 GND로 재스트랩해야 한다. 이 작업은 보드 개정(HW 변경)이 필요하다. 단 U9의 실제 SEL 스트랩이 이미 GND라면(QCC 측이 GND로 결정) 펌웨어 변경만으로 충분하다 — 그러나 그 경우 현재 DMIC2_DATA_FE 설정이 미스매치 상태임을 의미한다 (조사_SEL엣지-그라운딩.md §4, §6 미해결_1·2). (조사_SEL엣지-그라운딩.md §4, §6; 에이전트-로그/16-REFE-통일-.md 수렴결론 조건 (a)(b)(c))
- **U9 SEL 재스트랩 시 QCC 인터페이스 영향 가능성이 추가 HW 비용 요인이다**
  - 근거: U9(DMIC2)는 원래 QCC 담당이었으므로 SEL 스트랩이 QCC 기준으로 결정됐을 수 있다. QCC가 DIO17을 FE 기준(SEL=VDD)으로 수신한다면, SEL을 GND로 재스트랩 시 QCC의 DMIC2 캡처가 미스매치로 전환된다. 이는 단순 PCB 저항 변경 이상의 시스템 검증 비용을 수반한다 (토론 페르소나 16 반 근거 3; 조사_SEL엣지-그라운딩.md §6 미해결_2). (에이전트-로그/16-REFE-통일-.md §반 근거3; 조사_SEL엣지-그라운딩.md §6 미해결_2)
- **빔포밍 설계 관점에서 RE/FE 분리 유지가 현실적 권고이며, both-RE는 선택적 정리 작업으로 분류된다**
  - 근거: 기존 다중 페르소나 토론(16)과 검증(30) 양쪽이 동일 결론으로 수렴: '통일 불필요, 현행 유지 권고. 단 바꿔도 빔포밍 정확도에 실질 변화 없음.' 스큐 제거 이득(0.1302µs)이 HW 변경 확인 비용(회로도 검토·QCC 영향 검증)보다 실용적으로 낮다는 판단. 실질 관리 대상은 decimation 채널쌍 스큐(7.81µs)와 front mic을 홀수 채널에 배치하는 전략이다 (분석.md §1, §4). (에이전트-로그/16-REFE-통일-.md §수렴 결론; 에이전트-로그/30 §판정 CONFIRMED; 분析.md §4)

## 미해결 질문
- U7·U9 실제 SEL 스트랩(VDD/GND/floating) — 회로도 확인 없이 미판단. U9가 GND이면 이미 미스매치 상태이며 펌웨어 수정만으로 both-RE 전환 가능. VDD이면 PCB 재스트랩 필요.
- QCC가 DIO17(DMIC2)을 현재 FE 기준(SEL=VDD)으로 사용하는지 여부 — SEL 재스트랩 시 QCC 인터페이스 영향 범위 결정.
- CIC 6차 필터의 반주기 오프셋 흡수량 정량 — 데이터시트에 미기재. 0.22% 수준 잔류 스큐의 엄밀 검증이 필요하다면 시뮬레이션 또는 실측 필요(현 단계 우선순위 아님).
- both-RE 통일 후 AUDIO_MUX SRC_DMIC_DATA 레지스터 내부 라우팅 변화 여부 — DMIC2_DATA_FE→_RE 전환 시 ch2 decimation 경로 연결이 동일하게 유지되는지 HW 레지스터 맵 재확인 필요.
