# [분석 06] 회로 스트랩 의존성 분석가

**신뢰도**: medium

## 결론
SELECT 내부 풀다운은 데이터시트 §5(p.7)로 확정 사실이며, floating 또는 GND 스트랩 시 기본값은 Low(GND) = LOW 구간 유효(falling assert) = E8300 _RE(rising 캡처) 조합으로 귀결된다. 현재 펌웨어(DMIC1=_RE, DMIC2=_FE)는 U7 SEL=GND(풀다운 기본과 일치)와 U9 SEL=VDD(능동 스트랩 필수)를 동시에 요구하는 비대칭 구성이다. U9가 원래 QCC 담당이었으므로 U9 SEL 스트랩이 QCC 인터페이스 요구로 결정됐을 가능성이 있으나, 이는 회로도 없이 단정 불가하며 QCC가 FE 기준으로 DIO17을 수신하는지도 미확인이다.

## 발견(근거)
- **SELECT 내부 풀다운 → floating/GND 기본값 = Low = falling assert = E8300 _RE 조합**
  - 근거: SPH0641 데이터시트 §5 핀 설명: 'SELECT(Lo/Hi(L/R) Select, Digital I, 내부 풀다운 — floating 금지)'. §5 표(p.7): SEL=GND → 'Asserts DATA on Falling Clock Edge' → 데이터 LOW 구간 유효. E8300 HW Reference §18.2(p.563): 'low data channel(LOW 구간 데이터)은 rising 캡처 = DMIC*_DATA_RE(0x2)'. 따라서 floating/GND 시 기본 경로는 _RE 조합. 이 사실은 데이터시트로 확정. (SPH0641 §5 p.7; E8300 HW §18.2 p.563)
- **현재 펌웨어 DMIC2=_FE는 U9 SEL=VDD를 능동 스트랩으로 요구 — 풀다운 기본값과 불일치**
  - 근거: cfx lib_audio_in.h:80: LIB_DMIC_AUDIO_MUX_CFG_INPUT_CH_SRC = (ADC3_OUT | DMIC2_DATA_FE | DMIC1_DATA_RE | ADC0_OUT). _FE = falling 캡처 = E8300이 HIGH 구간 데이터를 수신한다는 설정. SPH0641 §5 p.7: HIGH 구간 유효는 SEL=VDD(rising assert)일 때만 성립. SELECT 내부 풀다운 기본은 GND = LOW 구간 유효이므로, U9가 GND/floating이면 _FE 설정과 미스매치 → 마이크 High-Z 반주기를 캡처하게 됨. 능동 VDD 스트랩 없이는 정합 불가. (cfx lib_audio_in.h:80; SPH0641 §5 p.7; E8300 HW §18.2 p.563)
- **U9가 원래 QCC 담당이었으므로 SEL=VDD 스트랩이 QCC 인터페이스 기준으로 결정됐을 가능성 있음 — 회로도 없이 단정 불가**
  - 근거: lib_audio_in.c:139 및 에이전트-로그 12: DIO17은 DMIC2(U9) 데이터 라인으로, 코드 주석에서 'QCC 담당'으로 표기됨. QCC가 전화통화(HFP SCO) 시 DIO17로 마이크 데이터를 수신한다면 QCC의 DMIC 인터페이스 캡처 엣지 기준으로 SEL을 결정했을 수 있음. 단, QCC가 DIO17을 FE 기준으로 수신하는지(즉 QCC가 HIGH 구간 데이터를 기대하는지) QCC 펌웨어/데이터시트로 확인된 사실이 없음. 'QCC 담당'이라는 코드 주석만 존재할 뿐 물리적 배선도 미확인(에이전트-로그 12 미해결 4항). (lib_audio_in.c:116-154; 에이전트-로그 12 미해결 4항)
- **회로도 확인 없이 단정 불가한 두 가지 핵심 항목: U7·U9 SEL 실제 스트랩, QCC-DIO17 물리 배선**
  - 근거: 조사_SEL엣지-그라운딩.md §6 미해결_1: '실제 보드 U7·U9의 SEL 스트랩(VDD/GND/floating) — 회로도 확인 필요'. 미해결_2: 'U9 SEL 스트랩이 QCC 기준으로 결정됐을 가능성 — E8300 캡처와의 정합 재확인'. 에이전트-로그 12 미해결 4항: 'DIO17(DMIC_OUT2) fan-out이 보드상에서 실제로 E8300과 QCC 양쪽에 물리적으로 연결되어 있는지 회로도 확인 필요 — 현재 그라운딩 사실에서 DIO17이 QCC에도 직접 연결된다는 명시적 증거가 없음(QCC 담당이라는 코드 주석만 존재)'. (조사_SEL엣지-그라운딩.md §6; 에이전트-로그 12 미해결 4항)
- **DATA 라인 분리 구성(U7=DIO23, U9=DIO17)에서는 두 마이크를 동일 SEL(both GND)+동일 엣지(both _RE)로 통일해도 HW 충돌 없음**
  - 근거: 조사_SEL엣지-그라운딩.md §5: '본 보드는 DATA 라인 분리(U7=DIO23, U9=DIO17) + 클럭 공유(DIO22). 즉 멀티플렉싱(1 DATA 라인 공유)이 아님 → 두 마이크가 같은 반주기에 출력해도 라인 충돌 없음 → 두 마이크를 동일 SEL(예: 둘 다 GND) + 동일 엣지(둘 다 _RE)로 통일 가능.' 단, SEL 재스트랩은 HW 변경(보드 개조)을 수반하며, U9 SEL이 실제로 VDD인지 GND인지 회로도 확인 전까지 통일 가능 여부의 전제 조건 자체가 미확인. (조사_SEL엣지-그라운딩.md §5)
- **미스매치 시 영향: 마이크 High-Z 반주기에 호스트가 샘플 → 플로팅/직전값 캡처 → 데이터 손상**
  - 근거: SPH0641 §6 타이밍도(p.7): 각 마이크는 자신의 반주기에만 DATA(VOH/VOL) 구동 후 나머지 반주기 High-Z. E8300 _FE 설정으로 HIGH 구간 캡처 시 U9 SEL=GND라면 마이크는 LOW 구간에만 구동하고 HIGH 구간은 High-Z → E8300이 High-Z 상태 또는 직전 구동값을 캡처하게 됨. 조사_SEL엣지-그라운딩.md §3: '미스매치 시: 마이크가 라인을 구동하지 않는 반주기(High-Z)에 호스트가 샘플 → High-Z/플로팅 또는 직전 값을 캡처 → 데이터 손상(노이즈·DC·간헐 오류)'. (SPH0641 §6 p.7; 조사_SEL엣지-그라운딩.md §3)

## 미해결 질문
- U7(DMIC1) SEL 스트랩 실제값: VDD/GND/floating 중 어느 것인가 — 회로도 확인 필요. GND/floating이면 풀다운 기본과 일치하여 _RE 정합, VDD이면 미스매치.
- U9(DMIC2) SEL 스트랩 실제값: VDD가 능동 스트랩되어 있는가 — 회로도 확인 필요. GND/floating이면 현재 _FE 펌웨어와 미스매치(High-Z 캡처).
- U9 SEL이 VDD로 스트랩되어 있다면: 그것이 E8300 _FE 요구로 결정된 것인지, 아니면 QCC의 DMIC 인터페이스 요구로 먼저 결정된 후 E8300 펌웨어가 _FE로 맞춘 것인지 — 설계 의도 확인 필요(PCB 설계 이력 또는 QCC 데이터시트).
- QCC가 전화통화(HFP SCO) 시 DIO17(DMIC2 데이터)를 실제로 어떤 캡처 엣지로 수신하는가 — QCC 펌웨어 또는 QCC DMIC 인터페이스 데이터시트 확인 필요. FE 기준이면 U9 SEL=VDD가 QCC 요구와 일치.
- DIO17이 보드 상에서 E8300과 QCC 양쪽에 물리적으로 연결되어 있는가 — 회로도 확인 필요. '코드 주석 QCC 담당'만으로는 물리 배선 확증 불가.
- QCC가 전화통화 시 DIO10(DMIC CLK2)의 클럭 마스터인가 슬레이브인가 — E8300이 마스터라면 단순 DISABLE 전환 가능, QCC가 마스터라면 output-to-output 충돌 위험 존재. 회로도 또는 QCC 펌웨어 확인 필요.
