# [분석 04] 현재 펌웨어 정합성 분석가 — 주어진 그라운딩 사실만 근거로 판단, 추측 배제

**신뢰도**: high

## 결론
현재 펌웨어 DMIC1=RE는 U7(Right front)에 SEL=GND를 요구하며, 마이크 내부 풀다운 기본값과 정합한다. DMIC2=FE는 U9(Left front)에 SEL=VDD 능동 스트랩을 요구하며, GND 또는 floating 상태면 마이크가 High-Z인 반주기를 E8300이 샘플링해 데이터가 손상된다. DATA선이 분리되어 있으므로 멀티플렉싱 충돌 문제와는 무관하게 각 마이크의 SEL 스트랩이 개별적으로 펌웨어 캡처엣지와 정합해야 한다.

## 발견(근거)
- **U7(DMIC1=RE) ← SEL=GND 요구 → 내부 풀다운 기본값과 정합**
  - 근거: SPH0641LM4H-1 §5 p.7: SELECT=GND → 'Asserts DATA on Falling Clock Edge' → 클럭 LOW 구간에 데이터 유효. E8300 §18.2 p.563: low data channel(클럭 LOW일 때 보낸 데이터)은 rising 엣지에 캡처 = DMIC1_DATA_RE(0x2). 두 정의가 동일 물리 반주기를 지칭하므로 RE+GND 조합이 정합. 마이크 내부 풀다운으로 SEL floating도 GND와 동일 → 추가 스트랩 없이 정합 성립. (SPH0641LM4H-1 §5 p.7; E8300 HW Reference §18.2 p.563; cfx lib_audio_in.h:80)
- **U9(DMIC2=FE) ← SEL=VDD 능동 스트랩 필수**
  - 근거: SPH0641LM4H-1 §5 p.7: SELECT=VDD → 'Asserts DATA on Rising Clock Edge' → 클럭 HIGH 구간에 데이터 유효. E8300 §18.2 p.563: high data channel(클럭 HIGH일 때 보낸 데이터)은 falling 엣지에 캡처 = DMIC2_DATA_FE(0x3). 정합을 위해선 SEL=VDD 필수. 마이크 내부 풀다운 기본값은 SEL=GND → U9 SEL이 GND 또는 floating이면 E8300이 마이크 High-Z 구간(클럭 HIGH 반주기)을 샘플링해 데이터 손상 발생. (SPH0641LM4H-1 §5 p.7, §6 p.7; E8300 HW Reference §18.2 p.563; cfx lib_audio_in.h:80)
- **DATA선 분리(U7=DIO23, U9=DIO17) → 두 마이크 SEL 스트랩이 서로 독립적이며, both-RE 통일도 하드웨어적으로는 가능**
  - 근거: 보드 구성: U7=DIO23, U9=DIO17(DATA 분리), CLK=DIO22(공유). 데이터시트 §6 p.7의 멀티플렉싱 전제(1 DATA선 공유 시 반주기 교대 출력)가 이 보드에는 해당하지 않는다. 따라서 SEL 스트랩을 동일(둘 다 GND=both-RE)로 통일해도 DATA 충돌은 없다. 단, 이 경우 펌웨어에서 DMIC2_DATA_FE → DMIC2_DATA_RE로 변경해야 소프트웨어도 정합된다. (보드 구성 사실(DIO23/DIO17/DIO22); SPH0641LM4H-1 §6 p.7)
- **미스매치 발생 시 장애 모드: 마이크 High-Z 구간 샘플링 → 플로팅/직전값 캡처**
  - 근거: SPH0641LM4H-1 §6 p.7: 각 마이크는 자기 반주기에만 DATA를 VOH/VOL로 구동, 나머지 반주기는 High-Z. E8300이 High-Z 구간을 캡처하면 DATA 버스 상태(플로팅 또는 이전 출력 유지)를 읽어 유효 오디오 데이터가 아닌 쓰레기값이 입력된다. (SPH0641LM4H-1 §6 p.7; E8300 HW Reference §18.2 p.563)

## 미해결 질문
- U9(DMIC2) SEL 핀의 실제 보드 스트랩(VDD/GND/floating)이 무엇인가 — 회로도 확인 필요. U9가 원래 QCC 담당이었다면 QCC 기준(QCC가 falling 캡처하는 경우 SEL=VDD일 수 있음)으로 결선됐을 가능성이 있으나 회로도 없이는 확인 불가.
- U7(DMIC1) SEL 핀이 실제로 floating인지, 명시적 GND 스트랩인지 — 내부 풀다운으로 정합은 성립하나 ESD/노이즈 내성을 위해 명시적 GND 스트랩이 권장되는지는 회로도로 확인 필요.
- DATA선이 분리된 현재 구성에서 both-RE 통일(SEL=GND x2 + 펌웨어 DMIC2 RE 변경)이 실제로 고려된 설계 의도인지, 아니면 U9 SEL=VDD 스트랩이 이미 보드에 존재하는지 — 둘 중 어느 경로인지에 따라 펌웨어 수정 필요 여부가 달라짐.
