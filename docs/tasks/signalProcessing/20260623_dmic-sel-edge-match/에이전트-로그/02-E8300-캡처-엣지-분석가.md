# [분석 02] E8300 캡처 엣지 분석가

**신뢰도**: high

## 결론
SPH0641 마이크 SELECT 핀과 E8300 DMIC 캡처 엣지의 정합 원리: "SEL=GND → 클럭 LOW 구간 유효 → E8300 low data channel → DMIC*_DATA_RE(rising 캡처)"가 유일하게 올바른 조합이며, 그 역("SEL=VDD → HIGH 구간 → _FE(falling)")도 동일 논리로 도출된다. 현재 펌웨어(h:80)는 DMIC1=_RE / DMIC2=_FE로, U7 SEL=GND·U9 SEL=VDD 스트랩이 각각 회로에 존재해야만 정합이 성립한다. U9 SEL 스트랩 실측값은 회로도 미확인으로 미해결 상태다.

## 발견(근거)
- **SPH0641 SELECT=GND 시 마이크는 클럭 falling 직후 DATA를 구동(LOW 구간 유효), 나머지 반주기(HIGH 구간)는 High-Z**
  - 근거: 데이터시트 §5 p.7 표: 'Mic(Low), SELECT=GND: Asserts DATA on Falling Clock Edge'. 타이밍도 §6 p.7: falling 직후 VOH/VOL 구동 → 반주기 후 High-Z 전환. /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_dmic-sel-edge-match/조사_SEL엣지-그라운딩.md §1 (데이터시트 §5, §6, p.7)
- **E8300 'low data channel'은 클럭이 LOW일 때 마이크가 보낸 데이터를 의미하며, rising 엣지에 캡처한다. AUDIO_MUX 설정값은 DMIC*_DATA_RE(0x2)**
  - 근거: HW Reference §18.2 p.563: 'low data channel = 클럭이 LOW일 때 보낸 데이터', 'low data channel은 rising DMIC 클럭 엣지에 캡처'. DMIC*_DATA_RE = 'Data provided from DMIC (rising-edge)' 0x2. /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_dmic-sel-edge-match/조사_SEL엣지-그라운딩.md §2 (HW Reference §18.2 p.563)
- **클럭 LOW 구간 데이터를 rising에 캡처하는 논리: 마이크가 falling 직후부터 LOW 구간 내내 라인을 구동하고, E8300은 다음 rising(LOW→HIGH 전환)에서 안정된 데이터를 샘플링한다**
  - 근거: 마이크: SEL=GND → falling 직후 DATA 구동(LOW 구간 유효). E8300: low data channel → rising 캡처. 즉 setup은 falling 직후~rising 이전, hold는 rising 이후~High-Z 전환 이전. 이는 표준 SPI/I2S 엣지-지연 캡처 패턴과 동일. /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_dmic-sel-edge-match/조사_SEL엣지-그라운딩.md §1~§3 (데이터시트 §6 p.7 타이밍도 + HW Reference §18.2 p.563)
- **올바른 조합: SEL=GND ↔ DMIC*_DATA_RE(rising), SEL=VDD ↔ DMIC*_DATA_FE(falling). 조합이 역전되면 High-Z 구간을 캡처해 데이터 손상 발생**
  - 근거: SEL=GND 마이크가 High-Z인 HIGH 구간에 _FE(falling)로 캡처하면 플로팅/직전값 획득. 역으로 SEL=VDD 마이크가 High-Z인 LOW 구간에 _RE(rising)로 캡처해도 동일. /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_dmic-sel-edge-match/조사_SEL엣지-그라운딩.md §3 (HW Reference §18.2 p.563 + 데이터시트 §5 p.7)
- **현재 펌웨어 h:80: DMIC1_DATA_RE(U7, ch1, Right front) → SEL=GND 요구. DMIC2_DATA_FE(U9, ch2, Left front) → SEL=VDD 능동 스트랩 필수**
  - 근거: lib_audio_in.h:80: LIB_DMIC_AUDIO_MUX_CFG_INPUT_CH_SRC = (ADC3_OUT | DMIC2_DATA_FE | DMIC1_DATA_RE | ADC0_OUT). /mnt/e/Claude/projects/Sound1/src/1__cfx/lib_cfx/lib_audio_in.h L80 (/mnt/e/Claude/projects/Sound1/src/1__cfx/lib_cfx/lib_audio_in.h:80)
- **U7 SEL=GND는 내부 풀다운 기본값과 일치하므로 floating이어도 우연히 정합 가능하나, U9 SEL=VDD는 회로에서 능동 스트랩이 없으면 미스매치(데이터 손상)**
  - 근거: SPH0641 SELECT 핀은 내부 풀다운 → 미접속 시 GND = LOW 구간 모드. U9가 DMIC2_DATA_FE(falling)를 요구하므로 SEL=VDD 능동 스트랩이 없으면 마이크는 LOW 구간 구동·E8300은 falling 캡처(HIGH→LOW 전환) → High-Z 캡처. /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_dmic-sel-edge-match/조사_SEL엣지-그라운딩.md §4 (데이터시트 §5 p.7 (SELECT 내부 풀다운))
- **보드가 DATA선 분리(U7=DIO23, U9=DIO17) + CLK 공유(DIO22)이므로, 두 마이크를 both-RE로 통일해도 라인 충돌 없음. 단 RE/FE 반주기 스큐(0.13µs)는 CIC 30클럭 적분 윈도우(7.8µs) 대비 무시 가능 수준**
  - 근거: 에이전트-로그 16번 수렴 결론: 반주기 스큐 0.1302µs = DELAY_FRACTIONAL 최소 해상도(0.2604µs)의 0.5 LSB = 빔포밍 목표 지연(58.3µs)의 0.22%. 지배 오차는 decimation 시분할 스큐(7.81µs) + 온도 음속 변동(4.12µs). /mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_beam-forming/에이전트-로그/16-REFE-통일-DMIC2(FE)DMIC1(RE)-반주기.md 수렴 결론 (/mnt/e/Claude/projects/Sound1/docs/tasks/signalProcessing/20260623_beam-forming/에이전트-로그/16-REFE-통일-DMIC2(FE)DMIC1(RE)-반주기.md)

## 미해결 질문
- U7(DMIC1)·U9(DMIC2) 실제 SEL 스트랩(VDD/GND/floating) — 회로도 미확인. U9 SEL=VDD 능동 스트랩 존재 여부가 현재 펌웨어 정합성 최종 판정의 전제 조건
- U9는 원래 QCC 담당이었으므로 SEL 스트랩이 QCC 인터페이스 기준으로 결정됐을 가능성 있음 — E8300 DMIC2_DATA_FE 설정과의 정합성 재확인 필요
- both-RE 통일 시 SRC_DMIC_DATA 레지스터의 DMIC2_DATA_SRC_DIO_17 플래그 재검토 필요 + QCC가 DIO17을 FE 기준으로 수신하고 있는지 여부 확인 선행 필요
