# [분석 05] 미스매치 영향 분석가

**신뢰도**: high

## 결론
SEL↔캡처엣지 미스매치는 "마이크가 High-Z인 반주기 끝에서 호스트가 샘플링"하는 구조로, 캡처 결과는 (1) 선행 마이크가 이전 클럭에 구동했던 직전값 잔류(float 용량), (2) DATA 라인 풀다운·풀업 저항 결정 전압, (3) High-Z→유효 전이 직후 setup 위반 중 하나다. 현재 펌웨어(DMIC1=RE, DMIC2=FE)에서 U9 SEL이 GND 또는 floating이면 DMIC2만 미스매치 상태이며, DATA 라인이 분리되어 있어 플로팅은 단독 발생(다른 마이크가 공유선을 당겨주는 멀티플렉싱 구제 없음). U9 미스매치는 음성 입력 ch2(좌측 마이크) 전체가 손상되므로 ch1(DMIC1) 미스매치보다 실 파급이 크나, 동일 메커니즘상 두 유형의 치명도 차이는 SEL 내부 풀다운 기본값 하나에 달려 있다.

## 발견(근거)
- **미스매치 시 물리적 캡처 결과: High-Z 구간 말단 캡처 → 3가지 가능 결과**
  - 근거: SPH0641 §5/§6(p.7): 각 마이크는 자기 반주기에만 DATA(VOH/VOL) 구동, 나머지 반주기는 High-Z. E8300 §18.2(p.563): low data channel = rising 캡처, high data channel = falling 캡처. 미스매치 = 마이크가 High-Z를 유지하는 반주기 말단에서 호스트가 샘플. 결과 ①: 이전 반주기에 마이크가 구동했던 값이 DATA 라인 기생 용량에 잔류 → 직전값(stale) 캡처. 결과 ②: DATA 라인에 풀다운 존재 시 서서히 GND로 끌려 중간 전압 → DC 오프셋 또는 logic 0 캡처. 결과 ③: 미스매치 엣지가 마이크 구동 시작(assert)과 동일 순간 → setup/hold time 위반 → 메타안정 샘플. 어느 결과가 나타나느냐는 DATA 라인 구성(풀다운 유무, 기생 RC)과 클럭 주파수(3.84 MHz ADCCLK, 반주기 130 ns)에 의존. (SPH0641LM4H-1 Rev.A §5 Table p.7, §6 Timing Diagram p.7; E8300 HW Ref §18.2 p.563)
- **오디오 증상 1: DC 오프셋 — 스테레오 공유선 구성에서만 구제 가능, 분리선 구성에서는 더 심각**
  - 근거: 스테레오 1 DATA 라인 공유(멀티플렉싱) 구성이라면 미스매치 마이크의 High-Z 반주기에 반대측 마이크가 라인을 구동(VOH/VOL)하므로 플로팅이 없고 DC 오프셋 발생 가능성이 낮다. 그러나 현재 보드는 DATA 라인 분리(U7=DIO23, U9=DIO17). 분리선에서 미스매치 시 High-Z 반주기에 다른 마이크가 라인을 당겨주지 않으므로 플로팅이 실제로 발생. DATA 라인 풀다운·풀업 저항 존재 여부에 따라 잔류 전압이 GND 또는 VDD 방향으로 끌리며, PDM 디코더(E8300 decimation 필터)는 이를 지속적인 편향 비트열로 처리 → DC 오프셋. (그라운딩 §5 미해결_1(회로도 미확인); lib_audio_in.h:48-49 (DIO23/DIO17 분리))
- **오디오 증상 2: 광대역 노이즈 및 간헐 손상 — PDM 비트열 50% 오류 시 SNR 붕괴**
  - 근거: PDM은 1비트 sigma-delta 스트림. 정상 캡처라면 SNR은 sigma-delta 루프 이득과 decimation 필터 차수로 결정(SPH0641 SNR 63 dB typ.). 미스매치 시 전체 짝수 또는 홀수 클럭 샘플이 High-Z/stale 값으로 대체 → 유효 비트 밀도가 절반으로 감소 + 비유효 비트가 무작위 DC·잔류값으로 채워짐 → decimation 필터 출력은 전 대역 노이즈 + DC 바이어스. 스테레오 1 DATA 선 공유(예: 두 마이크, 한 쪽 HIGH·반대 쪽 LOW 구간) 구성에서는 미스매치 채널이 상대방 채널 데이터를 캡처하는 경우도 있어 간헐 음성 패턴이 혼입되는 'cross-capture' 증상도 발생할 수 있다. 단 분리선 구성인 현 보드에서는 cross-capture는 발생하지 않고 플로팅 노이즈만 발생. (SPH0641 §5 p.7 High-Z 설명; E8300 §18.2 p.563 low/high data channel 정의; lib_audio_in.h:48-49)
- **유형 A(SEL=GND + FE 설정) vs 유형 B(SEL=VDD + RE 설정): 동일 메커니즘, 차별점은 내부 풀다운**
  - 근거: SPH0641 §5 p.7: SELECT 핀 내부 풀다운 → floating/GND 기본 = Low 상태 = SEL=GND. 유형 A(SEL=GND + 펌웨어 FE): falling에 마이크가 구동 시작, FE 캡처가 그 순간 샘플 → setup time 위반 경계. 유형 B(SEL=VDD + 펌웨어 RE): rising에 마이크가 구동 시작, RE 캡처가 그 순간 샘플 → 동일 setup time 위반 경계. 물리 메커니즘은 동일하다. 그러나 '잘못 스트랩하기 쉬운 방향'은 다름: SEL floating = 내부 풀다운 = GND, 즉 유형 A(FE 설정인데 SEL이 GND/floating)가 '실수로 발생'하는 케이스. 현재 U9=FE 설정이므로 U9 SEL이 GND/floating이면 유형 A 발생. (SPH0641 §5 p.7 SELECT 내부 풀다운 명시; 그라운딩 §4 U9 FE 요구 SEL=VDD)
- **현재 펌웨어 위험 포인트: DMIC2(U9, ch2, FE 설정)가 단일 위험 지점**
  - 근거: lib_audio_in.h:80: DMIC1_DATA_RE(U7, ch1) → 요구 SEL=GND = 내부 풀다운 기본값과 일치 → floating이어도 우연히 정합 가능. DMIC2_DATA_FE(U9, ch2) → 요구 SEL=VDD = 능동 스트랩 필수. U9가 원래 QCC 담당(그라운딩 §미해결_2)이었으므로 SEL이 QCC 기준(QCC의 DMIC 캡처 엣지에 맞춰)으로 결정됐을 가능성 있음. QCC가 E8300과 동일 FE 기준이라면 SEL=VDD 스트랩이 맞고 정합 상태. QCC가 RE 기준이었다면 SEL=GND/VDD 어느 쪽으로 스트랩했느냐에 따라 E8300 측에 미스매치 발생 가능. 회로도 미확인 상태에서 U9 SEL 스트랩 실제값 불명. (lib_audio_in.h:48-49, 80; 그라운딩 §4 §미해결_2)
- **치명도 비교: SEL 미스매치(HIGH-Z 캡처)가 RE/FE 반주기 스큐(0.13 µs)보다 수백 배 더 치명적**
  - 근거: RE/FE 엣지 차이에 의한 두 채널 간 반주기 스큐 = ADCCLK 반주기 = 1/(2×3.84MHz) ≈ 130 ns = 0.002 샘플(@16kHz). 이 값은 DELAY_FRACTIONAL 1 LSB(0.26 µs)의 절반이며 CIC 30클럭 적분 윈도우 내에서 흡수된다(16-RE/FE 에이전트 로그 수렴 결론). 반면 SEL 미스매치는 전체 캡처 비트열의 50%가 High-Z 잔류값/플로팅으로 대체 → PDM SNR 완전 붕괴(dB 단위 열화). 양자는 비교 가능한 영역의 오류가 아님. RE/FE 스큐는 빔포밍 지연 예산 0.22%의 위상 오차, 미스매치는 채널 자체의 기능 불능. (에이전트-로그/16-REFE.md 수렴 결론; 그라운딩 §3 미스매치 정의)
- **DATA 선 분리 구성은 미스매치 증상을 '더 쉽게 드러나게' 한다(공유선보다 나쁨)**
  - 근거: 멀티플렉싱(1 DATA선 공유) 구성에서는 미스매치 마이크가 High-Z일 때 반대 마이크가 라인을 유효 전압으로 구동하므로 플로팅 전압이 VOH/VOL 중 하나로 고정됨 → 잘못된 데이터이지만 적어도 로직 레벨이 안정. DATA 선 분리 구성인 현 보드(DIO23/DIO17)에서 미스매치 시 해당 선 High-Z 반주기에 아무도 라인을 구동하지 않으므로 기생 용량 방전 속도·라인 풀다운 존재 여부에 따라 불안정 중간 전압 → 메타안정 샘플 가능성 높음. (lib_audio_in.h:48-49 DIO23/DIO17 분리; SPH0641 §6 High-Z 타이밍도)

## 미해결 질문
- U7·U9 실제 SEL 스트랩(VDD/GND/floating) 미확인 — 회로도 없이 펌웨어 정합 여부 최종 판정 불가. 특히 U9 SEL이 VDD로 능동 스트랩되어 있는지 또는 QCC 기준으로 GND 스트랩되어 있는지가 미스매치 발생 여부를 결정함
- U9 SEL을 QCC가 제어하거나 QCC와 E8300이 동일 SELECT 핀을 공유한다면 — QCC 측 DMIC 캡처 엣지 설정이 무엇인지(QCC 쪽 RE/FE 기준)를 확인해야 E8300 측 정합 충돌 여부 판단 가능
- DATA 선에 외부 풀다운/풀업 저항이 실장되어 있는지 미확인 — High-Z 구간 잔류 전압 거동(DC 오프셋 vs 플로팅 노이즈)의 양상이 달라짐
- SPH0641 타이밍도(§6) 상 assert setup time(rising/falling 엣지 대비 DATA 유효화 지연)이 명시되어 있는지 미확인 — setup time이 E8300 hold time보다 크다면 미스매치 엣지에서도 유효 데이터가 캡처될 수 있어 증상이 간헐적(온도·전원 의존)으로 나타날 가능성
