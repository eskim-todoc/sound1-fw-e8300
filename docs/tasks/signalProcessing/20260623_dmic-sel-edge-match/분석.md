# 분석 종합 (7 페르소나)

**TL;DR**: SPH0641 마이크는 SELECT 핀이 **데이터를 구동하는 반주기**를 결정한다(SEL=GND→LOW 구간, SEL=VDD→HIGH 구간, 나머지 반주기는 High-Z). E8300은 LOW 구간 데이터를 rising(`_RE`)에, HIGH 구간 데이터를 falling(`_FE`)에 캡처한다. 따라서 **올바른 조합은 SEL=GND↔`_RE`, SEL=VDD↔`_FE` 두 가지뿐**이며, 역조합은 High-Z 구간을 읽어 데이터가 손상된다. 현재 펌웨어(DMIC1=`_RE`, DMIC2=`_FE`)는 **U7 SEL=GND(내부 풀다운 기본과 정합)·U9 SEL=VDD(능동 스트랩 필수)**를 요구한다.

> 페르소나 원본: [`에이전트-로그/인덱스.md`](에이전트-로그/인덱스.md) 01~07. 사실: [`조사_SEL엣지-그라운딩.md`](조사_SEL엣지-그라운딩.md).

## 1. 마이크 전기 동작 (PDM 멀티플렉싱)

- SPH0641은 SELECT로 **DATA를 구동하는 반주기를 선택**(데이터시트 §5·§6 p.7):
  - **SEL=GND(Low)**: falling 직후 DATA assert → **클럭 LOW 구간 유효**, HIGH 구간은 **High-Z**.
  - **SEL=VDD(High)**: rising 직후 DATA assert → **클럭 HIGH 구간 유효**, LOW 구간은 **High-Z**.
- 각 마이크는 자기 반주기에만 라인을 구동하고 나머지는 트라이스테이트(High-Z) → 1 DATA선을 두 마이크가 공유(L/R 멀티플렉싱)할 수 있는 구조.
- **SELECT 내부 풀다운** → floating/미접속 = GND = LOW 구간 모드(기본값).

## 2. E8300 캡처 엣지 정의

- HW §18.2 p.563: **low data channel = 클럭 LOW일 때 보낸 데이터 → rising 캡처**, **high data channel = 클럭 HIGH일 때 보낸 데이터 → falling 캡처**.
- `DMIC*_DATA_RE`(0x2)=rising, `DMIC*_DATA_FE`(0x3)=falling.

## 3. 올바른 조합표 (요구사항_3) ✅

| 마이크 SEL | 데이터 유효 구간 | E8300 채널 유형 | **올바른 캡처 설정** |
|---|---|---|---|
| **GND (Low)** | 클럭 LOW | low data channel | **`DMIC*_DATA_RE`** (rising) |
| **VDD (High)** | 클럭 HIGH | high data channel | **`DMIC*_DATA_FE`** (falling) |

- **역조합(SEL=GND+`_FE` 또는 SEL=VDD+`_RE`)은 반드시 손상** — 호스트가 마이크 High-Z 반주기에 샘플 → 플로팅/직전값 캡처.

## 4. 현재 펌웨어 정합 조건 (요구사항_4) ✅

| 마이크 | 채널 | 펌웨어 엣지 | **요구 SEL** | 비고 |
|---|---|---|---|---|
| **U7 DMIC1** (Right front) | ch1 | `_RE` rising | **GND** | 내부 풀다운 기본과 일치 → floating이어도 우연 정합 가능 |
| **U9 DMIC2** (Left front) | ch2 | `_FE` falling | **VDD** | **능동 스트랩 필수.** GND/floating이면 미스매치(손상) |

- **핵심 리스크**: U9는 SEL을 VDD로 명시 스트랩해야만 정합. U9가 원래 **QCC 담당**이었으므로 SEL 스트랩이 QCC 인터페이스 기준으로 결정됐을 수 있어, E8300 `_FE` 캡처와의 정합을 **회로도로 반드시 확인**해야 한다(미해결_1·2).

## 5. 미스매치 증상 (요구사항_4)

- 호스트가 High-Z 반주기 끝에서 샘플 → 캡처값 = ① 직전 구동값의 기생 잔류(플로팅 용량), ② DATA 라인 풀저항 결정 전압, ③ 누설·노이즈. → **PDM 비트 스트림 손상 → DC 오프셋·광대역 노이즈·간헐 오류**(decimation 후 가청 잡음).
- U9 미스매치 시 Left front 채널이 통째로 무효 → **빔포밍 자체 불성립**(한 채널 쓰레기).

## 6. 빔포밍 연계 — RE/FE 통일 판정 (요구사항_5, 포인트_3 해소)

- 본 보드는 **DATA선 분리**(U7=DIO23/U9=DIO17)+CLK 공유 → 멀티플렉싱 충돌 없음 → **두 마이크 both-RE(둘 다 SEL=GND) 통일 HW상 허용**.
- 통일 시 RE/FE 반주기 스큐(0.13µs) **원천 제거**. 단 빔포밍 영향은 어차피 미미(스큐가 목표 지연의 0.22%, decimation 시분할 스큐 7.81µs·온도 4.12µs가 지배).
- **결론**: 현재 RE/FE 분리는 "자유 선택"이 아니라 **각 마이크 SEL 스트랩에 강제된 설정**. both-RE 통일은 **SEL 재스트랩(HW 변경)을 전제**로만 가능하며, 빔포밍 정확도 이득은 한계적 → **우선순위 낮음**. 정합성(요구사항_4)이 훨씬 중요.

## 7. 분석 잔여 미해결

1. **미해결_1(최우선)**: 회로도에서 U7·U9 SEL 스트랩(VDD/GND/floating) 실측 — 펌웨어 정합 최종 판정 전제.
2. **미해결_2**: U9 SEL이 QCC 기준으로 결정됐는지 + DIO17을 QCC가 어느 엣지로 수신하는지.
3. **미해결_3**: both-RE 통일 시 `SRC_DMIC_DATA`(DIO17) 재검토·SEL PCB 수정 비용.
