# 분석: 5 변경 상세·영향·결정

**TL;DR**: 4 워킹트리 파일 변경 = 의미 변경 5건 + clang-format 포매팅 다수. 영구 변경 3건 (백텔 강제·stride 정책 명시·NofM 가용 조건 가드) + 임시 테스트 벡터 2건 (Phase 0 amplitude 강제·Map3 NofM 진입 강제). NofM 프레임 3 고정의 *경로*는 CM3 `stimulationParaCal.c` 가 공유메모리 `g_pcmFrameNum_per_channel` 에 3 을 쓰고, CFX `stimulationStrategy_NofM_PCM_Write()` 의 stride 가 그 값을 읽는 양방향 핸드셰이크. 16ch 미만 가드는 사용자 실수 방지 + NofM 의미 (다중 채널 동시 자극) 보존. 본 task 는 src commit + docs commit 분리 (2 commit) 후 develop·main `--no-ff` 머지.

## 1. 변경 5건 상세

### 1.1 ① CFX `driver_PCM_liveStimulation.c` `frame_3_perChannel()` — 백텔 강제

**위치**: `src/1__cfx/internalDevice/driver_PCM_liveStimulation.c` L154~165 부근

**변경**:

```diff
+   /* IMPORTANT : 펄스 폭 설정과 관계 없이
+    * pcm_Mold_connectionCheck 출력 후 바로 pcm_Mold_NopBacktel을 적용함으로써
+    * 백텔 수신 실패의 경우가 없도록 한다. */
+
    // 첫 번째 채널 데이터
    *((int _XMEM *) HEAR_ADDR_FIFO_PCM_WRITING)     = pcm_Mold_connectionCheck;
-   *((int _XMEM*) HEAR_ADDR_FIFO_PCM_WRITING - 1) = pcm_Mold_NopStandby;
-   *((int _XMEM*) HEAR_ADDR_FIFO_PCM_WRITING - 2) = pcm_Mold_NopStandby;
+   *((int _XMEM *) HEAR_ADDR_FIFO_PCM_WRITING - 1) = pcm_Mold_NopBacktel;  // pcm_Mold_NopStandby;
+   *((int _XMEM *) HEAR_ADDR_FIFO_PCM_WRITING - 2) = pcm_Mold_NopBacktel;  // pcm_Mold_NopStandby;
```

**이유** (사용자 설명): NofM 시 프레임 수가 3 으로 고정되는데, 펄스 폭 설정에 따라 FPGA COLA 프로토콜 전송 시간이 1 프레임으로 끝날 가능성 존재. 그 경우 `pcm_Mold_connectionCheck` 직후 슬롯이 NopStandby 면 내부기 Backtel 송신을 수신 못 해 에러 발생. NopBacktel 로 강제하여 항상 수신 준비 상태 유지.

**Trade-off**: 전력 소비 소폭 증가 (Backtel 회로 가동 시간 2 프레임 추가). 사용자 판단 = "2 프레임 정도는 큰 의미 없음".

**부수 변경**: `_XMEM*` → `_XMEM *` (포인터 공백 정리, clang-format) 파일 전체 다수.

### 1.2 ② CFX `stimulationStrategy.c` `stimulationStrategy_NofM_PCM_Write()` — stride 정책 명시

**위치**: `src/1__cfx/signalProcessing/stimulationStrategy.c` L390~395 부근

**변경**:

```diff
    int _XMEM *p_pcmFIFO = (int _XMEM *) HEAR_ADDR_FIFO_PCM_WRITING;
-   int stride = g_pcmFrameNum_per_channel;
+#if 1

+#else
+   int        stride    = 3; // IMPORTANT : NofM일 때는 자극 당 3 프레임을 고정 시킴

```

**이유** (사용자 설명): 초기에 NofM 시 stride 를 3 으로 직접 고정하려 했으나, 단일 함수 내 하드코딩보다는 CM3 측에서 공유메모리 `g_pcmFrameNum_per_channel` 에 3 을 쓰는 방향으로 전환. CFX 측은 공유메모리 값을 그대로 읽음 (`#if 1` 가지). `#else` 가지는 *backup 의도* 보존 (재활용 가능성).

**결과 흐름**: CM3 `stimulationParaCal.c` (요구사항_5) 에서 NofM 시 `frameNumPerOneChannel = 3` → 공유메모리 → CFX 가 stride = 3 으로 사용.

### 1.5 ⑤ CM3 `stimulationParaCal.c` `calculationStimulParaN_cfxShare()` — NofM 가용 조건 가드

**위치**: `src/2__cm3/Cortex-M3-src/signalProcessing/stimulationParaCal.c` L585~602 부근

**변경**:

```diff
    frameNumPerOneChannel  = calculationNumFramePerOneChannle(p_mapdata->stimulationPulsePhaseWidth);
    transferableChannelNum = calculationTransferableChanneNum(frameNumPerOneChannel, p_mapdata->numFrequencyBand);

+   /* IMPORTANT : NofM 사용 시 프레임 수 고정. NofM 가능 여부를 판별하는 기능이 필요함 */
+#if 1
+   if (p_mapdata->stimulationStrategy == df_stimulationStrategy_nOFm)
+   {
+       if (p_mapdata->numFrequencyBand < 16)
+       {
+           ci_printe("[PARAM] [NofM] NOT AVAILABLE! 'BAND NUM < 16' !! \r\n");
+       }
+       else
+       {
+           frameNumPerOneChannel  = 3;  // 채널 당 3 프레임
+           transferableChannelNum = 8;  // 1 밀리초에 최대 8 채널 자극
+           ci_printw("[PARAM] [NofM] FRAME NUM PER 1 CH  : 3 \r\n");
+           ci_printw("[PARAM] [NofM] TRANSFERABLE CH NUM : 8 \r\n");

+#endif
```

**이유** (사용자 설명): NofM 프레임 수 3 고정 → 1 밀리초 최대 채널 수 = 8 (=24/3). NofM 의 의미 (다중 채널 동시 자극) 가 살아 있으려면 가용 채널 수 ≥ 16 이어야 함. 16 미만이면 *에러 출력* (`ci_printe`) 으로 사용자에게 명시 + 자극 파라미터 자동 보정 안 함 (사용자가 맵 재구성 유도). 16 이상이면 `frameNumPerOneChannel = 3`, `transferableChannelNum = 8` 강제.

**연계**: 본 함수가 공유메모리에 `g_pcmFrameNum_per_channel = 3` 을 쓰는 경로. ② CFX stride 와 양방향 핸드셰이크 완성.

## 2. 영향 범위

### 2.1 영향 받는 함수·동작

| 영역 | 동작 변경 |
|---|---|
| NofM 자극 모드 진입 | Map3 자동 NofM (임시) |
| NofM 자극 시 PCM frame stride | 공유메모리 → 3 고정 (CM3 측 강제, CFX 측 그대로 읽음) |
| NofM 시 1 ms 채널 수 | 8 채널 (가용 채널 ≥ 16 일 때) |
| NofM 시 frequency band 16 미만 | 에러 메시지만 출력, 자동 fallback 없음 — 사용자 맵 재구성 필요 |
| `frame_3_perChannel()` 백텔 수신 | NopBacktel 2 슬롯 추가 → 항상 수신 준비 (FPGA COLA TX 1 프레임 종료 race 회피) |
| NofM 자극 amplitude (임시) | Phase 0/1 = 결정론적 16 값 (실 신호처리 무시) |

### 2.2 영향 받지 않는 영역

- CIS 자극 모드: `stimulationStrategy_CIS()` 무변경
- NofM 본체 알고리즘 (Peak_Pick, Interleaving, Packet): 다니엘 작성·검증 완료, 본 task 미변경
- Map1·Map2·Map4: `stimulationStrategy = 1` (CIS) 유지
- Backtel 인입 회로 동작 (`Enable_backtelCircuit()`, `Disable_backtelCircuit()`): 무변경

### 2.3 부수 효과

- 전력 소비: `frame_3_perChannel()` 의 NopBacktel 2 슬롯 추가 → 2 프레임 분 Backtel 회로 가동 (사용자 판단 = 무시할 수준)
- NofM 시 채널 수 8 고정 → 사용 가능 전극 수가 16 ≥ 인 맵 한정 (그 외 사용자 에러 안내)
- 임시 amplitude (③): NofM Peak_Pick·Interleaving 단계가 결정론적 입력 받아 검증 가능 — 사용자 빌드 후 출력 파형 분석 용도
