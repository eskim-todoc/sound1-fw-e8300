# 빔포밍 코드 리팩토링 — 요구사항

**TL;DR**: 기능 정확성이 검증된([`20260625_beamforming-impl-review`](../20260625_beamforming-impl-review/)) 빔포밍 구현을 **동작을 1비트도 바꾸지 않고** 리팩토링한다 — ① 매직 리터럴/숫자를 의미 있는 상수로 대체, ② 복사·반복문 효율 개선, ③ 누가 봐도 이해되는 주석. 다중 페르소나, **할루시네이션 0**, **계획대로·정확 구현 검증**이 최우선.

---

## 1. 배경
- 은수님 빔포밍 구현은 리뷰 결과 **기능적으로 정확**(검증 confirmed 3/반증 0). 재작성 불필요.
- 따라서 이번 작업은 **품질 리팩토링** — 동작 보존(behavior-preserving)이 절대 제약.

## 2. 목표 (요구사항)
- [ ] **요구사항_1 (상수화)**: 매직 리터럴/숫자(마이크 수, 블록 크기, 버퍼 블록 수, 마이크 인덱스, ÷2 정규화, 지연 오프셋 등)를 **대체 가능하면 의미 있는 상수**로. 단 상수값 = 원 리터럴값 **완전 동일**.
- [ ] **요구사항_2 (효율)**: 복사(`tdc_copy_DMIC_buffers`)·반복문(믹서 16줄 언롤 등)에서 **출력 동일을 보장하며** 효율/가독 개선 가능 지점.
- [ ] **요구사항_3 (주석)**: 버퍼 인덱스 규약(0=최신 등)·지연 메커니즘·L/R 조향·게인 의도(÷2 vs 비÷2)를 **제3자도 이해할 주석**으로.
- [ ] **요구사항_4 (검증)**: 모든 변경이 **동작 보존**임을 adversarial로 검증(상수==리터럴, 루프==원출력, 주석==사실). 할루시네이션(존재하지 않는 라인·잘못된 값) 0 보장.

## 3. 범위
- **대상 = 빔포밍 관련 코드만** (은수님이 추가·수정한 부분):
  - `lib_audio_in.{c,h}`: 빔포밍 매크로·상수·버퍼 선언·front-mic·enable_1/2_DMIC·2-DMIC 분기·statics.
  - `audioMixer.c`: `audio_mix_2_buffers_for_beamforming` (+ `audio_mix_2_buffers` ÷2 의도 주석).
  - `main.c`: `tdc_copy_DMIC_buffers`·`PCM_LiveStimulation_Mode` 빔포밍부·`normal_loop` 1↔2 전환·`g_enabled_mic_count`(데드 변수).
  - `system_control.c`: L/R 조향 switch 블록.
- **제외**: 기존 무관 코드 일괄 변경, 기능 변경, 알고리즘 변경.

## 4. 제약 (절대)
- **동작 보존**: 빌드 결과·런타임 동작 불변. 상수화는 값 동일, 루프 변경은 출력 동일.
- **신규 심볼 `tdc_` 접두어** 검토(루트 지침). 단 기존 심볼 일괄 rename은 별도.
- 4단계 프로세스: ①요구사항→②분석→③계획→**승인**→④구현+검증. 승인 전 코드 변경 금지.
- 방법: 다중 페르소나(분석·검증), 할루시네이션 검증 노드 강제.
