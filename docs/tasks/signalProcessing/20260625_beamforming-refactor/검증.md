# 동작 보존 검증 종합 (단계_4, 5 페르소나)

**TL;DR**: 리팩토링은 **동작 보존**으로 확정 — 5 페르소나 중 **preserved 4**, 나머지 1건 "regression"은 **오귀속 오탐**이다. 그 페르소나가 `git diff HEAD`(빔포밍이 아예 없는 원본)와 비교해 **은수님 구현 변경을 리팩토링 변경으로 오인**했다. 지적된 2건(COUNT==1 폴백 MUX·인터럽트 게이트 dac1)은 모두 **내가 편집하지 않은 라인**(은수님 구현)으로 라인 증거로 확인됨. 단, 둘은 은수님 코드의 **유효한 관찰**이라 별도 보고.

> [!NOTE]
> 페르소나 원본: [`에이전트-로그/인덱스.md`](에이전트-로그/인덱스.md) 10~14.

## 2. "regression" 2건 — 오귀속 분석 (anti-hallucination)

| 지적 | 실체 | 판정 |
|---|---|---|
| REGRESSION-1: COUNT==1 폴백 MUX 불일치 (`lib_audio_in.c:125/135`) | `#if (COUNT==1)` 브랜치의 `SYS_SET_ADC_DEC_CTRL(AUDIO, 1,..)`·`DMIC1_DATA_SRC_DIO_23` — **내가 편집하지 않은 은수님 구현** | 리팩토링 무관 |
| REGRESSION-2: 인터럽트 게이트 `mic1 && dac1` 추가 (`main.c:194`) | `pcm_out && mic0 && mic1 && dac1` — **내가 편집하지 않은 은수님 구현** | 리팩토링 무관 |

- 두 라인 모두 내 편집 목록(상수·주석·데드코드)에 **없음** → 라인 증거로 확인. 페르소나가 베이스라인을 HEAD(빔포밍 전)로 잡아 **은수님의 풀 구현 변경 + 내 리팩토링**을 합쳐 본 것이 원인.
- 같은 페르소나의 "g_enabled_mic_count가 HEAD/현재 모두 미존재라 무해" 판단도 동일 오류(실제로는 은수님 구현에 있었고 내가 데드 제거함).

## 3. 그래도 유효한 관찰 (은수님 구현 — 리팩토링과 별개)

> [!NOTE]
> 아래는 리팩토링 결함이 **아니며**, 은수님 구현에 대한 참고 관찰이다(20260625 impl-review와 일부 중복).

- **관찰_1**: `LIB_AUDIO_IN_DMIC_ENABLE_COUNT`을 1로 되돌리면 `#if(COUNT==1)` 폴백이 신규 ch0 패리티(DMIC0)와 불일치(여전히 ch1/DMIC1 경로). 현재 COUNT=2라 **비활성**이나, 헤더 `// 1` 흔적이 남아 스위치백 시 EZ 마이크 경로 불일치 위험. (impl-review에서도 1-DMIC 경로 관련 언급.)
- **관찰_2**: 인터럽트 게이트가 `mic1 && dac1`까지 요구 — 2-mic 빔포밍 처리 동기화를 위한 은수님 의도로 보이나, 초기화 직후 첫 dac1 인터럽트 전 startup 창은 HW 동작으로 확인 권고.

## 4. 결론

- **리팩토링은 동작 보존이다(preserved).** 상수=리터럴, 로직 불변, 빌드 안전, 빔포밍 동작 유지 — 4 페르소나 + 기계 검증 일치.
- "regression" 1건은 베이스라인 오류에 의한 **오탐**(라인 증거로 반증).
- 할루시네이션 0 원칙대로, 오귀속을 그대로 전파하지 않고 **검증·반증**하여 확정.
