# 리팩토링 인벤토리 분석 종합 (9 페르소나)

**TL;DR**: 실파일 정독으로 **76항목** 인벤토리 도출(상수 19·주석 27·데드코드 11·네이밍 8·루프 11). 할루시네이션 검증 **all_real(0건 창작)**, 동작보존 검증 **unsafe 3건 적발**(믹서 언롤→루프·I2S XOR·mic복사 삼항 — DSP chess 스케줄 위험). **안전 항목(상수화·주석·데드코드)만 채택**, 위험 3건은 제외. 추가로 **한 페르소나의 주석 제안에 지연값 오류**(FRAC=6을 6/32=0.1875샘플·25mm로 오기)를 발견 → 계획에서 검증값(6/240=0.025샘플·1.025샘플·22mm)으로 교정.

> [!NOTE]
> 페르소나 원본: [`에이전트-로그/인덱스.md`](에이전트-로그/인덱스.md) 01~09.

## 2. 제외 항목 (동작보존 위험 — 현행 유지)

| 항목 | 위험 | 사유 |
|---|---|---|
| 믹서 16줄 언롤 → 루프화 (`audioMixer.c:59-74`) | high | split-loop가 수학적으로 같아도 **CFX `chess_loop_range` DSP HW 루프 스케줄**이 완전 언롤과 달라질 수 있음. 언롤 유지 |
| I2S 버퍼 위치 XOR 토글 (`main.c:158`) | high | **빔포밍 범위 외** + `lib_i2s.c` modulo-8 경로와 결합. 손대지 않음 |
| mic 복사 루프 삼항식 (`main.c:324`) | medium | `(mic==0)?HCT_A0_0:HCT_A0_1`을 chess 루프 내 XMEM 포인터로 쓰면 CFX 처리 불확실. 현행 2-블록 유지 |
| 버퍼 블록 인덱스 `LATEST/PREV` 상수화 | medium | `MAX_CNT-2/-1` 산술은 BUF_MAX_CNT 변경에 적응하나, `LATEST=0/PREV=1` 상수는 MAX_CNT>2에서 틀려짐 → **산술 유지 + 주석**이 더 안전 |

## 3. ⚠️ 할루시네이션 catch (제안 주석 내용 오류)

- 주석 페르소나가 `lib_audio_in.h:112`·`audioMixer.c:55` 등에 제안한 주석에 **지연값 오기**:
  - 오기: "FRAC=6 → 6/32샘플 = 0.1875샘플", "총 지연 ≈ 1.1875샘플(~25mm)".
  - **정정(검증값)**: FRAC=6 = **6/240 = 0.025샘플**(fractional 스텝 1/240, 20260625 리뷰 확정), SW 1샘플 + HW 0.025 = **1.025샘플 ≈ 22mm**.
- 할루시네이션 검증기는 *기존 코드 실재성*만 확인 → *신규 제안 주석의 사실 오류*는 미적발. **계획의 모든 주석은 검증값으로 직접 작성**한다(페르소나 문구 그대로 복붙 금지).
