# 오케스트레이터 입력 — 리팩토링 인벤토리 분석 (②분석)

**TL;DR**: 빔포밍 관련 실파일을 정독해 리팩토링 인벤토리(상수·루프·주석·네이밍·동작보존위험)를 도출. 각 항목은 **file:line + 현재코드 + 제안 + 동작보존 근거**. 할루시네이션 방지 위해 각 노드는 실파일 Read로 검증, 별도 검증 노드가 인벤토리 실재성 재확인.

## 대상 파일 (빔포밍 관련만)
- `src/1__cfx/lib_cfx/lib_audio_in.{c,h}`, `src/1__cfx/systemControl/audioMixer.c`, `src/1__cfx/systemControl/main.c`(빔포밍부), `src/1__cfx/systemControl/system_control.c`(L/R switch).

## 분석 페르소나 (②, 7)
1. 상수화 인벤토리 — 매직 리터럴/숫자(마이크 수 2, 블록 16, BUF_MAX_CNT, 마이크 인덱스 0/1, ÷2, i+1 오프셋) → 상수 제안(값 동일 명시)
2. 루프·복사 효율 — tdc_copy_DMIC_buffers·믹서 16줄 언롤·시프트 순서, 출력 동일 보장 개선
3. 주석·가독성 — 버퍼 규약·지연·L/R·게인 의도 주석안
4. 네이밍·tdc_ 컨벤션 — 신규 심볼 tdc_ 접두어·s_/g_ 일관성·데드 변수(g_enabled_mic_count)
5. 동작보존 위험 감별 — 각 제안이 동작을 바꿀 위험(상수값·언롤→루프 시 chess_loop·오버플로·경계) 사전 식별
6. 헤더/스코프 정리 — 매크로 위치·중복·데드코드(_0_9958)·extern/선언
7. 인벤토리 종합·우선순위 — 항목 통합·중복제거·우선순위(저위험 우선)

## 검증 페르소나 (③ 직전, adversarial 2)
1. 인벤토리 실재성 검증 — 제안된 file:line·현재코드·리터럴값이 실파일과 일치하는지(할루시네이션 적발)
2. 동작보존 검증 — 각 제안이 정말 behavior-preserving인지(상수==리터럴, 루프==출력) 반증 시도
