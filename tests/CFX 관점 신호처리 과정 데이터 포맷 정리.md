<br/>

### 오디오 입력

* DMIC -> Digital Decimation Filter -> IOC -> FIFO 입력 : 24 비트 **Q1.23**, but **integer 24비트**로 사용
<br/>

### FIFO 이벤트 발생

* 입력 데이터에 일괄 ">>5" 적용 : 부호비트 유지 **Q6.18**, but **integer 24비트**로 사용 (유효 비트는 **Q6.18**)
* vAbsolute, MaxElement 모듈 사용하여 최대 크기 값 획득 
* 최대 크기 값 기준 AGC 적용.
* AGC (**Linear gain** 값 찾기) 과정에서 사용되는 주요 시스템 함수
	* cfx_pwr_to_dB() : 입력 Q1.47, 출력 Q8.16, (**주의 사항 : 정수 23 이상부터 정상적인 계산 가능**)
	* cfx_dB_to_pwr() : 입력 Q8.16, 출력 Q1.47
	* cfx_dB_to_pwr() 출력 결과에 **">>24" 적용하여 Q1.23 형식으로 정리**
	* **최종 Linear gain**은 추가적인 쉬프트 연산을 통해 **Q12.12로 반환**
* **오디오 입력 데이터 Q24.0 (실제 유효 비트 Q6.18) × Linear gain Q12.12** = Q36.12
* Q36.12 >> 12 = Q36.0에서 하위 24비트만 사용하여 **Q24.0으로 사용**
* **integer 24비트 범위 초과시 최소/최대 값으로 절삭** (**-8,388,608 ~ +8,388,607**)
* **게인 적용된 Q24.0 데이터를 FFT FIFO에 삽입**
<br/>

### Win_DFT_R_Forward 모듈 계산

* FFT 계산에 사용되는 **윈도우 계수는 Q1.23 형식**
* 출력되는 계산의 크기 정보
	* 일반적으로 **FFT는** 주파수 영역에서 **결과 값이 FFT_SIZE 만큼 배로 크게 출력**됨
	* 입력 신호가 사인파인 경우 **Real/Image 영역으로 에너지가 분산**되기 때문에 **Real 영역에서만 보면 1/2 크기**로 확인할 수 있음
	* **FFT 계산에 해닝 윈도우를 적용하기 때문에 약 1/2 에너지 감소가 발생**할 수 있음
	* **HEAR의 BFP 연산 특성으로 게인이 1/4 적용**됨 (**FFT 계산이 BFP 22비트로 출력**)
	* 결과적으로 **주파수 영역의 크기를 시간 영역의 크기로 변경하려면 아래의 계산을 따른다.**
	* "(결과  / FFT_SIZE) × (Real/Image영역에 대한 게인 2) × (해닝 윈도우에 대한 게인 2) × (HEAR BFP에 대한 게인 4)"
	* 즉, (결과 / (((FFT_SIZE / 2) / 2) / 4)) ==> (결과 / (FFT_SIZE / 16)).
	* **FFT_SIZE가 512**인 경우, (결과 / 32) ==> **(결과 >> 5)** 가 됨.
<br/>

### vMag 모듈 계산

* 기본적으로 VMAG_DOUBLE_PRECISION 이라서 48비트, Q2.46으로 출력함.
* 현재는 **VMAG_SINGLE_PRECISION 이기 때문에 상위 Q2.22를 추출해서 사용**.
* 그래서, **vMag 연산 결과도 1/2 작게 출력**됨.
<br/>

### 최종 결과

* vMag로 계산된 Energy 정보 256개가 출력됨. **(주의 사항 : 결과 [0] DC, [1] Nyquist)**
